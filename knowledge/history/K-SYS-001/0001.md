# K-SYS-001：保留主机调用与设备执行的时间关系

| 元信息 | 内容 |
|---|---|
| 条目标识 | K-SYS-001 |
| 主分类 | 系统语义与一致性 |
| 类型 | 异步时间语义与测量解释 |
| 状态 | 已有支持；具体数值仅属于本次用例 |
| 来源 | CASE-0001、区间数学性质与 NVIDIA 分析说明 |

## 核心认识

主机 API 的调用区间和设备工作的执行区间需要分别保留。提交调用尚未返回时，设备工作可能已经开始；调用结束到设备开始的差值不能无条件解释为实际排队时间。

如果多个事件的区间存在重叠，其累计时长与区间并集长度不同。累计时长有助于寻找调查入口；端到端延迟需要另外确认开始、结束和依赖关系。单个进程的已观察区间不能代表整台设备的全部活动。

## 适用条件与机制

首先确认事件来自可关联的时间轴与进程范围，再解释主机与设备的先后。跨采集文件、跨机器或只有相同关联编号时，需要额外的身份和时间对齐依据。

同一组事件的区间并集长度不大于其时长之和。多个 stream 或线程发生重叠时，不能通过简单求和得到耗时。不同进程和设备分别解释；身份不明的记录保留关联缺口。

## 可观察现象与调查依据

出现负的“设备开始减去 API 结束”差值时，先核对原始事件、身份和时钟关系，不将负数直接归零并命名为精确排队耗时。多个 API 候选需要保留歧义。

查看局部时间窗口时，相关提交可能发生在窗口之前。事件查询和关联查询需要各自合适的范围，否则容易把窗口裁剪造成的缺口误认为丢失提交。

## 证据与边界

[CASE-0001](../cases/CASE-0001-nsys-observability.md) 的首个 kernel 比对应主机调用结束早 1116 ns 开始。这个事实支持在当前采集中保留重叠关系；该差值不是理论延迟下限，也不是模型性能指标。

重叠区间合并、跨进程及跨 VM 的编号冲突、窗口之外的 API 查找通过了合成数据行为检查；这不能替代真实多进程、多卡实验。

NVIDIA 的 [kernel 启动与执行时间说明](https://docs.nvidia.com/nsight-systems/AnalysisGuide/index.html#cuda-kern-exec-sum-nvtx-name-base-mangled-cuda-kernel-launch-exec-time-summary) 提供了异步阶段可能重叠的机制依据。
