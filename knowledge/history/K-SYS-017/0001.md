# K-SYS-017：向量检索与 RAG：索引、版本与端到端质量

检索管线把输入转换成查询表示，在约定的候选集合中搜索，再取回材料、重排并交给下游模型。索引的近邻准确率、材料相关性和最终回答质量是三个不同层次；只有把它们连接起来，局部检索加速才有明确意义。

## 查询函数和候选集合先于索引选择

索引侧应固定文档切分、编码器、pooling、normalize、向量维度、数值格式、距离函数以及向量 ID 到材料版本的映射。查询侧应使用配套的编码函数。相同维度只证明张量能相乘，不能证明两个模型产生的坐标空间兼容。

内积取最大值，L2 距离取最小值；是否返回平方 L2 影响阈值解释，即使排序不变。双方单位归一化时，平方 L2=2−2内积，但未归一化向量的范数会影响内积排序。维度缩减、量化和额外变换应同时应用于正确对象，并保留建立精确参考所需的原始向量。

候选集合还受租户、权限、语言、时间和删除状态限制。先搜索全库再过滤固定 top-k，未必得到允许集合中的 top-k；它可能返回不足 k 个，甚至遗漏所有合法近邻。过滤与搜索的结合应是明示的算法选择，性能和 recall 都在相同合法集合上比较。

## 搜索空间裁剪与向量压缩是两条轴

Flat 扫描访问全部向量，便于构造精确参考；批量查询可以把距离计算组织成矩阵运算，但 top-k 选择和输出仍需成本。IVF 在构建时训练粗聚类，查询时选择若干倒排列表；nprobe 控制扫描范围，列表不均会改变实际字节和尾延迟。HNSW 等图索引通过邻接遍历逐步寻找候选，搜索宽度控制探索，但会引入图边、随机访问和构建成本。

PQ 将向量拆成多个子向量，用各自码本编码。查询可以预计算到码本的距离表，在压缩域累加距离，避免把所有向量先恢复成 FP32。码本、查表、残差编码、ID 与列表偏移都要计入容量。PQ 压缩改变距离；IVF/图搜索减少访问范围。两者叠加时，应分别判断误差来自候选没被访问，还是访问后排序被压缩误差改变。

精排可以对一份更大的候选 shortlist 读取原始或较高精度向量重新计算距离。它提高候选内部排序的准确性，却不能找回粗召回从未返回的材料。交叉编码器重排还会改变评分函数，不能把其质量变化解释成近邻搜索误差。

Faiss 固定论文是这些索引机制的来源；它将自身限定为检索库，并不提供一个完整服务所需的并发写入、负载均衡、分片和一致性保证。把索引嵌入 InfraAgents 构建的服务时，这些职责仍需显式设计。

## 构建、发布、更新和查询的生命周期

一个可用索引版本需同时包含编码/变换版本、粗聚类与码本、向量或代码、ID 映射、过滤元数据和材料定位。构建过程中完成某个文件，不代表版本可以被查询；发布点应在这些对象共同完整且质量检查通过之后。查询绑定一个明确版本，读取期间保留其引用，新版本就绪后再切换新查询。

增量添加、删除和更新是否支持，取决于具体索引实现。Faiss 2024-01-16 固定论文说明其当时 HNSW 不支持删除/修改、NSG 不支持增量加入，IVF 可结合 DirectMap 处理 ID 操作；这些是固定实现的边界，不能外推所有同名算法或后续版本。服务可以采用不可变主索引加小增量索引、删除集合和周期重建，但需要处理重复 ID、版本优先级和两路 top-k 合并。

删除标记必须在返回材料前再次得到一致的解释；只从向量索引删掉 ID，而材料缓存仍按旧标识命中，会留下不一致路径。查询中途遇到旧材料失效，应遵循既定快照或明确失败/重查，不能悄悄用新内容替换旧向量对应的材料。

持久索引可由材料和编码器重建，并不意味着重建成本为零。是否保存原始向量、码本训练样本和构建参数，取决于恢复时间目标与可追溯性。内存映射文件也会产生缺页与 I/O，预热后延迟不能直接代表冷服务。

## 分片、缓存与设备放置

按文档 ID 分片时，每个分片搜索后合并候选。若每片都用相同精确距离并返回本地 top-k，合并可得到全局 top-k；近似检索或更小本地候选预算会改变该条件。全局结果需要去重、过滤和确定的同分规则，慢分片缺失不能被当作完整结果。

按 IVF 列表分布可以只访问相关分片，但热点列表可能集中压垮少数机器。复制热点列表增加容量和更新工作；缓存检索结果则依赖查询表示、过滤条件及索引版本。材料缓存与向量缓存应分别计量，命中一个小 ID 列表不代表后续大文本已经在本地。

GPU 更适合较大批量、规则的距离计算与选择，CPU 对小批和不规则遍历有不同成本。选择时要计入编码器输出所在位置、查询搬运、索引驻留、结果回传及和生成模型的 HBM/算力竞争。把检索放上同一 GPU 并不自动减少完整 RAG 延迟。

## RAG 的时间与质量链

完整在线链为入口排队、查询编码、候选搜索、材料读取、重排、截断与排列、prompt 构造、生成 prefill、首 token 提交。各阶段可以有并行或流水，但只有实际依赖允许时才取最大值，串行阶段必须相加。只测 prefill 的 TTFT 应明确起点；用户端 TTFT 包含前面的检索链。

增加候选数会影响搜索、材料读取、重排和最终上下文长度。减少检索数可能降低时延，同时丢失回答所需证据；扩大上下文也不保证质量单调上升。固定材料集合与顺序的系统比较，用来评价执行优化；改变候选、重排、压缩或片段复用策略的比较，则需要端到端质量约束。

非前缀 KV 复用可接在材料组装之后，但文档向量的独立可缓存性不能传递成 decoder KV 的独立可缓存性。材料位置、顺序与前文改变后，要按上下文复用章判断精确前缀或近似融合，而不是直接拼接状态。

## C12-B：检索与 RAG 的完整验证场景

设定 N=1,000,000、d=768、FP32，Flat 向量本体为 3,072,000,000 字节，约 2.86 GiB。候选 A 是 Flat 精确扫描；候选 B 是 4,096 列表的 IVF，加 96 个 8-bit 子量化器。B 的代码为 96,000,000 字节、64-bit ID 为 8,000,000 字节、粗中心为 12,582,912 字节，PQ 码本为 786,432 字节，合计 117,369,344 字节，尚未含列表结构、变换、过滤、工作区与高精度精排副本。若另外保存全部原向量，不能仍宣称整个系统只用这个压缩容量。

在列表完全均匀的设定中，nprobe=16 平均扫描 1,000,000×16/4,096=3,906.25 个向量，还要计算粗中心距离和 query 查表；真实列表偏斜、过滤与并发需重新测量。把 nprobe 提高到 32、64，画出同一查询集的 recall—p99—内存关系，不预设某个值满足质量。

独立距离算例取单位查询 q=(1,0)，数据库向量 a=(1,0)、b=(0.8,0.6)、c=(0,1)。内积依次为 1、0.8、0，平方 L2 为 0、0.4、2。禁用 a 后合法 top-1 应为 b；“全库 top-1 再过滤”的空结果不是正确参考。构造重复 ID、相同距离、更新文档、删除、空库、k 超过合法候选数及缺失分片，检查结果语义。

质量分三层：ANN recall 对固定原向量的精确合法近邻；材料检索/重排用有相关性标注的 recall、MRR/nDCG；最终回答用任务正确性与证据一致性。前两层通过不保证答案通过。索引训练集、调参查询与最终测试查询分开，加入新领域和冷材料分布以检查偏移。

一个时序设定为查询编码 5 ms、搜索 8 ms、取材料 12 ms、重排 30 ms、构造 2 ms、模型 prefill 并生成首 token 80 ms、提交 5 ms；完全串行且不含排队时为 142 ms。若优化把搜索 8 ms 降到 4 ms，其他不变，整体只下降 4 ms。所有数字是验证预算的设定，不是目标机器性能。高复用稳定库可以承担较重索引构建；频繁更新、小库或严格 recall 则可能让 Flat/简单增量方案更合适。
