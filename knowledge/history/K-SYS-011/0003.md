# K-SYS-011：模型生命周期：加载、就绪、排空与版本切换

模型服务的版本是一组共同定义输入到输出函数的制品和执行约束。权重、配置、tokenizer/processor、adapter、量化参数以及执行布局必须在同一次请求中保持相容。生命周期管理解决的不是单纯启动或停止进程，而是三个问题：何时有资格接收请求；切流后谁继续履行旧请求；何时能够把旧资源交给另一个版本。

文件存在、端口能连接、加载调用返回和路由已经更新，分别只证明一部分工作完成。把这些事件混成一个 ready 标志，会使未完成的执行组接收请求，或让旧请求读取已经被覆盖的权重。

## 版本、实例和就绪范围

区分三个身份。

- 制品身份 v：固定清单所引用的权重、配置、processor、adapter、量化与必要布局依赖。读取清单后固定其版本，不能逐片重新解析 latest。
- 加载实例 g：一次具体加载及其执行组。相同 v 的重试也创建新 g；旧尝试的完成通知不能使新尝试就绪。
- 路由代次 e：一次准入配置的身份。即使别名经历 v1→v2→v1，e 仍递增，防止第一次 v1 的过期路由重新有效。

实例内还要保存逻辑 rank 到实际设备、设备资源与地址绑定的映射。容器里的 device 0 不是稳定物理身份；设备重建、MIG 配置或执行组改变后，需要重新验证相应依赖。[部署环境](deployment-environment.md)解释设备暴露与真实资源边界。

将请求 r 的一次合法执行写为

(y,S′)=F_v(x,S;θ_r)，

其中 x 是已经按该版本解释的输入，S 是 KV、递归状态、RNG、grammar 等请求状态，θ_r 是采样与执行选项，y 是本次产生的结果。生命周期输出除了 y，还包括请求的绑定 (r,v,g)、准入票据、状态归属与最后使用责任。processor 参与输入解释，因此不能先用可变别名对应的 tokenizer 编码，再随意绑定另一个版本。可以先固定版本并持有其责任后处理输入，也可以在正式准入时验证输入解释身份一致。

就绪证书可描述为

C_g=(v,g,E_g,P_g,Ω_g,Π_g)，

E_g 是环境和执行依赖身份，P_g 是完整 rank/设备/布局计划，Ω_g 是允许公开的请求范围，Π_g 是制品检查、完成证据和代表路径验证记录。Ω_g 应能判定模型、dtype、输入几何、上下文上限、adapter 路径、图桶或受验证回退路径是否合法。代表输入通过是该路径的证据，不是整个 Ω_g 的数值正确性证明；范围的推广还要依靠形状 guard、容量边界和执行契约。

就绪资格与瞬时可接收容量分开。C_g 仍有效，但 KV 满了，可以暂时拒绝或排队；一个 rank 或设备依赖失效，则撤销相关资格。不能把暂时过载变成反复重启，也不能把历史预热成功当作失效环境仍然有效的证明。

## 从制品到就绪的准备算法

采用 PREPARING、READY、OPEN、DRAINING、RETIRING、RETIRED，以及失败状态 FAILED。READY 的新准入门仍关闭；OPEN 表示可按当前路由取得新准入；DRAINING 允许已有请求继续，却不允许新请求绑定。状态名称可以合并，以下完成条件不能合并。

```pseudocode
输入：不可变清单 v；不复用的实例身份 g；执行计划 P；公开范围 Ω；资源预算
输出：未发布的就绪实例 C_g，或带明确阶段与未结责任的失败结果

1. 创建 PREPARING(g)，关闭准入门；初始化 rank 完成集合为空。
2. 固定清单与全部依赖身份；检查必要分片、长度、完整性、张量关系、
   processor、adapter 和量化/布局元数据。发现缺片或不相容则转失败。
3. 按每个设备和主机统计准备期间的唯一存储并集与预留。
   同时计入仍存活的旧版本、转换区、图池、通信区和预热状态。
   取得全部必要资源的预留；任一处不足则等待、调整计划或失败。
4. 对每个 rank，按 P 加载并转换完整张量，建立真实设备与布局映射。
   每次异步访问在提交前登记使用责任；源与目的地址受保护到最后访问结束。
5. 建立完整执行组及所需通信上下文；共同核对 v、g、P 和操作协议。
6. 为实际公开的执行变体建立或核对编译产物、图及工作区。
   复用 key 包含其真实依赖，不以模型名称单独判断命中。
7. 在实际执行线程设定模型评估行为和所需推理上下文。
   运行代表路径、边界与独立参考比较；检查必要 rank 的共同结果。
   预热的 KV、RNG、输出与测试请求使用隔离状态。
8. 等待影响执行可读性的加载、转换和初始化完成证据。
   清理或隔离预热状态；不能把测试请求历史交给正式请求。
9. 每个 rank 仅为当前 (v,g,P,Ω) 报告完成；重复或旧尝试报告不改变资格。
   只有全部必要 rank、依赖和验证条件满足，才发布 C_g 并进入 READY。
10. 任一步失败：关闭准入，记录最早失败与已完成范围，进入 FAILED。
    停止后续准备，排空已提交访问，解除绑定后释放可回收资源。
    超时只记录未结责任；重试使用新的 g，不复活这个失败尝试。
```

第 3 步需要逐设备判断。两个 rank 总需求小于两张卡的总容量，不保证某个 rank 的局部峰值可行。设备插件的 time-slicing 份额也不会创造额外显存或独立故障域；固定 v0.16.1 的共享资源声明只能支持相应访问与限额契约，不能代替这里的容量检查。

第 7 步同时涉及模型行为与运行簿记。[S-TORCH-INFERENCE](../sources/S-TORCH-INFERENCE.md) 的机制说明指出 inference_mode 是线程局部状态，不会自动调用 eval。入口线程进入推理模式，不证明后台执行线程相同；关闭 autograd 也不证明 Dropout、统计 buffer 或其他可变模型状态已经符合服务契约。

编译产物的失效范围由依赖决定。权重作为运行时参数、ABI 和布局保持相容时，数值替换不一定要求重编译；常量折叠、预打包格式或捕获地址改变时，则要重建受影响产物。无论是否复用编译代码，旧图仍引用的地址都不能被原地覆盖。详见[编译与动态形状](../frameworks/compile-dynamic-shapes.md)和[CUDA Graph](../frameworks/cuda-graph-buffers.md)。

## 准入与切流必须有共同排序点

定义权威路由 A=(e,g)，并为实例保存准入门。下面选择一个保守模型：路由变更、门控和请求责任登记在同一串行状态域中排序，设备资源由该域可核对的预留账保证。它说明需要的原子关系，不要求把所有设备工作放进一个锁。

```pseudocode
准入(r, 请求摘要, 期望路由 e/g, 请求范围 σ)：
  在权威状态域中：
    若 r 已有准入记录：
      同身份与摘要的重试返回已有记录；冲突输入拒绝。
    核对当前 A=(e,g)，实例为 OPEN，C_g 有效，σ 属于 Ω_g。
    核对输入解释身份与 v 一致。
    计算本请求所需的逐设备增量预留 δ，包括已承诺的在途增长上界。
    若资源不足，按既定策略返回等待或拒绝，不创建半份正式请求。
    原子取得预留，登记逻辑请求责任 R_g 中的 r，
      写入不可变绑定 (r,v,g) 与准入票据，再返回接受。

切流(op, 期望代次 e, 目标 h)：
  在同一权威状态域中：
    若 op 已有决定，核对参数一致并返回原决定。
    核对路由代次仍为 e。
    核对 h 为 READY，或为尚未进入 RETIRING 且重新验证合格的 DRAINING；
      C_h、分配和环境依赖仍有效。
    关闭旧目标 g 的新准入门，令其进入 DRAINING。
    打开 h 的新准入门，令其进入 OPEN。
    原子写入 A=(e+1,h) 和 op 的已提交决定。
    保留全部已接受请求的原绑定和预留。
```

准入先发生，旧请求已经在 R_g 中，即使队列消息在切流后才抵达 worker，仍由 g 履行。切流先发生，拿着旧 e/g 的新准入必须被拒绝或重新解析路由。不能先在路由器读取 g，再在另一处无条件递增引用计数；两步之间可能完成排空和卸载。

缓存路由只用于提出候选，不能自行签发旧版本的新准入。若使用分散式租约代替共同权威域，需要另行给出签发、撤销、租约存活与排空之间的证明；单纯等待一个估计的缓存传播时间不足以完成这个证明。多控制节点也不能各自根据本地超时开放实例。

跨节点预留若需多步完成，先取得临时预留，全部成功并重新核对路由后才安装正式准入。未提交预留失败时撤销；已经发出的设备访问继续承担排空责任。上述原子步骤不能直接推断任意远程 allocator 天然具有跨节点事务。

切流确认丢失时，控制者查询 op 的权威决定；相同 op 的重试返回原结果。结果未知时保留原资源责任，不能根据本地超时反向切流。回退是另一项有新 op 和新 e 的切流：它改变后续准入，不能撤回已经交付的回答，也不能重新绑定 v2 的活跃请求。

若旧实例仍完整驻留、尚未 RETIRING 且资格重新验证有效，可以重新开放它。已经开始拆除图、通信组或权重的实例必须重新准备，不能仅把状态标签改成 OPEN。别名回到同一个 g，也不使早期 e 的票据重新有效。

## 排空、取消与卸载算法

对实例 g 分开记录四类责任：R_g 是仍可继续执行的逻辑请求；U_g 是已经登记的 kernel、复制、传输等实际访问票据；B_g 是图、注册区和执行对象的地址绑定；O_g 是仍借用实例资源的输出消费者。每张票据含实例身份、用途和不复用的操作身份。请求数为零不等于后三者为空。

```pseudocode
已有请求继续执行：
  核对正式准入票据与不可变 (r,v,g)，不重新读取当前别名。
  核对请求仍有效，实例没有进入 FAILED、RETIRING 或 RETIRED。
  在提交任何异步访问前，为其全部实际资源登记 U 票据。
  对必要 rank 提交相容计划；发生部分提交失败时停止受影响尝试，
    按执行组恢复契约处理，排空已经发出的操作。
  输出若借用资源，先登记 O 再交给消费者，不能留下无人保护的交接窗口。

请求结束或取消：
  关闭该请求的新业务提交与新执行入口；按协议确定其终态。
  解除 R 与可解除的逻辑预留。
  保留已有 U、B、O；取消通知和终态标签不充当物理完成证据。

开始拆除实例：
  核对新准入门关闭，实例不再是有效路由目标，R 为空。
  原子进入 RETIRING；从此拒绝新请求、重新开放和新的地址绑定。
  停止准备及后台产生新工作的入口。
  在相关重放结束后拆除图、注册与通信绑定，逐项结束 B。
  持续处理真实完成证据，逐项结束 U 和 O。
  完成通知必须匹配 (g,操作身份,受保护范围)；旧代或重复通知不修改新责任。
  U、B、O 全部结束后，销毁执行对象并归还资源，进入 RETIRED。

排空期限到达：
  对仍活跃请求执行预先声明的终止、恢复或合法迁移策略。
  不伪造成功完成，也不把期限到达当作设备停止。
  无法证明结束的资源保持隔离，列出具体责任及解除条件。
```

这里选择整实例保守拆除。实际可以在对象级分别回收：若输出已经复制到独立主存且不再借用权重或设备缓冲，它不必延长这些对象的生命期；但复制完成与消费者交接必须有明确证据。反过来，主机响应线程结束也不证明设备 DMA 已经完成。

逻辑请求在 DRAINING 中仍可执行，因而不能仅因准入门关闭便拒绝所有旧迭代。取消则关闭该请求未来工作，但不能让某个 rank 单独跳过其他 rank 已经参与的 collective。执行组错误与单请求业务终态必须分别处理，见[推理服务恢复](serving-recovery.md)及[取消与完成](cancellation-resource-completion.md)。

本状态机的安全条件是：全部访问提交入口受责任登记约束，完成证据真实覆盖最后使用，控制决定有共同排序，接收端核对准入与执行身份。它不自行实现分布式共识、持久日志或设备中止。控制记录丢失、worker 崩溃或故障域不明确时，需要相应恢复协议；本地引用计数不能独立证明远端访问已经结束。

## 三种切换路线及状态相容边界

停止旧服务、排空后加载新版本，峰值较低，但存在服务空窗。新旧并存后切流，可以在准备新版本时继续服务旧请求，代价是双版本及准备过程的容量和资源争用。滚动更换多个副本，把容量峰值和容量下降分到多步，却要求每一步的剩余合格容量都足够。以上是带前提的策略选择，不是三种不同正确性要求。

一次请求始终绑定原 v。adapter 更新也以新不可变对象发布；不能在旧地址原地覆写 A/B、scale 或描述符。相同 adapter 名称、相同 shape 和相同物理地址都不证明内容身份相同。KV 的相容身份要覆盖影响该状态的依赖闭包，默认把模型与 adapter 版本纳入其中，见[多 LoRA 服务](../algorithms/lora-serving.md)。

会话下一轮使用新版本是协议选择。可以保留原版本并支付驻留，也可以用新 processor 重新解释可重放输入、重新计算状态；不能默认把旧 KV 接到新权重后继续。若声称某类状态可跨版本保留，需要证明该状态的全部生成依赖与后继消费契约相容，而不是只比较张量尺寸。

迁移地点与切换模型版本也不同。ServerlessLLM §5 利用相同只读模型下的 token 重算来重建 KV，并让目标先处理前缀、最后处理源端新增 token。这支持特定 Transformer 状态恢复路线，不证明任意模型状态只靠 token 即可恢复。通用迁移仍需冻结共同恢复边界、保存 RNG/grammar/递归与输出状态，并只移交一份提交权。

设已知 token 为 x[0,n)，已有完整模型状态到 p，p≤n。已采样或已交付 token 不一定已有自己的 KV。重建应明确恢复到 p，还是合法推进到另一个边界，避免重复采样或遗漏末行 logits。目标 READY 只说明具备接管条件，不等于已取得业务提交权。完整迁移与确认丢失处理沿用[取消与完成](cancellation-resource-completion.md)中的授权协议，本章的路由切流不替代它。

## 启动、驻留和有效容量的条件化成本

启动时间取决于资源等待、取得制品、加载转换、执行组建立、编译与预热、路由生效之间的依赖。对任务图中事件 j，若前驱集合为 pred(j)，独立资源且没有额外争用时有

F_j=max_{i∈pred(j)}F_i+t_j。

F_j、t_j 的单位为秒；无前驱时以前置可开始时刻为边界。共享 SSD、NIC、CPU 或主存的任务还要加入资源顺序或有效能力约束。不能同时给每个任务独占带宽并声称它们完全重叠。

若各 rank 独立完成本地流水，资源排队 q_r 发生在其前，L_r 已包含本地加载、检查、编译与预热，则

T_ready=max_r(q_r+L_r)+T_group。

T_group 只计真正位于这些工作之后的共同验证或屏障；已包含在 L_r 中的事件不能再加。两个 rank 的本地工作均需 4 s，排队分别为 0、1 s，之后共同验证为 0.5 s，则准备完成为 5.5 s。路由安装及必要传播另计；过期路由被安全拒绝期间，实际可接收吞吐仍可能下降。

ServerlessLLM §6.2 用 q+n/b 估计特定加载路径，其中 n 为模型分片字节，b 为所用流水中的慢层带宽。该系统以每服务器顺序加载减轻争用。这个估计不能直接覆盖任意并发、编译、预热和分布式准备图，也不能把热缓存下的 b 外推为冷启动带宽。

六类费用应在同一次切换范围中核对。

| 成本 | 需要计入的机制与条件 |
|---|---|
| 计算 | 解包、转换、完整性检查、编译、预热和可能的状态重算；重算是完整模型工作，不只包含 Attention |
| 访存 | 文件读取、CPU 转换读写、H2D、图输入与状态初始化；逻辑有效字节不等于 SSD、主存或 HBM 实际事务 |
| 通信 | 制品分发、执行组初始化、预热 collective、迁移和控制记录；按链路及单 rank/全组口径分别计量 |
| 准备 | 清单解析、对象建立、资源预留、设备映射、编译缓存核对与图捕获；常驻一次和频繁切换的摊销不同 |
| 同步 | 生产到消费、组内共同完成、准入切流排序和失败排空；host 返回不代表设备完成，逻辑发布也不必等于全设备同步 |
| 驻留 | 新旧权重、KV、执行/图池、转换区、预热状态及未排空资源；按同一时刻的唯一物理存储计数 |

对设备 d，容量峰值为

M_d,peak=max_t Σ_{a∈A_d(t)} size(a)，

A_d(t) 是该时刻占用预算的唯一 backing 集合，包括完整池及池外分配。池内活跃对象是池的一部分，不能再与整个池重复相加；共享不可变页计一次，真实复制两份计两次。主机内存、设备内存和存储分别建账。allocator 的 allocated/reserved 是统计口径，不能未经覆盖关系核对便作为额外对象相加。

设设备可用 24 GiB，旧权重 12 GiB、旧请求 KV 5 GiB、共同运行与临时区 3 GiB。新权重另需 12 GiB，即使忽略新图和转换峰值，并存也需 32 GiB；排空旧 KV 后仍需 27 GiB。因此这组条件下单卡双版本并存不可行。可改用其他设备、降低满足数值契约的表示容量，或选择有空窗替换。提前报告就绪不会减少所需字节。

在完全串行的停止替换路径中，关闭准入到恢复服务的空窗可写成排空、回收、新准备与发布之和；若某些准备已经安全提前完成，则按依赖图重算，不能继续使用该串行和。并存路线虽然避免等待新版本准备才继续旧服务，却可能因加载抢占 PCIe、CPU 或主存而伤害旧请求延迟，需要与稳态执行共同测量。

排空墙钟时间由仍需履行的请求、访问、绑定与输出交接的最后依赖决定。若最后 kernel 和输出消费可以并行，不能将两者全部时长相加。取消后停止未来迭代可以减少设备工作，却不立即降低尚被保护的物理容量。

滚动策略还受服务率约束。设四个独立副本各能在声明负载下合格处理 20 请求/s，更新时一个副本排空，同时要求承受另一个副本故障，则剩余容量仅为 40 请求/s。到达 45 请求/s 时，正常更新的 60 请求/s 看似足够，故障后的要求却不成立。需要更多已就绪冗余、减小更新影响或明确降低服务承诺；尚在加载的副本不能计为 20 请求/s。

token 重算迁移可减少网络字节，但会增加目标计算与双端驻留。若传输 n 个 int64 token，主载荷为 8n 字节；KV 的逻辑主项若为 nτ 字节，τ 是每 token 的状态字节，则二者可相差很大。真正选择仍需比较目标模型准备、完整重算、最终增量和提交权移交。目标重算速率不高于源新增工作速率时，反复追赶不保证收敛，应冻结、降低源推进速度或放弃迁移。

## 切流、取消与异步回收的组合轨迹

以下是设定轨迹。旧执行组 g10 和新执行组 g20 各有两个 rank，使用不同设备；每张设备预算 24 GiB。旧设备当前权重、KV 和运行区为 12+5+3=20 GiB。新设备准备的峰值主项假定为权重 12、运行区 3、池外 staging 2、隔离预热状态 1，共 18 GiB。这里只说明给定物理分配下的可行性，不证明实际实现没有其他对象。

| 事件 | 权威状态与责任 | 可以进行的下一步 |
|---|---|---|
| A=(7,g10)，rA 已准入 | rA 固定 v1/g10；已登记旧 kernel k、图绑定 b 和借用输出 o | 新版本准备不改变 rA 的输入、KV 或采样身份 |
| g20 的 rank 0 完成，rank 1 延迟 | g20 仍 PREPARING；旧设备仍占 20 GiB，新设备按实际准备进度计费 | 不能切流，也不能把半组算成就绪容量 |
| rank 1 完成共同验证 | g20 进入 READY，门仍关闭；预热状态已释放或隔离 | 可提交以 e=7 为条件的切流 |
| 切流提交 A=(8,g20) | g10 门关闭并 DRAINING；rA 绑定不变 | 新请求 rB 只能按当前票据绑定 v2/g20；旧路由准入被拒绝 |
| rA 取消 | R_g10 可为空，但 U={k}、B={b}、O={o} 仍在 | 可以封闭拆除入口；不能把取消当作容量已释放 |
| k 的实际完成到达 | U 为空，B 和 O 仍存在 | 重放已结束后可以拆图；输出借用继续保护其实际对象 |
| 图绑定解除，输出仍慢 | B 为空，O={o} | 保守整实例协议继续等待；若对象级证明允许，可先回收独立对象 |
| o 的真实借用结束 | 所有责任已结算 | 旧实例可完成卸载，其独占资源才进入可重用容量 |

若 rA 在切流前已经准入、但尚未开始首个 kernel，切流后仍必须能按原票据开始执行；R_g10 已经保护了这个窗口。若 rA 先取消，之后迟到的调度消息则不能创建新访问。两者区别来自请求责任和执行入口的顺序，不能只看消息抵达时间。

把旧地址原地写成 v2 是反例：k 或旧图可能读到混合内容，请求字段仍写 v1 也无济于事。把取消时的 KV 立即从容量账扣除是另一反例：新分配可能覆盖尚在途的旧写入。给这些完成事件加实例代次，可以阻止旧通知清掉新责任，但代次本身不会阻止已经发出的旧 DMA 写地址；仍需实际生命周期保护。

## 条件变化与区分实验

低流量、允许维护空窗且容量紧张时，可保留串行替换；短请求通常更易排空。严格连续服务、长流式请求或慢输出多时，并存或滚动更有价值，但必须重新支付双版本、长尾驻留及故障余量。热制品与编译缓存主要改变准备链，不消除请求绑定和最后使用条件。

新增模态、长上下文、adapter rank 或另一图桶时，应扩展 Ω_g、准备证据和资源边界；未覆盖路径等待、拒绝或走已经验证的相同语义回退，不能静默截断。设备、并行度或布局改变时重新核对 P_g 和状态转换；仅有相同制品身份不足以复用旧设备句柄。

| 观察 | 竞争解释 | 区分实验与修正 |
|---|---|---|
| 端口健康但请求失败 | 制品缺失、某 rank 未完成、路径未覆盖或容量不足 | 分别延迟一个 rank、越过 Ω 边界、耗尽 KV；记录证书与准入拒绝原因。只有容量变化时失败，先调整容量解释，不称为加载失败 |
| 切流后旧请求输出变化 | 活跃请求被重新绑定、原地覆写、图读旧地址或正常数值差异 | 用可区分的 v1/v2 小模型固定输入；检查每次执行的绑定、内容代次和图地址，再与各版本独立参考比较。字段正确而内容混合时修资源协议 |
| 路由已经撤销仍有旧请求开始 | 切流前已接受的排队请求，或切流后的非法准入 | 暂停队列投递，在切流前后各发一个请求，记录权威接受顺序。前者应继续，后者应拒绝；不能按 kernel 开始时间一概判错 |
| 回退后过期请求突然被接受 | 只比较别名或版本，遗漏路由代次 | 执行 g10→g20→g10，再提交第一次 g10 的 e；应拒绝。若接受，修复 ABA 边界而非延长缓存 TTL |
| 请求数为零但显存不降 | kernel、图绑定、借用输出、缓存池保留或泄漏 | 分别延迟实际访问、解绑和输出消费，按 backing 记录 used/reserved。责任已结束且无法解释的增长才支持泄漏方向 |
| 重试加载后突然就绪 | 旧尝试 rank 报告命中新实例 | 相同 v 创建不同 g，失败旧尝试，再延迟投递其成功报告；新尝试的完成集合不得改变 |
| 新旧并存时旧请求变慢 | 加载争用、预热计算、CPU 节流或实际执行配置变化 | 固定请求集，分别只启用读取、转换、H2D 和预热，观察最早变化的资源与时间线；阶段不相关时撤回原瓶颈解释 |
| 排空期限到了仍不能卸载 | 剩余访问、未解除绑定、慢消费者或通知滞后 | 单独延迟四类责任之一，保存真实结束与通知处理时间。延长等待不能证明责任已结束，强行释放必须作为负对照被检出 |
| 切流超时后出现双重决定 | 确认丢失被当成未提交，或控制域不一致 | 丢弃成功响应，按同一 op 查询和重试；只能返回原决定。无法查询时保持未知，不恢复旧准入权 |

实验数据应保留 offered、拒绝、等待、取消、失败与未完成请求，不能只统计新版本成功完成者。目标副本数、已分配数、准备中数、证书有效数与当前可接受容量分别记录；它们不应共享一个 running 计数。更新期间的质量、协议完成和尾延迟必须与准备阶段、驻留峰值同时解释。

## 配套检查与验证范围

交付文件为 `tools/check_k_sys_011_full.py`。它是确定、离线、只读的 Python 标准库模型，不导入项目或上游实现。模型保存可变实例、不可变请求绑定与三类物理责任；独立观察器从已经接受的事件历史重建状态，并检查发布时完整执行组、准入时路由代次、请求绑定不变和释放前责任为空。拒绝事件不进入已接受历史，且必须无状态副作用。

固定轨迹检查部分 rank、错误制品报告、相同制品的不同加载尝试、未就绪准入、容量与范围拒绝、切流前接受的旧请求、取消后访问、同名操作跨实例、重复完成、回退 ABA 和失败撤销资格。另枚举逻辑请求、kernel、图绑定与输出消费者的 24 种结束顺序。故障变体实际提前就绪、改写请求绑定、取消时删除访问、接受过期路由/切流、错配完成或忽略一种释放阻塞，必须被相同观察器或固定预期检出。

本轮没有执行交付 Python 文件。实际执行的是两个 V8 内存 CPU 模型：责任集合的 24 种结束顺序全部符合参考，取消时误清 kernel 的变体在 12 种顺序中被检出，忽略输出借用的变体在 6 种中被检出；另一模型检查完整 rank、切流绑定和回退代次，并检出三个故障变体。这些结果只属于实际运行的简化模型，不替代交付脚本的执行记录。

Python 模型的容量只是每实例两个逻辑请求槽，不模拟字节预留、加载流水或峰值显存；就绪范围只区分 short 与未公开路径。它使用单一串行权威域和完整完成事件，没有实现分布式共识、持久性、路由网络传播、真实 tokenizer、模型计算、迁移、CUDA Graph、设备内存可见性、GPU/NIC DMA 或设备性能。正文容量与时间数字是设定推导；有限 CPU 检查不能证明真实 GPU 安全、发布 SLO 或知识改善了 Agent 的构建效果。
