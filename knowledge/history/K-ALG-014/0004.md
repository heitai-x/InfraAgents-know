# K-ALG-014：多 LoRA 服务：低秩计算、驻留与缓存身份

LoRA 将任务适配表示为共享基座上的低秩增量。多 adapter 服务同时面对三个问题：如何共享基座矩阵乘而保留每行的增量；如何让 adapter、KV 和执行缓冲共同满足容量；如何保证请求、缓存和在途读取使用同一版本。支持加载很多 adapter 文件，并不等于能同时执行这些 adapter。

## 数学对象与执行边界

采用列向量约定。一个目标线性层的基座为 W₀∈R^{dₒ×dᵢ}，输入 x∈R^{dᵢ}，adapter 给出 A∈R^{r×dᵢ}、B∈R^{dₒ×r} 和缩放 s：

ΔW=sBA，u=Ax，y=W₀x+sBu。

r 是因子内维，rank(BA)≤min(r,dᵢ,dₒ)，不应把因子内维和增量矩阵的实际秩混为一谈。低秩服务通常选择 r≪min(dᵢ,dₒ)；可支持的 r、dtype 和布局还受执行器限制。r=0 在本章表示无增量的基座路径，直接跳过分支；若配置用 s=α/r 表示缩放，必须在 r=0 前分支，不能计算除零。

LoRA 原论文 §4.1 使用 W₀x+BAx，与本章约定一致。S-LoRA 使用行向量 xᵣWᵣ+xᵣAᵣBᵣ，其中 Aᵣ 为 dᵢ×r、Bᵣ 为 r×dₒ；转成列向量时 W₀=Wᵣᵀ、A=Aᵣᵀ、B=Bᵣᵀ。不能直接把行向量图中的矩阵形状搬进列向量算例。

一个 adapter 是完整的不可变对象：基座兼容身份、对象版本、目标矩阵集合、每个矩阵的 A/B、有效 r、scale、数值表示和布局。一次请求绑定该对象，后续路由别名更新不改变已有绑定。设备驻留还需要物理页、页代次、加载完成关系、请求/图引用和实际读者；主机中有对象，不代表设备内容已经可读。

共享计算发生在每个目标线性层内部。该层可将不同 adapter 请求的当前输入列组成 X，统一计算 W₀X，再按行归属加各自增量。上一层的增量已经改变隐藏状态，下一层必须使用更新后的输入。不能先独立执行完整基座模型，再在末尾加一个由原始输入算出的 adapter 修正。

输入包括请求生命期、基座与 adapter 版本、当前层输入、token 逻辑位置、行映射、状态句柄和本轮容量。输出是原请求顺序的层结果，以及模型继续执行后产生的状态和完成责任。LoRA 线性分支本身不完成 Attention、KV 管理或采样。

## 合法条件与方案选择

固定 adapter 可计算 W′=W₀+sBA，以普通线性层执行。合并需要更新完整、没有读者正在使用被覆盖的存储，并满足声明的数值契约。保留多个合并副本会复制完整基座；只保留一个副本并串行切换则放弃跨 adapter 聚批机会。两种方案都可能合法，选择由切换频率、容量和负载决定。

实数恒等式不保证浮点逐位一致。合并改变乘加顺序；量化基座还可能经历反量化、相加和重量化。运行时分支也有输入转换、低秩累加、scale 应用和最终相加的精度选择。比较时应固定参考表示、误差容限和输出判据。若 logits 的最大值与次大值间隔为 m，而每个 logit 的绝对误差不超过 ε，则 m>2ε 是保持该次 argmax 的充分条件；这不保证后续随机采样或整段文本完全一致。

按 adapter 分组必须保留输入行到输出行的逆映射。相同 r 只说明形状相容，不说明 A/B、scale 或版本相同。分组键至少能唯一确定该层使用的完整 adapter 对象；未被该 adapter 作用的层走零增量路径。

补齐到 R≥r 的一种充分构造是 A′=[A;0]、B′=[B,0]，于是 B′A′=BA。scale 保持原来的 s；若原来 s=α/r，不能因为物理桶宽改成 R 就改为 α/R。两侧补零是便于审计的规则，代数上更一般的条件是新增部分乘积为零。实际实现仍应初始化全部可能读取的 padding，不能依靠未初始化值碰巧抵消。该推导假设有限输入和可接受的中间数值；含 Inf/NaN 时，0×Inf 并不产生零，须拒绝、显式屏蔽或另订数值契约。

缓存身份由状态生成的依赖闭包决定。相同 token 在不同 adapter 下可能产生不同 K/V，即使 adapter 没有直接修改某层的 K/V 投影，上游隐藏状态也可能已经改变。默认将影响状态的 adapter 身份及版本纳入 key；只有证明某类状态不依赖该 adapter，才可省略。例如仅作用于最终输出头的增量不必影响此前已生成的 KV。

可以用完整身份 η 描述基座版本、adapter 对象版本、位置规则、数值表示、分片布局和模态条件，再以父前缀身份、本块 token、块边界及隔离命名空间组织缓存。哈希负责检索，碰撞处理和精确身份核对仍需有契约。salt 不替代授权。固定 vLLM 文档明确把 LoRA ID 列入额外哈希并仅缓存完整块；若允许同一 ID 更新权重，还要增加版本或内容身份。已有 KV 不要求 adapter 权重始终驻留，但后续执行该 adapter 时必须恢复相同对象。

## 每层计算、加载与完成的完整路径

下面选择一种保守组织：一轮执行前预留整批所需 adapter、KV 增量和缓冲；该轮使用不可变描述；资源不足则减少批次、等待或拒绝。逐层换入或分波执行也是候选，但需要重新推导传输、容量和完成关系。

```pseudocode
输入：请求快照；每层基座；不可变 adapter 仓库；设备页池；状态与输出预算
输出：按请求归属的结果；已完成的新状态；加载、引用和回收责任

初始化空计划、临时预留集合和行表 I
在协调区内，对候选请求逐一处理：
    校验基座兼容、完整 A/B 形状、scale、目标层、数值与分片契约
    固定对象身份 (adapter_id, version)，建立行到请求/位置的映射
    计算尚未驻留的唯一对象、KV 增量和执行缓冲的物理需求
    模拟合法淘汰；只使用已经满足回收条件的容量
    若加入后不可行，跳过或调整该候选，不发布不完整计划
    取得已有对象保护，预留新对象目的页及必要 staging
    任一步失败，撤销该候选已取得的临时资源，保留原请求状态

对新对象执行加载：
    标记 FETCHING；保持主机源和目的页有效
    复制完整 A/B、scale 与布局描述；等待真实完成并核对对象与分片
    成功才发布 READY；失败则不准入该对象的请求
    失败/取消的在途复制排空后归还预留，不能直接复用目的地址

提交前，为描述、输入、adapter 页和已有状态登记实际读取责任
将计划与必要就绪依赖一同提交；本轮不再原地改写描述

按模型拓扑逐层推进：
    取得上一层已经加入 adapter 增量后的输入 X
    对当前线性层，初始化各行 Y[i] ← W₀ X[i]
    以当前层对象身份分组，保存每组原始行号列表 J
    对每组：
        若该层无增量或 r=0，保留基座结果
        否则对每个组内行 j 和 k∈[0,r)：
            U[j,k] ← Σ_t A[k,t] X[J[j],t]
        确认 U 写入先于其消费者
        对每个组内行 j 和输出坐标 o：
            D[j,o] ← s Σ_k B[o,k] U[j,k]
            Y[J[j],o] ← Y[J[j],o] + D[j,o]
    由模型拓扑执行后续非线性、Attention 或其他算子
    产生的新 KV 写入预留的私有可写区，不覆盖共享命中页

完成时：
    核对请求生命期、绑定版本及所有必要模型状态
    建立后续消费者可见的完成关系，再提交请求状态与允许的输出
    仅已完成的完整缓存块取得目录资格，未满尾块保持私有
    取消则停止新业务提交与交付，已提交读写继续承担完成责任
    按实际最后使用释放读者；按请求/图生命周期释放逻辑引用
    无逻辑引用、无在途读写且已撤销发布/绑定的对象才进入空闲池
```

空批次直接返回，不加载对象或产生输出。加载失败不改变旧版本对象和已有 KV 快照。部分层计算失败时，不把其他层已经完成的新页单独发布成完整模型状态。重复完成通知须按执行身份去重，旧代通知不能减少新代引用。

KV 的“已发布”和“请求拥有”不是互斥的先后阶段。同一页可以同时被缓存目录保留、多个请求引用和多个在途读者使用；回收要求这些责任全部结束。adapter 的 READY、逻辑引用数、实际读者数和撤销状态也应分别记录，不能仅靠一个状态枚举推断可回收。

## 非连续权重怎样被计算消费

共同页池要求计算认识布局。下面给出独立的可实现寻址方案，不声称它就是 S-LoRA 内核的具体存储格式。

将一个 adapter 的各目标矩阵 A/B 按约定顺序打包成逻辑字节串，描述中保存各矩阵偏移、物理行跨度和有效 r。设元素宽度为 b 字节，页大小 P 是 b 的整数倍，页表 T 把逻辑页号映射到物理页。对逻辑字节偏移 z：

逻辑页号 ℓ=floor(z/P)，页内偏移 δ=z mod P，地址=pool_base+T[ℓ]P+δ。

有效 rank 为 r、物理桶宽为 R 时，可取 A 的物理布局 R×dᵢ、B 的物理布局 dₒ×R；于是 A[k,t] 的偏移为 off_A+b(kdᵢ+t)，B[o,k] 为 off_B+b(oR+k)。读取 B 时使用物理跨度 R，归约范围则由有效 r 或已证明的零 padding 决定。这两个量混用会把下一输出行或 padding 当成有效权重。

两阶段执行中，第一阶段按 adapter 组和输入行 tile 分配任务，从 J 收集输入，按页表装入 A 的归约片段，初始化累加器为零，遍历 dᵢ，写出 U。第二阶段按同组的输入行 tile 和输出 tile 分配任务，装入 U 与页表定位的 B，遍历有效 r，再按 J 写回 Y。每个输出坐标由一个任务完整归约时不需要原子加；拆分归约时必须另有归并缓冲和完成关系。prefill 的组有多行，可复用同一权重 tile；decode 常只有一行，更容易受权重 gather、页表访问和启动限制。

S-LoRA 的 MBGMM/MBGMV 支持异 rank、异长度和非连续 gather；论文没有提供足以恢复任意设备 lane、fragment 和矩阵指令布局的信息。本章恢复到逻辑 tile、地址和两阶段依赖，不猜测这些未公开映射，也不据此宣称达到其 CUDA 性能。改用量化权重时，字节寻址之外还需共同定位 scale、分组边界与解码布局。

## 张量并行的数据流与通信口径

以下推导使用列向量、N 个参与者，先假设相关维度可整除 N、同一组具有相同 adapter 版本。传统行向量图的 column/row parallel 名称容易混淆，下面直接说明分片轴。

对于按输出轴分片的线性层，W₀ 的输出行分给各 rank，输入 x 复制。将 A 的 r 行分片为 Aₚ，每个 rank 求 uₚ=Aₚx，all-gather 得到完整 u∈R^r；B 的输出行分片为 Bₚ。各 rank 得到本地输出 W₀,ₚx+sBₚu，与基座输出布局一致。后续按 head 独立计算的 Attention 可继续消费本地输出。此处通信的是低秩 u，而不是完整 dₒ 输出。

对于按输入轴分片的线性层，各 rank 持有 xₚ、W₀,ₚ 和 A 的输入列 Aₚ。先求部分 uₚ=Aₚxₚ，all-reduce 得到 u=Σₚuₚ。B 按输出行分片，每个 rank 求属于其输出区间的 sBₚu。基座部分结果 W₀,ₚxₚ 是完整输出宽度的 partial sum；将本 rank 的增量嵌入对应输出坐标，其余位置补零，再与基座部分结果相加，最后使用基座已有的 all-reduce。这样每个输出坐标的 LoRA 增量恰好加入一次。如果每个 rank 都计算完整 Bu 并在最终 all-reduce 前相加，增量会被重复 N 次。

两层 MLP 中，第一层按输出轴分片，局部非线性后的结果成为第二层按输入轴分片的输入。Q/K/V 与输出投影可使用相应关系，但 GQA、不同投影宽度和不同目标层集合需要重新检查分片，不能从方阵示意图直接推出合法布局。r 不能整除 N 时可选择合法 padding、不同分片或复制，通信和驻留式随之变化。所有参与者还必须确认同一完整对象，不能把 A、B 分别切换版本。

S-LoRA §6 的 Attention 设定包含 Q/K/V 的三个低秩 all-gather 和输出投影的一个低秩 all-reduce。令 Q 为 token 行数、h 为隐藏维，按其环形通信模型，每 rank 发送元素量为：

V_base=2(N−1)Qh/N，V_LoRA=3(N−1)Qr/N+2(N−1)Qr/N=5(N−1)Qr/N。

同一元素字节宽度下，比值为 5r/(2h)；r=16、h=4096 时约 0.00977。N=1 时二者均为零，不计算 0/0。字节量需乘通信 dtype 的元素宽度；全组发送总量再乘 N，不能和单 rank 口径混用。该比值是指定 collective 和融合的数据量关系，不是时间比：小消息启动、拓扑、负载不均及 collective 次数仍可能主导等待。

## 六类成本放在同一资源账中

每个目标矩阵的参数主项为 r(dᵢ+dₒ)b 字节。对组 g 有 Q_g 行、rank r_g，整批基座约为 2Qdᵢdₒ FLOPs，增量约为 Σ_g2Q_gr_g(dᵢ+dₒ)，另有缩放和逐元素相加。补齐执行时用实际执行宽度 R_g 替代 r_g。跨目标矩阵应求和，只有形状相同时才可直接乘矩阵数。

8 个 rank 16 与 8 个 rank 64 的单行请求，实际 rank 位置总数为 640，全补齐到 64 为 1024，低秩部分的维度工作量相差 1.6 倍。基座和 Attention 没有因此减少，不能报告为整个 forward 的 1.6 倍收益。

访存需区分逻辑请求量和设备事务。若某组的 A/B 在本轮各从 HBM 读取一次，增量权重读取主项为 r_g(dᵢ+dₒ)b；多行共享可摊薄该项，多个 tile 重读则增加。显式 U 需要 Q_gr_g 个元素，至少一次写入和一次读取；分支读取 X、对 Y 读改写、行索引和页表也产生流量。逻辑字节不能直接当作 HBM 实测事务：cache 命中、非连续 gather、访存合并、tile 重读和融合会改变它。

驻留按物理页并集计数。一个 adapter 被多个请求引用只计一份设备页，引用责任分别保留。打包对象 i 的字节量为 Dᵢ 时占 ceil(Dᵢ/P) 页；若每个矩阵或 KV 流独立舍入，应求 Σᵢceil(Dᵢ/P)，不能先合并所有字节再舍入。固定槽、空槽、最大 rank padding、量化元数据和旧版本并存都需计入。池内对象不能又与整个已分配池重复相加。

设 64 个 4096×4096 目标矩阵均为 rank 16、两因子 FP16：每矩阵 256 KiB，每 adapter 为 16 MiB。每 token KV 为 128 KiB 时，其有效字节机会成本为 128 token KV。取 P=1 MiB，假设 adapter 已紧密打包，KV 算例只有一条连续逻辑流，公共池为 64 页：一个 adapter 加 384 token 恰占 16+48=64 页；385 token 需 65 页；三个 adapter 加 200 token 需 48+25=73 页。若有多条独立尾流，还要逐流舍入。若将每个 128 KiB 因子独立分配为 1 MiB 页，上述 adapter 容量式也必须重算。

共同池可以借用两类对象的空闲容量；真实固定分池例如 adapter 16 页、KV 48 页，则没有 adapter 时 400 token 的 50 页 KV 会因 KV 分池上限被拒绝，而共同池可容纳。另一种错误是分别允许 adapter 和 KV 各使用 64 页，再称总预算仍是 64 页；这会错误接受前述 73 页需求。前者是合法方案的容量搁置，后者是预算错误。

加载与通信成本由实际路径决定。16 MiB 在有效 16 GiB/s 下的纯 H2D 数据时间为 0.9765625 ms，16 个不同冷 adapter 共 256 MiB，对同一链路为 15.625 ms。文件读取、反序列化、转换、staging 和队列等待另计；主存中的冷对象也受容量与 I/O 约束。预取只有在目的页已预留、预测对象正确且复制真正覆盖等待时才有收益，无用预取仍占带宽和容量。

准备包括行分组、页表构造、图桶选择和描述复制。用哈希分组可在通常假设下以 O(Q) 处理行，用排序则约 O(Q log Q)，不能将其一视为数学必需。同步包括加载完成、U 的生产消费、TP collective、状态发布和最后读取。低秩算术下界、HBM 下界、H2D 下界描述不同资源；可重叠阶段按依赖图求关键路径，不能把它们全部相加或全部取最大而忽略依赖。新旧版本、staging、预取和图缓冲同时存活时决定峰值，不能只列稳态权重与 KV。

## 更新、取消与容量的组合轨迹

以下是设定模型。共同池 64 页，每页 1 MiB；a/v1、a/v2、b/v1 各占 16 页；已有 KV 占 24 页。不含池外基座和执行区，它们已从总设备预算扣除。

| 事件 | 对象与责任 | 容量及允许后继 |
|---|---|---|
| r1 绑定 a/v1 | a/v1 已就绪，r1 与执行读者保护其页 | a/v1+KV 共 40 页，剩 24 页 |
| r2 绑定 b/v1，同 token 前缀 | b/v1 另占 16 页，不能命中 a/v1 产生的受影响 KV | 共 56 页，剩 8 页；新增 KV 还须预留 |
| 发布 a/v2 的制品 | 新请求可以等待 v2，r1 保持 v1 | v2 需 16 页，当前不能直接加载；完整并存需 72 页 |
| r1 取消，但旧 kernel 未完成 | 撤销新业务提交，实际读者仍存在 | a/v1 的 16 页不能扣掉，容量仍为 56 页 |
| r2 排空，b/v1 无请求/图引用 | 可撤销 b/v1 驻留并回收 16 页 | 降至 40 页，可预留 v2；加载期间峰值为 56 页 |
| v2 加载完成并发布 | 新请求绑定 v2，旧 r1 读者仍只读 v1 | 相同 token 的 v1/v2 KV 身份分离 |
| v1 最后读者完成 | 若所有逻辑/图引用已结束，可回收其权重页 | v1 的缓存 KV 可独立保留；未来 v1 计算仍需重新加载 v1 |

提前把取消视为释放，会在第四行产生虚假容量；原地覆盖 v1 为 v2，会污染旧读者。若 v2 的切流收益不足以承担并存峰值，可以等待旧版排空或使用其他设备；版本更新本身不会创造容量。预取 b/v1 也必须使用真实剩余页，不能撤销仍受保护的旧对象。

## 条件改变后怎样选择

| 改变 | 必须保留的关系 | 可调整方案与反转证据 |
|---|---|---|
| 一个长期固定的热 adapter | 数值与版本契约 | 合并减少运行时分支；频繁切换、合并误差或副本容量会推翻选择 |
| adapter 多、每轮活跃少 | 唯一对象计数和加载完成门控 | 热对象常驻、冷对象换入；冷风暴的等待和 staging 峰值可能要求限准入 |
| rank 高度异质 | 正确 scale、有效归约和行归属 | 细分组减少 padding，粗桶减少准备；用完整步时和租户等待决定 |
| KV 变长或尾流增多 | 逐对象舍入与在途保护 | 调整共同池分配、预取深度或并发；算子更快但准入下降时需反转 |
| TP 度或投影几何改变 | 全 rank 对象一致、增量恰加一次 | 重划分片或补齐；重新计元素量、启动次数和复制副本 |
| 固定图捕获具体地址 | 地址、布局、对象与最后使用一致 | 新绑定、受支持更新或固定槽替换；稳定地址不能证明版本正确 |
| 热租户请求持续到达 | 低频租户进度与硬容量 | 限制聚批等待、老化或欠额；总吞吐提高但冷租户长期等待时放弃纯聚类 |

例如低频请求每 100 ms 到达一条，若硬性等待四条才执行，仅收集就要约 300 ms。对其设置最大等待可限制这部分损失，但还需有限准入、可行容量和设备完成才能给出整体进度保证。S-LoRA 的聚类与 early abort 是特定负载下的策略，附录的排序证明使用凹奖励条件，不能推广成任意异长请求的最优调度。

## 竞争解释、区分实验与反证

| 观察 | 竞争解释 | 可区分的干预与修正 |
|---|---|---|
| 混合 adapter 吞吐下降 | 加载等待；小 kernel/启动；页压力；基座已经饱和 | 固定 offered 轨迹与行数，分别预驻留对象、改变分组、增加可用页；按阶段观察改善位置，不能只看总均值 |
| rank 桶增大后变慢 | padding 算术增加；图变体改变；驻留挤掉 KV | 固定实际 rank，只改桶宽，记录执行宽度、低秩段和准入；若只有排队增加，不能归因于 FLOPs |
| 同文本复用得到错误输出 | key 漏对象版本；KV 写错；位置/数值表示不一致 | 从相同完整输入独立计算状态，先禁用复用，再只改变 adapter；错误随命中出现才支持身份解释 |
| 更新后旧请求结果变化 | 原地覆盖；A/B 混合发布；描述错绑；TP 版本混用 | 延迟旧读者，保留 v1 并发布 v2，核对每次实际读取；只改路由字段而不保护存储的负对照应失败 |
| TP 输出增量恰多 N 倍 | 每 rank 重复加完整增量 | 令基座为零，独立算 BAx，比较分片输出；只在所属输出区间加增量后错误应消失 |
| 预取未改善 TTFT | 没有重叠；预测无用；容量阻塞；H2D 不在关键路径 | 固定请求集合关闭预取，记录预留、复制完成、实际引用及关键等待；等待不变而流量上升时修正预取策略 |
| 聚类改善平均值但冷租户恶化 | 等组造成饥饿；冷对象频繁被驱逐；长度分布差异 | 保持相同到达与长度轨迹，只改最长等待或驻留策略，按租户报告等待、拒绝和完成率 |

正确性先覆盖矩形形状、r=0、零 A/B、scale 为零、异 rank、同 rank 异对象、padding、重排行和非连续页。故意把 B 写成 r×dₒ 应在计算前被拒绝，不能依靠索引异常或 zip 截断发现。缓存检查必须让漏版本的命中返回实际错误状态；生命周期检查必须让提前复用或混合 A/B 改变旧读者结果。

设备实验另需固定模型、数值契约、请求到达、长度、取消和缓存条件；用独立运行或时间区组比较，并报告尾延迟、拒绝、未完成工作和不确定性。分组或图桶改变了数值路径时，应同时检查首次分歧。CPU 模型能够反驳错误组织，不能证明 GPU 可见性、kernel 性能或知识改善了 Agent 构建能力。

## 独立检查的范围

交付文件为本章及 tools/check_k_alg_014_full.py。脚本使用 Python 标准库的有理数，分别执行两阶段低秩计算和显式形成 W₀+sBA 的参考；检查混合行分组、同 rank 异 adapter、原失败的 B 形状、r=0、补齐 scale、非连续页、缓存错误命中、容量并集、更新/取消/迟到完成，以及两类 TP 分片和环形通信元素账。故障分支必须与独立结果或回收不变量冲突，才算负对照被检测。

脚本不读写文件，不导入项目或上游代码，不启动进程，不访问网络。它是 CPU 算术与有限状态模型；不覆盖真实 allocator、CUDA Graph 更新、stream/event 内存可见性、通信库或吞吐。本轮可用工具没有 Python 执行接口，交付脚本尚未执行；记录中的 check_execution 问题须由协调者运行完整候选后复核，不能仅凭修订声明关闭。
