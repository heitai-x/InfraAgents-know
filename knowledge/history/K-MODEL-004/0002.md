# K-MODEL-004：SSM 与混合模型：递归状态、扫描与恢复

递归状态是前缀的压缩摘要；它支持低增长成本的 decode，却改变了前缀复用、回滚和批次管理方式。

## 从递推看存储复杂度

简化状态空间关系写为 hₜ＝Aₜhₜ₋₁＋Bₜxₜ，yₜ＝Cₜhₜ＋Dₜxₜ。selective SSM 中部分系数依赖输入。decode 只需前一个递归状态以及模型要求的局部卷积历史，状态大小通常不随完整序列长度线性增长。prefill 则可利用专门的并行 scan/分块算法，不必逐 token 用同一小步 kernel 串行执行。

压缩状态并不意味着可以随机读取任意旧位置。全 KV 保存许多历史表示，递归状态只保留到某个前缀为止的摘要。要从较早位置分叉，需要保存该位置的状态快照或重放其后的输入。

## 状态包的内容

一条请求的状态可能包含每层 SSM 张量、卷积环形缓冲、全 attention KV、窗口 KV、逻辑位置与版本。各层状态大小和更新规则不同。batch 行重排时，这些对象必须使用同一请求映射；只重排主递归张量而忘记卷积状态，会导致似乎随机的跨请求污染。

在原地更新 h 的实现中，第 t＋1 步覆盖第 t 步。异步执行必须保证上一使用者完成；投机更需要保留接受边界的状态。将“把缓存长度改小”作为回滚方法对这种覆盖式状态不起作用。

## 前缀缓存从连续页变成检查点

一个状态快照可以代表长前缀，但只有它对应的准确位置可以直接恢复。假设每 256 token 保存一次递归状态，命中长度 700 时可以从 512 快照重算后续 188 个，而不能凭最终 768 状态倒推 700。是否能逆转取决于递推可逆性及数值稳定性，常规服务不应假定成立。

混合层模型的公共恢复点由所有层需要的状态联合决定。可以让全 KV、窗口历史和递归快照以同一恢复位置形成状态包；这增加写检查点成本，却简化共享与淘汰语义。检查点间隔因此是在存储、重算和命中粒度之间选择。

## 模型组合的成本

将部分全 attention 层换成递归层，会减缓 KV 容量增长，但全 attention 层仍可能在长上下文主导带宽。prefill scan、decode state update 与 attention kernel 的最佳批量形状不同，需要按层组分析。把所有层套入同一种分页接口可能既浪费容量，也掩盖错误的恢复条件。

## Scan 的并行依据与片上收益

把单步线性递推记成作用于旧状态的变换 (Aₜ,bₜ)，其中 bₜ 已包含该步输入作用。两个连续变换的合成为 (A₂A₁,A₂b₁+b₂)，该合成满足结合律；对角形式可以逐元素实现。前缀 scan 因此能组织同一层的多步状态，而不要求逐 token 发一个 kernel。输入相关系数必须由该层输入正确产生；这种结合关系不允许把不同网络层或包含额外非线性的任意状态更新混成同一个线性 scan。

Mamba 的技术正文与附录 D 将离散化、scan 和状态到输出的映射相关操作融合，在片上处理中间扩展状态，避免把完整 B×L×D×N 中间量反复写入 HBM。这里的映射是 scan 内部状态与 C 的乘加，不宣称整个 block 的最终 out_proj 都属于该融合 kernel。长序列分块时保留边界状态继续下一块。推理实现应核对是否真的只物化必要输出和边界，还是在框架张量之间构造了巨大临时状态；减少最后持久对象并不保证减少中间峰值。

prefill scan 与逐步 recurrence 要在相同初始状态、卷积历史和有效 token 边界上比较。不同归约顺序会产生有限精度差异，不能假定 bitwise 相同；若每块重置局部卷积或漏传边界状态，差异属于语义错误而非数值容差。

## 投机接受位置必须能恢复

用 p 表示已经消费的 token 数，S(p) 表示恰好消费这 p 个 token 后的完整递归与卷积状态。设从 S(1024) 验证 4 个候选，最终接受前 2 个。需要提交的是 S(1026)，不是把 S(1028) 的计数器改成 1026。可选方案是在每个可接受边界保留状态，或保留 S(1024) 并重放已接受的两步；二者分别支付快照字节与重算。

若混合 attention 层，未接受 KV 可以缩小有效范围，但它们仍可能正在被异步验证读取；窗口环形槽若已覆盖旧历史，恢复还需要原窗口快照或足够的重放起点。RNG、grammar 和输出提交也以同一接受边界更新。只有全套状态都恢复完成，下一轮正式生成才能启动。

例如递归和卷积完整状态合计 4.375 MiB，保留 4 个候选边界另需 17.5 MiB，且产生相应写流量；若仅保留起点，则新增快照少，但接受后至多重放对应候选。这是假设状态大小下的资源比较，最优间隔取决于接受分布、状态读写和重算时间，不能从“SSM 状态不随上下文增长”推出投机快照免费。

## 分层迁移仍以完整快照为边界

递归状态是被覆盖的可变对象，不能直接套用 append-only KV 的后台复制协议。可在一个已完成步骤复制稳定快照，让后续更新使用另一份状态；也可暂停到共同位置再复制。若同时存在全 KV 与窗口状态，所有对象必须标注相同消费位置、模型版本和请求代次。

目标收到完整状态包并建立执行依赖前，源端保留可恢复副本。中途缺失某层、卷积位置错位、旧版本迟到或目标失败，应放弃该次恢复而重用已知完整起点。验证包括跨 scan chunk、batch 行重排、只接受部分候选、窗口覆盖后回滚和复制途中取消，逐步对比状态及后续输出，而不只比较第一条恢复输出。
