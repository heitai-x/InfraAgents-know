# K-ALG-003：前缀缓存：计算等价类、Radix 与淘汰收益

可复用前缀是能产生等价中间状态的一组输入和执行条件；字符串相同只是其中一个投影。

## 为什么历史 KV 可以复用

因果模型中，位置 t 的各层状态只依赖可见前缀以及模型参数、位置规则和外部条件。当这些依赖保持一致，两个请求在分叉前的状态可以共用。此结论来自计算图：若某个依赖进入了状态生成，却没有进入缓存身份，命中就可能跨越不同计算。

因此身份一般需要模型及权重版本、规范化后的 token 序列、位置编码配置、影响状态的 adapter、多模态特征身份，以及隔离命名空间。sampling temperature 通常影响之后如何选 token，不影响已给定前缀的前向状态；但已采样出的 token 已经属于前缀。不要把所有配置都盲目混入 key，也不要漏掉真正参与前向的输入。

## 块哈希和 Radix 是两种索引结构

链式块哈希使当前块身份依赖父块身份、当前 token 和额外条件。相同 token 块出现在不同上下文中，不会被误认为相同状态。Radix 树把共享 token 路径压缩为边，前缀匹配可能在边内结束，此时需要拆分节点，节点下挂物理状态与引用关系。树负责发现最长共享路径，物理池负责保存内容，两者不必一一对应一个分配对象。

例如 A 的前缀是 a,b,c,d，B 是 a,b,c,e。共享可到 c；物理块大小若为 4，则逻辑前缀命中长度 3 与可直接共享整块数量 0 是不同结果。支持尾块复制可保留部分收益，否则重算这段可能比小块管理更划算。不能把逻辑最长匹配直接当作内核可跳过的 token 数。

## 命中长度是全状态一致的交点

有些层保留全历史，有些只保留窗口，有些保存递归状态。能恢复整个模型执行的位置，必须让所有需要的状态在该位置同时有效。某一层有 4k token KV 不代表模型可从 4k 继续，递归层可能只有 2k 处的检查点。分层命中长度的最小值仅在每层有效集合都是从零开始的连续前缀时成立；一般要取各类恢复位置集合的交集。

## 缓存价值与路由

命中收益近似为避免的重算时间减去索引、传输和映射成本。淘汰排序可以估计再访问概率×重算成本/驻留字节，并叠加引用保护。仅按 token 命中率会高估短且便宜前缀，忽视很长但少见的昂贵前缀。前缀亲和路由能提高局部命中，但可能把热门前缀集中到排队最严重的实例；路由代价应比较额外排队和节省的计算。

持有引用的共享节点不能仅凭 LRU 老化就释放。跨租户能否共享由隔离语义决定；即便结果数值相同，也可能不允许让缓存命中成为可观察的共享信号。缓存 key 的哈希用于身份检索，冲突处理与隔离规则才定义系统语义。

## 从前缀复用扩展到其他模型

固定 encoder context 的交叉 KV 可以按源内容与投影参数复用；扩散模型中随去噪步变化的 self-attention 状态通常不满足此条件；SSM 的前缀恢复需要该位置的递归状态。共同原则是依赖闭包一致，而不是对象名称中有没有 KV。

## 场景：长公共前缀与交错会话

以下全部为设计设定。模型 KV 为 128 KiB/token，100 条会话共用同一合法 8192 token 系统前缀，各有 256 token 私有尾部。GPU 的 KV 预算为 8 GiB；另外设每轮读取权重 12 GiB、有效设备带宽 1 TiB/s，交互 ITL 目标 30 ms。模型、adapter、processor 和位置规则一致，前缀对齐完整页，不计页尾和临时峰值。

完整独立副本需要 100×(8192+256)×128 KiB=103.125 GiB；共享公共前缀则为 1 GiB+100×32 MiB=4.125 GiB。共享因此显著改变所列状态的容量可行性，但仍需下一步增量、引用和在途页预算。

比较 A：每次重新计算并保留私有状态；B：本地共享公共前缀，分别保留尾部；C：公共状态主要放在共享远端池，需要时恢复。A 简化跨请求状态管理但重复 prefill 且容量不足以同时保留上述全部会话；B 节省容量和重复前缀计算，却可能集中路由与读取；C 扩展放置选择，但增加网络、目录和恢复等待。

容量允许保留 100 条会话，不等于应让它们同时 decode。若一轮读取每个请求全部逻辑历史，100 条的 KV 读取仍约 103.125 GiB，加权重后的理想下界约 112.43 ms，已经超过 30 ms。若当前只有 8 条活跃，读取主项为 12+8×1.03125=20.25 GiB，下界约 19.78 ms。实际公共页的 cache 重用可能减少 HBM 流量，但需观测，不能按物理共享比例直接扣减。

远端公共前缀为 1 GiB，若有效网络为 20 GiB/s，纯传输下界 50 ms。重算假设为 200 ms 时，远端恢复有潜在收益；若命中节点额外排队 300 ms，则直接去空闲实例重算仍可能更快。路由必须将命中、目标容量和排队联合比较，而不只最大化前缀长度。

验证从完全相同与只差一个 token 的前缀开始，再覆盖相同文本但不同模板/adapter、分叉尾部、取消后共享页仍被其他请求使用、目录过期和部分恢复失败。性能轨迹保留会话思考时间与交错重用距离，报告避免的 prefill、真实物理占用、读取字节、排队和联合 SLO。

公共前缀变短、重用变稀或模型版本频繁更新时，B/C 的管理和驻留成本可能不再值得；热点过于集中时复制或重算也可能优于亲和路由。这个场景给出选择关系与验证方案，不声称特定引擎已经达到目标。
