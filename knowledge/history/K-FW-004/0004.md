# K-FW-004：编译与动态形状：Guard、分桶和变体成本

编译把一组执行假设变成专门程序；动态服务必须判断请求是否满足这些假设，并管理符号范围、形状桶和可执行变体。特化可以减少解释、提交、中间张量和通用索引的成本，但也引入准备时间、覆盖边界和驻留对象。目标是在保持同一输入输出与状态语义的前提下，选择能在真实访问分布中摊销的程序族。

## 特化的对象、收益与合法域

把一次模型计算写成 `(y,z')=F(x,z;θ,ν)`。`x` 包括输入张量和逻辑长度，`z` 包括 KV、随机状态或其他可变状态，`θ` 是模型与 adapter 的实际参数绑定，`ν` 是数值契约。输出既包括 `y`，也包括状态变化 `z→z'`；输出张量接近而 KV 写错位置，仍然是不正确的执行。

请求描述至少保留逻辑 shape、物理 shape、rank、stride、dtype、device、布局、执行模式及实际特化依赖。逻辑 shape 描述任务，物理 shape 描述分配和执行容量，两者不能混为一谈。batch 相同但 stride、query 行数、历史长度或 LoRA rank 不同，可能需要不同变体；请求 ID 不影响生成程序时，则不应制造编译变体。

一个变体可写为 `a=(κ,g,P,R,e,s)`：

| 对象 | 含义 |
|---|---|
| `κ` | 图与算子语义、已折叠常量、目标架构、编译器/库版本、数值及布局选项等共同身份 |
| `g` | 对本次输入及绑定求值的 guard 谓词，包括尺寸范围、分支、stride、对齐、dtype 和资源条件 |
| `P` | 生成程序及其 ABI、输出和副作用合同 |
| `R` | workspace、固定缓冲、代码及其他资源需求 |
| `e` | 绑定与资源代次 |
| `s` | 构建、可用、排空或释放状态 |

合法域为 `D_a={r:g_a(r)=true}`。正确性要求在这个域内，`P` 实现 `F` 的约定语义与数值关系；guard 通过只是允许执行的必要条件，不能弥补错误的 lowering、mask 或状态绑定。允许误差、随机性归属和别名合同应单独定义，不能默认浮点逐位一致。

缓存通常先用 `κ` 找候选，再逐项检查 guard。符号变体可以覆盖一个范围，不能因每次请求的具体长度不同就人为拆成新缓存项；完全静态的变体则可能把桶尺寸纳入身份。命中时仍需核对实际输入，不能只信缓存索引，也不能把先前检查结果用于已经改变的请求快照。

固定 PyTorch Dynamic Shapes 文档说明：默认先按静态形状编译；自动动态在重编译时识别变化维度并尝试将其动态化；用户可以在编译调用之前标注动态维度并给出范围。标注可能因特化发生约束冲突，并不保证只生成一个程序。该版本将强制全部 size/integer 动态的 `dynamic=True` 标为不推荐，原因包括错误风险、性能退化和编译时间增加。动态尺寸不等于动态 rank；固定文档不支持一般的动态 rank 程序。

形状控制流说明了为什么符号化也需要 guard。设函数依次判断 `n=10`、`n≤30`，对应输出 `10x`、`200x`，否则输出 `nx`。三个分支的形状域分别为 `n=10`、`n≠10且n≤30`、`n>30`，还要与非负尺寸、布局及其他条件求交。在 `n=20` 上获得的第二分支不能直接接收 `n=10`；只保存 `n≤30` 会错误复用。0/1 等特殊尺寸还可能引起额外特化，不能由上述数学分支数量推断实际编译数量。

Guard 失效可以引发重编译、分图、通用路径或明确失败，具体取决于后端和策略。符号化减少部分形状变体，分桶把输入映射到有限物理容量；两者可以组合，但都不自动解决数据相关输出数量、自定义 kernel 的静态参数或固定 workspace 上限。

## 从图到执行计划：哪些改写可以保留函数

图获取必须保留 shape、stride、dtype、常量、别名及副作用。写 KV、更新随机状态、通信和事件不应被当作可任意重排的纯函数。Tracing 只走过某个样例路径时，图获取成功不能证明其他数据分支已覆盖。固定 NxD 文档明确其样例 tracing 只记录实际走到的路径，再由 HLO 经 Neuron Compiler 生成 NEFF。

图级 IR 描述算子及数据依赖，支持常量折叠、融合分组和布局传播；算子或循环级 IR 描述输出索引、归约域、存储位置和循环关系；lowering 把这些计划映射成库调用、目标指令和实际内存操作。固定 TVM v1 分离计算、schedule 与硬件 intrinsic，使同一计算可以采用不同合法实现。本章解释编译与服务交界，不指定一套通用 GPU lane 或矩阵 fragment 映射。

以 `Z=XW`、`Y=activation(Z+bias)` 为例，若 `Z` 只有这一消费者，可以在 GEMM epilogue 中完成 bias 和激活，避免一次 `Z` 的全局写出与读回。若另一分支还消费未激活的 `Z`，就必须保留、另行生成该值或改变融合边界。归约顺序、转换精度和饱和位置变化时，还需重新验证数值契约。最终 shape 相同不证明函数相同。

布局选择也要贯穿完整消费者链。权重预打包可能按部署摊销，激活转换往往按调用收费。某个 kernel 更快，但前后新增转换、破坏 residual 分支布局或增大临时区时，整段可能更慢。静态缓冲复用依据最后消费者；异步消费者完成之前，宿主调用已经返回也不能覆盖其输入。

Padding 是需要证明的图变换。`b≥n` 只证明容量足够，不能证明补齐后的程序与原函数等价：attention 要屏蔽无效 key，平均池化要使用有效分母，卷积与全局统计还要核对边界传播。形状分支尤其容易被补齐改变：上面的函数在逻辑 `n=20` 时应输出 `200x`，若先补到 32 再把物理 shape 当作分支输入，就会输出 `32x`。合法方案是按逻辑长度选择原分支，或让改写后的程序显式消费逻辑长度；仅屏蔽输出尾部无法修复这个错误。

编译器只能为它所见的依赖生成同步和复用证明。服务执行器仍负责合法输入、请求归属、外部拷贝和对象寿命。异步 copy 放到另一个 stream 后，必须把完成依赖接入执行计划；模型已经编译不构成额外的可见性保证。

## 二维前缀分桶：容量、重算与可见性

先限定为普通 causal decoder 的 context encoding。请求 `i` 的 prompt 长度为 `n_i`，本轮计划可复用的前缀长度为 `h_i`，原后缀长度为 `s_i=n_i−h_i`，均以 token 计，满足 `0≤h_i≤n_i`。桶族提供后缀容量集合 `B_P` 和前缀容量集合 `B_K`。前缀身份还须匹配模型、有效 token、位置及缓存表示；同长度本身不构成命中。

固定 NxD 文档的策略是：先选能容纳整批最大原后缀的最小后缀桶 `P`；优先把各请求前缀末尾移入后缀重算，再补 padding；最后按迁移后的最大有效前缀选最小前缀桶 `K`。其代数形式为：

`P=min{p∈B_P:p≥max_i s_i}`；

`m_i=min(h_i,P−s_i)`，`h'_i=h_i−m_i`，`q_i=s_i+m_i`；

`K=min{k∈B_K:k≥max_i h'_i}`，后缀无效槽数为 `P−q_i`。

`m_i` 是迁移并重新计算的 token 数，`q_i` 是实际有效 query 数。迁移不改变原 prompt，也不意味着物理 KV 立即被移动；它首先改变本轮复用和重算的逻辑边界。固定 NxD 的 block KV 路径另外包含 gather 到 flat、计算后 scatter 回块布局，不能把块状缓存登记等同于原生 paged attention。

```pseudocode
算法 PrefixBucket(batch, B_P, B_K)
输入：冻结的请求列表；排序、去重后的非负容量集合
输出：空计划、超范围原因，或 (P,K,每请求计划)

若 batch 为空：返回空计划，不启动设备程序
对每个请求 i：
    校验整数长度及 0 ≤ h_i ≤ n_i
    s_i ← n_i − h_i
P ← B_P 中满足所有 s_i ≤ P 的最小容量
若不存在 P：返回 suffix_overflow
对每个请求 i：
    m_i ← min(h_i, P − s_i)
    h'_i ← h_i − m_i
    q_i ← s_i + m_i
    记录复用区间 [0,h'_i)、重算区间 [h'_i,n_i)
    记录后缀无效区间 [q_i,P)
K ← B_K 中满足所有 h'_i ≤ K 的最小容量
若不存在 K：返回 prefix_overflow
返回 P,K 和上述区间、有效长度、请求及缓存身份
```

这里的零前缀桶适用于所有 `h'_i=0` 的批：既可能原本就没有命中，也可能原命中前缀全部迁入后缀。不能因原 `h_i>0` 就禁止 `K=0`。反过来，只要仍有 `h'_i>0`，零前缀桶就不足以承载它。

一种可检查的物理布局是前缀占 `[0,K)`、后缀占 `[K,K+P)`。请求 `i` 的前缀槽 `t<h'_i` 对应绝对位置 `t`；后缀槽 `K+j` 在 `j<q_i` 时对应绝对位置 `h'_i+j`。有效 query 行 `j` 只能看见有效前缀以及后缀行 `0…j`。前缀尾部 `[h'_i,K)` 和后缀尾部均不可进入 softmax 分母、KV 提交或输出解释。无效 query 行可以跳过或使用明确的空行合同，不能让全 mask 行的未定义结果污染有效状态。

有效输出必须按实际位置收集：最后 prompt 行是后缀行 `q_i−1`，不是总取 `P−1`。在 `n_i<P`、全部前缀已迁移且仍需 padding 时，后者会读取无效行。

迁移后的正确性不变量是：复用 token 与重算 token 依次拼接仍为原 prompt；每个有效 query 使用原绝对位置与相同 causal 可见集合；无效槽没有可见副作用；重算写入不会覆盖其他读者仍引用的共享前缀。需要写共享页时应使用私有写区、COW 或其他有证明的隔离方式，不能依赖重算值应该一样消除写竞争。

这组不变量还要贯穿全部 decoder 层。以下省略请求下标，令 `a=h'`、`q=n−a>0`，层数为 `L`。选择一个顺序 pre-norm decoder 说明数据流；实际模型的归一化、位置变换、residual 和 MLP 顺序必须遵守原模型，不能据此改成另一种 block。

第一层的后缀输入 `X⁰[j]` 来自原 token `token[a+j]` 的 embedding，以及该模型规定的输入位置处理，`0≤j<q`。迁移的旧 token 也从这些已知 token 重新开始，不能把旧 logits 或旧末层隐藏状态当成第一层输入。绝对位置仍为 `a+j`；RoPE 等若作用在 Q/K 上，就在对应层投影之后按此位置施加，不能再把物理槽号 `K+j` 当作位置。

第 `ℓ` 层从上一层后缀输出 `X^(ℓ−1)` 形成 `Uℓ=Norm_attn,ℓ(X^(ℓ−1))`，再投影出该层后缀 Q、新 K 和新 V，并按模型处理位置。其历史来源只能是旧提交快照的同一层 `KV_old[ℓ,0:a)`。把该历史与本层新增的 `ΔKV[ℓ,0:q)` 组成只供本次执行消费的视图。query `j` 消费历史 `[0,a)` 及新增 `[0,j+1)`，包含自身 key；未来后缀和所有 padding 均不可见。若缓存采用量化表示，编码、scale 和解码路径也属于这个视图的合同。

该层 attention 经输出投影后与 `X^(ℓ−1)` 做原模型的 residual，再按原模型的归一化、MLP 和 residual 得到 `Xℓ`。后继层消费的是这次重算得到的 `Xℓ`，不是重新使用 token embedding，也不是从第 `ℓ` 层缓存取出隐藏状态。普通 KV 缓存保存该层 attention 所需的 K/V，不承担任意层间激活接口。最终只在第 `L` 层完成后，对有效末行 `Xᴸ[q−1]` 应用模型的 final norm 和 LM head，得到位置 `n−1` 的 logits，用于预测下一个 token。

可以逐层证明这条路径的语义：在固定参数、位置、可见性和确定性推理函数下，前缀位置的 causal 依赖不包含新增后缀，因此有效的同层历史 K/V 可复用；若第 `ℓ` 层输入后缀与完整执行一致，本层所有可见 K/V 及运算也对应完整执行，于是产生相同数学结果并向下一层传递。浮点归约、融合或 KV 再量化可能改变数值路径，实际一致性仍按声明的数值契约验证，不能由这个实数推导保证逐位相同。双向 attention、依赖未来输入的全序列统计或不同状态族不能直接套用此证明。

逐层产生 KV 与请求可见提交是两个事件。设执行前的提交描述符为 `D₀=(请求身份,代次e₀,提交长度c₀,各层页表,logits归属)`，它表示所有必要层共同有效的状态。本轮计划可故意选 `h≤c₀`，再迁移到 `a≤h`；`a` 只是执行复用边界，不把旧提交长度降到 `a`。每层重算 `[a,n)` 写入本次尝试的私有区，并建立候选页表；候选可以内部读取已完成的本层私有写入，但调度器、其他请求及重试不能把它视为已提交历史。

```pseudocode
算法 RecomputeSuffixAndCommit(tokens, plan, D₀, model, attempt)
输入：已知 token[0:n)、a=h'、q=n−a>0、P/K、不可变旧描述符 D₀
输出：包含全层 KV 和末行 logits 的新提交，或保留旧提交的失败
前提：同一请求一次至多一个可提交尝试；模型、位置及缓存身份已验证

1. 固定 D₀ 和模型绑定，取得旧页的读引用。
   预留各层 [a,n) 的私有写区、必要 COW 页及输出存储。
   candidate ← 本次尝试私有描述符；公共描述符仍为 D₀。
   X ← 原 token[a:n) 的模型输入表示，位置为 a…n−1。
2. 对 ℓ=1…L：
       U ← 本层 attention 输入归一化(X)
       Q,ΔK,ΔV ← 本层投影(U)，按原绝对位置处理 Q/K
       将 ΔK/ΔV 写入本次尝试第 ℓ 层的私有区
       对有效行 j=0…q−1：
           本层历史 ← D₀ 第 ℓ 层的位置 [0,a)
           本层新增 ← 本次尝试第 ℓ 层的行 [0,j+1)
           O[j] ← 对上述集合执行原模型 attention
       R ← X + 本层 attention 输出投影(O)
       X ← R + 本层 MLP(本层 MLP 输入归一化(R))
       记录本层候选 KV 的生产完成依赖，不推进公共提交长度
3. logits ← LMHead(FinalNorm(X[q−1]))
   候选各层页表 ← D₀ 的 [0,a) 与本次尝试 [a,n) 的组合
   将必要 scatter/COW 写回目标也保持私有，不覆盖旧提交可读页。
4. 等待所有必要层、rank、写回和候选输出的真实完成；检查执行成功。
   在受保护的提交点再次确认请求未取消，且公共描述符仍为 D₀。
5. 若失败、取消或身份已过期：
       不发布 candidate；公共描述符及 c₀ 保持不变
       私有写区标为不可复用，直到全部在途访问排空后回收
       返回失败；重试从仍有效的旧提交重新规划
6. 否则：一次发布新描述符
       D₁ ← (相同请求,新代次,提交长度n,完整候选页表,位置n−1的logits)
       后继 forward 和输出消费者只从 D₁ 取得一致的状态
       旧页在其所有读者结束后按引用关系回收
       返回 D₁
```

上述 block 顺序是所选 pre-norm 模型的具体展开；其他合法模型应替换为其原始层函数。即使整个层循环被编译为一个 executable，这些数据依赖和发布边界仍存在，不要求宿主逐层提交 kernel。提交描述符的原子发布是服务执行器的一种实现选择，不声称 NxD 文档提供了这个事务 API。其他实现也必须满足等价的整次可见性与失败隔离合同。

以 `n=900,c₀=h=640,a=388` 为例，第 1 层可以已经物理写出位置 388…899 的私有 K/V，第 2 层随后失败。此时公共状态仍是各层共同有效的旧 `[0,640)`；不能把第 1 层长度 900 与其他层长度 640 拼成一个成功状态，也不能把公共长度先降到 388 来掩盖失败。重试仍可复用旧提交中经过身份验证的前缀，并重新选择桶。这里选择失败后整段重算，不继续使用失败尝试中部分层的写入；若要支持中途续算，还需完整保存并验证层间激活、完成依赖和尝试身份，不能仅凭已有部分 KV 推断可恢复。

私有区中的值即使已经写完，也不能在失败后立刻交给其他请求：旧设备工作或 scatter 仍可能写它。后层失败时，旧提交页必须一直未被覆盖；若实现只能原地破坏旧状态，就不能声称满足这个保留旧提交的合同，应先增加隔离，或明确将状态判为不可恢复并从合法输入重建。硬件错误使旧状态也不再可信时，同样不能盲目重试旧缓存。批内请求可以分别提交，前提是完成信息足以独立判定其成功；执行组失败不能被解释为每条请求都已成功。

完整命中需要额外判断服务是否已有合法末行 logits。若有，可以不再执行本轮 forward；若缺少 logits 且 `n>0`，一种安全恢复选择是令计划复用长度 `h=n−1`，重算最后一个已知 token，再进入分桶。旧提交长度 `c₀=n` 不随这个规划动作回退；恢复成功后发布与新 logits 一致的全层描述符，失败则保留旧描述符。这是服务推导，不是来源文档对任意缓存接口的保证。空 prompt 应按模型合同规范化或拒绝，不能构造位置 −1；空批则直接返回。采样在合法末行 logits 可用后进行；若将采样合入 executable，其 token 和 RNG 副作用也必须进入一致的提交合同。

以来源中的单请求 `n=900,h=640` 为例，原后缀为 260。选 `P=512` 后迁移 252 个 token，得到 `h'=388,q=512`；若前缀桶含 512，则 `K=512`。原有效后缀的 causal 配对数为 `260×640+260×261/2=200,330`，迁移后为 `512×388+512×513/2=329,984`。增加的 129,654 对来自重新计算位置 388…639，而不是 padding。若 kernel 对整个前缀桶付费，主配对规模为 `512×512+512×513/2=393,472`；其中另有 63,488 对对应前缀容量的无效部分。mask 保持语义，是否跳过这些计算由 kernel 决定。

来源还给出 `n=1600,h=1280`：最小后缀桶 512 迁移 192 后剩余前缀 1088，若最大前缀桶为 1024，则该选择失败。较大的 `P=1024` 会得到 `h'=576`，从容量上可以配合 `K=1024`；这说明固定策略失败和所有组合均不可行不同。显式尝试较大后缀桶可以是另一策略，但增加重算，且不能声称固定 NxD 策略会自动这样恢复。

保留全部前缀、只补后缀 padding 也可能是另一种合法策略；它不符合上述优先迁移的选择规则，却不天然违反 attention 数学。检查应分别判定选择策略是否实现，以及 token、容量和可见性是否正确。

## 变体选择、构建发布与执行寿命

编译产物、调优结果、打包权重和图实例是不同对象。运行时参数权重只要 ABI、布局和执行假设不变，其数值变化未必要求重编译；已折叠的权重或常量变化则使对应产物失效。模型请求仍须绑定正确权重版本。图捕获保存了指针时，还要核对地址及绑定代次，不能把程序可复用推成旧图可复用。

编译缓存 key 与图 key 应分开。后者可能额外依赖固定地址、拓扑、grid、按值标量、缓冲槽和代次；固定缓冲中的有效长度可以更新，但不意味着任意节点参数、容量或拓扑都能变化。更完整的图合同见[CUDA Graph](cuda-graph-buffers.md)。

```pseudocode
算法 ResolveAndExecute(request_snapshot, variant_index, graph_index, policy)
输入：不可变请求快照、缓存索引、准备与驻留预算
输出：与请求身份绑定的结果和状态，或明确回退/错误

1. 校验模型/adapter、模式、rank、dtype、布局、位置及状态身份。
   保留逻辑形状和旧提交描述符；处理形状分支和完整命中恢复。
2. 按所选后端决定使用符号输入或物理桶。
   前缀分桶调用 PrefixBucket；其他路径计算全部输入和派生区段需求。
   任一容量或语义条件失败则进入已验证回退，禁止截断输入。
3. 形成真实编译依赖 κ；遍历 variant_index[κ] 的候选：
       对实际逻辑条件、物理输入、布局和绑定求值 guard。
       在同一个受保护操作中确认 ready、资源相容并取得使用权。
   找到候选则转 5；没有候选则转 4。
4. 按构建身份预留唯一构建任务和预算，状态置 compiling。
   同身份请求等待该任务或走通用路径，不读取半成品。
   获取支持的执行路径与依赖；保留别名和副作用。
   在合法条件下改写图、选择融合/布局、生成循环与 schedule，lowering。
   若调优：枚举或采样完整合法候选，恢复相同测试初态，测量后更新选择。
   校验产物 guard、ABI、数值、workspace 和代表边界。
   构建失败则记录 failed 并回退；通过后发布不可变 ready 产物。
   等待者重新执行步骤 3，不能沿用构建前的过期检查。
5. 取得本次执行所需的可变 workspace、输入输出缓冲及可选图槽。
   并发执行不得无条件共用会冲突的可变区域。
   建立逻辑长度、位置、mask、页/槽映射、私有写区及输出行映射。
   完成必要布局转换，并建立输入生产者到设备消费者的依赖。
6. 若使用图：按图身份查找相容实例；不满足条件则捕获/更新或走非图路径。
   图实例对程序、权重和地址建立持续引用。
7. 前缀迁移路径按 RecomputeSuffixAndCommit 执行：
       逐层传递重算隐藏状态，读取同层旧 KV，写本次私有 KV
       最终层末行产生 logits；所有必要工作成功后发布完整请求描述符
       失败保持旧提交，隔离未提交写入；不得逐层发布部分成功
   其他路径也按自身输出与副作用合同完成一致提交。
8. 在真实设备工作、拷贝及输出消费者完成后释放本次使用权。
   排空对象只有在全部相关引用结束后才可回收。
```

步骤 4 的验证是发布前的必要证据，有限样本不能证明整个符号域。域的扩大还需要合法改写、索引与范围分析，以及 backend 的支持合同；无法证明的部分应缩小 guard 或采用回退。调优中的成本预测也不能决定合法性。

可执行产物采用以下状态关系：`absent→compiling→ready→draining→released`，构建失败为 `compiling→failed`。`ready` 表示当前身份和声明路径可以使用，不表示任意 rank、长尾尺寸或资源压力均已覆盖。`failed` 不对请求提供半成品；重试必须有新任务身份或明确策略，防止反复冷编译形成无界队列。产物状态与请求提交状态分开：程序处于 ready，不意味着某次请求的候选 KV 已提交。

一条组合轨迹是：产物 A 进入 ready，图 G 捕获并持有 A；请求 R 启动后持有执行引用；新代产物 B 发布，A 停止接收新请求并进入 draining；R 完成后，A 的请求引用归零，但 G 仍可能再次重放，因此 A 还不能卸载；G 被停用、全部重放完成并销毁绑定后，才结束该引用。释放条件必须同时覆盖请求、图、kernel 和异步传输。重复或迟到的完成通知应按对象、代次和使用票据幂等处理，不能减少另一个对象的引用。

新旧产物并存期间，权重、打包副本、代码、图池和工作区都可能形成峰值。清空一个缓存索引不等于底层对象已无读者，也不等于 allocator 已归还物理存储。多 rank 发布还要求所需 rank 的同一版本和执行合同共同就绪，不能把单 rank 成功当作整个执行组成功。

## 条件化成本与桶的选择目标

下列工作量先描述一个单请求模型，批处理按实际执行的有效行或桶容量求和。若程序还执行虚拟 batch 行，也要计入。工作量、逻辑字节、实际设备事务、容量和时间应分别保存。

对线性层 `XW`，后缀桶执行 `P` 行、输入输出宽为 `d_in,d_out` 时，主要 FLOPs 为 `2P d_in d_out`。若整桶均执行，原任务只需 `s` 行，则额外线性工作按 `P−s` 增长；其中已包含迁移重算行 `m` 和真正 padding 行 `P−q`，不能再把迁移成本加一遍。若 kernel 只执行 `q` 行，则应改用 `q`，并另计按桶分配但没有执行的容量。

attention 每个有效 query 与每个可见 key 的 QK、PV 主项，按一次乘加两 FLOPs 计，为 `2L H_q(d_k+d_v)` FLOPs/对；`L` 为层数，`H_q` 为 query head 数。softmax、mask、位置与 epilogue 另计。原后缀配对数为

`A_original=s h+s(s+1)/2`。

迁移后的有效配对数为

`A_valid=q h'+q(q+1)/2`。

若密集实现按全部前缀容量和后缀 causal 区域工作，模型为

`A_bucket=P K+P(P+1)/2`。

因此可以拆成 `A_bucket−A_original=(A_valid−A_original)+(A_bucket−A_valid)`，分别解释重算与物理容量工作。也可以直接使用 `A_bucket` 估算总量，再记录迁移比例；两种记账不能叠加。若实现先算完整 `P×P` 再 mask，后缀项应是 `P²`；若有有效长度剪枝，桶式可能只是上界。

无前缀的完整 attention，补齐 `n→b` 的矩形配对浪费为 `b²−n²`；不是 `(b−n)²`，后者遗漏原区域与新增区域的交叉项。causal 或窗口 attention 应按真实可见集合和实际执行方式重算，不能共用同一二次式。

访存至少包括权重、输入输出、中间结果、KV、mask/metadata 和布局转换。令全层每 token 的 KV 字节为 `v_KV=L H_kv(d_k+d_v)u`，其中 `u` 为每个 KV 元素字节。一次把 `a` 个有效 KV token 从块布局搬到 flat 的显式复制，逻辑读写主项为 `2a v_KV`；scatter 再按真正写回范围计费。若实现搬运整个容量而不是有效长度，应使用容量长度。共享前缀减少唯一驻留，不自动消除每条 query 的读取；cache、对齐和事务放大又使逻辑字节不等于 HBM 实际事务。

保留旧提交的私有写方案还支付候选 KV 的容量。若各层新增区都保留到统一提交，仅有效行的候选主项为 `q v_KV`；按整桶分配时可能是 `P v_KV`。它与旧提交同时存活，另有页粒度 COW、页表、隐藏状态和 logits 暂存。例中 `q=512`，不能只按原新增的 260 行预留候选写区，因为另有 252 行要重算并隔离旧副本。旧页与候选页共享的部分按物理并集去重；提交不会自动释放其他请求仍引用的旧前缀。采用候选页直接转正可避免一次复制，但描述符发布、完成依赖和旧页排空仍有成本。

融合一个大小为 `Z_bytes` 的中间张量，在确实消除一次物化写出和读回时，可节省约 `2Z_bytes` 的逻辑全局流量；其他消费者仍需该值时不能全额计入。融合也可能增加寄存器、片上存储、spill 或 workspace，从而抵消收益。

准备成本为编译、搜索/调优、打包、加载、图捕获/实例化和验证，按各对象实际复用边界记录。窗口内有 `N_req` 个请求，总准备耗时为 `C_prep` 时，每请求平均准备项是 `C_prep/N_req`。若窗口长度为 `T` 秒，则 `C_prep/T` 是耗时率，不能直接写成每请求成本。准备与执行重叠时，累计耗时也不能直接当成响应时间。

单变体准备成本为 `C_v`，每次命中相对同一合法基线节省 `Δt>0`，命中比例为 `φ>0`，且没有额外干扰时，时间回本条件为

`N_hit Δt≥C_v`，`N_req≥ceil(C_v/(φΔt))`。

设定 `C_v=3 s`、`Δt=0.05 ms`，需要 60,000 次命中；若只有 10% 请求命中，则需要 600,000 次提供请求。`φ=0` 或 `Δt≤0` 时不存在这个正向回本结论。新增变体挤占 KV、降低并发或拖慢其他请求时，还要把这些损失加入比较。这些数值是设定计算，不是实测。

容量应按同一时刻存活对象的物理并集计算，且区分主机与设备：唯一权重、打包副本、代码、活跃 workspace、图池、在途输入输出、布局暂存和运行时其他占用。共享对象只计一次；allocator reserved 与池中活跃对象不能重复相加。互斥工作区可按寿命复用，并发工作区则不能按顺序模型省略。

通信方面，单设备的本地分桶不凭空产生网络通信，但主机 metadata、输入输出搬运仍有成本；TP/PP 改变分片、collective 形状和每 rank 产物时，应重新核对编译与通信计划。同步方面，guard 求值、缓存锁、构建等待、图槽等待、逐层依赖、写回完成和跨 rank 发布都可能进入请求路径。时间应沿实际依赖取关键路径，并合并竞争同一带宽或执行资源的需求，不能把所有独占时间直接相加，也不能只看 kernel 时间。

桶的选择可以在经验联合分布上比较：窗口内执行与转换成本、准备成本，以及峰值容量和首请求约束。两个桶轴的完整组合数为 `|B_P|×|B_K|`；推广到更多独立轴时是各轴数量的乘积。只为一维分别选择看似合理的粒度，可能产生大量从未访问的联合变体。固定 NxD 文档提醒二维桶显著增加 context encoding 程序数量；二维计数本身应明确写成乘积。

一种可实施的有限候选策略是先保留合法通用路径，用实际请求轨迹统计每个候选桶覆盖量和节省；只在准备预算、驻留预算和首请求约束同时满足时增加变体；运行后重新估计命中、迁移及冷路径比例并淘汰低收益对象。该策略不是全局最优证明。若缓存淘汰、并发和重叠会影响成本，必须重放到达顺序，不能仅用无时间结构的长度直方图。

固定 Ansor v1 提供另一层搜索机制：从计算 DAG 产生结构草图，填入 tile、并行、向量化等细节，得到完整程序；用进化搜索和成本模型选择一批候选，编译并在目标硬件测量，更新模型和历史，再分配下一轮预算。其跨子图调度利用端到端目标、历史改善与相似任务估计分配调优资源。成本模型用于安排实验，不能替代合法性；论文的加权子图时间目标也不是任意服务尾延迟的证明。调优涉及 KV append、scatter 或随机状态时，每次试跑必须恢复同一初态，或分离可重复计算和一次性提交。

## 条件变化后的保留、调整与放弃

| 变化 | 应保留 | 应调整或放弃 | 决策所需证据 |
|---|---|---|---|
| 高频形状稳定、复用多 | 明确 guard 与数值合同 | 可增加高收益特化；删除无访问量变体 | 命中次数、完整调用节省、准备摊销 |
| 长尾稀疏、部署寿命短 | 合法通用路径 | 缩减桶与搜索，必要时采用部分编译或库调用 | 冷路径比例、构建队列、首请求延迟 |
| 前缀命中分布改变 | 缓存身份、逐层数据流与原位置 | 重选二维粒度、迁移策略和私有写区预算 | 跳过长度、重算、转换、候选峰值、桶组合数 |
| stride、布局或数值策略改变 | 原函数与允许误差 | 调整 guard、转换和生成程序，不能仅扩大容差 | 最早分歧、转换字节、KV 编解码和实际 backend |
| 权重更新 | 请求版本绑定 | 按折叠、打包、ABI 和地址依赖决定失效范围 | 哪些值被固化、旧对象读者、并存峰值 |
| 图捕获或固定地址引入 | 编译合同与请求提交边界 | 单独建立图身份、槽和绑定寿命 | 捕获外准备、图命中、地址及代次 |
| 目标、编译器或 TP/PP 改变 | 计算定义与逻辑长度 | 重建不相容产物、分片和通信计划 | 每 rank 就绪、workspace、通信和目标测量 |
| 内存压力增大 | 正确性与最后读者原则 | 减少常驻变体、并发槽或打包副本 | 准入、KV/COW 容量、失败排空与物理峰值 |

若高度动态的输出数量没有可接受上界、外部状态无法进入受支持表示，或成熟库已使可节省部分很小，应允许放弃整段专门编译。减少编译范围并不免除状态语义和回退验证。桶边界、kernel 切换和资源台阶会使成本不连续，只有验证单调的区间才能用二分等方法反求容量。模型引入双向依赖、窗口或异构状态层组后，应重新定义各层可复用状态和可见集合，不能仅保留本章的普通全历史 causal mask。

## 诊断：竞争解释、反例与区分实验

先固定模型及权重绑定、规范化输入、数值配置、资源预算、到达轨迹和测量窗口，再同时记录逻辑形状、物理桶、guard 失效原因、构建/命中、迁移 token、布局转换、workspace、等待和完整请求时间。编译后算子名或事件数量变少，不等于工作量和服务成本按同一比例下降。

| 观察 | 竞争解释 | 区分实验与不同预测 | 反证后的修正 |
|---|---|---|---|
| 每个新长度都慢 | 静态特化过细；未覆盖桶；缓存反复淘汰；构建锁等待 | 固定其他条件只改变一个维度，记录产物身份、guard 原因、构建与淘汰；符号化若有效应减少相应构建 | 构建已减少却仍慢，检查锁、转换或图准备 |
| 同一桶、同 shape 输出不一致 | stride/常量漏检；绑定错误；数值路径变化 | 同 shape 改 stride 和已折叠常量，要求 guard 拒绝；故意移除相应检查并执行错误复用，用独立索引参考捕获差异 | guard 正确且仍错，定位首次数值或状态分歧 |
| 分桶后形状分支错误 | 使用了物理长度；逻辑条件未传入程序 | 逻辑长度保持 20，比较物理容量 30 与 32；原分支应保持不变 | 仍随桶变化，修复分支输入或缩小融合边界 |
| 单层可见性通过而最终 logits 错 | 后层重置了输入；历史 KV 层号错误；过早应用 LM head；数值路径差异 | 与独立整段多层参考比较每层后缀输入、K/V、输出及最终末行；分别注入三种数据流错误 | 最早层边界已一致时再查末行归属和数值，不能凭单层检查排除层间错误 |
| 后层失败后重试不同 | 逐层提前发布；覆盖旧页；读入失败尝试；非确定数值或 RNG | 在某层私有写完后注入失败，核对旧描述符与旧页内容；重试仅读旧提交，并与无失败执行比较 | 描述符未变但旧页已变，修写隔离；旧状态完整仍不同，再查初态和数值路径 |
| 前缀命中反而更慢 | 迁移重算；前缀容量工作；block/flat 转换 | 分别控制命中长度、迁移量与 `P,K`，比较有效配对、实际执行和转换字节 | 重算下降但总时间不降，转查转换、读取或准备 |
| 桶边界附近延迟跳变 | padding；kernel 变体切换；workspace 或驻留台阶 | 同输入比较两个合法桶，记录生成路径、容量和完整调用；再扫描边界两侧 | 执行规模不变时，不能继续仅归因于 padding |
| 图命中但结果错或无加速 | 地址/内容代次错误；图外准备；提交已非瓶颈 | 同一编译产物走图与非图路径，固定输入并追踪槽、绑定、准备和完成事件 | 数值相同而时间不降，检查捕获外关键链 |
| 更新模型后出现混合结果 | 请求版本或图绑定过期；原地覆写在途权重 | 延长旧请求和拷贝，发布新代，逐结果核对版本及最后读者 | 版本归属正确仍异常，继续核对实际地址与参数内容 |
| 调优结果不稳定 | 副作用改变初态；搜索候选不合法；资源竞争 | 每次恢复 KV/RNG 并保持相同输入，区分候选、剪枝与最终配置 | 初态隔离后仍波动，转向计时、并发和资源解释 |

正确性参考应独立于被测布局与 mask 生成器。前缀迁移可以用 token 列表逐个从前缀末尾移到后缀开头，检查顺序、有效长度和容量；单层 attention 参考直接按绝对 query 位置遍历 `0…position`，不读取被测 mask。注入从前缀开头迁移、超出容量或将 padding 作为零分数项纳入分母，应由同一比较器拒绝。仅把 padding 的 V 清零不够，它仍可能夺走概率质量。

多层参考应完整计算每层的全序列隐藏状态和 K/V，再与只重算后缀的路径比较。历史参考按层分别保存，不从被测路径复制新增 K/V。除了 logits，还比较迁移区间的各层 K/V；最终输出碰巧接近不保证未来 decode 读到正确缓存。失败检查同时比较提交描述符和旧状态内容：公共长度没有推进，却已经原地改坏旧页，也违反保留旧提交的要求。

缓存负对照应实际执行遗漏 guard 后选中的旧程序，检查不同 stride 的访问和已折叠常量造成的输出错误；只打印两个不同 key 不能证明危险被阻止。形状分支负对照可删除 `n≠10`，或以物理桶 32 替代逻辑长度 20，观察与原函数的确定差异。

成本参考可以直接枚举矩形配对集合，拒绝 `(b−n)²` 的错误浪费式；摊销参考以累计节省达到准备成本为完成条件，拒绝忽略命中比例的回本数。生命周期参考则从捕获、启动、完成和销毁的事件历史重建尚存读者；故意在请求完成但图引用尚存时释放程序，必须触发错误。这些有限模型不证明真实设备同步或内存可见性。

设备与服务实验还要覆盖 guard 边界内外、0/1 或其他特殊尺寸、非连续输入、别名、不同 batch 组成、首次与重复调用、超容量回退和模型更新。性能比较使用相同任务和 offered workload，分别报告冷启动、稳定态、长时间变体增长及完整请求尾部；只比较命中 executable 的 kernel 时间，不能代表动态服务成本。

## 验证范围

随章交付 `tools/check_k_fw_004_full.py`，使用 Python 标准库、确定性整数/标量计算和有限事件模型，离线、只读，不调用项目、编译器或设备实现。保留迁移公式与独立 token 列表参考、两请求联合选桶、缺少前缀容量、零前缀桶、padding 的单层 attention 分母与末行归属、stride/常量和形状分支的错误复用、配对成本、命中率摊销，以及图持续引用下的释放门控。

单层 attention 检查使用由位置构造的分数和固定 token 值，只验证单层可见性与输出行归属。另加的三层玩具 decoder 具有层间隐藏状态和逐层 K/V，使用独立整段执行作为参考，比较后缀重算的各层输出、候选 K/V 与最终 logits；重置后层输入、错取历史层和提前应用输出头会实际进入错误路径。顺序提交模型还在每层候选写入后注入失败，检查旧描述符和旧缓存保持、候选未公开以及重试结果，并检测逐层提前发布。它不模拟真实 Transformer 的全部算子或硬件事务。

本轮未执行交付的 Python 脚本。在工具的 JavaScript 执行环境中，实际运行了同一数学定义下的 CPU 玩具模型复算：154 个三层后缀组合与整段参考一致，重置后层输入、错用历史 KV 层和提前应用输出头三种负对照均被检出；顺序提交模型覆盖三个层后失败点和一次成功提交，检出了逐层提前发布。该记录不等同于 Python 文件执行通过；上一轮协调者提供的 Python 成功记录也不作为本轮新脚本的执行结果。
