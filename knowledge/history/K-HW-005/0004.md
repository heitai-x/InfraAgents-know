# K-HW-005：CUDA 平台：SM 数据流、占用率与执行粒度

CUDA 优化要把算法的数据复用、并行度和状态生存期映射到 SM 的寄存器、共享存储、warp 调度和主机提交路径。一次发射是否合法、能驻留多少 block、实际搬运多少字节、主机是否成为关键路径，是不同问题，必须分别建模。资源模型可以排除某些候选；实际驻留、指令、同步和性能仍须由目标设备证据确认。

## 执行对象、状态与合法发射

一次普通 kernel launch 的主要资源参数可记为 K=(G,T,R,S,B)：G 是 grid 的 block 数，T 是每 block 线程数，R 是编译产物报告的每线程 32 位寄存器用量，S 是每 block 静态与动态共享存储的总字节数，B 表示所需 barrier 等额外片上资源。编译选项中的寄存器限制不能直接替代最终 R；限制可能改变指令和 spill。block 内线程按 warp 调度，本文平台的 warp 大小为 32；T 不是 32 的倍数时，末 warp 只有部分活跃线程。

逻辑状态包括输入输出张量、位置、可见集合和请求身份；执行状态包括驻留 block、warp 槽、寄存器与共享存储分配、同步阶段和在途操作。某个值数学上已经定义，不等于其生产操作已经完成；生产完成，也不等于最后一个消费者已经读完。这三个时刻分别约束消费、发布和覆盖。

合法发射至少要求 T 为正，并同时满足设备每 block 线程上限、各维限制及该 kernel 更严格的 launch 契约。每 SM 的线程上限不能代替每 block 上限：例如每 SM 可以容纳 2048 线程，并不允许一个 block 使用 1025 线程。R、S 必须非负，且满足每线程寄存器、每 block 寄存器和共享存储限制；每 SM 的线程、warp、block、寄存器、共享存储与同步资源还必须容纳至少一个 block。依赖超过 48 KiB 共享存储的路径须满足对应架构的动态分配和显式 opt-in 条件。地址、对齐、指令参与范围和数值契约另行检查，资源公式不能代替它们。

普通 grid 可以大于同时驻留的 block 总数，剩余 block 等待调度；block 顺序没有保证。因此不能让占满资源的驻留 CTA 等待尚未调度的 CTA。原子操作可以表达状态，不能单独保证生产者取得执行机会。跨 CTA 的依赖须由 kernel 完成边界、不会阻塞推进的协议或满足额外条件的协作执行承担。G=0 的逻辑工作应走不发射路径，不用零线程 block 表示空工作。

## 地址、线程映射与片上数据流

对 strided 张量 X，设存储基址为 base_X，元素字节数为 b_X，存储偏移为 o_X，各轴 stride 为 s_j，后两者均以元素计，则：

addr_X(i)=base_X+b_X·(o_X+Σ_j i_j·s_j)。

先决定每个 lane 读取哪些逻辑元素，再把坐标变成地址，才能讨论合并请求、bank 和复用。逻辑 tile 大小不直接决定线程数、每线程寄存器数或矩阵 fragment 内部布局。

对 compute capability 6.0 及以后的自然对齐标量 32 位访问，固定 Best Practices 给出的访问单元为 32 字节。32 个 lane 读取对齐数组中相邻的 32 位字，覆盖 128 字节，需要四个段；起点向后偏移 4 字节则跨五个段。这里数的是请求覆盖段，不是最终 HBM 事务。相邻 warp 的 cache 重用可能吸收多取的数据；非合并访问则可能读取大量未使用字节。不能把 128 字节误当作此模型的段大小。

共享存储的标量 32 位模型把字号 a 映射到 bank a mod 32。令 D_b 为本轮落在 bank b 的不同字号集合，冲突度为 max_b |D_b|。stride 1 的 32 个连续字分属不同 bank，冲突度为 1；字号 8λ+t 只触及四个 bank，且各地址不同，冲突度为 8；所有 lane 读取同一个字属于广播，冲突度为 1。向量或矩阵加载可能拆成多次请求，应按真实指令解释，不能直接套用这份标量模型。

一种普通数据路径是 global → cache → 共享存储 → 寄存器 → 计算 → 写回。共享存储由程序管理：协作写入后，读取前需要覆盖实际写者和读者的发布与同步；最后读者完成后才允许覆盖。异步加载还要等待对应复制完成。warp 内操作不能依赖隐含锁步，CTA 同步也不能自动建立跨 CTA、跨 stream 或主机可见性。

下面给出一条可重建的 SIMT attention 映射。它是便于解释的候选，不是推荐性能配置。令 d=dv=32、Br=2、Bc=32，输入和累加采用 FP32，CTA 有 64 个线程。线程 τ=32w+λ，w∈{0,1}，λ∈[0,31]。warp w 独占 query 行 q0+w，lane λ 保存该行 Q 的第 λ 维和输出累加 U[λ]；行统计 m、ℓ 由 lane 0 保存。每个 CTA 用单级共享数组 K_s[32,32]、V_s[32,32]。

对每级 KV tile，全体线程分别为 K、V 按 i=τ+64v、v=0,…,15 加载，映射为 key 局部行 floor(i/32)、维度 i mod 32。每个共享位置恰有一个写者；全局地址由真实 stride 计算。无效尾部不解引用，填充值也不作为可见 key 进入归约。CTA 发布输入后，每个有效 warp 依次处理真实 key j：各 lane 计算 Q[λ]K_s[j,λ]，通过显式 warp 归约得到点积；lane 0 根据可见性、缩放和后文在线公式产生 m新、ℓ新、旧贡献系数 r 与本项权重 p，再按正确参与掩码广播 r、p；各 lane 更新 U[λ]=rU[λ]+pV_s[j,λ]。不可见 key 保持状态。一个 warp 的 query 已越界时跳过算术和输出，但仍参加 CTA 的输入发布与读完同步。两个 warp 的最后读取均完成后，下一 KV tile 才能覆盖共享数组。遍历结束后广播最终 ℓ，非空行写 U/ℓ，空行写零。

该候选共享输入主项为 2×32×32×4=8192 字节；Q 与 U 的逻辑寄存器数据各为 256 字节，两行 m、ℓ 合计 16 字节，实际寄存器还包括归约、地址和临时变量。它逐 key 消费标量 p，不保留完整 P tile，因此不能给它强加后文两级 P 缓冲的容量。对齐且维度连续时，完整 warp 加载同一 key 的连续维覆盖四个 32 字节段；点积中的共享 K 读取与 U 更新中的 V 读取也按连续维分布。两行复用一份共享 K/V，但同一 KV 在不同 query CTA 间仍可能重读。改用矩阵指令时，应重做操作数布局、参与范围、归约交接与容量账，不能臆造未公开的 fragment 行列映射。更完整的矩阵与双缓冲交接见 [GPU 流水](gpu-kernel-pipelines.md)。

## 占用率：合法条件之后的资源上界

设每 SM 上限为 T_SM 线程、W_SM warp、B_SM block、R_SM 个 32 位寄存器和 S_SM 字节共享存储；另设独立的每 block 上限 T_block、R_block、S_block，以及每线程寄存器上限 R_thread。它们不能互相替代。对资源公式，要求 T>0、warp 大小和分配粒度为正，各预算有效；R、S 可以为零。

每 block 的 warp 数 W=ceil(T/32)。在采用每 warp 寄存器量子 g_R 的抽象模型中：

R_w=ceil(32R/g_R)·g_R，R_b=W·R_w。

若共享分配粒度 g_S 已知，则 S_b=ceil(S/g_S)·g_S；S=0 时 S_b=0。未知真实粒度时，S 只能作为分配量下界，须由目标工具确认。寄存器分配组织随架构变化，这份量子模型不覆盖所有平台。

先检查 T≤T_block、R≤R_thread、R_b≤R_block、S_b≤S_block 及其他 launch 条件，再定义资源限制函数：

L(C,x)=+∞，若 x=0；否则 L(C,x)=floor(C/x)。

于是：

A_model=min(floor(T_SM/T), floor(W_SM/W), B_SM, L(R_SM,R_b), L(S_SM,S_b), A_barrier)。

A_barrier 是目标同步资源给出的驻留 block 上界；没有相应资源用量时不构成限制。零共享存储或模型中的零寄存器用量不限制驻留，不能因分母为零就判定不能发射。T 和 W 是结构性分母，必须为正，不适用这个分支。合法条件不满足或最小限制小于 1 时，A_model=0；否则模型占用率为 A_model·W/W_SM，活跃线程数为 A_model·T。

这是资源上界，不是实际驻留保证，也不是完整 CUDA launch 验证器。barrier、寄存器分区、cluster、共享 carveout、驱动保留量和分片环境可能增加限制。目标 occupancy 工具和编译资源报告用于核对模型遗漏；理论与实际驻留不同还可能来自网格太小或负载不均衡。

可复算设定：T_SM=2048、W_SM=64、B_SM=32、R_SM=65536、g_R=256、S_SM=98304，block 上限足以容纳本例，取 T=128、R=37、S=0。W=4，32R=1184 向上取整为 1280，R_b=5120。共享用量为零，不限制驻留，因此 A_model=min(16,16,32,12)=12，占用率 75%。忽略量子而用 floor(65536/(128×37)) 会得到 13 个 block 和 81.25%，高估驻留。固定指南给出 CC 7.0 的对应粒度与 75% 实例；不能把该量子直接推广到所有 CC。

在相同抽象预算下，T=128、R=0、S=0 时寄存器与共享存储均不限制驻留，A_model=16。R=0 是用于检查零用量语义的模型输入，不声称某个真实 kernel 编译后必为零。取 T_block=1024、R=1、S=0，T=1024 时模型可容纳两个 block；T=1025 必须在每 block 合法性检查处拒绝，即使每 SM 的 2048 线程预算还能容纳它。

更高占用率可以增加隐藏访存或依赖延迟的机会，但不保证更快。缩小 tile、限制寄存器或增加线程还会改变复用、指令级并行和 spill。固定 Best Practices 也指出，足够的独立指令在某些情况下可以让低占用率 kernel 隐藏延迟。驻留 warp 还不等于 eligible warp：等待数据或屏障的 warp 暂时不能发射指令。grid 小于 SM 数时，一部分 SM 无工作；远大于同时驻留数时，形成多个 wave。对同质 block 的理想估计为 ceil(G/(A_model·N_SM))，前提是 A_model>0；尾部、调度和 cluster 会改变实际分布。

## Attention tile：归约、容量与选择反转

对一个 head，输入 Q∈R^(L×d)、K∈R^(S×d)、V∈R^(S×dv)，缩放 a，可见集合 A_r；输出为每行可见分数的 softmax 加权和。此处 S 是 key 长度。要求 d、dv、Br、Bc 为正，长度非负，可见分数与参与的 V 有限；特殊值和溢出须另行定义。空行采用零输出契约，L=0 返回空输出。

CTA 选择 Br 个 query 行，按 Bc 个 key 遍历。对已处理集合，保存逐行最大值 m、质量 ℓ=Σexp(z−m) 和未归一化输出 U=Σexp(z−m)V；空状态为 (−∞,0,0)。新块使最大值上升时，旧贡献必须乘 exp(m旧−m新)，因为旧、新贡献要使用同一指数尺度。旧状态为空时系数为零；本块为空时保持全部旧状态，避免负无穷相减与残留值。

```pseudocode
输入：Q[L,d]、K[S,d]、V[S,dv]，缩放 a，可见集合 A_r
      正整数 Br、Bc，有限输入与有限可见分数契约
输出：O[L,dv]，空行输出零
对 q0=0,Br,2Br,... 且 q0<L：
    取得本块真实 query 行，并载入 Q tile
    对每个真实行 r：m[r]=−∞，ℓ[r]=0，U[r]=零向量
    对 k0=0,Bc,2Bc,... 且 k0<S：
        只载入本块真实 K/V，等待输入完成并发布
        对每个真实行 r：
            C=A_r 与本块真实 key 范围的交集
            若 C 为空：保持 m[r]、ℓ[r]、U[r]
            否则：
                对 j∈C：z[j]=a·dot(Q[r],K[j])
                m新=max(m[r],max(z[j]，j∈C))
                若 ℓ[r]=0：r旧=0
                否则：r旧=exp(m[r]−m新)
                对 j∈C：P[j]=exp(z[j]−m新)
                U[r]=r旧·U[r]+Σ(j∈C) P[j]·V[j]
                ℓ[r]=r旧·ℓ[r]+Σ(j∈C) P[j]
                m[r]=m新
        确认全部有关消费者读完后，才允许复用输入槽
    对每个真实行 r：
        若 ℓ[r]=0：O[r]=零向量
        否则：O[r]=U[r]/ℓ[r]
        写回有效输出
```

每完成一块，状态都等于已处理可见集合的统计量，这是正确性不变量。尾部不能作为分母中的额外项；mask 不能仅在最终输出上应用。上述为同步数学数据流，异步实现必须保留输入就绪、矩阵完成与最后读者依赖。完整分区合并、两程算法和偏置扩展由 [Attention 的 IO 与在线归约](../algorithms/attention-io.md) 展开。

按乘加计两次运算，稠密 QK 与 PV 的计算主项约为 2LS(d+dv) FLOP，另有指数、归约、重标度和地址生成。若执行真正跳过不可见 query/key 对，可按实际计算对数重算；仅屏蔽结果不能扣除已经执行的矩阵工作。对 query 块在外、每个 CTA 各读取一次完整 K/V 的组织，忽略 cache、尾部和其他输入时，逻辑全局读取主项为 Ld·s_Q+ceil(L/Br)·S(d·s_K+dv·s_V)，输出写入为 Ldv·s_O。不同 CTA 的 cache 重用、GQA 共享、spill 和非合并访问使实际设备主存字节偏离这份逻辑账。

对实际保留完整 P tile 的候选，片上数据预算主项为：

C_tile=Br·d·s_Q+n_kv·Bc·(d·s_K+dv·s_V)+n_p·Br·Bc·s_P+Br·dv·s_U+2Br·s_stat+C_other。

s_* 为各对象元素字节数，n_kv 和 n_p 分别为 K/V 与概率缓冲级数；C_other 包括实际同时存活的对齐、barrier、转置、地址和 epilogue 临时量。该式描述选定生存期内的片上总预算。应按放置分别记入共享存储与寄存器，不能把两类容量互相借用，不能重复计入同一物理对象。分数和概率若同时存活且不复用同一空间，还须分别计账；额外局部输出 Ub 也不能无故省略。

设 Br=Bc=64、d=dv=128，Q/K/V/P 为 2 字节，U 与统计为 4 字节，n_kv=n_p=2、C_other=0。独立对象明细为 Q 16 KiB；K/V 两级 64 KiB；P 两级 16 KiB；U 32 KiB；统计 0.5 KiB，合计 128.5 KiB，即 131584 字节。漏掉 P 会报告 115200 字节；少一级 K/V 会报告 98816 字节。若所有对象都放共享存储，正确总量不能装入 99 KiB；少一级 K/V 的错误账却会错误放行。容量验证必须比较实际算法要求的对象、级数和放置，不能仅比较一个总数是否小于硬件上限。

这份总量能装入 227 KiB 不表示 kernel 已合法：还没计其他共享对象、寄存器、线程与同步限制。真实实现把 P、U 放寄存器时，应重新核算两份预算；寄存器有余量也不代表能满足目标矩阵布局。

增大 Br/Bc 可以提高复用、减少重复读取，却增加片上状态、尾部浪费，并可能减少 CTA 数或驻留。固定 FA3 v1 的两级消费者流水额外保留下一份 FP32 分数 Snext，至少增加 4BrBc 字节；64×64 为 16 KiB，若由 128 线程平均承担，仅此一项为每线程 32 个 32 位寄存器。其生存期不同于一份已转换概率，不可因为已有 P 缓冲就自动抵消。论文三级实验没有获得普遍优势，不能推出所有设备上更深总好或总坏。

decode 的 query 行少时，沿 KV 切分可增加 CTA 数。每个分区须输出 m、ℓ、U，再按最大值重标度合并，不能直接平均归一化输出。P 个分区的部分状态主项为 P·Br·(dv·s_U+2s_stat)，另付部分状态写读、重复 Q 读取和合并同步。query 块已足够多时，增加分区可能只增加这些成本。

## 从 eager 到图与持久 kernel

eager 按 kernel 提交；图预先保存节点和依赖，每步重放稳定执行段；服务级持久 kernel 则在设备内部反复分发任务。持久 attention tile 调度与整步模型常驻不是同一范围，FA3 中局部 kernel 的持久策略不能当成整步服务的性能证据。

设 D_dev 为同一步设备工作的下界，H_submit 为主机每步提交工作。在主机可提前排队、相关工作允许重叠的稳态模型中，步长下界为 max(D_dev,H_submit)。首次准备、图捕获与实例化另计；重复 N 次时可以讨论其摊销，但不能把它们伪装成稳态 replay 成本。依赖要求的等待、复制、采样和响应仍须进入关键路径。单请求下一步依赖本步采样，未必允许把全部主机工作提前；该情况下应按实际依赖链增加未重叠项。

若 D_dev=12 ms、H_eager=1.2 ms、H_graph=0.2 ms，两条路径的该下界都是 12 ms。图若仍产生约 1 ms 收益，需查原路径未重叠的主机空洞或其他变化，不能称图加快了矩阵计算。若 D_dev=0.8 ms，则 eager 下界为 1.2 ms，图下界为 0.8 ms，提交进入关键路径。这些是设定对照，不是测量。

持久化把同步、分发和不均衡成本移入设备。若 D_persist 是该组织的设备工作下界，C_device 是不能隐藏的额外设备同步与分发成本，则相应理想模型为 max(D_persist+C_device,H_persist)，再考虑未覆盖的串行项。不能把设备屏障成本只加到主机项，让它在设备主导时消失。资源占用和工作划分还可能改变 D_persist 本身，不能默认等于原 D_dev。

本章图路径采用固定参数 capture/replay：地址、形状、stride、kernel 变体和捕获参数要满足绑定契约；变长内容由有效范围、固定容量缓冲、桶和代次保护承接。受支持的图更新是另一种方案，更新成功仍不证明数据身份和生命期正确。图减少提交，不自动减少图内算术或 HBM 流量；详细绑定与槽协议见 [CUDA Graph](../frameworks/cuda-graph-buffers.md)。

持久执行必须分别证明内存顺序与调度推进。一个明确的选择是采用目标支持、运行时接受的 cooperative launch，并使用该契约允许的 grid 同步。对真实编译出的 kernel、动态共享配置及当前可用 SM，取得目标运行时给出的驻留容量；grid 必须符合协作发射上限及其他限制。G≤A_runtime·N_SM 是常见容量检查，但本文 A_model 的上界不能替代真实协作发射核验；普通 launch 即使碰巧使用同样小的 grid，也不因此获得 grid 同步契约。

在此选择下，把每层有限任务静态或动态分给参与 CTA。所有线程按一致阶段参加合法网格同步；没有任务的 CTA 也要到达，不能提前退出。任务开始前已有上层输入；完成本层异步操作及所需发布后才进入层末同步，下一层在同步后读取。设备异步复制或矩阵操作还要先满足它们自身的完成与可见性要求，不能认为一个任意 barrier 会自动完成全部异步操作。若一层内部的任务彼此依赖，也要划分生产、同步、消费阶段，不能把尚未就绪的工作当成独立任务分发。

```pseudocode
前提：协作发射受目标支持并被接受，参与网格满足驻留与同步契约
输入：本步就绪请求、稳定权重、各层状态与明确代次
对每层 l=1,…,32：
    对该层按数据依赖划分的每个有限阶段：
        每个 CTA 完成分配给它的本阶段任务，无任务者保持参与
        等待本 CTA 发出的有关异步生产与消费完成
        按所选内存作用域发布本阶段结果
        全部参与线程执行同一阶段的合法 grid 同步
        同步完成后，后继阶段才消费已发布结果
全部参与者经过最后完成边界后结束或进入下一次已定义迭代
```

若用标志发布结果，必须先汇合全部生产写者，再由发布者执行覆盖目标读者作用域的 release；消费者匹配代次，以 acquire 观察发布后才能读数据。标志初始化、阶段和缓冲生命期也须一致。原子性、release/acquire 和 fence 解决内存顺序，无法使一个未调度生产者获得执行槽。

具体死锁反例：设备只能同时驻留两个持久 CTA，普通 grid 有三个；先驻留的 CTA 0、1 都等待 CTA 2 的生产标志，且等待期间不退出。CTA 2 无槽可运行，系统没有后继事件。把标志升级为正确原子操作仍不能修复。无法满足协作契约时，可保留 kernel 边界；也可改成仅领取已就绪独立任务、不会占槽等待未调度生产者的工作队列，但须另证任务依赖、终止检测和推进。不能仅删除 grid barrier 后把同样依赖改写成自旋。

持久核整段占用寄存器、共享存储和 SM；采样、复制及其他批能否并行取决于剩余资源。取消应在明确边界停止新任务，已经提交的访问仍需排空。是否采用取决于测得的 launch 间隙与新增设备成本，固定材料没有给出本章整步持久服务的实测收益。

## L2 驻留与访问策略窗口

固定 CUDA 文档的 L2 保留区与访问策略窗口允许为连续全局地址范围施加持久访问策略。hitRatio 表示多少比例的访问按持久属性处理，不保证把整个窗口锁在 L2。既有固定例为保留区 16 KiB、窗口 32 KiB、hitRatio=0.5，约一半窗口访问按持久处理；hitRatio=1 试图覆盖整个窗口，容量不足仍会逐出。多个 stream 竞争同一保留区时，窗口容量不能分别相加。

反复读取的位置表、小 adapter、分页索引或热 KV 块可能受益；远大于 L2 的权重与长历史扫描应重新比较污染和复用距离。stream 与图 kernel 节点均可承载对应属性，但设置成功不证明命中。固定版本记录中 MIG 禁用该保留区功能，MPS 的大小配置受服务启动设置约束；应按实际模式确认。用工作集扫描、cache 与设备主存字节区分策略效果，不能把命中后的表观速率当作 HBM 带宽。

如果热工作集超过竞争后的有效保留容量，或复用距离增加使数据在重读前逐出，应减小持久范围、调整比例或放弃该策略。逻辑读取量没有变化时，性能改善的预测应是实际 HBM 交通或等待下降；只看到策略设置成功不足以支持收益。

## 时钟、功耗与可持续成本

既有固定 Nsight Compute 记录说明默认时钟控制以基准频率减少变化，热限流仍有更高优先级。replay、cache 清理和并发变化使 profiler 区间与服务稳态条件不同。所供原文明确说明默认在每次 replay pass 前清理 GPU cache，且多遍采集和保存恢复会改变环境；计数用于解释正常路径，不直接替代服务计时。

理论带宽由内存时钟、接口宽度和倍率得到；有效带宽按约定边界的有用读写字节除以完成时间。既有 Best Practices 记录对 GDDR ECC 给出 6.25% 容量开销及访问模式相关、约 20% 的带宽影响；HBM2 使用专用 ECC 资源，不能套用相同折减。实际容量和速率均应以目标配置为准。

内存与计算的理想下界分别为 T_mem≥D_HBM/B_eff、T_comp≥F/P_eff，允许理想重叠时取 max，再加入不能重叠的依赖和准备成本。共享同一带宽的阶段不能各领取一份峰值。B_eff、P_eff 应来自匹配访问形态、形状、并发、功耗和运行时长的可持续点；cache、copy engine、CPU 与 GPU 不构成互不争用的独立通道。另一机箱、功耗上限或共享设备条件下，应重新表征。方法见 [GPU 从零表征](../tools/gpu-characterization.md)。

## 场景：单 GPU 交互服务的完整选择

以下全部为设计设定。固定 GQA decoder 的权重驻留 14 GiB；设备可用容量 24 GiB，工作区 2 GiB、graph/固定缓冲 1 GiB、预留余量 1 GiB。模型为 32 层、8 个 KV head、head 维 128、KV 元素 2 字节。8 个活跃请求各有 2048 个全层已计算历史位置，另有本轮已知输入 token 等待 forward。ITL 目标 30 ms，主机与响应预算暂设 3 ms；设备有效读取带宽假设为 1 TiB/s，实际 kernel 能力仍需测量。

每 token 全层 KV 为 2×32×8×128×2=131072 字节，即 128 KiB；每请求 2048 位置为 256 MiB，8 个请求为 2 GiB。所列项合计 14+2+1+1+2=20 GiB。24 个同长请求的 KV 为 6 GiB，恰好耗尽剩余空间，未计本轮增长、页尾或额外工作区，不能直接作硬准入上限。8 个请求各追加一个已计算位置还需 1 MiB 逻辑 KV；分页分配与写时复制可能要求更多物理增量。

比较 A：全驻留、已验证 backend、eager 连续批；B：加入受时间预算约束的分块 prefill、合法前缀共享及固定缓冲图执行；C：在质量允许且验证通过时使用更低精度路径。A 是语义与成本对照，B 改变状态和执行组织，C 还改变数值路径，应逐项区分后再评估组合。

在每轮读取全部权重和每请求已有完整 KV 的设定下，基线读取主项为 14+2=16 GiB，按 1 TiB/s 为 15.625 ms；本轮 K/V 生成、写入和参与 attention 的新增交通还要计入。30−3−15.625=11.375 ms 是其他开销的剩余预算上限，并非已经可交给 prefill 的时间。实际矩阵、激活、同步、额外事务与排队仍会消耗它；混合批可行块长须从对应形状的服务曲面取得。

若 8 个请求共享合法的 1024 token 前缀，已有唯一 KV 可降为 128 MiB 公共部分加 8×128 MiB 私有部分，共 1.125 GiB。逻辑可见历史不变，HBM 流量是否因 cache 重用下降要另测。模型、adapter、位置处理或 processor 身份不相容时，不能套用共享算例。

把一个请求的本轮状态展开。令 t=2048，已知输入 x_t，历史全层 KV 覆盖位置 [0,t)，本轮开始时 x_t 尚无全层 KV。请求代次、位置、页表与图槽内容必须属于同一快照。执行链如下：

```pseudocode
输入：已知 token x_t，全部32层覆盖 [0,t) 的有效 KV，模型与请求身份
输出：采样 token y，以及覆盖 [0,t+1) 的已提交全层 KV
预留全部必要增量页，取得独占写区与本轮图槽
写入 x_t、位置 t、页表、有效范围和请求代次
等待输入与 metadata 发布后启动绑定的执行图
h_0=Embedding(x_t)，位置变换按模型定义应用
对 l=1,…,32：
    等待 h_(l−1) 可消费
    按该层模型的归一化和投影计算 q_(l,t)、k_(l,t)、v_(l,t)
    完成规定的位置处理及存储表示转换
    将 k_(l,t)、v_(l,t) 写入该层位置 t 的私有可写区
    等待完整 K/V 与必要尺度就绪，并向本层读者发布
    attention 消费该层历史 [0,t) 和当前位置 t 的 K/V
    完成输出投影、残差、归一化、MLP及模型规定的顺序，得到 h_l
    发布 h_l，才允许下一层消费
最后层完成后，经模型规定的最终归一化和输出头产生 logits
确认全部层 KV 写入及整步副作用成功，再提交全层已计算长度 t+1
按请求的采样状态从 logits 得到 y，提交一次输出记录
若继续生成：把 y 作为下一轮位置 t+1 的已知输入
```

这里按固定稠密 decoder 的层依赖描述，具体归一化、残差和位置算子顺序服从模型。每层 K/V 的局部就绪先于该层 attention，不必等待其他层才允许本层消费；对外的全层已计算高水位只在所有层成功后推进。不能因第 1 层已写 t 就宣称整个请求已经完成该位置。层内失败不得发布全层长度或采样输出，未提交写区按实际排空与恢复协议处理。若全层 KV 已提交而采样或交付失败，应保留已提交边界并处理输出的重试身份，不能重复追加同一位置。

新采样 y 的身份是位置 t+1 的 token；当前 logits 产生它，但尚未计算它自身各层 K/V。它在后续 forward 中才生成这些状态。若最后 prompt token 已完整命中 KV，却没有可用末行 logits，不能把剩余工作设为零并等待采样；须取得合法保存的 logits，或在隔离写区安全重算所需末 token。这些状态关系决定下一轮是否真的有输入。

释放分三类。本轮临时激活和工作区在其最后设备消费者结束后可复用；图槽还须等 metadata、输出及异步复制等全部消费者结束，或已把所需输出移入独立受保护存储。活跃请求的历史 KV 则要跨步保留，不能因本轮 attention 读完就释放。请求结束或取消后先停止新访问，再解除请求及缓存的相应引用；只有共享引用归零且全部在途读写、复制均排空，物理页才可回收。共享前缀仍被缓存或其他请求引用时继续存在。迟到完成事件按旧代次清理，不能释放已交给新请求的槽或页，详见 [内存分配](../system-semantics/memory-allocators.md)。

B 的图桶、槽和流水缓冲会挤占 KV 容量；C 的低位路径需要布局、尺度和质量证据，FA3 某个形状的 H100 结果不能填入此服务估时。GPU 已受设备主存交通限制时减少提交未必改变主项；短请求与大量小 kernel 则可能相反。低负载可保留 A，高前缀复用有利于 B，超长历史使 attention 与容量更突出，质量门槛收紧可能排除 C。硬件或负载改变后重新计算容量与关键路径。

## 按 compute capability 的执行资源与特性事实

以下保留既有 CUDA 12.8.0 固定规格记录，KB 按 1024 字节解释。它们是规格上限，不是本章的测量，也不保证编译出的 kernel 达到该驻留；表外代际须按固定来源核对。

| 项目 | 7.5 | 8.0 | 8.6 | 8.9 | 9.0 |
|---|---|---|---|---|---|
| 每 SM 最大驻留 block 数 | 16 | 32 | 16 | 24 | 32 |
| 每 SM 最大驻留 warp 数 | 32 | 64 | 48 | 48 | 64 |
| 每 SM 最大驻留线程数 | 1024 | 2048 | 1536 | 1536 | 2048 |
| 每 SM 共享存储上限 | 64 KB | 164 KB | 100 KB | 100 KB | 228 KB |
| 每 block 共享存储上限 | 64 KB | 163 KB | 99 KB | 99 KB | 227 KB |
| 每 SM 32 位寄存器数 | 64 K | 64 K | 64 K | 64 K | 64 K |
| 每线程最大寄存器数 | 255 | 255 | 255 | 255 | 255 |

所有列 warp 大小为 32，每 block 最多 1024 线程，共享 bank 数为 32，每线程本地存储上限为 512 KB。超过 48 KB 的每 block 共享分配依赖动态共享存储及显式申请。统一数据缓存在 8.0/8.7 为 192 KB，8.6/8.9 为 128 KB，9.0 为 256 KB；可划给共享存储的档位不同，carveout 偏好是提示，不能当作实际分配保证。

所列硬件加速 global→shared 异步复制、split arrive/wait barrier 和 L2 驻留管理从 8.x 起可用；线程块簇、分布式共享存储、TMA 和 DPX 从 9.0 起可用。bf16 算术从 8.x 起可用；8.9 与 9.0 的第四代 Tensor Core 接受 FP8，8.0/8.6/8.7 的第三代不含该 FP8 路径；128 位整数原子从 9.0 起提供。具体接口、形状和布局仍须分别核验，硬件特性标签不是任意矩阵 API 的许可。

三级 32 KiB 输入缓冲占 96 KiB，在 99 KiB 每 block 上限下只剩 3 KiB 给其他共享对象；在 227 KiB 上较宽松，但增加分配仍可能降低驻留。缺少 TMA 时可用普通线程加载或目标支持的异步复制组织相同依赖；没有簇时可通过全局部分状态与后续 kernel 交换，也可改变任务划分以避免交换。保留函数与最后读者关系，重新核算地址生成、指令、同步、交通和驻留，不照搬某一代 tile。

## 诊断：竞争解释与区分实验

| 竞争解释 | 可区分预测 | 干预与观测 | 反证后的修正 |
|---|---|---|---|
| 驻留不足限制延迟隐藏 | 可运行 warp 减少时，等待暴露和完整网格时间恶化 | 保持 kernel 与计算不变，用额外动态共享分配降低驻留，记录实际资源、eligible warp 与时间 | 驻留改变而时间稳定，降低此解释权重；改变块大小另有映射混杂 |
| 非合并访问增加实际交通 | 请求段增加，削弱 cache 后设备主存字节也增加 | 固定有效元素与映射，改变对齐或 stride，再扫工作集 | 段数增加而 HBM 字节未变，查 cache 重用，不能直接按段估设备事务 |
| shared bank 冲突 | 不同地址落同 bank 的布局变慢，广播不出现相同代价 | 对照 stride 1、stride 8、同址广播，核对实际指令分解 | 广播被判冲突先修模型；计数不变而变慢需查其他资源 |
| 大 tile 或深流水降低驻留或产生 spill | 逻辑读取下降，但资源台阶或 local 交通上升，完整时间反转 | 同一函数扫 tile/级数，记录编译资源、local 交通、尾部和完整网格 | 没有 spill 不能继续归因 spill；驻留未变则查同步、布局和并行度 |
| 图减少提交 | 设备工作近似不变，host 空洞减少 | 同内容比较 eager/replay，分记准备、API、设备区间和结果完成 | 空洞仍在查捕获边界；设备区间改变则查调度与竞争 |
| 持久核节省 launch | 原间隙较大时可能获益，同步或占用增加时反转 | 先核验推进契约，再测分发、层间等待、取消边界与整步时间 | 普通超额 grid 的停滞先按推进错误处理；合法但变慢时重算设备成本 |
| 采样输出已拥有 KV | 若此解释正确，下一步可跳过该 token forward | 跟踪 token 位置、逐层 K/V 发布和全层高水位，比较独立 forward | 采样后没有该位置各层 K/V，必须保留下一轮计算 |
| 本轮读完就可回收历史页 | 后续 decode 不再访问那些页 | 连续两步、共享分叉、取消后迟到完成与槽复用交错 | 活跃或共享引用仍存在时保留页；仅临时引用可解除 |
| profiler 区间代表服务 | replay、时钟和并发变化不影响结论 | 声明采集方式、cache 控制、频率与预热，以正常服务时间线复核 | 差异随这些条件变化时，限制 profiler 结论范围 |

正确性参考与性能实验分别安排。驻留参考独立枚举合法 block 数，不能复用被测函数的入口遗漏或舍入实现；容量参考展开每个实际对象与缓冲级数，再比较各类预算和放行结果。attention 用整行稳定 softmax，并逐块重算已处理集合的 m、ℓ、U。负对照必须作为缺陷实现进入同一验证器：遗漏每 block 上限、把零共享用量判非法、忽略资源粒度、漏 P、少一级 KV、把广播按 lane 数计冲突、错误重标度或把额外设备成本放进主机项，都要产生具体拒绝。

服务验证从固定前缀独立 forward、冷/热共享、非整除页和 batch 重排开始，再覆盖取消复用、逐层写入中断、图桶切换、prefill/decode 交错及低位异常值。性能固定到达轨迹与质量，记录 TTFT/ITL、完成和失败、主机空洞、实际字节与物理峰值，用独立重复确认；方法见 [统计实验](../tools/statistical-experiments.md)。

随章 tools/check_k_hw_005_full.py 为确定、离线、只读的 Python 标准库检查。它核对抽象驻留合法性与独立枚举参考、对象容量明细、标量请求段和 bank 模型、预计算有限分数的在线 attention 前缀统计、理想提交成本、wave 台阶，以及有限驻留的持久等待反例。脚本负对照实际进入对应验证器。它没有执行 QK 点积、完整线程映射或 32 层真实模型，也不证明 CUDA 协作发射、release/acquire、异步完成、GPU 调度、fragment、spill、事务或性能。本轮未执行该 Python 文件，不沿用旧候选退出码作为本轮交付已通过的证据；没有目标 GPU 测量或 Agent 使用效果证据。
