# K-WORK-008：弹性服务：启动延迟、可用容量与排空

弹性服务把负载变化转成启动、开放、排空和回收决定。控制面期望的副本数、已分配设备数、已启动进程数、完成预热的执行组数，以及能够接收新请求的容量，属于不同状态。新增容量只有在执行组验证合格且准入路由提交后才存在；缩容也只有在最后使用责任结束后才释放物理资源。

本章采用一个保守控制模型：路由、准入门和请求责任登记在共同权威状态域中排序，设备执行异步推进。该选择说明必须满足的原子关系，不要求所有工作使用同一把锁，也不声称所引论文已经实现本章协议。

## 从副本数到可兑现容量

设时间 t 的单位为秒。不可变制品版本为 v；一次准备尝试为 g＝(槽位, 不复用代次)；执行计划 P 包含完整 rank、实际设备和布局；公开请求范围为 Ω_g。就绪证书 C_g 将 v、g、P、环境依赖、范围与验证证据绑定在一起。相同版本的失败重试也使用新的 g，不能只按容器名或槽位接收完成通知。

q_g 是在声明请求类、负载区间、资源预算和质量合同下的合格服务率，不是 GPU 峰值。混合请求应保留容量向量。LLM 至少区分 prefill、decode、KV 增长与输出背压；队列中的请求数或 token 数不能直接替代设备秒。

| 状态 | 新请求准入 | 保留的责任 | 新准入容量 |
|---|---|---|---|
| PREPARING | 关闭 | 预留、加载、转换、建组、编译与预热 | 0 |
| READY | 关闭 | 已验证执行组，等待显式路由提交 | 0 |
| OPEN | 按当前路由和证书检查 | 已接受请求及实际访问 | 条件化 q_g |
| DRAINING | 关闭 | 已绑定请求可继续，已有访问与输出仍受保护 | 0 |
| RETIRING | 关闭 | 拆除绑定、结算最后访问和输出借用 | 0 |
| RETIRED | 关闭 | 实例资源已经归还 | 0 |
| FAILED | 关闭 | 保留失败前已经产生的未结责任 | 0 |

对一个路由范围，权威记录为 A＝(e,T)，e 是递增路由代次，T 是可供新准入选择的实例身份集合。正常提交保持 OPEN 的准入目标集合与 T 一致；若某个 OPEN 的证书失效，立即禁止其新准入并撤出 T，不能继续兑现历史容量。

令 A_g(t)＝1 表示 g∈T、状态为 OPEN 且 C_g 当前有效，否则为 0，则

μ_new(t)＝Σ_g A_g(t)q_g(t)。

DRAINING 可以继续完成已绑定请求，但不能再次作为新请求容量。已有请求、加载和排空还会争用 OPEN 使用的物理资源，因此 q_g 必须是在这些占用之后能够兑现的预算。不能为同一块设备的 OPEN 和 DRAINING 各分配一份独占吞吐。

对资源 r，令 a_{g,r} 为每单位服务消耗的资源量，R_r 为可用资源率，H_r 为突发、故障和切换余量，则候选服务率需满足

Σ_g a_{g,r}(t)q_g(t)＋L_r(t)≤R_r(t)−H_r(t)，

L_r 是加载、排空等未包含在 q_g 中的占用，不能重复计入。CPU、存储出口、PCIe、互连和设备执行分别检查。只有所有阶段按固定比例消耗同一资源向量时，才可用逐资源上界的最小值简化；一般情况需要阶段队列和事件模型。

## 启动路径与可用时间

启动是依赖图：取得资源和配额；固定制品清单；读取分片；建立主机页或固定块池；转换、对齐与校验；H2D；建立完整执行组和通信上下文；建立或核对编译产物、图与工作区；隔离预热；共同验证；最后提交路由。

对事件 j，前驱集合为 pred(j)，没有额外资源争用时，最早完成时刻为

F_j＝max_{i∈pred(j)}F_i＋t_j。

无前驱事件以允许开始时刻为边界。共享 SSD、CPU、NIC 或 PCIe 的任务还要加入资源次序或带宽约束，不能同时给每个任务独占带宽并假定完全重叠。

若 rank r 的本地排队为 Q_r，本地准备为 D_r，之后共同验证为 T_group，则

T_ready＝max_r(Q_r＋D_r)＋T_group。

已经包含在 D_r 中的工作不能再加进 T_group。两个 rank 分别排队 0、1 s，本地各需 4 s，后续共同验证 0.5 s，则为 5.5 s，不能串行相加成 9.5 s。路由安装及必要确认另计：T_available＝T_ready＋T_route_check。安全拒绝过期路由保证身份，但拒绝期间不产生可兑现吞吐。

[ServerlessLLM](../sources/S-SERVERLESSLLM.md) §4 将每 GPU 张量组成顺序数据文件，用名称到 GPU、偏移和大小的索引恢复地址；主机固定块池和多阶段队列串联存储、主存与设备复制。其 §6.2 使用 q＋n/b 估计加载，其中 q 为服务器加载队列等待，n 为模型或分片字节，b 为所用流水的慢层有效带宽。该估计依赖每服务器顺序加载及反馈校准，不覆盖任意并发启动、转换、编译、预热和分布式组装，也不能将热缓存带宽用于冷启动。

数据流必须落到实际对象：存储字节进入主机缓冲，CPU 转换读写目的区，设备复制读取源区并写入 HBM，tensor 索引和执行对象引用这些地址，验证消费完成后的对象，路由提交才开放新准入。源、目的和地址绑定都必须保留到其最后使用结束。

## 合法容量、准入与资源账

部分 rank 完成、通信组未建立、图只完成一半或代表路径失败时，实例不能成为 READY，更不能成为 OPEN。对设备 d，令 U_d(t) 为同一时刻占用预算的唯一物理 backing 集合，必须满足

M_d(t)＝Σ_{o∈U_d(t)}size(o)，max_t M_d(t)≤Cap_d。

集合包括权重、adapter、KV、工作区、图池、转换与 staging、通信区、预热状态、加载目的区及未消费输出。完整池已覆盖其内部活跃对象时不能再加一次；同一物理 backing 被多个读者引用只计一次，同设备上两份独立复制仍计两次。主机、设备和存储分别建账。总字节合格还不能代替对齐、连续区间、布局和映射可行性。

一次准入需在权威域重新检查

Admit(r,g)＝g∈T ∧ state(g)＝OPEN ∧ C_g.valid ∧ σ_r∈Ω_g ∧ e_request＝e ∧ reserve(r,g)可取得。

σ_r 包含输入解释、长度、dtype、adapter 和状态范围。预留覆盖承诺的在途增长，不能只看当前 KV 字节。取得预留、登记逻辑责任和写入不可变绑定 (r,v,g) 必须共同提交；失败返回等待或拒绝，不建立半份正式请求。请求身份重试返回原决定，输入摘要冲突则拒绝。

准入先于路由提交时，即使请求消息之后才抵达 worker，也仍由原 g 履行；路由提交先发生时，旧 e 的新准入须被拒绝或重新解析。缓存路由只能提出候选，不能绕过权威门签发票据。分散租约可以替代共同状态域，但必须另证撤销、租约存活与排空的关系，不能用估计传播时间代替。

## 控制算法与三种路由提交

控制输入包括 offered 轨迹、各阶段剩余工作、当前实例与责任集合、逐资源账、启动估计、故障余量及策略参数。输出包括启动票据、准入决定、路由提交、排空与回收，以及每项未结责任。阈值、滞回、最短驻留和候选排序是策略；身份、完整执行组、资源约束和最后使用顺序是硬条件。

```pseudocode
算法 ElasticTick(now, events, policy)
1. 按实例身份、操作身份和受保护范围幂等处理真实完成事件。
   旧代次、未知操作或冲突载荷不能结算当前责任。
   READY 通知只按下述准备完成协议处理，不能直接覆盖状态。
2. 核对证书和实际依赖；失效实例关闭新准入并撤出权威目标集合。
   从当前 T、OPEN 状态及有效证书重算新准入容量和逐资源预算。
3. 按请求类和阶段估计剩余工作；保留 offered、拒绝及未完成请求。
   用当前容量和预计启动依赖推演积压与 deadline 风险。
   尚在准备或 READY 的容量仅进入预测，不能签发即时准入。
4. 需要启动且策略允许时，枚举逐 rank 资源、制品位置、执行计划、
   故障域及共享链路；先排除非法候选，再比较 T_available 和边际容量。
5. 取得完整执行组的预留后，创建新 g 和唯一 prepare_op，置 PREPARING。
   登记准备依赖及完成条件，关闭准入；预留失败则等待、换候选或拒绝。
6. 准备达到全部条件后进入 READY。根据意图分别提交 FIRST、APPEND
   或 REPLACE；READY 通知本身不执行这些路由操作。
7. 缩容使用 STOP，只移除明确选中的目标；重新检查最短驻留、
   故障后余量及排空预算，不把预计释放的资源提前借出。
8. 对 DRAINING 且 R 为空的实例，封闭全部新业务与绑定产生入口，
   进入 RETIRING；按依赖推进绑定拆除和 U/O 完成结算。
   R、U、B、O 全空且拆除完成后才归还资源、进入 RETIRED。
9. 准备或执行失败时撤销新准入，保存最早失败和未结责任；
   停止未来业务，按恢复协议结束 R，再走相同拆除与结算路径。
   新尝试使用新 g；超时不能充当设备停止或资源释放证据。
10. 若有合法等待请求却无可执行目标，明确选择有后继事件的等待、
    合同允许的降级或拒绝；记录无资源、无候选或失去完成证据的原因。
```

准备过程展开如下。

```pseudocode
算法 PrepareReplica(v, g, prepare_op, P, Ω)
1. 固定不可变清单与依赖；核对分片、索引、形状、长度、dtype、
   processor、adapter 和量化/布局元数据。
2. 按主机与每张设备求准备期唯一 backing 并集与峰值，计入旧对象、
   staging、图池、通信区和隔离预热状态；取得全组预留。
3. 按块读取并转换到受控缓冲；异步读写提交前登记源与目的使用票据。
4. 完成设备复制和 tensor 地址映射，建立相容 rank 集合与通信上下文。
5. 按真实依赖核对编译缓存、图和工作区，不能仅用模型名判断命中。
6. 在实际执行线程运行代表路径、边界和必要独立参考比较，
   核对全部必要 rank 的共同结果；预热状态不得混入正式请求。
7. 等待影响执行可读性的完成证据，清理或隔离预热状态。
   汇总同一 (v,g,prepare_op,P,Ω) 的全部必要证据后发送完成通知。
8. 任一步失败则停止后继准备、记录最早失败、排空已提交访问，
   解除可解除绑定并释放未使用预留；不能凭部分成功发布 READY。
```

READY 通知的允许源状态只有 PREPARING。接收端核对当前 g、登记的 prepare_op、证书身份与范围、全 rank 完成和依赖有效性，全部满足才执行 PREPARING→READY，并保存已接受通知的指纹。同身份同载荷的重复通知返回原处理结果，状态不变；即使实例已经 OPEN、DRAINING、RETIRING 或 RETIRED，也不能重新写成 READY。相同操作身份配不同载荷是冲突；同槽旧代次、未知操作、准备已经撤销后的首次通知均无状态效果。证书失效后到达的历史重复通知也不能恢复其有效性；重新准备使用新 g。

路由操作另有唯一 op 和不可变参数。设新增集合为 H，明确移除集合为 D；操作在同一权威排序点执行。

```pseudocode
算法 CommitRoute(op, expected_e, mode, H, D)
1. 若 op 已有提交记录：参数一致则返回原决定，不再变更状态或代次；
   参数冲突则拒绝。确认丢失时查询该记录，不能按超时反向切换。
2. 要求当前 e=expected_e；H、D 身份完整，互不相交。
   H 中每个实例必须为 READY、证书有效、资源仍已取得，
   且符合本次公开范围与版本变更授权；H 不得已经属于 T。
3. 按 mode 验证并构造目标集合：
   FIRST：要求 T 为空、H 非空、D 为空，T′←H。
   APPEND：要求 T 非空、H 非空、D 为空，T′←T∪H。
   REPLACE：要求 H 非空、D 非空且 D⊆T，T′←(T−D)∪H。
   STOP：要求 H 为空、D 非空且 D⊆T，T′←T−D。
   任一前提失败，整个操作无部分更新。
4. 在同一提交中：仅关闭 D 的新准入并置 DRAINING；
   打开 H 的准入并置 OPEN；保留 T−D 的状态与准入；
   写入 A←(e+1,T′) 和 op 的已提交决定。
5. 不改变任何已接受请求的 (r,v,g)、预留或实际访问责任。
```

APPEND 没有隐含的旧目标。两台 OPEN 追加第三台时必须保留原两台；REPLACE 才关闭指定旧目标。FIRST 处理从零容量启动，也可用于当前目标集合已经为空但旧实例仍在排空的情形，前提仍需满足并存资源账。替换部分目标可以保留其他 OPEN，滚动更新由多个显式提交组成；它不是一次跨集群的天然原子事务。

本章不通过 READY 通知重新开放 DRAINING。若需要复用尚未拆除的旧实例，应定义独立重新验证与发布操作；已经 RETIRING 的实例必须重新准备，不能仅改回状态标签。

## 无循环等待的排空与退役

为每个 g 记录四类责任：R_g 是仍可继续执行的逻辑请求；U_g 是 kernel、复制、传输及必要拆除操作的实际访问票据；B_g 是图、注册区与执行对象的地址绑定；O_g 是仍借用实例资源的输出消费者。每张票据记录实例、操作身份和受保护范围。业务取消只关闭未来业务，不能伪造 U/O 完成。

DRAINING 关闭新请求和无关联后台业务入口，但已有 R 可以按原票据继续迭代、登记必要 U，以及在已授权范围中建立所需绑定。否则“停止新准入”会错误中断旧请求。所有这些登记必须与请求结束及进入 RETIRING 的决定排序。

```pseudocode
算法 RetireReplica(g)
1. 关闭新准入并从 T 移除 g；保留全部已绑定请求和资源，置 DRAINING。
2. 对每个请求的结束、取消或合法迁移：先关闭其未来业务提交入口，
   再结算对应 R；已经登记的 U、B、O 继续保留。
3. 在权威域确认 g 不在 T、准入门关闭、R 为空。
   原子封闭准备、后台、图重放及其他新业务和新绑定入口，进入 RETIRING。
   这里允许 U、B、O 非空，不等待 B 先消失。
4. 根据每个绑定的最后使用依赖推进拆除：
   图等待已登记重放结束；注册区等待相关 DMA 与借用者结束。
   依赖完成后解除该绑定，结算对应 B。
   拆除若产生异步访问，必须先登记独立 U 票据；只允许有限的已授权
   拆除任务产生这种访问，不恢复业务入口或新增任意绑定。
5. 持续按真实证据结算 U 和 O，重复通知不重复扣减。
   U 的完成不能以“B 已经全部拆除”为前提，绑定拆除也不能等待资源归还；
   按最后使用依赖建立有向无环的后继关系。
6. 仅当 R、U、B、O 全空、拆除任务已完成且没有任何产生新责任的入口，
   销毁剩余执行对象并归还资源一次，进入 RETIRED。
7. 无法证明完成时保留隔离资源，列出未结票据与所需证据；
   排空期限触发终止/恢复策略，不能直接跳到 RETIRED。
```

一条完整组合轨迹可以检查推进性。旧 g 已移出路由；请求 r 被取消后 R 为空，但仍有 kernel k、输出 DMA d、图绑定 graph、注册绑定 reg 和输出借用 o。graph 的最后使用依赖 k；o 的交接依赖 d；reg 的解除依赖 d 和 o。

| 事件 | 状态与责任 | 后继 |
|---|---|---|
| 撤销准入，r 尚活跃 | DRAINING，R={r} | r 仍可按旧票据执行 |
| r 取消并关闭未来提交 | R=∅，U={k,d}，B={graph,reg}，O={o} | 封闭入口，立即可进入 RETIRING |
| 尝试提前拆 graph 或归还资源 | k 未完成，绑定和访问仍存活 | 拒绝，保留 backing |
| d 完成 | U={k}，O={o} | 可以完成输出交接，不能仅据 DMA 完成删除 O |
| o 完成交接，解除 reg | O=∅，B={graph} | k 与 graph 继续保护旧资源 |
| k 完成，解除 graph | R、U、B、O 全空 | 拆除结束后归还资源并 RETIRED |
| 旧 READY 或重复完成迟到 | 已保存旧决定与票据结算 | 无状态倒退、无第二次归还 |

k 与 d 可以并行，表中的先后是一种合法交错。若逻辑请求结束时要求 B 已为空才进入 RETIRING，而唯一拆 B 的动作又只在 RETIRING 中运行，就会永久停滞。若忽略 B，只凭 R/U/O 为空归还资源，则仍存活的图或注册对象会引用已经复用的地址。正确协议同时排除这两个反例。

有限责任、最后访问最终完成、拆除后继无环且事件公平处理时，退役最终可以完成。设备永久不返回、远端访问范围未知或输出消费者永不释放时，这个活性结论不成立；必须保留责任或使用有独立证明的故障隔离与中止协议。

## 条件化成本与追加扩容轨迹

| 成本 | 同一候选、同一时间范围中的计量 |
|---|---|
| 计算 | 输入处理、转换、prefill、decode、迁移重算、编译、预热、重试与失败工作；重算是完整模型工作 |
| 访存 | 存储读取、主机转换读写、H2D、图输入、KV 与输出；逻辑有效字节不能冒充 DRAM/HBM 实际事务 |
| 通信 | 制品分发、组初始化、collective、迁移、路由记录与响应；按链路、单 rank 和全组口径分别计量 |
| 准备 | 清单、索引、候选扫描、资源预留、映射、编译缓存核对、图捕获和预热；常驻与频繁切换摊销不同 |
| 同步 | 完成可见性、共同验证、准入/路由提交、最后使用与拆除；host 返回不等于设备完成 |
| 驻留 | 新旧权重、KV、图池、staging、固定块池、预热与输出借用；报告唯一 backing 峰值及字节乘存活时间 |

共享存储交付 Z_unique 字节、有效带宽 B_eff 时，纯读取下界为 Z_unique/B_eff。四个冷启动各需 12 GiB，共享 6 GiB/s 出口且没有缓存或对等分发，总读取至少 48/6＝8 s；为每个实例使用独占的 2 s 会低估共同启动。若远程只交付一次 12 GiB，远程下界可以降为 2 s，但各设备的本地读取、转换、H2D 和初始化仍须完成。

设备可用 24 GiB，旧权重 12 GiB、旧 KV 5 GiB、共同运行区 3 GiB，新权重另需 12 GiB，即使忽略新增图和转换峰值，并存仍需 32 GiB；旧 KV 排空后仍需 27 GiB。这个具体分配不能在单卡并存，应改用其他设备、合法降低表示容量或选择带空窗的停止替换。提前发布 READY 不会减少字节。

对同质请求采用流体模型，B(t) 为尚未绑定的入口积压，λ(t) 为到达率，单位分别为请求、请求/s。B>0 时 B′＝λ−μ_new；B=0 时导数取非负方向。这里假设已有占用已进入 q_g 的预算，队列可以分配给全部合格 OPEN，忽略离散请求、执行内排队和服务时间变异。

设两实例 a、b 已 OPEN，各为 20 请求/s；第三台 c 已预留并在 t=0 开始准备；到达 70 请求/s 持续 10 s，之后为 20 请求/s。

| 时刻 | 控制事件和路由集合 | μ_new | 积压 |
|---|---|---:|---:|
| 0 | T={a,b}，c 为 PREPARING | 40 | 0 |
| 10 s | c 尚未 READY，原目标保留 | 40 | (70−40)×10＝300 |
| 20 s，提交前 | c 的准备完成通知使其 READY；T 仍为 {a,b} | 40 | 300−(40−20)×10＝100 |
| 20 s，APPEND 提交 | T={a,b,c}，三台均 OPEN，e 增加一次 | 60 | 瞬时仍为 100 |
| 22.5 s | 三台继续开放 | 60 | 100−(60−20)×2.5＝0 |

容量来自实际转换后的集合。若错误地把 APPEND 实现为关闭 a、打开 c，T 将是 {b,c}，容量仍为 40，清空要到 25 s。只预先填入“20 s 后容量 60”的积分检查发现不了这项错误。

READY 比实际开放早 δ 秒时，这段时间继续使用旧容量；本例会额外保留相应积压。若要求请求 1 s 内开始服务，反应式启动远晚于多数突发请求期限，需比较热备用、预测加载或明确拒绝。若 70 请求/s 持续 60 s，追加后 60 仍小于 70，积压继续增长；平均稳定至少需要四台同等总实例，故障余量与尾延迟要求另算。

滚动更新还要单独计算故障后容量：四台各 20 请求/s，更新排空一台再故障一台，仅剩 40；到达 45 时正常更新的 60 看似足够，故障要求却不成立。PREPARING 和 READY 都不能补上差额。

控制账也有成本。扫描 N 个实例和 E 条已排序事件约为 O(N＋E)，无序事件排序另需 O(E log E)；逐请求阶段估计、逐资源预留和候选枚举另计。保存操作去重记录和责任票据需要空间，不能无限保留而声称控制内存有界。外部日志压缩或回收必须保留足够身份，防止迟到事件再次生效。这些复杂度不是 GPU 服务时间。

## 条件变化后的保留与放弃

常驻容量直接吸收突发，支付闲置驻留；热备用与分层缓存降低部分准备时间，仍占用设备、CPU 内存或 SSD；按需启动减少闲置，却需要可预测负载、较宽松目标或拒绝策略。比较时应保留相同 offered 轨迹、质量合同和完整启动/排空费用，不能只比较接受请求的延迟。

| 条件变化 | 保留的机制 | 调整或放弃的结论 |
|---|---|---|
| 突发短于启动时间 | 证书、硬准入、真实容量账 | 放弃纯反应式扩容吸收全部突发的承诺，比较热备用、预测、排队与拒绝 |
| 到达持续超过追加后容量 | 排空与故障余量 | 重算总副本及共享瓶颈；已扩一台不证明稳定 |
| 冷缓存或共享出口变慢 | 唯一字节与依赖图 | 重算启动并发和可用时间；更多 GPU 可能只增加加载争用 |
| CPU、分词或输出网络饱和 | 分阶段人口与逐资源预算 | 给瓶颈阶段扩容或限流，设备增多未必增加合格完成 |
| 低负载、高变异、设备内存受限或紧 SLO | 合法执行组和统计复用分析 | 可比较模型并行；AlpaServe 的一次前向与模拟结论不能直接外推逐 token decode |
| 持续饱和、宽松 SLO 或阶段不均衡 | 独立副本和资源约束 | 并行通信与阶段开销可能使复制更合适，重新比较合格结果 |
| 路由确认变慢 | 共同排序、代次与旧请求绑定 | READY 到 OPEN 的窗口变长；调整门控或租约，不提前计算容量 |
| 长流、工具等待或慢消费者增多 | R/U/B/O 和声明的终止协议 | 增加排空预算、保留旧版本更久或合法迁移；不能用截止时间伪造完成 |
| 版本或 adapter 更新 | 不可变对象和证书依赖 | 用 REPLACE 改变后续绑定；旧请求继续旧对象，不原地覆盖 |
| 故障域失效 | 故障分散及失败身份 | 重算剩余完整组容量，明确降载或拒绝范围 |

滞回和最短驻留解决观测延迟与反复启停。短队列下降不立即回收仍在预热的实例，短尖峰也未必值得启动几十秒后才可用的副本。参数依赖启动、排空、计费粒度与负载变化，不是跨任务常数。

ServerlessLLM §5.2 的迁移选择以目标已有相同只读模型为前提：先传中间 token 并重算 KV，再冻结源推进、补齐增量，最后移交执行。其 §6.3 用 a(t_in＋t_out)＋b 估计恢复计算，传输与提交另计。token 重算不自动恢复 RNG、grammar、递归状态、工具结果或未提交输出；需要明确共同恢复边界和唯一提交权。若目标追赶速率不高于源新增速率，追赶不收敛，应冻结、降低源推进或放弃迁移。目标 READY 也不等于已经取得业务提交权。

## 竞争解释与区分实验

| 观察 | 竞争解释 | 可控干预、预测与反证修正 |
|---|---|---|
| 第三台启动后容量仍是 40 | 尚未开放、APPEND 错做替换、证书失效或共享瓶颈 | 记录提交前后 T 与实例状态，固定 q 和资源预算；T 只有两台支持路由错误，T 三台但资源完成率不变则转查共享瓶颈 |
| READY 期间提前接受请求 | 容量漏状态守卫、路由器绕过门或通知直接开放 | 使用有效证书的 READY，保持验证不变而延迟提交；仍接受则修正准入，不归因加载速度 |
| 无效证书的 OPEN 仍贡献容量 | 只检查状态、证书撤销未传播 | 保持 OPEN 标签而撤销证书；同一参考应判容量为零，删证书守卫的变体必须失败 |
| 旧通知使排空实例倒退 | 仅按槽位、缺操作身份、重复通知覆盖状态 | 分别注入同槽旧代次、同代次错误操作和已接受 READY 的迟到重复；只有 PREPARING 的合法首次通知能改变状态 |
| R/U/O 已空却不回收 | B 有真实依赖、拆除未调度或退役入口循环等待 | 保留无在途使用的图/注册绑定；应进入 RETIRING 并执行解除，仍停在 DRAINING 则修正进入条件 |
| 取消后立即出现空闲资源 | 最后使用确实完成，或业务终态被当作物理完成 | 分别延迟 kernel、DMA、输出借用和绑定解除；归还必须等待完整责任集合，不能只看请求计数 |
| 加载慢 | 存储争用、CPU 转换、H2D、组装、编译或路由等待 | 固定模型，分别改变出口、转换线程和组大小；只有相应阶段随干预变化才支持该解释 |
| GPU 增多而吞吐不变 | 主机、网络、准入、请求不足或绑定错误 | 固定 offered 轨迹，逐阶段记录等待，再只增加对应资源；设备增加无响应时撤回纯 GPU 瓶颈解释 |
| 频繁启停 | 测量噪声、滞回不足、驻留太短或准备/排空延迟 | 同轨迹只改变滞回与驻留，关联启停次数和合格结果，不能只用利用率曲线解释 |

性能实验保留真实时间与突发相关性，记录 offered、拒绝、接受、完成、未完成、状态时间戳、路由代次、责任集合和加载资源。注入资源申请失败、缺片、预热失败、路由迟到、确认丢失和缩容中断。按[服务成本与能耗](cost-and-energy.md)的共同边界比较常驻、热备用与按需启动，费用包含等待、失败、排空与必要冗余。

## 随章检查与证据边界

交付检查为 `tools/check_k_work_008_full.py`，仅使用 Python 标准库，确定性、离线、只读。容量以完整状态/证书决策表为参考，包含有效 READY 和无效 OPEN，使分别删除状态守卫与证书守卫的变体都被同一参考拒绝。READY 模型检查允许源状态、完成指纹、重复通知、错误操作及同槽新代次，重复通知不恢复状态或资格。

路由检查执行 FIRST、APPEND、REPLACE、STOP、重复提交和过期代次，随后用实际 OPEN 转换得到的容量驱动流体队列，核对 300、100 与 22.5 s；错误替换式追加产生 40 容量和 25 s 清空，必须被目标集合与积压参考发现。它没有模拟完整候选优化器、真实 PrepareReplica 或跨节点事务。

退役模型显式保存 R/U/B/O，以外部给定的原始票据集合和依赖次序重建剩余责任，检查 10 条合法完成/解除顺序的每个前缀。保留绑定的实例既不能提前归还，也必须能够进入 RETIRING 并最终结束。遗漏 B 的释放变体和等待 B 为空才进入 RETIRING 的停滞变体均须被拒绝。共享带宽、rank DAG、主机瓶颈与驻留阈值另有可手算参考及错误负对照。

本轮作者实际执行了只读 V8 CPU 有限探针，观察到追加容量 40→60、积压 300/100、22.5 s 清空、两种容量守卫删除后错误值 27/31，以及上述 10 条退役顺序。交付 Python 脚本尚未由作者执行，须由协调者对交付字节实际运行并保留结果；这些 V8 探针不能代替该执行记录。

所有检查均为串行事件与理想完成证据的 CPU 逻辑模型，不是 GPU、PCIe、NVMe、网络、图销毁或注册解除的实测，也不证明真实数值结果、尾延迟、SLO 或知识改善了 Agent 构建效果。目标系统仍需验证权威排序、实际票据覆盖、设备最后使用证据、共享干扰、控制崩溃恢复及长流排空。
