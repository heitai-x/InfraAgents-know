# K-TOOLS-001：缺少 trace 记录不等于缺少执行

| 元信息 | 内容 |
|---|---|
| 条目标识 | K-TOOLS-001 |
| 主分类 | 工具 |
| 类型 | 观测条件与诊断依据 |
| 状态 | 已有支持；限于下述条件 |
| 来源 | CASE-0001 的受控运行与原始导出 |

## 核心认识

执行事实和观测事实是两个问题。某类记录缺失，说明当前产物没有提供这类证据；不能直接推断目标系统没有执行相应工作。

## 适用条件与机制

本次证据来自同一 RTX 3090 上、Nsight Systems 2025.3.2 对一个微型 CUDA 程序的采集。开启 tracing 时能观察到 kernel 和拷贝；关闭 tracing 后程序仍正确完成，但相应表缺失。

其他版本、部分导出、未命中采集区间或采集失败也可能形成缺口，需要各自证据区分。本案例没有逐一验证这些原因，也没有证明某个具体缺表的唯一原因。

## 可观察现象与调查依据

| 现象 | 当前可以支持的判断 | 继续调查的依据 |
|---|---|---|
| 对应表不存在 | 当前导出未提供此类记录 | 采集状态、启用信号、覆盖范围、导出条件 |
| 表存在但当前窗口无完成区间 | 此窗口没有满足条件的区间 | 窗口边界、点事件、未完成范围、实际执行位置 |
| 有事件但部分身份或字段缺失 | 可使用的关联受到限制 | 原始 schema、进程身份和需要补采的信号 |
| 程序与采集均成功退出 | 这些执行步骤正常结束 | 仍须检查产物内容及目标所需证据 |

## 证据与反例

[CASE-0001](../cases/CASE-0001-nsys-observability.md) 是“没有 CUDA 表就没有 GPU 工作”的实际反例。它支持观测边界的认识，不支持任何模型性能或设备利用率结论。

后续若某工具在确定启用、覆盖完整且无丢失的条件下定义了零计数，应按该工具的语义解释；不能把本条目扩大为“任何零计数都没有意义”。
