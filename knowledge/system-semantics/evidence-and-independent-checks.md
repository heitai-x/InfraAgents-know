# K-SYS-006：工程认识如何成为可迁移的专家知识

知识的增量是对系统机制与设计关系的新增解释；运行结果为这些解释提供事实、区分和修正。

## 从现象走到解释

“改参数后更快”记录一个现象；“减少了哪些重复数据流、为何该运行点受到它限制”才形成可迁移解释。完整关系包含对象、依赖、干预、结果和竞争解释。例如开启前缀缓存后 TTFT 下降，可由少算 prompt、请求排队变化或预热差异导致，单个平均数不能区分。

系统知识可以来自算法定义、接口契约、代数推导和实际实验。来源支持一个机制存在，目标运行支持该机制在某组条件下的具体表现。将两者连起来，需要说明模型结构、硬件路径和 workload 如何满足推导前提。

## 什么值得进入正文

值得积累的是更准确的成本关系、更清晰的状态不变量、新发现的适用分支、可复现的反例及其原因，或原本分开的机制怎样组合。一次路径错误、固定文件名和临时命令通常属于运行记录；若它揭示更普遍的版本/所有权问题，再提炼其机制。

例如一次 graph 重放串请求的经历，可以推导“稳定地址与内容代次是两项独立契约”，并说明双缓冲何时足够、三个在途代次为什么还会冲突。这比增加一句“注意同步”提供更多设计能力。

## 独立核对的作用

实现者解释可能与其代码共享同一错误假设。诊断从任务函数、独立参考和原始执行观察出发，检验候选解释的可区分预测。局部 kernel 数值一致支持该 kernel 的某些输入范围，端到端 SLO 支持整个路径的一个运行点，各自都不能替代另一层证据。

RSI 的下一次使用是继续检验和扩展理解的机会。成功可能提示条件更广，失败可能揭示遗漏机制，也可能只是代码没有遵循知识。将后一种失败错误地当作知识反例，会让系统丢弃正确原理；将任务整体成功给所有被读条目记功，则会强化无效经验。

## 修订应保留推导能力

更新一个章节时，保留仍成立的对象模型、公式、布局和设计分支，把新认识放到它改变的地方。修订理由解释发生了何种认识变化。历史用于理解演化轨迹；正文应保持可独立阅读，而不是不断堆积时间顺序的日志。

## 把论断定位到它真正得到支持的位置

一篇论文可以支持一种算法定义，却未必支持某个 GPU、负载或生产配置上的速度判断。知识正文中的关键论断应能够追溯到固定来源的具体机制段、接口条款、推导前提或对应观测。只在章节末列出十个来源，不能说明哪个来源承担了哪个结论。

例如“分层存储可以扩大可驻留模型范围”与“本任务通过卸载降低尾延迟”是两个论断。前者可由容量分配关系解释，后者还需要排队、传输、预取和并发测量。将实验条件从低并发改为高并发后，容量关系仍成立，性能结论却可能反转。修订应改变受影响的论断范围，而非把整篇标成全部正确或全部错误。

来源的实际版本、编辑日期、实验观察日期分别记录。今天可以依据截止前的来源整理新的代数推导；今天观察到的工程事实应保留今天的日期，不能借引用旧论文把新观察放回历史 seed。

## 冲突先分辨函数、条件与证据层次

两个来源看似冲突时，先比较其目标函数与状态：吞吐和首 token 延迟、无损与近似、热缓存与冷启动、单请求与开放到达都可能不同。随后比较硬件拓扑、模型形状、实现成熟度和测量边界。只有共同条件下的互斥预测，才构成需要裁决的机制冲突。

一种有效的反例应能说明被反驳的具体量词。一个短请求上卸载更慢，可以反驳“卸载总会更快”，不能反驳“卸载在容量不足时提供可执行路径”。若失败来自实现违反已写明的所有权条件，应记录实现偏离与诊断证据，不能据此删除正确的资源回收原理。

## 跨机制组合需要新的核对

分别验证前缀缓存、量化、异步和迁移，不代表其组合已经验证。组合可能改变身份、恢复位置、scale 生存期、消费者完成点和随机状态归属。可沿共同边界组织检查：先确认各组件输入输出契约，再构造会触发交互的最小状态，最后在真实负载上验证资源和 SLO。

例如将量化 KV 迁到另一个实例，必须同时验证编码版本与元数据、分片布局、传输完整范围、目标可见性及旧实例的回收权。只对比传输字节哈希不能证明模型消费方式相同；只对比一次输出也不能证明取消或重试时不会释放在途状态。

## 怎样检验知识对设计过程的帮助

读取记录证明某个版本被访问，不能证明内容被理解、正确使用或造成收益。要研究知识本身的贡献，可以固定模型、任务族、资源、预算与评价规则，比较不同知识条件，并按任务或随机种子配对。生成过程存在随机性，单次最优结果不能代替多次结果分布。

评价同时覆盖设计正确性、完成率、满足质量/SLO 的有效产出、试验与实现成本，以及错误类型。需要区分知识帮助发现方案、缩小错误分支和改善最终引擎三种作用。对多轮搜索后的获胜方案，独立保留任务或轨迹用于最终评价；[实验统计](../tools/statistical-experiments.md) 解释搜索选择偏差和配对关系。

如果新增知识只减少错误尝试而没有提高最终吞吐，它仍可能改善构建效率，但结论应写在相应指标上。若差异在独立任务上消失，应收窄迁移范围，不能用一次被选中的成功运行替所有章节记功。
