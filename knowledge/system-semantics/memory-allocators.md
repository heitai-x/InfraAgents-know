# K-SYS-012：内存分配：地址、容量与在途所有权

分配器管理的不只是空闲字节，还包括地址稳定性、布局约束、共享引用和异步消费者的生命期。请求完成不等于设备最后一次访问已经结束；对象需要一页，也不等于系统必须再取得一页物理 backing。本章把容量准入、准备、发布、访问和回收接成一个可重建的协议。

## 问题、对象与不变量

固定容量的设备内存同时容纳权重、KV、递归状态、工作区、图缓冲和传输目的区。它们的生命期不同，一些对象还被多个请求或异步消费者共享。分配器要回答：谁有资格使用哪个版本，访问哪段地址，实际持有哪些物理页，何时可以覆盖或归还。

物理分配身份记为 x=(space,fid,e,size,compat)，其中 space 是设备或存储域，fid 标识物理区间，e 是该区间的分配代次，size 以字节计，compat 包含粒度、对齐、设备、权限和注册条件。逻辑对象版本 v 的页表为 P_v(j)=(fid,e,range)。同一物理区间的别名必须合并保护，不能只按 tensor 名字建账。请求尝试代次、对象视图版本、物理分配代次和操作身份是不同坐标。

对一个分配生命期 x，维护：

- L_x：逻辑持有票据集合，票据包含拥有者实例、对象版本及逻辑映射身份；不是可以被任意通知递减的整数。
- U_x：已经取得启动资格、尚未证明最后访问结束的责任集合，包括准备、kernel、复制、DMA 和输出读取。
- H_x：准备事务的保留票据，例如 COW 源页的快照保护。
- B_x：仍有效的未来绑定，例如允许继续重放的图地址资格。
- Q_x：未解决的隔离原因及解除条件。

拥有者实例另有 OPEN/CLOSED 资格。该记录在首次准备开始时就存在，不能等首次发布才创建。一个 OPEN 的拥有者可以尚无可见视图；一个 CLOSED 的拥有者可以仍有正在排空的准备或读取。关闭 A 只撤销 A 的资格和持有，不关闭共享页上 B 的资格。U 是否为空描述当前访问，不能替代未来访问资格。

本章采用以下不变量。

1. 唯一容量：同一 backing 在同一存储域只计一次。多个只读引用不产生多份容量，独立分配的相同内容仍是两份容量。
2. 发布门：页表、权限、初始化、必要复制及可见性齐备后，才一致发布对象视图；不能把某一层成功解释为全层成功。
3. 回收门：分配生命期已关闭，且 L=U=H=B=Q=∅，才允许解除旧访问路径并复用物理区间。映射撤销自身若异步，也必须取得其完成证据。
4. 登记先于提交：访问取得启动资格与资源保护必须先于实际提交。提交接受状态未知时保留责任，不能按错误返回推断未启动。
5. 操作身份不复用：同一作用域内的 uid 一旦登记，完成后也不能代表另一项工作。重复登记只能查询原操作，不能取得第二次提交资格。
6. 完成有身份：完成证书只结算匹配的操作及其完整访问集合。重复通知不能抵消另一访问，旧代通知不能清除新代票据。
7. 地址稳定与内容稳定分开：固定虚拟地址不证明内容版本、权限和所有者正确。
8. 事务失败只撤销本事务未提交的工作与承诺；已提交访问、源、目的及其地址路径继续受保护，直到最后访问有证据结束。

统一池、按生命期建池、页长、缓存保留阈值、同步还是后台映射，是这些约束内的设计选择。

## 容量准入：对象需求、复用与新增 backing

设区域 g 本次需要覆盖 r_g 字节，分配粒度为 G_g。先计算每个区域缺少的逻辑分配单元，再形成本次目的页需求集合 N。区域已有、可继续使用的页不属于 N；共享尾页需要 COW 时，其私有目的页属于 N。不同层的 K/V、不同状态族和不同设备分别取整，不能把总字节只舍入一次。

N 的字节数是对象需求 C_need，不是新增物理字节。分配器为 N 寻找兼容的 CACHED_FREE 页，得到复用集合 R；未被 R 满足的部分才需要新 backing A。兼容要求包括大小、对齐、设备、权限、地址绑定及旧访问已结束；总缓存字节足够并不证明存在合法匹配。

令 F_hold 是当前持有的唯一 backing 集合，E 是已经确认安全归还且在本次新增前完成归还的集合，A 是必须新取得的物理分配，J 是其他尚未兑现、也未包含在 F_hold 中的容量承诺。保守准入检查为：

C_plan = bytes((F_hold∖E)∪A)+bytes(J)+M_margin ≤ C_cap。

新 backing 在实际取得前以唯一承诺占预算；取得后从承诺转到 F_hold，不能两边同时计费。并发事务选择缓存页、登记承诺与检查预算必须串行化或原子提交。不能让两个事务都把同一缓存页或同一剩余预算当成自己的资源。

若准备过程中有先取得后归还的交叠，必须检查整条计划的 max_t C_plan(t)，不能只检查最终集合。未排空的旧源页不属于 E；选择驱逐也不等于已经归还。失败后新取得的 backing 可以安全归还系统，或按缓存策略保留；后者仍占容量，但不再是泄漏的事务预留。

按互斥分类显示物理容量时，可写为：

C_hold=C_active+C_preparing+C_cached+C_draining+C_quarantined+C_other。

每页只进入一个显示桶。C_other 包括尚未被其他桶覆盖的权重、工作区、图池和传输区。初始化或 COW 目的页若已在 C_preparing 中，就不能再作为在途目的区加一次；在途访问发生在已有页上时只增加 U，不增加容量。图池若已作为池总 backing 计入，也不能再加其中 tensor 的容量。纯虚拟地址预留 V 不进入物理账。

M_margin 表示上述集合与承诺之外的外部需求或不确定性余量。已明确预留、已经在 F_hold 内的备用页只计一次；若把它们叫作 guard，就不能又以相同字节加入 M_margin。已从 C_cap 扣除的系统占用也不能再扣一遍。

缓存占满预算的反例：C_cap=128 KiB，池中两个兼容的 64 KiB 页均为 CACHED_FREE，其他项及余量为零。申请一页时，C_need=64 KiB，R 有一页，A=∅。分类从 cached=128、preparing=0 变成 cached=64、preparing=64，C_hold 始终为 128 KiB，可以准入。使用 C_hold+C_need 会错误拒绝。若两页均不兼容且不能先安全归还，则需要新增 64 KiB，当前计划应拒绝或等待。

容量足够只是必要条件。物理连续区间、虚拟地址可用性、页粒度、权限及设备能力仍须独立满足。

## 拥有者、页状态与串行化边界

拥有者资格、事务状态和物理页状态分开维护。表中的状态是物理分配的概览，U、L、H、B、Q 保留实际责任身份。

| 页状态 | 含义与后继 |
|---|---|
| FREE | backing 不由本分配器持有；取得后进入 RESERVED |
| CACHED_FREE | 分配器持有，旧责任已清空，满足兼容条件才可转为 RESERVED |
| RESERVED | 目的页被一个事务独占，映射或权限尚未齐备 |
| MAPPED | 私有映射和权限齐备；允许受控准备访问，尚不允许普通消费者登记 |
| PUBLISHED | 有有效视图或保留资格，当前 U=∅；活跃拥有者可以继续登记 |
| IN_USE | 已发布页上 U 非空；部分完成后仍可为合法拥有者登记不冲突访问，U 清空后回到 PUBLISHED |
| DRAINING | 本分配已无可启动新工作的资格，或目的事务已中止；保留未完成责任，排空后才回收 |
| QUARANTINED | 缺少最后访问或撤销证据；仅凭明确解除条件离开，不能按超时释放 |

准备页上的 U 与 RESERVED/MAPPED 正交；初始化、复制不是普通发布后访问。一次读取完成不会关闭仍活跃的对象。A、B 共享页时退役 A，若 B 仍持有引用，则页保持 PUBLISHED/IN_USE，B 可继续工作。只有最后资格真正消失，才进入排空；长期绑定存在时，应先关闭其未来使用权，再解除绑定。

拥有者实例由请求身份和尝试代次组成，关闭后不重新打开。新的请求或执行尝试必须取得新实例身份。首次预留前先检查该实例是否已关闭；首次准备登记与拥有者 OPEN 记录在同一串行边界内建立。若退役先于任何预留到达，也保留 CLOSED 记录，阻止迟到的预留重新创建 OPEN。容量不足而没有启动准备，不必制造任何设备访问。

本章选择一个串行状态域作为基线：预算与空闲表、拥有者资格、视图版本、操作登记表、最后逻辑引用撤销、事务提交/取消及回收检查由同一事件循环或互斥事务保护。真实设备工作在域外执行，完成证书回到域内结算。

BeginAccess 先检查 OPEN 和当前视图，再把完整 U 写入，整个操作有一个线性化点。RetireOwner 在相同域内关闭拥有者、中止准备、撤销其 L 并检查回收。登记若先发生，退役会看见 U；退役若先发生，新的登记与发布均被拒绝。不能先检查引用为空、解锁，再允许另一个线程登记旧对象。多设备实现需要等价的协调协议；本章单域模型不证明任意分布式原子提交。

## 准备、COW、发布与失败收尾

事务 tx 保存：目标拥有者实例和预期旧视图版本、目的页清单、每页取得来源、私有映射与权限、源保留票据 H、准备操作及其接受/完成状态、未兑现容量承诺和提交状态。增长与视图替换采用已发布历史不可变、私有目的页准备的基线。独占页原地追加也是候选，但需要另证读写范围、有效长度和失败恢复；独占标量写检查不构成完整 KV 原地追加证明。

```pseudocode
ALGORITHM AllocateAndPrepare(owner, expected_version, region_demands)
输入：拥有者实例及预期视图版本；逐区域需求、布局与设备合同；池与预算
输出：PREPARING 事务，或 WAIT/REJECT；失败可能留下受保护的 ABORTING 事务

1. 校验非负需求、正粒度、对齐、权限与设备支持。
   空需求允许形成空视图，不分配页，不伪造设备访问。
2. 在串行域内检查 owner：已有 CLOSED 记录则拒绝；
   已有对象须 OPEN 且版本匹配；新实例在开始准备时登记 OPEN。
   形成新视图计划：保留可共享页；为新增范围和 COW 目的区列出 N。
   对将被复制的旧页取得 tx 的 H，保持其内容稳定。
3. 匹配兼容缓存 R，计算新增 backing A 和整个准备阶段的容量峰值。
   原子检查预算、独占 R 并登记 A 的容量承诺；不足则撤销本次 H 后返回。
4. 逐项取得目的页并记录日志；取得新 backing 时将对应承诺转为实际持有。
   失败立即转 Abort，不修改旧对象页表或旧 L。
5. 为目的页建立私有映射、权限和有效范围描述；逐项记录结果。
   不在原消费者仍使用的同一虚拟地址上提前重映射旧页。
6. 为初始化、复制和必要元数据生产分配不复用的操作身份：
   读集合含实际源页，写集合含私有目的页及辅助缓冲。
   在串行步骤中校验 owner 仍 OPEN、tx 可提交、源稳定、目的独占、
   范围与依赖合法；登记操作描述及全部 U，然后才授权一次实际提交。
   明确未接受的提交可撤销 U，但该操作身份仍保留终态，不能重新代表新工作。
   已接受或接受状态未知的提交必须保留 U。
7. 收集每项最后访问及成功/可见性证据；业务失败不发布部分数据。
   全部必要区域齐备后得到可提交视图，调用 Commit。
```

共享源页的写入与复制读取必须有序。H 保证源存活，内容冻结或冲突依赖保证源版本稳定；只有保留容量而没有版本稳定性，复制仍可能混入新旧内容。复制有效行时，还要复制解释这些行所需的位置、有效长度、scale/zero-point 等元数据。空槽残留不能成为有效数据。

```pseudocode
ALGORITHM Commit(tx)
输入：完成准备的事务；预期旧视图及版本
输出：新视图，或转 Abort

1. 在串行域内检查 tx 仍 PREPARING、未取消、owner 已登记且仍 OPEN，
   当前视图仍等于预期版本，全部生产成功且对消费者可见。
   任一条件失败则 Abort；不得只凭 U 为空推断生产成功。
2. 为新视图建立完整 L；将目的页的 tx 独占资格转换为对象持有。
3. 原子切换对象页表和版本，再撤销该对象被替换旧视图的 L。
   其他拥有者、显式旧快照和已登记旧访问继续保护旧页。
4. 释放 tx 的 H 及已兑现的事务承诺，标记 COMMITTED。
   对失去最后资格的旧页执行回收门检查。
   发布不创建或重新打开 owner 的资格。
```

第 2–3 步是同一提交边界，域外不能观察中间状态。若需要多个旧快照继续接受新访问，应为每个快照保留独立 L 和资格；本基线切换后，旧视图只允许已经登记的访问完成。并发准备针对同一旧版本时，至多一个事务能成功提交；另一个应重新规划或中止。

```pseudocode
ALGORITHM Abort(tx)
输入：准备失败、提交失败或取消
输出：ABORTED，或仍占容量的 ABORTING/QUARANTINED

1. 在串行域内关闭 tx 的新提交与发布资格，撤销未提交任务及未兑现承诺。
   不扣除旧对象的 L，不改旧页表；对象本身退役是另一个明确操作。
2. 未参与任何已接受访问的私有页可撤销映射并安全归还。
   对已接受或接受状态未知的访问，保留源、目的、辅助缓冲、U 和访问路径。
3. 按实际最后访问证据结算准备责任。错误或取消不等于排空。
   证据无法取得时添加带原因的 Q；保留保护，不按超时复用。
4. tx 的全部实际访问结束后，撤销私有映射与权限，释放 H，
   将目的 backing 归还缓存或系统，标记 ABORTED。
   操作终态记录继续服务重复登记与完成去重。
   映射撤销失败或仍有其他责任时继续保留并隔离。
```

若固定地址合同不允许建立新私有地址，不能直接套用原子指针切换。可选择先关闭并排空所有旧地址消费者，再进行受支持的重映射；或使用固定 arena 中的间接表、双缓冲或图更新。每个选择都改变同步、地址和容量账。

## 访问、完成和共享拥有者退役

操作身份 k 由分配器责任域、拥有者实例或准备事务作用域、局部 uid 组成。同一作用域内 uid 永不代表第二项操作。不同作用域可以使用相同局部数字，但完成处理不能只比较这个数字。新操作必须取得新的完整 k；同一操作的调用重试、提交状态查询和重复完成继续使用原 k。

操作登记表 O[k] 保存不可变描述 D、登记/接受/结束状态及结果收据。D 包含对象视图版本、规范化后的完整访问集合 {(space,fid,e,range,mode)}、准备事务身份、生产依赖，以及影响实际工作的内容版本或输入描述。相同 k 携带不同 D 属于身份冲突，不能解释成重试。别名应先合并，访问整页的模型可把 range 固定为 [0,G)。

O 与 U 的生命期不同：U 只保存未结清的物理访问；O 在 U 删除后仍保存足以识别已结束操作的记录。基线保留全部终态记录。若要压缩或回收记录，必须证明旧身份再也不能获得提交资格，例如关闭不复用的作用域并保留关闭墓碑，或用单调编号与不可回退的拒绝水位拒绝全部历史编号。仅以页 epoch 未变、U 中找不到 uid 或时间已过一段作为依据，均不充分。无法保存旧结果时可以拒绝历史重试，不能把它重新当成 NEW。

```pseudocode
ALGORITHM BeginAccess(owner, view_version, accesses, uid)
输入：拥有者实例；对象视图版本；底层范围、代次及读写模式集合
输出：NEW 收据、原操作的 RETRY 收据，或拒绝

1. 规范化描述 D，构造完整操作身份 k。
   在串行域内查 O[k]：
       若存在且描述不同：拒绝，无状态变化。
       若存在且描述相同：返回原状态与收据，不创建 U，不授权再次提交。
2. 对新操作检查 owner 已登记且 OPEN、版本匹配，全部页已发布且范围合法。
3. 检查实际读写冲突及生产依赖；共享页不得无序原地写入。
   合并别名；不得漏掉 workspace 或辅助缓冲。
4. 原子写入 O[k] 与整项操作的全部 U，返回一次性的 NEW 启动资格。
   实际提交者只消费该资格一次；重复 RPC 或轮询不重新执行。
5. 明确未接受、已接受及接受状态未知分别登记。
   只在确定未接受时撤销尚未发生的责任；再次执行仍需新身份。
```

受控准备登记使用同一操作表和去重规则，只把普通视图授权替换为 tx 的源保留、私有目的页及准备资格检查。不能只给普通读取实现完成幂等，而让初始化或复制重试绕过它。

```pseudocode
ALGORITHM Complete(certificate)
输入：完整操作身份 k、描述 D、最后访问证据、业务结果和可见性
输出：结算、幂等忽略，或保留责任并诊断

1. 查 O[k] 并核对不可变描述、作用域及证书覆盖的全部访问。
   未登记或描述不匹配：不修改现有责任。
   已结束且匹配：返回原终态，无状态变化。
2. 只有最后访问结束证据充分，且对应各分配代次和 U 均匹配时，
   才在一个串行步骤中移除本操作的全部 U，并把 O[k] 改为已结束。
   不能逐页移除一半后才发现另一页证书不匹配。
3. 失败结果可以结清物理访问，但不能使不完整数据进入发布路径。
   若 Q 仅由本责任缺少完成证据引起，匹配证据只解除这一个原因。
4. 有合法拥有者时，根据 U 是否为空保持 IN_USE 或回到 PUBLISHED。
   中止事务继续失败收尾；无未来资格时执行回收门检查。
```

```pseudocode
ALGORITHM RetireOwner(owner)
输入：关闭该拥有者实例未来工作的决定
输出：该拥有者 CLOSED；部分页仍可能被共享或排空

1. 在串行域内建立或更新 owner 的 CLOSED 记录。
   首次发布尚未发生、当前没有视图、甚至预留尚未来到，都不跳过关闭。
   重复退役幂等；不复用此 owner 实例。
2. 禁止新的访问、分享、准备提交和发布。
   查找属于 owner 的全部 PREPARING 事务并调用 Abort。
   已接受准备保持 ABORTING，源、目的、映射和 U 保留到结束。
3. 若 owner 有可见视图，一次性撤销其各逻辑持有并删除该视图；
   若没有视图，此步为空，但前两步仍必须执行。
4. 对涉及的每页：
   若仍有其他拥有者，继续允许其合法访问，不因本次退役转为 DRAINING。
   若仅有未来绑定，先保留它，再由其责任方明确关闭和解除。
   若已无未来资格但 U 或 Q 未清空，保持 DRAINING/QUARANTINED。
   若回收门全部满足，完成旧映射撤销，关闭旧分配身份，递增 e，
   加入兼容缓存或归还系统。
5. 完成事件继续按原操作结算；完成和发布均不得重新打开 CLOSED。
```

引用归零但旧 DMA 写入仍在途时，不能回收。递增 e 可以阻止旧完成事件结算新责任，却不能阻止旧 DMA 对同一物理地址写入。安全路径必须等待最后访问，或取得平台明确支持的整个访问域停止/撤销证据；代次不是物理写屏障。

## 一条共享、复制、取消和复用轨迹

设预算 128 KiB，两个 64 KiB backing 已预分配。P 保存值 7，A、B 共享 P；Q 是兼容缓存页。以下均为设定轨迹。

| 事件 | 视图与责任 | 容量分类 |
|---|---|---|
| 初始 | A→P，B→P，L_P 有两张票据 | active=64，cached=64 KiB |
| A 准备 COW | Q 转为 tx 私有，H_P 保护源；A、B 仍指向 P | active=64，preparing=64，持有仍为128 KiB |
| 复制接受 | U_P 有源读，U_Q 有目的写；Q 尚不公开 | 同上；不能因复制在途再加一份 Q |
| 复制中取消 tx | 禁止发布，旧 L 不变；源、目的及映射均保留 | Q 为 draining，物理持有不下降 |
| 复制完成 | 匹配证据结清两端 U，操作表保留终态；撤销 Q 私有映射，释放 H | active=64，cached=64 KiB；A、B 仍读7 |
| 以新操作身份重试并发布 | 重新预留 Q、复制完成后原子改 A→Q；此时才撤销 A→P | P、Q 各64 KiB，active=128 |
| A 更新独占 Q 为9 | 更新须独占且无冲突读者；B 仍读 P 的7 | 持有仍为128 KiB |
| 退役 B | 若 P 还有已登记旧读取，L_P=∅ 但 U_P 非空 | P draining；不能提前给下一请求 |
| 最后旧读取完成 | P 回收并改变代次；A 的资格不受影响 | active=64，cached=64 KiB |

若复制完成后、发布前才取消，处理相同：旧对象引用尚未转换，Q 可在所有访问结束后回收。若取得 Q 后、建立某层映射时失败，则按日志撤销已完成的私有映射；不存在异步访问时可以立即收尾，存在访问时必须走排空分支。

完成幂等还必须在不复用物理页的情况下成立。保持 A OPEN、P 的 e 不变，读取 k=(A,42) 完成后，U 中删去它，但 O[k] 保留 DONE。再次登记相同 k、相同描述只返回 DONE 收据，实际事件账没有第二项事件；相同 k、不同写入描述被拒绝。另一次读取必须使用 k'=(A,43)。重放 k 的旧完成证书不能删除 k' 的 U；即使随后退役 A，k' 仍阻止回收。只保留在途 uid 的错误实现会把第二次 42 当成新工作，旧证书随即误删它的责任；物理 e 完全不变，因此增加物理代次检查不能修复这个反例。

首次发布前的退役有三个不同收尾分支：

| RetireOwner 到达点 | 立即结果 | 保留与终态 |
|---|---|---|
| 首次取得目的页，尚未提交初始化 | owner CLOSED，无可见视图，事务中止 | 无实际访问时撤销私有准备并回收 |
| 初始化已接受且仍在途 | owner CLOSED，无可见视图，tx ABORTING | 保留目的映射及 U；初始化结束后回收，不能因成功结束而发布 |
| 初始化完成但尚未发布 | owner CLOSED，无可见视图，tx ABORTED | 目的页安全回收；迟到 Commit 和初始化重复证书不能恢复资格 |

这些检查必须从 RetireOwner 入口触发。直接调用 Abort 可以验证事务排空，却不能发现“没有已发布视图就跳过退役”的入口错误。

## 从对象生命期到碎片与组织选择

权重通常随模型版本存在；KV 和 recurrent state 随请求、分支或可复用前缀存在；工作区随执行阶段存在；图缓冲和通信注册区可能跨迭代存在。分池可减少生命期互扰，但硬划分可能让一个池空闲、另一个池停滞。固定权重池8 GiB、KV池8 GiB时，权重池空闲6 GiB而KV还需3 GiB，硬划分仍会失败。借用要求页字节、权限、对齐和未来回收合同兼容。

设申请量 r_i，舍入占用 a_i，内部碎片 W_int=Σ(a_i−r_i)。外部碎片表现为总空闲足够，却没有满足连续性、对齐或映射条件的区间。两个64 KiB空闲块不能保证满足一个128 KiB物理连续申请；应用块表则可能合法组合它们。尚未合并的 buddy 块与确实不相邻的块也应分别诊断。

| 组织 | 数据访问 | 主要容量与成本交换 |
|---|---|---|
| 连续预分配 | base加逻辑偏移 | 索引简单、地址稳定；按上界占物理容量时付出未使用槽和外部碎片 |
| 应用块表 | 逻辑块→物理块→页内位置 | 等大块便于共享/COW；kernel 要处理间接取址，主机要准备块表 |
| 虚拟连续、按需 backing | 连续虚拟地址→设备页表→物理页 | 保留连续接口；逐区域舍入，付出映射、权限、同步及TLB成本 |

块长 B 个 token、每token状态 c 字节时，非空请求长度 L 的尾部浪费为：

W_block=(⌈L/B⌉B−L)c；L=0 时为0。

L=31、B=16、c=128 KiB时，分配4 MiB，有效3.875 MiB，浪费128 KiB。块表、引用和其他元数据另计。

虚拟映射尾部为 W_virtual=Σ_g(⌈r_g/G_g⌉G_g−r_g)。设32层，每层K和V各2 KiB/token，31token时有64个62 KiB区域。G=64 KiB时共浪费128 KiB；G=2 MiB时共浪费130154496字节，约124.14 MiB。若先合并全部区域再按64 KiB舍入，会错误得到0浪费。层数、状态族和是否分别分配共同决定乘数。

[vAttention v1](../sources/S-VATTENTION.md) §5–6 为每worker各层分别预留K/V虚拟张量，请求占不重叠子区间，物理页按需映射。该版本更小的64/128/256 KB分配依赖修改开放部分的驱动；论文所述标准CUDA接口2 MB粒度是其版本背景，不能推广成任意设备能力。§6.2 预映射未来需求并延迟回收，每轮消费前仍检查当前映射真实完成，来不及时同步补齐。虚拟连续不消除GPU地址翻译，也不自动提供共享、COW、跨机迁移或SSD换入。

[PagedAttention](../sources/S-PAGED.md) §4.1–4.4 使用固定token块、块表和块级COW。块从左到右填满后才增加下一块，把每请求的槽位浪费限制在最后一块以内。引用计数负责逻辑共享；本章的准备事务、物理访问票据和原子发布是对异步组合的独立推导，不声称论文给出了相同协议。其§7.1报告当时块化attention kernel比高度优化的连续实现延迟高20–26%；§7.2在ShareGPT上观察16–128较好，Alpaca短序列上16和32较好，选择16。这些限定于其2023年A100、模型、kernel和轨迹。

块表准备的CPU开销另有出处：[S-VATTENTION](../sources/S-VATTENTION.md) §3.3.2 报告其早期实验中当时vLLM的块表准备曾占decode迭代延迟约30%，一次修复后仍可高至约10%。该段指出当时二维补齐块表的准备量随batch_size×max_num_blocks增长。两个数字属于vAttention作者对当时实现的观察，不属于2023年PagedAttention论文，也不是本章实测。

## 条件化成本：工作、关键路径与驻留

成本应在同一输入、候选和时间窗内分开计量。

| 成本 | 主要量与边界 |
|---|---|
| 计算 | 空闲结构搜索、块表构建、索引、引用/操作表更新；线性扫描为O(缓存页数+需求页数)，尺寸桶降低查找但增加维护 |
| 访存 | 块表与页表读取、清零、COW源读和目的写、元数据；共享容量去重不等于多个query的读取也去重 |
| 通信 | 跨设备或主机迁移、staging、协议元数据；同一链路上并发需求共享带宽 |
| 准备 | 取得backing、映射与权限调用、计划和图池创建、操作描述规范化；须注明每模型、每层、每请求或每步的频率 |
| 同步 | 生产可见性、跨stream依赖、发布门、最后访问、撤销映射及排空；host返回不能替代设备完成 |
| 驻留 | 活跃、准备、缓存、旧版本、draining、隔离、图与工作区的唯一backing；另计操作终态及拥有者墓碑的元数据 |

设本次新增映射页数m_g，每次映射成本c_map(G_g)，则串行近似 T_map=Σ_g m_g c_map(G_g)+T_sync。这里数的是本次确实需要映射的页；已经兼容映射、可直接重用的页不应重复收取同一工作。批量调用、后台并发和驱动内部行为会改变近似。

若距消费有slack S，并且资源与依赖允许重叠，暴露等待近似max(0,T_map−S)。它没有消除后台线程、调用量和提前驻留。vAttention §6.2 的设定中，60层一次扩展需要120次vMemMap，每次约9微秒，合计约1毫秒；这是来源测试床报告，不是目标机器保证。大页可能减少调用次数，却增加逐层尾部容量；小页减少尾部却可能增加调用、TLB和管理成本。

COW复制有效D字节，至少产生D字节源读和D字节目的写；若清零、转换和scale复制另有工作，也应计入。共用同一内存资源时理想流量时间下界为2D/β，不能给源读与目的写各自一份独占总带宽。复制整页与仅复制有效行是不同方案，不应采用前者的实现和后者的流量。

COW源目的同时存活：活跃目的需求增加一个复制粒度；若目的从已计入的缓存取得，设备总物理持有可以不变，但可再分配缓存减少。若必须取得新backing，设备持有峰值才增加相应字节。外部工作区或staging只在未被上述页覆盖时另加。失败后的排空也延长这些页的驻留。

总峰值为M_peak=max_t bytes(F_hold(t))，而不是各类独立峰值的和。权重8 GiB、KV2 GiB、工作区0.5 GiB、图池1.5 GiB、独立复制目的0.25 GiB、未被其他项覆盖的缓存0.5 GiB，只有同时存活时才得到12.75 GiB的设定峰值。驻留积分∫C_hold(t)dt描述延迟回收的容量时间占用，单位byte·s，不能直接加到毫秒延迟。

操作描述含a_k个规范化访问区间时，登记及完整证书核对至少要处理这些区间。哈希表通常可使身份查找接近期望O(1)，但描述比较仍有O(a_k)工作，最坏查找和串行域争用另计。保留N个操作记录的元数据约为Σ_k(b_fixed+a_k b_access)，字节常数由编码决定；不能因U已空就把这项驻留当成零。单调水位可以压缩历史拒绝信息，但乱序完成、仍需返回旧结果以及未结束操作会限制压缩。若没有安全的记录回收证明，应保留记录或限制该作用域接收新工作，不能通过遗忘身份换取错误的二次提交。

回收时间近似为T_stop+T_drain(U)+T_unmap+T_return。等待可能与计算重叠，但容量在最后责任和撤销证据结束前仍被占用。已选择驱逐、free入队和可无序复用是三个不同边界。

## Stream、图、工作区与方案反转

stream-ordered allocator 把分配和释放纳入执行顺序。设A分配并写入，B等待A后读取，释放stream F却只等待A：生产消费已排序，但B读取与释放没有排序。F必须覆盖B最后使用；有B、C两个读者时要汇合两条路径，不能按host发起时间猜最后读者。设备能力、跨stream使用与混用free规则须按固定版本确认，不推断任意free都会排空设备。

[PyTorch CUDA语义](../sources/S-TORCH-CUDA.md) 区分等待生产stream和通知allocator跨stream使用：前者保证执行顺序，后者保护生存期。缓存释放不触发设备同步；memory_allocated与memory_reserved口径不同，empty_cache只释放未用缓存，不释放活跃tensor。

固定文档中的CUDA Graph重放使用相同虚拟地址；图私有池随图及捕获期间创建的tensor保活。图总按捕获顺序、且不并发重放是一种共享池安全情形；互不依赖输出的独立图也可在不并发时共享。共享池仍可能覆盖另一图输出，所需输出应先复制并保护到复制读取结束。图内存节点的GPU顺序生命期是另一机制，不能把固定地址一律推断成永久独占物理页。

顺序算子可以复用workspace；并发执行使生命期重叠，原计划必须重算。一个workspace配依赖、每执行一个workspace、按已证明不重叠范围分区，分别交换同步、驻留和范围证明。增加缓冲只增加并发候选，不保证设备资源足以重叠。

条件改变后保留身份、发布和回收不变量，重新选择组织：

- 固定短请求长度且块长已经大于请求时，继续增大块长会增加尾部浪费，并可能降低共享机会。容量宽裕、共享少、连续kernel较快且准备更简单时，连续池可能占优；尾部浪费本身不独立证明反转。
- 长短混合、高前缀复用使细块的容量和COW粒度更有价值，但要同时计块表准备和kernel取址。
- 层数或独立K/V区域增多，逐区域舍入和映射调用乘数增大。小页依赖的能力不可用时，必须换合法粒度、组织或后端。
- 迭代缩短、一次跨多个页边界或后台资源不足时，映射可能超出slack；减少预取、预映射、批量映射或改块表后重新检查峰值与等待。
- 取消多、传输慢或完成证据缺失会扩大draining/隔离驻留。应降低并发、限制预取或恢复访问域，不能用更激进的早回收维持准入。
- 长生命期作用域操作很多时，终态记录可能成为主机元数据成本。可采用有证明的水位压缩、分段关闭作用域或新实例轮换；不得复用旧完整身份，也不能仅凭TTL清除保护。
- 需要物理连续区间、固定图地址或特定注册条件时，统一字节池未必可用；不兼容缓存应单列，不能作为可满足需求的容量。

## 诊断：竞争解释与区分实验

先固定模型、有效请求集、逻辑位置、数值合同、共享关系和完成边界，再改变一个因素。端到端差异不能自动归因于分页。

| 观察 | 竞争解释 | 区分干预与反证后的修正 |
|---|---|---|
| 缓存很多却分配失败 | 重复计费；缓存不兼容；仍有旧责任；连续性不足 | 构造满预算兼容缓存轨迹，记录R、A与事务后唯一集合；R足够仍被拒绝先修准入，兼容检查失败则不能称重复计费 |
| 一轮读完后下一轮停滞 | 完成错误关闭资格；真实退役；未满足生产依赖 | 保持owner OPEN，以新操作身份反复登记/完成；再仅关闭另一个共享owner，合法读仍应推进 |
| 重试后旧完成删除新责任 | 只按在途uid去重；完整作用域漏记；物理epoch误用 | 保持页和epoch不变，完成42、重试42、登记43、重放42；分别统计实际提交次数与独立pending事件，修复操作表而非只增加物理epoch |
| 首次初始化后取消仍出现视图 | 新owner没有关闭记录；RetireOwner跳过未发布对象；Commit重新打开资格 | 在取得页后、初始化在途、初始化完成但发布前分别调用RetireOwner；检查CLOSED、无视图、原事件保护和最终回收，不用直接Abort替代入口实验 |
| 取消后旧视图消失或内存污染 | 发布前扣旧引用；早回收复制目的；未保护源；旧DMA | 分别在取得页、映射、提交复制、复制完成和发布前取消；独立核对旧视图、事件责任及实际值 |
| 小页快，固定准入集后差距消失 | 容量减少等待，kernel未变快 | 分开比较固定消费集与开放准入；只在后者改善时收窄为容量解释 |
| 固定准入集后仍有差距 | 布局、间接寻址、COW、CPU准备或映射等待 | 分阶段计时；预先准备只读页，固定kernel与布局，再分别恢复复制和映射 |
| reserved不下降 | 合法缓存；图绑定；draining；泄漏 | 分解互斥容量桶，关闭一个责任再观察；不能只凭进程显存曲线判泄漏 |
| 复用后串数据 | 旧物理写；旧完成误删新票据；错页表；越界读 | 分别延迟实际写、重复旧完成、置换物理页和填充尾部poison；核对内容与责任，两类错误不能混为代次问题 |
| 映射尖峰消失但峰值变高 | 工作被提前或回收被延迟 | 记录调用与物理集合时间线；修正为隐藏关键路径成本，不宣称消除工作 |
| 图输出被改写 | 共享池覆盖；旧读者未结束；内容版本错绑 | 比较顺序/并发重放、独立输出复制及绑定身份；地址相同不是正确内容的证据 |

独立内容参考应从逻辑输入和版本历史构造，不读待测页表来定义期望。责任参考应从实际接受的事件及实际结束记录重建，不把allocator当前U或操作表状态当成自己的正确答案。操作唯一性还要检查历史接受事件，不能只检查此刻pending集合。拥有者关闭的期望来自退役输入，而不是从是否存在已发布视图反推。

## 检查覆盖与未验证边界

随章tools/check_k_sys_012_full.py为确定、离线、只读的Python标准库CPU模型。它实现缓存匹配与新增backing准入、RESERVED/MAPPED准备、受控初始化和复制、版本检查发布、取消排空、共享拥有者独立退役以及回收。执行观察器保存独立事件账，按尚未完成的实际事件重建页访问责任，并从历史接受事件检查完整操作身份是否重复；逻辑视图、关闭期望和内容由检查轨迹明确给出。

检查包含满预算缓存复用、缓存不兼容、空需求、逐区域舍入、取得部分页与建立部分映射后失败、初始化提交后失败、复制中取消、复制后发布前取消、COW成功及旧读者排空。操作检查保持页epoch不变，覆盖在途重试、已完成重试、同身份不同描述、以新身份启动、不同作用域相同局部uid、完整证书不匹配、缺少最后访问证据及旧证书重放。首次发布前退役分别从取得页、初始化在途、初始化完成三个阶段进入RetireOwner，检查关闭不可逆、无视图、责任保留与最终回收。

负对照执行遗忘已结束操作后重新登记同一身份、跳过未发布拥有者退役、泄漏部分预留、发布前扣旧引用、共享写污染、忽略作用域和epoch的完成处理器，以及带旧写提前复用。遗忘终态的错误分支先产生第二次实际提交，再让同一旧证书删除其责任，由独立事件账检出；旧写分支实际覆盖复用物理槽，说明epoch不能阻止物理污染。

模型采用一个责任域、单一串行状态域、固定大小页、整页访问和标量内容；NEW登记在模型中立即被执行观察器接受。它保留全部操作终态和拥有者关闭记录，不验证记录压缩或持久化恢复。绑定与隔离只抽象表示回收门。它不验证真实GPU页表/TLB、驱动扩展、映射撤销完成、stream/event可见性、DMA停止、CUDA Graph、真实线程竞态、提交接受状态未知的设备恢复、跨设备原子提交、完整KV布局/scale、kernel性能或端到端吞吐。执行结果须以绑定当前脚本和输入的真实记录为依据，覆盖说明本身不是执行通过记录。
