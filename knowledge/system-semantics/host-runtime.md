# K-SYS-015：服务主机运行时：执行域、队列与缓冲所有权

推理服务的 CPU 工作包括接收与解析、tokenization、调度、张量准备、提交、结果处理和响应编码。它们有不同的阻塞方式、并行度和生命期，必须与模型算子共享同一份主机资源预算。主机运行时要把请求身份、执行域、容量承诺、缓冲所有权和完成证据组织成可推进、可取消、可回收的路径。

## 问题、对象与不变量

逻辑请求记为 q，执行尝试记为 g，阶段记为 j，执行域记为 d。执行域可以是事件循环、线程池 worker、进程池进程或专用提交线程。阶段票据至少携带 (q,g,j,ticket_id)，物理对象身份为 x=(storage_id,range,epoch)。请求尝试 g 与物理槽代次 epoch 不同：前者决定业务结果归属，后者决定哪次分配仍受保护。重叠别名应合并为一个受保护存储范围，不能按张量名字分别宣称独占。

本章给出一种保守方案：状态拥有者串行处理容量、取消、访问登记、发布和交接事务；实际计算和可能阻塞的调用在事务外执行。多线程实现可以用锁或其他协调协议提供同样的线性化顺序。阶段处理状态为 PREPARING、QUEUED、RUNNING、WAIT_OUTPUT、SUBMITTED、WAIT_HANDOFF、DRAINING 和终态。业务资格 eligible 与物理阶段正交；取消令 eligible=false，不会自动消除 SUBMITTED 使用。

缓冲的主状态为 FREE、RESERVED、FILLING、PUBLISHED、READING、RETIRING。隔离原因集合 Q 与主状态分开；界面可以将 Q 非空显示为 QUARANTINED，但必须保留原阶段、未结算使用及每个原因的解除条件。缓冲另存容量 cap、有效长度 n、逻辑拥有者 L、唯一写者 writer、读取授权 R 和实际使用集合 U。每项使用键为 (q,g,x,uid,mode)，登记先于外部系统可能接受该访问。

任何合法设计至少保持以下关系：

1. 在声明的过载范围内，所有在途项、私有输出、等待记录和物理存储都有预算；不能先写入或入队再检查容量。
2. 生产写入、可见性、读取和复用有明确顺序。同一存储范围只有一个未结束写者；最后访问结束前不能覆盖或交给下一代。
3. 完成只结算匹配的使用身份。重复证书不重复扣账，旧代事件不能修改新代对象。
4. 数据队列饱和时，取消、deadline、关闭和完成处理仍可运行；独立控制队列不能弥补处理线程自身被阻塞的问题。
5. 提交返回、生产完成、业务发布、网络提交、远端消费和物理回收是不同边界。
6. CPU 预算取决于有效 cpuset、CPU 时间额度、祖先限制和竞争；可见线程或 CPU 数不等于独占算力。

本章选择读取授权与 READ 使用同时登记、同时结算。因此在一次拥有者事务结束的稳定边界，R 恰好是 U 中 READ 项的键集合。该关系同时防止漏记保护与残留授权；若另有先取得授权、稍后登记实际访问的设计，必须另外表示尚未启动的授权责任，不能直接套用这里的等式。

## 执行域的合法条件与选择

单事件循环适合协调大量等待中的连接和完成通知。合法性取决于声明的响应性预算，而不是调用名称。设一次控制轮询前最多执行 k 个数据回调，每个不可分割回调最多耗时 L，执行域获得运行机会的延迟上界为 J，控制处理本身耗时为 C，则一种足够的预算条件是 kL+J+C≤R_ctl。没有相应上界时，该式只能作为预算模型，不能声称已经保证取消时延。

有界、非阻塞的设备提交或短原生调用可以留在事件循环。若调用可能等待设备、驱动锁、文件或网络，或其不可分割 CPU 工作超过预算，就需要拆成有界分片，或者移到其他执行域。线程池隔离阻塞，但真正 CPU 并行仍取决于语言运行时、原生库、锁和总配额；线程池自己的排队与完成通知也必须有界。进程池增加地址空间与故障隔离，同时付出启动、IPC、序列化、内存副本和诊断成本。

一种可分析的责任划分是网络接入、输入解释、调度、设备提交、结果处理和响应交付。这些责任可以合并，也可以跨域拆分。跨域后要说明数据与请求如何对应、谁能更新共享状态、谁持有缓冲、完成如何通知以及异常退出由谁接管责任。共享内存减少复制，但延长生产者不能覆盖的范围；消息或管道简化隔离，却增加复制与序列化，并可能让数据阻塞控制消息。

专用提交线程是有条件的候选：它能隔离提交抖动，也增加交接、唤醒、排队和状态协调。提交很短且主循环预算充足时，单独设置线程未必有收益；提交存在长尾时，隔离可能改善控制响应。线程不能同时承担无界日志或阻塞等待完成，否则设备仍会饥饿。异步接口本身不创造独立工作，收益来自可以重叠的依赖与资源。

## 容量账与阶段交接事务

只限制队列中尚未取出的项，会把运行中和待交接输出藏到队列外。本章分别维护三种账。

| 账 | 包含范围 | 释放边界 |
|---|---|---|
| 阶段入口 Dⱼ=(items,bytes) | 已预留、准备中、排队、运行、等待交接及排空中的输入责任 | 该入口的逻辑持有已解除，且相应最后使用与读取授权都已结束 |
| 阶段私有输出 Oⱼ=(items,bytes) | 已预留、填充中、待完成、待交接及取消后排空的输出 | 成功转入下游入口账，或无责任后回收 |
| 全局物理预算 M | 各唯一存储分配及尚未物化的分配预留 | 物理回收或确定未分配后的回滚 |

每种账同时限制项数和字节。数据队列中的项是 Dⱼ 的子集，因此排队项不会超过入口项数预算；需要更小的独立队列上限时，也把该队列 credit 加入同一交接事务。控制通知不消耗数据 credit。

阶段字节按保留容量 cap 计，不按当前有效长度 n 计，要求 0≤n≤cap。输出 cap 必须在写入前由形状推导、可信上界或有界 chunk 契约确定。若实际输出长度依赖数据，生产者必须在每次写入前检查剩余容量；不足时在合法分片边界暂停、先扩容预留再写，或者失败。不能执行无界原生写入后才发现超限。异步操作若不能限制写入范围，就必须在提交前取得完整可信上界，否则该候选不可用。

物理容量只计一次：输出在 Oⱼ 与 Dₖ 之间交接时没有新增副本，M 不增加；复制到另一进程私有区或另一存储则需要新的物理预留，源对象仍保护到复制最后读取结束。阶段 credit 是局部责任预算，与全局物理账分别检查，不能把两者相加当成实际内存。预留池与池中对象同样不能重复计入物理容量。

本章选择先保留私有输出，再在输出就绪后尝试交接。另一候选是在执行前一起预留下游 credit，能减少完成后的等待，却会更早占住下游项数和容量。两者都必须保持等待有界、可取消，并说明 credit 持有时长。

```pseudocode
算法 ADMIT_INPUT(q,g,j,cap,deadline)
输出：PREPARING 票据，或 WAIT/REJECT 及原因

1 校验 cap、单对象上限、deadline 和下游输出契约
2 在状态拥有者内原子尝试：
    预留 D_j 的一个入口项及 cap 字节
    预留 M 的 cap 字节、输入对象记录和控制/完成责任记录
   任一不足：不取得部分 credit；返回 WAIT/REJECT
   WAIT 若保留服务端记录，该记录必须占已有有界准入预算
3 建立 x 的 RESERVED 分配，L={本入口票据}，n=0，eligible=true
4 在开始接收、复制或初始化前执行 BEGIN_FILL，登记生产使用
   可能阻塞的生产动作在状态事务外执行
5 生产完成后按 ON_DONE 结算；仅在成功与可见性成立后 PUBLISH
6 同一拥有者重新检查 eligible 与 deadline：
    成立：把已发布输入票放入 j 的队列，置 QUEUED
    不成立：不入队，走取消/失败及排空
```

入口网络读取也有已有缓冲的责任。若服务器已经交付一个 body，其存储不能因 ADMIT 返回 WAIT 而凭空消失；必须由接入层的有界账继续保护。对后续读取可以先预留 chunk 容量再请求数据。服务器内部缓冲和应用缓冲属于不同范围，应用的预算不能证明整个协议服务器内存有界。

```pseudocode
算法 STEP(j,ticket)
1 在本次数据推进前处理有界一轮控制/完成事件，核对取消和 deadline
2 只选择已 PUBLISHED 的输入；验证 (q,g,x,epoch)
3 推导私有输出容量 u；若 u 永远无法放入目标单对象/字节上限，失败或换合法分片路径
4 原子尝试预留 O_j 的一个项、u 字节和 M 的 u 字节：
    失败：保存 WAIT_OUTPUT 于原入口记录，注册容量/定时唤醒，立即返回
    成功：建立私有 RESERVED 输出；分配失败则撤销本次输出预留
5 BEGIN_FILL 输出，并为输入读、输出写及其他实际访问登记唯一使用票据
   在提交资格检查与启动协调下执行一次阶段工作
6 同步主机阶段：调用返回并证明本调用全部访问结束后，生成各项匹配完成证书
   异步阶段：提交返回只置 SUBMITTED；输入/输出使用和全部容量继续保留
   确定未接受的提交可撤销未启动责任；接受状态未知则隔离并保留责任
7 把输入 READ、输出 WRITE 及其他使用的证书分别交给 ON_DONE
   ON_DONE 按已登记模式分派；READ 完整完成原子结算对应 U 与 R
   证据未齐时返回，由后续完成事件继续推进，不等待设备完成
8 输出完整成功且 eligible 仍真：PUBLISH；置 WAIT_HANDOFF；尝试 HANDOFF
   失败或取消：不发布业务结果；撤销逻辑持有，保留实际访问，进入 DRAINING
```

同步阶段的 CPU 服务动作与拥有者事件循环可以处在不同域。上面的“立即返回”是状态推进函数返回，不能通过在该线程上阻塞等待空位来实现 WAIT_OUTPUT 或 WAIT_HANDOFF。调用返回只为它确实覆盖的访问生成证书；若库内部仍有异步读者，输入 READ 不能随该返回结算。一个适配器可以从同一平台事件产生多项证书，但必须逐项说明覆盖的身份与最后访问范围。

```pseudocode
算法 HANDOFF(ticket,j,k,output)
前提：output 已 PUBLISHED，携带完整身份、n、cap 及生产完成证据

1 在状态拥有者内重新检查 eligible、deadline、目标开放状态和对象代次
   若失败：走 ABORT；不取得下游引用
2 原子尝试预留 D_k 的一个项与 output.cap 字节，以及需要的队列 credit
   不足：
      保留 WAIT_HANDOFF；输出仍由 ticket 持有，继续占 O_j 和 M
      输入入口 D_j 仍保留；登记容量变化或 deadline 唤醒；返回 WAIT
3 在同一事务内：
      建立唯一的下游票及其输出逻辑引用
      将预留变成 D_k 的正式入口责任并入队
      从 O_j 移除对应输出 credit；撤销上游对该输出的逻辑持有
      记录交接已提交，不能重复交接；M 不变
   任一步提交前失败：完整回滚本次下游预留，上游责任保持原样
4 只有交接提交成功后，才解除本阶段对输入的逻辑持有
   输入实际使用/读者未结束时仍保留 D_j 和物理容量，阶段置 DRAINING
   全部局部责任结算后释放入口 credit，阶段置 COMPLETED
```

下游项的“消费”也不是仅从 FIFO 取走：运行中及排空中的输入仍占 Dₖ。这样下游满、上游完成时，不能通过隐藏到 worker 私有变量中逃避硬上限。

等待记录复用已准入票据，不为每次重试新建无界 waiter。容量释放唤醒候选，重试时重新校验资格和容量；唤醒不是成功预留。deadline 或取消由独立可运行路径处理。若不存在能释放所需容量的在途事件，继续等待没有成功推进保证：可以失败、拒绝、按任务允许的规则释放牺牲者，或者在准入时保留未来输出 guard。对于全部输入占满 M、无人能预留输出的轨迹，必须识别这种停滞，不能以无限 WAIT 宣称可行。

## 缓冲从首次取得到最后使用

本章选择“主机取得生产完成证书后才发布”的保守方案。因此 PUBLISHED 表示完整成功内容已经具备声明消费者所需的可见性，绝不表示只提交了生产工作。跨 stream 消费也可以在 host 尚未确认生产结束时先提交，但必须建立生产到消费的显式依赖，并独立保护消费者生存期；那种方案需要另定义带依赖的待就绪描述符，不能复用这里 PUBLISHED 的完成含义。

完成证书分别回答身份是否匹配、是否覆盖整项最后访问、结果是否成功以及所需可见性是否成立。结果失败但访问确已结束，可以解除对应访问责任；部分结果、超时或通知到达不能替代最后访问结束证据。来源未知或旧代事件不修改当前对象。使用身份在一代内不复用，已结束身份的重复处理无状态变化。

```pseudocode
算法 BUFFER_EVENTS(x,event)
所有变更在同一状态拥有者内处理；使用键包含请求、尝试、分配代次、uid 和模式

RESERVE(actor,cap)：
  要求 FREE，L/R/U/Q 均空，无写者，容量 credit 已取得
  置 RESERVED；L={actor}；writer=空；n=0；production_ok=false
BEGIN_FILL(actor,write_uid)：
  要求 RESERVED，actor 在 L，eligible=true
  登记 WRITE 使用到 U，绑定允许写范围；writer=write_uid；置 FILLING
  登记完成后才允许生产动作启动
SUBMIT_RETURN(write_uid)：
  只记录已接受提交；保持 FILLING、writer 和 U，不授权读取
ON_DONE(key,certificate)：
  未登记、旧代或已结束的 key：无状态变化并记录诊断；返回
  身份、模式或访问范围不匹配：保留原责任并记录诊断；返回
  尚不能证明整项最后访问结束：
    保留 U；若为 READ，也保留对应 R
    需要时添加该 key 缺少完成证据的隔离原因；返回
  读取 U 中已登记的 mode，不以通知自报模式覆盖它
  若 mode=READ：
    在本事务内调用 SETTLE_READ(key)
  若 mode=WRITE：
    移除 U 中该 key；清除相应 writer
    记录成功/失败、有效长度和可见性证据；不自动发布
  仅解除由该 key 缺少完成证据引起的隔离，不能清除其他原因
  记录该使用已经结束；资格不变
  重新检查对应阶段的排空、credit 释放及对象回收条件
SETTLE_READ(key)：
  仅由已经完成整项证书验证的 ON_DONE 调用
  原子移除 U 中该 READ 与 R 中同一个 key 的读取授权
  若主状态为 READING 且 R 为空：置 PUBLISHED
  若主状态为 RETIRING：保持 RETIRING，不接受新使用
  不解除其他读者、逻辑拥有者或其他隔离责任
RELEASE_READ(key,certificate)：
  这是 READ 完成适配入口，不是另一种无证据释放操作
  只接受已登记为 READ 的使用；转交 ON_DONE，执行相同验证和原子结算
  已结束或旧代 READ 的重复调用仍无状态变化
PUBLISH(actor)：
  要求 FILLING，actor 在 L，eligible=true
  要求所有必需生产使用已完整成功，writer=空，n≤cap，所需可见性成立
  置 PUBLISHED；写入范围封闭，此代不再接受写入
ACQUIRE_READ(actor,read_uid)：
  要求 PUBLISHED/READING，身份及资格匹配
  原子登记 R 中的读取授权与 U 中的 READ 使用；置 READING
  登记先于实际读取或异步消费提交
RETIRE/ABORT(actor)：
  不再授权新使用，解除 actor 的逻辑持有；进入 RETIRING
  已登记的 writer、读者和使用保持原身份，继续收集完成证据
RECYCLE：
  要求 RETIRING，L/R/U/Q 均空，writer=空且无长期绑定
  释放物理容量与对应入口/私有输出 credit；置 FREE；epoch 加一
```

SETTLE_READ 的原子性是两个集合在同一事务内更新，不要求设备停止和账务删除发生在同一物理时刻。证书先证明最后读取已结束，拥有者再解除保护；两者之间的通知延迟可以延长驻留。不能先删除 U、之后依赖另一个可能丢失的 RELEASE_READ 通知删除 R，也不能只删除 R 而保留无法归属的使用。幂等性来自完整使用身份及已结束记录，不能用读者计数减一实现重复处理。

已发布对象不可变是本方案的选择；需要 UPDATE 或原地追加时，应另证明访问范围、先后关系和失败后有效内容。空输出 n=0 仍有项数、身份和完成关系，不能跳过发布条件；零字节也可能有对象与 framing 成本。

正常主机轨迹是 FREE→RESERVED→FILLING→生产完成→PUBLISHED→READING→RETIRING→读者完成→FREE。读取完成也可以早于 RETIRE：同步调用的完整输入证书经 ON_DONE 同时移除 U、R，使 READING 回到 PUBLISHED；逻辑持有仍保护输入，之后交接成功或取消再解除 L、退休并回收。异步提交后，输入 READ 与输出 WRITE 的责任继续存在。输出生产证书不能自动结算另一个 stream 或库内部读者。

取消后的迟到输入完成仍经过 ON_DONE 的 READ 分支。它解除原使用、原读取授权及对应的缺证隔离，保持 RETIRING 与 eligible=false，不发布结果，也不建立下游票。仅递增 epoch 不能阻止旧 DMA 写入同一地址；地址必须保持到旧访问结束或取得平台明确的访问撤销证据。重复 uid 完成不能抵消另一个 uid，旧代完成也不能反向隔离当前新代对象。

以容量 4 B、入口 credit 为 (1 项,4 B) 的输入 a 为例，生产已经结束，唯一消费者为 r1。忽略其他独立责任时，取消与迟到完成的责任变化如下。

| 事件后 | 主状态 | L | U | R | Q | 入口 credit |
|---|---|---|---|---|---|---|
| 取得输入读取权 | READING | 本入口 | r1:READ | r1 | 空 | 1 项/4 B |
| 取消并解除本入口逻辑持有 | RETIRING | 空 | r1:READ | r1 | 空 | 1 项/4 B |
| 超时或范围不足的完成 | RETIRING | 空 | r1:READ | r1 | r1 缺证 | 1 项/4 B |
| r1 的完整最后读取证书进入 ON_DONE | RETIRING | 空 | 空 | 空 | 空 | 1 项/4 B |
| RECYCLE 提交 | FREE，epoch 加一 | 空 | 空 | 空 | 空 | 0 项/0 B |

该轨迹中，证书结算与回收是可分开的两个事务；完整证书后已具备回收条件，但 credit 只在对应释放事务提交时归还。若还有其他拥有者、读者、长期绑定或隔离原因，则仍不能回收。

一个会泄漏的反例是在 ON_DONE 中只移除 U 的 r1：最终出现 RETIRING、L=空、U=空、R={r1}。它没有提前覆盖，却永久阻断回收与入口 credit 归还。重复完成因使用已结束而被忽略，不能修复遗漏的授权结算。区分这种软件残留与真实迟到读取，应把读取授权逐项连接到登记票据及完整证书：前者在证书已经充分时仍残留 R，后者仍缺对应最后访问证明。修正应闭合统一完成入口，不能通过忽略 R 强行回收。

## 满下游时的一条完整轨迹

设入口 D_A 的上限为 (1 项,4 B)，D_B 为 (1 项,4 B)，A 的私有输出 O_A 为 (1 项,4 B)，全局 M 为 12 B。A 的输入 a 和 B 的旧输入 b 各保留 4 B，输出 o 需要容量 4 B。以下是容量与责任模型，不是硬件测量。

| 事件后 | D_A | O_A | D_B | M | 可推进动作 |
|---|---|---|---|---|---|
| a、b 已发布并进入各阶段 | 1/4 | 0/0 | 1/4 | 8 B | A 可预留输出；B 可消费 b |
| A 预留并开始写 o | 1/4 | 1/4 | 1/4 | 12 B | 保留输入读与输出写责任 |
| 仅收到提交返回 | 1/4 | 1/4 | 1/4 | 12 B | o 仍 FILLING，不可读 |
| 输入完整 READ 与输出完整 WRITE 证书分别结算，发布 o | 1/4 | 1/4 | 1/4 | 12 B | a 的 U、R 已结算，L 尚在；交接因 B 满返回 WAIT |
| 控制事件被处理 | 1/4 | 1/4 | 1/4 | 12 B | 可取消、处理 deadline；没有阻塞入队 |
| B 最后使用 b 结束并释放入口 | 1/4 | 1/4 | 0/0 | 8 B | 唤醒 A 重试 |
| 原子交接 o，解除 a 的 L 并回收 | 0/0 | 0/0 | 1/4 | 4 B | B 取得 o；A 完成 |
| B 完成 o 并回收 | 0/0 | 0/0 | 0/0 | 0 B | 全部责任结清 |

表中“1/4”表示 1 项与 4 B，不是比例。如果控制事件改为取消 A，则取消立即撤销交接资格；a、o 在最后使用结束后释放，b 继续正常消费，最终同样归零。若取消发生在提交后、完成前，M 仍为 12 B；迟到 READ 完成结算 a 的 U、R，迟到 WRITE 完成结算 o 的写者与 U，两者都不能恢复业务资格。若写入失败且证书已经证明访问结束，也可清理，但不能发布部分内容。若完成范围未知，保留责任和容量，不把失败通知或超时当作回收许可。

反例是 B 已占 1 项，A 直接追加 o，使 B 达到 2 项；只检查字节可能在 o 为零字节时漏掉该错误。另一反例是先撤销上游引用，再发现 B 满，形成无人负责的 o。交接必须把下游取得与上游放弃放在同一事务。若实现选择阻塞入队，而该线程负责取消或完成处理，控制路径也会被满队列阻断。

## CPU、通信与驻留成本

设阶段 j 每次访问消耗 cⱼ 个 CPU 秒，访问率为 λⱼ，每阶段分得 pⱼ 个有效核，则 λⱼcⱼ<pⱼ 是稳定性的必要条件，不保证尾延迟。一个准入请求可能重试、跳过或多次访问阶段，不能统一令所有 λⱼ 等于 offered 请求率。多个阶段共享主机时需合计模型内部线程、垃圾回收、通信、运行时及操作系统开销：

D_CPU=Σⱼλⱼcⱼ+D_other≤p_eff。

对普通 CPU 时间预算，配置上界可记为

p_cap=min(|cpuset.cpus.effective|,各有限祖先及本组 MAX/PERIOD)，p_eff≤p_cap。

MAX 和 PERIOD 使用相同时间单位；max 表示该项没有有限上限。有效 cpuset 限制允许放置的位置，quota 限制长期 CPU 时间，竞争与节流使实际供给更低；它们不能保证某线程随时运行。cpu.max.burst 不能转化成持续增加的长期平均额度。cpu.stat 的 usage_usec、nr_throttled 和 throttled_usec 应与阶段排队联合解释。

设允许在 8 个 CPU 上运行，每 100 ms 最多消费 400 ms CPU，且没有更严格祖先限制，则 p_cap=4。每请求分词 10 ms、网络解析 2 ms、调度响应 3 ms，后台另需 1.2 CPU 秒/s。200 请求/s 的需求为 200×0.015+1.2=4.2 CPU 秒/s，超过配置上界；180 请求/s 为 3.9，只通过必要条件。增加 worker 不会创造配额，64 个可见 CPU 也不能让 4.2 变得可持续。

在同一候选与观察边界中分别列账：

| 成本 | 条件化计算与影响 |
|---|---|
| 计算 | 分词、解析、编码、调度、账务与失败工作均消耗 CPU；拆域增加通知与 bookkeeping，通常不减少模型 FLOPs |
| 访存 | 共享句柄减少搬运；复制 b 字节至少有对应源读取和目的写入，实际缓存、NUMA 与分配器事务另测 |
| 通信 | 每次跨域有固定通知/序列化开销及实际 payload；共享内存仍有锁、缓存行交互与 IPC 元数据 |
| 准备 | 进程启动、线程池、pinned/IPC 区、对象表和完成适配器；固定池减少反复分配但占住容量 |
| 同步 | 容量预留、发布、交接与完成汇合形成依赖；等待证书可以由回调推进，不能因此把等待时间计为 CPU 服务时间 |
| 驻留 | 输入、私有输出、目标入口及取消后未排空对象按唯一物理存储求并集；更早预留下游会延长 credit 持有时间 |

以哈希表保存身份时，单项预留与交接的期望账务开销可为 O(1)，处理一份覆盖 m 项使用的证书仍需 O(m) 核对。READ 结算的两项集合删除仍为期望 O(1)，不能为了少一次更新省略授权解除。按每次释放扫描 W 个等待者会产生 O(W) 唤醒成本；按预算类别维护等待索引可以减少无效扫描，但增加元数据与公平性管理。控制事件去重、完成责任和终态记录同样需要有界保留策略，不能把日志当成无限免费的账本。

若对象容量为 b、最后读取结束到拥有者处理完整证书的延迟为 δ，则该延迟在无其他持有者的设定下增加 bδ 的驻留积分，并延长一个入口 credit 的占用 δ；它通常不增加 δ 个 CPU 服务时间。若授权结算被遗漏，δ 不再有有限清理上界，增加缓冲只能推迟耗尽，不能修复责任泄漏。

设单 worker 服务时间固定为 s，前方 N 项串行执行，忽略其他延迟时等待约 Ns；s=5 ms、N=20 时为 100 ms，剩余 deadline=90 ms 的同队列候选已不可行。服务时间有方差、优先级、抢占或多个 worker 时需要重新建模，不能把该算例当作通用预测。

物理驻留为 R_peak=max_t Σ_{x live at t}cap(x)，共享同一物理对象只计一次。输入队列允许 512×64 KiB，前处理产物另允许 512×4096×4 B，128 个输出各保留 64 KiB；三类互不共享且同时达到上限时主项为 32+8+8=48 MiB。还需另计连接缓冲、元数据、模态张量、pinned staging、IPC、分配器碎片和进程副本。取消后尚未排空的对象仍在 live 集合内。

## 背压、取消与关闭

慢客户端会延长待交付输出的生命期。每请求输出达到预算后，可以暂停后续生成或按协议结束；暂停又延长 KV 驻留。批量刷出 token 减少调用、唤醒和 framing，却增加首内容等待并改变 ITL 的事件位置。不能只比较内部生成吞吐。

控制路径可以使用每个已准入请求的合并取消标志、独立通知容量和预先登记的完成槽。通知只是唤醒，真实责任保存在有界表中；重复通知可合并，完成状态必须可再次查询或可靠交付，不能因通知满而丢失最后使用证据。预留在启动前取得，不能等设备完成时才发现无处记录。拥有者每轮先处理控制/完成，再按预算推进数据；也需在有限事件速率与公平服务假设下避免数据永久饥饿。

```pseudocode
算法 ABORT_AND_SHUTDOWN
CANCEL(ticket)：
  串行设置 eligible=false，记录至多一次业务终止原因
  移除尚未启动的队列项，取消容量等待，撤销未提交交接
  解除本票逻辑持有；未启动 RESERVED 可以直接进入 RETIRING 后回收
  已启动的输入读、输出写、网络借用及设备访问继续留在 U/R
  对每个对象尝试回收；有责任者保持 DRAINING 或隔离

SHUTDOWN：
  关闭新准入；对已有业务撤销后继提交资格
  继续处理控制、完成、管道输出和必要的排空消费
  所有最后访问证书进入 ON_DONE；READ 按同一规则结算 U 与 R
  等待超时：记录未结算身份与隔离原因，不宣称已经释放
  所有逻辑持有、使用、读者、长期绑定和隔离均结清后，才交还对应资源
  确认 worker/子进程的退出与输出处理边界，最后停止责任拥有者
```

子进程的控制消息、结果、stdout/stderr、退出状态属于不同通道。只等待退出而不消费有限管道，子进程可能因写满而无法退出；把全部日志捕获到内存又可能导致无界驻留。应持续有界排空，或选择有明确限制的日志策略。

超时、发出终止请求、操作系统实际退出、主机取得退出确认、管道 EOF 与排空分别记录。Python 的 Popen.wait/communicate 超时不自行证明进程终止；固定文档中 run 的 timeout 路径则包含 kill 和等待，不能把两种接口混为一谈。发出 kill 也不是已经取得退出确认。有管道时还需完成相应输出处理；父进程退出确认不能证明外部设备、后代进程或其他访问域已经排空。

## 条件变化与区分实验

输入变长、CPU 配额收紧时，保留身份、发布和最后使用规则，重新估计服务时间、项数/字节及准入；只增加 worker 可能扩大节流。输出上界变大时，重算 Oⱼ、Dₖ 和过渡峰值；原先能容纳的完整输出可以改为合法 chunk，不能静默截断内容。下游长期变慢时，增加缓冲只能吸收有限波动，应调整生产率、准入或协议终止策略。

共享改成复制时，保留两端独立完成责任，并增加目的存储与源最后读取；复制减少跨域共享责任的收益要与搬运、峰值比较。同步调用改成异步调用时，保留统一 ON_DONE 结算协议，调整证书产生时刻和覆盖域，不能再以提交返回代替输入读取结束。读者数增多时，每个 uid 独立结束；某一证书只能解除它实际覆盖的读者。

调用出现不可分割长尾时，可以调整执行域或采用分片；若提交一直有界且事件循环满足预算，则可以保留合并方案。设备已饱和而主机充足时，继续增加域与在途槽可能只增加驻留和尾延迟。

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 设备空闲、首内容慢 | 输入域饱和；提交域阻塞；输入供给不足 | 固定模型与设备，分别改变输入 worker、提交隔离和网络供给，记录各域入队/开始/结束；提交队列持续空而输入增长时先修输入与准入 |
| 下游满后取消很慢 | 阻塞入队占住拥有者；控制未轮询；原生工作不能中断 | 将 B 固定为容量 1 并停止消费，A 完成后注入取消和心跳；控制处理及时而最后使用晚属于排空，控制也停则修执行路径 |
| 增 worker 后 p99 上升 | quota 节流；锁竞争；cache/NUMA 争用 | 固定总预算比较请求 worker 与算子线程组合，联合看节流、等待和页放置；没有节流变化时保留其他解释 |
| 输出偶发读到旧值或部分值 | 提交当完成；缺 BEGIN_FILL；跨 stream 缺依赖；身份错 | 延迟生产证书，给目标区填可区分初值，读取前核对完整身份与发布；仅改变完成顺序就出错时先修就绪/生命期 |
| 取消后复用污染邻居 | 过早 RECYCLE；旧代事件改新代；漏记独立读者 | 保持邻居正常，延迟一个 uid、重放完成并反转顺序；检查最早覆盖点，不能以之后拒绝迟到释放掩盖此前覆盖 |
| U 已空但入口长期不释放 | R 结算遗漏；仍有合法 L/绑定；其他隔离原因未解除 | 让输入 READ 的完整证书只走 ON_DONE，分别测试正常结束与取消后迟到完成，核对 R 与历史未结束读取集合；证书充分仍残留同一 R 时修完成分派，不能绕过 R 回收 |
| 内存随满队列继续增长 | 私有输出未计；输入提前释放账；等待者或日志无界 | 按物理 id 和每次预留/交接/回收重建逐时并集；仅请求数归零而使用未归零不能证明清理 |
| 子进程超时后被标为清理成功 | kill 请求被当退出；退出已确认但管道未处理；外部责任未结算 | 在 timeout、kill 请求、退出确认、EOF 分别暂停；清理资格必须随证据改变，不能由 kill 参数直接给答案 |

观测应沿同一请求传播 q、g、阶段、ticket、物理代次和 uid，区分事件发生与回调处理时刻，分开排队、CPU 服务、提交和设备完成。trace/span 提供关联，不能代替资源责任或同步证据。比较方案时固定输入分布、任务语义、完成边界、总资源和 offered 人口；失败、拒绝、取消与未完成工作仍留在相应账中。

## 检查覆盖与未验证边界

配套 tools/check_k_sys_015_full.py 是标准库、确定性、只读、离线的 CPU 符号检查。阶段模型推进输出预留、RESERVED→FILLING→PUBLISHED、下游满时返回等待、控制服务、消费释放、交接与取消清理。独立判定器从对象归属重建入口、私有与物理账，拒绝超项、漏字节和无人负责对象；覆盖零字节、容量不足、输出越界拒绝和失败后清理。

缓冲 reducer 对 done 执行明确的模式分派，READ 的 U、R 原子结算；release 作为 READ 适配入口转入相同处理。独立审计器根据历史登记与完整证书构造未结束使用和应保留读取授权，核对每个快照。同步输入的 done、退休后完成、取消后迟到 done、双读者交错、范围不足、重复和旧代通知均在模型范围内；读取结束顺序及 done/release 路径组合采用小规模枚举。

遗漏读取授权结算的故障变体实际执行 done、移除 U，却保留 R。它必须被正常轨迹共用的审计器判为 READ_AUTHORIZATION_RESIDUE；另检查该状态不能满足回收条件且入口 credit 仍被占用，避免只观察 U 为空便宣布清理完成。提前发布、缺填充转换、访问未结束时复用及范围不足时回收也交给同一生命周期审计器拒绝。

进程检查使用有限管道和显式退出事件，区分 timeout、终止请求、退出确认、EOF 与清理资格。没有启动真实子进程，退出事件由确定性环境轨迹提供；它检验主机是否正确使用证据，不能证明终止信号必然生效。CPU 配额与物理容量算例另由精确算术和独立小集合参考核对。

生命周期模型固定一个请求尝试与存储槽，显式变化 epoch、uid 和使用模式；其证书字段表示匹配身份和整项结束与否，不模拟证书伪造、平台事件查询或真实访问范围。该模型把对象绑定一个入口 credit，以检查回收前后容量责任；不模拟多入口共享账的完整实现。阶段容量模型和异步生命周期模型分别检查其声明范围，没有把它们当作完整引擎集成验证。

这些检查不证明真实线程的原子性、锁与内存序、cgroup 节流、NUMA 放置、分配器行为、设备 DMA/可见性、真实子进程退出、网络交付或端到端 SLO。目标实验应保留有效资源配置、工作负载、阶段时间线、逐时容量、完成证据与客户端时延；CPU 模型不能写成 GPU 实测，也不能证明知识改善了 Agent 的构建效果。
