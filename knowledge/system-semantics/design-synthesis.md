# K-SYS-010：系统设计推导：把模型、缓存、执行与目标组合起来

本章连接从任务条件到系统结构的可反驳推导：状态模型、资源模型、候选设计、成本下界、证据状态和能区分竞争解释的实验。把性能结果作为合格Task候选的比较依据时，候选必须满足相应函数、身份、资源和完成要求。局部原型、成本测量与诊断实验可以在完整服务尚未交付时进行，其结果只支持实际覆盖的边界。下界通过只表示尚未被排除；上界未通过只表示尚未证明达标。两者都不能直接替代实际结果。

## 统一问题表述：从条件到设计证书

把设计条件写成 C＝(F,W,H,N,Q,S,E)。F 是模型函数、参数、位置规则、数值语义和必需状态；W 是到达过程、输入输出长度、前缀复用和会话依赖；H 是处理器、内存层级、互连、存储与拓扑；N 是运行时、编译器、驱动和可用执行路径；Q 是质量与数值容差；S 是首内容、逐 token、完成时间、吞吐、拒绝与公平目标；E 是已有来源事实、推导和测量及其作用域。设计变量 d 可以包含状态布局、缓存身份、调度粒度、执行后端、并行策略、阶段划分、队列和准入。

为展开本章的成本与证据推导，下面用“设计证书”表示候选 d 在条件格 k 下的合法性、状态转移、资源成本、证据支持的上下界、质量状态、排除理由和下一步区分实验。这是可替换的分析表示，不要求Agent另交一份同名产物，也不增加Controller或Task验收状态。条件格是 F、W、H、N 的有限代表区域，例如模型版本、批大小、历史长度与共享或独立内存域的组合；可以按当前问题选择其他表示。格内连续变化的量仍须保留范围，中心点的结果不能自动覆盖整个格。

设请求 r 的已知 token 数为 nᵣ，已提交且各必要层完整、可复用的 KV 终点为 cᵣ，满足 0≤cᵣ≤nᵣ。已生成文本不等于对应 KV 已计算；物理页已提交也不等于所有异步读者已经结束。系统在时刻 t 的驻留量为

M(t)＝W_phys(t)＋Σ_unique P_state(t)＋A_work(t)＋I_flight(t)＋Q_queued(t)，

其中 W_phys 是各物理副本的权重，P_state 是按存储域去重的状态页，A_work 是工作区，I_flight 是在途传输或暂定写，Q_queued 是消费者尚未释放的输出缓冲。同一物理 backing 在这些项间不重复计数。容量条件是 max_t M(t)≤M_cap；各项各自峰值之和只是保守上界，未必能在同一时刻达到。

设计还必须固定比较的时间量 θ。它可以是某次固定执行的完成时间、预先指定有限回放的最大 ITL，或某个到达分布下的总体平均值、p99。它们是不同对象。下界、上界、观测和目标只有指向相同 θ，或存在明确的蕴含关系时，才能共同裁决候选。

## 设计对象、合法性与证据状态

合法性至少包含四层。函数合法性要求候选实现任务规定的模型函数、mask、位置、归一化和输出；数值合法性要求 dtype、累加、缩放、舍入和容差契约相容；设备语义要求布局、指令、可见性和完成事件支持所选路径；身份与并发合法性要求请求、版本、页、adapter、输出和迟到通知不会串用。任何一层失败都不能用平均更快抵消。允许近似的任务可以比较不同表示或求解轨迹，但必须把相应质量门槛写入 Q。

普通稠密 GQA decoder 每 token 全层 KV 字节为

b_KV＝2·L·H_kv·d_h·s，

L 是层数，H_kv 是 KV head 数，d_h 是每 head 维数，s 是每元素字节。MLA 的持久 latent 不同，可按 L·(d_c＋d_Rh)·s 计算每 token 缓存主项。专家权重、临时分组激活、通信区与输出头另列。公式只描述声明的状态表示，不证明后端已选择相应 kernel。

逻辑共享不等于物理共享，物理共享也不等于每次读取只发生一次。多个请求映射到同一物理前缀页时，容量账计一次；没有跨请求广播、片上驻留或其他复用契约时，各请求 attention 仍须取得自身可见历史，流量账不能直接去重。将共享页从流量中无证据扣除会低估带宽时间；把每次逻辑读取都当成新物理页又会高估容量。

证书分别保存时间结论、质量状态与过期证据。下表的标签是主决策，原始证据及其他轴不因选择一个主标签而丢失。

| 标签 | 含义与处理 | 不能推出 |
|---|---|---|
| `ILLEGAL_LEGALITY` | 已确认硬合法条件失败；排除当前候选与条件格的组合 | 修改表示或算法后的新候选也非法 |
| `ILLEGAL_CAPACITY` | 已确认该执行计划必需的峰值驻留超过容量 | 仅因一个宽松容量上界超预算就证明不可容纳 |
| `EXCLUDED_LOWER_BOUND` | 有效时间下界超过目标，且未发现同作用域矛盾证据 | 其他条件格也应排除 |
| `EXCLUDED_MEASURED` | 相应作用域的直接观测或获准统计证据支持时间失败 | 任意保守上界超过目标即可排除 |
| `EXCLUDED_QUALITY` | 同作用域质量证据判定失败；当前组合不能满足联合目标 | 提升速度能抵消质量失败 |
| `LOWER_BOUND_SURVIVOR` | 当前未证明失败，也未证明时间与质量全部通过；保留开放候选 | 已满足 SLO |
| `QUALITY_PENDING` | 时间已获支持通过，质量未知或质量证据过期；保留但不计为合格方案 | 可以省略质量评估 |
| `VERIFIED` | 同作用域时间与质量均按声明证据口径通过 | 其他形状、设备、负载或总体分位数也通过 |
| `EVIDENCE_STALE` | 尚开放，且存在不适用的时间或质量证据；记录失配字段 | 证据本身错误，或有效的其他排除证据失效 |
| `INCONSISTENT` | 对同一时间量的有效约束无共同解；转诊断并暂停相互矛盾证据的裁决效力 | 目标实现一定不可行 |

质量采用 `pass`、`fail`、`unknown` 三态。未评估、区间不能裁决、任务分布改变或证据作用域失配都按 `unknown`；不能把没有发现质量错误解释为 `pass`。同作用域 `fail` 排除当前候选，`unknown` 保留候选但禁止 `VERIFIED`。质量评估依据可以是任务认可的独立数值参考、等价性论证或任务评估，具体范围必须记录。离线分类检查只消费这些状态，不生成真实模型质量结论。

容量也要区分证明方向：精确计划峰值或必要驻留下界超容量可以排除；保守容量上界超过容量只说明该上界不能证明容纳。资源尚无法裁决时保留为资源待确认的开放候选。随章分类函数的布尔容量参数限定为容量已决的情况，不模拟这个未决阶段。

## 上界、观测与统计口径怎样进入决策

对固定候选与条件格，设目标为 θ≤τ，且已有有效下界 L。时间证据分三类。

- 保守上界 U 声明 θ≤U。U≤τ 足以支持时间通过；U>τ 不说明 θ>τ。
- 直接观测 y 可以精确描述预先指定的有限执行或有限回放统计量，此时对那个有限对象有 θ=y。它不自动描述未来总体。
- 对总体均值或分位数的统计证据，应保留估计量、实验单位、区间 [a,b]、置信口径及方法假设。按预先声明的统计决策规则，b≤τ 支持通过，a>τ 支持失败，跨阈值则开放。点估计或样本最大值不能擅自变成总体硬上界。

作用域至少核对模型及制品、表示和布局、backend、dtype、batch 与长度、缓存条件、资源域与并发、到达和拒绝口径、计时起止、目标统计量及其人群。计时误差也要进入观测区间。将多个统计区间共同使用前，须说明联合覆盖或决策规则；分别名义 95% 的区间不能无说明地拼成一个确定证书。[性能实验](../tools/statistical-experiments.md)进一步区分运行、请求与环境重复。

把适用证据与下界相交，得到

L*＝max(L, 所有适用观测区间的下端)，

U*＝min(所有适用保守上界及观测区间的上端)，

没有上端证据时 U*＝＋∞。若 L*>U*，先进入 `INCONSISTENT`，即使 L 已超过目标也不能提前按它排除。这里的矛盾表示各前提或区间不能同时采用；对于统计区间，它还可能暴露覆盖失败或方法不适用，不能立即断言硬件违反物理定律。

宽松上界的反例是 L＝39.0625 ms、U＝80 ms、τ＝60 ms。实际值可以为 50 ms，同时满足 L≤50≤U 和目标；仅凭这组界必须保留候选。反过来，若已有同作用域有效上界 55 ms，而声明下界为 70 ms、目标为 60 ms，先排除会错删一个可能通过的方案。正确动作是保存冲突，检查单位、资源能力、缓存前提和计时边界，修正证据后重新分类。

若时间上界 55 ms 通过目标 60 ms，但质量为 `fail`，结果是 `EXCLUDED_QUALITY`；质量为 `unknown` 时是 `QUALITY_PENDING`；只有质量为有效 `pass` 才能成为 `VERIFIED`。这三个分支不要求离线检查执行真实模型评估。

## 完整推导算法：候选、条件格与证据更新

以下算法展示一种串联条件、合法性、容量、下界、观测、质量与下一实验的分析方法。候选族可以来自参数化搜索、已有实现或新设计，并可在新推导与实验后扩展；当前输入集合不穷尽合法方案。已有测量可以先于解析推导取得，Agent也可以修改或放弃这套表示，不要求研发按伪代码的论证顺序施工。下列分类标签只用于解释本例中的证据含义。

```pseudocode
算法 SYNTHESIZE(C,D,budget)
输入：C=(F,W,H,N,Q,S,E)；候选族 D；实验预算
输出：逐格设计证书、保留候选与下一实验，或明确的空集原因

1 归一化单位、逻辑轴、目标统计量和时间窗；将条件划分为有限格 K
  若 K 为空，报告缺少目标条件；若 D 为空，报告没有候选
2 建立依赖图：模型→必需状态；workload→逻辑需求；
  表示/后端→物理成本；调度/队列→用户可见延迟
3 对每个 k∈K、每个 d∈D：
    建立空证书，保留该候选版本及全部证据身份
    验证函数、数值、设备、身份和完成条件
    若硬合法条件已失败：记录 ILLEGAL_LEGALITY，继续
    构造请求状态、物理页、在途集合、输出队列与同时存活关系
    若必要峰值已确认超容量：记录 ILLEGAL_CAPACITY，继续
    若只有宽松容量上界超预算或资源关系未知：
        记录资源待确认，保留开放；不能由此删除候选
    对各目标时间量 θ：
        推导各资源必要需求与串行依赖，得到条件化下界 L
        从 E 选取对应 θ 的证据；逐项核对作用域、单位与统计规则
        将失配证据标为过期，不参加本格的界相交
        分别保留保守上界、直接观测和获准统计区间
        计算 L* 与 U*
        若 L*>U*：记录 INCONSISTENT，登记冲突证据并转诊断
        否则若有效 L>目标：记录该目标 EXCLUDED_LOWER_BOUND
        否则若适用观测或统计区间下端>目标：
            记录该目标 EXCLUDED_MEASURED，附有限回放或统计作用域
        否则若 U*≤目标：记录该目标时间通过及证据种类
        否则：记录该目标时间开放；宽松上界超目标仍留在这里
    核对质量证据，得到 pass、fail 或 unknown；失配按 unknown
    若存在时间证据矛盾：主标签 INCONSISTENT，暂停冲突裁决
    否则若质量 fail：主标签 EXCLUDED_QUALITY
    否则若某硬时间目标已获支持失败：保留其排除标签和依据
    否则若资源已确认容纳且所有时间目标通过且质量 pass：VERIFIED
    否则若资源已确认容纳且所有时间目标通过而质量 unknown：QUALITY_PENDING
    否则：保留开放；有过期证据时标 EVIDENCE_STALE，
          其余已通过资源检查的候选标 LOWER_BOUND_SURVIVOR
4 候选在某格失败只收窄该格的使用资格
  只有在全部目标格均已确认非法或获支持排除时，才从本轮全局候选集中删除
  开放、过期和矛盾格均不能充当全局删除依据
5 保留成本向量；未声明偏好前不将异单位成本直接相加
  仅有下界的 Pareto 排序用于安排实验，不能证明真实成本被支配
6 对开放项或冲突项，选择能改变竞争解释预测的干预与观察边界
7 若预算用尽，报告开放项与证据范围；否则执行获准实验后回到第 3 步重算
  不覆盖原始证据，不沿用已失效的主标签
```

在容量已经裁决、只有一个越小越好的时间目标时，随章 `classify` 对应上述证据分类分支。它显式接收质量状态，先做同作用域约束相交，再依据下界或观测排除。它不实施条件格划分、统计区间估计、容量计划或真实质量评估。

分类是不确定性随证据变化的结果，不是单调晋升阶梯。新的同作用域观测可能把开放候选变为通过或失败，也可能与旧下界冲突；模型、布局、NUMA、负载或计时边界改变后，应重新判定证据适用性。矛盾未解决时保留原候选与原始事实，暂停冲突证据的删选效力；修正具体前提后重新推导，不为使标签好看而删除反证。

候选在短请求格通过、在长请求格被容量排除时，可以作为带准入边界的短请求路径保留。对成本的安全支配也需要证据方向：若候选 A 的各项成本上界均不大于 B 的对应下界，且至少一项严格更小，才支持该范围内的支配关系；仅比较两个乐观下界不足以删除 B。

## 六类成本与条件化下界

| 成本 | 同一时间窗内应记录的量 | 常见错误 |
|---|---|---|
| 计算 | 有效乘法、归约、激活、索引与调度工作；对应执行能力 | 用峰值算力代替实际 kernel 时间；将逻辑工作视为已完成工作 |
| 访存 | 有效字节、实际事务、布局转换、cache/TLB 与重复读取 | 将共享容量去重直接搬到读取流量 |
| 通信 | 每条链路的字节、消息、集合操作、启动与等待；关键路径 | 将不同链路带宽相加；为每个并发使用者分配完整独占带宽 |
| 准备 | 加载、转换、编译、分桶、tokenize、页表与图准备 | 只计稳态 kernel，漏掉一次性和切换成本 |
| 同步 | 设备完成、跨 stream 依赖、消费者最后使用、屏障与排空 | 将 host 返回当成设备完成，将已提交当成可见 |
| 驻留 | 唯一权重、状态、工作区、在途、预留、队列与旧版本的同时存活峰值 | 共享页重复计；池与池中对象重复计；只算稳态 |

若资源 j 的必要需求为 A_j，而 B_j 是该条件下允许采用的资源服务能力，则 A_j/B_j 给出相应时间项。要作为有排除效力的下界，A_j 必须确为必需需求，B_j 必须是能力上限或明示模型设定，而不能用一次偏慢实测的带宽假装不可突破的硬上限。依赖图中必经串行链 P 的各项也须采用有效下界 t_v^LB。因此

T_LB＝max(max_j A_j/B_j, max_P Σ_{v∈P} t_v^LB)。

来源支持资源机制，不自动验证本任务的需求与能力前提。使用假设有效带宽时，结论是该假设下的排除；目标设备观察推翻前提后应重算。该式也不是完整预测：overlap 可隐藏某些传输，cache 可改变必需主存读取，tiling、NUMA、同步和队列又可能增加成本。观测低于下界时，先检查对象、层级、单位、计时边界和必需需求，不能当成无条件性能胜利。

对每轮读取一次权重的 decode 设定，同一副本内 b 个请求各有历史 h_i，且各请求需读取完整可见历史时，

T_iter(b)≥(W_r＋Σ_{i=1..b} h_i·b_KV＋A_other)/β_r。

W_r 是该物理副本权重字节，β_r 是该副本可用带宽的模型参数。若 r 个副本共享一个带宽域，均分设定下 β_r＝β_total/r；独立控制器、NUMA 域或本地 cache 条件改变时不能照用均分式。吞吐上界 b/T_iter(b) 也不能代替每请求 ITL，后者还包括等待其他批次、prefill、主机与输出路径。

## 场景一：长系统提示、高前缀复用的 GQA 聊天服务

先由 b_KV 和长度分布计算每请求驻留，再按共享前缀物理页唯一化得到容量；分页使共享完整页与私有尾部共存。命中长度 H 时，待算 prompt 后缀为 N−H，prefill 的 query 行数减少，但每次 decode attention 仍读取其可见历史。应分别说明省去哪些 prefill 位置和减少哪些物理页，不能合成一个无单位命中率收益。

命中后 query 很短时，主机调度、采样、提交、图选择、页表构造和输出唤醒可能占更大比例。固定缓冲图执行与异步准备值得评估，但必须满足地址稳定、输入缓冲不被覆盖、页表内容代次正确和输出消费者结束。地址稳定不证明共享页内容身份正确。

加入多 LoRA 后，缓存身份还需包含影响前向的 adapter、rank、缩放与接入位置。共享收益可能下降，亲和路由可能把请求集中到少数实例。区分路由集中与短 query 主机成本时，要固定请求及其执行时实际命中边界，只改变分发或准备路径。若关闭亲和同时降低命中率，就不能把总时间差单独归给路由。可通过预置相同合法缓存状态或分层报告实际命中，控制这个混杂。

另一个干预是固定计算与命中状态、只增加物理保留容量。若队列仍增长而计算时间不变，容量不足不是充分解释，应检查准入、路由与输出阻塞。保留更多缓存也会增加驻留时间和冷请求的容量压力，不能只看命中比例。

## 场景二：语音 Encoder-decoder 多请求服务

源音频先经过 processor 与 encoder，固定源可缓存各层 cross KV；decoder self KV 随目标长度增长，cross KV 由源长度、源表示与 encoder 版本决定，两个容量预算必须分开。encoder 可按音频长度聚批，decoder 按迭代推进。阶段间传递请求身份、源区间、模型版本和位置；队列压紧不能交换音频块、文本前缀或 cross 页的归属。

流式输入先判断 encoder 是否保证已提交表示稳定。双向 encoder 的旧表示可能依赖未来源，未定义稳定块协议时任意追加源并重用旧 cross KV 会改变函数。可以采用模型支持的块协议，或将独立窗口识别定义为另一任务；首个稳定文本时延必须包含输入窗口等待。稳定输出、暂定输出和 decoder 停止也应按任务分开，不能只测 decode 后宣称完整转写延迟通过。

## 场景三：MLA＋MoE 的多卡长上下文服务

MLA 用低维 latent 表示内容 K/V，并通过投影吸收减少历史展开；位置相关旋转不能与任意线性投影交换，因此采用解耦 RoPE 分量。容量分别计 latent、解耦位置分量、专家权重、临时分组激活、通信区和输出。每 token latent 变小不证明全部专家权重或远端 dispatch 消失。

EP 改变专家归属，TP 改变 attention 与线性层分片，两者通信频率、消息分布和失败域不同。高频同步的放置应比较实际互联组；远端 dispatch 需同时计算路径、排队、偏斜与接收端容量。若做 prefill/decode 分离，还需计状态传输、分片转换和完整提交。较小 KV 不等于网络免费，也不意味着专家热点解决。

区分实验可以固定模型和请求，只改变 EP 度数，记录每链路字节、专家最大负载及尾延迟；固定 EP、只改变 TP，记录本地分片与归约时间；固定并行计划、改变路由或共享前缀，观察队列和流量是否按预测变化。训练时的路由均衡目标不保证每次推理严格均衡。若实际干预同时改变副本、路由和 batch，需要拆开或记录这些中介变化，不能用一个平均吞吐裁决所有解释。

## 场景四：静态编译平台上的混合长度任务

模型函数固定而服务形状变化时，可按 prompt、query、context 和 batch 的联合分布选择有限桶。设备保留 KV，控制面推进真实长度；越界走明确回退、较粗桶或拒绝，不能静默截断。编译准备、executable、workspace 和图池驻留共同进入启动与容量预算。

前缀命中改变待算 query 分布，连续批改变 batch 分布，投机改变验证长度分布。桶选择应在这些机制组合后的 workload 上推导。命中后 query 变短、host 固定成本上升时，大 decode 桶未必优于专门小桶；长请求比例上升后，粗桶的 padding 和 KV 驻留又会改变比较。

固定 NxD Inference 文档的前缀缓存路径先 gather 块 KV，再转换到 flat 布局计算，最后 scatter 回去；这说明支持共享状态不等于直接使用 PagedAttention。布局转换的准备、读取、写入与驻留要进入该候选，不能把另一 backend 的流量模型直接移植过来。

## 组合轨迹：CPU 多请求生成的完整推导

以下参数全部是可复算设定，不是目标机器或模型实测。任务是固定版本稠密 GQA decoder 文本生成，质量由独立固定前缀 forward 与任务评估判定。8 个活跃交互请求，平均外部到达 2 请求/s，每请求生成 64 token，平均输入 512 token，缓存计算历史上限 2048。客户端 ITL 目标为 60 ms；主机与响应预算暂设 4 ms，真实排队和网络是否满足仍需测量。

硬件设定为一个 32 核、32 GiB 可用主存服务域，主存读带宽模型参数为 96 GiB/s；权重与已选布局合计 3 GiB，固定和临时工作区预算 2 GiB。状态参数为 24 层、4 个 KV head、head_dim＝128、每元素 2 字节。dtype、累加与指令路径仍须由实现确认，不能由权重大小推断。

### 模型与容量

每 token 全层 KV 为 2×24×4×128×2＝49,152 字节，即 48 KiB。2048 token 历史为每请求 96 MiB；8 请求为 768 MiB，权重＋工作区＋KV 为 5.75 GiB，另需页尾、输入输出、在途与保留余量。64 个同长请求的主项为 11 GiB；这只说明所列项未超容量。同域两副本各复制 3 GiB 权重与 2 GiB 工作区，再加总计 0.75 GiB KV，主项为 10.75 GiB。

加载按 [制品与布局](../frameworks/checkpoint-loading.md) 建立固定参数，避免不必要的完整转换副本。[分配器](memory-allocators.md)管理请求状态；初版不必使用共享前缀或分页，连续池与固定块池也可保持相同模型语义，应比较长短混合下的碎片和增长。已输出 token 与已计算 KV 的边界分别记录。

### 三个执行候选

| 候选 | 推进组织 | 主要收益与代价 |
|---|---|---|
| A：逐请求单独执行 | 每次一个请求推进一个 token，再轮转 | 路径简单，权重在请求间重复读取 |
| B：单实例连续批 | 同轮合并 8 个就绪 decode，prefill 受时间预算约束 | 摊薄权重读取，需要批次身份、状态与公平调度 |
| C：同域两个副本 | 每实例处理 4 个 decode | 隔离请求，复制权重与工作区，竞争同域带宽 |

在每次调用读取全部 3 GiB 权重、每请求读取全历史 KV、忽略其他流量的设定下，A 一次流量为 3.09375 GiB，带宽下界约 32.23 ms；8 请求轮转一次约 257.81 ms，无法支持各请求 60 ms 的间隔。B 一轮为 3.75 GiB，下界为 39.0625 ms，相应理想吞吐上界为 204.8 输出 token/s。

C 均分同域带宽时，每实例 48 GiB/s，流量 3.375 GiB，下界为 70.3125 ms，超过目标。两个实例各有独立 96 GiB/s 带宽域时，下界则为 35.15625 ms。副本是否共享资源必须成为条件格；独立域的选择反转也不证明真实时间已通过。

64 请求全进一轮时，权重加 KV 为 9 GiB，下界为 93.75 ms。内存容得下与 ITL 达标是两回事；轮转成多个小批仍有等待其他轮次的时间，admission 不能只按内存上限设置。若目标观测与这些下界冲突，先核对权重是否真的每轮从主存读完、历史读取层级和带宽设定，再作排除。

### 将 prefill、主机和质量接入同一方案

对 B，60−4−39.0625＝16.9375 ms 是理想 decode 下界之外的预算差，不保证真实实现仍有这些余量。计算、额外事务和同步可能先消耗它。需要测混合批时间曲面，再按 [分块 prefill](../algorithms/chunked-prefill.md)选择合法块；所有块均不满足时应调整运行点、准入或资源。

平均到达产生 128 输出 token/s，低于上述理想上界，但还要承担每秒 1024 个新输入 token 的 prefill，所以不能据此断言稳定。分词、调度、响应与输出队列有独立成本和容量；慢客户端、取消与迟到完成都要回传到资源责任账。

CPU 线性层比较无打包与预打包、线程数和 M 形态。B 每轮 M 约为 8，同一权重行可服务多请求。沿输出通道分线程可避免最终归约，沿 K 分线程需要部分和、工作区及同步。线程增多同时改变并行度、NUMA、cache 和争用；主存模型不证明线程越多越快。低位权重还需区分同量化制品的执行正确性和相对原模型的任务质量；字节下降后应重算资源账，不能直接乘理论压缩倍数。

### 一次组合状态轨迹

1. 准入计算唯一 KV、权重、工作区及增长、页尾、输出余量。容量预留不证明 ITL；预留池与池内物化页不重复相加。
2. 选择 8 个就绪 decode，为各请求保留可写尾页与输出槽，建立不可变执行视图，绑定请求生命期、逻辑位置、页映射、结果槽和轮次。共享尾页追加前按所选 COW 方案取得独占写区。
3. 按视图读取权重与各请求历史；39.0625 ms 仍是条件化下界。没有时间上界或有效观测时，候选只处于开放状态；质量也可能尚未知。
4. 完成通知核对轮次与代次，确认必要写入和结果读取达到完成边界，再提交 KV 前沿。到达已知前缀末行、确有合法 logits 且仍有生成配额时，才采样一次；输出按请求和序号入队。
5. 完整 KV 命中却没有末行 logits 时，不得因待算长度为零而永久等待。可以安全重算最后一个已知 token：逐层读取此前历史、在私有暂存计算当前行，不覆盖共享页；也可以使用绑定相同模型与前缀的有效 logits 缓存。已确认输出重放不再次采样。
6. 取消阻止未来业务提交，但不提前释放设备仍读取的页。读者结束后再降低相应执行引用；迟到通知只结算旧轮次，不写回新视图或下一生命期。
7. 若取得 80 ms 的保守客户端 ITL 上界，不能因它超过 60 ms 就排除 B，39.0625 到 80 ms 之间仍含满足目标的值。应收紧上界或取得同作用域观测。
8. 假设某个预先固定的有限回放，其客户端 ITL 最大值测为 55 ms，且计时含主机、排队与交付边界，该证据只证明该回放时间通过。质量 `pass` 才可在这个有限作用域标为 `VERIFIED`；质量 `fail` 排除，`unknown` 保留待验。该 55 ms 不能直接证明总体 p99 或每次未来请求通过。

上述轨迹不包含真实 CPU 性能计数器或 GPU 测量。真实时间受 cache/TLB、事务、线程调度、同步、网络和负载影响，质量需要另行评估。

### 区分实验与反转条件

先用独立固定前缀参考比较完整、分块与增量 forward，再改变 batch 排列、物理槽位、跨页和取消后复用。输出身份与采样状态分别检查；最终字符串相同不足以证明资源回收或取消正确。

性能实验扫描活跃数、历史、prefill 块、线程和副本，记录实际流量、阶段时间、TTFT/ITL、拒绝、超时与队列增长。首次加载和稳态分开，在独立运行或预定区组保留验证。低负载单请求时 A 可能更合适；独立 NUMA 域资源足够时 C 的隔离价值可能占优；长历史主导流量时 batch 的权重摊薄收益下降；离线且放宽 ITL 时可比较更大批与粗 prefill。改变条件后保留状态不变量，重算成本并重新取得适用证据。

## 实例方案要能落到服务和平台

多节点任务的执行组可能受 [集群放置](../workloads/cluster-resource-placement.md)拓扑与故障余量影响；共享制品、缓存和提交记录引入 [存储服务](storage-services.md)的相应语义。它们由候选实现还是环境提供，取决于任务；单机和离线引擎不因此自动增加功能要求。[部署环境](deployment-environment.md)说明真实配额、设备和版本，进程存活、文件存在或空闲卡数各自只提供局部信息。

这些示例通过任务条件、状态、计算、流量、容量、交互与观测解释方案。其他设计可以采用不同表示和组织；没有恢复或请求排队的任务不需要补造对应模块。已有优化可以按需求采用、重组或省略，结论取决于实际前提和证据。

## 设计例子的适用范围与未列路径

上述场景不穷尽架构或设计变量。Task 决定交付的函数、质量、性能与资源边界；一个例子的调度器、状态池、阶段和验证顺序不会自动成为另一任务的要求。独立调度、整体编译、持久执行和其他组织方式应按实际结果判断。

机制依赖与研发顺序不同。消费者需要有效输入，不等于工程上必须先冻结全部接口；可以用独立实验检查成本假设，再联合修正模型、表示、融合边界和调度。验证保留实际覆盖范围，最终按任务验收。

候选可以扩展、组合或全部放弃。新方案没有现成章节或来源实现并不失格；改变表示、硬件能力或任务质量后，原先的排除前提也可能不再成立。阅读来源、符合例子步骤或获得状态标签本身不构成正确或更优的证据。

## 布局改变后的完整成本与反转条件

以下是设定反例。原路径在输入已满足布局时计算 1.0 ms，新 kernel 计算 0.6 ms，但需要 0.5 ms 输入转换；两者串行且不能隐藏时，一次执行为 1.1 ms。同一合法转换结果可复用 R 次时，新路径总成本为 0.5＋0.6R ms，原路径为 R ms，严格获益要求 R>1.25；R＝2 时为 1.7 对 2.0 ms。

上游直接产生目标布局、融合转换与计算或改变状态表示，都会改变成本项。输入每次改变则复用前提失效；转换与其他消费者争用带宽也要重算。该公式判断声明的候选，不排除能改变其前提的新设计。准备时间的保守上界超过收益预算时，同样不能冒充实际一定更慢的证据。

## 区分实验、反证与修正

| 观察 | 竞争解释 | 区分干预与预测 | 反证后的修正 |
|---|---|---|---|
| 命中率上升但队列更长 | 亲和集中；短 query 主机成本；保留页挤占容量 | 控制实际命中边界后改路由；固定命中改 query；固定计算增加容量 | 按真正改变结果的干预修路由、准备或保留策略 |
| batch 增大后 token/s 上升而 ITL 超标 | 权重摊薄；轮转等待；prefill 干扰 | 固定历史改变 batch，分记每轮与请求等待；单独开关分块 | 收窄 batch、准入或阶段组织，不把总吞吐当 SLO |
| 两副本没有加速 | 共享带宽；权重复制；路由集中；锁或输出竞争 | 同流量比较共享域与独立域，记录带宽、份额与等待 | 独立域改善才支持带宽解释，否则检查其余路径 |
| 位宽下降而时间不降 | 解包、转换、归约、fallback；主机准备；事务未降 | 固定形状与质量门槛，分别改变位宽、kernel 与线程，核对实际路径 | 撤回不受观察支持的带宽归因，数值与质量另验 |
| 图重放仍有主机间隙 | 捕获不完整；缓冲更新；输入等待 | 固定请求改变捕获边界，分记 plan/replay，预填输入 | 准备增长则修准备，仍排队则查准入与供给 |
| 上界 80 ms 超目标 60 ms | 上界宽松；实际确实超标 | 取得同作用域观测或收紧上界；50 ms 的合法结果能反驳“上界超标即失败” | 保留开放候选，只有有效失败观测或下界才支持排除 |
| 耗时证据通过但不能认定合格 | 质量失败；质量未知或过期 | 固定候选，用既定独立参考与任务评估裁决质量 | 失败排除当前组合，未知保留待验，均禁止 VERIFIED |
| 观测或上界低于声明下界 | 单位、计时窗、读取层级或缓存前提错误；统计方法失配 | 核对对象与起止，隔离阶段并使用独立计数或参考 | 先转 INCONSISTENT，修前提后重算，不先用矛盾下界删候选 |

实验单位应是独立运行、条件格或预定配对区组，同一运行的相关 token 不自动独立。报告原始到达、完成、拒绝、超时和队列增长；不能只挑成功请求均值。一次干预同时改变 routing、缓存和 batch 时，需控制或报告这些变化。

随章 `tools/check_k_sys_010_full.py` 是标准库、确定性、离线、只读的软件模型。它用独立物理 token 槽集合与逐请求读取枚举核对容量和流量，用有理数核对 CPU 设定算例，再以有限可能耗时集合检验分类。负对照实际执行错误分类分支，包括宽上界当失败、忽略质量、矛盾检查之前按下界排除和下界当通过；集合参考必须拒绝这些结果。检查还覆盖作用域失配、阈值相等、区间跨阈值和直接观测。

该检查不产生统计区间，不证明输入证据真实或区间覆盖有效，不执行真实 forward、异步物理回收、CPU/GPU 性能或质量实验。分类枚举使用有限整数耗时域；另有明确的 39.0625 ms 有理数反例。目标平台的同步、事务、总体尾延迟和质量继续需要相应证据。

## 从推导到 RSI 增量

规划指出链条中最不确定的关系，执行实现对应机制，诊断核对预测与实际状态。进化把新认识写回受影响机制：补足成本、修正恢复条件或组合分支。成功不必产生新条目，更精确理解现有关系本身就是增量。

写回记录对象身份、依赖边、单位、条件格和证据口径。例如共享页降低容量与降低每请求读取是不同命题；保守上界超过目标与实际失败也是不同命题。页表唯一化支持前者的容量关系，广播或片上复用才支持读取去重；同作用域失败观测或下界才支持排除。把局部实验时间差或一个宽松界直接写成通用机制，会把证据范围扩成它未证明的结论。
