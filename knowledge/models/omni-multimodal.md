# K-MODEL-012：全模态系统：多时钟、分支依赖与背压

全模态推理是多个有依赖的计算分支组成的系统；文本、视频和音频不能压成同一个 token 长度。

## 分支和时钟

音频输入有采样时间，视频有帧时间，文本有语义位置，模型内部还有编码块和生成步。多模态位置编码将这些关系映射进模型。接收顺序与事件发生时间可能不同，网络抖动使“先收到的帧”未必代表更早内容，因此对齐需要源时间戳和明确缓冲策略。

Qwen2.5-Omni 的 Thinker/Talker 是一个具体分支例：文本思考分支的中间表示为语音分支提供条件，音频还需进一步解码。分支有可重叠区间，也有必须等待的依赖。把两个分支各自 benchmark 的耗时相加可能高估延迟，取最大值又可能忽略串行依赖。

## 用数据流图安排资源

将每个阶段标出输入可用条件、输出块、持久状态和资源占用。视觉 encoder、音频 encoder、共享主干、文本采样、声学分支和波形解码可以有不同 batch 组织。阶段间队列有容量，慢分支会通过背压影响上游；若只让快分支无限生成，会积累无法及时消费的隐藏状态和输出。

例如文本持续产生而声学解码落后，系统可以限制两者领先距离，而不是让所有文本完成后堆积整段声学条件。限制会影响文本输出速度，属于服务策略，需要与“同步说写”还是“文字优先”的产品语义一致。

## 请求身份扩展到模态块

每个块可由请求 ID、模态、源时间区间、分支、生成代次和块序号定位。跨阶段迁移还要说明其依赖哪个源版本。用户打断后新请求的音频不得接在旧请求的尾部，旧分支的晚到结果要按代次丢弃并完成资源释放。

## 完整质量和性能关系

文字准确、语音自然和图像理解分别良好，不足以证明跨模态对齐正确。文本与语音内容一致、时间戳和帧内容一致、打断后状态连续性都来自数据流关系。首文本 token、首音频包、视频处理吞吐和最终完成延迟是不同指标，应沿真实用户消费的路径定义 SLO。

## 将多模态依赖画成可执行的阶段关系

输入侧保存原始采集时间，媒体处理生成模型规定的块；视觉/音频 encoder 产生特征，Thinker 使用这些特征和已承诺上下文推进，Talker 消费允许使用的 Thinker 表示及文本，再由声学解码生成可播放块。某阶段已经完成，不意味着其下游依赖已经完整；文字先完成也不保证对应音频已可播放。

固定 Qwen2.5-Omni 报告用 2 秒时间块组织音视频表示，并描述音频 block attention 及语音输出的独立 lookahead。它给出了具体数据流依据，但不能由“支持 streaming”推断任意 100 ms 输入都能立即影响输出，或直接推断服务已支持任意全双工打断。下述全双工是需要系统与模型共同满足的设计场景，能力应逐环节验证。

## 场景：视频在场的双向语音交互

设任务持续接收摄像和语音，允许用户在系统说话时打断并开启新回复；输出要求文字与可播放语音内容一致，且已播放旧回复不混入新代次。候选 A 把所有模态等待至一段完整输入后串行处理；B 采用模型允许的分块感知和分支有界流水，共享设备；C 将感知与语音输出分配给不同设备/执行池。A 实现边界简单却增加感知等待；B 有较高复用但争用资源；C 更易隔离播放 deadline，但增加特征传输、常驻权重和放置成本。

按一个模型允许的 2 秒输入区间做假设计账：视觉阶段在某个不能与其他阶段重叠的设备资源上占 80 ms，音频阶段 60 ms，Thinker 120 ms，Talker 40 ms，waveform 阶段 60 ms，共 360 ms/区间。单会话在该资源的平均需求为 18%，八会话为 144%，所以同一串行资源无法稳定承接，即使每条分支单独测量都快于实时。若真实引擎可以重叠部分工作，应按实际共享资源分别计需求，不能无依据地直接取五个时间的最大值。

关键路径的等待还包括块形成、模态对齐和下游缓冲。2 秒输入块的模型契约本身就不支持“从第一采样起 300 ms 内消费整个新块”的承诺；可以报告块完成后的处理延迟，或者选择另一个有更细粒度合法输入的模型。摄像帧以源时间对齐音频，网络迟到策略应明确等待、丢弃过期帧或发布带缺失标记的输入；改变抽帧率会改变模型输入，不能只是把吞吐数字调大。

## 领先距离、优先级与可恢复状态

文字优先产品可以允许 Thinker 领先 Talker；同步说写产品则要限制领先的语义区间。限制应同时覆盖待消费 hidden bytes、声学未解码块、发送队列和客户端未播放时长。让一个分支无限领先，会推高内存和打断后的浪费；过小缓冲又放大网络抖动。两种产品约束应分别测量，不以某个统一 token budget 替代。

在共享设备上，临近欠载的音频块可获得更紧 deadline，但长视觉 kernel 是否可抢占由执行器决定。可比较较小视觉批、限制新视觉工作准入、将 vocoder 独立放置等方案。每个方案都要计传输、权重复制和 CPU 预后处理，不能假定分池后各阶段无代价并行。

请求恢复包需要各分支的共同语义位置，而不是同一个 token 计数：输入源块版本、Thinker 已提交文字、Talker 已消费条件、声学 token/solver 状态、codec lookback、最后已发送及已播放 sample offset。用户打断开启新代次后，旧视觉、旧文字或旧 waveform 的迟到结果不能重新激活原回复。在同一会话中是否保留已听到/看到的旧上下文，应遵守任务语义，而非无条件全部清空或全部继承。

验证将事件时间、接收时间、encoder 完成、文字提交、声学完成、网络到达和客户端播放放在同一轨迹。用可标注的画面事件与声音、重复/乱序块、沉默、打断、慢网络和分支失败测试对齐与最终内容；再报告首文字、首音频、感知更新滞后、欠载、打断残留与最终质量。平均各模态指标通过不能替代同一会话的联合通过。

低并发、权重放置紧张时 B 可能比 C 更合算；感知突发持续损害播放时，C 或更细的准入隔离可能必要；只要求离线总结时 A 仍可能满足目标并降低复杂度。这个选择建立在模型可见性与用户消费时钟之上，不能由一个总 tokens/s 指标决定。
