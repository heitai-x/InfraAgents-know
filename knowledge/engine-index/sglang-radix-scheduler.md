# K-ENGINE-004：前缀复用决策：树、块链与状态保护

前缀复用避免的是相同计算依赖下重复生成状态的工作。索引负责发现候选前缀；恢复资格、读取保护和容量承诺决定当前请求能否真正使用它。把这些责任压缩为一个“命中”布尔值，会同时掩盖身份错误、缺少末行输出、提前回收和超额准入。

SGLang 的 RadixAttention 提供了一个具体实例：CPU 上的压缩前缀树映射到分页 KV，活跃路径受引用保护，缓存从无保护叶子开始淘汰，调度顺序利用共享前缀。下面展开一种保守的串行协调模型。它借用这些机制，但不声称是固定提交的原样接口或完整并发实现。

## 等价、状态与恢复资格

固定影响状态生成的条件 η，包括模型与权重版本、规范化输入、adapter、位置与窗口规则、外部特征、数值表示合同，以及隔离命名空间 ns。请求已知 token 为 x[0:n)。S(p) 表示消费 x[0:p) 后，继续计算所需的全部状态；p 不是输出 token 数、已提交工作数或已分配槽数。

普通因果 decoder 的 S(p) 包含必要层和分片的历史 K/V。窗口、递归和外部控制状态可能只在离散位置可恢复。设索引匹配长度为 m，各状态族的恢复集合为 Rᶠ，任务允许的位置集合为 I，则合法位置满足

p∈{0,…,m}∩I∩⋂Rᶠ。

分别取各族最大值再取最小值，一般不能得到这个交集。例如 {0,4,8,12} 与 {0,6,10} 的共同位置只有 0，不能返回 10。位置 0 也必须具有合法初始化路径；不可重建控制状态丢失时，恢复集合可以为空。

只有 KV、没有合格末行 logits 的普通生成请求，需要处理最后一个已知输入位置。因此 I 还要求 p≤n−1；重算区必须私有，不能覆盖共享页。n=8、仅完整四 token 页可共享时，恢复上限是 4；n=9 时可到 8。单 token 输入需要从 0 计算；空生成输入由接口拒绝或补充合法起始输入，不能从空 KV 自动取得下一 token 分布。另有同合同 logits 或继续票据时，可以采用不同上限。

树、固定块链和直接重算都是方案选择。树便于表示多级公共前缀及边内分叉；块链令当前身份依赖父身份和本块内容，适合固定粒度索引；直接重算减少目录维护和长期驻留。三者都必须满足计算等价、共同恢复、写入隔离和最后使用条件。

## 树边、物理页与切分顺序

为完整解释树操作，本节选择单 token 页、不可变缓存内容、同一协调者串行修改目录的模型。每个非根节点 v 保存：本边 token 标签 label、按相同顺序排列的页句柄 pages、父节点、按首 token 索引的 children、保护票据集合 H 和访问时间 last。根标签和页列表均为空；不同 ns 使用不同根。

根到 v 的标签连接是完整逻辑前缀。本边 pages 只保存父前缀之后的新增状态；父路径与本边拼接，才构成到 v 的历史。本模型每个物理页只属于一个缓存边，多个请求共享该边，不再复制页内容。真实多 token 页、量化组或混合状态的切片资格需要另外证明。

保护票据保存取得时的不可变节点路径。H 的大小可以缓存为引用计数，但重复完成只能结算自己的票据。保护从取得读取资格开始，保持到该责任覆盖的最后实际访问结束；业务取消不能提前撤销它。缓存目录保留与请求私有页、在途访问分别记账。

一条 abcd 边在第二个 token 后切分，应成为 ab→cd，页 [10,11,12,13] 分成 [10,11] 与 [12,13]。物理内容不变。父索引仍以旧标签首 token a 指向原节点，必须先按旧身份摘除，再修改标签，否则摘除操作会拿新首 token c 查找旧索引。

```pseudocode
算法 SPLIT_IDLE_EDGE(child, k)
输入：无保护子边，0<k<len(child.label)，合法状态切片边界
输出：公共前缀节点 u；原 child 成为剩余后缀

在目录协调区内：
    要求 child.H 为空，必要状态确实支持此切片
    parent ← child.parent
    old_label ← child.label；old_pages ← child.pages
    old_key ← old_label[0]
    要求 parent.children[old_key] 恰好是 child
    从 parent.children 删除 old_key
    建立 u，标签 old_label[0:k]，页 old_pages[0:k]，H 为空
    child.label ← old_label[k:]；child.pages ← old_pages[k:]
    把 u 按旧首 token 挂到 parent
    把 child 按新首 token 挂到 u
    继承合适的访问时间；核对父指针、索引和页顺序
返回 u
```

切分后每条边非空，兄弟首 token 不同，所有完整前缀到页的映射保持不变。复制页句柄列表可能需要 O(边长) 主机工作；只有标签和页序列采用切片视图时，切分描述修改才可近似 O(1)。不能把“没有复制 GPU KV”写成“没有元数据成本”。

本章禁止原地切分 H 非空的边，避免旧票据仍指向旧边、祖先保护却未继承。合法替代是使用已有节点边界、暂缓缓存插入，或采用另有完整引用继承协议的实现。等待必须离开协调区，让完成事件能够释放保护。

## 查询、保护与完成发布

只读查询逐边比较 token，返回原始 LCP 长度 m，不改变树。保护阶段再选合法恢复位置；活跃边内部的位置在本保守模型中不可物化，已有边终点仍可使用。恢复集合有空洞时应向下枚举合法交点，不能先任取一个长度再伪造对应检查点。

```pseudocode
算法 ACQUIRE(ns, x, I, {Rᶠ}, ticket)
输入：身份相容的命名空间、已知输入、恢复资格、唯一保护票据
输出：p、状态清单、取得时的路径；或无合法恢复位置

在目录协调区内：
    从 ns 的根开始，按首 token 定位子边并逐 token 比较
    完整匹配则下行；缺边、分歧或查询结束时停止，得到 m
    枚举不超过 m 的共同恢复位置，由大到小尝试：
        已有节点边界可以使用
        边内位置只有在状态可切片且该边 H 为空时可以使用
        找到第一个合法位置 p；没有则返回失败
    若 p 在空闲边内部，执行 SPLIT_IDLE_EDGE
    形成根到 p 的节点路径和完整状态清单
    再核对真实页身份、代次、有效范围及消费者就绪关系
    为路径每个节点加入 ticket，记录不可变的取得路径
返回 p、清单、取得路径
```

索引中有 token 不代表全部层已经完成，READY 也不代表任意设备已经可见。本章树模型要求公开节点的状态完整且不可变；远端恢复、转换和跨 stream 可见性须先满足相应协议，才能进入上述清单。

插入只接收真正完成到 k 的状态 x[0:k)，不把已经采样但尚未计算自身 KV 的最后 token 算入 k。新节点应在完整范围核验之后一起公开。已有公共部分继续使用原目录页，重复计算的副本可以由当前请求暂时持有，不在活动执行期间强行改写其页表。

```pseudocode
算法 PUBLISH_COMPLETED(ns, x[0:k), completed_pages)
输入：全层完成且不可变的状态；其私有副本仍受拥有者保护
输出：缓存发布成功，或保留私有状态的 DEFER/失败

核对全部必要状态、表示、范围和发布资格；失败不修改目录
在目录协调区内，从根逐边匹配：
    没有下一子边：预建完成后缀节点，再将其挂入目录，结束
    完整匹配子边：下行并推进位置
    在子边内部结束或分叉：
        若子边 H 非空或状态不可切片：返回 DEFER，目录不变
        执行 SPLIT_IDLE_EDGE，得到公共节点
        若仍有新后缀：挂入预建的完成后缀节点
        结束
    全部状态已经存在：保留已有目录页，结束
更新此次实际访问路径的 last；交接新增缓存页的保留责任
返回成功

算法 END_HOLD(ticket, 最后使用证据)
核对证据确实覆盖 ticket 的全部访问
在协调区内：
    若 ticket 已结算：幂等返回
    沿 ticket 取得时保存的路径，恰好一次地移除 ticket
    标记 ticket 已结算
```

发布过程中可能细化目录或新增后缀，因此不能重新匹配完整请求，再把新路径当作旧保护路径释放。旧请求只取得 ab 的保护，发布后出现 abx；若沿新路径释放，会错误结算从未取得的 x 节点。未发布的重复私有页也不能因目录已有等价对象而提前释放，仍需等待其真实读写结束。

DEFER 不阻止已经完成的业务结果提交。当前请求可继续持有私有状态，在保护释放事件后重试缓存发布，或放弃本次缓存；不能在唯一协调线程中阻塞等待同一线程才能处理的完成。

## 叶淘汰、实际分配与一条组合轨迹

缓存叶只有在 H 为空、没有其他物理使用责任且内容允许丢弃时才能释放。先撤销可发现性，再释放目录持有；物理页满足全部责任结束条件后才进入空闲集合 F。last 决定合法候选的排序，不能覆盖保护资格。

```pseudocode
算法 EVICT_UNTIL(target_free, F)
当 |F|<target_free：
    寻找非根、无子节点、无保护和其他使用责任的缓存节点
    没有候选：返回容量不足及阻塞责任
    选择 last 最早者；同分使用稳定顺序
    按旧父索引摘除节点，撤销其缓存身份
    释放已满足物理回收条件的页，加入 F
    父节点可能成为下一轮合法叶
返回成功
```

当前叶集合不等于最终可回收集合。例如 ab→cd 都无保护，当前叶只有 cd，但淘汰 cd 后 ab 也能回收。本模型路径保护覆盖所有祖先、缓存页没有其他拥有者时，所有 H 为空的非根节点页都可以通过叶优先顺序最终回收。若另有读者、图绑定或恢复责任，必须从这个集合排除。

缓存感知排序只决定尝试顺序。每个请求本轮仍需取得具体私有页；保护共享页不会再产生一份同样大小的物理分配。

```pseudocode
算法 TRY_ADMIT(req, q, F)
输入：合法正工作范围、本轮私有写区与暂存需求、目录及页池
输出：取得的共享保护和具体新页，或无副作用的准入失败

在同一目录/页池协调事务内：
    调用 ACQUIRE，得到实际 p 和保护票据
    按该 p、q、COW、暂存与输出计划计算新增物理页需求 s
    E ← 本次保护之后仍能安全淘汰并释放的唯一物理页集合
    若 s>|F|+|E|：撤销本次尚未启动访问的保护，返回不足
    模拟并核对足量叶淘汰；不能预支尚未排空的页
    必要时执行淘汰，使 |F|≥s
    从 F 取 s 个具体页，交接为本次私有预留
    保存 p、原始保护路径、页身份和冻结执行范围
返回成功
```

若维护“空闲加可淘汰”的预算，新增保护使一部分旧冷页退出 E，需要扣除这一增量。但这一扣减是可用预算的变化，不能把它再加入 s 并分配成新页。多个请求保护同一祖先时，只在该页第一次从可淘汰转为受保护时改变预算。

取单 token 页、六页物理池，每页全层 KV 为 128 KiB。以下均为符号设定，暂不计权重和工作区：

| 事件 | 缓存、保护与私有状态 | 物理结果 |
|---|---|---|
| 初始 | 缓存 abcd 在页 0、1、2、3 | 页 4、5 空闲，缓存 512 KiB |
| B 输入 abx | 在 2 处切为 ab→cd；B 保护 ab，私有 x 取得页 4 | 共享页 0、1 只计一次；页 5 空闲 |
| D 输入 uvw | 需要三个私有页；cd 无保护 | 淘汰 cd 的页 2、3，D 取得 2、3、5；六页全部占用 |
| B 在途取消 | 关闭 B 的新业务提交，旧读取和私有写入尚未结束 | 不能释放 0、1、4；此时没有额外空闲页 |
| B 最后访问结束 | 结算原取得路径；若取消不允许发布，放弃私有 x | 页 4 可回收；ab 仍可由目录保留 |
| 再查询 abcd | cd 的旧身份已经撤销 | 最多命中 ab，不能读到页 2、3 上 D 的新内容 |

取消后私有 x 不发布，是本轨迹的业务选择。正常完成且仍有发布资格时，也可先把完成的 x 交给目录，再结算 B 原先取得的 ab 路径；新增 x 的缓存责任与旧保护票据不是同一责任。

D 的准入需要 3×128=384 KiB 新页，其中 256 KiB 来自实际淘汰，128 KiB 来自原空闲。若把 B 的 256 KiB 共享页当作可分配容量，就会覆盖仍被读取的状态；若把它作为新增私有分配再次扣账，则会错误拒绝本来可行的 D。

## 调度收益、离线结论与条件化成本

固定论文按匹配前缀长度优先组织等待请求。这里应区分一次快照排序与每次选择后更新命中长度。它们在变化中的缓存上不是同一个算法。

例如缓存容量为三 token，三个静态输入依次为 abc、xyz、abq，初始都未命中。只在初始按零命中及到达顺序排一次，会计算 9 个新 token；处理 abc 后重新匹配，下一条选择 abq，再处理 xyz，只计算 3+1+3=7 个新 token。这也是该请求树的七条单 token 边。

固定论文的离线定理限定同一已知请求集合、缓存容量至少为最长请求路径，以及证明中的访问与淘汰模型。每条边至少计算一次，DFS 使公共祖先在子树访问期间保持可用，从而达到新建 KV 工作量下界 Σ|edge|；动态最长共享前缀优先可对应某个 DFS 顺序。这个下界不是总 Attention FLOPs 或墙钟时间的无条件下界。未知输出、在线到达、并行在途、末行重算及公平限制都会改变设定；一次初始排序不能直接继承该定理。

在线调度可以在每轮或每次选择后更新候选匹配，再按实际可恢复 p、到达与服务合同排序。每个候选本次至多尝试一次；失败记录容量、状态或结构阻塞，继续扫描其他请求。持续到达的长共享前缀可能使短请求饥饿，应加入等待老化、租户份额或 deadline，并重验收益。命中率高不保证完成时间最短。

设 W 个等待请求、最大输入长度 n、E 个树节点。逐请求匹配约需 O(Wn) token 比较，散列表定位子边还依赖通常的散列假设；一次排序 O(W log W)。每选择一条都全量重算，最坏达到 O(W²n)。路径保护和结算与经过的节点数相关。每次淘汰重新扫描 E 个节点、共淘汰 R 个节点时，最坏 O(RE)，不能只写成一次 O(E)。维护叶堆可减少扫描，但增加候选失效、父节点入堆和引用更新成本。

对普通稠密 causal decoder，复用 p 后处理 q=n−p 个输入，必要 query-key 对数为

V=pq+q(q+1)/2=n(n+1)/2−p(p+1)/2。

对 L 层、Hq 个 query head、键值维度 dₖ、dᵥ，QK/PV 主项为 2LHq(dₖ+dᵥ)V FLOPs，另计 softmax、投影和 MLP。suffix 仍读取前缀，不能把命中比例 p/n 直接当成整个 forward 的时间节省比例。

| 成本 | 本章机制实际增加或保留的工作 |
|---|---|
| 计算 | token 比较、资格求交、切边、排序、淘汰与剩余模型计算 |
| 访存 | CPU 标签和页句柄访问、设备描述准备、suffix 对历史 KV 的读取及必要 COW |
| 通信 | 本地树修改不需要 KV 网络传输；分片协调、远端恢复与输出传输按实际路径另计 |
| 准备 | 身份核验、共同恢复清单、页计划、候选更新和具体预留 |
| 同步 | 查找到保护的协调、状态就绪、发布、最后访问与回收；不能在协调者内阻塞完成处理 |
| 驻留 | 唯一缓存页、私有页、暂存、未排空页和目录；共享引用不重复计页 |

物理共享降低唯一驻留，不自动消除各请求对公共 KV 的读取。是否减少 HBM 事务，需要目标内核与缓存行为的证据。多 token 页会减少表项，却增加尾部重算、COW 和淘汰粒度；量化会降低载荷并增加参数、封组和转换条件，不能沿用单 token 页的任意切分假设。

从同一请求可开始决策计到同一正确结果，串行估算可以写成

T_reuse(p)=T_lookup+T_acquire+T_wait+T_suffix(p)+T_publish。

重叠执行按依赖和共享资源求关键路径。驻留机会成本属于保留策略的目标账，不能无依据地当作额外 TTFT 相加。若需统一比较，必须显式将容量时间或被阻塞工作换算成同一目标单位。

设定一个长前缀请求冷路径 46 ms，合法命中路径的匹配保护 0.3 ms、suffix 6 ms、发布 0.1 ms，且没有额外等待，总计 6.4 ms，节省 39.6 ms。另一个短请求冷路径 2.5 ms，命中路径为 0.3+2.3+0.1=2.7 ms，应考虑重算。全部数值是条件化事件账，不是 GPU 测量。

前缀变短、重用距离增加或版本频繁改变时，可减少缓存保留；热点使亲和节点排队增加时，可复制、改路由或重算；容量不足时可缩小合法 q、等待或拒绝，但不能撤销仍在使用的保护。状态族或表示改变时，应重建恢复集合与切片资格，而不是只调整命中长度。

## 反例、区分实验与检查范围

| 观察 | 竞争解释 | 区分干预与反证后的修正 |
|---|---|---|
| 切分第一条边即索引失败 | 改标签后按新首 token 摘旧索引；或父指针损坏 | 固定 abcd→ab/cd，逐步核对旧索引、父指针和完整前缀到页映射；先摘除再改名仍失败时查连接关系 |
| 相同 token 得到错误内容 | ns、adapter 或位置身份遗漏；或旧页被复用 | 只改变一个参与前向的条件，再单独禁用物理复用；分别检查命中位置与实际页内容 |
| 完整命中后没有后继事件 | 缺末行 logits；或没有共同恢复点 | 固定输入，显式给出恢复集合及末行票据；合法末段重算恢复进度后，再讨论排序 |
| 发布后引用不平衡 | 沿新匹配路径释放旧保护；或重复完成 | 取得 ab 后发布 abx，再结算旧票据两次；第一次只能释放原路径，第二次无变化 |
| 准入预测有空间，实际分配失败 | 保护页仍算冷页；尚未排空的页被预支 | 延迟一个读者并施加页压力，比较预测集合、真实叶淘汰与具体空闲页；预测失败先修容量账 |
| 空间充足却拒绝 | 共享保护重复计作新分配；只统计当前叶 | 保持工作不变，展开唯一页并集和逐叶回收；若释放子叶后父页可用，修正可回收集合 |
| 命中率升高，尾延迟恶化 | 贪心饥饿；或热点排队和长历史读取 | 固定到达、输入与取消轨迹，只改变排序或路由；记录每请求等待、实际跳过计算和阶段时间 |

检查应让正常模型和缺陷变体走同一轨迹与审计条件。切边参考采用独立的“完整逻辑前缀→物理页”平面映射；LCP 用逐前缀枚举得到期望；保护审计根据外部记录的逻辑持有终点重建所需祖先，不以实现保存的路径定义正确答案。容量审计核对缓存、私有分配和空闲页的互斥并集。

随章 tools/check_k_engine_004_full.py 覆盖插入顺序、边内分叉、查询恰在边内结束、空查询、根处分叉、命名空间、活跃边延迟插入、恢复交点与末行上限、叶递归淘汰、具体页分配和重复结算。故障变体包括原先的改名后摘除、遗漏祖先保护、淘汰受保护节点、把保护页计为可用容量，以及发布后沿新路径释放旧票据。

这些是确定性 Python 标准库 CPU 符号检查的范围。它不计算数值 K/V 或 logits，不执行真实 SGLang、GPU、DMA、allocator、并发锁或跨设备可见性，不测性能和服务 SLO，也不证明知识改善 Agent 的使用效果。实际执行结果由绑定当前脚本及输入的真实记录承担。
