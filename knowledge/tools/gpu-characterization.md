# K-TOOLS-008：GPU 从零表征：可持续带宽、矩阵吞吐与测量条件

资源模型里的带宽、算力和提交成本应来自目标设备上、与服务形态匹配的测量；铭牌峰值、异代结果和未声明条件的单次最高值不能直接代入。从零表征是在辨识一个带条件的资源参数包。能力表与 compute capability 事实见硬件章节，本章不列 CC 差异表。

## 表征对象、条件身份与合法性

一次测量绑定条件元组

`c = (设备与介质, 主机拓扑, 驱动与运行时, kernel 或库路径, dtype 与 shape, 访问形态, 工作集与缓存状态, 并发与共置, 时钟与功耗状态, 计时边界, 持续时长)`。

输出是带条件谓词的参数条目

`p = (名称, 数值, 单位, 适用条件, 不确定范围, 证据身份)`。

顺序大块读、跨步随机读、L2 命中路径、矩阵指令路径、主机设备链路和短 kernel 提交是不同资源轴。一个条目只有在其适用条件被当前 workload 满足时才能进入成本模型；条件不满足时应重测、换条目或保留未知。把顺序读参数用于不规则 KV 读取，或把 L2 命中后的表观速率当作 HBM 带宽，都会改变参数身份。

对指定边界、方向和请求集合，定义消费者有效需求字节 `D_use`、实际事务字节 `D_tx` 和完成时间 `T`：

`B_use = D_use/T`，`B_tx = D_tx/T`；`D_use > 0` 时，事务放大为 `A = D_tx/D_use`。

有效需求按实际消费者请求累计，重复读取同一地址可以多次贡献需求；它不等于唯一对象容量。事务字节则按所选边界上的传送计量。两者必须具有兼容的请求范围和时间窗；上层逻辑请求字节与下层 DRAM 字节的比值混入缓存复用，不能直接称为同一层的合并效率。

若有效负载 128 B 被拆成 160 B 事务，匹配模式的有效带宽与事务带宽应给出同一时间：`D_use/B_use = D_tx/B_tx`。把 160 B 再除以已经包含放大的有效带宽会重复惩罚；把 128 B 除以事务带宽则遗漏放大。没有匹配事务计数时，可以直接使用匹配访问形态、缓存状态和并发条件的有效带宽，不能一边使用这种有效带宽，一边再扣一次同一缓存收益。

计算侧定义 `F` 为按声明规则得到的有效算术工作，`P_eff = F/T`。矩阵乘通常按一次乘加为 2 FLOPs 计主项；padding、重复计算、指数、解包和转换另列，不能未经说明一起除以矩阵峰值。

计时边界也属于量的身份：host API 返回、设备事件完成、输出消费者完成和完整请求完成是不同事件。CUDA API 可以异步返回，host 计时若未与设备完成对齐，会遗漏尚未完成的工作；设备事件也可能不覆盖输出复制与消费者。只有边界相同的量才能相减、相除或用于对照。

合法性条件包括：被测工作确实完成；分子与分母属于同一执行范围；计时区没有未声明的分配、首次缺页或额外同步；工作集、缓存状态、并发和时钟策略已记录；重复观察没有显示相关的强非平稳性。冷 cache 与热 cache 都可以测量，但应分别标记。锁定时钟是一种实验选择，不保证目标服务拥有相同功耗和散热条件。

单次最高值不能代表可持续参数。应保留重复层级、范围或离散程度，并区分短窗 boost 与长窗可持续点。实际有效速率是带条件的估计，不是数学上不可突破的硬件上限；它不能单独证明某个 kernel 已达到设备极限。

## 从测量计划到参数包

表征的状态链是：计划已定义 → 输入已准备并预热 → 样本已采集 → 条件与分母已核对 → 交叉条件已检验 → 条目已发布或标为未决。失败或未决条目保留原因，不能悄悄用默认峰值补洞。

```pseudocode
算法 CharacterizeDevice
输入：设备与拓扑身份；服务形态集合；访问形态与 shape 网格；时间与存储预算
输出：带条件标签的参数条目；未决原因；下一项区分实验

1 固定设备、驱动、运行时、kernel 或库路径、计时边界和并发集合
  记录实际内存介质、链路属性、时钟策略、功耗模式和机箱条件
2 为每个资源轴选择能区分解释的条件：
  顺序与跨步；工作集小于与大于 L2；dtype 与 shape 角点；
  单向与双向链路；消息大小；消费者数量和干扰强度
3 建立有效输入；分离首次分配、首次缺页、预热和统计区间
  需要冷 cache 时采用明确策略，并记录其范围与成本
4 对每个条件采集重复样本：
  完成时间、有效字节或 FLOPs、事务字节（若可取得）、
  时钟、功率、并发、输入输出身份、失败与未完成状态
5 核对完成边界、字节边界、方向、单位和工具采集环境
  拒绝零或负时间、分母缺失、未完成工作及必要条件缺失的速率样本
  空工作保留为空工作，不发布由零工作推得的设备能力
6 按相同范围计算 B_use、B_tx 或 P_eff
7 改变一个相关条件做交叉对照：
  扩大工作集削弱复用；改变跨度改变请求段；
  改变并发观察份额；延长负载观察漂移；改变方向观察链路共享
8 预测随干预得到支持时，保留条目及其条件谓词
  多个解释仍不能区分时，保存原始证据和未知项，不发布单一常数
9 将条目连同环境、方法、重复范围、证据身份和日期交给观测记录
  服务条件改变时重新选择或测量，保留旧条件的历史身份
```

候选先变成测量工作，再变成原始样本、按边界计算的速率，最后才是参数条目。`D_use`、`D_tx`、`F` 和 `T` 在这一链中不能换轴或换名。流程不要求每项都取得计数器：缺少事务证据时，可以发布明确口径的有效速率，同时保留事务解释未决。

测量自身也有成本。输入生成、重复计算与访存、主机设备搬运、预热与捕获、完成同步、工作集与日志驻留都会消耗预算。增加重复次数也可能改变热状态；统计区间变长不能自动保证条件保持不变。

## 可持续主存带宽：顺序、随机与事务粒度

设备主存可能使用 HBM 或 GDDR，应说明实际介质。顺序大块读、跨步随机读、读写混合和不同粒度得到的参数不同。将其中最大值作为所有路径的带宽，会低估不规则访问成本。

固定 CUDA 12.8.0 来源说明对 CC≥6.0 给出 32 B 请求段模型。32 个 lane 各读一个 32-bit 字，地址为

`addr(λ) = base + o + 4λ`，`λ = 0,…,31`。

每个 lane 的字节区间为 `[addr(λ), addr(λ)+4)`，请求段集合是这些字节的 `floor(address/32)` 并集。`base` 按 32 B 对齐、`o=0` 时，128 B 有效负载覆盖段 0…3；`o=4` 时覆盖段 0…4。若地址改成 `base+8λ`，32 个字覆盖段 0…7。尾部 mask、不同元素宽度和跨段元素须重新枚举实际字节区间。

这里数的是一次访问覆盖的请求段，尚不是最终 HBM 事务。相邻 warp 对过取数据的复用、L1/L2 命中、请求合并和写路径会继续改变下层字节；不能从五段直接断言目标 HBM 字节或时间比四段增加 25%。

设定算例：工作集 8 GiB，顺序读可持续 1.0 TiB/s，同设备同工作量的 128 B 跨步随机读取有效速率为 0.35 TiB/s。将后者需求代入前者，会把时间估值压低约 2.9 倍。这里是设定计算，不是某卡实测。

测量应固定读写方向、元素宽度、对齐、跨度、工作集、并发和完成边界。接入资源模型时，至少区分顺序权重读取与不规则 KV/索引读取；混合并发是否能沿用分项参数，还须核对共享控制器与混合访问曲线。

## L2：有效未命中需求与主存事务

L2 复用可能减少主存填充，但实际 HBM 字节不保证小于张量逻辑读取字节。稀疏读取可能有过取；大量热态重复读取又可能使逻辑需求远大于填充。必须分别命名请求、有效未命中需求与实际事务。

选择一个只读边界：请求已到达 L2，已排除上游命中所过滤的请求，并在同一窗口内累计这些请求的有效字节 `D_L2,use`。令其中由 L2 已驻留数据满足的有效字节为 `D_L2,hit,use`；部分命中须按实际覆盖字节拆分。由定义可得

`D_L2,miss,use = D_L2,use − D_L2,hit,use`。

这个减法仅建立有效未命中需求账。只有已确认全部剩余读取由本地 HBM 提供、没有其他缓存或 peer/主机路径满足它们时，才将它记为 `D_HBM,use,read`。如果从张量逻辑读取开始记账，还应先处理上游过滤，不能只减 L2 命中。

实际 HBM 读取事务字节另记 `D_HBM,tx,read`。从有效未命中需求到事务量，还要经过请求合并、填充粒度、过取、重复请求与在途合并、预取及压缩等机制。写回与写分配也不能混进只读减法；若观察的是读写总事务，应另外记入相同时间窗的写交通与其他消费者。L2 计数不能自动归因为单个消费者的 HBM 需求。

将 `D_HBM,use,read` 与 `D_HBM,tx,read` 直接设为相等，需要明确的简化假设：剩余请求全部访问本地 HBM；需求与事务采用相同方向和时间范围；每次有效未命中需求恰对应一次相同大小的传送；没有过取、额外预取、压缩、重复请求合并或未归属交通。真实计数不满足这些条件时，应独立取得事务量。

反例采用一个人为指定的串行只读模型：初始 L2 冷态，无其他层命中、无压缩、无预取、无写回；每个缺失的 32 B 段完整填充一次，填充完成后保留，期间不逐出。只读地址 0 的一个 4 B 字时：

`D_L2,use=4 B`，`D_L2,hit,use=0`，`D_HBM,use,read=4 B`，`D_HBM,tx,read=32 B`。

若这个模型的事务服务带宽为 32 B/s，填充需 1 s；错误地用有效未命中需求除以事务带宽会得到 0.125 s。匹配该稀疏形态的有效未命中需求带宽为 4 B/s，同样得到 1 s。这是用于区分口径的离散反例，不声称真实设备 HBM 对一个字必定进行 32 B 物理传送。

该模型可以按如下状态变化重建：

```pseudocode
算法 ReadFillLedger
输入：顺序执行的读取区间 (address,size)；初始有效段集合；段大小 G>0
输出：有效请求、命中、未命中需求、填充事务字节；填充序列

初始化 valid 为初始有效段集合，各字节账为零
对每个读取区间：
  拒绝负地址或负大小；size=0 时继续
  枚举与 [address,address+size) 相交的段，按地址递增处理
  对每个相交段 s：
    u=读取区间与该段的相交字节数
    请求有效字节 += u
    若 s 属于 valid：命中有效字节 += u
    否则：
      未命中有效需求 += u
      事务字节 += G；记录 s 的一次完整填充
      等待该填充完成，将 s 加入 valid
  本请求完成后，才处理下一请求
要求：请求有效字节 = 命中有效字节 + 未命中有效需求
返回账本；不将未命中有效需求自动改名为事务字节
```

对四次顺序读取同一完整 32 B 段，该模型得到请求有效字节 128 B、命中 96 B、有效未命中需求 32 B、填充 32 B。若仅计一次填充的 1 s 服务时间，表观速率为 128 B/s，事务速率为 32 B/s。把表观速率当作 HBM 事务带宽，再除填充量，会错误得到 0.25 s。真实 L2 命中自身仍有延迟与吞吐成本；这个简化服务模型只隔离字节身份错误。

真实表征可扫描明显小于和明显大于估计 L2 的工作集，并固定地址流、复用距离、并发和计时范围，记录命中相关信号及 HBM 事务。工作集越过竞争后的有效容量可能出现拐点，但不保证突变，也不保证大工作集自动消除全部复用。Nsight Compute 的 replay 与默认 cache 清理会改变观测条件，应与正常热态服务分开解释。

设定某读核在 8 MiB 工作集的表观速率为 2.5 TiB/s，在 2 GiB 工作集下降到 0.95 TiB/s。重扫数 GiB 权重的服务应选后者或更匹配的参数；热激活则建立自己的请求、命中与事务账。采用事务模型时用 `D_HBM,tx/B_HBM,tx`；采用匹配形态的有效模型时用 `D_use/B_use`。不能既减掉命中，又使用已经包含该命中收益的全请求有效带宽。

## 各 dtype 与 shape 家族的矩阵吞吐

矩阵能力随 dtype、累加精度、布局、M/N/K、实际矩阵指令路径和资源驻留变化。FP16 峰值不能外推到 INT8 或 FP8；同一 dtype 下小 M 的 decode 形与大 M 的 prefill 形也不共享一个无条件参数。

测量应声明库或 kernel 路径、数值合同、输入是否已在设备、计时是否包含 host 打包与布局转换，以及 shape 网格怎样覆盖目标服务。吞吐按有效 FLOPs 除以匹配的完成时间计算；同时记录 padding、转换、自动调优和一次性权重打包。源码声明支持某 dtype，不能证明本次 dispatch 使用了预期矩阵路径。

设定某形态 BF16 GEMM 可持续 150 TFLOP/s，同设备 FP32 为 40 TFLOP/s；M=1 的 GEMV 又可能远低于大矩阵吞吐。将大矩阵参数代入 batch=1 decode，会低估计算时间。若图桶增加实际执行行，设备工作也应随之重算，不能只按有效行估值。

接入资源模型时建立 `P(dtype,shape_family,layout,path)`，与匹配边界的带宽共同使用。低吞吐可能来自 shape 太小、路径回退、资源驻留或降频；应通过固定 shape 核对 dispatch、分离转换、延长负载与记录时钟来区分。

## Launch、图重放与提交边界

大量短 kernel 时，主机提交、依赖解析与空档可能进入关键路径。设每轮 eager 路径有 `K` 次提交，单次主机提交与分派成本约为 `h`，则主机工作 `H_eager=Kh`。图重放的主机提交成本记为 `H_graph=g`；相同语义的共同设备工作记为 `D`。`g` 不是图中设备工作的执行时间。

主机与设备能够充分重叠时，稳态周期可近似为

`T_eager ≈ max(H_eager,D)`，`T_graph ≈ max(g,D)`。

这些是周期模型，不能无条件当作单请求延迟。若本轮设备工作必须等待本轮提交，或下一 token 的主机准备依赖上一 token 结果，相应串行段应按依赖相加；有限流水的启动与排空也要另列。降低 host API 时间只有在它缩短关键路径时才改善完整 ITL。

设新增捕获、实例化和准备成本为 `C0`，共同首尾成本为 `C_common`。在按上述固定周期计费、共同首尾成本相同的设定模型中，完整总账为

`T_eager,total(N)=C_common+N T_eager`，

`T_graph,total(N)=C_common+C0+N T_graph`。

若 `Δ=T_eager−T_graph>0`，打平点为 `N*=C0/Δ`，严格收益要求 `N>N*`；整数调用数应选择严格大于该比值的首个整数。`Δ≤0` 且 `C0>0` 时，增加复用次数不能回本。真实首尾、更新、排空或重新捕获成本不同，就应分别加入两条总账后重算。

设定 eager 每轮 80 次 launch，每次主机提交成本 15 μs，故 `H_eager=1.2 ms`；图重放主机提交成本 `g=0.2 ms`。两条路径共同设备工作取 `D=0.8 ms`，不是 0.2 ms。在充分重叠的周期模型中，每轮分别为 1.2 ms 与 0.8 ms。取 `C0=10 ms`，共同首尾项在比较中抵消：

| 调用轮数 | eager 总账 | 图总账，含捕获 | 结论 |
|---|---|---|---|
| 24 | 28.8 ms | 29.2 ms | 图多 0.4 ms |
| 25 | 30.0 ms | 30.0 ms | 打平 |
| 26 | 31.2 ms | 30.8 ms | 图省 0.4 ms |

因此本例约 25 轮是打平点，严格收益从第 26 轮开始。若两条路径共同设备工作改为 12 ms，周期均为 12 ms，图总账始终多出 10 ms 捕获成本；不能把减少的主机提交再当作设备执行收益。若 12 ms 只是 HBM 项的估计，它也不允许同时把同一整段设备工作宣称为 0.2 ms。

以上数值都是设定计算。真实图若改变 padding、kernel 变体、布局或同步，应分别使用 `D_eager` 与 `D_graph`。地址、shape 或绑定失效时，稳态 replay 参数不能覆盖重新捕获、桶切换和旧图排空。具体捕获与缓冲合法性见图章节。

## PCIe 或其他主机设备链路：方向与双工

链路有方向、复制引擎能力和共享上游。设 H2D、D2H 字节为 `V_H2D`、`V_D2H`。若两条复制串行，时间为

`T_serial=V_H2D/B_H2D+V_D2H/B_D2H`。

若两个方向可以独立并行，而且使用的是相同双工条件下的每方向可持续速率，则理想完成时间为

`T_duplex=max(V_H2D/B_H2D,duplex, V_D2H/B_D2H,duplex)`。

只有实验证实两个方向能同时保持各自单向速率时，才能把单向参数代入这个式子。直接计算总字节除以两个单向峰值之和，还隐含负载比例与容量可同时取得；不平衡字节量即使在理想全双工链路上也可能被低估。

若采用共享容量 `B_shared` 的流体模型，还应同时满足每方向约束，因此必要时间至少为

`max(V_H2D/B_H2D, V_D2H/B_D2H, (V_H2D+V_D2H)/B_shared)`。

将此下界视作可达时间，需要持续速率可分配、消息开销可忽略等额外条件；否则应使用匹配消息大小与方向比例的双工曲线。

设定两个单向速率各为 28 GiB/s，同时双向时每方向只有 20 GiB/s。各复制 28 GiB，按双工方向完成条件需 1.4 s；错误的峰值相加算法计算 `(28+28)/(28+28)=1.0 s`。两个方向按单向速率串行则为 2.0 s，那是另一条合法串行路径，不能把它冒充峰值相加的负对照。

实际服务可能是 256 MiB 输入预取与 64 MiB logits 回传，方向比例与上述对称实验不同。应固定拓扑、链路宽度、主机内存位置和 pinned/pageable 状态，分别扫纯 H2D、纯 D2H、双向及消息大小；说明是否经过 bounce、GPUDirect 或共享 NIC/磁盘上游。host API 返回不等于复制完成。设备互连速率也不能填入主机设备链路项。

## 持续负载下的时钟、功耗与漂移

短微基准可能在 boost 区间完成；长窗服务可能触及功耗、温度或时钟限制。表征应在目标功耗模式与散热条件下，同步记录可持续 SM/内存时钟、整卡功率和限流信号，并区分仅拷贝、仅计算与混合负载。

设短窗矩阵吞吐为 `X`，连续 60 s 同核降到 `0.85X`，把 `X` 代入长窗服务会高估算力。这是设定算例。延长持续时间时还要检查输入与执行工作是否相同，避免将工作变化误归因于降频。

锁钟不能消除热限制，也不能保证另一机箱或生产共置下仍满足原条件。功耗、运行时长或风扇曲线改变后，应重测可持续点，或把原参数限定为短窗结果。功率与能量也不同，能量需在相同边界内对功率积分。

## 并发消费者与资源份额

多进程、多上下文和多流消费者可能共享 HBM、L2、复制引擎与 SM。单消费者结果是比较基线，不能保证共置时仍可取得同样份额；它也不是跨条件的严格硬上限。

设单消费者速率为 `R(1)`，`n` 个同强度消费者的总吞吐为 `R_total(n)`。只有份额近似相等时，每消费者才约为 `R_total(n)/n`，不能把总吞吐写成 `n R(1)`。设定单进程顺序读为 1.0 TiB/s，两进程合计 1.1 TiB/s、各约 0.55 TiB/s，第二副本没有获得另一份完整独占带宽。

应固定干扰源集合与强度，同时记录总吞吐、各消费者份额和完成时间。区分时间片共享与实际并行；MPS 或分片配置的隔离不证明物理带宽加倍。消费者不对称时，平均份额不能代替较慢消费者的服务参数。

## 参数包如何写入资源模型

参数包包含顺序和不规则访问的有效带宽、必要的事务口径、L2 容量与复用提示、`P(dtype,shape_family)`、主机提交与 replay 成本、单向和双工链路曲线、可持续时钟与功率点、多消费者曲线。条目选择需要同时匹配访问、工作集、并发、运行时长和完成边界；没有唯一匹配项时保留未决，不挑最大的数值。

对独立资源轴，局部必要时间可写为

`T_lb=max_j(F_j/P_j, D_j/B_j)`。

字节与带宽须成对采用有效口径或事务口径。这个 max 即使资源不能重叠，仍是必要下界；把它当作可达完成时间，需要足够并行度、独立资源与充分重叠。依赖阶段按路径连接，共用独占资源的需求应合并；一般 DAG 的真实调度时间不能仅靠递归套 max 与求和确定。

展开一轮设定轨迹：先读取 8 GiB 顺序权重，再读取 2 GiB 不规则 KV，匹配有效速率分别为 1.0 和 0.35 TiB/s。两个阶段的估值为 7.8125 ms 与约 5.5804 ms。因为本例指定串行且共用 HBM，合计约 13.3929 ms；不能各领取一份独占带宽后只取 max。若改成混合并发，需采用混合访问曲线或更细的共享资源模型，分项时间之和也不再自动是实测完成时间。

随后有 64 MiB D2H logits，匹配链路速率为 28 GiB/s，约需 2.2321 ms。若输出必须在这两个设备阶段后才产生，并且交付必须等待复制完成，则设备阶段加复制约为 15.6250 ms，尚未计其他计算、同步和准备。只有存在独立的可提前复制工作时，才可把相应区间放入重叠路径。80 次 launch 的主机预算约 1.2 ms 能否隐藏，同样由真实提交与设备时间线决定；不能仅因它比 HBM 项短就自动删去。

这些数值都是设定计算。完整服务与微基准之间的差额应拆成额外交通、准备、同步、争用和排队，不能通过调高某个峰值参数抹平。

| 成本类别 | 对象与边界 | 防止的误计 |
|---|---|---|
| 计算 | 有效 FLOPs、padding、转换、归约 | 将混合操作一起除以矩阵峰值 |
| 访存 | 请求有效字节、命中、有效未命中需求、各边界事务 | 将未命中有效需求当作实际填充；重复扣命中或重复加放大 |
| 通信 | H2D、D2H、双工、共享上游 | 总字节除以不能同时取得的单向峰值之和 |
| 准备 | 分配、缺页、打包、预热、捕获和实例化 | 把新增准备成本藏进稳态均值 |
| 同步 | 输入就绪、事件、屏障、输出完成与排空 | 把 host 返回当作设备或消费者完成 |
| 驻留 | 工作集、图池、workspace、在途副本与日志 | 池与池内对象重复计量；漏掉新旧状态并存 |

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的机制 | 调整或放弃的依据 |
|---|---|---|
| 顺序访问变成随机 | 有效字节与完成边界 | 换随机或混合带宽条目，重新核对事务与并行度 |
| 工作集越过 L2 或复用距离改变 | 请求、命中、未命中需求与事务分账 | 重建命中和填充证据，不沿用小工作集表观速率 |
| dtype、布局或 shape family 改变 | 算术计数与数值合同 | 重核 dispatch、累加、转换和驻留，旧矩阵吞吐不直接外推 |
| 消费者增加或强度不对称 | 总吞吐与份额记录 | 采用匹配共置曲线，不使用单消费者乘副本数 |
| 短窗变成长窗 | 工作身份与功率时钟采样 | 取可持续点，短窗 boost 参数停止外推 |
| 方向比例、消息大小或上游改变 | 链路字节、方向和完成事件 | 重测双工曲线与共享约束 |
| 图地址、shape 或变体改变 | 主机与设备时间分离 | 重核绑定与准备成本，重新捕获或回退 |
| 图复用次数不足或频繁失效 | 含准备成本的完整总账 | 净收益为负时保留 eager 或缩小图集合 |
| 驱动、运行时或库路径改变 | 输入输出和计时合同 | 重核执行路径与资源参数，旧条目只保留历史作用域 |

## 诊断：竞争解释、反例与区分实验

| 观察 | 竞争解释 | 可控干预与可区分预测 | 反证后的修正 |
|---|---|---|---|
| 不规则读慢于顺序读 | 事务过取、cache 复用减少、并行度不足、地址依赖 | 固定有效元素改变对齐与跨度，交叉扫描工作集，记录事务和时间 | 段数增加而 HBM 事务不增时，撤回直接按段估主存的解释 |
| 小工作集表观带宽高 | L2 命中、上游命中、短窗计时遗漏 | 扩大工作集，分记各层请求与 HBM 事务，核对完成边界 | 只证实热态复用时，限制条目作用域，不抬高全局 HBM 参数 |
| L2 未命中需求很小，HBM 事务仍多 | 填充过取、预取、写回或其他引擎 | 固定只读请求和归属范围，改变每段有效覆盖量，分离读写计数 | 事务不随有效覆盖同比变化时，拆分有效需求与填充账 |
| 矩阵吞吐低 | dtype 路径不符、shape 小、转换、降频或驻留不足 | 固定 shape 核对路径，分开转换，改变持续时间并记录时钟与资源 | 路径和时钟稳定后，继续检查并行度与资源限制 |
| 图 host 时间下降，ITL 不变 | 设备主导、反馈依赖、准备或输出等待 | 同工作切换 eager/图，分记 host、设备、消费者与完整请求 | 撤回端到端提交瓶颈结论，保留主机工作减少这一局部事实 |
| 少轮次图更慢 | 捕获未摊销、稳态也慢、图改变了设备工作 | 保留首次成本，累计每轮总账，比较打平前后并核对设备工作 | 仅首轮差异支持准备解释；稳态变慢时重建设备成本 |
| 双向复制慢于单向估计 | 共享上游、复制引擎约束、pageable 或小消息 | 分测方向与同时复制，改变消息比例、大小和内存状态 | 双工容量下降时，停止使用单向峰值相加 |
| 多消费者总吞吐次线性 | 共享 HBM/L2/引擎、时间片或不公平份额 | 固定总工作改变消费者数与强度，同时记录总量和各份额 | 不按副本数扩容量；不对称时停止采用平均份额 |
| 短窗快、长窗慢 | boost、热限制、功耗墙或工作漂移 | 延长同工作并同步采样功率、时钟和完成量 | 工作不变且可持续点下降后，限制短窗参数的适用域 |

反例还应进入相同判定边界。冷读 4 B、填充 32 B 可反证将有效未命中需求直接当事务；热态四次读同段可反证把表观速率当 HBM 事务带宽。两个有依赖的阶段分别需 2、3 个时间单位，取 max 得 3 仍是下界，但串行完成需 5。图的捕获成本必须进入总账，不能只检查打平公式或一个人为设置的错误常数。双向峰值相加错误应实际产生 1.0 s，再与方向完成参考 1.4 s 比较。

## 检查覆盖与未验证边界

随章 `tools/check_k_tools_008_full.py` 是 Python 标准库、确定性、离线、只读的 CPU 算术与离散模型。输入为脚本内固定数据。它用逐字节地址集合核对请求段；用逐字节有效状态与完整填充记录独立核对区间算法的请求、命中、未命中需求及事务账；覆盖冷读一个字、跨段、重复读取、初始热段与空读取。

带宽检查以指定填充服务时间为参考，分别验证有效与事务口径，并实际执行两条错误路径：将有效未命中需求当事务量、将全请求表观速率当 HBM 事务带宽。图检查用每微秒推进两条独立预算分支的累计参考，核对理想周期模型的完整总账，包括 24、25、26 轮和设备主导情形；忽略捕获的错误算法实际生成总时间并被拒绝。这个抽象预算模型不模拟真实 CUDA 提交因果或单请求反馈。

链路检查用固定时间片推进两个方向的剩余字节，核对对称双工完成时间；峰值相加算法实际计算总字节除以两个单向容量之和，并进入相同时间判定。其他检查包括事务放大重复计量、对齐偏移、串行阶段错误取 max、多消费者错误倍增和访问形态参数选择。负对照必须实际触发参考判定失败，不能只打印标签。

这些检查不执行 CUDA，不访问 GPU 计数器，不证明真实 cache 命中、HBM 物理事务、请求在途合并、压缩、预取、写回、驱动计时、链路双工、时钟降频或图捕获合法性。共享上游流体模型、完整表征发布状态机及真实服务调度也没有在此脚本中实现。它们不证明 tile、batch、图桶的最优性、服务 SLO 或知识使用效果。脚本执行状态由绑定当前脚本与输入的真实执行记录承担，正文不预写通过结论。
