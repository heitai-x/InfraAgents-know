# K-ALG-008：异步调度：依赖图、代次与双缓冲

异步调度把等待移到依赖真正需要满足的位置，使不同请求的准备、执行和结果处理可以重叠。它不改变模型的函数依赖，也不取消存储的最后使用条件。主机调用返回、设备完成、业务结果提交和物理槽可复用，是不同事件。

## 可以重叠什么

把工作表示为有向图。若 v 读取 u 的输出，存在 u→v；若两项工作无协议地访问同一可变对象且至少一方写入，也必须建立顺序或隔离存储。不同线程、stream 或 graph 实例不会自动消除这些边。

对请求 r，普通自回归分布为 p(x[n] | x[0:n])。正式计算下一位置需要已经确认的输入 token；本轮采样尚未产生的 token 不能提前作为正式输入。可以提前处理独立请求、解析输入、预留容量，或准备不依赖未知 token 的描述符草稿。投机执行另需[接受与回滚协议](speculation-budget.md)，未接受的候选不能进入普通确认历史。

把一次独立工作单位的主机准备、设备执行、结果处理分别记为 C、G、O。不同请求可以填充彼此的设备空隙；单条请求的 token→采样→下一轮输入依赖仍在。若读取主机标量、检查 EOS 或复制结果引入等待，应把它放回这条依赖路径，不能仅凭提交接口带有 async 就认定等待已经消失。

## 一张调度快照属于一个执行代次

本章构造一种保守实现：单设备、多请求、有限槽池；每个请求至多有一个尚未释放的执行代次，不含投机、beam、输入追加或故障重试。跨请求可以异步重叠。这个限制便于完整说明推进和回收，不要求所有引擎采用同样深度。

请求身份 r 包含不复用的请求实例身份。其第 g 次执行是 (r,g)，完整执行身份为 I=(r,g,s,epoch)，s 是物理槽，epoch 是该槽生命期。g 在请求内递增，epoch 每次释放已占用槽后递增；batch 行号只是一轮视图。

请求保存已确认 token 序列 x[0:n)、全层有效 KV 连续边界 k、采样/RNG 状态、生成计数与停止原因，满足 0≤k≤n。已知 token 和已计算 KV 不能混为一个长度。初始非空 prompt 已知，但没有执行时 k=0；空输入由明确的模型输入规则补 BOS，或在准入时拒绝。最大新增 token 数为零时直接结束，不制造设备工作。

一代的只读快照 S(I) 包含输入区间 [b,e)、x[b:e)、逻辑位置、历史范围 [0:b)、mask、页表与模型/adapter 版本、采样状态副本、输出和 workspace 地址、图实例身份。普通推进取 b=k、e=min(n,k+q)，q≥1。全层完成后只把 k 推到 e；若 e<n，仍是部分 prefill，不从中间行发布生成 token。若 e=n，末行 logits 才给出下一个 token 的分布。

采样成功后，将 token 放到原位置 n，再令 n 增一；它自己的 KV 仍未计算，因此 k 保持旧 n。下一代才以这个已知 token 为输入。逐层的 hidden state、KV、位置与 mask 契约见[连续批处理](iteration-batching.md)和[位置、Mask 与缓存](../system-semantics/position-mask-cache.md)；这里额外要求完成证据覆盖所有必要层，而非只覆盖 logits 所在的某条独立执行支路。

前缀缓存准入需要补充末行 logits 边界：若完整 KV 命中但没有兼容 logits，不能因 n−k=0 而停滞。可把本次可用边界取到 n−1，在私有写区安全重算最后一个已知 token，再取得末行 logits；共享页不能被原地覆盖。本章的检查从 k=0 开始，不模拟缓存页与 COW。

## 所有权、可见性与合法提交

物理阶段依次为 WAIT_SLOT → PREPARING → READY → SUBMITTED → DONE → RELEASED。canceled 和 failed 是独立标志；取消不把 SUBMITTED 改成另一个无法接收完成的物理阶段。DONE 表示本代主执行已经真实结束，仍可能有输出消费者或其他存储使用者。

合法性分成取得槽和持槽执行两个检查点。

- L1 输入合法：正式输入来自已确认前缀，依赖的状态、模型版本、mask 和读写区间一致。
- L2 快照稳定：任何已启动的读者结束前，不覆盖其输入、metadata、页表、输出或 workspace。
- L3 完成可见：消费等待覆盖实际生产写入；发起复制、主机函数返回和复制完成不能互相代替。
- L4 身份完整：准备、完成、消费、错误和回收携带 I；消费者另带本代唯一的 cid，独立物理使用者带 uid。
- L5a 取得槽：owner[s]=空，旧代所有使用责任已经结束，且容量预留成功。
- L5b READY 提交：owner[s]=(r,g)、slot_epoch[s]=epoch，本代准备完成、快照冻结且仍有提交权。这里要求当前代拥有槽，不能再次要求 owner 为空。
- L6 容量守恒：已拥有、预留和在途对象的物理并集不超过预算；共享页与预留池不能重复计字节，尚未真实释放的取消对象不能提前扣账。
- L7 取消有阶段：立即禁止未来业务提交和后继调度，保留在途准备、执行和消费者的物理结束责任。
- L8 共同输出：CPU/GPU 分片只有同代、同输入版本、同分片映射且满足归约与数值契约时才能合并；一侧失败不能把另一侧部分结果发布为完整层。

ledger 为每个物理对象记录拥有者、范围、容量以及尚未结束的使用责任集合 P。使用者必须先登记，再启动；同一责任只能由自己的真实结束事件撤销。consumers 不是一个可被任意通知递减的整数，而是 P 中消费者身份的集合视图。重复 cid 不会抵消另一个 cid。

本算法把一代的槽内对象保守地一起释放。输入、输出、workspace、graph replay、CPU 访问和传输源若具有不同生命期，也可以拆池，但必须分别保留最后使用证据。双缓冲只允许两组对象同时存在，不自动支持任意深度。

## 从到达到下一代的事件算法

调度器串行处理状态事件；多线程实现需要锁、原子事务或等价的消息所有权，使取消与业务提交具有明确先后。生产者执行只写本代私有结果，不直接修改请求历史或 RNG。

P 中 prep、device 分别表示准备和主执行责任。device 的真实结束证据须覆盖该执行包的必要计算、全层 KV 写入及其结果生产依赖；异构执行时包含必要的 CPU 分片、结果传输和合并。另有不被该证据覆盖的 reader uid 时，独立登记到 P。输出消费者在成功主执行完成后登记并启动；失败时尚未启动的消费者不存在，不留下永远等不到的虚构责任。

```pseudocode
算法 有界代次调度
输入：请求事件，槽集合，容量预算，最大提交未释放数 D，prefill 片长 q
输出：按请求顺序提交的 token、停止/错误、资源归还

初始化：
  owner[s]=空，slot_epoch[s]=0，inflight=0
  请求表、代次表、等待队列、ledger 为空

建立代次(r,g)：
  active[r]=g
  创建记录：phase=WAIT_SLOT，slot=空，P=空
  canceled=false，failed=false，counted=false，business_done=false
  need_next=false，result=空，消费者已处理集合为空
  将该代放入等待队列

处理 ARRIVE(r,prompt,limit)：
  若 r 已存在，按入口去重协议处理，不重复建立请求
  按模型规则处理空 prompt；建立 x、n、k=0、RNG、生成计数=0
  若 limit=0，标记请求结束，active=空
  否则标记 LIVE，建立代次(r,0)
  唤醒 WAKE

处理 WAKE：
  先对满足释放条件的 DONE 代执行 RELEASE
  再按有界且不使持续就绪请求永久饥饿的策略扫描 WAIT_SLOT：
    若请求已取消/失败，phase=DONE，等待 RELEASE
    否则选择满足 L5a 的空槽，并原子预留本代增量容量
    无合法槽或容量时保留等待，不持有部分预留阻塞其他请求
    成功后设置 owner、slot、epoch，phase=PREPARING
    取 b=k，e=min(n,k+q)，保证 b<e
    构造本代快照；在 ledger 登记 prep 后启动准备
  对 READY 代：
    检查 L1、L3、L4、L5b、L6，active[r]=g 且请求 LIVE
    若 inflight=D，保留 READY
    否则先登记 device 及执行包之外的全部计划使用者 uid
    提交执行包；确定已提交后 phase=SUBMITTED
    counted=true，inflight 加一
    提交返回不更新 k、x、RNG 或业务输出

处理 PREPARE_DONE(I,status)：
  只接收仍匹配 owner/epoch、phase=PREPARING 且 prep∈P 的事件
  事件须证明准备及其写入真实结束；否则保留责任并进入隔离/排空
  移除 prep
  若失败，failed=true，终止该请求的未来提交
  若 canceled 或 failed，phase=DONE
  否则 phase=READY，冻结快照
  唤醒 WAKE

处理 DEVICE_DONE(I,status,certificate,result)：
  只接收身份匹配、phase=SUBMITTED 且 device∈P 的首次完成
  若错误没有证明全部相关访问已结束：
    failed=true，停止请求；保留 device，等待真实排空证据
  否则移除 device，phase=DONE，保存首次结束记录
  若失败或 certificate 不完整：
    failed=true，停止请求；不发布部分 KV 或输出，不启动结果消费者
  否则若请求仍 LIVE、active[r]=g 且未取消：
    验证 certificate 覆盖快照区间、所有必要层和同代末行结果
    将已完成 KV 的有效边界 k 更新到 e
    若 e<n：need_next=true，不采样
    若 e=n：
      先登记唯一 result 消费者 cid 和所需的其他消费者 cid
      启动这些消费者；result 消费者使用本代 RNG 副本产生候选
  已取消代只保存完成与资源账，不产生新结果消费者
  唤醒 WAKE

处理 CONSUME_DONE(I,cid,status,candidate,RNG_next)：
  要求 I 仍匹配本代；cid 必须属于 P 中已启动的消费者责任
  旧代、未知或已经结束的 cid 不再改变任何请求状态或计数
  事件证明该消费者最后访问结束后，幂等移除自己的 cid
  若 cid 是 result：
    若失败，停止请求，不提交这个候选
    否则仅在 phase=DONE、未取消/失败、请求 LIVE、active[r]=g、
         business_done=false 且 k=e=n 时进行一次事务：
      business_done=true
      用 RNG_next 更新本请求 RNG，生成计数加一
      将候选追加到位置 n，n 加一；k 保持不变
      按输出协议提交非 EOS token 到独立响应对象
      若 EOS 或达到生成上限：标记请求结束，active=空
      否则 need_next=true
  其他 cid 只结束自己的资源责任，不采样、不提交 token
  唤醒 WAKE

处理 USE_DONE(I,uid,status)：
  身份必须匹配，uid 必须是尚未结束的独立物理使用责任
  仅在证据说明相应输入读取、输出写入和 workspace 访问均结束后移除 uid
  错误/超时本身不证明结束；不能确认时隔离对象，保留责任
  唤醒 WAKE

处理 CANCEL(r)：
  请求标记 CANCELED，active=空；禁止未来业务提交和后继代
  对尚未释放的当前代设置 canceled=true，不改写其在途物理阶段
  WAIT_SLOT 可转 DONE；READY 无在途准备/执行时可转 DONE
  PREPARING 等 PREPARE_DONE；SUBMITTED 等 DEVICE_DONE
  DONE 中已经启动的消费者仍须发送真实结束事件
  不因取消而清空 P，不递减 inflight
  唤醒 WAKE

处理 RELEASE(I)：
  仅允许 phase=DONE 且 P=空；重复 RELEASE 无效果
  有槽时验证 owner/epoch，解除 owner，slot_epoch 加一
  归还本代暂存及未发布预留；成功 KV 转为请求持有，不能随槽一起丢失
  若请求已终止，解除其逻辑持有，按各对象最后使用条件回收私有状态
  仅当 counted=true 时 inflight 减一，并设置 counted=false
  phase=RELEASED
  若请求仍 LIVE 且 need_next=true：
    建立代次(r,g+1)，使其进入 WAIT_SLOT
  唤醒等待槽、容量或提交额度的请求

关闭：
  停止新准入，撤销未来推进，继续处理能解除责任的完成事件
  只有所有 P 和已提交账务清空才报告排空
  未能确认完成时报告对象、身份、最后使用者与阻塞证据，不宣称已归还
```

WAKE 是可合并的调度通知；处理器空闲而等待真实外部完成时不应忙循环。空槽释放、准备完成、结果完成和额度归还都产生唤醒，避免存在合法工作却没有后继事件。等待策略的进度保证仍依赖有限准入、最终完成和可取得容量；消费者无限背压时，增加轮询不能保证进展。

提交在入队前被确定拒绝时，可以撤销从未启动的责任和预留；部分提交或入队状态不明时必须保留隔离并取得排空证据。设备上下文失败也不能以错误码代替所有访问已停止的证明。消费者启动失败同理：证明没有启动才撤销；已经启动则等待结束。这里把这些接口差异留在责任的证明条件中，没有假定所有错误都可正常回收。

业务结果一次性提交与资源消费结束是两件事。result 消费者可以先结束并提交 token，copy/archive 等读者随后结束；重复 result 通知不能再次采样，重复 copy 通知不能代替 archive。取消若先于业务事务被处理，该事务失去资格；事务先完成时，之后的取消不能撤回已经提交的 token。响应对象若复制了 token，可以独立发送；若发送还借用槽内地址，必须在启动前把发送责任加入 P。

一条普通轨迹为：ARRIVE(A,[a,b],2) → WAKE 取得 slot0、预留容量并启动准备 → PREPARE_DONE → WAKE 提交 g0 → DEVICE_DONE 确认 k=2 → result 完成、采样 c，得到 x=[a,b,c]、n=3、k=2 → 其他消费者结束 → RELEASE → 建立 g1 → 准备并执行 [2,3) → 全层完成 k=3 → 采样 d 后达到上限 → 所有消费者结束并释放。首次输出、KV 的一步偏移和后继代次均经过同一事件算法。

## 晚到结果、图与 CPU/GPU 共同提交

构造请求 A 的 g0 使用 slot0，请求 B 等待；图 P 读取该槽描述符，某层由 CPU 分片 c 与 GPU 分片 d 共同计算。ledger 必须覆盖以下对象关系。

| 对象 | 使用者与最后访问证据 | 释放要求 |
|---|---|---|
| A 的输入与页表 | 图 P、GPU d、CPU c 的读取或输入复制 | 全部实际读取结束；复制发起不够 |
| CPU 输出与 workspace | c 的写入、其结果传输的源读取 | c 结束且传输源读取结束 |
| GPU 合并目标 | 结果传输写入、GPU 合并与下一层读取 | 写入和后继最后读取结束 |
| 槽内 logits/输出 | result、复制或其他已登记消费者 | 各自 cid 均结束 |

采用本章统一槽的保守方案，时序如下。

t0：A 已提交，owner(slot0)=(A,g0)，图、CPU/GPU 与传输责任已登记。B 只能准备私有草稿，不能写 slot0。t1：处理 A 的取消，立即撤销业务提交权，物理阶段仍为 SUBMITTED。t2：GPU 分片结束，但 CPU 或其传输尚未结束，因此它只是局部完成，不能冒充覆盖完整执行包的 DEVICE_DONE，也不能释放槽。t3：CPU 分片、传输、图和合并相关访问真实结束，聚合完成记录到达；A 只完成资源账务，不采样。剩余消费者全部结束后才能 RELEASE，epoch 增一。t4：B 才能取得并写入该槽。

若 CPU c 到 t4 之后仍在读旧输入、写旧共享输出或使用旧 workspace，这条轨迹不合法，t3 必须后移。旧代身份只能阻止错误业务提交，不能阻止旧物理访问破坏 B。本方案不允许仍有这些访问时复用槽。t4 后允许到达的是已记录真实结束的重复通知，或只携带值且不再访问槽的通知；它们按旧 I 幂等忽略。

若要让旧 CPU 计算在槽复用后继续，必须改用独立生命周期：先完成从槽到私有输入的复制并结束所有槽访问，剩余 CPU 输入、输出、workspace 和传输目标均为旧 I 独占对象；这些私有对象继续登记到独立 ledger，直到计算及结果传输真实结束才回收。新请求不能复用它们。仅声称“结果会丢弃”不满足这一条件；这不是上述统一槽算法的默认路径。

[PowerInfer 固定来源](../sources/S-POWERINFER.md)把热点神经元放 GPU、冷部分放 CPU，双方计算后到 GPU 合并；CPU 真实工作集合为空时可以避免无意义同步。其评估模型、预测器与输入分布有边界：遗漏非零贡献可能改变函数，大 batch 或长 prompt 会降低联合激活稀疏性。精确实现须补算或验证；允许近似时需要明确质量契约，不能把跳过同步变成跳过必要贡献。

kernel 内部也有相同的两条边：生产完成→消费者开始，消费者最后读取→槽可覆盖。Hopper 上的 TMA、异步 WGMMA 和 warp specialization 可以实现具体流水，但加载完成不证明 WGMMA 已读完。FlashAttention-3 的环形缓冲与消费者交接支持这一生命周期解释；本章不指定未公开的 lane/寄存器映射，具体片上算法与同步作用域见[GPU 内核流水](../hardware/gpu-kernel-pipelines.md)。服务层两个 stream 的时间线不能证明 kernel 内部已形成有效重叠。

## 如何推导有效异步收益

C、G、O 和提交/释放开销 H 均以每单位独立工作的时间计。H_host 是无量纲的有效主机并行度，不是线程数量的简单计数；它还受串行调度域、CPU 额度、原生库线程和资源竞争限制。

在固定工作单位、设备串行服务需求为 G、主机工作可按 H_host 分摊、资源需求可持续且缓冲充分的条件下，平均启动周期 P 至少满足：

P ≥ max(G, (C+O+H)/H_host, max_j(Q_j/B_j))。

P 的单位是时间/独立工作单位，吞吐上界为 1/P；若一个单位包含多个请求或 token，需另按有效产出换算。Q_j 是同一工作单位在共享资源 j 上累计承担的字节，B_j 是相同并发条件下的可持续字节/时间。CPU 转换读写、DMA 和 CPU 分片若共用主存，应合计相应流量；不能把每段孤立带宽同时分配给它们。逻辑输入字节、设备实际事务量和峰值驻留是不同口径。该式是必要下界，不能把已经包含在 G 的访存时间再与 Q_j/B_j 相加。

第一单位仍经历依赖路径。固定独立阶段、没有反馈且资源互不冲突时，N 个单位的理想完成时间是各阶段之和加 (N−1)P；启动与排空不能从短任务中省掉。单请求若有 C_dep 依赖刚采样的 token，则 C_dep、采样和必要提交仍处在该链的周期上。

设定 C=2、G=8、O=1、H=0，串行每单位为 11。独立请求理想聚合周期可接近 8，对应约 1.375 倍吞吐；单链若仍需 1 单位依赖输入准备和 1 单位结果处理，周期下界接近 10。它们是不同依赖假设下的合成计算，不是硬件测量。

槽数由占用而非提交次数决定。某池从取得槽到最后使用结束的固定生存期为 L_j，启动周期 P，且边界结束后可立即复用，则正生存期至少需要 ceil(L_j/P) 个槽。随机长尾不能用平均 L_j 保证安全，仍由真实事件控制复用。输入占用 10 ms、输出占用 9 ms、周期 8 ms 时，各需两个槽；每输入槽 16 MiB、输出槽 1 MiB，这两个池合计 34 MiB，另计权重、KV、workspace、图池和主机 staging。多加一个槽不会缩短 8 ms 的设备服务需求。

计算、交通、准备、同步和驻留应列同一候选的账：模型 FLOPs 通常不会因异步接口减少；快照构造、页检查、packing、图选择、事件和 ledger 增加主机工作；跨设备分片增加输入/结果字节与合并；多代缓冲增加容量，kernel 内更深流水还可能增加寄存器、共享存储和 spill。共享对象按物理并集计容量。若每个额外在途代实际新增 K 页，增加 d 代才有 dK 页的增量；同一请求被多代引用的旧 KV 不能重复计成新页。

## 取消的两个响应时间

设取消通知到达为 t_arr，状态拥有者处理取消为 t_log，相关对象最后物理使用结束为 t_last，实际归还为 t_free。

- 逻辑响应为 t_log−t_arr。自 t_log 起，本算法禁止新的业务提交与后继调度；无需等待设备排空。此前已经提交的业务结果不能倒转。
- 物理回收响应为 t_free−t_arr，其中 t_free≥t_last。通知处理、设备队列、CPU 分片、传输和输出消费者都可能延长它。

只有在明确队列模型下才可估排空。例如单一 FIFO 设备、不能中止、目标前有 W 个尚未开始的工作、每项服务时间至多 G_max、当前执行残余至多 R_max，则目标设备结束的等待至多约 R_max+(W+1)G_max；它还未包括外部读者与归还处理。多 stream、并发 kernel、无服务时间上界或无限背压时，这个上界不成立。若取消回调本身被同一阻塞线程延迟，t_log 也会变大，应诊断控制路径可达性，不能把它归为取消天然必须排空。

深队列可能减少设备空洞，也会增加无效执行、容量保护和高优先级请求等待。评估同时比较逻辑取消延迟、最后物理结束、资源归还、有效产出与峰值驻留。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的约束 | 调整候选 | 反转信号 |
|---|---|---|---|
| 设备已经饱和 | token 依赖和结果归属不变 | 保持或降低 D，缩短排队 | 增槽仅增加驻留和时延 |
| 短请求占主导 | 启动、收尾与取消仍存在 | 浅流水、合并小提交 | 任务在填满前结束，固定开销变大 |
| 长上下文或 KV 紧张 | 最后使用前不能回收 | 减少在途、拆开不同生存期的池 | 新缓冲挤出 KV，准入与有效完成率下降 |
| 高取消率或频繁 EOS | 已发出的工作仍有责任 | 缩短队列，提高控制事件处理机会 | 无效工作超过新增有效输出 |
| 固定地址图重放 | 地址稳定不证明内容安全 | 分槽、图池或兼容的更新路径 | replay 仍读时覆盖 metadata/workspace |
| CPU/GPU 分片不平衡 | 同代合并和数值契约不变 | 重分片，真实空集合跳过同步 | CPU 成为关键路径，或预测漏算越出质量契约 |
| 统一内存或共享地址 | 可见性与最后使用不变 | 重算远端读取、缺页与竞争 | 省去显式复制却增加实际交通/等待 |
| 更激进的提前推进 | 安排与确认边界必须分开 | 保存 scheduled_len、confirmed_len 和原始执行视图 | 未兑现工作污染正式历史 |

vLLM 固定机制说明允许调度后先增加内部进度，结果返回再校正；本章选择完成后才推进 k。若引入前者，取消、拒绝和回滚都必须作用于暂定边界，不能把安排计数解释成设备完成。本章的保守算法不证明这种扩展已经正确。

## 竞争解释、区分实验与反证修正

先固定逻辑输入、工作量、正确性和计时边界，再比较性能。主机时间戳与设备时间域需要可靠关联；累计 kernel 时长不是墙钟关键路径。

| 竞争解释 | 可区分预测 | 干预与观测 | 反证后的修正 |
|---|---|---|---|
| 主机准备/结果处理限制 | 增加独立准备机会后设备空洞减少，设备服务区间近似不变 | 分记准备、提交、完成、采样和队列等待；固定计算扫描 D | 设备已满而排队增长，不能继续归因主机不足 |
| 单链反馈依赖限制 | 多独立请求能填满设备，单链仍有采样后的空隙 | 比较同工作量的单链与多链，追踪 token→下一输入 | 独立请求仍不能填满时，需调查资源与提交路径 |
| 提前复用或代次混淆 | 错误随取消、重用、迟到通知出现 | 注入重复完成、重复消费与旧 epoch；检查快照和输出位置 | 身份正确仍有内容变化，应查实际最后读取与写覆盖 |
| 完成证据过早 | 读到旧/部分结果，延迟复制时更明显 | 将等待覆盖移到最后生产写入，分别延迟 KV 和 logits | 全局同步使错误消失只提供线索，仍需定位遗漏边 |
| 容量挤占 | 深度增加后峰值升高、准入减少、释放滞后 | 相同到达轨迹比较 KV、图池、staging 与完成率 | 驻留未变仍变慢时，容量不足以解释 |
| CPU/传输成为关键路径 | 延迟该分片会延迟合并与槽归还 | 独立记录两侧计算、传输源最后读取与合并 | GPU 与 CPU 交替等待时，应修改固定分片比例 |
| 取消控制路径阻塞 | 设备未排空前本可抑制输出，却迟迟没有 t_log | 单独延迟通知处理与设备完成，比较 t_log、t_last | t_log 已及时而 t_free 晚，应转查物理责任 |

配套检查使用同一组 ARRIVE、WAKE、PREPARE_DONE、DEVICE_DONE、CONSUME_DONE、USE_DONE、CANCEL 事件推进有限模型。独立参考从完整 token 前缀直接计算玩具模型的串行输出，不使用调度器的 KV/代次状态；同时检查所有权、提交账务和责任身份守恒。覆盖首次输出及多代推进、分块 prefill、零新增输出、空输入补 BOS、各阶段取消、终态错误、多消费者乱序、释放前重复完成/消费、旧 epoch 和独立读者阻止回收。

故意错误的对照分别恢复“READY 提交要求空 owner”“取消后拒收完成”“未提交代也扣 inflight”“重复 result 再采样”“重复一个消费者抵消另一个责任”“未等独立读者就释放”。每个对照都必须被独立预期或不变量检出，不能仅打印预先写好的 PASS。

该检查只覆盖确定性的 CPU 协议模型和玩具函数，未执行 CUDA、真实 DMA、图重放、异构数值归约或缓存页分配。目标机仍需检验同步作用域、事件记录点、编译后访问、实际重叠与性能；CPU 检查不能写成 GPU 实测。观测落在重复测量的不确定区间时应保留未知，而非用重叠面积或单个利用率强行归因。
