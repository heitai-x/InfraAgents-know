# K-ALG-017：多级驻留：有效副本、预取、淘汰与重算

HBM、DRAM 与 SSD 提供不同的容量、带宽和访问路径。分层管理要让下一次合法计算取得正确版本的数据，同时限制源副本、预留目的空间、转换区和在途缓冲的同时驻留。所有对象能放入三级容量总和，并不能证明下一步计算有输入，也不能证明服务延迟可接受。

## 对象、范围与可消费副本

对象记为 O=(η,scope,r,κ)。η 包括模型、adapter、数据版本、表示、布局及必要量化参数；scope 标识层、head、请求或专家；r=[a,b) 是逻辑有效范围；κ 是恢复位置和必要控制状态。逻辑范围与物理分配大小分别记录：页尾的空槽占容量，却不是有效 KV。

权重在同一版本内通常只读；已封闭 KV 前缀可以共享；正在追加的尾块和递归状态会改变。可变对象复制前必须冻结版本，或将后续写入转到另一个版本。复制期间继续原地推进，可能产生各部分分别属于不同位置的撕裂副本。量化数据还须与 scale、zero point 和分组解释共同冻结；编码字节相同不证明解释相同。

副本 c=(O,tier,x,target,ready,state)，其中 x=(slot,epoch) 标识一次物理分配生命期。epoch 防止迟到通知被用于新分配；它不能阻止尚未结束的旧 DMA 实际写入同一地址，因此物理排空仍是复用前提。

| 状态 | 已成立的事实 | 可执行动作 |
|---|---|---|
| RESERVED | 目的容量和映射已独占取得，当前没有获准的生产访问 | 核验并登记一次新尝试，或撤销预留 |
| LOADING | 已登记生产意图，正在等待提交裁决或完整生产结果 | 处理接受状态、范围进度与终结，禁止消费 |
| READY | target 完整，身份和表示相容，生产完成对消费者可见 | 建立视图并取得读取权 |
| RETIRING | 已关闭新拥有权和新消费入口 | 继续结算既有读者与传输，禁止重新发布 |
| GONE | 本生命期已无物理访问责任，容量已归还 | 仅处理旧通知去重，不能复活 |

LOADING 不证明底层已经接受操作。登记必须先于启动，因此它包含一个等待提交结果的窗口；随后得到可信的全部未启动结果时，必须显式退出这个窗口。放弃候选走 RETIRING→GONE；保留候选重试则回到 RESERVED，并保留明确待办，不能继续把 LOADING 当作仍有生产者运行。

视图 v=(O,x,need) 解释消费者要读取哪个范围；它不是复制完成证据。逻辑拥有者集合 L_x 表示请求、缓存目录或恢复策略仍需保留该副本；使用集合 U_x 表示已经取得启动资格、尚未证明最后访问结束的操作。发布和取得使用权在同一串行状态域中检查，防止查到 READY 后、登记读者前被回收。

物理回收要求 RETIRING 且 L_x=∅、U_x=∅，并且没有尚未解除的未知访问隔离。两个读者分别持有 uid₁、uid₂；uid₁ 的重复完成只能命中自己的终结记录，不能抵消 uid₂。传输同时保护源和目的；源逻辑引用归零，不表示复制已经不再读取它。

范围检查先于查缓存、预留和提交。要求 need 是对象范围内的有序半开区间。对象为 [0,32) 时，[0,16)、[0,32) 和 [31,32) 都合法；[-1,16)、[0,33) 和反向区间非法。合法空范围 [a,a) 直接返回空结果，不预留或等待事件；非空副本的预留接口则拒绝空范围。这两个入口不能混为一个负例。

本章采用整目标完成后发布的保守协议。部分进度可以乱序、重复到达，按同一传输身份取覆盖并集；只有覆盖完整 target 且生产者最后访问结束，才可能 READY。多层恢复包还要等全部必需副本齐备，再安装共同位置的执行视图；不能逐层发布不同恢复位置。

## 容量与取得路径的共同账本

对层 t、时刻 τ，物理驻留为

U_t(τ)=Σ_{p∈P_t(τ)} bytes(p)，

P_t 是该时刻唯一物理 backing 的集合，包括有效副本、已分配目的区、staging、转换区、旧版本、工作区和池的保留空间。同一页的多个视图只计一次；两个真实副本分别计费。已计完整预分配池时，不再把池中 active 对象加一次。虚拟地址预留不等于物理 backing；尚未物化的容量承诺另列准入账，并与已占容量共同受预算限制。

一次迁移可能同时保留源、目的和 staging。压缩源经主机解包再进入设备时，还可能同时存在压缩源、展开目标、锁页区和设备执行表示。选中了淘汰对象但它仍有读者时，不能提前从 U_t 中扣除。

计划应对每层检查 max_τ U_t(τ)≤C_t。分别求每个对象的峰值再相加通常只是保守上界；只看最终稳态又可能漏掉迁移峰值。预留的结束时间若不确定，就持续计费到真实回收，不能按预测 deadline 自动释放。

保留、恢复与重算先满足相同语义边界，再比较成本。设保留 B 字节，下次使用概率 p，能够避免的净关键路径时间为 S，则 pS/B 的单位为时间/字节，可以作为淘汰排序线索。它没有解决未来访问估计、公平性、依赖包和容量排挤，不是全局最优规则。LRU 适合某些时间局部性；单遍扫描可能污染缓存，删除一个小检查点也可能使大状态包失去恢复价值。

淘汰最后一份有效状态前，必须证明还有满足合同的稳定副本，或保留了合法重建依据。普通确定性 Transformer 的已知 token 可以支持重新 prefill；递归状态、外部特征、随机分支和已提交外部记录未必能仅凭文本重建。重放固定已知 token 与重新采样也不同；切换数值路径后是否允许浮点差异，由任务契约决定。

## 从访问到取消的事件算法

下面给出单一状态拥有者下的保守算法。多线程实现需要等价的锁或事务顺序。算法允许异步数据路径，但状态线程不等待设备或满队列；它先处理完成和释放，再重新尝试等待计划。

逻辑持有记录必须能反查其责任方。计划代持的目的区、staging、工作区及源保护都应关联到实际 owner，不能因为用了内部计划身份而漏过取消。取消只撤销该 owner 对应的 L；已经登记的物理使用 U 独立存在。共享下载仍有其他等待者时，其候选和后续阶段继续按这些等待者的资格推进。

操作身份与计划身份分开。一次尝试的 op_uid 永不代表第二次实际执行；不可变描述包括全部源、目标、工作区、物理生命期、访问范围与模式。已终结记录保存成功、失败或 NOT_STARTED 结果。相同身份、相同描述的重复通知只返回原结果；描述不同则拒绝且不改变资源。计划可以用新 op_uid 重试，旧拒绝通知不能结算新尝试。

```pseudocode
算法 多级副本的取得、生产与回收
输入：对象 O、所需范围 need、期望执行层、期限 d；容量与路径图；访问和完成事件
状态：copies、alloc、views、operations、已终结操作身份、等待计划、owner 资格
每个副本保存：O、target、ready、物理生命期 x、state、逻辑拥有者 L、使用者 U
每个计划保存：资格、完整取得清单、计划持有、依赖待办、重试待办
输出：带读取权的视图、PENDING、容量不足或不可恢复失败

初始化：所有表为空；物理槽的 epoch 独立递增；操作身份不复用

WITHDRAW_HOLDS(已获准撤销的持有记录集合)：
  按完整物理生命期及责任方核对记录，只撤销指定 L 和该责任方对应的视图
  同一条持有重复结算不改变其他 owner，也不再次处理已归还的新生命期
  汇集受影响对象；本步骤不删除任何 U，不回收、不唤醒
  对每个仍存在的受影响生命期：
    若 L 已空：关闭新拥有权与新消费入口，明确置为 RETIRING
    若 L 非空：保留其他合法持有及其入口，不因为当前阶段结束而退休
  返回受影响集合；调用者在整个状态事务收尾后逐项 FREE，最后一次 WAKE
  U 尚未清空不阻止进入 RETIRING，但继续阻止 FREE

ACCESS(O,need,owner)：
  验证 owner 资格、对象身份与 need 范围，非法则失败且不改变资源
  若 need 为空：返回空结果，不创建操作
  搜索同一 O、执行表示相容、READY 且 ready 覆盖 need 的副本
  若命中：在同一状态事务内登记 owner 和唯一 reader_uid，再返回视图
  若已有相同需求的生产计划：加入合法等待者，避免重复下载
  否则枚举合法取得路径：保留命中、逐级复制与转换、从恢复点重算
  对每条路径展开目的区、staging、转换、重放工作区及旧副本生存期
  排除身份、恢复资格、最小工作单元或容量不合法的路径
  按期限、估计完成时间和机会成本选择候选；没有候选则等待或明确失败
  原子预留本阶段全部必要空间；失败时不留下部分预留
  建立私有 RESERVED 目的副本和可追溯到 owner 的计划拥有权
  保存本计划实际取得的全部持有，而不只保存最终目的对象
  进入 START_STAGE；返回 PENDING

START_STAGE(plan)：
  若计划已取消、失败或没有合法等待者：
      不提交后继；对无保留依据的计划持有调用 WITHDRAW_HOLDS
      对返回的全部受影响对象逐个尝试 FREE，最后执行 WAKE；返回
  若上游尚未 READY：保留待办，返回状态循环
  核对源 O、范围、表示、物理生命期、目的写权限及全部工作区
  重试也重新核对资格、路径和容量；已有预留只计一次，新增需求原子预留
  分配新的 op_uid，保存不可变描述
  在启动前，将 op_uid 登记到实际源读、目标写和工作区的全部 U
  将目的及生产工作区置为 LOADING，登记等待提交裁决
  再授权一次实际 I/O、转换或重算提交
  全部接受：登记接受事实，等待 PROGRESS 和 END
  明确全部未启动：进入 NOT_STARTED(op_uid,证据,放弃或重试)
  部分接受或是否启动未知：保留可能访问的责任，等待终结或可靠停止证据

NOT_STARTED(op_uid,证据,decision)：
  核对完整操作身份、不可变描述和覆盖全部访问的可信未启动证据
  已终结且匹配：返回原结果，不触碰任何当前对象或新尝试
  证据不足、描述冲突或操作已有接受/访问事实：不撤销责任
  在同一状态事务中保存本尝试终态 NOT_STARTED，禁止它再取得提交资格
  幂等撤销本次 op_uid 在全部源、目标及工作区上的 U
  不制造 END 或 READER_END；该尝试没有未来物理完成可等待
  若 decision=放弃：
      关闭失败计划的新提交与发布入口，撤销其后继与重试待办
      对本计划完整取得清单中的待撤销 L 调用 WITHDRAW_HOLDS
      目标、staging、工作区和临时源失去最后 L 时都经同一步骤退休
      保留独立缓存、其他请求与其他计划的 L
      对仍有其他合法 L 的对象：
          保留这些持有及入口；稳定 READY 源不改变
          未生产的目标/工作区回到 RESERVED，清空本次完成覆盖
          通知剩余责任方重新安排生产待办，不能继续声称有在途生产
      对全部受影响对象尝试 FREE，最后执行 WAKE；返回失败
  若 decision=重试：
      要求计划及等待者仍有资格，源稳定且已保留合法恢复依据
      保留明确列出的目的、staging、工作区预留及对应计划 L
      保留重试所需的源保护 L；独立源缓存持有也继续存在
      将未生产的目标和工作区退回 RESERVED，清空本次覆盖与就绪标记
      登记 RETRY_WAIT 待办及重试原因；旧 op_uid 不再位于任何 U
      执行 WAKE；后续调度从 START_STAGE 重新准入，并分配新 op_uid
      改路径时先核对并取得新增资源；不再需要的预留按放弃规则退休

PROGRESS(op_uid,描述,part)：
  要求匹配已登记、已接受且未终结操作的完整身份、生命期和范围
  要求 part 是该操作目标内的非空范围；不接受未登记的越界覆盖
  将本代成功范围加入覆盖并集；重叠和重复范围不重复计完成量
  进度不结算最后访问，不发布视图

END(op_uid,证书)：
  已终结且身份匹配：返回 DUPLICATE，不改变当前分配
  未登记或证书不能证明登记范围的最后访问结束：保留责任并记录原因
  否则结算该操作在所有源、目标及工作区上的 U，保存终结身份
  若成功且完整覆盖目标，并且目的仍为 LOADING、计划仍有合法等待者：
      核对表示与可见性，将目的置为 READY；标记依赖阶段可推进
  若失败、覆盖不全或已无合法等待者：
      不发布；将失败候选对应的计划持有加入待撤销集合
      保留原有恢复依据，其他仍在途操作继续结算
  共同收尾（成功与失败都执行）：
      关闭已结束阶段的新提交与重试入口；成功目的的合法持有仍保留
      将本阶段不再需要的临时源保护、staging 和工作区持有加入待撤销集合
      对整个集合调用 WITHDRAW_HOLDS；不能仅删除 L 就假设已经退休
      对仍有其他 L 的生产工作区，记录本阶段已结束，退回 RESERVED 等待其合法后继
      其已有 U 若尚未结束，仍阻止下一次生产准入及物理复用
      对所有受影响源、目的、staging 和工作区逐个尝试 FREE
      本次全部退休/回收尝试结束后才执行 WAKE，不在辅助对象收尾前提前唤醒

PUBLISH_AND_ACQUIRE(plan,owner)：
  要求 owner 仍有服务资格，全部必需副本为同一恢复位置和相容身份
  原子安装完整视图，并在启动消费者前登记各 reader_uid 到 U
  返回读取权；不能只安装部分层后让请求执行

READER_END(reader_uid,最后访问证据)：
  只结算该读者自己的责任；重复结束不减少其他 U
  对相关对象逐个尝试 FREE；执行 WAKE

CANCEL(plan,owner)：
  在同一状态事务中关闭该 owner 的未来取得、提交与业务发布入口
  撤销该 owner 尚未启动的待办与重试待办；共享计划只删除这个等待者
  从持有反查索引取得该 owner 的全部相关对象，形成受影响集合 A
  对该 owner 的视图和计划代持 L 调用 WITHDRAW_HOLDS
  保留其他请求、等待者和缓存的 L；它们继续承担相应生产或恢复责任
  不删除任何已接受 I/O、DMA、转换、重算或读者的 U
  对 A 中每个对象立即尝试 FREE，不等待未来 END 或 READER_END
  全部回收尝试结束后执行 WAKE，再返回取消结果
  此后继续接收原有 END 和 READER_END；它们仍分别尝试 FREE 和 WAKE

RETIRE(x)：
  先检查恢复合同允许撤销相应逻辑持有
  调用 WITHDRAW_HOLDS 撤销这些持有；其他合法 L 保留，已有 U 继续有效
  对全部受影响对象尝试 FREE，再执行 WAKE

FREE(x)：
  仅当 state=RETIRING、L=空、U=空且无未知访问隔离时执行
  要求 alloc 中当前生命期仍等于 x，归还其物理容量，置为 GONE
  不按地址相同处理其他 epoch；旧终结事件只作去重
  返回是否实际释放以及释放的层与容量，不在此启动新操作

WAKE：
  按不使持续可行计划永久饥饿的策略，重新检查容量、依赖和重试待办
  已取消或失败的待办不再启动；无法推进的计划保留明确等待原因
  能完整预留本阶段资源的计划原子取得资源，再进入相应合法阶段
  RETRY_WAIT 必须重新经过 START_STAGE，不能复用旧尝试的启动资格
  每轮扫描有界；没有进展时返回状态循环，不能占住线程等设备
```

WITHDRAW_HOLDS 是所有持有结算入口共用的状态转换，不只是失败处理的辅助动作。成功生产也可能使私有工作区或临时源失去最后 L；即使目的已正确 READY，这些辅助对象仍必须明确退休后才能 FREE。该步骤只决定是否关闭新入口，既不删除 U，也不把还有共享持有的对象当作无主。阶段已结束但仍被其他 owner 保留的工作区要交回合法备用状态，不能保留一个没有生产者或待办的 LOADING 假象。

全部未启动的证据必须覆盖整项操作，而非只有最后一个提交调用。若先前有一个分段已被接受，后一个分段被拒绝，就不能按整个操作 NOT_STARTED 撤销责任。接口返回错误但接受状态未知时也不能套用此路径。模型中的可信结果是适配器合同输入，不证明真实驱动能够提供这种证据。

放弃与重试承担不同容量成本。放弃会在本入口完成无保护候选的退休和回收；重试保留所列预留，因此仍可能挡住其他请求。等待重试期间没有在途 U，不代表预留已经空闲。若重试收益、期限或公平性不再支持继续保留，应显式转为放弃，不能无限保留一个没有待办的 RESERVED 候选。

取消入口也必须自己完成回收尝试。生产已经 END、候选 READY、L={A}、U=∅ 且没有读者时，取消 A 会直接得到 RETIRING→GONE。此时不存在待处理的生产或读者完成，不能把回收寄托于以后再来一个事件。若随后要唤醒的计划需要同一层全部容量，必须先归还容量，再重试预留；只发出取消响应不会推进它。

这与在途取消具有不同后继：若 U 非空，本次 FREE 只能返回未释放；原操作真实结束后，END 或 READER_END 才能完成回收。对已进入 RETIRING 的目的副本，完成事件仍须结算 U，但不得再改成 READY。共享候选仍有 B 持有时，取消 A 不使整个候选 RETIRING，也不撤销 B 的视图或生产需求。

安全性要求不能释放仍受保护的对象；推进性还要求无保护的放弃对象确实被处理，以及释放后的等待者确实被重试。这两个性质要分开检查。推进保证以必要终结证据最终到达、状态循环继续服务且调度公平为前提；无法证明最后访问结束的隔离对象继续占容量，是保守边界，不能伪造完成来满足推进。

按对象线性搜索已有副本需要 O(N_c) 次候选检查；完整身份索引可以缩小查找集合。淘汰排序的一个实现为 O(N_c log N_c)。取消或放弃若有计划/owner 到持有对象及视图的反查索引，遍历成本随本次受影响记录数增长；没有索引时应扫描全部副本和待办，不能只处理碰巧仍有完成事件的对象。WAKE 的成本还随等待计划数及其资源资格查询增长。操作、读者和终结去重账也占主机容量；去重记录的保留期限由接口合同决定。

## 预取窗口、有限流水与共享资源

对一段固定表示的传输，设实际载荷 D 字节、服务率 β、启动 S、排队 Q、转换 C，则粗估 T_m=Q+D/β+S+C。消费期限为 d 时，只有提前量覆盖 T_m、目的区可取得且共享资源允许，才可能隐藏全部取得时间。提前 h 层只是组织方式，每层计算时间和队列变化后要重新计算。

单块路径为 SSD→主机接收区→必要转换→锁页发送区→设备目的槽→消费者。每条边分别要求源稳定、目标有写权、范围正确和完成可见。固定宽表示中，逻辑位置 i 对应源偏移 (i−a_src)s 和目的偏移 (i−a_dst)s，s 为每位置字节；分段必须同时调整两个偏移。压缩组不能直接套这个线性映射，需取得完整编码组及解释元数据后转换。

不同块可以流水，但同一个块的这些依赖仍存在。主机接收区要保留到转换或 H2D 最后读取；设备槽要保留到最后消费者结束。一个 stream 的事件只覆盖其实际排序到的访问，不能自动涵盖外部 SSD 读取。

设连续 L 个工作单元依次经过复制 t_m、计算 t_c，两资源独立、各自串行、常数时间且有两个可复用槽，则有限任务时间为

T_L=t_m+t_c+(L−1)max(t_m,t_c)，L≥1；T_0=0。

一个槽要求上一单元计算结束后才能装入下一单元，时间为 L(t_m+t_c)。第一块仍付首填，最后一块仍须排空。更多槽不会缩短已饱和资源的服务需求，也不能消除同一请求的 token 反馈依赖。

多请求、多阶段共享资源 r 时，先累计该窗口中该资源实际承担的 Q_r，再检查周期 P≥Q_r/β_r。CPU 解包和 DMA 共享 DRAM 时，转换读写也进入 Q_r；权重、KV 与错误预取共用 H2D 时同样先相加。不同线程或 stream 不能分别取得同一链路的独占满速。

β 若是声明的硬能力上界，D/β 才提供相应严格下界；以某次测得的有效速率代入通常只是条件化估计。估计超目标需要重新校准，不能自动当作不可行证明。

| 成本 | 同一候选、同一窗口中的必要账目 |
|---|---|
| 计算 | 索引、校验、解包、转置、重算和真实消费者计算；重算按完整合法步骤计 |
| 访存 | 源读取、目标写入、staging 读写、转换中间量、页表和设备重复读取 |
| 通信 | 每条链路的实际载荷、填充、重载、错误预取、写回与重试；明确未启动的尝试没有数据载荷，提交和结算仍有开销 |
| 准备 | 格式整理、池和注册、路径规划、范围描述、版本匹配、操作登记与重试准入；一次性与每次工作分别摊销 |
| 同步 | 生产完成、消费者可见、最后读取、共同发布、失败排空、未启动结算、取消回收和容量唤醒 |
| 驻留 | 以上各对象和旧版本的同时物理并集；重试保留区继续计费，未兑现承诺另作准入约束 |

## 场景：16 GiB 设备上的三级存储

以下均为推导设定。GPU 可用 16 GiB，主存 64 GiB；模型权重及布局合计 20 GiB，设备工作区 1 GiB，双缓冲池合计 1 GiB。普通 KV 为 32 层、8 个 KV head、128 维、每元素 2 字节，每 token 全层 K/V 为 2×32×8×128×2=128 KiB。128 个请求各有至多 160 个已计算位置，主项为 2.5 GiB。

若 GPU 常驻 10 GiB 权重，另 10 GiB 在 DRAM 按层取得，设备主项为 10+2.5+1+1=14.5 GiB。双缓冲池已计一次，池中正在加载的权重不能再加一次；页尾、其他激活、metadata 和碎片仍须容纳于余量。主存另计自己的权重、接收和转换对象。

进一步假定本候选每个 decode 轮次确实要经过同一 H2D 搬运这 10 GiB，且链路服务率不可能超过 16 GiB/s，则仅传输就至少需 625 ms/轮。50 ms ITL 目标因此排除了这个明确候选；增加 SSD 容量和预取槽都不改变其必要字节。若改为跨轮保留、改变计算放置或采用合法的小表示，原排除前提改变，必须重算。

一轮推进 128 个请求时，该传输约束给出吞吐上界 128/0.625=204.8 token/s；每个请求仍等待自己的完整轮次，不能把吞吐倒数当作 ITL。若冷 SSD 的最高供给率设为 2 GiB/s，从该路径读取完整 20 GiB 至少需 10 s，H2D 和转换另受依赖与资源约束。

假定 10 GiB 非常驻部分均分到 32 层，每层载荷为 0.3125 GiB，单层复制理想项为 19.53125 ms。若当前层计算只有 2 ms，只提前一层不能隐藏约 17.53125 ms 的复制；若计算为 30 ms，在前述独立资源、双槽和完整依赖假设下，稳态复制才可能被覆盖。完整有限任务仍包含首填和末尾计算。

访问顺序也是变量。逐微批完整推进模型可能重复装载权重；按层让多个微批复用已载入权重可以摊薄这笔流量，但扩大同时存活的激活和 KV。不能只交换循环顺序而省略各微批的层间激活与 token 依赖。低位表示减少容量与传输时，还需增加恢复尺度、转换工作区和质量验证。

恢复与重算也可反转。同一语义边界占 512 MiB，H2D 服务率设为 16 GiB/s，纯传输项为 31.25 ms；SSD 为 2 GiB/s 时纯读取项为 250 ms。若合法重算为 20 ms，它可能优于恢复；若为 200 ms，DRAM 恢复具有优势的可能性增加，但 SSD 路径仍可能更慢。不能只依据缓存命中选择恢复。

## 共享、取消与槽复用的组合轨迹

设 DRAM 中稳定对象 O 的有效范围为 [0,32)，本次恢复 [0,16)。目标槽 h 的本生命期为 (h,7)，另有可靠恢复依据保留。以下是逻辑轨迹，不是设备测量。

| 事件 | 内容、拥有者和访问责任 | 容量及允许后继 |
|---|---|---|
| 预留 h，登记复制 op | 源和目的都有 op 使用责任；h 为 LOADING | 源与目的同时计费，不能发布 |
| [8,16) 先到，[0,8) 后到且重复通知 | 完成覆盖按同一 op 取并集 | 不因重复范围增加完成量；尚无最后访问证据时仍不可读 |
| op 完整成功且最后访问结束 | 结算源、目的的 op；h 进入 READY | 可建立 A、B 的共享视图，h 的物理容量只计一次 |
| A、B 分别取得 reader_A、reader_B；随后 A 取消 | 只撤销 A 的业务持有与视图；既有 reader_A 继续受保护 | B 和缓存拥有权不受影响；本次 FREE 因保留责任而不释放 |
| 撤销全部逻辑持有，申请淘汰 h | 关闭新消费，h 为 RETIRING；两个读者仍在 U | 不增加空闲容量 |
| reader_A 结束并重复通知 | 只结算 reader_A | reader_B 仍阻止复用 |
| reader_B 最后读取结束 | L、U 均空，FREE 释放 (h,7)，随后 WAKE | 等待计划才能取得容量，h 才能取得 epoch=8 |
| 新对象使用 (h,8)，旧 op 重复完成到达 | 旧通知命中终结记录 | 不发布、不释放新对象 |

还必须检查一个没有后续完成事件的取消分支：op 已结束、h 为 READY、仅 A 持有、没有启动读者。设 h 占满该池 16 个容量单位，N 正等待同样大小的预留。取消 A 后，CANCEL 立即撤销 L、置 RETIRING、调用 FREE，归还 16；随后 WAKE 为 N 原子预留 16。整个分支不增加任何 END 或 READER_END。遗漏 FREE 时旧对象滞留；遗漏 WAKE 时容量虽已空闲，N 仍停在等待队列。这是两个可分别触发的错误。

登记后全部未启动是另一条独立轨迹，不能用上述成功生产后的取消替代：

| 事件 | 责任与状态 | 容量及后继 |
|---|---|---|
| A 取得占满 16 单位设备池的 h，并取得主机工作区 w | h、w 为 RESERVED；稳定源 s 另有 cache 持有，计划另持有自己的源保护 | N 的 16 单位设备预留等待 |
| 登记 op₀ 的 s 读、h 写与 w 使用，然后授权提交 | 全部相关 U 含 op₀；h、w 为 LOADING | 尚不能消费，也不能把提交返回视为完成 |
| 适配器证明整项 op₀ 全部未启动，A 选择放弃 | 先记录 op₀=NOT_STARTED 并封闭失败计划，再撤销 op₀ 的全部 U 和本计划 L | 没有物理生产者，因此不会有未来 END |
| h、w 无其他 L | 关闭入口，明确 LOADING→RETIRING，再 FREE→GONE | h 归还 16，w 也归还自己的容量；s 的独立 cache 持有与 READY 内容保留 |
| 全部收尾结束，执行 WAKE | N 取得完整预留，可使用 h 的新 epoch | 准入不依赖任何补发完成事件 |
| op₀ 的拒绝通知重复到达 | 命中旧终结记录 | 不撤销 N 的 L/U，不改变新 epoch |

若第三行只撤销 U/L 而遗漏第四行退休转换，h 会停在无主、无生产者的 LOADING，FREE 的状态门不会打开，N 仍等待。这是实际资源泄漏，不能靠下一次 START_STAGE、额外 gc 或未来取消补救后宣称该入口已经闭合。

若选择重试，第三行保留明确的源保护、h 与 w 的预留和计划 L，h、w 回到 RESERVED，登记重试待办。N 此时继续等待是保留容量的结果。下一调度机会重新核验资格与源，再登记新的 op₁；op₀ 的重复拒绝不应减少 op₁ 的 U。若 A 放弃但 h 仍有 B 的合法持有，只撤销 A；h 回到 RESERVED，由 B 的待办重新生产，不能释放 B 的容量或冒充已有生产仍在运行。

成功 END 还需贯通辅助池：设目的在 D 池，工作区 w 占满 W 池 8 单位；临时源 s 仅有本阶段的 L，另有等待者需要这两份资源。完整成功 END 使目的 READY 并保留其消费者 L，结算本操作的全部 U，关闭阶段入口，再由 WITHDRAW_HOLDS 撤销 s/w 的最后 L，二者进入 RETIRING，FREE 后同一次 WAKE 推进等待者。此后不提供新的 END、READER_END 或补救 gc。若 s 另有 cache 持有，它继续 READY；若 s 没有其他 L 但仍有既登记读者 U，它进入 RETIRING 却不释放，只有该真实读者结束后才回收。若工作区仍有 B 的合法持有，它退回 RESERVED，保持容量并等待 B 的明确后继，不能为满足等待者而丢掉 B。

若在部分复制后取消最后一个等待者，目的改为 RETIRING，后续进度和终结仍按原 op 处理；即使最终字节齐备，也不恢复业务发布。若共享候选仍有 B 等待，则保留候选与 B 的后继。若终结报告失败，未发布的目的被丢弃，原有恢复依据继续有效。若无法证明最后写入结束，目的保持隔离，不能仅加 epoch 后复用。

重算路线也遵守相同事务：先保留恢复起点，预留私有目的与工作区，重放到目标边界，再共同发布。失败不能把某些层的新状态和其他层的旧状态拼在一起。取消或放弃必须遍历全部相关预留，不能只回收最后完成的一个目标而遗漏从未启动的工作区。

## 条件变化与可反驳选择

| 条件变化 | 仍须保留的关系 | 调整或放弃依据 |
|---|---|---|
| 重用距离缩短且其他条件不变 | 身份、容量和最后使用条件 | 通常提高保留价值；重新检查是否值得挤占其他状态 |
| 前缀变短、重算更便宜 | 恢复到同一边界 | 保留与恢复收益可能下降，比较直接重算 |
| 历史或活跃 decode 增长 | 所需历史不能凭放置被删除 | 重算 KV 容量、每步读取和共享链路需求 |
| 链路变慢、共享流量增加 | 完成与发布顺序 | 缩减预取、改变放置或降低并发；更多槽不能消除必要流量 |
| 模型、adapter 或表示改变 | 完整计算身份相容 | 旧副本重新验资格，必要时转换或失效 |
| 专家热点漂移 | 真正路由需求仍完整执行 | 关闭无收益预测或降低深度；错误预取与错误跳算分开 |
| 取消、失败和慢读者增加 | 未结束访问继续保护存储，无保护候选及时回收 | 增加排空账，减少在途；不靠提前释放维持吞吐 |
| 明确未启动的拒绝增多 | 每次尝试独立终结，保留与放弃分别列账 | 限制重试与预留持续时间；收益不足时退休回收，接受未知时仍保留责任 |
| 全部对象可常驻 HBM | 原函数与输入合同 | 删除人为每轮搬运，以全驻留为对照重新比较 |

错误预取增加流量和驻留，但只要真实需求仍被满足，就不必改变模型函数；为了省传输而跳过实际需要的专家、历史或权重，则改变了函数或质量契约。

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 预取更深却更慢 | 无用载荷、驱逐 KV、链路饱和、转换争用 | 固定真实访问，比较完美提示、错误提示和关闭预取；记录实际载荷、驱逐、等待和准入。完美提示仍无收益时，转查提前量和共享资源 |
| 命中率增加而 p99 变差 | 命中的都是小对象、慢缺失挡住发布、缓存挤占准入 | 固定命中数改变缺失大小，分记命中字节、最后必需对象和排队；撤回命中率代表收益的判断 |
| 目的成功但辅助池仍满 | 工作区仍有合法持有/在途使用，或成功 END 只删 L 而漏退休 | 让私有辅助对象没有其他 L/U，完整 END 后不再发送完成；应在同一共同收尾归还并唤醒。再分别保留 cache L 和真实读者 U，正确路径应按不同原因保留容量 |
| 提交失败后池满不再推进 | 接受状态未知、已有部分访问，或全部未启动收尾遗漏退休 | 让目标先占满池并真实经过登记和 LOADING，再注入可信整项 NOT_STARTED 并放弃，不提供后续完成。U/L 已空但仍为 LOADING 时修退休转换；不能归因于设备慢 |
| 取消已响应但容量未归还 | 真实物理排空未完成，或取消遗漏即时回收 | 先让生产完整 END，禁止启动读者，再取消最后 owner，之后不提供任何完成事件；仍占容量时查取消回收路径 |
| 容量已归还但新计划未动 | 没有重新检查等待队列、队头阻塞或依赖确未满足 | 固定为唯一等待者、输入已齐且刚好能完整预留；若仍未取得容量，查 WAKE。随后增加共享 owner 或在途读者，正确路径应继续等待 |
| 重试后责任突然消失 | 复用了旧 op_uid，或旧拒绝按地址结算了新尝试 | 先拒绝 op₀ 并保留预留，再登记 op₁，随后重复 op₀ 拒绝；op₁ 的完整 U 应保持。若变化，修身份与终结去重 |
| 取消或复用槽后串内容 | 提前释放、旧 DMA 尚未结束、代次或对象匹配弱 | 延迟真实写者，尝试释放和重分配，再让旧写到达；分别核对物理保护和通知归属，不能只检查 epoch 字段 |
| 传输字节减少但总时间不降 | 转换、设备重复读取或计算成为瓶颈 | 固定表示与输入，分别记录转换、复制、消费者和完整完成；字节下降不支持单独的性能结论 |
| 重算比恢复慢或输出不同 | 恢复点缺失、重放不完整、数值路径或输入身份改变 | 固定目标边界，比较全驻留参考、恢复和重放的完整状态与后续输出；不先用放宽容差掩盖身份错误 |

具体反例还包括：LOADING 时发布，读者看到 poison；把 [0,16) 错当成对象 [0,32) 的越界范围，使正确实现被检查误判；取消后不再接收传输完成，使在途目标不能回收；生产已结束时取消却只改 RETIRING，使无后继对象泄漏；只更新代次却提前复用地址，使旧写污染新对象；共享页按视图重复计费造成错误拒绝，漏掉预留和 staging 则造成过度准入。这些错误具有不同预测，应分别触发。

## 检查与证据边界

交付 `tools/check_k_alg_017_full.py` 是确定性、只读、离线的 Python 标准库 CPU 模型。范围检查保留 [0,16) 的合法回归对照和真正越界的拒绝，并要求拒绝不改变状态。状态模型实际复制小整数内容，检查乱序与重复进度、部分完成、失败、最后访问证明、两个读者、重复结束、源保护和物理槽代次复用。

取消通过显式 CANCEL 入口处理。该入口先关闭 owner，删除其待办和视图，再遍历全部相关逻辑持有，尝试回收，最后唤醒等待计划。专门轨迹要求生产已结束、没有读者、没有未来完成事件时仍回收并推进唯一容量等待者。还覆盖未启动预留、多对象取消、共享的 READY/LOADING 候选，以及取消后既有读者仍保护存储。

提交裁决模型先执行实际登记：源、目标及工作区的 U 均存在，目标已经 LOADING，然后才接收可信 NOT_STARTED 输入。放弃路径关闭计划、撤销该计划持有、显式退休、回收并唤醒；重试路径保留预留和持有、回到 RESERVED，之后以新身份重新登记。检查覆盖独立稳定源、同槽新 epoch、重复拒绝、工作区、共享剩余持有、无未来完成事件的容量推进，以及重试取消。

独立观察器从未终结操作和读者记录重建物理保护要求，并用逻辑内容参考检查 READY 数据；它不只相信副本自己的使用集合。无未来事件的检查直接依据输入轨迹规定应释放的旧生命期和应取得容量的等待者，不能靠额外执行一次 gc、wake 或注入完成来救活待测路径。提交拒绝的缺陷变体只省略退休转换，仍实际撤销 U/L、尝试 FREE 和 WAKE，必须由同一观察器检出残留的 LOADING 和未准入的等待者。检查模型把原始 L 撤销与显式退休分开，共同持有结算入口依次调用两者；缺陷变体只跳过后者，不借 remove_owner 的退休副作用修复自己。成功 END 的辅助池回归采用同样方法，核对关闭阶段→撤销持有→退休→全部回收→一次唤醒；成功目的及独立缓存持有保留。额外已登记读者阻止释放的控制与无未来事件的立即回收正例分开。

故意遗漏取消回收和遗漏唤醒的两个变异继续分别检出；观察器在查找事件位置前先以 CheckError 检查事件存在。其他负对照保留提前发布、带在途责任释放及共享视图重复计费。容量事件扫描与逐时刻枚举比较，有限流水递推与独立闭式公式比较。

检查是否实际通过，以绑定当前正文、脚本及输入身份的真实执行记录为准；检查设计和历史版本的结果不能替代该记录。

模型只使用小整数范围、连续执行表示和串行控制域。容量单位是逻辑模型单位，GONE 后保留的审计记录及模拟数组不是实际 allocator 测量。可信 NOT_STARTED 是模型输入；模型不验证真实接口的证据真实性，不模拟部分接受后的分段恢复。重试重新准入通过显式调度入口验证，不证明任意调度策略的公平性。它不实现真实压缩、重放 forward、多层设备原子发布、完整共享下载调度、未知接受状态恢复或持久化。它不执行 SSD、PCIe、锁页、CUDA 或 GPU，不证明设备可见性、真实物理排空、重叠、带宽、尾延迟或知识对 Agent 的使用效果。
