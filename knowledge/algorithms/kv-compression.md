# K-ALG-021：KV 压缩：表示、近似保留与传输格式

KV 量化、丢弃历史和压缩传输减少的是不同成本。设计应说明模型实际消费什么状态、哪些信息改变，以及节省的字节发生在驻留、读取还是网络边界。压缩比不能独立决定方案；还要计入表示转换、统计、临时副本和后续 attention 的成本。

## 问题、函数与语义边界

先考虑一层、一个 KV head，K、V∈ℝ^{L×d}，L 是已完成的逻辑 token 数，d 是通道数。本章为便于展开取 K/V 同宽；不同宽度时，分别使用 d_K、d_V。对 query q_t 和模型规定的可见集合 A_t，定义

z_j=a·q_t·K_j＋β_{t,j}，p_j=exp(z_j−m)/Σ_{i∈A_t}exp(z_i−m)，o_t=Σ_{j∈A_t}p_jV_j，

其中 a 是模型缩放，β 是位置偏置，m=max_{j∈A_t}z_j。不可见项不进入分母。本章有限输入模型规定空集合输出零并标记为空，不计算空最大值或除零；实际接口须明确自己的空行合同。

| 机制 | 改变的对象 | 需要验证的关系 |
|---|---|---|
| KV 低位量化 | K/V 的数值表示 | 固定制品的执行正确性、近似误差和任务质量 |
| 重要 token 保留 | 本次实际参与 attention 的历史子集 | 新的近似函数、未来依赖和长期质量 |
| 压缩传输/存储 | 序列化字节及恢复路径 | 熵解码、量化重建、身份与端到端成本 |
| 模型原生窗口 | 模型本来规定的 A_t | 既定窗口、位置与保留语义是否被保持 |

淘汰暂不使用的跨请求缓存副本，通常允许以后重算；直接删除当前请求本应可见的历史，则改变模型函数。量化保持位置集合但改变重建值。熵编码可以相对整数码无损，前面的量化仍然有损，不能据此称整条管线无损。

输入除了数值，还包含模型/权重与前缀身份、层和 head、位置规则、格式版本、分组轴、码域、舍入、有效范围及物理映射。输出是可供消费者读取的码、参数、残差或保留集合，以及共同完成的状态视图。已分配、已写入、已封组、已发布和仍被读者持有是不同事实，不能用一个长度字段代替。

## 分组量化的数值合同

对一组有限数 x_i，码域为整数 [q_min,q_max]，q_min<q_max。本章选择最近舍入 R(u)=floor(u＋1/2)，半整数向正无穷取整；这是明确的检查合同，不声称所有 KIVI 实现采用同一 tie 规则。实数偏移格式为

q_i=clip(R((x_i−b)/s),q_min,q_max)，x̂_i=b＋s q_i。

若用 min/max 覆盖整组范围，非恒定组必须取

s=(max x−min x)/(q_max−q_min)，b=min x−s q_min。

只有 q_min=0 时才能简写 b=min x。把这个简写直接用于有符号码域会错配重建区间并裁剪高端。例如 x=[−1,0,2]、码域 [−2,1] 时，正确 s=1、b=1，可以精确重建三个值；错误 b=−1 会把 2 裁成重建值 0。执行与参考若同时复制错误公式，往返自洽仍可能掩盖缺陷。

常数组 c 选择合法码 q_c=q_min、s=1、b=c−q_c，精确重建；空组拒绝。另一种格式 s(q−z) 使用整数零点 z，不能把实数偏移 b 当作 z。NaN、Inf、保存后为零或非有限的尺度应拒绝或进入明确的高精度例外。实际制品须先冻结保存精度下的参数，再编码；数学参数经过保存舍入后不能继续配旧码而声称同一重建值。

```pseudocode
输入：非空有限向量 x，整数码域 [qmin,qmax]，明确的参数保存格式
输出：整数码 q、正尺度 s、实数偏移 b

若 qmin≥qmax 或输入不合法：拒绝
若 min(x)=max(x)：
    qc←qmin；s←1；b←min(x)−qc
否则：
    s←(max(x)−min(x))/(qmax−qmin)
    b←min(x)−s·qmin
将 s、b 转成实际保存格式并冻结
若冻结后的 s 非有限或不为正，或 b 非有限：拒绝
对每个元素 x_i：
    q_i←clip(floor((x_i−b)/s＋1/2),qmin,qmax)
消费者按冻结的 s、b 重建 b＋s·q_i
```

在精确参数、无裁剪且最近舍入的模型下，单元素误差不超过 s/2；实际浮点运算和参数保存另有误差。attention 的误差还受 query 方向影响：Δz_j=a·q_t·ΔK_j，故 |Δz_j|≤|a|·||q_t||₂·||ΔK_j||₂。同一可见集合内，若 ||V_j||≤M，则

||ô−o||≤M·||p̂−p||₁＋max_j||ΔV_j||。

K 的重建误差先改变 softmax，V 的误差再进入加权和。较小的 KV 均方误差不直接保证较小的输出误差，更不能保证自回归轨迹或任务答案不变。

## KIVI 式流式表示：两个轴和两个残差边界

[KIVI v1](../sources/S-KIVI.md) §3 与附录 A 的机制是：K 固定 channel，跨 token 分组；V 固定 token，沿 channel 分组。对 K，参数身份为 (层、KV head、token 组 g、channel c)，g=floor(j/G)；对 V，身份为 (层、KV head、token j、channel 组 h)，h=floor(c/G)。名称 per-channel 描述参数属于哪个通道，不能理解为把不同通道任意混成同一组。

K 的离群通道观察解释了为什么隔离通道可能减少其他通道的网格损失；V 的 per-token 分组则使其他 token 的范围不直接改变某个重要 token 的量化网格。这是论文评估模型上的经验依据，不是所有架构、head 或 latent 表示的最佳轴定理。

选择正整数 G、R，且 R 是 G 的倍数。K 的残差是凑组缓冲：追加后达到 R 个 token 就按 G 封组并清空。V 的残差是最近 R 个 token 的高精度队列：超过 R 时量化最旧行。对从空状态顺序追加并完成封组的长度 L，有

r_K=L mod R，n_K=L−r_K；r_V=min(L,R)，n_V=L−r_V。

K 的已量化范围是 [0,n_K)，V 的已量化范围是 [0,n_V)，通常不同。例如 G=2、R=4、L=8 时，K 已全部量化，V 的后四行仍为高精度。不能按 K 的分区边界切出 V 的概率权重。

```pseudocode
输入：私有状态、当前层新 K_t/V_t、G、R、通道数 d、量化合同
状态初始化：L←0；K码/参数表、V码/参数表为空；Kr、Vr为空
           K起点←0；V起点←0
输出：长度 L+1 的新状态候选

核对新行宽度、身份与位置 t=L
将 K_t 追加到 Kr，将 V_t 追加到 Vr
若 len(Kr)=R：
    对偏移 u=0,G,…,R−G：
        对每个 channel c：
            量化 Kr[u:u+G,c]
            存入参数身份 (floor((K起点+u)/G),c) 对应的码与参数
    K起点←K起点+R；清空 Kr
若 len(Vr)>R：
    取最旧一行，其逻辑位置为 V起点
    对 h=0…ceil(d/G)−1：
        量化该行 [hG:min((h+1)G,d)]，不让填充参与范围归约
        存入参数身份 (V起点,h) 对应的码与参数
    删除 Vr 最旧行；V起点←V起点+1
L←L+1
等待全部码、参数、残差与描述完成后，才允许发布该候选
```

批量 prefill 可以按上述范围建立缓存，但论文强调当前 prefill attention 使用高精度 K/V，低位缓存供后续 decode 消费。逐 token 运行近似 attention 处理整个 prompt 是另一种算法，不能把它与该 prefill 路径混为一谈。L=0 时输出空缓存；L<R 时两侧都没有量化组；d 不能整除 G 时，V 的末通道组只包含有效通道。

解码按逻辑位置独立定位 K、V。得到全部 logits 后做整体 softmax，再按 V 自己的边界消费 p[0:n_V) 与 p[n_V:L)。也可直接使用下面的在线归约，避免完整物化 logits 和高精度 KV。

```pseudocode
输入：q、合法逻辑集合 A、K/V 的独立码表与残差边界
输出：attention 输出和可选的逐位置概率统计

m←未设置；质量 l←0；加权和 U←零向量
对 A 中每个逻辑位置 j，按不重复、不漏项的 tile 遍历：
    按 K 的组身份或 Kr 读取并重建 K_j
    按 V 的 token/通道组身份或 Vr 读取并重建 V_j
    z←a·q·K_j＋位置偏置
    若 l=0：m←z；l←1；U←V_j
    否则：
        m新←max(m,z)；r←exp(m−m新)；e←exp(z−m新)
        U←r·U＋e·V_j；l←r·l＋e；m←m新
若 l=0：输出零并标记为空
否则：输出 U/l；如需评分，再由最终 m、l 恢复各位置概率
```

分别对量化区与残差区 softmax 后直接相加是错误函数。三个等分数位置的 V 为 [0,2,4]，整体输出是 2；分成 [0] 和 [2,4] 后各自归一化再相加得到 3。K/V 边界不同还意味着即使完成整体 softmax，也必须让每个概率与同一逻辑位置的 V 配对。

## 从码到访问路径与条件化成本

一个可检查的示例格式可以将 w-bit 无符号码按 token-major 顺序组成连续位流。紧密存放时，元素 (j,c) 的位偏移为 w(jd+c)，字节位置为其除以 8 的商，字节内偏移为余数；跨字节码须合并相邻字节再掩码。分页、逐行补齐或稀疏压紧后，先由逻辑位置得到实际码槽，再计算位地址。参数仍按原逻辑组身份查找，不能用物理页号或压紧后的槽号替代。

消费者的完整路径是：固定可读快照 → 取得逻辑位置及 head 映射 → 定位码/残差 → 取得对应冻结参数 → 解包并恢复数值 → 计算 QK、整体归约及 PV → 等待最后读取结束后复用缓冲。tile 内解量化可将高精度片段限制在寄存器或片上暂存；完整展开则先写出全部高精度 KV，再由 attention 读取。前者可能重复解包，后者新增完整副本及写读交通。这里不指定某个 GPU 指令、线程布局或事务合并能力，实际硬件路径需要依据目标内核合同验证。

设每组 scale 与偏移合计 m 字节、高精度元素 b_H 字节，忽略对齐，采用独立的紧密 K/V 位流，则单层单 KV head 的容量为

B_code=ceil(n_K d w/8)＋ceil(n_V d w/8)，

B_meta=m[(n_K/G)d＋n_V ceil(d/G)]，

B_res=b_H d(r_K＋r_V)。

一组 G 个有效值的理想有效位宽为 w＋8m/G。V 的短末组、逐行/逐组字节对齐、索引和版本头会增加它。全模型再按实际物理 head 副本和层求和；GQA/TP 复制不能按唯一逻辑 head 数直接省略。

保留原设定：FP16 KV 共 2 GiB、4096 token，假设两侧各保留 128 个高精度 token，其余为 2 bit、G=32、m=4 字节。高精度为 64 MiB，码为 248 MiB，参数为 124 MiB，合计 436 MiB，约 21.3%。这是两侧都按 128 行残差计算的容量上界。按本节顺序追加后的精确边界，L=4096、R=128 时 r_K=0、r_V=128，对应码 252 MiB、参数 126 MiB、残差 32 MiB，合计 410 MiB。两个数采用不同残差条件，不能互相替代；均未包括工作区，也不声明质量达标。

量化一批 R 行 K 需要 O(Rd) 范围归约与编码，平均每新增 token 为 O(d)，但封组步会出现突发工作。V 稳态每步量化一行，也是 O(d)。attention 对 S 个实际可见位置的 QK/PV 主项约 4Sd FLOP，另有 O(S) 指数/归约和 O(Sd) 解量化操作。位宽下降主要减少候选读取字节，不按比例消除乘加。

| 成本 | 必须计入的对象 |
|---|---|
| 计算 | min/max、编码、解包、尺度应用、attention、评分与选择 |
| 访存 | 码与参数读取、残差、统计数组、gather、展开副本的写读 |
| 通信 | 实际传输的码、参数、头、概率表、位置表及物理副本 |
| 准备 | 格式转换、布局建立、预编码、概率统计和控制器校准 |
| 同步 | 封组完成、码与参数共同可见、统计完成、最后读者结束 |
| 驻留 | 码、参数、残差、旧快照、私有候选、工作区及双缓冲 |

峰值沿同时存活对象求和。被旧读者持有的版本不能提前扣除。存在重叠时沿依赖图和竞争资源估计关键路径，不能把全部阶段简单相加，也不能默认解码、传输和 attention 完全重叠。

## H2O 式保留：预算、初始化与提交

[H2O v1](../sources/S-H2O.md) §3–4 使用累计 attention 和近期 token。明确总预算 B=B_H＋B_R，B_H、B_R 为非负整数。论文 §5.1 均分两区，附录 A 用 k 分别表示两区，因此实际总槽数为 2k。百分比必须说明分母：prompt 1000 token、总预算 200，生成至总长 1500 后仍只占当前历史约 13.3%。

一种明确的初始化是先对 prompt 完成全历史 causal prefill，逐层/head 累计当时实际计算的归一化 attention，随后保留最近 B_R 行和其余位置中最高分的至多 B_H 行。空 prompt 的统计和集合为空，但这不自动提供生成所需的合法起始输入。若改成 prompt 内逐行淘汰，后续 prompt 行已经读取近似历史，应作为另一配置重新评估。

下面固定单 token 追加、预算不变、同分优先较小逻辑位置的执行约定。F 只需保留仍存活位置的累计分数，删除后不再追踪无法读取的真实未来贡献。

```pseudocode
输入：旧集合 S、旧累计分数 F、位置 t 的新 K/V、B_H、B_R
前提：|S|≤B_H+B_R；S 中的状态已完成；近期历史仍在 S 中
输出：本步输出、新集合与新分数的私有候选

A←S∪{t}；新 K/V 先置于独立 staging
对 A 读取旧状态和 staging，整体 softmax，得到 o_t 与 p_t,j
对 j∈A：F候选[j]←F.get(j,0)＋p_t,j
R←最近 min(B_R,t+1) 个逻辑位置；核对 R⊆A
C←A\R；H←空集
重复至多 min(B_H,|C|) 次：
    扫描尚未选择的候选，选 F候选 最大者，同分选较小逻辑位置
    将其加入 H
S新←R∪H；F新仅保留 S新 对应条目
核对 |S新|≤B_H+B_R
本步输出、评分快照和所有旧读取结束后，才允许覆盖淘汰槽
共同发布 S新、F新、逻辑位置映射、内容和槽代次
```

持久集合至多 B 行，当前步的 A 可能有 B＋1 行，staging 及旧读者还增加瞬时驻留。近期区的环形物理顺序不等于逻辑顺序；复用槽必须同时更新位置、内容、分数和代次。选择错误和提前覆盖是不同问题：即使 S新 正确，先覆盖旧槽再计算本步贡献仍会读错。

上述重复扫描为 O(B·B_H)，全排序可改为 O(B log B)。在固定预算、一次只新增一行且旧集合已满足条件时，可组织成一次淘汰扫描，但必须保持评分与近期保护规则。许多融合 attention kernel 只返回输出和 LSE，不能据此直接获得每个历史位置的 p。额外统计路径可能需要暂存或第二遍 QK；这一成本不能省略。

累计分数偏向有更多累加机会的旧 token。论文附录 B.2 报告平均分替代在其测试中退化，这既不证明累计分对所有任务最优，也不允许把换成平均分称作同一算法。在线策略只能利用已经观察的贡献，不能借用未来生成作为可部署选择器。

GQA/MQA 中，多个 query head 共享一个 KV head。可对对应 head 的分数求和或平均后共享选择；也可独立保存各自集合；或保留并集。若 B=3、近期位置为 3，两个 query head 分别选择 {0,1,3}、{1,2,3}，并集有四行，不能继续按三行计容量。独立副本则可能损失原有共享收益。这些组合需要新的质量与资源对照。

## 删除的误差、反例与证据范围

固定同一组完整历史的分数与 V，设删除集合 D 的概率质量 δ=Σ_{j∈D}p_j，保留集合非空且 δ<1。删除后重新归一化，输出差为

o−o_S=δ(μ_D−μ_S)，

其中 μ_D、μ_S 是各集合按原概率重新归一化的加权均值。若 ||V_j||≤M，则 ||o−o_S||≤2Mδ。这个局部界还没有包含后续层和生成轨迹变化；累计历史评分也不保证下一步 δ 小。

H2O §3.1 的稀疏性按每行最大 attention 的 1% 阈值统计，并非严格零。许多小项可以累积出大质量，大幅值 V 可以放大输出差。长时间低关注后突然查询早期实体或数字、话题切换、多轮追加、不同 head 依赖不同位置，都是必要反例。删除位置以后，扩大预算不能仅靠改长度恢复它，必须有合法副本或重算路径。

质量对照分别运行完整缓存、仅近期、仅重要和组合，并固定实际总预算。参考须实际消费各自历史；仅改变 mask、仍保留完整物理缓存可以研究近似输出，却不能证明容量收益。分支回滚、环形绕回和异步槽覆盖另查状态正确性。

性能证据仍受设置约束。H2O §5.2 使用等长 padding 的合成输入和固定输出长度；generation throughput 的分子为生成 token 数，分母包含 prompt 与 decode 时间。部分长上下文速度测试超出 OPT 原训练上下文，不能作为该长度长期质量证据。附录 C.2 的额外吞吐来自 FlexGen 权重压缩，不能读成任意 KV 量化与保留组合已经通过。真实服务还需到达过程、长度长尾、排队及相同质量约束。

## CacheGen 式传输：锚点、量化码与熵区间

[CacheGen v1](../sources/S-CACHEGEN.md) §4 将完整 KV 张量变成可传输位流。每个 chunk 的首 token 为锚点，先量化并重建 Â；其余 token 编码 Δ_j=F_j−Â，再量化 delta。解码使用同一个 Â，得到 F̂_j=Â＋Δ̂_j。若编码端减原始锚点 A，解码端却加 Â，会额外引入 Â−A 的偏移。

固定 v1 采用十 token chunk、锚点 8 bit，以及按浅/中/深层选择 delta 位宽的若干等级。这些是论文配置，不是通用最佳值。与链式相邻差分相比，共用锚点允许 chunk 内 delta 并行恢复；锚点精度和 chunk 长度又影响 delta 分布、开销和质量。

为说明熵编码本身，设一个独立符号流使用固定整数频数 f_s>0，总数 M，累计频数 C_s=Σ_{u<s}f_u。算术编码将符号序列缩成嵌套区间。下面是精确有理数解释模型，足以重建机制；生产实现通常使用有限宽整数区间与重整化，须另核对舍入、终止和格式兼容，不能直接用此模型推算吞吐。

```pseudocode
输入：量化整数符号序列、正频数表 f、符号数 N
输出：区间内的有限二进制标签及其位数

编码：
    low←0；high←1
    对每个符号 s：
        width←high−low；oldlow←low
        low←oldlow＋width·C_s/M
        high←oldlow＋width·(C_s+f_s)/M
    从 n=0 起递增：k←ceil(low·2^n)
    首次满足 k/2^n<high 时，保存 k 的 n 位标签和 N，结束

解码：
    x←k/2^n；核对 0≤x<1，N 与格式一致
    重复 N 次：
        找唯一 s，使 C_s/M≤x<(C_s+f_s)/M
        输出 s；x←(M·x−C_s)/f_s
    按约定的流顺序重组锚点码和 delta 码
```

必须由格式明确每个流属于 K/V、层、channel、锚点或 delta，以及使用哪份表。CacheGen 设计段描述按模型共享的层/通道统计，实施段又描述从对应 context 计数；不能把其中任一共享范围当作未经限定的统一 ABI。流长度、表版本、量化参数、chunk 边界、位置列表和模型/前缀身份共同决定恢复。

熵解码只保证在正确表和正确位流下恢复整数符号。它不是通用损坏检测器；损坏后的标签也可能解出另一合法序列。容器需要自己的长度、完整性与身份验证，失败时保持目的状态未发布。

```pseudocode
编码：
    固定完整、合法且不可变的输入快照
    对每层、head、K/V 和每个 chunk：
        量化锚点，使用实际保存参数重建 Ahat
        对其余有效位置：量化 F_j−Ahat
        按声明的层/channel/类型顺序组织符号流
        使用确定的频数表执行区间编码
    写身份、几何、有效长度、量化/表版本、流长度与完整性信息

恢复：
    预留私有目的空间，校验容器和所有格式身份
    解出符号，按各自参数重建锚点与 delta
    对每个有效位置写 Ahat 或 Ahat+Delta_hat；恢复原逻辑位置
    完成必要的设备布局转换，等待数据和描述共同可见
    全部必要层和范围完成后发布；任一步失败均不发布部分恢复点
```

## 控制器的临界点与预测边界

单次串行比较中，原始 D 字节、压缩比例 r、在线编码/解码及额外转换总时间 T_c、带宽 B，压缩优于原始传输需要

T_c＋rD/B<D/B，即 B<(1−r)D/T_c。

D=512 MiB、r=0.25、T_c=12 ms 时，20 GiB/s 的原始与压缩路径为 25 ms、18.25 ms；100 GiB/s 为 5 ms、13.25 ms；31.25 GiB/s 时都为 16 ms。单位必须把 MiB 转成 GiB，并把秒转成毫秒。只比较字节量会在高带宽处错选。

CacheGen 将编码移到查询到达前，所以在线路径通常只计解码，离线预编码多个等级的时间和存储仍应另报。通用控制器还要比较文本传输后重算：

T_KV,k=T_目录/排队＋S_k/B＋T_解码,k＋T_布局/H2D,k＋T_后续计算，

T_text=T_文本获取＋T_完整前缀及新输入计算。

若阶段流水化，应用依赖图替代串行和。后续计算仍包含新 query 对已恢复历史的 attention，随历史、query、batch、表示和实际 kernel 改变。论文仅以 prompt 长度拟合的经验项不是通用复杂度公式。其固定 TTFT 排除检索选择，网络模型假设带宽/RTT 已知，也不能直接替代用户端 TTFT。

控制器先过滤身份、质量和容量不合法的候选，再按目标选择：最小时间，或 deadline 内质量最好的等级。若没有可行候选，应报告不可行、等待或按服务策略拒绝；不能未经质量合同允许自动降低质量。带宽、CPU 解码负载和源端排队变化后，应重新校准并记录错选及超时。

压缩比、解码吞吐和任务质量受分布影响。固定 v1 的自由文本生成及超大模型验证有限；独立文档 KV 也不能因为位流可恢复就被视为精确可拼接。不同上文依赖的复用边界见相关条目。

## 组合轨迹：量化、保留和恢复的一次推进

一次单 token decode 从旧快照 S、F、量化参数和物理映射开始。先取得所有必要层的合法恢复状态；远端数据只在解码、转换和可见性完成后可读。当前层产生新 Q/K/V，将新 K/V 放入私有候选。按已声明封组顺序推进表示，再对 S∪{t} 进行整体 attention 和评分；产生下一层输入，准备 S新。所有层输出与状态完成、请求仍允许提交时，才共同发布新逻辑终点。失败保留旧已提交视图；取消后停止新工作，等待已经发起的读写结束再回收。

量化与保留的交界不能只写成“分别调用两种算法”。一种具体可执行的组合选择如下：

- 已封组 K 的组身份按原始逻辑位置保留。淘汰部分码后，可以压紧码槽，但每个存活元素仍引用原组参数；最后一个引用消失后才释放参数。压紧不会自动重新分组。
- 尚未封组的 K 凑组缓冲仍保存这一批原始 R 个生成位置，包括已不参与 attention 的位置，直到完成封组。封组后只保留当前集合需要的码与参数。这样分组可继续推进，却增加最多 R 行量级的暂存，不能按 B 行 KV 作为总容量。
- V 的参数按 token 建立，淘汰整行时可一起释放该行码/参数。近期高精度区与 H2O 的近期集合是两个条件，分别记录年龄和是否存活。
- 原组尺度不变时，保留元素的重建值不变；若改成重分组，需要从可用值重新编码，并承认新增量化误差、准备、工作区和发布成本。已丢弃的原始高精度数不能凭旧码恢复。

例如 G=2、R=4、B_H=2、B_R=1，完成位置 0…3 后可能只保留 {0,2,3}。K 已封组，位置 0 使用组 0 的参数，2、3 使用组 1；把码压紧到槽 0、1、2 后，位置 2 仍属于组 1，不能按新槽 1 推成组 0。V 此时仍为高精度；到长度 5 时，存活的位置 0 才因离开 V 的最近四行而量化。两侧转换时刻不同。

对该存活集合，K 参数有两个组，而不是按 ceil(3/G) 随意重建的两组新参数；数目偶然相同不代表元素归属相同。未来集合为 {0,4,8} 时，可能触及三个原组，每组每通道都需要参数，元数据不再按“存活元素/G”直接估计。保留孔洞与重新编码是不同成本选择。

共享前缀的码和参数一旦发布，不可因私有分支追加而改写。封组涉及共享元素时，要先隔离相关内容与参数，或者保留旧组快照；旧读者结束前不能复用它。回滚和新分支还须带前缀身份，不能仅按相同逻辑位置复用另一分支的组。

传输也有交界：如果希望保持既有量化制品，熵编码应保存原码及冻结参数；若先解量化，再做 CacheGen 有损编码，恢复后又量化为驻留格式，已经是多次近似的新制品，需要组合质量验证。稀疏历史若省掉 chunk 锚点，须保留解码需要的锚点依赖，或对私有存活快照重新编码并携带原位置列表，不能直接删除依赖字节。

## 条件改变后的选择

| 条件变化 | 保留的关系 | 调整与放弃依据 |
|---|---|---|
| 历史短、L≤R | 逻辑位置和整体归一化 | 大部分甚至全部为高精度，额外管理可能无收益 |
| G 减小或位宽增加 | 固定参数解释码的合同 | 重新编码并计参数流量；质量收益不足以抵消成本时改选 |
| R 增大 | 两侧残差边界仍独立 | 高精度驻留增加、封组突发变大；质量不随 R 保证单调 |
| 分布、任务或模型变化 | 原制品可按原参数解码 | 重测敏感层、长生成和罕见依赖；质量不达标则提高精度或放弃近似 |
| MHA 改为 GQA/MQA 或 MLA | 状态身份、位置与数值合同 | 重核实际 head 副本、评分聚合和量化轴，不能直接沿用原字节或位宽结论 |
| 保留预算增大、近期区扩大 | 仍存活内容可继续使用 | 已删除历史需要恢复或重算；缺失时不能只改集合描述 |
| 网络带宽提高 | 相同合法恢复点 | 解码成为主项时改原始传输；文本重算也须参与比较 |
| 设备、分页或并行布局变化 | 逻辑内容和分组身份 | 重做打包、映射、同步与物理副本账；无合法高效消费者时改成熟路径 |
| 容量释放后提高并发 | 单请求函数与质量要求 | 重新测排队、尾延迟与 goodput，容量增加不保证 SLO 改善 |

KIVI §4 中组长、残余和模型之间存在质量差异，Falcon 的 2 bit/4 bit 结果也不同。不能把 2 bit 作为所有模型默认保证，更不能将普通 KV 的分组轴直接移植为 MLA latent 的最优轴。

## 检查、竞争解释与未测边界

检查顺序是原模型参考、同一码与冻结参数的独立解码参考、实际消费者。第一与第二比较近似损失，第二与第三定位执行错误。固定前缀先定位首次分歧，再另测真实自回归和任务质量；不能在两路已经生成不同 token 后，把所有后续差异归为同输入 kernel 误差。

随附 tools/check_k_alg_021_full.py 为确定性、只读、离线的标准库软件检查。量化使用 Fraction 和枚举网格参考，覆盖有符号偏移、常数组、空输入、不同 G/R、短通道尾组和逐次封组；空输入入口只返回一个状态字典，不再把字典解包成两个返回值。attention 使用独立整行公式检查在线归约及不同 K/V 边界。H2O 用子集枚举验证选择和预算，并实际构造提前覆盖及 GQA 并集超预算。传输部分执行小型有理数区间编解码、锚点恢复和带单位的成本比较。

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 同一码重建值错误 | signed 偏移、组轴、保存参数或码槽映射错 | 枚举最近网格，分别改变一组参数与物理排列；失败先修制品执行 |
| 只在封组后失败 | K/V 边界混用、尺度发布或尾组问题 | 跨 R−1、R、R+1 连续消费；逐位置对照两侧边界 |
| 各分区输出合理，总输出错误 | 独立归一化、漏项或重复项 | 不等长分区加空分区，与整行 softmax 比较；拒绝直接相加 |
| 集合正确但本步输出错 | 提前覆盖旧槽或读者未结束 | 保持选择不变，只延迟写回；实际读取旧槽内容核验 |
| 长距离问题退化 | 冷门 token 被删、量化或任务漂移 | 分开启用量化与保留，再恢复早期 token；只在对应干预修复后支持归因 |
| GQA 仍报 B 行但容量扩大 | 并集或物理副本未计 | 枚举各 head 集合及物理并集，修正预算或选择策略 |
| 位流解出整数但状态错误 | 错表、错误锚点、位置/前缀身份错误 | 对照整数序列与独立重建；分别注入表错和原始锚点差分 |
| 压缩在高带宽反而慢 | 解码、转换、CPU 排队或预测单位错误 | 扫带宽，固定质量与计时边界；对照临界点并修正在线成本 |
| 字节减少但完整时间不降 | 事务未降、解包、统计、同步或排队主导 | 分开记录逻辑字节、设备事务、kernel 与完整调用，撤回未经支持的带宽解释 |

负对照必须实际进入被检路径。两份代码复制同一 min/max 公式不构成独立参考；只打印“发现超预算”而没有断言也不构成检测。算术编码往返不能证明损坏检测能力，软件发布次序不能证明 GPU 可见性。

本章检查不执行目标 CPU/GPU kernel，不模拟完整低精度舍入、有限宽算术编码器、真实分页异步协议或多卡通信，不测设备事务、网络吞吐、任务质量或 Agent 使用效果。Python 的真实执行状态由本轮执行记录说明，不由正文预先宣称。设备与服务实验仍须固定模型、制品、输入/输出分布、质量阈值、实际后端、预热及计时边界，报告转换、统计、同步、峰值和失败样本。
