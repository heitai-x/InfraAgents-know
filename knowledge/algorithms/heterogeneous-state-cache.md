# K-ALG-009：异构状态缓存：层组、恢复位置与联合分配

混合模型保存的是若干更新规则不同的状态族。统一的是逻辑消费位置和计算身份；物理页、块表、检查点与完成事件可以不同。恢复请求必须贯通三个环节：找到全部必需状态共同支持的起点，实际生成目标位置缺失的状态，以及在失败后排空物理使用再归还容量。

## 状态族、输入输出与恢复不变量

用 p 表示已经消费的 token 数，S_g(p) 表示状态族 g 在消费 x[0:p) 后的状态；下一步输入的位置是 p。计算身份 η 包括模型与权重、adapter、输入前缀、位置规则、外部特征、dtype 和量化布局。请求身份、尝试代次和隔离命名空间另用于授权与生命周期管理。跨请求共享可以复用相同计算身份的不可变状态，但每个请求仍须取得自己的持有票据。

输入是 η、目标 p、已知输入范围、各族状态描述、发布与完成票据，以及各池容量。输出是无需模型重算的 DirectPlan、从共同起点 c 推进到 p 的 ReplayPlan，或明确失败原因。DirectPlan 仍可能需要传输和布局转换；只有目标端全部必需状态已经完成、可见并发布，才形成可消费的 RecoveryView。视图包含每族的物理句柄、对象代次、有效逻辑范围、表示和依赖关系。

| 状态族 | 更新方式 | 直接恢复所需内容 |
|---|---|---|
| 全注意力 KV | 追加有效位置 | 同一前缀的完整历史 KV |
| 窗口注意力 KV | 保留最近可见位置，旧槽可能覆盖 | 恢复后第一步所需的完整窗口 |
| MLA | 追加 latent、位置分量及量化元数据 | 与执行路径相容的压缩表示，不能只核对普通 KV 形状 |
| 递归状态 | 通常覆盖上一步状态 | 准确消费位置的快照或可执行重放起点 |
| 局部卷积历史 | 短历史移位或环形覆盖 | 本层投影输入的最近历史，通常不是原始 token |
| encoder context | 固定源下只读 | 正确源身份、完整范围和表示 |

一个状态族还要记录层集合、更新函数、保留规则、粒度和发布条件。不能因为都叫缓存，就让它们共享相同的回滚与回收规则。

必须分开四个事实：已经分配、已经计算、已经发布、仍然保留。分配页不证明数据完成；增加长度不产生递归状态；传输提交不证明目标可见；目录存在不证明对象还组成完整恢复包。重放的目标位置也只是计划值，不能提前成为已完成长度。

本章使用以下不变量：

- 所有被读状态都属于正确的计算身份、层、逻辑位置和有效范围；物理槽号不代替逻辑位置。
- 共同直接恢复位置属于所有必需族直接集合的交集；各族最大长度不能代替交集。
- 重放从全部必需族共同可执行的 c 开始，每个完整模型步骤提交后，各族才共同推进一个位置。
- 共享历史保持只读；需要写的尾页、窗口槽、递归状态和卷积历史使用私有副本或写时复制。
- 逻辑引用与物理使用分别结算；所有已提交读写结束前，页与 staging 都不能重用。
- 多池预留整体成功或不改变容量；失败后按本事务的实际拥有关系归还一次。

这些条件约束正确性。统一池、检查点间隔、逐步提交粒度和淘汰权重则是可比较的设计选择。

## 层组、统一页与实际地址

令 c_g 为一个注意力层、一个 token 的 KV 字节，m_g 为组内层数，P_g 为 token 块长，则组页字节为

M_g＝m_g P_g c_g。

c_g 已包含该层 K 与 V，不能再重复乘二。递归状态按完整快照 B_g 字节计，而非按历史 token 数线性计页；卷积历史、量化 scales 和表示元数据也要进入状态大小。

三种组织都有合法应用：按族独立池使布局和生命周期直接，但可能一池空闲、另一池耗尽；同字节块统一池允许容量调剂，但要求各组物理页字节相同；大块内子分配容纳不同尺寸，却增加对齐、碎片和回收账务。

固定历史 vLLM Hybrid KV Cache Manager 文档把 kv hidden size、block size 与 page size 分开。文档中的 num_layers 是当前组涉及的层数，不是全模型层数。它要求组内 attention 类型相同，使同请求在组内需要相同块数；组间页字节相同，使一个池只有一种分配尺寸。

规则比例可以重复同一组分配结果。不规则层数采用按最小类型层数分组、末组补 padding 的启发式；padding 消耗容量但不产生有效状态。该启发式并非最优性定理，文档也给出应调整组大小的情况。

```pseudocode
算法 BuildGroups
输入：层类型、每层状态几何、保留规则、支持的块长与对齐约束
输出：分组、物理布局、padding 账，或统一池不可取的原因
1 将共享同一实际状态对象的层识别为别名，避免重复分配
2 按状态类型与保留/更新规则形成候选组
3 对注意力组计算 m_g * P_g * c_g；对递归组计算完整状态及填充字节
4 比较各组物理分配字节；不相等时搜索受支持的分组、块长或子分配
5 对每个候选计有效状态、无效层、页尾、复制粒度与元数据
6 若没有满足布局和容量约束的候选，改用按族池或其他受支持布局
7 返回实际组到层、逻辑块到物理片段的映射，不只返回统一页字节
```

固定文档 case 4 对 Mamba 类不同状态大小的处理是：增大注意力 block size，使 P·c_att≥s_mamba；将每层 Mamba 状态填充到 P·c_att；再使用不规则分组策略。文档指出这可能使块长超过 400，并将另一种含注意力层数的填充方向标为未完成设计。因此统一页只能是带条件的方案：增大页会减少表项，同时可能增大尾浪费、分叉复制和检查点内部碎片。

若使用 LCM，384 与 512 的 gcd 为 128，LCM 为 1536，不是乘积 196608。而且需要对齐的是实际组页字节，不能只对单层每 token 字节取 LCM，再忽略层数与块长。

逻辑块也不必是一段连续物理内存。固定文档对每组 m 层分配 m 个缓冲，各缓冲容纳不同组的一层片段；一个逻辑块映射为 m 个缓冲中的片段。以 m＝2、P＝4、c＝8 B 的独立设定为例，每个层片段为 32 B，一个组块合计 64 B。若某组块表为 [0,3]，则本组层内编号 j 的 token t＝5 位于缓冲 j 的基址＋3×32＋1×8；其中逻辑块号为 1，块内位置为 1。另一组可以使用同一缓冲的其他块号，不能把编号 3 当成每组各自独立的连续大页。

实际 K/V、head、通道与 padding 的片段内偏移须由所选布局继续展开，见[分页 KV](paged-kv-capacity.md)。本章的分组映射不是任意 GPU kernel 的地址 ABI，也不规定 warp 或矩阵指令布局。

## 直接位置集合与目标恢复规划

R_g^direct 表示无需执行模型即可取得可继续状态的位置。它允许搬运稳定副本，但目标消费仍须等待搬运、转换与可见性完成。共同直接集合为

D＝I∩⋂_g R_g^direct，

I 包含输入身份、允许的位置、源对象稳定性及发布资格。若原地递归状态正在推进，不能把它的不同层分别复制后拼成一个快照；应暂停到同一完成位置，或让后续写入进入另一份版本。

窗口宽 W 在这里包含当前 token。下一步 query 位于 p，因此旧状态只需提供

[max(0,p−W＋1),p)

的 KV，当前位置 p 的 K/V 由新一步产生。核宽 K_c 的因果卷积同理需要前 K_c−1 个本层输入。W＝1 或 K_c＝1 时，相应旧历史为空，不能因没有旧槽就拒绝恢复。

为避免 token 下标与消费长度错位，下面所有存储范围均为半开区间 [a,b)：

- 全注意力保存 [0,b) 时，可直接支持消费位置 0…b。
- 普通窗口保存 [a,b)，W>1 时，正位置 p 要满足上述完整窗口包含于 [a,b)。a＝0 时允许 1…b；a>0 时允许 a＋W−1…b，区间为空则没有正位置。
- 递归族支持保留检查点集合 C_g；初始化可用时还支持 0。状态 S_g(1024) 不能通过改长度变成 S_g(768)。
- 卷积历史按 K_c−1 的读取集合检查；历史值必须属于该层正确前向输入。
- encoder context 正确且完整时不随 decoder 消费位置变化；它仍是必需族，身份不符不能绕过。

这些公式适用于连续保留范围与普通窗口。存在缺页、sink/global tokens 或不规则稀疏关系时，应对实际可见集合逐范围核对，不能压成一个最小/最大下标。

```pseudocode
算法 DirectRecoverable(eta,p)
1 核对允许的消费位置、计算身份、源版本及发布票据
2 若 p=0：检查初始化和固定 context 可用，返回结果
3 对每个全注意力族：要求 [0,p) 全部已发布且仍保留
4 对每个窗口族：要求 [max(0,p-W+1),p) 全部可取得
5 对每个卷积族：要求 [max(0,p-K_c+1),p) 的本层历史或等价快照可取得
6 对每个递归族：要求准确的 p 检查点
7 检查固定 context、表示及其他必需辅助状态
8 全部满足才返回 true
```

直接位置查询与目标规划分开。最大直接位置回答“现在可从哪里开始”；目标 p 则可能需要从更早 c 实际重放。下面给出有限、可直接实现的基线，避免含糊的端点候选遗漏 p。

```pseudocode
算法 PlanRecovery(eta,p)
输入：目标 p、各族状态描述、输入记录和资源预算
输出：DirectPlan(p)、ReplayPlan(c,p) 或失败
1 若 p 超出允许范围或身份不相容，返回失败
2 在目录与页池协调关系内检查 DirectRecoverable(eta,p)
3 若通过：保护所需对象，计算目标搬运/转换资源，尝试全量预留
4   成功返回 DirectPlan；失败撤销本次保护并报告容量不足
5 否则从 c=p-1 到 0 下降检查：
6   若 DirectRecoverable(eta,c) 不成立，跳过 c
7   从 t=c 到 p-1 逐项核对 x_t 及本步必需特征；首个不可重放项即停止本候选
8   任一项不可重放则继续下一个 c；下一候选仍从自己的 c 重新扫描
9   要求所选模型执行、表示与数值契约支持该重放
10  计算保护 c、共享历史、私有写区、递归候选和在途对象的资源向量
11  在同一协调关系内保护 c 并尝试全量预留
12  若成功，返回 ReplayPlan(c,p,输入范围,资源及保护票据)
13  若失败，撤销本次保护，继续比较其他合法起点或报告容量失败
14 没有共同起点或缺少重放输入时返回具体原因；不能选择一个非共同检查点
```

这条基线没有对输入可重放性做区间预处理。输入核对会短路，但相邻候选仍可能反复扫描同一段输入；下降枚举本身不保证整个规划线性。输入记录在规划与执行之间也必须保持同一身份和有效性，不能在检查后无保护地删除或替换所需特征。

默认选择最大的可行 c 以减少步数；复制量、驻留层级和同步不同的场景可以比较总成本。存在递归族时可枚举其检查点交集；连续范围也可先转换成消费位置的闭区间再求交。若保留 token 为 0–9，候选上界应包含 p＝10，而不是只枚举原始 token 端点 9。任意缺页或非区间身份约束仍需最终资格检查。

以全 KV 为 [0,1024)、递归检查点为 {512,768}、窗口为 [640,1024)、W＝128、卷积历史为 [0,1024)、K_c＝4，且初始化可用为设定，D＝{0,768}。512 的窗口需 [385,512)，已缺失；1024 缺少递归快照。目标 1024 可以从 768 重放 256 步；目标 512 可以从初始化重放 512 步，前提是对应输入记录完整。

## 从共同快照到完整模型状态

重放 c→p 消费的是已经确定的 x[c:p)，不是重新采样一条路径。读取 c 的视图时，全 KV 截到 [0,c)，窗口和卷积只暴露 c 所需历史；即使物理页还存有后续位置，也不能让重放 query 读到它们。

对注意力层，当前层输入 h_l(t) 产生 q、k、v；q 在该层合法历史和当前 k 上归一化，再加权 V，经过模型要求的输出投影、残差、归一化与位置无关子层后得到下一层输入。高层 K/V 必须来自低层本步输出，不能仅用原始 token 和层号直接构造。

对含局部卷积与 selective SSM 的块，先由该块输入投影生成 u，再用当前 u 与保存的 K_c−1 个历史输入计算卷积结果；由相应表示生成输入相关系数，按模型的离散化规则取得 Ā_t、B̄_t，再计算

h_t＝Ā_t h_{t−1}＋B̄_t u_t，

y_t＝C_t h_t＋D u_t。

其中 u_t 应按具体模型图解释为送入 SSM 的表示，不与卷积前投影混用。门控、输出投影、残差及归一化仍按原图执行。卷积历史通常记录卷积前投影，递归快照记录 SSM 状态，两者更新顺序不能互换。该式解释状态推进，不假定任意递推可逆。

```pseudocode
算法 ExecuteRecovery(plan)
输入：DirectPlan 或 ReplayPlan、模型图及全部资源票据
输出：RecoveryView(eta,p) 或失败事务
1 创建唯一事务/尝试代次；目标处于未发布状态
2 将共同位置 c 的必需对象搬运或映射到目标，登记每项已提交操作
3 等待所需范围完成并建立可见性；可变状态复制到私有工作区
4 若为直接计划，转到步骤 12
5 committed←c
6 对 t=c…p-1：
7   hidden←输入嵌入及模型位置处理(x_t,t)
8   按模型层序执行：
      注意力：从当前 hidden 生成 q/k/v，读取本层合法历史与当前 k/v
      将本层新 KV 写入私有尾页或 staging，输出送入下一层
      卷积/递归块：投影、读取旧卷积历史、卷积、生成选择性系数、递推
      将新卷积历史与递归状态保存在候选版本，完整执行门控/投影/残差
      其他层：执行模型规定的变换；固定 encoder context 只读
9   等待本步全部必需写入与层间依赖完成
10  将候选状态共同提交为 committed=t+1；按规则裁剪窗口并推进环形标签
11  任一失败进入 AbortTransaction；不发布部分步骤或计划目标
12 核对全部族对应目标 p、表示与身份一致、所有必要操作已完成且可见
13 在协调提交点发布 RecoveryView；将目标持有责任转交消费者/目录
14 staging 在最后使用后回收；源保护在接管成功或失败排空后解除
```

步骤提交是逻辑边界，不要求每 token 都做主机全局同步。事件依赖或经过证明的分块实现可以表达相同先后关系；分块 scan 与逐步递推的有限精度结果还须满足选定数值契约。不能据此假定跨 backend 逐位相同。

共享尾页在追加前要复制；窗口环槽只有在旧物理读者结束后才能覆盖；递归与卷积候选不得覆盖共同起点。基线可以预留整个重放输出，也可以使用有界分块工作区，但后者必须在每次扩展前重新满足容量与发布条件。

恢复模型状态与取得下一 token 的分布也要分开。只有 KV 而没有末行 logits 时，恢复到已知输入末端并不自动产生第一条生成分布。可以保存相同输出契约的 logits，或选择不晚于末 token 的合法共同起点，安全重算所需后缀。递归模型不能直接把最后一步状态倒退一格。RNG、grammar 和外部输出游标应恢复到相同确认边界；已确定 token 的重放不重新采样，也不重复提交外部输出。

## 联合预留与按身份排空

一次恢复可能需要全 KV 目标页、窗口槽、递归候选、卷积缓冲、COW 与转换 staging。先占 A 池再等待 B 池可能形成持有并等待：自由容量为 (1,1)，两个请求各需 (1,1)，各先占一池后就都无法完成。

```pseudocode
算法 TryReserveAll(tx,demand)
1 验证需求非负，按真实物理池聚合别名与共享对象
2 在池协调区检查所有 free[g]≥demand[g]
3 任一不足则不改变任何池，返回失败
4 否则一次登记 tx 对全部预留的拥有责任，并扣减对应 free
5 返回实际物理句柄与复用代次
```

预留、物化和驻留不是三笔重复容量。一个已扣除的预留转成目标页后仍是同一份物理容量；源快照、私有目标和 staging 若同时存活，则分别计入峰值。

事务生命周期可写为 ACTIVE→PUBLISHED，或 ACTIVE→ABORTING→DRAINED→SETTLED。发布只转移完整目标的逻辑责任。失败先撤销逻辑资格，再排空物理工作；错误通知、超时或请求取消本身不证明 DMA 已停止。

每次提交前登记唯一操作票据，至少绑定事务、尝试代次、操作序号、方向、源/目的对象、逻辑范围和物理页复用代次。登记应先于设备/传输可能完成的时刻；提交失败只有在确认操作没有物理使用后才能撤销登记。进行中的集合使用这些完整票据，而不是一个可以被任意消息递减的计数器。

```pseudocode
算法 AcceptTerminalEvent(event)
1 从受信任的完成路径取得事件，并核对其终结语义
2 按完整票据查找原事务已提交且仍在途的操作
3 未知、重复、字段不符或属于其他尝试的事件：不改变当前在途集合
4 取消请求只记录意图；取消确认必须证明该操作不再访问任何受保护范围
5 合法完成/终结失败/取消确认只结算匹配操作一次
6 失败操作使事务停止新提交；其他尚未终结操作继续受保护
7 迟到事件交给原代次记录或已结算墓碑处理，不增加当前代次引用或空闲容量
```

```pseudocode
算法 AbortTransaction(tx,cause)
1 tx←ABORTING；禁止新步骤、复制和传输；撤销目标发布资格
2 保留源共同快照的恢复责任，以及全部已提交操作的源/目的保护
3 对可取消操作提出取消；对不可取消操作等待终结
4 用 AcceptTerminalEvent 逐项结算，直到已提交在途集合为空
5 核对不存在仍访问本事务页、描述符或 staging 的物理使用，再进入 DRAINED
6 按拥有账撤销目标持有、释放私有页和 staging，归还预留且只归还一次
7 解除本次源保护，进入 SETTLED；保留最早错误和结算记录
8 若等待超过业务预算，业务可以失败，但未排空资源留在隔离待回收集合
```

完成代次核验不能阻止已经发出的原始 DMA 写到同一地址。安全性首先来自旧操作排空之前不重用地址；代次用于防止迟到通知被结算到新使用者。若系统支持设备侧撤销或访问隔离，必须另有对应平台保证，不能把主机上的整数相等检查当成该保证。

具体轨迹如下：事务 T 的 A、B 两族传输已提交；A 报告失败后，T 停止提交，B 仍在写。此时两个未知完成事件不能减少 T 的在途集合；A 的终结事件只结算 A；B 的取消请求也不结算 B。直到 B 完成或得到可靠取消确认，才能归还目标页和 staging。页面随后交给 T 的下一尝试，旧 A/B 的重复通知只命中旧记录，不改变新尝试。

错误实现若在 A 失败后立即归还页，下一请求可以先写入新内容，随后旧 B 的物理写覆盖它。这个反例必须实际执行释放、重分配和旧写到达，检查新对象内容或“在途操作仍保护原租约”的独立不变量；只计算一个假想 free 向量不构成该负对照。

## 状态包价值与条件化成本

删除一个很小的递归检查点，可能让大量 KV 失去同位置继续执行的价值。设检查点 c 被状态包集合 Q(c) 依赖，删除后包 q 的额外重放步数为 Δ_q(c)，则可用

L(c)＝Σ_{q∈Q(c)} λ_q Δ_q(c)

估计损失；λ_q 将完整模型步折成时间或服务价值。它只能作为策略线索：共享物理对象、未来重用概率、公平性和 deadline 使多个淘汰选择相互影响。若删除后连合法重放起点都不存在，不能只给一个有限额外步数。

以下容量均为结构设定。8 层全 attention、8 层窗口 attention、16 层递归层；attention 每层 Hkv＝8、d＝128、K/V 每元素 2 B，消费长度 4096、窗口保留 256 个位置。单层每 token 为 2×8×128×2＝4096 B。

| 项目 | 算式 | 大小 |
|---|---:|---:|
| 全 attention | 8×4096×4096 B | 128 MiB |
| 窗口 attention | 8×256×4096 B | 8 MiB |
| 递归状态 | 16×4096×16×4 B | 4 MiB |
| 卷积历史 | 16×3×4096×2 B | 384 KiB |
| 主项 | 128＋8＋4＋0.375 | 140.375 MiB |

窗口容量采用保留 W 个槽的组织；下一步最少读取 W−1 个旧位置与当前 token，不能把读取下界与物理分配槽数混为一谈。删去 4.375 MiB 的递归和卷积状态，可能让另外 136 MiB 的 attention 状态失去原位置直接恢复资格。

若每 256 token 另存递归及卷积快照，16 份为 70 MiB。这里“另存”假设与当前工作状态不别名；若末端快照与当前不可变状态共享，应按实际唯一对象扣除重复项。设统一页为 512 KiB，每递归层连同卷积历史为 280 KiB，按层独占页时 16 层 padding 为 16×232 KiB＝3.625 MiB。多层打包会改变该账。

六类成本应在同一恢复计划上列出：

- 计算：T_replay(c,p)＝Σ_{t=c}^{p−1} C_step(t)，C_step 是完整模型步骤；目标 1024 从 768 重放需要 256 步，不能只计递归张量更新。检查点构造与格式转换也可能计算密集。
- 访存：状态读取、候选写入、检查点复制、COW 和块表访问。统一页分配字节不等于 kernel 实际读取字节，更不等于 DRAM 事务量。
- 通信：对每条共享链路 e，传输下界为 Σ_g B_{g,e}/β_e。独立链路可重叠，但总时间还受逐层依赖关键路径约束；不能只看最快到达的一族。
- 准备：身份核对、状态资格搜索、重放输入核对、页表与描述符、引用登记、子分配和 block/flat 转换。连续范围覆盖与检查点成员查询均为常数成本时，下降搜索中的状态族资格部分为 O(nF)，n 是候选位置上界，F 是必需族数；逐候选输入扫描的最坏 O(n²) 成本必须另计，不能把 O(nF) 当作完整规划成本。缺页结构另计范围查询成本，资源向量构造、保护与预留另按实际执行次数和处理对象计费。
- 同步：复制完成、层间依赖、步骤提交、最终发布以及失败排空。超时失败可能很快返回业务结果，但资源继续驻留。
- 驻留：唯一源对象、目标私有增量、检查点、padding、工作区、元数据和未排空对象的同时存活峰值。预留与其物化页不重复相加，共享页只计一次。

输入扫描的上界来自实际循环。目标 p≤n，候选 c 的区间长为 p−c；即使检查遇到缺项立即短路，总输入位置查询数仍可能达到

Q_input＝Σ_{c=0}^{p−1}(p−c)＝p(p＋1)/2。

若一次查询用常数时间判断该位置的 token 和全部必需特征可重放，则资格搜索加输入扫描最坏为 O(nF＋n²)。这里的常数时间假设针对已经可查询的输入记录，不包括读取外部特征文件、校验大对象或等待数据到达。若每位置还需检查 A 个独立特征项且每项为常数成本，输入扫描可达 O(n²(1＋A))；一般应累计实际检查项的成本。基线扫描只需常数额外游标空间，不创建输入可用性前缀表，原有输入和状态目录的驻留另计。

一个能达到二次查询量的失败轨迹是：目标 p＝n，全 KV 只保留 [0,n−1)，没有窗口、卷积或递归族限制，初始化可用；重放输入仅有位置 0…n−2，缺少最后的 x_{n−1}。目标 n 不能直接恢复，n−1…0 都是合法直接起点。每个候选都从自己的 c 开始，直到缺失的 n−1 才失败，因此依次查询 1、2、…、n 次，最后仍返回缺少输入。

| n | 输入位置成员查询数 n(n＋1)/2 |
|---:|---:|
| 64 | 2080 |
| 128 | 8256 |
| 256 | 32896 |

固定 F 后，该轨迹仍为 Θ(n²)。失败规划没有执行模型重放，也没有进入保护与资源预留，二次工作已经发生在准备阶段。若补齐最后一个输入，最高合法起点 n−1 只需一次输入查询即可返回重放计划；因此只检查成功结果或只测完整输入，会遗漏这条成本路径。本章保留上述基线及其真实成本，不声称已经实现输入区间预处理。

检查点间隔 Δ 增大通常减少快照字节和写流量，但增加重放距离；窗口淘汰可能让部分递归检查点根本不再是共同起点，所以平均重放不能无条件按 Δ/2 估计。恢复性能应量到第一个正确继续步骤，生成场景还要包含取得合法 logits 的成本。

## 条件变化、反例与区分实验

窗口扩大后，应重算所需历史与共同位置；旧窗口缺失时不能只扩一个长度字段。页长增大后，表项可能减少，但短请求尾浪费、共享分叉复制和统一页 padding 可能使选择反转。递归状态远大于注意力块时，可以放弃统一池，比较按族池、子分配或分层驻留。模型或表示改变时，旧状态只有经过明确的等价转换才可保留；仅总字节相同不构成复用资格。

复用变稀或前缀很短时，快照驻留和写带宽可能超过避免的重算；昂贵长前缀、较短重用距离则提高包级保留价值。完成延迟增大时，隔离待回收容量上升，应降低准入或调整预留，不能通过提前回收维持吞吐。长前缀且输入记录不完整时，准备搜索本身可能成为显著工作，应先核对输入查询量，再决定是否值得改用带明确构建、更新和失效成本的输入索引。

固定 Hybrid 文档给出 full attention 加一种高效 attention 的两类型交集思路，并说明多类型、无 full attention 的组合及 Mamba 前缀支持存在当时的实现限制。其布局示例又包含多个同类型层组，不能把“两种类型”机械解释为全模型只能有两个层组。本章的一般集合与事务算法是独立推导，不宣称该历史实现已经支持任意混合模型。

反例有不同的可观察后果。只取全 KV 命中长度会把 1024 错报为共同直接位置；复制但跳过重放会留下 S(768)；逐层提前发布会拼出不同位置的状态；源端原地推进期间复制递归层会形成撕裂快照；未知事件递减计数会伪造排空；提前释放后旧 DMA 到达会污染新请求；漏计输入重复扫描则会在规划结果正确时仍低估准备工作。不能把这些都归为一种异步错误。

区分实验应固定其余条件并给出可反驳预测：

- 固定准入请求、有效长度与计算图，分别改变 padding、块表取址和准入预算。若固定请求集后差距消失，优先支持容量与排队解释；若仍存在，再独立比较消费者和准备/复制路径。
- 固定输入，改变检查点间隔，记录共同直接位置、完整模型重放步数、快照写字节和峰值。若重放缩短而总时间变长，应转查快照写带宽、驻留或同步，不能继续只按步数预测。
- 对共享检查点负载比较单页 LRU 与包级淘汰，记录删除后丢失的共同起点及回退距离。若包级策略没有减少回退，却增加碎片，应修订其价值估计或放弃该策略。
- 对同一多层输入比较从零执行与各切点恢复，逐层核对 KV、卷积、递归和后续输出。参考按完整序列逐层计算，缓存路径按 token 推进；破坏高层输入、漏一段历史或跳过重放应产生差异。
- 延迟一个真实写者，注入未知、重复、字段错误和旧代次完成；正确轨迹不提前释放。负对照真正提前释放并重用页面，再让旧写到达，由独立物理租约/内容不变量发现污染。若只改事件到达顺序就失败，先查结算与生命周期，而非数值容差。
- 固定状态族数量与查询表示，使用上述缺少末端输入的轨迹，扩大 n 并直接统计输入成员查询；预测为 n(n＋1)/2，而非随 n 线性增长。随后仅补齐末端输入，预测最高合法起点一次查询即成功。若准备时间改变但计数不变，再检查单次查询、身份校验或资源操作的成本；操作计数本身不等于时间测量。

交付的 Python 检查定义的是确定性 CPU 模型：连续范围元数据、四层标量 attention/卷积递归模型、合成页池与物理事件账，以及基线规划的输入成员查询计数。它包含独立可见集合参考、逐层稠密参考和真实执行错误转移的负对照；不是引擎源码或真实设备测试。成本检查用原有 plan 路径计数，对照三角数和固定预期值，并拒绝错误的线性查询预算。其执行状态见作者记录，不以正文说明替代实际运行结果。真实 GPU 数值、访存事务、跨 stream/NIC 可见性、分布式故障和性能仍需对应实现与设备证据。
