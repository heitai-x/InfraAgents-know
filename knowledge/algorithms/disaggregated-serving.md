# K-ALG-013：Prefill/Decode 分离：状态传输与队列耦合

分离式服务将 prefill 与 decode 的资源策略解耦，同时引入第二份权重、状态传输、布局转换、两侧排队和接管提交。判断它是否有效，需要比较同一到达轨迹下的完整服务路径：阶段干扰减少多少，新增工作占用哪些资源，首内容与后续 token 分别等待什么。

DistServe 将阶段资源分配、并行选择和放置纳入 goodput 优化；Mooncake 将远端 KV、缓存亲和和未来 decode 负载接到这条路径。它们提供带实验条件的设计依据，不证明任意负载、拓扑或缓存命中下分离都更快。

## 请求、位置与两条就绪依赖

本章核心算法限定为固定模型、普通稠密 causal decoder、一个保留输出分支的提示词接管。其他状态族需要重新定义共同恢复位置。位置使用零起点和右开区间。规范化后的 prompt 为 x[0:n)，n>0，BOS 若存在也计入 n。首生成 token 记为 y_n：它从 prompt 位置 n−1 的末行 logits 采样得到，但自身位置 n 的 KV 尚未计算。目标第一次 decode 消费 y_n，读取提示词 KV [0,n)，计算位置 n 的 KV，再产生 y_{n+1}。

首 token 准备和 KV 准备是两个分别验证的依赖：

- FIRST_TOKEN_READY 表示位置 n 的唯一确认 token 票据可用。
- TARGET_COMMITTED 表示目标所需的提示词状态完整、数值身份相容，且已发布给模型消费者。

只有二者均成立，并且请求、容量及执行授权仍有效，才允许第一次 decode。已有 token 或 logits 票据不证明某个计算实例仍有提示词 KV；完整 KV 命中也不证明已有 logits 或 token。

| 符号或对象 | 含义与边界 |
|---|---|
| R | 逻辑请求及保留输出分支身份，绑定模型、adapter、规范化输入、位置和数值契约 |
| g、tx | 一次接管的授权代次与一次尝试身份；拒绝旧结果发布，不自动阻止旧操作物理访问 |
| H_d | 目标 d 已发布且经过验证的公共前缀终点，0≤H_d≤n |
| M_d=[H_d,n) | 目标仍缺的提示词状态；空范围仍需验证已有前缀与当前接管授权 |
| A_p | 源 p 本地逐层完整、合法的历史前缀终点 |
| b_p | 源完成显式载入后实际可消费的历史前缀终点，A_p≤b_p≤n |
| q_p=n−b_p | 源需要计算的 prompt 后缀行数；不能用 n−H_d 代替 |
| S_p(l,r) | 源第 l 层范围 r 的合法 K/V；发送许可还要求对应物理存储受保护 |
| C_d | 目标已发布的连续 KV 终点；接收中页不推进它 |
| ticket | token 或 logits 的内容身份、位置、采样状态和消费记录；不承担 KV 所有权证明 |
| flight | 已接受操作及其读取、写入、暂存、注册区、完成责任和最后使用者记录 |

目标前缀必须在接管期间保持可读，源发送范围必须在实际读取期间保持有效。源若需要计算，还必须取得计算所需的完整历史。H_d、A_p 和 b_p 分别描述不同实例的状态，目录命中不能使它们自动相等。

请求可以同时具有“token 已就绪、KV 尚在准备”等状态，因此不能用一条线性枚举代替依赖记录。正常推进可记录为 PLANNED、KV_PREPARING、FIRST_TOKEN_READY、TRANSFERRING、TARGET_COMMITTED、D_RUNNING 和 COMPLETED；失败还要区分逻辑终止与 DRAINING。FAILED 或 CANCELLED 不等于其资源已经空闲。

若首 token 为 EOS 或已经达到输出停止条件，提交终止结果，不再安排消费它的 decode；已接受的载入或传输仍按最后使用者结算。无需生成任何输出的请求在进入本算法前结束。没有外部 BOS 或等价规范化输入的空 prompt 应拒绝，不能恢复位置 −1。

## 合法条件、状态几何与所有权

模型状态必须属于同一计算等价条件：固定 checkpoint、adapter、规范化输入、因果上下文、位置规则、RoPE 或其他位置状态，以及约定的数值表示。相同 token 在不同位置或不同上下文中不产生相同 KV。跨 backend 重算是否相容，要按既定误差与状态表示契约验证，不能从实数数学等价直接推出浮点逐位一致。

状态描述至少包含层、KV head、通道、dtype、量化尺度、布局、页长、有效位置、源 TP/PP 分片和目标分片。不同 TP 可能要求切分、汇集、转换或复制。KV head 少于目标 TP 时，不能机械地把每卡状态除以 TP。窗口 attention、SSM、MLA 和混合模型的接管对象应是能够共同恢复模型函数的状态族，本章的连续普通 K/V 范围不直接覆盖它们。

目标先为 M_d、必要转换区和下一步增长预留容量，源才取得写入许可。源载入前缀、重算和末行恢复也需要自己的容量。共享页保持只读；追加到共享尾页时建立私有写区或执行 COW。PagedAttention 的块表、引用计数和 COW 可以表达逻辑共享，但逻辑引用清零不证明异步设备、NIC 或其他消费者已经停止访问。

本章采用全提示词状态提交后再开始第一次 decode 的基线。按层接收可以与源计算重叠，但不在目标发布部分恢复点。进一步允许目标逐层推进，需要另行追踪各层依赖、在途前向和失败排空，不能从“某层到了”推断整条请求可接管。

源端最后一份可恢复状态与发送 staging 分开管理。staging 可在其实际读取结束后回收；最后恢复副本的责任移交则需要目标提交确认或另外明确的恢复依据。目标确认本身也不能解除尚未结束的源端物理读者。

## 源端历史取得与 KV 准备

若源已有 A_p，而计划使用更长历史 b_p，必须显式载入 [A_p,b_p) 的逐层状态。缓存提供者可以是远端池，也可以是已有足够前缀的目标 d；后一种情况仍有一次目标到源的读取、转换、可见性和驻留成本。没有合法载入路径时取 b_p=A_p；没有本地历史时取 b_p=0，从零重算。

源计算 [b_p,n) 时，位置 i 的普通 causal query 读取合法 key 集合 [0,i]：历史提供 [0,b_p)，本次计算提供 [b_p,i]。有效 query-key 对数为

V_p(b_p,n)=Σ_{i=b_p}^{n−1}(i+1)=n(n+1)/2−b_p(b_p+1)/2。

它是逻辑可见关系的计数，不是实际 DRAM 事务。线性层还要处理 q_p 行，实际访存取决于 tile、head 复用、布局和 cache。

```pseudocode
ACQUIRE_PREFIX(p,R,A_p,b_p,g,tx)
输入：合法本地历史、候选远端历史和本次身份
输出：受保护且对 p 可消费的 [0,b_p)，或已结算的失败

1 验证并固定本地 [0,A_p) 的逐层只读历史；失败则重建本地方案
2 若 b_p=A_p，返回 LOCAL
3 为各层 [A_p,b_p) 建立本次私有接收区；登记操作身份和读写保护后才提交载入
4 等待全部所需层完成载入、身份校验、布局转换和消费者可见性
   本基线在全部层就绪前不启动依赖它们的后缀计算
5 全部成功：将本次历史作为只读输入固定，返回 PREFIX_READY
6 任一失败：撤销该尝试的新提交和逻辑发布资格，进入 DRAINING
   保留全部已接受操作及其源、目的、暂存和注册保护
   按 FAIL_AND_DRAIN 结算旧尝试；未排空的物理范围不得释放或改作计算写区
7 旧尝试在相关范围排空后，重新验证 A_p；生成新 tx
   可重新规划 b_p=A_p，或使用独立安全范围从 0 重算
   重新估算成本及 deadline；不可沿用载入成功时的预测
```

KV 准备方案独立于首 token 方案：

| KV 方案 | 证明与动作 | 完成条件 |
|---|---|---|
| NONE | M_d 为空，验证并保护目标 [0,n) | 当前接管绑定到有效完整前缀 |
| HOLD_M | 源已持有每层完整 M_d，内容身份成立；固定发送读范围 | 每个待发块已有合法、受保护且可见的生产结果 |
| LOAD | 源从合法副本载入所需状态；保守实现载入到完整 [0,n) | 载入、转换和可见性完成后才能发相应块 |
| REBUILD | ACQUIRE_PREFIX 后计算 [b_p,n)，保留 [0,b_p) 中也需发送的部分 | 所需发送范围全部产生并受到保护 |

HOLD_M 不要求源还保留不参与计算的 [0,H_d)，但每个发送块的身份必须包含其完整因果前缀依赖。如果需要计算或恢复 logits，则仍须满足计算端完整历史的前提。只证明一段裸 KV 字节存在不够。

```pseudocode
PREPARE_KV(plan,allow_sample=false)
输入：独立选择的 KV 方案，M_d，源历史方案和生命周期记录
输出：逐块 SOURCE_RANGE_READY，必要时附带末行 logits；或失败

1 若 NONE：验证目标完整前缀仍有效，返回空发送任务
2 若 HOLD_M：逐层验证完整 M_d 并固定读保护，发布对应 SOURCE_RANGE_READY
3 若 LOAD：登记并执行载入；完成转换和可见性后固定发送范围，发布就绪事件
4 若 REBUILD：
     执行 ACQUIRE_PREFIX，取得 [0,b_p)
     从 token x[b_p:n) 的 embedding 开始逐层处理
     每层读取合法历史和本次已算行，只向本次私有状态写入
     某发送块的 K/V 完成且可见后发布 SOURCE_RANGE_READY
     最后位置 n−1 的最终 hidden 经输出头产生 logits 时另发 LOGITS_READY
5 本过程不消费 logits 票据，不推进采样随机状态，不追加或发送输出
6 任一失败：FAIL_AND_DRAIN；无法安全载入或重算时排除候选或明确失败
```

因此，已有 token/logits 时仍可以为补齐 KV 重算 prompt；这次重算的 logits 被丢弃，不得再次采样。没有输出票据、需要正常 prefill 时，同一个 REBUILD 任务同时产生 KV 与末行 logits，不能再启动另一份相同计算。

## 首 token 的互斥路径与末行恢复

先验证票据，再按下表选择一条首 token 路径；另行选择上一节的 KV 方案。合法旧票据可以被新接管代次继承，条件是请求、输出分支、位置、模型、输入和采样确认记录一致。不能仅因 g 改变就重新采样。

| 首 token 路径 | 前提与动作 | 与 KV 准备的关系 |
|---|---|---|
| EXISTING_TOKEN | 验证已确认的 y_n 及其采样记录，返回原票据 | 无需为取得 token 做 prefill；仍独立执行必要 KV 准备 |
| VALID_LOGITS | 验证位置 n−1 的未消费 logits 票据，执行一次采样确认 | logits 不证明源 KV 存活；M_d 非空仍需合法生产者 |
| RECOVER_LAST_ROW | 没有 token/logits，但执行端 e 有完整可消费历史 | e=d 且 H_d=n，或 e=p 在显式取得完整历史后恢复；KV 发送另行判断 |
| PREFILL_SUFFIX | 没有上述票据或完整历史，源可取得 b_p<n 并计算后缀 | 订阅唯一 REBUILD 任务的末行 logits，再采样一次 |

若目标完整命中但缺输出，优先在有权重和完整状态的 d 恢复。若目标部分命中、源 b_p=n 却无输出，也可以在 p 恢复并发送 M_d。无法证明恢复历史或后缀计算历史时排除候选，不能选择 q_p=0 后永久等待一个不存在的 token。

```pseudocode
RECOVER_LAST_ROW(e,R,n,g,tx)
输入：n>0、完整提示词 token、e 的受保护逐层合法状态 [0,n)
输出：位置 n−1 的 logits；不推进已发布 KV 边界

1 验证并保护历史、模型权重及私有工作区；登记实际操作的完成责任
2 u ← EMBED(x[n−1])，使用位置 n−1 的位置规则
3 对每一层 l：
     从本层输入 u 按模型规则计算当前行 q,k,v
     读取该层历史 [0,n−1)，不读取历史中位置 n−1 作为第二份当前行
     以历史加私有当前 k,v 各一次做 causal attention
     经本层输出投影、残差、规范化和 FFN 等模型规定步骤得到下一层 u
     当前行 K/V 只写私有暂存，不覆盖共享页，不写位置 n
4 末层后执行模型规定的 final norm 和输出头，得到 logits
5 实际最后使用者结束后回收私有暂存；失败同样先排空再回收
6 返回 logits；已发布 [0,n) 和 C_d 不变
```

恢复重算一行而非整个 prompt，但每层仍读取 n−1 行历史，并执行一行线性层及输出头。它不是零服务时间，也不能因为 T_prefill(n,n)=0 就从时间模型中消失。

采样确认由唯一账本管理，键至少为请求、保留分支和逻辑位置；票据绑定 logits 来源、采样配置、随机状态及其他影响选择的状态。并发恢复或重试只能有一个结果取得确认权。

```pseudocode
SAMPLE_ONCE(R,n,logits_ticket,sampling_state)
输入：合法末行 logits 与对应采样状态
输出：唯一确认的 y_n 票据，或冲突

1 查 (R,保留分支,n) 的确认账本；已有结果则验证兼容并返回原票据
2 验证 logits 的模型、输入、位置 n−1 及未消费资格
3 在唯一确认权下计算采样结果，并原子记录 token、sample_id、输出序号和更新后的采样状态
4 重复确认返回原结果；冲突不得追加另一个 token，不得再次推进随机状态
```

## 规划、预留与执行事件

规划器输入模型、prompt、SLO、负载、拓扑、缓存副本和容量快照，输出合法的端点、两条准备方案、容量预留、身份与输出策略。候选估算没有写副作用；预留竞争失败不能留下其他候选的占位。

```pseudocode
PLAN_HANDOFF(R,P,D,cache,policy)
输出：含 first_plan、kv_plan、依赖图与预留的 PLAN，或拒绝

1 验证 n>0、模型、adapter、位置与请求状态；检查输出停止条件
2 只读枚举 p,d、合法 H_d、A_p 和可取得的 b_p
3 为每个组合分别构造：
     first_plan：已有 token、合法 logits、指定端点末行恢复或后缀 prefill
     kv_plan：NONE、HOLD_M、LOAD 或 REBUILD
   要求每个发送块都有合法生产者；每个计算或恢复步骤都有历史输入
   PREFILL_SUFFIX 与 REBUILD 共享同一任务；已有票据的重算禁止采样
4 分别估计 FIRST_TOKEN_READY、TARGET_COMMITTED 和第一次 decode
   加入源载入、KV 重建、恢复执行端排队、传输转换及两侧物理容量
   不可准备或不能保护状态的候选直接排除
5 按联合 SLO 与目标代价排序；估算期间不分配 g、tx，不占用候选容量
6 对选定候选重新验证；取得源、目标及恢复工作区所需的预留和历史保护
   可按固定顺序尝试取得资源；全部取得前不允许提交设备或网络工作
   任一失败则撤销已取得的空预留和保护，重新选择
7 全部资源取得后绑定新授权 g，生成 tx，并安装新操作登记入口
8 返回 PLAN；全部候选失败则明确拒绝或选择已定义的共置等降级方案
```

资源可用量按物理并集计算：共享页只计一次，但不同实例上的副本、载入暂存、转换区和旧尝试待排空页都是实际驻留。预留成功不保证此前负载预测继续成立，执行前仍需复核 deadline 和本地服务条件。

```pseudocode
EXECUTE_HANDOFF(plan)
输出：按序输出、目标接管或带排空责任的终止

1 验证授权、预留和固定历史；失效则进入统一失败出口
2 启动唯一 kv_job；按 first_plan 独立取得首 token：
     EXISTING_TOKEN：验证并采用原确认票据
     VALID_LOGITS：SAMPLE_ONCE
     RECOVER_LAST_ROW：等待 e 的完整历史和执行机会，恢复后 SAMPLE_ONCE
     PREFILL_SUFFIX：等待共享 kv_job 的末行 LOGITS_READY 后 SAMPLE_ONCE
3 FIRST_TOKEN_READY 只发布一次
   若为 EARLY，立即把同一票据交给按序输出器，可与 KV 准备和传输并发
   若 token 触发停止条件，则结束生成，并结算已接受工作
4 对每个 SOURCE_RANGE_READY(l,r)：
     复核 tx 和源读保护、目标写许可；先登记操作再提交发送
     目标在未提交范围接收，记录传输、转换和消费者可见性证据
5 当所有层 M_d 完整、转换与可见性完成、H_d 仍有效且预留有效：
     原子发布当前代次的目标状态，使 C_d=n，产生 TARGET_COMMITTED
   M_d 为空时仍执行完整前缀验证与本次授权绑定
6 GATED 输出器等待 FIRST_TOKEN_READY 与 TARGET_COMMITTED 两者，再发送票据
7 同时满足 token、目标状态、活跃授权、下一步容量和执行机会后：
     消费 y_n 于位置 n，读取已发布提示词状态，向私有增长范围写位置 n 的 KV
     完成全层计算及提交后，采样确认并按序交付 y_{n+1}
8 目标提交确认移交恢复责任；源各对象仍等待自己的最后物理使用者
9 任一失败或取消：FAIL_AND_DRAIN；禁止旧结果新增输出或发布
   已经发布或外部可见的结果按其真实边界处理，不能假装回滚成功
```

步骤之间按事件依赖执行。EARLY 发送挂在 token 就绪事件上；GATED 等待两个事件的交集。目标已经提交但 token 恢复较慢时，不能在提交事件上发送一个尚不存在的 ticket。

按序输出器以 (R,输出序号) 取得唯一逻辑发送资格，重复请求返回原处理状态；冲突 token 拒绝。取得资格、发送中与已确认分别记录，不能等发送返回后才建立并发去重记录。网络失败可能使客户端接收结果不确定，断线续传必须依赖明确的游标与确认协议，不能凭内存账本宣称网络恰好一次交付。第二 token 的发送还要等待首 token 的输出顺序，不能因网络路径较短而越序。

提前输出后接管失败，已可见 y_n 不能撤回。只能保留同一确认票据，从可信状态重建后续接，或显式截断并报错。门控输出在任一就绪条件成立前失败时没有新增首内容；提交成功但发送失败时也只能重发协议允许的同一逻辑结果，不能重新采样。

## 失败回滚、排空与物理复用

代次检查处理的是逻辑归属。已获准的 DMA、kernel 或传输可能继续访问旧地址，即使其完成消息会被拒绝发布。超时、目录失效、引用计数清零和旧 g 检查，都不能单独解除物理保护。

本章将传输完成语义委托给[通信传输](../hardware/transport-and-rdma.md)，将唯一接管权与恢复点委托给[服务恢复](../system-semantics/serving-recovery.md)，但必须传递以下具体记录：

| 记录 | 本章交付的内容与完成责任 |
|---|---|
| 操作身份 | R、g、tx、操作序号、执行组、操作类型；完成不能只按地址匹配 |
| 内容范围 | 模型状态身份、层/head/位置和布局；用于发布完整性检查 |
| 物理保护 | 源读范围、目标写范围、暂存、页表、工作区、注册或访问能力及分配代次 |
| 提交结果 | 哪些操作被接受，哪些确定未提交，哪些提交结果未知；批量部分成功逐项结算 |
| 完成责任 | 谁保存记录、接收完成、检查状态并解除哪一份使用权；控制任务结束后仍须有所有者 |
| 释放证据 | 针对该物理范围，证明所有已接受访问完成、可靠取消，或其未来访问能力已被可靠隔离 |

```pseudocode
FAIL_AND_DRAIN(attempt)
输入：失败尝试及其全部已接受、可能被接受的操作记录
输出：逻辑终止与逐范围可释放证据；排空未完成时保留责任

1 原子关闭该尝试的发布资格和新操作登记/提交入口
   与提交竞争的操作先确定其是否被接受；未知者保守纳入在途记录
2 未提交状态保持不可读；将相关物理范围标为 DRAINING，不退回空闲池
   已提交状态不倒退 C_d；停止受影响请求继续消费并保留已有读者保护
3 取消尚未接受的工作；请求传输层或设备层结算已接受工作
   允许这些操作按原保护完成，但迟到结果不能重新取得发布资格
4 对每个操作逐项取得完成、可靠取消或访问隔离证据
   隔离目标写能力不自动证明源 DMA 读取已结束；读写范围分别结算
5 仅在某物理范围的全部实际使用者均已终止且逻辑所有者已释放后，回收该范围
   无法证明安全的范围继续隔离并计入驻留；超时不能把它变成空闲
6 重试使用新 tx；复用旧范围前必须有步骤 5 的证据
   若使用独立新范围，仍保留旧尝试保护和容量账，不覆盖旧对象
7 保留已确认 token、输出账本和可信恢复点；根据 deadline 续接或明确终止
```

ACQUIRE_PREFIX 的失败回退也遵守这一顺序。若第 0 层载入失败、第 1 层仍向暂存写入，不能立即丢弃暂存并让重算写同一范围。先关闭旧尝试，等待相关旧访问排空；或者为新尝试分配与旧访问隔离的物理范围。后者减少等待，却增加峰值驻留。若既不能排空也没有安全新容量，该候选不可继续。

例如旧发送读取源页 s 并写目标页 d，目标转换又读取 d。取消后，源发送完成只能解除对应源读保护；d 仍可能被发送或转换使用。只有其全部使用者结束后才能把 d 交给另一个请求。重复旧完成只能结算原操作一次，不能递减新代次的保护。

## 条件化成本、时间模型与放置

普通 GQA 每 token 全层逻辑 KV 字节为

B_tok=2L H_kv d_h b，

其中 L 为层数，H_kv 为 KV head 数，d_h 为每 head 通道，b 为元素字节数。目标逻辑接收量 D_log_d=(n−H_d)B_tok；源取得历史的逻辑载入量 D_acq=(b_p−A_p)B_tok。LOAD 若载入到 n，应按实际范围计算。HOLD_M 仍有验证和固定页的准备成本，不能把它当作无条件零成本。

经过分片、复制、布局和路径后，分别得到 D_net_acq 与 D_net_d。以 Q 字节分块、消息启动延迟 α、路径有效带宽 β_eff 表示一次传输，可用

T_x≈α ceil(D_net/Q)+D_net/β_eff+T_convert

建立初始估算。它不是重叠执行的关键路径公式。多个流还会竞争 GPU 内存、PCIe、NIC、NUMA 和共享上行；peer access 可达不等于方向带宽相同。源先载入、再发送同一段状态时可能经过两跳，不能只按目标缺失字节记一跳。

设 t_0 为本次规划的时间原点，以下所有 F、C 和 U 都是相对此原点的完成时刻，Q、T 为非负时长。票据若尚在外部取得，须包含其等待和验证；已经对客户端可见的首 token 则沿用真实可见记录，不重复计算新 TTFT。

| 首 token 路径 | FIRST_TOKEN_READY 时刻 F 的定义 |
|---|---|
| EXISTING_TOKEN | F=t_token_available+Q_validate+T_validate；复核确认记录，无新采样 |
| VALID_LOGITS | F=t_logits_available+Q_validate+T_validate+Q_sample+T_sample |
| RECOVER_LAST_ROW | F=max(t_prefix_e,t_input_e)+Q_e_recover+T_recover(e,n)+Q_sample+T_sample |
| PREFILL_SUFFIX | F=t_logits_REBUILD+Q_sample+T_sample；订阅共享重建任务，不重复计算 |

Q_e_recover 是历史与输入就绪后在实际执行端 e 等待恢复工作的时间；T_recover 包含逐层历史读取、一行投影和模型层、输出头及必要同步。恢复在 d 上执行时，它与目标 decode 共享设备资源，其占用必须进入本地服务安排。已有 logits 时的采样队列与恢复队列也不能藏进一个统一的 P 池排队项。

KV 准备独立计时。保守串行的 REBUILD 估算为

U_rebuild=t_0+Q_p_prepare+T_acq(A_p,b_p)+Q_p_compute+T_prefill(b_p,n)。

末行 logits 时间还包括其输出头和完成处理；若已包含在 T_prefill 中，不再重复加入。HOLD_M 使用验证固定完成时间，LOAD 使用对应副本排队、载入、转换和可见性时间，NONE 不启动源准备任务。已有 token 或 logits 的路径也必须计算这些 U，只有采样依赖可以省掉，KV 准备不能随之消失。

更一般地，对每个目标必需块 j，令 K_j 为源合法生产结果及读保护就绪时刻，R_d 为目标预留完成时刻，则其发送不能早于 max(K_j,R_d)。按真实传输队列、转换依赖和消费者可见性计算 W_j。目标提交为

C=max(t_H_valid,R_d,max_j W_j)+T_publish。

空 M_d 时不取不存在的传输项，只验证完整已有前缀与本次绑定。目标接收处理的等待可以进入 W_j；第一次模型前向的等待另记为 Q_d_step，二者不能重复计为同一个 D 队列。

第一次 decode 起点及输出时间为

D_start=max(F,C)+Q_d_step，

V_1_early=F+T_out1，

V_1_gated=max(F,C)+T_out1，

E_2=D_start+T_decode_first，

V_2=max(E_2,V_1)+T_out2。

这里 T_decode_first 包含产生、采样确认第二 token 所需的工作；最后一式假设输出器按序服务，T_out2 表示首输出之后第二输出的服务尾段。实际输出合并、发送排队和客户端 chunk 口径应使用对应事件。TTFT 与第一次间隔分别由 V_1 和 V_2−V_1 得到。共享设备或链路使独立任务不能任意并行，候选必须先形成可执行资源日程，再沿依赖图求这些时刻。

完整命中反例：H_d=n、A_p=b_p=n，无 token/logits，目标状态在 t=0 就有效。设恢复执行端排队 7 ms、逐层末行恢复 13 ms、采样 2 ms，则 F=22 ms。即使 T_acq 与后缀 prefill 都为零，第一次 decode 仍不能早于 22 ms；随后若还有 decode 排队则继续增加。该例是设定模型，不是设备测量。

| 成本类 | 同一候选中需要列账的内容 |
|---|---|
| 计算 | q_p 行线性层与 V_p 历史 attention；票据已有时可能仍有 KV 重算；恢复是一行模型执行 |
| 访存 | 权重、历史 KV、新 KV 写入、布局转换、页表与暂存；逻辑对数不能当作 DRAM 字节 |
| 通信 | 源载入、P→D 传输、TP/PP 通信、复制、控制与重试；按实际经过边计量 |
| 准备 | tokenization、身份校验、页表、COW、描述符、注册、采样及输出处理 |
| 同步 | 源历史可消费、源块生产、接收转换可见、应用发布、恢复责任移交及排空证据 |
| 驻留与排队 | 两池权重、源发送保护、目标接收增长、恢复工作区、预留空转和旧尝试 DRAINING |

32 层、8 个 KV head、128 通道、2 字节时，B_tok=131,072 字节，即 128 KiB。n=4096 的完整 KV 为 512 MiB；H_d=1024 时目标缺 3072 token，为 384 MiB。20 GiB/s 下，两者纯传输下界分别为 25 ms 与 18.75 ms，尚未包含准备、转换、排队和竞争。

相同 n=4096、H_d=1024：源 b_p=0 时 q_p=4096、V_p=8,390,656；源取得 b_p=2048 时 q_p=2048、V_p=6,292,480，但目标仍接收 384 MiB。后者另有源载入成本。若 H_d 改为 3000 而 b_p 保持 2048，源工作量不变，目标接收变为 1096 token；源新算的 [2048,3000) 仍是其后续 query 所需历史。

一次具体重分片可以揭示逻辑字节与布局操作的区别。设上述模型源 TP2：p0 持 head 0–3，p1 持 4–7；目标 TP4：d0、d1、d2、d3 分别持 0–1、2–3、4–5、6–7，PP 层对应。源每层每种 K/V 为 NHD，目标接收暂存为 HND。对位置 t∈[H_d,n)、head h 和通道 c，源所在 rank 为 floor(h/4)，其层内 K 或 V 的字节偏移为

((t·4+(h mod 4))·128+c)·2。

目标 rank 为 floor(h/2)，接收区的层内偏移为

(((h mod 2)·(n−H_d)+(t−H_d))·128+c)·2。

每个发送项从源 NHD 的相应 head/channel 切片读取，打包或在目的端转成 HND，再建立实际页映射。p0 分别发送给 d0、d1，p1 分别发送给 d2、d3；此例没有 head 复制，目标每 rank 接收全层 96 MiB，源每 rank 发送 192 MiB，总计 384 MiB。转换额外读取和写入、打包暂存及消息数另计。若目标后端要分页布局，还须把该偏移再映射到实际页，不可直接把暂存地址发布为页表。不同头数、复制和拓扑需要重算映射。

静态配置先枚举 P/D 的 TP、PP、实例数与放置，检查每个执行组的权重、状态和工作区容量。跨节点链路弱时，可以要求相同 PP 层段的 P 与 D 位于同节点强互联域；这会约束两个阶段的联合候选，不能先取两侧局部最优再忽略放置。DistServe 的高带宽与低带宽放置算法分别展示了这种条件差异。

粗略阶段供给必要条件可写为 n_P≥ceil(λ/μ_P)、n_D≥ceil(λ/μ_D)，其中 λ 为请求到达率，μ 为指定长度分布、batch、并行度和 SLO 下的阶段有效服务率。真实 P 工作还可能包含为已有票据重建 KV，D 工作可能包含末行恢复；其频率应进入需求，不能只按新 prompt 与输出 token 分池。若平均每请求迁移 512 MiB、到达 8 请求/s，平均目标传输需求为 4 GiB/s；目标缺失减半时为 2 GiB/s，源载入、复制和重试另计。平均供给约束不保证尾延迟或联合 SLO。

## 组合轨迹与输出策略

先看合法 logits 与源 KV 丢失的组合：n=8、H_d=4、A_p=b_p=0，已有位置 7 的合法 logits 票据。

1. 规划分别选择 VALID_LOGITS 与 REBUILD。目标固定 [0,4)，预留 [4,8) 和位置 8 的必要增长；源预留完整重算所需状态与工作区。
2. 采样器从原 logits 确认 y_8，一次记录 FIRST_TOKEN_READY。EARLY 可以发送它；这时源尚不能发送 [4,8)。
3. 源从 x[0:8) 重算，每层计算合法历史，产生逐块状态。源为自身 attention 计算 [0,4)，但不把这段重复发给目标。
4. 每层 [4,8) 的结果可见且受保护后才发送。重算末行 logits 被丢弃，不第二次采样。已有 token 票据时采用相同 KV 路径，采样次数为零。
5. 目标完成所有层的缺失范围、转换和可见性后发布 C_d=8；第一次 decode 消费同一 y_8，写位置 8，再产生 y_9。
6. 若源无法重算、载入或固定完整发送范围，候选在规划时排除；运行时失效则排空并重规划，不能发送不存在的状态。

这条路径的首 token 时间可能很短，KV 重建仍可能主导第二 token。把“已有合法 logits”解释为“不需任何 prefill 计算”，会漏掉为接管状态付出的工作。

再看一条输出时间轴，全部为设定值。正常后缀 prefill 的 P 排队 10 ms、前缀取得 0、prefill 与首 token 处理合计 80 ms，F=90 ms。首 token 之后尚不能隐藏的传输尾段 25 ms、转换 5 ms、接收处理等待 10 ms，使 C=130 ms。第一次 decode 排队为 0，执行与第二 token 确认 10 ms，两次发送各 5 ms。

| 事件 | EARLY | GATED |
|---|---|---|
| FIRST_TOKEN_READY | 90 ms | 90 ms |
| TARGET_COMMITTED | 130 ms | 130 ms |
| 首内容可见 | 95 ms | 135 ms |
| 第一次 decode 起点 | 130 ms | 130 ms |
| 第二 token 可见 | 145 ms | 145 ms |
| 第一次间隔 | 50 ms | 10 ms |

在 TTFT≤150 ms、第一次间隔≤30 ms 的设定下，EARLY 只满足 TTFT，GATED 可同时满足两个约束。这不证明后续 decode 已满足 SLO。相同设定中，共置若排队 70 ms、prefill 80 ms、发送 5 ms，则首内容为 155 ms；共置加 chunked prefill 也应进入候选，但必须在同一外部到达轨迹下重新校准其干扰、队列与总工作。

层间发送与后续层计算重叠时，25 ms 表示仍阻挡消费者的尾段。不能把完整传输时间既计入 prefill 重叠区，又完整加到 prefill 之后。

## 条件变化、诊断与反证修正

短 prompt、低到达率、少量 GPU 或弱互联时，共置或分块 prefill 可能更合适；长输入干扰已有 decode、两个阶段适合不同并行配置且互联足够时，分离才更有空间。长上下文同时放大计算、状态驻留和通信，不能仅因 prefill 的增长通常快于线性传输，就断定网络不构成瓶颈。

缓存收益要分别观察：H_d 增大减少目标接收，b_p 增大减少源后缀计算，合法输出票据减少首 token 准备；三者不能互相替代。完整目标命中但没有输出时，压力可能转移到 D 端恢复队列。已有票据但源状态被逐出时，压力可能转移到 KV 重建。应据实际工作重新分配 P/D，而不是把 hit rate 直接当作可服务容量。

链路变慢、目标容量不足、源状态保护失败或 D 队列尾部增长时，可以调整路由、本地副本、分块、输出门控和池配比；若没有合法准备或安全排空路线，应放弃该候选。失败频率上升时，旧尝试驻留和重试流量可能使原可行方案失效。不可改变的是内容身份、确认输入、发送生产者、消费前可见和最后使用者结束后才复用。

正确性实验固定模型、输入、位置、表示与容差，比较共置、分离、前缀复用后接续及恢复后的至少两轮推进。独立参考直接按逻辑位置构造合法 key 集合与恢复边界，不复用被测页表或 mask。只比较首 token 不足以证明后续状态正确。

| 竞争解释 | 区分干预与不同预测 | 反证后的修正 |
|---|---|---|
| 分离收益来自阶段干扰消除 | 相同总资源和到达轨迹下比较已有 D 的步时，并分别记录传输尾段 | D 仍随 P 抖动时检查共享 HBM、NIC、CPU 与路由集中 |
| token/logits 票据代表接管状态也完整 | 保留合法票据，逐出所选源 KV，固定部分目标命中 | 必须出现载入、重算或候选排除；若立即发送则修复生产者依赖 |
| 目标命中直接减少源计算 | 固定 H_d 改变 b_p，再固定 b_p 改变 H_d | 源工作应只随自己的历史方案变化，目标接收应随 H_d 变化 |
| 完整命中时恢复可忽略 | 固定 H_d=n 且无票据，延迟 e 的恢复执行机会 | F 与第一次 decode 必须随恢复排队移动；不移动则修复路径时间模型 |
| EARLY 同时改善 TTFT 与第一次间隔 | 固定计算和传输，切换 EARLY/GATED | 第二 token 不变而首内容移动，说明是输出边界变化，不能归为接管加速 |
| 网络主导接管 | 固定源工作与票据，改变路径、分块或并发，记录实际字节和尾段 | 若恢复、计算或准备也变，重新分离解释，不能只按带宽归因 |
| 旧代次过滤足以安全回滚 | 一层载入失败，延迟其他层写入或源发送读取，尝试回退和复用 | 旧操作未终止时必须保留物理保护；只拒绝逻辑完成而允许复用说明仍有漏洞 |
| 预留越早越好 | 固定负载比较提前与惰性预留，记录等待占位、拒绝和接管尾部 | 没有降低尾延迟却增加空转时，调整预留时间或放弃该策略 |

随章检查使用确定性 Python 标准库 CPU 模型。区间实现与独立的逐 token、逐层集合参考对照；事件审计检查源生产、目标可见、提交、token 与消费依赖；生命周期模型将已接受访问和资源所有者分开记录。负对照实际注入无源 KV 的发送、缺层提交、未就绪消费、取消后提前释放与缺失恢复等待，并要求独立审计拒绝。它还检查票据保留时的 KV 重建不重复采样、只读候选估算、容量占用与输出时序。

这些检查不执行真实 attention、随机采样、CUDA kernel、NIC 取消或注册撤销，不证明设备可见性、真实并发原子性、网络重叠、吞吐或 SLO。设备实验还需记录提交结果、完成状态、实际可见性依赖、物理保护和真实分配代次，验证传输层提供的排空证据确实终止了相关访问。性能报告保留 offered、admitted、completed、failed、无效重算、源载入及待排空驻留，按同一批请求统计联合 SLO。
