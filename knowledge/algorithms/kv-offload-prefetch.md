# K-ALG-018：KV 卸载与预取：读集合、恢复点与迁移预算

KV 卸载需要同时回答存储在哪里、下一次 attention 会读哪些状态，以及何时能够恢复推进。暂停请求换出后恢复、低层前缀缓存命中和活跃 decode 的逐步卸载有不同的成本：前两者主要支付一次恢复费用，后者可能每步都搬运历史。释放显存、避免重复 prefill 和降低稳态流量必须分别判断。

## 对象、读集合与恢复位置

固定计算身份 η，包括模型与权重、adapter、实际输入前缀、位置规则、外部条件、数值表示和布局合同。令 p 为已完成模型消费的 token 数，S(p) 为消费 x[0:p) 后继续执行所需的状态包。普通全注意力 decoder 包含逐层历史 K/V；窗口、MLA、递归层和交叉注意力需要各自的状态。不同族必须支持同一个恢复位置，不能只比较长度字段。

S(p) 通常不包含末行 logits、已采样未消费的 token、随机状态和输出游标。若已保留下一输入 x_p，可直接从 S(p) 消费它；完整命中 KV 而没有下一输入或末行 logits 时，不能自动采样。可以保存必要 logits，或从合法的较早恢复点重算末尾。递归状态不能通过把 p 减一恢复到旧检查点。生成任务的空状态也不自动提供合法起始输入。

对层 l、位置 t 的 query，模型规定的可见位置为 A_{l,t}。当前位置 K/V 由当前层输入投影产生；历史读取集合为 H_{l,t}=A_{l,t}∩[0,t)。窗口宽 W≥1 在本章包含当前 token，故普通窗口的历史为 [max(0,t−W+1),t)；全注意力历史为 [0,t)。sink/global 等规则需要另外并入并去重，不能沿用纯窗口公式。

规划从位置 p 开始的 q≥0 次连续 query 时，必须区分两个集合：

- U(p,q)=∪_{t=p}^{p+q−1} H_t：这些步骤会读取过的全部历史位置，包含在本次推进中才生成、随后被读取的位置。
- E(p,q)=U(p,q)∩[0,p)：规划开始时已经存在、可以从旧状态副本预取的位置。U\E 必须由本次模型计算产生，不能从旧缓存复制。

q=0 时二者为空。q>0 时，全注意力 U=[0,p+q−1)；普通窗口 W>1 时 U=[max(0,p−W+1),p+q−1)；W=1 时每个 query 只读自己，历史 U 恒为空。区间均取整数位置，空区间不产生读取。E 再与 [0,p) 相交。因此 q>0 的纯全注意力 E=[0,p)，纯窗口 E=[max(0,p−W+1),p)。未来读集合并集不是每步流量之和，同一旧位置可以在多个步骤重复读取。

例如 p=10、q=1、W=4 时，U=E={7,8,9}，单次 query 不意味着空历史。p=0、q=3 的全注意力 U={0,1}，但 E 为空：前两步产生的状态供后续步使用。p=3、q=2、W=1 的 U 和 E 都为空。已知未来位置不等于已知未来 token；对自回归生成，后续输入仍要等实际采样或已有输入记录。

输入包括 η、p、已知输入及继续票据、各层状态描述、页表、源与目的容量、传输能力和完成责任。输出为同一恢复位置的 RecoveryView，或明确失败。视图给出每族的物理句柄、代次、有效范围、表示、定位方式和就绪关系。下面分别讨论完整安装视图，以及以低层有效副本为后备、按层取得 GPU 工作视图的方案。

## 布局、身份和可回收性

页长 P 个 token 时，位置 j 的逻辑页为 floor(j/P)，页内槽为 j mod P。页表还要绑定层、K/V、head 分片、物理池和分配代次；两个池中的同号页不是同一对象。共享引用只有在内容、表示和生存期相容时才可映射到同一目的副本。相同源需要写到两个独立目的分配时，仍需支付两次目的写入，不能按源身份去重掉一个需求。

一层等宽 K/V、H_kv 个 head、每 head 宽 d、每元素 s 字节时，每 token 有效载荷 τ=2H_kvds。紧密 NHD 页内，K 元素 (j,h,c) 的地址为 K_base+physical_page·D_K+s·(((j mod P)·H_kv+h)·d+c)，D_K 为按字节计的页 stride；V 使用自己的基址和 stride。布局改变时必须搬移或转换字节，不能只改描述符。量化还须定位码、scale、zero point、分组轴和必要残差。

取 P=4、A 页表 [7,1,3]、p=10。位置 0…3 在页 7，4…7 在页 1，8、9 在页 3 的前两个槽。下一 query 使用 W=4 时，旧历史为 {7,8,9}，对应页 {1,3}，页 7 不需要换入。若 H_kv=2、d=4、s=2，则 τ=32 B：精确有效范围为 96 B，按整页搬两页则为 256 B。后者包含过读，空槽即使被搬运也不能进入 attention。

另一请求 B 的页表为 [7,1,9]，也完成到 10。完整恢复两请求时，逻辑页引用为 3+3=6，唯一物理页为 {7,1,3,9}，即 4 页。整页目标占用为 512 B，独立六页为 768 B；唯一有效内容为共享 8 个位置加两个各长 2 的私有尾部，共 384 B。逐 token 展开有 20 个逻辑引用，它既不是六个逻辑页引用，也不是唯一有效 token 数。

共享尾块的写入必须隔离。例如 A、B 完成到 6，共享页 [7,1]，页 1 只有前两个槽有效。B 要生成位置 6 时，先建立私有页 9、复制页 1 的两个有效槽及解释元数据，完成后再写 B 的新槽；A 仍使用页 1。若 A 已有设备读者，B 撤销自己的共享引用不能释放 A 的页。引用计数为一也不自动允许覆盖仍被旧快照读者保护的范围。

把状态分成容量预留、传输在途、内容完整、获取开放和读者责任更清楚。RESERVED 不代表数据到达；COPYING 不代表完成；READY 表示本代完整内容对约定消费者可见。多个消费者可同时持有 READY 内容，读取中不应阻止其他合法只读获取。关闭获取后禁止新读者，已有读者继续受保护；只有拥有者、已提交复制和全部读者责任都结束，才可回收。

身份检查与读者登记必须同回收协调，避免检查成功后、登记之前对象已被换代。代次检查用于拒绝迟到通知和错误结算；它不能阻止已经发出的旧 DMA 写入地址。保护物理内容仍依赖旧访问真实结束，或使用另一块隔离存储。

## 换出、完整恢复与有界预取

换出基线在完整模型步骤边界固定 S(p)，复制期间源不可变。普通追加历史可能稳定，但正在封组的量化尾部会重编码旧值或更新 scale；这种尾部必须冻结或制作独立快照。复制源的读保护从提交前保持到真实复制读取结束；最后一份恢复副本的保留责任还可能更长。

```pseudocode
输入：固定 η、恢复位置 p、完整状态清单 M、旧有效视图 V
      目标层容量、布局合同和请求继续票据
输出：目标 RecoveryView，或失败及待排空责任

校验 M 覆盖全部必需状态族、有效范围和共同 p
固定源快照，取得源保护；建立私有目标描述和空完成账
预留完整安装所需的目标分配、元数据和转换空间
若任一预留失败：撤销未使用预留，保留 V，返回失败

对每个唯一目标物理需求 w：
    将逻辑范围映射到源、目的字节区间及辅助元数据
    若复用已有目标副本：原子核验身份并登记持有
    否则先登记操作责任，再提交复制或转换
    同步拒绝仅撤销明确未接受的责任
    部分接受或接受状态未知时，保持对应源、目的和暂存保护

处理完成：
    按尝试、操作、分配代次匹配；未知或重复通知不贡献覆盖
    记录实际成功范围；短范围不能补成完整范围
    等待全部必需复制、转换及消费者可见性成立
    任一失败或取消：禁止发布，停止新工作，排空已提交访问
                    只归还已经无访问责任的私有分配，保留旧视图

提交：
    在协调点重新核验 η、p、全部范围、表示、持有权和请求资格
    同时安装完整目标映射与继续票据，发布一次目标视图
    撤销本次不再需要的源持有；仍受其他读者或恢复责任保护的源不释放
```

D2H 换出遵循同一关系：目标主存或存储副本完成、验证并承担约定恢复责任后，才能移除源恢复责任。主机提交返回不等于 DMA 结束；写入页缓存也不等于满足持久性。可丢弃后重算的缓存与必须保存的检查点应声明不同合同。H2D 完整恢复则先安装全部必需层，再允许下一次 forward；恢复过程不执行尚未发布的层计算。

完整安装需要容纳完整目标状态。若目标只能容纳少数层，采用另一方案：低层后备状态先具备完整身份与恢复范围，GPU 只有 k 个工作槽。请求绑定的是后备对象和取用计划，逐层临时句柄仅在相应复制完成后交给本层消费者；全局视图不能保存指向已经循环复用槽的静态页表。

下面限定普通因果 decoder 的单 token 推进。已提交历史不可变，新增 KV 使用私有候选；全部层完成才发布 S(p+1)。窗口、递归或会改写历史的量化状态，须先把相应候选更新和回滚责任补齐，不能直接套用 append-only 基线。

```pseudocode
输入：已绑定的后备 S(p)、合法下一输入 x_p、k≥1 个工作槽
输出：完整步骤结果与 S(p+1)，或保留 S(p) 的失败

初始化本步私有新增状态、层输出和操作账；不改变已提交 p
生产游标 i←0；消费游标 l←0

重复直到所有层消费完成，或发生失败：
    生产者：按下一消费层顺序检查可用槽
        槽须无旧复制、旧读者及尚未完成的写回
        核验本层历史 E(p,1)，建立本代定位描述和源保护
        先登记责任再发起换入及必要转换，推进 i
        槽不足时先处理完成或等待最后使用，不等待整个模型全部换入
    完成处理：匹配本代操作，验证范围和表示，标记本层工作视图 READY
    消费者：当第 l 层历史就绪且上层隐藏输入就绪时
        原子核验并取得全部读取票据
        由本层隐藏输入生成 Q 与当前位置 K/V
        对历史及当前位置按模型可见集合共同归一化，完成本层计算
        真实读取结束后释放历史读者，保留本层输出给下一层
        将新增 K/V 安装到本步私有持久位置，或完成必要写回
        写回仍读取工作槽时，该槽继续受保护
        最后使用结束后归还槽，推进 l

成功：全部层新增状态、最终输出和必要写回就绪
      复核请求资格，共同发布 p+1 及完整结果
失败/取消：停止新提交，丢弃未发布业务结果；排空已提交访问
          释放私有候选，旧 S(p) 及其他请求的共享状态保持有效
```

源端持有全部层的后备副本，不要求全部层同时驻留 GPU。仅通过 READY 的本层输入可在私有步骤中被消费；这不等于把部分恢复状态发布给其他 forward。若允许多步同时在途，还需新的依赖、候选版本及容量模型，本基线不作该假设。

活跃卸载也必须保存新 KV。只搬回历史、计算后直接覆盖工作槽，会丢失下一步需要的新增状态。可把新 KV 直接写到独立 GPU 常驻区域，或写回主机后再释放槽；这两种选择分别增加设备驻留或写回交通。失败时若原地覆盖了旧量化组或递归状态，保留旧 p 字段不能实现回滚。

## 六类成本与流水约束

对等宽、非共享、无分片复制的一批普通全注意力状态，D=2LB_rNH_kvds 字节。变长请求改为逐请求、逐层求和；窗口层用实际保留或读取范围，额外 sink/global 单独并入。物理副本、页尾、padding 和量化元数据另计。这个 D 不是 GPU 的 DRAM 事务量。

| 成本 | 同一计划内需要计入的对象 |
|---|---|
| 计算 | attention 与逐位置网络通常不减少；增加解包、反量化、转置、校验及重算；CPU attention 另计点积、整体归约和结果合并 |
| 访存 | 源读、目的写、staging、页表、转换副本、新 KV 和写回；共享目标一份不保证各 query 的读取自动合并 |
| 通信 | 实际经过存储、DRAM、H2D、D2H 或网络的载荷、元数据及目的副本；同一资源上所有需求相加 |
| 准备 | 读集合规划、身份核验、分页映射、目标需求去重、分配、锁页或注册、描述构造、完成处理及回滚 |
| 同步 | 消费前数据就绪、层间隐藏状态、完整步骤提交、最后读取和失败排空；并发等待不能重复相加 |
| 驻留 | 有效后备、工作槽、私有新状态、旧快照、staging、转换空间、页尾、描述和未排空对象 |

规划遍历 J 个逻辑页引用、形成 K 个唯一目标需求时，使用散列表去重在通常假设下约 O(J)，不能把它写成只与 K 有关：重复引用也要被检查。本文集合公式可用区间表示；逐 token 枚举和 q 步逐项求并集是检查参考，不是高效实现的强制成本。

对存储层 h，容量应写为 M_h,peak=max_t Σ_{a∈Live_h(t)} bytes(a)，其中 a 是唯一物理分配。一个目的页从 RESERVED 到 COPYING 仍是同一分配，不能把两种角色各加一次；池 reserved 已包含其 active 槽时也不重复相加。不同存储层分别对照容量；将主存、设备和 SSD 总字节合成一个预算没有准入意义。

暂停恢复的简单串行路径为排队、读取、传输、转换和发布等待之和；允许流水时按真实依赖求关键路径。对共享资源 r，每次工作实际产生 Q_r 字节，能力上界 β_r 给出 T≥Q_r/β_r 的资源下界；代入测得的有效速率则只是对应并发条件的估计。两条 stream 不会创造两份 PCIe 或 DRAM 带宽。

考虑一个只读层输入模型：每层换入用一个串行复制引擎，计算用一个串行引擎，k 个循环工作槽从换入开始占用到计算最后读取结束。设 m_i、c_i 为非负持续时间，C_i 为换入完成，F_i 为计算完成，负下标时间取零：

C_i=max(C_{i−1},F_{i−k})+m_i，

F_i=max(C_i,F_{i−1})+c_i。

第一项表达复制引擎顺序，第二项表达槽的最后使用；消费者同时等本层数据与上一层计算。n=0 时完成时间为零，不等待最后票据。n>0 时总时间 F_{n−1}，各层暴露等待为 max(0,C_i−F_{i−1})。这个模型要求层输入可独立准备、源稳定且两种引擎能按假设服务。

四层 c=[5,5,5,5]、m=[3,3,3,3]、k=2，换入完成为 [3,6,11,16]，计算完成为 [8,13,18,23]，除首层外没有暴露等待；k=1 则总时间 32。把 m 改成 [8,8,8,8]，k=2 的总时间为 37，不能仍用 sum(c)+m_0=28；28 甚至小于同一复制引擎必须服务的 32。增加槽数不能消除持续带宽不足。

如果工作槽还保存待写回的新状态，释放点应改为真实写回完成 R_i，换入式变为 C_i=max(C_{i−1},R_{i−k})+m_i。独立串行写回资源下可再写 R_i=max(F_i,R_{i−1})+w_i；若 H2D/D2H 共用瓶颈，则必须使用共享资源顺序与联合带宽，不能假定两个独占引擎。这些附加责任没有包含在前述 23/37 的只读模型中。

设定 512 MiB 暂停状态、16 GiB/s H2D，纯数据项为 31.25 ms；同一恢复边界的重算若为 20 ms，命中不意味着更快；重算若为 200 ms，恢复才有潜在优势，仍需加排队、转换与同步。2 GiB/s SSD 读取同样状态的数据项为 250 ms。这些时间均为设定值。

再取 L=32、B_r=8、N=4096、H_kv=8、d=128、s=2，完整历史为 4 GiB，每层 128 MiB。16 GiB/s 下每层纯换入为 7.8125 ms，全部数据为 250 ms。若每层计算设为 20 ms，满足上述只读双槽条件时总时间为 647.8125 ms；它包含首层换入，且大于 250 ms 的链路资源下界。完整 KV 可常驻时，理想计算对照为 640 ms。真实活跃卸载还须计新增写回、权重流量、准备和拥塞，不能把这个只读流水当作完整 decode 实测。

CPU attention 可以保留主存历史、交换 query/激活和结果，以避免整段 KV H2D，但 CPU 点积、softmax、NUMA、主存争用和同步进入关键路径。分页组织交通，量化改变字节及解码成本，CPU 委托改变计算放置；三者不能互相替代，也没有统一最优组合。

## 条件变化、反例和选择反转

| 条件变化 | 必须保留的关系 | 调整或放弃的依据 |
|---|---|---|
| 前缀长且重复计算昂贵 | 同一身份、共同恢复点和继续票据 | 比较完整恢复等待与重算；短前缀或冷存储可能反转 |
| 活跃历史持续增长 | 模型实际可见集合 | 全注意力逐步流量增长；窗口层不能代替全层预算 |
| W 变为 1 或 p=0 | 当前 KV 的生产仍存在 | 旧历史可为空；不再发起空历史传输，但仍完成当前层计算 |
| 共享前缀增多 | 目的需求去重、独立读者与 COW | 唯一容量可能下降；kernel 的逻辑读取不保证同比下降 |
| 页长增大 | 有效范围、尾槽和布局合同 | 表项和小传输可能减少，过读、碎片及 COW 粒度上升 |
| 量化或布局改变 | 码与解释元数据一致 | 重算转换、临时副本和误差；旧字节相同不证明新表示合法 |
| 链路拥塞或层计算缩短 | 复制完成先于消费 | 重新求流水；持续带宽不足时减少卸载、改放置或限准入 |
| 目标容量减少 | 在途及旧读者保护 | 缩小预取深度或等待；不能通过提前归还槽制造容量 |
| 取消、部分失败或完成延迟 | 禁止新业务提交与排空分别处理 | 保留旧视图，等待真实最后访问；换代次不代替排空 |
| 模型、位置规则或 adapter 改变 | 状态依赖闭包 | 明确转换并验证，或放弃旧状态复用 |

非整页前缀不是普遍非法。页长 16、完成到 31 时，允许尾部迁移的协议可以复制最后 15 个有效槽和元数据，恢复到 31；只允许完整缓存页的协议最多复用到 16，剩余 15 个位置重算。把完整页粒度方案的 16 当成所有卸载的恢复上限，会无故丢失复用；把未复制尾部的描述写成 31，则会读到 poison 或旧请求数据。

共享分叉也须观察真实内容：只核对新页号不同，不能证明保留槽已复制；只核对 B 的新增槽，不能证明 A 的旧页未被改。应同时检查 A 的历史、B 的保留历史、新槽及各自有效长度。

发布与回收的反例具有不同后果。缺一层就发布，得到不完整模型输入；COPYING 时开放获取，读到未完成内容；取消后提前归还目的槽，再让旧 DMA 写入，会污染新对象。最后一种错误即使完成通知被代次检查拒绝，物理污染仍已发生。故负对照必须实际复用存储并让旧写到达，不能只检查一个错误状态标签。

## 区分实验与检查范围

| 观察 | 竞争解释 | 区分实验及反证后的修正 |
|---|---|---|
| 恢复慢 | 冷存储、链路、转换、准备或同步 | 固定有效范围与并发，比较热内存、DRAM、SSD；热路径仍慢时撤回纯 SSD 解释，分查转换与消费者等待 |
| 深预取无收益 | 槽不足、资源饱和、首层等待或计算主导 | 固定工作量改变 k，记录槽占用、复制起止和消费时间；峰值增加而等待不降时减少深度 |
| 命中却不能生成 | 共同状态不齐、缺下一输入或 logits | 分记匹配位置、可恢复位置和继续票据；补齐合法末行路径后再比较 TTFT |
| 共享后容量下降但 ITL 不变 | 唯一页减少，各 query 仍读取；或计算、排队主导 | 固定准入请求和输入比较实际传输与 kernel 读取，再单独开放容量准入；不能用容量比例推断带宽收益 |
| 跨页或尾部错误 | 页映射、有效长度、COW 复制或元数据遗漏 | 置换物理页并用 poison 填空槽，独立逻辑参考逐位置核对；定位首次错误槽和表示参数 |
| 取消或复用后串数据 | 旧 DMA、未结束读者、旧描述或重复完成 | 分别延迟复制与读者，注入旧代/重复通知；记录实际内容与责任，区别账务错误和物理覆盖 |
| 量化后省字节却更慢 | 解包、重编码、工作区或 CPU 委托退化 | 固定输入和质量合同，分别记录码/参数交通、转换与计算；转换主导时修订低位必快的判断 |

活跃 decode 对照应固定历史、batch、模型和完成边界，比较全驻留、逐步卸载、CPU attention 与合法分片放置，报告每步实际字节、暴露等待、ITL、预取浪费和分层峰值。全设备同步使错误消失，只说明某些执行关系改变，不能唯一定位缺失依赖，也不能作为正常性能对照。

配套 tools/check_k_alg_018_full.py 是确定、离线、只读的 Python 标准库 CPU 模型。读集合用逐 query、逐位置谓词枚举对照区间公式，同时检查 U 和 E；页账分别使用逻辑页编号、唯一物理页和逐槽内容集合；共享尾页执行实际复制和写入，并保留不做 COW 的内容污染负对照。

生命周期检查由独立事件观察器重建未完成复制、拥有者、获取资格和多个读者；覆盖取消、未知/重复完成、旧代通知及安全复用。提前开放、带读者回收、带在途复制回收的错误轨迹必须被检出；旧写污染另在内存模型中实际发生。完整安装检查覆盖全部层、身份、范围及辅助元数据的共同提交。流水递推与按整数时刻推进的独立引擎/槽模型比较，包含空任务、零持续时间、单槽、多槽和首尾排空。

这些检查覆盖普通全注意力、无额外 sink/global 的纯窗口集合、单层分页示例、有限生命周期和固定时间流水。它们不执行真实模型、文件 I/O、GPU、DMA、PCIe、锁页、设备可见性或多机授权；不证明低精度误差、真实事务合并、任意混合状态回滚、实际重叠和端到端性能。三阶段写回关系在正文中给出，配套流水穷举仅验证两阶段只读模型。检查执行是否通过由绑定当前脚本和输入的真实执行记录承担。
