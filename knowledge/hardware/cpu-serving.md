# K-HW-009：CPU 推理：线程、缓存层级与 NUMA 分区

CPU 服务需要把请求级并发、算子内并行、缓存工作集和内存归属放在同一资源账中。增加线程不会增加 CPU 时间额度，减少权重副本不会自动减少各请求的读取，跨域分片也不会消除一个请求的层间依赖。配置比较必须固定请求、历史状态和完成单位，再判断容量是否合法、哪些资源可以并发、哪些等待必然暴露。

## 对象、预算与请求状态

设到达率为 λ，单位是请求/秒；阶段 j 每请求平均消耗 c_j 个 CPU 秒，长期预留 p_j 个 CPU 秒/秒。阶段可以是解析、分词、模型执行、采样和响应编码。CPU 服务时间是各线程实际消耗的 CPU 时间之和，不是请求从入队到完成的墙钟时间。请求等待、线程阻塞和 CPU 运行应分别记录。

设获准运行的在线逻辑 CPU 数为 P_cpuset，CPU 时间额度为每个周期 τ 允许消费 Q，则长期 CPU 时间上界为

P_eff ≤ min(P_cpuset, Q/τ)。

Q、τ 必须使用相同时间单位。祖先限制、同组竞争者和节流可以进一步降低可用预算；这个上界不保证任何线程随时获得执行机会。逻辑 CPU 时间也不是固定的 FLOP 供给：SMT 共享执行资源，频率、向量指令和内存等待都会改变每 CPU 秒的有效工作量。部署口径见[有效资源与部署限制](../system-semantics/deployment-environment.md)。

请求状态可写成 QUEUED、ADMITTED、PREFILL、DECODE、OUTPUT、DONE、CANCELLED。状态表示逻辑推进位置，不证明所有借用缓冲的访问已经结束。必须保持以下关系：

- 输入、KV、logits 和输出携带同一请求身份及代次，不能由形状相同推断可复用。
- 已生成但尚未作为模型输入执行的 token，不具有对应的已计算 KV。
- 可变 KV 和工作区有明确写者；共享只读内容在完整发布后才被读取。
- 取消撤销未来提交和结果发布资格；回收仍等待已提交访问结束及最后读者退出。
- CPU、物理驻留和流量使用同一部署边界，分别记录线程位置、页所有者和实际读取路径。

## 线程预算必须同时检查需求与预留

这里采用一个明确的规划模型。W 个请求 worker 可以同时推进工作；每个 worker 最多使 T 个所计请求阶段的线程同时 runnable。T 包含调用线程在内，不能把“池中辅助线程数”直接当成总线程数。若前处理或其他请求阶段在独立池中并发运行，其 runnable 上界也必须纳入 S；只有这些工作都已包含时才可写 S=W·T。全局共享池则应使用实际全局 runnable 上界。

H 表示未计入任何 c_j、p_j 的剩余 CPU 预留，例如固定调度开销、后台维护和未分摊的网络工作，单位同样是 CPU 秒/秒。已经按阶段计入的分词、采样或编码不能再次放入 H。阶段集合互不重复，每项 CPU 工作恰好归入一个阶段或 H。

p_j 是同一时间窗口内可同时承诺的阶段预算，允许为分数；不是阶段实测消耗，也不是线程对象数。若使用共享池动态借用额度，p_j 可以解释为所选规划方案的保证份额；不能把每阶段单独运行时可取得的全部 CPU 都写成同时保证的 p_j。阶段预算由候选检查的调用者提供，检查器必须验证其总量，不能默认为调用前已经合法。

必要的需求与预留关系是

λc_j < p_j，Σ_j p_j + H ≤ P_eff。

第一式用于有正 CPU 需求的活跃阶段，要求稳定性余量；零需求、零预留阶段可跳过。还应检查总需求 λΣc_j < P_eff−H。阶段需求不饱和并不证明阶段预留总量合法。

保守 runnable 规划另检查

S + H ≤ P_eff。

S 与 p_j 描述同一批请求工作的不同约束，不能再计算 S+Σp_j+H。前者约束可能同时争用 CPU 的线程，后者约束长期承诺的份额。H 和 P_eff 本身是时间份额，因此这个 runnable 检查仍只是保守规划，不能证明瞬时无等待或尾延迟达标。

```pseudocode
算法：统一 CPU 候选检查
输入：非负整数 W、T；非负 P_eff、H、λ、D、B_mem；等长阶段向量 c、p
约定：阶段覆盖所有计入 S 的请求 CPU 工作；H 只覆盖剩余工作；D 为同一请求口径的主存字节
输出：违反约束集合；集合为空仅表示满足所声明模型的必要条件
1. 验证所有标量有限、单位一致，阶段向量等长，c_j、p_j 非负；非法输入拒绝
2. 初始化 violations 为空；S = W*T；P_model = P_eff-H
3. 若 H > P_eff，加入“剩余工作预留超限”
4. 若 S+H > P_eff，加入“runnable 规划超限”
5. 无论 λ 是否为零，都检查 Σp_j+H；若超过 P_eff，加入“阶段总预留超限”
6. 若 λ > 0 且 W=0 或 T=0，加入“活跃请求没有执行 worker”
7. 对每个阶段 j：若 λ*c_j > 0 且 λ*c_j >= p_j，加入该阶段饱和
8. 若 λ*Σc_j > 0 且 λ*Σc_j >= P_model，加入总 CPU 饱和
9. 若 λ*D > B_mem，加入主存带宽需求超限
10. 返回全部 violations；不把空集合解释为可达吞吐或延迟承诺
```

D、B_mem 必须是同一主存层级的有效或实际字节口径。λD=B_mem 只通过这里的非超额检查，没有留下带宽余量；事务放大、抖动和其他读写仍可能使服务不稳定。复杂 NUMA 路径需要使用下一节的逐资源检查，单一 B_mem 不能替代它。

设 P_eff=4、H=1、W=3、T=1、λ=1、c=(1,1)、p=(2,2)、D=1、B_mem=100。runnable 规划为 3+1=4；阶段需求各为 1，小于各自预留 2；总 CPU 需求 2 小于模型预算 3。但预留总量为 2+2+1=5，必须拒绝。删除第 5 步会错误接受这个候选。若把 p 改为 (1.5,1.5)，这些检查均可通过；这仍不能证明排队分布、阶段隔离或 SLO。

cpuset 为 8、额度为每 100 ms 消费 400 ms 时，上界为 4。H=1 后模型预算为 3，两个 worker 各使两个线程 runnable 的 S=4 已超限。宿主机即使有 64 个逻辑 CPU，也不能据此批准这个规划。闭环客户端在服务变慢后会减少发出速率，开环到达则继续积压，见[到达过程与并发](../workloads/arrival-and-concurrency.md)。

## NUMA：物理对象、读取矩阵与依赖图

绑核回答计算在哪个域执行，内存放置回答页在哪个域建立和驻留。采用首次触碰分配时，单线程初始化可能把权重页集中到一个域；之后分散计算线程不会自动迁移页面。文件映射的虚拟大小、干净页共享、写时复制、私有预打包副本和物理驻留必须分开。

域 d 的容量约束为

M_d = W_d + KV_d + A_d + P_d + R_d ≤ C_d。

W_d 是实际执行表示的物理权重，KV_d 是历史及新增状态，A_d 是激活与工作区，P_d 是页表、对齐及元数据，R_d 是未被前述对象覆盖的保留量。共享引用不重复计物理页；预留池若已覆盖其中存活对象，也不能再次相加。

设计算读取发生在 d，页所有者为 e，读取矩阵元素 R_{d,e} 的单位为字节。第一下标始终是读者，第二下标始终是页所有者。权重和 KV 分别记 R^W、R^KV，避免把驻留量当作所有读者的流量。本地量为 Σ_d R_{d,d}，远端量为 Σ_{d≠e} R_{d,e}。

一个远端读取既占用 owner 域内存控制器，也占用互联；这是对同一流量的两个资源约束，不能把两者再相加成独立逻辑读取。一般下界至少包括：

- 每条本地、远端路径上的字节除以对应可持续带宽。
- owner 域内存控制器承担的 Σ_d R_{d,e}，连同写入及其他流量，除以其带宽。
- 共享 fabric 上各实际经过路径的聚合字节除以该 fabric 的带宽；全双工独立方向和共享双向预算应分别建模。
- 请求依赖图的关键路径，以及同一独占资源上必须串行完成的工作。

这些下界取最大仍可能低于可实现完成时间。显式复制还需计源读、目的写、消息启动和完成关系；不能因为权重本地就把激活传递视为零成本。

```pseudocode
算法：固定工作量的 NUMA 候选审计
输入：请求集合及历史长度；逐层逻辑权重与 KV；本轮必须完成的请求—层工作集合；域容量；候选布局和执行轨迹
输出：逐域驻留、读取矩阵、消息、依赖图与违反条件
1. 先建立与布局无关的参考清单：每个请求要执行哪些层，结束时应产生哪些输出，每个请求每层有哪些 KV
2. 枚举物理权重副本与 KV 对象，记录逻辑身份、owner、大小和生命期；共享对象只建一份
3. 核对每个请求—层工作恰好执行一次；核对各布局的请求、历史、KV 逻辑对象及大小相同
4. 按生命期计算各域容量；任一域超限则标为容量不可行，仍可保留账本解释原因
5. 对每个工作，验证其读取的权重层和请求 KV 身份正确，再按计算域、页 owner 累加 R^W 与 R^KV
6. 对跨域依赖显式建立消息：生产者完成后才能发送，接收完整后消费者才能执行；记录源读、目的写与控制成本
7. 对线程、内存控制器和互联分别加资源约束；按依赖与资源顺序计算关键路径及完成时间下界
8. 返回账本与假设；不能只因 local+remote 等于某分支内部总量就认定方案可比
```

## 同一双请求工作量下的三种布局

以下全部为设定模型。两个 NUMA 域各有 16 核，可用容量各为 32 GiB。执行表示的完整权重为 20 GiB，不含下面的辅助预算；无跨层 tied-weight 去重。把模型抽象为四个等权重、等 KV 的连续层组，每组权重 5 GiB。按层分片固定以前两组归域 0、后两组归域 1，不混用输出通道分片的归约成本。

活跃请求固定为 A、B，互不共享前缀。各自历史长度为 122880，每个历史位置全层 KV 为 128 KiB，因此每请求历史 KV 为 15 GiB，总计始终是 30 GiB。完成单位固定为：从两个请求本轮输入已经就绪开始，各执行一次完整 decode 前向并采样一个输出，共两个输出 token。新采样 token 尚无 KV；本轮输入产生的 KV 增量另外进入预留。

不做跨请求 batching，也不假设两个调用从 LLC 复用整份权重；每个请求各读一遍全权重和全部历史 KV。每域另给 Z_d=2 GiB 辅助预算，覆盖激活、工作区、页表、未重复计数的保留量及本轮新增 KV。每请求新增全层 KV 为 128 KiB，已经由 Z 覆盖，不能再次加到表中。

| 布局 | 请求与计算归属 | 权重驻留 GiB | 历史 KV 驻留 GiB | 含 Z 的逐域容量 GiB |
|---|---|---|---|---|
| 完整副本 | A 全程在域 0，B 全程在域 1，各承担独立请求 | (20,20) | (15,15) | (37,37) |
| 共享权重 | A 在域 0，B 在域 1；权重只有一份，owner 为域 0；各请求 KV 留在计算域 | (20,0) | (15,15) | (37,17) |
| 连续层分片 | A、B 都先在域 0 执行前半层，再在域 1 执行后半层 | (10,10) | (15,15) | (27,27) |

层分片的每域 KV=15，来自 A 的半层 KV 7.5 加 B 的半层 KV 7.5；没有把总 KV 从 30 减成 15。在 32 GiB 边界，表中的完整副本和共享布局均不可行，层分片通过所列容量检查。共享方案的 owner 域仍是 20+15+2=37。若只算权重和历史 KV，也仍为 35，不能以“共享”推断可以驻留。

这个结论限于表中 KV 放置。允许把 KV 改放到远端，可以产生其他共享候选，但读取矩阵也会改变；不能沿用本表的流量结论。若容量改为每域 40 GiB，则表中三种布局均通过容量检查，可继续比较时间。布局转换期间旧副本、目标页和在途读者可能同时存活；从完整副本改为层分片时，历史 KV 有 15 GiB 需要跨域迁移，不能把稳态 27 GiB 直接当作转换峰值。

本轮权重读取矩阵如下，行是读者域、列是 owner 域，单位 GiB：

| 布局 | R^W | R^KV | 权重总读量 / 历史 KV 总读量 |
|---|---|---|---|
| 完整副本 | [[20,0],[0,20]] | [[15,0],[0,15]] | 40 / 30 |
| 共享权重 | [[20,0],[20,0]] | [[15,0],[0,15]] | 40 / 30 |
| 连续层分片 | [[20,0],[0,20]] | [[15,0],[0,15]] | 40 / 30 |

层分片虽然每域只驻留 10 GiB 权重，但每域要分别处理 A、B，所以各读 20 GiB。共享权重的物理容量只计一份 20 GiB，两个请求的读取仍计两遍，合计本地 20、远端 20 GiB。所有方案本轮逻辑读取主项都是 70 GiB。

设本地路径和各 owner 内存控制器的带宽为 100 GiB/s，远端路径及此例使用的 fabric 为 25 GiB/s。带宽是声明的模型参数，不是实测。

完整副本每域读 20+15=35 GiB，两个独立请求可并行，读取主项的整轮下界为 0.35 s。共享方案远端权重为 20 GiB，仅这一项就给出 20/25=0.8 s；owner 0 还承担本地权重 20、远端权重 20 和本地历史 KV 15，总计 55 GiB，对应控制器下界 0.55 s。取这些资源约束的最大值，仍至少为 0.8 s，不能使用半个请求 sweep 得到 0.4 s。

层分片的聚合资源账也是每域 35 GiB，资源下界为 0.35 s，但它不能描述有限双请求完成时间。每个请求的前半层必须先于后半层，每半段读 10 GiB 权重及 7.5 GiB 历史 KV。在纯读取、每域一次只执行一个半段的抽象中，半段服务时间 a=17.5/100=0.175 s。

设层边界隐藏向量为 4096 个 FP32 元素，每请求需从域 0 传给域 1 的有效激活为 16 KiB，两个请求共 32 KiB，另有请求身份、位置、代次和完成通知。这里传递的是后半层所需完整隐藏向量，不是输出通道分片的部分和，因此没有虚构 all-reduce。令每条激活消息占用独立通信资源的时间为 δ，其中包含有效载荷、启动和完成开销；源读、目的写及其争用未包含在纯读取数字中，实际使用时必须加入。

```pseudocode
算法：双请求连续层分片轨迹
输入：请求顺序 [A,B]；半段服务时间 a；单条激活消息时间 δ；独立的域 0、链路、域 1 资源
初始化：free0=0，free_link=0，free1=0
对请求 r 依次执行：
  start0[r] = free0
  end0[r] = start0[r] + a；free0 = end0[r]
  send_start[r] = max(end0[r], free_link)
  receive_done[r] = send_start[r] + δ；free_link = receive_done[r]
  start1[r] = max(receive_done[r], free1)
  end1[r] = start1[r] + a；free1 = end1[r]
  后半层及采样完成后发布该请求输出；消息源与目的缓冲等最后读者结束后复用
返回：两个输出的完成时刻 end1[A]、end1[B]，整轮完成时刻 free1
```

当 0≤δ≤a，域 0 的 A 前半段结束后，传 A 的激活并处理 B 前半段；域 1 收到 A 后处理其后半段，再处理 B。整轮为 3a+δ；当 δ>a，链路使 B 的消息等待，整轮为 2a+2δ。统一写作

T_pair = 2a + δ + max(a,δ)。

忽略消息及计算时，双请求下界是 3×0.175=0.525 s，第一请求为 0.35 s；不能把两域带宽相加后宣布单请求或整轮为 0.175 s。只计算权重时，相应双请求数字是完整副本 0.2 s、共享远端下界 0.8 s、层分片依赖下界 0.3 s；它们都固定为两个完整 sweep。

这些必要下界不能直接给出实际方案排序。在每域 32 GiB 时，应先排除表中的两个超容量候选；容量增加到至少 37 GiB 后，完整副本重新成为候选。在相同本地带宽的理想模型中，完整副本避开层流水首尾，有限双请求更有利。若实测分片半段时间为 a、共享方案整轮为 t_shared，则应比较 t_shared 与 2a+δ+max(a,δ)，并计入真实资源共享；增大的消息开销可以反转分片收益。若分片释放的容量允许原来无法准入的请求，其完成吞吐又可能更有利，但那是另一个明确声明的负载比较。

对更多独立请求，层流水可以摊薄首尾；在 δ=0、相同阶段速率且不 batching 的模型中，m 个请求为 (m+1)a，两个完整副本对偶数 m 为 ma。层分片没有凭布局创造额外带宽。单请求延迟、有限任务完成和稳态输出周期应分别报告。

## cache、TLB 与算子线程怎样连接

对 Y=XW，X 为 M×K、W 为 K×N、元素字节为 s，乘加主项约为 2MKN FLOP。忽略中间重复读取时，算术强度约为

I ≈ 2MKN / [s(KN+MK+MN)]。

M=1 且权重大于 LLC 时，主项接近 2/s FLOP/byte；增大 M 可以让同一权重服务多行，但会增加激活、KV、排队和容量。实际 cache 命中、打包、线程划分和归约决定主存字节，不能只靠 shape 判断瓶颈。

一种小 M 路径是沿输出 N 划分线程，每个线程独占一段输出。线程在其域中读取输入，加载对应权重列的连续或打包 panel，向量各 lane 对应不同输出列，沿 K 更新 accumulator，完成后写回独占输出。输入可被多线程重复读，权重的物理 owner 决定是否远端。若沿 K 分割，每线程只能生成部分和，必须增加工作区、合并和数值归约顺序；不能同时采用沿 N 无归约的成本。相邻输出虽由不同线程写，也可能共用 cache line，产生一致性流量。

对简化 panel 模型，A 为 m_c×k_c，B 为 k_c×n_r，C 为 m_c×n_r，容量至少检查

B_A=s m_c k_c，B_B=s k_c n_r，B_C=s m_c n_r，

B_A+B_B+B_C+reserve ≤ U_cache。

[Goto 作者稿](../sources/S-GOTO.md) 的特定多级存储模型还要求保留当前和下一组 B/C 的地址翻译：

T_A + 2(T_B+T_C) ≤ T_TLB。

因子 2 用于下一组 B/C 到来时与旧翻译共存、避免驱逐仍需复用的 A；它不等于所有实现必须额外分配两份用户缓冲。只有独立、连续、页对齐的对象，才可用 T_X=ceil(B_X/P) 计算最少覆盖页数。带页内偏移 o 的连续非空范围需 ceil((o+B_X)/P) 页；有 stride 的原始子矩阵要枚举实际页集合。同页共享、组相联、替换、预取和现代多级 TLB 都可能改变实际效果，旧平台的停顿和参数描述不能成为现代 CPU 的无条件事实。

设 m_c=240、k_c=256、n_r=4、s=8、P=4096，所有 panel 独立且页对齐。A=491520 字节，120 页；B=8192 字节，2 页；C=7680 字节，2 页。完整账为 120+2×(2+2)=128 页，125 个可用条目不足。只数 A 会错误通过。cache 主体为 507392 字节；500000 字节可用容量能容纳 A，却容不下 A+B+C。

打包读取原布局并写入连续 panel，通常包含至少一次源读和目的写；成本与 panel 字节成比例，不能记为零。固定权重可在加载后预打包，若一次性成本为 T_pack、每次调用节省 ΔT、重用次数为 R，只有 RΔT>T_pack 才在该窗口内摊销。激活随请求变化，通常不能跨请求沿用；私有打包副本也进入每域驻留。详细寄存器和分块路径见[CPU GEMM/GEMV](cpu-linear-kernels.md)。

## 低位表示、准备和执行路径

设权重位宽为 b_w，每 g 个权重一组，每组 scale、zero point 等元数据为 b_meta 字节。完整组的平均有效字节约为

b_eff=b_w/8+b_meta/g。

尾组、对齐和打包副本另计。4096×4096 的 4 bit 主体为 8 MiB；g=128、每组元数据 4 字节时，再增加 0.5 MiB，合计 8.5 MiB。同形状 FP32 为 64 MiB。

压缩文件不决定执行路径。逐 tile 解包需移位、符号扩展、scale 读取和转换；完整解包为 FP32 则另驻留 64 MiB，稳态还可能重新读这份副本。整数点积还要检查零点补偿、累加宽度、bias 单位、重新缩放、舍入和饱和；不同 K 组尺度不能在所有整数部分和相加后只乘一个全局 scale。[S-INT8](../sources/S-INT8.md) 支持这些仿射量化机制，但其 ARM 和视觉模型速度不证明本服务 INT4/INT8 路径会加速。

验证应先固定量化码，用独立高精度公式核对解包和补偿，再与原浮点模型比较表示损失。实际 dispatch、硬件指令、转换成本和物理字节决定性能；dtype 名称不证明已使用对应指令。详见[CPU 低位执行](../frameworks/cpu-quantized-kernels.md)。

## 线程池、分块与取消的组合轨迹

长期线程池减少反复创建线程的准备成本。自旋可以减少唤醒延迟，却持续消费 CPU 配额；阻塞等待节省空闲 CPU，但引入唤醒和调度。后台自旋若未进入阶段 c_j，就应进入 H，不能在预算里消失。预取需要可预测地址和合适提前量；提前过多会污染 cache，不能增加已经饱和的内存总带宽。

长 prefill 切块可以为 decode 和控制工作提供调度点，同时增加每块启动、状态保存和重复读取。设已提交 KV 前缀长度为 k，本次输入已知长度为 n；执行块只消费其合法输入区间，完成前不发布新 k。处理最后一个输入得到的 logits 才能用于下一 token 采样，采样出的新 token 不会立即使 KV 长度增加。

| 事件 | 数据与状态推进 | 失败或取消后的责任 |
|---|---|---|
| 准入 | 预留输入、输出、块工作区和新增 KV；绑定请求代次 | 预留失败撤销本次取得的容量，保留旧状态 |
| 提交一个 prefill 块 | 输入只读，目标 KV 为该请求可写区；记录在途线程及借用缓冲 | 停止后续块，不提前复用正在读写的区间 |
| 块完成 | 验证身份与成功状态后发布完整 KV 前缀和进度 | 失败块不作为已完成输入；迟到结果不写入新代槽位 |
| 转入 decode | 最后输入的 logits 已就绪，采样并发布一个新 token | 新 token 尚无 KV，下一步必须执行其输入计算 |
| 层分片消息 | 前半层完成后发送该请求的隐藏向量，后半层依赖接收完成 | 取消不撤回已发消息；源和目的保留到访问结束 |
| 输出与结束 | 发送消费者持有输出读取权；请求停止新工作 | DONE/CANCELLED 后仍汇合在途完成，读者归零才回收 |

若 A 在前半层完成后取消，而其激活已经发送，域 1 可以跳过尚未开始的后半层；已开始的调用则完成但不发布结果。A 的消息缓冲不能立即交给 B，否则 B 的内容可能被迟到接收覆盖。正常 B 仍应推进，取消不能令共享控制路径等待一个再也不会消费的数据队列。这里给出所有权和依赖要求，随章算术脚本没有验证真实线程可见性或取消实现。

## 六类成本与适用条件

计算、访存、通信、准备、同步和驻留需要分别列账。对某阶段，令 F 为运算量，P 为该路径有效计算率，D 为同一资源的字节，B 为可持续带宽。若计算与访存可重叠，但完成后的同步延迟 ℓ 必须串行暴露，则

T_stage ≥ max(F/P,D/B)+ℓ。

若同步自身属于可与主体重叠的独立活动，则只能先用 max(F/P,D/B,ℓ) 作为下界，不能套用前式。跨阶段则使用依赖图与资源顺序；不能把同时发生的全部阶段时长相加，也不能对必需串行阶段只取最大。

| 成本 | 本章对应对象 | 易漏项 |
|---|---|---|
| 计算 | 矩阵乘、attention、解包、采样 | SMT、向量频率、整数补偿和回退路径 |
| 访存 | 权重、历史 KV、激活、打包读写 | 实际 cache 层级、事务放大、owner 控制器 |
| 通信 | 远端读取、跨域激活、IPC | 方向与共享 fabric、源读目的写、消息首尾 |
| 准备 | 分词、页建立、布局转换、预打包 | 冷启动与稳态不同，转换过渡峰值 |
| 同步 | barrier、唤醒、队列、接收与完成通知 | 不可重叠的等待、取消排空 |
| 驻留 | 权重副本、KV、工作区、页表、保留池 | 共享去重、在途对象、旧新布局共存 |

条件改变时应保留数学语义与身份关系，重算成本和候选：

| 变化 | 保留 | 调整或放弃 |
|---|---|---|
| cpuset、quota 或竞争者变化 | 阶段工作身份 | 重算 P_eff、H、S 和 Σp；放弃旧线程额度 |
| 请求并发增加 | 每请求所有权 | 重测池争用、cache 重读、队列和尾延迟 |
| batch 或 M 增大 | 同一权重可复用 | 重算每 token 字节、KV、激活和等待，不沿用独立 sweep 模型 |
| 历史增长 | 请求可见历史 | KV 容量与读取增长，attention 可取代权重读取成为主项 |
| 单域容量不足 | 逐域容量约束 | 排除超限副本；共享须检查 owner，分片须检查依赖和消息 |
| 互联变慢 | owner 与读者映射 | 共享远端项及分片 δ 增长；比较实际完成单位后选择 |
| 页大小或地址布局变化 | panel 数学覆盖 | 重算页集合、对齐、碎片和分配条件 |
| 低位内核不可用 | 量化表示契约 | 重算解包或高精度回退，停止由文件大小预测速度 |
| 长 prefill 混入短 decode | 请求代次与完成关系 | 调整分块、准入和线程份额，复查新增同步与重读 |

## 竞争解释与可反驳实验

CPU 利用率低、IPC 低或 cache miss 多都不能单独决定瓶颈。实验固定语义、完成单位、请求历史及资源边界，每次改变能够区分假设的条件。

| 观察 | 竞争解释 | 干预、预测及反证修正 |
|---|---|---|
| 加线程后吞吐平台 | 主存饱和，或线程同步主导 | 固定放置扫描线程数，联合记录字节速率、运行与等待；带宽仍低时继续查并行度及依赖 |
| 加 worker 后 p99 上升 | 超额订阅、配额节流、cache 驱逐 | 固定额度降低 S，记录 runnable、节流与阶段等待；等待未变则不能只归因线程数 |
| 各阶段需求均有余量却无法兑现份额 | 阶段总预留超限 | 保持 c、λ 不变，单独核对并缩减 p；需求检查通过不能反驳预留冲突 |
| 共享后容量下降但时间不降 | 副本减少，读取仍由每个请求承担 | 固定请求、历史与 sweep 数，核对逐域 KV 和 R；若工作量变了，撤回原速度比较 |
| 层分片时间高于带宽聚合下界 | 层依赖、首尾、消息或计算主导 | 扫请求数并记录每个半段及消息；有限任务有首尾而稳态周期改善时，修正为流水解释 |
| panel 或步长改变产生台阶 | cache、TLB 或地址冲突 | 固定计算量改变跨页布局、偏移与 panel，关联页集合和可用事件；不能把所有 cache miss 当 TLB miss |
| 低位文件变小但服务不快 | 解包、尺度读取、私有副本或 dispatch 回退 | 分开准备与执行，固定质量和 shape，记录路径与字节；字节未减少就不声称带宽收益 |
| kernel 变快而 ITL 变差 | 算子池挤占调度、分词或输出 | 固定到达和总预算，改变 H 与分块，比较阶段等待；单算子时间不足以解释服务结果 |
| 总 CPU 低但队列增长 | 单域执行、远端路径或输入供给受限 | 按线程、域与请求记录运行和等待，分别改变计算亲和与页位置 |

[S-PERF](../sources/S-PERF.md) 的固定文档区分进程、线程、CPU 集合、系统和 cgroup 观察范围，并说明事件复用、运行比例和缩放。IPC 的 instructions 与 cycles 必须来自相同范围和时段；prefill 与 decode 混合时，不同窗口的两个计数不能组成有意义的比值。记录权限、采集开销、事件支持及迁移；这里没有声称执行 PMU 采集。

浮点加法不满足实数结合性，改变线程划分、批量或归约顺序可能改变结果。应以独立数值参考定位首次分歧，再分别评价容差、argmax 和任务质量；CPU 与 GPU 输入逐位相同也不保证输出逐位相同。

## 检查与未测量边界

随章 tools/check_k_hw_009_full.py 是标准库、只读、离线的 CPU 算术与依赖模型。它用离散份额槽位独立核对阶段预留；用固定请求—层清单检查跨布局工作覆盖和每个 KV 对象；用逐单位读取参考核对矩阵；用枚举各资源执行顺序和 DAG 最长路径核对流水递推。删除阶段总预留、共享方案减半 KV、丢失或重复请求、把远端流量改为本地、把层依赖当聚合带宽均有负对照。panel 页集合、尾组存储和串行同步也有边界复算。
