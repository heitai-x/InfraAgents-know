# K-HW-001：容量、算术强度与服务 Roofline

容量决定哪些状态能同时存在，带宽和计算能力约束处理这些状态的速度，依赖关系决定这些约束怎样进入服务时间。容量、流量和计算必须分账，再通过物理资源与执行时间线连接。Roofline 提供条件化下界和可检验的瓶颈假设；它本身不预测完整服务延迟。

## 三本账的对象、单位与边界

容量账记录同一时刻占用的物理字节，流量账记录指定执行范围内跨某条边界的字节，计算账记录同一范围内的算术工作。一个对象驻留一次，可能在许多 decode 步中反复被读取；多个请求共享一个对象，也可能分别读取它。

定义：

- F 为有效算术工作，矩阵乘通常按一次乘加为 2 FLOPs，主项为 2MKN。padding、重复计算和重算的执行工作另列。指数、整数解包与矩阵乘不能未经说明一起除以 Tensor Core 峰值；应拆成资源类别，或使用与混合操作匹配的参数。
- D_use,j 为边界 j 上消费者需要的有效字节；D_tx,j 为该边界实际传送的事务字节。边界可以是设备主存、L2、共享存储、主机内存、主机设备链路、网络或存储。方向、读写及缓存条件属于量的身份。
- P_eff 为匹配 dtype、shape、布局、指令路径和运行条件的计算能力，单位 FLOP/s；B_eff,j 为匹配访问形态与字节口径的带宽，单位 byte/s。
- C(t) 为时刻 t 的物理占用。物理对象用设备、分配身份和代次区分；别名与多个所有者不增加副本，另一设备上的复制则是另一物理对象。

对正的 P、B，以及非负的 F、D，局部资源模型为

T_lb＝max(F/P, D/B)，I＝F/D，R_roof＝min(P, BI)。

当 F＞0、D＞0 时，F/R_roof＝T_lb，交点强度为 I*＝P/B。I＜I* 表示该模型中带宽项较大，I＞I* 表示计算项较大。max 是各项必要时间的下界，即使资源不能重叠仍成立；要把它当作可达到的完成时间，才需要足够并行度、独立资源和充分重叠。完全串行时，这两个区间要相加。

实际可持续速率是带条件的测量参数，并非数学保证的硬件能力上限。用它构成的是相应条件下的理想资源估计；访问方式、并发、时钟或工作集变化后，不能继续把旧值称作无条件硬下界。直接用被诊断 kernel 的 F/T 同时定义 P，再用 F/P 解释该 kernel，只有恒等式，没有辨识出计算瓶颈。

有效字节与事务字节有两种一致用法：D_use/B_use，或 D_tx/B_tx。若有效负载 128 B 需要传送 160 B，匹配模式的有效带宽为 80 B/时间单位、事务带宽为 100 B/时间单位，则两式都给出 1.6 时间单位。把 160 B 再除以已经包含放大的 80，会重复惩罚同一次浪费。

容量峰值与驻留量也不同：C_peak＝max_t C(t)，驻留积分为 A_C＝∫C(t)dt，单位 byte·s。前者约束准入，后者描述容量被占用多久；不能把驻留积分直接加进毫秒延迟。

本章账本输入为对象生命期、消费者访问、算术事件、资源参数和阶段依赖图；输出为容量峰值、驻留积分、分边界需求、条件化时间下界及未解释成本。它不直接输出目标设备已经达到的性能。

## 记账合法性：去重、回收和资源合并

容量对象的区间采用 [birth, retire)。birth 是物理预留实际占用容量的时刻，而非首次读；retire 是逻辑持有者全部释放且已提交的物理访问全部完成后的可回收时刻。同一时间点先处理结束、再处理开始，并在该时间点全部事件处理完后统计峰值。零长度区间为空集，应跳过，不能先执行一次没有出生的回收。

一个对象可有重叠的持有记录：共享所有者、缓存保留和在途访问均可延长生命期。相同物理键按这些区间的并集计一次；记录必须覆盖真实预留的整个时间，不能只用 kernel 的读取窗口代替分配生命期。同一键的大小不一致应拒绝；地址用于下一次分配时必须改变代次。

预留池和池内对象也有包含关系。设备已经为 KV 池占用 4 GiB，其中活跃页 3 GiB、空闲保留页 1 GiB，物理占用为 4 GiB，不能再加上 3 GiB。若从活跃对象出发记账，只补未被这些对象覆盖的保留容量。页尾与对齐若已包含在整页大小中，也不能再额外加一次。

| 情形 | 合法记账 | 需要防止的误读 |
|---|---|---|
| 多个请求共享物理页 | 容量按唯一物理键计一次 | 读取流量也自动只计一次 |
| 两个消费者共用 HBM 或同一链路 | 合并该资源需求，再用共同能力估值 | 各自领取完整独占带宽 |
| H2D 与 HBM 读取属于不同资源 | 分别记账，并检查复制引擎及共享上游 | 用 HBM 带宽除 H2D 字节 |
| 两阶段有依赖 | 保留前驱完成条件 | 用 max 代替先后关系 |
| 不同方向有独立能力 | 使用双工曲线或分别建轴 | 无条件把读写或双向带宽相加 |
| 工作集命中 L2 | 减少相应 D_HBM，保留 D_L2 | 将命中速率当成全局 HBM 带宽 |
| F＝0 或 D＝0 | 相应需求时间为零 | 对纯搬运使用 F/R_roof 的 0/0 |

本章检查函数采用严格输入契约：F、D 非负，P、B 始终为正；无效参数抛出 ValueError，检查断言失败抛出 AssertionError。空工作 F＝D＝0 的资源时间为零，算术强度未定义；D＝0、F＞0 是纯计算边界，F＝0、D＞0 是纯搬运边界。不能把非法零能力悄悄替换成默认值。

## 从事件建立容量账与阶段下界

```pseudocode
算法 BuildResourceLedger
输入：物理持有记录 H；读取/写入与计算事件 E；参数包；阶段 DAG G
输出：C_peak，驻留积分 A_C，资源需求向量，各阶段下界，整体必要下界与未知项

验证所有大小和需求非负，能力为正，物理键大小一致，G 无环
为每个阶段建立计算类别和存储/通信资源轴
对 H 中每条记录 (key, birth, retire, size)：
    若 birth > retire：拒绝
    若 birth = retire：跳过
    在 birth 记录取得持有，在 retire 记录结束持有
按时间分组排序，初始化 total=0，peak=0，area=0，active_count 空
对每个时间点 t：
    area += total × (t - 上个时间点)
    先结束本时间点全部旧持有：计数减一，降到零时从 total 扣 size
    再取得本时间点全部新持有：从零变一时向 total 加 size
    peak=max(peak,total)
要求最终全部持有结束；返回 peak 和 area

对每个执行事件：
    将工作记到其阶段和计算类别
    将读写记到实际跨越的边界、方向和共享资源
    区分消费者有效字节、事务放大、缓存命中和重复读取
    未证实的缓存或多播收益保留为待验证假设
对每个阶段 s：
    τ_s=max(该阶段各资源需求 / 对应能力)
    若已知阶段内部必须串行，将它拆成有边的更细阶段
按拓扑序求 finish_lb(s)=τ_s+max(前驱 finish_lb)，无前驱取零
L_path=max_s finish_lb(s)
对每个共同资源 j：L_work,j=全图在该资源的总需求 / 能力_j
T_lb=max(L_path, max_j L_work,j)
输出局部项、整体下界和仍未建模的准备、同步、争用、排队等项
```

容量事件扫描的正确性来自计数的零到一、以及一到零转换：任何重叠持有都不会重复增加物理容量，最后持有结束前也不会扣掉它。按时间分组可以避免同一时刻多个开始事件的处理顺序制造虚假峰值。事件排序成本为 O(|H| log |H|)，扫描为 O(|H|)，活跃计数空间随同时存活物理键数增长；若保存完整轨迹，还需保存全部事件。阶段需求累加与 DAG 遍历分别随事件数和顶点/边数增长。

整体公式只是必要下界。一般 DAG 的资源争用与依赖交错，不能靠递归套 max、sum 就求出真实最短调度。设两块数据分别经过 X、Y 两个独占阶段，各阶段都需 2 个时间单位。每条路径长 4，X、Y 的总工作也各为 4，因此上述下界为 4；但第一块需要 X[0,2)、Y[2,4)，第二块最早 X[2,4)、Y[4,6)，全部完成需 6。下界没有错，把 4 报成完成时间才错。

对 n 个等长块、两个独立串行阶段、充足缓冲、无额外争用，令每块阶段时间为 a、b，则完整流水时间为

T_pipe＝a＋b＋(n−1)max(a,b)。

第一块与末块的首尾成本没有因流水消失。没有足够缓冲或两个阶段共用资源时，要重新构造时间线。比较设备结果时，可以用合法调度给出可行时间，再与必要下界夹住范围。

## 权重、KV 与共享尾页的一次组合轨迹

设同构普通全注意力模型有 L 层、Hq 个 query heads、Hkv 个 KV heads、每 head 通道 d、每元素 s 字节。每 token 全层普通 KV 主项为

c_KV＝2LHkvds。

无共享的有效状态为 c_KVΣ_r n_r；分页后的物理容量则按实际唯一页数乘页字节。令页长为 Bp，一页全层主项为 Bp·c_KV。量化参数、目录、并行副本、对齐及暂存另计。异构层、窗口和 MLA 必须逐层按实际状态族重算。

在每个请求每轮读取其可见历史、同组 query heads 理想复用 KV 的假设下：

D_KV,use≈c_KVΣ_r n_r。

这里 n_r 是本次 attention 实际可见的有效位置数；若把当前行包含其中，就不能再当作历史读取重复加一次。新 KV 的写入另外记账。共享前缀不改变各请求的合法可见集合；不同请求没有实际合并读取时，流量仍按读者累计。GQA 若缺少片上复用，实际读取还可能增加，不能仅从 Hkv 推出 HBM 节省。

忽略 softmax 与当前行等小项，decode 的 QK/PV 工作约为 4LHq dΣn_r。因此理想 attention 强度为 2Hq/(Hkv s)。历史增长同时增加计算与读取，不会单独提高这部分强度。Hq/Hkv 的头映射来自模型，已有 MHA checkpoint 不能仅靠修改头数就当作等价 GQA。

令 W 为本轮实际需要读取的权重主项，batch 为 b；每输出 token 的读取约为 W/b＋c_KV n_avg。交点为

b*＝W/(c_KV n_avg)。

设 W＝8 GiB，c_KV＝128 KiB/token，n_avg＝1024，则每请求 KV 为 128 MiB，b*＝64。b＝16 时权重加 KV 的读取主项为 10 GiB；假定同一 HBM 资源提供 1 TiB/s，对这部分读取得到 9.765625 ms。每轮产生 16 个输出 token，摊薄值为 0.6103515625 ms/token，但每个请求仍受整轮完成约束。这还未加入新 KV 写入、其他激活、计算、采样和排队，不能叫端到端延迟预测。

同一时刻若权重 8 GiB、KV 2 GiB、激活 0.5 GiB、workspace 与图池 1.5 GiB、通信缓冲 0.25 GiB，以及未被前述对象覆盖的保留容量 0.5 GiB，则设定峰值为 12.75 GiB。只有这些生命期确实重叠时才是该轨迹峰值；分别取各类峰值相加通常只是保守上界。

再看共享尾页追加。取 Bp＝16、c_KV＝128 KiB，一页为 2 MiB。请求 A、B 共享含 15 个有效 token 的页 P：

| 事件 | 状态与可见性 | 容量和流量 |
|---|---|---|
| 分支前 | A、B 都读取已发布 P | 唯一容量 2 MiB；两者分别读取时有效读量合计 3.75 MiB |
| A 准备追加 | 先预留私有目标 Q，P 保持可读 | P、Q 同时存活，容量 4 MiB |
| 复制与写入 | 将旧 15 行复制到 Q，再写 A 的新行 | 若只复制有效行，复制读和写各 1.875 MiB，另写新行 128 KiB |
| 发布 | 等待 Q 的内容、有效长度和目录一致后切换 A 的视图 | A 用 Q，B 及旧在途读者仍可用 P |
| 失败或取消 | 发布前失败撤销新预留，旧视图保留；已提交复制需完成后才回收 Q | 不能把发出取消当作物理容量立即释放 |
| 回收 | P 不再有逻辑保留且所有旧访问结束后回收 | 没有额外缓存保留时，最终仅 Q 占 2 MiB |

复制整页也是合法选择，但复制读和写各为 2 MiB。不能同时采用有效行复制的流量与整页复制的实现。这个抽象页汇总全层字节；若实际每层独立分配，必须确保全部必要增量成功后才发布一致视图。

## 从逻辑 tile 到地址、线程、共享存储和写回

下面选择一个便于复算的标量 FP32 GEMM 映射，说明减少全局重读如何支付片上容量与同步。它不是推荐的最佳 tile，也不声称使用矩阵专用指令。

令 Y＝AW，A 为 M×K、W 为 K×N，均行主序。一个 CTA 使用 8 个 warp、每 warp 32 个 lane，计算 8×32 输出。warp u∈[0,8)、lane λ∈[0,32) 对应输出 (m0＋u,n0＋λ)，持有一个标量 accumulator。全局元素地址分别为 base_A＋4(mK＋k)、base_W＋4(kN＋n)、base_Y＋4(mN＋n)。

沿 K 每次取 32 行。共享 A_s 为 8×32，W_s 为 32×32，字号分别为 32u＋t、32t＋λ。输入单缓冲占 4(8×32＋32×32)＝5120 B；地址、其他临时量、分配粒度及编译器产生的寄存器另计。

```pseudocode
算法 ScalarTiledGEMM
输入：行主序 A[M,K]、W[K,N]；非负整数 M,N,K
输出：Y[M,N]
若 M=0 或 N=0：结束，无输出元素
对每个输出 CTA 起点 (m0,n0)，步长分别为 8、32：
    所有 (warp u,lane λ) 初始化 acc[u,λ]=0
    对 k0=0,32,… 且 k0<K：
        每个线程载入 A[m0+u,k0+λ] 到 A_s[32u+λ]
            越界时写入零，不发出越界全局读取
        每个线程对 v=0,1,2,3：
            t=u+8v
            载入 W[k0+t,n0+λ] 到 W_s[32t+λ]
            越界时写入零
        全 CTA 完成共享写入并建立可见性
        对 t=0,…,31：
            acc[u,λ] += A_s[32u+t] × W_s[32t+λ]
        全 CTA 最后读者完成，之后才能覆盖这两块共享存储
    若 m0+u<M 且 n0+λ<N：写回 Y[m0+u,n0+λ]=acc[u,λ]
```

全部线程都参与两个 CTA 完成边界；尾部线程只屏蔽全局访问与最终写回，不能提前退出而使其他线程永久等待。K＝0 时没有输入循环，输出为零。每个合法输出恰有一个写者，每个有效 k 恰贡献一次乘积；共享缓冲必须先写完、后读完、再覆盖。第二个完成边界保护下一次加载，不能只保留第一个。

在固定 CUDA 12.8.0 文档的 CC≥6.0 访问模型中，lane λ 读取相邻 32-bit 字：起点按 32 B 对齐时，128 B 有效负载覆盖 4 个段；偏移 4 B 后覆盖 5 个段。以上 A、W、Y 的行首只有在基址、leading dimension 与 tile 起点共同满足对齐时才符合四段情况。K 或 N 非对齐、尾部 mask 都会改变段集合。段数不等于实际 HBM 事务；L1/L2 与邻接 warp 复用还会改变后者。

对文档中的 32-bank、连续 32-bit 字逐 bank 分配模型，A_s 的逐行加载和 W_s 的逐行加载按 lane 落到不同 bank。计算时，同一 warp 读取 A_s[32u＋t] 是同地址广播，读取 W_s[32t＋λ] 分布在 32 个 bank。一般字号 8λ＋t 只覆盖 4 个 bank、每 bank 有 8 个不同地址，属于该标量请求模型的 8 路冲突；不能把广播误判为 32 路冲突，也不能将该模型直接推广到向量或矩阵加载的内部请求。

忽略 cache、按被屏蔽后的有效全局访问累计，这条具体映射的字节为

D_use＝4[MK ceil(N/32)＋KN ceil(M/8)＋MN]，

M 或 N 为零时整体为零。A 会按输出列 tile 重读，W 会按输出行 tile 重读；不能一面采用此 CTA 划分，一面只计全矩阵各读一次。K 尾块的填零不发出输入读取，却仍可能执行乘加。若未消除填充计算，完整 tile 的执行主项为 2·8·32·32·ceil(M/8)ceil(N/32)ceil(K/32)，而有效主项仍为 2MKN。

增大输出 tile 可减少输入重读，却扩大 accumulator、共享缓冲和临时量；更深流水还增加同时存活输入。寄存器 spill 可能增加 local-memory 访问，其中经过 cache 后的主存事务需单独核对。共享存储与寄存器上限、分配粒度和实际活跃 CTA 决定驻留，不能用总共享字节直接证明性能。这里的 CPU 标量模拟验证地址、尾部和算术覆盖，不证明真实 barrier、设备可见性或编译器资源使用。

## 完整服务、准备与成本边界

计算、访存、通信、准备、同步和驻留都要对应同一候选及同一时间范围。准备包含分词、页表、布局转换、权重打包、编译与图捕获；同步包含生产者发布、消费者完成、归约和调度等待。单设备常驻 GEMM 本身没有跨设备通信；完整服务仍可能有 H2D、输出回传、TP collective、P/D 状态交换和网络发送。

设每轮 H2D 1 GiB、可用链路 16 GiB/s，另有设备内部读取 10 GiB、带宽 1 TiB/s，则两项为 62.5 ms、9.765625 ms。完全串行为 72.265625 ms；独立工作充分重叠时，较松的理想下界为 62.5 ms。同一数据必须先传完再计算时，不能仅凭有异步接口就声称后一结果已达到。共享 PCIe 上游或主机内存控制器还需合并需求。

ServerlessLLM 固定论文 §6.2 使用 q＋n/b 估计加载：q 是排队秒数，n 是模型或分片字节，b 是路径可用带宽，并在其多级流水中选慢端带宽。它适用于其调度与流水假设；有限块数的首尾、初始化和最后就绪同步仍可能带来残差。§4 的连续块格式、主机块池、直接文件访问与 pinned 内存改变启动路径，不证明所有 mmap 更慢，也不意味着常驻 decode 更快。

Amdahl 关系为 S_total＝1/[(1−f)＋f/s]。f 必须来自原关键路径上能被该改动缩短的时间，不能从重叠 kernel 的累计时长直接计算。若 f＝0.3、s＝2，其他不变，则总加速为 20/17≈1.176；新增转换或同步还会降低它。多个优化若都省同一次读取，不能重复扣流量或直接相乘加速比。

实例计费包括空闲、加载、服务和排空。能量为同一测量边界内功率的时间积分；设备、整机与机房口径不能混用。单位合格请求成本为总计费成本除以满足质量和 SLO 的请求数；失败、重算和未完成工作仍留在分子。提高 batch 后每 token 能量可能下降，但单请求等待仍可能上升。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的机制 | 重算的成本与反转条件 |
|---|---|---|
| batch 增大 | 权重可在一次调用内复用 | W/b 下降，KV、激活和等待增长；SLO 或容量超限时限制并发，b* 不是最佳 batch 定理 |
| 历史增长 | 逻辑位置与头映射 | KV 读取和容量增长；attention 主导后，只优化权重可能不再缩短关键路径 |
| 前缀共享增加 | 唯一物理页去重 | 读取仍按消费者、COW 按实际复制；只有容量下降时不宣称带宽同比改善 |
| 低位或分组变化 | 编解码身份与模型质量要求 | 加入 scale、解包、转换和实际指令；新增成本超过字节收益时保留较高精度路径 |
| 工作集越过 L2 | 合法计算不变 | 重建 D_HBM 与 D_L2；停止沿用小工作集的命中速率 |
| tile 或流水加深 | 输出覆盖与最后读者依赖 | 重算重读、准备、共享容量、寄存器和 spill；完整网格变慢时可回退 |
| GPU 换 CPU | 容量、流量与依赖抽象 | 使用 CPU 指令、cache/TLB、NUMA 和线程预算；不沿用 CUDA lane/bank 模型 |
| 采用统一物理内存 | 数据依赖和读写所有权 | 显式副本可能减少，共同带宽、容量和同步仍存在；不能假定双方获得独立峰值 |
| 页长改变 | 逻辑位置到物理页身份 | 页表、尾部浪费、COW、消息粒度及 kernel 并行度同时改变 |
| 加载路径改变 | 启动与稳态分别记账 | 块池副本、流水首尾和就绪同步改变；加载收益不能外推为 decode 收益 |

PagedAttention 固定论文在其 A100、OPT/LLaMA 与指定轨迹下报告：块表、分支和变长处理令 attention kernel 比其连续基线增加 20–26% 延迟；ShareGPT 上块长 16–128 较好，较短 Alpaca 上 16、32 较好，最终选择 16。这说明容量收益能够与局部算子开销同时存在，不能把 16 或该开销比例当成跨平台常数。

FlashAttention 固定 v2 的 Algorithm 1 用 K/V 外循环、Q 内循环，逐块回写输出与统计量；避免完整分数/概率矩阵，但仍有 Q、O 与统计量的多遍访问。其 M 是片上可容纳的标量元素数。Θ(N²d²/M) 是声明的二级存储模型中的 IO 阶，不是实际 HBM 事务字节。改为其他循环顺序会改变驻留对象、重读常数和并行度，必须重算；窗口或稀疏只有在模型函数允许时才可减少合法集合。

## 竞争解释、反例与区分实验

| 观察 | 竞争解释 | 可控干预及反证后的修正 |
|---|---|---|
| 低强度却远慢于 D/B | 事务放大、能力参数不匹配、并行度不足、依赖或启动主导 | 固定逻辑工作改变对齐/stride，再扩大工作集并记录事务和时间；字节下降而时间不降时，继续查计算与等待 |
| 共享后显存下降但吞吐不变 | 只减少副本，各请求仍分别读；瓶颈位于别处 | 固定前缀与历史扫读者数，比较容量、L2/HBM 字节和整轮时间；只证实容量时收回带宽结论 |
| batch 摊薄更好但 ITL 变坏 | 权重复用、KV 增长和排队共同作用 | 固定到达与历史，分别记录每轮时间、每 token 摊薄值和请求等待；不能将后三者合并为一个指标 |
| 大 tile 或深流水更慢 | 首尾、spill、驻留下降或没有重叠 | 扫 K 长度，分开单 CTA 与完整网格，核对 local traffic、资源分配及等待；长输入斜率更坏时，首尾不足以单独解释 |
| 量化后更慢 | 解包、尺度读取、事务未降或内核回退 | 固定质量与 shape，分开转换及执行并记录实际 dispatch；字节不降时不声称已取得读取节省 |
| 容量足够却 OOM/换出 | 池重复计数、漏尾页、COW、在途页或过渡峰值 | 记录预留、发布、最后读者和物理回收；分别检查容量峰值及驻留积分，不能仅看请求结束计数 |
| CPU 加线程后尾延迟上升 | NUMA、超额订阅、cache 驱逐或主机执行域饱和 | 固定配额、亲和和放置，改变线程/请求并发；总利用率低不能排除单域瓶颈 |
| 加载变快而热服务不变 | 改动只影响启动 | 分开冷启动、热启动与常驻调用；只修改启动参数，不给稳态 P/B 加同样收益 |

反例一：四个所有者共享 128 KiB，容量为 128 KiB，分别读取一次的有效请求量为 512 KiB。按所有者算容量会过度拒绝；按唯一容量算读量则低估流量。

反例二：两段各为 20、10 ms，独立重叠可以为 20 ms，串行或同一独占资源则为 30 ms。一般流水还有首尾；前述两块 X→Y 的下界为 4、最短调度为 6，说明 max 的下界性质和调度完成时间是不同结论。

反例三：共享页的第一个读者结束不会改变峰值，却可能使错误回收缩短占用时间。因此只核对峰值不够，还要比较逐段容量或驻留积分。零长度记录又必须贡献零，不能制造瞬间峰值或无出生回收。

随章 tools/check_k_hw_001_full.py 提供标准库、离线、只读的 CPU 算术与事件模型：明确区分 ValueError 与 AssertionError；用中点物理并集独立核对事件扫描的峰值和积分；以穷举调度区分下界与完成时间；以逐字节段集合核对对齐公式；以稠密点积核对完整 tile 映射、尾部及读取账。错误的所有者求和、提前回收、共享 stride、忽略地址偏移、重复事务放大与摊薄延迟均进入负对照。
