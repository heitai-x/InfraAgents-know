# K-HW-013：共享内存路径：统一地址、物理驻留与显式迁移

CPU 和 GPU 能使用同一个指针，只说明存在某种地址关系，不说明数据已在消费者附近、缓存已经一致、全部访问模式都受支持，或最后使用已经结束。共享路径设计需要分别证明地址可用、内容可见和存储仍归本代所有，再用同一访问轨迹比较显式复制、映射访问、可迁移统一内存与物理统一内存。

## 对象、访问与四种路径

逻辑对象记为 O=(id,va,D,v)：id 是对象身份，va 是虚拟地址范围，D≥0 是有效字节数，v 是成功写入的内容序号。底层存储另有身份 X=(pid,pool,size,epoch)。epoch 在物理槽排空并交给新对象时递增；写入内容或搬动一页不会因此自动创建新的对象 epoch。

部分改写需要范围版本图 ν(b)：它记录字节 b 最近一次成功写入的内容序号。实现可以用不重叠区间表示，不必逐字节保存。一次写入完成后，v 增一，仅将被写范围的 ν 更新为新 v；未写范围保留旧标签。副本有效性需要匹配被消费范围的 ν，不能要求所有字节具有相同标签，也不能只检查对象的全局 v。

访问描述为 a=(uid,phase,processor,mode,[s,e),queue,pred)。processor 是 CPU 或 GPU；mode 为 READ、OVERWRITE 或 UPDATE。READ 和 UPDATE 需要旧内容；OVERWRITE 完整定义其声明的 [s,e)，不读取这段旧内容，并不必然覆盖整个对象。范围采用半开区间，要求 0≤s≤e≤D。pred 是生产与执行依赖。uid 在同一 epoch 内不复用，完成通知携带 (pid,epoch,uid)；内容版本不能代替这个使用身份。

| 路径 | 数据流 | 主要资格与成本 |
|---|---|---|
| 显式复制 | 主机和设备分别保存缓冲；消费者读取已完成的本地副本 | 目的容量、源保护、复制完成、staging 与副本驻留 |
| 映射主机内存 | GPU 地址经受支持的映射访问主机物理页 | 锁页/注册、访问能力、远端事务、地址翻译与同步 |
| 可迁移统一内存 | 运行时按支持能力迁移页或建立远端访问 | 支持级别、缺页与迁移、页粒度、预取、来回迁移 |
| 物理统一内存 | CPU/GPU 使用共同物理池中的数据 | 共同容量、共享带宽、缓存与执行依赖 |

四种路径都需要区分四个关系：虚拟范围具有合法访问途径；物理 backing 存在且仍存活，或平台已经承担受支持的首次触碰供页；处理器支持实际访问宽度、对齐和操作；生产完成及最后使用之间存在所需同步。地址相同不蕴含后三项。

地址资格另记为 addr=(pid,epoch,processor,range,permissions,prepare_ticket)。它说明本次访问将使用哪个 backing、哪段地址、什么权限，以及分配或映射何时生效。内容资格 valid 则说明哪些字节已经初始化、具有哪次写入的内容。首次 OVERWRITE 可以没有 valid，但必须具备 addr；READ 同时需要两者。映射能力存在只是允许准备，不表示准备已经完成。

固定 MLX 文档描述 Apple Silicon 的共同内存池，以及框架为受跟踪数组操作建立的依赖。固定 CUDA 资料描述随系统能力变化的 Unified Memory，并明确数据移动仍会发生。固定 PyTorch 文档分别讨论异步执行顺序和 allocator 生存期。这些语义不能仅凭“统一内存”名称互换。

## 合法性：能力、可见性与地址保活

### 显式复制和映射访问

显式复制要求源范围已经初始化，目标容量足够，消费者依赖覆盖本次范围的复制完成。源在 DMA 最后读取之前不能改写；目标在复制写入完成之前不能被消费者读取，覆盖目标还要等它的旧读者结束。异步调用返回不等于复制结束。pageable 主存可能经过 staging；pinned 内存提供稳定页面，但分配、注册和锁页容量都有成本。

CPU 改写源后，相应设备副本范围失效。下一次 GPU 消费必须补齐所需版本；保留同一个设备指针不能恢复内容一致性。GPU 写入后 CPU 消费也需要相反方向的数据恢复，除非实际选择的共享路径已经提供合法访问。

映射路径要求目标支持映射主机页，并满足注册范围、映射使能、权限、访问宽度和对齐条件。所供 CUDA §3.2.6.3 摘录明确要求通过 stream 或 event 避免 RAW、WAR、WAW 冲突；映射页上的设备原子操作不保证从主机或其他设备看来仍然原子。文档对自然对齐的 1、2、4、8、16 字节访问给出保持单次访问的约束，这不是任意复合读写协议的原子性证明。

首次 GPU 只写同样需要合法设备地址：取得主机 backing，按目标要求锁页或注册，建立或确认设备别名，取得写权限，并使这些准备先于实际 store。省去旧字节恢复不能省去这些步骤。已有只读映射也不能直接授权 UPDATE 或 OVERWRITE；权限升级及其生效关系需要重新核对。所有内部复制的源和目的也必须满足各自的地址资格，不能只检查最终消费者。

write-combining 内存适合主机主要写入、设备读取的情形；主机读取可能很慢，CPU 原子支持也不能当作通用保证。映射消除了显式设备副本，并没有消除远端读取和同步。

### 可迁移与物理统一内存

CUDA Unified Memory 的资格应按实际分配类型和支持属性判断：系统分配是否可访问、Managed Memory 是否支持并发、主机原子是否支持等是不同问题。仅有统一地址而无完整并发支持的目标，必须遵守其 CPU/GPU 访问限制。不支持的路径应拒绝，不能把统一指针当作能力探测。

pointer attributes 表示分配或注册类型，不报告当前物理驻留。系统可能把页迁向访问者，也可能通过远端映射提供访问；应用不能由指针类型推定某次读取已经本地化。

预取是性能提示。所供 CUDA 摘录规定其在指定 stream 的前序工作之后开始、后序工作之前完成；这个顺序只覆盖相应执行关系。其他队列的读写仍需自己的依赖。程序正确性依赖合法访问和生产可见性，不应依赖提示必然把全部页永久留在目标内存。

首次触碰供页与未准备地址不同：在受支持的系统分配或 Managed Memory 契约内，应用可以提交访问，由运行时在实际访存时落实物理页；这不要求应用提前手工填充每页。应用仍须证明分配类型、范围、权限、设备和生存期合适。任意预留但未提供合法供页契约的虚拟地址不具备这种资格。

物理统一内存要求双方确实使用共同物理池。MLX 的自动依赖覆盖框架跟踪的操作；原生指针、外部库、其他进程和未声明别名要按互操作契约补齐同步。共享物理页不取消生产先于消费、最后读取先于覆盖的关系，也不授予 CPU/GPU 各一份独占带宽。

### 图重放与池共享

固定 PyTorch 文档说明，CUDA Graph 每次重放使用固定虚拟地址；地址被释放或分配给新 tensor 后，旧图可能非法访问或破坏新内容。图私有池保持到图及捕获期间创建的 tensor 都结束生命期。即使上一次 replay 已结束，只要仍允许未来 replay，就必须保留相应地址资格。

原文给出两种图池共享情形：一组图始终按捕获顺序重放且不并发；或者各图彼此不依赖对方输出且从不并发。第二种情形不需要被改写为固定捕获顺序。两种情形都要保护尚需保留的输出：共享池中的下一次重放可能覆盖旧输出，需要时先复制到独立存储，并让复制结束先于覆盖。具体封装 API 仍须遵守其自身捕获与调用顺序约束。

## 同一轨迹的字节与成本账

以下先核算相同 GPU 消费轨迹的路径成本；CPU 产出、改写和算子计算另列共同项。只有工作相同且资源竞争未改变这些共同项时，比较中才可约去它们。若 CPU 与 DMA 或 GPU 争用内存，必须重新计算共同资源负载。

设 GPU 的第 i 次读取范围集合为 A_i，有用请求字节为 U=Σ_i Σ_{r∈A_i}|r|。重复读取仍重复计入 U；对象唯一容量不等于累计读取量。定义：

- Q_c：实际跨链路复制的字节，包括实际补复制，而不是消费者读取量。
- Q_d：消费者在设备本地存储边界产生的实际读取字节。
- Q_remote：映射访问在指定远端数据链路上产生的实际字节。
- B_l、B_d：分别匹配这些事务口径与并发条件的链路、设备本地带宽，单位为 byte/s。
- α=Q_remote/U、β=Q_d/U，U>0 时定义。合并、缓存、重读和事务粒度决定它们；跨重复读取的缓存复用可能使该边界上的比值小于 1。

不能同时使用已经吸收访问放大的有效载荷带宽，再对字节乘同一放大系数。

在复制、读取串行且无其他重叠的简化条件下：

T_copy≈Q_c/B_l+Q_d/B_d+E_copy，

T_map≈Q_remote/B_l+E_map。

E_copy 包含尚未计入字节项的准备、staging 和同步；E_map 包含映射准备、地址翻译及同步等成本。staging 若用实测总时间计入，就不再另加其中相同的访存工作。小访问还可能受启动和访问延迟限制，字节除带宽只是主项，不能保证饱和带宽。

假设对象只读，先完整复制 D 一次；随后 R 次都读取 xD，0<x≤1，R≥1；无本地事务放大即 β=1。则同一轨迹应写为：

T_copy≈D/B_l+R·x·D/B_d+E_copy，

T_map≈R·α·x·D/B_l+E_map。

完整复制不会让消费者每次自动读取整个 D。取 E_copy=E_map，令两式相等，得到：

x*=1/[R·(α−B_l/B_d)]。

只有分母为正时才存在正交点；此时 x>x* 才由该简化模型支持复制。若 x*>1，合法访问比例内没有复制更快的区域；x=x* 为平局。若 α≤B_l/B_d，在忽略额外成本的这些条件下，完整复制没有正的读取比例优势。R=0 或没有实际读取时直接返回空工作，不创建一次无用复制，也不代入阈值。

若额外成本差为 ΔE=E_copy−E_map，交点改为 [1+B_l·ΔE/D]/[R·(α−B_l/B_d)]，其分子、分母和 [0,1] 取值域要重新检查。局部复制、缓存改变、写后补复制、方向不同的链路带宽或 β≠1 都应回到 Q_c、Q_d、Q_remote 原式，不沿用这个交点。

设定 D=64 MiB，B_l=16 GiB/s，B_d=512 GiB/s，R=4，α=β=1。完整读取 x=1 时，复制约 4.3945 ms，映射约 15.625 ms。此时 x*=8/31≈0.258065；改为 x=0.27，复制约 4.0381 ms，映射约 4.2188 ms，应选复制。若误用 R·D/B_d，本地读取被多算，复制变成 4.3945 ms，路径选择会反转。所有数值都是设定算例。

这个读取交点不用于仅写输出。首次 OVERWRITE 没有旧内容搬入项，但仍有目标分配或映射准备、实际 store、完成与驻留成本。映射输出的远端写字节应另记为 Q_remote,write；只有明确链路方向及相应带宽后才能估时。把“无需旧内容”解释为零准备、零通信或零访存都会漏账。

### 迁移事件、页表和数据事务

以实际页迁移事件集合 E 为准，事件 e 搬动 s_e 字节。页 p 的迁移次数为 m_p，页大小为 g_p，则：

Q_mig=Σ_{e∈E}s_e=Σ_p m_p·g_p。

统一页大小 g 时，M=Σ_p m_p 是总页迁移事件数，Q_mig=M·g，不能再乘触及页数 N_p。只有明确把 M_batch 定义为同一完整页集合的整批迁移轮数时，才可写 M_batch·N_p·g；页集合变化或各页次数不同就不能这样简写。

迁移路径的读取主项可写为：

T_mig≈Q_mig/B_l+Q_d,mig/B_d+Q_remote,mig/B_l+F·T_f+T_hint+T_translation+T_sync。

Q_d,mig 是实际在设备本地服务的消费者读取字节；Q_remote,mig 是实际由远端服务的读取字节。二者来自访问事件，不能用触及页容量替代。F 是所选观测口径中的缺页或控制事件数，T_f 是排除已计数据搬运后的平均控制开销；缺页可以合批，F 不一定等于页数或迁移次数。T_hint 只计提示提交等尚未计入的工作；预取已经搬动的字节属于 Q_mig，不能再加一次完整预取搬运时间。不同方向或链路应分别求和。

对唯一被访问的字节并集 U_unique，页覆盖量为 Σ_{p被触及}g_p；两者之比描述页覆盖放大，不描述累计重复读取。只访问一字节也可能因真实迁移搬动整页。

映射读取则不能由“每页一个元素”推出每次传输整页。它的数据事务由目标链路、访问合并、缓存和真实远端流量决定。页大小用于页表、TLB 和确实发生的迁移；TLB 缺失、页表访问和远端数据读取分别记账。所供 CUDA 摘录要求 mapped memory 合并访问，没有给出映射读取必然传输整页的保证。

例如一个明确设定、无跨访问缓存的 32 B 事务模型，对 16 个相隔 64 KiB 的 4 B 读取可产生 512 B 数据事务，而非 1 MiB。这里的 32 B 是模型参数，不是对实际映射链路的规格声明；目标系统必须观测其事务。

较小页通常降低页内浪费与迁移放大，却增加页表和 TLB 压力；较大页可能降低翻译压力，却增加整页迁移与延迟尖峰。这个权衡不允许反推映射数据事务等于页大小。

### 共同资源、驻留与重叠

物理共享路径没有显式 H2D 项，但应按共同资源累计实际 CPU、GPU、DMA 和其他使用者的流量 Q_shared，以匹配带宽 B_s 估计资源项 Q_shared/B_s。它不能被替换成两个处理器孤立耗时的最大值，除非重叠与资源条件确实成立。

容量按物理身份和池分别计算：

C_j(t)=Σ_{p∈Live_j(t)}size(p)，M_peak,j=max_t C_j(t)，要求 M_peak,j≤K_j。

同一主机页被 CPU 和 GPU 映射只计一次容量；锁页状态本身不产生第二份数据。新的 staging、设备副本和迁移在途 backing 若确实独立，则分别计入其池。图池或 allocator reserved 已经包含活跃对象时，不再把其中 used 重复相加。虚拟地址预留不是物理容量。逻辑释放但仍有使用者的存储仍在 Live 中。

共享恢复任务按实际启动的任务计 Q_c，不能按订阅消费者数重复收费。两个 READ 共用一次 B 字节恢复时，复制量为 B，累计有用读取仍是 2B；它们可能分别需要在两个执行队列上建立完成依赖。共享完成票据不等于只存在一个消费者或只需保护一个最后使用点。

若有 n 个恢复任务、u 个消费者订阅及 p 条未结束物理范围责任，直接扫描的准入实现每次检查至多比较 p 条责任，元数据规模随 n+u+p 及版本区间碎片增长。区间索引可减少查找，但不能省略重叠集合。保守地等待真实完成后再准入，会增加完成通知处理和串行等待；源、staging 与目标在等待和消费期间仍须保活。共享 pending 可以减少重复传输，却可能让多个消费者共同等待一个较慢任务，应与拆分范围或独立目标的额外容量比较。

对 w 个可重试 WAIT 任务，一轮重试扫描至多尝试 w 次物理准入，还要核对各任务冻结版本区间、地址和保活；不能只按启动成功的任务数计准备成本。若每项实际范围数有界，直接扫描的冲突部分为 O(w·p)。没有状态变化时不反复忙扫，等待真实完成、地址准备生效或其他已登记的解除条件；这减少空转，不取消后续事件到来时再次扫描的义务。

计算通常保持同一函数，但路径可能改变 CPU 放置、转换和资源竞争；访存按各存储边界计；通信按复制、远端事务和迁移计；准备包括注册、映射、首次触碰、描述符和捕获；同步包括准备生效、生产可见性、物理冲突准入、最后使用与关闭；驻留包括副本、锁定页、保留池和在途页。并发工作沿依赖图求关键路径，并核对每个共享资源的累计需求；不能把所有资源理想时间机械相加，也不能任意减掉串行传输。

## 按阶段推进路径与内容状态

下面选择单一状态拥有者和保守的全对象逻辑读写互斥：READ 可以并行；OVERWRITE、UPDATE 与任何活动逻辑访问互斥。范围版本用于精确失效和补复制。这会串行化某些不重叠写入，是简化协议的选择。逻辑 READ 并行不授权它们准备阶段的内部目标写并行；实际移动和消费还必须通过独立物理冲突准入。

每份物理表示保存 valid[range]=(epoch,ν快照,ready_ticket)。valid 仅表示该范围的相应内容已经完成；pending 复制和迁移不能冒充 valid。地址准备独立保存 addr 及 prepare_ticket，不以 valid 代替。输入依赖图必须为冲突逻辑访问指定顺序，明确读取哪一次生产结果；phase 序号本身不等于硬件屏障。以下基线在阶段之间排空，阶段内部按依赖推进。

物理责任记为 q=(opid,pid,epoch,[l,h),R或W,queue,last_ticket)。这里的 pid 是真实 backing 身份；虚拟别名和不同 tensor 视图先归一到该身份及实际偏移。两条责任在同一 backing、epoch 上范围相交且至少一方为 W，就发生冲突。复制同时具有源 R 和目标 W；UPDATE 的冲突资格按 W 处理，同时仍要求旧内容。判断依据是全部实际访问范围，包括完整复制策略扩大的范围、staging 和已知辅助访问，不能只使用父访问的逻辑切片。

本章采用完成后准入：一个实际操作只有在全部冲突的已提交物理责任结束后才启动。检查并登记操作的全部源、目标和辅助范围是同一状态事务，不能逐个取得后等待另一个范围。逻辑预约保留从准备到最后消费的内容与生存期责任，但尚未提交的未来消费者不进入物理 R 账；因此恢复不会等待自己的未来父访问。

恢复任务保存 key=(目标pid,epoch,实际目标范围,冻结ν快照)、合法源、全部实际访问范围、地址责任、状态、完成票据及订阅者集合。状态为 WAIT、ACTIVE、DONE 或 QUARANTINED。相同 key 的未完成任务可共享；仅数值相同、版本不同或 backing 不同不能合并。部分重叠而非相同的任务采用保守策略：后来的恢复等待已有任务完成，再重算缺失范围；不扩大已经提交的任务。

WAIT 是已经建立、尚未取得物理启动资格的同一任务。状态拥有者负责在处理完成事件后重试它；重新进入父访问的 RESTORE_RANGE 只复用其身份和票据，不能成为唯一的重试来源。每次重试从物理准入步骤继续，不重新授权 parent，不分配新 uid/opid，不更换冻结版本或订阅集合。下面将这个入口明确为 RETRY_WAIT_RESTORES。

```pseudocode
算法 PLAN_AND_EXECUTE_PATH
输入：O、访问集合 A、依赖 DAG G、目标能力 C、各池预算 K、页布局
输出：完成的读取/写入、准备/移动/消费责任及字节与驻留账；或拒绝、等待、隔离原因

校验 D、范围、处理器、模式、依赖和实际访问能力
忽略空范围；若没有访问，返回 NO_ACCESS，不准备地址、不复制、不迁移、不增加版本或 epoch
若 G 有环，或冲突逻辑访问没有可确定的生产顺序，返回 REJECT_DEPENDENCY
按实际页布局计算页集；边界页的完整 backing 和别名保护另行记录
筛选复制、映射、可迁移和物理共享候选
为每个候选在同一 A/G 上生成准备、数据移动账与逐池驻留时间线
删除能力或容量不合法者；按条件化成本选择路径

初始化：
    phase=OPEN，admission=true，active_readers=空，writer=空
    保留现有初始化范围、ν、各表示 valid 和逻辑/图拥有者
    逐项记录现有 addr；没有证据的分配、映射或权限取 NOT_READY
    新目的 valid 为空；恢复任务表 pending=空；物理责任表 physical=空
    本 epoch 已用 uid 集合为空；访问状态初始为 UNAUTHORIZED

按 phase 从小到大：
    等待前一阶段已授权访问、地址准备和内部移动结束
    while 本阶段仍有未完成访问或其内部责任：
        progress=false
        处理到达的完成通知，执行 COMPLETE；记录实际状态变化
        调用 RETRY_WAIT_RESTORES；其成功启动也计入 progress

        对依赖已经完成且尚未授权的访问 a：
            要求 admission、OPEN、epoch 匹配，且 uid 本代未用过
            READ 要求 writer 为空
            OVERWRITE/UPDATE 要求 writer 为空且 active_readers 为空
            冲突未排空则等待；不以队列调用返回冒充结束
            READ/UPDATE 要求所读范围已经初始化
            原子登记 a 的逻辑预约、所需内容快照及底层存储保活责任
            READ 加入 active_readers；写访问登记 writer=a；登记 uid 已使用
            a.state=PREPARING；记录 progress

        对已经预约且尚未提交的访问 a，继续其保存的推进位置，不重新授权 uid：
            对每种模式都先准备地址，不以是否需要旧内容为条件：
                显式复制路径：
                    为实际目标表示取得 backing、地址、权限和分配生效票据
                    范围覆盖已选分配方案和全部实际内部移动范围
                映射路径：
                    取得主机 backing；按目标要求锁页或注册实际映射范围
                    建立或复用本设备合法别名，核对 pid、epoch、范围和所需权限
                    READ 需要读权限；OVERWRITE 需要写权限；UPDATE 需要读写权限
                可迁移路径：
                    建立或校验受支持的系统分配/Managed 分配与访问契约
                    校验范围、权限、设备及并发限制；允许平台契约内首次触碰供页
                    不把提前本地驻留或旧字节初始化当作地址准备的必要步骤
                物理共享路径：
                    取得或复用共同 backing 和本处理器可用地址、权限与分配票据
                准备未生效时保存推进位置并等待，不能提交实际访问
                建立准备生效到实际访问队列的依赖
                从准备开始保留 backing、注册和映射，直到全部实际使用结束
                准备失败则不提交 a，按已发生责任执行失败清理

            a.state=RESTORING
            若 a 需要旧内容：
                显式复制路径：
                    调用 RESTORE_RANGE，首次可按已选策略完整复制 D
                    其后按所需 ν 恢复缺失范围；WAIT 时保留预约并继续处理其他工作
                映射路径：
                    若最新内容仅在设备独立副本，用 RESTORE_RANGE 恢复所需主机范围
                    恢复也必须检查真实源读、目标写和全部相关消费者
                可迁移路径：
                    可按策略为将被读取的页提交旧内容预取提示
                    由受支持运行时承担页迁移或远端访问契约
                    记录实际页移动及远端服务，不从指针或提示猜测本地驻留
                物理共享路径：
                    使用共同 backing 中的相应内容，不制造链路副本
                建立所需最后生产到实际消费队列的可见性依赖

            OVERWRITE 不恢复被完整覆盖范围的旧内容，但保留地址准备和冲突顺序
            对页粒度机制，仍按平台契约保护覆盖范围之外的字节及别名
            提交前在同一状态事务中统一校验：
                addr 与本 pid/epoch/processor/range/mode 匹配，准备生效已被排序
                backing、注册和映射的保活责任覆盖本次最后访问
                READ/UPDATE 的全部所需版本已经 valid，生产可见性完整
                所有可能写本次实际范围的 WAIT/ACTIVE 恢复任务均已结束
                    检查不限于 a 创建或订阅的任务
                解析本操作的实际物理 R/W 范围并调用 PHYSICAL_ADMIT
            任一项未满足则等待，不启动消费者
            准入成功后提交实际访问，记录覆盖其最后访问的票据；a.state=SUBMITTED
            记录 progress；返回描述符前完成责任登记，不暴露未登记的裸指针使用

        再调用 RETRY_WAIT_RESTORES，覆盖本轮新建及仍可重试的 WAIT
        记录准备、恢复及提交的实际状态变化；重复订阅或失败重试不算 progress
        若有 progress：继续下一轮，已登记的 uid/opid 不重新授权
        若仍有能解除等待的在途工作或已登记外部准备条件：等待对应事件再进入循环
        否则才返回 REJECT_OR_REPAIR_DEPENDENCY，并报告仍阻塞的任务与条件

PHYSICAL_ADMIT(op,全部实际访问范围)：
    将别名归一到真实 backing pid/epoch/偏移，合并本操作的重复范围
    只与此前已经提交但未证明结束的 physical 责任比较
    若同 backing/epoch 的交叠范围至少一方为 W：返回 WAIT
    在同一事务中登记 op 的全部物理责任；然后才能交给执行器
    不把父逻辑预约或未来消费者当作已提交物理读者
    部分提交结果不明时保留已登记责任并隔离，不直接撤账

RESTORE_RANGE(parent,target,所需范围及ν快照)：
    重新检查已完成 valid；已经满足则返回 READY
    按选定策略形成实际复制区间；扩大范围时也冻结其完整源版本并检查初始化
    对每个实际区间：
        若存在相同 key 的 WAIT/ACTIVE 任务：
            将 parent 加入订阅者，保存同一完成票据，不重复提交
            WAIT 的续执行由 RETRY_WAIT_RESTORES 承担，ACTIVE 只等真实完成
        否则若与已有未完成目标任务部分交叠：
            返回 WAIT；该任务完成后重新计算 valid 与剩余缺失范围
        否则：
            找到保存所需 ν 的合法源；补齐源、目标及 staging 的地址资格与保活
            分配一次 opid 和完成票据，建立 WAIT 任务并原子发布到 pending
            保存完整源、目标、staging 实际范围与冻结ν，不发布目标 valid
            调用 TRY_START_RESTORE；冲突时保留这个 WAIT 任务
    所有必要任务成功完成且目标版本匹配时才返回 READY
    同 backing 同位置的合法现有内容直接复用；需要移动的重叠别名复制另证算法或拒绝

RETRY_WAIT_RESTORES，由同一状态拥有者执行：
    对入口时已有 WAIT 任务按建立顺序取有限快照
    对快照中的每个任务至多调用一次 TRY_START_RESTORE
    ACTIVE、DONE 和 QUARANTINED 不取得新的启动资格
    统计真正的 WAIT→ACTIVE 转换，返回是否产生进展
    本轮创建的新 WAIT 由创建时尝试及主循环末尾扫描覆盖

TRY_START_RESTORE(task)，核对、准入和状态转换属于同一不可交错事务：
    若 task.state 不为 WAIT：返回 NO_NEW_SUBMISSION
    重新核对原 pid/epoch/opid、key、完整实际访问范围及原冻结ν
    要求源仍保存该冻结版本，原逻辑预约仍保护内容，源/目标/staging 保活仍在
    身份、冻结版本或保活证据失配：进入 QUARANTINED，通知原订阅者，不改成新任务
    地址准备尚未生效或资格尚未齐备：保留 WAIT，登记其准备解除条件
    核对每个实际源 R、目标 W、staging 访问的地址、范围、权限和准备生效关系
    调用 PHYSICAL_ADMIT(task,保存的全部实际访问范围)
    冲突仍在：保留同一 WAIT、parent、opid、票据和订阅集合，返回 WAIT
    准入成功：原子把 task 改为 ACTIVE，并消费本 opid 唯一的一次启动资格
    在保存的执行队列上提交一次复制，沿用原完成票据
    提交接受状态不明或完成记录失败：保留物理责任并隔离，不能退回 WAIT 再提交

COMPLETE(ticket)，全部账务更新由同一状态拥有者不可交错地执行：
    要求 ticket 的 pid、epoch、uid/opid、范围和操作身份与登记责任匹配
    旧 epoch、未知或重复通知不改变当前对象；旧责任只在原对象账中幂等结算
    证据不足或失败且无法证明访问结束：保留责任，进入 QUARANTINED
    地址准备成功：
        只发布相应 addr 资格及生效票据；不发布 valid，不增加 v
        不解除父访问的地址保活责任
    内部复制成功：
        校验冻结 ν，发布完成覆盖的目标 valid
        同一事务内结束源 R、目标 W 和相应 staging 责任，任务进入 DONE
        唤醒全部订阅者及因交叠等待的恢复；不增加逻辑内容版本 v
    内部页迁移成功：
        按真实运行时契约更新观测/模型驻留和在途容量；不增加内容 v
        无法观测的驻留保持 UNKNOWN，不虚构本地位置
    READ 成功：
        同一事务内清除本操作物理 R 责任和匹配 active_reader；不增加 v
    OVERWRITE/UPDATE 成功且可见性证据完整：
        在同一不可交错事务内完成：
            v 加一，将写入范围 ν 设为 v，发布写入表示的 valid
            使其他独立副本的重叠范围失效，未写范围保持有效
            清除本操作物理责任和匹配 writer
        事务结束后后继访问才能重新准入
    对应全部实际使用结束后，才解除本次地址保活责任并令 a.state=DONE
    返回主循环；释放责任之后实际执行 RETRY_WAIT_RESTORES，再推进等待消费者

关闭、取消与复用：
    取消先令 admission=false；停止授权新访问，不撤销已提交责任
    一个订阅者取消不删除其他消费者仍依赖的共享恢复任务
    保守地排空已有读写、地址准备和已建立的恢复任务；排空循环仍执行 WAIT 重试
    未知完成继续隔离；不以取消制造完成或清空 pending
    CLOSE 成功要求没有活动逻辑访问、pending、物理责任或未来图访问权
    有活动使用时 CLOSE 返回 BLOCKED，继续排空
    关闭并解除全部拥有者后才撤销注册/映射、RETIRE 并释放物理预留
    槽交给新对象时递增 epoch，清空地址及内容资格，重新初始化
```

逻辑预约覆盖准备到最后消费，防止“复制刚完成、消费者尚未登记时 CPU 已改写”的空隙。物理责任则约束真正提交的访问：两个逻辑 READ 可以共享源快照，却不能无序写入同一恢复目标。共享 pending 的查询、任务发布、消费者检查、WAIT 重试与物理准入必须由同一状态拥有者串行处理，否则两个线程仍可能同时看到“没有 pending”并提交重复复制。

消费者检查全部相关 pending 后立即登记物理责任，因此没有“检查时无写者、登记前新复制已进入”的空隙。后来建立的恢复任务可以等待已提交消费者结束；已经提交的消费者不再反过来等待这个后来任务。准备阶段的父预约没有物理完成票据，不能被放入恢复的等待集合。涉及多个对象时，也要先收集全部旧责任，再原子准入整个操作，避免部分取得范围后互等。

WAIT 重试解决的是已有任务在条件解除后的推进。对有限的已建立任务，一轮扫描不会因某项仍冲突而跳过其余项；重试成功后该项退出 WAIT，因此重复调用不会重复提交。它不保证任意持续到达负载下的无饥饿，也不能代替不完整源版本、失去保活或无法取得最后使用证据时的诊断。所有可解除条件已满足、没有其他在途工作却仍留有可准入 WAIT，应视为推进协议错误，不能解释成正常硬件等待。

上述软件准入用于应用管理的实际复制与物理访问，不要求应用拦截运行时内部的每次 UVM 页操作。合法 UVM 运行时可以按其契约在预取期间继续服务访问；应用需要遵守支持级别和读写同步，不能把本章的软件锁误作 CUDA 禁止预取期间访问的规定。

地址准备和内容恢复也可以预先完成，但入口必须验证等价的前置条件：映射属于本设备和本代，覆盖实际访问，权限合适，准备已生效，且仍有负责保活的拥有者。不能把“候选筛选通过”当作这个初始化证明。异步准备可以用队列依赖保证其先于访问，不要求每次都阻塞主机；本章物理冲突模型采用完成后才准入的保守策略。

准备失败且尚未提交访问时，先排空已发生的准备操作，再撤销本次预约及独占预留；只解除本次取得的责任，不破坏仍被其他拥有者使用的映射或共享恢复。访问已提交却缺少最后使用证据时，不得按准备失败路径直接释放。

异步提交与读写前沿的具体 stream/event 编排可采用 [K-FW-003 的完整协议](../frameworks/streams-allocator.md)，容量和拥有者关闭关系见 [K-SYS-012](../system-semantics/memory-allocators.md)。本章额外承担的是地址准备、副本范围失效、共享恢复与物理范围冲突、WAIT 续执行、映射资格和实际驻留转换。抽象票据不是某个硬件 API 已经满足可见性的证明。

写入失败可能留下部分物理修改，因此不能继续发布原 valid。应使受影响范围失去读取资格并隔离，或从有完整证据的未修改副本恢复；不能仅靠回退 v 宣称字节已恢复。取消后已提交写入仍可能完成，本章停止后继业务使用并排空，不提供数据回滚保证。

## 组合轨迹：改写、失效与再次消费

先检查首次只写的边界。设 O 有 8 B，主机 backing 已分配但内容未初始化，v=0；设备尚无注册、映射和地址资格。GPU 要 OVERWRITE [0,4)，写入四个已给定字节。状态推进为：登记写预约与 backing 保活 → 注册所需范围 → 建立具有写权限的设备别名 → 确认准备生效 → 提交 store → 确认最后访问与可见性 → 发布 v=1、ν[0,4)=1。旧内容恢复量为零，映射准备量并非零。其余 [4,8) 仍未初始化，不能随后读取全对象。

准备尚未完成时，提交被地址资格拒绝；只读映射、少覆盖一个字节、错误 backing 或失效代次也不能授权这次写。若删除准备步骤，条件“需要旧内容”为假，直接来到提交点，地址资格仍然失败。这个反例不依赖读取旧值或比较输出，因此不会被预先创建 H、D 数组的副本模型掩盖。store 在途时也不能撤销映射或释放 backing。

再考虑包含数据恢复的轨迹。设对象为页对齐的 64 MiB，g=64 KiB，B_l=16 GiB/s，B_d=512 GiB/s。CPU 初始化全对象；GPU 读前 1 MiB；CPU 改写同一 1 MiB；GPU 再读该范围。依赖为 CPU 写结束→首次 GPU 读结束→CPU 改写结束→第二次 GPU 读。数值是设定量。

CPU 初始化完成后 v=1，全部 ν=1。显式复制候选选择首次完整复制：取得设备 backing 和合法地址后，主机 H+b 的字节搬到设备 L+b，复制结束才发布设备全范围 valid。首次 GPU 读取 1 MiB，读取结束不改变 v。CPU 改写完成后 v=2，仅前 1 MiB 的 ν 变为 2，设备对应 valid 失效；其余 63 MiB 仍可保留标签 1。第二次 GPU 读发现缺失，必须提交 H+[0,1 MiB) 到 L+[0,1 MiB) 的补复制，完成后消费标签 2。可复用的设备地址资格不因这次内容失效而自动消失。

因此 Q_c=65 MiB，Q_d=2 MiB，读取与复制主项约 3.9711 ms。若另一候选首次只复制所需 1 MiB，则两次合计 Q_c=2 MiB；它属于不同复制计划，必须重新比较，不能把“显式复制”固定为全对象策略。

映射候选建立设备别名 M+b，由页表指向主机 backing。GPU 两次各读取 1 MiB，在 α=1 的设定下远端数据共 2 MiB，链路项约 0.1221 ms，另加注册、翻译和同步。CPU 改写要等首次读结束，第二次消费依赖新写入可见。

以 4 B 连续元素说明请求地址：CUDA 的一个 32 线程 warp 在逻辑起点 i=32w 时，lane l 读取偏移 b=4(32w+l)。这产生连续的 128 B 请求覆盖，但不能由这个覆盖直接宣称映射链路执行一笔 128 B 事务。实际合并、缓存和链路事务还需目标证据。改成每页一个元素，会改变合并和翻译局部性，不自动把一次读取变成整页传输。

迁移候选若确实采用如下串行页路径：首次 GPU 读将页 0…15 从主机迁到设备；CPU 改写前将它们迁回主机；第二次 GPU 读再迁到设备。每页 m_p=3，合计 M=48 个页事件，Q_mig=48×64 KiB=3 MiB。GPU 的本地读取仍只有 2 MiB，数据主项约 0.1869 ms。缺页/控制次数按实际合批记录，不能由“三个方向阶段”断言只有三次缺页。若页 0 迁三次、页 1 一次、页 2 两次，迁移量为 6g，不能用一个统一轮数覆盖这三个页。

这些迁移是指定策略的模型轨迹。真实系统可能远端访问或保留其他合法表示；发生这种情况就更新事件账，而非强套 3 MiB。页迁移还可能携带对象之外的边界页字节，页内无关对象与别名的保护由运行时及实际分配布局决定。即使应用完整覆盖自身声明范围，运行时也可能需要保存同页中范围之外的字节。

物理共享候选没有上述链路搬动，GPU 增量读取为 2 MiB。若其对应并发条件的 B_s=200 GiB/s，GPU 读取资源项约 0.0098 ms；CPU 初始化、改写和其他共同流量仍须计入完整路径。这不是总服务时间。

容量账也不同：完整显式复制需要独立的 64 MiB 设备表示；独立 staging 若同时存活还要加到主机账。映射和物理共享可让两种引用指向同一 backing，容量只算一次；实际迁移若源和目的 backing 在过渡期同时存在，分别计入相应池。版本变化不会自行释放旧读者所保护的存储。

### 两个并行 READ 共享恢复

把访问缩小到 4 B，以便完整列出物理状态。H 保存内容 (17,20,23,26)，ν=(1,1,2,2)；D 地址已准备好，但四字节均无 valid。同一 phase 的 r1、r2 分别在 GPU 队列 q1、q2 读取 D+[0,4)，二者都获得逻辑 READ 预约，逻辑 writer 始终为空。

| 步骤 | pending 与物理责任 | 有效性及可推进操作 |
|---|---|---|
| r1 准备恢复 | 创建 C0：H[0,2) R、D[0,2) W；C1：H[2,4) R、D[2,4) W | 两段仍是 pending，尚无消费者物理 R |
| r2 准备恢复 | 相同目标、epoch、范围和 ν，订阅 C0、C1 | 不再创建第二组目标写 |
| 启动复制 | C0 在 copy0，C1 在 copy1；两目标范围不相交 | 两复制可以同时在途，父逻辑预约不阻塞它们 |
| 后提交的 C1 先完成 | 清 C1 的源 R、目标 W；仅发布 D[2,4) valid | C0 仍可能写前半，两个全范围 READ 都不能启动 |
| C0 完成 | 发布前半 valid，清 C0 责任；正常循环重试 WAIT 并推进消费者 | 全范围版本匹配，相关 pending 写均结束 |
| 消费者启动 | 在 q1、q2 分别登记 D[0,4) 物理 R | R/R 相容，两个消费者可以并行；新目标 W 必须等待二者 |
| r2 先结束、r1 后结束 | 分别清各自物理 R 和逻辑预约 | 只有 r1 也结束后，覆盖与关闭才完全解除这组读取责任 |

这条轨迹的实际恢复量为 4 B，累计消费者读取为 8 B；交换复制或消费者的完成顺序不改变版本和准入条件。只共享 pending 而未把实际消费者登记为物理 R，仍不能保护后来新建的恢复写。

删除保护后，r1、r2 可以分别提交覆盖 D[0,4) 的复制 A、B。两者同时在途已构成 WAW。若后提交的 B 先完成，r2 只等自己的 B 就启动读取，而 A 仍在写 D，便又出现复制目标 W 与消费者 R 的冲突。两份复制写入完全相同的 ν 和数值，串行数值模型可能仍返回正确结果；独立物理访问不变量必须拒绝这条轨迹。

范围不完全相同时，设 a 读 [0,3)，b 读 [1,4)。a 的恢复 [0,3) 在途时，b 不另提交交叠复制。它结束后，b 重算仅缺 [3,4)；这段复制可以与 a 对 [0,3) 的物理读取并行，因为半开范围不相交。若策略却选择复制整个 [0,4)，它就必须等待 a 的物理读取结束。父访问 b 只需要 [1,4)，不能作为省略目标实际写范围检查的理由。

放大复制还需要完整的等待与恢复轨迹：old 已经在读取有效的 D[0,2)，new 需要失效的 [2,4)，策略却选择恢复整个 [0,4)。建立任务 move 后，第一次物理准入因 old 的 R 被拒绝，move 保持 WAIT。此时 new 只有逻辑预约，没有物理 R，不能阻塞自己的恢复。

| 真实事件与正常推进 | move 与责任变化 | new 的资格 |
|---|---|---|
| 创建扩大恢复并尝试启动 | 同一 move 为 WAIT；未登记其源 R 或目标 W | 目标 [2,4) 仍无 valid，不能消费 |
| old 的最后读取完成事件到达 | COMPLETE 原子清 old 的物理 R 和逻辑预约 | 仍等待 move，不能把 old 完成当成数据恢复完成 |
| 同轮调用 RETRY_WAIT_RESTORES | 重新核对原冻结ν、地址、保活和全部实际范围；同一 move 准入成功并进入 ACTIVE，只提交一次 | 继续等待 move 的真实完成 |
| move 的复制完成事件到达 | 发布 D[0,4) valid，清源 R 和目标 W，move 进入 DONE | 正常循环核对全部相关移动、版本和物理冲突，自动提交 new |
| new 的最后读取完成 | 清 new 的物理 R 和逻辑预约 | 该有限轨迹排空，值和 ν 与独立逻辑参考一致 |

重复进入 RESTORE_RANGE 或重复调用正常推进都不创建替代 move，也不重复提交 ACTIVE/DONE。一个订阅者取消同样不能使其他订阅者所需的复制或读取责任提前消失。

若删除已有 WAIT 的重试扫描，old 完成后既没有在途物理工作，也没有能自行产生 move 完成的执行。new 等 move，move 却没有启动入口，形成可判定的停滞。检查只能提交真实完成事件并调用正常推进；观察器不能手工启动 move、为 WAIT 制造复制完成，或清空 pending 来伪造排空。源端已有物理 W 阻塞恢复源 R 时也沿同一重试入口推进，但源版本若已改变，必须隔离旧快照任务，不能直接复制新版本冒充原结果。

## 条件变化后的选择

| 条件变化 | 必须保留的关系 | 调整或放弃信号 |
|---|---|---|
| GPU 重复读取增加 | 同一有用读取轨迹与版本资格 | 容量允许且本地复用降低总成本时保留副本；重算 x、R 和补复制量 |
| 并行 READ 共同缺失同一目标版本 | 共享恢复完成、实际物理冲突、WAIT 续执行和全部最后读者 | 合并相同 pending；部分交叠重算剩余范围；共享等待过长时比较拆分或独立目标容量 |
| 小比例或稀疏读取 | 真实范围、事务与页事件分账 | 比较局部复制、映射和迁移；事务、翻译或准备主导时改变布局或路径 |
| 首次访问改为只写输出 | 地址准备、写权限和最后使用保护 | 可去掉被完整覆盖范围的旧内容恢复；仍计准备和实际写流量 |
| CPU/GPU 交替改写 | 写后失效、生产可见性和最后读者 | 来回迁移随交替增长时比较批量交接、双缓冲或计算放置 |
| 页大小改变 | 数据事务和地址翻译仍分别记录 | 重算页覆盖、迁移尖峰与 TLB；不能按页大小直接缩放映射数据流量 |
| 容量紧张 | 逐池预算、物理身份去重和排空 | 缩小副本、锁页或在途范围；不能提前回收活动存储 |
| 映射或原子能力不足 | 正确访问与同步语义 | 降级为复制或串行分区；无法满足语义时拒绝 |
| 图共享池 | 不并发、地址保活和输出保护 | 按捕获顺序重放，或证明图间无输出依赖；需要并发时改独立池 |
| 物理共享负载上升 | 共同容量与依赖 | 总流量接近共同带宽时减少并发、改变计算放置或布局 |
| 支持级别或平台变化 | 内容身份和最后使用保护 | 重新核对系统分配、并发、映射及完成接口，不能沿用旧设备资格 |

固定 PyTorch 文档对适合放入 GPU 内存的深度学习负载建议显式放置，并指出内存饱和时 UVM 的逐出加换入可能形成昂贵双传输。这是该来源的负载与版本结论，不排除一次性小范围映射或其他平台的共同物理池。

## 竞争解释与区分实验

先固定输入、范围、内容版本、计时终点和并发，再改变能区分解释的条件。主机提交变快不证明消费者完成变快。

| 观察 | 竞争解释 | 干预、预测及反证修正 |
|---|---|---|
| old 已结束而恢复仍不启动 | 完成未清物理账、WAIT 重试遗漏、地址准备未生效或源版本失配 | 只提供 old 的真实完成与正常推进，分别检查原物理 R 是否清除、同一 move 是否被重试及其资格；账已清且资格完整仍 WAIT 支持重试遗漏，资格失配则按原原因等待或隔离 |
| 两个逻辑 READ 仍报告竞态，结果却常正确 | 重复恢复的目标 WAW、恢复与消费 RAW/WAR，或最终算子自身越界 | 固定相同内容和 ν，延迟并反转两个复制的完成顺序；独立记录真实物理范围的开始/结束；共享恢复或保守排序消除交叠才支持恢复解释，数值相同不能反证竞态 |
| 首次只写失败，先读后写却正常 | 只读分支建立映射、权限不足或分配尚未生效 | 从无映射状态分别提交 READ、UPDATE、OVERWRITE，记录注册、映射、准备完成和提交；只写缺准备时先修控制流；准备完整仍失败再查实际权限与范围 |
| 映射没有显式复制却慢 | 远端数据事务、TLB、同步或访问延迟 | 固定有用字节分别改变连续性与页布局，分别记录数据链路字节和翻译事件；只有翻译变化时不归因于整页数据传输 |
| 改页大小后变快 | TLB 改善、迁移减少或容量变化 | 保持请求地址和计算不变，核对页迁移事件及数据事务；事务不变而翻译下降支持 TLB 解释 |
| 复制与映射选择不符阈值 | 工作量不一致、额外准备、缓存或带宽口径错误 | 从同一读取枚举重建 Q_c、Q_d、Q_remote；x=0.27 案例若仍以 R·D 计本地读取，先修账 |
| UVM 周期性尖峰 | 缺页、回迁、预取挤出或共享带宽 | 记录逐页方向与时间，改变 CPU/GPU 交替次数和预取提前量；只有控制事件变化时不要把全部差异解释为搬运字节 |
| CPU 改写后 GPU 读旧值 | 旧副本未失效、补复制遗漏或生产依赖缺失 | 以不同内容改写小范围，保留全部对象，检查第二次复制和 ready 记录位置；保活无效而补复制修复支持副本解释 |
| 偶发读写冲突 | 读入未检查活动写者，或写入未检查读者 | 分别执行写→读、读→写的未完成轨迹，两种方向都必须阻塞；还需把内部复制加入物理账，逻辑 writer 为空不足以关闭问题 |
| 复用后新读者突然消失 | 旧完成按同名 uid 清账 | 旧读者结束并复用槽，登记同名新读者，再注入旧 epoch 完成；新责任必须保持，关闭仍应阻塞 |
| 图输出变化或重放非法 | 地址释放、共享池覆盖、并发或依赖错误 | 保留地址、对照独立池、禁止并发并复制需保留输出；独立图改变顺序仍合法时不能继续归因于捕获顺序 |
| 物理共享尾延迟上升 | 共同带宽、缓存或容量压力 | 分别增加 CPU 带宽负载和物理容量压力；只有容量逼近才出现尖峰时，转查驱逐与驻留 |

正确性检查应把错误变体送入同一参考或状态不变量。需要能够实际检出：首次 OVERWRITE 跳过地址准备；准备提交即冒充生效；权限或范围不足；把完整复制误作每次完整读取；把总迁移事件再乘页数；把映射事务等同于页；写后读和读后写冲突；活动读者尚在却关闭；旧 epoch 完成清除新代同名使用者；CPU 改写后缺失补复制；复制提交即发布有效范围；并行逻辑 READ 的内部目标写交叠；消费者漏等其他父访问的目标写；把未来父预约误作已提交读者造成恢复自依赖；冲突解除后遗漏已有 WAIT 的重试。

## 配套检查与证据范围

配套文件为 tools/check_k_hw_013_full.py，是标准库、确定性、离线、只读的 CPU 模型。它不读取项目或上游实现，不访问网络或凭证，不启动子进程，不写文件。

页计数以逐字节枚举对照算术页集。成本检查从同一缩小字节访问轨迹分别枚举复制、本地读取和远端有用读取，使用 Fraction 计算阈值，并检出旧复制公式。迁移检查将逐事件搬运对照各页次数汇总，覆盖 16 页各三次、不等次数与单字节触发页搬运。映射事务检查采用明确设定的事务粒度，检出把数据事务强制替换为页覆盖量的变体。

副本模型对照不含副本的单份逻辑内容参考，执行写入、失效、补复制、反向恢复和读取；另检查复制完成前不能发布目标有效范围。所有权候选用读者集合和写者字段；参考用访问历史、完整使用身份与对称冲突表。每个事件比较决定和活动责任，覆盖带读者关闭、两个方向的读写冲突，以及旧完成与同名新读者碰撞。

地址准备模型从无设备映射开始。候选生成准备与访问事件；独立检查器逐字节重建注册集合、设备地址到 backing 的关系、权限、准备完成和保活责任。首次 OVERWRITE 不生成旧内容恢复事件，但必须先形成合法写地址。删除准备步骤、遗漏准备完成、只给读权限、少映射一个字节的变体，都在同一提交地址不变量上失败；在途撤映射和解除保活则在相同事件检查器的生存期不变量上失败。空范围不准备、不提交；映射复用后改变访问权限也有单独轨迹。

并行恢复模型把逻辑父预约、WAIT/ACTIVE 恢复和实际物理访问分开。候选用区间检查准入；独立参考把开始事件展开为 (backing身份,epoch,字节) 的 R/W 集合，直接拒绝全部未结束访问之间的一方写冲突，不读取逻辑 writer 字段。两个共享失效设备范围的 READ 在不同队列上消费，覆盖两种请求顺序、两种分段复制完成顺序和两种消费者完成顺序；正常路径经公开推进入口启动已有恢复、接收完成并自动授权消费者，对照单份内容与范围版本参考，检查实际排空。

放大复制回归先建立 old 的物理读与 move 的 WAIT，再仅提供 old 的真实完成事件并调用正常推进。它要求同一个 move 自动进入 ACTIVE，物理 begin 恰好一次，原 parent、任务 key 和订阅关系保持；复制真实完成后 new 自动取得读取资格，最终值与 ν 对照独立参考。禁止已有 WAIT 重试的错误变体沿同一入口运行，在没有其他在途工作时留下 WAIT 与未完成消费者，被进度判据检出；观察器不手动调用 start_copy、不制造 WAIT 的完成、不清空任务。源端物理 W 结束后的恢复源 R 使用同一入口，另核对准备未生效时继续等待、冻结版本或保活失配时隔离。

同一物理审计器继续检查部分交叠恢复后的重算、半开边界、放大复制等待已有读者，以及消费者等待其他父访问建立的任务。错误变体实际启动重复复制或复制/消费交叠后再进入审计；即使同值同版本也被拒绝。恢复等待自己未来消费者的错误由进度不变量检出。模型的源端 W 探针只验证物理准入与 WAIT 重试，不冒充完整逻辑写入调度。

这些模型没有实现完整 phase/DAG 调度器，也没有穷尽异步交错、部分提交失败、任务取消或任意多设备别名。抽象开始/结束和完成证书由模型提供，不证明真实 API 作用域。它们不证明目标 GPU 的映射资格、真实事务粒度、TLB、页迁移策略、硬件可见性、allocator、CUDA Graph 重放、物理重叠或性能，也不证明 Agent 使用效果。设备实验仍需记录固定版本、能力、实际地址与范围、准备生效点、数据/迁移/翻译事件、最后访问、并发、计时边界和不确定性。

## 来源与推导

- [S-MLX-MEM：MLX：Unified Memory](../sources/S-MLX-MEM.md)：固定文档说明 Apple Silicon 的 CPU/GPU 直接访问共同内存池，MLX 数组创建时不指定位置，设备在操作执行时选择；框架为受跟踪的跨设备数组依赖建立顺序。文档的 M1 Max 算例报告特定 matmul 与小数组 exp 分工约 1.4 ms、全 GPU 约 2.8 ms，本章不把该倍率外推为通用服务收益。共同资源账和外部访问边界是据此展开的推导。
  [完整原文](../../references/S-MLX-MEM/reader.html) · [全文文本](../../references/S-MLX-MEM/fulltext.txt)

- [S-CUDA-ASYNC：CUDA Programming Guide — Asynchronous Execution](../sources/S-CUDA-ASYNC.md)：固定 CUDA 12.8.0 的所供摘录支持 stream/event 完成关系、page-locked、write-combining 与 mapped memory 条件，以及映射访问的同步和原子限制。§3.2.6.3 描述注册/映射及合法设备指针的条件，不能由设备具有映射能力推定某个范围已可访问；其中避免 RAW、WAR、WAW 的要求也不能因内部复制写入同值而取消。§10.1 将物理分配、虚拟地址预留、映射和权限控制分开。§5.3.1 要求 mapped memory 合并访问，没有保证每次映射读取搬动整页。所供 §19 摘录区分 Unified Memory 支持级别、分配类型、首次触碰与驻留，说明 pointer attributes 不表示物理位置、预取为 stream-ordered 提示，以及页大小对 TLB、碎片和迁移尖峰的权衡。本章据此分别建立地址资格、事务、页事件和内容资格模型，没有把预取作为通用正确性屏障，也没有把软件恢复准入冒充运行时内部迁移的实现。
  [完整原文](../../references/S-CUDA-ASYNC/reader.html) · [全文文本](../../references/S-CUDA-ASYNC/fulltext.txt)

- [S-TORCH-CUDA：PyTorch — CUDA semantics](../sources/S-TORCH-CUDA.md)：固定提交的文档区分异步入队、跨 stream 顺序与 allocator 生存期；锁页复制可支持异步重叠，但锁页准备和系统容量不能忽略。没有读依赖的写操作也可能需要等待地址旧使用结束，支持本章将地址准备与旧内容恢复分开。Graph memory management 原文明确给出按捕获顺序且不并发，以及无相互输出依赖且不并发这两种共享池情形，并提醒共享池可能覆盖旧输出。本章据完整原文保留两种情形；来源说明中的较窄摘要不作为排除第二种情形的依据。地址保活、范围版本、共享 pending、物理范围准入、WAIT 重试和使用身份协议是独立推导。
