# K-WORK-005：Goodput：联合 SLO、拒绝和容量前沿

服务能力是单位时间内完成有效任务且满足约束的数量，不能用总生成速度替代。优化 goodput 必须同时保留任务身份、逐请求资格、完整 offered 人口和资源成本；否则拒绝慢请求、裁短输出或提前关闭窗口，都可能制造虚假的提升。

## 先固定完成单位、事件和联合条件

一次比较的输入包含候选版本、资源预算、请求到达及依赖轨迹、输入输出分布、初始缓存状态、质量合同、延迟阈值和观察窗口。输出包括逐请求判定、业务状态分区、合格完成率、各类服务比例、未决责任及成本。会话、请求、embedding 条目、完整图像和可播放音频不是同一个完成单位；选择单位后，失败与重试也必须使用相同身份。

以下核心算法以非空文本响应为例。请求i的外部到达/计划为aᵢ，实际客户端发送为sᵢ，首个有效内容为fᵢ，正常业务完成为cᵢ，逐token可见时刻为tᵢ,1…tᵢ,n。cohort按aᵢ纳入；时延另固定合同起点oᵢ，可选择实际发送sᵢ或外部到达aᵢ，不能混用。TTFT＝fᵢ−oᵢ；n>1时TPOT＝(tᵢ,n−tᵢ,1)/(n−1)，最大间隔为maxₖ(tᵢ,k−tᵢ,k−1)。客户端持续时间使用同一客户端时钟，跨机拆分另需映射。只有chunk时间时可以评价明确chunk指标，不能伪装逐token ITL。

输出位置有序，但时间戳只要求非递减。有限时钟分辨率可以让多个位置拥有相同时间戳；这并不证明真实生成间隔为零，也不使记录非法。需要区分低于时钟分辨率的时延时，应提高采集精度或报告区间，不能通过强制严格递增来补造观测。

定义 Bᵢ 为合法准入且正常完成，Qᵢ 为质量通过，Lᵢ 为合同规定的全部延迟条件通过，Uᵢ 为输出范围、长度和停止原因符合任务。逐请求资格为

Cᵢ＝Bᵢ ∧ Qᵢ ∧ Lᵢ ∧ Uᵢ。

质量尚未判定时，Cᵢ 不能记为真。质量合同若只提供数据集级 ROUGE 等统计量，应先判断整个候选是否达到该质量门槛，再统计该候选的逐请求时延合格完成；不能凭空生成逐请求质量标签。本文检查中的逐请求布尔质量值是外部评价器提供的证书，并不实现真实语言质量评价。 下文将证书归一后的PASS、FAIL、UNKNOWN和CONFLICT分别保留；Qᵢ只在所选J视图显式PASS时为真，固定规则矛盾证书不能按最后值覆盖。

TPOT 约束与最大 ITL 约束是不同选择。例如间隔为 1、1、10 ms，TPOT 为 4 ms，但发生过 10 ms 停顿。只要求 TPOT≤4 ms 的任务可以接受，只要求所有间隔≤5 ms 的任务不能接受。n=1 时 TPOT 和后续 ITL 未定义；本章参考合同明确豁免后续间隔条件，仍检查 TTFT、正常完成、非空输出和质量。若业务不允许豁免，应更换合同，不能把未定义量默认为零。n=0 不满足本文非空文本合同。

同一人口内，TTFT 合格事件 A 与后续延迟合格事件 D 满足

max(0,P(A)+P(D)−1)≤P(A∩D)≤min(P(A),P(D))。

两项各有 95% 合格，交集可能只有 90%，也可能为 95%；乘成 90.25% 又额外假设了独立性。应关联同一请求后直接求交集。将所有 token 间隔混在一起的 p95，也不等于 95% 请求满足各自的间隔要求，长输出会获得更多统计权重。

## 窗口账与可复算的资格归约

本章选用到达 cohort：外部到达 aᵢ∈[0,T) 的请求进入分母，服务事件观察截止 H≥T，截止时刻发生的服务事件计入。质量证据另按可用截止 J≥H 选择，H与J分别冻结。它们须在可比较的报告时间域中表达；质量机的原始时钟不能直接拿来与客户端时延相减。令 O、A、N、V 分别为 offered、有效业务 admitted、H前正常完成和已证合格完成数。在资格证据完整且无冲突时，

G＝V/H，单位为请求/s；token goodput＝Σᵢ nᵢ1(Cᵢ)/H。

若仍有潜在合格但缺必要证据的u个请求，V/H只作已证下界，上界为(V+u)/H；尚未在H前正常完成的请求对这个固定“截止完成”问题不能因为J较晚就进入u。存在输出/证书身份冲突或同一固定规则的矛盾证书时，保留业务计数和冲突，但本轮资格归约为UNRESOLVED，不发布一个伪装完整的goodput或资格区间。有限对象的缺证据范围不是总体SLO概率置信区间。

token goodput偏重长输出，是另一个目标。V/O为offered合格比例，V/A为有效准入合格比例，V/N只是正常完成者中的合格比例。分母为零时比例未定义；空cohort的计数率仍可为零。固定完成窗口允许以前到达、当前完成的请求进入，是另一种人口；不能与这里的cohort数字混用。服务器取消后实际作出的接受决定属于物理责任账，不增加这里的有效A。

有限窗口中恒有G＝(O/T)(V/O)(T/H)，前提是O>0且V所需资格已结算；采用已证下界时也只能将右侧解释为同一下界。只有H=T，或长期稳定且首尾影响可忽略时，才能直接用offered到达率乘offered合格比例解释G。设10 s到达窗有100个请求，服务截止10 s得到72个合格结果，G为7.2请求/s；若明确延长服务观察到12 s得到81个合格结果，历时口径为6.75请求/s。81/10＝8.1是按原到达窗归一化的cohort产出，必须另标名称。仅把质量证据截止J从10改成12而不延长H，不能采用这个新分母，也不能加入10后才完成的请求。

账本不能只有accepted/completed两列。准入决定尚未到达时可能发生取消、超时或输入失败；准入之后也可能正常完成、失败、取消或超时。截止H的守恒分区为：

O＝准入待决＋拒绝＋准入前终止＋A；

A＝业务进行中＋N＋准入后失败/取消/超时；

N＝质量通过＋质量失败＋质量待判＋质量冲突。

最后一式在固定输出与评价规则、证据截止J下核算，前两式只由H服务快照决定。质量通过者仍须与Lᵢ、Uᵢ求交才能进入V。准入前已终止，之后才收到接受决定的请求，保留迟到决定计数和清理责任，不能追溯改成有效准入。业务进行中、质量待判和质量冲突不能静默丢弃；“截至H未正常完成”与“已完成但尚缺证据”不同。

对一个输出定义完整不可变描述Oᵢ：请求/尝试身份、输出版本、完整内容身份、有效范围或token数、停止规则及生产侧完整就绪事实。下文以SEAL表示这个事实成立，不要求系统实现一个同名API。SEAL不能由“这是日志里最后一条内容”或shape相同推出来。生产侧可以先完整就绪并评质，客户端仍在缓冲；例如SEAL25、质量证据28、客户端最后内容30、协议FINAL45并不矛盾。指标仍使用客户端内容时刻，质量绑定该生产侧完整Oᵢ。完整描述的证据若晚到，可以在J视图补证已经属于H前结果的身份；它的可用时间与所证明的生产就绪事实分别保留，不能用J中新产生的另一个输出替换H快照。

证书c包含请求/尝试、Oᵢ、评价规则及其版本、证据身份、判定与证据可用时刻。选择固定规则后，重复的同身份同载荷证书幂等；身份载荷不同，或同一输出与固定规则出现FAIL和PASS，进入CONFLICT而非最后写者获胜。不同规则的结论保留为不同视图，不能覆盖本合同。若评价器产生随机原始评分，先由明确的采样/聚合规则形成证书；原始评分不同不自动构成确定证书逻辑冲突，后来一个PASS也不自动修订既有FAIL。

```pseudocode
算法 CohortGoodput(service_events, quality_evidence, T, H, J, policy)
输入：完整到达身份、服务事件、完整输出描述、质量证据及固定资格合同
输出：H业务快照、J证据状态、已证/潜在资格或UNRESOLVED、计数与历时

要求T>0、H>=T、J>=H；固定cohort键与TTFT起点，它们不必相同
对每个a属于[0,T)的唯一请求/尝试：
    state←准入待决；content←空；output_descriptor←未知
    仅取发生时间<=H的服务事件，核对身份与字段并按稳定因果顺序推进
    同刻服务事件采用：准入决定、整数位置序的内容、SEAL、业务终止
    相同事件身份同载荷幂等；冲突身份或不可能转移使业务快照不可审计
    准入决定：
        不相同的重复决定报冲突
        若已准入前终止：只增加真实决定/迟到决定账与清理责任，不复活业务
        否则从待决转入拒绝或业务进行中
    内容：要求业务仍进行中，所选观察边界、位置与请求身份正确
    SEAL：核对并保存完整不可变输出描述；不将生产就绪当客户端已经看见
        不能改写同一输出版本的内容身份；有矛盾描述则报冲突
    业务终止：
        待决只允许准入前取消、超时或失败
        进行中转为正常完成或准入后失败/取消/超时；已有终态不被后续证据覆盖
    冻结state、内容事实、输出合同、TTFT/TPOT可观测性与业务完成时刻

另按证据可用时刻<=J收集证书；早期到达的证书不要求当时已经FINAL
按请求/尝试、完整输出、固定规则与证据身份归一：
    相同身份同载荷去重；身份载荷或固定规则判定冲突记CONFLICT
    尚无完整输出绑定事实：保留待绑定证据，质量为UNKNOWN，不能直接置PASS
    绑定有效且规则相符：保存PASS或FAIL；其他规则保持独立视图
    不把证据时刻改写成服务完成、内容可见或资源排空时刻

对H快照的每个请求：
    若没有H前正常完成：保持原业务分区；证书只留作诊断，不增加正常完成或资格
    若已正常完成：在J视图中计入PASS/FAIL/UNKNOWN/CONFLICT之一
    Q、L、U有一项确定FAIL：不合格；没有确定失败但缺必要证据：潜在合格
    全部已证PASS且正常完成：V加一，累计其合法输出数
    资格相关证据冲突：整份资格结算标记UNRESOLVED，保留原始业务计数与冲突
核对三条守恒式；无冲突时给V/H及潜在资格范围，完整时给确定合格率
J推进时另存新报表修订，复用同一个H快照；H改变则另立服务观察版本
```

此算法把服务状态推进和证据归一分成两个责任域，因此质量早到、晚到都不会改变业务终态。在线取J=H是一个明确的特殊观察契约：截至H没得到证书就保持待判，不表示该输出质量失败。离线评价常用J>H；它可以补齐H前完整结果的标签，不能把J内发生的未来FINAL算到H里。若用户交付本身等待审核，应另选审核后交付事件作为业务完成边界并计其真实成本。

与[服务指标](metric-events.md)的可执行衔接是：请求事件归约提供内容与终态事实，CohortGoodput的第一阶段提供不可变H业务快照；按Oᵢ/规则归一的证书视图进入SettlePerformanceEvidence，返回PASS、FAIL、UNKNOWN或CONFLICT及原因，再由这里的最后阶段计数。旧CohortReport中的good仅接受显式已证真资格；未知仍在待决清单和上界中，冲突阻止确定结算，不能把UNKNOWN强转成False后称最终失败，也不能重复运行一遍“最后标签覆盖”的质量分支。

例如SEAL30、证书35、FINAL45、H=60、J=60：证书在35时可以挂起，45后完成资格，G=1/(60 ms)=50/3请求/s，不必伪造一个45后的证书时刻。SEAL25、证书28、客户端末内容30同样合法。相同输出/规则先FAIL35、后PASS40时，即使FINAL45正常，也保持证据冲突；不能得到一个合格完成。若证书改在80到达，H=60、J=100可以补齐同一H前输出的标签，G分母仍是60；若FINAL改为70，H=60、J=100仍是未完成，证书不能使它进入V。

同刻排序在时间相同且类型相同后才比较该类型的载荷，因此没有混合类型之间的隐式比较。参考检查将决定和证书判定限定为布尔值，位置限定为非负整数，终态限定为normal、cancel、timeout、failed；先验证，再形成全为整数的排序键。证书按自己的证据域归一，不靠与FINAL的同刻类型优先级建立资格。枚举序只使冲突处理确定，不能让冲突事件变成合法事件。

例如一个请求在0获准，位置0…10的11个内容事件都记为1，完整描述在1可得，随后在2正常结束、3质量通过。数值位置序为0、1、2…10，合同下得到1个合格请求、11个合格token。字符串序为0、1、10、2…9，会在期待位置2时读到位置10，错误报告非法内容。检查必须让这条合法轨迹与不排序事件的端点参考一致，并让字符串排序负对照被检出。

这里的同刻服务类型顺序是一种明确合同：同刻接受再取消属于准入后取消；真正较早发生的取消属于准入前取消。实际协议若提供更细因果序号，应使用它，不能靠日志行顺序猜测。冲突、缺失必要字段或不可能转移使本次统计不可审计，不能通过删除该请求改善结果。设备晚完成与网络清理另记，不能再次触发业务成功。相关事件边界见[服务指标](metric-events.md)。

逻辑任务重试还需保留task_id与attempt_id。资源需求按所有尝试累计；业务任务goodput只在规定提交点成功一次。将失败尝试删去，或将两个成功重试都计成两个有效任务，都会改变定义。若offered单位选为尝试，应在整个账本和比例中保持该单位，另报逻辑任务结果。

## 准入必须区分硬合法性和时延预测

到达超过服务能力时，可以排队、拒绝或采用合同允许的降级。拒绝减少已接收者延迟，但不会消除 offered 失败服务比例；延后保留任务且继续消耗 deadline；降级改变模型、长度、分辨率或近似策略，必须采用对应质量合同。静默截断不能算作纯容量提升。

硬合法性包含：模型与输入身份有效；依赖就绪或具有合法等待路径；可用物理容量足够；输出与状态不会越界；请求未终止。时延可达性则依赖服务时间、排队、传输和输出的预测。预测通过不保证未来 SLO，预测失败也不自动证明数学上不存在其他调度方案。

一个保守且可实现的准入方案，为每请求最大合法长度及必要工作区预留容量。页式 KV 可按模型、dtype、页长、共享前缀引用和私有尾部计算。共享页按物理并集计一次；每个新请求仍取得自己的引用保护。若不按最大长度全量预留，而采用滚动预留，则每次增长前必须重新检查，并明确容量不足后的暂停、换出、重算或终止协议。长度预测不能授权越界分配。

```pseudocode
算法 TryAdmit(i, snapshot)
输入：请求 i、当前资源账、服务合同、带误差范围的延迟模型
输出：ACCEPT、REJECT 或有界 WAIT

校验任务身份、输入、依赖、最大长度与截止时间；非法则明确失败
构造物理预留集合：新增私有状态、共享对象引用、工作区和输出预算
估计首内容与后续间隔：排队、准备、执行、传输、发送及误差余量
若预测超限：按合同拒绝、有限等待或选择允许的降级候选
若继续准入：
    在同一原子事务中重新检查请求仍有效、资源版本和物理容量
    若竞争导致预留失败：重新估计或拒绝，不使用过时 snapshot
    成功预留后，记录唯一准入决定并发布到就绪/等待队列
每次启动工作：先登记该工作对预留对象的访问责任，再提交
业务完成或取消：禁止新工作，撤销业务继续资格
只有对象无业务保留需求且全部在途访问完成时，归还物理容量
```

候选评分、排序和预留是不同步骤。多个路由器读到同一空闲容量，不能分别无条件接受。已经决定驱逐、取消或迁移的页，在最后访问结束前仍占容量；把业务终止当物理释放会让下一请求与旧 DMA/kernel 访问重叠。

设容量为 5 单位，A 保留 4 单位并有两个在途读者。取消 A 后可用量仍为 1；需要 2 单位的 B 必须等待或拒绝。第一个读者完成仍只有 1，最后读者完成后才变为 5。这个轨迹只依赖所有权，不依赖取消能否缩短实际执行。

时延 admission 可按剩余预算计算：首内容预算为 D_first−(now−oᵢ)；已有流的下次内容预算为 D_gap−(now−last_content)。估计本轮所有串行依赖的时间及余量后再比较；已经包含在估计中的准备时间不能再扣一次。无法预测输出长度、突发或网络尾部时，保留硬容量检查，降低时延承诺强度，并用后续观测校准。

## 容量搜索与可行前沿怎样产生

容量不是一个跨负载不变的 tokens/s 常数。固定配置 θ 与负载族 W，定义测试运行点为 offered 到达率 λ_off、资源预算、联合资格规则、拒绝规则、初始状态与观察方法的组合。合同可以要求 admitted 联合合格率≥ρ，也可以要求 offered 合格率≥ρ，并限制拒绝率；必须预先说明选择。只用 admitted 比例而允许任意拒绝，会使接受极少请求的策略看起来总能满足 SLO。

在稳定、人口一致且时间边界影响可忽略的条件下，令 α 为合法准入数与 offered 数之比，λ_ad 为合法准入流率，p 为准入后的联合合格概率，则

λ_ad＝αλ_off，G≈λ_ad p＝λ_off αp。

α 不把准入前终止及迟到接受记为有效准入；存在这些状态时，1−α 不全是拒绝率。有限 cohort 中可以精确使用 A/O 与 V/A 展开计数，但不能忽略 T/H，或把 A/T 当成任意阶段同一物理窗口的实际进入率。

设定同一窗口 offered 1000 个请求：A 接受全部而 700 个合格；B 接受 800 个而 760 个合格。B 的合格数更高，但拒绝率为 20%；若合同最多拒绝 5%，B 仍不可交付。重试形成的尝试到达与成本还要另记。

有限试验只能确认所测窗口。完成率达到平台而积压持续增长、质量待判不断增加，或运行结束留下越来越多在途对象，都不能据此宣称长期稳定容量。应同时保留业务队列、估计剩余工作、物理驻留和首尾差异，并在更长窗口与独立重复中检查趋势；接近零的有限窗口斜率本身不是一般稳定性证明。

```pseudocode
算法 ExploreFrontier
输入：固定任务合同、候选配置集合 Θ、offered 负载扫描点 Λ_off、实验预算
输出：实测/模型可行点、不可行点、证据不足点、保留交付候选

保留已有合格交付候选；初始化记录表与前沿为空
对每个合法配置 θ：
    对每个 λ_off∈Λ_off，使用匹配的请求轨迹、初始状态和资源边界：
        运行或模拟，收集完整 offered 人口、阶段访问和资源事件
        用 CohortGoodput 归约，并检查质量、拒绝、各类约束和积压趋势
        缺事件、未决证据或不确定性跨决策界限：标为证据不足
        违反任一合同条件：标为不可行
        其余标为在当前测试范围可行；记录 G、成本、能量与各类结果
        只在可行集合内更新非支配前沿
按声明目标选择候选，冻结配置，在未参与搜索的负载与运行上确认
确认通过后更新交付候选；失败则保留旧候选并修正模型或选择
```

前沿可以在 G 越大、同范围总成本越小的二维空间定义：若 x 的 G 不小于 y、成本不大于 y，且至少一项严格改善，则 x 支配 y。质量、租户底线和拒绝限制先决定可行性，不能用更高 G 抵消。能量、恢复时间或稳健余量也可进入目标，但维度与权重需预先给定。

低负载下 batch 未形成、稍高负载下效率改善，再到饱和后排队上升，可能造成某些可行性判定非单调。服务桶、自动扩容、缓存和 admission 也可能制造离散变化。只有在固定配置和负载族上建立了相应单调性，才能把失败点当作全部更高负载的上界并二分；否则保留网格扫描和局部细化。本章不把一次最高通过点称为全局最优。

即使配置的每 GPU 容量更高，也不保证小规模需求下总成本最低。设 A 每实例 1 GPU、容量 6 请求/s，B 每实例 2 GPU、容量 13 请求/s。B 的每 GPU 容量为 6.5，高于 A 的 6；需求只有 6 时，A 用 1 GPU，B 用 2 GPU。副本数取整、故障余量和拓扑要求必须在最终选择中重算。

## 一条 P/D 组合轨迹与条件化成本

DistServe 提供将 prefill/decode 资源分配和并行选择解耦的依据；收益来自减少阶段干扰并选择不同配置，代价包括两侧权重、KV 交换、队列与接管。不能将两个阶段分别合格直接拼成联合合格，更不能把阶段容量相加。

下面构造串行依赖明确的设定轨迹，全部数字为模型输入，单位 ms。请求在 0 到达，prefill 排队 20、主机准备 5、prefill 执行 40，因此 65 时首 token 与提示词 KV 都就绪。首内容发送需 5，客户端在 70 收到。目标需迁移 KV 25，至 90 完成，再排队 10、decode 8、发送 2，第二内容在 110 到达。因此 TTFT＝70，首个后续间隔＝40。

若目标为 TTFT≤80、所有后续间隔≤30，首条件通过而联合失败。迁移降到 10 时，第二内容在 95 到达，间隔降至 25，TTFT 仍为 70。首 token 已收到不代表目标 KV 已提交；反过来，目标有 KV 也不代表首 token 票据存在。目标第一次 decode 必须等待二者及容量、授权均就绪。

这条轨迹假设首 token 可在迁移前独立发送，目标排队发生在 KV 就绪后，且没有其他重叠。如果协议要求接管后才发首内容，迁移就会进入 TTFT 路径；如果传输与其他合法计算重叠，要重新建立依赖图，沿关键路径求时间。不能无条件相加全部 profiler 区间，也不能无条件取最大值。

平均资源账必须使用实际进入资源的人口。分别记 λ_p、λ_d 为每秒进入 prefill、decode 池的完整请求级阶段访问次数，λ_x 为每秒 KV 迁移次数；一次 decode 池访问包含该请求在该池的全部生成工作，不能将它与逐 token 迭代次数混用。n_p、n_d 个实例在声明的请求形态下，单实例平均服务能力为 μ_p、μ_d，单位为阶段访问/s；每次迁移固定 K 字节，共享链路有效预算为 B 字节/s。忽略其他瓶颈的平均必要条件为

λ_p≤n_pμ_p，λ_d≤n_dμ_d，λ_x K≤B。

只有在全部准入请求各访问两池一次、各迁移一次、没有重试、旁路或中途终止，且处于稳定同人口口径时，才有 λ_p＝λ_d＝λ_x＝λ_ad＝αλ_off，从而

αλ_off≤min(n_pμ_p,n_dμ_d,B/K)。

K=0 的路径不做该项除法。μ 本身依赖 batch、历史、并行和质量策略；拒绝若筛选了长度分布，也必须按准入后实际形态重估 μ，不能继续套 offered 人口的服务能力。上述不等式包含等号，只表达平均资源不超额的必要条件，不证明队列稳定或尾部 SLO。

两台 prefill 各为 6 次/s、一台 decode 为 10 次/s，池上界分别为 12、10；每次迁移 0.5 GiB、链路有效预算为 4 GiB/s 时，迁移上界为 8 次/s。若合同允许拒绝 60%，λ_off＝20 请求/s、α＝0.4，则 λ_ad＝8，请求路径的三项平均资源需求分别为 8、8 次/s 和 4 GiB/s，均不超过上界。错误使用 λ_off≤8 会排除这个没有违反所列平均资源必要条件的点。是否满足完整合同仍需联合资格、拒绝规则、队列与尾部证据，不能由这个反例直接宣称可交付。

若存在重试、旁路或部分阶段取消，三种访问流率分别统计。全部工作均可归属所计准入请求时，可用每准入请求平均访问次数 ν_j 写 λ_j＝λ_ad ν_j；其他人口产生的工作另加，不能隐藏在 α 内。一次失败后重跑两池会增加 λ_p、λ_d、λ_x；仅迁移重传则可能只增加迁移次数或实际字节。迁移大小不固定时，网络账为 λ_x E[K|迁移]≤B，并按实际链路汇总其他流量；不能用 offered 平均大小替代迁移人口均值。

源缓冲也有自己的进入人口。设 λ_buf 为每秒进入源端待拉取保留区间的对象次数，每个区间固定保留 0.5 GiB、平均持续 0.2 s；无共享、稳定且统计边界一致时，平均占用为 λ_buf×0.2×0.5 GiB。本算例另假设每个准入请求恰好产生一个这样的区间，因此 λ_buf＝λ_ad＝8 次/s，得到 0.8 GiB；这里没有使用 offered 的 20 请求/s。重试产生额外区间、取消后等待排空或对象共享时，必须重新计区间和唯一物理对象。大小随时间变化时，使用 λ_buf E[∫m_i(u)du]；大小和停留时间相关时不能无条件相乘两个均值。平均占用不保证突发下峰值可容纳。

| 成本 | 在同一候选和观察边界内列账的方法 |
|---|---|
| 计算 | 预处理、未命中 prefill、全部 decode、验证、重算和失败工作均计入分子。稠密 attention 的输入阶段随有效位置配对增长，decode 还随历史增长；量化转换与投机验证不能只计接受 token |
| 访存 | 权重、KV、激活、页表、输出及观测日志分别计量；逻辑 KV 字节不等于 HBM 事务。分块可能增加历史重读，共享前缀减少唯一驻留但不自动消除各 query 的读取 |
| 通信 | KV 字节、布局转换、暂存、用户流式响应与模型并行通信共享实际链路预算；消息准备、注册和重传另计。K/B 只是特定无竞争条件下的数据传输下界 |
| 准备 | 模型加载、编译、预热、连接、校准与评价器准备按冷/热边界记录；新增 P/D 权重副本增加准备和常驻占用，不能只保留稳态收益 |
| 同步 | 预留事务、设备完成、传输可见、接管提交和输出 flush 形成依赖；同步可能打断重叠。累计资源忙时与端到端关键路径分别报告 |
| 驻留 | 权重、唯一 KV、工作区、源端待拉取状态、目标接收暂存、排队对象和待发送输出按同时存活集合求峰值；预留池与其中对象不能重复相加，取消后未排空对象仍占用 |

窗口总成本除以 V 得到每合格任务成本；能量同理，V=0 时未定义。分子包含该资源范围内的空闲保留、失败、拒绝处理、重试与排空。不能用合格请求的计算量作分子，却把全部保留 GPU 的费用藏掉。异构实例应使用真实费用或资源向量，不能仅按 GPU 数归一化。

准入评估若每到达扫描 R 个活跃请求，单次可为 O(R)；维护按资源聚合的账可减少重复求和，但共享对象引用、并发事务和候选预留仍有成本。已排序 E 条事件的归约为 O(E)，无序输入通常需 O(E log E) 排序；活跃状态、去重身份与日志分别占空间。此复杂度描述的是审计/控制模型，不是 GPU 服务时间。

## 负载、目标与租户变化后的选择

质量、延迟、拒绝与最低服务份额共同定义合法区域；它们不是每个系统必须采用相同阈值的统一规则。总体 goodput 很高仍可能饿死低流量租户。应预先固定租户权重、各类 offered/admitted 合格比例、最大等待或最低资源份额，再汇总。相同请求数、相同 token 数和相同估计设备时间表达不同公平目标；长历史或多模态输入下尤其不能互换。

| 条件变化 | 保留的机制 | 调整或放弃的结论 |
|---|---|---|
| 输入变长或缓存命中下降 | 身份、资格交集与容量所有权 | 重算 prefill、KV、传输和 TTFT；原 P/D 配比不再可靠 |
| 输出变长、慢客户端增多 | 原始内容与业务终态账 | 重算 decode、输出背压和字节×驻留时间；旧平均服务率不能直接外推 |
| 拒绝选择、路径或重试改变 | 完整 offered 人口与 task/attempt 身份 | 重算准入形态、各阶段访问、迁移和源缓冲进入率；放弃各阶段均等于 offered 的假设 |
| 突发持续时间改变 | 外部计划、资源账与排空责任 | 重算积压和峰值；只按平均 λ_off 的余量不足 |
| SLO 收紧或任务质量改变 | 同一批请求的事件关联 | 重新归约原始数据；缺少更细事件时只能补测，不能从旧分位数恢复交集 |
| GPU、CPU、网络或并行组改变 | 物理生命期与资源单位 | 重新校准服务曲面、事务、准备和通信；旧最优配置失效 |
| 离线不可拒绝任务 | 完整任务人口与质量合同 | 放弃依赖拒绝改善的在线比较，改用期限内完成量或总完成时间 |
| 音频、视频、RAG 或会话目标 | 联合资格与同单位分母 | 用首可播放、欠载、最终媒体/回答/会话质量定义完成；文本 token goodput 不能替代 |

量化扩大容量但降低质量、投机减少步数但增加验证负载、路由命中节省计算却增加热点排队，都可能使选择反转。应保留仍合法的旧交付候选，在新条件下调整参数或放弃相应优化，而不是把旧容量数字当作事实常数。

## 竞争解释、区分实验与反证修正

| 观察 | 竞争解释 | 区分干预与修正 |
|---|---|---|
| tokens/s 提高但 goodput 下降 | batch 变大导致间隔超限；输出变长；质量下降 | 固定输入、停止和质量合同，关联逐请求时序与输出量。若只是长输出增权，撤回容量提升解释 |
| admitted 延迟改善 | 服务更快；拒绝筛掉长请求；窗口末慢请求未完成 | 重放相同 offered 轨迹，恢复拒绝、各长度桶及 pending；拒绝超合同则候选不可交付 |
| offered 超过阶段上界而队列未增长 | 拒绝降低进入率；旁路减少访问；阶段日志遗漏 | 固定 offered 轨迹，改变准入比例并逐身份数阶段访问；无重试单路径下访问率应跟随 αλ_off。偏离时先核对路径、重试与首尾库存，再修正人口模型 |
| 两项 p95 均合格但联合不足 | 两类失败落在不同请求；统计人口不同 | 用同一请求 ID 构成交叉表，并构造失败集合互斥的负对照；聚合器若仍报 95% 联合则修正算法 |
| 同刻内容被判位置跳跃 | 真正缺位置；字符串排序；时钟精度不足 | 保持身份和位置，构造至少 11 个同刻 token，随机化日志排列；与直接端点参考比较。数值排序修复后应恢复全部位置，真实缺口仍须拒绝 |
| P/D 后 TTFT 好而第二 token 慢 | 传输/接管；目标排队；首内容 flush | 固定计算和请求，只改变链路预算，再改变 decode 容量。只有对应等待随干预变化才支持该解释；源缓冲增长还提示下游背压 |
| GPU 平均利用率低但队列增长 | 主机单执行域、网络、依赖或输出背压 | 分阶段记录入队/执行/完成，只增加对应资源；无响应则撤回该瓶颈解释，不用平均利用率排除局部饱和 |
| 取消后立刻接纳更多请求 | 真实排空；只改了业务计数；提前复用资源 | 延迟最后访问完成，检查新预留是否仍受旧对象占用约束。若取消即放行，修复生命周期而非报告收益 |
| 搜索最优点在复测时失效 | 选择噪声；状态漂移；长度或到达改变 | 冻结配置，在独立区组与保留轨迹复测；差异跨决策界限则记证据不足，恢复旧交付点 |

容量确认同时观察完整人口、联合资格、队列趋势、物理占用和每合格任务成本。先写出干预的可否定预测；如果时间改善却没有发生预测的工作量或等待变化，候选可以继续研究，但机制解释必须修正。目标设备上的端到端试验应包含突发、质量失败、生成器迟发、慢消费者和取消排空，不能仅凭 CPU 模型通过宣称 SLO 达成。

## 随章检查与证据边界

交付检查为 tools/check_k_work_005_full.py，使用 Python 标准库、整数时间和精确有理数，离线、只读、确定性运行。事件状态机与按请求端点直接分类的独立参考对照，覆盖窗口边界、空输出、单 token、阈值等号、拒绝、准入前取消及迟到接受、质量待判、重复事件与冲突。新增 11、12、101 个同刻内容位置，以及准入、内容、终态和质量全部同刻的轨迹；字符串排序负对照必须在合法 11-token 轨迹上被识别，其他字段采用经过类型验证的数值排序键。

流量检查从 10 s 内 200 个 offered 身份逐个构造 80 个准入、120 个拒绝，再独立数两池访问和迁移，核对 λ_off＝20、α＝0.4 与各阶段 8 次/s。源缓冲用逐对象字节×存活时间的面积参考核对 0.8 GiB，积分包含这些对象完整保留区间，再除以到达窗长度；这是 cohort 面积归一化，周期重放或稳定边界下才对应平均驻留。另有重试、旁路和阶段取消的访问轨迹，检验阶段流率可以不同；这些有限模型不证明稳定性。

资源模型以独立给定的可用量轨迹检查最后读者完成后才释放；前沿用全体两两支配参考核对增量算法。错误负对照还包括边缘最小值代替交集、忽略质量、待判质量算通过、遗漏拒绝、错误处理单 token、排空分母错误、只看平均间隔、取消即释放、不可行高吞吐点进入前沿、offered 率代替阶段率、offered 率代替源缓冲进入率，以及忽略额外访问。

新增 `tools/check_evaluation_goodput.py` 自包含一份与指标检查按规范JSON指纹绑定的共同八请求数据。独立的业务事件状态机与声明式终态/证据集合参考分别计算H快照、J质量视图和资格；它们不共享资格函数，也不导入其他检查脚本。覆盖早于FINAL的质量、早于客户端末内容但晚于生产SEAL的质量、固定规则FAIL→PASS冲突、身份载荷冲突、相同证据幂等、H后J前证书、H后FINAL不纳入及取消不复活。故障分支实际执行迟到要求、后写覆盖、J改H、证据复活业务和以client末内容猜SEAL，交给同一声明式参考。原检查继续承担其历史事件模型与资源/流量回归，不把它的严格证书到达顺序当作通用质量接口。实际检查结果须由当前绑定执行记录承担；共同数据的指纹和摘要可以跨两个独立脚本核对，不能代替独立参考。

这些检查不执行模型、tokenizer、真实质量评价、负载生成器、GPU、NIC 或并发原子事务，不证明硬件可见性、生产吞吐、长期稳定性、尾部概率或 Agent 使用效果。质量证书可靠性、真实请求事件完整性、服务时间预测误差及目标拓扑仍是接入后的具体验证边界。
