# K-WORK-003：工作负载分布：长度、复用、模态与相关性

系统成本由输入输出、到达、复用和完成边界的联合分布决定。两个平均长度无法恢复批次浪费、缓存命中或峰值驻留。本章从联合记录构造可重放档案，再按真实消费位置和唯一物理对象推导成本。公式、事件轨迹和容量数字均为声明条件下的分析模型，不是目标 GPU 实测。

## 不止两个平均数

对请求 i，记联合记录

`r_i=(id_i,s_i,a_i,D_i,u_i,m_i,x_i,y_i,o_i,c_i)`。

`id_i` 是请求身份；`s_i` 是会话、租户与分支归属；`a_i` 是外部到达约束；`D_i` 是上游依赖及其满足事件；`u_i` 是规范输入、模型条件与缓存身份；`m_i` 是媒体几何和 processor 配置；`x_i` 是模型实际消费的输入位置数；`y_i` 是实际正式选择的输出 token 数；`o_i` 保存停止原因与可见输出边界；`c_i` 保存客户端消费、取消与清理规则。一个依赖可以要求上游首内容、完整回答或工具结果成功提交，必须指明事件，不能只记录一条没有含义的边。

本章生成算例把合法 EOS 计入 `y_i`，但不把 EOS 当可见正文；预算停止不补造 EOS。客户端 chunk、正式选择的 token、已消费并形成 KV 的 token、解码字节与已提交字节是不同边界。GenAI-Perf 固定文档提供请求级输入/输出 token 指标和流式响应指标，但客户端 chunk 并不保证与模型 token 一一对应，其文档也保留 token 计数可能不精确的限制。

输入长度由模板、tokenizer、processor、模态桥接和特殊 token 共同决定，不是字符数或图片张数。输出长度既受任务影响，也受 EOS、采样、stop string、预算、错误和取消影响。描述执行负载至少需要联合规律

`P(L_in,L_out,H,M,A,D,S,C)`，

其中 H 是前缀身份序列及复用间隔，M 是媒体几何，A 是 adapter、grammar 和分支条件，D 是跨请求依赖，S 是停止/取消规则，C 是客户端消费行为。请求、token、字节与活跃时间加权统计回答不同问题，须声明分母。

考虑两个批：`W0={(100,100),(100,100)}`，`W1={(10,190),(190,10)}`。两者输入与输出均值均为 100。统一 padding 的线性位置数分别为 200 和 380；若执行完整方形 dense attention，配对数分别为 20000 和 72200，而 W1 的有效方形配对数仅为 `10²+190²=36200`。W1 的输入输出协方差为 −8100；把输出顺序反转后，边际完全不变，协方差却变为 +8100。这些逻辑量已经区分工作负载，尚不能直接换算成 GPU 延迟。

协方差也不是完整联合分布的身份证明。例如 `{(1,2),(2,3),(3,1)}` 与 `{(1,3),(2,1),(3,2)}` 的输入、输出边际和协方差相同，但联合频数不同。低阶摘要用于定位变化；有限离散样本若要声称经验联合分布完全相同，应比较规范联合记录的频数，而不能仅比较均值与协方差。

## 合法性：单位、边界与身份

规范记录进入档案前，需要满足以下条件。

- 模型、模板、tokenizer、processor、位置与停止合同相容。整数 ID 在 embedding 范围内只证明形状合法，不证明词义或制品相容。输入截断要记录允许删除的单元、实际删除范围及重建后的有效长度。
- 若潜在输出为 y*，预算 cap 产生的观测可能是 `min(y*,cap)`；LENGTH、取消与超时不能冒充自然 EOS。是否把它用于尾部分布估计，需要解释删失机制。失败和未完成请求仍保留在 offered/admitted/completed/failed 账中。
- 缓存复用要求完整计算身份相同、状态完成、物理副本仍驻留、路由可达及恢复点合法。相同字符串、URL 或 placeholder 都不足以证明命中。只存 KV 而未存末行 logits 的生成路径，通常最多跳过 `x_i−1` 个输入位置；完整页缓存还需向下取合法页边界。
- 媒体身份包含内容、processor、resize/crop、patch/merge、帧采样与时间位置。相同面积不等于相同网格和窗口；相同帧数不等于相同时间输入。
- 必需依赖必须在所选单元内闭合，或由明确、可验证的初始快照满足。缺少前一回合却保留第二回合依赖，不是合法会话重放。依赖图须无环，并有失败或取消后的终止规则。
- 开发、校准与保留集合按会话、近重复媒体和声明的时间/用户隔离规则划分。相关记录不能逐请求随机拆分后仍称独立保留。规则冲突时报告无法满足，不能静默打散依赖。

独立抽取各边际可以作为零模型或压力干预，但它改变联合规律。整条请求重采样保留请求内部配对，却仍可能破坏会话依赖、热点持续时间和跨请求复用距离；这三种性质应分别核对。

GenAI-Perf 固定文档提供合成输入/输出长度、前缀 prompt、固定 schedule 的 `hash_ids`、多轮 session 延迟及 goodput 约束。这些入口能控制部分边际、重复和到达。`hash_ids` 表达合成输入块复用，不能自动证明生产系统中的完整 KV 身份、驻留和就绪条件。

## 从记录到可重放档案

构造过程区分规范化、依赖单元和最终副本。请求状态为 `RAW → VALIDATED → ELIGIBLE → FROZEN`；合法性失败进入 `REJECTED`，合法记录所在依赖单元不完整则进入 `BLOCKED_DEPENDENCY`。后两者均不能落入最终档案。`VALIDATED` 仅表示本条记录的单位与身份合格，`ELIGIBLE` 才表示其重放前提已满足。

重采样单元有两类：真正独立的请求是单元素单元；多轮、fork/join 和工具链按完整会话或明确的依赖闭包组成单元。单元内保留全部必需祖先、依赖事件、输入构造规则与等待规则。若闭包跨越多个会话，就联合抽取该闭包；不能为方便抽样删除边。

```pseudocode
算法 BuildAndAuditWorkload
输入：原始记录 R，固定制品/单位/停止合同 M，隔离规则 split_rule，
      分层规则 strata，抽样单元权重 w，种子 seed，重放模式 mode
输出：规范档案 D、拒绝/阻塞记录、抽样来源与审计报告

1. 初始化 D、Reject、Blocked、候选池为空；所有记录状态为 RAW。
   固定 M、种子、权重来源、抽样单位和隔离规则。
   按必需依赖、会话与泄露隔离关系分配 split；冲突则报告失败。

2. 对每条原始记录 r：
   2.1 用 M 渲染、编码并展开媒体，取得实际 token/特征、位置和输入身份。
       记录输入截断、正式输出 token、停止原因、可见输出和取消规则。
   2.2 若缺失必要单位、制品不相容、媒体不可解码或结果边界不满足合同：
       状态置 REJECTED；记录原因到 Reject；立即继续下一条原始记录。
       不执行本条的后续提交，不用其他记录均值补造缺失值。
   2.3 状态置 VALIDATED；仅将完整规范记录放入暂存候选池。

3. 在原始依赖图上构造独立请求或完整依赖单元 U：
   3.1 核对单元所有必需记录均通过步骤 2，祖先闭合，依赖图无环，split 一致。
       初始快照若代替祖先，须核对其输入与状态身份，不伪造缺失回合。
   3.2 若任一条件失败：单元内仍为 VALIDATED 的记录置 BLOCKED_DEPENDENCY；
       保存原因到 Blocked；整单元不进入可抽样池；继续下一单元。
       已 REJECTED 的成员保持 REJECTED，不改写成其他成功状态。
   3.3 否则为单元定层；全部成员置 ELIGIBLE；原配对与依赖不变。

4. 对每个 split 和层检查支持情况：
   报告单元数、请求数、联合长度、复用间隔、删失、失败和取消。
   若 w[s]>0 而没有合法单元，报告 unsupported，不冻结代表该层的档案。
   w 的单位必须明确：本算法直接指定单元抽样概率。
   若目标是请求占比，先按各单元请求数求诱导占比，再选择/核对抽样方案。

5. 构造副本：
   5.1 若直接重放原时间轨迹：保留整个选定窗口及其依赖前置状态。
   5.2 若重采样：先抽层，再抽该层完整单元；独立请求单元可单条抽样。
       每次抽取分配全局唯一 copy_id；重写请求、会话、分支及依赖端点身份。
       不仅修改子请求 ID，也不得让两个副本共享可变会话历史。
       缓存内容身份按实际模型输入和隔离合同计算，不因 copy_id 任意失效或合并。
   5.3 为每个副本指定外部起点 b；保存单元内外部释放偏移与依赖等待规则。
       根节点按 b 加原偏移释放；有依赖节点先进入 WAIT_DEP。
       后续释放由步骤 6 的实际合格事件决定，不复制旧完成时间。
   5.4 若扰动输入、模态、停止或依赖：标明 intervention，重新规范化完整受影响单元。
       任何成员拒绝或闭包失败，整副本不提交；拒绝分支不能落入冻结集合。

6. 事件重放：
   初始化未发布、就绪、在途、完成及失败集合；按时间与稳定身份顺序处理事件。
   外部释放时，只有全部必需依赖事件满足的节点才能 READY，否则保持 WAIT_DEP。
   上游合格事件到达时：提交对应数据，更新依赖计数与最早释放时间。
       节点的就绪时间不早于外部释放界及每个依赖事件时间加其等待间隔。
       依赖清零且等待时间到达后，按输入构造规则组成本轮真实输入，再规范化。
   调度器只提交 READY 且资源合法的节点；记录开始、首内容、完成和清理事件。
   上游失败或取消若不能满足所需事件，按固定规则阻塞/终止后继，不能提前发出。
   全部节点完成或进入已解释的终止状态后，结束；未完成节点保留在报告中。

7. 独立审计：
   检查拒绝/阻塞集合与交付集合不相交，依赖端点存在且事件顺序合法，副本身份唯一。
   重新生成合并后的全局访问序列，计算实际副本交错下的复用距离。
   按物理对象去重核算驻留，按真实消费位置核算计算；报告分层与加权总体。
   加入会落入拒绝分支、孤立第二回合、过早释放、忽略淘汰和错误 decode 边界负对照。
   审计失败则保存反例，修正单位、依赖、权重或事件规则，不删掉不利样本。

8. 冻结：只有支持范围、权重、模式、单位与审计均已说明的产物进入 FROZEN。
   输出 D、Reject、Blocked、来源映射、种子、审计与未覆盖范围。
```

拒绝状态的最小轨迹为：记录 g 单位合法，`RAW→VALIDATED→ELIGIBLE`；记录 b 缺输入单位，`RAW→REJECTED`，随后立即跳过。若 b 是会话第二回合的必需祖先，第二回合即使自身合法，也只能 `RAW→VALIDATED→BLOCKED_DEPENDENCY`。交付集合只含 g，不能让 b 或其后继因循环落入成功提交。

这个过程还有可观测的准备成本。规范化需要读取文本、媒体及生成身份；依赖图检查可用入度计数与拓扑遍历，在 V 个节点、E 条边上为 `O(V+E)`，另计编码、媒体处理和排序成本。按时间合并 N 个事件可用优先队列，主项为 `O(N log N)`；若已排序，则合并成本可降低。保存完整副本和审计事件的空间随实际记录及媒体引用增长，不能把负载准备视为免费。

## 会话副本怎样保持因果顺序

取两回合单元：T1 在会话起点释放，模型服务时长设为 5 ms；T2 依赖 T1 完整回答成功提交，再等待 3 ms，服务时长设为 2 ms。本例无排队，只用于核对事件关系。

| 副本 | 起点 | 第一回合 | 第二回合 | 身份关系 |
|---|---:|---|---|---|
| C0 | 100 ms | 100–105 ms | 108–110 ms | `(C0,T2)` 依赖 `(C0,T1)` |
| C1 | 101 ms | 101–106 ms | 109–111 ms | `(C1,T2)` 依赖 `(C1,T1)` |

不能只抽 T2；也不能将 T2 固定放在起点后 3 ms，因为那时第一回合尚未完成。若候选系统让 C0 的 T1 到 112 ms 才完成，T2 应在 115 ms 后就绪。开放会话起点可以不变，会话内部请求到达却随真实完成改变；这与完全开放的逐请求时间轨迹是不同实验。

重放还要选择数据合同。固定回答 fixture 模式把原回答作为已声明的外部数据，在对应事件后才交给下一回合；它适合比较固定输入和依赖下的执行成本，不能证明新生成回答的质量或完整会话函数。真实闭环模式把本次实际提交的回答和工具结果写入下一回合，再重新计算模板、长度、缓存身份与停止边界；若内容改变，不能继续使用旧 x、y 或旧复用距离。

复制单元保留内部依赖规则，不保证保留原全局时间相关性。两个副本相互交错会改变缓存访问、热点与批形成。若目标是保持生产复用距离，应重放连续时间窗口及合法前置状态；若采用会话重采样，应报告这是另一种到达模型，并重新计算合并轨迹。

## 复用有时间结构

把合法逻辑块身份按访问顺序写为 `b_1,…,b_n`。在容量 C 个等大小块的完全相联 LRU 参考策略下，首次访问必然 miss。若 b_j 上次出现在 k，令

`Δ_j=|{b_(k+1),…,b_(j−1)}|`。

重复访问命中的充要条件是 `Δ_j<C`；C=0 时全 miss。这里的集合计不同身份，不计总访问次数。块身份必须包含父前缀和参与状态计算的条件，同一 token 段出现在不同历史中不能直接合并。

| 相同多重集的访问序列 | C=3 时 miss/hit | C=6 时 miss/hit |
|---|---|---|
| `A,A,B,B,C,C,D,D,E,E,F,F` | 6 / 6 | 6 / 6 |
| `A,B,C,D,E,F,A,B,C,D,E,F` | 12 / 0 | 6 / 6 |

第二条轨迹的重复访问之间有 5 个不同块，容量 3 无法保留。只统计“曾出现过”会错误报告 6 次命中。LRU 栈距离是独立参考，不能直接外推叶优先淘汰、CLOCK、亲和路由、未完成状态或不可淘汰块存在时的生产结果。

前缀命中省去的是相应输入位置的重算。新 suffix 仍读取命中前缀 KV；后续 decode 仍读取可见历史。命中在远端时，应比较

`T_remote≈目标排队+未重叠传输+恢复/就绪+尾部重算`

与本地重算路径。只提高目录命中率，可能同时增加热点排队和传输。PagedAttention 支持逻辑块映射、物理共享与写时复制；这不证明异步读者已结束，也不证明不同设备布局性能相同。

论文在其 A100、模型与轨迹条件下报告：ShareGPT 的 16–128 token 块较好，Alpaca 的 16 和 32 较好，最终选择 16。块越大，间接寻址与并行处理可能更有利，但页尾浪费和共享粒度也增大；这些结果不能变成跨负载常数。

## 按真实消费边界列计算账

以下限定普通因果稠密 decoder、单条生成分支、无投机和失败重试，x≥1；只缓存 KV 时恢复前缀 h≤x−1，未处理输入 q=x−h。每层每个 query head 的合法 query-key 配对数为

`P_pre=q h+q(q+1)/2`。

这是 q 个新 query 分别可见 `h+1,…,h+q` 个 key 的和。它不包括线性层、FFN、输出头或真实 tile 中被执行的无效位置。若另存合法末行 logits，可以采用不同恢复合同，并单独说明零输入重算路径。

prefill 末行 logits 已给出首个输出分布。正式选择第一个输出不会自动计算该输出自身的 KV。若最终选择 y 个 token，普通路径只需再消费前 y−1 个输出，最后一个终止或预算 token 无须为继续生成而前向。令 `m=max(y−1,0)`，则

`P_dec=Σ_(t=1)^m(x+t)=m x+m(m+1)/2`。

| x=10 的输出结果 | 后续消费 | decode 配对数 |
|---|---|---:|
| y=0 | 无选择、无后续消费 | 0 |
| y=1，首 token 为 EOS 或达到预算 | 首选择来自 prefill，不消费终止 token | 0 |
| y=3，第三个是 EOS 或预算末 token | 消费第 1、2 个输出 | 11+12=23 |

y=0 是否已经发生 prefill，由真实取消或预算检查事件决定：预算为零时可以在准备前结束，取消也可能发生在部分计算之后，不能仅凭 y=0 推断输入计算为零或完整。上式的 P_pre 只对实际完成所声明 q 个输入位置的路径计账，部分完成按事件列出真实 query。

普通 y≥1 路径结束时，已知 token 长为 x+y，已消费位置通常只有 x+y−1。若为了下一回合缓存显式补算最后一个 token，增加一次上下文长度为 x+y 的状态计算，并记入独立的 STATE_ONLY 成本；它不再选择或发送 token，也不能重新激活已终止请求。包含 EOS 的选中计数与不包含 EOS 的可见输出长度不能混用。

设每 token 全层 KV 字节为 `b_KV=2 N_layers N_KV_heads d_head s`，其中 s 是每元素字节数；量化尺度和其他状态另计。单请求每步全历史 KV 的唯一内容体积约为 `b_KV·(x+t)`，但多 query head 的请求流量、cache 重用和 DRAM 事务不同，不能把这个容量式直接称为硬件读取量。

统一 padding 的线性主项由 `Σx_i` 变为 `B max(x_i)`；执行完整方形 attention 时由 `Σx_i²` 变为 `B max(x_i)²`。若内核跳过无效 tile，浪费较小。长度分桶减少 padding，却增加等待、启动、变体准备和权重读取次数。缓存后应按待算 query 长和总历史共同分桶，不能仅使用原 prompt 长。

主机准备每请求耗费 c CPU 秒、到达率 λ、有效核预算 p 时，`λE[c]<p` 只是稳定性的必要条件。媒体解码、分词、路由和锁还可能竞争主存与线程。通信、复制和计算若重叠，应根据依赖关键路径估时；未重叠的传输、恢复、同步和排队仍需计入。

## 驻留按唯一物理对象计账

无共享、无请求外缓存、无页尾预留时，`Σ_i active_i(t)b_KV n_i(t)` 可描述活跃请求有效 KV 的逻辑容量；这里 n_i 是已消费位置数，不能用已选择长度代替。这个限定式无法表示共享前缀或请求结束后仍保留的缓存。

对设备 d，把物理对象身份记为 `p=(device,slot,generation)`，分配字节为 B_p。它可以是全层页组，也可以是某层/分片对象，但计账集合必须互不重叠。相同内容的两个物理副本仍算两份；同一页被两个请求映射只算一份。

采用四类保留责任：A 为请求映射，C 为缓存目录，R 为已提交读者/传输，W 为构造、复制或回收交接保留。请求完成只撤 A；目录淘汰只撤 C；设备操作完成才撤对应 R/W。直到协调回收点确认全部为零，页才回到空闲池；若回收处理被延后，该延后区间继续保留交接责任，不能从账上消失。

令 `U_d(t)` 为设备 d 上至少一种保留责任尚在的唯一物理对象集合，则

`M_live,d(t)=Σ_(p∈U_d(t)) B_p`，

`M_peak,d=max_(t∈[t0,t1)) M_live,d(t)`，

`I_d=∫_(t0)^(t1) M_live,d(t)dt`。

t 用秒时，I 的单位是 byte·s，`I/(t1−t0)` 才是平均驻留字节。离散事件间对象集合不变，积分可按各段字节数乘持续秒数相加。B_p 包含实际页槽、量化元数据与对齐；目录和页表自身另列。换出源、在途目标和远端副本按各设备实际对象分别计账。

若预分配固定池，`M_pool=M_free+M_live` 描述同一池的分解，不能把 M_pool 与其中的 M_live 再相加。设备分配峰值应统计权重、整个池、池外对象和同时存在的工作区；M_live 用来解释池内压力与可用容量，不等于分配器向设备申请的总量。

取页长 4、每 token KV 为 1 KiB，每页分配 4 KiB。共享前缀页 P 有 4 个 token，两个请求各有满的私有尾页 A、B。所有时间用秒，区间为半开区间。

| 时间区间 | 保留责任与事件 | 唯一物理驻留 |
|---|---|---:|
| [0,1) | 两请求都映射 P，各映射 A/B；目录保留 P；A 还有在途读者 | P、A、B，共 12 KiB |
| [1,2) | 两请求结束，所有请求映射撤销；P 的目录和 A 的读者仍在 | P、A，共 8 KiB |
| [2,4) | A 的最后读者完成；P 仍在缓存 | P，共 4 KiB |
| [4,5) | 淘汰 P，目录保留撤销并完成回收 | 0 |

峰值为 12 KiB，积分为 `12×1+8×1+4×2=28 KiB·s`，五秒平均为 5.6 KiB。逐请求求和在第一段会得到 16 KiB，因为共享页 P 被重复计入；请求结束后又得到零，漏掉缓存和在途读者。只按 A/C 而忽略 R 的模型在 [1,2) 会得到 4 KiB，仍然错误。这里的在途模型证明计账责任，不能证明真实 GPU 的完成事件或可见性实现正确。

## 模态具有独立几何

Qwen2.5-VL 固定报告 §2.1 与表 1 描述：图像高宽准备为 28 的倍数，patch 步长为 14，空间相邻 2×2 个 patch 特征合并后投影到语言模型。32 个视觉层中有 4 层使用全 attention，其余使用最大 112×112 像素、即 8×8 patch 的窗口；边缘小区域不强制 padding 到满窗。

对满足上述处理后尺寸合同的单图，忽略特殊 token 和额外裁剪：

`n_patch=(H/14)(W/14)`，`n_vis=(H/28)(W/28)`。

若第 w 个窗口有 n_w 个 patch，每个视觉 query head 的 attention 配对主项为

`4 n_patch²+28 Σ_w n_w²`。

完整视觉成本还包括投影、FFN、位置与 merger。H×W 相同只固定 patch 总数，未必固定窗口配对数。例如 56×224 与 112×112 均有 64 个 patch、16 个合并视觉 token；前者有两个 4×8 patch 窗，窗口配对和为 `2×32²=2048`，后者一个 8×8 窗为 4096。全 attention 配对相同，窗口部分不同。这是在声明窗口网格下的逻辑反例，不是两种图像在真实设备上的速度测量。

448×672 的设定图像产生 32×48=1536 个 patch、16×24=384 个 decoder 视觉 token。加 512 个文本 token 得到 896 个输入位置。再预留 256 个输出位置时，上界为 1152；这个预留不是普通生成结束时已消费 KV 的精确长度。

按报告 7B 配置的 28 层、4 KV heads、head size 128，并设 BF16，每 token KV 为 `2×28×4×128×2=57344` 字节，即 56 KiB。896 个输入位置的有效 KV 为 49 MiB，1152 位置预算为 63 MiB，尚未包含页尾、元数据、工作区和分片差异。普通路径若实际选择 256 个输出而未补算最后一个，结束时通常只消费 1151 个位置。

若 1536 个 1280 维 BF16 patch 特征、384 个 3584 维 BF16 合并特征和 448×672×3 的 FP32 像素同时存在，三者分别约占 3.75、2.625 和 3.445 MiB，共约 9.82 MiB。这不是整模型峰值，只说明媒体、视觉和语言阶段不能只按文本长度预算。

视频还包含时间 patch、帧分组与绝对时间位置；报告讨论两帧分组、动态 FPS 与时间对齐，单图公式不能直接当作完整视频 token 合同。视觉特征缓存绑定媒体内容与 processor；decoder 前缀缓存还绑定桥接特征、模板与位置。调整分辨率、crop 或抽帧规则后，应重新计算受影响输入和身份。

## 为不同推理家族建立负载档案

| 负载 | 至少保留的联合变量 | 容易误造的理想条件 |
|---|---|---|
| 多轮与 Agent 调用 | 回合依赖、历史增长、思考/工具时间、分支宽度 | 把依赖调用全部并行，或假设会话永不淘汰 |
| RAG 与 reranking | 查询、候选数、文档长度、过滤与索引版本 | 只测热向量索引，不计取文档和重排 |
| 离线批生成 | 批任务大小、期限、输入/输出联合长度、质量 | 只计算最快子集，忽略排空尾部 |
| Embedding | 文本/图像长度、batch、向量维度、pooling 与归一化 | 固定极短输入，却外推完整数据集 |
| 推荐 | 稀疏特征数、表大小、热门度、重复 ID、dense 部分 | 所有 embedding 行都留在 cache |
| 图推理 | 节点/边、度分布、邻居展开、采样与特征局部性 | 用均匀小图替代真实高阶节点 |

这些变量决定不同执行图，不能共用一个自回归输出长度模型。Embedding 的主要输出是向量；交叉编码器重排按实际候选句对工作；推荐中的重复 ID 有次数语义；图推理的唯一读取节点与实际消费边数不同。MoE 还应保留内容与专家路由的相关性：同样 token 数可以触及不同专家和远端目的，不能直接用平均 active fraction 代替权重读取与通信。

## 分层、校准与保留集合

分层优先保留改变执行或服务约束的交界，例如短交互、长文档、长输出、共享提示、多模态和取消密集。在层内保留联合记录及依赖单元，报告每层单元数、请求数、权重来源和空层。单元采样比例不等于请求比例；长会话被抽中一次会贡献更多请求。

页长前后、窗口 rollover、图桶边界、最大上下文、模板和停止边界适合机制验证；容量评估还要保留真实长尾、交错和持续时间。只用边界样本或只用平均长度都不足以代表容量运行点。

取消经常与等待、历史和工具失败相关，慢客户端会改变输出缓冲和 KV 驻留。将取消改成独立均匀事件，可能保留总取消率却改变高压状态。应记录条件规则或风险模型，并对等待相关与独立取消做敏感性分析。

开发集用于候选选择；量化校准集用于相关激活分布；保留集在候选与评分规则冻结后检验泛化。看过保留结果再调整权重或参数后，该次结果不再充当独立确认。只存在一个 synthetic workload 时，结论限于其分层、权重、依赖和复用轨迹。

比较优化版本时定义联合 goodput：

`G=(1/T)Σ_i 1(完成_i ∧ 质量_i ∧ TTFT约束_i ∧ ITL约束_i)`。

TTFT 与 ITL 各有 95% 合格率，并不保证同一 95% 请求同时合格。输出因提前 EOS、预算缩短或错误而变短时，吞吐上升首先意味着工作量变化；应固定任务合同并报告质量、实际长度、失败与未完成，才能判断执行优化。

## 条件变化后的保留、调整与放弃

| 变化 | 可保留 | 必须重算 | 放弃旧结论的条件 |
|---|---|---|---|
| 模型、模板、tokenizer、processor、位置或停止合同变化 | 原始消息和媒体 | 规范输入、输出边界、缓存身份与校准覆盖 | 旧 token 或状态身份不再对应同一函数 |
| 依赖、思考时间或真实生成内容变化 | 原始会话结构和业务目标 | 输入构造、就绪事件、全局交错与复用距离 | 旧固定输入轨迹不能代表新闭环 |
| 缓存容量、淘汰、路由或回收协议变化 | 逻辑输入与外部到达 | 物理命中、传输、唯一驻留与最后使用 | 高命中不再减少关键路径或容量不足 |
| 批形成、桶或到达方差变化 | 请求 shape 与服务目标 | padding、等待、变体准备和峰值 | 均值相同却因联合结构使选择反转 |
| 分辨率、crop、FPS 或窗口变化 | 媒体源和时间顺序 | patch、视觉 token、窗口与位置 | 旧几何不再代表实际工作 |
| adapter、grammar、分支、精度或取消变化 | 任务语义与独立参考 | 状态身份、字节、校准、完成与质量 | 旧等价性、容量或 goodput 条件失效 |

热点消失、复用变稀、缓存保留时间增大或远端排队超过省下的计算时，应放弃相应缓存性能结论。保留的是合法性不变量与原始证据，调整的是负载模型和资源参数，性能结论随其前提重新验证。

## 竞争解释与区分实验

| 观察 | 竞争解释 | 可区分的干预与反证修正 |
|---|---|---|
| 前缀缓存后吞吐提高 | 少算 prefill；重复排列更有利；输出更短；排队改变 | 固定请求群体和停止合同，只改变缓存容量，记录命中位置、重算 query、排队和驻留；若计算未减少，撤回少算解释 |
| 平均长度不变而尾部变差 | 方差、相关性、padding 或批形成改变 | 保持边际而置换输入输出配对，再固定/改变批顺序；联合结构改变才产生差异时，均值模型被反驳 |
| 多轮负载吞吐异常提高 | 合法加速；第二回合提前释放；缺祖先；fixture 代替真实回答 | 检查每条依赖的实际满足事件与输入来源；孤立 T2 和起点后 3 ms 释放必须失格，再比较合法轨迹 |
| y=1 仍被记一轮 decode | 首选择与消费混淆；显式状态补算；重试 | 对照首 token 为 EOS、预算 1 和 STATE_ONLY 三条轨迹；没有消费事件时 decode 前向应为零 |
| 请求结束后显存不降 | 缓存保留、在途读者、预留池或泄漏 | 分别撤请求、目录和最后读者，比较唯一存活对象与整个池；只在责任全撤后仍无法解释的对象才支持泄漏判断 |
| 图片数或面积相同但视觉阶段变化 | patch/窗口、aspect ratio、processor 或位置不同 | 固定内容来源和文本，扫描处理后几何；分别记录窗口配对、全 attention、准备与质量 |
| 取消率相同而驻留不同 | 取消与等待相关；慢客户端；清理延迟 | 保持边际取消率，对比等待相关和独立规则；驻留变化反驳独立取消足以代表生产的假设 |
| chunk 吞吐变化但 token 工作不变 | 分块、编码、stop 或网络缓冲变化 | 同时记录正式 token、chunk、可见字节与事件；不能由 chunk 数反推模型消费 |

随章检查用有限 CPU 模型核对拒绝状态、会话副本、消费边界和唯一物理驻留；另以列表 LRU 对照栈距离、按 patch 坐标合并对照视觉网格，并比较联合 goodput 与完成吞吐。错误负对照分别恢复拒绝落入、孤立/过早第二回合、重复计首输出、逐请求容量及忽略最后读者，必须被同一不变量或独立参考检出。

这些检查不执行真实 tokenizer、processor 或模型前向，不证明 GPU 同步、访存事务、通信重叠、生产调度性能或 Agent 使用效果。局部模型通过后仍须在目标制品、事件采集和硬件上验证相应主张；反证先定位单位、身份、事件与分母，再修正实现或缩小结论范围。
