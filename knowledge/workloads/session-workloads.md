# K-WORK-010：多轮与分支负载：依赖、状态驻留和到达过程

一组独立 prompt 不能完整描述聊天、工具调用和分支推理。后续请求的输入、到达时间与缓存身份可能取决于先前输出；这些依赖改变可并行工作、状态驻留和性能评价。需要同时保存三本账：业务依赖与提交账、物理访问责任账、包含失败和未完成者的测量人口账。

## 会话身份、输入和事件合同

会话 s 保存已提交历史、模型与 processor 契约、用户可见顺序和分支集合。请求实例记为 r=(s,β,k,g)：β 是分支，k 是逻辑调用序号，g 是尝试代次。重试增加尝试，不增加逻辑任务数；边必须绑定接受哪次尝试的哪个输出版本，不能在旧尝试完成时偷偷切换消费者身份。

把生成、工具、检索和质量判断写成有限 DAG G=(V,E)。一条边 d=(edge_id,u,v,e,w) 指定消费者 v 所需的生产者 u、事件类型 e 和非负等待 w。edge_id 区分同一对节点之间的不同要求。本章核心算法采用全部必需边都满足的 AND 合同；quorum、竞速选胜者和动态扩图需要另加共同选择事务，不能只把必需计数减小。

固定契约 C 包含权重、tokenizer、模板、位置与 mask、数值表示、processor 和工具版本。输入为

x_v = Build_C(分支历史快照, 各必需边绑定的已发布载荷, template_v)。

Build 必须按声明的角色、边顺序及版本构造输入。FIRST 消费者只取得该事件冻结的首内容快照，不能因为上游稍后产生更多内容而原地改变已经启动的 x_v。需要持续增量消费时，应另定义流式输入协议。历史截断、压缩和模板变化可以是应用策略，但必须进入 workload 合同；不能作为隐藏的性能优化。

事件身份采用 κ=(生产者完整实例,事件类型,输出版本)。同一 κ 的载荷、输入身份及发布时间不可变；重复通知只引用原记录。相同身份而载荷不同属于冲突。时间相同的两条记录仍需协调域内的递增序号 σ：消费者必须看到序号更早的发布证据，不能仅检查两个时间戳满足非严格不等式。

| 事件 | 生产和发布条件 | 消费范围 |
|---|---|---|
| FIRST | 生成执行器已得到首个可发布内容；必要前向、采样、decoder 和停止检查完成，内容及可见性已确认 | 冻结的首内容；空角色消息、原始 logits、未确认 token 不是 FIRST |
| FULL | 生成或检索节点达到规定完整输出边界；全部所需输出与实际承诺的模型状态范围完成并可见 | 完整输出快照；最后已采样 token 的 KV 是否存在另记 |
| TOOL_OK | 工具调用成功，结果 schema、调用身份、工具版本及规定的副作用确认条件满足 | 对应调用的成功结果；收到响应或超时不自动构成成功 |
| QUALITY | 独立评价节点消费了指定输出版本，并发布满足既定质量合同的证书 | 被证书绑定的输出版本与评价条件；不能泛指生产者任意结果 |

质量判断本身可以是一个节点，其输入边绑定被评价输出；本章不实现真实语言质量评价。工具的网络结束、幂等键与外部副作用恢复也由工具适配器承担，适配器必须提供上述明确证据。

业务状态为 BLOCKED、READY、RUNNING、COMMITTED、FAILED、CANCELLED。后三者不可逆；FAILED 可以带 EXECUTION_FAILED 或 DEPENDENCY_IMPOSSIBLE 等原因。FIRST 发布后生产者仍为 RUNNING，后续失败或取消不撤回已经合法发布的 FIRST。只有全部最终提交所必需的结果成功完成且可见，最终事件才具有共同提交资格；在同一事务中发布该事件、安装 output[v]、状态快照与 COMMITTED，再通知消费者。最终事件不能绕过共同提交门，以普通非最终成功事件的身份提前发布。COMMITTED 后收到取消，只关闭该分支未来服务意图，不把本节点改成 CANCELLED。取消先于提交时，未发布候选被拒绝；提交先于取消时，已发布证据继续存在。

操作访问结束和业务结果成功是两个独立结论。一个失败操作可以已结束全部物理访问，但无法产生所需输出；这时应结算该操作的责任，并使当前尝试进入 FAILED。已经取得访问权的其他操作继续排空，不能把它们一起判为完成。本章选择确定失败后不在当前尝试内自动恢复；重试需要新尝试身份、输入和输出版本选择以及真实后继事件，不由一次迟到成功通知隐式恢复。

合法性要求图无环、边事件及尝试版本确定、必需输入可重建、分支可写状态隔离、失败传播有终止规则、到达模式及完成边界明确。缺失前一轮却重放后一轮，或者只按会话 ID 复用状态，都不能满足这些条件。

## 缓存身份、已知输入与已计算状态

缓存命中要证明计算等价。前缀身份一般包含 C 中实际影响前向的条件、规范输入 token/特征、位置、adapter、模态内容和隔离命名空间。索引哈希只负责查找候选；采用概率性身份时还需说明碰撞合同。采样配置通常不改变给定前缀的 KV，但已经采样出的 token 已进入后续前缀。

vLLM 固定文档的块身份包含父块哈希、本块 token 和额外条件，并且只缓存完整块。这支持父上下文必须进入身份的机制解释；不意味着会话中的部分尾页只能重算。会话 fork 可以另外选择复制已完成的部分尾页，但这是本章的 COW 路径，不能归称为 vLLM 文档中的完整块缓存命中。

命中还要求实际物理副本仍驻留、句柄代次匹配、全部必要层或状态族完成、消费者可见并取得保护。目录有身份不等于有可立即读取的副本。模型、位置规则或状态格式改变后必须重新检查恢复资格；对递归或窗口覆盖状态，只有 KV 长度通常不足以证明可以恢复。

已知 token 长度 n、全层已完成 KV 边界 c、可写容量和末行 logits 是不同状态。仅存 KV 而未存末行 logits 的生成路径，安全可跳过上限通常为 n−1；完整页缓存还需向下取合法页边界。最后已知位置在私有写区重算，不能覆盖共享尾页。若保存相容的末行 logits，可以选择另一恢复合同，但必须绑定完整输入、数值策略与采样状态。

本章将模型内部推进委托给[连续批处理](../algorithms/iteration-batching.md)及[分块 Prefill](../algorithms/chunked-prefill.md)的算法。接口必须交付：已知输入、已确认状态边界、每轮实际读写范围、全层完成和可见性证据、正式输出序号与停止原因。主机已提交 kernel、某一层完成或最后 token 已发送，都不能替代该接口。

## 回合长度与分支物理容量

完整保留历史、暂不计模板和工具内容时，第 k 轮输入长度为

n_k = S + Σ_{j<k}(U_j+A_j) + U_k。

S、U_j、A_j 的单位都是 token 位置。若每轮 prompt 已完整消费，且回答采用最后一个已采样 token 尚未消费的路径，则轮末

c_k = n_k + max(A_k−1,0)。

下一轮新增 prefill 为 n_{k+1}−c_k，前提是输入构造未改写旧前缀且这些状态仍可恢复。A_k=0 的上述公式只适用于 prompt 确实完成的路径；输出上限为零而直接结束、未执行 prompt 的请求不能据此认定 c_k=n_k。

设 S=100，每轮 U=20、A=30，共三轮。完整 prompt 为 120、170、220，无跨轮复用时共 510 个位置；保留状态后新增 prefill 为 120、21、21，共 162。误把前两轮全部回答 KV 当成已算，会得到 160。提前补齐末 token 只把两个位置移到另一阶段，没有消除工作；回答生成的 decode 工作还需另计。

设前缀长 L，分支 j 追加 t_j 个实际消费位置。理想共享可以把前缀的重复计算位置从 bL 降为 L，但分支后缀仍分别执行 attention、投影和采样；共享容量不等于分支读取流量只剩一份。

为计算容量，定义逻辑页长 P，单位为位置；每位置全层 KV 字节为 τ，固定页组字节 B=Pτ，必要对齐、scale 和页元数据另计。pages(n)=ceil(n/P) 仅表示页数，不能直接与字节相加。本节选择全层页组来简化记账；真实部署应按每设备的状态分片分别核算。

任何布局都可以使用物理对象并集：

M(t)=Σ_{x∈A(t)} bytes(x)，M_peak=max_t M(t)。

A(t) 包含已分配状态、预留、COW 目标、源页、工作区、输出与在途缓冲；同一 backing 只计一次。不同物理副本即使内容完全相同，也各计一次。若已经把整个预留池计为设备占用，不再把池内对象重复相加；准入则需要池内真实可分配容量。

只有当前缀页对齐、没有额外副本、尾部预留或在途源页时，才可写状态页数为 L/P+Σ_j pages(t_j)。未对齐时令 q=floor(L/P)、u=L mod P。若每个追加分支都复制原尾页的 u 个有效槽并在私有页中连续追加，则在源尾页仍受保护期间，状态页数为

N_peak = q + 1(u>0) + Σ_{j:t_j>0} ceil((u+t_j)/P)。

未追加的分支仍引用原尾页。只有 u>0、所有分支均已转到自己的私有尾部、源页无其他拥有者且最后访问结束时，原尾页才可再减一页；源页保留于缓存或其他快照时不能减。u=0 时私有部分自然退化为 ceil(t_j/P)。这些计数未包含状态之外的工作区和输出。

取 P=4、L=3，两个分支各追加四个位置。原页 S 的有效槽为 [p0,p1,p2,空]；A 的两个私有页为 [p0,p1,p2,a0]、[a1,a2,a3,空]，B 对应为 [p0,p1,p2,b0]、[b1,b2,b3,空]。复制和旧读者尚未结束时，S、A0、A1、B0、B1 共五页，即 5B。两份复制分别读、写三个有效槽，合计源读 6τ、目的写 6τ，新增八个位置另写 8τ。若复制实现按整页搬运，读写各为 2B，不能继续沿用有效槽字节量。只有 S 的最后持有和实际访问都结束后才降至四页；不能在预留四个目的页之前拿这个未来释放支付准入。错误的 pages(3)+2pages(4) 只有三页，会放行无法容纳过渡峰值的方案。

## 到达、时间门与等待驻留

每个节点都保存外部时间下界 a_v，根节点和非根节点一致。对边 d，令 t_d 为绑定事件真正发布的时间，w_d 为从发布起算的等待间隔，n_d 为通知实际被接收的时间。全部必需事件已发布时，理想时间下界为

r_v = max(a_v, max_{d进入v}(t_d+w_d))。

本章消费者通过通知取得证据，因此实际启动还需满足

start_v ≥ max(a_v, max_{d进入v}(t_d+w_d), max_{d进入v} n_d)。

无入边时内部最大值省略。若通知延迟为 ℓ_d，且恰在 t_d+ℓ_d 到达，单边约束为 max(t_d+w_d,t_d+ℓ_d)，而不是 t_d+w_d+ℓ_d。等待从发布时间起算，传输和等待可以重叠。若应用要求收到通知后再思考，应显式采用另一合同 n_d+w_d，不能混用两种定义。

例如 U 在 1 发布 FULL，通知延迟 3，V 的等待为 2，外部下界为 0。等待在 3 到期，通知在 4 到达；无资源争用的 eager 模型在 4 启动 V。将两个门串加会错误要求 6。反过来，通知在 2 到达、等待在 6 到期时，应登记时刻 6 的唤醒；不能只检查一次等待未到期就停止。

FIRST、FULL 和质量事件的发布时间可以不同。A 在 1 发布 FIRST、4 发布 FULL，B 需要 FIRST 后等待 2 且通知立即到达，则最早在 3 启动；C 需要 FULL 后等待 2，但自身外部下界为 10，则最早在 10 启动。不能统一使用生产者最终完成时间。

严格闭环用户在本轮完成后思考 Z，再产生下一轮计划；稳定、同一人口且每用户只有一个未完成请求时，N≈λ(R+Z)。服务变慢会降低该生成器的流率。开放模式的 a_v 来自外部计划，不能随响应变慢后移；可以开放产生会话起点，并在内部保留依赖和思考时间。有限观察窗需要同时报告 offered、started、committed、failed、cancelled 和仍未完成者，不能只统计成功人口。

等待驻留使用字节时间积分。对窗口 [l,h)，按唯一物理对象 x 取其等待保留区间与窗口的交集，有

R_wait = (1/(h−l)) ∫_l^h Σ_{x∈WaitingPhysical(t)} bytes(x) dt。

同一页被多个等待者持有仍只计一次。若按会话分别记录 m_i(t)，必须采用不重复的物理归属分摊，才能直接求和。活跃、等待、在途是责任标签；同一物理页具有多个标签不增加容量。

等待 0–2 秒保留 4 MB、2–3 秒保留 6 MB，在 0–5 秒窗口的平均为 14/5=2.8 MB。将两个大小的算术均值 5 MB 乘三秒得到 3.0 MB，不符合该轨迹。窗口前已进入或窗口末尚未离开的等待也要按交集积分。只有稳定进入率为 λ_w、每段固定保留 K 字节且平均等待为 τ_w 时，才可简化为 λ_w τ_w K；可变大小的一般式是 λ_w E[∫m(t)dt]。

## 依赖推进、发布和取消回收算法

以下是一种保守设计：固定 AND DAG、每节点只启动一次、分支写区私有、共享页不可变，所有事务由同一协调域串行处理。并行实现需提供等价的线性化关系。算法不要求固定的排序策略；公平、deadline 和解除下游依赖都可以参与合法候选的排序。

业务账保存 state、started、output、固定输入身份、事件账 Published[κ]，以及按边保存的 satisfied[edge_id]=κ。另有本代候选账 Candidates[κ] 和成功完成证据账 Success[uid]：最终操作可以已经产生载荷，而其共同提交所需的其他结果尚未到齐。此时保留不可变候选及其必要逻辑持有，不把暂时不具备发布资格当作丢弃候选。物理账中，每个分配对象 x=(slot,epoch) 保存逻辑拥有者 L_x、尚未结束的访问票据 U_x、借用输出的消费者 O_x，以及实际存在的长期绑定 B_x 和隔离原因 Q_x。私有预留也是逻辑持有，不能在完成通知与发布之间失去保护。

本节固定执行描述给出最终提交必需的结果集合及其完成、可见性合同。事件类型为 FULL 不表示生产该载荷的操作必定最后结束；没有业务事件的辅助操作也可能属于共同提交的必需集合。检查模型在启动时冻结这组操作，允许辅助完成早于、同刻或晚于最终载荷。需要动态扩展该集合的实现须在发布前明确更新合同，不能把新增必需操作留到已经承诺完成之后。

票据包含请求/尝试、分配代次、uid、字节范围和读写种类。先登记再启动。完成证据必须覆盖该票据的最后访问；两个票据不能由同一重复通知互相抵消。epoch 能拒绝旧回调修改新元数据，但不能阻止旧 kernel 或 DMA 写同一个地址，因此仍须等待物理排空。

本章检查模型采用明确的同刻组织：按外部取消、操作完成、通知、时间唤醒的优先级处理，同类事件按稳定节点及操作身份排序。同一时刻的外部取消逐条处理，每条取消引起的失败传播仍在该事务内立即闭合；这些同刻取消全部处理完前，禁止启动新节点，随后恢复每条事件后的 eager 调度。已运行节点的责任保留与终态不受这一启动屏障改写。零时长操作只能在实际启动后产生完成，记录序号仍保存因果顺序。这是所选检查模型的保守组织方式；逐事件处理后立即调度也可以构成另一合法服务合同，但其参考必须同步建模，不能直接与本章精确启动轨迹混比。真实协议提供更细因果序号时，应采用真实序号。

```pseudocode
算法 ReplaySessionDAG
输入：有限 DAG、完整节点/边身份、固定合同 C、全部 a_v 与 w_d、
      外部取消/失败事件、容量与保留策略、执行适配器、观察截止 H
输出：业务终态与输出、不可变事件账、启动/提交轨迹、物理责任和未完成原因

初始化：
  校验图无环、身份唯一、必需事件有生产接口、版本绑定明确、等待非负
  对每个 v：state=BLOCKED，started=false，output=空，satisfied=空
  earliest[v]=a_v；timer_version[v]=0；容量等待集合为空
  Published、Candidates、Success、已结束票据、待回收集合为空
  为所有节点登记外部时间门；建立完成、通知、取消及容量事件的真实来源
  队列按时间、固定类型顺序和稳定身份处理；每条审计记录另取递增 σ

RECONSIDER(v, now)：
  若 v 为 COMMITTED/FAILED/CANCELLED 或 started=true：返回
  若某必需事件尚未收到合格通知：state=BLOCKED；保留通知监听；返回
  earliest[v]=max(a_v, 所有已满足边的发布时间+w_d)
  若 now<earliest[v]：
    state=BLOCKED；更新 timer_version，登记实际 WAKE(v,version,earliest)
    重复相同唤醒可以合并，但不能删除唯一有效唤醒；返回
  state=READY；进入唯一的就绪集合

PUBLISH(v,e,version,candidate)：
  在协调事务中：
    若 κ 已存在且载荷相同：返回原记录，不重复安装或发出新业务提交
    若 κ 已存在但载荷冲突：报告错误
    检查 v 仍 RUNNING、尝试/输入/输出版本相符，候选满足该事件合同
    检查本事件承诺范围成功完成且对消费者可见；失败或取消候选不能发布
    若 e 是最终事件：
      另外要求全部最终提交必需结果成功完成且可见、提交授权仍有效
      不满足则保留 Candidates[κ] 及其保护，返回 PENDING；不安装 output 或 COMMITTED
      不能转入非最终事件发布路径绕过此门
    为事件载荷及实际消费者取得持有，再交接生产侧保护
    安装 Published[κ]=(载荷,版本,发布时间,σ,必要状态描述)
    从待发布候选账移除已发布的 κ，避免重复发布
    若 e 是本节点的最终事件：安装 output[v] 与正式状态，state[v]=COMMITTED
    FIRST 只安装首内容记录，保持 RUNNING
  事务结束后向各出边投递可重放通知；输出借用者启动前登记 O

  若 v 不再 RUNNING 或提交授权失效：返回，不恢复旧候选资格
  先检查本代已保留的非最终候选，满足各自事件合同者尝试 PUBLISH
  若本代最终候选存在，且全部最终提交必需结果均成功完成并可见：

  尚缺结果则继续保留候选，等待已登记的必需完成；不得依赖最终操作重复通知

  若该边已满足：要求身份一致，幂等返回；冲突则报错
  否则保存 satisfied[edge_id]=κ；只在首次合格通知时结算该边
  不按生产者当前是否取消或失败删除已经发布的证据
  调用 RECONSIDER(消费者,now)，由统一门检查终态和启动资格

  否则撤销未来操作启动与业务提交资格，设置 CANCELLED/FAILED
  放弃本代尚未发布候选，解除其业务保留；已经取得物理访问权的责任仍独立排空
  移出就绪和容量等待集合，撤销尚未取得启动资格的后续工作
  撤销 v 自己的逻辑持有，不删除任何已经取得访问权的 U/O/B/Q

  私有页若仍有 U/O/B/Q，放入待回收集合，继续计占用；不得归还 free
  共享页也按完整物理资格处理，不能仅因本请求引用减少就回收
  对各出边检查：生产者已终止且某必需事件从未发布时，

    传播在当前事务内闭合；已发布事件仍可满足其消费者
  对相关对象执行 TRY_RECLAIM

  容量变化重验登记的等待者，不依赖下一次无关请求碰巧唤醒

  成功取得启动资格：started=true，state=RUNNING，冻结执行描述

  确定未启动的部分可凭证据撤销登记；接受状态未知的部分继续保护

  已结束且身份匹配的票据：返回 DUPLICATE，不重复结算
  未知、旧代次、范围不符或缺少最后访问证据：保留当前责任并诊断

  只解除由该票据缺失证据产生的隔离原因
  单独判断业务结果，不把访问结束当成结果成功：

      若它产生业务事件载荷，将本代不可变候选保存到 Candidates，不覆盖已有身份
    若确定失败使所需产物无法完成：
      标记失败范围不可发布；在当前协调事务内调用 FAIL(v,EXECUTION_FAILED)

  若 v 已终止：只结算物理责任，不发布未提交候选，不改变原业务终态

  对相关对象执行 TRY_RECLAIM；真实容量增加后发出 CAPACITY_CHANGED

  仍有缓存/事件保留者的对象继续驻留；淘汰先撤目录并释放对应持有

循环按序处理真实事件，每条事件的失败传播立即闭合：
  若同刻仍有外部取消，继续处理取消，不调度新节点
  同刻取消全部处理完后恢复 eager 调度；其后每条事件后重新调度

  最终发布具有共同提交资格、确定执行失败及时终止并传播、
```

FAIL 的传播检查生产者是否从未发布所需事件，不能只看通知是否收到。上游已经发布 FIRST、随后 FULL 失败时，需要 FIRST 的后继仍可接收迟到通知并启动；需要 FULL 的后继立即 FAILED。AND 消费者若已经启动，则其所有必需快照已经取得，本章的不可变事件合同不因生产者后来失败而使这些快照失效。

终态保留按确定顺序执行。例如 U 在 1 被取消，FULL 从未发布，V 必需 FULL，则 V 在同一事务中 FAILED；V 在 2 收到自己的取消命令时保留 FAILED。若 V 在 0.5 已取消，则后来的依赖失败保留其 CANCELLED。同刻时遵守已声明的稳定次序：先处理 U 的取消并传播，就不能让随后 V 的取消覆盖 FAILED；先处理 V 的取消则保留 CANCELLED。参考检查也必须推导依赖不可能发生的时刻，不能仅凭“取消计划中有 V”选择终态。

启动屏障不合并上述取消事务。例如 U 在 1 已成功提交 FULL，V 依赖此事件、通知延迟为零且 a_V=2；U、V 都在 2 收到外部取消。先处理 U 的取消时保留其 COMMITTED，V 的输入证据仍存在，但此时不启动 V；随后 V 的取消使其在未启动状态进入 CANCELLED，再恢复调度。轨迹因此只有 U.start=0，终态为 U 在 1 COMMITTED、V 在 2 CANCELLED，V 从未登记操作责任。若改成两条取消之间立即启动，V.start=2 后再取消也可能满足另一服务合同，但会产生额外在途操作和驻留，不能只比较最终状态就称两条轨迹相同。

最终资格还必须独立于候选排序。单节点 U 的唯一 FULL 操作在 1 确定失败时，参考只能产生该时刻的 FAILED 候选，不能同时无条件产生同键 COMMITTED 再依赖插入顺序裁决。若 U 的 FULL 操作在 1 成功、另一必需操作 TAIL 也在 1 失败，即使稳定操作身份使 FULL 的完成记录先到，FULL 也不具备共同提交资格，不能发布或安装 output；TAIL 随后立即确定 FAILED。相反，非最终 FIRST 若已满足自身合同并在失败之前合法发布，应继续保留。独立参考因而先判断最终资格，再建立 COMMITTED 候选，并把最终事件发布绑定该资格。

对应的全成功路径同样需要闭合：U 的 TAIL 与 FULL 操作都在 1 成功，稳定身份使 FULL 完成先到。此时保存 FULL 候选，仍保留其载荷及状态保护；TAIL 完成后先发布满足自身合同的 TAIL，再由同一次完成处理重新检查已保存 FULL，时刻 1 安装 FULL、output 和 COMMITTED。完整顺序是 FULL 成功证据 → TAIL 成功证据 → TAIL 局部发布 → FULL 共同发布，最终发布恰好一次。只在 FULL 自己的通知上检查共同资格会遗漏这个后继，不能靠改名字使 FULL 恰好最后完成来修复。

辅助操作没有业务事件，也必须触发这次重查。例如 FULL 载荷在 1 就绪，必需复制在 3 成功，则最终发布时间为 3，依赖 FULL 的消费者从 3 起计算通知和等待门；此前合法 FIRST 的发布时间不变。如果在复制结束前或同刻按选定取消顺序撤销资格，放弃未发布 FULL，保留已发布 FIRST；复制仍按自己的责任完成并排空，不能使请求复活。

对这个固定偏移、无资源争用的检查模型，令每项必需操作 u 的完成键为 c_u=(start+offset_u,操作完成优先级,节点身份,uid)。只有全部必需结果成功才有最终提交候选，其键取 C=max_u c_u，而非最终载荷操作自己的 c_final。局部非最终事件在自己的成功证据后发布；最终发布在 C 对应的最后成功证据及本事务的局部发布之后发生，可用附加局部序号区分。最终发布时间是 C 的时间分量。即使所有时间分量相同，顺序仍必须证明最后一项必需证据已经到齐。这个参考从静态操作集合推导 C，审计器另外从实际唯一 COMPLETE 记录的顺序重建最后证据，二者不共享候选状态或调度计数。

取消分支的入口先列出该分支尚未终止的节点，再逐个执行取消；它不等于取消同一父节点的所有子节点。取消或失败前已经发布的事件按既定保留策略继续存在；需要撤销应用结果时，应另有显式补偿协议，不能改写不可变事件账。

在途取消的一条完整轨迹如下。A 持有私有页 P，并与兄弟 B、缓存共同持有共享页 S。copy 和 kernel 都已登记对 S/P 的责任，B 另有对 S 的读者。A 取消后只撤销自己的逻辑持有，P 进入待回收；新请求 C 申请 P 必须等待。copy 完成只结算 copy，kernel 仍可能写 P；重复 copy 完成不减少 kernel 责任。kernel 最后访问结束后，P 才能以新 epoch 分给 C。此后 kernel 的重复通知不能扣除 C 的持有。S 即使撤掉 B 与缓存的逻辑引用，也必须等 B 的实际读者结束。

确定失败的组合轨迹则是：U 已 RUNNING，模型票据 m 与辅助票据 z 都登记了对私有缓冲 P 的访问。时刻 2，m 返回完整最后访问证据但结果失败。协调器删除 m 的 U，立即将 U 置 FAILED，撤销未来提交和自己的逻辑持有；缺失 FULL 的必需消费者 V 同刻 FAILED。z 仍在途，P 继续占用，新申请不能复用它。时刻 5，z 成功结束，只删除 z 的 U，不发布 U 的 FULL、不恢复 U 或 V；无其他持有时 P 才可回收。若 m 是最后一张票据，则时刻 2 同时达到业务失败与该缓冲可回收边界；仍必须记录 FAILED，不能留下 RUNNING 再将其误报为容量停滞。

## 条件化成本和策略反转

| 成本 | 同一会话范围内的账目与条件 |
|---|---|
| 计算 | 新增 prefill、逐分支 decode、重算、输入构造及事件处理。前缀共享减少重复前缀计算，不消除分支自己的顺序生成；失败前已经执行的工作仍计费 |
| 访存 | 权重、各分支历史 KV 读取、新 KV 写入、COW、页表与事件载荷。唯一容量与每分支逻辑读取分开；实际 DRAM 事务还取决于 kernel 和 cache |
| 通信 | 请求、流式内容、工具结果、取消与完成消息、跨设备状态和模型并行通信。单设备本地共享没有必然的 KV 网络传输；远端共享需计源/目标及传输责任 |
| 准备 | trace 规范化、模板与分词、模态处理、缓存身份、DAG 验证、私有页预留和 COW 描述。重复准备只有在固定输入身份下才可摊销 |
| 同步 | 依赖通知、等待 timer、复制到计算、全层完成到发布、消费者结束及容量唤醒。端到端延迟取依赖关键路径；可重叠阶段不能全数相加 |
| 驻留 | 共享页、各私有副本、未消费输出、等待保留、在途源/目标和待回收对象。取消或失败后的字节时间仍计费，future free 不构成当前容量 |

V 个节点、E 条边的图验证为 O(V+E)。使用反向边时，每条边首次满足只更新一次；重复消息仍有接收与身份查询成本。失败传播只对尚未终止节点首次安装终态，但检查出边和查事件账仍有成本。K 个队列事件使用堆通常为 O(K log K)，另计输入载荷处理和候选排序。事件去重账、已结束票据及保留输出也占主机内存；若允许任意迟到重放，不能无条件用短 TTL 删除身份后继续声称恰好一次。

保留最终候选还占用载荷、必要状态的持有和完成元数据。若 R 项必需结果的每次完成都扫描全部 R 项，共同资格检查可达 O(R²)；可按唯一 uid 结算剩余项或反向依赖，在最后一项成功时触发发布，把该账降到 O(R) 总更新，重复通知另付身份查询成本。优化必须保留候选、失败门和最终恰好一次语义；物理访问责任清零不表示仍未发布的候选载荷可以提前归还。

完整 AND join 的完成不早于所有必需输入可用和等待到期的最大值。快分支的结果与其必要状态可能一直驻留到 join 消费结束。较大分支宽度在并行空闲资源存在时可能缩短搜索时间，也可能增加共享历史读取、COW 峰值、尾分支等待及输出缓冲。质量改善必须由任务评价证明，生成 token/s 不是会话有效产出的替代量。

模板、tokenizer、工具结果或模型变化后，保留依赖与责任原则，重建受影响输入和缓存身份。实际 token、位置和前向条件仍相同的状态不必仅因模板文件名变化失效；相同可见文本也不足以证明仍相容。更长思考时间可能增加重用机会，却付出更多字节时间并挤占准入；更大的页减少管理频率，却增加尾部浪费和 COW 峰值。容量紧张且重用遥远时，可以放弃驻留而选择换出或重算，但目的容量、恢复计算与传输必须另计。

失败处理策略变化时，物理最后访问和不可变已发布事件的原则保留。若要从失败转入恢复，必须增加恢复状态、尝试/提交授权、可用旧快照、重试预算及实际唤醒；若没有这样的协议，应保留失败终态。无法取得最后访问证据时，业务仍可失败，但对应物理责任继续隔离，不能用终态代替排空。

## 反例、区分实验与检查边界

| 观察或反例 | 竞争解释 | 区分干预与反证后的修正 |
|---|---|---|
| 最后一项操作失败后仍显示 RUNNING，或被参考判成 COMMITTED | 失败未终止、参考无条件加入提交候选、同键候选依赖插入顺序 | 注入唯一 FULL 失败且有完整最后访问证据；要求 FAILED、无发布和输出、物理责任排空。删除不合格提交候选，不能只换插入顺序 |
| FULL 自身成功却在其他必需结果失败前被发布 | 只检查本操作成功、最终事件误走普通事件路径、缺少共同提交门 | 将 FULL 与另一必需操作置于同刻，分别让失败操作身份排在 FULL 前后；两者都不能发布最终事件。另保留先前合法 FIRST，以区分共同提交与局部发布 |
| 全部必需操作成功且已排空，仍留下 RUNNING | 最终候选被丢弃、只在最终操作通知上重查、辅助完成未触发发布 | 对相同 TAIL/FULL 身份分别测试失败和全成功；再使辅助完成同刻或更晚。全成功时保留候选并在最后证据后恰好一次共同提交；失败或取消时最终候选不得发布 |
| 两个实现终态一致但启动或驻留不同 | 同刻取消间是否调度的合同不同、启动记录遗漏、责任登记错误 | 固定 U 已提交、V 在时刻 2 才能启动，U/V 同刻取消；比较 starts、操作票据和缓冲轨迹。先统一组织合同，再判断实现是否违约 |
| 生产者失败，必需消费者仍等 FULL | 失败未传播、误将候选当发布、事件类型混淆 | 先发布 FIRST 再使 FULL 失败，同时设置 FIRST 与 FULL 消费者；前者可继续，后者同刻失败。若一起失败，应修已发布事件保留规则 |
| 取消后马上有空闲容量，随后新请求内容损坏 | 旧写未结束、重复完成清了别人责任、页代次或映射错误 | 固定数据与页池，延迟旧 kernel/复制完成；在结束前申请同页。若仍被分配，修回收资格；仅增加 epoch 不能修旧物理写 |
| 后继提前或重复启动 | 重复通知当成不同依赖、边身份混淆、终态门缺失 | 一个生产者重复通知，另一必需生产者延迟；用发布序号与边集合审计。时间戳相等仍要求证据记录先存在 |
| 合法后继被参考判为启动过早 | 等待起点定义不一致、传输和等待串加、实际证据缺失 | 固定发布 1、延迟 3、等待 2，检查收到证据后在 4 启动；再固定延迟 1、等待 5，检查在 6 唤醒。只改一个约束，重算其最大值 |
| 先依赖失败后取消却被记成 CANCELLED | 参考只看取消计划、实际实现覆盖终态、同刻次序不一致 | 分别重放较早依赖失败、较早本地取消和同刻两种稳定身份顺序；逐条检查第一次终态，不能只比最终取消集合 |
| 取消后继后被通知恢复，或上游提交后再取消导致后继停滞 | 通知直接设 READY、按生产者当前状态过滤旧发布 | 分别先取消消费者再交付通知、先发布生产者再取消并延迟通知；前者不得复活，后者仍可使用旧证据 |
| 队列耗尽但存在合法后继 | 非根外部下界遗漏、timer 未注册、容量监听丢失 | 没有无关输入事件时测试正等待和非根外部下界；仍须由明确 timer 或容量事件推进 |
| 高缓存命中伴随完成率下降 | 等待保留挤占容量、COW 准备、待回收对象或 join 尾分支 | 分别只改保留上限、分支宽度和 COW 布局，记录唯一物理对象、阻塞原因、字节时间与会话完成分布 |
| 闭环平稳而开放生产积压 | 闭环反馈自动减压、生成器迟发、服务容量不足 | 保留原始计划、实际就绪和发送；固定开放计划比较积压。offered 随变慢减少时，撤回固定到达能力结论 |

事件检查的独立参考从静态 DAG、操作偏移、通知延迟、失败结果和取消计划递归求约束，不读取调度器的就绪计数。每条边分别求发布时间等待门与通知接收门，取最大值。缺失事件的生产者终止时刻决定依赖不可能发生的时刻；参考将该原因与本节点取消、操作失败及具备资格的最终提交按固定次序比较，保留最先确定的不可逆终态。只有全部必需结果成功，参考才按最后一项必需成功证据建立 COMMITTED 候选，最终事件使用同一因果键发布。该条件不追溯删除更早合法的非最终发布。审计器从实际记录顺序重建候选保留、发布证据、按边交付集合和操作责任，另外比较最终因果键，不能只因同刻时间戳相同而忽略顺序。

参考与重放共同采用同刻取消全部处理完再准入新节点的合同，同时保留取消逐条处理、即时失败传播以及稳定身份顺序。检查完整比较 starts、publication、state、output 和首次 terminal，另外逐记录核对责任；仅终态相同不能通过。原有主轨迹与延迟、等待、外部下界、取消的组合检查继续保留；针对最终失败、同刻其他必需操作失败和取消准入边界增加明确手工期望。

同一个审计器覆盖正通知延迟与正等待的组合、等待长于传输、非根外部下界、重复通知、FIRST/FULL 区分、TOOL_OK/QUALITY 符号接口、依赖失败先于本地取消及同刻次序。故障变体包括忽略依赖、重复通知提前放行、误取消兄弟、漏唤醒、取消后复活、丢弃终止前已发布事件、失败不终止、推迟到排空才失败及失败即释放在途缓冲。独立参考的故障对照检查串加时间门、按取消计划覆盖较早 FAILED、恢复无资格 COMMITTED 候选及让最终事件绕过共同提交门；重放故障对照还恢复同刻取消之间启动的旧组织，要求在选定合同下检出。

成功与失败回归使用相同的 TAIL/FULL 操作身份；成功路径要求完整提交和空候选账，失败路径禁止最终发布。辅助操作身份分别排在 FULL 前后，并包含更晚完成；另外验证候选等待期间取消仍保留 FIRST 和物理排空。负对照实际丢弃暂不具备资格的最终候选、只重查当前事件、漏掉辅助完成重查，或把参考最终键退回 FULL 自己的完成键。相同时间戳的错误参考也必须被顺序见证拒绝，不能仅靠晚时刻例子检出。

资源检查使用预先给定的 copy/kernel/兄弟读者责任与手工检查点，核对运行中取消、旧写未结束时申请同页、分配代次、重复完成及共享页最后使用。页布局参考按实际槽内容分配物理副本，再核对对齐和未对齐容量；回合参考枚举已知与已消费 token 身份，而非重复调用长度递推。驻留按窗口交集积分，并与独立逐整数区间求和核对。

这些检查的模型范围是确定性的 CPU 符号事件、物理对象和整数槽布局。事件模型采用固定尝试及输出版本、预先声明的操作完成偏移、可靠重复通知、无资源争用且受同刻取消屏障约束的 eager 启动；精确启动时刻要求不直接套给真实排队系统。辅助操作在此模型中只设成功返回，检查其完成顺序及取消后排空；确定失败由产生事件载荷的必需操作注入。小资源模型的 O/B/Q 为空；操作缓冲与独立发布载荷分开，未模拟真实输出借用。检查不计算模型 logits，不验证 tokenizer、工具网络、副作用、质量证书真实性、GPU 全层写入、跨 stream 可见性、DMA 停止或实际 HBM 事务，也不证明服务性能和 Agent 使用效果。设备与服务实验应独立记录环境、时钟、证据覆盖和未完成责任。
