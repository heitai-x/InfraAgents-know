# S-FLASHATTENTION3：FlashAttention-3：异步流水与低精度

## 原文与问题

[原始 PDF](../../references/S-FLASHATTENTION3/original.pdf) · [完整原文](../../references/S-FLASHATTENTION3/reader.html) · [全文文本](../../references/S-FLASHATTENTION3/fulltext.txt)

来源版本 2407.08608v1，提交日期2024-07-11；核对日期2026-10-27。论文以 Hopper H100 SXM5 为实验对象：FA2 的同步数据流不能充分利用异步 Tensor Core 与 TMA 搬运，softmax 等非矩阵操作又与矩阵单元形成吞吐差距。

## 数学状态保持，执行时序改变

FA3 仍维护在线 Attention 的 m、ℓ、未归一化输出 U。每块更新 r=exp(m旧−m新)，ℓ新=rℓ旧+rowsum(P)，U新=rU旧+PV，最后 O=U/ℓ。先前本说明把 U 的缩放写成倒数，这是错误的；v1 PDF 第5页 Algorithm 1 第21行也有对应的反向打印式。本说明以统计量定义及独立稠密参考核对。

两块分数0、2且V为1、0时，最大值上升后旧贡献应乘 exp(−2)，输出约0.1192；若放大则越出[0,1]。数学状态和异步操作的完成状态必须分别维护。

## 生产者/消费者与缓冲生存期

生产者 warpgroup 发出 Q、K/V 的 TMA 加载；消费者 warpgroup 发出异步 WGMMA 矩阵乘和普通指令的 softmax。warpgroup 是 Hopper 上参与这类矩阵指令的四个连续 warp。寄存器可从加载侧转给计算侧，但资源总量不因此增加。

```pseudocode
生产者：等待某一代缓冲不再被消费 → 发出异步加载 → 加载完成后发布就绪
消费者：等待对应数据就绪 → 发出矩阵计算 → 等待最后读取该数据的操作完成 → 释放这一代缓冲
```

等待“加载完成”不等于确认“消费者读完”。多个消费者共享缓冲时，全部有关消费者结束后才能覆盖。环形槽还要区分代次，避免旧完成信号释放新数据。

## 消费者内部两级流水

目标是让当前块 PV 的异步矩阵乘与下一块 softmax 重叠。以下用完成事件表达依赖，覆盖启动与收尾；不是源代码或硬件指令清单。假设可同时保留当前 V 和下一 K，以及当前 P 和下一份 FP32 分数；成对缓冲至少需要两个槽，或由独立 K/V 缓冲提供等价生存期。

```pseudocode
准备第0块分数并等待完成；计算其 P、m、ℓ；初始化 U←0
对 j 从0到最后一块：
    若还有下一块，发出 QK下一块，保留独立的分数缓冲
    等待 V当前块就绪，发出 U←U＋P当前块·V当前块，不立即等待
    若还有下一块：
        等待下一块分数就绪
        在 PV当前块仍可能进行时，计算 P下一块、r下一块及新的 m、ℓ
    等待 PV当前块完成，之后才能访问或重标度 U
    若还有下一块，执行 U←r下一块·U，交接下一块 P
等待所有输出写依赖满足，按最终 ℓ 归一化并写回
```

softmax 对全 mask 行/块的处理沿用[模块共同算法](../frameworks/attention-backends.md)的显式规则。K/V 缓冲按实际最后读取者释放。v1 第7页 Algorithm 2 的打印循环边界不能直接充当完整实现：本说明显式覆盖1、2、3块，保证每块 QK、PV 各一次，并在最后一次 PV 完成后归一化。

## 跨消费者的乒乓调度

另一种重叠发生在不同消费者之间：一组做 softmax 时，另一组发出矩阵乘，再交换角色。它需要调节发射顺序和同步，区别于同一消费者的两级流水。不同 query 块的输出状态各自独立；共享加载缓冲的完成条件仍须一起满足。多一组消费者同时增加寄存器和状态需求。

## FP8 的布局、尺度与异常值

FP8 不只是更改 dtype。论文 §3.3（PDF第8–9页）先讨论两种布局不匹配，再讨论块量化和非相干处理。下列是论文机制；完整尺度算法与误差分解是[正文的独立推导](../frameworks/attention-backends.md)，其中选定的量化器和概率尺度不能反过来归称为论文完整实现。

V 的消费布局：输入通常在 head 维连续，而论文 FP8 第二个 WGMMA 要求 V tile 在序列维满足相应连续组织。只做 TMA 加载不能交换连续维。候选包括前置全局转置、与前驱融合、kernel 内转置；论文选择在生产者中用共享存储到寄存器再回共享存储的矩阵搬运组织 tile 转置。打包的8位元素还需要局部排列，不能把16位转置指令直接理解成任意8位转置。布局完成后才允许 PV 消费；转换可被其他计算隐藏，但仍占用指令、缓冲和依赖。

概率的消费布局：FP32分数累加片段的线程/寄存器组织与下一次FP8矩阵乘的寄存器操作数不同。论文Fig.3/4通过字节排列改变概率片段，并让V的对应行采用匹配排列，避免仅改变一侧的逻辑乘积。这里的正确性可由(PΠ)(ΠᵀV)=PV核对；Π是key轴的排列矩阵。它不指定新硬件必须采用相同寄存器分工。

块量化：论文给 Q 的 Br×d 块和 K/V 的 Bc×d 块分别保存尺度，减少单个异常值决定整张量尺度的问题。分数必须按Q/K尺度恢复；V贡献必须恢复到输出单位。量化可以与前驱融合，但“融合后没有额外慢下来”只在相关资源余量下成立，不表示量化计算或元数据不存在。v1主文没有逐项规定全部舍入、特殊值、P量化和流式尾块更新规则；新算法必须自己明确这些合同，不能从“块量化”一词推断。

非相干处理：在量化前对 Q、K 施加同一个随机正交 M，使(QM)(KM)ᵀ=QKᵀ。论文采用随机符号对角矩阵和Hadamard的组合，使变换可用O(d log d)工作实现，而非稠密O(d²)。归一化、支持的维度和M的一致性是恒等式前提；位置变换后再施加M可直接保留原已定义点积。流式缓存不能在某一步任意更换M。V不属于这条点积恒等式。正交变换只保证未量化点积不变，无法保证每组输入经量化后误差都下降。

需要分别核对QK输入量化、P量化、V量化、实际矩阵累加和输出舍入。正文给出原始稠密、解码输入稠密、额外量化概率、真实kernel四条参考链，以及全零块、分区尺度与缓存尾块的处理。它们是用于设计与定位错误的构造，不是目标机的数值观测。

## 资源、反转条件与论文实验

两级流水额外保存 Br×Bc 个 FP32 分数，至少增加4BrBc字节的逻辑片段；例如64×64为16 KiB，若128线程均摊仅此一项平均增加32个32位寄存器，实际分布和其他变量另计。更大 tile、更多级数和更多消费者共同竞争寄存器与共享存储，可能降低驻留、产生 spill。论文的三级流水实验并未得到普遍优势，不能据此推断更深总会更好或总会更差。

论文在 H100 SXM5、固定1830 MHz及其给定形状/精度下报告 FP16 前向最高740 TFLOP/s、相对当时 FA2 的1.5–2倍加速；FP8接近1.2 PFLOP/s。在含异常值输入上，块量化加非相干处理相对每张量缩放基线的误差更低。性能和误差是论文条件下的结果，不是本库实测。

检查时区分：生成指令是否真的重叠、寄存器/共享存储是否超预算、块数很小时启动收尾是否主导，以及低精度布局/尺度是否改变结果。不能在没有 TMA/WGMMA 的设备上照搬其指令组织；依赖关系仍可用其他指令实现，但成本要重新分析。FA2/FA3的比较与可复算检查见[模块正文](../frameworks/attention-backends.md)。
