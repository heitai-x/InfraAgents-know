## 源码展示了什么

一次 attention 调用在这份实现里分成两段，两段的输入与成本不同：

- 准备段消费 metadata：query 的分段偏移、页索引区间、每条请求的末页有效长度；按几何与设备条件选择 kernel 变体；计算工作划分并写入 workspace。它在 host 上执行，有些长度要从设备读回 CPU；自定义 mask 若没有预先打包成位图，这一步还要打包。准备段不能被图捕获。
- 执行段消费张量：按准备好的计划运行 kernel；若调用方没有提供输出缓冲则分配并清零；若要求返回 logsumexp 则另分配 FP32 缓冲；某些路径在 kernel 之后再对输出乘 value 的 scale。执行段可以进入图，前提是 batch 容量固定、metadata 缓冲在对象生命期内保留。

准备结果可以复用：同一步里几何相同的各层共享一份计划；batch 成员、分段、KV 长度、mask 或变体条件改变后旧计划失效。

三类 metadata 的单位各不相同：query 分段偏移以 token 行计，页索引区间以页索引数组中的位置计，末页长度以有效 token 计；同一入口下的不同实现分支用不同的量核对输入。实现选择"自动"时，在准备段按设备、位置编码模式、归约方式、mask 与 dtype 固定下来，之后不再改变。

页内布局有 token 优先与 head 优先两种；某些实现分支只接受其一，输入是另一种时在准备段转换轴顺序；对带块级 scale 的量化格式，转换是完整复制而不是视图。

workspace 分三部分：浮点区放沿 KV 切分后的部分输出，整型区放计划元数据，另有一块 pinned 主机缓冲用于异步复制；文档给出的建议容量是上界估计，不是所有形状的硬下界。

## 本库据此推导

- 准备与执行的分段及摊销边界是设计变量，不是常数；准备段的 host 读回、mask 打包与元数据复制是"非阻塞"标志不能消除的工作，见 [Attention 执行接口](../frameworks/attention-backends.md)。
- metadata 单位须逐接口核对，自动选择的实现不是每次重选，见同章"metadata 的单位与实际分派"。
- "支持两种布局"不等于两种布局成本相同，见同章"cache 布局、workspace 与并发"。
- 准备段不可捕获、执行段固定 grid 可捕获、归约顺序确定与图兼容相互独立，见 [CUDA Graph](../frameworks/cuda-graph-buffers.md)。

这是一个实现在一个提交上的选择，不证明接口必须如此划分。本说明交付独立设计需要的分段、数据单位与生存期关系，不充当该提交的完整API接入手册，也不要求Agent打开实现源码补全关键机制。具体库的直接接入应有可读文档所定义的接口合同；文档不能支持的组合不能仅凭本说明宣称可用。自建接口可以改变参数组织，但须明确相应输入、单位、所有权和有效域。设计推导为独立分析，不是目标机器实测；版本日期不证明模型训练实际包含该资料。
