# 从 Attention 扩展的第一组机制模块

这一批把[Attention 样例](attention-module.md)的解释深度用于已有的分页、调度与 GPU 流水专题。内容标准保持原来的六项，具体审查问题见[知识内容审查](knowledge-review.md)。专题数量仍为111；新增的是原章里的完整算法、映射、联立成本和组合推导。

| 模块 | 本章补足的连续推导 | 与其他模块的交界 |
|---|---|---|
| [分页 KV](../knowledge/algorithms/paged-kv-capacity.md) | 逻辑位置→物理页→NHD/HND字节地址；不可变追加、共享尾页COW、发布/失败回滚、取消与最后读者回收；页长改变时容量、交通与准备成本反转 | 调度承诺的是实际可写页；Attention消费的是同一快照的长度、布局与内容；固定图包不能提前覆盖 |
| [连续批处理](../knowledge/algorithms/iteration-batching.md) | 已知token与已完成KV边界→就绪性→预算预留→压紧执行视图→末行采样→结果提交；混合输入、取消与迟到完成的逐轮轨迹 | 不能把新采样token当成已有KV；不能按当前batch行解释旧结果；页与输出消费者未完成时仍占容量 |
| [GPU流水](../knowledge/hardware/gpu-kernel-pipelines.md) | 非矩阵指令GEMM的tile→地址→64线程职责→共享布局→累加/写回；多读者槽代次；有限流水时序、驻留与网格时间的反转 | 矩阵指令需另核对公开契约；复制完成、可见性与最后读取完成不同；源程序异步表达不能证明物理重叠 |

每章都把设定算例与来源事实分开。不可变页、单请求最多一轮在途、两warp SIMT例是便于核对的可替换方案。已有引擎和平台实例说明设计选择及其条件，不要求新引擎采用相同字段、组件或施工顺序。

## 怎样检验内容是否能使用

作者侧检查分别建立字节/逻辑状态、调度事件和标量矩阵/缓冲协议模型。主审检查完整正文、关键成本与来源解释，再由非作者处理正文没有直接演示的参数与状态轨迹。练习要求先保留推导、独立小实现和竞争解释，再接收反证并修正判断；作者检查脚本不作为练习答案来源。

本轮交叉练习共享父对话与仓库，资料限制通过任务说明实施，没有操作系统级隔离、固定token预算或知识版本对照。它能发现本次阅读后的具体推导和诊断问题；它不能单独证明知识对所有Agent有效，也不构成完整引擎构建或GPU效果评估。任务、答卷、实际执行与主审判断保存在[本轮记录](evidence/parallel-mechanisms-20261027/review.md)。
