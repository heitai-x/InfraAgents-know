# K-ALG-003：前缀缓存：计算等价类、Radix 与淘汰收益

可复用前缀是能产生等价中间状态的一组输入和执行条件；字符串相同只是其中一个投影。

## 为什么历史 KV 可以复用

因果模型中，位置 t 的各层状态只依赖可见前缀以及模型参数、位置规则和外部条件。当这些依赖保持一致，两个请求在分叉前的状态可以共用。此结论来自计算图：若某个依赖进入了状态生成，却没有进入缓存身份，命中就可能跨越不同计算。

因此身份一般需要模型及权重版本、规范化后的 token 序列、位置编码配置、影响状态的 adapter、多模态特征身份，以及隔离命名空间。sampling temperature 通常影响之后如何选 token，不影响已给定前缀的前向状态；但已采样出的 token 已经属于前缀。不要把所有配置都盲目混入 key，也不要漏掉真正参与前向的输入。

把一个明确的前向条件记为 η，已知输入 token 序列记为 x[0:n)。逻辑缓存对象是该条件下完成到位置 p 的状态 S(η,x[0:p))，不是一个 token 字符串或一个地址。复用要求能够还原同一后续计算所需的状态：普通因果 Attention 是每层有效 K/V，混合模型还可能需要窗口、递归状态等。请求输出是实际可继续的位置 p、对应的状态句柄与就绪关系，以及尚需处理的输入 x[p:n)。空缓存返回 p=0；空输入是否允许由任务定义，生成任务若没有任何输入，应先提供合法起始输入，不能从空 KV 自动生成一个已知末行。

模型函数上的等价不自动成为浮点逐位相同。状态格式、量化尺度、位置规则或允许的误差契约改变后，需要重验复用边界；同一前缀由不同数据流生成时也可能有舍入差异。若前向中存在影响状态的随机操作，还需保存相应身份/状态或禁用这种复用。缓存 salt 只提供一个隔离命名空间；是否授权共享、目录暴露与时序泄露的治理仍由系统语义决定。

## 块哈希和 Radix 是两种索引结构

链式块哈希使当前块身份依赖父块身份、当前 token 和额外条件。相同 token 块出现在不同上下文中，不会被误认为相同状态。Radix 树把共享 token 路径压缩为边，前缀匹配可能在边内结束，此时需要拆分节点，节点下挂物理状态与引用关系。树负责发现最长共享路径，物理池负责保存内容，两者不必一一对应一个分配对象。

例如 A 的前缀是 a,b,c,d，B 是 a,b,c,e。共享可到 c；物理块大小若为 4，则逻辑前缀命中长度 3 与可直接共享整块数量 0 是不同结果。支持尾块复制可保留部分收益，否则重算这段可能比小块管理更划算。不能把逻辑最长匹配直接当作内核可跳过的 token 数。

下面选“仅完整页进入缓存目录、固定页长 P、同一模型状态的所有必要层均完成后才发布”作为具体算法。它便于把命中、物理共享与追加分开证明；不要求其他引擎使用同样的块大小或结构。第 j 页的精确身份包含 η、页边界、父前缀身份及 x[jP:(j+1)P)。可以递推计算桶号 hⱼ=H(域标签, hⱼ₋₁, 本页 token, 额外条件)，根桶号包含 η。仅将本页 token 做哈希会把不同历史中的同一段混在一起。

哈希只缩小候选集合。本例保存可核对的完整身份，查询时核对 η、完整父身份与本页内容；父身份可以由共享的父结点表示，无须给每页复制一份完整 prompt。父哈希碰撞不能再用“父哈希相同”证明父身份相同。选用概率性身份时应明确其碰撞契约，不能将任意有限哈希写成无碰撞定理。序列化还须表达类型、长度与边界，否则不同字段连接可能先于哈希就变成同一字节串。索引元数据自身也需计容量和回收；保留子结点时仍须保留其身份依赖，不等于必须永久保留所有历史请求的 token 副本。

Radix 可以按 token 串而非整页寻找最长匹配。其边内分叉算法为：从根出发，与下一条边标签逐 token 比较；完整匹配则下行；在第 k 个元素处分歧则建立长度 k 的公共边，将旧剩余后缀与新后缀挂到公共结点下；若查询在边内结束，可返回该偏移，不一定要立即改变树。拆边只重排索引与状态切片的描述；物理页是否可共享仍由页边界、有效范围与所有权决定。插入尚未完成的 token 路径不能同时发布对应 K/V 已就绪。SGLang 固定论文的实例采用单 token 页，本节的 P>1 完整页策略是另一种独立构造，不能归为该论文的同一物理实现。

## 命中长度是全状态一致的交点

有些层保留全历史，有些只保留窗口，有些保存递归状态。能恢复整个模型执行的位置，必须让所有需要的状态在该位置同时有效。某一层有 4k token KV 不代表模型可从 4k 继续，递归层可能只有 2k 处的检查点。分层命中长度的最小值仅在每层有效集合都是从零开始的连续前缀时成立；一般要取各类恢复位置集合的交集。

令每种状态允许恢复的位置集合为 Rᵍ，索引与真实状态就绪共同允许的位置为 I，则选择 p∈I∩⋂Rᵍ。例如完整 KV 支持 0…12，递归检查点在 {4,8,12}，所需窗口只覆盖允许从 {8,12} 恢复的位置，而外部状态当前仅到 8，真正的共同上界是 8；分别取“每层最大长度”再忽略位置集合会给出错误结论。普通完整页算法只在 0,P,2P,… 上查找，遇到第一个缺页就停止；本例不能跳过缺失的父页而使用更深的孤立页。

即使 n 个输入 token 的 KV 全部命中，开始生成仍可能缺少最后一个已知输入位置的 logits。只存 KV 的本例令可跳过上限为 n−1，再按 P 向下取整；例如 n=8、P=4 时最多直接跳过 4 个 token，最后一整页需要安全重算，不能假装已得到第一个新 token 的分布。n=9 则最多跳过 8。若任务只需恢复 KV 而不需生成，或另外保存了满足同一输出契约的末行 logits，可使用不同上限。重算区域必须私有或经过证明的写入隔离，不能覆盖仍被其他请求共享的命中页。调度如何区分已知 token 与已完成 KV 见[连续批处理](iteration-batching.md)。

## 从查询到发布的完整操作

下面保持缓存页内容不可变，区分三种拥有关系。C 表示目录为了未来命中而保留该页；A 表示当前请求的逻辑映射；R 表示已经提交的实际读取；构造中的新页另有 W 写入/暂存保留。请求结束只撤销 A，不自动撤销 C，也不会结束 R。目录命中资格与物理复用资格因此不同。页可分给下一内容的充分条件是 C=A=R=W=0。这里把分页章中的逻辑所有者进一步拆成缓存与请求，两者合计才是完整的逻辑拥有责任。

对目录、页池与请求快照采用同一主机协调关系：查询后保护命中、选择淘汰对象和取得新页之间不能留出可被另一分配者抢占的空隙。可以使用串行协调或其他能证明同样线性化效果的方法；不是只给每条请求各加一把锁就自动保护了共享页池。

```pseudocode
输入：请求身份、η、已知 x[0:n)、本轮合法输入额度 q上限、目录与页池
核对生成所需的非空输入，确定可跳过上限及各状态共同恢复资格
在目录/页池协调区内：
    从根按完整页查询；每一步核对完整身份、真实句柄代次和状态就绪
    在第一个缺失或其内容未就绪的位置前停止，得到所有已匹配完整页边界
    将匹配边界与各状态恢复集合求交，选择可跳过上限内最大的 p；无非零交点则 p←0
    为全部命中页增加本请求的 A，形成不可变的命中快照
    令 q←min(q上限,n−p)，按实际写入方案计算新页、输出及暂存资源
    先模拟足以满足本轮资源的合法淘汰与分配；不足则撤销本次 A，不提交计算
    原子撤下被选冷页的目录资格，再释放其 C；取得全部新页的 W
提交本轮计算前，为命中状态和描述取得 R，并建立输入就绪依赖
在私有写区计算 x[p:p+q)；未完成的长度和 token 身份不进入可命中目录
计算结束后，核对所有必要状态确实完成，并建立消费者可见的依赖
在协调区内复核请求身份、当前快照及取消资格：
    若仍可提交，发布新的请求状态，将 W 交接为请求 A
    只把新完成的完整页加入目录，并取得 C；未满尾页保持私有
    若同身份已有可用页，保留已有目录项；本请求可暂持自己的重复副本
    若已取消，不发布新状态；等所有可能的读写完成后放弃构造页
按实际最后使用释放 R；事务恰好一次地交接或释放 W
最终请求结束时撤销 A；仍有 C 或 R 的页继续保留
```

本轮 q 可以小于 n−p，只有已处理完全部已知输入时，末行才具备生成资格。命中避免的是其前缀的重算，新 suffix 仍需要读取这些前缀 K/V 做 Attention。若一个状态族或远端传输尚未就绪，不能仅因 token 路径存在而让它进入已完成长度。模型计算发生错误时保留旧快照；设备已接受的读写必须经过已声明的完成/排空关系后才能释放。主机源描述在复制完成前也应保持有效。

同时计算出相同前缀的请求可能产生两份物理副本。立即改写正在消费的页表去消除重复需要额外证明；本例让已有目录页继续负责未来命中，另一份副本随当前请求结束后回收。身份相同不意味着可以忽略正在使用的实际句柄。若选择在提交消费者前统一映射到同一页，应把重映射、引用交接和旧副本释放写成另一个完成的事务。

## 淘汰、再次命中与最后读者

本例的缓存目录形成前缀依赖树，采用叶优先淘汰：只选择没有缓存子结点、A=R=W=0 的缓存叶；先撤销目录可发现性，再释放 C，将满足全零条件的页交给分配者。删除叶可能让其父结点成为新的候选。访问时间、估计收益或其他策略决定候选排序，但不能越过资格条件。持续没有可回收叶时应等待、减少本轮工作、重算/转移其他状态或拒绝，不保证 LRU 总能找到足够空间。

只有 R>0 的冷页，即使请求已取消，也不能当作可立即增加容量的淘汰对象。本例保留其目录直到可回收；另一设计可以提前撤目录、把物理页放入等待回收集合，但必须把“已从索引删除”与“可用容量已增加”分开。远端目录还需要证明位置/版本、传输结果和目标页就绪；目录曾经命中不保证后来仍持有同一内容。

取 P=4、每 token 全层 KV 为 τ=128 KiB、页组大小 512 KiB，物理池只有 5 页，即预留 2.5 MiB。以下小写字母代表不同 token ID，所有请求前向条件一致，仅完整页可缓存：

| 事件 | 目录、请求与实际使用 | 物理结果 |
|---|---|---|
| e0 | A 计算完 abcdefghij，完整页 abcd、efgh 在页 0、1；私有尾 ij 在页 2 | A 结束后 0、1 各保留 C=1；尾页 2 空闲，缓存占 1 MiB |
| e1 | B 输入 abcdefghx，命中 8 个 token，私有页 2 保存 x；读者 B0 使用三页 | B 取消后 A=0，但 0、1、2 均因 B0 的 R 存活；0、1 还由 C 保留 |
| e2 | C 输入 abcdwxyzz，命中页 0，页 3 保存完成的 wxyz 并入目录，页 4 是私有 z | 所有 5 页存活；请求 C 保护 0、3、4 |
| e3 | D 输入 QRSTU，需要两个私有页，当前没有可回收页 | 页 1 虽是冷叶，但 B0 未结束；页 3 仍被 C 拥有，不能将“缓存可淘汰”当作两页可用 |
| e4 | B0 真正完成，尾页 2 释放；从目录淘汰冷叶 efgh，撤销页 1 的 C | 现在 1、2 两页可分给 D；页 0 仍是 C 所需前缀，不能为了淘汰父页破坏活分支 |
| e5 | D 完成 QRST 的新页后可缓存；再次查询 abcdefghx | 只能命中 abcd，即 4 个 token；旧 efgh 身份不能命中已复用的页 1 |

e3 的失败不能通过忘记 R、复用旧句柄或覆盖 B0 的描述包解决。e4 后旧完成通知若重复到达，也不能减少 D 的引用。物理页 1 的新内容需要新复用代次；缓存桶中的旧条目必须在复用前撤销。C/D 后续结束后，一些页只由 C 保留而不属于活动请求，观察“活动请求数为零”不能推出池里没有缓存占用。缓存页与活动页共享物理池时，计容量按不同物理页求并集，不能把 C 和 A 各算一份字节。

## 缓存价值与路由

命中收益近似为避免的重算时间减去索引、传输和映射成本。淘汰排序可以估计再访问概率×重算成本/驻留字节，并叠加引用保护。仅按 token 命中率会高估短且便宜前缀，忽视很长但少见的昂贵前缀。前缀亲和路由能提高局部命中，但可能把热门前缀集中到排队最严重的实例；路由代价应比较额外排队和节省的计算。

持有引用的共享节点不能仅凭 LRU 老化就释放。跨租户能否共享由隔离语义决定；即便结果数值相同，也可能不允许让缓存命中成为可观察的共享信号。缓存 key 的哈希用于身份检索，冲突处理与隔离规则才定义系统语义。

具体比较从同一新请求可用时计到其第一个正确继续结果。令不命中时成本为 T全；恢复到 p 后重算 suffix 的成本为 T后(p)，查找与身份核对为 T索引，页面保护/映射与描述准备为 T接入，恢复或转换为 T恢复，额外排队为 ΔT排队，则该次复用的净收益为 T全−[T索引＋T接入＋T恢复＋T后(p)＋ΔT排队]。这里是串行例；可重叠的工作按真实依赖图求关键路径。T后(p) 仍包含 suffix 对 prefix 的 Attention 工作，不能用“命中 p/n”直接把整个前向时间按比例扣掉。目录索引、引用更新、主机/设备 metadata 交通发生的频率也需要分开。

设同一请求重算全部前向需 20 ms，本地命中到 p 后，索引/接入共 0.6 ms，剩余计算 7 ms，净省 12.4 ms。相同 p 的远端恢复量若为 32 MiB、有效链路为 8 GiB/s，则纯数据时间为 3.90625 ms；再加 0.4 ms 传输准备和 0.6 ms 接入，总时间为 11.90625 ms。远端实例额外排队为 12 ms 时，总计 23.90625 ms，反而应考虑空闲实例的 20 ms 重算。这里所有时间与带宽均为设定值，不是来源论文或本项目测量。多层流水、解码/scale、目标容量及传输失败会改变该式，复算时不能只换网络带宽一项。

驻留也有机会成本。若缓存对象大小为 D、下一观察窗口内复用概率为 π、命中时可避免的净重算为 V、维护成本为 M、驻留期间阻挡其他可用工作的代价为 Ω，则保留的设定期望收益为 πV−M−Ω。V 应是当前保留集合下该对象的边际价值，不能给每个共享祖先重复记同一整段重算收益。例取 V=12.4 ms、M=0.2 ms、Ω=2 ms，π=0.5 时为 4 ms，π=0.05 时为 −1.58 ms，选择反转。π 和 Ω 需要由重用距离、到达与容量压力估计，不是缓存固有常数。只有对象已具备可淘汰资格时才能实施该选择；活读者保护不能因为收益为负而撤销。

计算成本是避免前缀前向与新增索引/比较；访存含唯一存活状态、新 suffix 对旧 KV 的请求、复制和恢复；通信只在跨设备/主机边界真实发生时计入；准备含哈希、精确核验、路由与 metadata；同步含状态就绪与最后使用；驻留含缓存/活动/在途/构造页并集、目录和接收暂存。满块哈希预计算可分摊 token 扫描，但精确碰撞核验、模型身份序列化和目录维护不能都当作零开销。

## 怎样区分命中错误与收益消失

正确性参考从 η 和完整 token 序列独立执行同一数学/数值契约，不能用命中的页面本身定义期望。改变一个中间 token，后面的相同块也应重新考虑；改变参与前向的 adapter、位置或图像内容应使命中隔离；仅改变不参与既有前向的采样参数不应无条件打碎全部前缀。强制不同身份落入同一桶，能检查系统是否仍做精确身份核验；它验证碰撞处理，不能证明实际哈希分布或安全性。

设命中率高而 TTFT 未改善，至少有三个解释：命中太短或未得到共同可恢复状态；命中避免了计算，却引入传输/转换/排队；命中已正确生效，但新 suffix 消费长历史仍占主要时间。分别记录逻辑匹配、实际跳过位置、完成计算 token 数和准备/恢复/计算时间，再固定 p 比较本地与远端、固定路由比较只读缓存与冷启动、改变 suffix 长度并保持前缀相同。若避开的前向工作已明显下降而总时间仍由远端队列增加，继续优化哈希不能解释主要差距；若跳过位置一直为零，则先检查完整页/共同恢复资格与末行 logits 的边界。

偶发错误另做故障干预：强制哈希碰撞、改变命名空间、在 lookup 与保护之间尝试淘汰、延迟旧读者、目录项复用后注入旧完成、只发布部分层，以及让请求恰好完整命中但不保存 logits。若禁用页面复用后仍失败，不能只归因为提前回收；固定设备描述包后故障才消失，应继续记录实际消费的页表/长度与请求身份，区分描述覆盖和数据页污染。CPU 有限事件模型可反驳这些错误组织，不能证明真实 allocator、GPU 内存可见性或实际通信安全。

## 从前缀复用扩展到其他模型

固定 encoder context 的交叉 KV 可以按源内容与投影参数复用；扩散模型中随去噪步变化的 self-attention 状态通常不满足此条件；SSM 的前缀恢复需要该位置的递归状态。共同原则是依赖闭包一致，而不是对象名称中有没有 KV。

## 场景：长公共前缀与交错会话

以下全部为设计设定。模型 KV 为 128 KiB/token，100 条会话共用同一合法 8192 token 系统前缀，各有 256 token 私有尾部。GPU 的 KV 预算为 8 GiB；另外设每轮读取权重 12 GiB、有效设备带宽 1 TiB/s，交互 ITL 目标 30 ms。模型、adapter、processor 和位置规则一致，前缀对齐完整页，不计页尾和临时峰值。

完整独立副本需要 100×(8192+256)×128 KiB=103.125 GiB；共享公共前缀则为 1 GiB+100×32 MiB=4.125 GiB。共享因此显著改变所列状态的容量可行性，但仍需下一步增量、引用和在途页预算。

比较 A：每次重新计算并保留私有状态；B：本地共享公共前缀，分别保留尾部；C：公共状态主要放在共享远端池，需要时恢复。A 简化跨请求状态管理但重复 prefill 且容量不足以同时保留上述全部会话；B 节省容量和重复前缀计算，却可能集中路由与读取；C 扩展放置选择，但增加网络、目录和恢复等待。

容量允许保留 100 条会话，不等于应让它们同时 decode。若一轮读取每个请求全部逻辑历史，100 条的 KV 读取仍约 103.125 GiB，加权重后的理想下界约 112.43 ms，已经超过 30 ms。若当前只有 8 条活跃，读取主项为 12+8×1.03125=20.25 GiB，下界约 19.78 ms。实际公共页的 cache 重用可能减少 HBM 流量，但需观测，不能按物理共享比例直接扣减。

远端公共前缀为 1 GiB，若有效网络为 20 GiB/s，纯传输下界 50 ms。重算假设为 200 ms 时，远端恢复有潜在收益；若命中节点额外排队 300 ms，则直接去空闲实例重算仍可能更快。路由必须将命中、目标容量和排队联合比较，而不只最大化前缀长度。

验证从完全相同与只差一个 token 的前缀开始，再覆盖相同文本但不同模板/adapter、分叉尾部、取消后共享页仍被其他请求使用、目录过期和部分恢复失败。性能轨迹保留会话思考时间与交错重用距离，报告避免的 prefill、真实物理占用、读取字节、排队和联合 SLO。

公共前缀变短、重用变稀或模型版本频繁更新时，B/C 的管理和驻留成本可能不再值得；热点过于集中时复制或重算也可能优于亲和路由。这个场景给出选择关系与验证方案，不声称特定引擎已经达到目标。
