# K-FW-008：MLX 服务：惰性求值、编译与请求状态

MLX 的数组表达式可以延迟执行，服务循环必须明确计算何时提交、何时完成和何时释放状态。

## 图构造与求值

惰性执行时，数组运算先建立依赖图，直到求值或需要数据的操作才实际计算。打印数组、转为主机可见表示、读取标量和数据相关控制流都可能成为隐式求值点。计时若只围住表达式构造，会漏掉设备工作。

求值过频繁会切断融合和批量提交机会；长期不求值会积累大图、引用和中间状态。迭代生成自然形成一个节奏：本轮输出与必要状态达到完成边界，再让后续逻辑消费。能异步提交的部分仍需与输出交付和取消关系明确连接。

## 统一内存中的所有权

CPU/GPU 共用内存池使数据迁移形式不同，但可变数组仍有依赖和生存期。共享模型权重与每请求 KV 应分开，批次重排时相应状态同步迁移。若下一轮表达式还引用旧状态，Python 容器移除它不一定立即释放全部内存。

## 编译、形状与量化

编译功能与惰性求值是不同机制；具体可编译边界、动态 shape 和状态捕获以实际 MLX 版本为准。固定形状的设备计算可以形成稳定区域，变长调度与协议逻辑仍在外部。量化权重的打包、group size 与可用矩阵 kernel 一起影响带宽和精度。

批量 decode 可以摊薄权重读取，但扩大 batch 增加 KV 和每次求值的执行时间。对交互服务应同时观察首次输出、逐步延迟、系统内存压力和实际计算完成时间。CUDA 的对象和捕获术语不能直接作为 MLX 实现证明，应从该框架的数组和 stream 语义重新建立映射。

## 固定版本的编译与状态契约

补充的 [Compilation 与 Streams 文档](../sources/S-MLX-EXEC.md) 与原有惰性求值文档来自同一固定提交。Compilation 明确描述函数编译、首次 tracing、公共子表达式合并和算子融合；Lazy Evaluation 中仍保留“当前不编译并重跑计算图”的早期说明。判断该版本编译能力应使用专门的 Compilation 文档，不能由那句旧说明推断没有编译，也不能把每次惰性图构造都算成一次编译。

编译函数把未声明为输入的捕获数组视为常量。若 KV、逻辑位置或随机状态只通过外部可变容器间接访问，替换容器中的对象不保证下次调用看到新状态。服务步骤应把所需状态作为输入，把更新后的状态作为输出，或遵守该版本显式 inputs/outputs 捕获契约。Python 列表追加、请求注册和网络发送等副作用留在编译区域外。模型状态正确推进之后，才发布输出和新的已计算位置。

该版本默认可因输入 shape、dtype、输入数量变化而重新编译；在循环内不断创建新的被编译函数也会破坏复用。shapeless 模式避免部分形状变化触发重编译，但不能自动修复依赖首次 shape 的 Python 分支或 reshape 常量。请求 batch 从 1 变 2、KV 长度跨桶、空 batch 和不同采样参数应分别检验。动态值被当成常量时，即使形状不变也会产生错误。

## 求值、stream 与释放的同一条时序

一次生成步先构造输出 token、更新后 KV 和必要元数据的依赖，再对真正需要提交的对象求值。仅求值 logits 不证明所有独立的状态更新已经完成；求值后丢弃仍被下一步图引用的旧对象，也不等于物理内存立即可回收。计时至少区分建图、首次编译、求值完成和主机取回结果。

固定 Streams 文档说明 operation 可指定 stream 或 device；Unified Memory 文档说明 MLX 会为它所跟踪的跨 stream 数组依赖插入顺序。例如 CPU 产生 c、GPU 读取 c，后者等待前者。这不为框架之外的原地写入建立依赖，也不表示两个独立 stream 在物理资源上没有竞争。取消只能撤销尚未提交的服务意图；已提交数组计算及其缓冲仍需走完实际完成关系。

统一内存的容量账按物理对象计算。CPU 和 GPU 对同一数组可达，不应机械计两份；量化前后权重、重排后的 KV、求值中间量和未消费音频/特征队列却可能是真实的不同分配。容量接近上限时，设备可访问地址不保证没有系统内存压力，且 CPU 预处理会争用同一内存系统。

## 何时值得特化

设定一个可重复步骤的普通完成时间为 2.0 ms，编译后为 1.5 ms，一次首次编译为 200 ms；这些是假设值。仅从该项看，至少重复 400 次才补偿编译，1000 次的总时间由 2000 ms 变为 1700 ms。若每条短请求都产生新函数或新形状并触发编译，稳态节约不能抵偿首包成本。若额外特化版本占满内存，减少可接入请求的损失还需进入比较。

验证同时比较普通求值与编译路径的输出、KV、随机推进和取消后资源；记录实际编译次数、形状频率、完成时间、活跃数组与系统内存压力。小 batch 的主机提交占比高时融合更有机会；大 batch 已被权重或 KV 带宽限制时，应先核对真实省下的流量，不能沿用文档中某个 GELU 微基准的倍率作为服务收益。
