## 来源支持的机制与算法

调度把所需 token 范围与内部进度的差额转为本轮工作，计入投机 token 与异步输出占位。运行中请求先被考虑，并受长 prefill 阈值、本轮 token、模型长度、encoder 和 KV 条件约束；等待与恢复还有自己的就绪条件。排序和阈值是该实现的选择。

```pseudocode
初始化本轮计算与 encoder 预算
处理候选请求，按待推进范围和预算确定本轮数量
检查 encoder、KV 与传输相关条件，记录选中范围和新分配
生成请求到本轮 token 数、状态块与执行视图的对应
调度后提前推进内部进度，允许下一轮调度；结果返回时校正拒绝或未兑现部分
```

最后一步非常关键：归档中的内部“已计算”计数会在调度后提前增加，不等于设备已完成。它允许流水，也要求执行视图保留本轮原始起点，并在结果返回时调整。独立引擎可以选择更保守的确认时机，但仍需区分安排、执行和语义确认。
