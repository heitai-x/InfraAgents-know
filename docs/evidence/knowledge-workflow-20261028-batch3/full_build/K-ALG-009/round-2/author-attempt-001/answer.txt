{"chapter": "# K-ALG-009：异构状态缓存：层组、恢复位置与联合分配\n\n混合模型的状态缓存不是一组形状相同的 KV 页，而是若干更新规则不同的状态族。统一的对象是逻辑消费位置 p 和请求身份 η；物理页、块表、检查点与事件可以不同。恢复一个混合请求，至少要回答三件事：各必需族在哪个共同直接位置仍可用，从该位置到目标 p 的完整模型推进怎样执行，以及任一步失败后在途读写何时排空、预留何时归还。\n\n## 状态族、逻辑位置与四个事实\n\n设请求身份 η 包含模型与权重版本、adapter、位置规则、dtype、量化布局、请求代次和隔离命名空间。消费前缀 x[0:p) 后，状态族 g 的状态记为 S_g(p)。输入是 η、候选目标 p、已知输入范围、各族已发布的有效范围、检查点集合、发布票据和容量向量。输出要么是可立即执行的 RecoveryView，要么是带共同起点 c 的重放计划 ReplayPlan(c,p,x[c:p))，要么是明确失败原因。RecoveryView 必须同时给出每族的物理句柄、有效范围、版本、逻辑长度和就绪关系。\n\n一个族至少记录更新方式、层集合、每个逻辑位置的字节数、物理块或检查点粒度、保留规则和发布规则。普通全注意力 KV 可追加；窗口注意力的物理槽会回绕覆盖；递归状态通常原地推进；卷积历史是短环形缓冲；encoder context 是固定只读状态。它们不能仅因都叫缓存而共享同一生命周期。\n\n对注意力层，令 c_g 为单层、单 token 的 KV 字节数，m_g 为组内层数，P_g 为组内块长，则组页字节为 M_g＝m_g·P_g·c_g。这里 c_g 已经包含该层 K 与 V 的字节，不能再把 K、V 各乘一次。递归组不按 token 线性计页，而要按一次完整状态的字节 B_g 计检查点；卷积历史还要另计环形缓冲。总容量是各族驻留块或检查点、共享元数据、目录项、COW 复制和在途 staging 之和，共享物理页只计一次。\n\n需要分开四个事实：已经分配、已经计算、已经发布、仍然保留。一个块被分配不代表其中 KV 已完成；committed 长度变大不代表递归状态已更新；源端已发送不代表目标端可见；目录保留旧页也不代表它仍属于某个可恢复包。重放计划还要多一个事实：目标 p 是计划目标，只有完整步骤执行并且全部族发布后，p 才成为可消费位置。\n\n本章的不变量是：\n\n- 逻辑位置顺序和有效范围决定读取集合，物理布局只决定地址。\n- 每个族只能读取已经发布且属于同一 η 代次的范围；未完成、旧代次或越界内容不得进入 attention 或递归更新。\n- 直接恢复位置 p 必须属于所有必需族直接集合的交集；某一族的最大长度不能替代交集。\n- 重新执行 c 到 p 时，c 必须是所有必需族共同可执行的直接起点；目标 p 不能在没有执行重放时被宣布为已恢复。\n- 共享块必须是只读或在私有副本上写；引用计数管理逻辑所有者，完成事件管理物理读者，二者都成立才能重用。\n- 多池预留必须作为调度事务整体成功或整体回滚；部分成功不能发布新的可执行视图。\n\n## 层组、统一页与物理映射\n\n固定历史 vLLM Hybrid KV Cache Manager 文档区分三个量：kv hidden size 是单层一个 token 的 KV 字节；block size 是一个块的 token 数；page size 是该组层数乘 block size 再乘 kv hidden size。文档中的 num_layers 是该组涉及的层数，不是整个模型的层数。因而不能把模型总层数直接塞进每个组的页大小。\n\n为了让所有组进入同一个物理池，必须让各组页字节相等。文档给出的做法是先把层划成若干 KV cache group：组内 attention 类型相同，从而一个请求在组内需要相同数量的块；组间页大小相同，从而一个池只有一种块尺寸。规则比例模型可以把若干层重复成相同组；不规则模型取各类型层数的最小值作为组大小，剩余层用 padding 层补齐。padding 层占用页容量但不产生有效 token 状态，因此必须单独计浪费。\n\n```pseudocode\n输入：层集合、每层 attention 类型、单层每 token 字节、候选块长、各状态族的保留规则\n输出：若干同页字节的层组，或不可统一报告\n1 按 attention 类型和更新规则划分候选层组\n2 对每个候选组计算 M_g = m_g * P_g * c_g\n3 若所有 M_g 已相等，接受该分组\n4 若某递归状态族的单层状态字节 s_g 大于注意力单层一块的字节，\n   增大注意力块长，直到一个注意力块至少能容纳该递归状态\n5 若增大块长仍不能同时满足对齐、尾浪费和内核约束，放弃统一页方案，\n   改用按族池或带子分配的页，不假装统一页仍是最优\n6 记录 padding、无效层、最大块长和每组的实际有效范围\n```\n\n不同 kv hidden size 的混合模型是更硬的边界。固定文档的 case 4 先把注意力层的 block size 增大到 block_size×kv_hidden_size_att 不小于 Mamba 单层状态字节，再把每层 Mamba 状态填充到同一字节数，然后按 case 3 分组。文档自己指出这可能把 block size 推到 400 以上，并给出另一种以注意力层数参与不等式的填充方向，但仍标记为未完成设计。因此不能把统一页写成无条件的普遍最优：块越大，元数据越少，但尾部浪费、写时复制复制量和检查点内部碎片都可能上升。\n\n若用最小公倍数寻找共同页，必须算真实 LCM。384 与 512 的 gcd 是 128，LCM 是 1536，不是 196608。更重要的是，若每组 M_g 已经包含 m_g 和 P_g，只对 c_g 取 LCM 仍不够；要对齐的是组页字节，不是单个 token 字节。层数、窗口长、对齐要求和内核支持都可能让共同页不合算。\n\n物理布局也有两级。逻辑块是请求页表中的一个条目；物理页是池中的一个同尺寸块。固定文档的示例为一个组有 m 层时分配 m 个缓冲，每个缓冲被不同组中的一层共享，一个逻辑块映射到这些缓冲中的若干片段。于是，一个逻辑块不一定对应一段连续物理字节。内核必须按组和层取得块表，不能把一个组的块号直接解释为另一个组的完整连续页。\n\n## 直接集合、共同起点与重放关系\n\n对每个族定义两个集合。R_g^direct 是无需重算模型即可直接读取并继续的位置集合；R_g^replay(c,p) 表示从某个直接起点 c 出发，利用已知输入重放 c 到 p 的步骤后可以得到 S_g(p) 的关系。注意后一项不是只用 p 表示的集合，它带起点 c；同一目标 p 可能可从某些 c 重放，却不能从另一些 c 重放。\n\n共同直接位置为 D＝I∩⋂_g R_g^direct，其中 I 是索引、身份和就绪条件共同允许的位置。目标 p 若在 D 中，可以建立直接 RecoveryView；若 p 不在 D，必须存在 c∈D、c≤p，且对所有必需族 ReplayOK(g,c,p) 成立。不能先把目标 p 写成恢复视图，再指望复制现有对象产生缺失的递归状态。\n\n几个直接集合的形状不同：\n\n- 全注意力若已发布位置 [0,b] 的完整 KV，直接位置满足 0≤p≤b＋1。这里 p 是已经消费的 token 数，下一步 query 的逻辑位置是 p。\n- 窗口注意力若保留位置区间 [a,b]，窗口宽为 W，直接恢复 p 需要 [max(0,p−W＋1), p−1] 全部可读。p＝0 不需要前置窗口。若 a＝0，条件化为 p≤b＋1；若 a>0 且 p≥W，还要 p≥a＋W−1。\n- 递归状态若只有检查点集合 C_g，直接位置要求 p∈C_g 或 p＝0 的初始状态；p 之后的递推不能靠把计数器改小来逆转。\n- 卷积历史若核宽为 K_c，需要 [max(0,p−K_c＋1), p−1] 的输入历史或等价的步骤快照；少一个位置就可能改变第一个恢复 step。\n- encoder context 在源编码完成后是固定只读状态，其身份正确且完整到达时对所有后续 decoder 位置可用，但仍不能替代 decoder 自身的窗口或递归状态。\n\n设定全注意力已有 0–1023，递归检查点为 0、512、768，窗口池只保留 640–1023 且 W＝128，卷积历史覆盖 0–1023、K_c＝4。直接恢复位置为 0 和 768：p＝512 虽有递归检查点，但需要窗口 385–511，缺失；p＝1024 虽然全 KV 和窗口都覆盖，但没有 1024 的递归快照，不能直接恢复。目标 p＝1024 的共同直接起点是 768，需要重放 768 到 1024 的 256 个完整模型步。p＝512 的共同直接起点是 0，需要重放 512 步；把 512 称为零成本命中是错误的。\n\n```pseudocode\n算法 DirectRecoverable(eta, p)\n输入：请求身份 eta、候选位置 p、各族已发布范围与检查点集合\n输出：true 表示无需重放即可建立恢复视图\n1 若 p<0 或 p 超出已知输入上界，返回 false\n2 核对 eta 的模型、位置规则、dtype、布局和请求代次\n3 对全注意力族：若 [0,p) 不全部属于已发布范围，返回 false\n4 对窗口族：令 lo=max(0,p-W+1)；若 [lo,p) 不全部可读，返回 false\n5 对卷积族：令 lo=max(0,p-K_c+1)；若 [lo,p) 不全部可读，返回 false\n6 对递归族：若 p 不是初始位置或检查点，返回 false\n7 对 encoder 族：核对固定源身份和完整范围\n8 所有必需族通过且发布票据有效时返回 true，否则 false\n```\n\n```pseudocode\n算法 PlanRecovery(eta, p)\n输入：eta、目标消费位置 p、已知输入 x[0:n)、各族发布范围、检查点、容量\n输出：DirectPlan 或 ReplayPlan(c,p,x[c:p)) 或失败\n1 若 p<0 或 p>n，返回 MissingInput\n2 核对 eta 的模型、权重、adapter、位置规则、dtype、布局和请求代次\n3 构造候选 C：0、各族范围的端点与递归检查点，截到 0..p\n4 从大到小检查 c∈C：只有当所有必需族在 c 都有已发布 S_g(c) 时，加入 D\n5 若 p∈D：返回 DirectPlan(p)，不创建重放工作区\n6 从 D 中取所有 c<p，且对所有 g 满足 ReplayOK(g,c,p)\n7 若集合为空，返回 NoCommonStart，报告缺失族或缺失输入\n8 选择 c：默认取最大 c 以减少步数；若复制代价或共享保护不同，按 T_replay 加复制与同步成本比较\n9 保护 c 的快照，预留重放工作区、目标私有尾块和 COW 目标\n10 返回 ReplayPlan(c,p,x[c:p),预留,保护票据)\n```\n\nFindDirectPosition 只回答最大直接位置，不负责目标重放规划。实现不必对每个 token 逐一扫描；候选最大值一定在端点或检查点上，候选集合可以预先排序。但在窗口、递归和卷积混合时，不能只取各族最大值的 min，因为最大长度相同的族未必在同一位置同时可恢复，更不能在缺少共同直接起点时挑一个非直接检查点充当起点。\n\n## 完整模型重放与步骤提交\n\n重放不是把全 KV 页复制到 p 就结束。它必须从共同起点 c 的实际全模型状态开始，逐 token、逐层执行模型函数，并在每步结束时让所有族处于同一消费位置。下面的算法把共享历史保持为只读，把目标位置写入私有 staging；递归和卷积使用候选副本，直到整个步骤完成才提交。\n\n```pseudocode\n算法 ExecuteReplay(plan)\n输入：ReplayPlan(c,p,x[c:p))、各层参数、固定 encoder context、预留工作区\n输出：已发布的 RecoveryView(eta,p) 或失败原因\n1 建立事务 Txn，分配目标代次 gen_new；RecoveryView 处于未发布状态\n2 从 c 快照复制必需可变状态到私有工作区；共享只读块不原地写\n3 committed=c；打开 StepWorkspace 和步骤屏障\n4 for t=c..p-1:\n5   核对 x_t 的 token、逻辑位置和输入身份；hidden←输入嵌入(x_t,t)\n6   for l=0..L-1:\n7     attention 层计算 q、k、v；按逻辑可见范围读取 committed 历史和本步临时 k/v\n8     将本层 k/v 写到目标位置 t 的私有 staging；不改变 committed\n9     递归层在候选状态上执行 h_l←f_l(h_l,hidden)；卷积层把当前表示写入候选环\n10    hidden←本层输出；固定 encoder context 只读核对身份和无缺失\n11  全层完成后执行步骤屏障：检查所有候选族的布局、范围、可见性，然后 committed←t+1\n12 若步骤屏障失败：AbortTransaction(Txn,失败族/位置)，不发布 p\n13 全部步骤完成后核对每族有效长度=p、代次=gen_new、源 c 仍未释放\n14 等待所有已提交写入完成并可见，再发布 RecoveryView(eta,p,gen_new,handles)\n15 成功后按引用和完成事件关闭 c 的保护，不提前删除源\n```\n\n第 6 到第 11 步的层间数据流必须完整。attention 层的 query 只读取该层逻辑位置允许的 key/value；当前 token 的 k/v 先写入本层临时描述，attention 输出才进入下一层。递归层读取该层旧状态、当前 hidden 和该层输入相关参数，产生候选 h；它不能拿另一层的 h 充当本层状态。卷积层写入当前表示，保持核宽 K_c 所需的最近历史，不能把环回绕后的物理槽号当作逻辑位置。所有层都完成后，步骤屏障才把候选状态合并为 committed=t＋1；这保证不会出现全 KV 在 t＋1、递归在 t、卷积在 t−1 的混合视图。\n\n共享历史写区需要隔离。c 中的只读前缀可以映射到目标；目标在 c 之后需要的全 KV 尾页、窗口新槽、递归候选和卷积候选都必须私有，或写前复制。若 c 本身来自共享快照，重放不能原地覆盖它；否则其他仍从 c 恢复的请求会被破坏。重放输入的 token 必须来自同一 η 的已知输入记录，不能用模型输出或另一代次的 token 顶替。随机数、grammar 和外部输出状态也属于完整状态包；需要随机复现时必须保存对应状态，或者把该路径定义为重放不可恢复并从共同起点重新执行。\n\n硬件映射上，每层 attention 通过块表读取已提交的 KV 页；递归候选和卷积环放在私有工作区；步骤屏障是逻辑提交点，可由事件或串行协调区实现，不必假定一条全局硬件原子指令。层间流水和传输可以重叠，但任何读取都必须在对应范围完成之后，任何覆盖共享页的写都必须先完成 COW。CPU 模型或事件模型只能检查这些次序和守恒关系，不能证明目标 GPU 的数值、内存可见性或并发安全。\n\n## 联合预留、发布、失败排空与回收\n\n一次恢复可能同时需要全 KV 新页、窗口槽、递归候选、卷积 staging、COW 复制和重放工作区。若先占住 A 池再等待 B 池，而另一个请求反向占用，就可能形成持有并等待的僵局。这里的原子性是调度事务语义：可以串行化协调区，也可以用等价的线性化机制，不要求一条硬件原子指令。\n\n```pseudocode\n算法 TryReserveAll(eta, demand)\n输入：各池空闲向量 free、请求需求向量 demand\n输出：成功并扣除全部需求，或失败且不改变 free\n1 对每个池 g，若 free[g] < demand[g]，返回 false，不写任何池\n2 对每个池 g，执行 free[g]←free[g]−demand[g]\n3 记录这次预留属于 eta 的同一事务代次\n4 返回 true\n```\n\n成功路径不是先发布目标再补数据。目标句柄先处于 RESERVED 或 STAGING，复制或重放写入完成后进入 DRAIN_PENDING；只有所有必需范围完成、布局和代次核对通过、最后发布边界提交后，才进入可消费的 PUBLISHED。共享页只计一次容量；旧代次页、在途 staging 和不能释放的源快照仍占容量。\n\n失败路径必须排空在途操作。一个族失败时，其他族的 DMA、复制或重放写入可能仍在进行；撤销发布资格不等于这些物理使用已经结束。下面的事务把逻辑撤销和物理排空分开。\n\n```pseudocode\n算法 AbortTransaction(Txn, cause)\n1 Txn.state←ABORTING；停止新步骤、新复制和新传输\n2 撤销目标 gen_new 的发布资格；RecoveryView 不进入可消费集合\n3 保留源 c 的恢复票据；不删除源\n4 对每个已提交操作保留物理读者/写者票据，标记旧 Txn 代次\n5 可取消的操作请求取消；不可取消的等待完成\n6 维护 active_physical_ops；所有操作完成或取消确认后才进入 DRAINED\n7 迟到完成按 Txn、对象、范围、代次核对；不得覆盖新 Txn 的页，不得二次归还\n8 DRAINED 后回收目标页、staging、COW 复制页；归还本 Txn 预留且只归还一次\n9 容量守恒检查；返回最早 cause、缺失族和仍在途对象\n```\n\n若一个族失败而另一族写入已经完成，已完成写入先保留物理保护，目标句柄保持不可消费；等待未完成操作结束后统一回滚，不能因为一个族成功就把局部视图交给下一请求。若操作不可取消，只能等它完成；若取消得到确认，也要把取消确认当作该操作的完成记录。迟到的旧代次完成不能追加引用、不能写新代次页，也不能第二次增加空闲容量。只有在 DRAINED 后，目标页和
