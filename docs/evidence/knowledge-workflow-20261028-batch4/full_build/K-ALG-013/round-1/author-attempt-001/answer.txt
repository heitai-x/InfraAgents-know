{"chapter":"# K-ALG-013：Prefill/Decode 分离：状态传输与队列耦合\n\n分离式服务不是把 prefill 和 decode 放进两个进程就结束。它把一条自回归请求拆成两段执行权：prefill 池产生首 token 和后续 decode 所需的提示词 KV 状态，decode 池接收首 token 与状态，计算下一 token 及后续输出。收益来自阶段干扰消除和并行策略解耦；代价来自第二份权重、跨池状态、两侧排队和提交协议。只有把完整关键路径放在同一到达轨迹上比较，分离的结论才有意义。\n\n## 问题、对象与边界\n\nprefill 处理已知 prompt，通常有较多可用 query 行，较容易利用矩阵计算；decode 每步只增加少量 token，却仍要读取权重和长历史状态。共置时，长 prefill 可能推迟已有 decode，而两个阶段又被迫共享并行度、batch 和容量策略。分离允许分别选择这些策略，但每条请求必须把足够的中间状态交给 decode 池。DistServe 把 TTFT 与 TPOT 的目标和阶段资源分配联系起来，说明干扰消除的收益必须扣除状态通信和新增排队；这不是说任何负载下分离都更快。\n\n位置一律使用右开边界。设 prompt 终点为 n，prompt 位置为 [0,n)。设 H 为目标端已有、且与源端满足同一数值契约的公共前缀终点，0≤H≤n；M=[H,n) 是目标仍缺少的提示词 KV 范围。首 token 记为 y_n，它在位置 n 被采样，但其自身 KV 尚未计算。decode 端第一次前向会消费 y_n、读取 [0,n) 的 KV、写入位置 n 的 KV，并产生 y_{n+1}。把“首 token 已知”和“第二 token 所需状态已就绪”混为一谈，会得到错误的接管时序。\n\n| 对象或边界 | 含义 | 不能混淆的地方 |\n|---|---|---|\n| R、g、tx | 请求逻辑身份、请求代次、一次传输尝试身份 | 网络地址不携带模型或前缀身份；旧代次完成不能覆盖新状态 |\n| n、H、M | prompt 终点、目标有效前缀终点、目标缺少范围 | H=n 只说明提示词 KV 可能完整，不说明已有可采样的 logits 或首 token |\n| S_p(l,r) | 源端第 l 层、位置范围 r 的 K 与 V | 只有几何、dtype、scale、分片和位置规则都能共同解释时才可接收 |\n| y_n | 从 prompt 最后位置采样出的首 token | 它的 KV 不随首 token 自动出现；decode 的第一次前向才计算它 |\n| C_d | decode 端已发布、可供模型读取的 KV 前缀终点 | 到达、写入、可见和业务输出提交是不同事件 |\n| 输出策略 | 首 token 是否在状态提交前发给客户端 | 提前发送可改善 TTFT，却可能拉长第一次 token 间隔 |\n\n单请求可处于 PLANNED、P_RUNNING、FIRST_TOKEN_READY、TRANSFERRING、TARGET_COMMITTED、D_RUNNING、COMPLETED、REJECTED、CANCELLED 或 FAILED。状态推进必须满足：没有完整且可见的 M 时不能开始 decode 前向；没有 y_n 时不能用空输入推进位置 n；未提交的接收页不能被后续 query 读取；请求结束或失败后，源端和目标端按各自最后使用者回收。\n\n## 合法性：哪些条件决定可分离\n\n第一条是模型语义一致。两边必须匹配固定 checkpoint、adapter、规范化输入、位置规则、RoPE 或其他位置状态，以及影响中间值的数值表示。相同 token 在不同位置、不同上下文、不同 adapter 下不产生相同 KV；仅凭 token 文本命中缓存不构成复用。对于窗口 attention、SSM、MLA 或混合模型，所需状态不止普通 K/V，必须按能够共同恢复模型函数的状态族传输，不能只搬一个看似最大的 tensor。\n\n第二条是状态几何可解释。描述中至少要有层数、KV head 数、每 head 通道、dtype 与量化尺度、NHD/HND 或等价布局、页长、有效范围、源 TP/PP 分片和目标分片映射。源分片与目标 TP 不同可能需要汇集、切分和转置；KV head 少于目标 TP 时可能发生复制。复制因子、转换临时空间和目标实际接收字节要分别记账，不能把逻辑 KV 字节直接当成链路字节。\n\n第三条是容量与所有权。目标先为其将要接收的范围预留物理位置，才允许源写入；同一物理页不能同时作为新传输的未提交写区和活跃 decode 的私有尾部。共享前缀需要引用计数或等价的所有者记录；共享页只在所有逻辑读者与异步物理使用者都结束后回收。PagedAttention 的块表和 copy-on-write 能表达共享与分叉，但其逻辑引用计数本身不等于异步设备读取已经完成。\n\n第四条是首 token 因果。若 prefill 已从完整 prompt 的最后一行采样出 y_n，目标可以接收 y_n 和提示词 KV；此时目标能解码位置 n，但不能声称 y_n 的 KV 已在目标端存在。若目标已有完整提示词 KV 却没有同位置 logits，不能把“缓存完整”当成“已有输出”。合法做法是恢复计算最后已知位置以产生 logits，或由另一权威来源提供与该位置、模型和采样状态相符的输出票据。空 prompt 不得进入位置 −1 的恢复路径，H>n、负位置或 adapter 不匹配均终止请求。\n\n第五条是提交与释放。源端不能因为一次发送已提交或网络完成就删除最后一份可恢复状态；至少要在目标发布完整状态并回执后，或另有可重算路径时，才能释放。DistServe 论文没有把抢占和故障容错作为其已完成的运行时能力，故本章若加入回执、幂等重试或故障恢复，都是独立设计扩展，不能冒充该论文实测功能。\n\n## 接管算法：从请求选择到第一次 decode\n\n在线算法不能只选择 P 池最短队列和 D 池最短队列，因为两者相加不代表用户完成时间。它要同时估计 prefill 等待、prefill 执行、首 token 处理、传输尾段、转换、D 池等待、目标第一次前向和输出发送，并在选择前检查目标容量与状态身份。\n\n```pseudocode\nPLAN_HANDOFF(R, P池, D池, 策略)\n输入：请求身份 R、模型与 adapter、prompt 位置、到达时间、SLO、容量策略\n输出：PLAN(p,d,H,g,tx,预留,输出释放策略) 或 REJECT(reason)\n\n1  规范化输入并检查模型、adapter、位置合同；若空 prompt、超长或身份无效，REJECT\n2  令 n 为 prompt 终点，并为每个候选 d 计算公共前缀终点 H_d；若 H_d<0 或 H_d>n，排除该 d\n3  对每个可行 p,d 对：\n      若源端和目标端不能解释同一状态几何，排除\n      若 d 没有可接收的完整范围 M=[H_d,n)，检查是否已有 y_n 或同位置 logits\n          H_d=n 且没有 y_n、也没有 logits：标记 RECOVER_LAST_LOGITS\n      计算目标实际接收字节 D_net，包含分片、复制和布局转换后的写量\n      检查 d 的已承诺容量、在途接收、活跃 decode 和下一步增长是否容纳本请求\n      T_p_end ← 估计 p 排队 + prefill 执行 + 采样或首 token 处理完成时刻\n      T_state ← 估计转换尾段 + 传输尾段 + d 排队后的状态可见时刻\n      T_first_early ← T_p_end + 输出发送尾段\n      T_second ← max(T_p_end, T_state) + 第一次 decode 执行 + 输出发送尾段\n      按策略写入 D 预留、生成 g 与 tx，并用条件化 SLO 计算候选代价\n4  选择合法且预测代价最小、同时满足 TTFT 与第一次间隔目标的候选；不能只优化单池吞吐\n5  若无候选能同时保留容量、状态身份和 SLO 余量，REJECT 或返回明确的降级方案\n6  返回 PLAN；预测不是保证，执行前与第一次 decode 前仍要本地复核\n```\n\n`RECOVER_LAST_LOGITS` 是针对完整前缀命中的状态修复：读取已有 [0,n−1) 的合法历史，计算位置 n−1 的最后一行输出，取得可采样 logits；它不要求重算整个 prompt。若连这一恢复也不合法，请求应等待明确的输出票据或失败，不能以 q=0 的空 decode 永久停滞。\n\n```pseudocode\nEXECUTE_HANDOFF(PLAN)\n输入：已预留的 p、d、H、g、tx、输出释放策略\n输出：已提交到输出的首 token 与第二 token；或可回滚的失败\n\n1  再检查请求代次、模型/adapter、源状态所有者和目标预留；不匹配则停止新增写入\n2  若需要 RECOVER_LAST_LOGITS，在合法历史上恢复最后一行 logits，并得到 y_n\n3  在 p 上执行尚缺的 prompt 范围；块化和层间流水只能改变执行粒度，不能改变逻辑位置、因果 mask 或提交边界\n4  当 prompt 最后一行完成时，用固定采样状态得到 y_n，记录输出票据、位置 n 和请求代次 g\n5  将 M 按层、head/通道、位置或页分块写入 d 的未提交接收范围：\n       每个分块带 tx、范围、几何和尝试代次\n       记录已到达与已转换范围；到达但未转换的块不能发布\n       重复 tx 的完成只能消费一次，旧代次或错误状态不得覆盖当前对象\n6  当所有层的 M、布局转换和必要可见性都完成，且 d 的预留仍有效：\n       以 g 原子发布目标状态，令 C_d 覆盖 [H,n)\n       未到达范围、失败块和旧代次仍保持不可读\n7  按输出策略发送 y_n：若提前发送，记录客户端可见时刻但 Decode 仍等待状态；若门控发送，在可用时发送，但不能改变 y_n\n8  只有同时满足“y_n 已知”“C_d 覆盖 [H,n)”“d 容量与代次有效”时，才允许第一次 decode：\n       消费 y_n 于位置 n，读取已发布提示词 KV\n       计算位置 n 的 KV 和位置 n+1 的 logits\n       完成计算后才把新 KV 作为下一段提交，并采样、提交 y_{n+1}\n9  收到目标提交回执后，源端才能释放其最后一份可恢复状态；否则保留、复制到可恢复位置或明确失败\n10 任一阶段失败：停止新提交，回滚未提交目标预留，不推进 C_d，不把已采样但未提交的状态冒充外部输出\n```\n\n这里有两个合法重叠而不改变语义：层间传输可以在后续层计算时进行，但目标消费某层前必须完成该层的范围；首 token 的客户端发送可以与目标状态传输重叠，但第一次 decode 前仍要同时具备 y_n 和完整提示词前缀。重叠减少的是关键路径尾段，不是把所有分量无条件相加后再声称节省。\n\n## 静态放置、配比与成本\n\n静态放置先枚举可行的 prefill 与 decode 并行配置。一个配置至少包含实例内 intra-op、跨阶段或跨节点 inter-op、每实例 GPU 数、权重分片和 KV 分片。硬约束是每个实例的权重、工作区、输入/暂存和目标可接收状态都在容量内；如果跨节点链路弱，可要求对应 PP 阶段的 prefill 与 decode 段落在同一节点或同一强互联域，以便 KV 只走本地路径。这个约束会改变可达配置，不能先求出两个局部最优再忽略放置。\n\n对每个可行配置，用目标 workload 或校准后的模拟曲线估计 TTFT、TPOT、每 GPU 有效请求率以及尾部分布，再根据 SLO 选择较高的每 GPU goodput。粗配比可先由平均服务率约束给出：\n\nn_P ≥ ceil(λ / μ_P)， n_D ≥ ceil(λ / μ_D)，\n\n其中 λ 是到达率，μ_P、μ_D 是在指定 batch、长度、并行度和 SLO 下测得的阶段服务率或有效完成率。该式只排除显著不足的配置，不保证尾延迟；还需加入 P/D 两侧排队、传输共享、预留空转和故障余量。P 与 D 的实例数比不是固定一半一半，也不是一个总 GPU 数除以二。\n\n每个 token 的全层逻辑 KV 字节为 B_tok = 2 * L * H_kv * d_h * b，其中 L 为层数，H_kv 为 KV head 数，d_h 为每 head 通道数，b 为元素字节数。缺少范围 M 的逻辑字节为 D_log = |M| * B_tok。实际链路量还要经过源/目标分片映射、复制和布局转换，记为 D_net。若一条大消息拆成 Q 字节左右的分块，消息启动延迟为 α，路径有效带宽为 β_eff，则可先写：\n\nT_x ≈ α * ceil(D_net / Q) + D_net / β_eff + T_convert。\n\n这里的 β_eff 是实际经过的 GPU、PCIe、NVLink、NIC、交换结构和接收处理共同决定的有效带宽。peer access 可达不等于某方向有相同带宽，主机中转、注册、NUMA 或共享上行都可能进入路径。若层间传输与 prefill 重叠，`T_x` 的完整总量不能直接加到 prefill 后面；应取最后一个阻挡消费者的尾段。\n\n沿用 32 层、8 个 KV head、128 通道、2 字节，B_tok=2*32*8*128*2=131,072 字节，即每个 token 的全层 KV 为 128 KiB。N=4096 时为 512 MiB；在有效链路 20 GiB/s 下，纯传输下界为 25 ms，尚未计排队、转换、重试和共享流量竞争。若目标已有 H=1024 且数值契约成立，逻辑缺少范围是 3072 token，即 384 MiB；若不同 TP 需要重排或 head 复制，D_net 仍应按实际写入和发送计算。\n\n成本要按同一候选、同一输入和同一时间范围列账：\n\n| 成本类 | 主要来源 | 不能怎样算 |\n|---|---|---|\n| 计算 | prompt 上线性层与 attention 随 n、d 增长；decode 每步仍有权重读取和历史 attention | 不能把分离后的两池算力直接相加当作原共置算力相同 |\n| 权重驻留 | P 和 D 各自需要可执行的模型或分片副本，外加工作区 | 不能只计算活跃 KV 而忽略第二份权重的常驻容量 |\n| KV 驻留 | 源端在回执前保留，目标端接收与增长同时预留，共享前缀按唯一物理页计 | 不能把源保留、目标接收和共享副本重复当成三份逻辑需求 |\n| 通信 | D_net 经实际拓扑；消息数、复制和转换写入另计 | 平均带宽不能替代尾部分块和排队 |\n| 准备 | tokenization、页表、COW、描述符、量化和布局转换 | 小块高频准备可能比一次较大传输更贵 |\n| 同步 | 传输完成、目标可见、应用提交、源端释放的依赖 | 发送提交、CQE 和模型可消费不是同一事件 |\n| 排队与驻留 | P 队列、D 队列、预留空转、接收中状态和重试 | 不能只看 P 池吞吐或某一侧平均利用率 |\n\n设定算例中，P 排队 10 ms、prefill 执行 80 ms，故首 token 在 P 端于 90 ms 内部就绪；状态传输 25 ms、转换 5 ms、D 排队 10 ms，目标在 130 ms 提交。D 第一次前向 10 ms，输出发送 5 ms，因此第二 token 在 145 ms 可见。若首 token 在 90 ms 后立即发送并在 95 ms 到达客户端，TTFT 为 95 ms，但第一次间隔为 50 ms，超过设定 30 ms；若客户端首内容门控到目标提交后再释放，首内容为 135 ms，第二 token 仍为 145 ms，间隔 10 ms，同时满足 TTFT≤150 ms 和 ITL≤30 ms。该时间轴是设计算例，不是目标设备实测；它说明“首 token 更早可见”与“第二 token 更早可见”是两个目标。\n\n容量上，若到达 8 请求/s、平均每次缺 512 MiB，则平均传输需求为 4 GiB/s；若有效前缀命中使平均缺失减半，则平均约 2 GiB/s，但重试、复制、TP 重排和突发仍另计。平均链路余量不能证明尾部不拥塞。目标既保留接收中的状态，又保留活跃 decode 和下一步增长；预留 D 槽位能让接管更快，也可能让 D 在等待状态时空转。在线策略要显式比较这两种方案。\n\n## 条件变化与选择反转\n\n短 prompt、低到达率、模型能放在少数 GPU 上时，共置或分块 prefill 可能更简单，避免跨池权重副本和协议成本。长输入显著干扰已有 decode、TTFT 与 TPOT 可分别优化、互联足够强时，分离才更有机会。长上下文还会同时放大 prefill 计算和 KV 传输；通常 attention 工作随长度超线性增长，而传输随长度线性增长，但这一相对关系不证明网络不再是瓶颈。\n\n前缀命中率上升会减少 prefill 缺失范围，却可能把压力转移到全局缓存读取、D 池 decode 和路由热点。命中后剩余 prompt 很短时，主机准备和首行 decode 可能占比上升，应重新选择 batch、图和池配比。若目标 TP 或布局改变，原直接传输路径可能变成重排或复制，必须把转换临时空间和带宽加入比较；不能沿用原布局的传输时间。\n\n当有效链路下降、目标接收容量不足、D 队列尾部变长，或协议无法在源端释放前保留可恢复状态时，应调整为先共置、减少分离粒度、增加本地缓存，或放弃该请求的分离路径。若模型不是可保留历史 KV 的普通 causal decoder，或状态族无法在同一恢复位置共同提交，不能把普通 K/V 分块算法直接外推。无论条件怎样变化，逻辑位置、已确认输入、完整前缀和提交点这些不变量要保留；可替换的是页长、分块、并行度、输出门控和预留策略。\n\n##
