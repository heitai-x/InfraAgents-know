{"chapter":"# K-SYS-002：请求身份：逻辑序列、批次视图与结果归属\n\n请求是长期语义对象，batch 行与物理槽是临时执行位置；模型结果只有沿稳定身份、逻辑位置、版本和提交权回溯时，才属于某个用户请求或某个搜索分支。仅让张量形状合法或让最终文本看起来合理，不能证明归属正确。\n\n## 问题、身份与不变量\n\n请求身份问题来自多个时间尺度的交叉。一个请求可能经历多轮 prefill/decode、一次或多次执行尝试、压紧与重排、取消、迁移和槽位重用；设备 kernel 通常只看到本轮压紧后的 token 行。若每轮都从当前活跃列表或当前行号重新猜测某行属于谁，生成文本、KV、采样参数、grammar、随机状态和 usage 可能分别落到不同对象上。\n\n稳定请求生命期为 \\(r=(request\\_id,lifetime\\_id)\\)。lifetime 防止外部请求号被重用；租户、会话、回合和输入版本另行记录，不能只靠 request_id 推断授权或缓存等价性。\n\n分支身份不能只用父分支和分叉位置表示。定义\n\n\\[\nb=(r,branch\\_id),\n\\]\n\n其中 branch_id 在请求生命期内唯一、稳定且不复用。分支记录还保存关系字段\n\n\\[\nB=(b,parent\\_branch,fork\\_position,fork\\_ordinal),\n\\]\n\nparent_branch 与 fork_position 描述父路径和逻辑分叉位置；fork_ordinal 记录同一次分叉的创建序号。它们解释分支从哪里来，但不代替 branch_id。同一父分支、同一 fork_position 创建的两个独立样本是两个不同 b；即使它们选择了相同 token、使用相同输出序号或占用相邻物理行，也不能合并其 KV、grammar、RNG 和输出。\n\n一次执行尝试记为 g，本轮执行视图记为 t。物理槽为 σ，槽生命期为 eσ，每释放并重新分配槽时递增。对本轮选中工作，放置键为\n\n\\[\n\\kappa=(r.lifetime,b.branch\\_id,g,p),\n\\]\n\n其中 p 是分支内的逻辑绝对位置。一个逻辑原子还携带不可变版本元组 ρ=(model_revision,adapter_revision,processor_revision) 和可选的输出序号 o。o 是分支内序号，不是分支身份；两个兄弟分支可以都从 o=0 开始。需要多种采样目标角色时，应扩展目标身份或建立不同分支，不能只按 (r,p) 合并。\n\n选中工作集记为 A_t，物理行集合为 I_t={0,...,L_t-1}。视图的关键是一个双射\n\n\\[\n\\pi_t:I_t\\to A_t,\n\\]\n\n即每个物理行恰好指向一个逻辑原子。所有按行索引的张量 X 满足 X_t[i]=X_logical[π_t(i)]；不能只对 token 行做 gather，而让 positions、页表、长度、采样参数、输出目标或 mask 保持旧顺序。\n\n长期请求状态至少记录：已确认 token 序列 x_r[0:n_r)、全层有效 KV 连续边界 k_r、各分支保留路径和淘汰状态、采样与 RNG 状态、grammar 状态、累计生成序号、当前尝试 g、取消/失败标志和输出提交位置。0≤k_r≤n_r。已知 token 与已完成 KV 不是同一个量；采样得到的最后一个 token 也可能尚未计算自己的 KV。执行视图包含 π_t、输入 token 行、绝对位置、mask、页表/槽映射、模型与 adapter 版本、每个采样目标、输出槽和资源引用。输入是请求账、分支表、候选工作、资源与版本快照；输出是不可变视图和唯一执行记录。\n\n这组定义支持以下不变量：\n\n1. 分支唯一：每个分支有稳定 branch_id；同父同位置的两个兄弟分支可共享父路径、fork_position、token 内容和输出序号，但身份不同。\n2. 行唯一：同一视图内不能出现同一 κ 的重复行；不同 b 在同一 p 上出现候选是合法的。\n3. 位置一致：同一请求同一分支的位置按逻辑顺序增长，不越过已确认输入；prefill 的每一行都必须有正确绝对位置与因果可见集合。\n4. 字段同源：所有行索引字段来自同一个 π_t 快照；请求索引字段按稳定请求键和 branch_id 保存，不能借当前数组下标重新关联。\n5. 版本绑定：每行携带并遵守准入时绑定的模型、adapter、processor 与数值路径；混合版本只有在执行器确实逐行支持时才合法。\n6. 完成有权：结果提交必须匹配 view_id、请求生命期、branch_id、尝试 g、槽 σ 与槽生命期 eσ；旧结果或重复通知不能写入新生命期，也不能第二次推进输出。\n7. 资源有终：槽、页、输入/输出缓冲和每个消费者都有明确最后使用者；业务提交、输出读取和物理释放是不同事件。\n8. 可观察关联：trace 中的请求、batch、行、尝试和 branch_id 关系能被显式重放；父子 span 只是相关性，不是身份或授权的替代品。\n\n## 合法性与表示选择\n\n一个视图合法，首先要求 π_t 是双射，且 A_t 中不出现同一 κ 的重复行。q_r 必须为正整数；没有可执行工作的空计划不提交空 kernel，而应等待新的输入、资源或完成事件。两兄弟分支在同一父分支、同一位置分叉时，必须同时通过 branch_id 和 fork_ordinal 区分；不能用 token 文本、RNG 种子、页号或当前行号代替 branch_id。\n\n位置合法性依赖请求阶段。普通 decode 通常从 k_r 开始取 q_r=1；分块 prefill 取 [k_r,k_r+q_r)，且 k_r+q_r≤n_r，范围中的输入必须已经由模型输入契约确定。若 k_r+q_r<n_r，本轮只产生 KV，不因中间某行有 hidden state 就发布生成 token；若 k_r+q_r=n_r，末行 logits 才可以按该分支的采样状态产生候选。分支的每个节点也必须满足父路径、逻辑位置和可见 mask；物理行连续不说明它们属于同一序列或同一可见分支。\n\n版本是一个条件，不是可以从文本相似性推断的属性。一个 batch 内可以有不同 adapter 或不同模型版本，但只有当执行包、页表、权重地址和结果校验都按行携带版本，且执行器支持这种组合时才合法；否则应先分桶或拒绝。租户作用域同样不能由相同 token 自动推导：相同文本属于不同租户时，是否允许共享不可变公共前缀由缓存授权契约决定，至少不能仅凭内容 hash 合并拥有者。\n\n物理表示有选择空间。压紧行减少空行，却需要 gather/scatter 和 metadata 重排；固定槽或固定桶保留地址稳定，却可能计算填充行，并仍需在槽被重用时检查 owner 与 eσ。两者都合法，但都不能省掉“该行属于哪个 κ”的映射。固定槽不是放弃身份，只是把映射从每轮行置换改为槽占用表和行描述。\n\n旧式 request-level 批处理把一整批请求固定到全部完成；ORCA 的迭代级调度把 engine 的一次迭代作为边界，完成请求可退出，新请求在后续边界进入。这个改变使同一 batch 内不同请求可能处于不同长度、不同阶段，因而必须显式记录请求 id、当前 token 位置、输入行和结果目标。旧式整批完成只是在特殊情况下减少了映射变化，不是身份语义的充分条件。\n\n## 视图构造、冻结、完成与提交算法\n\n下面的算法把身份、压紧、首次完成和资源最后使用分开。选择哪些工作是策略；生成合法视图、冻结字段和判定提交权是机制。\n\n```pseudocode\n算法 1：构造并冻结一轮视图\n输入：请求账 L，分支表 B，候选工作集 C，页/槽/版本快照，本轮预算\n输出：不可变视图 V_t 与执行记录 E_t；若无合法工作则返回空计划和阻塞原因\n\nA ← 空；S ← 空\nfor each 候选 (r,b) in 策略顺序:\n    若 r 不活跃、已取消、b 已淘汰、该 (r,b) 已有禁止并发的在途尝试，或其输入/资源未就绪：跳过\n    读取分支记录 B[r,b]，核对 parent_branch、fork_position、fork_ordinal 与 b 的关系\n    p0 ← 本轮逻辑起点；选择正整数 q，满足位置上限、token 预算、页/槽预算与输出缓冲容量\n    若不存在正 q：记录具体阻塞原因并继续其他候选\n    for j ← 0 到 q−1:\n        p ← p0+j；κ ← (r.lifetime,b.branch_id,g,p)\n        若 p 越界、越过已确认输入、或 κ 已在 A 中：拒绝该候选并撤销临时预留\n        若 p 是采样末位置：o ← 本分支当前预留的下一个输出序号；否则 o ← ⊥\n        A ← A ∪ {(κ,ρ,o)}；记录行描述 (κ,σ,eσ,采样目标或 KV 目标)\n    记录段 (r,b,p0,q,g,σ,eσ,资源预留)\n    登记执行职责 dev(view_id)；若产生输出，登记输出职责 out(view_id,o)\n若 A 为空：返回空计划，不提交 kernel\n选择双射 π，使 I={0,...,|A|−1} 与 A 一一对应\nfor each 行索引字段 f: f_rows[i] ← gather(f_logical[π(i)])\nfor each 请求索引字段 h: h_view[r] ← snapshot(h[r])，只保存本视图引用到的请求和分支\n由同一 π 生成采样目标行、输出目标、KV 页引用和 mask\n校验：|A|=行数、π 为双射、κ 唯一、位置不重叠、字段版本与分支绑定一致、页/槽引用可用\n冻结 V_t；建立执行记录 E_t，保存 view_id、每个请求/分支的 g、σ、eσ、行范围、holders、claimed=false、committed=空、released=false\nreturn (V_t,E_t)\n```\n\n注意 E_t 保存的是实际执行信息，而不是从逻辑原子临时猜测槽。槽和 epoch 在视图提交时由槽表快照写入 E_t；之后所有完成、取消和回收都读取同一执行记录。\n\n```pseudocode\n算法 2：首次完成、业务提交与最后使用者回收\n输入：view_id，完成证书 C，行结果，请求账，槽表，执行记录表\n输出：至多一次业务提交；至多一次资源清账\n\nE ← 执行记录[view_id]\n若 E 不存在：返回 unknown；不改变请求或资源\n若 E.completion_claimed：返回 duplicate_noop；不追加输出，不删除 holder，不释放资源\n若 C 不覆盖 E 的全部必要写入、行范围、槽 owner 与 epoch：把 C 放入 E.quarantine；返回 incomplete_wait\n若 CAS(E.completion_claimed,false,true) 失败：返回 duplicate_noop\n保存 C 的首次完成证据\nfor each 行描述 d in E.rows:\n    a ← 由 π_t 和 d 取逻辑原子\n    若 d 不在 C 的行范围，或 C 未证明该行必要层/写入完成：E.quarantine ← true；丢弃本通知业务结果\n    否则若 r 已取消、失败、a.g ≠ current_attempt(r)、槽 owner/epoch 不匹配：标记该分支 discarded\n    否则把 (a,结果) 放入对应分支 staging\nfor each 请求分支 (r,b):\n    若 discarded 或 staging 不满足位置连续、全部必要行通过：不提交业务状态\n    否则若 commit_key Q=(r.lifetime,b.branch_id,g,o) 尚未在 E.committed：\n        原子地把 Q 写入 E.committed；追加一次输出、推进一次 RNG/grammar 和 output 序号\n    否则：不重复追加\nfor each 唯一执行责任 uid in C.execution_responsibilities:\n    若 uid 属于 E.holders：删除 uid，且只删除一次\nfinalize(E)：若 E.holders 为空且 E.released=false：\n    标记 E.released=true；释放执行视图引用；当槽引用为零且结果缓冲不再被读取时，slot_free(σ) 并 eσ←eσ+1\n```\n\n输出消费者不能复用完成证书来释放自己的引用，而应提交独立 cid。处理 consumer_done(view_id,cid) 时，仅当 cid 仍在 E.holders 中才删除；重复 cid 不删除任何东西。E.holders 为空之前，槽不能因完成通知而被释放；E.released 已为真时，重复完成或重复消费者通知都不能第二次递增 eσ。\n\n以一个设定例子说明映射。A 占 q_A=2 行，B 的两个兄弟分支 b1、b2 各占 1 行，C 占 q_C=3 行。若按 A、B.left、B.right、C 压紧，则 A 的行是 [0,1]，两个兄弟分支是 [2]、[3]，C 是 [4,5,6]。两个兄弟分支可以有相同 token 文本 X:0、相同父分支和 fork_position，也可以都使用输出序号 0；它们的 target key 仍因 branch_id 不同而不同。若 B.left 完成后压紧为 A、B.right、C，B.right 的旧行 3 变成新行 2，C 的旧行 4、5、6 分别变成新行 3、4、5。对所有行字段都必须有 X_new[2+j]=X_old[3+j]，而不能只移动 token 行。若 A 是 128 个 token 的 prefill，C 只有 1 行，则末行采样目标是 127 与 128；把 128 行误算成 C 的第一行，或把 127 行当作 C 的上下文，都会形成形状正确但语义错误的结果。\n\n采样目标也不能由“每请求固定一行”推断。prefill 只需要最后有效位置时，候选行是 p0+q−1；需要 prompt logprobs、分支验证或多个候选时，目标集合必须另行记录。两个兄弟分支即使选择同一 token，仍需各自独立的 RNG 子序列和输出位置；合并它们会得到一个看似相同、实际无法解释的随机轨迹。\n\n## 提交权、重复通知与资源最后使用\n\n请求长期状态可记为 LIVE、CANCEL_REQUESTED、DRAINING、DONE；槽可记为 FREE、RESERVED、INFLIGHT、QUARANTINED、FREE。名称可以合并，状态变化不能省略。取消首先禁止新的业务提交和后续调度，但已启动的 kernel、DMA、通信、结果消费者和 KV 读者仍要完成。物理完成事件到达后，旧槽才能进入可复用状态；eσ 递增使旧结果失去提交权。\n\n完成记录必须至少包含：view_id、请求生命期、branch_id、attempt、slot、slot_epoch、行范围、必要写入覆盖、holders、completion_claimed、committed 和 released。业务提交只允许执行一次；资源清账只允许按唯一 holder 删除一次。重复的合法通知在 E.completion_claimed 为真时直接返回 duplicate_noop，不进入 staging，也不删除任何 holder。\n\n设请求 A 在槽 σ=3、eσ=1 上执行一次旧尝试，结果尚未返回。A 被取消后，完成清理条件满足，槽 3 被分配给请求 C，eσ=2。此时迟到的 A 结果即使文本和形状都正常，也只能用于物理排空，不能写入 C 的第一 token。判定至少要求：view_id 匹配原执行记录，result.request=C、result.lifetime=current_lifetime(C)、result.branch 属于 C、result.attempt=current_attempt(C)、result.slot=当前槽、result.epoch=当前 eσ。只检查 slot 号会把旧 A 的结果误认为 C 的结果；只检查 request_id 会在外部请求号重用或重试时混淆生命期。\n\n有效通知重复到达是另一个独立反例：同一 view_id 的完成证书在 attempt 和槽生命期未改变时再次到达，第一次已经追加输出并删除 dev 责任；第二次若没有 completion_claimed 门，会再次推进 RNG、追加输出或释放 holder。原子提交只能避免一次更新内部的部分提交，不能防止重放。必须把首次完成、业务已提交和引用最后使用分别记入 E_t，并以比较并交换或等价事务消费提交权。\n\n输出缓冲也要有独立的提交与释放边界。模型执行完成而网络消费者尚未读取时，缓冲区仍活着；若为了腾出槽而过早覆盖，即使最终文本尚未产生，也会破坏重试或流式序号。若客户端已取消但结果仍在途，业务输出丢弃，缓冲直到最后一个读者结束才回收。这个边界与本轮 KV 的 k_r 更新不同：前者是外部交付，后者是模型状态。\n\n分支请求把上述规则扩展到 (r,b,g,p)。beam 淘汰一个分支、投机拒绝一个候选或重排候选顺序时，父路径与已确认位置不变；只有保留分支可以更新正式 token、评分、grammar 和随机状态。旧分支的完成通知仍要释放其页和缓冲，但不能把结果拼接到新分支。多样本、beam 和投机树的概率目标不同，不能用相同的“行结果”逻辑替代各自的接受规则。\n\n分布式执行还会增加执行地点。一个请求从 worker 1 迁移到 worker 2，逻辑请求身份和 branch_id 不变，但 attempt、执行组、槽和地址改变；目标只接收与当前授权相容的尝试。迁移期间源端和目标的提交权必须唯一，旧 worker 的迟到结果不能重新取得提交权。流式 trace 或 checkpoint 只保存文本而不保存输入版本、branch_id、模型版本和输出序号时，恢复后可能把重算结果接到错误位置。\n\n## 成本模型\n\n设一轮有 L_t 行、R_t 个被引用请求、B_t 个活动分支、F 个行索引字段和 G 个请求索引字段。使用哈希表把 κ 映射到行，生成视图的基本准备成本是\n\n\\[\nC_{prep}=O(L_t\\cdot F+R_t\\cdot G+B_t),\n\\]\n\n若实现为每行扫描活跃请求和全部分支再找所有者，则可能退化为 O(L_t·R_t·B_t)。完成验证按权威账查找每个行键，期望成本为 O(L_t+T_t)，其中 T_t 是采样目标数；若逐行线性扫描账本，则退化为平方级。压紧还需要 gather/scatter；如果所有字段都搬移，逻辑搬运字节可写为\n\n\\[\nB_{compact}=\\sum_{i\\in I_t}\\sum_{f\\in F} width(f)+请求字段的额外副本。\n\\]\n\n实际设备事务量还要按布局、对齐、合并和缓存层级重新计算，不能把逻辑字节直接当成设备耗时。固定槽省去部分行搬移，却可能执行填充行；填充比例 (P−L_t)/P 只描述槽位，不直接等于时间浪费。兄弟分支拥有相同 token 内容不会使独立 RNG、grammar 和输出状态的驻留成本消失；把它们合并成一个逻辑对象可能降低账面行数，却改变语义。\n\n映射本身需要 O(L_t+B_t+R_t) 个条目；若允许 D 个视图同时在途，执行记录、提交集合和输出缓冲驻留上界近似为 O(D·(L_t+B_t+R_t+T_t)) 加 O(D·L_out) 的结果容量。重复完成判断通常是常数次查找，但隔离通知、trace 事件和审计记录仍随事件数增长。准备、设备计算、结果处理和输出等待属于不同阶段；若它们有依赖，应沿关键路径相加；若能重叠，只能把共享资源和同步约束计入。\n\n## 条件变化后的保留与调整\n\n稳定请求、branch_id、逻辑位置和提交权在所有表示变化下保留。可调整的是视图表示：固定槽、压紧行、按请求分桶、分层传输或迁移执行地点。若只有一条请求且没有并发，仍可简化为直接索引，但只要存在槽位重用、重试、兄弟分支或缓存共享，就必须保留生命期、尝试、branch_id 和版本。\n\n当执行器使用大图重放或固定地址时，常见的调整是固定槽并只更新占用表和行描述。这样可以减少每轮 gather，却不能省略槽 owner、eσ 和逻辑位置校验；也不能把 padding 行当成有效请求。反之，当活跃集合变化很大、长 prefill 与短 decode 混合时，压紧更合适，但必须支付所有字段的重排成本。\n\n投机与 beam 扩大了行身份：一行可能对应一个候选节点而不是请求的正式下一 token。此时应保留父分支、分叉位置、fork_ordinal、branch_id 和接受状态；分支重排后，KV、grammar、RNG 和评分都要跟随同一分支原子。迁移或恢复改变的是尝试与执行地点，不应改变已经向用户承诺的请求身份；若目标没有当前授权，旧结果只能清理资源。\n\n前缀缓存命中只说明某些模型状态可能复用，不说明输出目标或提交权已经确定。共享页需要拥有者、读者和写时复制条件；一个请求命中另一租户的不可见前缀，不是合法共享。trace 上下文可以跨服务传播 trace ID 与 span ID，但请求到 batch 是多对多关系，需要额外的 view_id、batch id、行映射、请求键和 branch_id。\n\n## 区分实验、反例与负对照\n\n同一段输出看起来合理，可能来自数值模型、采样状态、版本绑定、分支身份或完成重放。应选择能改变一种解释而保持其他条件的实验。\n\n| 观察或实验 | 竞争解释 | 有区分力的检查 |\n|---|---|---|\n| 单请求执行正确，混批错误 |
