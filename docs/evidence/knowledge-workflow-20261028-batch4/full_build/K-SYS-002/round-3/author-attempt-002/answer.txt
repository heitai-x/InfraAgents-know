  "chapter": "# K-SYS-002：请求身份：逻辑序列、批次视图与结果归属\n\n请求是长期语义对象，batch 行与物理槽是临时执行位置。模型结果只有沿完整请求生命期、分支、逻辑位置、版本和提交权回溯，才能归属于某个用户请求。张量形状正确、最终文本合理，都不能证明归属正确。\n\n## 身份、状态与不变量\n\n身份问题来自多个时间尺度的交叉。请求经历多轮 prefill/decode、压紧、取消、重试和迁移；设备通常只看到本轮 token 行。若各阶段分别用当前活跃列表重新解释行号，token、KV、采样参数、grammar、RNG、计费与输出可能落到不同对象上。\n\n定义完整请求生命期为 r=(request_id,lifetime_id)。lifetime_id 只要求在同一个 request_id 的重用之间不复用，不要求跨 request_id 全局唯一。外部请求号需要先进入服务的去重命名空间；若不同入口可分配相同请求号，应把入口命名空间纳入 request_id。会话、租户、回合、输入版本与授权另行保存，不能从请求号或 trace ID 推断。\n\n分支身份为 b=(r,β)，β 是请求生命期内唯一、稳定且不复用的 branch_id。分支记录另存 parent_branch、fork_position 和 fork_ordinal，描述父路径与分叉关系。两个兄弟分支可以具有相同父分支、分叉位置、token 内容及输出序号；它们仍有不同 β 和各自的可变状态。fork_ordinal 可以辅助解释创建次序，但不能用文本、页号或当前行号替代 β。\n\n设 g 为当前执行尝试的授权代次；一次尝试内可以执行多个视图。t 是一次提交的唯一 view_id，不因重试通知而改变，也不分配给另一次提交。放置键统一为\n\nκ=(r,β,g,p)=((request_id,lifetime_id),branch_id,attempt,logical_position)。\n\n权威行账 H[κ]、去重表、逆映射、结果关联均使用这个完整键。仅保留 lifetime_id 不充分：A 与 B 可以同时具有 lifetime_id=1、β=1、g=0、p=0，二者必须独立保留。\n\n物理槽 σ 指本轮执行包所用的输入、metadata、workspace 和结果缓冲槽，不等同于长期 KV 页。槽生命期为 eσ；槽释放时递增，再次分配时使用新值。槽 owner 保存 view_id。逻辑键解释“算谁”，(view_id,σ,eσ) 解释“由哪次物理执行产生”。两者均不能省略。\n\n每个分支的长期状态 L[r,β] 至少包含：已确认 token 序列 x[0:n)、全层有效 KV 连续边界 k、输入与模型版本、grammar、RNG、下一个输出事件序号 o、状态修订号 v、当前授权 g、停止/取消/失败标志，以及尚未释放的执行视图。普通推进满足 0≤k≤n；已知 token 与已完成 KV 不同。新采样 token 可以已经进入 x，却尚未计算自己的 KV。以下 n、k、o 均按分支记录，不能让兄弟分支共享可变计数。\n\n本轮选中逻辑原子集合为 A_t，物理行集合 I_t={0,…,L_t−1}。视图保存双射 π_t:I_t→A_t。每个原子包含 κ、版本元组 ρ=(model_revision,adapter_revision,processor_revision)、输入 token、位置与可见性，以及可选采样目标。所有行字段必须满足 X_t[i]=X_logical[π_t(i)]。请求或分支字段则按 (r,β) 索引，不能借当前数组下标重新关联。\n\n机制输入是请求/分支账、候选工作、资源与版本快照；构造输出是不可变视图 V_t 和执行记录 E_t。设备完成后先产生候选结果，只有通过提交检查，才更新长期状态。需要保持以下不变量：\n\n1. 完整归属：π_t 是双射，κ 不重复；同一局部身份在不同 request_id 下不碰撞。\n2. 同源字段：token、position、mask、页表、参数、版本、logits 目标和输出目标来自同一视图快照。\n3. 连续状态：只把已证明全层完成且仍有效的连续范围推进到 k；候选 token 不自动成为已确认输入。\n4. 唯一提交权：完成必须匹配完整请求生命期、β、g、view_id 和槽凭据；取消、失效和重复通知不再次更新业务状态。\n5. 最后使用：每个实际物理使用者有独立责任标识；业务提交、消费者结束和槽释放是不同事件。\n6. 可重放观测：请求、分支、视图、物理行与尝试的关系显式保存，父子 span 不承担授权或去重职责。\n\n## 合法工作与表示选择\n\n本章的主算法采用保守范围：每个分支最多有一个尚未释放的视图；支持普通自回归生成、分块 prefill，以及已经建立独立状态的多个样本分支。跨请求、跨独立分支可以混批。beam 与投机验证需要后文说明的共同接受边界，不能直接把所有候选当作正式输出。\n\n普通推进选择 [p0,p1)=[k,k+q)，其中 q 为正整数，p1≤n，输入已经确认，历史与因果 mask 可用，写区具有独占写权或合法 COW。目标类型明确保存为：\n\n- KV_ONLY：p1<n。本轮只完成一段已知输入，不从中间 hidden state 发布生成 token。\n- SAMPLE：p1=n，且仍需生成。采样目标是逻辑位置 p1−1 对应的 logits 行，预测的是位置 n 的下一 token；不是给该输入行再生成一个 token。\n\n不能为了凑满 batch 执行尚未采样的普通自回归后继。prompt logprobs、树节点验证或多个 logits 消费角色需要独立目标描述，不能套用“每请求一行”的简化。\n\n空计划不提交 kernel；空 prompt 按固定输入契约补 BOS 或拒绝，本章例子选择拒绝。输出额度为零或已经结束的分支不创建生成工作。达到长度或生成上限后停止；无需为了补齐最后一个已交付 token 的 KV 而继续生成。\n\n还需避免完整 KV 命中后的停滞：若 k=n，却没有兼容的末行 logits，且仍需生成，仅计算 n−k 会得到零。可在准入/恢复时只把 min(命中长度,n−1) 作为本次可复用边界，并在私有写区安全重算最后一个已知 token；共享尾页先 COW，不能原地覆写。另一种选择是缓存并核验末行 logits，但必须绑定完整输入、模型与数值路径，且不能重放已经提交的采样。已有输出应从输出账恢复。\n\n混合版本只有在执行器逐行支持相应权重地址、页表与数值路径时才合法，否则分桶。相同 token 不证明缓存可共享；租户授权与计算等价性必须同时成立。压紧减少空行，固定槽或固定桶保留地址稳定；二者都是表示选择，都需要身份映射和槽生命期检查。\n\nORCA 的迭代级调度允许请求在迭代边界进入或退出，因而批组成与请求生命期不同。其选择性聚批把共享权重的线性操作聚合，把论文狭义 Attention 按请求组织。这一历史组织不能推出变长 Attention 在数学上不可聚批；现代分段执行仍须保持每段的身份、位置和可见集合。\n\n## 不可变视图与执行记录\n\n每个选中分支保存段描述\n\nS=(r,β,g,p0,p1,n0,o0,v0,目标类型,版本,输入与采样状态快照,资源引用)。\n\nn0、o0、v0 是构造时的状态，不能在完成时用当前账本重新推测。E_t 另存 view_id、σ、eσ、行描述、π_t、段集合、完成状态、各段处理结果、已提交键、消费者描述和 holders。槽凭据来自真实分配记录，不从 κ 临时猜测。\n\nKV 范围提交键为 J=(view_id,r,β,g,p0,p1,KV)，采样提交键为 Q=(r,β,g,o0)。二者都包含完整 r。跨尝试的逻辑输出账还以 U=(r,β,o0) 去重：更换 g 不能让已经确认的同一输出序号再次采样或发布。Q 标识执行尝试中的提交，U 标识对外可恢复的逻辑输出事件。键的存在不自动实现分布式一致性；共同账本仍需事务或等价授权协议。\n\n每个实际输出消费者分配唯一\n\ncid=(view_id,r,β,g,o0,role,instance_serial)。\n\nrole 可以是 transport、trace 或结果复制；同一角色有多个消费实例时由 instance_serial 区分。serial 在该视图内不复用。构造时先分配消费描述，实际启动前才把 cid 加入 holders，并且必须先登记后启动。未启动的描述不构成物理责任。纯 KV 工作没有输出消费者；取消或失败时也不保留一个永远不会启动的虚构输出责任。\n\n```pseudocode\n算法 1：构造、冻结并提交视图\n输入：L、分支关系表、候选工作、资源池、版本快照、本轮预算\n输出：V_t、E_t，或空计划与具体阻塞原因\n\n分配不复用的 view_id；临时段集合、原子集合、资源预留均为空\nfor each 候选 (r,β) in 策略顺序:\n    若分支不活跃、已取消/淘汰、已有尚未释放视图或依赖未就绪：跳过\n    读取完整 r、β、g、v、x、k、n、o、ρ、grammar 和 RNG 快照\n    在 1≤q≤n−k 内选择满足 token、页、位置和缓冲预算的正整数\n    无合法 q：记录原因，继续其他候选\n    p0←k；p1←k+q；kind←KV_ONLY 若 p1<n，否则 SAMPLE\n    临时预留该段独占写区和执行/结果容量；失败则撤销该候选预留\n    在候选私有集合中展开每个 p∈[p0,p1)：\n        κ←(r,β,g,p)\n        校验 κ 不重复、输入已确认、位置/mask/版本和读写权限一致\n        采样标记仅属于 kind=SAMPLE 且 p=p1−1 的行\n    任一校验失败：撤销整个候选，不向总集合留下半段\n    成功：合入原子集合；保存段 S，包含 p0、p1、n0、o0、v0 和 kind\n    若 kind=SAMPLE：为每个计划输出角色分配完整唯一 cid，保存消费描述\n若没有原子：撤销空预留，返回空计划，不提交 kernel\n\n选择 π_t；由同一 π_t gather 所有行字段并建立逆映射\n从同一段表建立 logits 目标与按 (r,β) 索引的状态副本\n核对完整 κ 的覆盖、唯一性、全部字段、目标资格和资源引用\n取得空闲执行槽 σ，记录 owner[σ]=view_id 和当前 eσ\n冻结 V_t；建立 E_t，completion_claimed=false，released=false\n登记准备/设备和执行包之外的实际使用责任 uid，再启动相应操作\n准备完成证据到达后，再次核验分支授权、快照修订号、槽 owner/epoch\n若取消或提交失败且确定设备未接受：不更新 k/n/RNG/输出，清理已结束责任\n若提交状态不明：保留责任，进入查询或排空，不能当作未提交直接重用\n提交成功：标记在途，禁止覆写视图使用的输入、metadata、页表和缓冲\n```\n\ng 在尝试内不随每轮增加，view_id 区分各轮；v 在长期状态变化时增加。这里等待本分支上一视图全部释放再构造下一视图，避免在说明身份机制时另引入同分支多轮流水。更深流水必须增加依赖、未确认进度和提交次序，不能直接删除这一限制。\n\n## 完成、纯 KV 推进与生成提交\n\n完成证据首先证明物理事实，再决定业务合法性。证据需要匹配 E 的执行身份，并覆盖必要行、全层 KV 写入、logits 生产以及声明的可见性边界。它不等于“主机调用返回”。实际 GPU/通信 API 如何提供这些证据，需另按执行路径核验。\n\n尚未证明相关访问结束时，保留设备责任并等待排空；已经证明排空却执行失败或缺少必要写入时，可以清理物理责任，但不能把部分 KV 或 logits 当作成功。本章采用整视图完成门；逐段完成是另一种实现，需要逐段首次处理门和相应资源责任，不能复用一个布尔量处理多次部分通知。\n\n状态事件由单一协调器串行处理；多线程实现需要等价锁或事务，使取消与提交具有确定先后。采样使用快照中的 RNG/grammar 副本，候选计算不能直接改写长期状态。\n\n```pseudocode\n算法 2：首次完成与分支状态解析\n输入：view_id、完成证据 C、行结果、L、槽表和 E 表\n输出：每段至多一次状态解析；物理责任按真实结束证据清理\n\nE←E表[view_id]\n若不存在：返回 unknown，不修改请求和资源\n若 C 的执行身份不匹配 E：隔离该消息，不消费任何责任\n若 E.completion_claimed：返回 duplicate_noop\n若 C 未证明相关设备访问全部结束：保留设备责任，返回 drain_wait\n原子判定并设置 E.completion_claimed；竞争失败则返回 duplicate_noop\n\n若 C 执行失败，或未覆盖 E 的必要行、全层写入与结果可见性：\n    标记本次执行失败；停止受影响旧授权的后续业务推进\n    不提交部分 k、token、RNG 或输出\n否则 for each 段 S in E:\n    按完整 (r,β) 查 L，并校验：\n        分支仍活跃、未取消/淘汰，g 和当前提交授权匹配\n        active_view=view_id；槽 owner/epoch 与 E 相符\n        当前 v=v0、k=p0、n=n0，输入与采样状态仍对应快照\n        staging 恰好覆盖 [p0,p1)，全部必要行通过\n    若任一失败：将该段记为 discarded，不更新业务状态\n    否则若 S.kind=KV_ONLY：\n        在同一事务中消费 J 并令 k←p1、v←v+1\n        x、n、RNG、grammar、o 和输出账保持原值\n    否则若 S.kind=SAMPLE：\n        仅取 π_t 对应 p1−1 的末行 logits\n        按规定顺序应用本分支采样变换和 grammar mask\n        在 RNG 副本上产生候选 y、后继随机状态与 grammar 状态\n        若无合法候选或采样失败：\n            消费 J，保存已证实的 k=p1，标记失败\n            不追加 token，不消费正式随机状态，不发布输出；恢复另行取得 logits\n        否则在同一事务中再次校验授权与快照，并检查 J、Q、U 尚未消费：\n            k←p1\n            若 y 是非停止 token：在旧位置 n0 追加 y，n←n0+1\n            若 y 是 EOS：按本章契约不把 EOS 加入 x，n←n0，记录停止\n            安装候选对应的 RNG 与 grammar 后继状态\n            写入唯一输出事件 (r,β,o0,内容或停止原因)，o←o0+1，v←v+1\n            消费 J、Q、U；已达到停止条件时禁止后继调度\n            给新有效 KV 建立长期引用，不能只留下 E 的执行引用\n            为真正启动的每个输出消费者，把其 cid 加入 holders 后启动\n    保存该段 resolved/discarded/failed 结果，之后不能再次解析\n\n仅删除本次证据确实覆盖的设备责任；不代替其他 uid 或 cid 完成\n调用 finalize(E)\n```\n\n采样推进量由采样契约决定：greedy 可以不消耗随机数；拒绝重采样可能消耗多个随机子序列，不能一律写成 RNG 加一。检查脚本选择“一次成功采样消耗一个符号抽样步”的模型，只验证归属与提交次数。EOS 记录停止事件且可终结 grammar；是否向客户端展示 EOS 由协议决定。本章的输出序号是事件序号，停止事件也有唯一身份。\n\nKV_ONLY 与 SAMPLE 的差别不是“是否存在 hidden state”，而是本轮是否到达当前已知前缀的采样末位置。纯 KV 完成没有 Q，也不以 o=⊥ 构造一个假输出提交。\n\n以下是非空 128-token prompt、初始 k=0、n=128、o=0、符号 RNG 步数为 0 的可复算轨迹。设两轮各处理 64 行，第二轮采到普通 token Y：\n\n| 事件 | 本轮范围与目标 | k | n | 输出 | RNG 步数 | 下一输入 |\n|---|---|---:|---:|---|---:|---|\n| 准入 | 尚未提交 | 0 | 128 | 空 | 0 | x[0:64) |\n| 第一轮提交 | [0,64)，KV_ONLY | 0 | 128 | 空 | 0 | 等待完成 |\n| 第一轮全层完成 | 消费 J，不采样 | 64 | 128 | 空 | 0 | x[64:128) |\n| 第一轮重复通知 | duplicate_noop | 64 | 128 | 空 | 0 | 不变 |\n| 第二轮全层完成与采样提交 | [64,128)，SAMPLE；取 p=127 的 logits | 128 | 129 | 序号 0：Y | 1 | x[128]=Y |\n| 第二轮重复通知 | duplicate_noop | 128 | 129 | 仍只有 Y | 1 | 不变 |\n\n第二轮结果是 k=128、n=129；Y 的 KV 要下一轮处理。若第一轮完成前取消，k 仍为 0；若第一轮已完成、第二轮完成前取消，保留 k=64、n=128，不追加 Y、不推进 RNG。失效尝试与取消采用同样的业务拒绝门，但仍要处理物理结束。\n\n## 消费责任、槽重用与组合边界\n\n```pseudocode\n算法 3：独立消费者结束与回收\nconsumer_done(view_id,cid,结束证据)：\n    查找原 E；核对 cid 的完整绑定和该消费者的真实结束证据\n    若 cid 不在 E.holders：返回 duplicate_or_not_started_noop\n    仅删除这个 cid；调用 finalize(E)\n\nphysical_user_done(view_id,uid,结束证据)：\n    仅当证据匹配已登记 uid 且证明其访问结束时删除该 uid\n    重复 uid 不抵消其他使用者；调用 finalize(E)\n\nfinalize(E)：\n
