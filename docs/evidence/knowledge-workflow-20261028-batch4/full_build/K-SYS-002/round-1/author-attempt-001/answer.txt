{"chapter":"# K-SYS-002：请求身份：逻辑序列、批次视图与结果归属\n\n请求是长期语义对象，batch 行与物理槽是临时执行位置。模型输出只有能沿稳定身份、逻辑位置、版本和提交权回溯时，才属于某个用户请求；仅让张量形状合法或让最终文本看起来合理，不能证明归属正确。\n\n## 问题、对象与不变量\n\n请求身份问题来自多个时间尺度的交叉。一个请求可能经历多轮 prefill/decode、一次或多次执行尝试、压紧与重排、取消、迁移和槽位重用；而设备 kernel 通常只看到本轮压紧后的 token 行。若每轮都从当前活跃列表重新猜测某行属于谁，生成文本、KV、采样参数、grammar、随机状态和 usage 可能分别落到不同请求上。\n\n设稳定请求生命期为 r=(request_id,lifetime)，其中 lifetime 防止外部请求号被重用。租户、会话、回合和输入版本另行记录，不能只靠 request_id 推断授权或缓存等价性。分支身份记为 b=(r,parent_branch,fork_position)；同一请求的不同 beam、多样本或投机候选可以在同一逻辑位置产生不同路径，因此 b 不能由物理行号代替。\n\n一次执行尝试记为 g，本轮执行视图记为 t。物理槽为 σ，槽生命期为 eσ，每释放并重新分配槽时递增。逻辑原子是\n\nA_t = {(r,b,g,p,model_revision,adapter_revision,processor_revision,output_ordinal)}，\n\n其中 p 是 token 的逻辑绝对位置。选中工作集 A_t 可能包含同一请求的多个连续位置，也可能包含多个请求和多个分支。物理行集合为 I_t={0,...,L_t-1}。视图的关键是一个双射\n\nπ_t: I_t → A_t，\n\n即每个物理行恰好指向一个逻辑原子。所有按行索引的张量 X 满足 X_t[i]=X_logical[π_t(i)]；不能只对 token 行做 gather，而让 positions、缓存页表、长度、采样参数或输出目标保持旧顺序。\n\n长期请求状态至少记录：已确认 token 序列 x_r[0:n_r)、全层有效 KV 边界 k_r、各分支的保留路径、采样与 RNG 状态、grammar 状态、累计生成序号、当前尝试 g、取消/失败标志和输出提交位置。0≤k_r≤n_r。已知 token 与已完成 KV 不是同一个量；采样得到的最后一个 token 也可能尚未计算自己的 KV。执行视图包含：π_t、输入 token 行、绝对位置、mask、页表/槽映射、模型与 adapter 版本、每个采样目标、输出槽和资源引用。输入是请求账、候选工作、资源与版本快照；输出是不可变视图，完成并合法提交后才是长期状态变化。\n\n这组定义支持以下不变量：\n\n1. 唯一归属：每个物理行只属于一个逻辑原子，每个被选中原子只出现一次。\n2. 位置一致：同一请求同一分支的位置按逻辑顺序增长，不越过已确认输入；prefill 的每一行都必须有正确绝对位置与因果可见集合。\n3. 字段同源：所有行索引字段来自同一个 π_t 快照；请求索引字段按稳定请求键保存，不能借当前数组下标重新关联。\n4. 版本绑定：每行携带并遵守准入时绑定的模型、adapter、processor 与数值路径；混合版本只有在执行器确实逐行支持时才合法。\n5. 完成有权：结果提交必须匹配请求生命期、分支、尝试 g、槽 σ 与槽生命期 eσ；旧结果不能写入新生命期。\n6. 资源有终：槽、页、输入/输出缓冲和消费者都有明确最后使用者；资源完成不等于业务结果可提交。\n7. 可观察关联：trace 中的请求、batch、行、尝试和分支关系能被显式重放；父子 span 只是相关性，不是身份或授权的替代品。\n\n## 合法条件与可替代表示\n\n一个视图合法，首先要求 π_t 是双射，且 A_t 中不出现同一 (r,b,p) 的重复行。不同分支在同一 p 上出现不同候选是合法的；同一分支重复选择同一位置则会使 KV 或输出被写两次。q_r 必须为正整数；没有可执行工作的空计划不提交空 kernel，而应等待新的输入、资源或完成事件。\n\n位置合法性依赖请求阶段。普通 decode 通常从 k_r 开始取 q_r=1；分块 prefill 取 [k_r,k_r+q_r)，且 k_r+q_r≤n_r，范围中的输入必须已经由模型输入契约确定。若 k_r+q_r<n_r，本轮只产生 KV，不因中间某行有 hidden state 就发布生成 token；若 k_r+q_r=n_r，末行 logits 才可以按该请求的采样状态产生候选。分支的每个节点也必须满足其父路径和可见 mask。\n\n模型版本是一个条件，而不是可以从文本相似性推断的属性。一个 batch 内可以有不同 adapter 或不同模型版本，但只有当执行包、页表、权重地址和结果校验都按行携带版本，且执行器支持这种组合时才合法；否则应先分桶或拒绝。租户作用域同样不是可由相同 token 自动推导的：相同文本属于不同租户时，是否允许共享不可变公共前缀由缓存授权契约决定，至少不能仅凭内容 hash 合并拥有者。\n\n物理表示有选择空间。压紧行减少空行，却需要 gather/scatter 和 metadata 重排；固定槽或固定桶保留地址稳定，却可能计算填充行，并仍需在槽被重用时检查 owner 与 eσ。两者都合法，但都不能省掉“该行属于哪个逻辑原子”的映射。固定槽不是放弃身份，只是把映射从每轮行置换改为槽占用表。\n\n旧式 request-level 批处理把一整批请求固定到全部完成；ORCA 的迭代级调度把 engine 的一次迭代作为边界，完成请求可退出，新请求在后续边界进入。这个改变使同一 batch 内不同请求可能处于不同长度、不同阶段，因而必须显式记录请求 id、当前 token 位置、输入行和结果目标。旧式整批完成只是在特殊情况下减少了映射变化，不是身份语义的充分条件。\n\n## 一轮视图的构造、提交和完成算法\n\n下面的算法把身份、压紧和提交分开。选择哪些工作是策略；生成合法视图、冻结字段和判定提交权是机制。\n\n```pseudocode\n算法 1：构造并提交一轮不可变视图\n输入：稳定请求账 L，候选工作集 C，页/槽/模型版本快照，本轮预算\n输出：不可变视图 V_t；若无合法工作则返回空计划和阻塞原因\n\n构造(V)：\n  A ← 空；S ← 空；按策略得到候选顺序\n  for each 候选 (r,b) in 候选顺序:\n      若 r 不活跃、已取消、已有禁止并发的在途尝试、输入或资源未就绪，则跳过\n      p0 ← 本请求本轮起点（普通推进取 k_r，分块 prefill 取连续已知范围）\n      选择正整数 q，满足位置上限、token 预算、页/槽预算与结果缓冲容量\n      若不存在正 q，则记录具体阻塞原因并继续其他候选\n      for j ← 0 到 q−1:\n          p ← p0+j\n          若 p 越界、越过已确认输入、或 (r,b,p) 已在 A 中，则拒绝该候选并撤销临时预留\n          a ← (r,b,g,p,model_revision,adapter_revision,processor_revision,output_ordinal)\n          A ← A ∪ {a}\n      记录段 S ← S ∪ {(r,b,p0,q,g,资源预留)}\n      仅当 p0+q 是请求的采样末位置时，登记一个采样目标；否则只登记 KV/logits 需要\n  若 A 为空：返回空计划，不提交 kernel\n  选择双射 π，使 I={0,...,|A|−1} 与 A 一一对应（可以按稳定段顺序压紧）\n  for each 行索引字段 f:\n      f_rows[i] ← gather(f_logical[π(i)])\n  for each 请求索引字段 h:\n      h_view[r] ← snapshot(h[r])，只保存本视图引用到的请求\n  由同一 π 生成采样目标行、输出目标、KV 页引用和 mask\n  校验：|A|=行数、π 为双射、位置不重叠、字段版本与请求绑定一致、页/槽引用可用\n  冻结 V_t，登记输入、metadata、页、槽和输出缓冲的读者引用\n  return V_t\n\n提交(V_t)：\n  再次核对请求生命期、槽 owner/epoch、页所有权和提交权\n  若失败：撤销临时预留与执行引用；长期 n/k/输出/RNG 不变\n  若提交成功：标记 V_t 在途；禁止改写本视图使用的输入、metadata、页表和输出缓冲\n```\n\n当一轮完成后，不能按完成时刻的当前 batch 行重新猜请求。结果必须携带视图 id、逻辑键和完成证据。\n\n```pseudocode\n算法 2：处理完成、取消和迟到结果\n输入：V_t，完成证书，逐行结果，当前请求账与槽表\n输出：合法的长期状态变化；已取消或旧代次的业务结果被丢弃\n\n处理完成(V_t, certificate, rows):\n  若 certificate.view_id ≠ V_t.id，或完成证书没有覆盖必要写入，则隔离并等待排空\n  for each 行 i in rows:\n      a ← π_t(i)\n      若证书未证明该行、该层或该写入范围完成：记录失败，不提交部分 KV/部分输出\n      若 a.attempt ≠ current_attempt(a.r)、a.epoch ≠ current_epoch(a.slot)\n         或请求已取消/失败：只记录物理完成，丢弃业务结果\n      否则把候选 token、logits 选择、KV 写范围和状态变更写入 staging\n  对每个请求按逻辑键原子提交：所有必要行通过且位置连续，才更新 k_r、n_r、分支、RNG、grammar 与输出序号\n  若请求已取消：不再产生新业务输出，但仍在途资源按完成证书清理\n  释放本视图引用；当槽引用为零且结果缓冲不再被读取时：\n      slot_free(σ)；eσ ← eσ+1\n```\n\n以一个设定例子说明映射。A 占 q_A=2 行，B 占 q_B=1 行，C 占 q_C=3 行。若按 A、B、C 压紧，则 A 的行是 [0,1]，B 是 [2]，C 是 [3,4,5]；若 B 完成后压紧为 A、C，则 C 的旧行 3、4、5 分别变成新行 2、3、4。对所有行字段都必须有 X_new[2+j]=X_old[3+j]，而不能只移动 token 行。若 A 是 128 个 token 的 prefill，C 只有 1 行，则末行采样目标是 127 与 128；把 128 行误算成 C 的第一行，或把 127 行当作 C 的上下文，都会形成形状正确但语义错误的结果。\n\n采样目标的映射也不能由“每请求固定一行”推断。prefill 只需要最后有效位置时，候选行是 p0+q−1；需要 prompt logprobs、分支验证或多个候选时，目标集合必须另行记录。物理行连续只说明内存相邻，不说明它们属于同一序列或同一可见分支。\n\n## 完成、取消、迟到结果与槽位重用\n\n请求的长期状态可记为 LIVE、CANCEL_REQUESTED、DRAINING、DONE；槽可记为 FREE、RESERVED、INFLIGHT、QUARANTINED、FREE。名称可以合并，状态变化不能省略。取消首先禁止新的业务提交和后续调度，但已启动的 kernel、DMA、通信、结果消费者和 KV 读者仍要完成。物理完成事件到达后，旧槽才能进入可复用状态；eσ 递增使旧结果失去提交权。\n\n设请求 A 在槽 σ=3、eσ=1 上执行一次旧尝试，结果尚未返回。A 被取消后，完成清理条件满足，槽 3 被分配给请求 C，eσ=2。此时迟到的 A 结果即使文本和形状都正常，也只能用于物理排空，不能写入 C 的第一 token。判定至少要求：\n\nresult.request = C、result.lifetime = current_lifetime(C)、result.branch 属于 C、result.attempt = current_attempt(C)、result.slot = 当前槽、result.epoch = 当前 eσ。\n\n只检查 slot 号会把旧 A 的结果误认为 C 的结果；只检查 request_id 会在外部请求号重用或重试时混淆生命期。连接 id、worker pid、batch index 和当前行号都可能因重试、压紧或迁移变化，不能单独承担逻辑去重。\n\n输出缓冲也要有独立的提交与释放边界。模型执行完成而网络消费者尚未读取时，缓冲区仍活着；若为了腾出槽而过早覆盖，即使最终文本尚未产生，也会破坏重试或流式序号。若客户端已取消但结果仍在途，业务输出丢弃，缓冲直到最后一个读者结束才回收。这个边界与本轮 KV 的 k_r 更新不同：前者是外部交付，后者是模型状态。\n\n分支请求把上述规则扩展到 (r,b,g,p)。beam 淘汰一个分支、投机拒绝一个候选或重排候选顺序时，父路径与已确认位置不变；只有保留分支可以更新正式 token、评分、grammar 和随机状态。旧分支的完成通知仍要释放其页和缓冲，但不能把结果拼接到新分支。多样本、beam 和投机树的概率目标不同，不能用相同的“行结果”逻辑替代各自的接受规则。\n\n分布式执行还会增加执行地点。一个请求从 worker 1 迁移到 worker 2，逻辑请求身份不变，但 attempt、执行组、槽和地址改变；目标只接收与当前授权相容的尝试。迁移期间源端和目标的提交权必须唯一，旧 worker 的迟到结果不能重新取得提交权。流式 trace 或 checkpoint 只保存文本而不保存输入版本、分支、模型版本和输出序号时，恢复后可能把重算结果接到错误位置。\n\n## 成本模型\n\n设一轮有 L_t 行、R_t 个被引用请求、F 个行索引字段和 G 个请求索引字段。生成视图的基本准备成本是\n\nC_prep = O(L_t·F + R_t·G)，\n\n若实现为每行扫描活跃请求列表再找所有者，则可能退化为 O(L_t·R_t)。压紧还需要 gather/scatter；如果所有字段都搬移，逻辑搬运字节可写为\n\nB_compact = Σ_{i∈I_t} Σ_{f∈F} width(f) + 请求字段的额外副本，\n\n实际设备事务量还要按布局、对齐、合并和缓存层级重新计算，不能把逻辑字节直接当成设备耗时。固定槽省去部分行搬移，却可能执行填充行；填充比例为 (P−L_t)/P 只描述槽位，不直接等于时间浪费。\n\n映射本身需要存储 π_t 或等价的段表、反向索引和槽占用表，约为 O(L_t+R_t) 个条目；结果验证通常可用请求键和尝试键做常数次查找，但每条迟到结果都要保留到完成或隔离期。若允许 D 个视图同时在途，结果/输出缓冲驻留上界近似为 D·L_out·b_out 加上分配器元数据；这只是容量账，不是硬件实测。trace 的额外成本随事件数、行映射和属性基数增长，不能只按请求数估算。\n\n准备、设备计算、结果处理和输出等待属于不同阶段。若它们有依赖，应沿关键路径相加；若能重叠，只能把共享资源和同步约束计入，不能用“总工作量相加”代替完成时间。稳定身份检查会增加少量元数据访问，但它避免的是把结果写错请求这一语义失败，不能仅按吞吐差异决定是否保留。\n\n## 条件变化后的保留与调整\n\n稳定请求、分支和逻辑位置身份在所有表示变化下保留。可调整的是视图表示：固定槽、压紧行、按请求分桶、分层传输或迁移执行地点。若只有一条请求且没有并发，仍可简化为直接索引，但只要存在槽位重用、重试或缓存共享，就必须保留生命期、尝试和版本。\n\n当执行器使用大图重放或固定地址时，常见的调整是固定槽并只更新占用表和行描述。这样可以减少每轮 gather，却不能省略槽 owner、eσ 和逻辑位置校验；也不能把 padding 行当成有效请求。反之，当活跃集合变化很大、长 prefill 与短 decode 混合时，压紧更合适，但必须支付所有字段的重排成本。\n\n投机与 beam 扩大了行身份：一行可能对应一个候选节点而不是请求的正式下一 token。此时应保留父分支、分叉位置和接受状态；分支重排后，KV、grammar、RNG 和评分都要跟随同一分支原子。迁移或恢复改变的是尝试与执行地点，不应改变已经向用户承诺的请求身份；若目标没有当前授权，旧结果只能清理资源。\n\n前缀缓存命中只说明某些模型状态可能复用，不说明输出目标或提交权已经确定。共享页需要拥有者、读者和写时复制条件；一个请求命中另一租户的不可见前缀，不是合法共享。trace 上下文可以跨服务传播 trace ID 与 span ID，但请求到 batch 是多对多关系，需要额外的 batch id、行映射和请求键。\n\n## 区分实验和反例\n\n同一段输出看起来合理，可能来自数值模型、采样状态、版本绑定或身份映射。应选择能改变一种解释而保持其他条件的实验。\n\n| 观察或实验 | 竞争解释 | 有区分力的检查 |\n|---|---|---|\n| 单请求执行正确，混批错误 | 映射错误、数值误差、批次 kernel 差异 | 先用相同逻辑参数逐请求重放；若单请求一致而混批随行重排变化，优先检查 π 与逐行 metadata |\n| 重排请求后输出跟着行号走 | 随机流绑定到行、输出目标错误、batch 归约副作用 | 固定请求种子和逻辑位置，仅改变行顺序；要求请求级结果不变（数值误差按声明容差处理） |\n| 同一 slot 旧结果出现在新请求 | 迟到结果未按 attempt/epoch 拒绝、输出缓冲提前复用 | 人为延迟旧完成通知，槽重分配后再投递；检查新请求内容和物理排空账 |\n| 分支重排后 grammar/RNG 改变 | 分支映射遗漏、参数仍按旧行索引 | 只重排分支槽，不改变父路径与逻辑位置；逐分支比较 KV、评分、grammar 和随机轨迹 |\n| 相同文本跨租户或 adapter 混用 | 缓存身份不足、授权错误、版本未绑定 | 使用相同 token 但不同租户/adapter
