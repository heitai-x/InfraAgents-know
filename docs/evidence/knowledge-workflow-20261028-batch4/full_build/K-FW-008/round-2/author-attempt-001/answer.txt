{"chapter":"# K-FW-008：MLX 服务：惰性求值、编译与请求状态\n\nMLX 的数组表达式可以延迟执行。服务循环必须明确：哪一步构造了图，哪一步真正求值，哪一步允许采样，哪一步把 token、KV、位置和随机状态作为同一个业务提交交付。只把“表达式已构造”“设备求值已返回”“输出已发送”中的一个当作完成，都会留下旧状态、部分 KV 或错误随机状态。本章按固定历史文档讨论机制；文档中的微基准只作为来源报告，不是目标设备测量。\n\n## 问题、状态与不变量\n\n一次生成步包含多个数组操作。主机构造表达式时尚未得到数值结果，但服务必须决定本步消费哪些已知 token、哪些层的 KV 已经完成、logits 是否来自完整已知前缀，以及采样产生的新 token 自身是否已经有 KV。请求状态写成：\n\nS_r = (x_r[0:n_r), k_r, ell_r, rho_r, v_r, flags)\n\n其中 x_r[0:n_r) 是已经确认的 token 序列；k_r 是已经完成全部层写入的 KV 连续边界，满足 0≤k_r≤n_r；ell_r 是最后一个可用 logits 的行位置，ell_r=-1 表示没有可用末行；rho_r 是采样随机状态；v_r 是状态版本；flags 包含停止、取消、失败等标志。\n\nell_r=m 的合法含义是：logits 由精确前缀 x_r[0:m+1] 的全层 hidden 产生，并且 m<n_r；它预测 x_r[m+1]。只有 ell_r=n_r-1 时，才允许直接采样 x_r[n_r]。若 k_r=n_r 但没有兼容末行 logits，不能因为“KV 看起来已满”就停滞；需要走私有重算最后已知 token 的入口，或者明确拒绝该状态。\n\n逐层数据流可以写成：对位置 t，先有 h_t^(0)=Emb(x_t,t)；对每一层 l=0..L-1，读取该层位置 [0:t) 的 K/V，执行 Block_l，得到 h_t^(l+1) 并写入位置 t 的 K/V；全部层完成后，才可由 LM(h_t^(L)) 得到该行 logits。一个 token 的 KV 只有全层写入都完成，才能把它计入 k。采样出的新 token 位于旧 n 的位置，但它自己的 KV 尚未计算，因此提交后 n 增一，k 仍停在旧 n。\n\n本章使用以下不变量：\n\n- I1 图构造不证明设备计算完成；只有被求值根及其依赖闭包完成，才能消费相应数值。\n- I2 一次业务提交必须覆盖后续步骤会读取的全部状态根；只求值 logits 不能证明独立的 KV、位置或随机状态分支已经完成。\n- I3 编译区域是纯函数区域：trace 期间不能打印、读取标量做分支、发送网络消息或修改未声明的外部容器。\n- I4 未声明为输入或输出的捕获数组按常量处理；外部容器替换对象不保证下一次调用看见新值。\n- I5 shape、dtype 或输入数量变化可能触发重编译；缓存键必须覆盖实际分支条件。\n- I6 统一内存中的同一物理数组只按一份容量计；但不同图中间量、工作区、量化打包和编译产物仍是独立分配。\n- I7 释放需要最后使用者结束。Python 容器删除不等于设备、图或编译闭包已经松开引用。\n- I8 stream 依赖只覆盖框架跟踪的数组依赖；框架之外的原地写入仍要由协议建立顺序。\n- I9 k 只在一个区间的全部层完成且有证书后推进；logits 只在 e=n 时作为末行结果提交。\n- I10 新采样 token 的 KV 不在本次提交中产生；下一次服务步才消费该 token 并写入其 KV。\n\n## 服务步的推进契约\n\n设请求已经通过准入，r.live=true，r.limit>0，0≤r.k≤r.n。片长 q≥1。若 r.n=0，必须先按模型输入规则补 BOS，或在准入处拒绝；本章不把空输入当成一次正常前向。若 r.k>r.n、r.k<0 或 r.ell 越界，进入显式状态修复或拒绝入口，不用一次 BUILD_GRAPH 掩盖状态错误。\n\n推进分三种合法情形：\n\n1. r.k<r.n。令 b=r.k，e=min(r.n,r.k+q)。本步消费 x_r[b:e)，位置 b..e-1，读取 KV 前缀 [0:b)。逐 token、逐层计算，把新 K/V 写入私有写区；只有 [b,e) 的全部层和必要最后一行的 logits 都有完成证书，才提交 k=e。若 e<r.n，不采样，不能从中间行发布 token。若 e=r.n，末行 logits 是 x_r[n_r] 的分布，可以采样。\n2. r.k=r.n 且 r.ell=r.n-1，并且 logits 与当前版本兼容。本步不需要新 KV；直接用 rho_r 采样 x_r[n_r]。采样后 n 增一，k 仍为旧 n，新 token 的 KV 待下一次计算。\n3. r.k=r.n 但没有兼容末行 logits。若 r.n>0，在私有写区重算位置 r.n-1 的最后一行：读取 KV 前缀 [0:r.n-1)，消费 token x_r[r.n-1]，经过全部层得到 logits；不得覆盖共享 KV 页。重算得到一个可采样的末行后，仍按情形 2 提交。若共享页不可私有重算，或 r.n=0，则返回 REPAIR_UNAVAILABLE 或 REJECT_NO_ROW，而不是猜测一个 logits。\n\n```pseudocode\n算法 服务步的准备\n输入：请求 r，片长 q≥1\n输出：待提交对象 prepared，或拒绝原因\n\nPREPARE(r):\n  若 r.n=0：返回 REJECT_NO_INPUT\n  若 r.k<0 或 r.k>r.n：返回 REJECT_STATE\n  若 r.k<r.n：\n    b=r.k；e=min(r.n,r.k+q)\n    若 e≤b：返回 REJECT_Q\n    local=复制 KV 前缀 [0,b)\n    last_h=空\n    对 t=b 到 e-1：\n      h=EMBED(r.x[t],t)\n      对 l=0 到 L-1：\n        k_t,v_t,h=BLOCK(l,h,local[l,0:t],t)\n        local[l,t]=(k_t,v_t)\n      last_h=h\n    logits=空\n    若 e=r.n：logits=LM(last_h)\n    返回 (local,b,e,k_after=e,ell_after=-1,logits,\n          证书=[b,e) 全层 KV，e=r.n 时末行 logits)\n  否则：                         # k=r.n\n    若 r.ell=r.n-1 且 r.logits 非空：\n      返回 (r.kv,r.n,r.n,k_after=r.n,ell_after=r.n-1,r.logits,\n            证书=采样专用，无新 KV)\n    若 r.n=0：返回 REJECT_NO_ROW\n    若共享 KV 不能私有重算：返回 REPAIR_UNAVAILABLE\n    logits=私有重算最后一行(r.kv,r.x[0:r.n])\n    返回 (r.kv,r.n,r.n,k_after=r.n,ell_after=r.n-1,logits,\n          证书=私有末行，不写共享 KV)\n```\n\n采样使用提交快照中的 rho_r，而不是求值过程偶然产生的另一个随机值。SAMPLE(logits,rho) 必须返回 (token,rho_next)；rho_next 只在同一业务提交成功时安装。若采样本身被放进编译区域，随机状态必须作为显式输入和输出，不能隐藏在未声明的外部容器中。\n\n```pseudocode\n算法 采样、线性化与提交\n输入：请求 r，快照版本 snap，prepared，可选 token 与 rho_next\n输出：COMMITTED / PREFILLED / CANCELED / FAILED\n\nSERVE_AND_COMMIT(r,q):\n  snap=r.version\n  prepared=PREPARE(r)\n  若 prepared 是拒绝：返回 prepared\n  r.phase=EVALUATING\n  try:\n    result=EVAL(prepared.roots)\n  except e:\n    r.commit_eligible=false\n    若 e.certificate 覆盖全部相关访问结束：\n      r.phase=COMPLETED\n    否则：\n      r.phase=FAILED_DRAINING\n      r.retained.add(e.use_id)\n    返回 FAILED\n  若 result.certificate 不覆盖 prepared 证书：\n    r.commit_eligible=false\n    r.phase=FAILED_DRAINING\n    r.retained.add(result.use_id)\n    返回 FAILED\n  若 r.canceled：\n    丢弃 result\n    返回 CANCELED\n  token=空；rho_next=空\n  若 prepared.logits 非空：\n    token,rho_next=SAMPLE(prepared.logits,r.rho)\n  return COMMIT(r,snap,prepared,token,rho_next)\n\nCOMMIT(r,snap,prepared,token,rho_next):\n  LOCK(r.state_owner)\n  若 r.canceled 或 r.version≠snap 或 not r.live：\n    UNLOCK；返回 CANCELED\n  # 下面是业务提交的线性化点：以下写入同时生效\n  对 prepared 中的 [b,e) 私有 K/V：写入 r.kv\n  r.k=prepared.k_after\n  r.ell=prepared.ell_after\n  r.logits=prepared.logits\n  若 token 非空：\n    r.x.append(token)\n    r.n=r.n+1\n    r.rho=rho_next\n    r.ell=-1\n    r.logits=空\n  r.version=r.version+1\n  r.phase=COMMITTED\n  UNLOCK\n  若 token 非空：PUBLISH(token)\n  若 token 非空：返回 COMMITTED\n  否则：返回 PREFILLED\n```\n\n这里 COMMIT 是同一个串行状态拥有者保护的临界区。EVAL 和 SAMPLE 可以在临界区外执行，但它们的结果只有在版本未变、请求未取消时才被安装。准备阶段的私有 K/V 在提交前对请求状态不可见；提交失败时旧状态仍然有效。\n\n## 编译、纯函数与形状\n\nCompilation 文档说明：首次调用编译函数时用占位输入 trace、优化并生成代码；之后同一编译函数被缓存。改变输入 shape 或维数、输入 dtype、输入数量都可能重编译；只在循环内创建新的匿名编译函数会反复 trace。图构造与编译是不同事件：惰性图在每次表达式运算时构造，编译只在编译函数首次 trace 或缓存键失配时发生。\n\n编译函数按纯函数使用。trace 期间没有真实数组，打印或读取占位数组会出错；把数组追加到外部列表，列表里留下的是没有数据的占位对象。正确做法是返回更新后的状态，或用 inputs 与 outputs 显式声明捕获。若状态数组只在外部容器中，且没有被声明为输入，编译函数把它视为常量；外部替换容器中的对象不保证下一次调用看见新值。\n\n设编译函数 F(I;C) 的公共输入为 I、公共输出为 O，C 是 trace 时捕获的常量。合法使用要求：对相同 I 和相同 C 给出相同结果；所有随请求变化的状态在 I 或显式 inputs 中；所有需要返回的状态在 O 或显式 outputs 中。缓存键至少覆盖函数身份、输入 dtype、输入数量和输入 shape。声明 shapeless 后，shape 变化可以不再触发重编译，但依赖首次 shape 的 Python 分支和硬编码 reshape 常量仍会出错。文档中的例子把首次形状固化为 reshape(6,-1)，下一次 5×5×3 的总元素数为 75，旧 reshape 不再合法；改成不依赖静态总元素数的 flatten 才可能合法。\n\n对自回归服务，KV 长度是输入 shape 的一部分。若编译步直接以当前 KV 长度为形状键，长度每步增长就可能每步重编译。可选路线包括：使用不依赖静态长度的 shapeless 图；把长度补齐到少数桶；只编译形状稳定的子图；对变长部分保留普通求值。文档只说明 shape 变化和 shapeless 的一般规则，不证明任一具体 attention 实现已经支持所有动态长度。\n\n## stream、统一内存与容量\n\nUsing Streams 文档说明每个操作可以指定 stream 或 device；未指定时使用默认设备的默认 stream。不同设备上的操作在没有依赖时可以并行，但它们仍共享物理内存带宽和系统资源。框架跟踪的数组依赖会建立顺序：CPU 先产生 c，GPU 后面的操作读取 c，调度器会在两者之间插入依赖。这不为框架之外的原地写入、原生指针写入或其他进程访问建立依赖；这些路径需要显式协议和完成检查。\n\n统一内存减少显式设备间复制，不取消访存和同步。CPU 和 GPU 对同一数组可达时，容量账只计该数组一次；但 CPU 预处理输出、待消费 token/特征队列、GPU 中间量、图缓冲和编译产物可能是不同分配，需要分别计入。CPU 与 GPU 同时读取共享内存会竞争带宽，两个阶段分别测量后取最大值可能低估并发成本。固定文档在 M1 Max 上报告过一个 matmul 加小 elementwise 的分工示例；那是来源报告，不是本库测量，也不能推出任意服务都能获得同样比例。\n\n释放至少满足两个条件：没有后续图或编译闭包引用该对象，且所有已经提交的读者结束。删除 Python 列表中的引用可能只是减少一层引用；旧图、缓存、捕获常量或未完成的求值仍可能持有数组。服务步骤应在提交新状态后显式移除不再需要的旧句柄，并在取消或淘汰编译缓存时检查其捕获的权重和状态是否还占用容量。\n\n## 成本模型与摊销\n\n设一次步骤的图构造、求值、采样、主机结果处理和发布成本分别为 T_build、T_eval、T_sample、T_host、T_publish；编译未命中另付 C_compile。总成本可写成：\n\nT_step ≈ T_build(n_ops) + T_eval(C(R),B,shape) + T_sample + T_host + T_publish + 1{compile miss}·C_compile。\n\n其中 n_ops 是构造的操作数，C(R) 是求值闭包，B 是批次。T_build 主要随图大小增长；T_eval 包含固定提交开销、实际设备工作和实际访存。若设备计算与访存重叠，不能把峰值算力和峰值带宽的时间直接相加；Q/B_eff 只是相应资源的关键路径下界。k 推进的片长 q 还会改变每步固定开销与图大小的比例：q 太小，提交次数多；q 太大，首 token 延迟和私有写区驻留增加。\n\n编译摊销要用同一候选、同一输入和同一计时边界。设普通求值每次 T_plain=2.0 ms，编译后稳态 T_comp=1.5 ms，一次首次编译 C_compile=200 ms；这些是设定值。一次编译后调用 N 次：\n\nN·T_plain 与 C_compile+N·T_comp\n\n相等发生在 N=400；N>400 后编译路径才开始占优。N=1000 时普通为 2000 ms，编译为 200+1500=1700 ms。若每个请求都换形状或换函数，额外编译率 q 使近似成本变为 C_init+N(T_comp+q·C_compile)。此时单次稳态仍需满足：\n\nT_plain−T_comp > q·C_compile。\n\n代入 0.5 ms 的稳态差和 200 ms 编译成本，q 必须小于 0.0025；q=0.01 时额外编译期望为 2 ms，已经超过 0.5 ms 的节省。该式没有计入编译缓存驻留、代码内存和淘汰造成的抖动，因此只是必要条件，不是收益保证。\n\n内存账按对象而不是按设备名重复计数。对每 token 的全层 K/V，若层数为 L、KV head 数为 H_kv、每 head 维数为 d_h、每个元素 b_a 字节，未压缩且 K/V 同精度的基础量为：\n\nb_kv = 2 · L · H_kv · d_h · b_a。\n\n设定 L=32、H_kv=8、d_h=128、b_a=2 字节，则 b_kv=131072 字节=128 KiB/token。四个请求各 4096 token 的活跃 KV 为 4×4096×128 KiB=2 GiB。若量化权重 14 GiB、工作区 1 GiB、图/中间量 0.5 GiB，则设定峰值约 17.5 GiB；在 16 GiB 统一内存的假想设备上已经不可行。这个算例只展示容量关系，不是任何机器的实测；分页舍入、共享前缀、KV 量化或不同层配置都会改变公式。\n\n批量 decode 的权重读取可以摊薄。若每步读取全部量化权重 W_q，并读取所有活跃 KV，则近似的逻辑访存量 Q_step≈W_q+Σ_r n_r·b_kv；权重项每批只读一次，KV 项按请求累计。实际事务量还受 cache、合并访问、分块和算子融合影响，不能把逻辑字节直接当成设备事务。编译融合可能减少中间数组的写回和再读取，但如果大 batch 已被权重或 KV 带宽限制，文档中的小算子微基准倍率不能直接搬到服务。\n\n## 取消、失败与完成\n\n请求状态机可以写成 GRAPH_BUILT → EVALUATING → READY → COMMITTING → COMMITTED → PUBLISHED；CANCELED、FAILED_DRAINING、QUARANTINED 是独立标志或旁支。取消在业务提交之前阻止提交，在业务提交之后不倒转已经提交的 token；它不证明设备工作已经停止。\n\n设取消通知被状态拥有者处理的时刻为 t_c，业务提交的线性化点为 t_lin。若 t_c<t_lin，COMMIT 在临界区内看到取消，返回 CANCELED，不安装 token、KV、RNG 或版本；若 t_lin<t_c，token 已经提交，取消只能阻止后续推进和后续输出，不能把已提交结果改回旧状态。PUBLISH 发生在提交之后；发布失败可以影响客户端是否看到结果，但不能让已经提交的状态回滚。\n\n求值异常必须区分业务失败和物理完成。EVAL 抛出错误，不等于部分 kernel、私有写区或其他使用者已经结束。若异常证书明确说明全部相关访问已经结束，可以进入 COMPLETED；若不能保证，只撤销业务提交资格，保留图、缓冲和完成责任，进入 FAILED_DRAINING，等待排空证据。无法确认完成时保持 QUARANTINED，不把对象交给下一请求。\n\n```pseudocode\n算法 求值失败后的完成责任\n输入：请求 r，求值异常 e\n输出：COMPLETED 或 FAILED_DRAINING 或 QUARANTINED\n\nON_EVAL_ERROR(r,e):\n  r.commit_eligible=false\n  若 e.certificate 覆盖 roots 的全部访问结束：\n    r.phase=COMPLETED\n  否则：\n    r.phase=FAILED_DRAINING\n    r.retained.add(e.use_id)\n    等待 USE_DONE(e.use_id)\n\nON_USE_DONE(r,use_id):\n  若 use_id 不在 r.retained：忽略重复事件\n  仅当事件证书覆盖该使用者的最后读写：\n    r.retained.remove(use_id)\n  若 r.retained 为空且 r.phase=FAILED_DRAINING：\n    r.phase=COMPLETED\n  若超时仍不能确认：\n    r.phase=QUARANTINED\n```\n\n取消后的结果如果已经被设备写入，仍需按最后读者释放，不能因为业务取消就立即覆盖。只有业务提交资格被撤销且物理完成责任全部结束，COMPLETED 才表示可以回收；它不是“请求成功”的同义词。\n\n## 和参数更新；若在 mx.eval(loss, model.parameters()) 之前打印 loss 或读取 loss 标量，会触发一次只计算前向的 partial evaluation。这个观察只能说明优化器更新尚未被证明完成，不能说“随后读取更新后的参数一定得到旧值”。更新后的参数句柄可以仍连接待求值的更新图，随后实际读取这些参数会触发其依赖。若要看旧值，必须明确读的是更新前保留的旧参数对象，或错误发布的旧快照；这是对象身份和发布边界问题，不是 update 未完成时的普遍现象。服务中的对应情形是：只求值 logits 不能证明独立的 KV、位置或 RNG 根已经完成；提交必须覆盖全部会被下一步读取的状态根。\n\n反例二：把状态留在未声明的外部容器。函数体看起来每次读取 state[0]，但 trace 时 state[0] 是常量；外部把它从 1 改成 5，输出仍按 1 计算。这个反例说明“Python 代码每次执行”不等于“编译图每次重新捕获”。显式参数或 inputs/outputs 声明才把状态身份带入下一次调用。\n\n反例三：用 shapeless 掩盖静态 reshape。第一次 shape 为 2×3×4，代码把总元素数固化为 6 的倍数；第二次 shape 为 5×5×3，总元素数为 75，旧 reshape 不合法。shapeless 避免了仅因 shape 变化而重编译，却让错误更晚出现。必须用不依赖首次 shape
