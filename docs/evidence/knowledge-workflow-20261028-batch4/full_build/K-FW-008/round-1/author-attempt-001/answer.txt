{"chapter":"# K-FW-008：MLX 服务：惰性求值、编译与请求状态\n\nMLX 的数组表达式可以延迟执行，服务循环必须明确计算何时提交、何时完成和何时释放状态。本章把惰性数组、编译函数和请求状态放在同一条完成边界上，讨论一个固定历史文档版本支持的机制；文档中的微基准只作为来源报告，不作为目标设备测量。\n\n## 问题、对象与不变量\n\n问题：一次生成步由多个数组操作组成，主机在构造表达式时尚未得到数值结果；但服务必须知道哪个 token 可以发布、哪段 KV 已经写入、哪个随机状态已经推进、哪块内存仍被旧图引用。若把“表达式已构造”“求值调用已返回”“输出已发送”混为同一事件，就会发布旧状态或在独立分支未完成时释放资源。\n\n把一次图构造表示为有向图 G=(V,E)。v 是一个数组操作，边 u→v 表示 v 读取 u 的结果。对根集合 R，EVAL(R) 计算 R 的依赖闭包 C(R)={v | v 是 R 中某根或其依赖}。没有被 R 引用的独立分支不属于 C(R)。求值前，数组句柄可以存在，但其数值尚未被设备生产；求值后，所列根及其依赖达到可被主机或后续图消费的完成状态。打印、转成主机数组、memoryview、保存、读取标量 item 和用标量数组做控制流都可能触发隐式求值。\n\n请求 r 的已提交状态写成 S_r=(x[0:n), k, ρ, h_r)。x[0:n) 是已确认的 token 序列，k 是已经完成全层写入的 KV 边界，满足 0≤k≤n；ρ 是采样/随机状态，h_r 是可选的上一步末行结果或隐藏状态。服务步只读取一个不可变快照，成功后才把 S_r 换成 S′_r。这个长度记账与异步调度章节一致；本章不重写请求调度，只要求一次求值不能把未完成分支算进已提交状态。\n\n编译函数写成 F(I; C)→O。I 是公共输入，O 是公共输出，C 是 trace 时捕获的常量。合法使用要求 F 对相同 I 和相同 C 给出相同结果；所有需要随请求变化的状态必须在 I 或显式捕获的 inputs 中，所有需要返回的状态必须在 O 或显式捕获的 outputs 中。缓存键至少覆盖函数身份、输入 dtype、输入数量和输入 shape；声明为 shapeless 时，shape 变化可以不再触发重编译，但静态 shape 分支仍需单独检查。\n\n本章依赖以下不变量：\n\n- I1 图构造不证明设备计算完成；只有求值根及其闭包完成，才能消费相应数值。\n- I2 一次提交必须覆盖所有被后续步骤读取的状态根；只求值 logits 不能证明独立的 KV、位置或 RNG 分支已经完成。\n- I3 编译区域是纯函数区域：不能在 trace 中打印、读取标量做分支、发送网络消息或修改未声明的外部容器。\n- I4 未声明为输入/输出的捕获数组按常量处理；外部容器中替换对象不保证下一次调用看见新值。\n- I5 形状、dtype 或输入数量变化可能触发重编译；缓存键必须覆盖实际分支条件。\n- I6 统一内存中的同一物理数组只按一份容量计；但不同 CPU 队列、图中间量、量化打包和编译产物仍是独立分配。\n- I7 释放需要最后使用者结束。Python 容器删除不等于设备、图或编译闭包已经松开引用。\n- I8 stream 依赖只覆盖框架跟踪的数组依赖；框架之外的原地写入仍要由协议建立顺序。\n\n## 从请求状态到一次求值\n\n惰性服务步的自然节奏是“构造本步依赖，求值本步需要的全部根，提交状态，再发布输出”。求值过密会增加每次图的固定开销；长期不求值会让图、引用和中间对象增长。文档建议每次求值包含几十到几千个操作通常都可以，但这是该文档的指导，不是目标机器的性能保证。\n\n一次步骤可以经过 GRAPH_BUILT → EVALUATING → COMPLETED → COMMITTED。取消或失败可以发生在 COMMITTED 之前：已经提交的求值不能被业务取消倒转，但可以丢弃其结果，等真实完成后再释放；未提交的图可以直接放弃。首轮编译、首次 trace 和稳态求值属于不同事件，不能混在同一计时桶里。\n\n```pseudocode\n算法 惰性服务步骤\n输入：请求 r，模型版本 m，执行策略 π\n输出：至多一个已提交 token，或失败/取消\n\n状态：GRAPH_BUILT → EVALUATING → COMPLETED → COMMITTED\n取消可在 COMMITTED 前发生\n\nSERVE(r):\n  若 r 已停止、没有新增输出或为空批次：\n    不建立图，不求值，直接返回\n  s = r.state                    # 只读已提交快照\n  key = (m.version, s.public_ops,\n         s.input_dtypes, s.input_arity,\n         s.shape_signature 或 SHAPELESS)\n  f = CACHE_LOOKUP(key)\n  若 f 不存在：\n    若 π 允许编译且编译缓存有容量：\n      f = COMPILE(m.step,\n                  inputs=s.state_arrays,\n                  outputs=s.new_state_spec,\n                  shapeless=s.shapeless_flag)\n      CACHE_INSERT(key, f)\n    否则：\n      f = m.step\n  g = BUILD_GRAPH(f, s)          # 此阶段不要求设备计算\n  roots = [g.logits, g.kv_new, g.rng_new, g.position_new]\n  若 NOT PURE(g) 或 NOT COVERS_ALL_STATE_WRITES(roots):\n    标记失败，保留旧 s，不发布\n    phase = COMPLETED\n    return\n  phase = EVALUATING\n  try:\n    result = EVAL(roots)         # 所列根及其依赖闭包达到完成状态\n  except:\n    标记失败，保留旧 s\n    phase = COMPLETED\n    return\n  若 r 在 COMMITTED 前已取消：\n    丢弃 result，等待真实完成\n    phase = COMPLETED\n    return\n  若 result 缺少 roots 中任一必需值：\n    标记失败，保留旧 s\n    phase = COMPLETED\n    return\n  token = SAMPLE(result.logits, result.rng_new)\n  r.state = COMMIT(result.kv_new, result.rng_new,\n                    result.position_new, token)\n  PUBLISH(token)\n  phase = COMMITTED\n```\n\n这个算法的关键是：`EVAL(roots)` 只保证根闭包，不保证另一个独立 stream、另一个独立输出或另一个请求的未求值分支。若真实依赖需要 `kv_new` 才能产生 `logits`，它自然在闭包内；若它被建成独立分支，就必须把 `kv_new` 也列为根。失败时保留旧 `S_r`，不能把部分图已计算的部分状态当成完整新状态。\n\n边界输入单独处理：空 batch 不产生编译或求值；零新增 token 的请求直接结束；首轮编译计入首包而不是稳态；最后一轮输出仍要完成采样和发布，不能只释放图。取消后的结果如果已经被设备写入，仍需按最后读者释放，不能因为业务取消就立即覆盖。\n\n## 编译、形状与状态契约\n\nCompilation 文档描述函数编译：首次调用用占位输入 trace 计算图，优化并生成代码，之后同一编译函数被缓存；缓存命中不重新编译。改变输入形状或维数、输入 dtype、输入数量都可能触发重编译。只在循环内创建新的匿名编译函数会反复 trace，不能因为函数体相同就假定复用。\n\n编译函数被当作纯函数。trace 期间没有真实数组，打印或读取占位数组会出错；把数组追加到外部列表，列表里留下的是没有数据的占位对象。正确做法是返回更新后的状态，或用 `inputs=...` 与 `outputs=...` 显式声明捕获。若状态数组只在外部容器中，且没有被声明为输入，编译函数把它视为常量：外部把 `state[0]` 从 1 改成 5，函数仍可能继续加 1。把状态作为参数传入，或使用该版本的显式 inputs/outputs 契约，才能让新值进入下一次调用。\n\n形状是服务中的关键条件。设固定形状的编译步在第一次调用时把某个 reshape 常量固化为 6，下一个请求把形状从 2×3×4 改为 5×5×3；总元素数从 24 变为 75，旧的 `reshape(6, -1)` 分支不再合法。声明 shapeless 可以避免仅因输入 shape 变化而重编译，但它不会自动把 Python 中依赖首次 shape 的分支改成动态逻辑，也不会修复硬编码的 reshape 常量。使用 `flatten` 一类不依赖静态总元素数的操作，或者显式分桶/补齐，才是候选方案；它们是否合法仍取决于具体算子和版本。\n\n对自回归服务，KV 长度是输入 shape 的一部分。若编译步直接以“当前 KV 长度”为形状键，长度每步增长就可能每步命中新的形状并重编译。可选路线包括：用不依赖静态长度的 shapeless 图；把长度补齐到少数桶；只编译形状稳定的子图；对变长部分保留普通求值。文档只说明 shape 变化和 shapeless 的一般规则，不证明任一具体 attention 实现已经支持所有动态长度。选择前应记录真实编译次数和输出正确性，不能只看某一轮的首包时间。\n\n同一固定提交中的 Lazy Evaluation 文档还保留早期说法“当前不编译并重跑计算图”。判断该版本的编译能力应使用专门的 Compilation 文档；不能由那句旧说明推断没有编译，也不能把每次惰性图构造都算成一次编译。两者是不同机制：图构造发生在每次表达式运算，编译发生在编译函数首次 trace 或缓存键失配时。\n\n## Streams、统一内存与释放\n\nUsing Streams 文档说明每个操作可以选择 stream 或 device；未指定时使用默认设备的默认 stream。不同设备上的操作可以在没有依赖时并行，但它们仍共享物理内存带宽和系统资源。框架跟踪的数组依赖会建立顺序：例如 CPU 先产生 c，GPU 后面的操作读取 c，调度器会在两者之间插入依赖。这不为框架之外的原地写入、原生指针写入或其他进程访问建立依赖；这些路径需要显式协议和完成检查。\n\n统一内存减少显式设备间复制，不取消访存和同步。CPU 和 GPU 对同一数组可达时，容量账只计该数组一次；但 CPU 预处理输出、待消费的 token/特征队列、GPU 中间量、图缓冲和编译产物可能是不同分配，需要分别计入。CPU 与 GPU 同时读取共享内存会竞争带宽，两个阶段分别测量后取最大值可能低估并发成本。固定文档在 M1 Max 上报告过一个 matmul 加小 elementwise 的分工示例；那是来源报告，不是本库测量，也不能推出任意服务都能获得同样比例。\n\n释放至少满足两个条件：没有后续图或编译闭包引用该对象，且所有已经提交的读者结束。删除 Python 列表中的引用可能只是减少一层引用；旧图、缓存、捕获常量或未完成的求值仍可能持有数组。服务步骤应在提交新状态后显式移除不再需要的旧句柄，并在取消或淘汰编译缓存时检查其捕获的权重和状态是否还占用容量。容量接近上限时，设备可访问地址不等于没有系统内存压力；CPU 预处理也会争用同一个内存系统。\n\n## 成本模型\n\n设一次步骤的图构造、求值、主机结果处理和发布成本分别为 T_build、T_eval、T_host、T_publish；编译未命中另付 C_compile。总成本可写成：\n\nT_step ≈ T_build(n_ops) + T_eval(C(R), B, shape) + T_host + T_publish + 1{compile miss}·C_compile。\n\n其中 n_ops 是构造的操作数，C(R) 是求值闭包，B 是批次。T_build 主要随图大小增长；T_eval 包含固定提交开销、实际设备工作和实际访存。若设备计算与访存重叠，不能把峰值算力和峰值带宽的时间直接相加；Q/B_eff 只是相应资源的关键路径下界。\n\n编译摊销要用同一候选、同一输入和同一计时边界。设普通求值每次 T_plain=2.0 ms，编译后稳态 T_comp=1.5 ms，一次首次编译 C_compile=200 ms；这些是设定值。一次编译后调用 N 次：\n\nN·T_plain 与 C_compile+N·T_comp\n\n相等发生在 N=400；N>400 后编译路径才开始占优。N=1000 时普通为 2000 ms，编译为 200+1500=1700 ms。若每个请求都换形状或换函数，额外编译率 q（每次调用的期望重编译次数）使近似成本变为 C_init+N(T_comp+q·C_compile)。此时单次稳态仍需满足：\n\nT_plain−T_comp > q·C_compile。\n\n代入 0.5 ms 的稳态差和 200 ms 编译成本，q 必须小于 0.0025；q=0.01 时额外编译期望为 2 ms，已经超过 0.5 ms 的节省。该式没有计入编译缓存驻留、代码内存和淘汰造成的抖动，因此只是必要条件，不是收益保证。\n\n内存账按对象而不是按设备名重复计数。对每 token 的全层 K/V，若层数为 L、KV head 数为 H_kv、每 head 维数为 d_h、每个元素 b_a 字节，未压缩且 K/V 同精度的基础量为：\n\nb_kv = 2 · L · H_kv · d_h · b_a。\n\n设定 L=32、H_kv=8、d_h=128、b_a=2 字节，则 b_kv=131072 字节=128 KiB/token。四个请求各 4096 token 的活跃 KV 为 4×4096×128 KiB=2 GiB。若量化权重 14 GiB、工作区 1 GiB、图/中间量 0.5 GiB，则设定峰值约 17.5 GiB；在 16 GiB 统一内存的假想设备上已经不可行。这个算例只展示容量关系，不是任何机器的实测；分页舍入、共享前缀、KV 量化或不同层配置都会改变公式。\n\n批量 decode 的权重读取可以摊薄。若每步读取全部量化权重 W_q，并读取所有活跃 KV，则近似的逻辑访存量 Q_step≈W_q+Σ_r n_r·b_kv；权重项每批只读一次，KV 项按请求累计。实际事务量还受 cache、合并访问、分块和算子融合影响，不能把逻辑字节直接当成设备事务。编译融合可能减少中间数组的写回和再读取，但如果大 batch 已被权重或 KV 带宽限制，文档中的小算子微基准倍率不能直接搬到服务。\n\n## 条件变化后的保留、调整与放弃\n\n| 条件变化 | 保留的约束 | 调整候选 | 反转信号 |\n|---|---|---|---|\n| 形状稳定、同一模型被反复调用 | 纯函数、状态显式输入输出 | 保留编译和缓存；预热首轮 | 编译次数仍高、缓存挤占 KV，或稳态不缩短 |\n| KV 长度每步变化 | 输出必须完整提交 | 尝试 shapeless、长度分桶、只编译稳定子图或退回普通求值 | 正确性失败、仍频繁重编译、首包不可接受 |\n| 状态在外部可变容器中 | 下一次调用必须看见新状态 | 把 KV/位置/RNG 作为输入输出；使用显式捕获 | 输出仍停在旧常量，改参数后恢复 |\n| 小 batch、主机提交占比高 | 输出与取消边界不变 | 融合可融合的 elementwise 操作，减少求值次数 | 融合后固定开销或编译成本更大 |\n| 大 batch、权重/KV 带宽受限 | 容量和依赖不变 | 先核对融合是否减少真实事务；不要只追倍率 | 增加 batch 只增加驻留和时延 |\n| 统一内存接近上限 | 同一物理数组只计一次 | 限制并发、编译缓存、图中间量和输入队列；考虑量化 | 降低并发后延迟改善，说明容量/带宽是限制 |\n| CPU 预处理与 GPU 计算并发 | 共享内存的完成顺序 | 调整分工、减少 CPU 队列或让阶段串行 | 两个阶段都变慢，且共享带宽或 CPU 饱和 |\n| 请求频繁取消 | 已提交工作仍要完成 | 丢弃结果、降低在途、缩短队列 | 取消后仍长时间占用容量或输出迟到 |\n\n一个常见错误是把“更多批处理”当成无条件优化。批量增加会摊薄权重读取，但增加 KV 驻留和一次求值的执行时间；若内存或带宽已经饱和，新增请求可能只增加排队。另一个错误是把“shapeless”当成动态形状的完整解决方案；它只覆盖形状触发的重编译，不覆盖静态分支和 reshape 常量。\n\n## 反例与区分实验\n\n反例一：只求值 loss。固定文档的训练示例先构造 loss 和参数更新，若只对 loss 求值，得到的是前向部分，优化器更新仍未完成，随后读取参数会看到旧值。服务中的对应情形是把 logits、KV 更新、位置更新和 RNG 更新建成独立输出；只求值 logits 不能证明后三者已经提交。正确做法是把所有会被下一步读取的状态根一起求值，或在图结构上让它们成为 logits 的依赖。\n\n反例二：把状态留在未声明的外部容器。函数体看起来每次读取 state[0]，但 trace 时 state[0] 是常量；外部把它从 1 改成 5，输出仍按 1 计算。这个反例说明“Python 代码每次执行”不等于“编译图每次重新捕获”。显式参数或 inputs/outputs 声明才把状态身份带入下一次调用。\n\n反例三：用 shapeless 掩盖静态 reshape。第一次 shape 为 2×3×4，代码把总元素数固化为 6 的倍数；第二次 shape 为 5×5×3，总元素数为 75，旧 reshape 不合法。shapeless 避免了仅因 shape 变化而重编译，却让错误更晚出现。必须用不依赖首次 shape 的操作，或接受重编译/分桶。\n\n反例四：在循环里创建新的编译函数。每次迭代都创建新函数身份，缓存无法复用；即使函数文本相同，也会重复 trace 和编译。反例五：删除 Python 列表就认为内存已释放。旧图、编译闭包和在途读者仍可能持有数组；物理回收要等最后使用者结束。\n\n区分实验要先固定逻辑输入、正确性和计时边界。至少把建图、首次编译、稳态求值、主机取回和发布分开记录。以下预测用于区分竞争解释，不等于已经执行：\n\n| 竞争解释 | 可区分预测 | 干预与观测 | 反证后的修正 |\n|---|---|---|---|\n| 编译没有摊销 |
