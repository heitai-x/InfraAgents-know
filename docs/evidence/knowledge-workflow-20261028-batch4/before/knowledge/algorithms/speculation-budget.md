# K-ALG-006：投机解码：分布保持、状态提交与收益模型

投机用便宜候选换取目标模型的并行验证；真正推进系统的是被确认的前缀，而非写入过缓存的全部 token。

## 问题、不变量与设计轴

问题：自回归 decode 每步只产生一个 token，设备在小 batch 下远未饱和；用某种更便宜的过程提出多个候选，让目标模型一次验证，可以把串行步数换成并行宽度。要回答的是"候选从哪来、验证到哪一步为止算确认、未确认的状态怎样撤销、什么时候不值得"。

不变量：输出分布与不投机时的目标分布一致（随机采样下通过接受/修正规则，greedy 下通过逐位比较）；只有已确认前缀进入下一轮可见历史；KV、递归状态、语法状态、随机状态和输出缓冲按同一确认边界提交或回滚；候选位置与其 KV 的一步偏移被正确处理。

成本项：草稿生成、目标验证（随候选数增长）、拒绝后的撤销与回收、调度与图桶的变长处理、以及被挤占的其他请求预算。收益是每次目标前向的期望确认 token 数，它随接受分布与 batch 大小变化。

设计轴：草稿来源（独立小模型 / 目标特征预测 / 无模型的 n-gram 或 prompt lookup / 多头并行）；候选结构（单链 / 树）；验证规则（greedy 比较 / 随机接受修正）；深度与宽度的决定方式（固定 / 按近期接受分布在线调整 / 按 batch 占用率关闭）；状态撤销机制（延迟回收页 / 快照恢复 / 重算）。无模型草稿把草稿成本降到查表，前提是输出中存在可从上文复制的片段，接受率随任务变化很大；它在设计轴上是"零草稿成本、低接受率"的一端。本章后续展开各点的前提与代价。轴上未列点同样合法。

## 两种语义不能混用

greedy 场景中，草稿提出若干 token，目标模型对相同前缀并行计算这些位置，保留直到首次不符合目标 greedy 选择的位置。随机采样场景中，简单比较 sampled token 是否相等会改变分布。设草稿条件分布为 q，目标为 p，候选 x 的接受概率是 min(1,p(x)/q(x))；拒绝后从与 max(p−q,0) 成比例的剩余分布抽样。在双方共享正确条件前缀等前提下，这类修正才保持目标分布。

temperature、惩罚、top-k/top-p、grammar 都改变用于采样的分布。接受比必须对应实际应用这些处理后的 p 和 q，而不能将原始 logits 的概率与截断采样混合。分布等价也不意味着在相同 seed 下逐 token 一致，随机数消耗路径可能不同。

## 缓存推进是一次提交

草稿提出 γ 个候选时，目标验证要读已确认状态并计算候选对应的状态。假设只接受前 a 个，后续候选的 KV 虽然可能已经写入，但不能成为下一轮的可见历史。系统应有“已保留容量、已写入状态、已确认长度”三个概念；拒绝处理改变后两个的有效范围，物理页可延迟回收。

还存在一个常见的一步偏移：预测某个 token 的 logits 来自其前一位置的隐藏状态，而该 token 自己的 KV 需要在它作为输入参与前向后才存在。额外抽样出的 bonus token 未必已经具有 KV。调度器必须按实际计算位置推进，不能直接将输出 token 数当成新增 KV 数。

递归模型的状态被覆盖后不能像 append-only KV 一样只缩短长度。投机需要递归状态快照、可恢复检查点或重新计算。grammar 状态、随机状态、输出缓冲区也必须与接受边界一起提交。

## 收益不是接受率一个数

设一轮草稿成本 Dγ、验证 Vγ、管理 Hγ，最终平均产出 E[L] 个已确认输出，单位 token 成本约 (Dγ＋Vγ＋Hγ)/E[L]。只有它低于普通目标 decode 的成本才有收益。在独立、固定接受率 α 的简化模型中，带 bonus 的 E[L] 可写为 Σᵢ₌₀^γ αⁱ；真实接受事件有条件相关性，应测接受长度分布。

举例：普通每 token 10 个时间单位；γ＝4，一轮草稿 8、验证 13、管理 3、平均产出 3，则新成本 8，理想吞吐提高 25%。若 batch 扩大后普通 decode 已降为 6，同一投机配置反而更慢。额外目标验证 token 还可能占据其他请求的计算预算。

## 和调度、图执行的关系

不同请求接受长度不同，使下一轮 query 数、页增量、输出数量都变长。图可以按最大候选数保留固定缓冲区，但 mask 和 valid lengths 必须表达真实提交范围。调度器可按近期接受分布调整 γ，将额外验证预算给高收益请求；这是一项在线资源分配问题，不能把 γ 固定为越大越好。

## 草稿来源、树形预算与指标

草稿可以来自小模型、特征预测或其他明确的候选生成过程。[EAGLE v1](../sources/S-EAGLE.md) 将目标特征和已采样的下一 token 一起用于后续特征草稿，说明条件输入需要包含影响下一状态的不确定性。草稿结构改变不取消目标验证、拒绝修正与共同提交的要求。

树形验证可以在一次目标前向中覆盖多个候选位置，但每个节点只看到自己的祖先。链式接受率与树的候选通过比例不是同一个指标；多条兄弟候选通常只有一条进入最终路径。更有用的是目标前向数、已确认输出长度、无效验证量、管理开销和端到端 goodput。

动态选择深度/宽度时，除近期接受分布，还要考虑其他请求的预算、KV/递归快照、graph 桶与草稿启动成本。低接受率、目标 batch 已充分利用或草稿占用关键资源时，应允许关闭投机。成本下降必须与目标分布/质量及服务约束共同确认。

故障或重试后，应从已确认路径及相应随机/grammar 状态继续；不能把之前已写入但被拒绝的候选重新当作有效历史。针对每种候选生成与验证协议保留独立小分布参考，不能把论文的理论等价性直接视为本项目实现已经正确。
