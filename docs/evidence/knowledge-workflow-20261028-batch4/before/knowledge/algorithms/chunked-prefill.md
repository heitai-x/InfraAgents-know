# K-ALG-007：分块 Prefill：服务时间切片与历史可见性

分块 prefill 将已知 prompt 的执行切成可调度时间片。每块只计算一段连续位置的 query，却仍读取这些位置之前完整且有效的上下文。块边界改变执行机会，不改变请求身份、逻辑位置或 causal 可见性。

## 问题、不变量与状态对象

长 prompt 若一次执行，会延后同实例上已有 decode 的服务机会。切片要同时回答：哪些输入已经确定，哪些状态已经完成，本轮选择多少工作，以及该混合视图能否在时间和容量约束内完成。缩短单次设备工作并不自动缩短客户端 ITL；块间准备、其他轮次等待、采样与输出也进入服务路径。

本章先限定为固定模型、普通稠密 causal decoder、无投机、每请求最多一轮设备工作在途。位置从零开始，长度均为右开边界：

| 状态 | 含义与约束 |
|---|---|
| P | 本次请求固定的 prompt 终点，prompt 位置为 [0,P)，最后位置为 P−1。规范化后的 BOS 若存在，也计入 P |
| A | 已确认 token 的终点；token[0:A] 已知，包括 prompt 和已接受的生成 token，不包含未接受候选 |
| c | 已提交、所有必要层均完整且可复用的连续 KV 终点；KV 覆盖 [0,c)，满足 0≤c≤A |
| ℓ | 尚未消费的下一 token logits，或空。非空时携带来源位置、请求身份、代次和输出票据；其来源必须为 c−1，且 A=c≥P |
| g、tx | 请求代次与本轮事务身份；完成通知必须同时匹配，重复通知只能处理一次 |
| page_map、flight | 已发布页表与在途记录；后者另存读取页、暂定写页、COW、工作区及全部已接受操作的完成责任 |

初始 A=P；有效前缀命中可令 c=H，其中 0≤H≤P。尚在 prefill 时，c<P、A=P、ℓ 为空。进入普通生成后，A−c 只能为 0 或 1：A=c 表示最后一行已算完，但尚未确认下一个输入；A=c+1 表示 token[c] 已确认，其 KV 尚未计算。持续 decode 允许 c>P，不能继续用 c≤P 检查生成进度。最大位置和输出长度限制另外约束 A 与后继事件。

一个块的输入不仅是块长 q，还包括已确认 token[c:c+q]、逻辑位置、每行可见集合、旧状态身份以及暂定物理写区。输出是相应位置的逐层 KV 和 hidden；只有到达 prompt 终点的末行，或一次 decode 的末行，才形成下一次采样所需的 logits。设备提交与设备完成都不直接等于用户输出。

必须保持：query 位置连续；每行只读取自己请求中不晚于它的合法 key；块间不重置位置；未提交 KV 不供后续轮读取；中间 prefill 块不采样；失败不推进已提交边界；取消不能使仍被异步访问的地址提前重用。数学等价按同一模型函数成立，浮点实现仍按约定容差比较。

切分依据可以是固定 token 数、时间预算反求、页或图桶对齐；预算策略可以是 decode 优先、deadline、轮转或欠额；执行组织可以是混合批、交替轮次或 P/D 分离。SARATHI 的固定块与 decode-maximal 混合是其中一个设计点。它不规定所有运行点都必须混合，也不保证固定 token 块严格等时。

## 数学关系与合法切分

用 H 表示已缓存前缀长度，用 N=P−H 表示本次尚待计算的 prompt 后缀长度，避免把总终点 P 与新增长度混用。令各块 qᵢ>0、Σqᵢ=N，第 i 块起点 hᵢ=H+Σⱼ<ᵢqⱼ。其第 j 行位于 p=hᵢ+j，合法 key 集合为 {0,…,p}。

每块有效 query-key 对数为

Vᵢ=qᵢhᵢ+qᵢ(qᵢ+1)/2。

历史项来自已提交前缀，三角项来自本块自身及过去位置。求和得到

ΣVᵢ=P(P+1)/2−H(H+1)/2。

这是把相同的 (p,k) 对重新分组。仅检查总数相同还不够：遗漏一个过去位置、补入一个未来位置也可能保持总数，因此正确性参考应比较具体可见关系和输出。把块内位置重新编号为零、漏掉自身 key、把其他请求的历史拼进来，都会改变函数。

块级 KV 重读可以另建解释性模型：假设每块完整扫描一次其历史及本块 KV，N 被等分为 K 块，则读取的 token 状态数为 R_K=KH+N(K+1)/2；整段一次为 H+N，额外为 (K−1)(H+N/2)。这里的读取单位是一次完整 token KV 状态，不是有效 QK 对，也不是实测 DRAM 字节。tile 复用、L2、query-head 分组、布局和并行划分会改变实际事务。

合法性来自模型依赖。普通 causal decoder 的过去表示不依赖未来，因此可以保留过去 KV。双向 encoder 的任意切片通常不满足这一点。窗口层必须使用窗口可见集合，并保留恢复所需位置；SSM 或混合循环模型还要保存共同边界的其他状态。前缀复用须同时匹配内容、模型、adapter、位置规则和缓存数值表示；页长只是物理粒度，不要求等于 chunk 长。

## 从 logits 到下一轮输入

logits 就绪与 decode 输入就绪是两个状态。对 A=c≥P 且 ℓ 非空的请求，采样器消费位置 c−1 的 logits，确认位置 c 的 token；只有确认事件成功后，A 才增加，才能安排位置 c 的设备行。

```pseudocode
ACCEPT_NEXT(r, expected_ticket, sampled_token)
输入：有效且未消费的 logits 票据；采样结果及相应随机状态
要求：请求仍活跃、无设备工作在途、A=c≥P、ℓ.position=c−1

若身份、代次或票据不匹配：拒绝此事件，保持状态
若相同票据已接受：返回原确认结果，不再次追加或发送
若输出限额或位置合同已禁止继续：标记结束，不安排 decode

原子确认：
    将 sampled_token 追加为 token[A]
    记录输出序号、票据结果及采样随机状态
    A ← A+1
    消费 ℓ，令 ℓ ← 空
若该 token 为 EOS 或达到输出停止条件：标记结束
否则：位置 c 的输入已就绪，等待下一次设备调度
确认失败：不追加 token，不消费 ℓ，不推进随机状态
```

输出可在确认后按序交付，但发送重试不能再次采样。若 token 已确认而其 decode 执行失败，重试使用相同 token[c]；不能回到旧 logits 重新抽样，否则已经交付的输出与内部输入会分叉。EOS 通常不必再计算自身 KV；结束时 A 可以比 c 大一。

若 A=c≥P 而 ℓ 为空，不能安排位置 c 的 decode，因为 token[c] 尚不存在。这是 RECOVERY：重新求位置 c−1 的末行输出，或等待外部提供合法 logits。完整 prompt 命中时，恢复位置就是 P−1。

对于本章限定的普通 causal decoder，可从 token[c−1] 的 embedding 开始逐层重算：每层读取已有位置 [0,c−1) 的 KV，在暂存区计算当前行的 Q/K/V，attention 只加入一次当前 K/V，再继续 residual、MLP 和后续层。已有位置 c−1 的缓存项应被排除或由经过验证的等价规则替代，不能同时追加两个自身 key。恢复不追加逻辑 token、不推进 c，也不直接改写共享缓存。窗口已丢弃必要历史、混合状态缺少恢复点，或量化表示不支持相同数值合同的恢复时，必须使用受支持的检查点重算路径；不能仅凭 KV 长度完整就声称能够恢复。

## 完整混合视图的调度算法

以下是本库独立构造的算法，不声称与某个引擎字段或事务边界完全一致。采样确认作为独立事件处理；调度器遇到 SAMPLE_READY 时通知采样器，不把它当作设备输入。

budget 的单位为 ms，覆盖本轮从规划开始到模型结果提交完成的局部关键路径。后述 Estimate(view) 估计同一范围，准备成本只计一次。空视图不启动设备。候选枚举不分配物理页；实际选择才取得预留。

```pseudocode
SCHEDULE(requests, budget, page_pool, legal_shapes, policy)
输出：已取得资源承诺的非空 view，或 idle / blocked_by及后继事件
初始化：view ← 空；tickets ← 空；reasons ← 空
若 requests 为空：返回 idle

for r in requests:
    若请求身份或代次失效：记录 stale；continue
    若 P<1，或端点非整数，或 P>A，或 c<0，或 c>A，或越过模型范围：
        记录 invalid_state；continue
    若 c<P 且 (A≠P 或 ℓ非空)：记录 invalid_state；continue
    若 c≥P 且 (A−c不属于{0,1}，或ℓ与A、c、来源位置不一致)：
        记录 invalid_state；continue
    若 r 已结束：continue
    若 r 有在途设备工作：记录 wait_completion；continue
    若 c<P：分类为 PREFILL
    否则若 A=c+1：分类为 DECODE_READY
    否则若 ℓ非空：分类为 SAMPLE_READY；通知采样器
    否则：分类为 RECOVERY

for d in policy排序后的 DECODE_READY:
    构造一行段：输入token[c]，位置c，q=1，历史起点h=c
    proposed ← view 加该段
    检查 proposed 的完整形状、Estimate(proposed)+余量及资源峰值
    若不可行：记录该decode的具体限制；continue
    原子尝试取得相对于 tickets 的新增页和工作区预留
    若失败：撤销本次尝试取得的部分预留，保留原 tickets；continue
    view ← proposed；更新 tickets

candidates ← 空
for r in PREFILL 或 RECOVERY:
    若 PREFILL：枚举合法 q，满足 0<q≤P−c；段位置为[c,c+q)
    若 RECOVERY：仅在恢复合同受支持时形成位置c−1的单行暂存段
    对每个段 s：
        proposed ← view 加 s
        用完整 proposed 重新选择桶并估计时间、padding和资源峰值
        页需求包含已选decode的预留；增量检查使用扣除tickets后的可用容量
        若全部约束成立：加入 candidates；否则记录原因

按 policy 尝试 candidates，至多选择一个prefill或recovery段：
    对选定段尝试取得新增资源承诺
    若部分失败：撤销这次新增预留，保留已有decode视图，尝试其他候选
    成功后加入 view，结束本次候选选择
若 candidates 为空或均预留失败：保留已有 view

若 view 为空：
    释放所有未提交预留
    返回 blocked_by、对应等待事件或需调整的约束；不得推进状态或忙等

冻结每段的请求身份、代次、输入边界、页表版本和输出归属
提交前再次核对；若有变化：撤销未提交预留并重新规划
返回 view 和 tickets
```

零个 prefill/recovery 段与若干 decode 是合法视图。因此 decode-only 能执行，所有长 prompt 候选因时间或页不足被排除时，已经选中的 decode 仍能执行。若 decode 自身也超过预算，应明确记录不可行或已过期状态；过载策略可以另外决定继续服务，但不能把该轮称为满足原时间约束。

这里每轮至多加入一个 prefill/recovery 段便于说明。扩展到多个段时，每次加入都检查完整的新视图，并禁止同一请求的重叠范围或多轮在途。decode 优先只是一种策略；持续到达的 decode 可能使 prefill 饥饿。进度保证还需要有限准入、可行最小服务片、资源最终完成及轮转、欠额或等待老化等条件。

## 执行、提交与物理排空

runner 将选中段压紧为 M 行，同时保留每行到请求、逻辑位置和输出位置的映射。逐层先对这些行做共享权重的线性运算，得到 Q/K/V；attention 再按请求自己的页表和可见集合读取，输出合并回相同行序，继续输出投影、residual 和 MLP。现代 ragged kernel 可以一次处理多个独立段，合法性仍由段内关系决定。

设页长为 Bp，位置 p 的逻辑页号为 floor(p/Bp)，页内槽为 p mod Bp。实际地址来自该事务冻结的 page_map[逻辑页号]，再加层、K/V、KV head、槽和通道的布局偏移。模型位置编码使用逻辑 p，不能用物理页号替代。padding 行不属于任何请求，不写有效 KV，也不进入采样。

普通写段只写暂定后缀。独占尾页可以利用其空槽，但必须保证失败写入不触及 [0,c) 的旧内容；共享尾页则先建立私有 COW 副本。复制源、复制目标与页表版本都进入在途记录。recovery 使用暂存当前行，不发布新的 KV 页。

```pseudocode
EXECUTE_AND_COMPLETE(view, tickets)
为所有段记录旧提交快照，并取得旧页和执行缓冲的访问保护
准备COW、暂定页表与行映射；发布给执行器前建立所需依赖
逐次记录已经被运行时接受的复制、层计算、通信及输出读取操作
执行本轮；每请求仍只允许这一轮在途

等待覆盖全部已接受操作的完成汇合点
若存在部分提交失败：未发出的工作停止，已接受工作仍必须排空

若全部成功、请求身份及事务仍匹配且未取消：
    prefill：c ← 旧c+q
             若 c=P，提交来源位置P−1的logits；否则ℓ仍为空
    decode：要求输入token[旧c]仍是已确认token
            c ← 旧c+1；A不变；提交来源位置旧c的logits
    recovery：c与A均不变；提交来源位置c−1的logits
    原子发布有效页表、完整KV边界及对应logits票据
否则：
    不发布暂定页表、部分层KV或logits；已确认token与旧提交边界保持
    取消的请求保持结束状态；普通失败可在排空后重试同一输入

在完成汇合点之后处理资源：
    未发布的新页、COW目标及临时缓冲撤销预留
    已发布页转为请求拥有；旧页撤销本事务访问保护
    仅当共享引用为零且所有异步访问均完成时，物理页才回到空闲池
事务完成通知只处理一次；清除flight，或完成旧代次的退休记录
```

这个版本保守地等待整个视图排空后提交；实现可以提供经证明的逐请求完成协议，但不能以 host 调用返回代替设备完成。跨 stream、复制引擎或多卡操作需要相应事件依赖及完成确认。部分层已执行、后续层未提交时，前面接受的读写仍然存活。取消只禁止新业务结果，不撤销已经接受的设备访问；需要完成通信协议的工作也不能任意丢弃。

若提交出错后无法取得可信完成事件，要通过运行时支持的同步、故障恢复或上下文终止确认访问已停止。无法证明停止时，相关地址保持隔离，不能因超时或 generation 不匹配而重用。代次检查防止迟到结果改写新请求；物理访问保护防止迟到设备工作破坏已复用地址，两者承担不同责任。[内存分配](../system-semantics/memory-allocators.md)进一步解释引用、完成与回收的区别。

一条可持续推进的轨迹如下；表中 A、c 均为操作后的边界，采样 token 仅为设定值：

| 事件 | P | A | c | 未消费 logits 的来源 | 下一项工作 |
|---|---:|---:|---:|---|---|
| 8-token prompt 的 KV 完整且有末行输出 | 8 | 8 | 8 | 7 | 采样确认，尚无位置8的输入 |
| 接受 token 42 | 8 | 9 | 8 | 空 | decode位置8，输入42 |
| 位置8执行失败并排空 | 8 | 9 | 8 | 空 | 重试同一位置和输入，不重采样 |
| 位置8成功提交 | 8 | 9 | 9 | 8 | 采样确认 |
| 接受 token 43 | 8 | 10 | 9 | 空 | decode位置9，输入43 |
| 位置9成功提交 | 8 | 10 | 10 | 9 | 可以继续采样 |

## 混合批的组合轨迹

设页长 Bp=4。本轮 A 请求的 P=11、A=11、c=5，选择 q=2；B 请求的 P=8、A=9、c=8，且 token[8] 已确认；C 请求的 P=A=c=4，只有完整 KV，没有 logits，并具备合法恢复合同。

压紧后的四行依次为 A 的位置5、6，B的位置8，C的恢复位置3。它们的可见 key 数分别为6、7、9、4，总有效对数为26。线性层处理4个有效行；若图桶为16行，另外12行仍付执行成本，但不产生语义写入。attention 的四行不能因为同处一张压紧张量就相互可见。

A 的位置5、6位于逻辑页1已有尾部，不需新增逻辑页；若该页共享，则需要1个 COW 物理页。B 的位置8开启逻辑页2，需要1个新页。C不新增持久页，但需要恢复暂存。故在 A 尾页共享的设定下，持久页池至少要承诺2个新物理页，旧共享页和所有历史页仍保持存活；不能把 COW 源页提前抵扣。

本轮成功后，A的c=7且无采样输出；B的A=c=9、logits来源为8；C的A=c=4、logits来源为3。随后采样确认使B的A=10、C的A=5。下一轮可以选择A的位置7到10、B的位置9及C的位置4，共6个有效行。A的四行可见数为8、9、10、11，B为10，C为5，总计53。A末行10=P−1产生首个生成 token 所需 logits；B、C继续正常 decode。该轮A跨入逻辑页2，B利用已有私有页尾，C开启逻辑页1，新增页需求分别为1、0、1。两轮中的页映射、输入就绪和输出归属均可逐行重建。

## 完整视图的时间、流量与容量账

令 V 为一个候选视图，M(V) 为有效 query 行数，M̄(V) 为选定桶实际执行行数；hᵣ、qᵣ 分别为每段起点和行数。普通段的有效对数为 qᵣhᵣ+qᵣ(qᵣ+1)/2；恢复单行使用 h=c−1、q=1，得到 c 个可见 key。

一个适用于经校准形态的初始模型为

T̂(V)=Tprep(V)+Fdev(shape)+βshape M̄(V)+γshape ΣᵣVᵣ+Tcomm(V)+Tfinish(V)，单位 ms。

Tprep 包括扫描、候选评估、metadata、页表和 COW 准备；Tfinish 包括完成处理和提交。Fdev 与线性项如何分摊权重读取，由校准模型定义，不能再把同一权重搬运时间重复相加。融合线性层的时间通常既不等于独立 decode 与 prefill 时间之和，也不等于只有 prefill 的时间。候选必须用全体 decode 的历史、总行数、桶、padding、dtype、backend 和工作区重新估计。若 attention 也对历史或段补齐，应计入实际执行形状，不能仅用有效对数。

若准备、设备与完成处理存在重叠，应沿真实依赖取关键路径，不能把所有累计时长直接相加。分段拟合、查表或在线残差修正都可以；预测误差余量 ε(V) 与模型适用范围一起保存，接受条件为 T̂(V)+ε(V)≤budget。

从客户端目标间隔 D 出发，距上次输出已过去 w，局部轮次以外的采样、发送等预计耗时为 t_other，则可取 budget=D−w−t_other。准备若已计入本轮 T̂，就不应再从 budget 扣一次。负预算表示该运行点已经有违约风险；网络、排队和输出事件口径必须与 SLO 一致。

设定一个把准备、固定设备成本和完成处理合计为2 ms的模型：

T̂(V)=2+0.01M̄+0.000001ΣᵣVᵣ ms。

先无 decode、h=1000、桶以16行递增，10 ms预算允许最大 q=704，时间9.992160 ms。再加入4条 h=7000、q=1的 decode，必须使用 M̄=16ceil((q+4)/16)，并加上4×7001个对。最大 q变为692：时间9.999782 ms；q=693为10.001475 ms，必须拒绝。原来的q=704在这个混合视图中需要10.180164 ms。分别判断两类工作各自小于10 ms会错误放行。

在没有 padding 的同一设定模型中，h=1000和7000的最大独立块分别为704和464；后续历史变长可以使最大合法块缩小。只有已验证单调的形状区间才能用二分反求；桶或 kernel 路径不连续时应枚举可行形状，不能假定整数 q 的成本处处平滑。

对整个后缀，取H=1000、N=4096、P=5096。无padding和其他请求时，整段一次的设定时间为55.446656 ms；分成8个512-token块，总有效对数和线性工作不变，但固定项付8次，总时间69.446656 ms。最后一块从h=4584开始，单块9.598336 ms。切片提供更短的服务边界，同时增加总成本和块间等待；这些系数不是设备实测。

计算账中，attention 的 QK 与 PV 乘加还要乘 query head 数、层数及相应通道维；线性层近似随执行行数增长。访存账中，每 token 全层 KV 字节为 L·Hkv·(dK+dV)·b，新增普通行至少写入相应 KV；历史读取次数取决于 kernel 复用。共享前缀减少唯一驻留，不自动消除不同请求的 attention 读取。权重、KV、metadata 和暂存流量应各自对应实际存储边界。

单设备且无卸载时，本例没有模型状态的跨设备通信；主机 metadata 和用户输出仍有传输成本。TP/PP 下则需加入逐层 collective、阶段间激活、控制与同步。块数增加可能增加消息及流水首尾次数；相同 token 块也会因历史不同而不等时，不能把论文的均匀工作目标当成任意部署中的严格保证。

容量检查采用物理并集。已有历史、共享前缀、在途未回收页、已选 decode 的预留、候选新增页、COW目标及工作区必须同时可容纳。同一共享页计一次；已经选择驱逐但尚未结束访问的页仍不空闲。

在没有额外预分配、尾页独占时，普通段新增页数为

Δpages=ceil((c+q)/Bp)−ceil(c/Bp)。

一般 allocator 还要扣除已有可写预留，并加入 COW 和暂存；工作区若随桶变化，必须检查新的峰值。设c=1000、Bp=16，尾页有8个空槽，原有4个空闲页支持q≤72。若已选decode先占2个新页，剩余容量只支持q≤40；若prefill尾页共享且另需1个COW页，则只支持q≤24。检查使用扣除已有承诺后的容量，不能期待取消稍后恰好回收。

## 块长选择、边界与条件反转

P=1时首块也是末块，唯一有效位置为0；自身 key 必须可见。没有外部 BOS 或等价规范化输入的空 prompt 应直接拒绝，不能进入位置−1的 recovery。身份失效、负c、c>A及不相容 logits 状态均终止分类分支，不参加预留或设备行构造。完整前缀命中而缺 logits 应走恢复或明确等待路径，而不是选择q=0后永久停滞。

小块不必然改善ITL。构造设备段与不可重叠主机空档：128-token块分别为6.0、0.4 ms，64-token块分别为4.8、3.0 ms。即使设备段缩短，间隔仍从6.4增为7.8 ms。修复主机空档、降低页事件频率或改变桶，可能比继续缩块更有效。把中间prompt行送去采样则会制造虚假的TTFT改善：它预测的是prompt内部下一位置，改变了任务语义。

低负载且没有decode等待时，大块或整段执行通常更易摊销准备和权重路径。严格ITL且长输入干扰突出时，小块、准入限制或P/D分离更有空间；分离需另外支付状态传输及两侧排队。长历史KV读取主导时，缩小q可能收益有限，并增加重读。窗口缩短可见历史、缓存命中改变后缀分布、模型或dtype改变kernel路径，都需要重新校准混合成本与桶，而不是保留旧的最大q。

可以保留的是逻辑位置、确认输入与提交状态的区别，以及资源完成后才回收的原则。需要调整的是mask、缓存族、页需求、成本参数和策略；缺少稳定因果前缀或恢复合同的模型，应放弃直接套用这套KV分块算法。

## 诊断与区分实验

正确性参考先固定模型、输入、位置规则、缓存表示和容差。比较整段、非均匀分块、非零前缀命中后接续及逐token执行；完整KV命中但缺logits时，再检查恢复与后续至少两轮decode。独立参考直接按逻辑位置构造可见集合，不调用被测mask或页表生成器。只对齐首token不能证明后续缓存读取正确。

随章检查使用Python标准库，范围是CPU模型：两层标量softmax attention的分区等价与恢复、采样/执行状态轨迹、混合视图预算与页边界、以及异步资源排空的事件模型。它包含去掉自身key、把logits当成输入、漏推进decode、非法状态贯穿、prefill失败连带丢弃decode、忽略decode预算和取消即释放等负对照。事件模型不能证明CUDA或其他设备上的实际内存可见性，标量模型也不覆盖真实模型的量化误差和kernel数值路径。

性能实验固定外部到达、输入输出长度、缓存条件、取消和资源预算，记录逐轮选中范围、已确认输入、历史长度、桶与padding、跳过原因、预留、COW、提交/完成/排空事件、主机空档、TTFT、ITL、拒绝、重算及联合SLO。独立重复与尾部不确定性按[性能实验](../tools/statistical-experiments.md)处理。

| 竞争解释 | 不同预测 | 区分干预与反证修正 |
|---|---|---|
| 块过大拉长已有decode | decode确实入选，但完整混合视图更长 | 固定到达和有效工作，限制视图时间；若设备段未下降，重查历史读取、桶及预测误差 |
| prefill失败分支误丢decode | 存在可行decode却出现空视图，设备甚至空闲 | 强制所有prefill候选时间或页失败，核对decode-only回退；若decode仍执行，转向其他解释 |
| logits尚未转成交付输入 | 有末行输出却没有已确认token[c]，或重复消费票据 | 延迟采样确认并观察调度，禁止凭logits标志造设备行；确认正常后仍停滞才检查执行层 |
| 主机准备频率过高 | 小块设备段更短，但设备间空档增大 | 等价视图预备与重放；若空档不随准备下降，检查页等待和选择频率 |
| 页不足、COW或待排空资源 | 慢轮与物理容量事件对齐，逻辑取消后仍有在途占用 | 固定形状改变可用页，延迟完成通知；若无页事件相关性，不继续归因为容量 |
| 桶或kernel形状跳变 | 设备重放也变慢，padding或执行路径变化 | 比较边界q及混合总行数，按实际shape重新拟合；放弃跨路径的单一线性参数 |
| generation检查掩盖提前释放 | 结果归属正确，但旧工作仍能触及被重用地址 | 取消发生在部分层完成后，延迟复制/输出消费者；只有真实完成依赖才能支持物理复用 |

若64-token视图的主机空档降到0.5 ms后，其余条件不变而间隔成为5.3 ms，支持该设定中的主机解释；若仍慢且页等待吻合，就转向容量解释。所有结论应分别声明来自代数、CPU模型、真实设备还是服务测量。本章没有GPU实测或Agent使用效果证据。
