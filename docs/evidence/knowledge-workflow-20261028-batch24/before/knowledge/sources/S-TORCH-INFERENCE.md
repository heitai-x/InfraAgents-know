## 为什么推理状态需要独立管理

推理通常不需要为反向传播维护图与额外跟踪状态。归档说明的推理模式比仅关闭梯度进一步关闭 view 跟踪与版本计数更新，也关闭前向自动微分；代价是其中创建的张量受到后续 autograd 使用限制。这是减少运行簿记与限制可组合性的交换，不改变模型本应计算的数学函数。

```pseudocode
明确这一计算区域不会与自动微分记录交互
进入当前线程的推理状态，执行所需计算
退出区域时恢复先前线程状态
对模型的训练/评估行为和请求可变状态另行设定与验证
```

该状态是线程局部的，不自动影响其他线程，也不自动将模型切成评估模式。Dropout、归一化统计与共享 buffer 的行为仍由模型状态决定。将“没有梯度”当作“所有推理语义已正确”会漏掉这些独立状态。

## 成本与验证边界

收益来自避免不需要的图与状态维护，大小随运算和对象模式变化，不能据此保证某个固定加速比。分别固定模型行为、数值输入和请求状态，比较不同梯度/推理状态下的输出、时间与内存；需要在其他线程执行时检查该线程实际状态。见[推理模式与模型状态](../frameworks/inference-eval.md)。本说明描述归档版本，无目标机实测。
