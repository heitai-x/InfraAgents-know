# K-MODEL-013：Embedding 与重排：编码函数、批量与评分契约

Embedding 将输入变成可复用的定长表示，重排将查询与候选对变成分数，再按请求组织结果。前者把昂贵的文档计算移到离线阶段，后者通过查询—文档交互表达更细的相关性，但每个候选都要支付句对编码成本。它们的主要状态是制品、有效输入、层间激活、输出身份和提交资格；不能直接套用自回归 decode 的逐 token KV 生命周期。

## 编码函数、输入输出与状态

令制品 A 固定权重、tokenizer、模板、截断、特殊 token、segment、位置、可见性、pooling、任务头、归一化、数值路径和输出格式。一次编码为：

x=τ_A(s)，H=E_A(x,φ,M;θ)，p=Pool_A(H,P)，e=Serialize_A(N_A(p))。

s 是原始输入；x 是实际有效 token；φ 是模型位置；M 是 attention 可见关系；H 有 token 和隐藏通道两轴；P 是参与 pooling 的位置集合，可以是全部有效 token，也可以排除特殊 token。P 与 attention 的有效位置集合不必相同。p 是池化或投影后的向量，e 是最终输出，输出维度记 d_out。空文本可能经模板成为非空特殊 token 序列；原始文本为空与 P 为空是两种边界，分别按制品合同处理。

例如均值池化为 p_c=(Σ_{j∈P}H_{j,c})/|P|，要求 |P|>0。CLS pooling 读取制品指定的聚合位置，last pooling 读取最后一个合法位置，而不是固定物理末列。若后接投影，投影权重、bias、激活及其顺序也属于 A。

本章示例 L2 合同选择 ε≥0：‖p‖₂>ε 时返回 p/‖p‖₂，否则返回零向量并携带 zero_norm 标志。拒绝近零向量或使用 p/max(‖p‖₂,ε) 也可以是另一合同，不能与本合同混用。输出舍入后不保证范数精确为 1。零向量分支提供有限输出，但不会使原本未定义的余弦自动有定义；下游仍需拒绝、单列或采用明确的零向量评分规则。

| 状态 | 含义 | 不能由它推断 |
|---|---|---|
| A | 完整编码与数值制品身份 | 同维度模型产生同一向量空间 |
| r、occurrence | 请求与候选出现身份 | 文档 ID 相同就可以删除重复出现 |
| x、φ、M、P | 实际输入、位置、可见性与池化域 | 物理宽度等于有效长度 |
| X^ℓ | 第 ℓ 层输出，供下一层消费 | 可以脱离本次输入上下文复用 |
| p、e | 池化值与最终序列化向量 | 归一化后相同证明池化过程正确 |
| z、score | 评分头输出与解释后的分数 | 任意跨查询比较或概率校准成立 |
| pending/scored/failed/cancelled | 本次候选的处理与提交状态 | 宿主调用返回意味着设备访问已结束 |

BERT 固定 v1 使用深层双向 Transformer encoder，每层的有效 token 可以读取同一输入序列的左右文。句对用分隔符、segment 与位置表示组织；分类任务使用 CLS 的最终状态。这个结构支持句对交互，并不证明原始 BERT 的任意 CLS、末行或均值池化天然适合语义检索。

截断会改变剩余 token 的上下文。长度 128 截到 64 后，前 64 个位置的深层状态通常也会改变；双向 encoder 因而不能直接复用“追加前计算的全部前缀深层状态”。文档向量可独立缓存，是因为文档编码函数的输入已经完整确定，不是因为双向前向具有因果前缀不变性。

## 双塔、交叉编码器与评分合法性

双塔计算 e_q=f_q(q)、e_d=f_d(d)。两个塔可以共享权重或采用配套训练的不同权重，合法性由训练与制品合同决定；维度相同只证明形状可乘。文档向量可离线构建，在线编码查询并搜索。选择该路径意味着依赖已训练的向量距离表达相关性。

对非零 u、v，cos(u,v)=⟨u,v⟩/(‖u‖₂‖v‖₂)。双方单位归一化时，内积等于余弦，平方 L2=2−2内积。这里是充分条件：对固定非零查询，若所有文档范数相同，原始内积与余弦也有相同排序；只归一化文档即可消除候选范数对单查询排序的影响，而查询范数仍影响分数尺度。仅归一化查询通常不能消除文档范数偏置。因此排序等价、分数相等与跨查询阈值可比应分别判断。

反例取 q=(1,1)、a=(10,0)、b=(1,1)：内积为 10 与 2，偏向 a；余弦为 1/√2 与 1，偏向 b。把未归一化内积称为余弦，会改变候选选择，不只是改变显示单位。

交叉编码器将 q、d 放入同一 attention 域，由任务头给出 s(q,d)。同一 pair 内查询与文档之间必须允许制品定义的交互；不同 pair 即使共享查询，也不能互相看见。文档的深层状态通常依赖查询，不能把双塔的独立文档缓存直接移植过来。Faiss 的高精度向量精排仍在重算约定距离；交叉编码器改变评分函数，两种“精排”不能混为同一个算法。

评分头可能输出标量 logit、多个类别 logits 或集合内选择概率。若用类别 softmax，应在同一 pair 的类别轴上归一化并读取指定相关类别；若用候选集合 softmax，则概率为 p_i=exp(z_i−m)/Σ_{j∈D}exp(z_j−m)，m=max_{j∈D}z_j，且集合 D 进入概率身份。两个零 logit 候选各为 1/2，加入第三个零 logit 后各为 1/3；旧 pair 的 logit 可以复用，旧集合概率不能直接复用。跨请求合并 softmax 会让无关查询改变概率，违反请求隔离。

有限分数的排序可以约定按“分数降序、文档 ID、稳定 occurrence ID”决胜。occurrence 是输入计划分配的出现身份；保留重复文档时不能只用文档 ID 建字典覆盖。固定唯一候选身份后，候选排列变化不应改变返回的分数—身份配对。按原索引决胜也是合法选择，但置换会改变同分次序，不能同时要求其具备 ID 决胜的置换不变性。数值容差用于比较结果，排序本身需要明确全序；“差值小于容差就视为同分”未必具有传递性。NaN 或无穷评分应拒绝或进入声明的专用规则。

## 批量编码、packing 与状态推进

先展开一个可重建的 BERT 式 post-norm encoder 教学模型。设层数 L_e，隐藏维 d=h·d_h，h 为 head 数，FFN 中间维 f；每层有独立参数。输入行是 token、segment、位置 embedding 之和，以及制品规定的输入归一化与推理变换。选择确定性推理，关闭训练用 dropout；其他制品应遵循自己的推理合同。

每个 head 对有效行形成 Q、K、V，分数 z_{t,j}=⟨Q_t,K_j⟩/√d_h；在合法可见集合上减最大值、指数、归一化后加权 V。合并 heads、输出投影、residual 和 LayerNorm 后进入 FFN。LayerNorm 在同一行的 d 个隐藏通道上计算 μ=Σx_c/d、σ²=Σ(x_c−μ)²/d，输出 γ_c(x_c−μ)/√(σ²+ε_LN)+β_c。它的 ε_LN 与向量 L2 的 ε 是两个参数。FFN 是 φ_A(UW₁+b₁)W₂+b₂；φ_A 和近似方式由制品给定，不能在部署时随意替换。

以下循环解释模型数据流；不要求宿主逐 head 或逐行启动 kernel。

```pseudocode
算法 EncodeBatch
输入：冻结请求 s[0:B)、制品 A、布局 λ、各执行桶容量
输出：按请求身份排列的向量、有效输入与分支记录，或明确失败

1. B=0 时返回空结果。逐请求检查制品、输入类型及预算。
   按模板、分词和允许的截断形成 x_i；记录实际删除范围。
   构造模型位置、segment、有效集合 V_i 和 pooling 集合 P_i。
   P_i 为空按制品拒绝或进入定义好的空输入路径。
2. 为每个有效位置建立 λ(i,t) 及逆映射，检查容量和唯一输出归属。
   padding 不属于任何 V_i 或 P_i。
   独立序列 packing 时，M[(i,t),(k,j)] 仅在 i=k 且 j∈V_i 时为真；
   序列内部额外限制遵循 A。双向句对内部的两个 segment 可以交互。
3. X⁰_i[t] ← A 的 token/segment/position 输入表示。
4. 对层 ℓ=1…L_e：
     对每个 head a：
       Q,K,V ← X^(ℓ−1) 与本层各投影权重的乘积，应用各自 bias。
       对每个有效 query t：
         J ← 由 M 指定的合法 key 集合；空集合进入声明分支，不能默认均匀。
         对 j∈J：z_j ← dot(Q[t],K[j])/sqrt(d_h)。
         m ← max z_j；w_j ← exp(z_j−m)；den ← Σ_j w_j。
         O_a[t] ← Σ_j w_j·V[j]/den。
     O ← 按模型顺序拼接 heads，再做本层输出投影。
     U ← LayerNorm_1(X^(ℓ−1)+O)。
     F ← φ_A(UW₁+b₁)W₂+b₂。
     X^ℓ ← LayerNorm_2(U+F)。
     下一层仅消费本次产生且已就绪的 X^ℓ。
5. 对每个请求：
     H ← X^L_e；由 A 选择 CLS、last 或 mean 等明确 pooling：
       CLS：读取指定聚合位置；
       last：按有效位置映射读取最后合法位置；
       mean：acc←0，count←0；
             遍历 P_i，逐通道累加 H 并增加 count，p←acc/count。
     应用 A 指定的可选投影、归一化与输出转换。
     检查有限性、输出维度和分支记录，结果状态置 scored。
6. 等待本次输出所需生产、拷贝与转换完成。
   在提交点核对请求身份与取消状态，发布向量及其编码身份。
   失败不发布半成品；已取消请求不取得新的输出提交资格。
   层间缓冲在全部消费者结束后才可回收。
```

上述教学模型的 post-norm、head 维度与 FFN 顺序是明确前提，不是所有 embedding 模型的统一结构。pre-norm、因果编码、加权 pooling 或多模态 encoder 需要替换相应层函数与可见性，不能仅更换模型文件后沿用全部假设。

物理 padding 行可以被密集算子计算，但不能进入有效 key 集合或 pooling 统计。排除无效行应发生在读取/归约域选择时；若 padding 含 NaN，先读入再乘零仍可传播 NaN。左 padding 的物理行号也不能直接变成模型位置。独立序列 packing 需要边界、位置重建、逆映射与块对角可见性，普通 padding mask 不足以隔离多个有效序列。

L2 归一化还需避免中间平方溢出。对有限 p，令 a=max_c|p_c|。a=0 时走零分支；否则 r=√Σ_c(p_c/a)²，比较 a≤ε/r 判断近零，非零输出 (p_c/a)/r。它避免先形成 a·r 或 Σp_c²；mean 的累加仍有自己的溢出与舍入边界，不能因为 norm 稳定就宣称整条路径稳定。

```pseudocode
算法 RerankBatch
输入：查询、候选出现表、交叉编码器 A、评分解释及稳定决胜合同
输出：完整分数与顺序，或显式失败/部分结果

1. 冻结每个请求的候选义务与 occurrence ID，初始化全部状态为 pending。
   空集合直接返回空结果；重复文档按合同保留、合并或拒绝。
2. 逐 pair 形成 A 规定的输入。
   BERT 式示例为 CLS、query、SEP、document、SEP，分配两个 segment。
   预算包含全部特殊 token；查询与文档的截断份额由 A 固定。
   不足以容纳必需包络时失败，不静默删除包络。
3. 按长度聚批，保留物理行到请求/occurrence 的逆映射。
   使用 EncodeBatch 的输入与逐层计算步骤，到任务头前保留所需 hidden。
   同 pair 内保持交互；不同 pair 隔离。
4. 从 A 指定的聚合位置计算任务头 logits：
   标量头 z=w·H_CLS+b，或类别头 z=H_CLS W+b。
   按标量、指定类别概率或其他已声明合同转换，检查有限性。
   按逆映射将结果写入相应 occurrence；成功置 scored，失败置 failed。
5. 若合同采用候选集合归一化：
   等待该请求全部必要 logit 就绪，再仅在该集合上归一化。
   不能用实际成功子集冒充原集合。
6. 独立核对每个预期 occurrence 恰有一份正确归属的结果。
   按固定全序对完整 (身份,分数) 记录排序，保留二者绑定。
   不能排序 ID 后再与原分数数组按位置拼接。
7. 提交前核对取消与完成。完整结果合同要求全部义务 scored；
   允许部分结果时，必须显式返回缺失/失败身份与 partial 标记。
   取消、失败不能隐式变成零分或最低分。
```

聚批变化只改变执行组织，不能改变实际 pair、截断或评分域。取消只撤销提交资格，不证明设备工作已经结束；共享批中其他请求继续消费时，不能提前覆盖公共输入或输出缓冲。本章不规定某个异步运行时的事件 API，完成证据仍需在目标执行器上验证。

## 成本：计算、访存、准备、同步与驻留

设有效 token 数 S=Σ_i n_i，密集统一桶宽为 L，实际执行 token 行数记 T_exec。真正跳过无效行时 T_exec=S；整桶线性层则 T_exec=B·L。按一次乘加两 FLOP、上述 d=h·d_h、标准两层 FFN 计算，每层 Q/K/V 与输出投影主项为 8T_exec d²，FFN 为 4T_exec d f；bias、激活与归一化另计。不能把有效长度 S 直接代入实际执行 padding 行的实现。

令 A_exec 是每层每 head 实际计算的 query-key 坐标对数。QK 和 PV 合计主项为 4h d_h A_exec FLOP；全部层还乘 L_e。有效双向配对数为 A_valid=Σ_i n_i²。统一 padding 的密集执行可能支付 B L²；长度桶 b_g 则支付 Σ_g B_g b_g²。块对角 mask 只限制语义：若 backend 仍计算连续总长 S 的完整矩阵，再屏蔽非对角块，仍支付约 S²；只有 ragged、分段或真正跳过块的实现才能把算术主项降到平方和。

Pooling 为 O(S_pool d)，S_pool=Σ_i|P_i|，另有投影和 O(B d_out) 归一化；完整重排排序为 O(K log K)，结果与身份表为 O(K)。只返回 top-k 时可用有序选择减少排序工作，但仍需履行输入候选与分数归属合同。

交叉重排的实际 pair 长 l_i 包含模板与特殊 token，attention 有效主项为 Σ_i l_i²，每个 pair 还重复计算查询部分及其与文档的交互。双塔在线只编码一次查询，搜索成本取决于索引、距离和访问范围；离线文档构建成本不能从部署总账删除。减少候选 K 改变计算和召回集合，属于算法变化。

输出主体为 B d_out s_out 字节；完整 token hidden 回传则约 T_exec d s_H，二者差额不等于设备全部流量。文档向量主体为 N_doc d_out s_out，ID、版本、过滤信息、索引结构与可选高精度副本另计。

| 成本 | 条件化账目 |
|---|---|
| 计算 | 上述投影、FFN、实际 attention 坐标、pooling、任务头、归一化和排序 |
| 访存 | 权重、token/位置、层间激活、mask、输出和索引；多次执行可能重读权重 |
| 通信 | 密集 ID 主体 B L s_id 或 ragged 的 S s_id，加位置/边界；回传向量、材料读取与远端重排另计 |
| 准备 | tokenizer、布局与 packing、模型加载、权重打包、编译、桶变体与索引构建，按真实复用范围摊销 |
| 同步 | 输入生产到设备消费、分数回填、集合归一化屏障、输出拷贝与提交完成 |
| 驻留 | 权重、当前层活跃 hidden/residual、QKV、FFN 中间态、attention 工作区、候选输出和缓存的物理并集 |

非融合 attention 若物化分数，其主项为 h A_storage s_score，A_storage 由真实分配布局决定，不一定等于有效配对数；概率另存时再计一份。FFN 中间态主项约 T_exec f s_act；流式或融合可以减少部分物化，但可能增加片上驻留、spill 或限制 kernel 选择。不同层可复用同一工作区，不能无条件把每层峰值乘 L_e；同时存活的 residual、拷贝和并发批则不能遗漏。共享物理缓冲计一次，额外副本各计一份。

端到端延迟沿排队、准备、传输、前向、pooling/评分、归还的依赖关键路径计算。只在完全串行时相加；异步重叠还受共享带宽、计算和缓冲约束。缓存命中改变剩余冷请求长度分布，可能改变聚批效率。离线长文档、在线短查询、交叉重排分别报告吞吐、延迟与候选分布，单一 token/s 不足以比较。

## 条件变化后的保留、调整与放弃

缓存身份应覆盖实际影响结果的依赖：模型/任务头、有效 token 或特征、位置与可见性、pooling 域、归一化、数值合同及输出格式。以原始输入建键时，还要包含全部前处理与截断配置；以规范有效输入建键时，必须完整保存这些变换的实际产物。仅配置名称、同维度或同文档 ID 都不足以证明相同。

截断上限从 64 改到 128，对足够短且实际输入完全不变的文档可以保留结果；对长文档则需要重算。保守地把配置纳入键可以减少错误复用，但会放弃部分合法命中，不代表配置字符串变化必然改变数学结果。pair logit 缓存依赖有序查询—文档输入和头；集合概率缓存还依赖完整候选出现集合、multiplicity 与归一化规则。

| 变化 | 可保留 | 调整或放弃的依据 |
|---|---|---|
| 模型、模板、tokenizer、位置或 pooling 改变 | 原始材料与外部 ID | 重建受影响有效输入与向量空间；旧编码依赖不相容则放弃复用 |
| 仅截断配置变化 | 实际有效输入与全部依赖不变的结果 | 长输入重算，不能凭原文本相同复用 |
| normalize、精度或输出格式变化 | 可追溯且仍相容的中间 p | 重做后处理，核对距离、阈值和排序边际；仅改输出 dtype 不代表前向精度相同 |
| batch、桶、packing 或设备变化 | 数学函数与逻辑身份 | 重验可见性、位置、容差、实际执行量和峰值；布局泄漏则放弃等价结论 |
| 候选集合改变 | 独立 pair logit，若其依赖未变 | 重算集合概率及质量；候选减少不能归为纯执行加速 |
| 索引距离、过滤或材料版本变化 | 相容的查询表示 | 重查候选与材料身份；不能拿旧检索结果代替新合法集合 |
| 到达稀疏、长尾或缓存比例改变 | 编码与请求隔离不变量 | 重估等待、饥饿与利用率；分桶节省小于排队/准备增量时调整或放弃 |

浮点 batch 与切片路径不保证逐位一致。若每个分数绝对误差不超过 δ，参考相邻分数间隔大于 2δ 足以保持该相邻次序；top-k 边界也可使用同样的充分条件。间隔不够时只是证书不足，应检查实际排序与任务指标，不能自动认定错误或无损。设备/数值路径变化后的证据作用域也随之改变。

## 诊断：竞争解释、区分实验与反证

| 观察 | 竞争解释 | 区分实验与修正 |
|---|---|---|
| 离线/在线向量不同 | 模板、token、位置、截断、pooling、normalize 或权重不同 | 固定输入逐阶段比较，从首个不同表示修正归因；最终维度相同不排除身份错误 |
| 单条/聚批不同 | padding 进入统计、位置改变、packing 泄漏或舍入差异 | 独立单条与左右 padding、批次置换对照；只改变相邻请求内容，合法输出应在容差内不变 |
| 最终归一化向量相同但怀疑 pooling 错 | 错分母、误读同方向行被 L2 消去 | 同时比较 P、count、p 与 e；只比较 e 无法证明前处理正确 |
| 重排看似质量下降 | 分数—身份错位、漏候选、重复覆盖或模型误差 | 冻结完整出现义务，逐 ID 核对分数、缺失与重复，再核对排序 |
| 加候选后概率都变化 | 合法集合 softmax 或错误跨请求归一化 | 固定本请求集合，只改其他请求；自身概率变化支持跨请求泄漏解释 |
| packing 后逻辑配对少而时间不降 | 仍算完整矩阵、准备/拷贝增加或小块效率下降 | 核对实际执行路径、工作区和完整调用时间；mask 稀疏本身不是少算证据 |
| 近邻 recall 与最终质量变化不一致 | 搜索误差、编码相关性、交叉评分或材料变化 | 先固定原向量和合法集合测精确距离，再固定 shortlist 比较评分，最后单列端到端质量 |

一个确定的池化参考取两行有效 hidden (1,0)、(0,1)，p=(1/2,1/2)，e=(1/√2,1/√2)。padding 选 (100,−20)，固定末列和错误纳入 padding 都能制造方向差异；它们必须交给同一个数值比较器拒绝。

同时保留一个检查器反例：padding=(100,100) 与 p 同方向，错误末列的归一化结果恰与 e 相同；错误分母把 p 乘以正数也会被 L2 消去。此时不能报告负对照检出。应通过独立有效行参考比较 pooling 前的值，并用非共线输入检验最终向量。选择负对照必须先确认它确实改变了被观察量。

Packing 检查既核对块对角 mask 的逐坐标关系，也执行小规模单 head attention，与逐请求 Decimal 参考比较实际输出；错误全局 mask 必须产生跨请求差异。仅检查 mask shape 或向量长度没有这种判别力。

排序参考冻结 a=0.5、b=0.9、c=0.5、d=0.1，按 ID 决胜期望 b、a、c、d。输入 d、c、b、a 时，只做稳定分数排序会得到 b、c、a、d：分数配对正确，同分次序错误。另把正确排序记录提取出的 ID 与原分数按位置拼接，会产生 b=0.1、a=0.5、c=0.9、d=0.5，应由独立分数表拒绝。比较器还要拒绝嵌套元组冒充 ID、缺失、额外和重复结果，返回具体见证，不能自己因查表异常而中止其余检查。

## C12-A：Embedding 与重排的完整验证场景

固定同一编码函数，输出 768 维 FP32。八条输入包括四条 64 token 和四条 512 token，长度包含制品需要的特殊位置。整批统一 512 桶，密集配对为 8×512²=2,097,152；两组恰好长度桶为 4×64²+4×512²=1,064,960。比值约 1.97 只描述配对；线性层执行行数为 4096 与 2304，比值约 1.78。输出主体均为 8×768×4=24,576 字节。若连续 packing 后仍执行总长 2304 的完整方阵，会计算 5,308,416 对，块对角 mask 不会自行消除这些工作。

候选 A 使用统一桶与有限等待窗口；候选 B 使用 64/512 两桶与各自等待上限。B 少算 padding，但可能增加启动、权重重读、变体驻留和等待。对某条请求，若新增等待与准备 ΔT_wait+ΔT_prep 超过节省的执行时间，其响应反而变慢；到达稀疏时可选择更小批，离线高积压时分桶可能更易摊销。这些条件需要实际时间线裁决，不能从配对比直接得出时延加速。

一次组合轨迹是：冻结八个请求与编码身份；分别形成两桶及逆映射；计算层间 hidden；pooling 与归一化后生成带身份的暂存向量；等待输出转换和必要拷贝完成；逐请求检查成功/取消并提交；最后消费者结束后释放层间与输出缓冲。若一个短请求在设备启动后取消，只撤其提交资格，其他请求仍按原映射得到结果，在途访问完成前相应缓冲继续驻留。若一桶失败，成功桶可以按独立请求合同提交；失败桶不得发布部分 hidden 或用旧向量覆盖本次结果。

重排为每查询固定 20 个候选，实际 pair 长度设为 288，已包含特殊 token。有效配对为 20×288²=1,658,880；统一填充到 320 时为 2,048,000，多出 389,120 对。把 padding 浪费写成 20×(320−288)² 会遗漏交叉项。串行句对与聚批句对使用同一集合、同一截断与评分合同，先核对每个 occurrence 的分数，再评估稳定排序与相关性。将 20 候选减成 10 会同时改变召回，需另作质量比较。

随章检查 tools/check_k_model_013_full.py 的范围是确定性 CPU 逻辑模型：Fraction 的独立未填充均值、Decimal 的范数与逐请求 attention 参考、左右 padding、零范数/阈值/极大有限值、块对角隔离、候选置换、同分、分数身份、重复出现、集合概率和逻辑成本。故障负对照穿过相同比较器，并保留归一化掩盖错误的反例。

它不执行真实 Transformer 全前向、tokenizer、checkpoint 任务头、FP16/FP32 设备舍入、编译后端、GPU 同步/事务、服务尾延迟、索引 recall、nDCG/MRR 或 Agent 使用效果。完整验证还需在目标制品上覆盖只有特殊 token、超长截断、混合长度、取消和部分失败，并分别记录编码、完整重排延迟、候选分布、内存峰值与质量；小模型检查不能替代这些证据。
