# K-ENGINE-002：状态分配决策：命中、预留、发布与回收

缓存命中、容量已经分配、数据已经可消费与请求已经完成是不同事实。KV 管理把计算身份、恢复位置、物理容量和最后使用连接起来：命中决定可以避免什么计算，预留决定本轮能否承担资源承诺，发布决定消费者可以相信什么，回收决定何时可以覆盖存储。

## 状态边界与分配对象

令位置 p 表示已经消费输入 x[0:p)，下一输入是 x[p]。S_g(p) 是状态族 g 在该位置继续执行所需的状态。普通全注意力族需要历史 KV，窗口族需要模型规定的近期历史，递归族需要对应位置的检查点；它们不能只用同一个最大长度描述。

计算身份 η 至少包含模型与权重、adapter、实际输入前缀、位置规则、外部特征和数值合同。物理描述还要包含状态族、层组、head 分片、布局、有效范围、量化参数以及分配代次。共享获取另须满足命名空间和访问授权。哈希用于寻找候选，不能替代完整身份核验；相同 token 片段在不同上文之后的 KV 通常不同。

对一条请求区分以下量：

| 量 | 含义 | 不代表什么 |
|---|---|---|
| N | 当前已知输入的长度，单位为 token | KV 已经计算到 N |
| h | 目录或块索引匹配到的候选恢复位置 | 目标端已有可消费的 S(h) |
| c | 已完成、符合确认条件且已提交的状态边界 | 所有已安排工作都已完成 |
| s | 本次尝试已安排到的边界 | 设备成功、投机接受或输出提交 |
| a | 简化连续模型中的已分配槽位上界 | 槽内已有有效 KV |
| q、r | 本轮实际计算量与额外预留量，单位为 token | q+r 个 token 都能发布为确认前缀 |

单一连续前缀、没有回滚时可用 c≤s≤a 描述部分关系；混合族、窗口、外部传输和投机需要逐范围记录。外部目标已经分配但数据尚未到达时，a 可以增长，c 不增长。提交的是同时满足输入确认、计算完成和表示完整条件的最大连续前缀，不能直接把草稿接受数当成 KV 提交增量。已经采样但尚未被模型消费的 token，也不自动具有对应 KV。

物理页的生命周期用几种正交责任表达：请求持有 O、准备事务保护 H、已提交但未结束的访问集合 U、私有准备归属 T，以及可撤销的缓存保留 C。U 同时覆盖读取、写入、复制和传输，而不只是模型 kernel。

- 缓存页可以没有活动请求持有，仍保存有价值的内容。只有不存在 O、H、U、T 时，它才可能被淘汰并交给新内容。
- 请求撤销 O 不会消除已登记访问 U；取消首次发布前的事务也必须关闭其未来提交和发布资格。
- 缓存淘汰先关闭发现和获取，再使旧身份失效并重新分配。身份核验、命中保护和淘汰必须协调，避免查到之后、保护之前被换代。
- 保护源的生存期不自动冻结源内容。可变状态还要冻结版本、复制快照或建立冲突依赖。
- 分配代次防止旧通知结算新对象，但不能阻止已经发出的旧 DMA 写到同一地址。旧访问结束之前不能复用地址。

事务另保存可枚举的 Held(tx)：本次取得 H 的全部对象句柄，绑定物理池、对象与分配代次，包含本地命中、恢复源和最终未采用的候选，不能从新视图的目标 handles 反推。T 表示私有目标归属，Held(tx) 表示准备保护；一个事务没有私有目标，也可能持有源页 H。同一对象的多个准备用途须聚合到该对象的最后用途；不同 tx 的 H 各自结算。结算日志与事务终态继续保留去重身份，不能把已结算的 tx 身份重新用于另一事务。

这些责任是本章解释协议的独立模型，不要求实现采用相同字段或组件。

## 从命中到可继续执行的位置

[S-VLLM-KV](../sources/S-VLLM-KV.md) 的机制说明区分完整块命中、新计算、外部状态、lookahead 和 encoder 状态。该固定版本只复用完整缓存块，并为取得 logits 保留末段重算机会；目录匹配、外部完成和新 token 分配不是一个进度量。

设完整块长度 B>0。只考虑普通全注意力，已知输入非空、需要生成、没有满足同一输出合同的末行 logits，也没有可直接消费的下一 token 时，恢复位置受 p≤N−1 限制。若相关完整块全部命中，则

p=B⌊(N−1)/B⌋，重算输入数为 N−p。

因此 N=32、B=16 时只能复用 16 个 token，需要重算 16 个；N=33 时可以复用 32 个、重算 1 个。相关块全部可用时重算量在 1…B 之间；存在缺块时可以更多。保存 logits、提供合法下一输入或允许部分块恢复都可能改变此边界，同时增加表示、身份和驻留责任。N=0 时不能对 N−1 套负数取整；空状态也不自动提供生成起始输入。

对多个状态族，令 R_g 为该族当前能够合法恢复的位置集合，I 为任务和输出合同允许的位置集合。共同恢复点满足

p∈I∩⋂_g R_g。

只有每个 R_g 都是从零开始的连续位置集合时，才可以用各族最大位置的最小值求交。反例：R_1={0,4,8,12}，R_2={0,6,10}，各最大值的最小值为 10，但共同位置只有 0。不能把位置 10 的递归检查点修改长度后当成位置 8 的状态。位置 0 也须有合法初始化依据；必要外部状态不可重建时，交集可以为空。

固定 [Hybrid 设计文档](../sources/S-VLLM-HYBRID.md) 描述 full attention 与一种高效 attention 的协调：先从左向右找到完整注意力前缀上界，再从该上界向左寻找另一类型的合法恢复点。纯窗口的可恢复集合可能有空洞，所以其搜索方向与 full attention 不同。窗口宽 W 包含当前 token，下一 query 需要的旧历史是 [max(0,p−W+1),p)，W=1 时不需要旧窗口历史；物理组织仍可能保留 W 个槽。

```pseudocode
算法 MatchRecovery(η, N, 输出合同, 各族目录)
输入：已知输入、初始化依据、块粒度、各族身份与状态描述
输出：候选 p 及全部族清单，或明确失败

核验 η、访问资格、输入范围和允许的初始化状态
依据输出合同构造允许位置 I；空输入单独处理
若有 full attention：
    从首块向右检查身份、完整性和可取得性
    首次缺失即停止，得到 full 前缀上界
否则使用各族共同候选的已声明枚举规则
按递减顺序枚举不超过上界且属于 I 的候选位置 p：
    对每个必需状态族构造 S_g(p) 所需清单
    核对身份、有效范围、表示、检查点与可取得性
    任一族不成立则继续更早的合法候选
    全部成立则返回 p 和完整清单
没有候选时返回缺状态、缺输入或无合法初始化等具体原因
```

匹配结果仍是需要在分配阶段重新保护和核验的候选。外部副本 READY 只说明源端满足其合同；目标端必须完成传输、转换和消费者可见性。共同恢复与完整模型重放详见[异构状态缓存](../algorithms/heterogeneous-state-cache.md)。本章的分配事务接收这些清单，不凭字节数推断恢复资格。

最大的合法恢复位置也不一定具有可行容量或最低成本。一个候选容量失败后，应撤销本候选尚未使用的保护，再比较更早共同位置、其他副本或重算；异构检查点和工作区不同，容量不一定随 p 单调。已经发起访问的候选则必须先保留其排空责任，不能把回退当作无成本撤销。

## 需求展开、命中保护与联合预留

对不共享、全历史驻留、按 B 个 token 分页的单个状态族，当前完成到 c，已经持有 n_hold 页，本轮计算 q、预留 r，所需新增页数为

Δn=max(0,⌈(c+q+r)/B⌉−n_hold)。

这里 c、q、r 是 token 数，n_hold 是同一目标映射中可使用的页数。外部源端的页不能计为目标已经持有的页。B=16、c=31、n_hold=2、q=2 时，r=0 需新增 1 页；r=16 时目标上界为 49，需新增 2 页。

这不是所有分配场景的通式。共享尾页追加可能需要 COW：B=4、两请求共享到 c=6、各持有两页时，一条请求追加 1 token，取整差为零，但写入隔离仍可能需要一张私有尾页。窗口也不能只按最终保留长度分配：本轮 q 跨越多个窗口时，旧读者、当前读取与新写入可能同时存活，能否循环复用取决于真实最后使用顺序。

需求规划应形成物理资源向量：保留哪些既有对象，为哪些逻辑写范围取得私有目标，哪些外部对象需要目标页，哪里需要 COW、转换 staging、encoder 状态及元数据。按真实物理池和别名聚合，共享对象计一次；同一内容需要写到两个独立目标时，两个目标都必须计入。

命中页还会改变可分配集合。设 E 是当前可立即重用的页集合，其中可能包含没有活动引用的缓存页；本次命中页集合为 H。保护命中之后，可供新目的区使用的是 E\H。若需要 D 张新页，条件是 D≤|E\H|，不能仍与保护前的 |E| 比较。命中页不需要重新初始化，但会占用本来能够淘汰的容量。

```pseudocode
算法 ReservePlan(req, attempt, expected_view, candidate, q, r)
输入：请求资格、预期旧视图、完整恢复清单、计算与预留需求、各池状态
输出：私有事务 tx 与执行计划，或不改变旧视图的失败

校验 q、r 非负，下一步输入可用，范围和表示合法
展开各族读取、新写入、COW、外部目标及辅助资源
建立不复用的 tx 身份，初始化 Held(tx)、私有归属账和操作账
在协调区核验 req 仍开放、旧视图版本未变
重新核验命中与恢复源身份；取得每项 H 时同时记入 Held(tx)
按唯一物理需求聚合各池增量；从可分配集合排除刚保护的对象
若任何池不足：
    关闭 tx 新提交和发布资格；此时尚未授权实际访问
    对 Held(tx) 全集结算本次 H，不留下部分预留，返回容量失败
一次登记全部池的容量责任和私有目标归属 T
为目的页取得新分配代次，建立私有页表和操作账
返回 tx；旧请求视图保持有效，目标仍不可作为有效缓存发现
```

这是一种便于失败恢复的独立联合预留基线，不宣称固定源码具有相同原子接口。先占 A 池再等待 B 池可能形成持有并等待：两池各空闲一页，两请求各需一页 A 和一页 B，分别先占不同池后都不能完成。联合预留避免这一轨迹；固定顺序与失败回滚也是候选，但不能持有半套资源无限等待。不同池的空闲字节总和不能代替逐池条件。

完整序列准入与本轮分配是两条轴。前者检查声明上界是否可容纳，后者承担当前真实资源；其他请求、失败待排空和表示变化仍可能改变后续可用性。一次准入判断不等于所有未来分配已经兑现。

## 私有准备、共同发布与失败排空

分配后的数据流为：受保护源 → 私有目标定位 → 复制或模型写入 → 表示与元数据齐备 → 消费依赖成立 → 请求状态提交与完整块缓存发布。事务内部可以消费已经就绪的恢复子视图，前提是全部必需族在同一恢复位置齐备；这不等于向其他请求发布部分状态。

```pseudocode
算法 PrepareAndExecute(tx)
输入：全部资源责任、恢复清单、已知输入与本轮模型工作
输出：可提交候选，或进入排空的失败事务

对每项复制、转换或模型操作：
    在提交协调点核验 req 仍开放、attempt 匹配、tx 仍允许新工作
    核验源版本稳定、目的独占、实际读写范围与依赖合法
    先登记唯一操作身份、tx、源/目的句柄、范围、代次及辅助缓冲责任
    再授权一次提交；重复登记不得取得第二次启动资格
    明确未接受的提交才可立即撤销访问责任；身份仍保留终态
等待恢复清单全部必需状态到达、转换完成且对消费者可见
共享尾块先完成有效内容及解释元数据的复制，再写入分叉内容
按模型层序消费本轮输入，产生私有新状态和输出
后续输入依赖采样或外部结果时，在其就绪后才授权对应工作
记录每项真实完成、成功范围及可见性；提交返回不算完成
任一失败或取消：关闭新提交和发布资格，转入 AbortAndDrain
全部必要操作完成后，形成候选提交范围及其表示描述
```

提交资格与取消需要同一协调关系。取消先发生时，不能再授权新操作；操作已经授权且被接受，或接受状态未知时，取消必须保留其源、目的、描述符和辅助缓冲。不能通过删除主机任务记录证明设备未开始访问。

COW 不能只复制码字而漏掉 scale、分组轴或有效长度。对于每 token KV 为 τ 字节、旧尾有效 u 个 token 的简单非量化页，复制旧有效内容至少读写 2uτ，再写 q 个新 token 的 qτ。B=4、u=2、q=1、τ=32 B 时为 160 B 逻辑读写；实际事务和元数据另计。若两个分支未经隔离地向同一尾槽追加不同 token，后写者会改变先写者的状态，即使两条请求的长度字段都正确。

本章选择保守的逐对象 H 结算时点：tx 关闭新工作后，从未使用或用途已取消的保护立即解除；被本事务实际访问的对象，等本事务涉及该对象的最后访问证据成立后再解除。成功接管的新视图先建立 O，已登记消费者继续由 U 保护；若某源还承担必须保留的恢复用途，先把该用途交给明确的持有责任，再解除 H。另一事务的访问或持有可以比本事务更长，它们仍由自己的 O、H、U、T 保护，不要求等待全系统读者结束才结算本 tx 的 H。

```pseudocode
算法 SettleTx(tx)
输入：已关闭新提交的 COMMITTED 或 ABORTING 事务及其责任账
输出：部分已结算，或全部事务资源责任已结算

若 tx 尚允许新工作：不结算准备保护
在责任协调区内，对 Held(tx) 中每个尚未结算的对象 h：
    核对原池、对象与分配代次；身份异常则保留并诊断，不触碰新对象
    若 tx 对 h 仍有已接受或接受未知且未证明最后使用结束的操作：继续保留 H
    否则核验 h 的后续必需用途已取消或已有明确责任接管
    只删除 h 上属于 tx 的 H，记录该项已结算
对本 tx 尚未转交的私有目标和预留：
    仅在无后续用途且全部实际访问结束时撤销 T 并归还容量一次
对责任改变的对象重新检查 O、H、U、T 回收门
全部本 tx 的 H、T 和预留均已结算时，记录资源结算完成
保留提交/中止收据和操作终态；重复调用只处理尚未结算的项
```

```pseudocode
算法 Commit(tx, result)
在协调提交点：
    若本 tx 已有逻辑终态，返回原收据，不再次安装视图或取得责任
    核验 req 未关闭、attempt 匹配、tx 可发布、旧视图仍为 expected_view
    核验所有必需族、范围、表示和输出属于同一次候选
    从结果取得同时满足确认输入与完成状态的最大连续前缀 k
    核验数据、参数、页表及消费者可见性，不以在途集合为空代替成功
    为完整新请求视图的目标建立请求持有 O，再转交对应私有归属 T
    同时安装新视图与有效边界，推进到计划起点+k
    撤销被替换的旧逻辑持有；旧快照与已登记消费者仍保留各自责任
    只把身份完整、已确认且生产完成的完整块加入共享缓存
    未确认槽、部分尾块与额外预留不作为完整前缀发布
    为仍必需的恢复用途建立接管责任；取消未采用候选的未来用途
    记录 COMMITTED 与唯一收据，关闭本 tx 后续提交
    调用 SettleTx，遍历 Held(tx) 全集，包含未进入新视图的源和未采用命中页
    本 tx 尚有真实访问的对象保留 H，随其最后使用事件继续结算
```

安装新视图、接管责任和首次结算属于同一协调提交边界，不能让域外观察到新页表配旧有效长度，也不能在建立 O 或其他接管责任之前先撤销 H。COMMITTED 表示逻辑提交已完成；残余访问尚未结束时，事务资源账可以继续待结算。针对同一 expected_view 的并发准备至多一个成功提交，另一个重新规划或中止。结果确认边界按实际模型输出语义解释；投机拒绝之后的槽即使有字节，也不能直接进入确认缓存。覆盖这些槽之前仍须等待旧访问结束。

```pseudocode
算法 AbortAndDrain(tx, cause)
关闭本次尝试的新提交与发布，记录唯一 ABORTING 收据
请求取消另行永久关闭该请求实例；即使尚无视图也保留关闭事实
若 tx 已成功提交，不倒退其终态；请求退役另按 O 与 U 处理
保留旧已提交视图；未发布目标不能取代它
取消本事务尚未执行的计划用途，保留必要的旧恢复责任
立即调用 SettleTx：
    从未被接受操作使用、或已证明用途结束的 H 可以立即结算
    从未被实际访问且无其他责任的私有资源可以立即归还
对已接受或接受状态未知的操作保留源、目的、描述和辅助缓冲
按完整操作身份、tx、尝试与分配代次处理终结事件
未知、重复或字段不符的事件不减少其他操作责任
只有真实最后使用证据成立时才结算匹配 U；随后自动再次调用 SettleTx
本事务对某源的最后访问结束后，结算该源 H，即使它不是私有目标或新视图成员
全部访问结束后，核验 Held(tx) 无未结算项、剩余 T 与预留均已归还一次
记录资源结算完成；重复中止、完成和收尾不改变已结算状态
不能取得结束证据时保留隔离责任，不按超时复用地址
```

完成处理是排空事务的后继入口：结算匹配 U 后，立即续办该 tx 的 SettleTx，不依赖另一请求退役或以后恰好发生一次释放调用。失败结果和取消意图本身都不是最后使用证据。若某对象上另有 tx₂ 的 H，tx₁ 收尾只能删除自己的保护；强行清空整个 holds 集合会把容量泄漏变成提前复用。

操作完成记录要足以拒绝历史重复登记。只从在途集合删除编号，随后把相同编号当新操作，会允许旧完成错误结算新访问，即使物理代次没有改变。终态保留、关闭不复用的操作作用域，或有充分依据的历史编号拒绝规则都可以解决；终态元数据本身也占容量。本章检查采用保留终态的简单模型。

## 一次外部命中、预留与取消的完整轨迹

设 B=4，每 token 的 KV 为 τ=32 B，一页 D=128 B，设备池预分配 6 页，共 768 B。请求 A 的已知输入长度为 10，没有末行 logits，候选恢复位置为 8。页 0 是本地完整缓存块 [0,4)，外部源保存 [4,8)；页 1 的旧请求已结束，但旧读者仍在途。页 2…5 可立即使用。本例只涉及一个普通全注意力状态族。

| 事件 | 页、内容与资格 | 设备池内受保护容量 |
|---|---|---:|
| 发现候选 | 逻辑匹配到 8；目标端只有 [0,4) 的缓存内容 | 页 1 受旧读者保护；页 0 尚可淘汰 |
| 保护与预留 | 页 0 的 H 记入 Held(tx)；q=2、r=3，目标上界 13，四页映射为 [0,2,3,4] | 页 0、1、2、3、4，共 640 B |
| 外部搬运 | 页 2 接收 [4,8)，页 3 用于位置 8、9，页 4 为未来容量 | 分配页 2 不等于位置 8 已可恢复 |
| 恢复齐备 | 搬运完成并建立可见性；私有执行视图可从 S(8) 推进 | 页 0、2 是本轮读取源 |
| 执行在途 | 模型读取页 0、2，向页 3 写入位置 8、9；页 4 尚无访问 | 页 0、2、3 都有操作责任 |
| 此时取消 A | 关闭首次发布与新提交资格，归还未使用的页 4；页 0 的 H 因本 tx 仍在读取而保留 | 页 0、1、2、3，共 512 B |
| 本轮访问结束 | 完成入口结算 U 并续办收尾，解除页 0 的本 tx H，撤销页 2、3 的 T；页 0 可继续保留缓存并可被淘汰 | 页 1 仍须等自己的旧读者 |
| 旧读者结束 | 页 1 才能安全换代复用 | 本轨迹不再保护页 1 |

640 B 包含本轮保护页和旧读者页，是该阶段不能立即让给新内容的唯一页容量；池的固定保留量始终为 768 B，不能再把两者相加。源端外部页另占源端存储；源端为本事务取得的保护也必须列入对应责任账，在源读取结束且恢复责任已有接管后结算。

外部整页搬运载荷是 128 B，逻辑源读加目标写是 256 B；本轮新 KV 写入为 64 B。额外预留的三个 token 槽没有因此产生三个 token 的 KV。与 r=0 相比，r=3 使请求目标从三页增长到四页，增加 128 B。它可能避免未来一次分配，也可能阻挡另一条请求，收益取决于后续到达和推进轨迹。

若不取消，全部工作成功后可以提交 c=10。先建立新视图对页 0、2、3 及保留容量的 O，再结算 Held(tx)；页 0 此时本 tx 的访问已结束，H 随提交解除。完整块 [0,4)、[4,8) 具备进入完整块缓存的粒度条件，位置 8、9 仍是部分尾块；缓存发布还须满足身份与确认条件。若请求之后取消，而长度 10 的读者仍在途，页 0、2、3 继续由 U 保护，未被读取的纯预留页 4 可以提前归还。读者结束后，不应还残留准备 H 阻止这些页被淘汰。

Held(tx) 全集与目标视图的差别可以用一个恢复源检查：另有源页 s 被复制到页 2，或候选命中页 s 最终未采用，则 s 不在 [0,2,3,4] 中。提交只遍历目标 handles 会漏掉 H_s；中止只释放私有页也会漏掉它。未使用的 s 可在关闭用途时立即解除本 tx H；已读过的 s 在本 tx 对它的最后读取结束后解除，无需等待 A 退役。s 若仍有另一事务的 H，则仍不可淘汰，这不是本 tx 泄漏。

按保护命中前的空闲量分配可能把页 0 同时交给新内容；按取消时间回收页 3 则可能让旧模型写入污染下一请求。遗漏 H 结算则相反：内容没有被破坏，但请求和访问都结束后可分配容量仍无法恢复。只检查输出正确或一个最终空闲数，不能区分这些错误。

## 层组如何映射到实际字节

Hybrid 文档区分单层每 token 的 KV hidden bytes、按 token 计的 block size，以及管理器语境中的物理 page size。其 page size 可以覆盖一个组内多层；文档指出实现描述中的单层片段大小是 Bτ，两个量不能混用。

沿用文档的规则分组机制，设 10 层 full attention、20 层窗口 attention，每层 τ=4096 B，B=16，窗口驻留跨度取 32 个 token。分成三个组，每组 10 层：full.0…9、sw.0…9、sw.10…19。长度 112 的稳定快照需要 full 组 7 个块，两个窗口组各 2 个块，共 11 个块标识。

每个标识覆盖 10 个缓冲中的各一个片段。单层片段 D_layer=16×4096=65536 B，管理器的一页 D_group=10D_layer=640 KiB。可以分配 10 个缓冲，每个缓冲含池容量那么多个 64 KiB 片段；第 i 个缓冲承载 full.i、sw.i、sw.(10+i) 的不同块。

取 full 块标识 0…6，第一窗口组用 7、8，第二窗口组用 9、10。窗口快照保留位置 [80,112)，即逻辑块 5、6；块表必须保存这些绝对逻辑块身份，不能把它们解释成序列开头的块。

为明确字节定位，本例设每层每 token 紧密保存 K 后保存 V，Hkv=8、d=128、每元素 2 B，每侧 2048 B。缓冲 i 的基址为 A_i，物理块标识 z、页内位置 u、head h、通道 d_c 的地址为

K_addr=A_i+65536z+4096u+2(128h+d_c)，

V_addr=K_addr+2048。

这里 0≤i<10、0≤u<16、0≤h<8、0≤d_c<128；该排列是解释映射的设定，不是归档源码 ABI。full.i 的 token 111 使用 z=6、u=15，行首偏移为 454656 B；sw.(10+i) 的同一 token 使用 z=10，行首偏移为 716800 B。相同 token 在不同层不是相同内容，重复使用块标识到不同缓冲也不意味着它们互相别名。

该快照的容量是 11×10×65536=7208960 B，即 6.875 MiB。若 30 层都按全历史保留，则为 30×7×65536=13.125 MiB。前者是稳定驻留快照账；准备下一轮时仍须加入未结束读者、私有写区和转换空间，不能据此假设窗口旧块立即可覆盖。

不规则层数需要比较减少组数与 padding 的交换。文档以 52 个窗口层、10 个 full 层按 10 层分组，末组只有 2 个真实层，仍占 10 层的分配宽度。若该组有两个块，padding 为 8×2×65536=1 MiB。不同 hidden bytes、递归状态、层间 KV sharing 都会改变需求和别名关系，不能只替换层数。

文档的搜索论述以 full 加一种高效 attention 为范围，Mamba prefix caching 当时仍属未完成工作。其 Overview 中“两个组”的表述与同文三组例存在措辞不一致；可明确重建的是两类型搜索和上述三组分配映射，不能仅由该概述判定实际实现支持任意组数。类型数与同类型组数不是同一量，也不能把早期设计外推成任意混合模型已经受支持。

## 同一计划的成本与方案反转

固定请求、合法输出终点和资源时间窗后，应分别列账：

| 成本 | 条件化推导 |
|---|---|
| 计算 | 命中减少相应前缀重算，后缀仍执行完整模型并对合法历史做 attention；转换、校验、封组和重放另计，不能只计算 KV 写入 |
| 访存 | 源 KV、私有目标、页表、COW、量化参数和 staging；唯一页容量减少不代表不同 query 的读取请求自动合并 |
| 通信 | 实际外部载荷、控制消息、辅助参数、目标副本和重试；共享链路按全部工作量合计 |
| 准备 | 输入身份构造、块匹配、族清单展开、命中保护、需求去重、分配、页表安装、责任结算和完成处理；注明每请求或每轮发生的频率 |
| 同步 | 数据到达、表示完成、消费者可见性、共同提交与最后访问；取消可先结束业务，却继续占用待排空页 |
| 驻留 | 唯一源、私有目标、尾部空槽、额外预留、padding、在途旧版本、操作终态及辅助缓冲的同时存活峰值 |

令时刻 t 存活的唯一分配集合为 Live(t)，则占用峰值 M_peak=max_t Σ_{p∈Live(t)}bytes(p)。固定池保留量另报；预留转换为物化页是同一容量责任，不能重复收费。异构池分别满足容量条件，把所有池的空闲字节相加没有联合准入意义。

匹配工作量取决于实际循环。完整注意力扫描 m 个块为 O(m) 次查找；尚未增量构造身份时，还要处理实际输入字节。对每个候选都重新检查窗口清单的基线，其查找量为 Σ_候选 Σ_窗口族 清单页数，不能因为搜索方向向左就宣称整体线性。任意族通用枚举若反复展开整个前缀，还可能产生二次描述访问。分配规划遍历 J 个逻辑引用、形成 K 个唯一目的需求时，散列表的通常模型约为 O(J+K)，而不是只与 K 有关。容量失败后反复回退也要累计已做的展开、保护和撤销工作。

Held(tx) 含 L 个唯一对象时，完整结算至少处理这些责任项；按每对象计数或操作反向索引维护最后使用，可避免每次完成都扫描全部操作。直接在每个完成事件重扫全部责任和操作的解释模型则有额外重复工作，不能把一次 O(L) 当作整个排空成本。账中 H、T、U 的角色重叠不增加该页的物理字节，漏结算却会延长其不能让出的驻留时间。

令实际链路载荷为 D_wire，链路能力上界为 β，则 T≥D_wire/β 是资源下界。串行路径可以累加匹配、准备、传输、转换、后缀计算和发布；存在重叠时按真实依赖求关键路径，共享 HBM、链路或 CPU 的工作仍竞争同一资源。

不同恢复点必须比较到同一任务终点。设 T_suffix(p) 是取得 S(p) 后完成剩余输入和规定输出的成本，则串行估算可写为 T_restore(p)=T_acquire(p)+T_suffix(p)，从初始化重算为 T_suffix(0)。后者已经包含完整输入计算，不能再加一次 prefill；前者也不能只量到状态到达而省掉剩余输入和末行输出路径。

设定 512 MiB 在 16 GiB/s 下纯传输为 31.25 ms。在后续工作相同的条件下，若可替代的重算仅需 20 ms，命中仍可能更慢；若需 200 ms，恢复才有潜在收益，仍须加入其他开销。这些是设定比较，不是设备测量。

连续分配、分页和虚拟连续映射都是候选。连续物理存储可以降低间接访问，但可能需要扩容复制或保守预留；应用分页提高共享和增长粒度，增加块表准备与取址；虚拟连续可以改变物理 backing，仍需映射、权限与最后使用证明。卸载增加源保护、目标容量、传输和转换，不能由一次目录命中省略这些阶段。

条件变化后应按约束决定保留、调整或放弃：

- 增大 r 可减少未来分配次数，但提高当前不可让出的容量。若主要失败来自待排空页，继续增加 r 通常不能解决瓶颈。
- 增大 B 可减少表项与匹配次数，却扩大末段重算、短请求尾浪费和分叉复制；必须同时比较准备与设备消费。
- 窗口扩大后，旧历史缺失不能靠增加长度字段补回；需要合法副本或重放。递归状态也不能任意倒退。
- 模型、adapter、量化或布局改变时，重新建立身份与转换合同；相同字节数不证明可复用。
- 外部带宽下降、转换变重或重算变快时，重新比较完整候选，允许较短共同恢复点或放弃外部命中。
- 层组 padding 或递归状态粒度过大时，可以比较分池或子分配；统一池减少管理种类的收益可能被内部浪费抵消。

## 竞争解释、反例与检查边界

命中率高而 TTFT 没改善，可能是完整块末段重算、外部未到达、准备成本、容量等待或恢复成本超过重算。固定身份、输入、合法输出终点，分别记录匹配、保护、预留、到达、可消费、模型完成与发布时间。固定恢复点只改变传输条件，才能检验传输解释；若容量变化导致恢复点变化，应把新增后缀计算一起列出。目标状态已就绪但没有生成分布时，检查末行 logits 和下一输入，而不是继续扩大缓存。

空闲字节很多却分配失败，可能是命中保护消耗了可淘汰页、独立池不足、物理粒度不兼容或旧操作未结束。保持逻辑工作不变，分别改变 r、跨页位置和一个读者的完成时间，记录各池可立即分配、受保护缓存、私有准备与待排空页。若仅延迟旧读者就减少可分配量，支持生命周期解释；不能归因于请求长度变化。

若请求已退役且全部操作已结束，可分配集合仍未恢复，应枚举 tx 的原始取得清单，与剩余 H 逐项比较。固定同一清单，分别让源进入目标视图、仅被复制、完全未采用；只在后两类泄漏，支持结算范围误用目标 handles 的解释。若有真实在途访问，保留 H 属于本章保守时点；若只剩另一 tx 的 H，容量仍受保护也合法。独立责任观察器必须区分这些情况，不能用清空所有 holds 验证“修复”。

共享后显存下降但 ITL 不变，可能只是唯一页减少，各 query 仍读取相同历史，也可能计算或排队主导。先固定准入请求集比较消费路径；再放开容量准入比较等待和吞吐。两个实验的收益不能归为同一种机制。

错误只在取消或复用后出现时，分别延迟写者、读者和完成通知，并实际执行复用与旧写到达。旧通知被拒绝但新页仍被旧写覆盖，反驳的是物理回收顺序，不能用增加代次比较修复。固定页面、取消和事件次序后仍出错，则转查内容身份、页表、有效长度和表示参数。首次发布前取消还要从请求取消入口检查：没有当前视图，也必须留下关闭事实。

配套检查 tools/check_k_engine_002_full.py 使用确定性的 CPU 符号页模型。扩容公式与逐 token 所需页集合比较；在初始化可用、普通 full 加纯窗口、统一块边界的范围内，恢复搜索与逐位置资格枚举比较。页模型执行外部写入、私有计算、提前发布拒绝、首次发布前取消、旧读者、重复完成、单池容量失败和复用。独立观察器从未结束操作记录重建物理保护责任。

H 回归把目标命中页、未入新视图的已读源和未使用候选同时纳入取得清单。publish 先安装目标 O 并转交 T，再进入 SettleTx 对应的结算入口；release_tx 关闭准备资格并调用同一入口；complete 在证明最后使用、结算 U 后自动续办。检查对照外部保存的原始取得清单、操作记录和请求视图，独立计算应保留的 H 与可分配集合，核对请求及读者结束后的容量恢复、未使用保护立即结算、在途源延后结算、另一 tx 保护保留和重复收尾不变。故障变体实际遗漏成功 H、只清目标 handles 或遗漏中止源 H，再交给同一观察器检测残留及容量滞留。

既有故障对照实际绕过发布门、清除在途保护并复用页面，使旧写污染新内容；共享尾槽另比较隔离分叉与别名覆盖。它们能发现相应内容或责任不变量被破坏，而不只是检查最终空闲数。脚本中的操作登记表示已经授权的物理工作，tx 终态门仅覆盖此符号事务作用域，不实现完整请求授权入口；多池联合事务、预期视图竞争和任意族回退不因该脚本存在而获得完整验证。

这些检查不执行 vLLM 源码、真实模型或 GPU，也不证明哈希安全、任意混合族恢复、低精度误差、真实 CPU 线程原子性、跨 stream/NIC 可见性、DMA 停止、事务合并、图地址合同、设备性能或服务 SLO。层组地址和容量例是明确布局下的推导，不能代替目标 kernel 的布局与硬件验证。
