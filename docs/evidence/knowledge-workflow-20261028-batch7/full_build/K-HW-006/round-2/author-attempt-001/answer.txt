  "chapter": "# K-HW-006：ROCm 平台：CU、Wave 与 AMD 算子路径\n\nROCm 移植需要保持模型函数，同时把逻辑 tile 重新映射到 AMD 的 CU、wave、LDS、寄存器和算子路径。HIP 接受一次调用，只说明接口边界通过；实际选择了哪个 kernel、线程和存储映射是否合法、是否新增转换或准备工作，需要分别核对。\n\n## 问题：函数、数学状态与执行所有权\n\n对一个请求的某个 query head，设 Q∈ℝ^{L×d}、K∈ℝ^{S×d}、V∈ℝ^{S×dv}，缩放为 a，位置偏置为 bᵢⱼ，每行可见 key 集合为 Aᵢ。推理前向、不使用 dropout 时，模型函数为：\n\nzᵢⱼ=a·QᵢKⱼᵀ+bᵢⱼ，pᵢⱼ=exp(zᵢⱼ)/Σ_{t∈Aᵢ}exp(zᵢₜ)，Oᵢ=Σ_{j∈Aᵢ}pᵢⱼVⱼ。\n\n不可见位置不进入分子和分母。GQA 的 query head 到 KV head 映射、非方形因果对齐、分页位置、dtype、舍入和统计量底数都是函数契约。移植可以改变执行组织，不能偷偷改变这些关系。\n\n一次执行的输入条件可写为 P=(算子、dtype、shape、stride、paged layout、mask、目标架构、编译目标、库版本、数值策略)。P 决定合法候选集，库名或 dtype 名称不能决定真实 kernel。需要区分三层状态：\n\n- 逻辑状态：Q/K/V、页表、绝对位置、可见集合和输出位置。\n- 数学状态：每行的最大值 m、归一化质量 ℓ、未归一化加权和 U。\n- 执行状态：每个 lane 持有哪些元素、LDS 槽的写者与读者、何时发布和允许覆盖。\n\n本章标量基线要求 L、S 为非负整数，d、dv 为正整数；输入、参与计算的 V、可见偏置以及计算后的可见分数均有限。点积溢出、NaN、正无穷与特殊值策略超出该基线，调用方须拒绝或选择另有定义的路径。L=0 没有输出工作；S=0 或整行不可见时，本例规定 O 为零、empty 为真。这个空行契约不自动代表任意库接口。\n\n## 合法执行：wave、CU、LDS 与指令契约\n\n固定 HIP 硬件说明把计算资源组织为 shader engine、shader array 和 compute unit。CU 内以 wave 为指令发射与活跃掩码粒度；同一 workgroup 的 wave 被安排在同一 CU，才能使用 workgroup 范围的同步和 LDS 通信。workgroup 到 CU 的映射不确定，算法不能依赖固定 CU 编号。\n\nwave 宽度不是跨架构常数。所供概述以 RDNA 的 wave32 和 CDNA 的 wave64 说明主要组织；实际执行模式仍须绑定编译目标。CDNA 的 SIMD、寄存器和矩阵资源也随代际变化。把 32 当作全部 AMD GPU 的宽度，或用 wave64 的 lane 编号解释 wave32 活跃集合，会破坏归约、写者归属和同步参与条件。\n\nSPI 跟踪影响并发执行的 warp slot、VGPR、SGPR 和 LDS。增加寄存器可能减少可驻留 wave；增加 LDS 可能减少可驻留 workgroup。驻留只是资源约束，不能单独推出性能。所供 LDS 说明给出 CDNA/CDNA2/CDNA3 的 32 个 4 字节 bank，以及 CDNA4、RDNA2/3/4 的 64 个 4 字节 bank。不同地址落在同一 bank 可能串行化；相同地址的多 lane 读取可以广播。服务周期还取决于指令、lane 分组和行距，不能只看逻辑数组名。\n\nMFMA 是 CDNA 的矩阵加速入口。所供示例 `v_mfma_f32_16x16x4f16` 表达 16×16、内维 4、FP16 输入和 FP32 累加；操作数使用寄存器，支持的架构还可能使用 AGPR。示例支持指令形状和资源入口的说明，没有提供任意 tile 的 lane 到 fragment 元素排列。缺少目标 ISA 或编译接口契约时，不能猜内部 fragment。\n\n合法映射至少要满足：\n\n- 目标 wave 宽度、活跃集合、线程分工和同步作用域一致；所有真实生产者和消费者被所用完成契约覆盖。\n- 每个非原子输出元素有唯一写者；相同写值不能使多个并发写者自动合法。标记数组也属于输出。\n- LDS 输入先完整写入并发布，再被消费；最后一个读者结束后才允许覆盖。复制完成、消费者可见和读者结束是不同条件。\n- 分页与普通张量地址使用实际 stride、有效长度和足够宽的整数索引。无效地址不得先解引用再靠输出 mask 补救。\n- MFMA 的形状、dtype、操作数布局、参与范围和完成依赖由目标接口支持。FP32 accumulator 不能概括输入转换、概率精度或输出舍入。\n- 输出彼此不重叠，也不覆盖仍会读取的输入；需要原地更新时另证访问次序。\n\n下面选用一个 workgroup 恰有 64 个线程、目标恰以一个 wave64 执行的基线。所有交接使用覆盖这 64 个线程的 workgroup 同步。这样可以明确同步契约，又不把 wave 锁步执行当成任意 LDS 访问已经完成的证明。\n\n## 一条完整的 wave64 子组 attention 轨迹\n\n选择 Br=4、Bc=16，把一个 wave64 分成四个 16-lane 子组。lane∈[0,64)，g=⌊lane/16⌋，l=lane mod16。子组 g 负责 query_row=r0+g；lane 的子组内编号 l 同时指定本块的一个 key。输出 value 维归属为 D_lane={l+16q | q≥0，l+16q<dv}。因此每个有效输出元素只有一个 lane 持有 U 和执行写回。\n\n协作装载所有权与计算所有权不同。搬运 Q 的线性位置 a=lane+64v 对应 g2=⌊a/d⌋、t=a mod d，其全局行是 load_row=r0+g2。load_row 只能用于这次搬运，不能成为 lane 的 query 身份。每个 lane 在装载完成后独立绑定 query_row=r0+g，后续分数、mask、bias、有效行和输出判断始终使用它。\n\n设页大小为 Gp，逻辑 key j 的物理页为 T[⌊j/Gp⌋]，页内位置为 j mod Gp。以元素为单位，K 的地址为：\n\naddrK(j,t)=baseK+bK·(offsetK+T[⌊j/Gp⌋]·sKpage+(j mod Gp)·sKtoken+t·sKdim)。\n\nV 用自己的基址、元素字节和 stride 替换；Q、O 也按实际 stride 寻址。页表长度至少覆盖 ⌈S/Gp⌉ 个逻辑页，末页只消费有效 token。计算块大小 16 不要求等于页大小；一块跨页时，每个位置分别定位。不同逻辑页可以合法共享只读物理内容，但其位置偏置和可见性仍绑定逻辑 key。\n\n本例 LDS 全部采用 FP32：Q_s 的行跨度为 d；K_s、V_s 按行连续；Z_s、P_s 的行跨度为 17，只使用前 16 列。增加这一列是可替换的布局选择，不构成无 bank 冲突的证明。m、ℓ 在同一子组的 16 个 lane 中复制，U 只按 value 维分片。下面的 m_lane、ell_lane 和 rescale 都是 lane 私有状态。\n\n```pseudocode\n输入：Q[L,d]、分页 K/V、页表、S、实际 stride、scale、bias、可见性 A(r,j)\n      d>0、dv>0；workgroup=64 线程；目标为单个 wave64\n      Br=4、Bc=16；本 workgroup 负责 r0..r0+3\n输出：独立 O[L,dv]，独立且每行一个可寻址 32-bit 元素的 empty[L]\n\nlane∈[0,64)；g=floor(lane/16)；l=lane mod16\nD_lane={u | u=l+16q，q≥0，u<dv}\nLDS：Q_s[4][d]、K_s[16][d]、V_s[16][dv]\n     Z_s[4][17]、P_s[4][17]、M_s[4]、Sum_s[4]\nm_lane=-∞；ell_lane=0\n对 u∈D_lane：U_lane[u]=0\n\n对 a=lane；a<4·d；a=a+64：\n    g2=floor(a/d)；t=a mod d；load_row=r0+g2\n    若 load_row<L：Q_s[g2][t]=按实际 stride 读取 Q[load_row,t]\n    否则：Q_s[g2][t]=0，不访问 Q\n同步整个 workgroup，发布 Q_s\nquery_row=r0+g                 # 独立绑定；不使用 load_row 的最终值\n\n对 k0=0,16,32,… 且 k0<S：\n    对 a=lane；a<16·d；a=a+64：\n        j=floor(a/d)；t=a mod d；key_pos=k0+j\n        若 key_pos<S：K_s[j][t]=按页表和实际 stride 读取 K[key_pos,t]\n        否则：K_s[j][t]=0，不访问 K 或该越界位置的页表\n    对 a=lane；a<16·dv；a=a+64：\n        j=floor(a/dv)；u=a mod dv；key_pos=k0+j\n        若 key_pos<S：V_s[j][u]=按页表和实际 stride 读取 V[key_pos,u]\n        否则：V_s[j][u]=0，不访问 V 或该越界位置的页表\n    同步整个 workgroup，发布本块 K_s/V_s\n\n    pos=k0+l；z=-∞\n    若 query_row<L 且 pos<S 且 A(query_row,pos)：\n        acc=0\n        对 t=0..d-1：acc+=Q_s[g][t]·K_s[l][t]\n        z=scale·acc+bias(query_row,pos)\n    Z_s[g][l]=z\n    同步整个 workgroup，发布 Z_s\n\n    若 l=0：M_s[g]=max_{q=0..15} Z_s[g][q]\n    同步整个 workgroup，发布 M_s\n    bmax=M_s[g]\n\n    若 bmax>-∞：\n        m_new=max(m_lane,bmax)\n        若 ell_lane=0：rescale=0\n        否则：rescale=exp(m_lane-m_new)\n        p=(z>-∞) ? exp(z-m_new) : 0\n    否则：\n        m_new=m_lane；rescale=0；p=0\n    P_s[g][l]=p\n    同步整个 workgroup，发布 P_s\n\n    若 l=0：Sum_s[g]=Σ_{q=0..15} P_s[g][q]\n    同步整个 workgroup，发布 Sum_s\n\n    若 bmax>-∞：\n        对 u∈D_lane：\n            add=0\n            对 q=0..15：\n                prob=P_s[g][q]\n                若 prob>0：add+=prob·V_s[q][u]\n            U_lane[u]=rescale·U_lane[u]+add\n        ell_lane=rescale·ell_lane+Sum_s[g]\n        m_lane=m_new\n    同步整个 workgroup，确认本块所有读者结束后才进入下一轮\n\n若 query_row<L：\n    对 u∈D_lane：\n        若 ell_lane>0：O[query_row,u]=U_lane[u]/ell_lane\n        否则：O[query_row,u]=0\n    若 l=0：empty[query_row]=(ell_lane=0)   # 每行恰写一次，位于 value 循环外\n```\n\n处理完任意前缀 key 后，同一有效行的各 lane 持有相同的 m 和 ℓ；m 是该前缀内可见分数最大值，ℓ=Σexp(z−m)，每个 U_lane[u]=Σexp(z−m)V[u]。新块把最大值改为 m_new 时，旧 ℓ 和旧 U 同乘 exp(m_old−m_new)，再加入新贡献。最终 U/ℓ 恢复整行 softmax。数学等价不代表真实 FP32 归约、指数或输出转换逐位相同。\n\n首个非空块取 rescale=0，避免计算 −∞−有限值；全空块完全保持旧 m、ℓ、U。全空块可能出现在第一个非空块之前、两个非空块之间或最后，不能只验证 S=0。非空状态在精确模型中有 ℓ≥1，故 ell=0 可以识别尚无可见项的状态；实际数值路径仍须排除溢出等例外。\n\nQ_s、K_s、V_s 的每个槽按线性位置模 64 唯一分配给装载者；Z_s[g][l]、P_s[g][l] 由对应 lane 写，M_s[g]、Sum_s[g] 仅由 l=0 写。O 的 value 维模 16 唯一，empty 的每行仅由 l=0 写。empty 采用独立的 32-bit 行元素，避免把此处证明错误推广到多个线程对位打包标记的读改写。\n\n无效 query 行的 lane 仍装载分配给自己的输入并到达所有同步，不写输出，也不读取该行 mask 或 bias。每块有六次完整同步：输入、Z、M、P、Sum 的发布，以及最后读者结束；Q 开始另有一次发布。下一块不得提前覆盖仍在被读取的 K/V/P。扩大 workgroup 后，即使每个 wave 的 LDS 区不重叠，仍须保证所选同步参与者及循环次数合法；不能让不同 wave 在不同次数的 workgroup barrier 上等待。\n\n这是一条普通标量运算与显式 LDS 交接路径，没有声称是 AITER 的实现或 CDNA 高吞吐路径。改用 MFMA 时，QK/PV 数学与在线状态可以保留；fragment 装载、矩阵指令参与范围、累加器归属、概率到矩阵操作数的布局转换和完成依赖必须重新证明。\n\n## 算子库与真实分派\n\nROCm attention 可以经框架可用实现、Triton 或 AITER 等路径接入。真正兼容性是模型语义、dtype、shape、stride、分页布局、mask、图执行要求和目标架构的交集。\n\n所供 S-AITER 原文只有 README，没有算子实现。它说明 AITER 汇集 Triton、模板 C++ 和手写汇编等后端，覆盖 attention、MoE、块级缩放 GEMM、归一化、量化和通信等算子族，并按设备与模型发布调优配置。设备支持程度不同；这不能证明每种 shape、dtype、mask 或分页组合具有同一路径。以下是本章的接入推导，不冒充 AITER 内部 dispatch。\n\n```pseudocode\n输入：op、arch、dtype、shape/stride、paged 与 mask 模式、图执行要求\n      模型/设备配置、库版本、数值策略和质量约束\n输出：合法后端及配置，或明确回退/拒绝\n\n1 核对接口接受的函数、几何、页表单位、mask、dtype 和编译目标\n2 核对执行契约：目标二进制、wave、LDS/寄存器、矩阵或向量操作数布局\n3 形成候选集合；每个候选保留自己的设备、shape、layout 与数值条件\n4 按实际 arch、shape 桶、layout、mask、数值策略及配置选择候选\n5 无合法候选时使用数值等价通用路径，或明确拒绝；不截断输入或改写可见集合\n6 记录实际后端及配置身份；对照独立参考后，再比较完整调用成本\n```\n\n形状桶、页模式、mask、设备、dtype 或库版本变化，可能使旧分派和准备状态失效。Triton 的机制说明也区分逻辑 tile、编译变体、合法域、搜索候选和最终配置；看到一个 tile 参数不能反推出真实 lane/LDS 布局。\n\n预打包、gather、转置、dtype 转换、JIT、调优、参数准备、launch 和输出交接应按真实发生频率计费。跨 backend 共用模型文件不证明共用设备内布局。准备成本 Cprep 若可复用 R 次、每次执行节省 Δt，只有 R·Δt>Cprep 才能在该范围内收回准备；输入变化导致失效时重新计费。图支持还需验证稳定地址中的内容与本次输入匹配。\n\n## 条件化成本：容量、逻辑交通与服务周期\n\n以下数字对应上述全 FP32 标量候选，不能用于某个未知 MFMA kernel。每个 workgroup 的 LDS 容量为：\n\nC_LDS=4·[Br·d+Bc·d+Bc·dv+2·Br·17+2·Br] 字节。\n\n取 Br=4、Bc=16、d=128、dv=16：Q_s 为 2,048 B，K_s 为 8,192 B，V_s 为 1,024 B，Z_s/P_s 各 272 B，M_s/Sum_s 各 16 B，合计 11,840 B，即 11.5625 KiB。填充列占容量但不被本算法读取。对齐、编译器额外 LDS 和同步实现另计。双缓冲 K/V 另加 9,216 B；不能把容量增加等同于读取字节增加，也不能在算法没有复制 Q/Z/P 时给所有对象都乘二。\n\n满块、四行有效且全部 16 个 key 可见时，QK 和 PV 的乘加主项为 2·Br·Bc·(d+dv)=18,432 FLOP；softmax、scale/bias、U/ℓ 重标度、归约和归一化另计。一次 PV 更新还为每个 U 元素执行旧值缩放与相加。mask 会减少这里按分支写出的标量乘加，但生成程序的指令数、尾部浪费和时间未必按相同比例减少。\n\n指数必须分开计数。本例每 lane 计算自己的概率，满块共有 64 次概率指数；首次非空块没有重标度指数。后续非空块中，旧 ℓ>0 的每个 lane 还执行一次 exp(m_old−m_new)。本伪代码把 m/ℓ 和重标度计算复制在子组内，因此四行均已有贡献时另有 64 次重标度指数，合计 128 次。某行当前块为空则两类指数均不执行；此前只有空块的行在第一次非空时仍无需重标度指数。可以改为每子组指定 lane 计算一次 rescale 后发布，把额外指数降至每行一次，但那是另一个候选，需要补共享状态、读取和同步证明。数学 exp 也不直接等于某条 ISA 指令的数量，底数转换与编译降低须检查生成程序。\n\n按实际伪代码逐个标量读取计，满块且概率为正时，主要 LDS 消费读取如下：\n\n| 消费对象 | 读取元素数 | 给定参数下的 FP32 字节 |\n|---|---:|---:|\n| QK 中 Q_s | Br·Bc·d | 32,768 B |\n| QK 中 K_s | Br·Bc·d | 32,768 B |\n| PV 中 P_s | Br·Bc·dv | 4,096 B |\n| PV 中 V_s | Br·Bc·dv | 4,096 B |\n| 上述主项合计 | 2·Br·Bc·d+2·Br·Bc·dv | 73,728 B |\n\n因此 Q/K 两类合计是 65,536 B，不能把它们合并成只有一次 Br·Bc·d 的读取。PV 中每个输出维各读一次概率，不能只按 64 个概率值计一次。概率为零时本代码跳过相应 V 读取，但仍先读取 P。\n\n另外，l=0 扫描 Z 和扫描 P 求和各读 256 B；64 个 lane 读取 M 和 Sum 各读 256 B。在四行非空的满块中，这些辅助读取再加 1,024 B，总逻辑消费读取为 74,752 B。每块逻辑 LDS 写入为 K/V 的 9,216 B、Z/P 的 512 B、M/Sum 的 32 B，合计 9,760 B；Q 的 2,048 B 写入只在开头发生。尾部仍填满片上输入槽，但不为无效位置发出全局读取。\n\n这些是程序逻辑读写，不是 bank 服务周期。Q_s 同行元素可能被子组广播；K_s 的同一元素可能被不同子组读取；P_s 也可能广播。广播可以改变物理服务工作，不能回头从已声明的逻辑读取计数中删掉读者。bank 周期须结合生成的标量或向量指令、服务 lane 分组、行距和
