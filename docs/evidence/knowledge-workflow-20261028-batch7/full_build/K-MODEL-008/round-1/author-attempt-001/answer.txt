  "chapter": "# K-MODEL-008：视觉语言模型：Patch、模态桥接与联合位置\n\nVLM 的服务输入不是“若干张图加一段文本”，而是由媒体快照、processor 配置、视觉编码器、桥接器、文本模板和位置规则共同定义的多模态序列。图像张数、文本字符数或 URL 都不能单独决定视觉 token 数、KV 容量和缓存命中。本章以 Qwen2.5-VL v1 报告中的具体机制为锚点，推导可复用的几何、状态和成本账本；具体 checkpoint 的 processor 与模型契约必须以固定版本为准。\n\n## 对象、状态与不变量\n\n设一次请求 r 的有序媒体列表为 m_1,...,m_k，文本消息为 M。固定 processor 契约 P 和模型契约 Q。对第 i 个媒体定义：\n\n- 不可变媒体快照 s_i：由内容身份、字节范围、解码/方向/色彩配置和源时间信息组成。仅凭 locator、文件名或 URL 不能证明内容相同。\n- 预处理张量 X_i：按 P 完成方向、色彩、resize、crop、归一化、帧选择后的像素或帧张量。\n- 视觉网格 G_i=(T_i,h_i,w_i)：T_i 是时间片数，h_i 和 w_i 是 patch 网格的高和宽。静态图通常 T_i=1；视频还有抽帧和时间轴。\n- patch 特征 F_i：视觉编码器逐 patch 的输出；合并/桥接特征 Z_i：按模型规定的 merge 与 projector 产生的语言侧特征。\n- 语言输入 L：文本 token、特殊 token、视觉占位符和 Z_i 按媒体顺序组成的规范序列；其位置映射为 Π，可见性关系为 A。\n- decoder 状态：逐层 K/V、已提交 token、已生成 token 和输出事件。\n\n阶段状态可取 ACCEPTED → MEDIA_READY → PREPROCESSED → ENCODED → MERGED → PACKED → PREFIX_READY → DECODING → DONE，以及 INVALID_MEDIA、INVALID_GEOMETRY、IDENTITY_MISMATCH、CAPACITY、CANCELLED 等失败态。状态表示的对象不同：MEDIA_READY 只表示快照可读，不表示像素布局已满足模型；ENCODED 表示视觉特征完成，不表示已被语言侧消费；PREFIX_READY 表示所选 decoder 前缀的 token、位置和 mask 已一致，不表示新 query 的输出已经产生。\n\n不变量如下。\n\n1. 媒体顺序、视觉占位符顺序与 Z_i 顺序一一对应。多图输入不能因批处理压紧而交换两个 image placeholder 的特征段。\n2. 网格、merge 规则、token 数和位置映射必须来自同一个 processor/模型契约。H、W 能被 28 整除只证明满足 Qwen2.5-VL 报告所述 resize 条件之一，不证明任意实现都接受该形状。\n3. 视觉特征缓存身份覆盖内容、processor、编码器、merge/projector、数值表示和几何；decoder 前缀身份还要覆盖文本 token、模板、位置、mask 和 adapter。视觉特征可复用不等于完整前缀可复用。\n4. 一个缓存或 KV 对象只在全部生产者完成并发布后对消费者可见；取消后的迟到结果按请求和代次丢弃，不写入已复用槽位。\n5. 视觉 token 已被编码，不等于其 KV 已计算。decoder KV 只覆盖实际进入 prefill/decode 的 token；缓存特征也不等于缓存 KV。\n6. 位置与可见性是模型函数的一部分。形状相同而 Π 或 A 不同，不能做等价前缀命中。\n\n## 几何账本：Patch、窗口与合并\n\nQwen2.5-VL 报告给出的锚点为：输入高宽 resize 到 28 的倍数，patch 边长 14，视觉 encoder 使用窗口注意力，最大窗口 112×112，即最多 8×8 个 patch；32 层视觉 encoder 中只有 4 层使用全注意力；桥接器把空间相邻的 4 个 patch 特征拼接后经两层 MLP 投影到语言模型维度。7B 配置的 ViT hidden 为 1280，merger 输出为 3584，LLM 为 28 层、4 个 KV heads、head size 128。以下公式以这些事实为特例，不把 7B 参数写成所有 VLM 的定义。\n\n静态图不考虑 crop 时，n_h=H/14，n_w=W/14，N_p=n_h n_w。若按 2×2 合并，且 n_h、n_w 均为偶数，则 N_v=N_p/4。H、W 是 28 的倍数意味着 n_h、n_w 是 2 的倍数，因此在报告所述 resize 条件下 2×2 分组可以整除。448×672 的处理后图像给出 n_h=32、n_w=48、N_p=1536、N_v=384。若文本为 512 token，decoder 输入长度为 896；不是 512 加图片张数。\n\n每边分辨率翻倍时，n_h、n_w 翻倍，N_p 和 N_v 变为 4 倍。若视觉 self-attention 是 dense 的，成对 score 数按 N_p² 增长，即 16 倍。窗口注意力把大部分层的成对工作限制在窗口内。设窗口划分集合为 W，窗口 w 的 patch 面积为 a_w≤64，全注意力层数为 L_f，窗口层数为 L_w，则每个 head 的成对 score 计数为\n\nC_pair = L_f N_p² + L_w Σ_{w∈W} a_w²。\n\n对 448×672、L_f=4、L_w=28，网格正好分成 24 个 8×8 窗口，因此 C_pair=4×1536²+28×24×64²=12,189,696。若 32 层全为 dense，则 32×1536²=75,497,472；前者约为后者的 1/6.19。这个数只数成对 score，不含 Q/K/V 线性投影、FFN、softmax、访存、head 维度和 kernel 效率，不能直接当作端到端时延比。若图像小于一个窗口，窗口层可能退化为单个窗口，此时窗口注意力没有渐近收益，额外调度或边界处理甚至可能占主导。\n\n合并不是免费的。2×2 合并把 4×1280=5120 维输入经 MLP 投到 3584 维；它把 decoder 视觉 token 数减少到 1/4，但视觉 encoder 仍处理 N_p 个 patch，merge 自身也有线性层和临时缓冲。两层 MLP 的隐藏宽度在供应文本中没有给出，因此只能确定输入/输出维度和每 token 的符号成本，不能虚构隐藏层 FLOPs。\n\n视频多一个时间轴。报告描述动态 FPS、绝对时间编码，以及把连续两帧成组以减少 token。若某实现把每两帧作为一个时间片并对每个时间片做 2×2 空间合并，则在偶数帧、固定空间网格的设定下可写成 N_v=(T/2)n_h n_w/4；但报告供应范围没有给出奇数尾帧、精确 merge 边界和所有时间压缩细节，本章不把这些当成模型事实。视频 token 数至少取决于帧数、抽帧时间、空间网格和时间分组；报告实验还给出每视频最多 768 帧、视频 token 不超过 24,576 的评测上限，这是该实验设置，不是所有服务的通用上限。\n\n## 联合位置、可见性与前缀等价\n\nMRoPE 类方案把位置表示为至少三个分量：时间 t、高 h、宽 w。对文本 token，Qwen 报告说明三个分量使用相同 position ID，因而在该模型中等价于传统一维 RoPE。对图像，时间分量在视觉 token 上保持不变，h/w 分量按 token 在图像网格中的行列分配。对视频，时间分量随帧推进；Qwen2.5-VL 进一步把时间分量对齐到绝对时间，使不同 FPS 下的时间间隔表达事件节奏。精确的数值映射（时间戳到 ID 的比例、取整和边界）不在供应文本中，必须由 checkpoint/processor 合同给出。\n\n因此不能把所有视觉 token 按行主序编成 0,1,2,... 的单维位置后仍声称函数不变。以 2×2 图像、时间基准 t_0 为例，正确结构是 (t_0,0,0)、(t_0,0,1)、(t_0,1,0)、(t_0,1,1)；扁平化为 (0,0,0)、(1,1,1)、(2,2,2)、(3,3,3) 会同时改变时间、行和列的解释。形状仍是 4 个 token，但模型函数已改变。\n\n可见性 A 也是模型合同：decoder 的自回归 mask、视觉 token 是否对全部后续文本可见、padding 和特殊 token 的可见关系，都必须按所选模型核对。固定文档对 KV 缓存的说明是：历史 K/V 逐层复用，新增 K/V 计算后与历史拼接，增量 attention mask 要覆盖历史与新增 token；这支持“逻辑位置、可见性和物理槽位分开”的实现，但不能从字段名推断所有模型的 position_ids 或 cache_position 合同。另一个边界是：对不可见位置只把 score 乘零不能保证 softmax 后概率为零，必须按实际可见集合或等价的加性遮罩定义。\n\n前缀等价的必要条件是：语言 token 序列、媒体段顺序、视觉 token 数、Π、A、模板、adapter 和数值表示都相同，且这些量对应的特征/KV 已按同一身份发布。只比较输入形状、图片数量或文本长度不足。相同图片配不同前置文本时，视觉特征 key 可以相同，但完整 decoder 前缀 key 通常不同；相同 URL 配不同内容时，连视觉特征 key 也必须不同。\n\n## 桥接路径、缓存身份与完整算法\n\n至少有两条接入路径。\n\n- projector + decoder self-attention：视觉特征经 MLP/projector 变为语言维度，插入 placeholder，和文本 embedding 一起进入 decoder。Qwen2.5-VL 报告属于这一类。视觉 token 增加 decoder 序列长度和 self-KV；视觉 encoder 的窗口注意力只降低视觉阶段成本，不会自动降低 decoder KV。\n- cross-attention：语言 query 读取视觉源 K/V。S-TRANSFORMER 定义的 encoder-decoder attention 中 Q 来自 decoder、K/V 来自 encoder 表示；当源表示和投影固定时，源 K/V 可以构建一次、多次读取。目标 self-KV 与源 K/V 是两套状态，容量、身份和可见性要分开。\n\n两条路径都可能合法，选择取决于模型结构和质量契约，不是“有缓存”就选 cross。projector 路径的桥接参数和 merge 规则属于 Z 的身份；cross 路径还要把源层、head 映射、源位置变换和可见集合纳入源 K/V 身份。\n\n缓存身份可分为：\n\n- source_key：不可变媒体内容、解码/方向/色彩、resize/crop/插值、归一化、帧时间、patch/merge 和模型输入几何。\n- feature_key：source_key + 视觉 encoder 权重/精度/布局 + merge/projector 权重/精度 + Z 的维度和表示。\n- prefix_key：feature_key + 文本 token、模板、特殊 token、媒体顺序、Π、A、adapter、decoder 权重/精度和 KV 布局。\n\nsource_key 相同的 URL 不构成证明；必须来自不可变快照或经验证的内容摘要。缩略图、方向元数据、EXIF 旋转、色彩空间和帧时间都可能改变 X，从而改变特征。数值“接近”不是精确缓存条件；若允许近似重用，要另行定义误差和质量契约。\n\n下面是处理器、视觉桥接和 decoder 的完整主路径。伪代码强调状态与提交顺序，不绑定某个库的 API。\n\n```pseudocode\nALGORITHM RunVLM(r, P, Q, FC, PC)\n输入：请求 r 含有序媒体、消息、采样参数；processor 契约 P；模型契约 Q；特征缓存索引 FC；前缀缓存索引 PC\n输出：文本/多模态输出事件；或 INVALID_MEDIA、INVALID_GEOMETRY、INVALID_LAYOUT、IDENTITY_MISMATCH、CAPACITY、CANCELLED\n\n1. state←ACCEPTED；按 r.media_order 取得不可变媒体快照 s_1..s_k。\n   若 locator 没有经验证的内容身份，先取得内容并计算摘要；摘要失败返回 INVALID_MEDIA。\n2. 对每个 s_i：\n   X_i,G_i←Preprocess(s_i,P)\n   若 H_i、W_i 或时间分组不满足 P/Q 的合法性，返回 INVALID_GEOMETRY\n   fkey_i←FeatureKey(s_i.content_id,P.digest,Q.encoder.digest,Q.merger.digest,G_i,Q.dtype)\n   若 FC 中存在 ready 且身份完全相等的条目：\n      F_i,Z_i←Restore(FC,fkey_i)\n   否则：\n      F_i←VisionEncode(X_i,G_i,Q.encoder)\n      Z_i←MergeProject(F_i,G_i,Q.merger)\n      仅当全部层和表示元数据完成后，以 fkey_i 和本次 generation 发布 FC 条目\n   记录 i 的媒体顺序、网格、Z_i 字节数和 fkey_i\n3. L←Pack(r.messages,r.media_order,Z_1..Z_k,P.placeholder_policy)\n   若 placeholder 段数与媒体数不等、顺序不一致或视觉 token 数与 G_i/merge 不符，返回 INVALID_LAYOUT\n   Π←PositionIDs(L,G_1..G_k,Q.position_contract)\n   A←Visibility(L,Q)\n4. pkey←PrefixKey(L,Π,A,Q,P,r.adapter)\n   若 PC 有完全相等的 ready 前缀：\n      复用该前缀的 KV 与已提交状态\n   否则：\n      只复用最长合法公共前缀；对不一致后缀重新 prefill\n      在本次 generation 下发布新前缀，禁止把部分新层与旧层拼成一个前缀\n5. 进入 DECODING：每步用当前 token 的 Q 读取已有 KV，按 Q 计算并追加新 K/V；\n   位置和 mask 与 L 的实际 token 对齐；输出事件带请求 ID、代次和已提交 token 边界。\n6. 完成时提交 DONE；失败或取消时停止新提交，撤销未提交预留，\n   对已提交异步工作和缓存读者排空后回收；迟到 Z/KV 按 (请求,generation) 丢弃。\n```\n\n算法中有三个容易出错的提交边界。第一，F/Z 缓存发布只能在 merge/projector 和元数据都完成后；读取到半写的 Z 比 miss 更危险。第二，decoder 前缀命中只覆盖公共前缀，新 query 仍要 prefill；不能把完整前缀命中当成完整响应命中。第三，取消后媒体读取、H2D、视觉 kernel 和 KV 写入可能仍在途，只有完成事件和引用归零后才能复用槽位。\n\n## 成本：视觉注意力、桥接、KV 与主机\n\n设 d_v 为 ViT 宽度，d_l 为语言宽度，b_v、b_l 为元素字节，N_t 为文本 token 数，N_v 为视觉 token 数，N_o 为预留输出 token 数。先区分四类量：\n\n- 逻辑 token 数：N_p、N_v、N_t、N_o。\n- 逻辑字节：像素 H W C b_pix；patch 特征 N_p d_v b_v；合并特征 N_v d_l b_l。\n- 设备事务量：实际 kernel 读写、padding、布局转换、H2D/D2H 和缓存恢复字节。\n- 关键路径时间：阶段依赖、排队、同步和未重叠的执行。\n\n视觉 encoder 的成对 score 计数已在上节给出。若粗略把每个 score 记为 d_k 次乘加，则 QK 与 PV 各带来与 C_pair d_k 成比例的工作；实际还要加线性投影、FFN、softmax、归一化和访存。窗口注意力使 C_pair 从 N_p² 转向 Σ a_w² 的线性项，但全注意力层仍按 N_p² 增长；因此“使用窗口注意力”不能推出任意分辨率下成本都线性。merge/projector 的每 token 成本为输入 4d_v 到隐藏宽度、再到 d_l 的两层线性变换；隐藏宽度未给出时只保留符号成本。\n\ndecoder KV 的每 token 字节数为\n\nB_kv = 2 L_dec H_kv d_head b_kv，\n\n其中因子 2 对应 K 和 V，L_dec 是 decoder 层数，H_kv 是 KV heads，d_head 是每 head 维度，b_kv 是每元素字节。Qwen2.5-VL-7B 配置给出 L_dec=28、H_kv=4、d_head=128；在 BF16、无额外元数据和页尾的设定下，B_kv=2×28×4×128×2=57,344 字节=56 KiB/token。projector 路径的输入 KV 为 (N_t+N_v)B_kv；若再预留 N_o 个输出 token，完整预留为 (N_t+N_v+N_o)B_kv。cross 路径要把目标 self-KV 与源 cross-KV 分开，不能把 projector 路径的 N_vB_kv 直接套到 cross 源上。\n\n仍用 448×672、384 个视觉 token、512 个文本 token、256 个输出预留：输入为 896 token，输入 KV 为 49 MiB，完整预留为 63 MiB/请求。8 个请求的该项为 504 MiB。视觉 patch 的 1280 维 BF16 特征为 3.75 MiB，合并后的 3584 维 BF16 特征为 2.625 MiB，FP32 三通道像素为约 3.445 MiB；三者若同时存活约 9.820 MiB。20 份合并特征另占 52.5 MiB。以上只是所列对象，不含权重、层中间量、媒体解码缓冲、工作区、页尾和对齐，不能当作整模型峰值显存。\n\n主机路径的成本不是一次复制：媒体获取/解码、方向/色彩、resize/crop、归一化、连续化、可能的 pinned staging、H2D、视觉 kernel、merge、语言 prefill 和首内容发送都可能在不同执行域。像素字节、patch 特征字节和合并特征字节是不同对象；若它们同时在途，容量要按同时存活关系加，若生产者及时交还则不能重复加同一物理副本。小 metadata 可能受提交次数和同步主导，大图更接近像素/特征带宽问题；要把每阶段的队列时间和 CPU/GPU 服务时间分开。同步成本包括媒体解码完成、H2D 完成、视觉 kernel 完成、feature/prefix 发布和首内容提交；这些事件在关键路径上不一定能相互覆盖。\n\n设一次冷路径的媒体获取 20 ms、预处理 15 ms、视觉 encoder 35 ms、桥接 5 ms、语言 prefill 60 ms、所有队列合计 25 ms、首内容发送 5 ms，则串行 TTFT 为 165 ms。若特征缓存查找/恢复共 8 ms，并确实消除预处理、视觉和桥接 55 ms，但内容身份仍需获取媒体，则 TTFT 为 20+8+60+25+5=118 ms；若身份可由经验证快照直接证明而不取媒体，才可把 20 ms 去掉，得到 98 ms。这个差值不是缓存“免费”的证据，而是身份验证路径的成本。若完整前缀命中再省 60 ms prefill，但路由/抢占增加 30 ms 队列，则可能只得到 88 ms 或更差；必须把命中收益、排队和 KV 容量放在同一时间范围比较。\n\n这些时间均为设定算例，不是 GPU 或 CPU 实测。真实设备上的窗口注意力、merge、H2D 和 prefill 可能重叠，也可能被共享带宽或 kernel launch 主导；不能把多个阶段的最大值简单当成总时延，也不能把串行和相加当成所有实现。\n\n## 三阶段队列、批处理与服务指标\n\n把请求拆成媒体、视觉、语言三段，不是为了固定三个进程，而是为了分别计量就绪条件、资源单位和背压。\n\n| 阶段 | 队列计量 | 就绪条件 | 主要风险 |\n|---|---|---|---|\n| 媒体 | 原始字节、像素、帧数、解码工作 | 快照可读且内容身份可验证 | CPU 解码/resize 阻塞；同一 URL 内容变化 |\n| 视觉 |
