{"chapter":"# K-MODEL-006：MLA：压缩状态、矩阵吸收与解耦 RoPE\n\nMLA 通过缓存低维 latent 与解耦位置分量改变 KV 的表示。逻辑容量下降不等于执行流量下降：只有内核沿压缩状态完成分数与值聚合，才能避免每步展开全部历史。\n\n## 问题、函数与状态\n\n普通 MHA 每层每 token 缓存 2 n_h d_h 个元素；长上下文与大批量下，KV 容量和 decode 读取成为瓶颈。GQA/MQA 通过减少 KV head 数缩小状态，但会改变 query 到 KV 的映射。MLA 不共享普通 KV head，而是让所有 head 共用一份内容 latent，再用每个 head 自己的上投影恢复内容 K/V。设 hidden 为 h_t，层参数为 W^{DKV}、W^{UK}、W^{UV}、W^{KR}、W^{DQ}、W^{UQ}、W^{QR}、W^O，维度为 d、n_h、d_h、d_c、d′_c、d_R。DeepSeek-V2 的一种配置是 d_c=4d_h、d_R=d_h/2；具体制品必须按 checkpoint 核对。\n\n内容 latent 与解耦位置分量定义为：z_t=W^{DKV}h_t，s_t=φ(z_t)，k^C_{t,i}=W_i^{UK}s_t，v^C_{t,i}=W_i^{UV}s_t，k^R_t=RoPE(W^{KR}h_t,t)，c^Q_t=W^{DQ}h_t，q^C_{t,i}=W_i^{UQ}c^Q_t，q^R_{t,i}=RoPE(W_i^{QR}c^Q_t,t)。φ 是制品的逐 token 固定变换；没有额外归一化时 s_t=z_t。若 DeepSeek-V3 所述 latent 后 RMSNorm 与宽度瓶颈缩放存在，必须把归一化后的 s_t 或足以恢复它的逐 token 标量纳入状态，不能把非线性跨过矩阵乘法消去。查询压缩只降低训练/激活内存，不自动降低 KV 缓存；DeepSeek-V2-Lite 甚至不压缩 query，不能把 query 压缩当成 MLA 的必要条件。\n\n每个 token 的每层持久状态是 s_t 与 k^R_t，另有逻辑位置、有效长度、量化 scale/offset、残余高精度窗口和页表等元数据。逻辑缓存元素数为 L(d_c+d_R)N；若每个 head 各存一份 k^R，则 d_R 要乘 n_h，不能沿用共享 key 的公式。查询 q_{t,i}=[q^C_{t,i};q^R_{t,i}]，key k_{j,i}=[k^C_{j,i};k^R_j]，分数为 q^T k / sqrt(d_h+d_R)，可见集合 A_t 只包含模型允许的位置。输出 u_t=W^O[o_{t,1};…;o_{t,n_h}]，其中 o_{t,i}=Σ_{j∈A_t} softmax_j(score) v^C_{j,i}。这与 GQA 不同：GQA 的共享对象是普通 K/V head；MLA 的共享对象是内容 latent，各 head 仍有不同的上投影，容量和 scale 都不能用 Hkv 与普通 head_dim 直接套算。\n\n## 合法性：吸收、非线性与位置\n\n内容分数的吸收来自 q^C_i^T W_i^{UK}s_j=(W_i^{UK,T}q^C_i)^T s_j。令 qtilde_{t,i}=W_i^{UK,T}q^C_{t,i}，则历史 key 不需要逐 token 上投影成 k^C。值聚合同理：o_{t,i}=Σ_j a_{ij}W_i^{UV}s_j=W_i^{UV}z_{t,i}，z_{t,i}=Σ_j a_{ij}s_j；最终输出可写成 u_t=Σ_i W_i^O W_i^{UV} z_{t,i}，也可以先对每个 head 算 W_i^{UV}z_{t,i} 再拼接过 W^O。两种写法在实数中等价，但预乘 G_i=W_i^O W_i^{UV} 的权重大小是 d×d_c 每 head，未必比先降到 d_h 再乘 W^O 便宜；吸收是代数事实，不规定必须把所有矩阵预先合并。\n\n合法性要求：上投影与输出投影的 head 切片必须与 query/key 的 head 身份一致；s_j 必须是所有消费者共同解释的那份状态；softmax 的 score 使用 sqrt(d_h+d_R)，不是 sqrt(d_h)；位置分数只来自 q^R 与 k^R 的点积；mask、因果和分页只改变 A_t 与地址，不改变上述函数。若缓存原始 z_j 而在读取时逐 key 应用 φ，分数是 (W^{UK,T}q)^T φ(z_j)，不能换成 (W^{UK,T}q)^T z_j。若 φ 是 RMSNorm 加对角 gain/scale，可以在写入时存 s_j，或另存逐 token 归一化标量并在读取时使用；漏存这个标量会改变函数。\n\nRoPE 与投影不可任意交换：位置相关旋转若插在 W^{UK} 与 s_j 之间，历史 key 的旋转随 j 变化，固定 query 侧矩阵无法把所有位置吸收掉。DeepSeek-V2/V3 因此把位置分量解耦成共享 k^R_t 与 per-head q^R_{t,i}。把整个 latent 当普通 RoPE head 旋转、或把 k^R 省略，都会改变分数。长上下文 YaRN 等位置缩放作用于解耦位置路径；报告明确提到作用于 k^R，若制品还把缩放用于 q^R，应以制品核对，不能从一句话推断所有实现只改一侧。\n\n量化改变的是数值，不改变吸收等式：只要所有 head 消费同一份反量化后的 s_j，内容分数仍可用 qtilde 计算；但 latent 的一个通道误差会经 W^{UK}/W^{UV} 影响多个 head，不能把 KIVI 对普通 K 的 per-channel、V 的 per-token 结论直接当成 MLA latent 的最优分组。KIVI 的分组轴与高精度残余区是待验证的候选；scale/offset 必须跟随正确的组、token 和层，页边界与残余窗口不能改变逻辑位置。\n\n## 完整算法与提交边界\n\n下面的 decode 步骤把当前 token 的 s_T、k^R_T 先作为临时量参与 attention，只有在输出成功提交后才写入持久缓存；这样失败步骤不会留下一个已消费但无输出的长度。\n\n```pseudocode\n算法 MLA_DECODE_STEP\n输入：层参数；请求缓存 S[0:T-1]、KR[0:T-1]；当前 h_T；逻辑位置 p=T；可见集合 A_T⊆{0,…,T}\n输出：u_T；提交后的缓存 C′\n1 z = W_DKV h_T；s = LatentState(z)；若只存原始 z，则记录归一化标量 r\n2 kr = RoPE(W_KR h_T, p)\n3 cQ = W_DQ h_T；qC = W_UQ cQ；qR = RoPE(W_QR cQ, p)  // qR 按 head 切分\n4 u = 零向量[d]；对每个 head i：\n5     qt_i = W_UK_i^T qC_i\n6     对 j∈A_T：\n7         sj = (j<T ? S[j] : s)；krj = (j<T ? KR[j] : kr)\n8         score_ij = (qt_i·sj + qR_i·krj) / sqrt(d_h+d_R)\n9     a_i = StableSoftmax(score_i 在 A_T 上)；A_T 为空则按显式空策略拒绝或返回零\n10    z_i = Σ_{j∈A_T} a_ij sj\n11    u += W_O_i W_UV_i z_i   // 或先算 W_UV_i z_i 再拼接过 W_O\n12 若 u_T 成功提交：\n13    S[T]=s；KR[T]=kr；T=T+1；发布 C′\n14 否则不发布 C′；返回 u_T\n```\n\nPrefill 可以按行块执行。若选择展开路径，先对历史与块内可见 key 计算 k^C=W^{UK}s、v^C=W^{UV}s 到临时 K/V，再调用标准分块 attention；持久缓存仍只写 s 与 k^R，临时展开区在最后读者结束后释放。若选择吸收路径，对每个 query head 先算 qtilde，在 s 上做内容分数、在 k^R 上做位置分数，用在线 softmax 逐 KV 块归约，值在 latent 上聚合后再过输出投影。块内因果 mask 必须按绝对位置构造；L≠S 时不能默认 query 行号就是 key 位置。分页缓存下，逻辑 token 到物理页的映射只改变 sj、krj 的地址，不改变 A_T。prefill 的临时展开、split-K 的 partial 状态和 workspace 必须分别计入峰值；完成后按层/请求提交，不能只发布长度而漏掉 latent 或位置分量。\n\n## 成本：容量、计算、通信与驻留\n\n逻辑容量为 B_state=L(d_c+d_R)bN，b 为每元素字节。设 L=32、n_h=32、d_h=128、d_c=512、d_R=64、BF16、N=8192，则 MLA 每 token 为 32×(512+64)×2=36 KiB，总 288 MiB；同尺寸 MHA 为 32×2×32×128×2=512 KiB/token，总 4 GiB，逻辑比例 7.03%。这个比例来自所设结构，不是某个部署模型的通用性能。DeepSeek-V2 报告的 93.3% 是相对 DeepSeek 67B 的部署比较，不能直接当成任意 MHA 配置的比例。\n\nTP 会改变物理账。若按 query heads 做 TP，每个 head 的内容上投影仍需要全部 d_c 个 latent 通道，常见简单组织是每 rank 复制整份 s/k^R；TP4 时每 rank 仍为 288 MiB，全组 1.125 GiB。若 MHA 按 head 分片，TP4 每 rank 为 1 GiB、全组 4 GiB；MLA 的全组物理比例变成 28.1%，而不是逻辑上的 7.03%。另一种按 latent 通道分片可把每 rank 状态降到 72 MiB，但每个 query-key 的内容分数需要跨 rank 求和；以 n_h=32、S=8192、FP32 分数为例，一层一个 decode 步的分数 all-reduce 发送量约为 1.5 MiB，32 层约 48 MiB，尚未计值聚合的 partial 和同步。两种组织都必须写出所有者、归约和输出拼接，不能只从权重被切分推断缓存同步被切分。EP 分散 FFN 专家，不自动分散 attention latent；attention 状态仍属于拥有该请求 attention 的执行组。\n\n计算主项可用 S 个可见 key、L 个 query 行估计。展开路径每层约为：历史 K/V 上投影 S n_h 2 d_c d_h；QK/PV 的 L S n_h(2d_h+d_R)；输出 L n_h d_h d。吸收路径每层约为：每个 query 的 qtilde L n_h d_c d_h；内容分数与 latent 值聚合 L S n_h 2d_c；位置分数 L S n_h d_R；输出若先降维再乘 W^O 为 L n_h(d_c d_h+d_h d)，若预乘 G_i 则为 L n_h d_c d。decode 的 L 很小，吸收省掉随历史增长的 K/V 上投影；prefill 的 L 很大，展开的 K/V 投影可被多个 query 行摊销，而吸收的内容点积维度从 d_h 变成 d_c，可能反超。d_c 越大于 d_h，这个反转越早出现。预乘 G_i 还可能把权重从 d_c d_h+d_h d 增大到 d_c d 每 head，必须把参数驻留和每 token 计算一起比较。\n\n访存上，吸收路径每层每 query 至少读取历史 s 与 k^R 的有效字节，若内核在片上重读或 split-K 分块，实际事务高于逻辑字节。展开路径若把 k^C/v^C 写回设备内存，会增加 S 2n_h d_h b 的写和后续读；若只在片上展开，仍要付投影计算和片上容量。split-K 的 partial 状态包含每个 head 的 m、ℓ 和 d_c 维 Z，合并成本随 d_c 与分区数增长；在线 softmax 的 rescale 也随 head 数与 KV 块数增长。准备包括 latent 归一化、RoPE、页表、末页长度、量化 scale 和输出 workspace；该实现的 attention 接口把准备段与执行段分开，metadata 的 query 分段、页索引和末页长度单位不同，MLA 内核不能把这些单位混用。执行段可复用计划，但 batch、分段、KV 长度、mask 或变体条件改变后旧计划失效；图捕获还要求 metadata 缓冲在生命期内稳定。\n\n一个可复算的硬件映射是：一个 CTA 处理 B_q=1 行、H_tile=8 个 query head、B_s=128 个 key。共享区放 S_tile[B_s,d_c] 与 KR_tile[B_s,d_R]；寄存器/共享区放 qtilde[H_tile,d_c]、Z[H_tile,d_c] 和 scores[H_tile,B_s]。先做 Qtilde·S_tile^T 得内容分数，再做 QR·KR_tile^T 得位置分数；按 head 行在线 softmax，再做 P·S_tile 得 latent 聚合。BF16 下 S_tile 为 128×512×2=128 KiB，KR 为 16 KiB，qtilde 为 8×512×2=8 KiB，scores 为 8×128×4=4 KiB，Z 为 8×512×4=16 KiB，合计约 172 KiB，尚未计双缓冲、对齐、barrier、输出投影和 split-K partial。这个账只展示容量约束，不指定最佳 tile；若共享存储上限更小，应缩小 B_s 或 H_tile，若双缓冲 S_tile 则再增 128 KiB。矩阵指令的 fragment 布局、warp 分工和完成依赖须按目标指令契约核对，不能从逻辑 tile 推断线程映射。\n\n## 条件变化与选择反转\n\n长历史 decode 的 L 很小，吸收路径通常先减少历史 K/V 上投影；短 prompt 或小 S 时，投影、准备和输出主导，展开路径可能并不更慢。prefill 同一请求内 L 接近 S 时，展开 K/V 的上投影被多行 query 复用，而吸收的多出 L S n_h(d_c-d_h) 内容点积，选择可能反转。多请求 batch 不自动把不同请求的历史 K/V 投影合并；只有共享同一前缀且展开结果被复用时，才可能摊销。TP 复制 latent 会让逻辑容量收益在 rank 或全组层面缩水；若容量是准入瓶颈，应按每 rank 实际字节决定，而不是按单请求逻辑字节。量化后 latent 误差经所有 head 放大，质量门槛可能迫使更高位宽或更大的高精度残余窗口，从而抵消容量收益。RMSNorm、宽度缩放、RoPE/YaRN 频率或 head 映射改变后，旧缓存只有在表示转换和位置规则都明确等价时才能复用；仅总长度相同不构成复用资格。分页页长、量化组长和残余窗口不一致时，尾页、跨页组和迁移都要重新计账。\n\n## 诊断与区分实验\n\n先判断驻留对象：若持久缓存只含 s 与 k^R，容量公式才有意义；若同时保留展开 K/V，峰值要相加。再判断每步是否临时展开全部历史：记录持久 bytes、当前 query 展开、历史展开、split/merge workspace 和分片复制，不能只看张量总长度。正确性参考应独立构造整行可见集合，分别比较内容分数、位置分数、softmax 权重和最终 head 合成；只比较最终生成文本会把 head 映射、RoPE、量化和舍入混在一起。\n\n| 观察 | 竞争解释 | 区分实验与反证修正 |\n|---|---|---|\n| 缓存类名为 MLA，但每步时间随 2n_h d_h 增长 | 仍在展开历史 K/V；或只是带宽瓶颈 | 记录实际读取字节和 workspace；若展开对象存在，改走吸收路径；若字节已降而时间不降，转查并行度、非矩阵指令和同步 |\n| 短序列正确，长序列或位置变化后错 | RoPE 作用在 latent 上、漏 k^R、位置缩放不一致、页边界错 | 固定内容分量只比位置分数；用解析旋转样例和不同 p-j 检查相对位置；注入错误旋转/漏 k^R 的负对照应被独立参考发现 |\n| TP 下每 rank 缓存没有按 TP 缩小 | 按 head 分片但复制 latent；或按 latent 通道分片后未做分数归约 | 直接量每 rank 的 s/k^R bytes 和 all-reduce 消息；若分数归约缺失，长历史会出现系统性错误而非普通舍入 |\n| 量化后质量下降但容量看似很小 | latent 组轴/尺度错、误差经多 head 放大、残余窗口太小 | 固定量化码与元数据，逐层比较内容 logits 和最终质量；用错误组 scale 的负对照验证解量化；不要直接把 KIVI 的 K/V 轴当成 latent 最优 |\n| prefill 比 decode 更慢或吸收路径反超 | L 大时展开投影被摊销；吸收的 d_c 点积和输出投影更贵 | 固定 S、d_c、d_h，扫 L 比较展开与吸收的完整调用；若 L 增大后吸收变慢，不能用 decode 结论外推 prefill |\n| split-K 合并后输出偏差 | 直接平均 partial、漏 rescale、空分区未处理 | 用完整 softmax 作独立参考；构造两个不同 m 的分区，负对照用未加权平均应被拒绝；再测空分区和单分区边界 |\n| 只换后端或图模式后结果漂移 | 准备 metadata 单位、布局转换、workspace 代次、量化 scale 未随状态 | 固定输入比较 plan/run 边界和 metadata 单位；检查页索引、末页长度、latent 与 k^R 的布局；图捕获后仍要验证缓冲代次 |\n\n这些是 CPU 代数、容量与事件模型的检查方向，不是 GPU 实测。真实设备还要固定 shape、布局、dtype、mask、计时边界和预热条件，观测实际 HBM 事务、寄存器/共享存储、spill、同步与时间线；本章没有目标 GPU 测量，也不声称已经证明 Agent 使用效果。\n\n## 来源与推导\n\n- [S-MLA：DeepSeek-V2：MLA
