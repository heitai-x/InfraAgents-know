要求逻辑持有者全部释放，且已经启动的异步访问全部结束。地址再次分配时必须使用新的分配身份或代次，不能只按地址去重。\n\nC(t)=Σ_{p∈Live(t)}s_p，M_peak=max_t C(t)。\n\nLive(t) 是按物理身份去重的集合。逻辑数组是视图 v=(p,offset,shape,strides,dtype,version)。同一 p 上的多个视图、CPU/GPU 各一个引用、共享前缀页的多个读者，不会仅因引用增多就复制容量。反过来，dtype、stride、连续布局转换或显式复制若产生新分配，源和目标同时存活时必须分别计账。\n\n请求的已提交状态为\n\ns=(x[0:n),k,KV,ell,logits,id_logits,rho,version)。\n\nx 是已确认 token，n 是已知长度，k 是全部必要层 KV 都已完成的连续边界，0≤k≤n。rho 是采样状态。ell=m 表示缓存 logits 来自精确前缀 x[0:m+1) 的最后一行，预测位置 m+1；本章只保留可以直接采样的末行缓存，因此有效缓存要求 k=n、ell=n−1。无缓存时 ell=−1。id_logits 必须匹配 token 前缀、模型、adapter、位置规则、mask 和数值表示；长度相同不能代替身份相同。\n\ntoken 追加到 x 不等于它的 KV 已完成。若原已知长度为 n，处理到 e=n 后采样并追加 x[n]，新的已知长度为 n+1，而 k 保持 n。下一步才计算这个新 token 的全层 KV。\n\n成本至少分为计算 F/P_eff、跨指定存储边界的字节 Q_j/B_eff,j、准备与建图、同步及交付、物理峰值 M_peak 和驻留积分 A_C=∫C(t)dt。P_eff 和 B_eff,j 必须匹配 dtype、shape、布局、并发及访问形态；A_C 的单位为 byte·s，不能直接加到毫秒延迟中。\n\n## 合法性与设备放置\n\n固定 Unified Memory 文档说明：Apple Silicon 的 CPU/GPU 可直接访问同一内存池，创建 MLX 数组时不必指定位置，设备在操作执行时选择。没有依赖的两个操作允许并行；若 CPU 先产生 c，GPU 随后消费 c，调度器会建立依赖，使后者在前者完成后开始。\n\n| 来源机制 | 可以保留的结论 | 不能据此推出 |\n|---|---|---|\n| CPU/GPU 消费同一数组 | 不必为该访问显式建立设备副本 | 没有访存、同步或固定开销 |\n| 无依赖操作允许并行 | 调度允许重叠 | 两个设备各有一份完整独占带宽 |\n| 数组表达式已构造 | 图节点已经存在 | 结果已经完成或对主机可见 |\n| 调度器跟踪数组依赖 | 受跟踪操作有执行顺序 | 外部原生指针、其他进程和未声明别名自动有序 |\n| 多个视图指向同一物理页 | 容量只计一次 | 不同消费者的读取流量也只计一次 |\n| 权重量化减少存储 | 容量和读取字节可能下降 | 完整服务时间按同一比例下降 |\n\n合法执行要求如下。\n\n1. 同一物理范围发生 RAW、WAR 或 WAW 冲突时必须建立依赖。设备不同不能证明访问独立；统一地址也不取消生产完成先于消费、最后读取先于覆盖的关系。\n2. 自动依赖只覆盖框架跟踪的操作。通过外部库、原生指针或其他进程访问时，需要依据互操作契约建立显式同步、复制或序列化，并验证可见性。\n3. 目标设备必须支持实际算子、dtype 和布局。不支持时选择回退、转换或拒绝；统一内存文档不是任意算子组合都已实现或优化的证明。\n4. 片长 q 必须为正整数。空输入由入口补合法 BOS 或拒绝，不能从不存在的末行采样；要求生成零个新 token 时直接结束。非法 k、缓存身份不兼容或全层 KV 不完整时不得进入正常推进。\n5. 容量准入使用 M_peak+C_reserve≤C_budget。M_peak 始终只表示物理对象占用峰值，C_reserve 是尚未计入对象集合的外部需求及不确定性余量；预算口径若已扣除了某项系统占用，就不能再预留同一项。\n6. 打印、转为主机表示、memoryview、保存、读取标量和标量数组控制流可能触发求值或等待。构造表达式、设备完成、主机可见、业务提交与用户收到输出分别记录。\n\nCPU 预处理与 GPU 推理同时运行时，必须合并它们对共同内存资源的需求。把两个孤立时间取最大值，需要独立能力与重叠条件支持；仅把工作放到不同设备上并不满足这些条件。\n\n## 惰性图、模型准备与提交边界\n\n固定 Lazy Evaluation 文档说明：操作先记录图，显式 eval 或特定主机访问才触发求值；重复 eval 同一结果可视为 no-op。过密 eval C(R)，不能证明另一个独立分支已经完成。数组句柄存在、图已经构造、设备访问结束、业务状态提交和客户端消费，是不同事件。打印数组、转为主机可见表示、memoryview、保存、读取标量及标量数组控制流，都可能触发隐式求值。\n\n请求的已提交状态为：\n\nS_r=(x[0:n),k,ell,rho,v,KV,logits)。\n\nx 是已确认 token，n 是已知长度；k 是所有必要层的 KV 都已完成的连续边界，0≤k≤n；rho 是采样状态；v 是业务版本。ell=m 表示 logits 来自精确前缀 x[0:m+1) 的最后一行，预测位置 m+1；本章只保存可直接采样的末行，因此有效缓存必须满足 k=n、ell=n−1。ell=−1 时没有缓存 logits。模型、位置规则、mask、数值表示和 adapter 身份也必须与这个快照一致。\n\n对位置 t，先构造 h_t^(0)=Emb(x_t,t)。第 l 层由当前 hidden 产生该位置的 K/V，并结合该层历史 [0:t) 和当前位置的 K/V 得到 h_t^(l+1)。全部层完成后，LM(h_t^(L)) 才是该前缀的 logits。一个位置不能因为某一层先结束，就被计入 k。采样 x[n] 之后，n 增一，但新 token 的 KV 尚未计算，k 保持旧 n。\n\n除业务状态外，请求拥有者保存 live、canceled、failed、commit_eligible、phase、active_execution 以及尚未结束的物理使用责任集合 P。每次执行有不复用的执行身份 I=(请求实例,g)。完成、错误和最后使用事件携带 I 与使用者 uid；版本 v 负责业务快照检查，不能替代执行身份和物理结束证据。\n\n本章采用保守边界：每请求至多一个尚未结束的执行；失败撤销该请求实例的后续提交资格，不支持原地重试。排空后可以回收，但不能自动重新变为 live。若系统需要恢复，应在旧责任结束后，用新请求实例及新的执行身份显式准入，另行定义恢复和输出去重协议。\n\n关键不变量如下：\n\n- 图构造不证明完成；提交证书必须覆盖本步全部层 KV、必要的末行结果及其他独立状态根。\n- 准备和采样只产生私有候选；已提交 token、KV 边界、RNG 和版本只由同一状态拥有者安装。\n- 提交资格要求 live、commit_eligible、未取消、未失败、身份及版本匹配，且处于允许提交的阶段；FAILED_DRAINING、QUARANTINED 和终止状态均不能推进。\n- 失败排空只解除物理责任，不恢复业务资格；迟到成功结果同样不能提交。\n- 已提交读写的最后使用结束前，不覆盖或回收其存储。删除 Python 引用不证明这一条件成立。\n- 编译区的动态状态必须是显式输入和输出；未声明输入的数组捕获按 trace 常量处理。\n\n## 服务步与 KV 存储契约\n\n普通推进取片长 q≥1、b=k、e=min(n,k+q)，消费已知输入 x[b:e)。若 e<n，只推进 prefill，不采样；若 e=n，末行才预测下一个 token。空输入由模型入口补 BOS 或拒绝；零新增输出直接结束，不建立图；非法 k、越界 ell 或不兼容缓存必须拒绝或进入明确修复入口。\n\n本章选择的 local 不是整段 KV 的数据副本，而是“只读前缀引用＋私有增量”。其逻辑索引为：\n\nlocal[l,t] = base[l,t]，当 0≤t<b；\nlocal[l,t] = delta[l,t]，当 b≤t<e。\n\nbase 是已提交快照的不可变引用；delta 在准备前预留，只属于本次执行。WRITE(local,l,t) 只能写 [b,e)，任何前缀写入都必须拒绝。逐 token 推进时，位置 t 可以读取 base 的旧前缀，以及本执行已经产生的 delta[b:t)。提交前 delta 对请求不可见；成功提交通过新的范围描述符或块表安装这些对象，将其所有权转给请求，不搬运旧前缀，也不复制 delta 的有效载荷。失败或取消时保留 base；delta 等最后使用结束后丢弃。\n\n这是服务候选的存储契约，不是对某个 MLX attention 实现已经支持分段 KV 的断言。后端必须能消费这一逻辑视图，或使用满足同样隔离条件的预留区间；若实际数组拼接、更新或 kernel 接口会物化连续副本，就必须采用后面的复制成本，不能沿用无前缀复制的预算。共享物理页的尾部若不能保证写入隔离，应使用私有增量或必要的写时复制，并单列其代价。\n\n当 k=n 且有兼容末行 logits，可以只采样。当 k=n 但没有末行 logits，不能因 n−k=0 而停滞：在私有区重算最后一个已知 token，读取 [0:n−1) 的只读前缀，得到末行结果后丢弃重算 KV；既有 KV 对象及边界不变。无法建立安全私有区时返回 REPAIR_UNAVAILABLE。\n\n```pseudocode\n算法 PREPARE\n输入：不可变快照 s，片长 q≥1\n输出：prepared=(base,delta,b,e,k_after,logits,required_roots)\n\n若 s.n=0：返回 REJECT_NO_INPUT\n若 s.k 不在 [0,s.n] l=0 到 L-1：\n      K_t,V_t=PROJECT_KV(l,h,t)\n      WRITE_PRIVATE(delta,l,t,K_t,V_t)\n      h=BLOCK_REMAINDER(l,h,local[l,0:t+1],t)\n  logits=空\n  若 e=s.n：logits=LM(h)\n  required_roots=delta 的所有必要层写入，以及非空 logits\n  返回 (base,delta,b,e,k_after=e,logits,required_roots)\n\n若 s.ell=s.n-1 且 s.logits 身份兼容：\n  返回 (s.KV,空,s.n,s.n,s.n,s.logits,缓存完成证书)\n\n若不能私有重算最后一行：返回 REPAIR_UNAVAILABLE\n建立只读前缀 [0,s.n-1) 与私有单位置增量\n按上面的全层循环重算 t=s.n-1，得到末行 logits\n返回 (s.KV,不安装的重算增量,s.n,s.n,s.n,logits,重算全部必要根)\n```\n\n伪代码逐 token、逐层展开依赖，便于恢复机制；实际 prefill 可以将一个区间按层并行计算，只要因果 mask、位置和全层完成证书等价。没有被根引用的独立位置、RNG 或元数据更新必须另列为根；不能仅凭 logits 求值成功就宣布这些写入完成。\n\n## 准备、采样和提交的同一条轨迹\n\n状态拥有者串行处理准入、取消、失败、提交和完成事件。设备工作可以在外部执行，但只能写本执行私有区。入口检查与 COMMIT 检查都需要存在：入口阻止失败请求产生新工作，COMMIT 阻止已经准备好的旧候选在资格撤销后安装。\n\n```pseudocode\n算法 SERVE_AND_COMMIT\n输入：请求 r，片长 q\n输出：PREFILLED、COMMITTED 或拒绝/终止原因\n\n由 r.state_owner 串行处理：\n  若 r.canceled：返回 CANCELED\n  若 not r.live 或 not r.commit_eligible 或 r.failed：返回 BLOCKED\n  若 r.phase 不在 {READY,COMMITTED}：返回 BLOCKED\n  若 r.active_execution 非空 或 r.P 非空：返回 BLOCKED\n  校验输入、q、KV 边界、缓存身份及增量容量\n  s=冻结已提交状态；I=分配新的执行身份\n  prepared=PREPARE(s,q)\n  r.active_execution=I；保存 s、prepared 及所有引用\n  在启动访问前登记 (I,eval_use) 到 r.P\n  r.phase=EVALUATING\n\n执行 EVAL(prepared.required_roots)\n若返回错误或缺少必要结果证书：\n  交状态拥有者执行 ON_FAILURE(I,证据)\n  返回 FAILED\n\n由状态拥有者确认完成证书及身份：\n  证书必须覆盖本执行全部相关访问结束\n  幂等结束 (I,eval_use) 的物理责任\n  若资格已撤销：丢弃候选；仅做完成清理；返回 BLOCKED\n  r.phase=READY_TO_COMMIT\n\n若 prepared 有 logits：\n  token,rho_next=SAMPLE(prepared.logits,s.rho)\n否则 token=空；rho_next=s.rho\n将候选交给同一状态拥有者执行 COMMIT\n\nCOMMIT(r,I,s,prepared,token,rho_next)：\n  要求 r.active_execution=I 且 r.version=s.version\n  要求 r.live 且 r.commit_eligible 且未取消且未失败\n  要求 r.phase=READY_TO_COMMIT 且 r.P 为空\n  任一要求不满足：不改变已提交状态；返回拒绝\n  验证区间、全层证书和末行前缀身份\n  原子执行以下业务事务：\n    以新描述符安装本次有效 delta，旧前缀对象保持只读共享\n    r.k=prepared.k_after\n    若 token 非空：\n      将 token 追加到旧位置 n；r.n 加一\n      r.rho=rho_next；清除末行缓存\n      将带请求及输出序号的交付记录追加到响应对象\n    否则：保持 token 序列与 rho 不变\n    r.version 加一；r.phase=COMMITTED\n  解除本执行记录及已结束的临时引用\n  按响应记录执行输出交付\n  返回 token 非空时的 COMMITTED，否则 PREFILLED\n```\n\n业务事务是线性化点。SAMPLE 只消费冻结的 rho，返回 token 和 rho_next；两者同时提交，失败候选不推进 RNG。若采样位于编译区，随机状态也必须是显式输入和输出。\n\n取消由同一拥有者撤销 live 和 commit_eligible。取消先于线性化点时，COMMIT 必须拒绝，包括采样已经完成的情况；提交先于取消时，已提交记录不能回滚。响应记录的安装和网络交付分别计时：发送失败或客户端未收到，不改变内部已经提交的事实。实际系统需要另行定义重送、输出序号和去重规则；本章 CPU 模型只交付一次已提交记录，不证明网络行为。\n\n## 失败、排空和迟到完成\n\n失败不是一个可再次调用正常服务步的中间成功状态。本章在同一拥有者下同时设置 failed=true、live=false、commit_eligible=false。即使错误返回已经带有完整结束证据，进入 COMPLETED 也只表示物理责任结束，不表示恢复服务资格。\n\n```pseudocode\n算法 失败与最后使用\n\nON_FAILURE(I,evidence)：\n  只处理属于本请求已登记执行的事件\n  r.failed=true；r.live=false；r.commit_eligible=false\n  若 evidence 证明某已登记使用者的全部访问结束：\n    仅移除该使用者自己的责任\n  若 r.P 非空：r.phase=FAILED_DRAINING\n  否则：r.phase=COMPLETED；解除本执行的保留引用\n  不安装 KV、token、RNG、版本或响应记录\n\nON_USE_DONE(I,uid,certificate)：\n  若执行身份不匹配，或 (I,uid) 已结束/不存在：忽略\n  若证书不能证明该使用者最后访问结束：\n    保留责任及存储；r.phase=QUARANTINED；返回\n  幂等移除 (I,uid)\n  若资格已撤销且 r.P 为空：\n    r.phase=COMPLETED；解除本执行的保留引用\n  不恢复 live 或 commit_eligible，不执行候选提交\n\n超时仍无结束证明：\n  保持 QUARANTINED 和责任账，不宣称已经回收\n```\n\n完整轨迹为：旧状态冻结 → 私有增量建成 → 求值失败但 eval_use 未结束 → 请求终止并保留私有区 → 再次 SERVE 被入口拒绝 → 已准备候选的迟到 COMMIT 被资格检查拒绝 → 不完整结束通知保持隔离 → 真实 USE_DONE 只解除物理责任 → 排空后再次 SERVE 仍被终止资格拒绝。全过程旧 KV、token、版本、RNG 和输出记录都保持不变。\n\n旧事件不能用来清除新执行的责任，重复事件也不能多扣一次。仅递增业务版本不足以保护还在写入的物理地址；存储仍要等最后使用结束。失败后无法证明访问停止时，应报告执行身份、对象和阻塞证据，而不是把等待超时改成完成。\n\n## 编译、捕获与形状选择\n\n固定 Compilation 文档说明：首次调用编译函数时用占位输入 trace、优化并生成代码，随后复用缓存。输入 shape 或维数、dtype、输入数量变化可能触发重编译；频繁创建并销毁新函数身份会破坏复用。缓存选择至少覆盖函数及模型身份、输入 dtype、数量、形状策略和影响静态分支的配置。缓存未命中时，只有编译准备和驻留预算允许才建立新版本，否则选择普通求值。\n\n编译区域按纯函数使用。trace 中读取占位数组的真实值或打印会失败；向未声明的外部列表追加数组，可能把没有数据的占位对象留在列表中。网络发送、请求注册等副作用应由外部状态拥有者处理。动态 KV、位置和 RNG 应作为参数返回更新结果，或遵守该版本显式 inputs/outputs 捕获契约。\n\n令编译函数为 F(I;C)→O。I 是每次调用的输入槽，C 是 trace 时保存的常量。未声明为输入的外部数组被当作 C：文档示例中 state[0] 初值为 1，外部替换为 5 后，编译的 x+state[0] 仍使用原常量；显式传入 state 或声明 inputs，才使新值进入调用。\n\n这个机制需要区分 trace 和执行，不能用每次调用时的一个分支直接假定答案。最小解释模型如下：\n\n```pseudocode\n算法 TRACE 与 EXECUTE\n\nTRACE(函数体，输入规格，外部对象)：\n  为公共 x 建立 INPUT_SLOT(0)\n  若 state 是显式输入：为 state[0] 建立 INPUT_SLOT(1)\n  否则：把 trace 当时 state[0] 的值保存为 CONST\n  用占位符执行一次函数体，生成有序操作表示\n  保存操作、常量和输出节点；不保存重新读取外部容器的指令\n\nEXECUTE(保存的表示，本次输入)：\n  为本次调用绑定各输入槽\n  按依赖顺序执行 INPUT、CONST 和算术节点\n  返回输出节点；不重新执行 Python 函数体或重新 trace\n```\n\n配套 CPU 检查用 2x+s 作为非对称探针，既能区分常量与输入槽，也能暴露 x 和 s 错绑。检查者在 trace 外保存常量快照，随后分别改变 x、显式 s 和外部容器；预期由该快照及本次显式输入计算。故意把显式 s 固化、让隐式常量重新读外部对象、交换输入槽或每次重 trace 的变体，都接受同一判据。\n\nshapeless 允许 shape 变化不触发重编译，但不把依赖首次 shape 的 Python 逻辑自动改成动态逻辑。来源例子的首次输入为 2×3×4，reshape 的首轴固化为 6；改成 5×5×3 后，75 个元素不能 reshape 为 (6,−1)。使用保持轴语义的 flatten(0,1)，结果应为 (25,3)，不是任意全展平都算等价。\n\n自回归 KV 长度增长时，可以比较 shapeless、长度分桶、只编译稳定子图和普通求值。每个候选都要核对算子支持、输出与状态正确性以及真实编译次数。文档的一般规则不证明具体 attention 已支持任意动态长度。同一提交的 Lazy Evaluation 文档仍保留早期“不编译并重跑图”说法；该版本编译能力据专门 Compilation 文档判断，惰性建图与编译是两个事件。\n\n## stream、统一内存与驻留\n\nUsing Streams 文档说明操作可指定 stream 或 device；未指定时使用默认设备的默认 stream。Unified Memory 文档说明 CPU/GPU 可访问同一内存池，并为框架跟踪的数组依赖建立顺序。例如 CPU 生产 c，GPU 随后读取 c，后者等待前者完成。该保证不自动覆盖框架外的原生指针写入、其他进程或未声明的别名访问。\n\n统一内存减少显式设备间复制，不消除读取、同步和竞争。同一物理数组同时被 CPU/GPU 引用只计一份容量；量化前后权重、重新打包布局、私有增量、工作区、图缓冲、编译产物和输入队列若为不同分配，就分别计账。权重加载时源表示与目标表示共存的峰值见权重加载章节，不能只按最终量化权重预算启动。\n\nCPU 预处理和 GPU 同时工作可能争用共同带宽，孤立测量后取两者最大值可能低估并发时间。来源在 M1 Max 报告过 matmul 与小 elementwise 分工的示例；它不证明任意服务具有相同比例的收益。CUDA Graph、迁移页和 allocator 的特定语义也不能直接当作 MLX 保证。\n\n物理回收要求逻辑持有和所有执行、输出读者都结束。旧图、编译常量、缓存和失败排空中的使用者都可能继续持有对象。缓存驱逐或删除 Python 容器只是解除某些引用；尚未实际释放的对象仍占容量。\n\n## 同一候选下的成本\n\n令准备描述符和增量分配成本为 T_prepare，建图为 T_build，求值为 T_eval，采样为 T_sample，拥有者处理与提交为 T_owner，交付为 T_publish，编译未命中准备为 C_compile。按这些阶段串行的单步近似为：\n\nT_step≈T_prepare+T_build+T_eval+T_sample+T_owner+T_publish+1{miss}C_compile。\n\n实际允许跨请求重叠时，应沿依赖路径计算墙钟时间，并累计共享资源需求，不能把全部阶段时间机械相加。T_eval 包括固定提交、计算和访存；Q/B_eff 是相应资源下界，不能再与已经包含这段访问的测量时间重复相加。CPU/GPU 的隐式标量等待、跨 stream 依赖和结果可见性都应放入真实路径。\n\n对全层 K/V，层数 L、KV head 数 H_kv、head 维 d_h、每元素字节 b_a，未压缩同精度的每 token 有效载荷为：\n\nb_kv=2L H_kv d_h b_a。\n\n设定 L=32、H_kv=8、d_h=128、b_a=2，则 b_kv=128 KiB/token。四个请求各持有 4096 token KV，共 2 GiB。量化权重 14 GiB、工作区 1 GiB、图及中间量 0.5 GiB，列项基线是 17.5 GiB，已经超过假想 16 GiB 设备；这些是容量设定，不是测量。\n\n本章共享前缀候选的瞬时容量应写成：\n\nM_peak=max_t |物理对象并集(t)|≈W+KV_committed+delta_live+workspace+graph+compile+queues+retained，\n\n各项只有确属不同对象才相加；工作区预算若已经包含某增量或中间量，就不能再计一次。一次正常推进的私有 KV 有效载荷是 (e−b)b_kv，重算末行需要一个 token 的私有区但不安装。四个请求在各自 4096 token 的旧 KV 之外各新增一个私有位置，额外载荷为 512 KiB；若上述列项未包含它，峰值至少为 17.50048828125 GiB，另加描述符、舍入和在途保留。提交通过转移这些对象的持有关系完成，不再制造另一份 delta。\n\n只读前缀引用不产生 b·b_kv 的 KV 数据副本，但需要描述符、地址映射和引用维护。按页描述时准备成本随触及的描述符数增长；预分配或分层表可以改变这项成本。CPU 检查为了便于审查复制字典的元数据引用，成本为 O(Lk)，不复制 KVCell 有效载荷，也不代表生产实现具有常数时间准备。\n\n在假设每个查询逻辑上读取一次相应全层 KV、暂不计 head 重读及 cache 的口径下，处理 [b,e) 的逻辑 KV 读取量约为：\n\nQ_KV,read≈b_kv Σ_{t=b}^{e−1}(t+1)，\n\n新增有效载荷写入为 Q_KV,write≈(e−b)b_kv。q=1 的批量 decode 若每批读取一次权重，读取简式为 Q_read≈W_q+Σ_r n_r b_kv；包含新增 KV 写入后还要加 Σ_r b_kv。完整账还应包括激活、中间量、采样、元数据和主机访问。实际设备事务受 query head 重用、融合、cache、布局及分块影响，不能把这个逻辑口径当作 DRAM 事务测量。分块 prefill 的权重利用和计算密度也不能直接沿用单 token decode 估算。\n\n若后端必须物理复制旧前缀，准备阶段额外 KV 读写约为 2b·b_kv，额外副本驻留约为 b·b_kv；复制时间下界受实际读写带宽限制，还需分配和提交成本。旧前缀在旧读者结束前不能释放。若 append 也复制已有 delta，或页尾写时复制按整页进行，应按实际复制范围继续增加。此时无复制的 Q_read 简式只覆盖模型读取部分，不能冒充完整服务流量。\n\n编译是否划算取决于同一调用序列。设普通步骤 2.0 ms、编译稳态 1.5 ms、首次编译 200 ms，均为设定值：N=400 时总成本相等，N>400 才开始节省；N=1000 时分别为 2000 ms 和 1700 ms。令额外编译率为 eta，每次调用的期望额外准备是 eta C_compile，必要条件为：\n\nT_plain−T_comp>eta C_compile。\n\n该例 eta 必须小于 0.0025；eta=0.01 的额外准备已达 2 ms/调用。编译代码和捕获常量还会挤占 KV，故该式只是必要条件。片长 q 则在固定提交次数、图规模、首 token 延迟和私有区驻留之间取舍。\n\n## 条件改变后的选择\n\n| 条件变化 | 必须保留 | 反例、区分实验与检查范围\n\n只求值 loss 不能证明优化器更新已经完成。来源说明在完整求值前读取 loss 会只计算前向；它没有说明随后读取更新后的参数必然得到旧值。更新后参数句柄可能连接尚未求值的更新图，读取它会执行依赖。旧值应对应保留的旧参数对象或错误发布的旧快照。服务中的同类错误是以 logits 完成替代所有状态根完成。\n\n把新 token 的 KV 边界提前推进到新 是各项必要时间的下界，即使资源不能重叠仍成立；要把它当作可达到的完成时间，才需要足够并行度、独立资源和充分重叠。完全串行时，这两个区间要相加。\n\n实际可持续速率是带条件的测量参数，并非数学保证的硬件能力上限。用它构成的是相应条件下的理想资源估计；访问方式、并发、时钟或工作集变化后，不能继续把旧值称作无条件硬下界。直接用被诊断 kernel 的 F/T 同时定义 P，再用 F/P 解释该 kernel，只有恒等式，没有辨识出计算瓶颈。\n\n有效字节与事务字节有两种一致用法：D_use/B_use，或 D_tx/B_tx。若有效负载 128 B 需要传送 160 B，匹配模式的有效带宽为 80 B/时间单位、事务带宽为 100 B/时间单位，则两式都给出 1.6 时间单位。把 160 B 再除以已经包含放大的 80，会重复惩罚同一次浪费。\n\n容量峰值与驻留量也不同：C_peak＝max_t C(t)，驻留积分为 A_C＝∫C(t)dt，单位 byte·s。前者约束准入，后者描述容量被占用多久；不能把驻留积分直接加进毫秒延迟。\n\n本章账本输入为对象生命期、消费者访问、算术事件、资源参数和阶段依赖图；输出为容量峰值、驻留积分、分边界需求、条件化时间下界及未解释成本。它不直接输出目标设备已经达到的性能。\n\n## 记账合法性：去重、回收和资源合并\n\n容量对象的区间采用 [birth, retire)。birth 是物理预留实际占用容量的时刻，而非首次读；retire 是逻辑持有者全部释放且已提交的物理访问全部完成后的可回收时刻。同一时间点先处理结束、再处理开始，并在该时间点全部事件处理完后统计峰值。零长度区间为空集，应跳过，不能先执行一次没有出生的回收。\n\n一个对象可有重叠的持有记录：共享所有者、缓存保留和在途访问均可延长生命期。相同物理键按这些区间的并集计一次；记录必须覆盖真实预留的整个时间，不能只用 kernel 的读取窗口代替分配生命期。同一键的大小不一致应拒绝；地址用于下一次分配时必须改变代次。\n\n预留池和池内对象也有包含关系。设备已经为 KV 池占用 4 GiB，其中活跃页 3 GiB、空闲保留页 1 GiB，物理占用为 4 GiB，不能再加上 3 GiB。若从活跃对象出发记账，只补未被这些对象覆盖的保留容量。页尾与对齐若已包含在整页大小中，也不能再额外加一次。\n\n| 情形 | 合法记账 | 需要防止的误读 |\n|---|---|---|\n| 多个请求共享物理页 | 容量按唯一物理键计一次 | 读取流量也自动只计一次 |\n| 两个消费者共用 HBM 或同一链路 | 合并该资源需求，再用共同能力估值 | 各自领取完整独占带宽 |\n| H2D 与 HBM 读取属于不同资源 | 分别记账，并检查复制引擎及共享上游 | 用 HBM 带宽除 H2D 字节 |\n| 两阶段有依赖 | 保留前驱完成条件 | 用 max 代替先后关系 |\n| 不同方向有独立能力 | 使用双工曲线或分别建轴 | 无条件把读写或双向带宽相加 |\n| 工作集命中 L2 | 减少相应 D_HBM，保留 D_L2 | 将命中速率当成全局 HBM 带宽 |\n| F＝0 或 D＝0 | 相应需求时间为零 | 对纯搬运使用 F/R_roof 的 0/0 |\n\n本章检查函数采用严格输入契约：F、D 非负，P、B 始终为正；无效参数抛出 ValueError，检查断言失败抛出 AssertionError。空工作 F＝D＝0 的资源时间为零，算术强度未定义；D＝0、F＞0 是纯计算边界，F＝0、D＞0 是纯搬运边界。不能把非法零能力悄悄替换成默认值。\n\n## 从事件建立容量账与阶段下界\n\n```pseudocode\n算法 BuildResourceLedger\n输入：物理持有记录 H；读取/写入与计算事件 E；参数包；阶段 DAG G\n输出：C_peak，驻留积分 A_C，资源需求向量，各阶段下界，整体必要下界与未知项\n\n验证所有大小和需求非负，能力为正，物理键大小一致，G 无环\n为每个阶段建立计算类别和存储/通信资源轴\n对 H 中每条记录 (key, birth, retire, size)：\n    若 birth > retire：拒绝\n    若 birth = retire：跳过\n    在 birth 记录取得持有，在 retire 记录结束持有\n按时间分组排序，初始化 total=0，peak=0，area=0，active_count 空\n对每个时间点 t：\n    area += total × (t - 上个时间点)\n    先结束本时间点全部旧持有：计数减一，降到零时从 total 扣 size\n    再取得本时间点全部新持有：从零变一时向 total 加 size\n    peak=max(peak,total)\n要求最终全部持有结束；返回 peak 和 area\n\n对每个执行事件：\n    将工作记到其阶段和计算类别\n    将读写记到实际跨越的边界、方向和共享资源\n    区分消费者有效字节、事务放大、缓存命中和重复读取\n    未证实的缓存或多播收益保留为待验证假设\n对每个阶段 s：\n    τ_s=max(该阶段各资源需求 / 对应能力)\n    若已知阶段内部必须串行，将它拆成有边的更细阶段\n按拓扑序求 finish_lb(s)=τ_s+max(前驱 finish_lb)，无前驱取零\nL_path=max_s finish_lb(s)\n对每个共同资源 j：L_work,j=全图在该资源的总需求 / 能力_j\nT_lb=max(L_path, max_j L_work,j)\n输出局部项、整体下界和仍未建模的准备、同步、争用、排队等项\n```\n\n容量事件扫描的正确性来自计数的零到一、以及一到零转换：任何重叠持有都不会重复增加物理容量，最后持有结束前也不会扣掉它。按时间分组可以避免同一时刻多个开始事件的处理顺序制造虚假峰值。事件排序成本为 O(|H| log |H|)，扫描为 O(|H|)，活跃计数空间随同时存活物理键数增长；若保存完整轨迹，还需保存全部事件。阶段需求累加与 DAG 遍历分别随事件数和顶点/边数增长。\n\n整体公式只是必要下界。一般 DAG 的资源争用与依赖交错，不能靠递归套 max、sum 就求出真实最短调度。设两块数据分别经过 X、Y 两个独占阶段，各阶段都需 2 个时间单位。每条路径长 4，X、Y 的总工作也各为 4，因此上述下界为 4；但第一块需要 X[0,2)、Y[2,4)，第二块最早 X[2,4)、Y[4,6)，全部完成需 6。下界没有错，把 4 报成完成时间才错。\n\n对 n 个等长块、两个独立串行阶段、充足缓冲、无额外争用，令每块阶段时间为 a、b，则完整流水时间为\n\nT_pipe＝a＋b＋(n−1)max(a,b)。\n\n第一块与末块的首尾成本没有因流水消失。没有足够缓冲或两个阶段共用资源时，要重新构造时间线。比较设备结果时，可以用合法调度给出可行时间，再与必要下界夹住范围。\n\n## 权重、KV 与共享尾页的一次组合轨迹\n\n设同构普通全注意力模型有 L 层、Hq 个 query heads、Hkv 个 KV heads、每 head 通道 d、每元素 s 字节。每 token 全层普通 KV 主项为\n\nc_KV＝2LHkvds。\n\n无共享的有效状态为 c_KVΣ_r n_r；分页后的物理容量则按实际唯一页数乘页字节。令页长为 Bp，一页全层主项为 Bp·c_KV。量化参数、目录、并行副本、对齐及暂存另计。异构层、窗口和 MLA 必须逐层按实际状态族重算。\n\n在每个请求每轮读取其可见历史、同组 query heads 理想复用 KV 的假设下：\n\nD_KV,use≈c_KVΣ_r n_r。\n\n这里 n_r 是本次 attention 实际可见的有效位置数；若把当前行包含其中，就不能再当作历史读取重复加一次。新 KV 的写入另外记账。共享前缀不改变各请求的合法可见集合；不同请求没有实际合并读取时，流量仍按读者累计。GQA 若缺少片上复用，实际读取还可能增加，不能仅从 Hkv 推出 HBM 节省。\n\n忽略 softmax 与当前行等小项，decode 的 QK/PV 工作约为 4LHq dΣn_r。因此理想 attention 强度为 2Hq/(Hkv s)。历史增长同时增加计算与读取，不会单独提高这部分强度。Hq/Hkv 的头映射来自模型，已有 MHA checkpoint 不能仅靠修改头数就当作等价 GQA。\n\n令 W 为本轮实际需要读取的权重主项，batch 为 b；每输出 token 的读取约为 W/b＋c_KV n_avg。交点为\n\nb*＝W/(c_KV n_avg)。\n\n设 W＝8 GiB，c_KV＝128 KiB/token，n_avg＝1024，则每请求 KV 为 128 MiB，b*＝64。b＝16 时权重加 KV 的读取主项为 10 GiB；假定同一 HBM 资源提供 1 TiB/s，对这部分读取得到 9.765625 ms。每轮产生 16 个输出 token，摊薄值为 0.6103515625 ms/token，但每个请求仍受整轮完成约束。这还未加入新 KV 写入、其他激活、计算、采样和排队，不能叫端到端延迟预测。\n\n同一时刻若权重 8 GiB、KV 2 GiB、激活 0.5 GiB、workspace 与图池 1.5 GiB、通信缓冲 0.25 GiB，以及未被前述对象覆盖的保留容量 0.5 GiB，则设定峰值为 12.75 GiB。只有这些生命期确实重叠时才是该轨迹峰值；分别取各类峰值相加通常只是保守上界。\n\n再看共享尾页追加。取 Bp＝16、c_KV＝128 KiB，一页为 2 MiB。请求 A、B 共享含 15 个有效 token 的页 P：\n\n| 事件 | 状态与可见性 | 容量和流量 |\n|---|---|---|\n| 分支前 | A、B 都读取已发布 P | 唯一容量 2 MiB；两者分别读取时有效读量合计 3.75 MiB |\n| A 准备追加 | 先预留私有目标 Q，P 保持可读 | P、Q 同时存活，容量 4 MiB |\n| 复制与写入 | 将旧 15 行复制到 Q，再写 A 的新行 | 若只复制有效行，复制读和写各 1.875 MiB，另写新行 128 KiB |\n| 发布 | 等待 Q 的内容、有效长度和目录一致后切换 A 的视图 | A 用 Q，B 及旧在途读者仍可用 P |\n| 失败或取消 | 发布前失败撤销新预留，旧视图保留；已提交复制需完成后才回收 Q | 不能把发出取消当作物理容量立即释放 |\n| 回收 | P 不再有逻辑保留且所有旧访问结束后回收 | 没有额外缓存保留时，最终仅 Q 占 2 MiB |\n\n复制整页也是合法选择，但复制读和写各为 2 MiB。不能同时采用有效行复制的流量与整页复制的实现。这个抽象页汇总全层字节；若实际每层独立分配，必须确保全部必要增量成功后才发布一致视图。\n\n## 从逻辑 tile 到地址、线程、共享存储和写回\n\n下面选择一个便于复算的标量 FP32 GEMM 映射，说明减少全局重读如何支付片上容量与同步。它不是推荐的最佳 tile，也不声称使用矩阵专用指令。\n\n令 Y＝AW，A 为 M×K、W 为 K×N，均行主序。一个 CTA 使用 8 个 warp、每 warp 32 个 lane，计算 8×32 输出。warp u∈[0,8)、lane λ∈[0,32) 对应输出 (m0＋u,n0＋λ)，持有一个标量 accumulator。全局元素地址分别为 base_A＋4(mK＋k)、base_W＋4(kN＋n)、base_Y＋4(mN＋n)。\n\n沿 K 每次取 32 行。共享 A_s 为 8×32，W_s 为 32×32，字号分别为 32u＋t、32t＋λ。输入单缓冲占 4(8×32＋32×32)＝5120 B；地址、其他临时量、分配粒度及编译器产生的寄存器另计。\n\n```pseudocode\n算法 ScalarTiledGEMM\n输入：行主序 A[M,K]、W[K,N]；非负整数 M,N,K\n输出：Y[M,N]\n若 M=0 或 N=0：结束，无输出元素\n对每个输出 CTA 起点 (m0,n0)，步长分别为 8、32：\n    所有 (warp u,lane λ) 初始化 acc[u,λ]=0\n    对 k0=0,32,… 且 k0<K：\n        每个线程载入 A[m0+u,k0+λ] 到 A_s[32u+λ]\n            越界时写入零，不发出越界全局读取\n        每个线程对 v=0,1,2,3：\n            t=u+8v\n            载入 W[k0+t,n0+λ] 到 W_s[32t+λ]\n            越界时写入零\n        全 CTA 完成共享写入并建立可见性\n        对 t=0,…,31：\n            acc[u,λ] += A_s[32u+t] × W_s[32t+λ]\n        全 CTA 最后读者完成，之后才能覆盖这两块共享存储\n    若 m0+u<M 且 n0+λ<N：写回 Y[m0+u,n0+λ]=acc[u,λ]\n```\n\n全部线程都参与两个 CTA 完成边界；尾部线程只屏蔽全局访问与最终写回，不能提前退出而使其他线程永久等待。K＝0 时没有输入循环，输出为零。每个合法输出恰有一个写者，每个有效 k 恰贡献一次乘积；共享缓冲必须先写完、后读完、再覆盖。第二个完成边界保护下一次加载，不能只保留第一个。\n\n在固定 CUDA 12.8.0 文档的 CC≥6.0 访问模型中，lane λ 读取相邻 32-bit 字：起点按 32 B 对齐时，128 B 有效负载覆盖 4 个段；偏移 4 B 后覆盖 5 个段。以上 A、W、Y 的行首只有在基址、leading dimension 与 tile 起点共同满足对齐时才符合四段情况。K 或 N 非对齐、尾部 mask 都会改变段集合。段数不等于实际 HBM 事务；L1/L2 与邻接 warp 复用还会改变后者。\n\n对文档中的 32-bank、连续 32-bit 字逐 bank 分配模型，A_s 的逐行加载和 W_s 的逐行加载按 lane 落到不同 bank。计算时，同一 warp 读取 A_s[32u＋t] 是同地址广播，读取 W_s[32t＋λ] 分布在 32 个 bank。一般字号 8λ＋t 只覆盖 4 个 bank、每 bank 有 8 个不同地址，属于该标量请求模型的 8 路冲突；不能把广播误判为 32 路冲突，也不能将该模型直接推广到向量或矩阵加载的内部请求。\n\n忽略 cache、按被屏蔽后的有效全局访问累计，这条具体映射的字节为\n\nD_use＝4[MK ceil(N/32)＋KN ceil(M/8)＋MN]，\n\nM 或 N 为零时整体为零。A 会按输出列 tile 重读，W 会按输出行 tile 重读；不能一面采用此 CTA 划分，一面只计全矩阵各读一次。K 尾块的填零不发出输入读取，却仍可能执行乘加。若未消除填充计算，完整 tile 的执行主项为 2·8·32·32·ceil(M/8)ceil(N/32)ceil(K/32)，而有效主项仍为 2MKN。\n\n增大输出 tile 可减少输入重读，却扩大 accumulator、共享缓冲和临时量；更深流水还增加同时存活输入。寄存器 spill 可能增加 local-memory 访问，其中经过 cache 后的主存事务需单独核对。共享存储与寄存器上限、分配粒度和实际活跃 CTA 决定驻留，不能用总共享字节直接证明性能。这里的 CPU 标量模拟验证地址、尾部和算术覆盖，不证明真实 barrier、设备可见性或编译器资源使用。\n\n## 完整服务、准备与成本边界\n\n计算、访存、通信、准备、同步和驻留都要对应同一候选及同一时间范围。准备包含分词、页表、布局转换、权重打包、编译与图捕获；同步包含生产者发布、消费者完成、归约和调度等待。单设备常驻 GEMM 本身没有跨设备通信；完整服务仍可能有 H2D、输出回传、TP collective、P/D 状态交换和网络发送。\n\n设每轮 H2D 1 GiB、可用链路 16 GiB/s，另有设备内部读取 10 GiB、带宽 1 TiB/s，则两项为 62.5 ms、9.765625 ms。完全串行为 72.265625 ms；独立工作充分重叠时，较松的理想下界为 62.5 ms。同一数据必须先传完再计算时，不能仅凭有异步接口就声称后一结果已达到。共享 PCIe 上游或主机内存控制器还需合并需求。\n\nServerlessLLM 固定论文 §6.2 使用 q＋n/b 必须来自原关键路径上能被该改动缩短的时间，不能从重叠 kernel 的累计时长直接计算。若 f＝0.3、s＝2，其他不变，则总加速为 20/17≈1.176；新增转换或同步还会降低它。多个优化若都省同一次读取，不能重复扣流量或直接相乘加速比。\n\n实例计费包括空闲、加载、服务和排空。能量为同一测量边界内功率的时间积分；设备、整机与机房口径不能混用。单位合格请求成本为总计费成本除以满足质量和 Σ(aᵢ−rᵢ)、外部碎片、分配器保留而未使用的容量、映射与权限管理、分配/回收路径的主机时间、以及地址稳定要求对压缩和搬移的限制。\n\n设计轴：分配粒度（整对象 / 固定块 / 映射页）；地址连续性（物理连续 / 块表 / 虚拟连续）；池划分（按生命期 / 按对象类型 / 单一池）；回收时机（同步 / 按 stream 顺序 / 事件驱动延迟）；所有权记录（引用计数 / 代次 / 二者）。连续预分配、应用块表、虚拟地址加按需 backing 是粒度与连续性两轴上的三个点；stream-ordered 分配器是回收时机轴上\"按 stream 顺序\"的点。轴上未列点同样合法。\n\n## 从对象生命期划分空间\n\n权重通常随模型版本存在；KV 和 recurrent state 随请求或可复用前缀存在；工作区随执行阶段存在；图缓冲和通信注册区可能跨多个迭代存在。按这些生命期建池可以减少互相造成的碎片，但池之间的容量划分过硬也可能让一个池有空闲、另一个池无法推进。\n\n设对象 i 的申请量为 rᵢ，按分配粒度舍入后的占用为 aᵢ。内部碎片为 Σ(aᵢ−rᵢ)。外部碎片体现为总空闲足够、却没有满足连续性或映射条件的区间。allocator 保留而未给活跃对象使用的内存又是另一项；它可以加快下一次分配，但仍占物理容量。虚拟地址预留则不能直接加到物理驻留量上。\n\n完整峰值取 maxₜ[权重+活跃状态+可复用缓存+在途缓冲+工作区+保留池]，并避免把同一物理页在共享引用中重复计数。分别取每项最大值再相加是保守上界；只计算权重加稳态 KV 又可能漏掉最危险的过渡峰值。\n\n## 连续缓冲、块表和虚拟映射\n\n连续预分配适合已知上界、地址稳定且容量足够的对象，索引简单，但最大长度预留会浪费尚未使用的空间。应用层固定块池通过块表把逻辑序列映射到离散缓冲，便于共享与写时复制，要求消费者理解块布局。虚拟内存方案预留连续地址，逐步提供物理 backing，保留连续张量接口，但新增映射、页粒度与权限管理成本。\n\n[vAttention v1](../sources/S-VATTENTION.md) §5–6 展示了第三种方案。该版本获得更小页粒度还使用了驱动扩展，不能据此宣称所有 CUDA 环境都直接具备相同能力。设备支持、映射粒度和同步条件必须由目标版本确认。虚拟地址连续也不自动提供跨请求前缀共享、写时复制、跨机迁移或 SSD 换入换出。\n\n两种分页有不同尾部账。设定每请求全层 KV 为 128 KiB/token，应用块长 16 token，31 token 请求占两个 2 MiB 块，尾部浪费 128 KiB。另一设定是 32 层、每层 K 和 V 各 2 KiB/token，物理映射粒度 64 KiB：同一请求每层的 K/V 各需 62 KiB，也总计浪费 128 KiB。若映射粒度变为 2 MiB，每个层状态的尾部开销就大幅增加。这个算例用于显示粒度如何乘上层数与状态类型，不代表任意平台实际支持这些页大小。\n\n## 分配、提交和回收\n\n| 转换 | 必须成立的关系 |\n|---|---|\n| 空闲 → 预留 | 申请者独占容量预算，其他申请不能重复消费 |\n| 预留 → 可读写 | 地址/块表、权限和必要初始化都已完成 |\n| 可读写 → 在途 | 明确哪些 CPU、设备或网络消费者仍持有访问权 |\n| 在途 → 待回收 | 不再接收新访问，但已有访问仍受保护 |\n| 待回收 → 空闲 | 共享引用为零，所有相关异步访问已完成 |\n\n多步分配必须允许部分失败后释放已取得资源。若先更新请求页表再发现其他层无法分配，该请求不能带着不完整状态进入执行。可先预留全部必要增量，再发布新的可执行视图；失败时撤销本次预留，保留旧视图的一致性。\n\n同一个地址被下一代请求重用时，迟到完成事件必须仍能区分旧对象。引用计数负责“谁还可能使用”，完成事件负责“已提交的使用是否结束”；两者不可互相替代。跨 stream 的释放依赖见 [streams 与 allocator](../frameworks/streams-allocator.md)，请求取消的时序见 [资源完成](cancellation-resource-completion.md)。\n\n## 工作区复用与容量调度\n\n顺序执行的两个算子可以共享同一工作区；让它们并发会使生命期重叠，原先的内存规划便失效。融合、图重放、双缓冲、投机树和 P/D 传输都会改变同时存活的对象集合。地址稳定的图缓冲还可能限制压缩或搬移，必须把这种约束回传给容量规划。\n\n准入要为本轮新增 KV、共享尾块的写时复制、采样/归约工作区和不可回收在途页预留空间。缓存驱逐能提供容量，但若被引用或仍在 DMA 中，就不能把“已选择驱逐”计作“现在可用”。达到容量边界时比较等待、分块、驱逐、重算或降低并发，不能依赖偶然的分配成功维持正确性。\n\n##
