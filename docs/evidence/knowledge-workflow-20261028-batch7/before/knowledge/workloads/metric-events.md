# K-WORK-001：服务指标：事件边界、Token 间隔与用户时间

一个延迟指标是两个明确事件的时间差；指标名字相同而事件定义不同，会导致不同结论。

## 一条生成请求的时间轴

记客户端发送为 t₀，服务接收为 tᵣ，首个内容 token 可见为 t₁，最后内容为 tₙ，协议完成为 t𝒻。客户端 TTFT＝t₁−t₀ 包含网络、排队、预处理和首步执行；服务内部的首 token latency 若从 tᵣ 或开始执行计时，则是另一指标。结束延迟通常与 t𝒻−t₀ 有关，可能包含最后封包和传输。

对 N>1 个输出 token，平均 TPOT 常定义为 (tₙ−t₁)/(N−1)；N＝1 时没有 token 间隔，应单独处理。逐 token ITL 是相邻内容 token 的时间差，p99 ITL 反映间歇停顿，不能由平均 TPOT 推断。若传输 chunk 包含多 token，客户端只能直接观测 chunk 时间，逐 token 时间需要额外定义。

## 聚合顺序改变含义

先算每请求平均 TPOT 再平均，给每请求相同权重；把所有 token 间隔合并后平均，长输出权重大。先求每请求 p99 再平均，不等于所有间隔的全局 p99。吞吐的分母应说明是完整测量窗口、从首发到末完成，还是只计算稳定区间。

空角色事件、心跳和 usage 消息不能自动计为首个内容。detokenization 缓冲和 stop string 检测可能让模型已产生 token 而用户尚未收到字符，这个延迟属于真实服务体验。

## 非文本输出的事件

语音关注首个可播放包、累计音频时长和供给间隙；视频/图像关注完整可用输出或明确的预览事件。一个音频包对应多长播放时间比“多少 tokens/s”更直接。多模态服务可以同时报告文本和音频两条时间线，并使用各自 SLO。

将模型计算事件与客户端消费事件连接起来，才能解释优化究竟减少了哪一段时间。内部 kernel 加速若被协议缓冲掩盖，用户 TTFT 可以保持不变。

## 为不同任务选择完成事件

| 任务 | 可交付结果的事件 | 需要同时保留的条件 |
|---|---|---|
| 多轮会话或工具流程 | 必要依赖完成且最终回答可用 | 中间回合、工具失败、取消和会话级质量 |
| Embedding | 全部规定向量已返回且可供消费 | 输入条数、维度、归一化与数值/检索质量 |
| 检索与 reranking | 满足过滤规则的排序结果可用 | top-k、候选集、索引版本和 recall/排序质量 |
| 图像生成或识别 | 完整图像或规定预测结果可用 | 分辨率、预处理、生成步数及质量条件 |
| 语音识别 | 首个稳定文本与最终转录分别可用 | 音频窗口、修订规则和词错误率等目标 |
| 语音/视频生成 | 可连续消费的包及完整输出 | 播放时长、间隙、帧顺序与联合质量 |

生成 tokens/s 不能替代这些任务的完成率。会话有 5 次模型调用时，5 个请求成功不一定意味着整个工具流程成功；embedding 的长文档分块数量增加也不能直接算作业务吞吐增加。度量单位要与用户需要的产物一致。

## 时钟、边界与未完成样本

同一进程的时间差应使用适合测量持续时间的时钟；跨机器事件相减还需要已知的时钟同步误差。trace 身份可以连接因果关系，但不能自动使时钟精确对齐。对很短的网络/设备阶段，测量误差可能与所报告变化同量级。

测量窗口内到达但尚未完成的请求不能消失。可以采用固定到达窗口后排空并报告总完成情况，也可以报告稳定窗口的吞吐并单列窗口边界与残留队列；两者的分母不同。超时、拒绝、取消与质量不合格分别标记，按目标定义进入成功率和延迟解释。

## 成本与能量的分母

单位有效输出成本=所选时间与资源边界内的总成本/有效输出数，单位有效输出能量同理。分子包含失败、缓存预热、空闲保留和重算所消耗的资源。整机能量与仅设备能量需分开；为保持比较可解释，说明是否扣除空闲基线，以及为何该口径符合使用目标。

若新方案返回更少 token、更低分辨率或更短音频，吞吐与能效改善可能来自任务改变。应先核对任务与质量，再将同一有效输出单位的延迟、成本和能量一起比较。相关的尾部样本与区间条件见 [实验统计](../tools/statistical-experiments.md)。
