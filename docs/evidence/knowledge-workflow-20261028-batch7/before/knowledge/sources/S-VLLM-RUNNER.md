## 来源支持的机制与算法

执行器先更新请求状态和持久批：移除结束请求，处理新请求与恢复请求，更新采样信息和状态块映射；随后将本轮不同长度的 query 压紧，生成逻辑位置和输入张量。归档中特别将页表复制提前，以便与后续 host 准备重叠。

```pseudocode
更新持久请求集合与槽位，保存请求到槽的映射
对各请求本轮 token 数求前缀和，展开每行所属请求与绝对位置
收集该轮输入，生成缓存写入与 attention metadata
依据普通生成、prompt logprobs 或投机需要选择 logits 行
执行并采样，将结果沿本轮映射交回请求
```

例如 token 数 [2,5,3] 对应压紧偏移 [0,2,7,10]。压紧和持久槽可共存，不能把其中一个等同于“是否支持图”。新模型状态必须从规格、分配、metadata 一直匹配到消费者；只改变物理 tensor 的 shape 不足以保证接入正确。
