# K-ALG-001：连续批处理：从自回归依赖到迭代调度

连续批处理将资源分配单位从整条请求改成一次可执行的 token 推进；批次是请求状态的临时视图。

## 问题、不变量与设计轴

问题：多条互不依赖的自回归请求共享一套权重与一台设备，每条请求的下一步只在它自己的前一步完成后才可执行，而请求到达、完成与长度都不可预知。调度器要回答的是"下一轮执行哪些请求的哪些 token，用哪些状态，把结果归还给谁"。

任何解都必须满足的不变量：每个请求的 token 按逻辑位置顺序推进且不越过已确认前缀；一轮读取的状态版本与写入区间互不冲突；完成、取消、抢占后的资源最终归还；结果归属可追溯到请求身份。违反其一，批处理就不再是同一个模型函数的并行执行。

成本项：每轮固定成本（提交、调度、同步）、与总 token 数近似成比例的线性层成本、与 Σqᵣhᵣ 相关的 attention 成本、KV 容量占用、以及等待中请求的时间。吞吐与单请求间隔不能由同一除法得到。

设计轴及已有方案所在的点：分配单位（整请求 / 固定 token 块 / 时间片 / 混合）——静态批在整请求端，迭代级调度在 token 推进端，分块 prefill 在时间片端；准入依据（到达顺序 / 估计剩余工作 / deadline / 公平份额）；抢占方式（保留 / 换出 / 重算）；批组成（纯 decode / 纯 prefill / 混合，混合时如何限制单轮时长）；重叠程度（同步每轮 / 主机与设备流水 / 多代次在途）。本章后续各节按轴展开已有方案并注明前提。轴上未列点同样合法。

## 计算依赖决定调度单位

对请求 r，下一 token 的分布依赖已经确认的前缀。不同请求之间没有这种因果边，因此同一迭代可以合并多个请求各自已就绪的计算。一次普通 decode 使每个入选请求前进一个位置；prefill 则能在因果 mask 下同时求出一段已知输入的位置。两类工作共享层权重，但 query 数、历史长度和产生输出的位置不同。

静态批处理等最慢请求结束才更换整个批次。若同批输出长度是 2、3、8，单步成本暂按常数估计，8 轮中只有 13 个有效 token，而固定三槽执行了 24 个槽次。连续调度在请求完成后的边界填入新请求，回收的是这类空槽机会，并不消除每条请求自身的顺序依赖。

## 一轮包含什么

| 对象 | 语义 | 为什么不能混为一个长度 |
|---|---|---|
| 已知且确认的 token 长度 | 输入与已接受采样 token 构成的逻辑前缀 | 最后一个已采样 token 可能尚无 KV；投机候选不自动进入此边界 |
| 已完成 KV 边界 | 所有必要层已生成且可恢复的连续状态范围 | 前缀缓存命中可贡献此值；提交设备工作不证明已经完成 |
| 本轮 token 数 | 分配给请求的计算量 | prefill 可能多个，decode 通常一个 |
| 分配容量 | 已保留的物理槽位 | 包含页尾空槽和 lookahead |

调度结果需要同时描述请求身份、读取的状态版本、写入区间以及结果归属。执行后只有已完成且语义有效的部分进入下一轮；取消、EOS、抢占和投机拒绝都可能改变下一轮集合。调度器维护长期状态，runner 将本轮视图压紧成张量，采样器再将行结果还原到请求。

## 从资源约束推导策略

一轮不能只限制请求数。设请求 r 被分配 qᵣ 个 query token、当前历史长 hᵣ，普通稠密 causal attention 的有效 QK 对数量随 qᵣhᵣ＋qᵣ(qᵣ＋1)/2 变化；线性层工作近似随总 qᵣ 增长。token 预算限制线性层规模，页预算限制驻留与增量分配，最长历史又影响 attention 时间。因此“同样 256 tokens”并非相同成本。

吞吐导向可以用较多就绪 token 摊薄权重读取；交互导向必须限制一轮耗时，使已有 decode 不被长 prefill 拖延。老请求优先可稳定 ITL，却可能让等待中的长请求饥饿；公平机制应按等待时长或累计服务量补偿，而非仅按当前 batch index 排序。

## 缓存和抢占如何进入调度

前缀命中减少待算输入，但命中页仍占物理内存并需要引用保护。资源不足时，暂停并保留页、换出状态、丢弃状态再算，是三种不同成本的抢占方式。重算代价取决于前缀长度和模型，换出代价取决于状态大小与链路，保留代价则是阻止其他请求进入。选择应基于下一次服务机会的估计，而不是把暂停等同于释放。

新请求进入、旧请求离开、批次压紧与页重用的交界是连续批处理真正的实现核心。单请求逐步输出只是一个退化情形；能够导出混合批每一行的逻辑位置、页表和输出请求，才说明调度模型已经落实。更深的主机/设备重叠由异步调度章节推导。

## 比较策略时先说明分配单位

FCFS 可以按请求首次到达决定准入顺序，也可以在每轮对已就绪的请求排序；两者并不等价。短工作优先需要估计剩余服务量，生成输出长度未知时只能依赖可说明的预测；预测失败会让长请求长期得不到机会。优先级与 deadline 则表达业务约束，但要明确是否允许低优先级饥饿，以及过期请求是取消、降级还是继续计算。

| 候选策略 | 主要依据 | 必须补上的约束 |
|---|---|---|
| 按到达顺序准入 | 到达事件与可用容量 | 长 prefill 不能无限阻塞所有 decode |
| 按估计剩余工作排序 | 模型与长度的服务成本估计 | 未知输出、估计误差与等待老化 |
| 按 deadline 紧迫度 | 剩余时间减估计服务时间 | 估计不准、已经不可达的 deadline 和拒绝语义 |
| 按公平份额分配 | 累计服务量、权重或欠额 | 服务量单位、跨轮记账和最大等待 |

公平的单位可以是请求、token、估计设备时间或租户资源份额。相同 token 数在不同历史长、模型和模态下未必消耗相同资源；按 token 公平与按计算成本公平会产生不同结果。调度应记录采用的单位，并能解释谁获得资源、谁付出等待。

## 未知长度下的逐轮修正

新请求进入时可以先预留输入状态与可执行的近期增量，随后按真实生成进度补充预算。对输出长度的预测可以用于排序或容量规划，但不能代替每次执行前的硬容量检查。临近上限时，任务的最大输出长度、取消、抢占和释放协议决定如何继续，不能把越界写入当成预测误差的自然后果。

设定一轮最多提供 4 个服务单位，长请求 A 已等待，短请求 B/C/D 不断到达。若永远优先新短请求，A 可以无限延期；一种可分析的规则是为等待超过阈值的 A 保留一个单位，其他三个再按估计工作量排序。阈值和保留份额都是目标参数。对已经运行的 decode，还要检查它距上次输出的时间，避免为了新请求的 TTFT 破坏已有请求 ITL。

调度器不应仅维护一个排序分数：可执行性检查先排除状态未就绪、资源未完成或模型版本不匹配的工作，然后在合法集合中选择。否则高优先级请求可能反复占据队首，却无法推进，使可执行请求也被阻塞。

## 抢占与恢复的完整时序

在迭代边界确认旧执行完成，记录请求的已计算、已确认和已输出边界；选择保留、换出或重算；需要释放时，先终止新访问，再等待既有消费者完成；恢复时重建所需状态与映射，确认连续位置和输出提交点，最后重新进入可执行队列。每一步都保留请求身份与代次，迟到结果不能改变新一轮状态。

保留状态的暂停几乎不支付恢复计算，却仍占容量；换出支付传输、缓冲和恢复等待；重算释放较多状态，却增加未来计算和首个恢复 token 的延迟。多次来回抢占可能产生比新增有效服务更多的搬运/重算，所以需要比较抢占频率、已投入成本和预计再次运行时间。

验证包含持续短请求下长请求是否获得服务、低优先级的等待分布、错误长度预测、共享前缀分叉后抢占，以及取消与恢复交错。候选策略用同一到达轨迹比较联合 SLO、拒绝、重算和各租户份额；平均吞吐提高不能单独证明调度选择正确。

## 把一个 token 的四个时刻分开

下面构造一种完整但保守的调度算法：一个请求最多有一轮在途，普通自回归生成，不含投机、beam 或输入追加；不同请求可同批。它说明怎样从依赖组织执行，并非要求引擎采用同样字段或同步粒度。[vLLM 固定实例](../sources/S-VLLM-SCHED.md)允许提前增加内部进度以组织流水，必须另外保留未确认边界；本例在完成后才更新 KV 边界。

对请求 r，已确认的 token 序列为 xᵣ[0:nᵣ)，初始为完整的非空 prompt。kᵣ 表示全层有效 KV 的连续前缀 [0:kᵣ)，0≤kᵣ≤nᵣ；aᵣ 是可写容量，页式存储时是已分配页数乘页长。输入 token 已知与 KV 已计算不是同一件事。轮次中的工作为 [kᵣ,kᵣ+qᵣ)，必须有 1≤qᵣ≤nᵣ−kᵣ、kᵣ+qᵣ≤aᵣ，且该范围的输入和所有模型依赖已经就绪。

当 kᵣ+qᵣ<nᵣ 时，只完成部分已知输入，不从中间行交付生成 token。当 kᵣ+qᵣ=nᵣ 时，末行 logits 给出 xᵣ[nᵣ] 的分布。按本请求的采样状态得到一个非停止 token 后，先以原序列末位置 nᵣ 记录该 token，再令 nᵣ←nᵣ+1；此刻 kᵣ 仍是旧 nᵣ。因此它可以已经被用户收到，却还没有自己的 KV。下一次 decode 才处理这个已知 token，产生其 KV 并预测后继。不可为了凑满 q 而预先执行尚未采样的普通自回归后继。

准入与恢复还要处理“完整前缀 KV 命中，但没有末行 logits”。KV 保存注意力状态，不保证保存可直接采样的输出。若仍需生成，本例最多复用 min(命中长度,n−1) 的 KV，重新执行最后一个已知 token；n=1 时复用零个。对共享的命中尾页，先复制所需前缀到独占可写页，或者使用另一个有证明的安全写区，再计算最后位置，不能原地覆盖共享或在途页。故本例未结束请求的初始候选始终有 k<n。另一种设计是额外缓存末行 logits，但要绑定模型、完整输入与数值策略，并明确采样状态和是否已经提交输出；它不是仅缓存 KV 就自动拥有的能力。若只是重放已确认输出，应从输出账恢复，不得重新采样。

若末行产生 EOS，本例记录停止事件并结束请求，不要求为 EOS 再算 KV；协议是否把 EOS 作为可见内容由输出契约决定。本例另外规定 n 不超过给定总 token 上限 Nmax：n=Nmax 或已达生成数量上限时，完成当前必要计算后直接结束，不再产生新 token；若采样使生成数量刚达上限，保留该已确认输出并结束，不再计算它的 KV。空 prompt 需要事先约定 BOS 或拒绝，本例拒绝空输入；准入时拒绝 n>Nmax，输出上限为零的请求无需启动生成。投机、分支和多模态输入需要各自扩展确认规则，不能只放大本例 q 的上界。

还需区分采样已确认与输出已交付。假设本例有带序号的可靠输出队列，gᵣ 是已确认的生成内容数，dᵣ≤gᵣ 是消费者已确认接收的个数。输出记录以请求生命期、生成序号去重；业务取消后停止新增交付。等待网络或消费者释放的结果缓冲仍占容量，不能因为 KV 已完成就覆写它。随机采样状态也按请求和逻辑位置关联；批次压紧不应改变哪条随机流属于哪个请求。

## 选择、预留、提交和完成的完整算法

输入是长期请求状态、模型与资源就绪事件、页池、输出队列以及一组可测量的本轮预算。输出是一份不可变执行视图及其完成后的状态变化。以下用独占可写尾页简化说明，共享前缀的身份和 COW 由[分页 KV](paged-kv-capacity.md)承担；预留函数返回的必须是已验证可写的页集合，不能只返回一个足够大的计数。

协调器顺序处理到达、取消、提交和完成事件，设备按视图运行。排序是一个可替换的选择步骤；把排序、可执行性和容量承诺混在一个优先级分数里，无法保证合法。某个高优先级请求未就绪时，扫描其他候选而不让它占用本轮预算。对已知 q 范围，可用单调校准模型或枚举合法图桶求最大可行 q；模型非单调时不能擅用二分。

```pseudocode
输入：请求账、已确认完成事件、可写页池、本轮 token/时间/输出缓冲预算
准入/恢复：校验非空输入和长度上限；按上述规则建立可生成的 KV 边界与独占写区
先处理完成与取消事件；释放条件已满足的对象进入空闲池
按所选公平/优先策略生成本轮候选顺序，初始化临时预算与空计划
对每个候选请求 r（本轮最多扫描一次）：
    若已结束、已有在途轮次、输入/模型/状态未就绪，则跳过
    在 [1, n[r]−k[r]] 内选择 q：
        满足模型位置上限、token 预算、加入当前计划后的时间估计和结果缓冲容量
        所需新增可写页足够；包含共享尾页时先计入 COW 和其暂存空间
    若不存在正 q，则记录具体阻塞原因，继续其他候选
    临时预留页与结果槽；失败则撤销该候选的临时改动
    记录请求生命期、起点 k、终点 k+q、输入范围、物理映射与结果归属
    记录是否到达当前已知前缀末尾；扣减临时预算
若计划为空，则等待新的就绪/资源/到达事件，不提交空 kernel
逐项再次确认请求生命期与资源承诺；构造不可变执行视图
    query 行区间、绝对位置、KV 映射、采样末行、结果槽均来自这同一视图
    给全部被读取/写入的页和描述符加执行引用，记录唯一轮次凭据
提交失败且确定设备未接受：撤销执行引用和临时预留，长期 k/n 不变
提交成功：把预留交给各请求，标记本轮在途；禁止改写此视图使用的缓冲

收到轮次完成通知：
    先核对轮次凭据，确认全部相关写入与结果读取已达到声明的完成边界
    重复通知不重复提交、不重复释放
    对原视图每条请求记录（不能用当前 batch 行重新猜请求）：
        若该请求生命期已取消/失效，则丢弃业务结果，保留物理完成清理
        否则核对仍由此轮持有提交权，令 k←本轮终点
            若未到达当前已知前缀末尾，保持 n 不变，不采样/交付
            若到达末尾且 n<Nmax、生成配额未尽，提交末行采样结果：
                停止则结束，否则追加已知 token；本次输出用尽配额时结束
            到达末尾但 n=Nmax 或配额已尽时，结束且不再追加 token
            给新输出分配本请求生成序号；按输出契约入队
    清除有效请求的在途标记；归还执行引用与无需保留的预留
    只有逻辑拥有者、在途使用者和相关输出消费者都结束的对象才可复用
```

这里的“提交失败”特指确定未入队。若 API 返回值不能确认是否接受，保留对象并查明完成状态，不能既让设备继续写又当作已回滚复用。执行失败时也不能把一部分层已写入的 KV 直接当成完整连续前缀；隔离未确认写区，等待全部使用结束，再恢复到最后有效边界或结束请求。本例不把错误结果填零继续运行。

该算法的安全性可由三点推导。每份视图从已知输入和已完成状态构造，且本请求没有第二个在途写者，所以不会重复或越过因果边界。设备实际消费的页、query 区间和结果行绑定同一原始视图，所以其他请求退出和压紧不会改变归属。完成与取消只改变业务提交权，物理引用独立归还，所以取消不会允许在途写入污染新请求。多轮在途是合法扩展，但必须给出相应范围依赖、完成顺序与回滚协议，而不能只去掉“已有在途则跳过”。

## 一份贯通混合批、取消和迟到通知的轨迹

取页长 P=4，每 token 全层 KV 为 128 KiB，每页 512 KiB，页池共 8 页。本例只管理请求私有页，权重、工作区和输出缓冲已经从总设备容量扣除。初始 A 的 n=6、k=4，有一页有效 KV；B 的 n=5、k=4，也有一页。二者输入已知，尚未处理的输入分别是 A 的位置 4、5 与 B 的位置 4；C 尚未到达。为便于核对，首轮 token 预算为 3，并选择 A 后 B。

| 事件 | 逻辑状态与压紧行 | 页的实际责任 |
|---|---|---|
| 建立轮次 0 | A 分配 q=2，行 [0,2)，位置 4、5；B 分配 q=1，行 [2,3)，位置 4 | A、B 各新预留一页，总共占 4 页；所有 4 页和本轮映射加执行引用 |
| 提交后 C 到达 | C 的 n=3、k=0；它不改变已提交视图 | C 尚未占 KV 页，不得把当前活跃列表改成 A/C 后解释行 2 |
| B 在途取消 | B 停止未来调度和业务交付 | B 的 2 页逻辑拥有权撤销，但执行引用仍在，不能交给 C |
| 轮次 0 完成 | A 的 k=6；末行 1 产生 a₆，追加后 n=7、k=6。行 2 仍属于旧 B，其采样结果丢弃 | 释放本轮引用，B 的 2 页现在才空闲；A 的 2 页继续拥有 |
| 建立轮次 1 | 示例顺序 C 后 A：C 的 q=3，行 [0,3)；A 的 q=1，行 [3,4)，位置 6 | C 需要 1 页；A 已有容量 8，无新增页。此轮映射与轮次 0 独立 |
| 轮次 1 完成 | C 的末行 2 产生 c₃，n=4、k=3；A 的末行 3 产生 a₇，n=8、k=7 | 后继 token 只有在此次采样完成后才成为已知输入 |
| 旧 B 完成通知重复到达 | 即使请求字符串 B 已被新生命期重用，也不能向新 B 交付旧结果 | 旧轮次凭据已消费，不再减引用；新 B 的页和进度不变 |

首轮读取集合的 attention 对数是 A 的 5+6=11 与 B 的 5，共 16 对（每 head、每层）。新 KV 写入是 3×128 KiB=384 KiB；完成前保留 4 页即 2 MiB，不能把未用满页或已取消但在途的页视为空闲。A 首轮结束后的 a₆ 没有 KV，所以第二轮 A 的历史是 6、q=1，而不是历史 7 又计算一个未知 token。这个差一位置的错误常被最后生成文本暂时掩盖。

首轮创建 3 个 query 行，但只有 A 的行 1 和 B 的行 2 是采样候选。第二轮则为 C 的行 2 和 A 的行 3。采样参数、RNG、停止条件和输出序号随这种映射移动；不能取每个请求的第一个行号，也不能把上一轮的结果下标复用到新视图。请求 ID 可以被复用，完整生命期和执行凭据在旧资源结束前不能重复。

## 把工作、容量和时间放进同一个候选

令本轮集合为 J，Q=Σqᵣ，总 attention 对数 V=Σ[qᵣhᵣ+qᵣ(qᵣ+1)/2]，其中 hᵣ=kᵣ 为该段前已有的有效历史，q 个当前 token 的 causal 对角线包含自身。对 N 层、Hq 个 query heads、维度 dₖ/dᵥ，QK 与 PV 的主要 FLOPs 合计为 2NHq(dₖ+dᵥ)V；另计 softmax、位置变换、线性层、MLP 和采样。线性层的主要矩阵行数随 Q 增长，但实际效率会随形状与 kernel 改变。

每 token 的 KV 字节 kbytes=N·Hkv·(dₖ+dᵥ)·b，b 为元素字节；普通新增写入至少 Q·kbytes。若每请求每层独立扫描一次当前可见 K/V，逻辑请求读取量的粗模型为 Σ(hᵣ+qᵣ)·kbytes；若每个 query 或 query head 重读，乘相应重读因子。共享前缀减少唯一驻留字节，并不自动消除不同 query 的读取和计算。cache、GQA 组内共享与块调度会改变物理流量，因此前者是数据流假设，不能直接作为带宽测量的分母。

独占尾页且没有预分配余量时，新增页数 Δᵣ=ceil((kᵣ+qᵣ)/P)−ceil(kᵣ/P)。一般情况应减去已保留的可写页容量，而非只看 k；共享页还可能产生 COW 页、复制与暂存。硬容量条件是在途、已拥有、临时预留各物理页的并集不超过池容量，不能把不同引用重复算成多份页，也不能把取消未完成页扣掉。描述符、工作区、图包、待发送输出与权重需要各自计入驻留峰值。

时间模型可以从以下可校准分量建立：主机扫描/排序、页检查与 metadata 填充、提交与返回、设备执行、输出处理；分布式执行另外包括激活/collective 和相关等待。本例单设备的网络通信量为零，但用户输出传输仍进入端到端指标。逐轮同步实现的关键路径可求和；若主机准备与另一批设备执行重叠，应根据依赖画时间线，使用关键路径而非把全部分量相加。

例如局部拟合 Tdev=α+βQ+γV，单位 ms。α 可以包含固定启动和权重通路的影响，不能又把相同权重读取时间再加一次。若每轮实际需读 W 字节权重、有效带宽为 B，则 W/B 是相应数据流下的下界之一；批次增加 Q 可摊薄每 token 权重成本，但在计算、KV 或其他资源饱和后不再线性受益。已有服务目标 D 和距上次输出已过去 w 时，设备预算最多为 D−w−预计主机/输出时间−不确定性余量。负预算表示目标已不可达，应报告或调整准入/优先级，不能声称换一个 q 就一定解决。

## 一个时间预算与页预算给出不同答案的算例

下面完全是设定模型，不是 GPU 测量或推荐参数。取 Tdev=4+0.015Q+0.0000005V ms，本轮设备预算 5.6 ms、token 预算 128。已有 16 个 decode，每条 h=8192、q=1：Q=16，V=16×8193=131088，Tdev=4.305544 ms。加入一个 h=0 的新 prefill，若其 q 个 token 全已知，求得时间约束下最大整数 q=86；q=86 时总时间为 5.5974145 ms，q=87 时超过 5.6 ms。若 prefill 已有 h=4096，则相同时间预算只容许 q=75；q=76 超预算。

再加入物理条件：页长 P=16，所有 decode 的旧历史恰好在页边界，池中只有 20 个空闲可写页。16 条 decode 各需 1 页，剩余 4 页只支持新 prefill 的 64 个 token。因此本轮应重新取满足全部条件的 q≤64；选择 q=64 时，h=0 的总时间为 5.266584 ms，h=4096 时为 5.397656 ms。不能先按 q=86 发布计划，再寄希望于取消请求及时归还页。若采用暂停保留旧请求，也不会凭空多出这 20 页。

同一设定模型还能展示切片的取舍。只有一个 512-token prompt、h=0，无其他请求时，整段 prefill 的 V=131328，时间 11.745664 ms。拆成 8 个 64-token 片，整个 prompt 的总 V 仍为 131328，总 Q 仍为 512，但固定项付出 8 次，总设备时间成为 39.745664 ms；最后一个片的时间为 4.975376 ms。没有竞争请求时，整段更省总服务时间；需要频繁给其他 decode 服务时，小片提供更短的调度边界。它不会减少总语义工作，也不无条件改善 TTFT。主机准备、图桶、cache 和利用率变化会进一步改变这组数字，必须重新校准。

## 公平分配的前提与进度证明

按最短已知剩余输入排序可以降低一部分请求等待，却可能让持续到达的短请求把长 prefill 永久推后；“只先服务已有 decode”也可能使新请求始终没有首 token。轮转、欠额、等待老化或租户权重均是可比较的选择。本例可用一个简单轮转规则：在已准入且就绪的队列中，每次给队首一个可行最小服务片，再移到队尾；新请求追加到队尾，未就绪请求跳过而保留等待记录。

若活跃且持续就绪的请求不超过 M，每轮至少容纳一个最小片，每个最小片都能获得状态容量、资源最终完成、每轮从提交到再次调度不超过 T，那么每条请求在至多 M 个服务机会内取得进展，等待上界可用 M·T 粗估。该推导依赖有限准入与可行容量；当所有页被不可释放状态占满，或输出消费者无限背压时，轮转本身不能保证进度。必须选择拒绝新准入、限制保留、等待确定可回收资源或采用有证明的抢占/恢复方案。

服务片的单位也改变公平含义。相同 q 在 h=32 与 h=32768 时 attention 工作相差很大；等 token 轮转不等于等设备时间。按预测成本扣欠额可缓解差别，但估计有误时需要按完成观测修正，并限制一次不可抢占片的大小。输出长度预测只用于优先级和期望容量；每轮硬页检查与模型位置限制不随预测放宽。

抢占的选择可以写成同单位成本：保留所需的额外驻留 ΔM 与预计等待 Δt 形成容量时间 ΔM·Δt；换出/换入至少支付实际状态字节除相应有效链路率，加注册、打包、暂存和等待；丢弃重算支付恢复点之后的计算与权重/状态读取。容量时间本身不是 ms，需要根据被阻塞请求的收益或 SLO 转为目标代价后再比较。共享页只因最后一个拥有者离开才真正回收，频繁抢占可能付了重算而没释放期待的容量。

## 用一次反常结果区分竞争解释

设同一开放到达轨迹下，prefill 片从 128 缩为 64 后，decode 的设备段变短，ITL 却变差。以下为构造的诊断例，不是实测结论：前者关键设备段 6.0 ms、不可重叠主机空档 0.4 ms，后者分别为 4.8 ms、3.0 ms；若等待与输出段其余部分相同，间隔从 6.4 增为 7.8 ms。设备段改善 1.2 ms，被新增主机空档 2.6 ms 抵消。平均 kernel 时间或 token/s 单独看不出这个原因。

| 竞争解释 | 与其他解释不同的预测 | 有区分力的干预与证据 |
|---|---|---|
| 更频繁 metadata/分配/提交消耗主机 | 固定设备视图重放时慢化消失；设备空闲与主机准备相邻 | 保存逐轮选择与页数，预备等价视图作诊断重放；比较主机区间和设备间空档，避免重放改变实际请求工作 |
| 页压力造成等待、抢占或重算 | 慢轮与页不足/COW/恢复事件对齐；改变可用页量后行为改变 | 保持到达与形状，在不改变权重路径的条件下增加可用页或移除可解释的预留；检查有效服务量和重复计算 |
| 策略使 decode 更少入选 | 设备可能一直忙，但请求距上次服务的轮数增加 | 固定相同任务集合改变排序，核对每个请求选择/跳过原因；不能把未入选等待归因于 kernel 慢 |
| 小形状走了低效 kernel/图桶 | 只重放设备工作也变慢，且资源或指令路径发生变化 | 保持合法输入与数值契约，对比分段设备时间、生成指令、padding 和事务；更小 q 不保证更低总调用成本 |

若将 64-token 视图的主机空档降至 0.5 ms 后，间隔变为 5.3 ms，且选择频率、实际处理范围和数值结果一致，就支持本例的主机空档解释；这不能证明所有规模都由主机主导。若预备视图后空档仍在，而迟迟未满足的页事件与空档吻合，则修正解释并转向资源等待。若差异落在重复实验的不确定区间内，保留未知，不按一次轨迹排序。实验比较须固定外部到达、模型、输入输出长度分布与取消行为，同时报告 TTFT、ITL、拒绝、抢占、重算和完成请求联合 SLO；不能通过减少 offered 工作假装改善策略。
