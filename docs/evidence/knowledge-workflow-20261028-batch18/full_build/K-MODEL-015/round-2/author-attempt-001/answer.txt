  "chapter": "# K-MODEL-015：推荐推理：稀疏表、特征交互与请求批量\n\n推荐推理的参数量常由 embedding 表主导，但单请求只读取其中少数行；完整成本来自不规则 lookup、bag 聚合、分片合并、特征交互、稠密网络和请求批量。表容量、每请求读取量与请求完成时间是不同对象。本章展开已冻结模型制品的前向服务；训练、离线特征生成和标签回流不属于该前向路径。\n\n## 请求、制品与函数\n\n一次服务绑定制品 A=(schema,mapping,{E_t},θ_bottom,θ_top,π_num,π_pair,head)。E_t∈R^(V_t×d) 是第 t 个表，V_t 为行数，d 为公共 embedding 维度。schema 规定连续特征变换、类别特征顺序、bag 模式、缺失与未知类别规则。mapping 将类别值转换为表 ID 和行 ID，或转换为已声明的 OOV 行。相同整数在不同表中不代表相同含义。\n\n请求包含连续特征 x_cont∈R^c 和 F 个类别 bag。对 bag b，逐出现项的行 ID 为 i_(b,k)，权重为 w_(b,k)，长度为 n_b。定义\n\nS_b=Σ_k w_(b,k)E_(t_b)[i_(b,k)]，N_b=n_b，W_b=Σ_k w_(b,k)。\n\n本章区分三种模式：SUM 返回 S_b；MEAN_UNWEIGHTED 要求权重全部为 1、N_b>0，返回 S_b/N_b；MEAN_WEIGHTED 要求权重有限且非负、W_b>0，返回 S_b/W_b。SUM 允许有限的有符号权重，空 bag 返回零向量。均值空 bag 按制品声明返回独立的空结果，或拒绝；下文参考算法选择拒绝。未知类别只有在 mapping 声明了合法 OOV 行时才能继续，该行必须真实存在并属于本次表版本。\n\n同一 ID 重复出现具有次数含义。bag [a,a,b] 的无权求和为 2E[a]+E[b]。读取时可以合并重复项，但消费时必须恢复出现次数；加权模式必须恢复重复项的权重和。缓存减少读取次数，不改变函数。\n\nDLRM 固定论文 §2.2 的参考结构是：类别特征经 embedding/bag 聚合；连续特征经 bottom MLP 得到 z∈R^d；令 u=[z,y_1,…,y_F]，按固定 π_pair 计算不同向量间的点积；将结果与 z 拼接，再经 top MLP 和 sigmoid 得到概率。本章选择 π_pair 为按 j 递增、再按 k 递增枚举的 0≤j<k≤F。因此 pair 数为 P=F(F+1)/2，交互向量 p∈R^P，top 输入 h=[z,p]∈R^(d+P)。这是一项明确的权重接口选择，不声称所有制品采用同一种三角展开顺序。\n\n改变 π_pair 而不相应重排 top 第一层的列，会改变函数，即使 shape 完全相同。类别 bag 按契约产生零向量时，仍占据 u 中原来的位置；不能删除该特征再使用原 top 权重。\n\n## 稠密网络的逐层算法与输出边界\n\nS-DLRM §2.1.4 式 (5) 给出了逐层仿射与激活。这里将它展开为 bottom 和 top 共用的算法。对一个 L 层网络，宽度为 n_0,…,n_L；第 l 层 W_l∈R^(n_l×n_(l−1))、bias b_l∈R^n_l。以列向量记法定义\n\na_0=x，q_l[j]=b_l[j]+Σ_i W_l[j,i]a_(l−1)[i]，a_l[j]=φ_l(q_l[j])。\n\nφ_l 是制品逐层声明的函数；本章参考路径使用 IDENTITY(x)=x 或 RELU(x)=max(0,x)。激活只在完整仿射归约和一次 bias 之后应用，不能在 K 轴部分和上提前应用。其他激活必须由其制品另行给出函数及数值边界。\n\n```pseudocode\n算法 ForwardMLP\n输入：x[n_0]，L≥1，逐层 W_l、b_l、φ_l，数值契约 π_num\n输出：a_L[n_L]，或 REJECT/FAILED\n1 在计算前核对所有宽度、W_l 行列、bias 长度和激活定义\n2 a=x；a 与参数保持可读，输出不得覆盖仍有消费者的输入\n3 对 l=1…L：\n4    分配本层 q[n_l] 和 next[n_l]，或取得合法的融合输出区\n5    对 j=0…n_l−1：\n6        acc=0\n7        对 i=0…n_(l−1)−1：acc+=W_l[j,i]·a[i]\n8        q[j]=acc+b_l[j]\n9        next[j]=φ_l(q[j])，按 π_num 执行规定的转换和舍入\n10   全部 next 写入完成且对本层消费者可见后，令 a=next\n11   上一层缓冲只有在全部读者结束后才可回收\n12 返回 a\n```\n\nbottom 的 n_0=c、n_L=d，初始输入是完成 schema 变换后的 x_cont；它返回交互使用的 z。top 的 n_0=d+P，二分类参考路径的 n_L=1，初始输入为完整 h；top 最终层 φ_L=IDENTITY，返回一个 logit ℓ。本章检查用例选择两网络隐藏层 RELU、bottom 最终层 IDENTITY。若实际制品规定 bottom 最终层 RELU，必须保留该激活；不能由网络名或输出维度推断它。具体激活选择属于制品，逐层执行顺序属于算法。\n\n二分类 head 恰好应用一次 sigmoid：ℓ≥0 时 q=1/(1+exp(−ℓ))；ℓ<0 时令 e=exp(ℓ)，q=e/(1+e)。这个分支避免计算巨大的正指数。top 最终层已经输出概率的制品必须使用另一项明确的接口，不能再把概率作为 logit 输入 sigmoid。多任务输出也必须声明输出宽度、各 head 的输入切片和函数，本章不将二分类公式推广到所有推荐任务。\n\n两层网络的中间状态不能省略解释：第一层先从 a_0 得到 q_1，再得到 a_1；第二层只读取 a_1，得到 q_2 后应用自己的 φ_2。非零 bias、负中间值以及负 logit 可以区分漏 bias、漏隐藏激活、错误最终 RELU 和重复 sigmoid。这些错误不会必然表现为 shape 错误。\n\n## 合法性、bag 算法与分片合并\n\n请求需要满足：schema、mapping、表、dense 参数、数值契约及 pair 顺序属于兼容制品；行 ID 在范围内，或按规则得到合法 OOV；bag 边界覆盖输入且无跨请求混合；权重符合模式；每个逻辑出现项只有一个贡献。复制表可以增加读带宽，但多个副本不能同时被当作同一出现项的不同贡献。\n\n用 owner_t(i) 表示该放置计划中第 t 个表第 i 行的贡献分片。按唯一 ID 组织读取时，每个分片保存 id→(mult,wsum)：mult 为出现次数，wsum 为逐次权重和。\n\n```pseudocode\n算法 AggregateBag\n输入：表 t、row_ids[0:n]、weights[0:n]、模式 mode、表版本 v、owner、已完成集合 C\n输出：y[d]、N、W，或 REJECT\n1 检查模式、长度、行宽、表身份；检查所有权重有限\n2 无权均值要求全部权重为 1；加权均值要求全部权重非负\n3 初始化 parts 为空；每个分片中的唯一行记录初始为 (0,0)\n4 对每个出现项 k：\n     按既定 mapping/OOV 规则取得合法 id；检查 0≤id<V_t\n     s=owner_t(id)；检查其有效副本属于 v\n     parts[s][id].mult+=1；parts[s][id].wsum+=weights[k]\n5 冻结必需分片集合 R=keys(parts)\n6 若 R 不是 C 的子集：拒绝消费，不把缺失分片视作零\n7 对每个 s∈R：初始化 S_s[d]=0、N_s=0、W_s=0\n8 对该分片每个唯一 id：\n     读取一次 E_t[id]\n     对每个通道 j：S_s[j]+=wsum·E_t[id][j]\n     N_s+=mult；W_s+=wsum\n9 在合并端确认全部 partial 完整、可读、同身份；每个分片仅接收一次\n10 S=Σ_s S_s；N=Σ_s N_s；W=Σ_s W_s\n11 核对 N=n、W=Σ_k weights[k]；数值归约按 π_num 比较\n12 SUM 返回 (S,N,W)\n13 均值若 n=0 则 REJECT\n14 无权均值返回 (S/N,N,W)\n15 加权均值若 W≤0 则 REJECT，否则返回 (S/W,N,W)\n```\n\n计数守恒能发现一类遗漏，却不能证明向量完整：错误实现可能保留 N、W，却漏加某个 S_s。因此还需要逐出现项的独立数值参考。只返回各分片局部均值也不充分；正确总体无权均值为 Σ_s S_s/Σ_s N_s，加权均值为 Σ_s S_s/Σ_s W_s，不能等权平均局部均值。\n\n例如两分片分别处理 3 个和 2 个出现项，重复 ID 在第一分片出现两次。只测试第一分片非空，无法检验成功的跨分片合并；仅测试第二分片未完成而被拒绝，也无法检验两个分片完成后的归约循环。\n\n## 完整请求、批量与状态推进\n\n请求状态为 NEW、FEATURES_FROZEN、LOOKUP_PENDING、BAGS_READY、DENSE_READY、COMMITTED，以及 FAILED、CANCELED。状态表示本请求的完整输入或结果达到相应边界，不由某一个分片的最后通知推断。\n\n```pseudocode\n算法 ExecuteRecommendationRequest\n输入：请求 r、不可变制品 A、放置计划 P\n输出：概率或声明的 head 输出，或 REJECT/FAILED/CANCELED\n1 状态=NEW；检查请求、计划和制品身份及全部形状\n2 预留输入、partial、bag、交互、MLP 工作区和输出；取得参数读保护\n3 规范化连续特征；映射类别值，生成 row_ids、weights 和 bag 边界\n4 冻结这些输入和版本；状态=FEATURES_FROZEN\n5 为每个 bag 冻结必需分片及接收账，登记访问责任后提交 lookup\n  状态=LOOKUP_PENDING\n6 接收同身份完整结果；全部 bag 的必需分片成功且可读后执行 AggregateBag\n  全部 bag 合法才进入 BAGS_READY\n7 z=ForwardMLP(x_cont,θ_bottom)；验证长度 d\n8 u=[z,y_1,…,y_F]；初始化 p[P]\n  按 π_pair 逐对初始化 acc=0，再遍历 d 个通道累加 u_j[c]·u_k[c]\n  将每个完整点积写入其固定槽位\n9 h=[z,p]；logits=ForwardMLP(h,θ_top)\n  检查 head 宽度，应用一次声明的 head；状态=DENSE_READY\n10 在与取消、失败协调的提交点重新核对身份和发布资格\n   完整输出写入成功且可读时发布；状态=COMMITTED\n11 失败或取消：停止未启动工作，不发布部分结果\n   等待已启动读取、传输和消费者真实结束后回收其缓冲\n```\n\nbottom 不依赖类别 bag，可以在特征冻结后与 lookup 并行执行；交互仍须等待 z 和全部 bag 就绪。上面的串行顺序是一条可实现路径，不是要求放弃这种重叠。\n\n批量执行可把 bag 表示为 CSR：indices、weights 及 offsets，另带每个 bag 的 request_id 和 feature_id。offsets 从 0 开始、单调不减、终点等于 indices 长度。空 bag 用相邻相等的边界表示。每个 bag 必须对应同一请求的同一特征，跨请求全局求均值会改变函数。执行 padding 不能进入 bag 的 N、W 或真实交互列。\n\nlookup 可以乱序完成，但成功集合必须完整。一次通知只更新它所绑定的分片；重复、旧版本或旧请求通知不能推进当前请求。这里的完成还包括结果在合并端可读，CPU 聚合完成但结果搬运未完成时不能消费。\n\n## 成本、聚合位置与通信\n\n表主体容量为 M_table=Σ_t V_t d s_t，另计量化元数据、对齐、目录、索引和复制副本。容量按同时存在的物理副本计；流量按真实读取和传输计，不能把完整表容量写作每批通信量。表在 SSD 时，随机小读的 IOPS、读放大和尾延迟不能由顺序带宽代替。\n\n以下固定同一批 bag，记 n=Σ_b n_b 为出现项总数，G 为 bag 数，U 为按表和版本去重后的实际读取行数，s_e 为表行元素字节，s_a 为传输聚合元素字节，s_acc 为累加元素字节。无缓存、无读取去重时逻辑表读取为 nds_e；去重或缓存改变实际读取数，但仍须恢复每个 bag 的贡献。跨 bag 共享读取还需保留消费映射。\n\n两种放置都必须产生相同 S、N、W 和 y：\n\n| 路径 | 数据流 | 聚合与归一化 | 传输及中间驻留 |\n|---|---|---|---|\n| 表侧聚合 | ID/权重路由到表所在侧→读行→形成 S_s,N_s,W_s→送合并端→合并→归一化 | 加权乘法和行累加在表侧；跨分片向量合并及最终均值在合并端。整个 bag 在一侧时，可在该侧直接产生 y | 每个非空 bag—分片贡献发送 d 个累加元素和必要计数；表侧保留 partial，目标保留接收及合并缓冲 |\n| 传原始行 | ID 路由→表侧读行→传行及消费映射/权重→目标侧按 bag 聚合→归一化 | 同样的加权乘法、行累加和均值仍需完成，主要移到目标侧 | 按出现项发送时为 nds_e，另计权重、边界和身份；目标若全部物化需 nd 个行元素及聚合输出，也可用有界块流式消费 |\n\n原始行传输没有消除 bag 聚合。若按唯一行发送，则行净荷可变为 Uds_e，但必须另传每个 bag 的行引用及 mult/wsum；这既不是语义去重，也不是自动消除目标侧计算。\n\n对逐出现项、零初始化累加器的明确实现，无权 SUM/均值需要 nd 次向量加法；从首行初始化的非空实现可将这部分改为 Σ_b(n_b−1)d 次加法。加权路径若对每个出现项显式乘权重，另有 nd 次乘法，以及计算 W 的标量加法；无权常数 1 可以省乘法。最终均值每个非空 bag 需要 d 次除法，或一次倒数加 d 次乘法，其数值契约须匹配。重复 ID 先合并权重后，可将向量乘加次数降到每个 bag 的唯一行数乘 d，但增加分组和 wsum 构造；浮点重排不保证逐位一致。\n\n设一批共有 R 个非空 bag—分片贡献。表侧 partial 路径的向量传输主体为 Rds_acc；集中单侧且每 bag 仅发最终向量时为 Gds_a。合并端零初始化实现还需 Rd 次 partial 向量加法和最终归一化；无 partial 切分的单侧实现可以直接采用该侧结果。不能用 Gd 公式估计任意按行分片计划。\n\n未融合的加权实现若先物化 nd 个加权元素再归约，会增加该中间量的一次写出和一次读入；读行后直接执行乘加可以省掉这两次逻辑访问及相应临时区。它保留必要的权重乘法和求和。类似地，边接收原始行边累加可避免整批原始行缓冲，但接收槽仍须保留到累加最后读取结束。融合是否增加寄存器压力、spill 或调度开销，需要目标实现证据。\n\n两网络 dense 主项统一为 BΣ_l n_(l−1)n_l MAC，求和覆盖 bottom 和 top；bias 另有 BΣ_l n_l 次加法，非恒等激活、head 和必要转换另计。dense 权重主体为 Σ_l n_(l−1)n_l s_w，另加 bias。逐层物化会写出并读入中间激活；合法融合可能减少这些交通，但保留活跃 z：z 既参与点积，也直接进入 top 输入。\n\n交互需要 BPd 次乘法、BP(d−1) 次非空点积加法；若按 MAC 主项记账，则为 BPd MAC。显式保存 p 需要 BPs_p 字节，h 物化另占 B(d+P)s_h。共享视图可以避免复制 z，但其最后消费者结束前必须保留原存储。\n\n准备包含 schema 变换、映射、CSR 构建、owner 路由、去重分组、dense 预打包及必要的缓存填充。同步包含生产者完成、传输可见、必需分片集合门控、合并和最终发布。驻留同时计表、dense 参数、活跃请求、接收槽、partial、交互、MLP 工作区和在途旧版本；预分配池与其中的对象不能重复相加。\n\n按表均匀分到 D 个设备、各请求只有一个 dense 所有者且分配与表位置均匀时，跨设备聚合向量主体约为 BFds_a(D−1)/D。真实计划应按请求—表位置求和，并另计输入路由、计数及消息控制。按列分片还可能需要点积归约或向量交换，不能直接沿用按表模型。\n\n时间须结合依赖与资源估计：同一 DRAM、HBM 或链路承担的服务量相加；独立工作可以重叠。单请求关键路径、每个资源的服务时间下界和批间流水周期分别建模，不能把全部阶段耗时相加，也不能把有依赖的串行阶段只取最大值。\n\n## 更新、取消与条件变化\n\n长驻状态包括表、映射、dense 参数、路由和缓存；单请求状态包括冻结输入、分片账、缓冲及输出身份。缓存键需要能区分模型/表示版本、schema、表、行及其版本。TTL 控制年龄，不证明旧行与新 dense 头兼容。\n\n一次版本切换轨迹是：请求 r 绑定 A_v 并取得读保护→提交 lookup→新请求开始绑定 A_(v+1)→旧请求继续读取 A_v→收齐同版本 partial→交互与两网络完成→在仍有效的请求资格下提交→最后读者退出后才回收旧对象。如果更新策略允许旧快照完成，不能仅因全局最新版本已变就把它混成新快照；若策略撤销旧执行资格，则阻止其未来提交并等待物理排空。\n\n若 r 在一个 partial 到达后取消，应关闭后继工作及发布资格；其余已提交读取、DMA
