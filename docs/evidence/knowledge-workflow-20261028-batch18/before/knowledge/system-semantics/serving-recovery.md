# K-SYS-014：推理服务恢复：提交边界、执行组与重试身份

恢复首先要确定哪些结果已经成为不可撤回的服务承诺、哪些状态仍可信，以及谁有权继续提交。超时表示尚未观察到所需结果；重新启动进程表示建立了一个新进程。两者都不能独立证明旧尝试没有提交、旧设备访问已经结束，或新实例能够继续原请求。

本章采用一个保守基线：固定模型与输入解释合同，在完整模型步骤边界发布状态；请求推进和接管经过共同的权威排序点；外部输出先登记为不可变逻辑事件，再由协议适配层发送。权威记录的持久性必须覆盖声明的故障域。若记录只存在于单进程内存，本协议只能讨论该记录仍存活时的恢复，不能承诺机器失效后的连续服务。

## 三个边界与恢复对象

令 x[0:A) 为某条保留分支已经确认的已知 token，S(p) 为完整模型恰好消费 x[0:p) 后的充分状态，下一次消费位置为 p。对当前确认分支，0≤p≤A；投机分支已经写入的更远状态另行登记，不能并入这个 p。普通全注意力 decoder 的 S(p) 包含全层 KV[0:p)，混合模型还可能需要递归状态、卷积历史、窗口及外部特征快照。

消费位置、确认位置和输出位置不属于同一坐标系。

| 记录 | 含义 | 恢复时不能据此推断 |
|---|---|---|
| p | 全部必需状态族共同有效的输入消费位置 | 已有下一条采样分布、已确认 p 个输出 token |
| A、x[0:A) | 保留路径的已知 token 及其确认边界，包含 prompt | 每个 token 都已有自身 KV |
| pending | 已确认但尚未消费的 token、位置和选择票据 | 应重新采样这些 token |
| E | 已提交不可变输出事件的数量，序号为 [0:E) | 全部事件已发出或已被客户端消费 |
| C_s | 当前协议流中顺序 send 成功返回的内容字节前沿 | 客户端已收到同样多的字节 |
| ack | 应用协议明确确认的连续事件或字节前沿 | 音频已播放、工具动作已执行，除非确认合同明确如此 |

prefill 消费全部 prompt 后，p=A；末行 logits 可以选择一个新 token，使 A 增加而 p 不变。下一次模型前向消费该 token 后，p 才增加。反过来，全部 KV 命中但未保存末行 logits 时，p=A 并不表示可以立即采样。

E 是本章选择的逻辑承诺边界。对外可见内容必须来自已经登记的事件，但登记的事件可以尚未发送。token 经过 tokenizer decoder、停止串过滤、编码或音频适配后才形成事件；一个 token 可以不产生内容，多个 token 也可以合成一个事件。因此不能要求 E、A、C_s 相等。输出适配器尚未发布的尾字节、跨 token 停止串匹配状态、音频 overlap 和 sample offset，也属于需要保存或可重放重建的控制状态。

恢复描述至少包含：

- 请求生命期 R、保留分支、可信租户命名空间和入口幂等键；同一键但规范化输入摘要不同应冲突。
- 计算身份 η：模型、权重、adapter、tokenizer/processor、输入与外部特征、位置规则、采样和约束配置，以及数值、布局与表示合同。
- 已确认 token、共同消费位置、可恢复的状态清单、pending token 或有效 logits，以及各对象的有效性和持有责任。
- RNG 的算法、状态或逻辑事件键，grammar、分支、停止判断和输出适配状态；不能把随机数消耗次数一概当作输出 token 数。
- 已提交输出历史、终态、客户端确认合同、deadline、重试预算及提交决定。

请求身份、执行授权代次 e、执行尝试 g、迁移事务 tx、执行组 incarnation 和物理分配代次分别回答归属、权限、尝试、传输、组身份与地址生存期，不能合并成一个地址或版本号。

## 权威提交与确认丢失

本章把权威记录抽象为能够串行排序请求提交、取消、接管和执行组失效的状态域。多控制节点需要提供等价的一致性；各节点分别加本地锁或根据自己的 timeout 选 owner，不满足这个条件。记录不可达时暂停依赖它的新提交，保留状态和访问责任；可用性损失不能通过同时授权多个 owner 解决。

对请求保存 H=(η,e,owner,g,v,phase,p,A,control,E,terminal)。v 是已提交语义快照版本；phase 区分 LIVE、FROZEN、RECOVERING 和 TERMINAL。另保存按提交身份 cid 查询的不可变决定。owner 只能是一个完整实例身份或空，包含进程/节点 incarnation；同名进程重启不继承权限。

模型工作只写本次私有候选。候选绑定预期快照 v、执行授权、执行组、输入范围、完整状态生产证据，以及本次选择后的 RNG、grammar、输出适配状态。不能先推进正式 RNG 或输出序号，再检查提交资格。对象字节可以先写入私有存储；它们在提交前必须完整、稳定且满足所需持久性，提交记录不能引用尚未完成的对象。

```pseudocode
算法 CommitCandidate(candidate)
输入：cid、不可变参数摘要、R、η、owner、e、g、group_incarnation、parent_v、候选
输出：原有决定、新 COMMITTED 决定，或拒绝及原因

在权威排序域内：
  若 cid 已有决定：
    参数完全一致：返回原决定，不再次安装状态、推进序号或启动执行
    参数不一致：返回 CONFLICT
  核对请求身份、η、LIVE、terminal 为空、owner/e/g 和 parent_v 均匹配
  核对实际执行组仍 OPEN，incarnation 匹配，本步骤全部必要 rank 证据齐备
  核对候选读取原快照，写区受保护，全部必需状态对应同一消费位置 p_new
  核对 0≤p_new≤A_old；新确认 token 只能延长原保留路径
  核对 RNG、grammar、停止规则和输出适配状态属于同一确认结果
  核对新输出事件延续 [0:E)，终态与最后事件没有冲突
  任一检查失败：不改变正式状态，候选进入撤销与排空
  否则原子安装：
    新状态描述、确认 token、pending、control、v+1 和连续输出事件
    若本次终止：安装唯一 terminal，关闭生成权限并撤销 owner
    保存 cid、参数摘要、提交结果和需要的恢复依据
  返回 COMMITTED

离开排序域后：
  按服务协议发送已提交事件；借用缓冲先取得消费者责任
  候选和旧对象按最后使用结束证据交接或回收
```

原决定查询先于当前授权检查，使“提交成功、答复丢失、随后已经接管或终止”的旧 cid 仍能查到成功。但返回历史成功不会恢复旧 owner 权限，也不会再次触发发送、采样或计费。重试若修改了候选参数，必须使用新的 cid 并重新满足当前资格。

确认丢失时先查询 cid。查到 COMMITTED 就沿记录恢复；查到确定拒绝才清理未提交候选；查询结果未知时保留可能被提交的对象，不猜测回滚。决定记录与去重墓碑的保留期必须覆盖允许的重试窗口；超出保留期应明确表示历史不可判断，不能把旧请求当作全新操作。

输出记录可作为 outbox，由独立输出器按 R、分支和 seq 顺序发送。已经提交的事件在接管后保留原 seq 和 payload，新的 e、g 或网络流身份不改变事件身份。ASGI response body 的 send 返回只证明内容进入服务器发送缓冲；发送失败也可能发生在部分内容已流出之后。没有应用确认与客户端去重时，只能报告交付未知或失败，不能宣称网络恰好一次。

有续传协议时，客户端按稳定事件身份去重、验证重复 payload 一致，并只确认连续前缀；服务端重发未确认的同一历史事件。重复确认幂等，越过已提交范围或无法证明连续性的确认应拒绝。事件内部的字节 offset 必须有独立定义。终止事件也参与顺序：只有客户端取得所需的全部内容及正常终止证据，才能认定完整成功。

正常完成后仍可交付既有 outbox。取消后按既定协议关闭新内容发送，已登记发送继续结算，历史不得改写。历史查询或断线续传是一项明确的协议能力，不使终止请求重新获得生成权。工具调用等外部副作用还需要接收方幂等键或可查询的业务决定；模型输出去重本身不能让外部动作恰好执行一次。

## 从可信状态重建下一步

状态恢复的输入是冻结的语义快照、目标计算身份、可用副本和资源预算，输出是未发布的完整 RecoveryView，或者具体的不可恢复原因。模型状态可以重算，不代表已提交业务结果可以重新选择。

对每个必需状态族 f，令 D_f 为当前对象、身份和表示合同下可直接恢复的位置集合。合法共同起点属于 D=∩_f D_f。全 KV 的长度、窗口的逻辑标签和递归检查点集合可能不同；取各族最大位置的最小值不一定得到交点。例如 KV 可恢复位置为 {0,2,4}，递归为 {0,3}，共同位置只有 0，不能返回 3。

从共同位置 c 恢复到 p，需要固定输入与特征 x[c:p) 全部可重放。重放消费已确认 token，执行完整模型图和必要 collective，产生 S(p)；它不再次采样、不推进正式 RNG、不追加输出，也不执行外部副作用。各层新状态来自本步低层输出，不能根据 token 和层号直接拼出高层 KV。递归、卷积和窗口更新必须使用对应位置的旧状态，并在全步骤完成后共同推进有效位置。

```pseudocode
算法 BuildRecovery(snapshot, target, capacity)
输入：η、p、A、已确认 token、控制状态、可用状态族与输入记录
输出：私有 RecoveryView(η,p)，或失败及待排空责任

核对目标模型、表示和数值合同；取得所需不可变输入与对象的保护
枚举共同恢复位置 c≤p；逐项核对各族、输入范围及目标资源
比较合法候选的复制、重放、排队与驻留成本，取得一个完整预留
无合法候选：返回缺身份、缺共同状态、缺输入或容量不足的具体原因

建立新 g、tx 和私有工作区，登记每项已接受或接受状态未知的访问
搬运 c 的状态；等待完整到达、转换和消费者可见依赖
对 t=c…p−1：
  消费固定 x_t 及本步特征，按模型层序计算完整步骤
  写入私有 KV、窗口、卷积及递归候选
  全部必要层和 rank 成功后，将私有共同位置推进到 t+1
  失败则停止后继提交，保留旧恢复依据并进入排空
核对全部必需状态恰好对应 p，恢复确认边界的 control 与输出历史
标记私有视图 READY；此时仍没有业务提交权
取得权威接管决定后才交给正式执行路径
```

枚举最大的共同 c 可以减少重放步数，但不保证最快：更早检查点可能已在本地，较晚检查点可能需要慢链路转换。容量也不一定随 c 单调。对尚未消费的 x[p:A)，接管后按已知输入继续前向，不能把它们当成待采样位置。

如果 p=A、没有 pending token 且需要继续生成，必须有对应前缀的有效 logits/末行表示，或者安排能重新产生末行输出的重放。普通全注意力模型可把合法历史读取视图截到 A−1，隔离共享末页写区，然后重算最后已知 token。递归模型不能只把长度减一：需要真实的 S(c)，其中 c≤A−1，再重放到 A。A=0 时只能使用模型合同规定的初始化、BOS 或其他起始输入；本章不假定存在凭空可用的空前缀 logits。已有终态的请求不为继续生成补算 logits。

精确恢复同一随机轨迹还要求相同的采样算法、随机定位和足够相容的数值执行。保存 seed 不保证跨 backend、平台或 PyTorch 版本逐位一致。已确认 token 必须固定重放；未来未确认选择采用逐事件相同、给定误差合同或分布合同中的哪一种，应事先声明。无法满足业务要求时应明确失败，而不是静默改变已经承诺的前缀。

## 分阶段迁移与唯一接管权

Llumnix v1 §4.2 利用旧 KV 不再改写的 append-only 前提，分阶段复制历史、追赶新增状态，最后在完整步骤边界暂停源端。每阶段先请求目标预留，目标容量不足、源请求完成或被抢占时中止迁移。这个机制减少停顿；它本身没有给所有故障模型提供持久请求恢复。

本章在数据迁移之外定义显式授权协议。复制事务 tx 绑定完整端点 incarnation、η、源 e 和阶段清单。阶段完成证明包含各必要状态族、逻辑范围、表示、目标分配代次和可见性，不能只统计收到多少条完成消息。物理分配与传输算法详见[分布式状态迁移](distributed-state-transfer.md)。

```pseudocode
算法 Handoff(R, tx, source, destination)
输出：唯一目标授权、确定中止，或保留责任的未知状态

准备阶段：
  目标取得相容执行组、联合容量预留和私有写区
  源固定每阶段不可变范围，登记源读、目标写及 staging 责任
  完成各阶段复制或 token 重放；目标不提交模型推进或新输出
  若追赶不收敛、预算不足、请求终止或任一端失败，转异常分支

冻结阶段，在权威域排序：
  按 tx 查询已有冻结决定；同参数重复调用返回原决定
  要求源仍是 LIVE owner、e/g 匹配、请求未终止
  原子关闭源提交权，e←e+1，owner←空，phase←FROZEN
  固定 v、p、A、control、E 与恢复描述，保存冻结决定

最终准备：
  取得冻结快照，补齐最终差量、pending 与全部控制状态
  验证目标完整恢复到该快照的 p；标记 PREPARED(tx,v,manifest)

接管阶段，在同一权威域排序：
  按 tx 查询已有接管决定；参数一致则返回原决定而不重新授权
  要求仍是本 tx 的 FROZEN 快照、v 未变、terminal 为空
  核对目标 incarnation、执行组 OPEN、容量与完整 manifest 仍有效
  原子安装目标视图，e←e+1，owner←目标，g←目标尝试，phase←LIVE
  保存不可变接管决定和剩余恢复责任

收尾：
  目标验证决定后开始执行；源永久失去旧 e 的提交权
  按实际最后使用和恢复保留策略结束源、目标临时对象的责任

异常或确认丢失：
  查询冻结/接管决定，不能用 timeout 推断决定不存在
  已接管：按目标 owner 继续恢复，源不得自行恢复执行
  尚未接管且决定可确定：权威域可以中止 tx，并以新 e 授权源或其他实例
  决定未知：暂停相关提交，保留可能已安装的视图及实际访问责任
```

冻结与接管分别增加 e，使源回退也必须得到新授权。旧 owner 在本地先读一次 e、稍后自行发布，仍存在检查与提交之间的竞态；资格校验与结果安装必须在共同排序点完成。网络分区中的旧 worker 可以继续浪费私有计算，但无法越过权威门提交。输出器只接受已提交的逻辑事件，不能允许旧 worker 绕过门直接发送新内容。

若量化组封组会改写旧编码或 scale，旧页不再满足本协议的不可变前提，应冻结该组、复制独立快照或把它留到最终阶段。窗口覆盖、递归原地更新和投机回滚也需要版本化快照；仅复制不同时间取得的各层状态不能组成共同 S(p)。无法提供稳定版本时，应放弃在线追赶，改用暂停后完整复制或从可信输入重算。

最后一个源副本释放前，必须明确剩余恢复依据。可保留源到目标确认、依赖另一份有效副本，或依靠覆盖所需故障域的持久输入与控制记录重算。仅在两台机器内存中迁移不能保证两机同时失效后的恢复。目标 PREPARED 后失效应拒绝接管；目标接管后失效则是新一轮恢复，不能复活源的旧授权。

## 执行组失败与请求恢复的衔接

TP、EP、PP 等执行组的成员需要执行相容计划。逻辑步骤键至少关联执行组 incarnation、请求/分支、e、g、快照 v、层/操作序号及参与集合。某个 rank 的局部完成不能证明整个模型步骤成功；相同形状也不能证明属于同一请求或同一层。

固定 NCCL Group Calls 文档区分成组发起与设备完成。组内单个调用可以在操作尚未入 stream 时返回；nonblocking group end 返回 IN_PROGRESS 时，需要等待涉及的 communicator 达到成功状态，才能执行依赖发起完成的相关 CUDA 操作。即使发起成功，也仍需实际设备完成与消费者依赖。group calls 不提供请求事务、跨 rank 回滚或本章的接管授权。

```pseudocode
算法 RecoverExecutionGroup(group_incarnation, failure)
输入：完整参与集合、已登记计划、每 rank 最早错误及在途账本
输出：新组 READY、明确失败，或保持隔离的未决责任

在权威排序域将旧组从 OPEN 改为 FAILED，禁止新准入与新步骤提交
使依赖该组且尚未提交的候选失去资格；保留已提交请求历史
与上述决定串行排序：
  COMMIT 在 FAIL 之前：保留其结果，故障不能追溯删除已提交事件
  FAIL 在 COMMIT 之前：拒绝该候选，其他 rank 局部成功也不能发布

停止旧组后继工作；按固定通信库、设备和传输适配合同处理错误
逐项保留已接受及接受状态未知的 kernel、collective、DMA 和消费者
取得最后访问结束或整个访问域可靠停止的证据；不能用超时代替
无法结算的范围保持隔离，不进入新分配池

建立新 group incarnation，重新核对 rank 到实际设备的映射
准备相同模型/adapter，重建 communicator、执行上下文、页表和必要图对象
全部必要 rank 完成共同准备与代表路径检查后，才发布新组 READY
对每个受影响请求，从其权威已提交历史独立规划恢复
取得新 e/g 后继续，或按 deadline 与恢复条件确定唯一失败终态
```

上述顺序不要求先等旧设备完全排空才使用其他隔离设备恢复；它要求新旧物理访问域确实隔离，并同时计入两份驻留。失效句柄、注册区和图对象不能因为地址相同就继续使用。请求取消也不能让一个 rank 单独跳过其他 rank 已经进入的 collective，应结算既有计划或共同结束受影响组。

本章不指定某个 NCCL abort 调用必然能够终止所有相关访问。具体中止、错误查询、跨 stream 可见性和上下文销毁的完成语义需要固定平台证据。没有该证据时，安全结果是保留未决责任，并采用经证明隔离的恢复路径。

## 故障矩阵与一条组合轨迹

| 故障位置 | 需要判定的事实 | 恢复与清理 |
|---|---|---|
| 准入或输入处理进程失败 | 幂等记录是否已接受，固定输入能否重放 | 查询原逻辑请求，撤销确定未使用的预留；不重复建立同键请求 |
| 单个计算 rank 退出 | 失败与步骤提交的权威先后，完整参与集合 | 关闭受影响组，从已提交快照重建；其他 rank 成功不能补齐缺失证据 |
| KV 部分传输失败 | 哪些范围被接受、哪些完成且可见 | 未完整目标不发布，旧访问排空后释放；重试用新 tx 或隔离范围 |
| 源在冻结前失效 | 最后已提交 token/control 与可恢复状态 | 放弃不可信候选，从权威历史恢复；没有足够记录则明确失败 |
| 源在接管确认期间失效 | tx 是否已经授权目标 | 查询决定；已授权沿目标继续，未知时不能同时恢复两个 owner |
| 目标准备或接管后失效 | 目标只是 PREPARED 还是当前 owner | 前者中止候选；后者重新 fencing 和恢复，不倒退到旧源授权 |
| 控制节点或提交存储不可达 | 权威记录是否仍可一致查询 | 暂停受影响提交；恢复查询后续接，不能分别按本地超时接管 |
| 磁盘、压缩或校验失败 | 缓存是否可重建，提交记录是否仍可信 | 失效对应缓存；控制记录丢失时不能借模型重算猜测既有输出 |
| 客户端断线或 send 异常 | 已登记、已发、交付未知与已确认的范围 | 按协议取消、失败或重发同一历史事件；保留借用缓冲的最后使用责任 |

下面设一个普通 decoder 请求，R 固定、源 e=7、v=12。prompt 长 4，已确认输出为 x4、x5，因此 A=6；模型只消费到 p=5，x5 是 pending。输出事件 seq=0、1 已提交，客户端只确认 seq=0。目标已经复制 S(4)，源还持有一条读取 S(5) 的传输票据 u。

| 事件 | 权威与模型状态 | 输出和资源后果 |
|---|---|---|
| 开始最终冻结 | owner 置空，e=8，固定 v=12、p=5、A=6 | 源不能再提交；x5 和 seq=1 不能丢失 |
| 目标补齐 | 目标取得完整 S(5)、pending x5、控制状态和输出历史 | 复制 S(4) 的成功不足以替代 S(5)；目标仍无 owner 权限 |
| 接管提交 | 目标取得 e=9、新 g，仍是同一确认历史 | 源 e=7 的迟到候选被拒绝 |
| 接管答复丢失 | 目标查询 tx，得到原 COMMITTED 决定 | 不再增加 e，不重复安装或重新采样 x5 |
| 客户端重连 | 在合同允许时重发原 seq=1 | payload 必须相同；若旧流实际已送达，由客户端去重 |
| 目标继续前向 | 消费已经确定的 x5，完成 S(6)，然后才能选择 x6 | 先消费 pending，不能在 S(5) 上重新选择一个 x5 |
| 源请求结束，但 u 未完成 | 逻辑 owner 已移走，源物理读仍在途 | 源页仍受保护，不能复用给其他请求 |
| u 的真实完成到达两次 | 第一次结算 u，第二次命中墓碑 | 不影响新 g 的任何票据；无其他持有者后才可回收 |

若目标在 S(5) 未完整时接管，可能混用不同位置的状态；若把 A=6 当成 KV 长度，会跳过 x5 的消费；若把 seq=1 未确认当成从未提交，会重新生成它。这三个错误的最终文本偶尔都可能看起来合理，必须分别核对状态位置、选择票据和事件身份。

## 条件化成本与恢复预算

比较候选时固定起点和终点，例如从检测到故障开始，到相同确认历史下的下一条新合法输出可交付。检测、排队、组重建、状态恢复、授权和输出恢复都是依赖图节点。令节点 j 的服务时长为 t_j，前驱为 pred(j)，在资源独立且无额外排队时，完成时刻满足 F_j=max(F_i，i∈pred(j))+t_j。共享 NIC、HBM、CPU 或存储还需加入服务顺序与争用；不能直接把所有阶段时间相加，也不能把有依赖的阶段全部取最大值。

| 成本 | 同一恢复候选应记录的工作 |
|---|---|
| 计算 | 校验、解码/转换、完整模型重放、无效候选、重新编译与预热；token 重建仍包含投影、MLP 和必要通信 |
| 访存 | 检查点读取、源状态读取、目标写入、转换读写、重放历史访问、输出重放；逻辑字节与实际设备事务分开 |
| 通信 | 状态或 token 传输、目标物理副本、组初始化、重放 collective、授权与输出历史查询；按方向和共享链路计量 |
| 准备 | 对象/清单解析、联合预留、注册、映射、执行组和图重建、版本校验；温热实例与冷实例不同 |
| 同步 | 发起确认、设备完成、目标可见性、全 rank 共同步骤、提交记录持久化和 fencing 查询 |
| 驻留 | 恢复副本、私有目标、COW、staging、输出历史、旧尝试隔离区及仍被消费者借用的对象 |

对每个设备或主机内存域，峰值为 M_peak=max_t Σ size(a)，求和对象是同一时刻占用预算的唯一物理 backing。完整池和池中存活对象不能重复相加；真实双副本必须分别计入。e 检查可以拒绝旧结果，却不能阻止旧 DMA 写地址，因此使用独立新范围恢复时必须保留旧范围的成本。

以普通 GQA 为设定，L 层、H_kv 个唯一 KV head、K/V 通道均为 d、每元素 b 字节，则每 token 逻辑 KV 为 B_tok=2LH_kvdb。取 L=32、H_kv=8、d=128、b=2 B，得到 128 KiB/token；4096 token 的冻结状态为 512 MiB，而 int64 token 记录为 32 KiB。目标分片或 head 复制会改变实际网络量，不能无条件再除以 TP。

设目标权重与执行组已经就绪、无排队，有效链路为 20 GiB/s，冻结 KV 的纯 payload 服务为 25 ms。再设转换 5 ms、授权提交 5 ms，且三者串行，状态接管为 35 ms。若相同终点的 token 重算需要 180 ms，则该路线约为 185 ms 加 token 搬运及尚未包含的准备；这里的 180 ms 是演算输入，不是设备测量。链路降为 1 GiB/s 后，KV payload 为 500 ms，复制路径约 510 ms，选择可能转向重算。若重算争用正在服务其他请求的 GPU，还应比较对其他请求造成的延迟，而非只看本请求恢复时间。

这个冻结复制设定中，源与目标各 512 MiB，两个 32 MiB staging 同时存活，跨两端 payload 驻留主项为 1088 MiB，尚不含权重、页表和工作区。若旧失败目标的 512 MiB 尚未排空，新目标另需 512 MiB，则主项至少升为 1600 MiB；旧尝试另有未释放 staging 时继续增加。跨节点合计容量不能替代每张卡的准入检查。

活跃迁移另有增长成本。设初始待复制状态 D 字节，新增速率 g 字节/s，有效复制速度 B 字节/s，忽略固定开销并假设复制与生成确实能重叠。r=g/B，连续在线阶段的待复制量为 D、Dr、Dr²…。做 k 个在线阶段后停止源，最终残量为 Dr^k，最终复制停顿为 Dr^k/B；总 payload 和总复制服务分别为 DΣ_{i=0}^k r^i 与 D/B·Σ_{i=0}^k r^i。只有 r<1 才有几何追赶机会，r≥1 时继续原策略不会缩短残量。

取 D=1000 MiB、g=10 MiB/s、B=100 MiB/s，三个在线阶段依次复制 1000、100、10 MiB，耗时 10、1、0.1 s；最终冻结复制 1 MiB，停顿 0.01 s。全过程为 11.11 s、1111 MiB，另加准备和提交。不能把 10 ms 停顿写成迁移总成本。实际共享资源争用可能同时降低 B、改变 g，因此需要观察阶段残量和期限，并允许提前冻结或放弃迁移。

检查点也有代价。作为简化推导，设每隔 τ 秒进行一次不重叠检查点，其成本 C 秒；独立、低频且相对检查点相位近似均匀的故障率为 λ/s。检查点开销率约 C/τ，故障丢失工作率约 λτ/2；只优化这两项可得 τ≈√(2C/λ)。它不包含固定重启时间、状态大小增长、持久化带宽、相关故障及 SLO，不能直接用作默认周期。组内独立恒定故障率下 λ_group 可相加；节点、电源或网络相关失效时，应改用实际故障域模型。

## 重试、过载与条件变化

重试在旧任务尚未结束时可能同时占用资源。逻辑请求 ID 解决业务去重，cid 解决结果提交重放，tx/范围 ID 解决传输重试，物理票据解决最后使用结算；任一层的幂等性不能替代其他层。

重试控制应同时约束活跃尝试数、总工作/字节额度、总时间与 deadline。退避减少同步重试峰值，但不能证明下一次有容量；每次重试仍须重新准入。预算耗尽或没有足够的剩余时间时，保存已承诺前缀并确定合适终态，不能隐藏此前失败后无限重试。

若单次失败概率为 f、各次独立且最多执行 m 次，期望尝试数为 Σ_{i=0}^{m−1} f^i；f<1 时等于 (1−f^m)/(1−f)，f=1 时为 m。这只是固定概率模型。过载会同时增加失败率和重试量，破坏独立假设；应以真实额外工作进入容量账。例如原工作需求为 0.8 倍容量，若期望工作放大到 1.5 倍，就会达到 1.2 倍容量，退避只能改变时间分布，不能让长期工作量自动可行。

| 条件变化 | 保留、调整或放弃的依据 |
|---|---|
| 请求短、故障少、输入完整可重放 | 保留提交与身份规则，可减少 KV 检查点，比较失败后完整重做 |
| 长历史、交互连续性严格 | 增加可恢复快照或副本，计入正常路径开销、输出历史和故障域；不只优化平均恢复时间 |
| 目标无同模型温热实例 | 加入加载、组建立、编译和预热；小 token 传输不能抵消冷启动 |
| B 接近或小于 g | 停止几何追赶假设；比较暂停复制、token 重算、迁移其他请求或中止 |
| 模型含覆盖状态、量化封组或投机分支 | 保留共同快照原则，增加版本化/COW；无法稳定快照时放弃在线复制 |
| backend、并行度、表示或随机算法变化 | 重核状态相容、重分片及复现合同；固定 token 可以重放，但未来结果不能凭 seed 承诺相同 |
| 控制存储不可达 | 保留唯一提交权，暂停依赖权威的新提交；不能以分裂授权换取表面连续性 |
| 旧尝试长期无法排空 | 隔离并计入容量；有独立新资源时恢复，否则终止或等待，不能提前复用 |
| 慢客户端或长时间断线 | 有界保留输出历史，明确续传窗口、确认粒度和超限行为；不能无限驻留或静默丢失未确认结果 |

## 竞争解释、区分实验与检查边界

诊断保留各 rank 的最早偏离、逻辑操作键、父快照版本、权威决定、输出序号和物理票据。最后一个 timeout 往往是连锁结果；跨设备时间戳没有可靠因果关系时，应保留多个最早失败候选，不能仅按墙钟挑一个根因。

| 观察 | 竞争解释 | 干预、预测与反证修正 |
|---|---|---|
| 重连后重复 token | 重新采样；outbox 重复安装；历史事件重传但客户端不去重 | 分别核对选择票据、cid 安装次数和稳定 seq。相同 seq/payload 的重传支持交付层问题，不证明模型重复推进 |
| 接管后第一个 token 错 | pending 遗失；KV 长度用成 A；末行 logits 缺失；数值合同变化 | 分别恢复 pending、保留末行 logits、从更早共同点重放；核对逐步消费位置。状态依赖修正仍有数值差异时再检查 backend |
| 迁移偶发分叉 | 源/目标同时提交；旧 parent_v 候选覆盖；状态快照不一致 | 在冻结、授权前后延迟旧结果并修改 v；同一提交点应拒绝旧授权和旧父版本。仅放大 timeout 不构成修复 |
| 单 rank 完成后请求被发布 | 完成集合漏成员；旧组证书串入；失败晚于提交 | 删除一个必要 rank、替换 group incarnation，分别安排 FAIL→COMMIT 与 COMMIT→FAIL；前者拒绝，后者保留历史 |
| 已取消请求仍写坏新请求 | 旧 DMA 仍在途；重复完成误扣新票据 | 一组保留旧 backing 但注入重复完成，另一组忽略旧逻辑结果却提前复用地址；分别检验账本和物理隔离 |
| KV 读取成功却无法恢复 | 必需递归/窗口快照缺失；输入不可重放；容量不足 | 构造非区间恢复集合、删一项输入、降低某个池容量，要求给出不同拒绝原因和合法回退位置 |
| 低停顿但其他请求变慢 | 链路/HBM 争用；CPU staging；目标重算挤占 | 固定迁移输入，分别限制复制流、移除重算或改变 CPU 额度；测全过程、停顿、实际字节与其他请求尾延迟 |
| 故障后吞吐持续下降 | 隔离资源未结算；重试放大；冷组重建 | 分别关闭重试、保留隔离但提供新容量、预建温热组；依据改变的阶段修正瓶颈，不以重启次数解释全部现象 |

随章检查采用确定性 CPU 符号模型：穷举源提交、冻结、目标接管、目标提交、取消和执行组失败的事件排序，以独立的事件位置判据核对允许输出；检查确认丢失后的幂等查询、旧父版本、完整 rank 集合、错误组代次和部分目标清单。故意忽略 fencing、重复安装、忽略父版本或漏 rank 的变体应被检测。

恢复检查以仿射递推的乘积求和展开式作为独立参考，覆盖共同检查点交集、空输入、末行输出缺失、输入记录缺口、容量回退及重放不采样。资源检查使用独立操作身份和重复完成负对照，检查 timeout 不解除在途保护。成本检查用精确有理数核对阶段增长、总字节与最终停顿。

这些检查覆盖有限协议与算术模型，完成/排空证书是模型输入。它们不验证真实模型 logits、任意 grammar、PRNG 分布、持久日志实现、跨控制节点一致性、GPU/NIC 可见性、设备中止、真实通信排空或性能，也不证明知识改善了 Agent 的系统构建能力。真实服务实验需要在预留、部分传输、冻结、授权、输出提交和最后使用前后注入故障，并保留固定环境、全部参与者终态、权威记录与实际资源峰值；CPU 模型结果不能记作 GPU 实测。
