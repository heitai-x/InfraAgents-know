# K-WORK-004：性能实验：稳定态、对照与不确定性

可比较的性能结果不是两个孤立数字，而是在声明任务、负载、初始状态、事件边界和估计量后，能够重建测量过程的证据。加载、预热、缓存、采集工具和候选搜索都可能改变被比较的对象。统计区间表达特定模型内的不确定性，不能修复计时漏项、任务变化或分母不一致。

## 测量对象、身份与可比性

一次测量计划写成 $M=(c,e,w,s,b,i,a,r)$：c 是候选身份，包括代码、权重、tokenizer/processor、配置、编译产物和确定性设置；e 是设备、软件、资源配额、NUMA、网络、功率及邻居负载；w 是逻辑输入与到达/依赖轨迹；s 是初始状态及重置/复用策略；b 是计时和完成边界；i 是采集方式；a 是聚合与估计量；r 是运行顺序、区组和重复层级。

记录使用运行、候选、区组、逻辑请求生命期和尝试序号关联。重试增加尝试，不增加原始逻辑任务；批次行号、连接号和复用后的请求字符串不能单独充当身份。候选不同是实验处理的一部分，不能要求候选身份相同；应要求处理之外的比较合同相同，或相应因素按预先声明的设计随机化。

合法比较至少需要以下条件：

1. 任务合同一致。模型函数、质量 oracle、权重、模板、停止规则、采样参数和输出要求须明确。量化、近似或模型切换可以作为处理，但必须通过共同任务的质量要求；缩短输出不自动成为效率提升。
2. 负载人口与依赖一致。输入/输出长度、租户、模态、前缀复用、会话和到达结构不能随意改变。多轮请求的后续输入依赖前序输出时，应比较共同应用合同；不能声称不同生成轨迹逐请求计算工作量完全相同。
3. 初始状态相容。前缀缓存、页缓存、allocator、编译/autotune 缓存、图池、连接、队列基线和功率状态属于测量条件。“warm”不足以说明命中长度、已准备路径和驻留对象。
4. 事件与时钟相容。主机提交、设备完成、首个可见内容、最终响应和质量通过是不同边界。不同主机或设备时间域之间相减，需要经过核验的映射及误差界；无法对齐时保留各自本地经过时间。
5. 聚合、分母和窗口一致。均值延迟、p99、请求吞吐、token 吞吐和 goodput 回答不同问题。失败、超时和窗口结束未完成者不能静默删除。
6. 环境与资源范围一致。同一机器仍可能有不同 CPU quota、NUMA 放置、MIG 划分、时钟、功率和邻居干扰。
7. 采集条件一致。服务计时、框架 profiler 和计数器 replay 改变执行的程度不同，不能把不同采集窗口混成一个成绩。

其中任务、单位、事件边界和身份是结论成立的条件。预热策略、缓存保留方式、采集细节、区组顺序和置信水平是需要声明的设计选择。不能在看到结果后挑选有利条件，再把它称作预定实验。

对请求 i，记实际发送、首个可见内容和最终响应时刻为 $s_i,f_i,c_i$，单位统一为秒，则 $TTFT_i=f_i-s_i$、$L_i=c_i-s_i$。缺少首内容的请求保留状态和缺失原因；不能删除后把剩余请求的 TTFT 解释为全部人口结果。

GenAI-Perf 的固定文档把 TTFT 定义为发送到首个响应到达，把 request latency 定义为发送到最终响应，并按相邻中间响应间隔除以较后响应生成的 token 数定义 ITL。因此客户端 chunk 数不等于模型 token 数。报告 token 间隔时，需要保存响应事件、分词器身份和 token 计数口径；合并 chunk 可以改变观测间隔而不改变模型计算。

对窗口 $[u,v)$，$T=v-u>0$，请求吞吐可定义为所选人口中满足 $u\le c_i<v$ 的最终响应数除以 T。它可能包含窗口前已发送、窗口内完成的请求；若只考察窗口内发送的 cohort，必须另加发送条件并说明删失。窗口结束后的完成不能回填分子。仅对窗口内完成者计算的延迟分布，是完成条件下的分布，不能自动代表全部到达请求。

## 冷启动、预热覆盖与测量状态

冷启动必须先指定起点。至少区分三类目标：

| 目标 | 起点 | 终点与输出 | 进入目标时间的工作 |
|---|---|---|---|
| 完整实例冷启动 FULL_COLD | 外层观察者触发实例建立或目标加载之前的 $t_0$ | 首次有效最终响应 $c_1$；另报就绪 $t_r$ 和首内容 $f_1$ | 从该边界开始的实例建立、加载、必需准备、等待和首次请求 |
| 已加载实例的冷执行 LOADED_COLD | 明确的加载完成事件 $t_l$，且目标执行路径尚未准备/执行 | 首次有效最终响应 $c_1$ | 加载之后的首次编译、autotune、图准备、触碰和请求；加载单列 |
| 稳定路径 STEADY | 必需准备完成且满足声明状态策略后打开的窗口 u | 固定窗口 v 及其冻结快照 | 窗口内执行与等待；准备成本另报 |

FULL_COLD 不默认包含机器启动、镜像下载或制品获取：这些是否属于 $t_0$ 之后的目标路径必须明确。进程新建也不代表驱动、文件页和编译缓存全冷。每次冷启动重复都要重新满足声明的状态策略；同一实例第二次执行不再是同一种完整冷启动重复。

令 $t_0\le t_l\le t_r\le s_1\le f_1\le c_1$，则

$T_{startup}=t_r-t_0$，$T_{cold}=c_1-t_0$，$T_{loaded\_cold}=c_1-t_l$，$L_1=c_1-s_1$。

$T_{cold}=(t_l-t_0)+(t_r-t_l)+(s_1-t_r)+(c_1-s_1)$。

这是同一时钟下按相邻里程碑切分的墙钟恒等式，各段可以包含内部重叠；不能再把段内每项累计设备时间全部加上。若加载和准备交叠，$t_r-t_l$ 只是加载完成后的剩余时间，不是全部准备工作量。就绪证明须对应目标模型、必需 rank、输入路径和资源范围；仅有“加载调用返回”不能代替就绪。

设定轨迹为：$t_0=0$，加载完成 $t_l=10$，必需准备完成并就绪 $t_r=12$，首次请求发送 $s_1=12$，首内容 $f_1=12.25$，最终有效响应 $c_1=13$，物理排空 $d_1=14$，单位均为秒。完整冷启动为 13 s，已加载冷执行为 3 s，请求延迟为 1 s，启动至就绪为 12 s，最终响应后仍有 1 s 排空。只记录发送到响应会漏掉 12 s；把 $T_{setup}$ 另列但不连接 $t_0$，也不能恢复完整冷启动估计量。若首次请求失败或超时，则报告启动失败/超时及已知里程碑，不以超时点冒充成功的 $c_1$。

测量控制状态可按下表实现。控制器可以先建立身份记录，但 FULL_COLD 的目标计时必须先于实例建立或加载动作。

| 状态 | 已成立的事实 | 后继 |
|---|---|---|
| COLD | 身份与初始策略已记录；尚未执行目标冷路径 | 完整冷启动先开启外层计时，再建立实例；稳态实例进入准备 |
| WARMING | 正在执行稳态预热，或冷启动所需的必需准备 | 覆盖及准备完成后 READY；错误进入失败和排空 |
| READY | 必需依赖、队列基线和声明状态满足 | 稳态此时打开窗口；冷启动外层计时继续 |
| MEASURING | 正在执行目标请求并记录事件 | 固定窗口结束或冷启动首次目标结果确定后 DRAINING |
| DRAINING | 不再提交新的目标请求；业务快照已冻结 | 物理责任全部结束后 CLOSED；到边界仍未结束则返回未决清理账 |
| CLOSED / FAILED | 成功关闭或已经失去成功资格 | 失败不覆盖既有窗口事实；仍在途责任继续保留 |

READY 只表示准备条件成立，不证明系统物理稳态。预热覆盖集合应由目标轨迹导出。路径桶可写为 $p=(操作,shape,batch,缓存状态,图/replay路径)$，必需集合为 $P^*$，每桶要求执行次数为 $k_p$。令 $h_p$ 为已经成功完成的预热次数，Q 为尚未完成的编译、autotune、捕获或首次触碰责任，则覆盖就绪要求

$\forall p\in P^*:h_p\ge k_p$，且 $Q=\varnothing$。

不能在提交时就增加完成次数。只预热 batch=1 不会证明 batch=32 的首次编译和工作区已准备。即使全部桶已执行，仍有异步准备事件未结束时也不能进入 READY。空必需集合在确实没有目标路径时集合条件恒真；非空目标负载却导出空集合属于计划错误。

稳定判断另行声明指标、窗口、漂移容限和停止规则。最近几个窗口的最大/最小比值只是工具规则，不能排除队列增长、周期性淘汰或功率下降。持续漂移时应调整设计、按阶段报告或保留未决，不能挑最快区间称为稳态。冷启动不做会消除目标首次成本的预热；为冷启动准备负载生成器时，也不能顺便执行目标模型路径。

## 区组、随机性与状态继承

用同一时间区组内的 A/B 运行控制时间漂移，并预先随机化或均衡安排先后。执行次序应以“区组 → 本区组候选顺序”展开；先跑完全部 A 再跑全部 B，不能仅靠事后按编号配对消除时间混杂。配对单位是独立运行或区组，不能把同一运行内强相关 token 当作独立重复。

随机顺序降低部分漂移偏差，但不能清除 carryover。B 可能继承 A 的页缓存、allocator、连接、编译产物和功率状态。若合同要求独立状态，应使用独立实例或经过核验的重置；若部署目标本就共享状态，应声明继承规则，保留顺序，并把结论限定于该规则。重置本身有时间、通信和驻留成本，不能凭“reset”标签认定状态已经相同。

固定 seed 只控制特定随机源。PyTorch 的固定资料明确不保证跨版本、平台以及 CPU/GPU 执行逐位一致。cuDNN benchmark 可以对新尺寸运行多种算法，并受噪声影响选择结果；关闭 benchmark 与要求算法本身确定性是不同设置。确定性算法和未初始化内存填充可能增加成本。比较时采用共同设置并记录算法选择状态；若研究的是最佳正常吞吐，也要保留这些运行间变化，不能只挑最快一次。

单因素对照用于识别机制，多因素组合用于评价最终方案。两者都应核对质量、实际输出长度、停止规则、重试与终止事件。候选变化导致输出轨迹不同后，可以继续比较应用层结果，但不能仍把耗时差全部归因于固定计算量下的 kernel 效率。

## 估计量、有效重复与区间条件

令 $Y_{g,b,j}$ 为候选 g、区组 b、请求 j 的指标，单位和人口预先固定。先说明目标参数，再选择估计量与区间。

### 均值比与逐对比值

平均延迟的比值可估为 $\hat\theta=\bar Y_A/\bar Y_B$，而逐请求相对变化的平均为 $\frac1n\sum_jY_{A,j}/Y_{B,j}$。它们不同：A=[1,9]、B=[2,8] 时，均值比为 1，逐对比值平均为 $13/16=0.8125$。前者按两个总体平均时间比较，后者给每个配对相对比值相同权重。不可配对的样本不能任意按位置建立逐对比值；分母为零时相应比值未定义。报告“加速比”须同时说明方向和估计量。

### 配对差值的精确与近似 t 区间

同一区组采用共同输入合同，可以定义区组指标差 $D_b=Y_{A,b}-Y_{B,b}$，负值表示 A 的延迟较低。对于固定样本量 $n\ge2$ 和预定 $0<\alpha<1$，常用区间为

$\bar D\ \pm\ t_{1-\alpha/2,n-1}\,s_D/\sqrt n$，

其中 $s_D^2=\sum_b(D_b-\bar D)^2/(n-1)$。需要区分：

- 若 $D_b$ 独立同分布于正态分布，方差有限且严格为正，配对和计时合同有效、无未建模的 carryover，学生化统计量服从自由度 n−1 的 t 分布，得到精确的固定样本覆盖率。
- 若差值不正态，iid、有限正方差使学生化均值在 n 增大时具有相应渐近性质，但某个实际 n 是否足够仍需依据。强偏态、稀有长尾和少量有效区组可能使近似很差；不能用统一的样本数门槛或“iid”标签保证小样本覆盖率。有限三阶绝对矩等更强条件有助于研究近似误差，但也不自动给当前样本足够精度。
- 方差不存在、强自相关、持续漂移、配对不成立或选择性停止时，不能直接套用该固定样本区间。观察到 $s_D=0$ 也不证明总体方差为零；若样本确实来自已知恒定机制，则应单独说明该退化模型。

设定 n=16、$\bar D=-2$ ms、$s_D=1$ ms，采用双侧 95%、自由度 15 的临界值约 2.131，代数结果为 [−2.53275,−1.46725] ms。它只核对给定统计量的计算，不证明真实差值正态、不保证长尾数据覆盖率，也不是未来单请求延迟的预测区间。

一个能反驳“iid 足以保证小样本 t 区间”的分布是：D 以 0.99 概率等于 −2 ms，以 0.01 概率等于 98 ms。总体均值为 −1 ms，方差为 99 ms²，样本可以独立且没有 carryover。16 次全为 −2 的概率为 $0.99^{16}\approx0.851458$；此时样本标准差为零，区间退化为 [−2,−2]，不覆盖均值。因此覆盖率至多为 $1-0.99^{16}\approx14.8542\%$，远低于 95%。这不是设备实验，而是有限离散模型的严格反例。

遇到近似依据不足，应增加真正独立且覆盖稀有事件机制的重复、改进分层设计或报告区间有效性未决。对已经观测到的 16 个相同值做普通 bootstrap，仍只会反复产生相同值；换成重采样不能创造未出现的长尾证据。

### 运行层方差与平铺池化

设 R 个独立运行，每运行 n 个请求，运行均值为 $\bar Y_r$，总体样本均值为 $\bar Y$。在共同运行人口、相同重复结构和相应独立条件下，使用

$S_{run}^2=\frac1{R-1}\sum_r(\bar Y_r-\bar Y)^2$，$\widehat{Var}(\bar Y)=S_{run}^2/R$。

这是方差估计，不自动赋予小 R 的 t 区间精确覆盖率；运行均值的分布仍须满足上面的精确或近似条件。非平衡运行还要先决定目标是等权运行还是按请求量加权，不能悄悄改变估计量。

两个运行各 1000 个请求，运行内分别恒为 100 和 200，则运行均值样本方差为 5000，均值方差估计为 2500，标准误为 50。把 2000 个请求平铺后按独立样本计算，均值方差为 $2500/1999\approx1.2506$，标准误约 1.118。增加同一运行内的请求不能消除运行间放置和环境差异。两个运行只是揭示平铺错误的算例，不是推荐的正式重复数。

在两层模型 $Y_{rj}=\mu+U_r+\epsilon_{rj}$ 中，若运行效应独立、方差为 $\tau^2$，运行内条件独立残差方差为 $\sigma^2$，各项满足模型独立条件，则

$Var(\bar Y)=\tau^2/R+\sigma^2/(Rn)$。

这一分解说明内层采样只压低第二项。S-STATS 的平衡嵌套随机效应模型进一步区分更多层级；它不自动覆盖配对设计、非平稳服务和任意尾分位数。

### 尾部、失败与重采样

p99 依赖尾部少量请求，需声明经验分位数的计算规则、样本数和人口。超时是失败或删失，不能伪造为成功延迟，也不能删掉后把快请求的 p99 当作全体结果。如果 SLO 要求 deadline 内成功，超时、质量失败和拒绝按共同 SLO 合同计入。

对预定阈值下 n 个独立同分布 Bernoulli 超限事件，固定样本观察零超限时，单侧置信度 $1-\alpha$ 的超限率上界为 $1-\alpha^{1/n}$，由零超限概率 $(1-q)^n$ 反解。n=100、α=0.05 时约为 2.95%；这不支持同等置信下超限率低于 1%。突发相关、漂移和选择性停止会破坏这个算例的前提。

层级 bootstrap 应从最高独立运行/区组有放回抽取，再按实际设计处理下层。独立两系统比较分别抽取其独立运行；配对比较则联合抽取同一区组的 A/B，不能拆散配对。只有下层条件独立的模型才支持相应逐层重采样；时间相关数据需要保留块或使用更高层独立重复。每个复制重新计算目标均值、比值或分位数，最后按预定分位数规则取区间。复制次数减少数值模拟误差，不能弥补原始独立块太少、长尾未出现或非平稳等问题。

## 工具扰动与条件化成本

工具提供的证据范围不同。服务计时连接发送与用户结果；框架 profiler 连接操作、设备工作、shape、调用栈和内存；kernel 计数器解释代表执行的硬件活动。诊断收益最终需要在共同负载的正常执行中确认。

| 成本 | 具体来源与条件 | 核算边界 |
|---|---|---|
| 计算 | 计划生成、分词、序列化、时间戳、事件处理、聚合、栈与形状采集 | 客户端和服务端 CPU 分开；profiler 可改变目标执行本身 |
| 访存 | 输入/输出、事件表、保留张量、replay 保存恢复和缓存刷新 | 逻辑对象字节与设备事务不同；缓存状态是处理条件 |
| 通信 | 请求与流式响应、连接建立、日志导出、设备保存区溢出后的主机传输 | 区分关键路径通信与后台导出，不能因后台完成晚而全额计入请求延迟 |
| 准备 | 实例建立、权重加载、编译、autotune、图捕获、首次触碰、计数器配置 | FULL_COLD 进入目标链；STEADY 另列而不从运行总账消失 |
| 同步 | 测量起止、事件查询、全设备屏障、range 边界与缓存刷新 | 同步可能破坏生产重叠；host 返回不是设备完成证明 |
| 驻留 | 权重、KV/工作区、allocator/图池、profiler 保留引用、replay 备份和日志缓冲 | 同一时刻按唯一 backing 去重；池容量不再加池内对象 |

框架 profiler 的 schedule 区分等待、预热、记录和记录后保存，由调用方推进步计数；未记录窗口不能解释为没有工作。形状与栈采集增加开销，部分形状跟踪保留张量引用，可能改变生命周期与引用计数相关优化。所供 profiler.md 原文是文档生成入口，未展开这些 API 说明；这里的 schedule 和引用机制依据完整来源说明，不声称本轮独立核验了展开后的上游 API 或源码。

Nsight Compute kernel replay 将一个 kernel 实例所需指标分到一个或多个 pass。多 pass 时先保存 kernel 可访问的 GPU 内存，识别被写子集，并在后续 pass 前恢复该子集；只有单 pass 时工具不做该保存恢复。备份优先使用可用的相应快速存储，设备容量不足时可能转移到主机，因此保存区会同时改变驻留和通信成本。

默认情况下工具在每个 replay pass 前刷新 GPU 缓存；生产路径可能依赖此前工作建立的热状态。Application replay 重跑完整应用，无须工具保存恢复该 kernel 内存，但重复主机启动、准备和文件访问，并要求 kernel 活动及 GPU/context/stream 等分配可匹配且具有确定性。Range replay 捕获 API/kernel 范围，可保留范围内并发，指标属于整个范围；范围开始的同步、支持的 API 和主机内存恢复条件限制其适用性。共享 MIG 单元的指标可能无法采集，缺失不能写成零。

在串行重放的范围内，可条件化写成

$T_{replay}=T_{config}+T_{save}+\sum_{p=1}^{P}(T_{kernel,p}+T_{collect,p}+T_{flush,p})+\sum_{p=2}^{P}T_{restore,p}$。

单 pass 时 $T_{save}=0$，恢复和为空；关闭缓存刷新时相应项为零。P 取决于指标集合、硬件和采集机制，不是固定常数。此式不是无采集 kernel 的耗时，也不覆盖 application replay 重复的全部主机工作；range 内有并发时，应按范围关键路径计算，不能用 kernel 耗时总和替代墙钟。

一次实验可以按不交叠阶段记 $T_{run}=T_{setup}+T_{warm}+T_{measure}+T_{drain}+T_{export}$。若导出与测量交叠，应改用区间并集或关键路径，不能再次相加。FULL_COLD 的目标时间可能跨越 setup 和首次执行；它不能直接替换成稳态的 $T_{measure}$。

若有 E 个事件、每条序列化大小约 b 字节，日志载荷约 Eb，索引与压缩工作另计。已有有序事件的审计扫描通常为 O(E)，乱序事件需排序时为 O(E log E)；全日志占 O(E)，在线活跃请求、路径桶和物理责任另占状态空间。这是模型复杂度，不是实际工具开销测量。

重复预算同样有条件。两层模型中，设每次运行准备成本为 $c_0$，每个内层样本成本为 $c_1>0$，总预算为 C，平衡设计满足 $C=R(c_0+nc_1)$。代入方差分解，随 n 变化的项为 $c_1\tau^2n+c_0\sigma^2/n$；当两层方差均为正、连续近似和成本模型有效时，驻点为 $n^*=\sqrt{c_0\sigma^2/(c_1\tau^2)}$。实际需取合法整数并保留足够独立运行。运行效应为零、内层强相关、冷启动不可重复或成本随 n 改变时，不能沿用该驻点。这解释了准备很贵时增加内层采样可能有利，也解释了运行间差异大时继续加 token 样本价值有限。

## 从计划到确认的完整算法

以下算法输出事件、冻结快照、启动指标、请求指标和统计结论。模型模式只能消费显式给定的事件，实测模式必须等待真实完成证据，不能按名义延迟伪造时间戳。

```pseudocode
算法 MeasureAndCompare(G, E, W, S, B, I, R, D)
输入：候选 G；环境 E；负载/依赖 W；状态策略 S；边界 B；
      采集配置 I；区组、顺序和固定重复计划 R；决策规则 D
输出：完整记录、比较资格、估计量/区间、接受/拒绝/未决及清理责任

1 校验身份、单位、目标人口、非空目标、依赖存在且无环
  B 声明 FULL_COLD、LOADED_COLD 或 STEADY、成功终点和失败规则
  固定质量 oracle、聚合方向、窗口端点、置信水平和停止规则
  按 W 推导必需路径桶及完成次数；非空目标不得得到空路径合同
2 创建日志，键包含 run、candidate、block、request-life、attempt
3 按预定时间区组 b 顺序：
    按 R 中本区组预定的候选顺序运行：
        result[g,b] = RunArm(g,b,E,W,S,B,I)
        保留全部结果，包括启动失败、请求失败、不可推进和清理未决
    检查各候选实际任务、环境、负载、状态策略、边界及采集合同
    有未授权差异则该区组不可比较，记录原因
    一侧失败不删除该侧或将另一侧提升为完整配对
4 对每个区组分别生成：
    启动成功/失败与 t0、tl、tr、f1、c1；缺事件的量保持未定义
    冻结窗口计数、发送与完成 cohort、超时/失败/拒绝/未完成项
    请求指标及实际 token、chunk、质量和重试计数
5 对可比较记录计算预定估计量：
    差值按区组配对；比值检查分母；层级聚合保留真实独立单元
    区间方法先检查精确模型或近似依据；不足则输出有效性未决
    不能以删除失败、改变人口或增加内层重复修复缺失配对
6 探索阶段保存全部候选和淘汰原因；选择后冻结实现与验收规则
  用未参与选择的确认区组重跑步骤 3 至 5
  质量不通过则拒绝；性能区间无有效依据或跨决策阈值则未决
  否则按预定方向及最小有意义效果接受或拒绝
7 输出证据范围、未测条件和物理责任；不把未决写成成功

过程 RunArm(g,b,E,W,S,B,I)
1 建立控制器元数据；校验并记录声明的冷/热状态，置 COLD
  准备外层低扰动观察者和时钟，不提前执行目标加载或模型路径
2 在触发实例建立或加载之前记录 t0
  若目标为 FULL_COLD，此刻开启目标计时
  建立实例、加载目标制品，消费真实加载完成证据，记录 tl
  若失败：记录失败与已知里程碑，停止新提交，进入失败排空
3 若目标为 LOADED_COLD，从 tl 开启该目标计时；加载耗时独立保留
  对两个冷目标：只做执行所必需的准备，不做消除首次成本的预热
  对 STEADY：
      置 WARMING；初始化每桶成功完成次数 hp=0、待决责任 Q
      提交可覆盖未完成桶的预热，先登记责任再交付执行
      消费完成事件；成功完成才增加对应 hp，解除匹配的 Q 项
      重复至全部 hp>=kp 且 Q 为空
      无即时进展但有待决事件则等待；达到期限或无唤醒来源则失败
4 核验必需 rank/输入路径、队列基线、缓存策略和准备完成证据
  记录 tr，置 READY
  FULL_COLD 与 LOADED_COLD 计时保持开启，不在 READY 重新归零
5 置 MEASURING
  STEADY 此时打开固定窗口 [u,v)，按 W 发送
  冷目标按预定规则发送首次目标请求；记录等待以及 s1
  对每个请求消费 send、first-visible、final、quality、timeout 等事件
  验证身份与次序；重复通知幂等；业务终态最多提交一次
  缺失事件保持缺失，不能凭后续事件猜测更早的首次事件
6 STEADY 到 v 时按半开端点冻结窗口快照，停止新的目标提交
  冷目标在首次成功完成边界记录 c1，并输出 c1-t0 或 c1-tl
  若首次目标失败/超时，则输出失败，不制造成功 c1
  若成功终点包含质量检查，等待其真实结果并使用相应终点
7 置 DRAINING，停止后继业务发布，继续消费已提交工作的物理完成
  迟到结果追加在排空日志，不修改冻结窗口和已有业务终态
  物理责任全结束则 CLOSED；到 drain 边界仍未结束则返回责任账
  错误失去成功资格后，即使后来收到成功事件也不恢复资格
8 返回日志、启动指标、窗口快照、状态与清理未决项
```

关键不变量是：FULL_COLD 起点早于被计入的首次建立/加载；稳态窗口晚于所有必需准备完成；完成次数来自完成证据；比较保留相同人口及配对关系；窗口快照和业务终态不能被迟到完成改写；业务失败不解除尚未结束的物理责任。

算法进展依赖准备事件、资源释放和请求结果最终可发现。必须有等待期限和失败出口，不能在没有任何唤醒来源时忙等，也不能因超时就假定设备访问已经结束。启动成功、业务完成、窗口关闭和物理排空分别提供不同证据。

## 竞争解释、反证与条件变化

| 观察与竞争解释 | 区分干预 | 预测及修正 |
|---|---|---|
| 首次运行慢：加载或首次执行准备 | 从建立前记录 t0，并记录加载、就绪、发送和结果；分别比较三类目标 | 总冷启动变化而请求延迟不变支持准备成本解释；仅请求计时不能否定加载变化 |
| 大 batch 首次慢：预热漏桶或真正规模效应 | 完成目标桶覆盖，检查待决准备，再重测首次与后续 | 首次差异消失支持冷路径；持续差异要求重查计算、容量或资源 |
| B 后跑更快：优化或继承 A 的缓存 | 独立实例/显式重置，并均衡先后 | 隔离后收益消失支持 carryover；保留则说明它不是唯一解释 |
| profiler 下更快：正常优化或观测效应 | 同负载做采集开/关，逐项改变 shape/栈与窗口 | 仅详细采集下有收益，支持生命周期或同步被改变；正式结论回到正常路径 |
| replay hit rate 变化：生产瓶颈或工具缓存状态 | 对比缓存刷新条件、pass 数及正常服务时间 | 计数变化而服务时间不变，不能据计数宣称生产瓶颈已改善 |
| 平均差稳定且区间极窄：真低噪声或漏掉长尾/运行层 | 增加独立启动/时间区组，保留稀有事件与运行身份 | 内层增加而运行差异不减，否定平铺独立模型；全同样本不证明零总体方差 |
| 吞吐变高：容量改善或积压增长 | 同到达轨迹记录到达、完成、期初期末积压和未完成 | 积压持续增加时，只支持有限窗口完成率，不能支持长期稳定容量 |
| 延迟变短：效率提高或输出工作量减少 | 固定任务、停止和质量合同，记录实际长度 | 控制长度后收益消失，修正为任务量变化解释 |
| 探索最佳值很高：真实效应或选择噪声 | 冻结候选，在未参与选择的区组确认 | 效应明显缩小支持选择噪声；保持也只支持确认范围 |

干预前写出可否定预测。例如减少权重读取预计改善小 batch decode，但大 prefill 可能受计算限制；需选择能区分两种解释的 shape 和字节/时间观测。若最终时间改善而预计字节变化没有发生，应修改机制解释，即使候选仍可保留。一次全设备同步同时改变依赖、并发和缓存，异常消失不能唯一定位缺失的同步边。

条件变化后应重新建立相应合同：shape/batch 变化重建路径桶；缓存策略变化重新定义初始状态与驻留；版本或平台变化重核随机性、计时和工具能力；多 stream 或多实例变化重核资源作用域与重复层级。可以保留任务身份、边界和守恒关系，但不能直接沿用旧准备证书、计数器常数或独立性假设。

探索记录候选、失败和试过的范围，确认阶段冻结代码、权重、配置及规则。固定样本区间不能支持不断查看直到显著的停止方式；需要预先设计或使用适用的序贯方法。确认区间跨过最小有意义效果时，增加有效重复或报告未区分，不能把单次最好值当作结论。

## 离线检查与证据范围

配套检查为 `tools/check_k_work_004_full.py`，采用 Python 标准库、精确有理数和有限枚举，确定性、离线、只读。它检查比较合同、预热覆盖及待决责任、冷启动边界、两种比值、运行层方差，以及稀有长尾反例；不实现真实负载生成器、profiler 或 GPU 时间测量。

冷启动参考由预先给定的加载、准备、发送等待和请求持续时间独立求和，再与事件端点计算比较；含加载为零、非零准备、发送等待及排空等边界。故意只计发送到完成的版本在非零加载轨迹上被识别。层级方差同时与成对平方差恒等式及绝对参考 2500 核对；平铺版本在增加内层重复后被识别。

t 区间检查只是给定临界值的算术器，不是正态性判定器。脚本按 16 次试验中稀有事件数 k=0…16 枚举二项概率，以独立的计数均值/方差公式核对区间计算，并验证全部概率和为 1、全普通值样本不覆盖真实均值，以及覆盖率上界低于 15%。这反驳 iid 自动保证 95% 覆盖率的错误规则，不证明真实服务分布满足任何区间模型。负对照数量由实际成功区分的记录计算，不使用固定 PASS 数代替断言。
