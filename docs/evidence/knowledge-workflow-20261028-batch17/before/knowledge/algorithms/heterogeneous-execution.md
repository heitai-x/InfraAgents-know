# K-ALG-020：CPU–GPU 计算放置：传数据、传结果与共同提交

异构执行可以按层、算子、输出分片、归约分片或专家分配计算。决策比较的是同一函数的完整依赖路径：把主存中的权重搬到 GPU，还是让对应计算留在 CPU、只交换输入和结果。容量、共享带宽、准备、同步和结果归属都可能改变选择，孤立峰值算力不能决定答案。

## 问题、对象与状态

设一层或算子为 $Y=F_θ(X;S)$。X 是输入，θ 是权重，S 是本次计算读取的状态快照，例如 KV、mask、位置和归一化参数。本章展开一次层输出的计算与发布；它不自动等同于整个请求的 token 提交。若算子更新可变状态，必须另外保证私有更新与输出的安装边界相容，不能在失败前先改写共享状态。

执行单元为 $u∈{c,g}$，分别代表 CPU 和 GPU。放置计划 π 给出权重和状态的驻留位置、任务分片、读取范围、表示与布局、输入准备路径、结果合并位置和所需缓冲。计划本身也必须有不可混淆的版本身份。

冻结执行身份为

$J=(r,ℓ,g,v,p,w,k)$，

分别表示请求、层或算子、执行代次、输入版本、计划版本、权重版本和状态版本。J 绑定完整分片表与数值契约 κ。缓冲地址、shape 或可复用槽号不能替代 J；它们相同不证明 mask、位置、权重或输入内容相同。

每个分片有阶段、私有结果和独立物理访问责任。非空分片从 READY、SUBMITTED 推进到 DONE 或 FAILED；空分片记为 DONE_EMPTY。整代另有 WAITING、MERGING、MERGED、COMMITTED 阶段，以及取消、失败和当前提交资格。DONE 表示完整结果已经在合并端可读且生产者不再写入，不只是 CPU 算完或复制已提交。DONE_EMPTY 是成功终态，表示该分片按冻结计划没有贡献，也没有访问需要等待。

输入、权重和状态快照在所有读取结束前保持不变。版本切换应撤销旧执行的未来提交资格，并保留旧读者需要的物理对象，不能仅修改版本号后原地覆盖内容。

## 分片合法性与同一函数

### 按输出通道切分

对于 $Y=XW$，X 为 $M×K$，W 为 $K×N$。令完整通道集合 $C={0,…,N−1}$，分成互不重叠的 $C_c$ 和 $C_g$，且并集为 C。每个分片计算

$Y[:,j]=Σ_{t=0}^{K−1}X[:,t]W[t,j]$，$j∈C_u$。

双方各自完成完整 K 归约，最后按原通道位置 scatter。分片可以非连续、长度不整除或一侧为空，但必须保留原位置映射。bias 与逐元素 epilogue 可以在对应输出拥有者上应用一次；跨通道的 norm、softmax 等操作必须等完整输入就绪，除非另有可合并统计量。

按输出通道切分在实数上保持同一矩阵乘法，却不自动保持浮点逐位一致。CPU 和 GPU 可能使用不同累加顺序、矩阵指令、中间精度或舍入方式。

### 按归约轴切分

若 $Z=Σ_{j∈C}b_j$，先分别计算 $Z_u=Σ_{j∈S_u}b_j$，再合并 $Z=Z_c+Z_g$。归约集合仍须互不重叠且完整覆盖。bias 通常在合并后加一次，不能在两个部分和里各加一次。一般也不能先局部应用非线性：例如部分和为 −2 和 3，合并后 ReLU 得 1，而局部 ReLU 再相加得 3。

Attention 的 softmax 可以通过统计量合并。对一行 query，设合法位置分数为 $a_j$，value 为向量 $V_j$。非空分片保存

$m_u=max_{j∈S_u}a_j$，

$ℓ_u=Σ_{j∈S_u}e^{a_j−m_u}$，

$U_u=Σ_{j∈S_u}e^{a_j−m_u}V_j$。

先令 $M=max_u m_u$，再计算

$ℓ=Σ_u e^{m_u−M}ℓ_u$，$U=Σ_u e^{m_u−M}U_u$，$O=U/ℓ$。

分片必须使用同一位置、mask、分数尺度、指数底数、value 表示和状态版本。空分片不参与最大值与指数计算。全部为空时返回预先声明的空行结果与标志，或按接口拒绝；不能执行除以零。配套模型选择零向量加 empty 标志作为空行契约。非空公式以合法位置分数有限为前提；NaN、正无穷等情况需要单独数值契约。

这个合并在实数上等于完整 softmax。直接等权平均各分片已经归一化的输出会丢掉分片的概率质量，即使输出 shape 正确也可能错误。

### 数值与近似契约

至少区分逐位一致、容差一致、argmax 等离散选择一致，以及分布或任务质量要求。浮点非结合性、批量与切片路径、平台和中间精度都会影响误差；固定 seed 下偶然生成相同文本不能证明这些契约。

稀疏预测还会改变工作集合。已知真零可以在精确契约下跳过；预测为零但实际非零则必须补算、验证，或明确进入允许近似的质量契约。热点放置与跳过贡献是两个决定，不能把前者的合法性当成后者无损的证明。

## 从驻留位置到结果可读

以输入最初在 GPU、冷权重在主存、合并端在 GPU 的输出通道切分为例，一条完整数据流如下。

| 对象与阶段 | 数据流与完成条件 | 保留到何时 |
|---|---|---|
| 冻结输入 X | GPU 分片直接读取；CPU 所需输入经 D2H 到可读主存，必要时转换布局 | GPU 读者与输入复制都结束；主存副本保留到 CPU 最后读取 |
| CPU 冷权重 | 按通道表读取主存权重，必要时使用预打包 panel；线程独占各自输出 | CPU 计算真实结束；旧版本仍有读者时不能覆盖 |
| CPU 私有结果 | CPU 写完后，作为 H2D 的源，复制到本代 GPU staging | CPU 写完且 DMA 不再读取源；目的 staging 保留到合并读完 |
| GPU 私有结果 | GPU 计算指定通道，完成事件证明本代结果在合并端可读 | 合并最后读取结束 |
| 合并目标 | 合并队列等待 GPU 结果和 CPU 结果 H2D 完成，再按原位置 scatter | 发布后保留到全部下游读者结束 |

CPU 计算完成时，如果结果还在主存等待 H2D，分片尚不能记为 DONE。反过来，CPU 工作集合为空时，无需建立一次没有数据或贡献的传输与同步。统一地址或物理共享内存可以改变复制路径，却不取消生产完成先于消费、最后读取先于覆盖的关系。

这里映射的是跨设备任务、对象和事件。CPU 核内向量化与 GPU kernel 内部 lane 布局由各自执行器实现；不能从这条任务时间线推定某种矩阵指令、设备可见性或 kernel 内部重叠已经成立。

## 完整混合执行算法

下面采用单一串行状态拥有者处理完成、取消、版本失效和提交事件；执行器并发计算。所有访问责任先登记再启动。结果接收与物理访问结算分别处理：旧事件不能推进当前结果，但仍须由旧代对象的责任账处理。

```pseudocode
算法 ExecuteHybridLayer(J, π, X, W, S, κ):
  输入: 冻结身份 J、计划 π、稳定输入/参数/状态快照、数值契约 κ
  输出: 共同提交的完整 Y，或 REJECT/FAILED/CANCELED

  1. 检查与预留
     检查分片无重叠且覆盖全部必需范围，原位置映射与归约方式合法
     检查 dtype、布局、mask、位置、尺度及 κ 相容
     检查 J 与快照、计划身份一致，取得快照读取保护
     按唯一物理范围检查容量，预留私有分片结果、staging 和 merge_buf
     任一条件不满足则释放未使用预留，返回 REJECT
     初始化 canceled=false、failed=false、committed=false、整代阶段=WAITING
     在当前执行登记事务中冻结分片表，设置 active[r,ℓ]=J

  2. 建立并启动分片
     对每个单元 u:
       若 S_u 为空:
         phase[u]=DONE_EMPTY，结果[u]=该输出集合或归约的空贡献
       否则:
         phase[u]=READY
         为输入准备、计算和结果搬运登记各自访问责任
         输入可读且目的空间已独占预留后，phase[u]=SUBMITTED
         启动执行器；部分提交或启动结果不明时保留隔离责任
     执行器按依赖完成输入准备、计算与结果搬运
     中间完成只结算所覆盖的物理访问，不冒充完整分片成功
     最终通知携带 (J,u,分片范围,结果句柄,状态,完成证书)
     证书须证明完整结果在合并端可读，且生产者不会再修改它
     调用 MaybeStartMerge；两侧均为空时也经过空输出/空行契约

  3. 接收完成，所有状态处理均在同一串行状态域内
     收到完成 e:
       用原对象、分配代次、访问责任与范围查找相应责任账
       验证证书覆盖范围；只幂等结算有真实最后访问证据的责任
       错误通知、超时或不完整证书本身不证明访问已结束
       若 e.J≠J，或 u 未登记，或是已接收最终完成的重复通知:
         不改变当前代 phase、结果或 visible；旧责任由原账结算
       否则若范围/结果所有权不合法，或执行失败:
         failed=true；不启动合并或提交；保留未证明结束的访问责任
       否则若 phase[u]=SUBMITTED 且完整结果证书有效:
         保存本代私有结果句柄，phase[u]=DONE
         调用 MaybeStartMerge
       否则:
         不补齐成功集合；等待必要证据或按错误处理

  4. MaybeStartMerge
     成功终态(u) := phase[u]=DONE 或 phase[u]=DONE_EMPTY
     仅当整代阶段=WAITING，所有分片均为成功终态，且
       未取消、未失败、active[r,ℓ]=J 时:
       整代阶段=MERGING；登记合并的读写责任，然后启动合并
       输出通道切分: 按原位置 scatter 全部分片到 merge_buf
       归约切分: 合并完整部分和；attention 按 (m,ℓ,U) 合并再归一化
       最后应用必须看到完整输入的 epilogue
       空分片直接提供空贡献，不读取不存在的结果句柄
       合并读取结束前禁止覆盖任何被读取分片
     条件未满足时等待后续真实事件，不读取尚未就绪的结果

  5. 接收合并完成
     在同一串行状态域中检查合并身份、首次完成和证书覆盖
     合并失败则 failed=true，不发布；仍等待真实访问排空
     合并成功且完整写入完成则整代阶段=MERGED
     合并结束与提交之间，取消或失效仍可撤销提交资格

  6. 共同提交事务，与取消/失败/版本失效处理串行化
     重新检查整代阶段=MERGED、所有分片为成功终态、J 完整匹配、
       active[r,ℓ]=J、未取消、未失败且 committed=false
     条件成立时，在一次不可分割事务内:
       将 merge_buf 的发布所有权交给 visible[J]
       committed=true，整代阶段=COMMITTED
       在交出地址之前登记下游消费者责任
     条件不成立则不提交；不得把任一局部结果发布为完整层

  7. 取消、版本失效与清理
     取消或失效先撤销未来提交资格，停止尚未启动的后继工作
     对已登记但能证明从未启动的责任，安全撤销登记
     取消先于提交事务处理: 本代不得发布
     提交事务先完成: 后来的取消不撤回已经提交的事实
     对未提交代，等待已启动的 CPU/GPU/DMA/合并访问真实结束
     对已提交代，还要等待所有输出消费者结束
     只有相应物理范围再无读写责任时才回收；未知结束则隔离并报告
     返回已提交结果，或在排空后返回 FAILED/CANCELED
```

成功推进有三个不同边界：最终分片通知被接受后进入 DONE；全部分片处于 DONE 或 DONE_EMPTY 后才能开始合并读取；合并完成后，提交事务再次检查资格再发布。串行拥有者也可用具有同等线性化语义的锁或事务实现，但不能把资格检查和结果安装拆成无保护的两步。

核心不变量是：可见完整输出只包含同一冻结身份的完整贡献，任何局部完成、失败、取消或旧代通知都不能单独推进下游。结果身份门控不能阻止旧物理写者破坏新对象，旧范围仍须保留到真实最后访问结束。

安全性不等于进度保证。正常推进还依赖所需输入最终到达、任务与搬运最终完成、事件得到处理，以及足够容量。超时不能替代成功完成或物理排空证明。

## 成本、容量与共享资源

### 同一候选的完整账

计算包括 CPU 冷部分、GPU 热冷部分、预测器、部分归约和最终合并。访存包括各自权重、激活、KV、staging 与合并读写；通信统计实际跨链路字节及事务放大，不能把逻辑张量大小直接当作所有边界的流量。

准备包括离线统计、计划生成、权重打包、线程组织、布局转换、锁页注册与任务提交。可复用准备成本 $T_p$ 在 R 次合法复用中的平均项为 $T_p/R$，但首次调用仍承担实际准备延迟；输入或表示改变后不能继续使用旧打包结果。同步包括完成通知、依赖等待与串行提交，等待时间按依赖路径计算，不能把已经包含的计算或传输重复相加。

容量按每个存储域内同时存活的唯一物理对象计算：常驻副本、迁移源与目的、CPU/GPU 私有结果、合并区、workspace 和在途旧代。同一底层分配的别名不重复计容量，迁移中的不同源/目的可能同时占用。驻留积分 $A_C=∫C(t)dt$ 的单位是 byte·s，描述占用持续时间，不能直接加到毫秒延迟中。

### 三条放置路径与全驻留对照

设冷权重为 $W_c$ 字节，链路有效带宽为 $B_l$；CPU 冷部分计算时间为 $T_c$，GPU 冷部分为 $T_g$，GPU 热部分为 $T_h$；CPU 路径交换输入和结果共 A 字节，额外同步为 $T_s$，最终合并为 $T_m$。以下从共同输入就绪开始，不包含尚未列入的准备和排队。

若冷权重整块到达后 GPU 才执行冷部分，传输可与热部分重叠，且 GPU 热冷计算按所述顺序执行，则

$T_{move}=max(W_c/B_l,T_h)+T_g+T_m$。

分块可以让冷权重传输与冷计算流水，冷路径局部项在充分独立 tile 和缓冲条件下可能逼近 $max(W_c/B_l,T_g)$。整层仍受热冷部分共用 GPU 的服务需求、启动排空与依赖约束，不能孤立替换一项后宣称整层已经达到该最大值。

若冷计算留在 CPU，且两分支可在共同输入就绪后独立推进，保守模型为

$T_{cpu}=max(T_h,A/B_l+T_c+T_s)+T_m$。

输入与输出有先后依赖时，应展开为 $A_{in}/B_l+T_c+A_{out}/B_l+T_s$。输入可分块提前消费时，再按实际流水重算。整层留在 CPU 是另一候选，其热部分、线程和布局可能不同，必须独立取得 $T_{allcpu}$，不能只用冷部分时间代替。

若全部权重和状态可以合法常驻 GPU，按同样热冷分片顺序执行的对照为 $T_{full}=T_h+T_g$，没有每轮冷权重搬运项。整个算子的融合 GPU 实现还可能有不同时间，不能把这个顺序对照当成它的精确性能。

### 同一资源合计，独立资源取最大

先为每一条流量 e 标明经过哪些物理资源。设它在资源 r 上产生 $q_{e,r}$ 字节，定义

$Q_r=Σ_e q_{e,r}$。

CPU 读取、格式转换的读写和 DMA 源读取若经过同一 DRAM 控制器，就在该资源上合计。同一 payload 也可能分别对 DRAM 和 PCIe 产生需求；这是两个资源各自的账，不代表这两项必须串行。

在带宽 $B_r$ 与相同并发条件相容时，每工作单位的稳态周期 P 必须满足

$P≥max_r(Q_r/B_r)$。

再把计算资源、串行状态拥有者和真正的反馈依赖纳入必要下界。例如计算资源 d 每单位承担 $F_d$ 运算、可持续速率为 $R_d$，状态拥有者每单位承担串行服务时间 $H_{owner}$，跨单位反馈给出的最小周期为 $P_{dep}$，则

$P≥max(max_r Q_r/B_r, max_d F_d/R_d, H_{owner}, P_{dep})$。

$P_{dep}$ 只包含限制相邻工作启动的反馈或循环依赖。对独立批，单批依赖路径很长并不直接要求启动周期同样长。单次完成延迟另外满足依赖 DAG 的关键路径下界 $L_{DAG}$。路径内确有先后关系的阶段时间可以相加，跨独立资源的服务需求不能普遍求和。已经包含访存的实测计算时间，也不能与同一访存下界机械相加。

这些是必要下界，不是可达性证明。有限缓冲、调度冲突、共享上游链路、并发带宽下降与同步都可能让实际周期更大；各资源带宽必须能在同一并发配置下同时成立。

### batch、历史与激活稀疏

冷权重每轮传输量通常不会随 batch b 线性增长，而 CPU 工作、激活交换、KV 与预测集合可能增长。每请求摊销的权重传输项是 $W_c/(bB_l)$，但单请求仍等待本轮排队与依赖；吞吐倒数不能冒充交互延迟。

FlexGen §4.2 的简化 decoding attention 模型中，搬历史 KV 的字节约为 $4bNh_1$，交换 query 或激活约为 $4bh_1$，理想字节比约为历史长度 N。它比较的是指定移动对象，完整实现还须统计结果、元数据及转换。这个比例不证明 CPU 点积、softmax 或主存竞争免费。窗口、MLA、压缩、不同 KV head 数或状态已在 HBM 时，必须按实际表示重算。

## 设定算例与反例

以下时间与带宽均为设定值，不是设备实测。某层冷权重为 512 MiB，设备容量不足以永久容纳它，链路为 16 GiB/s；CPU 冷计算为 8 ms，GPU 冷计算为 1 ms，GPU 热计算为 6 ms；输入与结果交换共 2 MiB，额外同步 1 ms，合并 0.5 ms。

冷权重传输为 $512 MiB/(16 GiB/s)=31.25 ms$。整块模型给出

$T_{move}=max(31.25,6)+1+0.5=32.75 ms$。

输入与结果交换为 $2 MiB/(16 GiB/s)=0.1220703125 ms$，于是

$T_{cpu}=max(6,8+0.1220703125+1)+0.5=9.6220703125 ms$。

若容量允许全驻留，匹配的顺序 GPU 对照为 7 ms。若保持其他设定，只把 CPU 冷计算改为 80 ms，CPU 分工变为 81.6220703125 ms，搬权重路径的 32.75 ms 反而占优。这是参数化反转，不表示真实 batch 增大时其他项会保持不变。

共享资源反例：两条并发路径各在同一 DRAM 上产生 64 MiB 流量，该并发条件下可持续带宽为 8 GiB/s。资源总量为 128 MiB，周期至少为 15.625 ms。把两条孤立的 7.8125 ms 取最大会低估同一资源的需求，两个线程或 stream 不会产生两份 DRAM 带宽。

再改变物理映射：两条路径分别经过两个真正独立的资源，各产生 64 MiB，各有可同时维持的 8 GiB/s 带宽，没有相互依赖且缓冲充分。每单位两条传输同时服务，每隔 7.8125 ms 启动一次的计划即可达到这个周期。跨资源求和会错误要求 15.625 ms，排除该合法重叠计划。

若给这两个独立资源增加“第二段必须等待第一段”的依赖，单单位延迟成为 15.625 ms；多个独立单位仍可流水，周期保持 7.8125 ms。只有进一步存在下一单位必须等待上一单位整条链结束等反馈，串行路径才限制周期。资源服务量、单次关键路径和跨单位反馈因此需要分别建模。

## 条件变化后的保留、调整与放弃

| 条件变化 | 必须保留的关系 | 调整或放弃的判据 |
|---|---|---|
| 全部权重或 KV 可以常驻 GPU | 同一函数与数值契约 | 全驻留候选移除每轮搬运项；仍选异构需有新的资源或并发理由 |
| batch 增大 | 分片完整覆盖和共同提交 | 重算权重摊销、CPU 工作、激活交换、联合活跃集合与 KV 容量 |
| 历史增长 | 同一位置、mask 与归一化 | 比较搬历史、CPU attention、分片 KV；不能继续使用短历史字节账 |
| 热点漂移或稀疏性下降 | 神经元原身份与权重版本 | 更新放置并计迁移成本；CPU 成为慢端时减少委托或放弃预测稀疏路径 |
| 启用激活预测 | 精确补算规则或近似质量契约 | 漏项不能被共同提交协议修复；重新校准并做质量回归 |
| 更低位表示 | 分组、尺度、解包与精度关系 | 容量下降可能被 CPU 解包抵消；重新比较完整路径 |
| 链路或主存拥塞 | 同一物理资源上的总需求 | 使用联合并发带宽；增加缓冲不能消除持续带宽缺口 |
| 统一地址或物理共享内存 | 可见性、生产消费顺序和最后使用 | 重算远端读取、缺页、迁移与共享带宽 |
| 取消、失败或版本切换 | 提交资格与物理访问分别结算 | 禁止未来单边发布；未结束访问仍持有旧对象，不能只靠换代次复用地址 |

## 一次层执行的共同提交轨迹

设 CPU 处理通道 {0,2}，GPU 处理 {1,3,4}，共同读取同一 J 的输入快照，合并端在 GPU。

- t0：输入准备、CPU/GPU 计算与结果传输责任已登记，两个非空分片进入 SUBMITTED。结果和 merge_buf 均为本代私有。
- t1：GPU 完成记录通过身份、范围和可读性检查，GPU 分片进入 DONE。CPU 仍在计算，成功集合不完整，不能读取 CPU 结果或发布输出。
- t2：CPU 算完，但其结果 H2D 尚未结束。CPU 分片仍不能进入 DONE；CPU 结果源与 GPU staging 都继续保留。
- t3：H2D 完成，覆盖完整 CPU 结果的通知被接收，CPU 分片进入 DONE。两个分片均成功，状态拥有者只启动一次合并。
- t4：合并按原通道位置读取两个私有结果，写完 merge_buf，完整合并证书被接收，整代进入 MERGED。此时仍未对下游发布。
- t5：提交事务重新检查当前身份、全部成功终态和取消/失败资格，登记消费者并发布 visible[J]。取消先处理则拒绝；事务先完成则后来的取消不能撤回已提交事实。
- t6：上一代迟到或重复通知到达，只按旧对象责任结算，不改变本代结果。若旧物理访问未结束，相应范围原本就不能复用。
- t7：全部下游读者结束后，合并结果才可回收。下一代只能使用安全归还的范围，或另外预留的新对象。

交换 CPU 与 GPU 的完成顺序不改变发布条件。若 CPU 集合为空，它从初始化起就是 DONE_EMPTY，不发起空传输；GPU 完成后即可启动合并。两侧均为空只在完整必需集合确实为空时合法，不能把漏掉工作伪装成空分片。

## 诊断：竞争解释、区分实验与修正

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| CPU 分工比搬权重慢 | CPU 计算过长、主存争用、同步或预测开销 | 固定输入与分片，先测空 CPU 分片的固定开销，再恢复计算、交换与预测；共享负载改变耗时时修正带宽模型 |
| batch 增大后收益消失 | 权重摊销改善，但 CPU 工作、活跃并集、KV 或排队增长 | 固定历史扫 batch，再固定 batch 扫历史；记录实际活跃集合、字节、阶段完成和排队 |
| CPU attention 省字节却更慢 | 点积/softmax、NUMA、布局转换或线程同步主导 | 固定 KV 布局与函数，分别改变线程、内存归属与分片；消除转换后仍慢时降低布局解释权重 |
| shape 正确但数值错误 | 缺失/重复分片、提前非线性、版本错配或浮点差异 | 先用有理数稠密参考与独立 softmax 参考，再交换完成顺序、注入单字段旧身份；定位首次分歧 |
| GPU 先完成时偶发缺通道 | 提前合并、CPU 结果传输未完成或错误空集合 | 延迟 CPU 完成和 H2D，要求合并读取始终为零；若仍读取，修复门控，不能归因数值精度 |
| 取消后仍发布 | 资格检查与安装分离，或取消晚于提交 | 在合并中、合并后和事务后分别注入取消；前两处拒绝，事务后保留既有提交 |
| 合法重叠被模型判为不可行 | 把独立资源服务时间相加 | 保持字节与带宽，分别映射到同一 DRAM 和独立资源，构造可服务时间线；独立案例仍要求双倍周期时修正公式 |
| 量化后委托收益消失 | 解包/尺度恢复占 CPU，或数值契约改变 | 分开测解包、计算、传输和质量；不能把压缩倍数当作端到端加速倍数 |
| 没有显式复制仍很慢 | 远端访问、缺页、迁移、缓存或共享带宽 | 改变重读次数、访问比例与驻留条件，结合实际事务或缺页观察；地址相同不能证明数据在近端 |

验证先做代数与协议模型，再做允许精度下的数值比较，最后才测设备时间与资源。性能对照固定函数、输入、dtype、质量契约和计时边界，记录真实完成而不是仅记录提交返回。局部层收益还要放回完整模型与服务调度评估，不能直接推导用户 SLO。

## 具体系统中的组合限制

PowerInfer 固定 v1 的离线 profiler 用 C4、Wikipedia 等输入统计神经元激活，求解器结合激活频率、层内通信和容量安排热点/冷点，在线预测器与神经元感知算子减少工作，CPU 结果送到 GPU 合并。论文 §5.3 的依赖 DAG、双方完成后合并以及 CPU 工作为空时跳过无意义同步，支持本章的数据流动机；本章的冻结身份、串行资格检查和责任账是独立推导，不声称论文实现了这套协议。

其评估包括 OPT、Falcon(ReLU)-40B 和 LLaMA(ReGLU)-70B 等模型。§3 的统计中，单 MLP 层内 OPT-30B 约 26%、LLaMA(ReGLU)-70B 约 43% 的神经元承担 80% 激活，整模型对应约 17% 和 26%。这些是指定模型与输入分布的统计。§8.2 讨论大 batch 和长 prompt 下联合稀疏性下降、CPU 成为瓶颈；§8.4 承认预测器可能漏掉活跃神经元并产生任务分数波动。它们不构成任意稠密模型的稀疏性或无损保证。

FlexGen 固定 v1 面向允许较高延迟的吞吐任务。§4.2 用主存 KV 与激活的移动字节差解释 CPU attention delegation；§5 将权重和 KV 压缩为 4-bit，计算前恢复 FP16，但因 CPU 解压开销在该实现中关闭量化时的 CPU delegation。因此不能把两种配置的收益直接相乘。新的组合必须重算解包、主存读取、attention、交换与容量，并独立验证质量。

FlexGen 的成本模型假设理想重叠，放松离散放置且可能产生 OOM，需要手动调整；吞吐实验使用 dummy weights，质量实验使用真实权重。其附录 I/O 近优结论还限定无 CPU 委托和简化存储、工作流条件，不证明包含真实有限缓冲与服务反馈的端到端计划最优。

## 检查与未验证边界

配套候选为 `tools/check_k_alg_020_full.py`，只使用 Python 标准库，确定、离线、只读。输出通道检查以完整有理数矩阵为参考，覆盖全部两侧通道分配、空侧、非连续映射与零归约长度；attention 合并对照 70 位 Decimal 整行参考，覆盖空分片、全空行和大分数范围，并检出等权平均错误。
