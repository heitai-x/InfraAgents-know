{"chapter":"# K-WORK-003：工作负载分布：长度、复用、模态与相关性\n\n系统成本由输入输出的联合分布决定；平均长度会丢失影响缓存、批次和尾部行为的结构。本章把负载定义为一组带身份、到达和结果边界的联合记录，并给出从记录到可重放档案、成本预测和区分实验的算法。以下公式与算例是分析模型，不是目标 GPU 实测；来源数字只在声明条件下使用。\n\n## 对象：请求是联合记录\n\n对请求 i，记\n\n`r_i = (s_i, a_i, u_i, m_i, x_i, y_i, o_i, c_i)`。\n\n其中 `s_i` 是会话、租户或流量分组及其依赖关系，`a_i` 是到达或依赖就绪时间，`u_i` 是前缀、媒体和 adapter 等缓存身份链，`m_i` 是模态几何与 processor 配置，`x_i` 是模型实际消费的规范输入 token 数，`y_i` 是本次实际生成并选择的输出 token 数，`o_i` 是停止原因和可见输出边界，`c_i` 是客户端消费、取消和清理状态。调度还需要批、队列和完成事件；它们由这些记录在时间轴上派生，不能只从两个平均数恢复。\n\n`x_i` 不是原始字符数、字节数或图片张数。它应由固定模板、tokenizer、processor 和模态桥接共同决定；多模态输入还要把视觉或音频 token 加进模型实际序列。`y_i` 也要声明口径：是正式选择的 token、包含 EOS 的 token，还是用户可见字符。GenAI-Perf 所核对版本把 Input Sequence Length 和 Output Sequence Length 作为请求级 token 指标，同时把客户端流式 chunk 与模型 token 分开；同一请求的 chunk 数、已选 token 数、已解码字节数和已提交字节数不能互相替代。\n\n真正影响执行的是联合规律\n\n`P(L_in, L_out, H, M, A, S, C)`，\n\n其中 `H` 表示前缀或块身份序列及复用间隔，`M` 表示媒体几何，`A` 表示 adapter/grammar 等条件，`S` 表示停止与取消，`C` 表示客户端消费。请求均值、token 加权均值、字节加权均值和活跃时间加权均值回答不同问题；没有说明分母的“平均长度”不足以比较系统。\n\n一个均值保持反例即可说明。令 `W0={(100,100),(100,100)}`，`W1={(10,190),(190,10)}`。二者输入、输出均值都为 100。若两条请求组成一个密集批：线性主项被 padding 到最大输入，逻辑工作量分别约为 `2·100=200` 和 `2·190=380`；若 dense attention 不跳过错位，成对分数工作量约为 `2·100²=20000` 和 `2·190²=72200`，而真实输入平方和是 20000 和 `10²+190²=36200`。`W1` 还有负相关：`E[L_in L_out]=1900`，但它等于 `100·100−8100`。这些是逻辑工作量，不是时延；但已经证明均值相同的负载可以有不同批浪费和尾部结构。\n\n## 合法性：单位、边界与身份\n\n负载模型合法，不只是“数字能生成”，还要让每个量对应真实执行条件。\n\n1. 输入长度必须由声明的模板、tokenizer、processor 和特殊 token 规则产生。相同文本在不同模板或 tokenizer 下可能有不同 token 数；同一词表大小的不同制品也可能把同一整数解释成不同内容。图片应按实际 resize、crop、patch 和桥接规则计入视觉 token，而不是字符代理。\n\n2. 输出长度的停止边界必须记录。若潜在输出为 `y*`，服务在 `cap` 处结束，则观察到的是 `min(y*,cap)` 并带 LENGTH 原因；这是删失或截断，不是自然 EOS。把截断样本当作普通完成会低估长输出尾部；把取消、超时或错误请求直接从分母删除，会制造虚假的更快结果。若任务允许不同输出长度，比较应使用与质量、联合 SLO 和完成条件一致的 goodput，而不是默认每个输出 token 同等有用。\n\n3. 缓存命中需要至少同时满足：完整前缀身份一致、模型和位置/adapter/媒体条件一致、物理块仍在容量中、状态确实完成、路由能到达该位置，并且请求在合法恢复点。相同字符串、相同图片 URL 或相同 placeholder 都不构成命中证明。若只缓存 KV 而没有保存末行 logits，生成任务通常还要保留最后一个已知输入位置；本章把它记为 `h_i ≤ x_i−1` 的生成边界，具体任务若另有 logits 合同可以不同。\n\n4. 媒体身份至少包括内容摘要、processor 版本、resize/crop、patch 规则、帧采样和时间位置。相同像素面积、相同图片张数或相同分辨率不代表相同几何；aspect ratio、窗口边界和时间顺序都可能改变成本或模型函数。\n\n5. 会话、用户、媒体内容和时间必须按规则划分开发、校准与保留集。把同一会话的不同回合随机拆开，会让保留集通过共享历史和近重复内容泄露信息。开放到达与闭环用户也不能混用：闭环用户的思考时间会随服务变慢而改变后续到达。\n\n6. 独立抽取输入和输出边际是一个合法但不同的假设，可以作为零模型或压力测试；它不能被称为“保持了原联合分布”。合成档案若只匹配均值，必须明确说明被破坏的相关性和未被覆盖的层。\n\n所核对 GenAI-Perf 版本提供合成输入均值/标准差、输出 token 均值/标准差、前缀 prompt 数量与长度、固定 schedule payload 的 `hash_ids`、多轮 session 延迟和 goodput 约束等入口。它们能控制部分边际、重复和到达，但不能自动保持真实联合记录、缓存身份或取消相关性。\n\n## 从真实记录到可重放档案\n\n下面的算法先规范化单位，再保留整条联合记录和会话隔离，最后用独立参考审计。外部工具或现成生成器只能提供输入，不能替代这里的验证。\n\n```pseudocode\n算法 BuildAndAuditWorkload\n输入：原始记录 R，目标模型与执行档案 M，分层键函数 strata，目标权重 weights，\n      会话/时间隔离规则 split_rule，随机种子 seed，审计条件 audit_checks\n输出：可重放档案 D={development, calibration, holdout}，拒绝与删失记录，\n      每层权重来源、规范记录、种子和审计报告\n\n1. 初始化：D 的三个集合为空；Reject 为空；每条记录状态为 RAW；\n   固定 M 的模型、tokenizer、模板、processor、位置和停止合同；\n   解析 seed；把 weights 的来源标为生产频率、目标比例或明确假设。\n\n2. 对 R 中每条原始记录 r：\n   2.1 按 split_rule 用会话、用户或时间来分配唯一 split；\n       同一会话的其余回合跟随该 split，不能逐回合随机拆分。\n   2.2 用 M 渲染并编码输入，得到规范 x 和完整输入身份；\n       多模态输入同时计算媒体几何、视觉/音频 token、特殊 token 和位置元数据；\n       记录删除范围、截断原因和实际有效长度。\n   2.3 取得输出边界：selected_tokens、可见输出、stop_reason、是否在 cap 处截断；\n       若无法区分自然 EOS 与预算停止，标记 censored，不伪造一个 EOS。\n   2.4 若单位缺失、输入身份与 M 不相容或媒体无法按合同解码：\n       状态改为 REJECTED，把原因加入 Reject；不得用其他样本均值补造。\n       若合法输入被预算截断：保留截断后的真实样本，标 truncation 和删除区间。\n   2.5 计算 K=(split,strata(r),session_id,arrival_bin,复用类别,模态类别)；\n       把整条规范记录加入对应集合，保留 x、y、H、M 的原配对；\n       状态改为 CANONICAL；不在这里把各列独立打散。\n\n3. 对每个 split 和层 s：\n    统计 n_s、权重来源、x/y/media/复用间隔的联合摘要、尾部、取消和删失数；\n    若 weights[s]>0 但 n_s=0：标记 unsupported，停止把它外推为该层；\n    由授权操作者补充数据或把 weights[s] 改为 0 并记录变化原因。\n\n4. 构造开发集：\n    若重采样真实记录，则先按层权重抽层，再从该层有放回抽取整条记录；\n    若构造合成样本，则先抽层，再抽同层整条 seed 记录并复制其联合结构；\n       只允许按声明模型扰动明确列出的轴，例如时间、分辨率或长度；\n       每次扰动后重新执行 2.2 至 2.4，更新全部派生长度、媒体身份和停止状态；\n    若扰动改变了输入或输出函数，标记为 intervention，不能当作原分布的观测样本。\n\n5. 用独立参考审计：\n   5.1 分别按请求、按 token、按字节和按活跃时间报告均值、方差、协方差、\n       分位数、尾部以及删除/删失比例。\n   5.2 在固定重放顺序和固定缓存容量 C 下，用块身份的栈距离参考计算命中；\n       没有完整物理身份时只能报告逻辑前缀，不能称实际缓存命中。\n   5.3 用固定到达、批和完成轨迹回放，报告排队、峰值驻留、取消、完成和 goodput；\n       若输出被截断或人为改短，goodput 与质量必须单独列出。\n   5.4 加入负对照：打散输出与输入配对、把重复前缀连续聚在一起、\n       把客户端 chunk 当 token、把完成数当 goodput；审计必须拒绝或标为不同假设。\n\n6. 校准集只用于拟合量化尺度、敏感激活范围或等价阈值；\n   开发集用于选择和调整；保留集在候选、代码和评分规则冻结后按预注册次数读取。\n   若发现保留集被用于调参，保持该次记录，但降低其作为独立证据的身份。\n\n7. 若审计失败：保留原始记录、拒绝和反例证据，回到单位、身份、权重或边界修正；\n   不得删除长尾、失败、取消或慢客户端样本，使均值或总体指标通过。\n\n8. 完成条件：所有目标层均有支持，所有拒绝/删失均可解释，\n   权重来源和 split 规则已冻结，种子和档案来源标识已记录；\n   输出 D、Reject、审计报告和已知未覆盖层。状态改为 FROZEN。\n```\n\n状态中 `CANONICAL` 只表示规范化和身份已建立，不表示它代表生产；`FROZEN` 只表示本次证据版本不再被搜索挑选，不等于跨模型或跨硬件有效。重采样整条记录和分别抽取各列会产生不同联合规律；若后者用于敏感性分析，应明确标为独立边际模型。\n\n## 复用有时间结构\n\n把请求的逻辑 KV 块身份按访问顺序写成序列 `b_1,b_2,…,b_n`。在容量为 `C` 个块的完全相联 LRU 参考策略下，第一次访问必然 miss；同一身份 `b_j` 上次出现在位置 `k` 时，令\n\n`Δ_j = |{b_{k+1},…,b_{j−1}}|`。\n\n只有当 `Δ_j < C` 时，这次重复访问才命中；否则即使“曾经见过”也已不在容量内。`C=0` 时全部 miss。这个栈距离模型是独立参考，不是对任意生产引擎策略的断言；叶子淘汰、CLOCK、亲和路由和未完成状态会改变结果。\n\n反例保持相同多重集、相同唯一块集合和相同访问次数，只改变复用间隔。令 `A` 到 `F` 各出现两次，容量 `C=3`：\n\n| 序列 | 12 次访问的排列 | miss/hit |\n|---|---|---|\n| 相邻重复 | `A,A,B,B,C,C,D,D,E,E,F,F` | 6 / 6 |\n| 交错重复 | `A,B,C,D,E,F,A,B,C,D,E,F` | 12 / 0 |\n\n交错序列每次第二次访问前都有 5 个不同块，大于容量 3，所以全部 miss；把容量改为 6，后六次才变为命中。这个例子说明平均前缀长度、唯一块数和“重复了多少次”都不能代替复用距离。\n\n命中收益也要分账。逻辑上避免的 prefill 位置约为 `Σh_i`，但物理节省取决于共享块实际被保留多少、是否被多个请求引用以及是否仍在设备上。目录中的共享前缀、请求私有尾块和正在读取的块不能简单相加。远端命中还需把路由排队、传输、恢复和目标端容量纳入比较：\n\n`T_hit_remote ≈ 排队 + 传输 + 恢复 + 目标端重算尾块`。\n\n若本地重算更快，远端“前缀命中”仍可能不是系统命中。PagedAttention 的机制说明支持逻辑块到物理块的映射、共享和 copy-on-write；它不证明任意异步系统已经在最后读者完成前安全释放，也不证明任意设备上的块布局同速。论文报告的块大小结果只针对其当时模型和轨迹：ShareGPT 上 16–128 表现好，Alpaca 上 16 和 32 好，论文选择 16；这是受控实验事实，不是本章推荐值。页长前后、窗口 rollover、图桶边界和最大上下文都要作为负载边界单独覆盖。\n\n## 条件化成本\n\n设请求 i 已恢复或命中的完整前缀为 `h_i`，尚未处理的输入为 `q_i=x_i−h_i`。在普通因果稠密 attention 的逻辑账本中，prefill 的分数对主项可写为\n\n`P_pre,i ≈ q_i h_i + q_i(q_i+1)/2`，\n\ndecode 若每生成一个 token 读取全部历史，则\n\n`P_dec,i ≈ Σ_{t=0}^{y_i−1}(x_i+t)`。\n\n这些是 query-key 配对数或逻辑乘加的主项，不是 GPU 时间；线性层、FFN、归一化和 kernel 效率另有系数。它们仍能显示：缓存减少的是新 query 对历史 key 的读取，不是把后续 decode 的历史访问全部消除；长输入仍在每次 decode 中形成读取和容量压力。若前缀只恢复 KV 而缺少生成所需末行 logits，`h_i` 还要受前述生成边界约束。\n\n设每 token 全层 KV 字节为 `b_KV`，请求 i 在时刻 t 的有效 token 数为 `n_i(t)`，活跃指示为 `a_i(t)`。峰值与容量积分分别是\n\n`M_peak = max_t Σ_i a_i(t)·b_KV·n_i(t) + 其他工作区`，\n\n`M_tokensteps = b_KV·Σ_i ∫ a_i(t)n_i(t)dt`。\n\n前者决定是否能容纳，后者描述驻留压力；共享缓存容量只能计一次，不能把目录项、请求映射和物理块重复相加。若到达率稳定，请求驻留时间 `T_i=排队+prefill+decode+流式排空+清理` 与平均活跃请求数的关系要按开放/闭环分别处理；不能把平均输出长度直接乘到达率当作稳定容量。\n\n批处理的选择依赖联合分布。一个大小为 `B` 的批若把输入 pad 到 `X_B=max x_i`，线性主项从 `Σx_i` 变为 `B·X_B`，浪费为 `B·X_B−Σx_i`；若 dense attention 也按整个方形 tile 执行，分数对浪费为 `B·X_B²−Σx_i²`。若实现能 masking 或跳过无效 tile，实际浪费会小。相反，把长度差异很大的请求拆成多个小批减少 padding，却增加启动、权重读取和排队。哪种选择成立取决于当前 shape、kernel、批形成和到达，不是固定桶宽。\n\n缓存和路由改变关键路径时，准备与同步也要入账。主机每请求准备成本 `c_prep`、到达率 `λ` 和有效核预算 `p` 满足 `λE[c_prep]<p` 只是稳定性的必要条件，不保证尾延迟；媒体解码、tokenize、网络和锁竞争可能在同一 CPU 域排队。若远端命中把设备计算换成通信，重叠部分不能无条件相加，但未重叠的排队和传输必须计入。\n\n最终比较使用联合 goodput 形式\n\n`G = (1/T)·Σ_i 1(完成_i ∧ 质量_i ∧ TTFT约束_i ∧ ITL约束_i)`。\n\nTTFT 合格率和 ITL 合格率分别是 95% 不保证同一 95% 请求同时合格；分母还要保留 offered、admitted、failed 和未完成。若输出长度因较早 EOS 或更短截断而下降，吞吐提高首先是工作量变化，不能直接归因于执行优化。\n\n## 模态具有独立几何\n\n以所核对 Qwen2.5-VL 报告的结构为例：输入图像的高宽在处理时按 28 的倍数准备，vision transformer 以 14 为 patch 步长，空间相邻的 2×2 个 patch 特征再拼接投影到语言模型；多数视觉层使用窗口注意力，只有少数层做全注意力。于是对一个满足该合同、忽略特殊 token 和裁剪的单图，可写\n\n`n_patch=(H/14)·(W/14)`，\n\n`n_vis≈(H/28)·(W/28)`。\n\n第二个式子只是 2×2 合并后的 decoder 视觉 token 数，不是完整视频 token 合同。报告还讨论动态帧率、时间位置和视频帧分组，具体视频 token 数必须按处理器和模型制品重算。\n\n设定处理后图像为 448×672：patch 数为 `32·48=1536`，合并后视觉 token 为 `16·24=384`。若另外有 512 个文本 token、输出预算 256，则完整长度约为 1152。按报告给出的 7B 配置，28 层、4 个 KV head、head size 128、BF16，估算每 token KV 为 `2·28·4·128·2=57344` 字节，即 56 KiB；1152 个 token 约为 63 MiB。若 1536 个 patch 的 1280 维 BF16 特征、384 个合并后的 3584 维特征和 448×672×3 的 FP32 像素同时存在，仅这三项就约为 3.75、2.625 和 3.445 MiB，合计约 9.82 MiB；它们不是整模型峰值，但说明媒体、视觉和语言阶段不能只按文本字符数入账。\n\n同一张图数但不同分辨率会改变 patch 数和视觉 attention 的工作；相同面积但不同 aspect ratio 也可能改变窗口边界、位置与媒体身份。视频还有帧数和绝对时间轴，不能把“同样几帧”当作同样输入。缓存视觉特征时必须绑定内容与 processor；缓存完整 decoder 前缀还要加入桥接特征、位置和文本模板。动态分辨率、窗口编码和时间相关位置来自 Qwen2.5-VL 报告；上面的容量数字是本库推导的设定算例，不是目标设备实测。\n\n## 分层、校准与保留\n\n分层的目的不是把每个变量切成更多格，而是保留会改变执行图或服务约束的交界。可用少量层：短交互、长文档、长输出、共享系统提示、多模态、取消密集；再在层内保留输入/输出联合记录、复用间隔和到达方式。层的键可以由输入长度分位、输出长度分位、媒体面积或时长、adapter、复用类别和客户端行为组成，但应报告每层样本数、权重来源和空层。\n\n优先保留真实联合记录；资料不足时，独立边际模型只能作为零模型，或按层复制整条 seed 记录后再扰动已声明轴。设置目标比例后，总体结果必须同时给出各层结果和加权总体，权重不能在看到保留结果后调整。开发集用于机制边界和候选选择，校准集覆盖量化敏感的激活或媒体分布，保留集检验搜索后的泛化；同一对话、同一媒体或同一近重复内容应留在同一侧。\n\n长度边界需要专门样本：页长前后、窗口 rollover、图桶边界、最大上下文、最大输出、模板和停止边界。容量评估则要保留真实长尾，不能只使用边界输入或只使用短请求。两类集合回答不同问题，不能互相替代。若只有一个合成 workload，结论只限于它的分层、权重、相关性和复用轨迹；改变长尾、复用间隔或到达方差后应重新扫描。\n\n## 条件变化后的保留、调整与放弃\n\n| 变化 | 仍可保留 | 必须重算 | 何时放弃原结论
