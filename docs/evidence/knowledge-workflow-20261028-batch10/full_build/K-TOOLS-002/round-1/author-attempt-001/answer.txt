{"chapter":"# K-TOOLS-002：时间线分析：从请求路径定位执行瓶颈\n\n时间线分析要解释一个具体请求为什么在某个时刻还没有完成，而不是先找累计时间最长的名字。一个 kernel 累计 8 ms，可能只在一个批次中服务十个请求；一个 host API 很长，也可能只是在等待此前提交的设备工作。归因需要把事件身份、依赖、资源覆盖、请求归属和观测完整性连起来，再回到关键路径与反事实预测。\n\n## 1. 问题、对象与归因目标\n\n设目标请求为 r，共同起点为 0，完成事件为 F_r，观测窗口为 W=[W0,W1)。一次时间线问题写成 Q=(r,W,C)。C 说明要回答的是存在、持续时间、请求归属还是因果解释。例如“r 在 W 内等待过复制”与“复制使 r 的完成时间推迟”不是同一主张。\n\n时间线记录首先是一个事件，而不是一个名字加一个数字。可以把事件写为 e=(d,k,a,o,t,φ)。d 是时间域，k 是事件类型，a 是逻辑对象或请求，o 是进程、线程、设备、context、stream、队列等作用域，t 是点时刻或半开区间 [s,e)，φ 保存尝试、代次、shape、字节和调用上下文。事件类型必须说明它代表发生、提交、完成、可见还是消费。\n\n| 对象 | 定义 | 不能自动替代 |\n|---|---|---|\n| 请求 | 业务身份，连接输入、输出和完成条件 | batch、kernel 名或 correlation ID |\n| 批次 | 一次调度或执行共同服务的请求集合 | 单个请求的独占工作 |\n| 提交实例 | 一次 host API 调用或一次入队 | 设备已经执行 |\n| 设备实例 | 一次实际的 kernel、复制或传输 | 同名 kernel 的另一次执行 |\n| 完成事件 | 某次工作完成的证据 | 结果已被业务消费者读取 |\n| 消费事件 | 下游 kernel、主机或远端应用取得结果 | 物理传输完成 |\n\n点事件和持续区间必须分开。点事件 t 在窗口内的判定是 W0≤t<W1，它证明发生过，但不贡献忙碌时间。持续事件 [s,e) 要求 s≤e，s=e 是零持续时间事件，不能当作正长度覆盖。半开区间意味着 [0,10) 与 [10,20) 在 10 时刻不重叠，但它们的并集是连续的 [0,20)。\n\n事件还要区分发生时刻与发现时刻。设备完成、CQE 可取回、完成通知被处理、主机回调读取结果以及业务输出提交，可能是不同时间。若只记录回调时间，它度量的是完成加通知和调度延迟，不能直接当作设备完成时刻。\n\n## 2. 身份、关联与合法时间\n\n请求、批次、提交和 kernel 通常是多对多关系。令 B⊆R×Batch 表示请求与批次的成员关系，P⊆Batch×Submit 表示批次与提交的关系，E⊆Submit×Dispatch 表示提交与设备工作的关系。逻辑请求到设备工作的投影是：只要存在 b 和 a 使 (r,b)∈B、(b,a)∈P、(a,k)∈E，k 就与 r 相关。一个 kernel 可以服务多个请求，一个请求也可以产生多个 kernel、复制和同步。\n\n精确关联至少需要以下条件：关联字段的语义已经核验；键在对应运行、进程、设备、队列和代次内唯一；作用域完整；时间域可比较或已有误差界；对象的逻辑范围与物理范围一致。仅有时间接近、同名 kernel 或父范围包含关系，只能形成候选，不能提升为精确关联。\n\n关联结果应分成精确、候选和未决三类。全部设备工作必须被精确与未决集合划分，二者不相交且并集等于全部实例。若 correlation ID 在设备 0 的队列 0 上出现一次，又在队列 1 上出现但没有该队列的匹配提交，后者必须留在未决集合，不能按最近时间接回原 API。\n\n时钟关系也要显式。设同一物理时刻满足 t_B=t_A+δ，在窗口内 δ∈[δ_lo,δ_hi]。A 发送读数为 a，B 接收读数为 b，则传输或跨域经过时间属于：\n\nT∈[b-a-δ_hi, b-a-δ_lo]∩[0,∞)。\n\n非负下界来自发送先于接收。若交集为空，身份、校准或事件语义至少有一项不相容，不能把负上界静默改成零。若窗口内还有漂移率上界 ρ，经过 h 时间后应把偏移界限放宽 ρh，再计入时间戳误差。没有校准证据时，两台机器的时间戳只能用于各自域内的先后，不能直接相减。\n\n因果边也必须来自证据。stream 内顺序、经过核验的 event 等待、数据依赖、资源移交或明确的完成屏障可以提供边；两个时间戳中一个更早，本身不提供因果边。父 span 包含子 span，不等于父 span 完成先于子 span 开始，不能把包含关系直接变成完成边。\n\n观测覆盖同样是合法性条件。一个事件被支持、启用、纳入作用域、落在采集窗口、成功刷新、被导出并成功关联，才有完整观测。工具不支持、未启用、作用域外、窗口外、缓冲丢失、导出缺表、字段非法、身份未决和成功关联必须保留为不同状态。缺表或空表不能写成零成本。\n\n## 3. 区间账：累计、并集与并发\n\n对已限定资源作用域、统一时间域并去重的持续区间，定义：\n\nS=Σ_i(e_i-s_i)，U=|∪_i[s_i,e_i)|，K=max_t |{i:s_i≤t<e_i}|。\n\nS 是累计时长，U 是资源至少被一项所选活动覆盖的时间，K 是最大并发。一般有 U≤S≤K·U。重叠时 S 可以大于墙钟，U 不能超过墙钟。例如 [0,10)、[5,15) 给出 S=20、U=15、K=2；[0,10)、[10,20) 给出 S=20、U=20、K=1。把 S 当 U 会把两个真实并发工作错记为更长墙钟，把相邻区间当并发又会制造假热点。\n\n```pseudocode\n算法 IntervalLedger(raw, W)\n输入：每条记录至少含 (start,end,physical_id)；W=[W0,W1)\n输出：累计 S、并集 U、最大并发 K、合并区间 merged、零持续时间点数\n\n检查 W0、W1 有限且 W0<=W1\nseen=空；work=空；point_count=0\nfor 每条原始记录:\n    检查端点和单位；若 end<start，拒绝\n    若 physical_id 已出现，跳过重复导出\n    把 physical_id 加入 seen\n    若 start==end:\n        若 W0<=start<W1，point_count 加一\n        继续\n    a=max(start,W0)，b=min(end,W1)\n    若 a<b，把 [a,b) 与 physical_id 加入 work\nS=work 中各区间长度之和\n按 (开始,结束,physical_id) 排序 work；merged=空\nfor [a,b) in work:\n    若 merged 非空且 a<=最后一段结束:\n        最后一段结束=max(原结束,b)\n    否则追加 [a,b)\n为每个 work 区间建立 (a,+1)、(b,-1) 端点\n按 (时间,增量) 排序；同一时刻先结束、后开始\nactive=0；K=0\nfor 每个端点:\n    active=active+增量\n    若 active<0，拒绝\n    K=max(K,active)\n若 active!=0，拒绝\nU=merged 各段长度之和\n返回 S、U、K、merged、point_count\n```\n\n扫描不变量是 merged 的并集等于 work 的并集，区间互不重叠，端点处理完后 active 回到零。去重按物理实例、作用域、尝试和代次，不按 kernel 名。同名工作可以是不同执行，一次物理工作也可能被重复导出。两个不同 physical_id 落在完全相同区间时，必须计两次真实并发；同一 physical_id 的重复记录只计一次。\n\n排序和扫描需要 O(n log n) 时间、O(n) 空间；输入已按开始排序且只求并集时可以 O(n) 扫描，但求 K 仍需结束次序。窗口裁剪只能发生在合法性检查之后；逆向区间不能借窗口外裁剪隐藏错误。零长窗口返回空账，零长事件单独保留为点，不贡献 U。\n\n## 4. 从依赖图到关键路径\n\n区间账回答资源覆盖，不回答某个请求为什么晚。把不可再分的工作或同步点建成有限有向图 G=(V,E)。节点 v 的持续时间下界为 d_v≥0，释放时间下界为 r_v≥0；边 u→v 的长度 l_uv≥0 表示 u 完成后至少经过 l_uv，v 才能开始。所有时间使用同一单位，共同起点应在全部释放之前。若关系连接的是开始点、范围完成点或外部输入，应先拆成事件节点，不能把整个 API 或 kernel 当成一个完成边。\n\n每个节点都受自己的释放约束：\n\nES_v=max(r_v, max_(u→v)(EF_u+l_uv))，EF_v=ES_v+d_v。\n\n根节点没有前驱时只保留 r_v。漏掉内部释放会低估等待。例如 d=(2,3)、r=(0,10)，边 0→1 的等待为 4，节点 0 在 2 完成，边只要求节点 1 在 6 开始，但释放时间是 10，故完成下界为 13，不是 9。\n\n```pseudocode\n算法 EarliestCompletion(V, d, r, E, target)\n输入：有限节点；非负有限 d、r；边 (u,v,l)；可选 target\n输出：ES、EF、完成下界、一条达到该下界的约束路径；或拒绝原因\n\n检查端点、数值和目标身份\n同一有序节点对的重复边须先明确合并语义；本算法直接拒绝\n建立 pred、succ 和入度；零入度节点入队\norder=空\nwhile 队列非空:\n    u=取出节点；加入 order\n    for v in succ[u]:\n        入度[v]=入度[v]-1\n        若入度[v]==0，入队\n若 order 未包含全部节点，返回 Cycle\n若图为空且指定 target，拒绝；未指定 target 返回完成下界 0 和空路径\nfor v in order:\n    ES[v]=r[v]；parent[v]=空\n    for (u,v,l) in pred[v]:\n        若 EF[u]+l>ES[v]:\n            ES[v]=EF[u]+l；parent[v]=u\n    EF[v]=ES[v]+d[v]\n若指定 target，end=target；否则 end 取 EF 最大的节点\npath=从 end 沿 parent 回溯到空，再反转\nscore=r[path 首节点]+路径节点 d 之和+路径边 l 之和\n检查 score==EF[end]，否则拒绝\n返回 ES、EF、EF[end] 和 path\n```\n\n这个递推是给定边和释放约束下的最早完成模型。它不自动包含共享 SM、复制引擎、内存带宽或链路容量的竞争；两个 stream 可以重叠，不等于两项工作同时拥有无限资源。若共享资源只能顺序服务，应增加队列等待节点、资源可用时间或单独的排队模型。没有这些证据时，结果只能作为无资源竞争时的下界，不能冒充真实调度。\n\n请求路径的完成时间可写为该路径起点释放时间加上路径上持续时间与边等待：\n\nT_path=r_first+Σ_(v∈path)d_v+Σ_(u→v∈path)l_uv。\n\n反过来，缩短非关键路径上的工作不应自动缩短目标请求。两条等长关键路径也只缩短其中一条时，另一条仍决定完成。每次改变 d、r 或边后都应重新求最大约束路径，不能永久给某个节点贴关键标签。\n\n共享工作的物理时间只出现一次，逻辑请求却都可能等待它。对服务多个请求的物理工作 p，令 d_p 为持续时间，选择非负权重 w_(p,r) 且 Σ_r w_(p,r)=1，则资源账可写 charged(p,r)=w_(p,r)·d_p。这样资源账总和仍为 d_p。若每个请求都报告等待了完整 d_p，可以各自用 d_p 解释其逻辑等待，但不能把这些 d_p 再相加成设备物理时间。\n\n请求状态也要能停住。典型状态是：输入已知、容量已分配、已提交、设备已开始、已完成、已可见、已被消费者读取、输出已提交。若所有已记录工作都完成而请求仍不前进，可能是缺少通知、消费者未运行、事件未导出、身份未关联，或存在未建模的释放条件。时间线分析应找这个停滞状态，而不是继续在已完成 kernel 上找累计热点。\n\n## 5. 条件化成本与观测扰动\n\n时间线分析自身也消耗资源。令 N 为事件数，L 为关联边数，M 为合并后的覆盖段数，P 为 profiler pass 数。使用比较排序和哈希索引时，一次流水线可估为：\n\nT_ingest=O(N log N+L+M log M)，M_mem=O(N+L+M+P)。\n\n这些是所选索引与排序策略的条件化成本，不是 profiler 固定开销。无索引的逐对关联可能退化为平方量级，提前聚合又会丢失实例和边界信息。\n\n| 成本 | 计量对象与条件 | 常见漏算 |\n|---|---|---|\n| 计算 | 探针、采样、shape、stack、解析、排序、区间扫描和关键路径 | 只计设备时间，漏掉导出与查询 |\n| 访存 | 事件负载、缓冲复制、索引、trace 文件和结果集 | 只计有效 payload，漏元数据和重复导出 |\n| 通信 | 多机 trace 汇聚、远程查询、控制消息 | 把关联 ID 字节当成链路延迟 |\n| 准备 | 域与窗口配置、权限、schema 识别、时钟校准、请求映射 | 把首次准备算入稳态 |\n| 同步 | 刷新、等待报告、工具插入的同步、事件等待 | 把重叠工作相加，或删除必要前驱 |\n| 驻留 | 未导出缓冲、索引文件、未闭合记录、框架保留的张量引用 | 只算 trace 文件，漏运行时缓冲 |\n\n设备忙碌覆盖 U、累计区间 S 和请求路径 T_path 是不同对象。墙钟从共同起点到 F_r，不能由 S 或 U 单独推出；请求路径还要包含队列、同步、通知和消费。若边和释放已经覆盖全部等待，T_path 是相应路径的完成下界；没有覆盖的等待必须留在未知项，不能补成零。\n\n跨主机时，固定字节数 D 和有效带宽 B 只给出理想传输下界 D/B；握手、排队、转换、重试和其他请求共享链路还要另计。profiler 观测时间也不能简单写成服务时间加一个固定常数：详细采集可能改变并发、cache、时钟和队列，只有确认不改变依赖和重叠时，才可以把扰动当作可加项。\n\n## 6. 条件变化后的保留、调整与放弃\n\n| 条件变化 | 保留的关系 | 调整或放弃的结论 |\n|---|---|---|\n| 单 stream 变为多 stream | 生产、完成、消费与最后使用关系 | 放弃单一全序；分别限定资源和作用域，再求区间并集 |\n| 只关心累计热点 | 事件类型与资源作用域 | 聚合表可能足够；若要解释单请求或重叠，必须回原始事件 |\n| 窗口扩大或移动 | 身份、时钟界和覆盖状态 | 扩窗重算缓冲与导出；缩窗保留跨边界事件和截断标记 |\n| API 变短但输出不变 | 提交与消费边界 | 支持等待位置转移，不支持服务已经加速 |\n| 并发升高后预取退化 | 物理读取、驻留和排队证据 | 检查预取占用容量和共享链路，不能只保留低并发改善区间 |\n| 设备由空闲变为饱和 | 请求路径与资源账 | 优化非关键工作可能改善容量，却未必缩短当前请求 |\n| 跨机偏移老化 | 本地经过时间、身份和误差界 | 扩大候选范围；无法裁决时保留未区分，不能沿用精确对齐 |\n| 采集缺失或扰动增大 | 正常路径测量与缺口状态 | 补针对性信号或缩短窗口；只在 profiler 下出现的收益不外推 |\n| 存储、NIC 或 GPU 平台改变 | 问题、状态机和单位 | 重核队列表、完成语义和容量；不复制 CUDA stream 或 block 队列常数 |\n\n条件变化后，最重要的保留项是事件语义和因果边，最容易错误保留的是旧时间差与旧利用率。一次低并发下成立的预取深度，到高并发时可能只增加驻留和排队；一次 profiler 下变快的融合，到正常运行点可能因额外同步或缓存状态变化而消失。\n\n## 7. 竞争解释、反例与区分实验\n\n| 观察与竞争解释 | 区分实验 | 预测与反证后的修正 |\n|---|---|---|\n| GPU 有长空洞：主机准备不足、依赖等待或采集缺口 | 补线程运行/阻塞、输入就绪和提交事件；保持有效工作 | 等待和完成都提前支持供给解释；补表才填满空洞而输出不变支持观测缺口 |\n| API 很长：提交开销或内部同步 | 分记 API、此前设备完成和输出消费；只改变等待位置 | API 缩短而输出不变支持等待转移，不能声称服务加速 |\n| 多 stream 没有变快：错误依赖或共享资源饱和 | 只删除有证据的边；对照独立 workspace 或释放资源 | 去边后空洞改变支持依赖解释；只增加排队则重查资源需求 |\n| 累计 kernel 很大但目标不慢：重叠或共享重复归因 | 按物理实例去重，求区间并集，再求目标路径 | 缩短非关键工作而目标不变，反驳它直接决定该请求延迟 |\n| 异步 API 更早返回：并行改善或仅移动等待 | 同时记录提交、设备开始、完成和输出 | profiler 下更快：真实优化、cache/clock 改变或串行化 | 开/关采集对照，最后回到正常运行点 | 差异只在采集环境成立时，限制结论范围 |\n\n反事实预测必须先于干预写清。若减少历史复制是原因，相同上下文下复制字节随步数的增长应减弱；若降低调度开销是原因，host 准备间隙应缩短，而单 kernel
