# K-HW-011：GPU 矩阵与归约流水：布局、资源和完成依赖

一个 GPU kernel 的设计同时决定数据怎样进入计算单元、哪个线程持有什么片段、临时状态占多少资源，以及何时允许覆盖。tile 更大、流水更深或矩阵指令更多，都只有在这些关系成立时才可能改善性能。

## GEMM 的数据依赖与资源账

对 C=A·B，令输出块为 Mₜ×Nₜ、沿归约轴每次处理 Kₜ。一个阶段读取 A 的 Mₜ×Kₜ 片段和 B 的 Kₜ×Nₜ 片段，输出 accumulator 跨多个 K 阶段保留。数据依赖是：全局读取 → 片上数据就绪 → 矩阵乘加 → accumulator 可消费 → epilogue → 输出可见。下一个 K 阶段的读取可以提前，但不能覆盖仍被矩阵指令读取的片上缓冲。

若输入每元素 s 字节、流水深度 n，单 block 的输入缓冲主项为 n·s·(MₜKₜ+KₜNₜ)，输出累加主项为 a·MₜNₜ，a 为累加元素字节。还要计入对齐、barrier、转置区、地址与 epilogue 临时量。共享存储、寄存器、线程数和 block 数约束共同限制驻留；仅检查共享存储够用不足以证明没有 spill。

设定 Mₜ=Nₜ=128、Kₜ=64、输入 2 字节、累加 4 字节。每级输入缓冲为 32 KiB，三级为 96 KiB；输出 accumulator 为 64 KiB。若由 128 个线程均摊，仅输出就平均需要每线程 128 个 32 bit 寄存器，尚未计其他变量。改成两级减少 32 KiB 片上缓冲，但能否增加驻留 block，还取决于寄存器与目标架构限制。这个算例描述资源占用，不指定任意 GPU 的最佳 tile。

## 先适配指令布局，再安排线程

矩阵指令要求的 fragment 布局不等于用户矩阵的行列布局。全局合并访问、共享存储 bank、矩阵操作数布局与输出写回应作为一条路径比较。局部转置或 swizzle 增加地址/搬运工作，却可能减少非合并事务和 bank 冲突；也可能让后续消费者再支付一次转换。

固定来源中，[FlashAttention-3 v1](../sources/S-FLASHATTENTION3.md) §2–3 以 Hopper 的 TMA、异步 WGMMA 和 warpgroup 组织流水，warpgroup 由 4 个 warp 组成。这是具体架构上的实现入口。[ROCm 固定文档](../sources/S-ROCM.md) 则描述 CDNA 的 MFMA、VGPR/AGPR 与 LDS。两条路径的线程片段、寄存器资源和异步能力需要分别核实，不能将 CUDA 指令、32 线程约定或某一 bank 数直接替换成 AMD 名称。

相同 dtype 也可能有不同操作数布局限制。FA3 对 FP8 的讨论说明，前一 GEMM 的 accumulator 要交给后一 GEMM 时，转换与排列是实际成本；FP16 路径可用不意味着只更改 dtype 就能得到合法 FP8 kernel。低精度还要重新验证 scale、累加、异常值和任务质量。

## 一个完整的非矩阵指令映射：两 warp 共享输入

先把逻辑算法落实到可检查的普通线程运算，再考虑改用矩阵指令。定义 A∈ℝᴹˣᴷ、B∈ℝᴷˣᴺ，均按行连续保存，输出 C∈ℝᴹˣᴺ；本例只计算 C=AB，不读取旧 C，没有 bias 或其他 epilogue。输入和输出为 FP32，累加也为 FP32；数学参考使用实数求和，真实运算是否融合乘加及其舍入另行核验。维度可为零，K=0 时有效输出为零，M=0 或 N=0 时不启动输出工作。

选择一个 CTA 的输出 tile 为16×32，归约阶段为8，CTA有64线程。输出块坐标为 (m₀,n₀)=(16bₘ,32bₙ)，阶段 j 的归约起点 k₀=8j，共 J=⌈K/8⌉ 阶段。这个小例子旨在展示映射与生命周期，没有声称它能接近矩阵单元吞吐。

线程编号 τ=32w+λ，其中 w∈{0,1} 是 warp，λ∈[0,31] 是 lane。warp w 独占本输出块第16w至16w+15列。lane λ 保存8个累加量，令 u∈[0,7]，i=λ+32u，则它负责局部坐标 r=⌊i/16⌋=2u+⌊λ/16⌋、c=16w+(i mod16)。64×8=512个坐标恰好覆盖16×32输出，没有重复写者，也不需要跨 warp 合并输出。

每个输入槽保存行主序共享矩阵 Aˢ[16,8] 和 Bˢ[8,32]。全体64线程按线性下标搬运：Aˢ 的 a=τ+64v，v=0,1，映射为 (⌊a/8⌋,a mod8)；Bˢ 的 b=τ+64v，v=0,1,2,3，映射为 (⌊b/32⌋,b mod32)。每个共享位置有唯一写者。若全局基址是 pA、pB、pC，字节地址为：

- A：pA+4[(m₀+r)K+(8j+k)]，前提 m₀+r<M 且8j+k<K。
- B：pB+4[(8j+k)N+(n₀+c)]，前提8j+k<K 且 n₀+c<N。
- C：pC+4[(m₀+r)N+(n₀+c)]，前提 m₀+r<M 且 n₀+c<N。

非法输入位置填零，且不计算、解引用越界地址；非法输出位置不写回，但其线程仍参加规定的集体同步。对 K 尾块，A/B 的同一无效归约项都为零，因此补齐到8不改变有效 C。全局地址按各自实际 stride 计算，共享地址按本节定义的紧密布局计算，不能把两者混用。

设 M=19、N=35、K=17，选最后输出块 m₀=16、n₀=32。j=1、局部 r=2、k=3、c=2 对应 A[18,11]、B[11,34]、C[18,34]，相对基址字节偏移分别为1268、1676、2656。j=2只有归约位置16有效；这个输出块只有3×3个合法输出。此处行跨度68/140字节，不具有统一的16字节行对齐；4字节元素复制合法，不能给整行虚构更强的对齐证明。

消费者按 k=0…7 读 Aˢ[r,k] 与 Bˢ[k,c]，更新自己持有的8个累加量。两个 warp 共享 A，分别读取 B 的不同16列。以固定 u、k 的标量共享读取为例，同一 warp 的两组16 lane各读同一 A 值；B读取16个不同字，每字被两 lane读取。依据[共享存储广播与 bank 规则](../sources/S-CUDA-BEST.md)，相同字的多 lane读取是广播，不能按32次独立事务计费；若改变行跨度或lane坐标，需要重算实际冲突。协作写共享时，字下标 τ+64v 的 bank 为 λ，单条标量写指令覆盖32个不同 bank。

这条路径已连续给出逻辑 tile、元素地址、线程归属、共享布局和输出写回。把标量 k 循环换成矩阵指令时，仍要另外证明形状、dtype、布局、参与线程和完成依赖；并非保持这份 lane 所有权就能直接替换指令。[Attention 的 warp 矩阵实例](../frameworks/attention-backends.md)采用公开的矩阵装载/存储接口交接，明确不假定内部 fragment 的 lane/寄存器排列。跨指令或平台应重新核对契约。

## 从一个槽到多槽：每代数据的完整协议

定义 d≥1 个槽，每槽的身份为 (s,g,j)，s=j mod d、g=⌊j/d⌋。一个槽从“空闲”到“复制中”，再到“可读”，最后到“读者全部结束”。槽内的 A/B 有同一个逻辑阶段 j，但可以由多条复制组成；仅完成 A 或某一线程发出的复制，不足以宣布整个槽可读。两个 warp 都是 A 的读者，各自又是对应 B 半块的读者；本例保守地将整个 A/B 槽一起释放。

这里区分三类完成：复制完成使相应字节到达共享存储；具有正确作用域的同步使消费者能安全观察这些写入；每个消费者完成最后一次共享读取，才允许下一代覆盖。消费者若改成异步矩阵指令，线程发射返回也不等于指令结束读取；必须以该指令规定的完成条件释放。不同槽的复制可以提前，某槽的代次不能提前。

下面是本例的一种完整组织。复制过程可由硬件异步操作承担，也可由同步加载实现；伪代码中的“等待”明确表达依赖，不指定某个 CUDA API 的机械一一替换。若把两个 warp 的完成合并为 CTA barrier，所有64线程都必须以一致顺序到达。

```pseudocode
输入：A、B、M/N/K、输出块坐标、d≥1
所有lane的8个累加量初始化为0；建立d个空闲槽及各代次
定义提交阶段(j)：
    s←j mod d，g←floor(j/d)
    确认槽s上一代全部复制/写者及两个warp读者已结束
    设置本代身份(s,g,j)，清除本代完成状态
    全体线程按上述地址划分：合法元素复制，无效元素写零
    将本代所有输入写入纳入同一个完成契约；提交复制票据
若J=0：只写有效输出零，结束
启动：依次提交 j=0…min(d,J)−1
对j=0…J−1：
    等待身份(s,g,j)的全部复制与零填完成，并建立CTA可见性
    每个warp按k=0…7消费A/B，更新它独占的输出累加量
    每个warp在最后共享读取完成后到达本代“读完”条件
    等待两个warp都读完；此后槽s才可释放
    若j+d<J：提交阶段(j+d)，把新复制与后续已就绪阶段的计算重叠
排空：确认全部已提交票据和消费者结束，不产生未消费阶段
每个lane只向有效(m₀+r,n₀+c)写自己的8个结果
```

J=1时只提交和消费阶段0；J=2时只消费0、1，不访问并不存在的“下一块”；J=0时不等待未创建的票据。d大于J时多出的槽为空闲，静态分配仍可能为它们付容量。每个阶段被消费恰好一次，输出在处理前 j 个阶段后等于这 j 段乘积之和；同一输出的累加次序始终沿 j、k递增，warp的不同调度顺序不改变其拥有的输出集合。

取消也不能跳过已参与的集体同步，或让一部分线程提前退出。可以在统一边界停止提交新阶段，排空已提交复制和消费者，再放弃输出；若必须保留部分结果，则另外定义它对应哪些归约区间。本章的 C=AB 没有将部分 C 发布为完整结果的语义。

本例采用“整个输入槽等两个warp”的保守释放。若仅等第一个warp、或只等复制票据结束，就可能在第二warp仍读取旧 A 时写入新阶段。若精细拆开A/B资源，A必须等两个warp，B各半块可以分别等对应warp；那需要独立身份和复用条件。减少等待的收益要与增加的同步状态比较，不是多计几个barrier就自动更可靠。

## 抽象票据怎样落实到 CUDA 的同步契约

固定 [CUDA 12.8 指南](../sources/S-CUDA-ASYNC.md) §7.26–7.28区分了 barrier阶段、异步复制与多级pipeline。普通线程的共享写入可通过CTA同步建立可见性，但单独的CTA同步不能替代尚未完成的异步复制等待。反过来，一个线程等完自身复制，也不能自动证明其他线程的复制已完成或所有读者已结束。必须核对同步对象的参与者和作用域，保证全部生产者写入被消费者等待所覆盖。

指南所述 global→shared 硬件异步复制可采用4/8/16字节粒度，要求对应大小与地址对齐；API还可能做运行时检查或采用其他实现。128字节对齐是其性能建议，不是任意合法4字节复制必须满足的数学条件。本例的尾部可采用受保护的4字节复制与普通零填；将两类写入一起纳入CTA可见性，禁止为越界向量读伪造对齐或有效字节证明。

commit/arrive 等操作的参与线程应保持约定的收敛执行。固定文档描述 warp 内实际批次序列与各线程感知序列可能因分歧而不同，造成额外等待；把“每线程循环次数相同”当成完整证明不够。barrier初始化要先于参与者使用，每一代的预期到达与真实参与者一致；退出需遵循其协议。本章的无效输出lane继续参与，正是为保留这一集体契约。

若硬件没有相应异步加速，普通加载、寄存器中转与共享写入也能实现相同数学算法和槽生命周期，但会多付指令、寄存器和可能暴露的等待。异步API被接受、生成了异步指令、实际发生有益重叠，是三种不同结论。

## 工作、交通、同步与驻留必须使用同一候选

本例一个完整归约阶段做2×16×32×8=8192 FLOPs，读取512字节A和1024字节B，共1536字节有效输入请求；一个完整输出块最终写2048字节。对所有输出tile，令 Gₘ=⌈M/16⌉、Gₙ=⌈N/32⌉。若每个CTA独立读取它需要的输入且尾部不越界，A请求约为4MKGₙ，B请求约为4KNGₘ，输出为4MN；输入的唯一持久字节则只有4(MK+KN)。前者体现CTA之间重读，后者体现数据驻留，二者都不是已测的设备主存事务。

padding可能使计算仍执行2×16×32×8×GₘGₙJ FLOPs，而有效函数工作是2MKN；M/N/K很小时无效lane和尾部工作不能忽略。按每个乘加各读取两个共享标量计，一个完整阶段的消费者逻辑共享读取为32768字节，另有1536字节生产者共享写入。广播与cache改变物理交通；这些逻辑字节不能再次除设备主存带宽加入总时间。共享读者通信没有网络通信，跨CTA拆分归约才另外引入部分结果写读及合并边界。

每槽输入容量1536字节，d槽为1536d字节；本例64线程×8个FP32累加量为2048字节逻辑状态，每线程8个32bit累加量。实际寄存器还含地址、循环、暂存、编译器分配及任何中转，不能用2048字节直接宣称真实寄存器占用。barrier、对齐、调试区或epilogue另计。旧的大tile算例同样成立：128×128×64、FP16输入每级32KiB，3级96KiB，FP32输出逻辑累加64KiB；128线程均摊仅累加就相当于每线程128个32bit值。

设每CTA共享分配 S(d)、实际分配寄存器 R(d)、线程数 T，目标SM相应容量为 Sₛₘ、Rₛₘ、Tₛₘ，warp上限 Wₛₘ、block上限 Bₛₘ。忽略分配粒度时，同时驻留CTA数至多为 min(⌊Sₛₘ/S(d)⌋,⌊Rₛₘ/R(d)⌋,⌊Tₛₘ/T⌋,⌊Wₛₘ/⌈T/32⌉⌋,Bₛₘ)。真实配置还受每block上限和资源分配粒度约束，应按编译结果与目标机核对。减线程数可能增加每线程累加和寄存器需求，不能从线程项变松直接推出驻留上升。

完整调用还包括参数/描述符准备、可能的编译与布局转换、launch、kernel首尾和输出交接。准备若被多次调用复用，以真正复用次数摊销；转换若每次发生，以每次计费。copy等待已在kernel关键路径里，就不能作为额外同步再次加上。深流水没有消除等待，而是让部分等待被独立计算覆盖；暴露多少取决于资源和输入规模。

## 延迟模型、首尾与一个选择反转

只用每块加载时间L与计算时间C写 max(L,C)，会混淆复制延迟与复制吞吐。定义 L为发出一阶段后数据就绪的延迟，I为复制通路允许相邻阶段发出的最小间隔，C为消费者处理一阶段的时间。以下理想模型假设复制可流水、各阶段顺序消费、同一个CTA串行消费、槽直到消费结束才复用；发出成本已包括在I内，无额外干预。令 xⱼ为发出时间、yⱼ为消费完成时间：

```pseudocode
x₀←0，y₋₁←0
对阶段j依次计算：
    若j>0：xⱼ←xⱼ₋₁+I
    若j≥d：xⱼ←max(xⱼ,yⱼ₋d)       # 旧读者结束才有槽
    yⱼ←max(xⱼ+L,yⱼ₋₁)+C
J=0时kernel内部阶段耗时为0，否则取最后阶段的y
```

此递推是理想设备可以及时发出复制的乐观时序；普通“全CTA只在消费完成后提交新槽”的上节伪代码不一定实现它的所有发出时刻。例如空闲槽很多时，其预取提交在启动段已发生；稳态若需要计算中途更及时发出，可采用专门生产者或更合适的指令调度，仍要保持同一完成协议。不能把理想下界直接称为所写伪代码的真实耗时。

长序列稳态平均周期受到 I、C、(L+C)/d 三项下界限制；后者来自每个槽从发出到消费结束至少占用L+C时间。有限J必须使用递推或实际时间线，首块始终先付L再付C，不能用 J·max(I,C)抹去首尾。d达到足够覆盖后继续增加没有必然吞吐收益。

全部为设定值：L=6、I=2、C=3，单位记为τ。J=8时，d=1的完成时刻为9、18、…、72；d=2为9、12、18、21、27、30、36、39；d=3为9、12、15、18、21、24、27、30。单CTA三级39→30τ有收益，四级仍为30τ。J=1各候选均为9τ；J=2时d=1为18τ，d≥2的候选为12τ，第三槽没有收益。这里没有从阶段数推断GPU的真实L/I/C。

再设一个用于隔离容量影响的假想SM：扣除固定状态后只剩6KiB用于这些输入槽，其他block/线程/寄存器限制允许至少两个CTA；同步对象另外预留且不占这6KiB。两级每CTA3072字节，允许两CTA，三级4608字节只允许一CTA。若在各自驻留下每CTA服务时间仍分别为39和30τ、无共享通路额外争用，4个CTA的保守分波估计为两级2×39=78τ、三级4×30=120τ。单CTA胜者反而输掉整网格。这个6KiB不是某真实GPU规格；共享复制通路或带宽争用存在时，L/I/C必须作为驻留数的函数重测，不能独立复制单CTA曲线。

如果有效共享预算提高至9KiB，三级可同时容纳两个CTA，同一假设下4CTA变成60τ，优于两级78τ；若J=1，多一个槽依旧不加速。改变工作网格、每CTA寄存器、K长度或复制吞吐，都能改变选择。还可能通过不同tile或精细释放B半块改变模型；保留哪个候选由合法域、资源和校准后的关键路径决定。

## Attention 中归约与矩阵流水怎样连接

Q tile 与多块 K/V 组合时，QK 产生分数，在线 softmax 更新每行最大值 m 和归一化质量 ℓ，随后把加权 V 合入未归一化输出 U。若最大值从 mₒ 改为 mₙ，旧质量与旧 U 都要乘 exp(mₒ−mₙ)，最后才用 ℓ 归一化；完整推导见 [attention IO](../algorithms/attention-io.md)。

核对缩放方向的设定反例：两块分数分别为 0、2，对应 V 分别为 1、0。输出应为 1/(1+exp(2))≈0.1192，落在 V 的凸包内。若把旧累加量向相反方向放大，会立即破坏该关系。应从归一化恒等式检查伪代码，不能仅因材料是固定论文就照抄所有公式排版。

QK、softmax、PV 在同一块内有顺序依赖；跨块或跨 warpgroup 可以重叠部分矩阵与标量工作，但要同时保留所需分数、概率和输出代次。额外 Bq×Bk 分数片段会增加寄存器压力。增大 Bq 提高 K/V 重用，增大 Bk 改变加载和归约粒度；长历史 decode 的少量 query 又可能需要拆分 KV 以获得并行度，再支付部分统计合并成本。

## 如何验证选择及其反转

在代表 shape 上分别比较单/多级缓冲、普通/专门分工、不同 tile 和融合程度。检查实际生成的指令路径、共享存储与寄存器、spill、内存事务及时间线，而不把源代码中的异步调用当成已经重叠的证据。正确性覆盖非整除尾部、全 mask 行、不同历史长度、GQA 映射和归约次序。

短输入或小矩阵可能由启动与调度支配，深流水的启动/收尾反而较贵；长 prefill 更容易摊薄这些成本；长历史小 batch decode 可能受 KV 带宽与并行度约束。最终对照还要回到服务 SLO，避免局部 kernel 的工作区或驻留资源挤占可服务请求。

## 诊断案例：三级为何比两级慢

设已经确认两候选产生相同容许误差的输出，输入、tile、线程映射、计时边界与预热条件相同，仅改变缓冲级数。在目标机测得三级更慢，至少要区分下表的竞争解释。下表是待实施的实验推理，不是本库已经测得的GPU结果。

| 解释 | 可区分的预测 | 保持可比的干预与观测 | 什么结果要求修正解释 |
|---|---|---|---|
| 首尾比重增加 | 长K时固定额外代价被摊薄，稳态斜率应更好或接近；J很小时差距大 | 固定tile与实现，扫J，拟合固定项和每阶段项；逐次计时而非只计峰值吞吐 | 三级的长J斜率更坏，不能再只归因首尾 |
| 寄存器压力造成spill | 三级新增local读写，寄存器/片段生存区间改变，长J也持续支付交通 | 检查实际生成程序和local交通；缩小非关键临时量或改变其生存区间，再以相同计算验证 | 未出现spill或消除spill后仍不改善，需要其他解释；“寄存器数高”本身不等于spill |
| 驻留降低 | 单CTA三级可能更快，足够CTA的整网格反而慢；共享/寄存器限制对应驻留台阶 | 分开比较单CTA与多CTA，记录实际资源和活跃CTA；只改变可用资源或tile时重新记录工作量 | 驻留不变且未受资源限制时，这个解释缺少支持 |
| 没有形成预期重叠 | 源程序增加异步表达，实际复制/矩阵指令或等待位置却未改善，暴露空洞仍在 | 查生成指令与依赖，使用时间线/受限微实验；保持工作量检查copy与compute是否能独立推进 | 等待确实减少但运行变慢，应调查新增交通/驻留，不能仍称“没有重叠” |
| 准备或转换增加 | 只看kernel可能改善，完整调用却变慢；重复复用准备后差距应改变 | 分别记录准备、转换、kernel和输出可消费时刻，按真实复用频率比较 | 差距全在kernel内时，准备不能解释它 |

给一个可复算的反驳过程。若两级时间模型为T₂=10+2J，三级为T₃=18+1.7J，单位均τ，则J=8时26对31.6、J=64时138对126.8，交点约26.67。“小输入三级慢主要因为首尾”与这组设定一致。随后若新增长输入观测却符合T₃′=18+2.4J，J=64时为171.6，则更大的固定项已经不足以解释，必须调查稳态瓶颈。所有值为合成观测，不能放入运行观测库冒充设备测量。

若再发现三级共享分配超过某个驻留台阶、local交通没有增加，应把“spill导致更慢”的假设降级，优先检验资源驻留；但驻留和未重叠可以同时发生，消除一个因素后仍需复测完整边界。只降低寄存器上限可能诱发更多spill，不是隔离驻留的干净实验。改变tile也同时改变复用、任务数和算术强度，应明确这些混杂，而非把每次变快都归因于唯一指标。差异落在重复测量的不确定区间时保留未知，方法见[统计实验](../tools/statistical-experiments.md)。

正确性诊断使用与性能假设分开的反例：K=0/1/7/8/9/17，M/N非整除，交换两warp结束次序，延迟最后一次复制；用独立稠密参考检查每个输出，再注入“只等一个读者”“把旧代票据当新代”“少消费最后阶段”“将全局stride误用为共享stride”。先确认这些错误确实可被检查发现，才讨论流水更快。标量参考与有限事件模型不能证明真实GPU的作用域、可见性或内存竞态均正确。

## 流水的首尾与短输入必须单独推导

固定 [FA3 v1](../sources/S-FLASHATTENTION3.md) 的多级伪代码展示了重叠意图，但打印的循环边界和部分状态交接不足以直接作为实现。例如两阶段示意在只有两块 K/V 时，需要明确计算第二块分数，并依次使用两块各自的概率与 V；不能让循环为空后仍引用未生成的最后概率。独立时序表应保证每个必要 K/V 块恰好计算一次、输出使用同一最大值尺度、收尾按最终归一化分母处理，并覆盖 1、2、3 块、非整除尾部和取消前的最后访问。

其三阶段实验也说明，更多理论重叠可能因额外概率片段和缩放状态挤占寄存器，迫使 tile 变小；实际编译结果又未得到预期的全部重叠。因此候选选择应同时比较算法依赖、生成指令和资源占用，不能只比较源代码里的阶段数。

## 没有 TMA 与线程块簇时的流水组织

固定 CUDA 12.8.0 编程指南的特性表将TMA单元、线程块簇与分布式共享存储支持的边界列为CC 9.0，将所述global→shared硬件加速异步复制与硬件split arrive/wait barrier的边界列为CC 8.0。这里说的是所列特性的硬件支持，不能由没有硬件加速推出不存在软件同步。本章的生产者/消费者与复用依赖也不要求某一代专有指令。

同为8.x也不能共用一组容量。固定指南Table 24列出下列值；其中KB按1024字节解释。它们是规格上限，不保证编译出的kernel达到该驻留，较大动态共享分配还需满足相应配置与opt-in条件。

| CC | 每SM线程/warp上限 | 每SM共享上限 | 每block共享上限 |
|---|---:|---:|---:|
| 8.0 | 2048 / 64 | 164KiB | 163KiB |
| 8.6 | 1536 / 48 | 100KiB | 99KiB |
| 8.7 | 1536 / 48 | 164KiB | 163KiB |
| 8.9 | 1536 / 48 | 100KiB | 99KiB |
| 9.0 | 2048 / 64 | 228KiB | 227KiB |

全局到共享存储的加载：没有TMA时，可以由线程计算地址，通过普通加载或可用的异步复制指令搬运。对齐、swizzle和索引可能增加发射与寄存器需求。cp.async可使用4/8/16字节片段，按所用接口的批次/同步对象等候；TMA处理多维描述符与事务完成时有不同契约。一次tile复制不等于物理上只有一笔事务，任何路径都应区分描述符数、发出指令与实际存储事务。

跨block的部分和交换：选择不同CTA各算一段归约时，常规独立CTA实现可经设备全局存储写部分结果，再由后续kernel或合适的原子协议合并；这会增加交通与完成边界。存在具备其自身launch/驻留约束的协作执行等其他选择，不能断言无簇时所有组织都只能采用某一协议。另一选择是不拆到多个CTA，直接避免跨CTA部分和，但可能留下并行度不足。真实收益取决于额外交通与所缓解的瓶颈。

片上容量：三级32KiB输入缓冲已占96KiB，在99KiB每block上限下只剩3KiB给其他共享对象，不能再增加完整32KiB一级；在227KiB上容量约束较松，但多分配仍可能降低每SM驻留。缩小Kₜ或减少级数是候选，改变线程数、累加放置与tile则要一起重算寄存器和共享账。延迟隐藏可能来自更多可运行warp、每线程独立工作或异步重叠，不能由CC标签直接判定哪一种占主导。

矩阵指令：固定指南§16.7–16.8区分CC 8.0/8.6/8.7的第三代与8.9/9.0的第四代Tensor Core及其输入格式支持；9.0另有warpgroup范围的异步矩阵机制。具体形状、dtype、布局与工具链入口仍按目标指令核实，不能从“支持FP8”推出任何矩阵API都支持FP8。把Hopper的warpgroup分工改到warp级指令，需要重新安排accumulator持有者、交接与完成范围；改到ROCm的MFMA/LDS或其他平台同理，不能继承32lane与CUDA barrier约定。

这些替代各自的成本可以单独测量：加载指令占比、cp.async 等待空洞、全局交换字节与归约 kernel 时间、占用率上限下的实际驻留。它们是设计轴上的点，不是 8.x 的固定配方；一个在 9.0 上最优的流水在 8.9 上可能被更浅、更小、更多 block 的组织超过。轴上未列点同样合法。
