{"chapter":"# K-WORK-009：服务成本与能耗：按合格结果计算资源代价\n\n服务成本回答“交付相同质量与服务目标的结果，消耗了多少资源”。峰值吞吐、最大设备利用率与最低瞬时功率都不能独立回答这个问题。比较前先固定 offered workload、输出工作量、质量判定、事件边界和服务目标，再定义合格完成的分母。总成本较低不等于单位合格结果成本较低；平均功率较低也不等于完成同一任务消耗更少能量。\n\n## 计量合同：分母、窗口与资源域\n\n一次成本比较写成合同 `O=(c,W,P,[a,b),h,D,B,Q,S,π,α)`：`c` 是候选身份，包括代码、权重、配置和精度；`W` 是输入、到达过程、缓存与状态条件；`P` 是逻辑请求总体；`[a,b)` 是准入观察窗；`h` 是排空与完成边界；`D` 是资源计量域；`B` 是完成事件边界；`Q` 是质量判定；`S` 是时延与成功条件；`π` 是价格或权重；`α` 是共享资源的分摊规则。\n\n本章采用到达 cohort 作为主口径：在 `[a,b)` 内首次进入服务总体的逻辑请求组成分母总体，资源从 `a` 计到 `h`。若生产服务继续接收其他请求，资源账包含混合工作，必须另用隔离或分摊；不能把全部设备占用都归给该 cohort。窗口完成账是另一种口径：只统计 `[a,b)` 内完成的结果，并只计同一窗口资源；它可能包含窗口前已开始的请求，必须显式声明。\n\n对逻辑请求 `i`，令 `G_i=1` 当且仅当它已被合法准入、在 `h` 前产生唯一的最终有效结果、通过质量判定，并满足所选首 token、ITL 或完成时延条件。重试共享逻辑请求身份，不增加 `G_i`。于是\n\n`N_good = Σ_i G_i`，`C_unit = C / N_good`，`E_unit = E / N_good`。\n\n`N_good=0` 时单位成本与单位能量未定义，不能报告为零、无穷或“无成本”。拒绝、超时、质量失败、取消和 `h` 时仍未完成者不进入合格分母，但保留状态计数和已发生成本。不同输出长度、分辨率或音频时长若已改变任务身份，不能直接用缩短后的合格结果与原来的任务比较。\n\n合法性还包括：窗口和单位有限且一致；候选、质量 oracle 与服务条件在分子分母中一致；同一物理 backing 不重复计费；累计能量计数在同一计量域内读取；层次计数器不把祖先与后代相加；共享资源的逻辑分摊不冒充物理测量。闭环请求生成会在系统变慢时降低后续压力，独立到达则不会，因此不同到达模型下的同一 `N_good` 与 `C` 不能直接互换。\n\n## 合格结果的完整归约\n\n下面的算法把请求状态、尝试、质量、时延和成本绑定在同一个合同上。它只消费显式事件，不根据“已生成 token”推断请求完成。\n\n```pseudocode\n算法 AccountCohort(O, requests, attempts, usage_segments, meters)\n输入：观测合同 O；逻辑请求；尝试与终态事件；资源占用区间；计量读数\n输出：N_good、各状态计数、资源向量、单位指标；或未定义原因\n\n1 校验 O：时间单位、窗口、候选身份、质量与 SLO 谓词、资源域、价格单位\n   要求 h≥a，资源计量范围与分母 cohort 可关联\n2 建立逻辑请求映射；同请求的重试不新开分母条目\n   同一事件身份重复且载荷相同则去重；同身份不同载荷报冲突\n3 对每个逻辑请求 i：\n   若首次发出或准入时间不在 [a,b)，从主 cohort 排除并记录原因\n   若从未取得合法准入，计 rejected 或 pre_admission_terminal，G_i=0\n   否则按尝试顺序检查最终事件：\n     无终态且 h 已到：计 censored，G_i=0\n     终态为取消、超时或错误：G_i=0，保留已发生资源\n     正常终态但质量不合格：G_i=0\n     正常终态且质量合格但 SLO 不合格：G_i=0\n     唯一最终有效结果在 h 前且质量与 SLO 均合格：G_i=1\n4 汇总 N_good、N_offered、N_admitted、N_rejected、N_failed、N_censored\n   若 N_good>0，计算 goodput=N_good/(b-a) 与 C_unit=C/N_good\n   若 N_good=0，单位指标返回 undefined，并保留窗口总资源\n5 对每个资源域，把占用区间裁剪到 [a,h)，按物理资源身份取并集\n   设备秒、CPU 秒、内存字节秒、存储字节或请求、网络字节分别累计\n6 对能量读数选择互不包含的计量覆盖；同一域读取同一计数器\n   有重置、回绕不唯一或域不匹配时，能量记为不可用，不以零替代\n7 若价格与资源单位完整，计算货币成本 C=π·u+固定费用\n   否则只返回资源向量 u，不把不同单位直接相加\n8 返回分母、完整状态、资源向量、单位指标或明确缺失原因\n```\n\n正确性不变量是：分母中的每个 `i` 身份唯一；最终结果唯一；失败与重试仍进入资源账；资源区间取并集后再计物理占用；没有质量与 SLO 证据的结果不因“已返回字节”自动合格；没有计费证据的资源不因价格为零而消失。\n\n## 成本向量与共享资源的可加性\n\n成本先表示成带轴和单位的资源向量\n\n`u = (U_dev, U_cpu, U_mem, U_io, U_net, E)`，\n\n其中 `U_dev` 是设备占用秒，`U_cpu` 是主机 CPU 秒，`U_mem` 是字节秒，`U_io` 是存储字节或请求数，`U_net` 是链路发送与接收字节，`E` 是焦耳。只有在价格、计量域与时间范围一致时，才写成\n\n`C = p_dev U_dev + p_cpu U_cpu + p_mem U_mem + p_io U_io + p_net U_net + p_E E + C_fixed`。\n\n设备占用包括加载、预热、等待、执行、排空、失败重试和必要热备用。对同一设备上的并发使用者，设备秒应按实际占用区间的并集计算，而不是把重叠区间直接相加。主机 CPU 秒可以跨核心相加，但不等于墙钟时间。内存使用可写成 `U_mem=∫M(t)dt`；`M(t)` 是同一时刻唯一物理 backing 的集合大小，已由池覆盖的内部对象不能再次相加，`peak` 与字节秒是两个不同指标。\n\n层次资源计数器需要选择互不包含的覆盖。父层 cgroup 的 `memory.current` 包含后代，父子读数不能相加；CPU quota 是每个周期的上限，不是已经消耗的 CPU 秒或能量。相同规则适用于设备与网络的层次统计。\n\n多租户共享时，物理总量与逻辑分摊分开记录。设分摊系数为 `α_i`，`Σα_i≤1` 或按服务契约定义的份额归一化；租户成本为 `α_i C`，这是归因规则，不是单租户的物理测量。按请求、设备时间、KV 驻留或预留容量分摊会得到不同结果。暂时闲置但必须保留的故障容量要明确计入哪一方的预算。\n\n## 能量积分、计数器回绕与分层功率域\n\n能量是观察区间内功率的积分：\n\n`E([a,b)) = ∫_a^b P(t)dt`，`P_avg = E/(b-a)`。\n\n平均功率低而运行更久，可能消耗更多能量。可以报告总能耗，也可以报告相对空闲基线的增量 `E_inc=E-E_idle`；二者回答不同问题，必须写清系统边界、空闲基线与测量区间。板卡、CPU package、DRAM、整机入口和机房设施属于不同计量域，不能因为名称相近就相加。\n\nLinux powercap 的累计能量单位为微焦，并提供 `energy_uj` 与 `max_energy_range_uj`。在同一域、无重置且已确认至多一次回绕时，可从两端读数恢复增量：\n\n`Δe = e_b-e_a`，若 `e_b≥e_a`；否则 `Δe=e_b+R-e_a`，其中 `R` 是计数范围。\n\n`E_J=Δe/10^6`。若计数器可被重置，必须结合重置事件；若出现多次下降、域切换或无法排除重置，不能把简单差分当能量。`e_b=e_a` 也可能是零增量或整周回绕，缺少中间证据时该区间不唯一。\n\n```pseudocode\n算法 EnergyFromCounter(readings, R, reset_events, domain)\n输入：同一计量域的累计读数 (t,e)，计数范围 R，重置事件\n输出：Δe 与 E_J，或不可用原因\n\n1 要求 R>0、读数时间严格递增、e 在 [0,R] 内\n2 对每对相邻读数：\n   若区间内有 reset 事件：返回 reset_unresolved\n   若 e_next≥e_prev：增量=e_next-e_prev\n   否则：增量=e_next+R-e_prev，并记录一次回绕\n3 若总回绕次数大于 1：返回 multiple_wraps_unresolved\n4 若端点相等且无法证明没有整周回绕：返回 equality_ambiguous\n5 返回 Δe 与 Δe/10^6 J；不把毫秒、微秒或瓦特混入\n```\n\n层次 power zone 中，父区包含子区。例如 package 区包含 core 与 uncore 子区；只能在一个互不包含的覆盖上取总量，不能把 package 与 core、uncore 同时相加。多个互不重叠的 package 顶层可以相加。RAPL 不提供瞬时功率值时，不能用约束窗口参数代替实际功率积分；接口存在也不保证所有平台暴露相同域。\n\n## 条件化选择：频率、批量、冗余与空闲\n\n降低频率或功率上限可能降低瞬时功率，却延长执行、扩大队列并改变 `N_good`。设候选 1 与候选 2 的平均功率分别为 `P1,P2`，完成同一合格输出集合的时间为 `T1,T2`，则只有在 `P2T2/N2 < P1T1/N1` 时，单位合格结果能量才下降；若 `N2` 也下降，必须把质量失败和超时计入。\n\n增加 batch 可能摊薄权重读取、主机调用与准备开销，也可能增加等待、峰值内存和尾延迟。比较时保持输出任务与 SLO 不变，记录 batch 形成等待和失败。热备用减少冷启动与首 token 超时，却支付闲置驻留；按需启动节省驻留，却可能增加启动失败和排队。公平比较应使用同一 offered 轨迹、同一完成边界和包含失败、排空与必要冗余的总成本。\n\n硬件采购、租赁价格和电价属于不同决策模型。短期任务可用实际计费单位；长期自建需显式给定摊销和利用率假设。若目标只是比较设备时间或焦耳，应先报告这些可复核量，避免价格假设掩盖机制。\n\n## 设定算例：总成本较低但单位成本较高\n\n以下价格、功率与请求数均为设定值。两候选在同一小时、同一 offered workload 与同一质量合同下运行：A 总设备与主机成本 4 单位，合格完成 10,000 请求；B 成本 3 单位，合格完成 6,000 请求。\n\nA 的单位成本为 `4/10000=0.0004`，B 为 `3/6000=0.0005`。B 的每小时费用较低，却没有更低的合格结果成本。若 B 经合法调度在同一成本下完成 9,000 个合格请求，单位成本才降至 `3/9000≈0.000333`。\n\n再设同一完整计量域内 A 的平均功率为 500 W，B 为 350 W，测量区间均为一小时。A 消耗 1.8 MJ，单位合格结果 180 J；B 消耗 1.26 MJ，单位合格结果 210 J。若空闲基线均为 100 W，增量分别为 144 J 与 150 J；增量指标不包含全部运行能量，不能替代总能耗披露。\n\n若 B 通过缩短输出或丢掉质量失败请求获得 6,000 个合格结果，任务身份已经改变。必须先恢复共同质量与输出合同，再重算分母；不能仅凭 tokens/s 或每小时总成本认定改善。\n\n## 共享基座、租户分摊与预留容量\n\n多租户共享基座时，物理资源和逻辑份额要同时保留。若同一 GPU 在一小时内被两个租户并发使用，设备秒的并集只能是这一小时；按各租户占用区间分摊后，两个份额之和不应超过物理总量。按请求数、KV 驻留或保留容量分摊会给出不同的租户成本，分摊规则属于服务契约，不能把没有实际减少的设备时间当作节省。\n\n预留池与其内部存活对象不能重复相加。若为故障保留一台设备，闲置能量和容量属于服务可靠性成本；它可分摊给租户或平台预算，但不能同时作为可用容量出售。把热备用关闭后，若冷启动失败增加，失败请求已消耗的加载、排队和重试资源仍要进入分子，合格分母却不会增加。\n\n## 条件变化后的保留与放弃\n\n| 条件变化 | 保留的机制 | 应调整或放弃的结论 |\n|---|---|---|\n| 输出长度、分辨率或音频时长改变 | 任务身份与质量 oracle | 不能沿用原单位成本；恢复共同输出合同后重算 |\n| 到达从闭环变成独立到达 | 完整 offered 与状态账 | 旧平均吞吐不能代表新压力；重算排队、拒绝与 N_good |\n| 频率降低或功率上限收紧 | 能量积分与完成时间 | 若 P 下降但 P·T/N_good 上升，放弃“更节能”结论 |\n| batch 增大 | 质量、TTFT、ITL 与峰值驻留 | 若等待或尾延迟使 N_good 下降，重新比较单位合格成本 |\n| 热备用切换为按需启动 | 启动、失败、排空和驻留成本 | 若冷启动失败与首 token 超时增加，不能只报闲置能量下降 |\n| 设备域或平台改变 | 计量域身份、范围和单位 | 旧计数器常数、回绕范围与域关系不能直接沿用 |\n| 共享租户或故障余量改变 | 物理总账与分摊规则 | 必须分别报告平台总成本、租户分摊和可靠性预留 |\n\n条件变化后，任务身份、事件边界和守恒关系可以保留；价格、功率、到达、质量、窗口和硬件域变化时必须重新建立相应合同。\n\n## 区分竞争解释与反证修正\n\n| 观察 | 竞争解释 | 可控改变、预测与修正 |\n|---|---|---|\n| 总能量下降而单位能量上升 | 真实效率提高、输出变短、失败增多或分母变化 | 固定任务与质量，恢复相同输出长度，保留全部失败；若差距消失，先修正分母解释 |\n| 平均功率下降但总能量上升 | 运行更久或测量区间不一致 | 固定同一区间与域，同时报告 P_avg、E 与完成时间；E 上升则不能称总能耗改善 |\n| 计数器差分为负 | 一次回绕、重置、域切换或读数错误 | 检查范围、重置与同域身份；能证明一次回绕才恢复，否则报不可用，不能把负数截为零 |\n| package 与 core 相加后能量偏高 | 层次功率域重复计数 | 改用互不包含的覆盖；父区与子区同时出现时拒绝求和 |\n| batch 增大后每 token 能量下降 | 固定开销摊薄、测量窗口变化或输出变短 | 固定质量与 token 身份，计入等待、KV 驻留和失败；单位合格结果仍下降才支持机制 |\n| 频率降低后每小时电费下降 | 功率下降、运行时间变化或价格假设变化 | 固定电价和任务，比较 E/N_good 与 C/N_good；若完成量下降，分开报告总费用与单位费用 |\n| 关闭热备用后闲置能量下降 | 真实节省、冷启动失败或服务目标退化 | 保持 offered 轨迹与 SLO，计入启动、重试和超时；合格结果成本不降则撤回节省结论 |\n| 某平台没有能量计数 | 域未暴露、权限或配置不足 | 报告缺失与覆盖范围，不把缺失写成零；改用可复核的功率采样时另写采样误差 |\n\n负对照必须实际进入判据。例如，重复的成功完成事件若被当成两个逻辑请求，独立身份参考应拒绝该分母；把一次回绕的读数和直接末值相减，参考应给出负值或不可用；两个重叠设备区间直接相加，参考应比区间并集大；父区与子区同时求和，参考应比顶层覆盖大。只有这些故障变体被同一判据拒绝，检查才测试了机制，而不只是重述公式。\n\n## 随章检查与证据边界\n\n配套文件为 tools/check_k_work_009_full.py，仅使用 Python 标准库，确定性、离线、只读。它以独立逻辑请求身份核对去重与合格分母，以分段增量核对累计计数器的一次回绕，以端点网格核对资源区间的并集，以祖先关系核对功率域覆盖；同时检查 `N_good=0` 时单位指标未定义、重复成功事件不得增加分母、重置与多次回绕不得被当作正常能量。\n\n检查故意包含故障变体：重复成功事件被误计为两个请求、回绕差分直接取末值、重叠区间直接相加、父子功率域同时求和。它们都必须被独立参考或显式不变量拒绝。该检查是 CPU 上的逻辑与代数模型，不测 GPU、RAPL 平台、真实服务、网络、租户分摊、统计尾延迟或 Agent
