# K-ALG-022：非前缀上下文复用：依赖、位置与选择性重算

同一段文本在两个请求中出现，只能证明输入内容重复。它在某层产生的状态还取决于可见上文、位置规则和模型版本。非前缀复用的设计起点，是判定哪些依赖保持不变，以及允许用多少计算和质量损失处理其余依赖。

## 一段文本有多种可以缓存的对象

分词结果、独立文档 embedding、检索结果、decoder 的逐层 KV 和最终回答，依赖范围各不相同。固定 tokenizer 下的文档 token 可以脱离用户问题保存；双向编码器的文档 embedding 若由独立文档输入生成，也可在相同编码函数下复用。decoder 的第二段 KV 通常已经包含第一段的信息，不能仅用第二段文本定位一个通用的精确状态。

对因果 decoder，设输入为 A、B、Q，分别表示两个材料片段与问题。第一层投影的输入主要来自 token embedding、位置和该层前处理；经过 attention 后，B 的隐藏状态已吸收允许看到的 A。更深层 B 的 K/V 因而依赖 A。将 B 改到 C 后面，即使 B 的 token 完全相同、位置也碰巧相同，逐层状态仍可能改变。状态缓存身份应描述实际依赖，不能把文本哈希当作这些依赖成立的证明。

需要区分三个结果目标：完整函数的数值一致、在允许误差内的一致、任务质量达到阈值。选择性重算通常属于第三类；少数任务上的回答相同，不能升级为任意输入的精确复用。

## 精确复用需要满足依赖条件

已有完整前缀的 KV 可以在相同模型、adapter、token 序列、位置/窗口和数值格式下复用。若某模型明确规定片段间互不可见，独立片段的计算才有机会直接组合；这时参考函数本身必须采用相同可见性。人为关闭跨片段 attention 会改变原模型，不能作为原函数精确复用的实现技巧。

对于 RoPE，若旋转前向量确实相同，旧位置 p 的 K 可以通过 R(p′)R(p)ᵀ 转到位置 p′。这个等式修正的是旋转坐标；它不会重新生成因上文变化而改变的隐藏状态，也不会补回跨片段 attention。频率、缩放、旋转维度及其布局都必须相同。使用绝对位置 embedding、其他位置变换或依赖当前长度的缩放时，应重新建立对应的变换条件。

一个二维反例能检查实现是否保留了完整旋转。令旋转前 q=(1,0)、k=(0,1)，q 旋转 π/2、k 保持角度 0，则旋转后两者均为 (0,1)，点积为 1；只保留与 cos 对应的同维乘积会得到 0。相对位置不变性应由完整旋转矩阵验证。CacheBlend v1 附录的打印展开式省略了混合分量，本章使用矩阵恒等式推导，不依赖该展开式。

## 选择性重算如何连接缓存与当前输入

CacheBlend 的固定 v1 提出逐层融合：为一部分 token 重新计算当前层的 Q/K/V，将其 K/V 写入对应的逻辑位置，其余位置沿用缓存；被选择的 Q 与该层完整可见 K/V 做 attention，得到下一层需要的隐藏状态。被选择 token 的计算量下降，但全历史 K/V 的读取、装载和索引工作仍然存在。

选择集合必须来自在线可取得的信息。先完整计算一个早期探测区域，再比较新旧状态并逐步缩小重算集合，是一种可实施的路线。使用所有层完整重算得到的误差来选 token，属于离线 oracle，只能评价选择策略上限。具体在哪层观察偏差，要与真实计算顺序一致：若第一层投影尚未吸收上文，不能假定它已经暴露了深层跨片段偏差。

集合在逐层缩小时，下一层需要的 token 必须仍有合法输入隐藏状态；已丢弃 token 不能只凭一个新索引重新加入。允许重新扩张集合的实现，需要保留相应中间量或补算其依赖。查询文本、未命中的新片段以及必须产生最终输出的 token 应单独处理，不能被缓存命中比例掩盖。

这些规则保留了“部分更新”的可执行性，但不证明质量。高偏差 token 与最终回答的重要性并不总是一致：一个数值很小的否定词、跨材料的实体对应或少数位置的错误，也可能改变任务结果。重算比例应绑定模型、片段构造和任务分布；论文中的经验比例不能成为知识库默认保证。

## 多层缓存的状态与所有权

独立预计算的片段缓存与某次请求融合后的缓存是不同对象。融合结果依赖该请求的前序片段、顺序、位置和选择策略；将它覆盖回“独立片段 B”的公共条目，会污染后续请求。公共对象应保持其原始依赖含义，修改部分使用私有缓冲或写时复制；确需保存组合结果时，应登记组合依赖。

请求状态至少包含片段及版本序列、各片段的 token 范围、原位置与目标位置、每层就绪范围、重算选择集合、数值格式和当前代次。加载完成、位置变换完成、部分更新完成、消费者可见是不同事件。当前层只能读取已完成的数据；异步获取下一层时还需计入在途缓冲。取消后停止新工作，并等待已提交的读写结束再复用缓冲。

KV 量化、裁剪与片段融合的误差不能分别通过后直接视为组合通过。量化会改变偏差排序，裁剪会删除融合需要访问的位置，稀疏页布局也会改变 gather 的成本。近似缓存应沿用其构建策略身份，避免精确前缀路径误读它。

## 计算与传输要分别记账

设总材料长为 L，第 i 层重算 rᵢ 个 query。该层 attention 的逻辑工作与 rᵢL 相关，投影和 MLP 工作与 rᵢ 相关；加载缓存仍可能与 L 相关。选择、gather/scatter、位置变换、缓存解码、尾块浪费和不规则 kernel 的效率也都需要计入。因此“重算 10% token”等于“耗时 10%”仅是粗略候选模型。

对逐层加载与计算流水，设每层加载 a、计算 c，有 H 层且独立资源和足够缓冲，则理想时间为 a+c+(H−1)max(a,c)。设定 H=4、a=6 ms、c=2 ms，得到 26 ms，串行为 32 ms；若 c 增为 9 ms，流水为 42 ms，计算不能被 6 ms 的加载隐藏。实际还包括启动、尾部、选择和竞争开销。相同 PCIe、DRAM 或 HBM 被两阶段共用时，a、c 必须在并发条件下测量。

缓存容量也不是命中片段数乘一个常数。一个标准 KV 片段的有效字节为 2H L Hkv d s，此外有格式元数据、页尾、私有更新、位置转换和双缓冲。若多个组合必须分别缓存，复用率上升可能伴随容量急剧增加，需要比较保存独立片段后近似融合与保存少数常用完整前缀。

## 验证、反例与方案反转

先建立完整 prefill 参考，固定材料文本、顺序、问题、模型和采样设置。覆盖 A→B 与 C→B、A→B 与 B→A、同文本不同位置、一个字的否定修改、跨片段指代、不同 adapter、缺失缓存以及加载中断。记录逐层状态/最终 logits 偏差，同时在真实任务上测答案正确性、依据一致性和长材料表现。性能统计包含检索后到首输出的全部阶段；若声明用户端 TTFT，还须包含检索和重排。

精确前缀命中高、材料很短或设备重算很快时，常规前缀缓存与全量 prefill 更有利。长材料的非前缀复用高、传输可以与少量重算重叠且质量阈值允许时，选择性重算才可能获益。跨材料依赖强、查询分布变化或高精度答案要求提高时，应提高重算范围或回到完整函数。决定反转的信号是实际端到端成本与质量约束，而不是缓存命中率本身。
