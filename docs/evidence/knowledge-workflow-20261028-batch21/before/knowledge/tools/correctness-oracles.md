# K-TOOLS-006：正确性 Oracle：函数参考、状态变形与服务契约

正确性验证需要一组互补、具有明确前提且能够拒绝已知错误的 oracle。函数参考约束数值函数，变形关系约束执行组织改变后的语义，概率 oracle 约束分布，协议与资源 oracle 约束身份、事件、所有权和终态。它们提供不同范围的证据，不能由一条看起来合理的最终文本相互替代。

## 任务契约、身份与判定域

设任务契约 C 包括输入规范化、模型与权重身份、processor、位置与 mask、数值策略、采样和停止规则、协议终态与资源责任。一次执行尝试记为 R=(r,g,x,θ,ε,h,Obs)：r 是请求身份，g 是执行尝试代次，x 是规范化输入，θ 是模型和采样配置，ε 是环境，h 是执行历史，Obs 是观测。物理槽 s 的分配代次 e 与请求尝试 g 是两个独立坐标；同一请求重试可以改变 g，同一槽被另一个请求取得可以改变 e。

一个 oracle 定义为 O=(D,Pre,Rel,Ev,Cmp)。D 是输入与状态域；Pre 是合法前提；Rel 是应成立的关系；Ev 指明可用证据及其覆盖；Cmp 指明比较算法、单位和容差。另附独立性声明 Ind：预期值或判断规则不能依赖正在检验的故障组件。例如参考可以共用权重文件，但验证分页索引时不能共用被测页表；验证 processor 时不能共用同一个 processor。

应检查实例集合 Ω 必须由任务预先给出，不能从实际返回的成功记录反推。每个实例进入以下一种结果：PASS 为前提相容、证据完整且关系成立；FAIL 为具有有效失败见证；INVALID 为参考定义、版本或比较单位已知不相容；UNKNOWN 为缺少必要证据而无法判定。Ω 为空不能借全称命题的空集真值报告完成；负对照未被拒绝时，检查器不具备该维度的判别资格。

需要区分两种身份不符：把另一个模型版本的参考误拿来比较，属于比较前提 INVALID；在已经冻结、身份可信的任务表下，服务把旧尝试结果提交为当前结果，则违反输出归属义务，属于 FAIL。若连日志归属都无法确认，应保留 UNKNOWN，不能直接归因于引擎数值错误。

状态记录按所检验机制携带请求 r、尝试 g、槽及其代次 (s,e)、分支、逻辑位置 t、对象或表示版本 v 和事件序号。没有一个固定短键可以替代所有层次。例如一次请求可能使用多页，不能要求其所有对象共享一个槽号；终止记录也不能用终止发生时槽的当前拥有者替换产生该尝试的原始身份。

## 函数参考与合法域

固定函数写为 y=F_C(x;θ)。x 包括 token 或特征、逻辑位置、有效输入、可见集合、padding 和缓存状态；θ 包括权重、adapter、归一化、量化参数和推理模式。输入规范化、tokenizer/template、模型参数、位置、mask、dtype 与量化契约必须相容。改变窗口、adapter、stop 规则或前处理，可能已经改变任务函数，不能用放宽数值容差处理。

对有限参考 b 和观测 a，逐元素容差可定义为 |a−b|≤atol+rtol·|b|；向量比较也可声明 ‖a−b‖∞≤atol+rtol·‖b‖∞。这两种关系不同，应固定使用哪一种。atol 与张量的物理或数值尺度相联系；参考接近零时，不能只依赖相对误差。NaN、正负无穷和空张量由契约单独处理，默认不把 NaN 与 NaN 当作通过，也不把 inf−inf 的结果交给普通容差分支。

浮点归约重排、批量与切片路径可能产生差异，因此数学等价不要求跨后端逐位一致。但容差通过也不证明最终选择相同。设参考最高两个分数 z(1)≥z(2)，各分数观测误差均不超过 ε。最高分最多下降 ε，竞争者最多上升 ε，因此 z(1)−z(2)>2ε 足以保证 argmax 不变。等号处不能保证，margin 更小时应报告证书不成立，再检查实际选择或提高参考精度，不能自动宣称实现错误或质量合格。

低位路径先验证固定量化函数，再评估原模型质量。对 r=S(q−Z)，输入参数为 (S1,Z1)、(S2,Z2)，输出为 (S3,Z3)。长度 N 的整数点积为

A=Σj(q1j−Z1)(q2j−Z2)
 =Σj q1j q2j−Z1Σj q2j−Z2Σj q1j+NZ1Z2。

若 bias 使用 Sbias=S1S2、Zbias=0，整数 bias b 加入 A。理想输出码坐标为 q3*=Z3+(S1S2/S3)(A+b)，实际输出还要按契约做舍入、饱和及激活钳位。q3* 通常不是整数，不能省略这些步骤后声称得到实际输出码。独立参考可先逐项解码相乘，再与补偿式核对；漏零点补偿、多加 bias、错误处理负数中点舍入应成为能触发差异的反例。该参考验证同制品计算，不证明校准分布上的模型质量，也不把特定 ARM 中间累加条件推广为任意 INT8 硬件保证。

参考还需要状态独立。分页检查从逻辑 token 历史重建输入；前缀缓存检查从相同不可变前缀独立重算；取消检查从冻结的请求义务与资源票据出发。直接复用待测缓存加速参考，会失去对应缓存索引与内容身份的独立证据。

## 变形关系与状态推进

变形关系记为 MR=(Pre,T,Q,≈)：当 Pre(x) 成立时，Q(F(x))≈F(T(x))。T 改变执行组织，Q 恢复结果身份或顺序，≈ 是精确关系或声明的容差。改变采样随机流、模型版本或可见窗口后，原来的文本等价关系可能不再适用。

批次置换要求 F(π(X))=π(F(X))，比较前先按请求与分支还原结果。它检查 batch 行映射、采样参数和输出归属，不要求不同 batch 几何的浮点结果逐位相同。取消或压紧一行时，token、length、adapter、RNG、KV 句柄和输出目标必须来自同一身份快照；只移动 token tensor 会把一行拼成不同请求的混合状态。

分块 prefill 保持完整逻辑 token、全局位置和可见集合不变，只改变提交边界。普通因果 self-attention 的合法集合为 A_t={j：j 属于同一请求且 0≤j≤t}。第二个 chunk 的局部行号不能重置模型逻辑位置。一个可复算的小模型取 token=(1,2,3,4)、位置权重=(1,3,5,7)，全局参考为 1+6+15+28=50。按 [0,2)、[2,4) 分块仍为 50；第二块错误重置位置后得到 1+6+3+12=22。这个模型检验位置推进，不模拟真实 attention 数值。

物理页置换改变 locate(l,j)，但不改变逻辑位置 j、内容与表示元数据。前缀命中等价要求 tokenizer/template、模型与 adapter、位置规则、前缀内容和 KV 表示身份相容；scale、zero point 或分组改变后，不能拿旧码配新尺度并继续声称同一函数。参考关注合法命中后的语义，不要求缓存策略一定命中。

取消后使用回收槽的请求，应与从全新槽执行具有相同业务语义和资源终态。合法复用要求旧生命期的全部实际访问结束；递增 g 或 e 只能拒绝旧结果提交，不能阻止旧 DMA 写同一地址。测试需控制旧工作晚到、新工作先返回、取消与提交竞争、部分传输完成等时序。随机压力有发现价值，确定性时序便于归因，两者的一次通过都不能证明全部竞态消除。

边界由机制选择：空输入、单 token、跨页、非整除尾部、零长度 chunk、最大合法长度以及空可见集合各有不同前提。合法零长度 chunk 不推进状态；所有 chunk 的有效区间仍须不重叠、无缺口地覆盖输入。空求和参考返回零，不等于空请求义务集合已经验证成功。

## 概率 oracle 与 CDF 边界

对离散概率 p，先要求词表非空、p_i≥0、Σp_i=1，且正概率支持集包含于任务允许集合。约束采样若合法集合质量为零，应按契约失败，不能静默回退到被禁止的 token。

令 C_−1=0，C_i=Σj≤i p_j。对 u∈[0,1)，选择首个满足 C_i>u 的位置，即唯一满足 C_i−1≤u<C_i 的非空区间。这是左闭右开的规则；零概率项的区间为空，必须跳过。

```pseudocode
算法 InverseCDF(p,u)
输入：非空离散概率向量 p；u∈[0,1)
输出：所选 token 下标，或输入/数值覆盖错误
1 核对每个 p[i] 非负、总和为 1，且 u 在声明范围内
2 c←0
3 对 i=0,…,V−1：
    c←c+p[i]
    若 u<c：返回 i
4 报告累计覆盖错误；不得无条件返回最后一个 token
```

p=(1/5,3/10,1/2) 的区间依次为 [0,1/5)、[1/5,1/2)、[1/2,1)。因此 u=0 选择 0，u=1/5 选择 1，u=1/2 选择 2。p=(0,1)、u=0 必须选择 1。p=(0,1/5,0,4/5,0)、u=1/5 选择 3，内部零概率区间与末尾零概率项均不能被选中。使用 C_i≥u 的错误版本会在这些明确边界上失败。

连续均匀 u 落入区间 i 的概率等于区间长度 p_i，给出逆变换的分布依据。实际 RNG 只有有限离散输出，边界可能有正概率，因此不能用“相等事件概率为零”忽略比较符号。浮点累计还可能因归一化或舍入留下覆盖缺口，应预先声明数值策略并检查；无条件返回最后一项可能把末尾零概率项变成可选项。CDF 预处理为 O(V)，线性查找 O(V)；保留累计数组后可用寻找首个严格大于 u 的二分查找，单次 O(log V)，额外驻留 O(V)。重复累计值仍按同一严格边界处理。

固定 seed 的一条文本只支持特定随机轨迹回归。频率检查需预先声明样本数、统计量、阈值和停止规则，例如总变差 0.5Σi|c_i/n−p_i|；其阈值与样本数和任务风险有关。置信区间或拟合检验还依赖独立性、平稳性及多重比较条件。确定性网格枚举能核对小分布的边界映射，不能冒充随机样本的统计检验。投机或拒绝采样还需证明接受与修正规则保持目标分布，单条输出相同不足以证明。

数值容差、分布保持与任务质量分别判定。ASR 词错误率、分类准确率、检索排序、检测定位、图像或语音质量使用各自单位、保留集和失败规则。开发样例用于选择与定位，最终保留样例覆盖未参与选择的输入分层和状态时序。

## 请求结果与终止记录的身份算法

预期内容正确并不意味着结果属于当前尝试。设 A 当前被授权的结果身份为 (A,2,a,8)，值为 17；旧结果 (A,1,a,8,17) 仅改变尝试代次，仍必须拒绝。结果 (A,2,a,7,17) 仅改变槽代次，也必须拒绝。结果值完全相同，说明内容比较不能代替代次比较。

一个有限检查可以冻结表 E[r]=(g,s,e,value,status)，其中每个 r 在本次检查范围内只有一个被授权尝试、一个指定结果槽以及一个应有结果和终止记录。E 从输入计划和授权快照独立声明，不从实际结果或终止记录生成。若生产任务允许同请求多个分支、多槽结果、取消后无结果或多个历史尝试，应把这些义务显式展开；不能直接套用这个单结果模型。

```pseudocode
算法 CheckIdentity(E,Results,Terminals)
输入：独立冻结的非空 E；完整导出的结果与业务终止记录
输出：缺失、额外、重复、身份、内容与终止状态问题
1 分别建立结果账与终止账；两个账均以 r 定位本次义务
2 对两个账中的每条记录：
    若 r 不在 E：记录额外记录
    若同一账已出现 r：记录重复；不能以后一个覆盖前一个
    若 r 在 E：逐字段核对 g、s、e 与 E[r] 相同
3 对每个 E[r]：
    要求结果与终止账各恰好有一条对应记录
    结果内容必须等于 E[r].value
    终止状态必须等于 E[r].status，不能仅检查属于某个状态枚举
4 返回具体字段、预期值和实际值；任一问题均不能汇总为通过
```

r 定位义务不代表忽略代次；g、s、e 必须分别比较。相反，若仅用观测的完整身份键建表，却不与授权 E 比较，旧结果仍可能被错误接受为另一个合法实例。两个账也必须各自对 E 核对，不能让错误结果与错误终止记录互相证明。

完整日志范围内，预期 A=17、B=99，却返回 A=17、B=17，应拒绝 B 的内容；只保留 A 会产生缺失，重复 A 不能抵消缺失 B。导出链不完整时，缺失检查点是 UNKNOWN；随章脚本采用完整合成记录的前提，因而能明确拒绝缺失、重复和额外记录。真实运行需先证明相应日志覆盖。

## 服务协议与共享取消组合

协议 oracle 把响应看作有身份的事件序列。一个明确的普通流式合同可以要求：一个 start 先于 data；data 序号从 0 连续递增；恰好一个业务终止；终止后不再提交内容；按序拼接内容等于终止合同允许的内容；usage 与外部提交至多一次。这是应用合同，不能把一个简化状态机称为完整 ASGI、WebSocket、stop string 或背压实现。

ASGI 固定文档允许断开通知与发送失败存在竞争，旧版本也不保证关闭连接上的 send 一定报错。因此不要求 http.disconnect 与发送异常固定先后。send 返回只支持内容已进入服务器发送缓冲的相应语义，不证明客户端消费，也不能统一推导应用借用缓冲已经不再被读取。业务终态、设备排空、发送访问结束和远端消费分别记录。

沿 A/B 共享前缀、A 取消和私有槽复用展开一条轨迹。P 是共享页，a 是 A 的私有槽，初始分配代次为 7；B 的 kernel 读取 P，A 的 DMA 使用 a。为便于核对，下表暂不设置缓存保留策略与隔离原因。

| 时刻与事件 | P 的逻辑拥有者 / 未结束访问 | a 的逻辑拥有者 / 未结束访问 | 互斥容量类别与提交资格 |
|---|---|---|---|
| 登记访问后启动 | {A,B} / {B-kernel} | {A} / {A-DMA} | P、a 各计一次 Inflight；票据先于启动登记 |
| A 业务取消 | {B} / {B-kernel} | 空 / {A-DMA} | 两者仍为 Inflight；撤销 A 新输出资格，保留两项执行责任 |
| B-kernel 结束，B 仍继续 | {B} / 空 | 空 / {A-DMA} | P 转 Active；a 仍为 Inflight，不能交给 C |
| A-DMA 最后访问结束 | {B} / 空 | 空 / 空 | a 关闭旧生命期后转 Free；A 的业务终态不改变 |
| C 取得 a，代次推进至 8 | {B} / 空 | {C} / 空 | a 转 Active，初始化本代数据后才能发布给消费者 |
| A 的旧业务结果或重复完成晚到 | {B} / 空 | {C} / 当前代责任 | 旧 (A,g,a,7) 无提交权；旧已结算票据不能删除 C 的责任 |
| B、C 最后使用结束并释放拥有权 | 空 / 空 | 空 / 空 | 关闭取得旧对象的新资格后归 Free；若 P 被策略保留，则转 Retained |

若 A-DMA 的完成证据缺失，a 进入 Quarantined，同时继续保存 A-DMA 责任；超时不能代替完成。业务取消可以先发生，资源责任在后续真实结束证据到达时结算。若每个页占 b 字节，A 取消后两个页仍有访问，暂时不可复用容量为 2b；不能因为仅剩 B 一个业务拥有者就只记 b。共享 P 的容量始终只有 b，不按 A/B 引用数倍增。

参考分别从 A、B、C 的逻辑输入重建，检查 B 历史未被取消污染、C 未接收 A 的迟到结果、P 未被提前回收、a 未在旧访问结束前复用。身份错误、共享引用错误和完成错误具有不同见证。仅比较 B/C 最终文本可能漏掉迟到写入；仅检查最终全部空闲可能把提前回收也误判为成功。

## 从正交责任生成互斥资源分区

先固定容量统计域与物理对象粒度。Total 是本域内不重叠的物理单位 s；别名先归并到同一单位，或证明字节范围互不重叠。不同大小单位使用容量 b_s，不能只比较对象数量。每个单位保存当前分配代次 e，容量只计 s 一次，票据仍绑定 (s,e)。预留池容量与池内对象不能重复相加，虚拟地址预留也不自动等于物理驻留。

对每个物理单位记录以下正交字段：

- L：业务或模型版本的逻辑拥有者；共享页可同时有多个拥有者。
- U：已取得启动资格、尚未证明最后访问结束的执行责任，包括 kernel、DMA、图重放和外部读者。
- O：已取得输出读取权、尚未结束的消费者。
- B：长期地址或其他绑定责任。
- H：预留、未完成初始化或尚未取得启动资格但仍需保留对象的计划责任。
- K：具有具体策略与容量解释的保留根，例如缓存目录；它不等于请求拥有者 L。
- Q：隔离原因及逐项解除条件。
- closed：旧生命期已关闭新的取得资格；已有拥有者的合法使用仍按串行状态规则登记。

这里把请求拥有权与缓存保留根分开，是为了说明归类；实际实现可以用带类型的统一责任表。不能把缓存目录既作为 L 又额外计一份物理容量。

采用以下优先级，得到唯一类别：有 Q 则 Quarantined；否则有 U 或 O 则 Inflight；否则有 L、B、H 或尚未关闭取得资格则 Active；否则有 K 则 Retained；剩余为 Free。类别只用于容量投影，不删除其他字段。于是

Total = Free ⊎ Active ⊎ Inflight ⊎ Retained ⊎ Quarantined，

Σs∈Total b_s = Σ各类别 Σs∈类别 b_s。

A/B 共同拥有且 B 正在读取 P 时，P 只计入 Inflight，L_P={A,B} 与 U_P={B-kernel} 都保留；不是同时放入 Active，也不是为了互斥而删掉在途责任。隔离页即使仍有拥有者和 DMA，也只归 Quarantined，具体阻塞仍由 L、U、O、B、H、Q 解释。

```pseudocode
算法 ClassifyPhysicalSnapshot(Total,Raw)
输入：同一一致性边界上的物理单位全集及完整正交状态
输出：五个互斥容量列表和保留原字段的诊断快照
1 初始化五个列表为空；核对每个 s 恰好有一份 Raw[s]
2 对每个 s：
    若 Q[s] 非空：类别←Quarantined
    否则若 U[s] 或 O[s] 非空：类别←Inflight
    否则若 L[s]、B[s]、H[s] 任一非空，或 closed[s]=false：类别←Active
    否则若 K[s] 非空：类别←Retained
    否则：类别←Free
    把 s 加入唯一类别；保留所有责任字段及代次
3 核对列表内外均无重复、并集等于 Total、容量和相等
4 用独立操作票据账核对 Raw 中 U/O 的完整性和 (s,e) 身份
5 返回分区与阻塞责任；仅分区成立不等于已排空
```

一个错误分类器可能把 P 仅放 Active，此时并集与唯一性均成立，却违反语义优先级。因此检查需要同时验证“分区是否完整互斥”与“类别是否由真实责任得到”。另一个错误观测器可能删掉 U 后将 P 放 Active；如果没有独立的启动/完成票据账，任何只读这个残缺快照的分区算法都无法恢复丢失事实。受控逻辑实验可用预先声明的票据作为独立参考，真实系统则需要对应域的完整登记与完成证据。

责任登记、关闭生命期与生成快照需要同一串行状态域，或等价的锁、原子事务与一致性快照。分别读取两个时刻的 L 和 U，可能制造不存在的 Free 状态。完成只结算匹配 (r,g,s,e,uid) 的责任；重复旧通知不能递减另一个使用者，未知通知也不能清空当前代。

对本章的可排空请求池，静止态要求 U、O、Q 为空且无 Active；Free 等于 Total 减去有解释的 Retained。服务级长期权重、图绑定等若属于统计域，应与预先声明的存活基线比较，不能要求仍在服务的权重全部释放。RSS 不下降时，要区分分配器可复用保留、策略缓存和不可达泄漏；最终归类与容量解释比单一进程指标更有判别力。

## 检查流程与条件化成本

检查先冻结要求，再判断观测，最后验证检查器的辨别力。

```pseudocode
算法 ValidateObligations(C,Oracle,Expected,Observed,Terminals,Resources)
输入：任务与 oracle 契约、独立预期义务、观测与终止、资源证据
输出：逐实例判定、失败见证、缺口和明确覆盖范围
1 核对版本、输入、单位与参考合法域；已知不相容记 INVALID
2 保留预先声明的全部义务；未采集或被前序失败阻断的义务不删除
3 核对结果、终止与资源票据身份；按对应契约检查重复、缺失和额外记录
4 对证据充分且前提相容的实例执行函数、变形、概率或协议关系
5 从完整正交责任生成并验证资源分区；单独判断排空与允许基线
6 把已知错误输入或错误算法送入实际比较器，要求产生对应失败见证
7 负对照未检出则撤回相应检查器资格；不能输出该维度的引擎通过
8 仅当义务非空、全部完成有效判定且均通过，汇总本次通过
  其他情况保留 FAIL、UNKNOWN、INVALID 与具体未覆盖范围
```

设序列长度 T、隐藏维 d、层数 L、词表 V。每个生成位置都重做长度 t 的完整稠密 prefill，attention 主项累计 Σt²d=O(T³d)；仅对最后一个 query 使用合法独立历史，主项累计 O(T²d)，但各层历史 K/V 仍须合法产生。其他投影和 MLP 成本要另计；减少 attention 主项不自动给出完整模型加速。

全部层 hidden 的观察驻留为 O(LTd)，逐层只保留一对为 O(Td)。设 T=2048、d=4096、L=32，FP32 一份 hidden 为 32 MiB，一对为 64 MiB，32 层全部配对为 2 GiB；不含 Q/K/V、权重和缓存。V=32000 时全量 logits 为 250 MiB，末行约 125 KiB。只观察末行减少采集与传输，却没有检查未导出的层、位置和状态。

身份、协议与资源元数据检查的平均时间可分别随记录数、内容字节与责任条目数线性增长；哈希账需要相应驻留，若排序输出诊断还要支付排序成本。协议内容分块保存后统一拼接，可避免每次追加复制整个已收内容。保存所有历史快照的驻留随时间增长，可用增量账与选定检查点，但必须保留重建所需事件和覆盖范围。

六类成本应同时列账：计算包括影子前向、独立整数参考、CDF 和比较；访存包括被比较张量与元数据遍历；通信包括设备到主机快照和跨设备摘要；准备包括模型加载、前处理、独立页表与量化元数据构造；同步包括主机读取设备结果、完成等待和一致性快照；驻留包括影子权重、激活、观测缓冲、票据账及在途采集。一次一个设备标量的读取可能引入很多同步，不能只按几个字节估价。

端到端时间沿依赖关键路径与共享资源计算，不能把可重叠阶段的耗时全部相加，也不能假定完全重叠。诊断同步、复制与影子参考会扰动执行，甚至掩盖竞态；正常性能运行与诊断运行分别计时。逻辑容量算例不构成设备事务量或实测时延。

## 条件变化与区分实验

| 条件变化 | 保留的关系 | 调整或放弃的依据 |
|---|---|---|
| 长度、页长或 chunk 改变 | 输入历史、全局位置和可见集合 | 重算参考与采集成本；不能为容量静默截短任务 |
| dtype、量化格式或尺度改变 | 原模型质量基线与独立代数 | 重建同制品参考及舍入契约；旧码不可任意配新尺度 |
| batch、物理页与完成顺序改变 | 请求归属、对象身份和责任守恒 | 核对逆映射及浮点重排；增加受控时序 |
| 前缀缓存、迁移或驱逐改变 | 内容、模型与表示身份 | 身份不相容则放弃缓存等价，改查重建和质量 |
| 重试或部分输出合同改变 | 逻辑任务身份与提交权限 | 显式展开各尝试、允许内容和终止义务，不按返回结果删样本 |
| RNG、设备或归约树改变 | 数学函数、支持集和任务质量 | 重建随机流与数值路径；放弃无依据的跨平台逐位要求 |
| 资源池或保留策略改变 | 唯一物理容量与责任完整性 | 重定统计域、策略保留根与静止基线，不能沿用旧 RSS 阈值 |
| 协议版本与连接行为改变 | 业务终态和外部提交语义 | 重核发送、断开与借用缓冲边界，不要求固定竞争顺序 |

诊断需要竞争解释与可否定预测。

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 常规采样正常，精确边界错 | 非严格 CDF 比较、零概率处理或 RNG 映射 | 用精确有理数固定 u=累计边界及零概率首项；数值无舍入仍错则修选择规则 |
| 共享页被报重复占用 | 真正重复账或将拥有权与执行责任混作容量类别 | 固定 L={A,B}、U={B-kernel}；应仅计一次 Inflight，仍能列出两个拥有者 |
| 分区互斥却提前回收 | 启动票据遗漏、错误完成结算或快照不一致 | 保持物理集合不变，独立核对启动/完成账；删 U 后不能靠并集通过掩盖缺失 |
| 同值旧结果被接受 | 只比较内容、仅按 rid 去重或终止账未校验代次 | 固定内容，仅分别改变结果与终止的 g、s、e；每个错误字段都应被实际比较器拒绝 |
| 仅跨页或 chunk 失败 | 页映射、位置重置、尾部可见性或尺度 | 保持逻辑输入，分别改页排列与 chunk；随物理页走时查映射，随 chunk 走时查位置推进 |
| token 改变而 logits 接近 | 小 margin、processor 或选择规则变化 | 比较处理前后分布并计算 margin；大于 2ε 仍改变时不能仅归因于该误差界内的舍入 |
| 取消后 RSS 不下降 | 分配器保留、缓存根、未结束访问或真实泄漏 | 核对互斥容量、正交责任和结束证据；无完成证明的页继续隔离 |
| 同 seed 文本不同 | RNG 消费顺序、非确定性归约或身份串用 | 固定逐请求随机数重放同一快照；随机数固定后仍失败则继续检查数值与状态 |
| 局部整数参考一致但质量下降 | 近似损失、校准漂移或跨层组合 | 分别恢复权重、KV 与敏感层精度；只有相应干预有效才收窄归因 |

反证应修改判断。提高参考精度后仍有固定漏项，应转向索引和覆盖；删除诊断同步后竞态重现，不能把有同步的通过当作正常路径安全证明。负对照应尽量只改变所研究维度，防止同时破坏全部格式而无法知道哪个规则生效。

## 会话失败范围与检查器修复

多轮会话的后续输入可能依赖前序有效输出。前一轮失败后的未执行请求属于缺失或被阻断，不能从预先计划的会话集合删除，也不能计为通过。分别报告计划逻辑轮次、实际发起、接纳、拒绝、完成、取消、超时与质量失败。请求级分母由任务预先声明；会话成功需要全部必要依赖完成，请求级条件成功率不能替代会话成功率。

用户要求完整历史、精确内容或完整候选集合时，测试驱动不能为了可运行而截短历史、忽略错误请求或放松质量定义。可以选择小规模独立参考，但应明确它缩小了证据范围，原任务要求并未因此改变。

发现比较器缺陷后，定位受影响规则、检查版本和历史结论。原始输入、输出、身份与事件足够时，可用修订后的检查器重新分析并保留新旧身份；缺少必要字段时，需重跑对应路径。修复身份比较器恢复了拒绝旧结果的能力，不能自动证明过去候选的输出从未串代。也不应把与缺陷无关的全部证据笼统清零。

## 随章检查及未验证范围

随章文件 tools/check_k_tools_006_full.py 是确定性、离线、只读的 Python 标准库检查。它具有独立给定的身份预期、CDF 边界表、全局位置加权参考、协议固定内容与序号规则，以及资源手工期望分区和独立票据账。负对照穿过实际比较器，包括非严格 CDF、同内容旧代次、错误槽、终止身份串代、共享页错误分类、遗漏在途责任和重复物理计数。

身份模型检查 rid、attempt 对应 g、slot 对应 s、epoch 对应 e，以及结果值和终止状态；结果与终止各自对冻结预期核对。模型假定每个请求在该批只有一个授权的成功结果和一个指定结果槽。它没有实现分支 ID、逻辑 token 位置 t、模型/表示版本 v、逐 chunk 请求映射、生产提交权限或任意多槽请求。资源票据额外携带 (r,g,s,e,uid)，但仅验证有限快照中的匹配与完整性，没有实现真实设备完成适配器。

资源检查覆盖共享拥有者与在途访问同时存在、取消后仍在途、访问结束后转 Active、最终释放与策略保留，以及 Quarantined 优先归类；它不证明实际登记链没有漏掉未观测访问。协议检查仅为单条合成流的 start/data/terminal、序号与拼接内容，不覆盖真实背压、usage、stop string、客户端消费或完整 ASGI。位置参考是标量模型，不是完整多层 attention。脚本没有实现 INT8 输出流水、经验频率统计或任务质量评估。

检查脚本、输入绑定与实际执行结果见[检查记录](../../docs/evidence/knowledge-workflow-20261028-batch12/K-TOOLS-006/round-2/check-0.json)。没有执行生产引擎、CPU/GPU kernel、实际取消排空、显存或时延测量，也没有 Agent 使用效果证据。CPU 或主机逻辑模型不能写成 GPU 实测。
