# K-SYS-018：推理存储服务：制品、缓存、索引与提交记录

推理存储既包含权重等稳定制品，也包含可重算 KV、检索索引和不可随意丢弃的提交记录。存储服务必须回答：对象属于哪个版本和表示，由哪些完整字节组成，何时可以读取，何时可以承诺故障后仍能恢复，以及最后一个读者结束前由谁保留它。把所有对象放入同一个高速缓存，或者全部按最强持久化处理，都可能付出不必要的代价。

## 先定义对象契约

对象合同记为 O=(ns,a,q,R,d,c)。ns 是租户或隔离命名空间，a 是不可变内容版本，q 是解释字节所需的表示合同，R 是必需逻辑对象及范围，d 是持久性要求，c 是缓存与保留策略。q 包括适用的 dtype、量化尺度、轴序、tokenizer、编码器或索引参数。相同名称、shape、长度或者物理位置都不足以证明对象可互换。

| 对象 | 主要读取/更新模式 | 丢失后的恢复条件 |
|---|---|---|
| 模型、adapter、tokenizer 与量化制品 | 版本内只读，分片/范围读取，批量分发 | 从可信且完整的相同版本和表示重新取得；缺片不能发布 |
| 可复用 KV 或中间状态 | 按前缀/层/块读取，逐步产生或封闭 | 保留完整计算身份、输入和充分恢复状态；不是所有递归状态都可仅凭文本恢复 |
| embedding 与检索索引 | 查询、批量构建、增量更新或整体替换 | 保留材料版本、编码器、索引参数以及删除/更新依据 |
| 请求提交、计费或必须保留的事件 | 追加和查询，通常小而频繁 | 依据业务协议恢复原决定；模型重算不能恢复已经发生的承诺 |
| 临时 staging、可再生编译缓存 | 短期读写，格式与环境绑定 | 可删除重建，但重建成本、环境资格和峰值必须进入预算 |

可重算只描述恢复路线，不等于恢复免费。缓存丢失后集中重算会争用 CPU/GPU，影响仍正常的请求；索引重建还可能包含长时间的数据扫描。外部工具结果、随机过程和不可重放控制状态需要单独声明保留范围。

持久性 d 必须绑定故障模型。例如“进程退出后本机文件仍可读”“单节点失效后可由其他节点恢复”“整个指定故障域掉电后仍可恢复”是不同合同。副本数不是故障独立性的证明；两份副本共用供电或存储出口时，不能按两份独立保障计算。

## 接口与完成边界

对象接口用键与版本定位整体对象或范围，适合不可变分片和分发，但不能假设跨多个对象的原子发布或目录 rename 语义。文件接口提供路径、偏移与文件系统操作，具体原子性、缓存可见性和持久性仍依赖所选实现。块接口提供地址空间与 I/O，文件布局、版本和发布由上层负责。这些接口没有天然的快慢顺序：大量小元数据请求可能限制启动，大对象顺序读则可能受出口带宽限制。

至少区分以下完成事件：操作被接受、部分字节到达、全部必需字节可读、指定副本接收、达到声明持久性、权威清单发布、最后消费者结束。它们不是一个可以用 running 或 done 概括的状态。

[Ceph 2006](../sources/S-CEPH06.md) §5.3 和 Figure 4 将可见确认与安全落盘分开：更新应用到副本 OSD 的内存缓冲后返回 ack，安全提交到磁盘后才返回 commit。该论文还明确原型 MDS 恢复尚未实现，安全协议等机制仍有未完成范围。因此，它支持区分同步与安全的机制，不能证明当前任意 Ceph 后端或对象存储提供相同接口、恢复能力或性能。

[Linux 6.12 I/O 文档](../sources/S-LINUX-IO.md)明确块层和设备协议不保证请求完成顺序。iomap 的直接 I/O 返回还区分实际传输字节、异步排队、错误和回退到缓冲路径；直接读前刷新相关脏页缓存，直接写前刷新，并在写前后失效相关页缓存。这些是固定内核内部接口的语义，应用适配层仍须核对实际用户态接口。直接 I/O 不自动等于异步，不证明持久化，也不证明 SSD 直接向 GPU DMA。

数据路径应落实到对象：存储读取写入页缓存或用户缓冲；校验读取源字节；转换读取源并写目标表示；H2D 读取主机区并写 HBM；设备消费者取得适用的完成与可见性依赖后才能使用。缓冲的回收还要等待所有实际消费者结束。

## 完整版本如何发布与读取

令制品清单的主体为 M=(ns,a,q,R,{s_i})，清单摘要为 d_M=H(canonical(M))。摘要不包含自身，规范序列化要保留字段类型、长度和边界。每条源段 s_i 至少记录逻辑对象、逻辑覆盖范围、不可变文件或对象身份 f_i、文件内偏移 o_i、真实载荷长度 n_i 和期望摘要 h_i。量化尺度、索引码本等辅助对象也是依赖，不能只检查主载荷。

R 必须来自可信配置或独立的必需对象描述，不能由“实际找到的分片集合”反推。否则删掉一条清单记录后，剩余记录仍可能自称完整。对每个逻辑对象分别检查必需范围被覆盖；对每个物理文件分别检查 0≤o_i≤o_i+n_i≤length(f_i)。两个文件都从 offset=0 开始合法，不能把它们的偏移混入一个全局区间。

本章采用严格的清单合同：目标逻辑范围完整且唯一覆盖，未声明的共享源范围或交叠拒绝；合法共享通过一个不可变源根及明确的多个消费者表达。物理载荷长度按实际打包、分组填充、尺度和对齐计算，不能只比较元素数。摘要证明字节匹配，表示与坐标检查证明这些字节实现指定对象，两者不能互相替代。摘要的可信身份来自权威清单；自行计算一份摘要不构成来源认证。

```pseudocode
算法 PublishArtifact(op, expected_epoch, ns, a, q, required_schema, shards, d)
输入：唯一发布操作及不可变参数；预期路由代次；制品身份、必需对象和持久性
输出：原决定、新 PUBLISHED 决定、明确拒绝，或结果未知

1 从 required_schema 建立必需逻辑对象与范围 R；校验 q 和全部依赖
2 检查分片身份、物理边界、真实长度、逐对象逻辑覆盖与显式共享关系
  空载荷仅在 schema 明确允许时合法；缺失非空对象不能被空集合掩盖
3 以不可变键写入未发布对象；同键已有内容必须完全一致，否则冲突
4 等待写入终结；重新核对长度与摘要，任一失败则停止发布
5 等待全部依赖达到 d；读取正确不能替代持久性完成证据
6 构造 M 和 d_M，写入不可变清单；核对清单并等待其达到 d
7 在权威发布域中：
  若 op 已有决定：参数一致则返回原决定；参数不同则冲突
  重新核对依赖仍受保留保护，当前 epoch 等于 expected_epoch
  原子安装 root=(epoch+1,ns,a,d_M)，登记已发布版本与 op 决定
  若合同要求发布决定可恢复，等待该决定达到相应持久性
8 确认成功后返回 PUBLISHED；旧版本仍受读者和恢复引用保护
9 答复丢失则查询同一 op；未知时保留可能已发布对象，不猜测回滚
```

合法性要求是不可变内容、完整依赖、统一发布点及清晰完成边界。CAS、外部事务记录或等价排序机制是实现选择。仅对 latest 原地覆盖一个字符串，没有代次与条件更新，不能解决并发发布和回退后的 ABA。没有跨对象事务时，上述步骤用“先完成并保留依赖，再发布一个权威引用”组织原子可见性；它不把多次上传变成天然事务。

读取要同时解决版本固定和旧对象保护。先读 latest，过一会儿才登记读者，会留下 GC 已删除旧版本的窗口。下面选择共同排序的引用登记；分布式租约替代它时，还需证明撤销和读者停止的关系，不能仅凭时钟超时删掉仍可能访问的对象。

```pseudocode
算法 OpenSnapshot(requested_version, ns, expected_q, required_ranges)
输入：明确版本或 latest；读取身份、表示和范围
输出：绑定单一清单的 Snapshot，或具体失败

1 在与回收共同排序的状态域内：
  只解析一次 latest，或定位明确 requested_version
  要求版本已经发布且未封闭新读者入口
  固定 (ns,a,d_M)，登记唯一读保护票据，再离开状态域
2 获取该清单，验证权威 d_M、ns、a、q 和必需范围
3 只按该清单定位 (f_i,o_i,n_i) 并读取；保留每段的短读和错误
4 聚合完整成功范围；不能按完成通知数量推断覆盖
5 核对长度、摘要、表示和全部必需覆盖
6 全部通过则返回 Snapshot(a,d_M,范围,读保护票据)
7 任一步失败则不交付部分对象；结束已接受访问后结算票据
8 使用者及其借用消费者全部结束后，幂等释放读保护
```

读取失败时，可重建缓存可以退化为 miss 或重算；制品必须报告缺失或损坏，不能用其他版本补齐；提交记录不能用模型输出猜测。旧版本 GC 需在共同状态域中关闭新读者入口，并确认它不再被 root、在途 Snapshot、回退策略或恢复记录引用，实际访问也已结束。若不同版本共享内容寻址对象，应对共享依赖求引用并集，不能删除一个版本时直接删除共有分片。

## 共享缓存的填充与回收

缓存键至少为 K=(ns,a,q,t,s)，其中 t 是加载或转换实现身份，s 是分片或范围。它区分同名模型的不同版本、表示和租户。命中证明该键下存在相容内容，不证明它就是当前 latest，也不证明设备消费者已经可读。

| 状态 | 已经成立 | 后继与限制 |
|---|---|---|
| ABSENT | 无可读项 | 可建立新填充尝试 |
| LOADING | 唯一逻辑 loader 与等待者已登记 | 部分数据不可交付；取消等待不结束物理写入 |
| READY | 必需字节完整且合同校验通过 | 取得读保护后交付；设备可见性另行建立 |
| FAILED | 本次结果失败 | 传播本代错误；物理访问结束后才可安全复用范围 |
| EVICTING | 已封闭新取得入口 | 等待读者、绑定和实际访问结束后删除 |

```pseudocode
算法 CacheEvent(K, event)
状态：entry 含 attempt、state、waiters、readers、实际访问责任

GET(owner)：在同一状态域内
  READY：登记 owner 的读保护后返回
  LOADING：加入本 attempt 的 waiters，等待同一填充
  ABSENT 或可重试 FAILED：创建不复用 attempt，置 LOADING
    登记唯一 loader、owner 等待及目的缓冲责任
  离开状态域后启动 loader；不得占着状态锁等待 I/O

CANCEL_WAIT(owner)：
  仅删除该 owner 的等待资格；其他 waiters 和 loader 责任不变
  若内容已交付，取消等待不代替读者或设备访问结束

LOADER_TERMINAL(attempt, result)：
  先匹配 K、attempt 和实际操作身份，幂等结算本操作责任
  旧尝试结果不得修改当前 entry，也不得释放新代缓冲
  本代失败或校验不符：置 FAILED，向本代等待者返回失败
  本代完整且校验通过：在同一状态变更中
    将仍有效 waiters 转成 readers，置 READY，再发送完成通知
  清空本代 waiters；无人等待也不能提前回收仍在写的缓冲

RELEASE_READER(ticket)：只结算该读者；重复通知不清除其他读者
EVICT：封闭新 GET，重新核对全部保留与实际访问责任
  责任为空才删除并归还物理容量；否则等待明确后继
```

等待者转成读者必须和 READY 发布共同排序。若先清空 waiters、再异步通知读者登记，淘汰器可能在中间把刚加载的内容删除。失败重试也不能只改 attempt 后在同一地址继续写：代次能拒绝旧结果，不能阻止旧 DMA 或 I/O 改写地址。应等旧访问结束，或为新尝试使用独立且有预算的范围。

并发合并只适用于相同 K。一个等待者取消不应取消其他人的共享填充；全部等待者取消后，可以让本次读取完成并缓存，也可以尝试中止，但回收必须依据真实终结证据。这是缓存策略选择与最后使用条件的区别。

## 索引与提交记录的恢复依赖

检索索引版本应绑定材料集合、切分与编码器、距离与变换、训练参数或码本、索引分片、ID 到材料版本的映射以及删除记录。查询固定一个完整索引清单，材料缓存也按材料版本解释；不能拿旧向量对应的 ID 悄悄换成新材料。

删除语义需要明确选择。历史快照查询可以按绑定代次解释普通内容更新；权限撤销或必须立即生效的删除，则可能要求在返回材料前核对当前权威过滤状态。此时固定旧索引仍不足以授权返回旧材料。删除传播、索引快照与权限检查不能压成一个 latest 标签。

增量添加、删除和修改是否支持，取决于具体索引实现；不支持时可以构造新分片并重新发布。重建需要材料、编码器和构建依据，但不必保证重新生成逐字节相同的索引；应重新校验声明的查询语义与质量。索引算法、过滤和质量参考见[向量检索与 RAG](retrieval-pipeline.md)，本章承担其依赖发布与保留责任。

提交记录至少含租户、cid、不可变参数摘要、连续日志位置、输出摘要或载荷，以及所引用制品和结果的身份。相同 cid 且参数完全一致时返回原状态；参数不同则冲突。参数摘要必须覆盖影响决定的载荷与引用，不能只覆盖一个请求名。

重复查询要区分 PENDING 与 DURABLE。已经创建可见记录、尚未达到持久性时，重试只能得到待定状态或继续等待，不能因为“cid 已存在”便返回 durable ack。确认丢失时查询原决定；未知不能当作从未提交。

```pseudocode
算法 AppendCommit(cid, immutable_params, payload, references, d)
输入：提交身份、全部不可变参数、载荷、恢复依赖和持久性
输出：CONFLICT、PENDING、原 DURABLE 决定或新 DURABLE 决定

1 在权威排序域查询 cid：
  已有且参数冲突：返回 CONFLICT，不覆盖旧记录
  已有且相同：返回原 PENDING 或 DURABLE 状态，不推进序号
2 核对当前写授权、连续位置及引用对象完整、相容且满足 d
  为这些引用取得持久恢复保留；latest 后续切换不撤销该保留
3 分配唯一日志位置，形成含长度、身份与校验信息的完整记录
  原子登记 cid→PENDING 与追加意图；相同 cid 不再创建第二条记录
4 发起所需写入、复制和同步，保留部分完成与错误
5 完成时只接受匹配操作和记录身份的证据
  对本章前缀日志，持久提交前沿只能越过连续、完整且校验通过的记录
  后一条先落盘不允许跨过前一条缺口
6 将已经满足提交前沿及依赖条件的记录标为 DURABLE
  只有此后才能发送 durable ack；重复通知不重复执行业务动作
7 恢复校验日志身份、长度、序号和摘要，从检查点后的完整已提交前缀重建
  首个缺失、破损或未提交位置结束该前缀；未知决定保留待查
8 日志与去重记录保留覆盖允许重试窗口；回收引用还须满足恢复保留策略
```

这是保守的前缀日志方案。独立分片日志可以有各自的前沿；不能把一个分片的连续性外推为跨分片事务。检查点或压缩若删除旧日志，需先持久化等价的决定、去重和依赖保留信息，不能只留下一个最大序号。

提交记录保存的是既有业务决定。模型重算得到相同文本，也不证明计费、工具动作、输出序号或客户端确认没有发生。存储内部 cid 去重不自动提供外部副作用或网络交付恰好一次；接收方仍需协议身份与相应去重。请求恢复与输出承诺的完整关系见[推理服务恢复](serving-recovery.md)。

## 版本切换的组合轨迹

以下为设定轨迹，展示发布、缓存、提交与 GC 的交界。v1、v2 各有 32 GiB 唯一制品，单副本存储预算为 100 GiB，另有 4 GiB 独立 staging 预算占用；不考虑共享内容和其他元数据。

| 事件 | 身份与保留责任 | 合法后继 |
|---|---|---|
| root 指向 v1，读者 A 打开 Snapshot | A 在共同状态域固定 v1 并取得票据 | v1 可继续被读；不能只凭 root 将变化便回收 |
| B、C 同时请求 v2 的同一缓存分片 | 相同完整 K 合并为 attempt g，waiters={B,C} | 只有一次填充；v2 整体尚未发布 |
| B 取消，loader 仍在写 | waiters={C}，g 的物理责任仍在 | 不删除 C 的下载，不复用 loader 缓冲 |
| v2 全部分片和清单完成且达到要求持久性 | v1、v2 与 staging 同时存活，主项为 32+32+4=68 GiB | 校验成功后可以尝试 CAS；若预算仅 60 GiB，应换路线，不能先删 A 的 v1 |
| CAS 成功，但发布答复丢失 | root 已是 v2；原 op 的决定可查询 | 查询原 op，不能按超时重写或清理 v2 |
| C 取得内容，请求产生 cid=j 的结果 | j 的恢复引用包含 v2；记录先 PENDING | 依赖及日志达到要求后才返回 durable ack |
| root 回退到 v1，C 已结束读取 | v2 已无普通读者，但 j 仍引用 v2 | 若恢复合同需要 v2，GC 仍不得删除它 |
| j 的保留责任按协议结束，实际访问均排空 | v2 不再被 root、读者或恢复记录引用 | 关闭新取得入口后回收 v2；staging 按自身最后访问释放 |

如果 v2 校验失败，root 仍为 v1，不能用 v1 的一个分片替代坏片后继续声称 v2 完整。如果在日志持久前崩溃，结果是否已提交须查询权威恢复依据；不能因为 C 曾经读到 v2 就推断 j 已持久。这个轨迹中的容量是同一时刻的唯一对象和独立 staging 之和；池已包含 staging 时不能再加一次。

## 成本与共享资源

设一个当前版本的唯一载荷为 B 字节，实际副本因子为 r。在当前版本、旧版本、未发布 staging、恢复中新副本和元数据互不重叠的记账条件下，存储量可写为

B_store(t)=rB+B_old(t)+B_staging(t)+B_recovery(t)+B_meta(t)。

若它们共享不可变 backing，应改为同一时刻物理集合的并集求大小；上述分类不能重复包含同一对象。100 GiB 逻辑制品、三副本时数据主项已为 300 GiB，旧版本和恢复副本另计。主机、设备和存储分别取时间峰值，不能用跨域总空闲量替代逐域预算。

| 成本 | 本章机制实际产生的工作 |
|---|---|
| 计算 | 清单解析、范围排序与覆盖检查、内容摘要、解包/转换、索引重建、日志校验与恢复 |
| 访存 | 存储读入、页缓存或用户缓冲写入、校验再次读取、转换读写、设备复制及恢复扫描 |
| 通信 | 制品分发、后台复制、控制查询、重试、重平衡和恢复；按真实链路与方向计量 |
| 准备 | 必需 schema、索引与清单构造、离线预打包、池分配/锁页、权限与租约准备 |
| 同步 | 并发填充等待、CAS 排序、数据到消费者的依赖、持久同步、确认查询和取消排空 |
| 驻留 | READY 缓存、LOADING 目的区、旧读者、持久恢复引用、双缓冲、旧版本与未完成尝试 |

S 个源段按文件和逻辑对象排序通常需要 O(S log S) 比较，摘要随实际校验字节增长。摘要校验额外读源字节，转换至少包含源读取和目标写入；低位展开、对齐过读与额外 staging 会使主存、存储、网络和 H2D 流量不同。只用逻辑模型大小不能描述全部事务量。

没有本地命中、没有对等分发且每个节点都需一整份时，N 个节点需要共享出口交付 NB 字节。出口有效能力为 B_s 字节/s 时，纯传输主项为 NB/B_s；若 B_s 是已知容量上界，它给出时间下界；若 B_s 是特定负载下的观测速率，它只是条件估计。各节点按字节命中比例 h_i 不同时，出口需求为 Σ_i(1−h_i)B_i，而不是未区分版本和大小的请求命中率。

设定 B=32 GiB、N=16、共享出口为 8 GiB/s，出口需交付 512 GiB，纯传输主项为 64 s。每节点一半字节已在本机时，该主项变为 32 s；本地读、校验、转换和 H2D 仍需计算。不能为 16 个节点同时各用独占出口估成 4 s。

树形或对等分发减少中心出口压力，却增加节点间字节、临时驻留和失败路径。[Borg](../sources/S-BORG.md)利用已有不可变包的局部性，并用树形、类 torrent 协议并行分发包，这是固定论文的集群机制，不是当前推理集群的最优拓扑或块大小证明。恢复与重平衡还会消费在线读取所需的磁盘和网络；可恢复不等于恢复期间维持原 SLO。

[ServerlessLLM](../sources/S-SERVERLESSLLM.md) §4 将每 GPU 参数组成二进制数据文件，索引记录 tensor.name、GPU id、offset、size，利用对齐和 base+offset 恢复地址；固定块池、锁页内存和阶段队列组织存储到设备的流水。该方案已包含目标放置选择，准备和格式失效成本应纳入比较。其 §6.2 的 q+n/b 估计依赖每服务器顺序加载、慢层带宽及反馈校准，不覆盖任意并发、转换、编译与预热。

对 N_c 个等大块、三个独立单服务阶段，时长分别为 t_r、t_c、t_d，缓冲充足且无其他依赖时：

T_0=0；N_c≥1 时，T_Nc=t_r+t_c+t_d+(N_c−1)max(t_r,t_c,t_d)。

不等长块可递推 F_i,k=max(F_i−1,k,F_i,k−1)+t_i,k，边界为零。两块、各阶段时长 1 时，读第一块在 [0,1)，下一块读取与第一块转换在 [1,2)，随后复制与转换在 [2,3)，最后复制在 [3,4)，完成时间为 4，六份阶段工作的总量为 6。共享 CPU、DRAM 或 PCIe 时须加入共同资源边，不能继续假设独占速率。p 个 b 字节缓冲槽占 pb 字节，增加槽数只有解除真实等待且预算允许时才有收益。

同一缓存键的 c 个并发 miss 合并后，理想情况下源填充从 cB 降为 B，节省 (c−1)B；如果每个消费者还需自己的设备副本，后续复制并未消失。合并也让等待者共享一个 loader 的延迟与失败。命中概率 h 下，hC_hit+(1−h)C_fill 是相同请求分布上的期望费用，不能直接拿它当 p99 或把字节命中率代入请求概率。

提交批处理设每条载荷 b 字节、固定同步成本 F 秒、持久带宽 B_d 字节/s，一批 n 条的串行服务模型为 S(n)=F+nb/B_d，理想饱和率为 n/S(n)。F=2 ms、b=1 KiB、B_d=1 GiB/s、n=64 时，载荷项约 0.061 ms，服务约 2.061 ms，理想记录率约 3.1 万条/s。它未包含复制、排队和失败重试，也不是设备实测。只等满批会在低到达率下无限延迟，需声明超时或其他推进条件；批窗口只限制主动凑批等待，不自动约束服务队列。更长的持久等待还会延长 PENDING 记录及其依赖对象的驻留。

## 条件变化后的选择

| 条件变化 | 应保留的机制 | 调整与放弃的依据 |
|---|---|---|
| 权重长期稳定、节点反复启动 | 不可变身份、清单与校验 | 本地缓存、预打包和分发准备更易摊销；挤占 KV 或源已足够快时收益下降 |
| 版本频繁变化或回退频繁 | Snapshot 固定版本、代次与保留引用 | 重算旧版本并存峰值；容量不足时采用其他节点、分批更新或允许空窗的替换 |
| 存储源变快 | 完整性、表示与完成边界 | 瓶颈可能转到摘要、解包、转置或 H2D；增加读线程可能只增加队列与驻留 |
| 小对象和元数据请求增多 | 必需对象检查与权限 | 比较清单批量解析、范围合并和并发填充；大块造成过读和首块等待时缩小粒度 |
| 索引材料频繁更新 | 版本、材料映射与删除语义 | 只有实现支持时采用增量更新；否则重建并发布，不能只替换一个向量文件 |
| 提交记录不可丢 | 原决定去重、持久前沿与恢复依赖 | 可以批量同步或分片；不能把 visible ack 改称 durable ack |
| 故障域相关或节点短命 | 声明的恢复合同 | 增加同域缓存不替代独立副本；重新预算恢复流量与在线争用 |
| 缓存接近容量上限 | 最后访问责任与唯一 backing 记账 | 调整保留排序、预取和准入；仍在访问的冷对象不能立即变成空闲容量 |

策略没有脱离负载的统一最优参数。块大小、批窗口、副本数和保留时间改变成本；对象身份、完整覆盖、合法授权与最后使用边界仍需成立。表示、恢复语义或故障模型改变时，原方案可能不再合法，不能只调整一个性能参数继续使用原结论。

## 竞争解释与区分实验

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 版本切换后得到混合对象 | 逐片解析 latest；缓存键漏身份；清单覆盖错 | 用可区分的 v1/v2，在两片读取之间切 root；另固定清单但只改变 q。固定版本后仍错则查键和布局，不能归因正常数值差异 |
| 分片数正确却缺字节 | 范围有洞；重复范围抵消缺口；短读被当完整 | 构造两个重复前半区与缺失后半区，再注入短读；总字节数相同仍应拒绝。若覆盖正确仍失败，查摘要和文件身份 |
| 读 latest 后偶发找不到旧片 | 解析与 pin 不共同排序；GC 不看在途读者；真实源失效 | 暂停在解析与保护之间并尝试 GC，再用原子保护入口对照。只有原子入口消错才支持取得/回收窗口解释 |
| 一个等待者取消使其他人失败 | 删除共享下载；误停 loader；通知交接有空窗 | 同一 K 的 B、C 等待，取消 B 后完成 loader；再在 READY 交接间尝试淘汰。分别检查存活等待者和读保护，不能用全局禁淘汰掩盖交接错误 |
| 重试后旧完成让新项就绪 | attempt 复用；按地址匹配；旧写尚未结束 | 失败 g1 后创建 g2，延迟 g1 通知；另真实延迟旧物理写。通知拒绝但仍损坏时，修隔离与排空，不只加代次 |
| durable ack 后恢复缺记录 | 可见误作持久；落盘有洞；破损记录；依赖已 GC | 分别在 visible 后崩溃、让后一记录先落盘、破坏前一校验、回收被引用制品。各干预应留下不同失败证据 |
| 索引命中但材料过期或无权读取 | 索引代次错；材料缓存漏版本；删除/权限传播滞后 | 固定索引与查询，只推进删除或权限，再只切材料版本。根据快照与强制撤销合同分别判断，不能只调 top-k |
| 冷启动慢或恢复时尾延迟高 | 元数据、出口、校验转换、设备复制或恢复争用 | 固定版本与有效字节，分别改变冷热状态和后台恢复速率，记录阶段与链路流量。转换主导时撤回纯存储带宽归因 |

实验应固定版本、有效字节、并发、缓存状态和完成边界，再改变能让竞争解释产生不同预测的中介量。命中率上升不保证端到端延迟下降；全局同步消错也不能唯一确定缺失哪条依赖边。性能验证保留拒绝、失败、取消和未完成请求，不能只报告成功者。

## 检查覆盖与证据边界

配套 `tools/check_k_sys_018_full.py` 是确定、只读、离线的 Python 标准库 CPU 模型。区间覆盖与逐字节集合参考比较；流水递推与独立闭式公式比较。制品模型使用单命名空间、恒等字节表示和连续逻辑地址，检查完整准备、摘要、条件发布、明确空 schema、未发布拒读、版本固定、读保护与 GC，并拒绝缺片、截断、损坏和错误表示。

缓存模型将同键填充、取消等待、等待者转读者、读者释放、失败重试和旧 attempt 通知连成一条轨迹。完成事件在模型中表示该 loader 的实际访问已经终结；它不模拟设备物理排空。日志模型检查同 cid 的 PENDING/DURABLE 区别、参数和载荷冲突、乱序落盘、破损记录以及连续恢复前沿；有限落盘次序与独立磁盘子集参考比较。

故障变体实际采用总长度替代覆盖、逐片跟随 latest、取消时删除共享填充、跳过日志缺口、visible 即 durable ack，以及把串行工作量当流水完成时间。它们必须触发同一参考或不变量的失败，不能只打印成功标签。正文不预写脚本执行通过结论，实际执行结果应绑定脚本与确定输入。

检查不证明真实文件系统或对象后端的事务、fsync、复制故障域、并发线性化、跨文件偏移映射、量化转换、索引删除实现、网络排空、GPU H2D 可见性、吞吐或 p99。模型把共同排序与持久存储作为显式假设；这些假设在实际平台上需要独立证据。也不能由 CPU 模型推断知识改善了 Agent 的系统构建效果。
