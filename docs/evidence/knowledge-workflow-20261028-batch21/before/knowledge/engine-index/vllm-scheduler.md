# K-ENGINE-001：调度决策：进度、就绪与资源承诺

动态服务中，请求长度、输入就绪、缓存可用、设备完成与输出交付不在同一时刻变化。调度器需要确定本轮允许推进的逻辑范围、输入依赖、资源承诺及结果的提交资格。排序只能在合法候选中选择，不能创造尚未生成的输入或尚未取得的容量。

## 问题、状态与不变量

以下基线限定固定模型的普通 causal decoder、非空规范化输入、无投机，每请求至多一个未解析模型视图。空输入先按模型合同补入 BOS 或拒绝。树验证、同请求多视图流水和递归状态需要扩展状态集合，不能直接套用两个前沿。

请求身份为 (r,g)，g 是不复用的授权代次；η 记录模型、adapter、规范化输入来源、位置规则和数值表示。当前已确认输入为 x[0:n)，包含 prompt 与已接受生成 token；输入追加通过状态版本区分。

| 状态 | 含义与边界 |
|---|---|
| c | 全部必要层完整、可恢复的连续 KV 终点；有效前缀为 [0,c) |
| s | 已承诺给模型执行的逻辑终点；安排不代表完成 |
| a | 当前已取得逻辑写入资格的容量，包含可写页尾与预留位置；不等于本轮最多可以扩展到的终点 |
| v | 请求状态版本；输入追加、结果安装、取消或失败解析均改变它 |
| active | 当前未解析条目的完整身份；恢复也占用此字段，即使 s=c |
| ℓ | 绑定 (r,g,η,v,n−1,ticket_id) 的未消费 logits 票据，或空 |
| draining | 已失去逻辑推进资格但仍未结束的实际访问责任 |

稳定边界保持 0≤c≤s≤n≤L_model、s≤a。无 active 时 s=c；反过来 s=c 不证明无在途工作，因为 RECOVER_LAST 不增加前沿。n 可以大于 a：刚接受的 token 已是合法输入，其 KV 容量可以在下一轮取得。a 可以因页取整超过模型长度，执行终点仍不能超过 L_model。

c=s=n 且 ℓ 有效表示可以采样；c=s=n 且无 ℓ 表示需要恢复末行输出；c=s<n 表示存在已知但未计算输入。普通生成中，prefill 完成后的 n−c 通常为 0 或 1。刚交付的 token 可以尚无自身 KV，不能把新的 n 同步赋给 c。

所供 vLLM 机制说明指出内部进度可在调度后提前增加、返回后再校正。本章分别用 s 和 c 表示安排与确认，是独立的语义组织，不声称这些就是上游字段。

## 合法候选与预算口径

硬条件包括：请求仍有授权；冻结输入与模型身份相容；选中 token 已知；历史状态完整可读；必要外部输入已到达；写区、输出目标和工作区能取得承诺；结果可以沿不可变映射回到原请求。高优先级不能越过这些条件。

π 决定候选顺序及每请求允许的有限正整数 q 集合，例如 running-first、FCFS、轮转或 deadline。本章参考策略按候选顺序扫描，在每请求允许集合中按 q 递减尝试。running-first 可保护 decode 间隔，但可能使新请求长期没有首 token；公平性需要持久等待或服务账，不能由固定扫描顺序推出。

一轮预算为非负整数向量 (B_tok,B_seq,B_enc)：

- token 预算按真实模型 query 行计数，COMPUTE 消耗 q，RECOVER_LAST 消耗 1。
- sequence 预算按本轮选中的模型请求段计数，两种模型工作都消耗 1；基线每请求至多一段。
- encoder 预算按本轮新增 encoder token 工作计数。展开候选所需 encoder 块集合，扣除已有可用特征及本轮已安排的同身份块，得到增量 e。共享工作只扣一次，引用和驻留分别保留。

encoder 特征已经可用时 e=0。外部媒体尚未到达则 not_ready；媒体已到达但特征待算时，计划必须包含 encoder 计算及其完成到 decoder 消费的依赖。已安排 encoder 不能当作已完成特征。恢复也要核对真实 encoder 需求。

B_tok=0 或 B_seq=0 禁止任何模型条目，仍可返回现存采样票据。B_enc=0 只禁止 e>0 的计划，不能终止 e=0 请求的扫描。全部累计预算在预留和状态修改之前检查；一个候选失败后继续扫描其他候选。预算只限制声明的工作量，相同 q 在不同历史下可能有不同服务时间。

## 从候选到冻结执行视图

输入包括请求、就绪信号、页池与其他资源池、预算和 π；输出为 (V,S,reasons)。V 是模型执行条目，S 是采样就绪通知，reasons 保存阻塞原因及对应唤醒条件。空 V 不提交空模型调用；有 S 时仍存在合法后继。

```pseudocode
算法 1：SCHEDULE_ROUND
初始化 V←空，S←空，reasons←空
初始化 used_tok←0，used_seq←0，used_enc←0，selected_encoder_blocks←空
分配不复用的视图号 t

for r in π 给出的候选顺序，每个请求只出现一次：
    在状态拥有者内读取当前 (r,g,η,v,x,n,c,s,a,active,ℓ)
    若状态不变量不成立：记录 invalid_state；continue
    若已结束、已取消或授权失效：记录 terminal/stale；continue
    若生成配额为零、配额已满或 n=L_model：结束请求；continue
    若 active 非空或存在冲突 draining 责任：记录 wait_completion；continue
    若必要外部输入未到达或历史不具备读取资格：记录 not_ready；continue

    若 c=s=n 且 ℓ 是有效未消费票据：
        S.add(r,g,ticket_id)；continue
    若存在不相容票据：记录 invalid_ticket；continue
    若 c=s=n：
        若 n<1 或恢复合同不成立：记录 recovery_unsupported；continue
        kind←RECOVER_LAST；start←n−1；候选数量集合←{1}
    否则：
        kind←COMPUTE；start←s
        候选数量集合←π 允许集合中满足 1≤q≤n−s 的数量，按递减顺序排列

    accepted←false
    for q in 候选数量集合：
        展开本候选新增 encoder 块、依赖与增量工作 e
        若 used_tok+q>B_tok 或 used_seq+1>B_seq 或 used_enc+e>B_enc：
            记录相应预算限制；continue
        若 start+q>L_model：记录 model_limit；continue

        若 kind=COMPUTE：
            从实际已持有可写页、共享尾页与目标终点 start+q
            推导新增页、必要 COW 与复制依赖
        否则：
            保持原长期 KV；要求历史 [0,n−1) 可读
            推导一行全层私有 K/V 暂存与末行输出所需资源
        同时推导历史读取保护、encoder、metadata、工作区和输出容量
        到达已知末端的条目必须包含下一 token logits 输出目标

        事务式尝试全部增量预留：
            逐项核对当前资源池并取得临时承诺
            任一失败：撤销本次尚未启动访问的全部局部承诺
        若预留失败：记录 capacity 及资源变化唤醒；continue

        在请求状态拥有者内重验授权、版本、边界、取消、active 和输入身份
        重验失败：撤销本次承诺；记录 changed；结束此请求的数量尝试
        冻结 A=(r,g,η,v,t,start,q,kind,原 n/c/s/a,页承诺,依赖,输出目标)
        原子登记 A 为 active，并将其加入 V
        COMPUTE：a←已取得写入资格的新容量；s←start+q
        RECOVER_LAST：c、s、n、a 均不变
        used_tok←used_tok+q；used_seq←used_seq+1；used_enc←used_enc+e
        合入 selected_encoder_blocks；accepted←true；结束本请求数量尝试
    若未 accepted：保留具体阻塞原因，不把零长度条目当作推进

冻结 V、S 和原始身份映射；返回 (V,S,reasons)
此时 c 尚未因安排而推进
```

扩容提案由已知输入 n−s、策略与计算预算产生，不能先被 a−s 截成零。例如 n=5、c=s=a=4，即使现有容量用完，也应尝试为位置 4 取得新页。预留失败不修改前沿；较小 q 可行时，本算法继续尝试。共享尾页需要 COW 时，复制目标和依赖也属于承诺，不能只比较 token 终点。

预留阶段不启动异步复制或计算，因此可以撤销尚无访问的局部承诺。真正准备与提交时，再次验证请求资格，并在外部系统可能接受操作之前登记访问责任。确定未接受的提交可以撤销未启动责任；接受状态未知必须保留地址并进入排空。准备或提交失败经结果失败入口解析，不能留下永久 active。

执行器按冻结条目构造 query、绝对位置、历史页表、私有写区和输出描述。每层从当前 hidden 产生 Q/K/V，新写入按依赖供本层 attention 消费，再产生下一层 hidden；只有到达当前已知末端的末行才提供普通下一 token logits。中间 prefill 只推进 KV。具体行展开见 [ModelRunner](vllm-model-runner.md)，本章的提交依据仍须覆盖所有必要层与输出目标。

RECOVER_LAST 从 token[n−1] 的输入表示开始逐层重算。每层读取原历史 [0,n−1)，把本行 K/V 写入私有暂存，让 attention 恰好包含一次本行 key。不能同时读取旧位置 n−1 又追加一份自身 key。恢复成功只安装 logits，既不追加 token，也不推进 c；它确实执行了一行模型计算，不能称为零工作。窗口历史丢失、递归状态缺检查点或数值合同不支持时，应拒绝单行恢复，采用受支持的检查点重放。

## 结果授权、失败与采样后继

事件与旧冻结条目互相匹配，只证明它们属于同一次旧尝试，不证明当前请求仍授权该尝试提交。物理完成账和请求逻辑账分开：旧事件可以结束旧访问，不能修改当前同号请求。

```pseudocode
算法 2：RESOLVE_RESULT(A,e)
先按完整物理使用身份处理可证明的最后访问证据；重复结算幂等
若 e 的身份、范围或角色与 A 不一致：返回 REJECT，不改请求逻辑状态

在请求状态拥有者的同一原子域内：
    若 A 已有唯一逻辑解析记录：返回原解析收据
    读取当前请求，而不是只读取旧 A
    核对当前授权 g、身份 η、状态版本 v、取消与结束状态
    核对 active 恰为 A，当前 n=A.原n、c=A.原c
    COMPUTE 还要求 start=A.原c、s=start+q
    RECOVER_LAST 还要求 c=s=n、start=n−1、q=1
    任一不成立：记录旧尝试无提交权；返回 STALE

    若 e.status=FAIL：
        COMPUTE：c、n 保持原值；s←A.原s；a←A.原a
                 撤销本次新增逻辑容量资格，失败写区不发布为有效 KV
        RECOVER_LAST：原 c、s、n、a 均保持；不安装恢复票据
        清除 active；v←v+1；记录唯一失败解析
        临时页、工作区与读取保护进入排空；最后访问结束前不得复用
        返回 FAILED 或 DRAINING

    若 e.status 未终结，或必要全层 KV、输出及可见性证据不完整：
        保留 active 与必要责任；返回 WAIT，不进入成功安装

    COMPUTE：c←start+q；s←c；安装有效全层 KV 的长期持有
    RECOVER_LAST：保持 c、s、n、a；暂存 KV 不替换长期 KV
    清除 active；v←v+1；记录唯一成功解析
    若 c=n 且有生成资格：安装绑定新 v、位置 n−1 的唯一 logits 票据
    移交长期引用后，临时对象按最后使用条件排空
    返回成功及可重复投递的采样就绪通知
```

取消也在同一拥有者内发生：撤销未来提交资格、增加 v、解析或退休 active；COMPUTE 的未确认 s 回到原 c，RECOVER_LAST 保留原边界。已启动访问仍留在旧责任账。失败后可以恢复逻辑就绪，但冲突写区尚在排空时不能再次提交；需要等待完成或另取经证明不冲突的私有版本。

采样通知不是 token 输入。通知可以重发，唯一消费发生在请求拥有者内。采样器可在事务外计算候选，但必须绑定票据、采样参数、grammar 与 RNG 快照；接受失败不提交 RNG 或 grammar 的推进。

```pseudocode
算法 3：ACCEPT_SAMPLE(r,ticket,candidate,next_rng,next_grammar)
在请求状态拥有者内：
    若此请求生命期内 ticket_id 已有接受记录：
        返回原 token/停止收据，不再次追加、推进随机状态或新建交付事件
    核对当前授权、η、v、未取消、未结束、无冲突在途工作
    要求 c=s=n，当前 ℓ 恰为 ticket，来源位置为 n−1
    不满足：返回 REJECT，输入、票据、RNG 与 grammar 均不变
    若生成配额已满或 n=L_model：结束请求，不采样后继

    原子消费票据，保存接受结果及随机/grammar 后继
    若 candidate=EOS：
        记录停止事件；结束请求；不追加 EOS，也不计算其 KV
    否则：
        将 candidate 追加为 x[n]；n←n+1；生成内容计数←计数+1
        c、s 不变；保存按请求生命期和生成序号去重的输出事件
        若生成配额已满或 n=L_model：结束请求
        否则通知调度器：位置 c 的已知输入可执行
    ℓ←空；v←v+1；返回原子接受结果

输出发送重试读取接受账，不重新消费 logits 或重新采样
交付入口仍核对当前业务资格；旧收据不恢复已取消请求的交付权
```

这是本章选择的 EOS 合同；其他展示方式可以另行定义。停止时可以 n=c+1，因为最后一个已接受 token 不一定需要再计算 KV。decode 失败重试同一个已接受 token，不能回到旧 logits 再抽一次。

## 恢复、失败、扩容与 decode 的连通轨迹

设页长 B=2，长期页独占，n=c=s=a=4，无 logits，模型仍允许生成，池中有一页空闲。预算为 (1,1,0)，encoder 增量为零。

| 事件 | 前沿与身份 | 资源及后继 |
|---|---|---|
| 完整 KV 命中 | c=s=n=4，active 为空 | 两页长期 KV，缺位置 3 的 logits |
| 安排恢复 | start=3、q=1，登记恢复 active；c=s=n=4 | 一页私有暂存；消耗一个 token 和一个 sequence |
| 恢复失败 | c=s=n=4，清除逻辑 active，无票据 | 暂存及读取责任排空；不能把 s 回滚为 3 |
| 排空后重试并成功 | c=s=n=4，安装位置 3 的新票据 | 暂存最后使用结束后归还空闲页；通知采样器 |
| 唯一接受普通 token z | x[4]=z，n=5，c=s=4，a=4 | 旧票据已消费；重复通知读取同一接受收据 |
| 安排 decode | start=4、q=1；取得新页后 a=6、s=5、c=4 | 原历史两页加一页新增容量；预留成功前不推进 s |
| decode 成功 | c=s=n=5 | 位置 4 的 logits 形成下一票据 |

恢复失败统一执行 s←start 会得到 c=4、s=3，直接破坏不变量。以 a−s 限制扩容提案则会在接受 z 后永久停滞，即使页池充足。若 decode 预留失败，正确状态仍为 n=5、c=s=a=4，等待资源变化或策略调整后重试。

这条轨迹不保证任意负载都能推进。全部容量被不可释放状态占满、最小服务片不可行或消费者无限背压时，需要有界等待、调整准入、换出/重算或明确失败。滚动预留不能继承最大长度预留的后续无分配阻塞保证。

## 同一候选中的成本与容量

设扫描候选数为 R、选中段数为 K、显式 query 总数为 Q。排序通常为 O(R log R)，已维护顺序时扫描可为 O(R)。每请求至多尝试 q_max 个数量时，预算评估有 O(R q_max) 次；encoder 集合、页表和资源核对另按实际清单长度计。metadata、行展开、分配、锁、提交、通知与输出账均有主机成本。

对条目 i，令 h_i=start_i，q_i 为真实 query 数。普通稠密 causal attention 的合法 query-key 对数为

V_i=q_i h_i+q_i(q_i+1)/2，V=Σ_i V_i。

COMPUTE 使用原 s 作为 h；RECOVER_LAST 使用 n−1，单行对数为 n，旧末行不得重复加入。模型有 J 层、H_q 个 query heads，键和值通道维为 d_k、d_v 时，QK 与 PV 主工作约为 2 J H_q(d_k+d_v)V FLOPs，乘加按两次计。线性层、MLP、位置变换、softmax、encoder 和采样另计。

设 H_kv 为 KV heads 数、s_bytes 为每元素字节，则每 token 全层完整 KV 的逻辑字节为

b_KV=J H_kv(d_k+d_v)s_bytes。

这里已经包含 J，不能再按层乘一次。定义 Q=Σ_{i∈V}q_i，Q_C 为 COMPUTE 行数之和，Q_R 为 RECOVER_LAST 行数之和，故 Q=Q_C+Q_R。普通新 KV 写入至少 Q_C b_KV；恢复私有暂存写入至少 Q_R b_KV，后者不增加长期有效前缀。两类实际执行的逻辑写入下界合计 Q b_KV；COW、量化元数据、对齐和重复写入另计。

例如 J=32、H_kv=8、d_k=d_v=128、s_bytes=2 时，b_KV=131072 字节=128 KiB。前述恢复和 decode 分别写一行，attention 对数分别为 4 和 5。页长 2 时，一页全层 KV 主项为 256 KiB；两页长期状态加一页恢复暂存的主项峰值为 768 KiB。暂存释放后的 decode 阶段也可达到 768 KiB，两阶段峰值不相加。

无共享、无 COW、尾页独占时，持有容量 a 对应 ceil(a/B) 页，扩展到终点 e=s+q 的增量为

Δpages=max(0,ceil(e/B)−ceil(a/B))。

仅在 a=s 且无额外预留时才能化为 ceil((s+q)/B)−ceil(s/B)。B=16、s=31、a=32、q=2 时需一页；若再预留到 49 则需两页。一般容量按同一时刻唯一物理对象并集计算：共享前缀只计一次，但请求页表和读取保护各有成本；COW 新旧页、恢复暂存、在途未回收页、权重、工作区、图池与输出副本都进入峰值。池与池内对象不能重复相加。

逻辑字节不能直接当作 HBM 事务。历史读取受 query 复用、GQA、页布局、cache、dtype 与 kernel 工作划分影响。分块不减少合法 query-key 对总和，却可能重复历史读取和固定准备。长片摊薄准备但延长不可抢占区间；短片增加服务机会，同时增加调度频率。

单设备且无卸载时没有模型状态的设备间通信，仍有输入、metadata、结果与用户输出传输。跨 worker 时，控制消息、阶段间 hidden、collective、远端 KV 和换入换出按实际表示与拓扑列账；发送 token 与发送完整 logits 的成本不能互换。

准备→encoder/传输→逐层 decoder→结果提交→采样→交付形成依赖。时间按关键路径与共享资源争用计算，不能把可重叠阶段全部相加，也不能无条件取最大值。乐观安排允许不同请求的主机准备和设备工作重叠，但增加视图驻留、校正与排空责任；本章单请求单视图限制仍保留。

## 条件变化时保留、调整与放弃

保留输入确认与 KV 确认的区别、预留先于承诺、当前授权重验、唯一消费和最后使用条件。页长、dtype、层组、窗口、adapter 或设备路径改变后，重新推导资源清单、恢复可读范围、桶、encoder 需求和成本。

长 prefill 干扰 decode 时，可限制 q、按时间预测选择片长、提高运行中请求优先级或分离 P/D；它们分别增加准备、饥饿风险或状态传输。缓存命中使 query 变短、主机开销占主导时，应调整 metadata 和调度频率；保留更多缓存挤占准入时，比较省下的重算与容量时间，不能只追求命中率。

恢复私有写区无法隔离、必要历史丢失或模型含未保存递归状态时，放弃单行恢复，采用真实检查点重放或限制完整 KV 复用。固定 vLLM 状态来源所述完整块命中限制，可能让实际重算不止一行；本章的私有单行恢复是独立方案，不能替换成对该实现的事实描述。

模型、位置、adapter 或数值身份变化后，旧页和旧票据失去直接复用资格。引入投机或同请求多视图流水时，需要显式分支、祖先依赖、接受前缀、状态副本与提交次序；缺少这些记录时保持单视图基线，不能只把 q 放大后沿用普通成功安装。

## 诊断、区分实验与检查边界

固定到达轨迹、模型、输入输出条件、取消行为和预算，逐轮记录 (r,g,η,v,t,n,c,s,a)、三类预算、选中范围、预留、跳过原因、票据与接受记录，以及提交、完成和排空事件。总 token/s 无法区分调度、依赖与输出路径。

| 观察 | 竞争解释 | 区分干预与反证后的修正 |
|---|---|---|
| 空闲但请求未推进 | token、sequence、encoder、页不足或缺 logits | 分别改变一个预算、页池或特征到达；e=0 在 B_enc=0 下应可执行。仍不变化则检查后继通知 |
| 容量耗尽后永久停滞 | 把持有容量当增长上界，或真实池满 | 设置 a=s<n 并提供空闲页；应取得新页并推进 s。预留失败时前沿保持不变 |
| 完整命中后无首 token | 恢复未入视图、恢复未完成或采样未交接 | 逐段检查恢复条目、active、票据通知、唯一接受和随后 decode |
| 恢复失败后 c>s | 错用普通范围回滚 | 注入恢复失败；c、s、n 保持，排空后可重试 |
| 迟到结果修改新请求 | 仅匹配旧条目与事件 | 同时提供互相匹配的旧 A、旧 e，再改变当前授权或 active；当前逻辑状态必须不变 |
| 输出重复或输入分叉 | 重复消费通知、发送重试重新采样 | 重复发送同 ticket；接受账、n 和随机状态只推进一次；否则修复消费事务 |
| 检查拒绝合法等待 | 把本轮新建视图当作全部在途视图 | 输入已有 COMPUTE 或 RECOVER_LAST active；本轮应保留原状态且不创建重复工作 |
| token/s 提升而 ITL 变差 | 长片、主机准备、饥饿或驻留变化 | 固定 offered 工作分别改排序、q 与页余量；联合记录 TTFT、ITL、拒绝、重算和等待 |

随章检查 tools/check_k_engine_001_full.py 是确定性、离线、只读的 Python 标准库 CPU 符号模型。被测调度器自行选择数量和更新安排状态；独立参考从原始请求枚举满足 token、sequence、encoder 与页数约束的候选，按声明策略选最大可行 q。页参考枚举逻辑位置对应的页集合，不调用被测页数函数。

审计区分本轮新建条目与输入已有 active：新条目必须唯一登记；已有在途请求必须保持原冻结关系，不要求它出现在本轮新建列表。正常检查覆盖普通与恢复在途、混合新旧请求、重复扫描、零预算、累计预算、encoder 零需求、容量增长、预留失败、失败后重试、采样到 decode，以及当前授权、版本、active、取消、重复结果和证据不足的逻辑门。

负对照实际改变调度或协议行为，再进入正常实现使用的同一审计器，包括零工作停滞、忽略预算、遗漏预留、丢弃已有 active、恢复错误回滚、安排即确认及仅匹配旧事件。独立参考建立与正常实现审计均在负对照捕获域外；参考失败不能算作预期缺陷检出。

检查只以非共享整数工作成本表示 encoder，不验证真实块去重、特征计算或依赖实现。排空仅有符号门，不模拟具体物理消费者、COW、DMA、网络或跨 stream 可见性。采样输入是外部给定 token，不验证概率、RNG/grammar 数值或 Transformer 前向；也不覆盖真实投机、崩溃恢复、任意并发交错、GPU 全层写入、性能或服务 SLO。检查覆盖描述不是执行通过记录。
