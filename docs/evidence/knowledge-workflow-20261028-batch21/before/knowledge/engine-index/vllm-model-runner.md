# K-ENGINE-003：执行视图决策：压紧、固定槽与结果归属

动态请求集合需要转成设备可执行的张量，但请求身份、逻辑位置和结果归属不能随物理行号改变。执行器要构造一份可逆的本轮视图，把输入、位置、缓存写入、attention metadata 和输出描述绑定起来，并保护这些对象直到最后使用结束。持久批槽、本轮 query 行和固定图缓冲可以同时存在，它们承担不同责任。

## 对象、输入与不变量

本章先讨论确定性推理下普通 causal self-attention Transformer 的连续 query 段。对请求分支 (r,β)，冻结请求授权代次 g、状态版本 v、模型与输入版本 η、已知 token 序列 x、已确认计算边界 k。本轮安排连续区间 [a,a+q)，其中 q 是非负整数，0≤a≤a+q≤n，n=|x|。通常 a=k；为取得缺失 logits 而重算末 token 时，可以显式选择 a<k，但必须隔离重算写区，不能覆盖旧快照。

q=0 表示本轮没有 query，不产生可采样的空行。分块 prefill 若尚未到达已知序列末端，只推进 KV，不据中间行生成普通后继 token。完整 KV 命中却缺少末行 logits 时，不能从空视图采样；可重放最后一个已知 token，保护历史并使用私有写区。空序列使用模型规定的起始输入或起始分布。

逻辑 query 键为 κ=(r,g,β,p)，p 是绝对位置。执行视图 V_t 保存不复用的视图号 t、段表、物理行到 κ 的映射 π_t、输入 token、位置、读写页映射、输出描述和资源责任。请求授权 g、状态版本 v、视图号 t、固定槽 s 及其复用代次 e_s 不可互换：g 决定请求是否仍有提交权，v 区分同一授权内的状态变化，t 决定使用哪份行映射，e_s 防止迟到通知解除新占用者的责任。

正确性要求：

- 每个选中 κ 恰有一行；每个真实行恰有一个 κ。padding 不属于真实请求。
- token、位置、mask、页映射、模型版本和采样参数来自同一冻结快照。不能让行描述与各字段一起错后互相证明正确。
- 每个必要 (层,κ) 的新 KV 有完整且唯一的写入；逻辑写键唯一还不够，两个不同键也不能无协议地写同一物理单元。
- 输出描述保留来源 query、角色、目标事件位置和分支身份。结果按本轮描述解释，不能根据完成时的当前槽表重新猜归属。
- 已提交访问和已保留的未来消费者都阻止覆盖。请求取消撤销未来业务交付资格，不证明 kernel、DMA 或网络读取已经结束。
- 发布与完成提交分别重新检查授权和状态快照。检查与安装由同一串行拥有者或等价事务保护。

这是一种连续段、每分支同一时刻只有一个未解析视图的参考组织。树验证、递归状态或同分支多轮流水需要增加祖先可见性、状态副本及提交次序，不能直接把连续段长度当作全部状态。

## 压紧、输出行与重排

按本轮确定的请求分支顺序，对 q_i>0 的段计算 u_0=0、u_{i+1}=u_i+q_i。段 i 的局部 query j 位于物理行 u_i+j，绝对位置为 a_i+j。总真实行数 Q=u_N。普通生成末行是 u_{i+1}−1，但只有该段到达当前已知末端、且具备生成资格时，才成为 SAMPLE 来源。

q=[2,5,3] 时，偏移为 [0,2,7,10]，末行是 [1,6,9]。起点 [100,200,50] 对应末行绝对位置 [101,204,52]。请求顺序反转后，q=[3,5,2]、偏移 [0,3,8,10]，末行应为 [2,7,9]；绝对位置按请求身份仍分别为 C:52、B:204、A:101。重排改变物理行，不能改变逻辑位置。

输出描述不是每行一个布尔采样标志。它至少包含来源 κ、物理行、角色、目标事件位置和样本序号。普通 next-token SAMPLE 使用位置 p 的 logits 预测 p+1；已知 token 的 LOGPROB 同样要区分来源 p 与被评分的 p+1。若被评分 token 的前驱 query 不在本轮，需要保留前轮结果或安排合法重算，不能把当前 token 的 logits 当作它自身的概率。多个输出事件可以共享来源 logits，但仍保留各自身份与随机状态。

```pseudocode
算法 1：建立本轮执行草案
输入：冻结请求/分支快照，显式选择的连续段，输出描述，资源与桶规格
输出：不可变视图草案及预留，或具体拒绝原因

初始化段表、行表、输出表和临时预留为空；offset←0
for each 候选段 in 确定顺序:
    检查身份、授权、输入版本、位置规则、输入就绪与无冲突在途工作
    检查 a、q 为整数且 0≤a≤a+q≤|x|；任何非法值立即拒绝
    q=0 时不建立真实段；若仍要求本轮输出则拒绝
    核对每层历史可读，预留全部新写区及必要 COW/结果容量
    在候选私有草稿中展开 p∈[a,a+q)：
        κ←(r,g,β,p)；拒绝重复 κ
        row←offset+(p−a)
        同时收集 token x[p]、绝对位置 p、版本与本层读写映射
    候选检查失败则撤销其全部临时预留，不遗留半段
    成功后合入总草稿，保存段起点；offset←offset+q

Q←offset；若 Q=0，返回 NOOP，不提交设备计算
根据输出描述定位真实来源行：
    SAMPLE 必须来自有生成资格的已知末端
    LOGPROB 必须有声明的已知目标及正确前驱来源
    KV_ONLY 不创建普通 SAMPLE
    拒绝缺失来源、越段目标、重复输出事件及 padding 目标

检查桶签名、每请求限制、整批 query/page 容量及派生计划全部区段
无相容桶则换桶、合法拆批或普通执行，不截断 query 或历史
冻结段表、行字段、逆映射、目标表与全部预留
返回草案；尚不修改长期 token、KV 边界、grammar 或 RNG
```

如果物理执行还要进一步排序，所有字段必须经同一置换 gather，输出描述也经其逆映射更新。检查参考从原始请求与选中区间重建 κ 和字段，不能只比较两个已经一起重排的候选数组。

## 固定容量、缓存寻址与消费契约

压紧减少无效行，但增加收集、前缀和、排列和 metadata 准备。固定槽稳定地址，有利于图重放与缓冲复用，却可能执行 padding，并增加多桶驻留。固定版本 vLLM 的机制说明使用持久批状态，再压紧本轮 query，说明这两个选择可以组合。

桶签名包含真正影响执行结构的 dtype、布局、head 几何、页长、backend、mask、adapter 路径和模型模式等条件。可由设备读取的固定地址 metadata 内容可以变化；被捕获为常量、grid 或具体指针的条件变化，需要换执行产物或使用明确支持的更新。

设桶提供请求容量 N_cap、query 容量 Q_cap、页索引容量 P_cap，以及每请求 q_max、p_max。必须同时满足 N≤N_cap、Σq_i≤Q_cap、Σp_i≤P_cap、q_i≤q_max、p_i≤p_max，再检查任务队列、mask、partial output 等派生区段。页索引条目和唯一物理页是不同计数：共享前缀可以减少物理页，却不一定减少各请求自己的索引条目。

例如 q=[6,5]、q_max=6、Q_cap=10，两个请求逐项合格，整批仍越界。Q_cap=16 承载 Q=10 时，空置比例为 6/16=37.5%；这只描述行数，不能直接解释为运行时间损失。

本章选择的尾部契约是：有效请求数、有效 query 数与设备任务队列限制实际访问；固定偏移数组在真实段之后重复末偏移；尾部行没有真实 owner。稠密层若仍计算尾部，输出丢弃；KV 写入必须跳过或进入隔离区。有的 backend 不接受零长尾段，需要其支持的 dummy 请求布局；此时重新计算包含 dummy 的全部需求，不能让多个 dummy 无协议地写同一地址。host 标记无效不能独立约束设备写入。

为说明从逻辑位置到存储的连接，选择一种普通分页 KV 布局：块长 b token，每层页表 T_ℓ 将 floor(p/b) 映射到物理页 z，页内位置 o=p mod b。若 K、V 各采用 [page,b,H_kv,d] 的连续布局、元素宽 s 字节，则分量 c 的地址为 base_K或V,ℓ+s·(((z·b+o)·H_kv+h)·d+c)。这只是可替换的教学布局，不声称是所归档执行器的实际 stride。

构造视图时同时保存位置 p、逻辑页、物理页与页内偏移。不同请求的只读前缀可指向同一页；共享不可变尾页的首次冲突写入需要私有化。COW 先分配新页、复制必要有效前缀并等待可见，再让新写者使用新页；旧页继续保护旧快照读者。仅改变 page id 或引用计数，不能代替复制完成。真实布局若使用不同轴序、量化 scale、窗口覆盖或层组，须重建相应地址和状态合同。

## 从发布到逐层执行、提交和回收

固定槽保存 phase、视图号 t、复用代次 e、高水位 high、ready 依赖、实际访问责任与未来消费者描述。phase 包括 FREE、WRITING、READY、RUNNING、DRAINING；失败且尚未排空时进入隔离状态。high 在回到 FREE 后保留，失败尝试的代次也不再次分配。请求授权 g 不随槽的每次使用递增。

```pseudocode
算法 2：发布、执行和结束
输入：视图草案、固定槽及拟用代次 e、绑定的执行产物、消费者清单
输出：按原视图路由的结果，或失败/取消；最终安全归还资源

在发布拥有者的串行域内：
    槽非 FREE 则返回 BUSY；e≤high 则返回 STALE；拒绝路径不写内容
    重验全部请求授权、状态快照、输入、历史保护与预留
    原子绑定视图、槽和分支在途关系；槽进入 WRITING
    登记准备责任后启动输入、页表、metadata 和计划准备
    保持异步复制源与目标，建立生产到执行的 ready 依赖
    准备成功才发布完整内容、映射和消费者描述；high←e；phase←READY
    准备失败：停止后继，保留已发出访问；排空并初始化后才能 FREE

提交前重验资格：
    确定未提交：结束业务解析，撤销尚未启动的未来消费者
    提交已接受：设备责任已先登记，phase←RUNNING
    接受状态未知：保留设备责任及地址，不猜测为未提交
    只能启动与本桶、本槽地址相绑定的执行产物

逐层前向：
    h⁰[row]←同一 κ 的 token 与模型规定的位置输入
    for 每个必要层 ℓ：
        从 h^(ℓ−1) 产生本层 Q、新 K/V，应用规定位置变换
        向本层私有写区写入 K/V，建立写入到 attention 读取的依赖
        每行只读取本分支该层历史 [0,a) 和本轮截至自身的合法 K/V
        在完整可见集合归一化 attention，按固定图产生 h^ℓ
        本层 hidden 完成可见后下一层才能消费；传输保留 κ 与版本
    从目标行末层 hidden 产生所需 logits
    汇集全部必要 (层,κ)、目标结果与复制的完成及可见性证据

完成通知：
    不匹配 t、槽身份或 e 的通知不修改当前占用者
    重复责任通知幂等处理；没有相关访问结束证明则继续等待或隔离
    相关访问确已结束后，结束匹配设备责任，进入 DRAINING
    执行失败或必要覆盖不全：拒绝业务提交，不把部分结果当成功
    成功时按冻结 π 和目标表暂存结果
    在请求状态拥有者内重验 g、v、η、预期边界、取消及唯一提交资格
    资格成立才原子安装有效全层 KV 拥有权和进度，再提交合法采样后继
    重算范围不倒退 k；新采样 token 尚未计算，不能计入其 KV 边界
    提交失败或取消：不交付正式结果，结束未启动消费者描述

输出和回收：
    消费者在启动前取得受保护引用；按完整消费者身份逐项结束责任
    重复完成不能减少另一个消费者的责任
    业务已解析、全部实际访问结束、未来使用已结束或撤销后才 FREE
    解除执行引用前先完成必要长期 KV 引用移交；保留 high
```

完成证据不是“某层写过一次”。它要覆盖每个必要层、每个选中 κ 和每个必要目标。末层 logits 就绪不能替代其他层 KV；设备访问已经结束但结果失败时，可以清理物理责任，却不能推进成功边界。长期 KV 安装与采样后继还应服从[请求状态提交协议](../system-semantics/request-batch-identity.md)；本章不把结果路由等同于完整生成事务。

设槽 3 的 high=4，发布视图 t=7、e=5，保留采样与输出复制两个消费者。设备尚未结束时取消请求，槽仍保留在途责任。设备结束后业务拒绝，尚未启动的消费者可撤销；已经启动的复制仍需结束。正常成功路径中，采样先结束也不能释放输出复制的责任；重复采样通知同样不能清零它。两者都结束后槽才 FREE，high 仍为 5。下一视图使用 e=6 后，t=7、e=5 的迟到通知只能归入旧记录。

代次校验只隔离旧通知，不能阻止旧 kernel 继续写地址。因此旧设备访问未结束时把槽交给下一视图本身已经违法，增加 epoch 字段不能修复物理覆盖。CUDA Graph 固定的是地址及执行结构，地址里的内容仍需要上述协议保护。

## 条件化成本与方案反转

设 N 个真实段、Q 个 query、F 个行字段、G 个段字段、T 个输出描述、P 个页索引或引用条目、H 个消费者责任、J 个必要层。显式逐行构造、哈希查账的准备工作期望为 O(QF+NG+T+P+H)；完整逐层覆盖审计为 O(JQ+T+P+H)。段表可以把连续位置表示压缩到 O(N)，但显式逐行 gather 仍有 O(Q) 工作，不能保留展开算法却只计段表成本。

输入与 metadata 的逻辑复制量为各实际复制字段字节之和；持久设备数据未改动时不应重复计传输。页表复制可以提前，与后续 host 准备重叠，但 attention 必须等其完成。每次锁页、分配、COW、计划构建和桶选择另有成本，不能把它们归入一次免费的 replay。

对相同有效输入，行映射不减少模型数学工作。普通稠密 causal attention 有 J 层、H_q 个 query heads、head 维 d、每段可见历史 h_i=a_i 时，QK 与 PV 主工作量约为 4JH_qd·Σ_i[q_i h_i+q_i(q_i+1)/2] FLOP，按乘加计两次运算。位置变换、softmax、线性层、MLP 和采样另计；窗口、稀疏或递归模型不直接使用此式。

若每 token 每层完整 K/V 表示占 B_kv 字节，新增逻辑写入约为 JQ B_kv。实际 HBM 读取受 KV head 数、页布局、dtype、query 复用、融合和合并访问影响，不能从逻辑字节直接推定事务与时间。显式 logits 物化量为 T·V·s_logit 字节，V 是词表大小；共享来源行时可物化更少份，但输出事件仍有独立路由和后继状态成本。

padding 成本按实际消费计划计算：稠密线性层可能按 Q_cap 执行，attention 的额外工作则取决于 dummy 历史、mask 和任务队列，不能只用 Q_cap/Q 推算全部模型时间。图捕获、编译和预热是准备成本，只有同一相容执行产物被重复使用时才能摊销。

跨 worker 的 metadata 若简单复制给 W 个接收方，逻辑发送量为 W·M 字节；传递 hidden 时，每个实际边界约传 Q·D_model·s_hidden 字节，模型并行 collective 按具体分片与拓扑另计。传 token/状态码与传完整 logits 相差一个词表维度。不能因为行映射只在 host 构造，就忽略其派生通信。

驻留按同一时刻唯一物理存储的并集取峰值：权重、唯一 KV、新旧 COW 页、固定缓冲、workspace、输出副本、图池和剩余保留容量分别列账。图池若已包含工作区，不再重复相加；共享页只计一次物理容量，但每个引用仍有簿记。慢消费者延长槽占用；稳定条件下占用速率 λ 与平均持有时间 τ 给出平均在途量约 λτ，不能据此替代变化大小对象的峰值容量。

时间沿准备→复制→逐层执行→结果→提交→输出的真实依赖计算。独立段可重叠，共享 CPU、主存、PCIe 或 NIC 的工作仍累计资源需求。把全部阶段相加会漏掉重叠；把独占测得的各项全部取最大又可能漏掉共享带宽争用。

活跃集合变化大、长 prefill 与短 decode 混合时，压紧可能减少无效计算；若准备成为关键路径，应考虑段表、增量更新或准备缓存。shape 稳定且提交开销占主导时，固定桶可能受益；若多桶驻留压低 KV 准入、填充工作增加或慢消费者占满槽，应减少桶、调整捕获边界、使用独立输出存储或回退普通执行。独立输出复制能缩短图槽持有，却增加字节、复制依赖和副本驻留，不能认为一定更快。

加入 prompt logprobs、分支或投机后，必须放弃“每请求最后一行就是全部输出”的简化。模型、adapter、页长、位置规则或 backend 改变后，重新检查签名、状态相容性和地址绑定。表示可以调整，身份、完整覆盖和最后使用条件仍须保留。

| 观察 | 竞争解释 | 控制改变、预测与反证后的修正 |
|---|---|---|
| shape 正确但输出错配 | token gather、位置、输出目标或请求路由错误 | 固定原始请求，枚举请求顺序，按完整 κ 重建字段与目标；物理行变化但同一逻辑事件应不变。字段均对仍有数值差异时转查 kernel 与数值契约 |
| 重排后末行检查失败 | 布局实现错或检查预期算错 | 独立枚举每个请求的绝对位置，再定位最后一行；q=[3,5,2] 的 [2,7,9] 会反驳 [2,8,9]，不能为迎合错误预期改变布局 |
| 单请求正常、共享前缀混批错误 | 物理写入别名、COW 未完成或 mask 跨请求 | 保持逻辑键不同，故意令两个写键指向同一物理单元；再恢复独占写区。独占后消错支持写区解释，否则继续查可见集合与版本 |
| k 增长但部分历史缺失 | 只看 logits、只看末层或漏掉一行 KV | logits 保持完整，删除某层一个 κ 的证据；不得提交成功边界。拒绝完整正确证据则修正检查域 |
| 固定桶更慢 | padding、准备、池驻留或准入变化 | 先固定已准入输入比较准备和执行，再放开准入观察队列及尾延迟；只有放开准入才反转时，修正容量与排队解释 |
| 下一轮读旧结果或覆盖新结果 | 过早回收、错槽执行、旧通知或重复消费者扣账 | 延迟设备结束与输出复制，注入旧 t/e 和重复消费者通知；应等待或无状态变化。静态单轮也失败时先查地址绑定 |
| 取消后仍交付，或取消后无法回收 | 资格检查未原子化，或未启动消费者没有撤销 | 分别在提交前后取消；提交前不得交付，但仍排空实际访问。访问已结束且业务已解析后仍占槽，检查未来责任是否遗留 |

随章 `tools/check_k_engine_003_full.py` 使用 Python 标准库建立确定性、离线、只读的 CPU 符号模型。压紧参考直接从原始请求的绝对位置逐项枚举，独立检查行、token、位置、偏移和输出描述；覆盖零长度、所有小规模请求排列、同局部字段的不同请求/分支、显式 logprob 目标、总容量和 padding。物理写区检查同时核对完整 (层,κ) 覆盖、写者唯一性、历史冲突和共享不可变页。

负对照实际修改目标行、token/身份字段、写入地址、覆盖证据或槽协议，再交给相同参考或不变量检查；包含旧错误预期 [2,8,9]、只检查逐请求容量、提前释放、重复责任扣减、忽略槽代次及取消/授权失效后提交。正常状态轨迹还检查空消费者、准备依赖未满足、未结束完成通知、部分覆盖与旧视图通知。

该模型不运行 Transformer 数值前向，不模拟真实 COW 复制、准备失败后的运行时排空或提交接受状态未知的 API，也不证明真实页表 stride、CUDA Graph 捕获、跨 stream 可见性、GPU 全层写入、DMA/网络结束或性能。它验证的是声明范围内的映射、容量、写区和协议关系。Python 是否执行及执行结果由绑定当前脚本与输入的真实记录承担，正文的覆盖说明不构成执行通过记录。
