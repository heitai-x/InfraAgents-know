## 为什么仍有改进空间

FlashAttention 已避免将完整分数与概率矩阵写回设备主存，但这不保证矩阵单元高效工作。FA2 §3 分析三项剩余成本：非矩阵操作吞吐低；仅按 batch 和 head 划分时线程块数量不足；沿 K 分给不同 warp 会产生需要跨 warp 合并的部分输出。

矩阵乘与标量运算不能只按 FLOPs 相加比较。论文用 A100 的 FP16/BF16 矩阵峰值 312 TFLOP/s 与非矩阵 FP32 峰值 19.5 TFLOP/s 说明吞吐量级差；这不是每条标量指令都固定慢16倍，也不是跨设备的常数。

## 减少非矩阵工作：推迟归一化

对已处理的合法分数，维护 m=max(z)、ℓ=Σexp(z−m)、U=Σexp(z−m)V，最终才计算 O=U/ℓ。若每个块都保存已归一化 O，则每步既要恢复旧质量，又要除新分母；维护 U 可避免重复输出归一化。更新最大值时仍必须同时缩放旧 ℓ 与 U，不能省略必要操作。

```pseudocode
为每个 query 块载入 Q，初始化 m←−∞、ℓ←0、U←0
对需要访问的每个 K/V 块：
    计算合法分数 Z，取得 m新←max(m，本块最大值)
    r←exp(m−m新)，首次非空块取 r←0
    P←exp(Z−m新)，不可见位置取零
    ℓ←r·ℓ＋rowsum(P)；U←r·U＋PV；m←m新
最后计算 O←U/ℓ，按需要保存 LSE←m＋ln ℓ
```

空行和全 mask 块按[模块正文](../frameworks/attention-backends.md)的显式规则处理，不能直接计算 −∞−(−∞)。原论文用方形输入简化表达；推广到不同 query/KV 长度时要保留绝对位置与可见性，不把某个接口的默认对齐当作数学定义。

## 两层工作划分

线程块之间：将不同 query 行块交给不同 CTA（协作线程块）。这种划分下，网格任务数约为 batch·query heads·⌈L/Br⌉；不同块拥有不同输出行，前向无需跨 CTA 合并输出。它增加长序列、小 batch 时的可调度工作，但可能重读 K/V；增大 Br 的复用收益与减少任务数的代价要共同分析。query 只有一行时，这个轴几乎不能增加任务数，沿 KV 分区仍是另一种选择。

线程块内部：论文 Fig.3 将 sliced-K 与 sliced-Q 比较。sliced-K 让不同 warp 处理同一批 query 的不同 K/V 部分，需要借共享存储合并部分输出；sliced-Q 让每个 warp 拥有不同 query 行，所有 warp 可消费共享 K/V，各自维护对应的 m、ℓ、U，省去这种跨 warp 输出合并。共享 K/V 的加载就绪与缓冲复用仍需要同步，不能解释成整个 kernel 无同步。

设 Br=128、4个 warp，均分时每个 warp 拥有32个 query 行；这描述逻辑行归属，不指定实际矩阵指令的寄存器布局。改变 head 维度、warp 数、tile 或硬件后，重新核对寄存器、共享存储、尾行和驻留约束。

## 论文结论与适用条件

论文在 A100 上报告约2倍于当时 FlashAttention 的加速，达到矩阵理论峰值的50%–73%；另报告 GPT 类模型训练最高225 TFLOP/s/A100。前者是其 Attention 基准，后者包含训练系统，不能作为目标机器的前向推理数字或任意 shape 的保证。§4 与图表给出具体长度、head维度、因果与非因果设置。

反向传播只保存 LSE 并按块重算概率，是论文另一个重要点；它不意味着纯推理必须为了训练保留全部统计量。GQA/MQA 可通过 head 索引共享 K/V，而非复制为 query head 数。

## 算法核对与设计意义

v1 PDF 第6页 Algorithm 1 第10行的打印式给旧累加量写了反向缩放。这里采用由 U 定义推导的 r·U，而不照抄该打印式。设两块分数0、2，V分别1、0，正确输出为1/(1+exp(2))≈0.1192；反向放大旧 U 会得到大于1的值，越出 V 的凸包。出处不能替代数学核对。

从本论文可以提炼：减少全局 IO 后，非矩阵工作、可用并行度和片上通信会继续成为瓶颈。FA2 的三项选择可分别做对照，而不是把整个版本当作不可拆的方案，见[模块中的 FA2 节](../frameworks/attention-backends.md)。本说明没有目标 GPU 实测。
