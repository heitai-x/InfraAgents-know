# K-ALG-002：分页 KV：逻辑位置、物理布局与共享所有权

分页把序列长度的动态增长转换为块映射变化；attention 语义仍由逻辑位置与有效长度决定。

## 问题、不变量与设计轴

问题：每条请求的 KV 随生成逐 token 增长，长度上界未知且各请求不同，设备容量固定且被多请求共享。状态表示要回答"逻辑位置 t 的 K/V 放在哪里、谁拥有它、何时可以回收"。

不变量：逻辑 token 顺序与有效长度决定 attention 读取集合，物理放置不改变结果；一个物理位置在同一时刻只有一个写者；共享的内容在任一所有者修改前被复制或隔离；回收发生在最后一个读者（含已排队的设备工作）结束之后；容量账中共享页只计一次。

成本项：尾部碎片（粒度越大越多）、元数据与间接寻址（粒度越小越多）、kernel 对非连续布局的读取效率、分配/回收与页表更新的主机时间、共享分叉时的复制、以及地址不稳定对图执行的影响。

设计轴：分配粒度（整请求预留 / 固定 token 块 / 字节级虚拟映射）；地址连续性（物理连续 / 逻辑连续物理离散 / 虚拟连续按需 backing）；所有权模型（独占 / 引用计数共享 / 写时复制）；层间组织（所有层同一页 / 按层或层组独立池）；回收时机（引用归零立即 / 等待完成事件 / 延迟批量）。PagedAttention 位于固定 token 块与引用计数共享的交点，vAttention 位于虚拟连续与按需映射，整请求预留是最简单的一端；各点的前提与代价在后续节中展开。轴上未列点同样合法。

## 从逻辑状态到字节地址

一层普通注意力缓存的逻辑轴是请求 r、绝对 token 位置 t、KV head h、通道 c，以及独立的 K/V。令该请求已提交且完成的 KV 长度为 Lᵣ，页长 P，以 0 为起点。合法读取要求 0≤t<Lᵣ、0≤h<Hkv、K 的 0≤c<dₖ 或 V 的 0≤c<dᵥ。输入是逻辑 Kᵣ[t,h,c]、Vᵣ[t,h,c] 与请求状态；输出是等价的物理表示及可供消费者读取的描述。这里的 Lᵣ 表示已完成 KV，不等于已输出 token 数、分配槽数或投机容量。

逻辑页号 j=⌊t/P⌋、页内位置 u=t mod P，页表 Tᵣ[j] 记录物理页标识 p 及其复用代次 g。代次不是数学函数所需，而是本例检测旧异步事件的手段。模型语义还要求同一页中的内容来自正确模型、层、head、位置和前缀；仅仅物理地址相同不证明状态相同。全层或层组可以各有页表，下面先按单层、K/V 分池推导。

设输入元素 b 字节，K 页实际 stride 为 Dₖ≥P·Hkv·dₖ·b，V 类似。NHD 表示页内逻辑形状 [P,Hkv,d]，HND 表示 [Hkv,P,d]；两者的最后一轴都为通道。没有额外 padding 时：

| 表示 | K 元素的字节地址 |
|---|---|
| NHD | K基址＋p·Dₖ＋b·((u·Hkv＋h)·dₖ＋c) |
| HND | K基址＋p·Dₖ＋b·((h·P＋u)·dₖ＋c) |

V 使用 V 基址、Dᵥ 和 dᵥ。这张表的 stride 明确按字节，而张量接口可能按元素表达，接入时必须转换单位。K/V 若交错、量化分组或使用不同 padding，要从实际轴和 stride 重推，不能把本式当作通用 ABI。NHD/HND 是物理排列选择，改变描述符不会移动既有字节。

完整定位例取 P=4、Hkv=2、dₖ=dᵥ=4、b=2。每个 K 页 64 字节、每个 V 页 64 字节，一对页共 128 字节，基址分别设为 4096 和 8192，页表为 [3,1]，Lᵣ=6。读取 t=5、h=1、c=2 时，j=1、u=1、p=1；NHD 页内偏移为 28 字节，K 地址为 4188、V 地址为 8284；HND 页内偏移为 44 字节，地址为 4204 和 8300。两种布局必须各自存放同一个逻辑值；拿 NHD 字节直接按 HND 读会把别的 token/head 当成该元素。

消费者对 j=0…⌈Lᵣ/P⌉−1 顺序取页，再只取 min(P,Lᵣ−jP) 个有效位置。物理页顺序 [3,1] 不改变逻辑顺序。最后一页空槽即使已有旧字节，也不进入 attention。Lᵣ=0 时页表为空；Lᵣ>0 时本例规定末页有效数为 1＋((Lᵣ−1) mod P)，整页是 P，不能用 0 同时表示空请求与满页。query 的分段偏移和 KV 页偏移表达不同轴。

Attention 数学函数仍由 Q、这些逻辑 K/V 及合法位置集合决定。分页消费可以逐页进入在线 softmax，也可以付出 gather 成稠密数组的代价；两者都要保持相同的可见集合和 head 映射。完整在线归约见 [Attention 执行](../frameworks/attention-backends.md)。物理位置正确只是必要条件，不能替代 mask、位置变换和数值契约。

## 不可变快照与追加的完整算法

下面构造一种便于独立实现和检查的方案：每个已发布页的有效内容不可修改，追加总是在新页中重建被触及的尾部，再发布新的请求快照。已填满且未触及的页继续共享。它比独占尾页原地追加多付复制，却让旧消费者稳定读取旧快照；不是 PagedAttention 论文或任何引擎的唯一实现。

快照保存请求身份与代次、KV 长度、各逻辑页的 (物理页,复用代次)、布局与数值身份。每请求一次最多有一个追加事务；请求元数据操作串行化，消费者领取快照也参与同一个主机侧协调。物理页维护 O 个当前请求映射、R 个在途读取票据，以及 W 个独占写入/暂存保留权。W 从分配一直保留到发布，或写入排空后的放弃；“复制已完成但尚未发布”的页不能因此变成空闲。

只有 O=R=W=0 才允许重新分配该页，并增加其复用代次。O 归零不代表 GPU 或传输读者已经结束。R 也包括事务复制旧尾页时的读取保护。真实实现可以用完成事件、资源租约等表示这些关系，本例的计数并不规定数据结构。

```pseudocode
输入：活动请求当前快照 S，追加的 q 个已合法产生的 K/V，页池与最大长度
若 q=0，返回 S；若 S.长度+q 超过模型/任务上限，拒绝且不改变 S
在请求元数据协调区内：
    核对请求身份/代次、当前快照仍为 S，取得该请求唯一追加权
    令 j起←floor(S.长度/P)，j止←ceil((S.长度+q)/P)
    一次取得 j止−j起 个空闲页的写入保留权；容量不足则不启动写入
    若旧尾页未满，给复制源尾页领取读取票据
    新页表保留逻辑页 0…j起−1，之后依次放入新取得的页
在新页中构造数据：
    若旧尾页未满，逐 token/head/channel 复制其有效前缀，K/V 同时保持布局身份
    对 q 个新逻辑位置，根据新页表和字节地址公式写入对应 K 与 V
    等待所有复制、写入和必要转换完成；未写入空槽不被标记为有效
    准备新长度、页表和布局/数值身份组成的完整描述
在请求元数据协调区内再次检查：
    若请求已取消/换代或当前快照不是 S，进入放弃分支
    建立数据及描述准备完成 → 消费者可读取的依赖
    发布新快照；增加新页的请求映射，移除被替换尾页的请求映射
    释放新页写入保留权、复制源读取票据及请求追加权
    对此刻 O=R=W=0 的页允许回收
放弃分支：
    不发布新长度/页表，不修改仍有效的旧快照
    等本事务所有复制/写入结束，再释放新页保留权和复制源票据
    若请求曾被取消，其旧请求映射由取消操作负责移除，不能重复减计数
```

q>0 时暂存页数为 a(L,q)=⌈(L＋q)/P⌉−⌊L/P⌋。它包含未满尾页的替换，因此不能只预留“页表长度增量”；L=6、P=4、q=1 时页数仍为 2，但本方案需要 1 个暂存页。所有必需页先取得再写，避免写到一半才发现容量不足。q>1 只适用于已知输入段、已验证的分支结果或其他已满足依赖的 K/V，不能提前产生未知自回归 token。

发布在这里是一个逻辑切换：主机协调保证消费者取得完整版本，设备依赖保证数据与设备描述可见。它不假设多字段设备 metadata 可以原子写入。若 graph 从固定地址描述包读取页表，要先取得没有在途读者的包，复制整份一致描述，排好数据/描述完成依赖，再启动 graph；包的地址稳定不能保护被覆盖的内容。快照已经发布在主机而没有空闲图包时可以等待或选用另一合法执行路径，不能覆盖忙包。

消费者领取快照时，在同一协调关系内核对请求仍活动、页身份和准备条件，给全部将读取的页及描述领取独立票据，然后才提交工作。完成事件绑定票据、物理页及其代次；每张票据最多释放一次。取消先阻止新领取、移除当前请求映射，已有票据仍等实际最后读取完成。结果归属再核对请求代次，旧结果不能提交到重新使用同一请求槽的新请求。设备工作异常时必须经过已声明的排空/重置语义才能释放，超时本身不是读取已经结束的证明。

另一种合法选择是在独占尾页里只写旧长度之外的新位置，保留旧快照的有效前缀；它可避免逐 token COW，但需要证明旧消费者不会读取新写区域，追加失败时旧可见长度不变，并处理共享尾页、并发写者与异步读取。也可以只共享完整页、保持各请求私有尾页。是否需要复制由所有权、读取范围和发布协议共同决定，不能仅因“还有空槽”就允许写入。

## 共享尾页、图消费、取消与复用的贯通轨迹

仍取上述 128 字节页对。A、B 都长 6，内容身份相同，共享逻辑页表 [3,1]：物理页 3 有位置 0…3，页 1 有位置 4、5。共享半满页只是本例的策略；若仅共享整页，初始容量与后续复制账都要重算。

| 事件 | 请求映射与设备读者 | 可否回收 |
|---|---|---|
| e0 | A/B 各映射 3、1；空闲图包 G0 领取 A 的长度 6 快照并开始读取 | 页 3、1 都有 O=2、R=1 |
| e1 | A 取得页 2，复制页 1 的两个有效 token，再写位置 6；旧页 1 获复制读取票据 | 页 2 的 W=1，不能因 O=0 回收；复制完成前也不能回收源页 |
| e2 | 数据/描述就绪后发布 A 的长度 7、页表 [3,2]；释放复制票据与 W | 页 1 的 O=1、R=1；页 2 的 O=1；旧 G0 仍看到 [3,1] |
| e3 | 空闲 G1 领取 A 的新快照开始读取；取消 B | 页 1 的 O=0、R=1，仍保留；不能把 B 取消当成 G0 完成 |
| e4 | 取消 A，移除其当前 [3,2] 映射，阻止新读取 | 页 3 的 R=2，页 1、2 各 R=1，三页都仍存活 |
| e5 | G1 先完成实际读取并释放其票据 | 页 2 可回收；页 3、1 仍被 G0 保护 |
| e6 | G0 后完成 | 页 3、1 才可回收；两个图包各自在其全部读写/输出使用结束后复用 |

e1 的旧有效前缀是 2×32=64 字节，因此 COW 至少读 64、写 64，再写新 token 32 字节，共 160 字节设备主存逻辑交通；metadata 和实际事务另计。e1…e5 同时有 3 对物理页，占 384 字节，尽管逻辑请求映射数曾达 4；不能把共享页按两个请求重复计容量。G0 的 A 长度 6 与 G1 的 A 长度 7 都必须各自得到对应稠密参考，不能拿新页表验证旧输出。

若 e1 分配不足，没有任何新写入；若复制之后请求被取消，则新页只有在写入完成后才能放弃。若 e2 之前准备失败而请求仍活动，A 仍保持原长度 6 和 [3,1]。页 2 在 e5 被分给 C 时应取新复用代次；重复或迟到的 G1 完成事件既不能减少 C 的读者，也不能回收 C 的页。本例使用代次检查与一次性票据实现这点，隔离资源池也是可论证的另一种方式。

量化页把“内容”扩大为码字、scale、分组轴和转换身份；复制只移动码字就不再保持同一逻辑 K/V。压缩传输还增加接收完整性与解码就绪关系。它们可以进入本协议的数据准备阶段，不能绕过准备完成后才发布的依赖。[Attention 的组合案例](../frameworks/attention-backends.md)具体推导 FP8 封存与固定图包，本节则独立覆盖共享未满页的 COW。远端页要在目的容量、数据/scale 完整且访问权成立后才能发布；网络地址也不等于物理内容身份。

## 容量、交通、准备与关键路径的同一份账

令一个设备负责的层数为 N，普通均匀 KV 的每 token 字节 τ=N·Hkv·(dₖ＋dᵥ)·b；异构层需逐层求和。每页对实际 stride D≥Pτ，量化 scale、对齐或分层分配会改变 D。设某时刻因请求映射、在途读者或写入保留而存活的不同物理页集合为 U，则页池的占用是 |U|D；固定预分配整个池的保留显存是池容量×D，不能用当前占用代替。共享页在 U 中只出现一次，旧快照和暂存副本必须出现。

不共享且没有在途副本时，请求长度 Lᵣ 需要 nᵣ=⌈Lᵣ/P⌉ 页，分配容量 ΣnᵣD；若 D=Pτ，尾部浪费为 Σ(Pnᵣ−Lᵣ)τ。平均浪费 (P−1)τ/2 只适用于长度余数近似均匀且尾页独占的假设；不是任意实际轨迹的定理。平坦变长表若每项 e 字节，批中 B 条请求的表项主项为 eΣnᵣ，另加 B＋1 个偏移、B 个长度及布局/身份字段。padded 表则按 B·max nᵣ 分配。一个 graph 包的容量按其最大表宽预留，不能只记当前有效项。

保留原来的全层算例：N=32、Hkv=8、dₖ=dᵥ=128、b=2，τ=131072 字节，即 128 KiB。P=16 的页对组是 2 MiB；长度 18 需要 4 MiB，真实 KV 为 2.25 MiB，尾部浪费 1.75 MiB。这不要求所有层放在同一个物理张量。权重、激活峰值、图包、通信区、量化元数据和分配器保留还需从设备预算另扣。

本节不可变追加中，若旧尾有效 r=L mod P>0，复制旧前缀至少产生 2rτ 字节读写，新 q 个 token 的 KV 写入为 qτ。页表复制、padding 初始化、数值转换、实际合并事务可能增加交通；逐次追加总成本不能仅算最终有效 KV。若为了连续 kernel 另做 gather，每个被 gather 的有效 KV 至少再读/写一次，额外约 2ΣLᵣτ，且稠密副本增加容量峰值。

Attention 主要 FLOPs 不因页长改变；某候选对 K/V 发起的请求量由 query tile/head 复用决定，不能从唯一物理页容量直接推断。共享前缀节省容量和 prefill 重算，也不等于不同 query 无需各自做 attention。物理事务受布局、向量宽度、对齐和 cache 影响，必须与本节的逻辑字节分开。相关计算/流量联立见 [Attention 成本](../frameworks/attention-backends.md)。

将准备、复制、描述发布、kernel 和完成画成有向依赖图。如果本例选串行执行，新增时间可估为分配/准备＋复制交通/有效带宽＋描述传输＋kernel增量＋同步；允许重叠后，时间是各依赖路径之和的最大值，不能无条件把相同项相加或取最大。跨设备还需计状态传输、访问授权与接收暂存；单设备本地分配例没有网络通信，通信成本为零，不能编造一个必须存在的项。

## 页长变化怎样使选择反转

以下是用于核对推理的设定模型，不是目标设备测量：三条不共享请求当前长 5、6、9，都追加一个已合法产生的 token，使用 τ=128 KiB 的全层 KV，D=Pτ。仅比较 P=4 和 P=8，不可变追加每条都产生一个新尾页；三条旧尾余数之和分别为 4 和 12。

| 项目 | P=4 | P=8 |
|---|---:|---:|
| 当前有效 token / 页数 | 20 / 7 | 20 / 4 |
| 当前容量 / 尾浪费 | 3.5 / 1 MiB | 4 / 1.5 MiB |
| 三个暂存尾页容量 | 1.5 MiB | 3 MiB |
| 旧页尚存时容量峰值 | 5 MiB | 7 MiB |
| 本轮旧尾复制＋新增 KV 写入 | 11τ=1.375 MiB | 27τ=3.375 MiB |

用 8 字节表项、4 字节偏移和 8 字节长度作本例元数据约定，单份有效变长表连长度/偏移分别为 96 和 72 字节；其他身份字段未算入。假设每轮按每个表项支付 α 微秒准备成本，复制有效带宽 β=1 TiB/s，β 按“读＋写总字节/时间”定义，复制与准备串行，其余共同时间记为 T共同，则 T₄=T共同＋7α＋11τ/β，T₈=T共同＋4α＋27τ/β。这里没有声称每项真实准备都线性或 β 能直接达到。

两者差 T₄−T₈=3α−16τ/β，16τ/β≈1.90735 微秒。α=0.8 微秒时新增项分别约 6.91130 和 6.41865 微秒，P=8 较小；将准备缓存或其他优化使 α=0.1，分别约 2.01130 和 3.61865，P=4 反而较小。测得 α 后还要检查假设：准备和复制已重叠、输入 kernel 时间随 P 改变，或独占尾页选择原地追加时，本式都要重算。

若可供这三条请求当前页和暂存页的预算仅 6 MiB，P=8 的“同时准备三条追加”方案不合法，即使上述时间较短；可以改为分批准备、采用另一尾页写入方案或拒绝本轮工作，再重新算时间和峰值。容量不足不是把一个失败方案的延迟记成更大数值。P 增大还可能减少表项、改善一次搬运，但使分叉复制和尾部浪费增加；这组条件而非固定页长决定保留、调整或放弃。

## 连续虚拟地址是另一种取址选择

应用页表、整请求连续预留、连续虚拟地址加按需物理 backing 解决的是相关但不同的问题。[vAttention v1](../sources/S-VATTENTION.md) 保留 kernel 所见连续虚拟地址，把物理映射推迟到需求出现；分页 kernel 则显式处理应用块表。应用 token 页长 P 不能等同于平台按字节规定的映射粒度。

按需映射的粗略容量需按每个 K/V 虚拟区域分别向映射粒度 G 向上取整，再对所有区域求和；如果各层/各 head 的缓存分配分开，不能把全层总字节只取整一次。预留虚拟范围的大小也不等于已提交物理显存。映射调用、访问权限设置、页表/TLB 行为、预测预映射和延迟回收进入不同成本项。固定 v1 的小粒度依赖驱动扩展，不能视为任意设备的既定能力。

若待用映射总在前一轮结束前完成，后台映射可隐藏关键路径时间，但容量峰值和主机开销仍在；若短轮次或一次跨过多个粒度使映射来不及，则当前轮必须等待或走可说明的替代路径。比较两种取址方法应固定语义、布局和工作负载，分别计 kernel、CPU 准备、映射、峰值与共享能力，不能拿不同 kernel 的一次端到端差异归因给“分页”一个因素。

## 区分容量收益、间接寻址和生命周期错误

设观察到“小页快、大页慢”，至少有四种解释：大页尾浪费降低可准入 batch；大页的实际访存布局/复用变差；复制/暂存交通增多；准备或图包更新的工作量发生变化。先固定已准入请求、有效 KV、query 和 kernel 数据流，测消费阶段；再独立固定消费者比较准备与复制；最后放开准入，比较端到端 SLO 和拒绝。若只在放开准入后出现差距，容量解释获得支持，但不能据此证明 kernel 更快。

例如设某轨迹 P=8 比 P=4 慢 8 微秒。将有效请求集固定后，差距缩至 1 微秒，同时页池峰值下降能容纳更多请求，支持“主要差距由准入/等待引起”；若固定请求集后差距仍大，关闭 COW 而使用已准备只读页又使差距消失，才应转查复制与发布。对照也改变布局、数值策略或有效 query 时，不能单独归因。这里是诊断例，不是本库实测结果。

错误仅在取消或页面回绕后出现时，则竞争解释不同：地址公式/布局错误通常在固定页面的稠密读取就可重现；越过有效长度会随尾部 poison 和长度改变；早回收会对完成事件延迟和空闲槽复用敏感；错请求结果会随批次压紧/请求代次变化。可分别固定页号、填充无效位置、延迟一个读者、让完成顺序反转，并保存每次快照的长度、映射和实际数据参考。不能把所有随机错误都称为“异步问题”。

验证的独立参考从每条请求的逻辑 token K/V 构造稠密数组，不读取页表来定义期望值；NHD/HND、任意物理页置换后都必须重建同一数组，并在同一数学/数值契约下得到 attention 结果。边界覆盖 L=0、整页、非整页、q 跨多页、容量不足、追加失败、共享尾页分叉、旧快照在途、取消和重复/迟到完成。CPU 字节与票据模型可反驳错误公式和次序，真实设备的内存可见性、并发安全与性能仍需在所用实现中验证。
