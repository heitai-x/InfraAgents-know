# K-SYS-013：分布式 KV 存储：目录、有效副本与可恢复状态

分布式缓存把状态保存位置与计算实例分开，使多个实例能够重用前缀。一次目录命中只说明找到了候选对象；版本匹配、完整范围、存活副本、读取成本和目标恢复能力仍要逐项确认。

## 对象身份与目录分开

缓存身份包含影响状态的模型/权重/adapter、规范化输入、位置规则、状态几何和表示策略。分块身份还要包含父前缀依赖，避免把不同上下文中的相同 token 块当成同一状态。目录保存对象到位置、副本与生命周期的映射，不应把远端地址或槽号直接用作内容身份。

目录可以按 token 前缀、块链或其他依赖索引查找；物理位置可能是 GPU、DRAM 或 SSD。一个节点上的状态完整，不意味着其他节点可以按相同布局直接读取；不同 TP/PP、分页和量化格式可能需要转换。混合状态模型还需要所有状态族在同一恢复位置可用。

[Mooncake v1](../sources/S-MOONCAKE.md) §3–5 给出共享 KV 池、链式块身份、传输组件和缓存感知调度的组织实例。它提供设计分支，不能替本项目证明任意缓存对象都可跨实例互换。

## 发布完整副本，再允许消费者使用

目的端先预留容量，将到达范围记为未提交；完成读取、转换及必要可见性后，才发布可消费副本。目录可以先登记正在构建的位置用于合并同类请求，但读者必须知道它尚未就绪，不能把它当作命中后可立即执行。

不可变前缀可有多个相同副本；可变尾块必须封闭版本或采用明确的更新协议。淘汰先阻止新引用，再等待在途读取与引用结束，最后释放物理位置。目录中的旧记录可能仍被迟到请求使用，因此位置代次与实际内容检查不能省略。

| 故障或竞争 | 可保持的语义 |
|---|---|
| 目录说存在但源已失效 | 将该位置视为不可读，选择其他副本或合法重算 |
| 一部分块到达后失败 | 保留未提交范围或撤销预留，不发布完整恢复点 |
| 同一前缀同时构建 | 可以合并等待，也可产生等价副本；容量与引用分别结算 |
| 模型版本改变 | 新旧身份分开，旧副本按旧读者生命周期回收 |
| 淘汰与读取交错 | 已取得访问权的读者仍受保护；新读者重新查找 |

缓存丢失通常可以通过重新计算恢复，但输出提交、请求随机状态或其他不可重建信息不能因为名称叫缓存就一并丢弃。控制平面重建目录，也不代表已恢复在途请求的业务状态。

## 本地命中、远端命中和重算

本地命中要计索引与映射，远端命中增加目录往返、源排队、传输、转换和目标容量等待；重算则支付剩余前缀执行。三者比较同一模型与输入语义，不能将任意文档单独计算的 KV 直接拼成新上下文。

设定对象 512 MiB，远端有效带宽 20 GiB/s，传输下界 25 ms，目录/排队/转换另需 15 ms。若重算为 30 ms，远端“命中”反而慢；若重算为 180 ms，则有潜在收益。[KV 压缩](../algorithms/kv-compression.md) 可进一步改变传输量，但需要编码身份、解码容量和质量条件。

负载维度也重要：到达率 λ、远端命中比例 h、每次实际读取 D，则平均网络需求约 λhD，副本复制、写入和重试另计。多个实例争用同一缓存节点/NIC 时，单次读取带宽不可直接沿用；目录查询本身也可能成为热点。

## 副本、热点和缓存预算

复制热门前缀可以分散读取和路由负载，却增加存储、后台网络与失效管理；逐出冷前缀又可能增加未来 prefill。可比较固定副本数、按读取压力增减、按预测收益放置和仅按请求拉取。缓存命中率、命中 token 数和真正避免的关键路径时间分别度量不同收益。

缓存池应保留服务状态与在途目的空间的余量。若所有容量都装满只读副本，新请求可能没有地方接收自己的状态。共享基础设施还需按模型、租户和权限命名空间定义可复用边界，不能让全局哈希替代隔离规则。

## 验证与选择反转

使用同一到达轨迹比较仅本地缓存、共享远端池和直接重算，扫描前缀重用距离、对象大小、冷热分布与源节点压力。验证旧目录、损坏范围、部分到达、源退出和重复请求的状态不变量，记录失效重算与资源释放。

长而昂贵、重复访问的前缀更有机会受益；短前缀、弱互联、高目录压力或热点排队可能更适合本地重算。分布式缓存的价值由这些条件和 SLO 共同决定，不能由池容量或命中率单独证明。
