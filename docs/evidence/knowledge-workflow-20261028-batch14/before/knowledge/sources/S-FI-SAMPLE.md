## 分布、行映射与随机流

按行采样需要明确每个输出对应哪一行分布；归档允许用索引将多个输出映射到同一概率行，以避免重复存储。相同分布可以产生多个样本，不能把“复用概率行”误作“复用同一个随机结果”。输入概率与 logits 的处理路径也不同。

语义参考可以先将合法 logits 变成分布，应用截断并归一化，再按随机数在累计质量中选择类别。归档的融合 GPU 路径描述为无需显式排序的拒绝采样；Python 包装文件不足以证明其全部设备内循环，因此下面的逻辑是分布定义，不冒充设备源码。

```pseudocode
为每个输出确定概率行和该请求的截断条件
按明确顺序建立合法类别集合，去掉被屏蔽质量并归一化
从该请求的随机流取得随机状态，按目标分布生成类别
回传到对应请求/位置，并按实际随机数消费推进随机状态
```

## 截断顺序是语义

归档区分先 top-k 再 top-p 与联合处理。二者不能仅按名字视为等价。设原分布 [0.5,0.3,0.2]、k=2、p=0.6：先截 top-k 并归一化为 [0.625,0.375]，再取 top-p 时首类已够 0.6；若 top-p 的质量阈值在原分布上定义，则需前两类，再与 top-k 相交仍保留两类。这说明参考算法必须写明阈值使用哪份归一化分布。

显式随机种子与偏移由调用方维护，重复传入同一状态不会自动产生新的随机流。确定性实现标志也不表示每次采样都应产生同一个类别；比较需要固定输入、映射和随机状态。独立请求的流随 batch 重排是否保持身份，是设计与验证条件，见[批量采样](../algorithms/batched-sampling.md)与[结构化输出](../algorithms/structured-output.md)。
