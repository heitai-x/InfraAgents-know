# K-TOOLS-002：时间线分析：从请求路径定位执行瓶颈

时间线分析解释一个具体请求为什么在某个时刻还没有完成。累计时间最长的名字只是候选：一个长 kernel 可能同时服务多个请求，一个长 host API 可能正在等待此前提交的设备工作。归因需要连接事件身份、完成条件、依赖、资源覆盖与观测缺口，再提出能够被反驳的预测。

## 事件对象、时间与请求归属

设目标请求为 r，观测窗口为 W=[W0,W1)，请求完成事件为 F_r。必须先声明完成语义：设备计算结束、结果对主机可读、应用消费和输出提交可以是四个不同事件。以相同起点比较不同完成边界，会得到不可比较的延迟。

事件记录至少包含类型、时间域、单位、运行、进程、线程、设备、context、stream 或队列作用域，以及逻辑对象、执行尝试、对象代次和物理实例身份。时间对象分为发生点 Point(t) 和持续区间 Span(s,e)。点在窗口内的条件为 W0≤t<W1；区间采用半开形式 [s,e)，正长度活动要求 s<e。

零长半开集合 [t,t) 本身为空。若导出 schema 明确以相等端点表示一次发生，可以规范化为发生点，持续时间账仍为零；若相等来自舍入，只能说明没有可分辨的持续时间。没有相应 schema 时保留几何未决，不能凭空制造点事件或以删除该行证明没有执行。逆向、非有限或单位不明的端点应拒绝或保留未决，不能先裁剪掩盖错误。

| 对象 | 可以说明 | 不能自动替代 |
|---|---|---|
| 请求身份 | 输入、分支、输出和业务完成归属 | batch 或 kernel 名 |
| 批次身份 | 某次共同执行服务的请求集合 | 单请求独占工作 |
| 提交实例 | 一次 API 调用或入队 | 设备已经开始执行 |
| 设备实例 | 一次 kernel、复制或传输 | 另一次同名执行 |
| 完成证据 | 指定操作或范围已经完成 | 应用已经消费、输出已经提交 |
| 发现事件 | 查询、CQE 取回或回调处理 | 物理完成时刻 |

请求、批次、提交和设备工作通常是多对多关系。令 B⊆Request×Batch、P⊆Batch×Submit、E⊆Submit×Dispatch，则请求 r 与工作 k 相关，当且仅当存在 b、a，使 (r,b)∈B、(b,a)∈P、(a,k)∈E。一个共享 kernel 可以属于多个请求，但其物理执行只有一次。

恢复这些关系不等于恢复了完整因果图。R1 等待同批 R2 的输入准备，或者等待其他请求释放 workspace 时，决定 R1 完成的路径可以经过其他请求的工作。只投影出“属于 R1 的 kernel”再求最长路径，会漏掉这些前驱。

## 关联、时钟与覆盖的合法条件

精确关联要求字段语义已核验、键在相应作用域与代次内唯一，并且逻辑范围与物理范围相容。下面使用一个字段齐全的保守模型：提交键为 q=(run,pid,device,queue,correlation,generation)，一个提交可以产生多个 dispatch。它是检查模型的选择，不是所有工具都提供的固定 schema。API 未携带队列时，应使用该工具明确支持的关联关系，不能填默认队列伪造完整键。

```pseudocode
算法 Associate(submits, dispatches, schema)
输入：提交与设备实例；已核验的关联字段语义
输出：精确边 E、候选边 C、未决集合 U 及原因

检查提交和 dispatch 各自的实例身份唯一
按 schema 规范化关联键；保留原字段与缺失标记
为每个完整提交键保存全部匹配提交，不任意消除歧义
E=空；C=空；U=空
for 每个 dispatch k:
    若关联字段缺失：把 k 加入 U，记录缺字段
    否则查找同作用域完整键：
        恰有一个提交：建立精确边，保留一对多关系
        无提交：把 k 加入 U，记录无同域匹配
        多个提交：把 k 加入 U，记录键歧义
    对未决实例，仅在时间、字段和顺序允许时生成候选
    候选不能删除未决状态或自动升级成精确边
检查精确匹配的实例与 U 不相交，且并集等于全部 dispatch
组合已核验的请求—批次—提交关系，输出逻辑归属
```

缺失字段使用明确标记；若契约允许 0 或空字符串作为 ID，它们仍是有效值。相同 correlation 出现在另一队列而没有匹配提交时，该 dispatch 留在未决集合。时间最近、同名或父范围包含只能提供候选。父 span 包含子 span 也不表示父完成先于子开始。

物理实例去重同样需要冲突检查。同一完整物理身份、同一端点及负载的重复导出只计一次；同键但端点、设备或负载冲突应报告身份冲突，不能任意保留第一条。不同物理身份即使区间完全相同，也仍是两项工作。

跨域时间相减另需校准。设同一物理时刻满足 t_B=t_A+δ，当前窗口 δ∈[δ_lo,δ_hi]，A 发送读数为 a，B 接收读数为 b，则经过时间属于：

T∈[b−a−δ_hi, b−a−δ_lo]∩[0,∞)。

非负约束来自发送先于接收。交集为空说明身份、校准或事件语义不相容，不能把负上界裁成零。若 a=10、b=15、δ∈[−2,4]，只能得到 T∈[1,7]，图上的差值 5 不能支持精确单向延迟。校准后经过 h 时间，相对漂移率有界为 ρ 时，偏移界向两侧各放宽 ρh，并计入时间戳误差。OTel 上下文传播连接操作，不提供时钟校准或链路对称性。

因果边来自生产消费、经过核验的 stream 顺序、event 等候、资源移交或屏障；较早时间戳本身不是因果边。还应分别保留不支持、未启用、作用域外、窗口外、缓冲丢失、导出缺表、查询过滤和身份未决。缺表、空表或无法关联都不能直接写成零成本。

## 累计、覆盖与并发的区间账

对已限定资源作用域、统一时间和单位、按物理身份去重的正持续区间，定义：

S=Σ_i(e_i−s_i)，U=|∪_i[s_i,e_i)|，K=max_t |{i:s_i≤t<e_i}|。

S 是累计时间，U 是至少一项所选活动覆盖的时间，K 是最大活动并发数。令 C(t) 为活动数，则 S=∫C(t)dt、U=∫1[C(t)>0]dt，因此 U≤S≤KU。空输入三者均为零。

```pseudocode
算法 IntervalLedger(raw, W)
输入：已统一作用域和时间单位的 (start,end,physical_id)；窗口 W
前提：零持续时间记录已按 schema 规范化为发生点
输出：累计 S、并集 U、并发 K、规范合并区间、点数

检查 W0、W1 有限且 W0<=W1
seen=空映射；work=空；points=0
for 每条原始记录 (s,e,id):
    检查身份有效、端点有限且 s<=e
    若 seen 已有 id：
        若原始端点或已核验负载冲突，拒绝
        否则跳过相同实例的重复导出
    保存原始描述到 seen
    若记录为规范化发生点：
        若 W0<=s<W1，points 加一
        继续
    a=max(s,W0)；b=min(e,W1)
    若 a<b，把 [a,b) 加入 work
S=work 中各长度之和
按 (开始,结束) 排序；merged=空
for [a,b) in work:
    若 merged 非空且 a<=最后一段结束：
        最后一段结束=max(原结束,b)
    否则追加 [a,b)
为每段建立 (a,+1)、(b,-1)
按 (时间,增量) 排序，同刻先结束再开始
active=0；K=0
for 每个端点:
    active 加上增量；检查 active>=0
    K=max(K,active)
检查最终 active==0
U=merged 各段长度之和
返回 S、U、K、merged、points
```

合并不变量是 merged 表示已处理区间的并集，段之间既不重叠也不相邻。[0,10)、[5,15) 给出 S=20、U=15、K=2；[0,10)、[10,20) 给出 S=20、U=20、K=1。相邻半开区间可以合并，却不能在共同端点制造并发。窗口裁剪前必须检查原始区间，即使逆向区间落在窗口外也应拒绝。

排序和扫描为 O(n log n) 时间、O(n) 空间。只求并集且开始已排序时可以线性扫描；最大并发仍需要正确的结束次序。U 只表示选定活动的时间覆盖：复制覆盖不证明 SM 忙碌，多个 stream 区间重叠不证明每项工作都获得完整设备吞吐。不同设备的累计时间也不能直接成为整机墙钟。

## 带释放时间的关键路径与独立参考

建立有限有向图 G=(V,E)。节点 v 的持续时间下界为 d_v≥0，释放时间下界为 r_v≥0。边 u→v 的长度 l_uv≥0 表示 u 完成后至少经过 l_uv，v 才能开始。时间单位统一，共同起点位于所有释放之前。连接开始点、部分范围完成或外部输入的关系应拆成事件节点，不能强行解释为整个 API 或 kernel 的完成边。

最早完成递推为：

ES_v=max(r_v, max_(u→v)(EF_u+l_uv))，EF_v=ES_v+d_v。

没有前驱时只保留 r_v。已有前驱的内部节点也受自身释放约束。设 d_0=2、r_0=0，d_1=3、r_1=10，边 0→1 的 lag 为 4。前驱只要求节点 1 在 6 开始，但释放约束要求 10，因此 EF_1=13。

```pseudocode
算法 EarliestCompletion(V,d,r,E,target)
输入：有限节点；非负有限持续时间、释放时间与边长度；可选目标
输出：ES、EF、目标完成下界和达到该下界的约束路径；或拒绝原因

检查节点身份、数值、边端点和目标身份
本算法拒绝重复有序节点对；有意合并时须先声明边的语义
建立 pred、succ、入度；零入度节点入 FIFO 队列
order=空
while 队列非空:
    取出 u，加入 order
    for v in succ[u]:
        入度[v]减一；变为零时入队
若 order 未包含全部节点，拒绝环
空图无目标时返回完成 0、空路径；有目标时拒绝
for v in order:
    ES[v]=r[v]；parent[v]=空
    for (u,v,l) in pred[v]:
        若 EF[u]+l>ES[v]:
            ES[v]=EF[u]+l；parent[v]=u
    EF[v]=ES[v]+d[v]
end=指定目标，或 EF 最大的节点
从 end 沿 parent 回溯到空，再反转得到 path
score=r[path 首节点]+路径节点持续时间之和+路径边长度之和
检查 score==EF[end]
返回 ES、EF、EF[end]、path
```

拓扑处理 v 时全部前驱 EF 已确定，取最大值同时满足释放和全部前驱约束；任何更早开始都违反至少一项约束。由此逐节点得到无额外资源限制时的最早完成。FIFO 拓扑遍历、递推和回溯为 O(|V|+|E|) 时间，图与状态占 O(|V|+|E|) 空间，不依赖节点标签的数值顺序。

释放约束主导内部节点时，回溯路径可以从内部节点开始。更完整的路径定义是：对任意结束于目标 t 的非空有向路径 p，分数为 r_first+Σd+Σl；EF_t 等于这些路径分数的最大值。等价地，增加虚拟起点，以长度 r_v 的边连接每个节点。

这也决定了独立参考的正确范围。旧检查的参考器只枚举从原图根出发的路径，最小算例只得到 0+2+4+3=9，漏掉单节点路径 [1] 的 10+3=13。主算法保留内部释放是正确的，修复应让枚举从每个节点开始，不能为了迎合旧参考而删除主算法的 r_v。修订后的检查同时验证旧参考确实返回 9、新参考及递推返回 13。

固定算例之外，还需让随机 DAG 的内部节点具有非零释放、节点标签与拓扑次序不同，并逐目标比较。参考器直接枚举所有路径，不调用最早完成递推；其路径数可能指数增长，因此只用于小图检查。

这套模型没有自动求解共享 SM、复制引擎、内存带宽或链路容量的调度。若一个已知 FIFO 资源必须串行服务，可增加资源顺序边；若只知道容量有限但顺序未知，需要另建调度模型。把实测间隙全部写成固定释放可以重建旧轨迹，却不保证优化后这些释放不变。反事实必须区分外部固定释放与随前驱变化的等待，重新计算后再验证。

多条等长路径也限制优化收益。只缩短其中一条，另一条仍可能决定目标；每次改变 d、r 或边都应重算，不能永久给某节点贴关键标签。

## 共享工作、阶段流水与条件化成本

共享工作的资源账与请求等待分开。对物理工作 p，持续时间 d_p，选择非负权重 w_(p,r) 且 Σ_r w_(p,r)=1，令 charged(p,r)=w_(p,r)d_p，资源分摊总和保持为 d_p。权重可按 token、字节或工作量选择，须说明规则；没有依据时保留未分摊共享时间。各请求都可以引用完整 d_p 解释自身等待，但不能把这些等待相加成物理执行时间。

预取收益还取决于缓冲何时可复用。设读取、H2D 复制、计算分别耗 10、4、6 个时间单位，三种引擎独立且顺序服务，无转换和其他竞争。使用两个主机 staging 槽和两个设备槽，主机槽到对应复制结束后释放，设备槽到计算结束后释放。

第一块读取 [0,10)、复制 [10,14)、计算 [14,20)；第二块读取 [10,20)、复制 [20,24)、计算 [24,30)。稳定周期为 10，n≥1 块完成时间为 20+(n−1)10。两个主机槽让第二次读取不必等待第一次复制释放槽。

若只有一个主机 staging 槽，第二块必须在 14 才开始读取，随后复制 [24,28)、计算 [28,34)，周期变为 14，完成时间为 20+(n−1)14。设备仍有双槽也不能消除读取与复制对同一主机槽的生命周期约束。若每槽 b 字节，这两个候选的槽容量分别为 4b 与 3b，原有池与池内槽不能重复相加。n=0 时无有效工作，但实际接口的准备成本另计。

可用图表达这些约束：每块 read→copy→compute，各引擎增加相邻块顺序边；H 个主机槽增加 copy_(i−H)→read_i，D 个设备槽增加 compute_(i−D)→copy_i。槽依赖来自最后使用结束，不能仅凭提交返回释放。固定阶段时间只是设定模型；实际 SSD、主存和 PCIe 共用上游时应重估服务时间与竞争。

令原始事件数 N、关联边数 L、覆盖段数 M。采用哈希去重与索引连接、比较排序时，预期处理时间为 O(N log N+M log M+L)，保留全部事件、映射和图需要 O(N+M+L) 条状态。逐对关联可能退化为平方量级；提前按名称聚合则失去实例与依赖，不能声称仍有相同归因能力。

| 成本 | 同一候选内需要列出的对象 |
|---|---|
| 计算 | 探针、shape/stack 采集、解析、排序、连接、区间扫描与图遍历 |
| 访存 | 事件负载及元数据、缓冲复制、导出文件、索引和查询结果 |
| 通信 | 多机 trace 汇聚、远程导出与控制消息；按实际共享链路计量 |
| 准备 | 域、权限、schema、窗口、时钟校准、请求与编译产物映射 |
| 同步 | 刷新、报告就绪、工具插入的等待，以及真实完成和消费依赖 |
| 驻留 | 未刷新缓冲、未闭合记录、索引、在途槽和诊断性引用保留 |

条目数复杂度不能代替字节预算。文件主项为 Σ_k N_k b_k，其中 b_k 包含对应类型记录与元数据；索引、临时导出和运行时缓冲另计。多次采集按各次实际事件量和运行成本相加，不能只给单次加一个固定 profiler 百分比。

设备覆盖 U、累计 S 与请求完成 F_r 是不同量。只有同一条串行依赖路径才能直接相加；共享资源还会改变可行重叠。D/B 在 B 为可信能力上界时是传输下界，用实测有效速率则是相应条件的理想估计，排队、握手、转换和重试仍需另计。详细采集可能改变并发、cache、clock 与驻留，未经验证不能把扰动当作可减掉的固定常数。

## 一条请求、批次、复制与消费的组合轨迹

下面是时间单位 τ 的设定轨迹，不是设备实测。R1 到达于 0，R2 到达于 1；全部时间已转换到同一坐标。

| 区间 | 事件与约束 |
|---|---|
| [0,2) | host h1 规范化 R1 |
| [1,3) | host h2 规范化 R2 |
| [3,4) | batch B 等待两个输入后形成并准备参数 |
| [4,5) | 提交复制及执行依赖 |
| [5,7) | copy engine 执行 H2D |
| [7,14) | stream s0 执行共享 kernel G |
| [14,17) | s0 执行 R1 的 P1 |
| [14,16) | R2 仍等待外部 workspace 可用 |
| [16,19) | s1 执行 R2 的 P2，要求 G 完成且 release=16 |
| [17,18) | 主机消费 R1 结果并提交输出 F1 |
| [19,20) | 主机消费 R2 结果并提交输出 F2 |

设备活动账为 H2D、G、P1、P2，S=2+7+3+3=15τ，U=14τ，K=2，重叠位于 [16,17)。等待 workspace 不作为设备正工作区间计入 S。stream 区间重叠不证明 SM 资源翻倍。

R1 的设备结果完成于 17，输出完成于 18，端到端延迟为 18−0=18τ。R2 的设备结果完成于 19，输出完成于 20，端到端延迟为 20−1=19τ。相同的设备覆盖 14τ 不能替代其中任一延迟。两个请求也不足以估计总体 p99。

R1 的最大约束路径实际经过 h2：R2 在 1 释放，规范化 2、批次 1、提交 1、复制 2、G 7、P1 3、消费 1，总计共同坐标 18。h1 虽属于 R1，却在 2 已完成；只保留 R1 自己的 host 事件会漏掉批次形成的制约。R2 的最大约束路径可从 P2 自身释放 16 开始，加 P2 3 和消费 1，得到 20。

G 的物理时长 7τ 按等权分摊，各请求计 3.5τ，总和仍为 7τ；两者逻辑上都等待 G，不能把 7+7 再记成设备工作。

反事实应写清释放语义：

- G 从 7 缩短到 5，外部 workspace 仍固定在 16 可用，则 F1=16、F2=20。共享计算改善并未缩短 R2 的完成。
- 若 workspace 由另一条随 G 同步提前的路径释放，明确把 release 从 16 改为 14，则 F1=16、F2=18。这个假设需要资源释放事件验证。
- 只把 P1 从 3 缩短为 1，保持其余条件，F1=16、F2=20；它改善 R1，不改变本轨迹的 R2 目标。

硬件映射中，host 完成输入、参数与提交，copy engine 执行 H2D，stream 顺序或覆盖复制完成的 event 建立 G 的依赖；G→P1 是 s0 内顺序，G→P2 是经过核验的跨 stream 关系，workspace 可用是另一项约束。主机消费还需要对应的完成和可访问性。抽象边不代表已经选择了正确的 CUDA 同步对象，实际作用域与记录点须在目标环境核验。

## 存储、RDMA 与状态停滞

一段加载或迁移至少经过请求创建、容量就绪、提交、派发、范围完成、目标可见、应用消费及输出提交。每项完成只解除其契约规定的责任。取消可能结束业务输出，却仍需结算在途 I/O、DMA 或设备读，不能在时间线中删除这些物理工作。

Linux 6.12 的 blk-mq 文档区分软件暂存与硬件派发队列，并明确完成顺序没有统一保证。文件调用还可能由页缓存满足，或拆分、合并成多个物理请求，因此系统调用不是磁盘服务区间。iomap 文档区分排队返回、部分完成、写回与持久性；应按对象、范围和代次累计完成，不能按提交次序猜测消费者已有完整输入。

RDMA 同样区分 WR 提交、CQE、完成通道事件与应用接管。固定 verbs 文档说明提交列表可以在首个可立即检测的失败处停止，已接受部分仍需结算；取回 CQE 会移除它；CQ overrun 后不能继续把 CQ 当作正常。错误完成也不能沿用成功时全部字段的含义。

一次性通知并非逐 CQE 计数。通知可能在 CQ 已被轮询清空后才处理，出现没有待取 CQE 的额外事件。成功完成与本地缓冲复用须按操作和 flags 解释，inline 发送还有例外；本地完成不证明远端应用已经消费，也不证明任意并发 GPU kernel 已取得所需可见性。

若全部已记录 kernel 完成而请求仍停住，应沿状态追踪缺少哪个后继：所需范围尚未齐全、完成尚未被发现、可见性尚未建立、消费者未获调度、授权尚未提交，或相关事件根本没有被采集。补相应事件可区分这些解释；继续只排序已完成 kernel 的累计时间不能解决停滞。

## 条件变化与区分实验

| 变化或观察 | 保留、调整与区分预测 |
|---|---|
| 单 stream 变多 stream | 保留生产完成和最后消费关系，放弃全局全序；重算各资源覆盖及目标图 |
| GPU 长空洞 | 主机供给、依赖等待与采集缺口竞争；补线程运行/阻塞、输入就绪、提交和完成事件。只有真实完成也提前，才支持供给改善 |
| API 变短但输出不变 | 支持等待位置转移；分别记录此前设备完成和消费，不据 API 返回声称服务加速 |
| 多 stream 不加速 | 核验依赖记录点，并比较合法并发与独立 workspace。去除多余约束后空洞变化支持依赖解释；只增排队则重查资源竞争 |
| 累计 kernel 时间超过墙钟 | 按物理身份去重、求并集，区分真实重叠、共享重复计费、祖先 inclusive 范围和时钟错误 |
| 低并发预取改善、高并发退化 | 保留读取及生命周期证据，重测物理字节、容量等待与共享链路。等待减少但驻留挤压其他请求时应降低深度或放弃预取 |
| CQE 早、应用推进晚 | 分别观察工作完成、通知处理、可见性和接管；转查后续状态，不直接归因链路带宽 |
| 跨机差值发生变化 | 同时保留偏移界和客户端本地经过时间；只有显示对齐变化支持时钟解释，界限过宽则保持未区分 |
| 采集窗口移动 | 保留跨边界事件、截断和在途项；不能仅按 API 是否在窗口内决定全部设备工作归属 |
| profiler 下出现收益 | 做采集开/关对照，核对批次、cache、clock 和驻留；最终在正常运行点确认适用范围 |
| 平台、文件系统或 NIC 改变 | 保留问题、身份、状态与单位，重核队列和完成契约，不复制旧 CUDA 或块队列常数 |

干预前写出可否定预测。例如减少历史复制应降低相同上下文下的复制字节增长；降低 host 调度开销应缩短准备间隙，单 kernel 算量未必变化。若总性能改善而预测没有出现，应修改机制解释，即使候选本身仍可保留。全设备同步使异常消失同时改变多项关系，不能唯一定位缺哪条边。

比较尾部时保留超时、失败和窗口结束仍未完成的请求；阶段均值之和不能解释请求 p99。重复层级、正常运行测量与统计不确定性见相关实验章节。

## 检查、修复与未测边界

配套文件为 `tools/check_k_tools_002_full.py`，使用 Python 标准库，确定性、离线、只读，不导入项目实现、不启动子进程、不访问网络或写文件。

区间参考按端点切成基本单元，用单元中点独立计数，再积分得到 S、U、K；主算法使用合并与端点扫描。关键路径参考从每个节点枚举全部有向路径，与拓扑递推逐目标比较。检查保留旧根路径参考作为故意错误版本，确认最小释放反例给出正确 13、错误 9。另有同刻先开始、累计冒充并集、漏内部释放、汇合只等最早前驱、只按 correlation 关联和共享全额重复计费等负对照。

脚本还检查冲突物理身份、裁剪、点边界、空窗口、分数端点、空图、环、非法边、乱序标签、关联未决分区、共享权重守恒、流水槽复用、组合轨迹与时钟区间。递推检查使用精确整数及有理数，避免把浮点求和顺序差异误判为路径错误。

本轮实际执行的是只读 JavaScript 对应有限模型：300 个随机区间案例、200 个随机 DAG 的 744 个目标节点、336 个时钟案例与独立参考一致；组合轨迹及所述错误对照也已核对。这不是交付 Python 文件的执行结果。当前工具没有 Python 执行能力，指定 Python 脚本仍需协调者在隔离环境执行并保存 stdout、stderr 与返回码，不能沿用上一轮失败或对应模型结果声称本轮 Python 已通过。

这些模型不执行 CUDA、DMA、Nsight Systems、块设备、RDMA 或真实服务，不证明真实时钟校准、无损失采集、设备可见性、资源调度、GPU/CPU 性能或 Agent 使用效果。任意实数精度、非恒定漂移、独立端点误差、工具 schema 解析、真实排队和观测扰动仍需目标环境证据。本文所有阶段时间与槽容量是设定推导。
