# K-ALG-010：交叉注意力缓存：固定源、独立几何与可见性

交叉注意力的 K/V 由源表示及该模块的投影决定。在这些依赖固定时，K/V 不随 decoder 步数改变，可以构建一次、多次读取。缓存消除重复源投影；每次调用的 query 投影、QKᵀ、softmax、PV 和输出投影仍然存在。源缓存可以共享，也不自动证明目标 self 状态可以共享或在源更新后继续。

## 对象、形状与共同函数

本章讨论推理态、无 attention dropout、可见分数有限的情况。设某个 cross 模块为 c，源表示 E∈R^{S×d_e}，有效源行集合为 V_s⊆{0,…,S−1}，每行另有模型使用的逻辑位置 π_s(j)。S 是缓存覆盖的源行槽数，S_v＝|V_s| 是有效行数，二者在含 padding 时不同。

第 t 次调用的投影前隐藏状态记为 X_t∈R^{n_q×d_d}；n_q 是本次 query 行数，既不是投影张量，也不是目标历史长度。定义：

- W_Qc∈R^{d_d×(H_q d_k)}，Q_flat,t＝X_t W_Qc∈R^{n_q×(H_q d_k)}；拆分后 Q_t∈R^{n_q×H_q×d_k}。
- W_Kc∈R^{d_e×(H_kv d_k)}，K_flat,c＝E W_Kc；拆分后 K_c∈R^{S×H_kv×d_k}。
- W_Vc∈R^{d_e×(H_kv d_v)}，V_flat,c＝E W_Vc；拆分后 V_c∈R^{S×H_kv×d_v}。
- query head h 使用模型规定的 KV head ρ(h)，其中 0≤ρ(h)<H_kv。均匀 GQA 可以令 ρ(h)＝⌊h/(H_q/H_kv)⌋，但不能把这个映射当作所有模型的定义。

本式省略投影 bias；实际存在时须加入，并纳入相应参数身份。源侧位置变换若被物化进 K/V，也属于构建函数。依赖目标位置的分数偏置在读取时计算，不能直接当作固定源张量写入缓存。

对 query 行 i、head h，当前合法源集合为 A_{t,i,h}⊆V_s。令

z_{i,j,h}＝Q_t[i,h]·K_c[j,ρ(h)]/√d_k＋b_c(i,h,π_s(j))，

p_{i,j,h}＝exp(z_{i,j,h})/Σ_{j′∈A_{t,i,h}}exp(z_{i,j′,h})，

U_t[i,h]＝Σ_{j∈A_{t,i,h}}p_{i,j,h}V_c[j,ρ(h)]。

逐 head 输出 U_t 的形状为 n_q×H_q×d_v。按规定 head 顺序拼接得到 Z_t∈R^{n_q×(H_q d_v)}。令 W_Oc∈R^{(H_q d_v)×d_o}，本章读取算法返回 Y_t＝Z_t W_Oc∈R^{n_q×d_o}。残差、归一化及门控由外层模型结构执行；直接与 X_t 相加需要 d_o＝d_d，不能由 attention 公式自行假定。

例如 n_q＝2、d_e＝3、d_d＝5、H_q＝4、H_kv＝2、d_k＝2、d_v＝3、d_o＝7 时，X_t 为 2×5，Q_flat,t 为 2×8，K/V 每源行分别有 4/6 个通道，U_t 为 2×4×3，Z_t 为 2×12，W_Oc 为 12×7，返回 Y_t 为 2×7。该配置能暴露重复 query 投影、仅返回一个 head，以及把 d_v 当作最终宽度的错误；它是接口核对设定，不对应某个 checkpoint。

不可见位置不进入 softmax 分母。空可见集合不具有非空 softmax 的归一化定义；只有模型明确允许并规定空行值时才能采用该约定。本章非空 query 遇到空可见集合返回 EMPTY_VISIBILITY。n_q＝0 则返回形状为 0×d_o 的空结果，不推进目标状态。

## 缓存身份、前驱与请求绑定

必须把“到哪里寻找前驱”和“这个缓存是否就是本次需要的对象”分开。

| 名称 | 绑定内容 | 用途 |
|---|---|---|
| lineage_id | 一个源演进分支的稳定谱系身份 | 缩小前驱候选范围；不能证明内容相同或允许共享 |
| source_key | 不可变源快照的内容身份、版本、processor/encoder 身份及配置、E 的数值表示、覆盖范围、有效性和逻辑位置 | 区分源快照；源更新后通常改变 |
| R_c | 模块/层 c、K/V 投影参数及 bias 和计算精度、源侧位置变换、head 几何与映射、布局/页长/stride、dtype、量化分组及对应 scale/zero-point 的解释和身份 | 固定该层 K/V 的函数及表示契约 |
| cache_id_c＝(source_key,c,R_c) | 完整源快照、层与表示 | 精确命中、发布和读取校验 |
| generation | 一次构建、分配或发布的执行代次 | 隔离迟到完成与物理槽复用；不是内容身份的替代物 |

source_key 中的内容身份必须来自不可变快照或经过验证的内容登记。URL、请求槽号、长度、版本整数都不能单独充当内容身份；仅给张量贴一个新标签也不能证明字节正确。实现可以用规范化描述与摘要表示这些字段，但必须定义摘要对应的内容及冲突处理。

源构建者为新快照记录 predecessor_source_key 和 predecessor_version。候选索引可以按 `(lineage_id, predecessor_version, c)` 查找，再核对候选的完整 predecessor_source_key。存在分支或多个物理表示时，不能挑“最新的同长度缓存”作为前驱。新快照的 source_key 不用于查找旧版本；它用于发布新对象和校验新请求。

前驱找到后仍需证明旧行稳定。本文选择的追加路径要求旧槽范围 0…S_old−1 保持原来的 E 值、有效性和逻辑位置，新槽只出现在其后；投影及 R_c 对旧行也不变。可以逐行比较规范化 E，或使用源生产者提供的、绑定这两个完整快照的不可变前缀证明。仅传入一个调用者任意设置的 `prefix_unchanged=true` 不足以完成证明。数值“接近”不是精确复用条件；允许近似复用时应另行定义误差和质量契约。

每个目标请求的 SourceView 保存已经接受的源快照、逐层期望 cache_id、可见性规则以及目标状态依赖的源版本。调度器从这个 SourceView 构造读取快照，不从传入的缓存对象反向生成期望身份。源切换时，SourceView 的更新与目标状态继续/重算决策一起提交，不能先改版本号、后补其他字段。合法共享的不同目标可以各自绑定完全相同的 cache_id；目标 token、长度和 mask 不必进入固定源 K/V 的内容身份，但仍属于各自的执行输入。

例如源 A、B 都是 version＝4、S＝100，几何、dtype 和布局完全相同，仍可能有不同 E。A 请求误拿 B 的缓存时，仅检查 version 与计划几何会通过；比较请求预先绑定的 cache_id 必须在任何 K/V 读取前拒绝它。反过来，两个目标分别用不同 X_t 和 A 读取同一源 A，是合法共享，输出一般不同。

缓存不变量是：每个合法逻辑行的 K、V、位置标签与表示元数据属于同一完整身份；每个消费槽都有已完成或受 ready 依赖保护的生产者；未发布的写入不被消费；已发布内容只读；读者和在途设备访问结束前物理页不回收。计划相容只证明能按相应几何执行，不能证明源内容正确。

## 固定复用与追加的合法边界

K_c、V_c 不含目标步 t，所以固定源的跨步复用合法。需要保持不变的是实际依赖闭包：相关 E 行，K/V 投影及 bias，物化到源缓存的变换，数值表示、量化尺度和解释方式，以及读取 head/位置的契约。若条件源中包含随目标步或扩散时间变化的调制，K/V 也可能变化，不能继续套用固定缓存结论。

可见集合或 query 改变可以保留 K/V 内容，但要重新计算分数、归一化和加权和。把旧 attention 输出当作新输出，需要另外证明 Q、可见集合、偏置和其他依赖全部相同，不属于本章的 K/V 缓存优化。

“源更长”不等于“旧表示稳定”。双向 encoder 在新增音频后可能重新解释旧帧，E_new[:S_old] 与 E_old 不同，此时必须重建。即使 E 稳定，跨新旧行重算的量化 scale、重新编号的位置或非逐行源变换，也可能使旧物理表示失效。

追加时，旧范围使用的 scale/zero-point 及分组解释须保持不变；新增行可以附加自己的元数据。若某量化组跨过追加边界，新增值导致该组 scale 改变，就不能直接复制旧编码再配新 scale。可选择在新独占缓冲中恢复并重新编码整个受影响组，或重建更大范围；这条路径必须为组内旧行重新产生数据。本章下面的直接复制追加路径只处理旧编码与解释均稳定的情况。

只追加源 K/V 不证明目标 self KV 可以继续。高层目标 self 状态可能已经依赖旧源；目标状态更新必须遵从模型和服务定义。将旧 token 在新源下强制 replay，只得到“保留这些 token”的条件状态，不证明完整新源重新生成时仍会选择这些 token。

## 构建、发布与读取算法

下面采用不可变版本与事务式发布。页共享是表示选择；没有稳定性证明时走全量重建，不能因缓存命中而省略合法性判断。所有已发布页均只读，包括末页尚未使用的空槽；追加不得借空槽绕过这一选择。

```pseudocode
ALGORITHM BuildCrossVersion(E, source_manifest, layer_contracts, registry)
输入：不可变 E[S,d_e]；源清单含 lineage_id、新 source_key、version、
      predecessor_source_key/version、有效性、逻辑位置；逐层 R_c
输出：完整新版本的逐层缓存清单，或 EMPTY_SOURCE、FAILED、CANCELLED

1. 校验源清单与 E 的形状、范围、有效性及内容登记相符。
   若没有有效源行，返回 EMPTY_SOURCE；非法元数据返回 FAILED。
2. 为本次构建分配不复用的 generation g；保存新完整身份集合。
3. 对每个所需层 c，先取得前驱并制定分配/生产计划：
       candidates ← registry[lineage_id, predecessor_version, c]
       old_c ← 从 candidates 中选择完整 source_key 等于 predecessor_source_key
               且可协调取得只读引用的已发布候选；没有则为空
       append_ok ← old_c 存在，前驱版本一致且早于新版本，S_new≥S_old
       append_ok ← append_ok 且旧范围的 E、有效性、逻辑位置保持不变
       append_ok ← append_ok 且旧行投影、固定变换和 R_c 的解释均不变
       append_ok ← append_ok 且量化组边界、旧编码及其 scale/zero-point 不变
       若 append_ok：
           待投影范围 ← [S_old,S_new) 中的有效源行
           若 S_new=S_old：新页表引用全部旧页，不产生尾页写入
           否则：
               新页表引用旧范围中的完整页，并为这些共享页取得新版本引用
               若 r=S_old mod P_c 非零：
                   a←floor(S_old/P_c)；old_tail←旧页表[a]
                   为逻辑页 a 分配独占 new_tail；不发布其未初始化内容
                   新页表[a]←new_tail
                   复制集合←{j | aP_c≤j<S_old 且 j 为旧有效行}
                   为 old_tail 登记复制读取责任，并持有到复制最后使用完成
               为其余新增逻辑页预留独占缓冲
           共享页的旧 ready 依赖加入新版本依赖集合
       否则：
           待投影范围 ← 全部有效源行；建立独立新页表
       预留本层全部所需容量；任一层预留失败则进入步骤 5
4. 所有层预留成功后，对每层安排实际生产：
       若有隔离尾页：
           将复制读取排在 old_tail 的 ready 依赖之后
           对复制集合的每个 j：
               从旧页复制该槽的全部 K/V heads 与通道到新页同一逻辑槽
               同时复制有效性、逻辑位置及解释这些编码必需的表示元数据
               块级 scale/zero-point 须复制覆盖该槽的完整必要描述
           记录 copy_done；复制源引用只在实际最后读取结束后释放
           将 copy_done 加入新版本 ready 依赖，并令后续尾页写入依赖它
       对待投影的每个有效行 j：
           K_j←E_j W_Kc；V_j←E_j W_Vc；按模型加入 bias
           仅执行属于源缓存的固定位置变换
           写入新版本拥有的槽、位置及完整表示元数据
           不写任何仍属于已发布版本的页
       记录新增投影、布局转换、元数据写入和传输的完成依赖
       无效槽保持不可消费；它们的残留值不构成有效 K/V
5. 若失败或取消：禁止发布新版本；保留旧版本及其读者。
   未提交工作立即撤销；已提交异步工作、复制源和目的缓冲排空后才释放。
   按新 cache_id 与 g 结算迟到结果，返回 FAILED 或 CANCELLED。
6. 全部所需层的生产覆盖和 ready 依赖齐备后，一致发布：
       每个有效槽的生产者为共享旧页、尾页复制或本次投影三者之一
       每层 C_c←(新 cache_id_c, 页表, 有效性, 逻辑位置, g, ready 依赖)
       版本清单进入 READY；不把部分新层与旧层拼成一个新清单
7. 将源前驱索引更新为包含新版本的条目。
   旧版本若不再接收新引用，进入 RETIRED；已有读者仍持有其快照。
8. 返回新版本清单。旧页只有在全部快照引用、复制读取及其他已提交访问
   都结束后才可回收；新版本共享的完整旧页继续受新版本引用保护。
```

第 6 步的 READY 表示消费者可以依据明确的完成依赖安全提交读取，不要求 host 先阻塞等待全部设备工作。尾页复制完成、写新增槽完成和发布是不同事件；仅提交复制或只等待新增投影，都不足以让新尾页可读。跨 stream 的可见性与原子发布由实际运行时实现；伪代码不替代设备内存语义。

对任意新版本有效行 j，生产覆盖可以逐项核对：完整旧页上的旧行由受保护的旧生产结果提供；被替换尾页内的旧行由复制提供；新增有效行由投影提供；重建路径的全部有效行由本次构建提供。页表改指新地址本身不会产生数据。

取 P＝2、S_old＝3、S_new＝5，旧页表为 [A,B]。B 的槽 0 保存 j＝2，槽 1 对旧快照无效。新页表为 [A,C,D]：C、D 是独占新页，A 只读共享。

| 顺序 | 生产和依赖 | 对消费者的意义 |
|---|---|---|
| 预留 | C、D 的空槽可以填 poison；旧 B 保持不变 | 未初始化值仍不属于有效缓存 |
| 复制 | 等 B 就绪，将 B[0] 的 K/V、位置及必要尺度复制到 C[0] | j＝2 在新地址上有生产者 |
| 复制完成 | 记录 copy_done；B 的复制读取责任在最后读取完成后结束 | 旧快照读者仍可继续保留 B |
| 新增投影 | copy_done 后写 C[1] 的 j＝3，并写 D[0] 的 j＝4 及各自元数据 | 新行不覆盖 B[1]，D[1] 仍无效 |
| 发布与读取 | 新版本依赖旧共享页就绪、copy_done 和新增写入完成 | 新读者读取 0…4，旧读者仍读取 [A,B] 的 0…2 |

若省略复制，C[0] 的 j＝2 留有 poison；即使新增 j＝3、4 完全正确，新快照仍错误。若改为写 B[1]，则违反已发布页只读的方案，也可能改动与旧槽共用的块级元数据。若只复制编码、不复制对应 scale/zero-point 或位置标签，读取的值或偏置仍可能错误。若旧长度恰好整页，追加从新页开始，没有旧尾槽需要复制；若长度不增长，也无须为只读版本复制尾页。

读取取得请求的固定 SourceView 快照和受保护缓存引用。新引用只从可获取的已发布版本取得；版本随后 RETIRED 不撤销已有引用，已有读者仍可读自己的旧快照。校验与引用取得必须协调，不能检查后被回收。

```pseudocode
ALGORITHM CrossAttentionRead(request_snapshot, c, X_t, cache_handle, plan)
输入：X_t[n_q,d_d]；请求预先绑定的 expected_cache_id_c；
      query 逻辑位置、可见性与偏置；W_Qc、W_Oc；缓存句柄和计划
输出：Y_t[n_q,d_o]，或 STALE_CACHE、INVALID_VIEW、EMPTY_VISIBILITY

1. 协调取得缓存只读引用，固定句柄及 generation。
   校验已发布资格、完整 cache_id 等于 expected_cache_id_c，
   且层 c、版本、R_c、页表有效范围与请求 SourceView 一致。
   再校验 plan 的几何、布局、dtype/scales、metadata 与本次视图相容。
   失败时不得读取 K/V 数据页，按统一结束路径释放责任并返回错误。
2. 校验 X_t、W_Qc、W_Oc 的形状及 head 映射；可见集合须为 V_s 的子集。
   若 n_q=0，返回空的 [0,d_o] 结果并结束引用。
   将消费者读取排在全部 ready 依赖之后，其中包括尾页复制完成。
3. Q_flat←X_t W_Qc                  # [n_q,H_q d_k]，只投影一次
   Q←按规定顺序拆 head              # [n_q,H_q,d_k]
4. 对每个 query 行 i、query head h：
       m←−∞；ell←0；u←零向量[d_v]；kvh←ρ(h)
       按 plan 遍历源块，每个合法逻辑源行恰好覆盖一次：
           J←本块中 j<S、j∈V_s 且 j∈A_{t,i,h} 的行
           若 J 为空，跳过；不读取尾页空槽
           按页表与 R_c 读取 J 的 K/V、位置及必要表示元数据
           按对应 scale/zero-point 恢复 K/V
           z_j←Q[i,h]·K[j,kvh]/√d_k＋b_c(i,h,π_s(j))，j∈J
           m_new←max(m,max_j z_j)
           alpha←0（若 ell=0），否则 exp(m−m_new)
           w_j←exp(z_j−m_new)
           u←alpha u＋Σ_j w_j V[j,kvh]
           ell←alpha ell＋Σ_j w_j；m←m_new
       若 ell=0，走统一结束路径返回 EMPTY_VISIBILITY，不发布部分输出
       U[i,h,:]←u/ell                 # 每个 head 宽 d_v
5. Z←ConcatHeads(U)                   # [n_q,H_q d_v]
   Y_t←Z W_Oc                        # [n_q,d_o]
6. 将完整输出交给本次请求的消费者；记录实际设备访问完成责任。
   所有退出路径均保留在途访问所需的引用，最后使用结束后释放。
   本算法不做残差/归一化，不修改源缓存，不推进目标 self KV。
```

在线归约的不变量是：处理过的合法集合 B 上，m＝max_B z，ell＝Σ_B exp(z−m)，u＝Σ_B exp(z−m)V。最大值变化时，旧 ell 与 u 同乘 exp(m_old−m_new)，所以最终 u/ell 等于全体合法源行上的 softmax 加权和。分块之间不能漏行或重复行；浮点归约顺序改变通常只承诺指定容差内相符，不承诺逐位相同。

## 分页、混批与运行计划

query 段长与源段长独立编码。例如请求 A 有一行 query、100 个源行，B 有三行 query、40 个源行。query 行偏移、源页索引区间和末页长度分别以 query 行、页索引数组位置、有效源槽计量。batch 压紧必须同时更新 query 输出归属和请求到 SourceView/源页表的映射。

页长 P 时，逻辑行 j 对应逻辑页 a＝⌊j/P⌋、页内槽 u＝j mod P，页表给出物理页 p。设元素宽 b 字节、K 页 stride 为 D_K 字节，没有额外页内 padding 时：

| 布局 | K[j,h,k] 的字节地址 |
|---|---|
| NHD | K_base＋p D_K＋b((u H_kv＋h)d_k＋k) |
| HND | K_base＋p D_K＋b((h P＋u)d_k＋k) |

V 使用自己的基址、stride 和 d_v。模型位置 π_s(j) 与物理页号无关。页表置换只改变放置，不改变结果；把 NHD 字节仅改名为 HND 不会完成转换。

具体取 P＝2、S＝5、逻辑到物理页表为 [2,0,1]，读取 j＝4、h＝1 时，a＝2、u＝0、p＝1。若 H_kv＝2、d_k＝2、d_v＝3、b＝2，紧密 K/V 页分别为 16/24 字节；NHD 中 K 通道 1 的页内偏移为 6 字节，V 通道 2 的偏移为 10 字节。最后一页只有 u＝0 有效，u＝1 即使存着旧数据也不读。这个地址模型说明逻辑到物理的完整取址，不规定某个 GPU kernel 的线程映射。

计划通常依赖几何、query 分段、页索引区间、末页长度、mask、dtype、backend 与 workspace 契约。同一源没有变化，batch 成员、query 段或 mask 改变仍可能使计划失效。语义相同的缓存内容可以被多个合法计划消费；计划复用与内容复用需要分别证明。量化布局转换还要移动对应 scale/zero-point；涉及完整复制时，要计入转换流量和两份副本同时存活的峰值。

## 计算、流量、通信与驻留成本

一次乘加记一个 MAC。令实际 cross 层数为 L，D_Kc＝H_kv,c d_k,c、D_Vc＝H_kv,c d_v,c。若只计算 S_v 个有效源行，完整构建的 dense 投影约为

M_build＝S_v Σ_c d_e(D_Kc＋D_Vc) MAC。

固定源被调用 R 次时，逐次重投影支付 R M_build，缓存支付一次。严格合法追加 ΔS_v 个有效行时，新增投影为 ΔS_v Σ_c d_e(D_Kc＋D_Vc)；旧行证明、尾页复制和发布另计。逐行比较旧 E 的证明读取可达 O(S_old d_e)，还可能需要保留旧 E；可信稳定块证明能改变这笔成本，但不能没有证明。

对第 c 层，设隔离尾页内需保留的旧有效行数为 r_v,c。相同元素宽 b 时，需要复制的 K/V 主体为 B_copy,c＝b r_v,c(D_Kc＋D_Vc)，再加位置、有效性和必要表示元数据。若源和目的在同一存储层，理想直接复制至少涉及这些有效字节的一次读取和一次写入，合计约 2B_copy,c；实际可能按整块、对齐或量化组搬运而更多。这不是新增投影，也不是整份旧缓存重打包。复制完成还增加生产到新增槽写入及发布的依赖；是否在关键路径上取决于实际重叠。

若长度增长且旧末页非整页，新版本分配页数为 ⌈S_new/P⌉−⌊S_old/P⌋，其中包含隔离尾页；旧完整页共享。整页边界追加不付尾页复制。P＝2、3→5 的单层例中，旧版本占 2 页，新版本引用 3 页，同时保留旧快照时唯一物理页合计 4 页：A、B、C、D。不能把两份页表的 2＋3＝5 页当物理容量，也不能只计最终新版本的 3 页而漏掉仍在用的 B。

每次调用仍有 Q 投影 n_q d_d H_q d_k 和输出投影 n_q H_q d_v d_o MAC。attention 的 QK/PV 主项为 Σ_{i,h}|A_{t,i,h}|(d_k＋d_v) MAC，softmax 另有 O(Σ|A|) 标量工作。所有 query 看完整有效源时，主项简化为 n_q H_q S_v(d_k＋d_v)。GQA 按 H_kv 存储，却仍有 H_q 组 query 输出；不能按 KV head 的减少比例直接缩减 query 算术。

若各元素统一 b 字节，紧密有效 K/V 主体为

B_cross,logical＝b S_v Σ_c(D_Kc＋D_Vc)。

物理分页需要按每个实际分配对象舍入。若 S 个槽含 padding、每层独立分配、无页内额外 padding，则主体近似 b Σ_c[⌈S/P_c⌉P_c(D_Kc＋D_Vc)]，再加尺度、页表、对齐等元数据。不能用有效逻辑容量代替真实驻留，也不能将 metadata 当作无单位的元素数直接乘 b。

条件设定 S＝S_v＝1000、d_e＝1024、L＝12、各层 K 和 V 总宽都为 1024、BF16：E 为 2,048,000 字节＝1.953125 MiB，cross K/V 为 49,152,000 字节＝46.875 MiB，主项是 E 的 24 倍。100 条不同源分别为 195.3125 MiB 的 E 或 4.57763671875 GiB 的 cross K/V。一次构建为 25,165,824,000 MAC；重复投影 100 次就是该项的 100 倍。这些是设定计算，不是设备测量。

源缓存命中仍要读取 K/V。若上述单请求每次调用都将完整各层 K/V 从 HBM 取回一次，100 次调用对应 4.57763671875 GiB 的主体流量；100 条不同源合计 457.763671875 GiB。这个结果以所设路径为条件：多个 query 或 heads 的重复加载可以增加事务，片上跨 query 复用和 cache 命中可以减少 HBM 访问；它不是所有实现都必须支付的 DRAM 下界。

encoder 与 decoder 分设备时，可以传 E、在 decoder 侧投影，也可以先投影再传全部 cross K/V。上述设定后者主体字节是前者的 24 倍；选择还取决于两侧算力、复用次数、链路和重叠。迁移路径需分别计源读取、链路传输、目标写入、布局转换以及后续消费，缓存容量不能代替整个通信路径。相同内容的只读副本可以各自有效，但目的副本完整并满足可见性前不能发布给消费者。

准备工作包括索引查找、内容/前缀证明、分配、页表复制、mask 打包、计划生成、布局与量化转换。同步工作包括源就绪、复制完成、跨设备完成依赖、发布以及最后使用的回收门控；host 提交返回不代表设备完成。关键路径应按依赖和共享资源计算，已经重叠的投影、复制、传输与计算不能无条件相加。

驻留峰值计入 E、cross K/V、目标 self KV、workspace、页表、证明材料、转换副本和在途 staging。共享物理页只计一次，但每个读者有自己的生命期。稳定追加可能临时同时保留旧尾页和新尾页；源重建会保留仍在读取的旧版本。encoder 领先时，排队中尚未解码的源产物同样占容量，因而准入应按产物 bytes 与等待范围约束。

比较缓存与只存 E 时，可先比较源投影节省 `(R−1)M_build`，再检查额外读取、准备、迁移和容量挤占。算术量不能直接兑换成时间；短源、短目标或仅使用一次的源，可能不能摊薄构建和管理成本。

## 条件变化与组合状态轨迹

| 条件变化 | 保留的关系 | 调整或放弃的部分 |
|---|---|---|
| 固定源的目标调用次数增加 | 源 K/V 内容与身份 | 源投影更易摊薄，但重复读取增长；重算放置和带宽账 |
| 多个目标读取同一源 | 只读共享 K/V 与唯一物理容量 | 分别保留目标 self 状态、mask、输出和读者责任 |
| 源短、只使用一次 | attention 数学与身份校验 | 可比较直接投影、逐层构建或只保存 E |
| 新源只增加稳定行 | 经证明不变的旧完整页 | 新身份、新页表与新增投影；非整页尾页复制旧有效槽及其解释，再写新增槽 |
| 新源改变旧 E、有效性或位置 | 旧快照仍服务其在途读者 | 放弃精确追加，重建新版本；重新判断目标状态 |
| 新增行改变尾部量化组尺度 | 源数值及有效性定义 | 不能直接复用旧编码；隔离并重新编码受影响组，或重建 |
| 只有 query 或可见集合改变 | 同一源 K/V | 重算当前分数、归一化与输出，必要时重做计划 |
| dtype、量化分组、投影或源变换改变 | 源快照身份 | 旧 R_c 不再匹配；生成并验证新表示 |
| 显存或链路受限 | 内容依赖与合法共享规则 | 比较 E-only、按层换入/投影、准入后构建；计入恢复延迟与峰值 |
| backend、batch 或图契约改变 | 固定源的数学对象 | 核对布局、metadata、workspace、地址与计划生命期，必要时转换或回退 |
| 源更新后继续旧目标 | 已发布源版本可供原读者使用 | 只有模型/服务定义允许时延续目标；否则重算规定范围 |

一条组合轨迹如下。源快照 v 完成编码，发布各层 cross 缓存；目标 A、B 分别绑定 v 并取得引用。v+1 到达，携带同一 lineage_id 与明确前驱 v 的完整身份。构建者通过前驱索引找到 v，比较旧 E、位置与 R_c；成立时共享旧完整页，隔离非整页尾页，复制旧有效槽和解释元数据，随后只投影新有效行。新版本的发布依赖同时覆盖这些生产路径。A 已在途的读取仍消费 v；B 下一次是否转向 v+1 由其目标状态规则决定，不能只把版本字段加一。

若 v+1 改变早期帧，则全量重建，旧 v 仍存活到读者结束。假设该设定需要完整新源语义，B 应从规定目标起点重算；保留旧 token replay 属于另一条有明确条件的服务路径。若 B 在尾页复制或投影中取消，禁止后续业务发布，但已经发出的复制、DMA、attention 和输出消费者仍须排空。复制源旧页的责任不能因业务取消而提前结束；目的页也不能在迟到写入结束前重新分配。旧代次迟到完成按原身份与 generation 清理，不能写入新请求槽。

容量也随分支改变：稳定追加增加新页、页表及可能的尾页副本；全量重建期间可能同时驻留两版完整 K/V。只看最终 v+1 的容量会漏掉过渡峰值。若预算容不下，选择等待旧读者、分层构建或重算放置，而不是提前回收仍在用的 v。

## 竞争解释、反例与检查范围

| 观察 | 竞争解释 | 区分实验与修正 |
|---|---|---|
| 同版本、同形状下结果串源 | 请求绑定错；仅按几何验缓存；页表归属错 | 用内容不同但 version、S、R_c 相同的两个源交叉传缓存，要求读取前拒绝；若被接受，先修完整身份校验 |
| 稳定增长仍总是全量投影 | 按新完整 key 查旧版本；前驱缺失；表示契约实际变化 | 记录谱系索引查询、完整前驱匹配、逐行证明及投影行数；相同契约的稳定前缀应走追加，改变旧行则重建 |
| 只有非整页追加后出错 | 新尾页漏复制旧槽；复制缺元数据；旧尾页被原地改写；发布漏等复制 | 固定 P＝2、3→5，让新页初始为 poison；检查 j＝2、复制元数据和旧页字节，分别删除复制、元数据或依赖；若 j＝3、4 对而 j＝2 错，优先查旧槽生产路径 |
| H_q＝1 正确，多头错误 | 重复 Q 投影；head 拼接顺序错；返回宽度错；ρ 错 | 使用 d_d、H_q d_k、H_q d_v、d_o 互不相等的配置，逐 head 标量参考核对到 W_O 后输出；定位首次形状或数值分歧 |
| 源更新后输出错误 | 非法追加；读取旧版本；目标 self 状态延续不合法；mask/位置错 | 固定目标输入，比较新源全量重建与追加；再固定 cross 结果比较目标重算；分别修源和目标依赖 |
| 非整页或长源错误 | 忽略末页长度；页表置换错；query 偏移当源偏移 | 独立逻辑稠密参考，置换物理页；令可见性谓词对尾槽也返回允许，并填 poison，确保忽略长度的变异实际被检测 |
| 换 mask 后结果没变 | 错复用旧输出；mask 未生效；选例不敏感 | 固定 Q/K/V，选择 values 不同的可见集合；独立参考先确认输出应改变，再检查待测实现 |
| 开缓存总时延不降 | 投影已省但读取增多；准备未摊薄；驻留降低并发 | 固定输入与准入分别计构建、准备、执行和流量，再放开容量准入；结果不支持时调整放置或 E-only 策略 |
| 取消或复用槽后偶发错 | 早回收；旧完成写新代次；workspace 并发覆盖 | 延迟读者或复制，反转完成顺序、复用槽；记录身份、代次与最后设备访问；CPU 次序模型不能替代设备可见性验证 |
| 低精度或布局转换漂移 | scale/zero-point 缺失；head/分组轴错；量化误差 | 同一源分别比较高精度、完整恢复尺度、故意缺尺度的路径；按组边界和极值定位，不能用形状相同证明等价 |

独立数值参考应直接从 E、X_t、投影权重和逻辑可见性构造完整 attention，不借待测页表定义期望值。前驱检查必须实际经过索引查询和旧行验证，不能把 old 对象及“稳定”布尔值直接作为证明。读取检查的期望身份必须从请求 SourceView 得到，不能复制待测 cache_id 作为答案。

尾页复制检查还需要观察真实的模型存储路径：新页初始为 poison，只从旧物理页复制保留槽，只对新增有效行投影；不能先拼接完整逻辑 K/V，再全量 pack，以免自动补好缺失的旧槽。应同时核对新快照、旧快照、旧页未改、完整页共享、尾页独占，以及复制完成进入发布依赖。旧快照正确但新快照的 j＝2 留 poison，能区分“漏复制”与“旧源投影本来就错”；两版同时变化则支持共享写入或旧页改写的解释。

随章 `tools/check_k_alg_010_full.py` 是确定、离线、只读的 Python 标准库 CPU 小矩阵模型。它直接维护物理页池、页表、页内位置和表示元数据。追加路径不保存稠密 K/V 副本，也不重新打包旧行；已发布页拒绝写入，完整页共享，尾页从 poison 开始复制旧有效槽，再写新增有效行。独立参考从完整 E/X 和权重逐标量计算，核对物理缓存及 attention 到 W_O 的结果。

检查包含 P＝2 的 3→5 轨迹、无增长、整页边界、页内追加、跨多页追加、有效性空洞、NHD/HND 和物理页置换；保留多头/GQA、前驱查询、真实前缀校验、请求身份、空源/query/可见性和大有限分数检查。漏旧槽复制和仅复制编码却漏位置/尺度的负对照必须实际失败；正确路径恢复后仍须通过。其他负对照覆盖错误前驱查询、忽略前缀变化、弱身份校验、head 输出宽度、head 映射、mask 和末页长度。

页内表示使用可精确恢复的仿射编码 `(code−zero_point)×scale`，采用二进制幂尺度且不舍入，仅用于检验编码与解释元数据一起搬运；它不是 BF16、INT8 或真实块量化精度实验。复制引用与 ready 依赖只作同步事件次序模型，页池不实现异步回收或并发分配器。本轮未执行该 Python 脚本；协调者须运行本轮完整脚本并保存真实结果。它不证明 GPU 内存可见性、异步发布/回收、多层事务、图捕获、真实事务、端到端性能或知识对 Agent 的使用效果。
