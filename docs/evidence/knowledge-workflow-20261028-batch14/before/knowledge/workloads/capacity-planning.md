# K-WORK-006：容量设计：驻留、服务率与阶段配比

容量设计把模型状态、阶段服务能力、到达过程以及设备、网络和主机资源放在同一张账上，选择实例数、并行组、批上限、驻留池与准入策略。需要分别回答：任意时刻是否放得下，长期需求是否供得上，请求是否能在质量和尾延迟约束内完成。一个平均 tokens/s 不能同时回答这三个问题。

## 问题、输入输出与状态

设请求类别为 k，逻辑到达率为 λ_k，单位请求/秒；重试放大为 a_k≥1，尝试流率为 λ_eff=Σ_k a_kλ_k。类别绑定模型、adapter、规范化输入、长度分布、前缀共享关系、到达过程、质量标准和完成边界。重试增加尝试及资源需求，不能同时增加原始逻辑任务的成功数。

将路径拆成阶段 s，例如主机预处理、prefill、状态传输和 decode。请求在资源 j 上的需求为 d_{k,s,j}，其单位可以是 CPU 秒、设备计算秒、链路字节或容量占用的字节·秒；不同单位不能直接相加。

| 对象 | 定义与边界 |
|---|---|
| M_d | 设备 d 可供本计划使用的物理字节，扣除不属于计划的运行时保留 |
| W_d、F_d、G_d | 权重、固定工作区、图与通信池等基线驻留；同一 backing 只计一次 |
| C_d(t) | 时刻 t 的唯一物理占用；不是累计分配字节 |
| C_peak、A_C | max_t C_d(t) 与 ∫C_d(t)dt，单位分别为 byte、byte·秒 |
| c_j | 匹配访问模式、dtype、shape、布局和竞争条件的资源能力 |
| r_s(config,W) | 一个指定配置实例在 workload W 和阶段延迟条件下可持续服务的请求率 |
| 物理页身份 | 设备、池、页号与分配代次；地址重用后属于另一分配 |
| 请求视图 | 已提交的逻辑位置到物理页映射及有效长度，不含未完成写入 |
| 访问责任 | 已接受操作对源、目的、暂存或注册范围的实际使用责任及其匹配完成条件 |

输入是模型状态描述、设备与拓扑、请求轨迹或分布、服务曲面、质量/SLO 和成本目标。输出为计划 P=(实例数与并行组、池大小、批上限、准入限制、缓存目标、热备与放置)，或不可行证书及尚需测量的参数。

计划的 DRAFT 状态只含假设；CHECKED 表示完成了声明范围内的检查；ACTIVE 才能接收流量。REPLANNING 期间旧计划仍负责已有请求，新计划在资源和状态准备完成后接收新请求；RETIRED 停止新准入并等待排空。新计划不能把旧计划已经占用、但尚未排空的容量再次出售。

业务终止与物理回收另行记录。请求可以已经 CANCELLED，但初始化、复制、NIC 或 kernel 仍然访问它的页；DRAINING 表示这些责任尚未结清，而不是 free 的另一种名称。

## 驻留约束：唯一副本与互斥容量账

标准稠密 K/V 的每 token 全层字节为

b_token=2·L_layers·H_kv·d_h·q。

L_layers 是层数，H_kv 是 KV head 数，d_h 是每 head 维度，q 是每元素字节。若一页包含 B 个 token 的全部这些状态，b_page=B·b_token。分层或分 head 的页应按相应身份分别计算；MLA、SSM、量化尺度和多模态状态应由各自描述符确定，不能机械套用标准 K/V 公式。模型并行后的每设备账也必须按实际分片、复制和元数据计算，不能无条件除以卡数。

令 Pages(i,t) 是请求 i 已提交视图对应的物理页集合，U(t)=∪_i Pages(i,t)。请求逻辑状态容量按 |U(t)| 计；同一页被多个请求引用只占一次，另一设备上的复制则是另一个物理对象。缓存保留、未发布页和在途访问还可能持有不在这个请求集合中的页，因此 |U(t)| 不是完整池占用。

本章采用预分配固定页池，池内每页恰属于以下一个容量类别。下文 L 专指 LIVE 页数，与层数 L_layers 分开。

| 类别 | 计数 | 语义 |
|---|---:|---|
| LIVE | L | 已提交的请求状态或仍被缓存保留的唯一物理页；在途读者不会另加一份容量 |
| GUARD | H | 已独占取得、尚未交给物理操作的未来推进页 |
| RESERVED | R | 当前事务的未发布页，包括初始化、尾页替换和状态接收目的页；可能已有实际访问 |
| DRAINING | D | 已撤销未来提交与发布资格、无其他逻辑持有，但仍有未结束或接受状态不明的实际访问 |
| FREE | F | 没有逻辑持有、未来使用与实际访问责任，可以重新分配 |

对每个设备与池始终保持

N_pool=L+H+R+D+F，且所有项非负、物理页集合两两不交。

DRAINING 是容量类别，不能又包含在 LIVE 或 RESERVED 中。一个仍被其他请求、快照或缓存持有的共享页继续属于 LIVE；取消一个所有者只减少该所有者的引用。只有最后逻辑持有结束时，才依据实际访问集合选择转 DRAINING 或 FREE。

guard 在这里是已经独占的物理页，不是尚未兑现的预算。请求尾页内的未填槽已包含在该 LIVE 页中，不再计成额外 guard；但“有未填槽”也不证明所选追加协议无需替换页。guard 被初始化或用于复制之前先转为 RESERVED；从这一刻起，其回收取决于真实访问责任，不能再按未使用 guard 立即释放。staging、COW 目的页和普通增长页按用途分别估算，再对物理页取并集，不能让同一页同时承担两个互斥用途。

启动时已分配整个池，设备驻留账计 N_pool·b_page，不能再把 LIVE、FREE 等池内项加一次。池外独立对象按实际持有区间计入。完整设备约束是

C_d(t)=W_d+F_d+G_d+请求池 backing+池外 staging(t)+池外 workspace(t)≤M_d−margin_d，

其中各项必须互不重叠。预分配池的设备驻留可能一直不变，但池内可再次准入的 F 仍在变化；这两个观察量应分开报告。

准入计算新增物理页时，先识别已经存在且可合法固定的共享页，再建立缺失状态、写副本和暂存的独立集合。若 Δfresh 是尚未计入写副本的缺失页数，Δcopy 是实际需要另建的写副本，h 是推进 guard，t 是同池额外暂存，则 need=Δfresh+Δcopy+h+t。若新映射的物理增量已经包含写副本，就不能再加 Δcopy。所有者必须在事务内重新验证命中、引用和 free，避免只读估算与实际预留之间的竞争。

特别要区分三个量：提交后存活页的净增量、提交前必须取得的目的页、旧页最后使用结束前的过渡占用。一次尾页替换可以使净增量为零，却仍需先取得一整页，且旧页排空延迟会延长双份占用。

剩余 16 GiB、平均状态 512 MiB 给出的 32 个请求只是平均估计。长度尾部、同时跨页、尾页替换、暂存和排空都会改变峰值；共享前缀又可能使逐请求求和高估容量。它们的误差方向不同，不能靠统一乘一个经验系数修补。

## 服务率与阶段配比

阶段服务时间应写成条件化曲面

T_s=T_s(模型版本、dtype、布局、shape、batch 组成、历史长度、缓存条件、并行组与放置)。

由相同 workload 和完成边界取得每实例可持续请求率 r_s。它不是理论峰值，也不因实例复制就自动保持不变；共享 CPU、链路和存储可能使每实例能力下降。解析下界与原型测量可以交替修正，未知参数不必等全部模型建立后才测量。

令 δ_k^P、δ_k^D、δ_k^T 分别表示类别 k 是否进入 prefill、decode 和传输阶段。混合类别可拆成路径不同的子类。则

λ_eff^P=Σ_k a_kλ_kδ_k^P，λ_eff^D=Σ_k a_kλ_kδ_k^D，λ_eff^T=Σ_k a_kλ_kδ_k^T，

n_P≥ceil(λ_eff^P/r_P)，n_D≥ceil(λ_eff^D/r_D)。

完整 KV 命中不一定能跳过取得首 token 所需的计算：没有末行 logits 或合法 token 票据时，可能仍需恢复末行。此时应把恢复工作放入对应服务曲面，不能仅凭 KV hit 将 δ_k^P 设为零。首 token 已为 EOS 或不再需要后续生成的请求可以不进入 decode，但已经接受的物理工作仍要排空。

对实际 decode 步数 m_k，另查 token 工作轴：Λ_D=Σ_k a_kλ_kE[m_k]≤n_D r_D^step。若首 token 在 prefill 产生，m_k 通常不等于完整输出 token 数；应按执行边界记录。请求率约束、步率约束和驻留约束须共同满足。

两池均有正需求、r_P 和 r_D 为正，并暂时忽略整数取整、余量与共享资源约束时，按需求恰好配置有

n_P/n_D≈(λ_eff^P/λ_eff^D)·(r_D/r_P)。

只有 λ_eff^P=λ_eff^D 时，才化简为 r_D/r_P。整数需求很小时，应直接比较 ceil 后的实例数。若 λ_eff^P=0、λ_eff^D>0，计算下界允许 n_P=0，比值为零；反向情形允许 n_D=0，不定义有限的 n_P/n_D；两者都为零时不定义 0/0。启动、恢复或热备实例另计。正需求配零能力表示不可行。

例如 λ_eff^P=1、λ_eff^D=4、r_P=r_D=1 请求/秒，恰好需要 1 与 4 个实例。省略流率比会错误地给出 1:1。部分请求跳过 prefill、复用历史或提前终止时，阶段流率必须随路径重新计算。

对共享资源 j，平均必要条件为

D_j=Σ_k a_kλ_kE[d_{k,j}]≤n_jc_j。

CPU 秒、设备计算秒和链路字节各用自己的轴；同一链路上的状态传输、模型并行、缓存填充和重试要合并。若请求需迁移 K 字节，则该项至少为 λ_eff^T E[K]。单链路只有 1.5 GiB/s 而需求为 2 GiB/s 时，增加 P/D 实例并不增加链路供给。

这些不等式可排除必要条件不满足的配置，不能证明尾延迟。利用率接近 1 时，方差和突发会产生积压；M/G/1 的平均等待公式只在 Poisson 到达、相应服务纪律和独立服务假设下使用。batch 组成改变服务时间、有限 KV 限制准入、会话与共享前缀引入相关性时，应转向轨迹评估。

## 合法条件与方案选择

| 合法条件 | 不成立时的动作 |
|---|---|
| 共享状态的模型、adapter、输入上下文、位置、mask 和数值表示一致 | 重算或执行有依据的转换；不能只按相同文本共享 |
| 所选不可变视图方案只向私有未发布页写入 | 预留目的页；容量不足时暂停，不能临时偷换为原地写入 |
| 初始化、接收、转换和消费者可见性完成后才发布 | 保持 RESERVED；提交返回不等于就绪 |
| 取消、发布、访问登记与回收由同一拥有者串行化或事务协调 | 先解决竞争，不能让取消检查与提交之间漏记责任 |
| 每次物理重用改变分配代次，完成事件匹配操作及分配身份 | 忽略旧/重复通知对新分配的修改；仍须单独证明旧物理访问已经结束 |
| 回收要求逻辑持有、未来使用和实际访问均已结束 | 保留 DRAINING；无法取得排空证据时隔离该范围 |
| 故障余量按主机、NIC、存储路径等共同故障域计算 | 不能把同主机多个实例当成独立冗余 |
| 降精度、缩短输出或改变模型符合任务质量合同 | 不符合时保留原语义路径，不把改任务记作容量提升 |

同置或分离、页长、批上限、缓存保留期、热备数量、副本或模型并行，以及排队、拒绝、换出或重算，都是有条件的选择。硬条件限定合法空间，不规定统一架构。优先级可以分配等待，不能创造总容量。

本章具体增长轨迹选择“已发布页不可变、部分尾页每次追加都替换”的可恢复基线。这比仅在共享引用大于一时 COW 更保守，是本章的方案选择，不是 PagedAttention 论文的普遍要求。允许原地追加的另一方案，需要独立证明读写范围不冲突、仅写未提交槽、有效长度发布顺序，以及部分失败后哪些字节可再次写入；它的容量和成本应另算。本章算例与检查不采用该路径。

## 从候选计划到事件推进

PLAN_CAPACITY 的候选估算只读。每个候选使用独立模拟状态，实际预留与发布全部由同一分配/事务拥有者执行；规划器不得在 TRY_ADMIT 成功后再次扣 free、再次提交或再次发布。运行时也采用同一责任划分。

```pseudocode
算法 PLAN_CAPACITY
输入：状态描述、设备与拓扑、workload W、服务曲面 S、质量/SLO、余量和成本目标
输出：条件成立的计划，或瓶颈证书及待测项

1 校验单位、身份、非负需求和能力；正需求配零能力标记不可行
2 按设备建立权重、固定区、各状态族、池外暂存及故障域的唯一物理账
3 固定 W 的到达模型、长度、路径、重试、共享关系、质量与完成边界
4 用服务曲面和资源必要条件裁剪候选，保留相邻整数配置
5 对每个候选创建独立空池及事件队列；共享缓存若预热，显式计入加载与驻留
6 按时间处理到达、完成、取消和 deadline；同时间事件遵守声明的排序
   a 到达：仅调用 TRY_ADMIT；它独占负责本次预留及后续提交/发布
   b QUEUE/REJECT：记录决定与重试；不得记成成功服务
   c 已就绪工作：按批和历史取匹配的阶段时间，登记实际访问后提交
   d P→D：由目标拥有者预留接收区和 guard；源、目的、暂存各自保持责任
      等完整状态、首 token 依赖及可见性成立后才启动目标 decode
   e 每次追加：调用 ADVANCE_GROWTH，包含部分尾页替换，不能只检查跨页
   f 正常结束、失败或取消：停止未来工作，通过 ABORT_OR_RETIRE 结算责任
   g 完成通知：仅解除匹配的操作责任；必要时触发发布、回收或队列重试
7 每次事件后核对各池 L+H+R+D+F=N_pool
   记录驻留、完整流量、队列、有效长度、阶段延迟及临时目的页需求
8 若等待但没有能释放资源的在途事件或合法抢占路径，报告不能推进
   不把无限等待当成可行计划
9 在独立 holdout 到达与长度轨迹上检验硬容量、质量和联合 SLO
10 在可行候选中比较总成本/合格请求、能量和故障余量
   记录扩缩容就绪时间、迟滞和未测服务曲面点
```

准入事务具有请求、尝试和分配代次，以及 eligible、私有页表、未来工作、逻辑引用和实际访问表。以下“提交”指操作被执行系统接受；“发布”指完整视图交给模型消费者。

```pseudocode
算法 TRY_ADMIT
输入：请求 r、计划 P、当前池状态
输出：QUEUE/REJECT，或持有容量的 PREPARING 事务；就绪事件可使其变为 ADMITTED

1 只读推导需要固定的已有页、新状态页、写副本、临时区和推进 guard
2 在池拥有者下重新验证身份、命中和旧视图；固定共享页引用
   若任一设备或资源不能取得完整预算，撤销本次新引用并返回 QUEUE/REJECT
3 原子地从 FREE 取得唯一一次容量：当前数据/暂存页转 RESERVED，未来推进页转 GUARD
   建立私有页表，eligible=true；外部消费者不能读取这个私有视图
4 对依赖已满足的初始化、复制或接收：
   在外部系统可接受操作之前，登记操作身份、源/目的/暂存保护和完成责任
   与取消协调地检查 eligible，再提交一次
   确定未接受：撤销对应实际责任；已接受：保留责任至匹配完成
   接受状态未知：保留保护并隔离，不推定其未执行
5 收集匹配完成；全部必需写入成功、身份检查与可见性成立且 eligible 仍真时：
   在同一拥有者下将当前数据页 RESERVED→LIVE，安装引用并发布完整视图
   GUARD 保持 GUARD；临时页仅在没有后续用途和访问后归还
   返回/通知 ADMITTED；无写入的合法全命中也走这次发布检查
6 任一失败、取消或 deadline：调用 ABORT_OR_RETIRE，不执行统一的 reserved 减 need
```

部分提交允许一部分 RESERVED 页已有物理责任，另一部分尚未使用；必须按实际页集合结算。共享源页的临时读保护不增加新容量，却延长该页的可回收时刻。

```pseudocode
算法 ABORT_OR_RETIRE(tx)
1 在拥有者下撤销 tx 的未来提交和业务发布资格；撤销待执行工作与未发布页表
2 区分三条路径：
   未提交撤销：取消未来用途；无实际责任且无其他引用的 RESERVED/GUARD→FREE
   已接受但未发布：撤销逻辑结果；有实际责任的 RESERVED→DRAINING
   已发布后终止：撤下本请求未来可执行视图并释放它的逻辑引用
     仍有其他请求/快照/缓存引用的页保持 LIVE
     最后逻辑引用结束且仍有实际责任的 LIVE→DRAINING
3 对上述各路径中无逻辑持有、无未来用途且无实际责任的页，从其当前类别转 FREE
   guard 若从未交给操作即可立即归还；已转 RESERVED 的页按其责任处理
4 继续处理已接受操作的完成；匹配身份后仅解除该操作涉及的实际责任
   某页全部责任结束且无其他持有：DRAINING→FREE，或回收事务临时页
5 旧代次和重复事件不得扣新分配；超时不代表完成
   接受状态未知或缺少终止证据的范围保持隔离并计入 D，不允许复用
```

这里先禁止未来提交，再结算旧访问；仅撤销发布资格不能阻止已经接受的 DMA。分配代次能防止迟到回调修改新元数据，也不能阻止旧 DMA 写坏同一地址，所以它不替代排空。

## 私有尾页追加、guard 与过渡峰值

增长以“下一轮实际会计算的状态”为边界，不以已经发送的 token 数代替已计算 KV 长度。以下展开固定页长 B、普通稠密 K/V、一次追加一个已知输入位置的算法。空状态也可以追加，但输入 token 必须已由上游合法提供。

设已提交长度为 n。n=0 或 n mod B=0 时，旧页均不改写，为新增逻辑页取得一个目的页。0<n mod B=u<B 时，为旧部分尾页取得一个替换页，复制其中 [0,u) 的有效状态，再写入槽 u。两条路径都先取得一页；前者发布后净增一页，后者在旧私有尾页最终释放后净增零页。多个请求同轮推进时，先对整个选中集合取得目的页，不能拿提交后预计释放的旧页支付提交前的预算。

```pseudocode
算法 ADVANCE_GROWTH(selected_requests)
输入：每请求已提交视图 (pages,n)、下一位置输入、现有 guard、池状态
输出：各请求的新视图，或没有提交该增长的 PAUSED/失败结果

1 在拥有者下固定每请求的旧视图版本；同一请求最多一个未结算追加事务
2 对每个请求：
   若 n=0 或 n mod B=0：计划新逻辑页，replace_old=空
   否则：计划私有替换页，replace_old=旧尾页，copy_valid=n mod B
   当前目的页计一页；另按实际算法加入池外/池内工作区与其他状态族预算
3 验证所有设备与资源预算；本次 guard 与 FREE 不足时，不改变任何视图
   返回 PAUSED；可缩小选中集合、等真实回收或使用合法抢占/换出/重算
   不得因 LIVE 净增量为零跳过目的页预留
4 原子取得全部目的页：本次使用的 GUARD→RESERVED，缺口 FREE→RESERVED
   旧页保持 LIVE；新页不进入可消费映射；有效长度保持 n
5 逐请求协调取消，按 TRY_ADMIT 登记实际责任后提交：
   部分尾页：复制旧尾页全部必要层的 [0,u) 有效状态到目的页
     复制成功且对后继可见后置 COPY_READY
   整页边界：没有旧尾页复制依赖，置 COPY_READY
   执行下述 PRODUCE_POSITION，在目的页槽 s=n mod B 逐层产生新位置 K/V
   旧页不接受本次写入；事务外消费者仍只使用旧映射和长度 n
6 等待 PRODUCE_POSITION 的 POSITION_READY；任一必需操作失败时：
   撤销该追加事务的未来提交与发布，不终止仍合法的旧视图
   新目的页按其实际责任转 DRAINING 或 FREE；旧映射和 n 保持不变
   已接受操作排空后才重试；未知接受状态保持保护
   若是整请求取消，则再按 ABORT_OR_RETIRE 撤销旧请求视图
7 在拥有者下复核旧视图版本及追加资格，发布新映射与 n+1：
   目的页 RESERVED→LIVE；新逻辑页追加到映射，或用新尾页替换旧尾页
   原子地使后续消费者取得新映射和新长度，不能混用两代字段
   解除旧尾页的本视图引用：
     其他请求/快照/缓存仍持有时保持 LIVE
     最后逻辑引用结束但仍有旧物理读者时 LIVE→DRAINING
     无逻辑持有、未来用途和实际责任时 LIVE→FREE
8 按下一次推进目标 h_target 补充 guard：
   h=max(0,h_target−当前 H_r)
   FREE≥h 时显式 FREE→GUARD；否则保留已经提交的新视图并标记保护不足
9 保护不足不自动撤销本次成功，也不授权下一次写入
   下次追加重新计算目的页与工作区预算；没有可推进事件时明确失败或重规划
```

这里的新位置状态由一次逐层前向产生。令 x_n 为位置 n 已知的合法输入 token；它可能来自 prompt，也可能是上一步确认的输出。首层输入 h_0 来自 x_n 的 embedding 及模型规定的输入处理，不能拿位置 n−1 的最终 hidden 直接替代。绝对位置 embedding 若由模型使用，则在规定位置加入；RoPE 等 Q/K 位置变换在对应投影后执行，不能重复加入。下面用常见的串行 pre-norm decoder 块具体展开；其他归一化、残差或 FFN 次序必须按 checkpoint 计算图替换，容量协议不授权改变模型函数。

```pseudocode
算法 PRODUCE_POSITION(r, old_view, n, x_n, destination, COPY_READY)
输入：受保护的逐层已提交历史 [0,n)、已知 token x_n、私有目的页及槽 s=n mod B
输出：POSITION_READY，或交给 ADVANCE_GROWTH 步骤 6 的失败

1 要求 COPY_READY；从 Embedding(x_n) 和规定的输入位置处理得到 h_0
   初始化每层 KV_READY[l]=false、H_READY[l]=false
2 对 l=1 到 L_layers：
   等待 h_(l−1) 的生产成功且对本层可见；l=1 时等待 h_0
   a_l=Norm_attn,l(h_(l−1))
   q_l=W_Q,l a_l，k_l=W_K,l a_l，v_l=W_V,l a_l
   按模型加入投影 bias，并对 Q/K 执行位置 n 的规定变换
   在接受写入前登记 destination 的本层槽 s 写责任
   将 k_l、v_l 写入该私有区域；成功且对本次 attention 可见后置 KV_READY[l]

   建立仅供本追加事务使用的本层读取描述符：
     历史 [0,n) 取自 old_view 的本层 K/V，包含旧部分尾页
     位置 n 取自 destination 本层槽 s 的新 K/V
   登记全部实际历史页读取、私有目的槽读取及 Q/工作区访问后才接受 attention
   等待 KV_READY[l] 及本层全部输入可见
   对每个 query head a，按模型映到 KV head g(a)：
     对 j=0 到 n：z_j=dot(q_l,a,k_l,g(a),j)/sqrt(d_h)+模型规定的 bias/mask
     在全部合法位置 j 上共同 softmax，得到 p_j
     o_l,a=Σ_j p_j·v_l,g(a),j
   不读取未填槽；复制到新尾页的历史不再作为第二份历史参与求和

   r_l=h_(l−1)+W_O,l concat_a(o_l,a)
   h_l=r_l+FFN_l(Norm_ffn,l(r_l))
   等待本层算子及必要的模型并行通信成功完成，h_l 对下一层可见后置 H_READY[l]
   仅此时允许下一层消费 h_l；本层 KV_READY 不替代 H_READY
3 所有必要层 KV_READY 与 H_READY 均成立，复制完整且成功，
   全部必需目的写入完成，发布后的消费者可见性关系成立时，返回 POSITION_READY
   任一必需操作失败、接受状态未知或资格撤销，不返回就绪，不发布部分长度
```

这里的 k_l,g(a),j 与 v_l,g(a),j 是读取描述符解析出的同层、同 head、同位置状态；j=n 来自本轮私有生产者，j<n 来自已提交历史。softmax 的分母跨全部合法位置，不能把历史与自身分别归一化后相加。n=0 时历史为空，仍执行各层前向，普通 causal attention 的合法集合只有位置 0。若需要生成下一 token，h_L_layers 再经过模型规定的最终归一化与输出头产生位置 n 的 logits，采样得到的是下一位置的 token；它自身的 KV 不因此已经计算。

每个操作在被接受前都按 TRY_ADMIT 规则登记请求、追加尝试、层、物理页代次、访问范围和匹配完成条件。责任包括全部层历史 attention 读、旧尾页复制读、私有目的复制写与新 KV 写、随后 attention 对私有 KV 的读，以及权重、hidden 和工作区的实际使用。历史页即使不是复制源尾页，也不能漏记；复制完成不解除后续 attention 读责任，目的写者结束也不解除目的页后续读者。计划中的后续用途和逻辑引用在尚未提交时继续保护对象，已接受责任到对应最后物理访问结束才解除。权重和工作区按各自池及驻留口径记账，不重复加进 KV 页数。

例如 B=16、n=513 时，目的页 p′ 先复制旧尾页位置 512 在各必要层的槽 0 状态。新位置的跨层轨迹是 x_513→h_0→Q/K/V_1→本层 attention→h_1→Q/K/V_2→本层 attention→h_2→…→h_L_layers。每层 attention 的历史读者 A_l 读取旧映射 [0,512) 与旧尾页位置 512，本轮私有读者读取 p′ 的本层槽 1；新 KV 写者只写 p′，旧页始终不写。共同完成条件为 COPY_READY∧所有层的 KV_READY[l]∧H_READY[l]，再满足发布可见性、旧视图版本与追加资格复核，才替换尾页映射并发布长度 514。仅第一层 KV 完成既不能启动第二层，也不能发布长度。第二层失败时，旧长度 513 和旧页仍有效，新页已接受的写者与读者各自排空后才回收。其他并发旧视图读者可以晚于新视图发布结束；它们约束旧页回收，不要求为了发布一律先排空所有外部读者。

步骤 6 的回滚边界是一次追加，不是把已经发布的整个请求重新算成 RESERVED。部分写入只发生在新页，旧页与旧有效长度保持可恢复。新页即使已经完成某些层，也不能发布部分长度；失败页仍被 kernel 使用时先进入 DRAINING。外部输出、采样或随机状态的确认应绑定同一执行结果，不能把一次失败重试算成第二次合法输出。

对 q 个旧尾页独占、没有外部旧读者的请求，设起始为 (L,H,R,D,F)，从 guard 使用 a 页、从 free 使用 q−a 页。替换期间变为

(L,H−a,R+q,D,F−(q−a))。

复制/写入完成且发布后，新增 q 个 LIVE 同时解除 q 个旧尾页的最后逻辑持有；无旧访问时，结束状态为

(L,H−a,R,D,F+a)。

LIVE 净增为零，但写入期间明确占住 q 个目的页。若旧页仍有 q 个未结束的物理读者而无逻辑持有，发布后为

(L,H−a,R,D+q,F−(q−a))，

随后最后访问结束才 D→F。若旧快照仍持有逻辑引用，旧页继续计 LIVE；直到快照释放后才按实际责任转 D 或 F。不能不加条件地承诺替换完成立即释放旧页。

guard 是有限前瞻，可以用于跨页，也可以用于净增量为零的尾页替换。它不能保证任意长输出永不暂停。补充失败后继续假称每请求仍有保护，会掩盖下一步失败；强制所有请求等待整体补充又可能形成容量死锁。计划应明确回收事件、可推进子集、公平顺序、抢占与恢复预算，以及 deadline。换出目的容量同样要先取得。

## 成本分解与关键路径

| 成本 | 条件化账目及限制 |
|---|---|
| 计算 | 分阶段工作除以匹配形态的有效能力；batch 摊薄权重成本，也改变轮次时间；重算和失败工作仍计费 |
| 访存 | 权重、KV 读取/写入、页表、尾页复制与元数据；区分逻辑字节、cache 流量与 HBM 事务 |
| 通信 | P→D、模型并行、缓存填充与迁移；按实际链路合并需求，另计转换、协议与重试 |
| 准备 | 制品读取、转换、加载、编译、预热和池建立；加载改善不自动提高常驻 decode 服务率 |
| 同步 | 队列、提交、复制→写入依赖、完成、可见性、发布及最后使用；异步返回不能缩短物理生命期 |
| 驻留 | 权重、池、热备、同时存在的源/目标与 DRAINING；C_peak 限制容量，A_C 描述占用时间，不是延迟 |

共享 128 KiB 的四个所有者只占 128 KiB；如果各自读一次，有效读取量为 512 KiB，实际事务还依赖 cache。共享减少容量不证明流量同比下降。

私有尾页路径另有可计算的复制成本。尾页有效槽为 u 时，只复制有效状态的实现每请求增加 u·b_token 的源读取和同量目的写入，另写本次 b_token；若实际按整页复制，则读取和写入各为 b_page。量化尺度、对齐和元数据按实际布局另计。该字节量只描述复制负载，不能代替整个 decode 的历史读取；HBM 时间估值还需匹配事务口径、带宽、cache 与重叠条件。改用满足合同的原地路径会取消这次复制及目的页需求，但必须重新验证协议与失败边界。

回收延迟也有成本。两页各 768 KiB，取消或替换后还需 3 秒才结束最后访问，额外不可复用量为 2×768 KiB×3 秒=4.5 MiB·秒。在预分配池上，这不会使池 backing 再增加一次，却降低期间可准入容量；按需分配口径下也延长物理驻留。

时间先由依赖图确定，再结合共同资源。独立且充分重叠的两项可能取 max，串行或共用独占资源的区间必须相加。n≥1 个等长块经过两个独立串行阶段，每块时间为 a、b，缓冲充足时 T_pipe=a+b+(n−1)max(a,b)；空输入 n=0 的时间为零。没有足够缓冲、共享链路或新增依赖时，应重建时间线。

规划器本身也有准备成本。若有 K 个候选，每个处理 E 个事件，使用事件堆的调度部分约为 O(KE log E)，另加物理页集合、身份与责任记录的访问成本；有序日志扫描可更低。全轨迹空间随事件数增长，在线状态随存活页、请求和在途操作增长。这是模型算法复杂度，不是线上 CPU 开销实测。

## 条件变化后的保留、调整与放弃

| 条件变化 | 可以保留 | 必须重算或放弃 |
|---|---|---|
| 到达均值改变 | 身份、单位与容量守恒 | 重算全部资源轴、队列与实例数，不能只按旧 tokens/s 缩放 |
| 突发、方差或相关性改变 | 事件账和完成边界 | 重算残余积压、热备与排空；放弃只凭平均 λ 的尾部判断 |
| 输入、输出或分支数增长 | 位置与页归属规则 | 重算 KV、步数、写副本、guard 和服务曲面 |
| 前缀命中提高 | 唯一物理页去重 | 重算实际 P/D/传输流率与末行恢复，不能按命中率直接缩放两池比例 |
| batch 或页长改变 | 请求身份、最后使用条件 | 重算页尾、替换粒度、复制流量、寻址、服务时间与 ITL |
| 尾页追加协议改变 | 有效长度和逻辑位置语义 | 重新证明写权与失败恢复，重算目的页峰值；不能混用私有页成本与原地推进轨迹 |
| 链路变窄或采用 P/D 分离 | 阶段依赖与状态身份 | 重算每条共享链路、目标预留与接管；必要时回到同置 |
| 存储变快 | 冷启动数据路径 | 只更新相应准备项；常驻执行能力需另测 |
| 取消比例、旧快照或完成延迟上升 | 业务/物理双状态 | 重算 LIVE 保留与 DRAINING 峰值；活跃请求下降不表示容量已经释放 |
| 模型、表示或并行组改变 | 容量、流量与依赖抽象 | 重建每设备状态、质量、kernel 和通信模型 |
| SLO 更紧 | 原始到达与结果事件 | 重新选择余量和运行点，或判定不可行 |
| 开放到达改为闭环 | 同人口身份与资源账 | 重新解释压力；客户端等待会自动减压，不能证明原开放容量 |

## 诊断：竞争解释与区分实验

| 观察 | 竞争解释 | 区分实验与反证后的修正 |
|---|---|---|
| 平均状态很低仍 OOM | 长度尾部、替换、暂存、排空或池重复计数 | 记录唯一页与五类分区，延迟复制完成并查过渡峰值；池内正常而池外升高时转查工作区与另一 allocator |
| 页内有空槽却不能整批追加 | 私有替换目的不足、旧页未排空，或错误把净增量当预算 | 固定部分尾页与长度，分别给 q−1、q 个可取得页；私有路径应前者暂停、后者先 R 增 q；若零预留成功，检查是否偷换为原地写入 |
| 新长度可见却缺层，或后层 KV 错误 | 用 KV_READY 代替 hidden 就绪、缺层发布、漏记历史读责任 | 延迟第一层 H_READY 或后层 KV 写完成，核对下层接受与全层发布事件；另延迟非尾页历史读，保护不能因尾页复制完成而解除。若违反这些预测，修复依赖和责任登记；这些是待执行的区分实验，不由符号 token 检查证明 |
| 替换后 free 没有立即恢复 | 旧快照逻辑持有、旧实际读者，或泄漏 | 分别只延迟快照释放与只延迟读完成，观察旧页留 L 或转 D；责任全清仍不释放时再查泄漏 |
| 取消后立即能接纳同页 | 合法释放未提交预留，或错误释放已接受操作 | 在提交前、接受后未发布、发布后分别取消；延迟最后访问并再次申请同页，比较旧访问实际读取内容；发现提前复用即撤回“取消等于释放” |
| 第一轮增长正确，下一轮失败 | guard 被消耗但未补充，或新请求抢占补充空间 | 固定初态，逐事件记录 H→R→L、旧页回收与 F→H；关闭新准入后仍失败则检查补充目标和尾页协议 |
| P/D 比例与预期不同 | 阶段流率不同、取整、链路或服务曲面改变 | 固定各池能力，只改变阶段旁路比例；需求随 λP/λD 改变时收回仅按 rD/rP 的判断 |
| 完成吞吐平台且队列增长 | 服务饱和、生成器不足或拒绝掩盖过载 | 同时报 offered、admitted、completed、failed、迟发和队列斜率；增加生成器资源后压力改变时先修生成边界 |
| 分离后延迟未改善 | 传输、两侧排队、转换、负载偏斜 | 固定 workload 和放置，分开 P 执行、传输、D 排队与执行；链路已满时停止只加计算实例 |
| 加 GPU 无收益 | CPU、共享链路、存储或单执行域饱和 | 一次改变一个资源轴，记录实际额度和单域服务时间；总 CPU 利用率低不能排除单域满载 |
| 命中提高而尾部恶化 | 路由集中、缓存占用、复制或共享页竞争 | 固定路由/淘汰策略，对照物理页、队列、读取字节和尾延迟；只证实容量收益时收回带宽结论 |
| 冷启动变快而热服务不变 | 改动只作用于加载 | 分开冷启动、热启动和常驻执行，修正收益的适用阶段 |

分段常数流体模型可帮助检查突发，但需要保留残余积压。固定服务率 μ、段长 τ、到达率 λ 时，Q_next=max(0,Q+(λ−μ)τ)。μ=100 请求/秒，160 持续 2 秒使积压达到 120；随后 60 持续 1 秒只降到 80，再来相同突发则达到 200。每段重置为空只得到 120。真实离散组批、变长服务和抢占需要另一层模型。

另一个反例是两池各自满足平均计算需求，但每秒 4 请求各迁移 0.5 GiB，需求为 2 GiB/s，单条 1.5 GiB/s 链路仍不足。再如把实例就绪时间从 90 秒降为 60 秒，仍赶不上仅持续 30 秒的突发；需要热备、提前扩容或准入策略，而不是宣称加载优化已经解决该突发。

## 组合轨迹：共享、尾页替换、排空与阶段需求

以下全部为可复算设定，不是目标 CPU、GPU 或网络实测。模型为 24 层、4 个 KV head、每 head 128 维、2 字节，标准 K/V 得 b_token=49,152 byte=48 KiB。B=16，b_page=768 KiB；800 页池占 600 MiB，池外权重、工作区与元数据另计。

32 个请求各有 512 个已计算 token，其中 128 token 为合法共享的完整前缀。无共享时为 32×32=1024 页；共享后为 8+32×24=776 个唯一页。但每请求独占一页 guard 时，776+32=808，32 个不能全部准入。

先准入 30 个，已提交唯一页为 8+30×24=728，guard 为 30。采用上述私有尾页基线，每次只追加一个已知位置并发布；共享完整前缀不改写，旧私有尾页在替换发布后若无其他持有或访问就立即回收。下表先设没有外部旧读者、没有其他准入或暂存事件；表内长度为每请求已计算 KV 长度。

| 事件与长度边界 | L | H | R | D | F | 合计 |
|---|---:|---:|---:|---:|---:|---:|
| 初态，n=512 | 728 | 30 | 0 | 0 | 42 | 800 |
| 512→513：跨页目的从 guard 取得，未发布 | 728 | 0 | 30 | 0 | 42 | 800 |
| 发布 n=513，每请求新尾页有效 1 槽 | 758 | 0 | 0 | 0 | 42 | 800 |
| 显式补充下一次推进的 30 页 guard | 758 | 30 | 0 | 0 | 12 | 800 |
| 513→514：取得 30 个私有替换页，复制/写入中 | 758 | 0 | 30 | 0 | 12 | 800 |
| 发布 n=514，旧尾页最后使用结束并回收 | 758 | 0 | 0 | 0 | 42 | 800 |
| 再次补充 30 页 guard | 758 | 30 | 0 | 0 | 12 | 800 |
| 同样替换并补充，直至 n=528，尾页填满 | 758 | 30 | 0 | 0 | 12 | 800 |
| 528→529：跨页取得并发布另一批 30 页 | 788 | 0 | 0 | 0 | 12 | 800 |
| 补充 30 页失败；整批 529→530 也预算不足 | 788 | 0 | 0 | 0 | 12 | 800 |

从 513 到 528 的 15 次追加都替换已发布部分尾页；不能在首步取得新页后把后续位置直接原地填入。每次替换的 LIVE 净增为零，但准备时都需 30 个私有目的页。表中 F 从 12 回到 42 来自旧页回收，从 42 降到 12 来自另一次显式 guard 补充，二者均不隐含在“净增为零”中。

这 15 次替换若仅复制有效状态，每个请求复制的 token 状态总数为 1+2+…+15=120；30 请求的复制源读取与目的写入各为 30×120×48 KiB=168.75 MiB。两方向复制负载合计 337.5 MiB，另有 512→528 这 16 个新增位置的 22.5 MiB 状态写入。若实现每次整页复制，复制读写各为 337.5 MiB，合计 675 MiB。两种实现都还需普通模型计算、attention 历史读取、元数据与同步，数字不能解释为实际 HBM 事务或耗时。

最后一行中，尾页各有 15 个空槽，但整批追加到 530 仍需 30 个替换页，F=12 无法满足。可以先选择至多 12 个请求取得目的页；它们发布并释放旧尾页后，F 可恢复为 12，再推进其他请求。该顺序会改变批组成、等待和公平性，不能沿用 30 请求同批的服务时间。若必须作为一个不可拆工作组提交，则暂停整组，等待真实回收、执行合法抢占/换出或明确失败。

若这 12 个请求的旧尾页仍有物理读者而无逻辑持有，轨迹是 (788,0,0,0,12)→(788,0,12,0,0)→(788,0,0,12,0)，直到旧访问结束才恢复为 (788,0,0,0,12)。若旧快照仍有逻辑引用，发布后旧页留在 LIVE；不能把它先记成 D 再同时计入快照容量。

两个等待请求各需 24 页私有状态加一页 guard。在初态 F=42 时不能同时进入；若选择准入其中一个，就消耗 25 页，后续为 30 个在服请求补充 guard 的决定会改变。准入策略必须明确是否优先保护在服推进。

再用独立两页小池检查取消：A 预留两页时 R=2、F=0。尚未提交且无其他持有时取消，可立即变 F=2；初始化或复制已接受时，即使从未发布，取消后也应为 D=2、F=0，B 的两页申请在最后访问前拒绝。多个访问中第一个完成不解除另一个的责任。全部结束后 B 才能取得新代次。若 A 已发布，则从 L 转 D，不能再次扣 R。错误实现若取消时先归还再排空，B 会覆盖 A 仍在访问的地址；代次过滤不能修复这次物理覆盖。

服务侧另设每秒 4 请求，每请求有 1000 个未命中输入 token 和 100 个实际 decode 步；每实例分别服务 2500 输入 token/秒、250 decode 步/秒，则两池计算轴都至少需要 2 个实例。每请求传输 0.5 GiB 时，单条 1.5 GiB/s 链路不足；两条独立同速链路的聚合平均能力为 3 GiB/s，但固定到一条链路的单次传输仍至少约 0.333 秒，不能由聚合可行推出单请求尾延迟可行。

若路径改为 λP=1、λD=4，且两池每实例都能服务 1 请求/秒，实例下界变为 1 与 4。这个变化来自阶段需求。冷启动、热备权重、故障域和全部排空成本继续进入同一候选账。

## 校准、检查与证据边界

服务曲面至少在有解释的坐标上取点：query 长度、历史长度、batch 组成、dtype、缓存条件、模型版本、并行组与放置。记录计算时间、设备/主机流量、工作区峰值、提交和完成边界。插值只适用于已声明区域；kernel 切换、桶边界、重编译或跨 NUMA 后另建区段。探索轨迹与 holdout 分开，不能用选出参数的同一批结果证明其泛化。

容量扫描同时保留 offered、admitted、completed、failed、取消、未完成、队列斜率、C_peak、A_C、五类池分区及阶段延迟。完成吞吐达到平台而队列持续增长，不是稳定 SLO 容量。

配套 tools/check_k_work_006_full.py 是确定性、标准库、离线、只读的 CPU 算术与事件模型。页集合与独立 token trie 的页边界参考对照；实例上取整与从零开始的整数可行性枚举对照；流体递推与保留末段余量的细步积分对照。生命周期检查覆盖未提交撤销、接受后未发布取消、发布后取消、部分接受、多个最后使用者、旧/重复完成和缺失完成。

追加模型保存每请求已发布映射与有效长度，实际构造私有尾页内容，并与独立的逐位置参考序列对照。它覆盖空状态、满页边界、部分尾页、513→528 的逐步替换、guard 补充、529→530 预算不足、私有写入后失败与旧读者延迟。负对照故意用净增量零申请零目的页，随后向旧尾页写入；独立的目的页与已发布集合不相交检查，以及旧页完整内容冻结检查，都要求拒绝这条路径。

另一个事件审计器从分配、接受、完成与释放日志重建仍存活的物理责任，不读取池的 free 标志证明安全。提前释放负对照实际重新申请同页，使旧访问读到变化后的载荷，并要求审计器拒绝。服务与队列检查保留忽略阶段流率比、向下取整、遗漏网络和重置积压的数值负对照。

Tails.write 用 token_at 构造的是符号状态，并不从 hidden 计算 Q/K/V，也不执行 PRODUCE_POSITION。上述脚本支持容量、符号内容和生命周期性质；它不验证新增逐层前向的数值等价、层间执行依赖或全部 attention 历史访问登记。新增的数据流说明与待执行区分实验不能倒写成该脚本已经覆盖的结果。

本轮通过工具内 V8 实际执行了两层符号时序审计：合法轨迹在两个 hidden 完成后发布；提前进入下一层、第一层结束即发布、历史读者未结束即回收三个负对照均被拒绝。该有限审计没有执行投影、softmax 或 Python 脚本。交付 Python 保留既有内容，本轮未实际重跑；新候选的正文与脚本 SHA 绑定执行须由协调者另行保存，历史执行记录不能代替。算术和串行事件模型都不证明设备可见性、真实并发原子性、GPU kernel、NIC 排空、实际带宽、质量、尾延迟或 Agent 使用效果。
