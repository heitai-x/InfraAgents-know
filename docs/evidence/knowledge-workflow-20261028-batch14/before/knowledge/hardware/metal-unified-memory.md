# K-HW-007：Apple Silicon：统一内存、带宽与交互式推理

Apple Silicon 的统一内存让 CPU 与 GPU 访问同一物理内存池；MLX 数组不预先绑定设备，设备在操作执行时选择。它减少显式的设备间副本，却不消除读取、容量、依赖顺序和主机可见性。交互式推理需要将这些成本与请求推进、提交和最后使用结束连在一起。

## 问题与对象：共享物理内存不等于零成本

设物理分配 p 的字节数为 s_p，生命期为 [birth_p,retire_p)。birth 是容量实际被占用的时刻；retire 要求逻辑持有者全部释放，且已经启动的异步访问全部结束。地址再次分配时必须使用新的分配身份或代次，不能只按地址去重。

C(t)=Σ_{p∈Live(t)}s_p，M_peak=max_t C(t)。

Live(t) 是按物理身份去重的集合。逻辑数组是视图 v=(p,offset,shape,strides,dtype,version)。同一 p 上的多个视图、CPU/GPU 各一个引用、共享前缀页的多个读者，不会仅因引用增多就复制容量。反过来，dtype、stride、连续布局转换或显式复制若产生新分配，源和目标同时存活时必须分别计账。

请求的已提交状态为

s=(x[0:n),k,KV,ell,logits,id_logits,rho,version)。

x 是已确认 token，n 是已知长度，k 是全部必要层 KV 都已完成的连续边界，0≤k≤n。rho 是采样状态。ell=m 表示缓存 logits 来自精确前缀 x[0:m+1) 的最后一行，预测位置 m+1；本章只保留可以直接采样的末行缓存，因此有效缓存要求 k=n、ell=n−1。无缓存时 ell=−1。id_logits 必须匹配 token 前缀、模型、adapter、位置规则、mask 和数值表示；长度相同不能代替身份相同。

token 追加到 x 不等于它的 KV 已完成。若原已知长度为 n，处理到 e=n 后采样并追加 x[n]，新的已知长度为 n+1，而 k 保持 n。下一步才计算这个新 token 的全层 KV。

成本至少分为计算 F/P_eff、跨指定存储边界的字节 Q_j/B_eff,j、准备与建图、同步及交付、物理峰值 M_peak 和驻留积分 A_C=∫C(t)dt。P_eff 和 B_eff,j 必须匹配 dtype、shape、布局、并发及访问形态；A_C 的单位为 byte·s，不能直接加到毫秒延迟中。

## 合法性与设备放置

固定 Unified Memory 文档说明：Apple Silicon 的 CPU/GPU 可直接访问同一内存池，创建 MLX 数组时不必指定位置，设备在操作执行时选择。没有依赖的两个操作允许并行；若 CPU 先产生 c，GPU 随后消费 c，调度器会建立依赖，使后者在前者完成后开始。

| 来源机制 | 可以保留的结论 | 不能据此推出 |
|---|---|---|
| CPU/GPU 消费同一数组 | 不必为该访问显式建立设备副本 | 没有访存、同步或固定开销 |
| 无依赖操作允许并行 | 调度允许重叠 | 两个设备各有一份完整独占带宽 |
| 数组表达式已构造 | 图节点已经存在 | 结果已经完成或对主机可见 |
| 调度器跟踪数组依赖 | 受跟踪操作有执行顺序 | 外部原生指针、其他进程和未声明别名自动有序 |
| 多个视图指向同一物理页 | 容量只计一次 | 不同消费者的读取流量也只计一次 |
| 权重量化减少存储 | 容量和读取字节可能下降 | 完整服务时间按同一比例下降 |

合法执行要求如下。

1. 同一物理范围发生 RAW、WAR 或 WAW 冲突时必须建立依赖。设备不同不能证明访问独立；统一地址也不取消生产完成先于消费、最后读取先于覆盖的关系。
2. 自动依赖只覆盖框架跟踪的操作。通过外部库、原生指针或其他进程访问时，需要依据互操作契约建立显式同步、复制或序列化，并验证可见性。
3. 目标设备必须支持实际算子、dtype 和布局。不支持时选择回退、转换或拒绝；统一内存文档不是任意算子组合都已实现或优化的证明。
4. 片长 q 必须为正整数。空输入由入口补合法 BOS 或拒绝，不能从不存在的末行采样；要求生成零个新 token 时直接结束。非法 k、缓存身份不兼容或全层 KV 不完整时不得进入正常推进。
5. 容量准入使用 M_peak+C_reserve≤C_budget。M_peak 始终只表示物理对象占用峰值，C_reserve 是尚未计入对象集合的外部需求及不确定性余量；预算口径若已扣除了某项系统占用，就不能再预留同一项。
6. 打印、转为主机表示、memoryview、保存、读取标量和标量数组控制流可能触发求值或等待。构造表达式、设备完成、主机可见、业务提交与用户收到输出分别记录。

CPU 预处理与 GPU 推理同时运行时，必须合并它们对共同内存资源的需求。把两个孤立时间取最大值，需要独立能力与重叠条件支持；仅把工作放到不同设备上并不满足这些条件。

## 惰性图、模型准备与提交边界

固定 Lazy Evaluation 文档说明：操作先记录图，显式 eval 或特定主机访问才触发求值；重复 eval 同一结果可视为 no-op。过密 eval 有固定开销，过大未求值图也有开销。其经验图规模不是跨版本常数。

设图 G=(V,E)，u→v 表示 v 消费 u。根集合 R 的闭包为

C(R)=R∪{u | 存在路径 u→…→r，r∈R}。

EVAL(R) 成功完成只覆盖 C(R)。来源中的 loss 示例说明，提前读取 loss 只计算前向，不能证明梯度及参数更新已经完成。对应到服务中，logits 的数值依赖可能经过 K/V 计算，但独立的缓存写回、描述符构造等输出未必都在其闭包内，必须检查实际图，不能按名字推定。

模型准备明确委托给 [K-FW-008 的“服务步与 KV 存储契约”中的 PREPARE，以及“准备、采样和提交的同一条轨迹”中的 SERVE_AND_COMMIT](../frameworks/mlx-serving.md)。本章消费 PREPARE 返回的 base、delta、b、e、k_after、末行 logits 及 required_roots，再增加物理对象准入、设备放置、依赖和完成责任。该委托的必要契约如下。

- 当 k<n，b=k，e=min(n,k+q)，只消费已经确认的 x[b:e)。对位置 t，先得到 h_t^(0)=Emb(x_t,t)，再逐层从该层输入 hidden 产生当前位置 Q/K/V，写入私有 delta[l,t]。attention 消费该层已提交 [0:b) 和本执行 [b:t+1) 的 KV，按模型的因果 mask、位置变换、归一化及剩余 block 得到下一层 hidden。全部层完成后才可将位置 t 纳入 k；末层最后一个位置的 hidden 才能经 LM head 产生末行 logits。普通 attention 的核心关系是 softmax(Q_t K_[0:t+1]^T/√d+mask)V_[0:t+1]，具体 norm、残差和 MLP 顺序服从模型定义。
- 当 e<n，只推进 prefill，不产生可用于本请求下一 token 的 logits，也不采样。中间前缀的 logits 即使能够计算，也不能冒充完整已知输入的后继分布。
- 当 e=n，产生身份为完整 x[0:n) 的末行 logits，允许采样。
- 当 k=n 且缓存末行 logits 兼容，复用其结果和完成证据，不读取空输入区间来假装重新推进。
- 当 k=n 且没有缓存末行 logits，在私有单位置区重算 t=n−1，读取已提交 [0:n−1)；得到完整末行 logits 后丢弃重算 KV。原 KV 对象和边界保持不变。不能安全隔离重算写入时返回 REPAIR_UNAVAILABLE。这里的实际重算访问区间是 [n−1,n)，不能用不变的已提交边界代替工作范围。

本章使用“只读前缀引用＋私有增量”的候选：local[l,t]=base[l,t]，当 t<b；local[l,t]=delta[l,t]，当 b≤t<e。WRITE 只能写本执行私有范围。逐 token 描述便于恢复依赖；按层处理整片 prefill 也合法，但必须保持等价的因果关系、位置和全层完成条件。

这不是某个 MLX attention 已支持分段 KV 的事实声明。若后端要求连续物化、拼接复制或整页写时复制，就使用同样隔离的私有目标，并增加复制流量和同时驻留容量；不能继续使用无前缀复制预算。

硬件映射也要落实到物理范围。例如每层 K/V 分别采用连续的 [位置,KV head,通道] 布局时，私有片起点为 b，元素 (t,h,d) 的字节偏移为 b_a[(t−b)H_kv d_h+h d_h+d]，地址为对应私有分配的基址加该偏移。历史前缀使用自己的分配身份和局部起点；分页布局则先经块表取得物理分配及页内位置。每个 CPU/GPU 操作消费的是这些范围及版本，转换目标是另一个分配。框架建立受跟踪依赖后，消费者才可读取。这里不假定未公开的 Metal lane、bank 或矩阵指令内部映射。

需要区分三类对象：设备结果根、私有候选和业务发布。设备根可以是全层 delta 写入、logits、必要转换结果，以及设备采样产生的 token/rho_next；它们只写本执行私有区。私有候选描述完成后的拟提交状态。请求已提交字段、响应记录和网络发送不放入这些设备根中。

采样分支还必须区分“没有 logits”和“存在完整末行 logits”。has_full_logits 是根据结果描述符、完成边界及前缀身份判断的结构条件，不通过读取 logits 标量作控制流。合法的 e<n 分支没有 logits 句柄和采样输出节点；完整处理分支缺失末行结果则是执行错误，不能降格为一次成功 prefill。

```pseudocode
算法 UNIFIED_INTERACTIVE_STEP
输入：模型 M；请求 r；正整数片长 q；物理预算 C_budget；余量 C_reserve；设备策略 σ
输出：PREFILLED、COMMITTED、等待或拒绝原因

由同一状态拥有者串行处理入口：
  若取消、失败、终止或提交资格已撤销：拒绝
  若仍有活动执行或未结束使用者：等待
  若剩余输出额度为零：结束，不建立图
  校验已提交状态、q、全层 KV 和缓存身份
  冻结 s；分配不复用的执行身份 I
  按 PREPARE 的推进、缓存复用或私有末行重算分支确定工作
  预测全部私有区、工作区、转换、图和结果缓冲的同时存活对象
  若物理对象峰值加一次 C_reserve 超过 C_budget：
    尝试等待、减小片长、减少并发、释放已无使用者的保留对象
    仍不可行则推迟或拒绝；不得启动未获预算的访问
  预留全部必要对象；部分分配失败则撤销本次取得的对象
  prepared=K-FW-008.PREPARE(s,q)
  记录 s、prepared、I 及所持对象
  校验 prepared 的结构契约：
    若 prepared.e<s.n：要求 logits 为空且 k_after=prepared.e
    否则：要求存在完整末行 logits，k_after=s.n，前缀身份匹配
    不满足则按执行失败处理，不进入采样或提交
  has_full_logits=prepared 存在上述完整末行 logits

对 prepared 图中的操作 o：
  按 σ 选择实际支持该算子、dtype、布局的设备
  必要转换写入独立私有对象；新增分配前重新检查容量
  对受跟踪的重叠范围建立 RAW/WAR/WAW 依赖
  外部访问按互操作契约建立完成及可见性边界

若采用主机采样：
  roots=prepared.required_roots
  在启动访问前登记 (I,每个实际使用者) 的最后使用责任
  EVAL(roots)；取得覆盖全部根的结果证书
  若 has_full_logits：
    为实际存在的 prepared.logits 建立 HOST_VISIBLE
    token,rho_next=纯采样(prepared.logits,s.rho)
  否则：
    token=空；rho_next=s.rho
    不访问 logits，不建立其主机可见性，不调用采样

若采用设备采样：
  roots=prepared.required_roots
  若 has_full_logits：
    建立采样节点，显式消费 prepared.logits 和冻结的 s.rho
    建立其私有 token、rho_next 输出及必要结果描述符
    仅将这些实际存在的输出根追加到 roots
  否则：
    不建立采样节点和采样输出根
    在求值前令 token=空；rho_next=s.rho
  在启动访问前登记全部实际使用者的责任
  EVAL(roots)；取得覆盖全部根的结果证书
  若建立了采样节点：
    从已完成的私有输出取得 token、rho_next
    若拥有者需要主机读取，建立这些实际输出所需的可见性

由同一状态拥有者处理结果：
  根据各使用者的真实结束证书幂等解除责任
  结果缺失、执行错误或取消：不安装候选
  失败撤销本请求实例的后续提交资格
  尚有访问未结束时保留全部相关对象，不把超时当作结束
  仅在结果完整、物理使用责任已结束且候选可读取时进入 READY_TO_COMMIT

COMMIT：
  复核 I、快照 version、活动执行和 READY_TO_COMMIT 阶段
  复核 live、提交资格、未取消且未失败
  复核全层结果、区间和完整末行前缀身份
  任一失败：保持已提交业务状态不变
  否则在同一业务事务中：
    普通推进：用新描述符安装有效 delta，前缀对象保持只读
    缓存复用或末行重算：保持原 KV；重算 delta 不安装
    r.k=prepared.k_after
    若 token 非空：
      r.x=s.x 追加 token；r.n=s.n+1
      r.rho=rho_next；清除旧末行缓存及其身份
      追加带请求实例及输出序号的响应记录
    否则：
      r.x=s.x；r.n=s.n；r.rho=s.rho；不追加响应记录
    r.version=s.version+1；解除活动执行
  事务提交之后，按已提交响应记录进行输出交付
  临时对象仅在逻辑持有及最后使用均结束后回收
```

主机路径先完成必要结果根，仅在存在完整末行 logits 时建立其主机可见性并采样。设备路径先从必要结果根初始化集合，只有创建采样节点后才添加它的输出根。没有 logits 时，两条路径都返回空 token 与冻结的 rho；设备路径在 EVAL 之前就确定这两个值，求值根中不存在未产生的采样输出。缓存复用可以没有新增模型根，但仍须有缓存结果的既有完成证据。

两条路径中的采样都不修改请求 RNG。设备采样显式成为图的一部分，主机采样在结果可读后执行；业务字段均在资格复核之后安装。实际实现若继续让输出设备读者消费结果，可以转移其已登记的持有责任，但必须另行证明提交后读者和回收协议；上述保守算法在提交前排空本执行使用者。

COMMIT 是业务线性化点。取消先于该点时，已经准备甚至已经采样的候选也不能安装；提交先于取消时，已提交记录不能回滚。网络发送失败或客户端尚未收到，不改变内部提交事实。重送和客户端去重需要另定协议，本章只要求输出交付依据已提交记录。

失败排空不会恢复 live 或提交资格。执行身份 I 不能用业务 version 替代；旧事件、错误身份和重复完成事件不能清除其他使用者的责任。没有最后访问结束证明时保持隔离，并报告对象与执行身份。

沿一次组合轨迹检查这些条件：

| 事件 | 已提交状态与私有对象 | 允许的后继 |
|---|---|---|
| n=4、k=2、q=1 | 私有计算位置 2 的全层 KV，e=3，logits 为空 | 主机路径只求值必要根；设备路径不创建采样节点，求值前确定空 token 与旧 rho；仅提交 k=3 |
| 再处理 [3,4) | 私有位置 3，末行 logits 身份为 x[0:4) | 主机路径先求值再建立 logits 可见性；设备路径创建并求值采样输出根；提交 n=5、k=4 及同一次采样的 rho_next |
| 完整命中 n=k=4，但无 logits | 只读 [0,3)，私有重算位置 3 | 原 KV 不变；重算结果支持采样，提交后 n=5、k=4 |
| 完整命中且缓存 logits 兼容 | 使用已有完整末行结果及其完成证据 | 主机只读取实际缓存，设备采样节点依赖该缓存；均不制造新增 KV |
| 采样完成后取消先被拥有者处理 | token/rho_next 仍是私有候选 | 拒绝提交，旧 token、KV、rho 和响应均不变 |
| 失败但使用者尚在途 | 旧 KV 与私有区继续占容量 | 迟到成功也不得提交；最后使用结束后才解除容量责任 |

## 容量、带宽和驻留账

普通全注意力模型有 L 层、H_kv 个 KV heads、每 head 通道数 d_h、每元素 b_a 字节时，每 token 全层 K/V 有效载荷主项为

b_kv=2L H_kv d_h b_a。

因子 2 来自 K 和 V。设定 L=32、H_kv=8、d_h=128、b_a=2，则 b_kv=131072 byte=128 KiB/token。四请求各持有 4096 token 的未共享 KV，载荷共 2 GiB。窗口、异构层、MLA 或量化 KV 应按实际状态族、元数据和存储格式重算，不能直接套用这个主项。

共享前缀只减少唯一物理对象。两个请求真正共享同一段 1 GiB 前缀时，容量计 1 GiB；若两者分别读取，逻辑流量仍累计两个读者，除非 cache 或合并读取另有证据。

令 W、KV_committed、delta_live、workspace、graph、compile、queues、retained 均表示相应时刻的物理分配集合。并集作用于物理对象，竖线表示集合的字节测度 |P|_bytes=Σ_{p∈P}s_p，而非对象个数。容量定义保持为

M_peak=max_t |W(t)∪KV_committed(t)∪delta_live(t)∪workspace(t)∪graph(t)∪compile(t)∪queues(t)∪retained(t)|_bytes。

另定义准入需求

D_admit=M_peak+C_reserve，准入条件 D_admit≤C_budget。

预留只在 D_admit 加一次。实际已经占用的池或转换目标属于物理集合，不能再以“预留”重复相加；若池大小已包含其中活跃对象，按包含关系去重。准备阶段尚未精确建模的转换峰值可以使用余量覆盖，知道其真实分配后应转入对象账并调整对应余量。分别取各类峰值再相加通常只是保守上界，精确峰值需要同一时间线。

设定 C_budget=16 GiB、W=12 GiB、四请求 KV=2 GiB、workspace=0.75 GiB、graph 与队列=0.5 GiB，假设这些对象同时存活且互不包含，则 M_peak=15.25 GiB。再加一次 1 GiB 外部余量，D_admit=16.25 GiB，应拒绝。三请求时 KV=1.5 GiB，M_peak=14.75 GiB，D_admit=15.75 GiB，列项准入通过，剩余 0.25 GiB。新增私有 KV、分配舍入、重算区和转换若尚未包含，仍需从这段空间中满足，不能仅凭列项通过就断言真实运行一定可行。

普通推进新增私有有效载荷为 (e−b)b_kv；安全重算末行需要 b_kv，但不安装。四请求各新增一个位置，私有载荷另增 512 KiB。描述符安装只是转移持有关系，不应凭空再计一份 delta；后端实际复制则另计。若必须物化 b 个位置的旧前缀，准备阶段至少增加约 2b·b_kv 的复制读写及 b·b_kv 的同时驻留副本，另加分配、目录及同步；整页 COW 按真实复制页数计。

访存账先选口径。假设每个查询逻辑上读取一次其可见的全层 KV，暂不计跨查询 cache、head 重读和分块复用，处理 [b_r,e_r) 的累计读取位置数是

A_r=Σ_{t=b_r}^{e_r−1}(t+1)=(e_r−b_r)(b_r+e_r+1)/2。

Q_KV,read≈b_kv Σ_r A_r，Q_KV,write≈b_kv Σ_r(e_r−b_r)。

这里 t+1 包含当前位置。对 [2,4)，查询位置 2 读 3 个位置，查询位置 3 读 4 个位置，共 7 个位置读取，另写 2 个位置；不能用旧历史长度 2 替代累计读取量。对一个普通单查询 decode，b=n−1、e=n，A=n，才可简写为每请求 n·b_kv 的读取，另加一个位置写入。满 KV 缓存 logits 复用不进行本次模型 KV 读取；私有重算末行则读取 n 个逻辑位置并写一个私有位置，即使最终不安装，成本仍发生。

完整逻辑账可写为

Q_step,use≈Q_W,use+b_kv Σ_r A_r+b_kv Σ_r(e_r−b_r)+Q_CPU,use+Q_other,use+Q_copy,use。

重算分支按其实际 [n−1,n) 计算，不能用返回的已提交边界差零来抹去成本。Q_W,use 是本候选的实际权重遍历主项；更一般地 Q_W,use=Σ_l m_l W_l，其中 m_l 是该层在本范围内的逻辑遍历次数。逐 token 执行 q 行可能遍历 q 次；按层将整个片段作为矩阵执行，可能在一次层调用内复用权重。批量 decode 也只有在实际合并读取的候选下，才可用每批一遍权重。不能给逐 token 循环配一遍权重账，再声称适用于任意 prefill。

逻辑读取不是共享内存事务实测。片上保留、GQA head 复用、融合、cache 命中可以减少下层事务；布局、非连续访问、重复载入和解包元数据可能增加事务。应使用 Q_use/B_use 或 Q_tx/B_tx 的匹配口径，不能把事务放大再除以已经包含同一放大的有效带宽。共同资源上的 CPU/GPU 流量要合并，再用匹配的条件化 B_eff 估值。

设定权重读取 12 GiB、KV 读取 2 GiB、CPU 及其他共同流量 0.5 GiB，匹配带宽设为 200 GiB/s，则对应资源项为 14.5/200 s=72.5 ms；遗漏 CPU 项得到 70 ms。这里只核算列出的读取范围，尚未包括新增 KV 写入、其他中间量和完整服务阶段。这些是设定算术，不是 Apple Silicon 带宽测量，也不是端到端延迟保证。

准备包括描述符、私有区分配、布局转换、建图和实际发生的编译；同步包括依赖、求值边界、主机采样可见性及拥有者处理。设 m 为本步求值边界数，固定提交成本为 T_eval_fixed，执行资源估计为

T_resource=max(F/P_eff,Q_shared/B_eff)。

max 是资源必要时间的模型下界；把它作为执行时间近似，还需要充分并行、重叠和匹配参数。若阶段实际串行，应按依赖相加。对于本章串行主机采样路径，可用

T_step≈T_prepare+T_build+T_eval+T_host_visible+T_sample+T_owner+T_delivery+T_queue，

其中 T_eval 包含约 m·T_eval_fixed 和实际计算访存；不能再把已经包含的 Q/B 与实测 T_eval 重复相加。无 logits 的片段没有 logits 主机可见性和采样阶段，但仍支付全层 KV 求值、拥有者处理和提交成本。设备采样将采样工作及输出根纳入求值，其结果描述符的可见性按实际读取方式另计；不能同时把相同采样工作记入 T_eval 和独立 T_sample。

跨请求重叠时沿关键路径计算，同时累计共同资源工作。无显式 H2D 不代表无通信成本：主机可见性、输出序列化和实际网络交付仍在服务路径上；发生互操作复制时按真实边界另计。

图遍历与常规调度准备通常随 |V|+|E| 增长；过大的未求值图还增加元数据驻留。过密 eval 增加固定边界，过大片段增加私有区、激活和首 token 等待。只有同一输入、同一结果根和同一输出事件范围下的比较，才能确定取舍。

固定 Unified Memory 文档在 M1 Max 报告过一个设定示例：4096×512 与 512×4 的矩阵乘，以及在 512×4 数组上执行 500 次 exp，全 GPU 约 2.8 ms，矩阵乘留 GPU、exp 循环放 CPU 约 1.4 ms。它支持在该形状下小 elementwise 工作可能受 GPU 固定开销限制的解释。原文没有完整重复统计、背景负载和主机可见性计时协议，不能把这个倍率外推为任意模型的服务收益。

驻留积分 A_C 描述对象占用多久。保留缓存可能增加 A_C 却减少后续工作；逻辑释放但最后读者尚未结束的对象仍占容量。峰值与驻留积分分别记录，不能以请求已经结束代替物理回收。

## 条件改变后的保留与放弃

| 条件变化 | 保留的机制 | 调整候选及反转信号 |
|---|---|---|
| 权重与 KV 容量宽裕 | 共同物理池、依赖及提交隔离 | 比较 batch、片长和求值粒度；预算不足或尾延迟上升时收缩 |
| CPU 预处理与 GPU 同时运行 | 无依赖工作允许重叠 | 合并共同流量、限制并发；两侧同时变慢时停止用孤立时间取最大值 |
| 小 elementwise 循环增大 | 同一输入输出和依赖 | 比较 CPU、GPU、分工的完整路径；规模或主机负载变化后重新选择 |
| 上下文增长 | 真实历史、位置与因果语义 | 限并发、比较 KV 表示和 prefill 分块；KV 成为主项后不能只优化权重 |
| batch 增大 | 输出归属和全层边界 | 权重复用可能改善，KV、工作区、等待增加；吞吐提升而 ITL 变坏时限制 batch |
| 片段尚未覆盖全部已知输入 | 全层 KV 完成边界，不消费中间前缀分布 | 两种采样路径均跳过采样；出现 logits 主机访问或采样输出根时修复控制流 |
| 满 KV 缓存没有 logits | 从完整前缀采样 | 兼容缓存复用或私有末行重算；无法隔离则明确拒绝修复 |
| 后端要求连续 KV | 旧前缀不可被候选覆盖 | 增加复制流量和峰值；复制成本超过收益时改布局或缩小并发 |
| dtype 或 stride 改变 | 数值契约和物理身份 | 显式转换；转换副本、解包或回退抵消收益时保留原路径 |
| 图过密或过大 | 根闭包和完成证据 | 合并求值或缩短图；固定开销、元数据及驻留分别诊断 |
| 系统内存压力上升 | 实际对象峰值及一次外部余量 | 减并发、释放已无读者对象、拒绝新请求；压缩或换出不能作为交互 SLO 保证 |
| 外部原生访问出现 | 明确读写责任和最后使用 | 按互操作契约同步或复制；框架自动依赖覆盖不到时不能归咎于随机数值误差 |
| 取消或失败频繁 | 提交资格复核和最后使用责任 | 缩短在途工作、及时处理控制事件；排空不得恢复终止实例的资格 |

## 反例、区分实验和检查边界

没有显式 H2D 仍然需要读取权重和 KV；共享容量只计一次仍可能有多个读者流量。量化字节减半也不能直接推出延迟减半，因为解包、尺度、布局及 kernel 路径可能变化。

只求值 logits 就提交，会遗漏不在其闭包内的写回。把业务发布作为求值根、先执行再检查取消，也不能通过“所有根都完成”补救：完成证明不等于发布合法性。正确边界是设备根产生私有候选，同一拥有者复核后安装业务状态。

处理 n=4、k=2、q=1 时，e=3，完整请求的末行 logits 不存在。主机路径若先调用 HOST_VISIBLE 再检查 e，会在合法 prefill 上访问空结果；设备路径若无条件添加 token/rho_next 根，会引用未建立的节点。把空值判断只放在测试的 sample 调用之前，不能检出这两个更早的错误。检查必须执行可见性操作和根集合构造，并让空访问及未知根立即失败。

在中间片采样会忽略尚未进入模型的已知 token；采样后把 k 推到新 n 会使下一步读取不存在的 KV。满 KV 无 logits 却直接返回空工作，又会让一个合法请求永久没有后继。

| 观察 | 竞争解释 | 区分干预与反证后的修正 |
|---|---|---|
| 部分 prefill 在采样前报错 | 空 logits 可见性访问、不存在的采样根、必要 KV 根本身失败 | 固定 n=4、k=2、q=1，分别运行主机和设备路径；记录实际存在节点、求值根及访问事件；完整路径正常而部分路径失败时先查分支，不能归因为 GPU 数值 |
| 完整命中后不再生成 | 空区间停滞、缓存身份错误、采样或输出阻塞 | 分别注入兼容缓存、无缓存和错误前缀缓存；无缓存应私有重算，错误身份应拒绝；内部已提交而客户端无输出时转查交付 |
| 分块后首 token 或序列异常 | 中间前缀采样、层 KV 不完整、位置或 RNG 错误 | 固定输入和 rho，比较完整前缀参考与多片推进；逐步检查 n/k、每层 KV 和采样前缀；先定位首次分歧再修正 |
| 取消后仍有输出或状态变化 | 发布过早、迟到提交、取消在线性化点之后 | 在求值后、采样后、事务后分别注入取消；前两处不能安装，事务后保留已提交事实；记录输出序号区分发送与提交 |
| 分工比全 GPU 快 | 固定开销、共享带宽、依赖串行或计时范围 | 固定总工作，扫描 exp 规模与次数，统一根和主机可见事件；规模增大后优势消失支持固定开销解释 |
| 长历史变慢但未满内存 | KV 读取、attention 计算、图开销或 CPU 竞争 | 固定 batch 扫历史，再固定历史扫 batch；记录累计查询读取、真实事务和求值次数；仅容量不变不能排除带宽 |
| prefill 流量低于逐查询账 | 分块复用、cache 命中或漏计查询 | 固定 [b,e)，逐查询枚举访问作逻辑参考，再观察设备事务；真实复用成立时调整事务映射，不能修改因果可见集合 |
| 三请求也被容量模型拒绝 | 漏对象、重复余量或池内对象重复计数 | 分开记录 M_peak 与 D_admit，并按物理身份检查包含关系；14.75+1 被算为 16.75 时关闭重复预留错误 |
| 峰值高于权重加 KV | 私有区、转换、图、保留池或在途读者 | 记录 birth、发布、最后使用和 retire；身份未增加却报容量增加时查别名重复计数 |
| 标量读取后时间突变 | 隐式 partial evaluation、同步或输出缓冲 | 将读取移至完整根求值后并记录完成事件；差异消失时修正原计时范围，仍存在则查排队及主机负载 |
| 外部访问偶发错误 | 未跟踪别名、回收过早或缺少可见性 | 加同步或私有复制，重放同一轨迹；同步消除错误支持协议解释，仍错则查数值和地址范围 |

随章 tools/check_k_hw_007_full.py 是标准库、确定性、离线、只读的 CPU 模型。它用按层完整前缀参考核对逐 token 私有增量；覆盖部分 prefill、完整推进、缓存复用、满 KV 无 logits 的私有重算、多步追加、RNG、取消、失败和迟到最后使用事件。参考使用整数因果加权归约，刻意不模拟真实 softmax 或 GPU 算术。对象身份检查验证只读前缀共享与候选隔离；图模型检查独立写回根，物理事件扫描对照按时刻并集，累计读取公式对照逐查询访问枚举。

采样检查直接执行两种编排：主机路径包含实际的模型 HOST_VISIBLE 操作，设备路径构造并求值具有显式依赖的采样图。空 logits 可见性访问和未知根均触发断言；无采样设备路径另检查 EVAL 之前 token 已为空、rho_next 已等于冻结 rho。参考按完整前缀边界决定是否允许采样，并从独立完整前缀结果计算期望输出。检查也将这两条编排接入同一提交与多步追加轨迹，而非在测试外先排除部分 prefill。

负对照实际进入相同判据，包括主机先访问空 logits、设备无条件添加采样输出根、中间前缀采样、完整命中停滞、复制旧前缀、提前发布、改写已提交状态、错误推进 k、错误 RNG、取消后提交、重复或遗漏容量余量、别名重复计数，以及 prefill 漏计查询。它们验证局部模型能够拒绝具体错误，不能证明真实后端遵守协议。

本轮工具内 V8 控制流模型实际核对了 230 条主机或设备路径，并检出上述两个采样分支故障变体；交付 Python 脚本尚未在作者环境执行。前轮协调者提供的 Python 成功记录只绑定前轮脚本，不作为本轮脚本的运行结果。未运行 MLX、Metal 或 GPU，没有真实带宽、stream 可见性、内存压缩/换出、服务延迟或 Agent 使用效果证据。设备实验还需报告版本、输入、布局、并发、结果根、完成事件、事务口径和测量不确定性。
