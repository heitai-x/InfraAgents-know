# K-HW-010：CPU GEMM/GEMV：寄存器、缓存与线程划分

CPU 线性层需要在存储层之间移动权重、激活和输出，同时保持足够多的独立乘加链。优化的依据是数据在何处重用、由谁读取、何时写回，以及准备和同步能否摊销。GEMV、小批 GEMM 和大 prefill GEMM 的重用条件不同，不能仅靠增加线程数统一处理。

## 问题、输入输出与完成条件

采用逻辑关系 Y=XW，X 为 M×K，W 为 K×N，Y 为 M×N。M=1 时是 GEMV。更完整的逐元素契约为

Y[m,n]=Convert_y(φ(Σ_k X[m,k]W[k,n]+b[n]+βY_old[m,n]))。

未启用的 bias 取零，β∈{0,1}；β=0 时不读取旧输出，未启用激活时 φ 为恒等函数。乘法、局部累加、宏块累加、epilogue 和输出转换的精度分别声明。这里的分块正确性推导采用有限输入的精确算术；真实浮点还需要误差与非有限值策略。

输入包括形状、存储偏移、各轴 stride、dtype、线程数及放置、宏块 m_c/n_c/k_c、微块 m_r/n_r、输出处理方式，以及预打包权重的参数身份和布局版本。元素宽度记为 s_x、s_w、s_y，累加状态宽度为 s_acc，单位均为字节。stride 则以元素计，不能与字节宽度混用。

若其他条目采用 W[N,K]、X[K,M]、Y[N,M]，应整体转置逻辑视图，同时映射 bias、量化尺度、零点和打包轴；shape 相容不能证明下标或参数身份相容。

一次输出块的状态为：取得独占写权 → 输入 panel 就绪 → K 归约部分完成 → 完整归约后执行 epilogue → 输出发布。核心不变量是：每个有效输出恰好有一个最终写者；每个有效 k 恰好贡献一次乘积；输入先写完再读，最后读者结束后才覆盖；epilogue 只对完整归约执行一次。

M=0 或 N=0 时没有输出元素；K=0 时归约为零，非空输出仍须执行 bias、旧输出累加、激活与转换。输出发布表示所有必要写入已经达到消费者所需的完成边界，不只是任务已经入队。

## 合法性与方案选择

合法条件包括非负整数形状、正整数 tile 和线程参数、足够宽的地址计算、有效加载与写回边界，以及输出与仍被读取的输入不重叠。若允许输入 view 重叠，它必须保持只读；输出 view 的有效位置应具有互不重叠的存储位置。原地覆盖需要另证不会破坏后续输入。

K 分段必须互不重叠且覆盖 [0,K)。split-K 可以产生空段，但不能丢失非空段，也不能把尚未完成的部分和当成完整结果。bias、旧 Y 和非线性处理应放在合并之后；分别对部分和应用 φ 通常不等价。

尾部有两种合法路径：屏蔽无效乘积，或在消费者定义的表示中补数学中性值。有限实数 GEMM 可使用零填充；量化码 0 未必解码为实数零，需要按零点、分组和补偿契约处理，详见 [CPU 低位执行](../frameworks/cpu-quantized-kernels.md)。加载掩码与最终 store 掩码各自必要，不能用正确 store 掩盖此前越界读取。

改变分块、FMA、归约树、线程合并顺序或累加精度可能改变浮点结果。逐位一致、容差一致、argmax 一致和任务质量一致是不同结论。输入存储为 BF16 或 INT8 也不证明当前二进制使用对应指令；硬件能力、操作系统状态、编译目标、布局与实际 dispatch 必须共同成立。

沿 N 向量化、沿 K 点积、是否打包、共享或私有 panel、沿 M/N/split-K 划分都是选择空间。它们满足同一函数后，再比较实际资源成本。

## 分块算法与可重建的打包布局

以下给出一种行主序逻辑视图、微 panel 打包和显式宏块累加缓冲的完整算法。它便于说明数据流，不宣称等同于某个 BLAS 的最优循环顺序。

对 X，元素地址为 base_X+s_x(o_X+m·d_Xm+k·d_Xk)；W 和 Y 分别使用其 k/n、m/n stride。连续行主序才可化简为 mK+k、kN+n 和 mN+n。

令 m̂=ceil(m_c/m_r)m_r，n̂=ceil(n_c/n_r)n_r。为一个 K panel 分配 m̂k_c 个 Xp 元素和 k_cn̂ 个 Wp 元素。局部下标 i、j、q 的打包元素偏移为

idx_Xp(i,q)=(floor(i/m_r)k_c+q)m_r+(i mod m_r)，

idx_Wp(q,j)=(floor(j/n_r)k_c+q)n_r+(j mod n_r)。

因此一个微块在每个 q 取得连续 m_r 个激活和连续 n_r 个权重。超出有效矩阵、当前宏块或尾 K 的位置填零；这些位置不发出源读取。

```pseudocode
算法 PackedGEMM
输入：X[M,K]、W[K,N] 的只读 strided 视图；独立输出 Y[M,N]
      正整数 m_c,n_c,k_c,m_r,n_r；bias、β、φ 与转换契约
输出：完整 Y

校验形状、地址范围、输出所有权和数值契约
若 M=0 或 N=0：结束
m̂=ceil(m_c/m_r)m_r；n̂=ceil(n_c/n_r)n_r
对 n0=0,n_c,... 且 n0<N：
  对 m0=0,m_c,... 且 m0<M：
    初始化 Cacc[m̂,n̂]=0，使用宏块累加精度
    对 k0=0,k_c,... 且 k0<K：
      初始化 Xp[m̂*k_c]=0、Wp[k_c*n̂]=0
      对 i∈[0,m_c)、q∈[0,k_c)：
        若 m0+i<M 且 k0+q<K：
          Xp[idx_Xp(i,q)]=按实际 stride 读取 X[m0+i,k0+q]
      对 q∈[0,k_c)、j∈[0,n_c)：
        若 k0+q<K 且 n0+j<N：
          Wp[idx_Wp(q,j)]=按实际 stride 读取 W[k0+q,n0+j]
      等待本轮全部打包写入完成，建立消费者所需可见性
      对 mi=0,m_r,... 且 mi<m_c：
        对 nj=0,n_r,... 且 nj<n_c：
          将 Cacc[mi:mi+m_r,nj:nj+n_r] 载入寄存器微块 R
          对 q∈[0,k_c)：
            对 r∈[0,m_r)、c∈[0,n_r)：
              R[r,c]+=Xp[idx_Xp(mi+r,q)]*Wp[idx_Wp(q,nj+c)]
          将 R 保存回 Cacc 的对应位置
      本轮所有 panel 读者结束后，才允许覆盖 Xp、Wp
    对 i∈[0,min(m_c,M-m0))、j∈[0,min(n_c,N-n0))：
      z=Cacc[i,j]+启用的 bias[n0+j]
      若 β=1：z+=Y_old[m0+i,n0+j]
      Y[m0+i,n0+j]=Convert_y(φ(z))
全部必要输出写入完成后，发布 Y
```

处理 t 个 K panel 后，有效 Cacc[i,j] 等于对应输出在 [0,min(tk_c,K)) 上的乘积和。所有补出的位置为零，完整微块计算不增加有效结果。最后一个微块可能超出 m_c/n_c，因此打包和写回还须服从当前宏块边界，否则会与相邻宏块重复处理有效元素。

这里 Cacc 是内存中的宏块状态，只有当前 R 是寄存器状态。每个 K panel 都重新载入并保存 R，不能把整个 m̂×n̂ 宏块写成始终驻留寄存器。另一种循环把完整 K 归约放进一个微块，可以减少 Cacc 往返，但会改变输入 panel 的重读和可共享范围，必须重新列账。

固定权重可提前按上述 Wp 布局打包。替换第一个算法中的 PackW 时，权重值、有效 K/N、微块参数、dtype、布局版本必须一致。新权重版本先建立并发布新副本；旧调用保持旧副本到最后读者结束。激活属于本调用，不能跨请求复用旧 Xp。预打包是独立候选，其读取和准备账不能继续采用每宏块重新 PackW 的账。

## 向量通道、寄存器链与两条 GEMV 路径

假定抽象向量宽度为 V 个元素，沿 N 向量化时，微块中第 v 个向量的 lane ℓ 对应 j=nj+vV+ℓ。每个 r 广播 Xp 中的一个激活，加载 Wp 中相邻通道的权重，更新同一输出行的向量 accumulator。j≥nj+n_r 的 lane 不参与，最终输出仍受全局边界保护。各 lane 沿 K 保持自己的累加链，无需跨 lane 水平归约。

这个映射从逻辑输出、原始 stride 地址、打包偏移、向量 lane 一直连接到最终 store。实际机器的 V、指令支持、掩码和寄存器分配必须来自目标路径；这里没有指定某条 ISA 的硬件常数。

若每周期可发射 U 条相关向量乘加、依赖延迟为 L 周期，维持该理想发射率至少需要约 UL 条独立累加链。这只是必要的调度条件，还受加载、前端、端口和频率限制。微块约需 m_r·ceil(n_r/V) 个向量 accumulator，另加权重向量、广播、预取和 epilogue 临时量。增大微块可以增加链数，也可能超出寄存器预算而 spill。

M=1 时还可以采用 K 连续的权重布局，例如 Wcol[n,k]=W[k,n]，沿 K 做点积。此时 lane ℓ 累加 k=a+ℓ，对每个输出形成 V 个部分和，最后必须合并。

```pseudocode
算法 GEMVAlongK
输入：x[K]、K 连续的 Wcol[N,K]；正整数 V；输出处理契约
输出：y[N]

校验布局、边界和输出写权
对每个独占输出 n∈[0,N)：
  初始化 lane_sum[0:V]=0
  对 a=0,V,... 且 a<K：
    对 ℓ∈[0,V)：
      k=a+ℓ
      若 k<K：lane_sum[ℓ]+=x[k]*Wcol[n,k]
      否则不读取输入、不更新部分和
  z=按声明顺序合并全部 lane_sum
  对 z 执行一次 bias、旧输出累加、φ 和转换，写回 y[n]
输出写入完成后发布 y
```

K=0 时所有 lane_sum 为零，仍执行输出处理。沿 N 的路径减少水平归约，但依赖 N 连续的权重访问；沿 K 的路径适合 K 连续制品或很窄的 N，却支付水平归约与可能的重排。不能同时采用两者各自较低的准备和归约成本。

## 线程划分、split-K 与完成证据

沿 N 划分时，线程 t∈[0,T) 负责 [floor(tN/T),floor((t+1)N/T))。沿 M 划分对称。二者使线程独占输出，无需跨线程最终归约；T 大于被划分轴时存在空区间，空线程不写输出。

沿 N 划分会让多个线程读取 X，沿 M 划分会让多个线程读取 W。它们在私有 cache、共享 cache 和主存上的重复程度不同。二维划分可同时限制重复和增加块数，但也改变 panel 分享、容量及 NUMA 放置。

输出独占不等于没有一致性流量。行主序 Y 的不同列可能位于同一 cache line；相邻线程写不同元素仍可能造成伪共享。按连续块划分、对齐或调整布局是候选，应结合实际行跨度和并发写入比较。

M/N 并行块不足时可切 K。以下 P 是分段数，不要求等于物理线程数；执行池可以顺序或并行处理这些段。

```pseudocode
算法 SplitK
输入：X[M,K]、W[K,N]；正整数 P；同一调用身份与输出处理契约
输出：完整 Y

为每个 p∈[0,P) 分配零部分矩阵 Z_p 和未完成记录
对每个 p：
  a=floor(pK/P)；b=floor((p+1)K/P)
  对每个有效 (m,n)：
    Z_p[m,n]=0
    对 k∈[a,b)：Z_p[m,n]+=X[m,k]*W[k,n]
  完成本份写入后，发布属于本调用和 p 的唯一完成记录
等待全部 P 份不同的完成记录，建立部分矩阵读取可见性
对每个有效 (m,n)：
  z=按声明顺序或归约树合并全部 Z_p[m,n]
  只执行一次 bias、旧 Y 累加、φ 与转换，写回 Y[m,n]
最后部分和读者结束后回收工作区；输出完成后发布 Y
```

P>K 时允许空段，其数学贡献为零，但仍须满足所选完成协议。K 覆盖检查和完成记录检查承担不同责任：逐 k 覆盖无法发现漏掉空段的完成记录；完成数等于 P 也无法排除重复记录替代缺失记录。

数值相等同样不能证明工作覆盖完整。本轮失败用例为 x=(1,−2,3,4,−5,6,7)、w=(2,1,−1,3,2,−2,1)，K=7、P=3。三个区间为 [0,2)、[2,4)、[4,7)，部分和分别为 0、9、−15，总和 −6。省略首段仍为 −6，因为首段贡献 2−2=0。正确修复是保留这个抵消反例，以实际消费的 k 次数和分段身份检出缺失，再用非零贡献用例确认数值比较器能够拒绝漏段。

例如 x=(1,2,3,4,5,6,7)、w 全为 1，同样分段得到 3、7、18。正确结果为 28，漏首段得到 25。两类检查互补，不能通过删除抵消输入来宣称覆盖检查已经充分。

提前执行 epilogue 也有直接反例。两段为 2、−3，bias 为 1、φ=ReLU：完整合并后为 ReLU(2−3+1)=0；各段分别加 bias 并激活再相加得到 3。这改变函数，不能归为浮点舍入差异。

## 六类成本与同一候选的资源账

有效乘加主项按每次乘和加各计一次，为 F=2MKN FLOP；bias、激活、归约、打包和转换另计。第一个算法完整计算补齐的微块和 K panel，其执行乘加量为

F_exec=2·ceil(M/m_c)·ceil(N/n_c)·ceil(K/k_c)·m̂·n̂·k_c。

它可能高于有效 F。该式对应完整零填充计算；真正跳过尾部算术的候选应按实际执行重新计数。K=0 时乘加项为零，epilogue 仍非零。

设该路径有效计算率为 P_eff，则 T_comp≥F_exec/P_eff。P_eff 受独立链、指令、加载、SMT、频率和线程实际额度影响，不能直接用标称峰值代替。

### 逻辑读取、打包交通与累加缓冲

一次冷的、完整读取的逻辑最小字节为

D_min=s_xMK+s_wKN+s_yMN。

β=1 时另加旧输出读取。这个逻辑量尚未描述 cache 命中、写分配和真实主存事务。

对第一个算法的非预打包路径，令 B_M=ceil(M/m_c)、B_N=ceil(N/n_c)、Q=ceil(K/k_c)。从原始视图读取的有效元素次数恰为

L_X=B_N·MK，L_W=B_M·KN。

因为每个列宏块重新打包 X，每个行宏块重新打包 W。尾部零初始化不读取源。这个账可以通过实际 PackX/PackW 的读取轨迹核对；它不是主存流量公式，同一源元素可能从 cache 命中。

在此之外，Xp/Wp 的目的写入和消费者读取、Cacc 的往返都属于 scratch 交通。若 Cacc 在所计层级完全物化，清零一次、每个 K panel 读写一次、最后读取有效元素，则其逻辑字节为

D_Cacc=[(1+2Q)B_MB_Nm̂n̂+MN]s_acc。

编译器保留部分状态或 cache 命中会改变跨更低层的真实事务；不能把这个逻辑式直接称为 DRAM 字节。宏块工作集主项为

S_macro=s_xm̂k_c+s_wk_cn̂+s_accm̂n̂。

若还有当前寄存器微块、预取或转换缓冲，按实际同时存活对象补充。累加宽度应使用 s_acc，不能无条件使用输出宽度 s_y。

独立复制 B 字节的打包操作至少读源 B、写目的 B，重排、复制 lane 或转换可能增加工作。若源读已包含在 L_X/L_W 中，汇总同一层交通时只补充尚未计入的目的写与后续读取，不能再把完整 2B 复制流量重复相加。跨不同 cache 层级则分别列账。

固定权重预打包改变准备和源读取：首次创建副本支付源读与目的写，复用调用读取打包副本，不再每次读取原布局做相同转换。设一次性成本 T_p、每次净节省 ΔT、复用 R 次，在其余条件相同且 ΔT>0 时，严格收益条件为 RΔT>T_p；等号只是收支相抵。

### GEMV 与小批 GEMM 的条件化算例

取 K=N=4096、FP32 输入/权重/输出、β=0、无 bias。M=1 时 F=33,554,432 FLOP，权重 64 MiB，输入和输出各 16 KiB，D_min=67,141,632 B，强度为 1024/2049≈0.49976 FLOP/B。假定同一读取资源可持续提供 80 GiB/s，仅权重的一次读取下界为 0.78125 ms。这是设定带宽下的下界，不是实测总延迟。

M=32 时 F=1,073,741,824 FLOP，输入输出各 0.5 MiB，D_min=68,157,440 B，强度为 1024/65≈15.754 FLOP/B。只计权重会错误得到 16。若按 M 分成四组，各组都不能通过共享 cache 复用权重，权重请求主项可达 256 MiB；若共享 cache 保留了它，主存流量可以更低。必须说明读取层级和复用条件。

### cache 与 TLB 是两条约束

连续非空字节区间 [a,a+B) 在页长 P_page 下的页数为

floor((a+B−1)/P_page)−floor(a/P_page)+1。

B=0 时为零。使用页内偏移 o∈[0,P_page) 才可简写为 ceil((o+B)/P_page)。有 stride 的子矩阵需要枚举实际页集合，不能把有效字节数直接除页长；例如三个相隔 4096 B 的行各读取 8 B，触及三页，打包后的 24 B 可以只占一页。

Goto §4.2.3 的一个共存模型是 T_A+2(T_B+T_C)≤T_TLB，其中 A 是仍需复用的打包 panel，B/C 是当前和下一组块的翻译。因子 2 为替换期间保留 A 留出余量，不表示所有实现必须分配两份用户缓冲，也不是前述任意循环的统一必要条件。

单独采用该模型，令 m_c=240、k_c=256、n_r=4、元素为 8 B、页为 4096 B，三个对象独立且页对齐。A 为 491,520 B、120 页，B 为 8192 B、2 页，C 为 7680 B、2 页；完整共存需要 128 页。125 个可用条目不足，而简单相加得到 124，会错误通过。现代多级 TLB、组相联、共享页与替换策略需目标证据，不能从这项页模型推导确定停顿时间。

### 通信、同步、准备与驻留

普通输出独占不需要跨线程归约，但共享 panel 仍有一致性与同步成本。split-K 若每份保留完整 M×N 部分和，工作区为 P·MN·s_acc，部分和写出和重读主项约 2P·MN·s_acc，最终输出另计；合并约需 (P−1)MN 次加法。按输出块分批处理可降低峰值工作区，同时增加调度或同步次数。

共享 panel 有两个边界：打包完成后才能消费，最后读者完成后才能覆盖。双缓冲可允许准备下一 panel 与当前计算重叠，但增加容量和完成状态；提前覆盖不会因最终再等一次而恢复已经读错的数据。

跨 NUMA 域还要分别统计远端权重/激活读取、部分和或中间输出的传递。每域私有预打包副本可能减少远端读取，却增加容量、创建和版本更新成本。跨域总字节不能无条件除以全机带宽之和。

驻留包括原权重与打包副本、各线程 Xp/Wp、Cacc、split-K 部分和、输出、转换缓冲和完成记录。物理共享对象只计一次；每域私有副本分别计；旧新版本交替期间的共存也要计入峰值。预留池与池中已经物化的对象不能重复相加。

若计算与同一资源的访存可重叠、随后同步必须串行暴露，可用 T_stage≥max(F_exec/P_eff,D_layer/B_eff)+T_sync。打包、归约或同步能够重叠时，应按依赖与共享资源重算，不能机械相加，也不能把必需串行阶段只取最大值。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的关系 | 调整或放弃的候选 |
|---|---|---|
| M=1、N 较大 | 输出独占和逐 k 覆盖 | 沿 N 并行可提供足够输出；比较 N 连续与 K 连续布局，避免无收益的 split-K |
| M/N 都很小 | 完整归约与单次 epilogue | split-K 可增加工作块，但需支付部分和、屏障和合并；固定开销主导时回退少线程 |
| M 增大 | 同一权重服务更多行 | 重算权重复用、Cacc、寄存器链和计算下界，允许转向矩阵微内核 |
| K 很小 | 数学输出不变 | 打包、调用和同步可能主导，比较直接小内核 |
| 权重冷且调用少 | 参数函数不变 | 摊销不足时放弃完整预打包；分别报告首次准备和调用 |
| 权重长期复用 | 版本匹配的副本可只读共享 | 预打包并复用；权重或布局变化时重建，保护旧读者 |
| 工作集越过 cache | 有效归约域不变 | 重算各层请求和事务，停止沿用热权重假设 |
| 页长、偏移或 stride 改变 | 有效元素身份不变 | 重建页集合、对齐、打包收益和碎片 |
| 跨 NUMA 或请求并发增加 | 每请求输出与完成责任不变 | 重测远端读取、cache 竞争、配额和队列，调整线程及副本预算 |
| dtype 或指令路径改变 | 形状和覆盖关系不变 | 重算转换、尺度、累加误差、寄存器和真实 dispatch |
| β 从 0 改为 1 | 每个输出单次最终提交 | 加入旧输出读取，检查旧值生存期和别名 |

例如 M=N=1、K=4096、P=32 时，每段仅约 128 个乘积，增加的屏障和合并可能超过计算收益；N 很大时沿 N 已有足够独立输出，再切 K 可能只增加成本。固定权重长期复用可以摊销打包，但格式频繁变化或部署寿命短时选择可能反转。

从单算子转向多请求服务后，更多算子线程可能挤占分词、调度和响应执行。应固定总 CPU 预算比较请求并行与算子并行，并把等待和尾延迟纳入决策，不能继承离线单调用的最佳线程数。

## 诊断、竞争解释与反证修正

先核对函数和工作覆盖，再解释性能。数值参考直接遍历有效 m/n/k，不复用打包结果；布局检查使用带偏移和非连续 stride 的视图，并在每次实际源读取时拒绝越界。线程与 split-K 另查唯一写者、逐 k 消费次数和完成身份。

| 观察 | 竞争解释 | 区分实验与预测 | 反证后的修正 |
|---|---|---|---|
| 加线程后吞吐平台 | 带宽饱和，或同步/并行度受限 | 固定形状与放置扫描线程数，联合看读取速率、运行和等待 | 带宽仍低且等待增长时，降低带宽解释，查同步和可用输出块 |
| panel 或 stride 改变出现台阶 | cache、TLB、地址冲突或计算量变化 | 固定有效工作，改变偏移与 stride，枚举页集合并核对事件和填充执行量 | 页集合和相关事件不变时，不能继续只归因 TLB |
| 大微块更慢 | spill、加载端口受限或块数不足 | 查生成资源与局部访存，比较微内核和完整调用，缩短临时量生存期 | 无 spill 且并行度足够时，转查布局、端口和频率 |
| split-K 更慢 | 工作区流量、屏障、归约或负载不均 | 固定 M/N 扫 K 与 P，分开主体和合并；固定项主导时，长 K 的相对开销应下降 | 长 K 仍恶化时，检查流量与共享资源，不能只用启动解释 |
| 打包后稳态快、首调用慢 | 一次性准备换取复用 | 分开 pack 和复用调用，扫描 R，对照严格摊销条件 | 稳态没有收益时，撤回原摊销预测 |
| IPC 降低但总时间减少 | 指令数减少、cycles 减少或频率变化 | 同范围记录 instructions、cycles、墙钟与完成工作 | IPC 单项不能判定退化；范围不匹配时停止计算比值 |
| 最终数值相等 | 实现正确，或缺项恰好抵消 | 保留零贡献段，核对逐 k 覆盖，再用逐位置基向量和非零段作数值干预 | 数值相等但覆盖失败时，修复工作划分，不能关闭问题 |
| 单算子快而服务 p99 差 | 线程挤占、cache 驱逐或队列增长 | 固定请求到达和总预算，限制算子线程，记录各阶段等待 | 等待与资源未对应变化时，保留其他解释 |

[S-PERF](../sources/S-PERF.md) 的固定手册区分进程、线程、CPU 集合、系统、cgroup、事件组和聚合范围，并说明计数运行比例与缩放。IPC 的分子分母应有可比范围和时段；事件未共同调度或工作非平稳时，比值需要额外限定。这里没有目标机器 PMU 观测。

计时分开首次打包、首次调用和稳态复用；冷/热权重的建立方式、CPU 集合、NUMA、并发与计时完成边界分别记录。只有相同完成工作和数值契约下的比较才能用于选择。

## 检查范围与未测边界

配套文件为 tools/check_k_hw_010_full.py。它使用 Python 标准库，确定性、只读、离线，不调用项目或上游实现。检查以独立稠密参考核对完整打包、宏块、微块和 epilogue，覆盖正 stride 的转置视图、偏移、非整除维度、微块大于宏块、负数、空 M/N 和 K=0；实际读取次数与条件化源读取公式对照，实际乘积次数与填充执行量对照。

split-K 检查同时保留原抵消回归、非零贡献漏段、逐位置基向量、P>K 空段，以及缺失/重复完成记录。原反例漏首段数值仍为 −6，但消费覆盖明确缺少 k=0、1；独立非零用例则由 28 变为 25。其他负对照包括非零 K 填充、列区间重叠/缺失、漏水平归约、提前 epilogue、页数向下取整、TLB 共存漏因子、只计权重字节和非严格摊销。

本轮实际执行的是工具 V8 中的整数交叉模型，涵盖 720 组 strided GEMM、99 组 split-K 形状、36 组 lane 点积，以及页集合和成本复算。当前工具没有 Python 执行入口，交付的完整 Python 脚本尚待协调者隔离执行；V8 结果不能写成该 Python 文件已经通过。

这些模型不执行目标 ISA，不验证真实寄存器分配、FMA 舍入、cache/TLB 事务、线程可见性、NUMA 页迁移、权重版本并发发布、内核 dispatch 或服务性能。目标机器仍需构建产物、受控运行和完成依赖证据。CPU 软件模型不构成 GPU 数值、同步、通信或吞吐实测，也不证明知识改善了 Agent 的构建效果。
