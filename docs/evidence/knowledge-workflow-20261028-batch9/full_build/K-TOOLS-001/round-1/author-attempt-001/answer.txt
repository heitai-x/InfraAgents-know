{"chapter":"# K-TOOLS-001：可观测性：执行事件与采集事件的映射\n\ntrace 是由采集范围和工具机制生成的观测，不是系统全部执行事实的无损副本。一个记录从发生到能被查询，至少要经过探针、运行时收集、缓冲、导出、查询和关联；任何一层缺失，都可能让正确的问题得到错误的“没有发生”。\n\n## 问题与观测对象\n\n观测问题应写成 Q=(k,S,W,C)，其中 k 是事件类型，S 是被观察对象或对象集合，W=[W0,W1) 是查询窗口，C 是主张类型。主张可以是“存在一个事件”“某对象在此窗口内没有事件”“事件持续多久”“事件属于哪个请求”或“两个事件有因果关系”。这些主张需要的证据不同。\n\n把一个执行事件实例写成：\n\ne=(d,k,s,z,I,a,g,p)\n\n其中 d 是采集域，k 是事件种类，s 是逻辑主体，z 是进程、线程、设备、context、stream、QP 等作用域，I=[t_s,t_e) 是半开时间区间且 t_e≥t_s，a 是尝试序号，g 是对象代次，p 是负载或字段。逻辑主体 s 可以是请求、批次、对象范围或队列项；它不等于地址、线程号或 correlation ID。\n\n采集配置可以抽象为：\n\nD：启用的采集域集合；\nP、H：进程、线程、设备、队列等作用域；\nW_c：采集时间窗口；\nB、F：缓冲容量、刷新或导出策略；\nX：导出表和字段；\nQ_q：查询窗口、过滤条件和关联规则。\n\n记录 r 对查询可见，不等于事件 e 发生；它表示 e 在某个被选中的观测路径上留下了记录。用 Obs(e;c;Q_q) 表示这条路径成功，它至少要求：事件种类被采集器支持并启用，主体和作用域被覆盖，事件落在采集与查询的可见范围内，记录没有被缓冲丢弃，导出含相应表，查询条件没有把它过滤掉，并且需要请求归属时存在有效关联。\n\n因此，“无记录”不是单一状态。至少应区分：\n\n- 工具不支持该事件类型；\n- 工具支持但本次采集没有启用该域；\n- 域已启用但进程、线程、设备或队列不在作用域；\n- 事件在采集窗口外；\n- 事件在窗口内但被缓冲覆盖、丢弃或截断；\n- 导出没有该表，或有表但字段或值为空；\n- 导出有记录，但查询窗口或过滤条件把它排除；\n- 记录存在但无法与目标请求关联；\n- 记录真实存在并已成功关联。\n\n这些状态不能都用“0 条”表示，更不能把最后一种以外的状态解释成成本为零。\n\n## 观测包络与状态机\n\n把一条事件记录的状态写成离散层，便于定位证据断点。状态是逐事件的，不是整个采集会话只有一个状态。\n\n| 层 | 状态 | 已证明 | 仍未证明 |\n|---|---|---|---|\n| 0 | UNSUPPORTED 或 DISABLED | 当前工具或本次配置不提供该域 | 事件没有发生 |\n| 1 | OUT_OF_SCOPE | 记录若发生也不在本采集的主体或设备范围内 | 其他进程或设备没有执行 |\n| 2 | OUT_OF_WINDOW | 事件在采集窗口之外，未被请求覆盖 | 窗口外没有执行 |\n| 3 | LOST 或 UNKNOWN_LOSS | 记录可能被缓冲、刷新或导出截断 | 未记录的部分成本为零 |\n| 4 | NOT_EXPORTED | 导出没有相应表或字段 | 原始采集中一定没有该记录 |\n| 5 | EXPORTED_NOT_QUERIED | 表存在，查询过滤或时间条件排除了记录 | 系统没有执行 |\n| 6 | PRESENT_UNJOINED | 记录在作用域和窗口中存在，但缺少请求身份 | 记录属于哪个请求 |\n| 7 | PRESENT_JOINED | 记录存在且与目标对象有可核对关联 | 关联一定表示因果或独占 |\n\n状态推进不是自动可逆的。一个记录到达第 7 层，仍可能只是同一物理工作的重复导出；一个记录停在第 5 层，不能把其时间从总成本中删掉；一个记录停在第 0 层，不能把“未观察”改写成“未执行”。\n\n时间戳也有层。事件发生时刻、写入采集缓冲时刻、刷新到存储时刻、导出处理时刻和主机读取回调时刻不是同一个量。只记录回调时刻，会把完成、通知、调度和排队叠加在一起；只记录 host API 开始时刻，也不等于设备工作开始。导出同时保留原始时间戳和转换后时间戳时，不能混用两个时间域。\n\n## 覆盖矩阵与缺失分类\n\n覆盖审计需要针对问题保留对象和作用域，而不是只记录“已开启 profiler”。下表给出不同问题和它们至少需要的观测；表中列出的信号是所需证据的类型，不保证任一工具默认提供全部字段。\n\n| 需要区分的问题 | 至少需要取得的观测 | 单独不足的信号 |\n|---|---|---|\n| 主机线程在计算、阻塞还是等待 | 线程运行与阻塞区间、调用路径、同步或系统调用包装、CPU 采样或上下文切换 | 进程总 CPU 百分比；只有 GPU kernel 表 |\n| 设备是否执行、何时开始和结束 | API 记录、GPU kernel 或 copy 的设备区间、设备与 stream 作用域、关联字段 | GPU 利用率；API 调用时长；kernel 名 |\n| 框架算子的高层身份和输入形状 | 算子记录、shape、调用栈、设备工作关系、所选记录窗口 | 仅按 kernel 名聚合；预热或未记录窗口 |\n| 文件读取是页缓存命中、排队还是设备服务 | 文件范围、软件队列、硬件派发、完成标签、字节数和错误状态 | 单个 read 调用的总耗时 |\n| RDMA 是提交、CQE、通知还是应用消费 | WR 与 wr_id、CQ 与 CQE、状态、事件通道、应用消费点 | 仅收到一个 CQ 事件；仅统计网络字节 |\n| 自定义范围是否真的对应设备执行 | NVTX 或框架范围的 domain、开始结束关系、是否有设备投影 | 仅有 CPU 范围；未闭合范围 |\n\nNsight Systems 的 CUDA 记录分成 API 调用和 GPU workload 两类，二者可以借助 correlation 字段关联；但 correlation 只说明某次 API 与某段 GPU 工作的匹配关系，不等于请求身份，也不能跨进程或跨设备无条件复用。CPU 指令指针采样、线程上下文切换和系统级事件计数是另外几类观测：系统级 CPU 事件计数不直接归属于某个进程或线程，采样间隔还可能因操作系统节流而变得不规则。\n\n覆盖窗口可以用半开区间合并表示。对查询窗口 W_q 和一组满足域、作用域及无损失条件的采集块 C_i，覆盖集合是：\n\nCov(W_q) = ∪_i (C_i ∩ W_q)\n\n只有 Cov(W_q)=W_q 时，才能把该窗口称为完整覆盖。端点相接的 [0,5) 与 [5,10) 可以覆盖 [0,10)；[0,5) 与 [6,10) 留下 [5,6) 的缺口。零长区间 [5,5) 不贡献覆盖；负长度区间必须拒绝。\n\n缺口不是唯一失败。若采集块本身可能丢记录，即使集合覆盖了 W_q，也不能据此证明没有事件。若窗口是从更大的导出结果中裁剪出来的，事件可能开始于 W_q 之前、结束于 W_q 内部，裁剪只保留了尾部；因此“事件开始于 W_q 内”和“事件在 W_q 内活动”是不同主张。后者需要额外的起始记录，或把采集窗口向前扩展至少一个可能的最大事件持续时间 L_max。没有 L_max 的记录，只能声明有限范围。\n\n```pseudocode\n算法 覆盖审计(chunks, W_q, 所需域, 所需作用域)\n输入：采集块列表，每项含 [a,b)、域、作用域、损失状态；查询窗口 W_q=[W0,W1)\n输出：覆盖缺口列表；空列表仅表示在所声明条件下没有被检出的窗口缺口\n\n1. 验证 W0、W1 为有限整数或可比较时间单位，且 W0<=W1；不满足则拒绝\n2. 若 W0==W1，返回 EMPTY_QUERY，不把空查询当成完整覆盖\n3. merged=空；丢弃域不匹配、作用域不匹配或损失状态未知的采集块\n4. 对每个可用 [a,b)：\n     若 b<a，拒绝\n     c=max(a,W0)；d=min(b,W1)\n     若 c<d，把 [c,d) 加入 merged\n5. 按开始时间、结束时间排序 merged，并合并相交或端点相接的区间\n6. cursor=W0；gaps=空\n7. 对 merged 中每个 [s,e)：\n     若 e<=cursor，继续\n     若 s>cursor，记录缺口 [cursor, min(s,W1))\n     cursor=max(cursor,e)\n     若 cursor>=W1，停止\n8. 若 cursor<W1，记录尾缺口 [cursor,W1)\n9. 返回 gaps\n```\n\n这张算法只审查窗口和采集块。它不证明采集块内部没有丢失，也不证明每个事件都已从设备缓冲刷新到导出文件。\n\n## 事件身份、时间窗与连接\n\ntrace 中的 correlation ID 是连接记录的工具字段，不是全局主键。安全的物理工作键至少应包含采集会话、进程或设备作用域、域、context 或 stream、correlation 或 launch 标识，必要时还要包含对象范围和代次。若两个进程恰好有相同的 correlation 数值，它们不应被合并；若一个 API 启动多个 kernel，也不能只保留一个 correlation 就丢掉其余实例。\n\n建议区分：\n\n- physical_id：设备上实际执行的一次 kernel、copy、DMA 或 WR 完成；\n- logical_id：请求、批次、对象范围或一次尝试；\n- map(logical_id)：与该逻辑对象相关的物理工作集合；\n- map(physical_id)：该物理工作服务的逻辑对象集合。\n\n一个批处理 kernel 可以同时服务多个请求，因此 map(physical_id) 的大小可以大于 1。一个请求也可能触发多次重试、转换或复制，因此 map(logical_id) 也可以包含多个物理实例。不能把两个方向的映射都假定为一对一。\n\n两段半开区间的重叠长度为：\n\no(I,J)=max(0, min(e_I,e_J)-max(s_I,s_J))。\n\n存在性只要求 o(I,J)>0；完整持续时间要求 I 被查询窗口或采集窗口完整包含；区间并集要先去重，再做覆盖长度。只有完整包含的记录才能直接声称“这段执行全部在窗口中”，边界处的部分记录只能支持部分活动或位置未知。\n\n时间戳不确定性也必须进入判断。若某个记录的时间有误差界 ε，不能把 t+ε<q0 与 t−ε<q0 当成同一件事；当记录落在查询边界附近时，应返回 UNKNOWN_AT_BOUNDARY。若跨主机时钟满足 t_B=t_A+δ，而 δ∈[δ_lo,δ_hi]，那么一条 A 域记录只有在映射后确定落在 B 域查询内时，才能作为 B 域窗口内的完整证据；边界落在可能偏移范围内时，不能把“图上看不见”写成“没有发生”。\n\n## 从记录到结论的完整算法\n\n下面的算法把“有记录”“有表但空”“无法关联”和“可以支持无事件”放在同一条审计路径中。它返回的是证据状态，不是把空结果直接变成布尔假。\n\n```pseudocode\n算法 观察审计(Q, capture, exported, query)\n输入：Q=(kind, subject, W_q, claim)，claim 为存在、缺失、持续时间或归属之一\n       capture：支持域、启用域、作用域、采集块、损失状态\n       exported：按域产生的表、字段、记录\n       query：查询窗口、域过滤、对象连接规则\n输出：presence、absence、归属、可见记录、原因列表\n\n1. 验证 W_q 为半开有限窗口；若 W0==W1，返回 NO_QUERY\n2. reasons=空；presence=UNKNOWN；absence=UNKNOWN；joined=空\n3. 若 kind 未被工具支持或本次未启用：加入 NOT_INSTRUMENTED\n4. 若 subject 不在 capture 的主体、线程、设备或队列作用域：加入 OUT_OF_SCOPE\n5. 若 capture 对该域没有无损失证据：加入 LOSS_UNKNOWN\n6. 若 exported 没有 kind 的表或字段：加入 EXPORT_MISSING\n7. 若 query 没有启用 kind 的域过滤：加入 QUERY_FILTERED\n8. gaps=覆盖审计(capture.chunks_for(kind,subject), W_q, kind, subject)\n9. 若 gaps 非空：加入 WINDOW_GAP，并保留第一个缺口及其时间范围\n10. R_all = exported.records(kind) 中时间与 query 窗口相交、且 query 域过滤接受的记录\n11. R_win = R_all 中落在 query 时间语义内、字段合法、没有明显重复导出的记录\n12. 对 R_win 中每条记录调用 query.join(record, subject)\n13. 若至少一条记录 join 成功：presence=SUPPORTED；joined=成功集合\n14. 否则若 R_win 非空但 join 无法完成：presence=PRESENT_UNJOINED\n15. 否则若 R_win 为空且 reasons 为空：\n      若 claim 是缺失或 claim 利用空结果排除事件：absence=SUPPORTED_UNDER_CERTIFICATE\n      否则 absence=NOT_APPLICABLE\n16. 否则 absence=UNSUPPORTED，返回全部原因，不把缺口对应阶段成本记为零\n17. 若 claim 是持续时间：仅对完整包含在采集与查询窗口内、且关联成立的记录计算；边界裁剪记录标为 PARTIAL\n18. 若 claim 是因果：另需满足有依据的依赖边；时间重叠或 join 成功本身不提供因果边\n19. 返回 presence、absence、joined、R_win、reasons\n```\n\n无事件证书至少要求：域已支持并启用，主体和作用域覆盖，采集块完整覆盖 W_q，损失状态为零或已知不会影响该窗口，导出含表，查询过滤正确，时间边界没有未知偏移，且空的 R_win 不是由无法关联造成的。缺少其中任何一项，正确输出是“未取得足以排除事件的证据”。\n\n表存在但为空时，只有上述条件都成立，才能支持“该域在该窗口内没有匹配事件”。表不存在时，只能支持“这次导出没有提供该表”。表在导出中存在但查询为空时，还要检查查询窗口、过滤条件和字段是否把记录排除。\n\n## 聚合、共享物理工作与逻辑归属\n\n对已限定域、作用域、时间域并去除重复导出记录后的区间集合 I_i=[s_i,e_i)，定义累计时长 S 和覆盖并集 U：\n\nS = Σ_i (e_i-s_i)，U = |∪_i [s_i,e_i)|。\n\n当区间重叠时 S≥U；只有全部区间互不重叠时 S=U。K=max_t |{i: s_i≤t<e_i}| 是所选作用域内的最大并发数。U 可以解释为所选资源被所列活动覆盖的时间，但不能自动解释为 SM 忙碌、整机忙碌或请求独占时间。\n\n一个物理工作 p 持续 d_p，可以服务多个逻辑请求。若要把资源成本分摊给请求，可定义非负权重 w_{p,r}，并满足 Σ_r w_{p,r}=1：\n\ncharged(p,r)=w_{p,r}·d_p。\n\n这样所有请求的资源归属之和仍为 d_p。若请求路径报告的是“该请求等待了整段共享工作”，每个请求都可以引用 d_p 作为延迟的一部分；但把这些完整等待再次相加成设备忙碌时间，就重复计算了同一段物理工作。没有分摊规则时，应分别报告物理 U、逻辑等待集合和未分摊的共享时长，不能直接把逻辑时长相加冒充物理资源。\n\n去重应按物理身份、范围、尝试和代次进行，而不是按内核名去重。两个同名 kernel 可能是不同设备上的不同执行；一个 kernel 被导出两次则可能是同一物理执行。两者都不能只凭名字判断。\n\n## 条件化成本\n\n观测成本不是只有“打开 profiler 的百分比”。同一候选应在同一问题、窗口和作用域中列账。\n\n| 成本 | 应计算的对象与条件 |\n|---|---|\n| 采集计算 | 每个事件的探针、调用栈、shape、内存跟踪、采样和导出处理；细节采集通常增加 CPU 或工具内部工作量 |\n| 访存 | 采集缓冲、trace 文件、索引和查询结果的字节；记录负载与元数据分别计 |\n| 通信 | 多机 trace 汇聚、远程导出和控制消息；不能把 correlation 字节当成链路延迟 |\n| 准备 | 启用域、选择活动、设置窗口、获取权限、创建表和准备关联规则的固定成本 |\n| 同步 | 刷新缓冲、保存报告、等待导出完成、采样节流以及版本相关的保存路径；采集同步可能改变队列和重叠 |\n| 驻留 | 未导出的缓冲、已导出文件、查询索引、框架 profiler 保留的张量引用和未完成记录 |\n\n一个简单的有界缓冲模型是：令 A(t) 为累计写入字节，D(t) 为累计导出或排空字节，P(t)=P(0)+A(t)−D(t)。若缓冲容量为 B，且在整个关注区间内 P(t)≤B，则这个模型没有预测到容量溢出；P(t)>B 的区域必须标为可能丢失。若 A≤a、D≥d，一次刷新间隔为 F，则一个充分条件是 P(0)+(a−d)F≤B。它只是充分条件，不是对真实设备带宽或工具调度的实测。\n\ntrace 文件大小的量级可以写成 Σ_k N_k·b_k，其中 N_k 是保留记录数，b_k 是每条记录加元数据的平均字节数。导出、索引和查询还会产生额外的临时空间和时间；来源说明明确指出，大型采集的导出可能耗时数分钟，因此不能把“采完”当成“查询已就绪”。\n\nCPU 采样不是逐事件日志。采样频率为 f_s 时，名义间隔约为 1/f_s；短于采样间隔的事件可能没有样本，样本间隔也可能受节流影响而不规则。没有指定采样过程和损失模型时，只能声明“这份样本支持这些观察”，不能从样本数量反推出精确事件次数。perf 计数还需要记录事件运行时间与运行比例；当多个事件共享计数器或发生复用，缩放计数与同一时段的原始计数含义不同，IPC 也只能在同一作用域、同一时间窗口和同一统计对象上计算。\n\n框架 profiler 的等待、预热、记录和保存状态也属于成本边界。实际输出只覆盖选中的记录窗口，预热区间不应被当成没有工作；shape 或 stack 采集会增加开销，部分形状跟踪会保留张量引用，可能改变引用计数相关优化和内存表现。RDMA 的完成事件是一次性通知：通知数量不等于 CQE 数量，通知还可能在实际轮询清空 CQ 之后才被处理；本地 CQE 也不证明远端应用已经消费。块 I/O 的软件队列、硬件派发队列和乱序完成会把“提交顺序”与“服务完成顺序”分开，tag 复用还需要代次保护。\n\n## 条件改变后的保留与调整\n\n| 条件变化 | 应保留 | 应调整或放弃 |\n|---|---|---|\n| 单进程变多进程或多节点 | 每个进程或设备的独立作用域、事件身份和时钟界限 | 不能把多个导出的同名表直接合并；不能把 correlation 当全局主键 |\n| 单 stream 变多 stream | 真实生产、消费、完成和最后使用关系 | 不能用一个全序解释所有区间；重叠并集要按作用域分别计算 |\n| 采集窗口扩大或缩小 | 查询窗口与采集窗口的包含关系、边界保护带 | 扩大窗口前先检查缓冲和导出预算；缩小窗口时不能把未采区间当零成本 |\n| 采样率降低 | 样本覆盖范围和采样间隔 | 不能把低采样率下的安静区间解释成没有短事件；需要事件计数或更细窗口 |\n\n条件变化后，先检查依赖是否仍成立，再改变候选。低采样率适合看长期趋势，不适合证明短事件不存在；更细的采集适合定位机制，不自动适合作为服务性能数字；增加缓冲可以减少已知溢出，却不会消除采样遗漏、错误过滤或无法关联。\n\n## 区分实验与反证修正\n\n下表是验证设计，不代表这些实验已经在目标机器上运行。关键是让竞争解释给出不同的可观察预测。\n\n| 观察与竞争解释 | 区分实验 |
