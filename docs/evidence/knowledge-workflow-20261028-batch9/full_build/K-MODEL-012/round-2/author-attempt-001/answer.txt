  "chapter": "# K-MODEL-012：全模态系统：多时钟、分支依赖与背压\n\n全模态推理包含多个有依赖的计算分支。源采样、模型位置、文本生成、声学生成和客户端播放各有自己的时钟。系统必须记录一个结果属于哪个请求、代次、源区间和计算前沿，才能判断它是否允许被消费。“算完”“已提交”“已发送”和“已播放”是不同事实。\n\nQwen2.5-Omni 的 Thinker/Talker 是具体实例：Thinker 产生文本及高维表示，Talker 接收这些条件，自回归生成语音 token，随后由 Flow-Matching DiT 和 BigVGAN 转为波形。不同阶段既有重叠机会，也有必须满足的依赖。把各分支耗时相加可能高估延迟，直接取最大值又会漏掉串行依赖。\n\n## 对象、坐标与提交前沿\n\n请求身份记为 r=(q,g,v)：q 为逻辑请求，g 为执行代次，v 包含模型、processor、模板与声学边界契约版本。模态 m∈{txt,aud,vid}。源块携带源标识、半开源区间 [τ0,τ1)、内容摘要和到达时间。源时间与接收时间分开保存；乱序与重传不能改变媒体事件的时间。\n\n给定锚点 τ_anchor 和模型输入块长 Δ_m，第 b 块覆盖 [τ_anchor+bΔ_m,τ_anchor+(b+1)Δ_m)。边界只属于后一块。Qwen2.5-Omni 报告对带声音视频按实际时间划分 2 秒块，块内视觉表示在前、音频表示在后；音频 encoder 也按 2 秒块做 attention。输入块、Talker 声学 code 块和网络包是三个对象，不能默认块长相同。\n\nTMRoPE 将位置分为时间、高和宽。报告中一个音频时间 ID 对应 40 ms，视频时间 ID 按实际帧时间调整；图像视觉 token 的时间 ID 不变，高宽 ID 随空间位置变化。对恰好位于 40 ms 格点的相对时间，可写 q_aud(τ)=(τ−τ_anchor)/40 ms。非格点的取整、抽帧与插值由固定 processor 决定。后一模态的位置编号从前一模态的最大位置 ID 加一开始；不能把 encoder 行号当原始 sample offset，也不能把时间 ID 当作不同模态 token 数的等价单位。\n\n本章用排他前沿计数，初始均为 0：\n\n| 状态或前沿 | 精确定义 |\n|---|---|\n| ALIGNED / ENCODED | 源区间已形成合法输入块 / 该块全部 encoder 层与桥接已完成并发布 |\n| Thinker known、n_T | 已知输入序列 / 所有 Thinker 层共同完成的输入位置数 |\n| p_T | 已提交条件记录数；c_0,…,c_{p_T−1} 可被 Talker 读取 |\n| p_K | 已完整纳入 Talker 持久状态的条件记录数；未消费队列为 [p_K,p_T) |\n| n_K、j_A | Talker 已消费的内部输入位置数 / 已选择的有效声学 code 数 |\n| Q_code、b_D | 已封闭 code 块及末尾未封闭块 / 下一个待解码块编号 |\n| pcm_end、sent_end | 已稳定生成 / 已交给协议发送层的排他 sample offset |\n| acked_end / played_end | 仅在客户端协议提供确认时记录的接收或播放前沿 |\n\np_T、p_K 的共同单位是“一个 Thinker 条件记录”，包括模型规定的结束控制记录。它们既不是声学帧数，也不直接代表秒数。领先量 L=p_T−p_K。固定每记录一个文本 token 时，L 也是待消费文本条件数，但 token 数不等于可听语义时长；同步说写还应另测文本与音频的语义滞后。\n\n条件 c_k=(q,g,v,k,i,h_i,y_k) 同时包含 Thinker hidden 和采样文本 token。位置 i 是产生预测的已消费输入位置，y_k 是该预测选择的下一 token。报告说明仅 hidden 可能保留语义相似性而不能消除发音歧义，因此不能省去 y_k 的 embedding。\n\n所有成功提交保持：各层有效 KV 长度等于相应 n；下游只读完整、身份匹配的产物；队列不丢弃已承诺内容；p_K≤p_T；sample offset 单调且无重复区间。代次门拒绝旧结果发布，物理缓冲还必须等最后访问完成才能重用。\n\n## 合法输入、声学窗口与首尾边界\n\n源输入只有完整覆盖模型块，或满足明确的末块规则时才可进入 encoder。部分末块需要固定的 padding、有效长度与 mask；填充值不算真实源数据。内部缺口不能借用“末块不足”规则跳过。更改已编码区间、processor 或多模态排列，会改变后续函数和缓存身份。\n\nencoder 的稳定提交还要求其所有合法上下文就绪。代表块式 encoder 可在块内做双向 attention，访问哪些历史块由模型 mask 决定；不能把当前完成的一行在其他必需上下文未到时提前发布。各层依次从输入特征计算 Q/K/V，在合法位置集合上做缩放点积、稳定 softmax 和 V 加权，再执行投影、残差、norm 与 FFN。视觉 patch 的空间网格和 merge、音频卷积或降采样均先按 processor/encoder 契约完成，桥接特征与位置元数据一起发布。视觉几何的进一步展开见[视觉语言模型](vision-language.md)。\n\n生成侧也必须固定源可见性。本章逐层推导采用一次回复的固定合法多模态 prompt：源可以分块准备和 prefill，回复生成使用其已承诺快照。若模型支持在同一回复中继续插入媒体，必须另给出插入位置、mask 和旧状态稳定性契约。不能因为 encoder 支持块处理，就默认任意追加源都能沿用正在生成的全部 KV。持续摄像与打断可由后续回合或新代次组织。\n\n报告的 DiT 窗口包含前 2 块、当前块和后 1 块。内部块 b 的逻辑窗口为 {b−2,b−1,b,b+1}，但首尾必须分别处理：\n\n- 左边界：b=0 的 −2、−1，b=1 的 −1 不会由生产者生成。初始化时必须提供模型参数 B_left，说明这些位置采用哪些已核验的初始状态、mask 或填充；续接旧音频时则使用属于同一合法流的真实历史。二者不可互换。\n- 右边界：只有 Talker 已产生合法语音结束、code 流已封闭为 N 个块时，位置 j≥N 才能交给 B_right 处理。输入源 FLUSH、Thinker TEXT_DONE 与 code 流结束是不同事件；前两者不能单独授权右侧补齐。\n- 窗口内的非负历史位置必须来自真实且已封闭的 code 块；缺失意味着等待实际生产、非法缺口或过早回收，不能用左边界契约覆盖。\n- BigVGAN 还需独立提供初始状态、固定感受野、尾部处理、overlap 裁剪及实际样本长度规则。DiT 就绪不自动表示 PCM 已稳定。\n\n固定报告没有给出上述边界参数的全部数值和实现。本章将 B_left、B_right、B_vocoder 列为部署模型必须提供并核验的参数；缺失时返回 FAILED_BOUNDARY_CONTRACT，不能等待负编号块。测试中的“屏蔽负编号位置”只是显式声明的合成契约，不是 Qwen2.5-Omni 的已核验实现。\n\n因此非 FLUSH 的首包路径可以是：真实 code 0、1 已封闭，左侧由 B_left 合法初始化，解码块 0；此时不需要语音结束。只有 code 0 时仍需等待真实 code 1。若整个语音只有一个块，则语音结束后才可用 B_right 处理其右侧。空语音是否允许、末块是否可不足整块，也由模型契约规定。\n\n容量还必须支持这些依赖。按顺序解码并保留前两块时，常规四块窗口需要能够同时保留相关 code；若容量只能容纳当前块却必须先生成下一块，背压会形成无唤醒事件的循环。准入应保证最小窗口、未封闭块及一个最大输出事务的容量。永久不可能装下的原子事务应拒绝，不能无限 WAIT_CAPACITY。\n\n## 从已知输入到文本与双轨声学状态\n\n先展开两个 decoder 共用的代表性逐层机制。它用于恢复输入、KV、logits 和选择的对应关系，不宣称报告公开了所有层配置。实际 norm 顺序、GQA、位置变换、激活和头结构必须采用固定模型定义。\n\n设非空 prompt 为 z_0,…,z_{m−1}，其位置可包含文本 embedding 和桥接后的媒体特征。后续 z_{m+k}=y_k。消费位置 i 后得到末层 H_i，logits_i 预测位置 i+1。故首个 y_0 配对 H_{m−1}，一般 c_k 配对 H_{m+k−1} 与 y_k。选择 y_k 后，其自身位置 m+k 尚无 KV；下一次消费它才产生该位置的 KV。\n\n代表的 pre-norm decoder 在第 l 层执行：a=Norm_l(u)；q=aW_Q、k=aW_K、v=aW_V，对 q/k 应用规定的位置变换；把当前 k/v 暂写到位置 i。每个 query head 对允许的 j≤i 计算 s_j=q·k_j/√d_h+bias(i,j)，在合法集合内减最大值、指数归一化，再求 Σ_j softmax(s)_j v_j。拼接各 head 后投影并加残差得到 u′，再由模型 FFN 和残差得到下一层输入。例如门控 FFN 可写 u″=u′+[σ(Norm(u′)W_g)⊙Norm(u′)W_u]W_d；这只是代表结构，不能替换模型的实际激活。末端 norm 与输出头形成 logits。\n\n```pseudocode\nALGORITHM ConsumeKnown(D)\n输入：decoder D，known 输入、n、逐层 KV、固定位置与 mask\n前提：n < length(known)，本位置所需上游和 KV 增量容量均已就绪\n1. i ← n；u ← known[i] 对应的合法输入 embedding/特征；\n2. 为位置 i 建立逐层暂写区，所有有效层前沿仍为 n；\n3. 对 l 从第一层到末层：\n      依该层 norm 与投影得到 q、k、v，并应用位置变换；\n      在第 l 层位置 i 暂写 k/v；历史位置不得再次追加；\n      对 mask 允许的历史和当前位置执行缩放点积 attention；\n      按固定结构执行输出投影、残差、norm 和 FFN，更新 u；\n4. H ← 末端处理(u)；logits ← 输出头(H)；\n5. 全层完成且代次仍有效后，原子提交位置 i：n ← i+1；\n   若该输入是 Talker 条件 C_k，同时令 p_K ← k+1；\n6. 若 n=length(known)，保存 (H, logits, predicts=n, prefix_version)；\n   否则清除生成用 logits，继续消费 known 后缀；\n7. 失败时不推进有效 n；撤销暂写或令请求失败。\n```\n\n这里预算在一个可提交操作前检查。若实现允许在层间暂停，应保存层号、暂写区和完成事件，再从下一层继续；不得重跑已追加的位置。对外仍不能看到各层长度不一致的状态。GPU 操作已提交但未完成时返回的是等待完成事件，不能将其当作预算暂停后可立即重写的空闲区域。\n\nknown、有效 logits、已选 token 和发布是四个边界。完整 KV 命中而没有末行 logits 时，必须保留对应 H/logits 或按明确路径重算最后已知位置；不能对同一位置再次追加 KV，也不能凭 KV 长度推断可采样。相关的一般 decoder 机制见[Encoder-decoder](encoder-decoder-streaming.md)，本章的条件配对与提交门如下。\n\n### Thinker 的预留、选择与发布\n\n每个未消费条件的实际字节为 h_k；除 hidden 外还计其 token、身份元数据及必要副本。令 R 为尚未发布但已预留的条件数，M_res 为相应预留字节，M_live 为队列及尚未完成最后访问的原 hidden 字节。必须保持 L+R≤Lmax，M_live+M_res≤Hcap。KV、logits 暂存和文本发送队列也有独立容量；不能把条件队列限制当全部内存限制。\n\n```pseudocode\nALGORITHM ThinkerPublishOne(r)\n前提：已有预测位置正确且源快照匹配的 H/logits，或已有本事务的 SELECTED 状态\n1. 若尚无事务：\n      在锁/单写者事务中检查代次、L+R+1≤Lmax、\n      M_live+M_res+h_k≤Hcap，并预留文本输出事件与其余必要容量；\n      任何一项失败：不采样、不推进 p_T，记录等待的释放事件；\n      成功则建立 RESERVED(k=p_T, H位置, 容量令牌)。\n2. 若状态为 RESERVED：\n      按固定约束、temperature、top-p 等规则处理 logits；\n      若合法候选为空则失败并撤销事务；\n      从归一化分布选择 y，持久化 y、随机状态和约束状态，置 SELECTED；\n      暂停后只恢复此选择，不再次使用同一 logits 采样。\n3. 对 SELECTED 再检查代次和依赖版本；\n   原子追加 known 中的 y、条件 c_k=(k,i,H_i,y)、文本输出/结束事件；\n   p_T ← p_T+1；预留转换为队列占用，清除待选 logits；\n   y 自身的 KV 尚未计算，n_T 不变。\n4. 若 y 是合法 EOS 或达到长度上限，记录 TEXT_DONE 及原因；\n   条件流随后按模型契约关闭。EOS 控制记录不作为可见正文发送。\n5. 取消或失败只撤销未发布事务；已发布文本不得因容量不足回滚。\n```\n\n本代表路径只允许一个待发布 Thinker 事务。批量发布可一次预留全部增量，也可按记录逐个提交合法前缀，不能先发布整批再检查。若 p_T=8、p_K=3、Lmax=5，新记录必须被挡在发布前。若 p_T=7、p_K=3，只能再提交一条；申请两条的事务必须拒绝或先拆成合法的一条。\n\n消费者没有“L 必须严格小于 Lmax”的门。达到上限正是应排空的状态。Talker 将 c_k 完整纳入持久状态后才推进 p_K；原 hidden 在最后读取完成后才能释放字节额度。若先复制成设备暂存再推进消费，复制目标、在途原副本及后续条件状态必须分别计账。\n\n### Talker 的条件前沿与双轨前沿\n\n报告说明 Talker 为双轨自回归 decoder，生成文本与音频 token，但未公开足以唯一重建的全部轨道排列、延迟、融合和结束细节。以下给出一种完整代表结构，用于说明状态转换；它不是对 Qwen2.5-Omni 源码的断言。部署时必须核验并替换其输入投影、轨道分布和排列参数；缺失时不能声称已经实现该模型。\n\n代表结构把 Talker 的因果内部输入分为两种记录：条件输入 C_k=A_h H_i+A_y Embed_T(y_k)+type_C，以及生成对输入 A_j=E_text(u_j)+E_audio(a_j)+type_A；二者都加模型规定的位置。初始非空输入含 BOS、音色信息及合法历史表示。代表历史可以逐位置投影 Thinker prompt hidden 后作为前缀输入，投影和位置属于固定参数；报告所说“共享历史”并不能证明任意缓存字节可直接共享。\n\n这条内部输入流逐条调用 ConsumeKnown，每条输入只产生一份逐层 KV。条件 C_k 完整消费时推进 p_K；生成对输入被消费时只推进 n_K，不改变 p_K。末层 hidden 分别经文本头和音频头得到两个分布。本代表选择条件独立的双头分布 P(u_j,a_j|prefix)=P_text(u_j|prefix)P_audio(a_j|prefix)；若实际模型采用顺序条件头或不同排列，必须用其真实因子分解。\n\n定义模型参数 d(j)：选择第 j 个声学位置前至少要消费多少条 Thinker 条件，d 单调不减。它规定因果可见性，不宣称一个文本 token 对应固定数量声学帧。模型也可用等价的在线推进规则产生 d。条件流关闭后，d 不得请求超过最终 p_T 的条件。文本轨 EOS 后使用的 PAD/结束输入、是否允许强制文本轨、语音 EOS 和空语音均须由固定契约提供，不能临时补定。\n\n```pseudocode\nALGORITHM TalkerOne(r)\n1. 若有未消费的 known 输入：\n      对最早输入执行 ConsumeKnown；若它是 C_k，则原子推进 p_K；\n      记录原 hidden 的最后使用事件；返回本分支进展。\n2. 否则若 p_K < d(j_A)：\n      若 p_K < p_T 且有条件输入/KV 容量：\n          将唯一的 C_{p_K} 追加到 Talker known，清除旧 logits；\n          不提前推进 p_K；下一次消费此输入。\n      若条件流已关闭且 p_T < d(j_A)：失败 INVALID_TRACK_CONTRACT；\n      否则记录等待条件发布或容量释放。\n3. 否则若双头 logits 有效、没有未消费输入、下一个声学输出槽已预留：\n      按轨道分布选择 (u_j,a_j)，原子保存两个结果、RNG 与约束状态；\n      对尚未结束的轨道更新其停止状态；已结束文本轨只用契约规定的输入；\n      若 a_j 为普通有效 code：\n          追加到当前未封闭块；j_A ← j_A+1；\n          达到规定块长且所有 codebook/延迟轨到齐时封闭此块；\n      若 a_j 为语音 EOS：\n          验证条件流已关闭、p_K=p_T 及模型的文本轨结束要求；\n          按末块规则封闭非空残块，无残块时不创建空块；\n          关闭 code 流并记录最终块数 N 与实际长度；\n      若仍需下一次预测，将本生成对追加到 known，清除旧 logits；\n      刚选出的生成对没有 KV，下一次只消费一次。\n4. 语音 EOS 前仍可继续声学生成，即使 Thinker 已 TEXT_DONE；\n   只有各轨道合法结束并封闭残块后才记录 TALKER_DONE。\n```\n\n每次重入先消费已有 known，再决定是否补入新条件或采样，避免对已过期 logits 重新选择。提前结束但仍有必要条件未消费时是契约错误，不能将其偷偷丢弃，也不能无限等待一个已经出现的 EOS 自行改变。模型若允许局部结束，必须另外定义局部到最终结束的状态关系。\n\n例如 d(j)=(1,1,2,2,2)，五个有效 code 只需要两条条件。块长设为 2 时，块长依次为 2、2、1，末块在合法 EOS 时封闭；条件消费数为 2，声学前沿为 5。这是代表状态轨迹，不是报告的真实帧率或轨道参数。反之，一个条件也可能生成零个音频 code，例如只承担结束控制；系统不能通过“消费一条条件就生成一个整块”实现所有长度关系。\n\n## 对齐返回、分支调度与波形提交\n\n对齐接口同时返回已交付块列表和尾部状态。尾部等待不能覆盖本次已经形成的块。\n\n```pseudocode\nALGORITHM AlignChunk(r, m, optional_chunk, flush)\n输入：源身份、整数采样/时间刻度区间、内容、固定块长和边界契约\n输出：(new_blocks, tail_state)\n1. 检查代次、区间非空、摘要和源身份；先验证再修改区间表。\n   完全相同的重复输入幂等；非相同的重叠按本路径拒绝；\n   FLUSH 后只接受幂等重传，不能接入新的源内容。\n2. 将合法新区间放入乱序缓冲，next_b 仍指向最早未交付块。\n3. new_blocks ← 空列表；\n   当 next_b 的整个半开区间均已覆盖：\n      构造源映射、有效长度和位置元数据，追加 ALIGNED 块；\n      next_b ← next_b+1；同一块不再产出。\n4. 若 flush：\n      若没有未交付数据：tail_state ← FINAL，不创建额外空块；\n      否则若从当前块起点到真实源末端存在内部空洞：tail_state ← FAILED_GAP；\n      否则若模型允许该非空部分末块：\n          按末块契约追加一次 partial ALIGNED 块，记录真实长度；\n          推进交付记录，tail_state ← FINAL；\n      否则 tail_state ← FAILED_PARTIAL_CONTRACT。\n5. 否则：若存在阻挡连续前沿的空洞，tail_state ← WAIT_GAP；\n   若有不完整连续残留，tail_state ← WAIT_MORE；否则 tail_state ← EMPTY。\n6. 无论 tail_state 是等待还是最终状态，均返回 (new_blocks, tail_state)。\n```\n\n完整一块的普通输入返回非空列表和 EMPTY；完整块加残留返回非空列表和 WAIT_MORE；重复输入不重复交付。FLUSH 恰好在整块边界只结束尾部。失败尾部与先前合法块的账务仍需保留，是否将已接受的部分任务对外发布由任务协议决定，不能丢失已经形成的内部产物记录。\n\n声学解码对 b_D 按顺序执行。取逻辑四块窗口，负编号由 B_left 解释；非负编号优先读取真实块；只有 code 流已结束的 j≥N 才由 B_right 解释。固定求解步数为 S 时，保存初始噪声/RNG 和 solver 当前步，按模型给定的速度场与积分规则逐步更新 mel 状态，例如显式 Euler 代表式 x_{s+1}=x_s+(t_{s+1}−t_s)v_θ(x_s,t_s,window)。求解器和步表属于模型配置，此式不规定实际部署必须使用 Euler。\n\n完成全部 solver 步才发布稳定 mel。BigVGAN 依固定卷积/上采样网络和边界状态产生扩展波形；从扩展结果中仅提交本块拥有的稳定 sample 区间 [pcm_end,new_end)，裁去已发布 lookback 与尚不稳定的右侧。保存下一块需要的 overlap；最后一块按真实长度裁剪。若模型没有足够规则确定这个区间，就不能承诺流式 PCM 正确。窗口、mel、PCM 和发送槽在各自事务前预留，不能先产生无处提交的无限临时结果。\n\n```pseudocode\nALGORITHM OmniStep(r, budget)\n1. 汇合到达、完成、发送和确认事件；旧代次事件仅执行安全清理。\n   若取消：撤销未来提交资格，返回 CANCELLED 并保留在途清理责任。\n2. 重复一个有界、公平的调度轮次：\n      progressed ← false；wake_set ← 空集合；\n      a. 尝试发送已有文本/PCM；只更新协议承诺的 sent 前沿；\n         未发送成功的内容继续保留，记录 SOCKET_WRITABLE 等事件。\n      b. 判断整请求完成：所需源最终处理已完成、TEXT_DONE、条件流关闭、\n         TALKER_DONE、所有 code 块已解码、vocoder 已结束、输出队列已排空，\n         并满足任务要求的发送/确认边界；若成立，返回 COMPLETE。\n      c. 若声学/vocoder 分支就绪且有输出容量，在预算内推进一个可恢复操作；\n         窗口不足只给此分支记录 CODE_BLOCK、CODE_FINAL 或边界失败。\n      d. 若 Talker 就绪，执行一个 TalkerOne 操作；\n         Thinker 等源或领先达到上限不阻止它消费已有条件。\n      e. 若 Thinker 有已保存的发布事务或有效 logits，尝试 ThinkerPublishOne；\n         否则若最早 known 的源依赖完整且 KV 容量足够，执行 ConsumeKnown；\n         未就绪只记录 SOURCE_READY、CAPACITY_RELEASE 或完成事件。\n      f. 对合法 ALIGNED 块推进一个 processor/encoder 操作；\n         完整块提交 ENCODED；输入不足只记录 SOURCE_CHUNK/SOURCE_FINAL。\n      每次操作前检查预算，每个提交点重查代次、依赖和容量；\n      某分支不就绪时继续考察其他分支，不在局部分支返回整请求等待。\n3. 再处理可发送结果和完成判定；\n   若仍有可执行工作但预算已尽，返回 PAUSED_BUDGET；\n   若本轮有进展且预算仍足够，继续下一轮；\n   若所有分支均无可执行工作，返回 WAIT(wake_set)；\n   若未完成且 wake_set 为空，返回 FAILED_CONTRACT_DEADLOCK。\n```\n\n发送成功和终态检查在等待判定之前；COMPLETE 不依赖“再出现一个可解码块”。WAIT 携带具体唤醒来源，不能用一个 WAIT_SOURCE 表示 Talker、网络和源三种不同阻塞。预算不足但已有工作可做是下一调度时间片，缺源是输入事件，在途操作是设备完成事件。\n\n一条组合轨迹是：Thinker 暂时没有新源，队列已有 c_0；Talker 消费它并生成 code 0、1；在没有语音 FLUSH 时，块 0 用 B_left 和真实右上下文解码并发送。块 1 等右上下文时，之前的 PCM 仍可发送。随后条件流关闭、Talker 合法结束，块 1 用 B_right 解码；最后 PCM 发送后直接 COMPLETE，不再检查不存在的块 2。把任一局部等待提前返回都会破坏这条轨迹。\n\n打断将 g 增加，撤销旧代次的新提交资格；旧 kernel、DMA、codec overlap 和发送操作仍可能访问原缓冲。只有引用归零且最后使用事件完成才回收。客户端按协议丢弃未播放的旧代次数据；已经播放的样本不可撤销。新代次从约定的确认位置继承或重新开始，不能将旧尾音直接拼接到新回复。\n\n## 条件化成本：计算、流量、队列与资源\n\n六类成本都要落在同一请求范围和候选方案中：计算包含 encoder、两个 decoder、DiT 与 vocoder；访存包含权重、逐层 KV、hidden、code、mel、PCM 与暂写；通信包含特征/条件跨设备传输和客户端音频；准备包含媒体解码、重采样、mel、resize、抽帧与分词；同步包含块形成、条件等待、lookahead、solver 完成和发送缓冲；驻留包含所有活跃、预留和仍在途的对象。\n\n设阶段 i 每块在资源 j 上占用 w_{i,j} 秒，同类块周期为 Δ 秒，则单会话的资源需求为 ρ_j=Σ_i w_{i,j}/Δ。N 个同类会话共享串行资源时，稳定性必要条件为 Nρ_j<1；这不保证尾延迟。分支若以不同频率运行，应使用各自 λ_i，写成 ρ_j=Σ_i λ_i w_{i,j}，不能把每个文本 token、每个音频块和每个视频块当作相同频率。\n\n报告的音频参数为 16 kHz、128 通道 mel、25 ms 窗与 10 ms hop，encoder 表示约每 40 ms 一帧。稳态 1 秒约 100 个 mel hop，2 秒约 200 个；严格首尾帧数还取决于窗中心、padding 和 flush。2 秒约有 50 个 40 ms 表示单位。16-bit 单声道输入 PCM 每秒 32,000 字节，2 秒 64,000 字节；这是原始输入大小，不是 encoder 激活或设备峰值。\n\n视觉侧，处理后 H×W 且尺寸满足网格要求时，14 像素 patch 给出 P=(H/14)(W/14)，空间 2×2 merge 后约 P/4 个语言侧视觉 token。视频两帧成组还会改变时间维，不能再按每原始帧重复计同一输出。Qwen2.5-VL 的 112×112 窗口对应最多 64 个 patch，大部分窗口层 attention 约 O(P·64·d)，全注意力层仍约 O(P²d)，投影与 FFN 另计。报告的 VL 层数和 KV 配置不能直接当 Omni 的全部配置。\n\n对本章代表 decoder，宽 d、FFN 宽 d_ff、上下文 n 的一次单位置推进，投影/FFN 工作约 O(d²+d·d_ff)，attention 约 O(n·d)，再乘实际层数和模块数。逐层 KV 容量为 nΣ_l(D_K,l b_K,l+D_V,l b_V,l)，分别对 Thinker 与 Talker 计账。Talker 的 n_K 包括条件输入、历史前缀和已消费生成对，不能用 p_K 或 j_A 直接替换。每条条件消费和每个生成对消费均有 decoder 工作；双头词表投影、采样和轨道 mask 也有成本。\n\n若 DiT 每 code 块 C 个位置、窗口宽 4C、宽度 d_D、S 个 solver 步，则固定窗口代表结构的 attention 工作约 O(S·L_D·(4C)²d_D)，投影/FFN 约 O(S·L_D·4C·d_D²)，具体还取决于 mel/code 对齐和条件路径。初始左边界、末尾右边界可能改变有效位置，不能未经核验假定总是实算四个满块。BigVGAN 的卷积、上采样、overlap 和工作区按实际网络计，不能由 code 个数推出全部 FLOPs。\n\n队列使用守恒式而非截断式：Q_{t+1}=Q_t+A_t−C_t，0≤Q_{t+1}≤cap，其中 A_t、C_t 是真正获准提交和消费的数量，0≤C_t≤Q_t+A_t。申请但未获准的工作留在上游；用 min(cap,…) 隐去溢出会掩盖丢内容。\n\n前沿的正确更新为：\n\nL_{t+1}=p_T(t+1)−p_K(t+1)=L_t+Δp_T−Δp_K。\n\nΔp_T、Δp_K 均以条件记录计，L 非负由消费合法性保证，不能靠 max(0,…) 掩盖超前消费。以 p_T=6、p_K=3 为例，不动时 L=3；仅提交一条为 4；仅消费一条为 2；同时提交两条、消费一条为 4。把累计位置差再次加到旧 L 会在没有任何工作时虚构驻留增长。\n\n等宽单份 hidden 时，未消费主项为 L·d_h·b_h；实际条件容量还包括预留、元数据、副本和最后使用尚未完成的退休对象。消费后进入 Talker KV 的历史仍驻留，不能说 p_K 增长就释放了全部语音状态。物理峰值应取 max_t[各类同时存活且不共享的字节]，共享存储只计一次，预留池和其中的对象也不能重复相加。\n\n播放缓冲以秒计：B_{t+δ}=max(0,B_t+A_play−δ)，A_play 是该 δ 秒内真正到达的可播放音频时长；发生 B_t+A_play<δ 时另记欠载，不能只观察最后的正缓冲。PCM 容量为时长×采样率×每样本字节×声道数。24 kHz、单声道、16-bit 的 2 秒为 96,000 字节，仅为通用换算，不是 Omni 输出采样率事实。\n\n保留原设定的资源算例：2 秒输入区间在同一不能重叠的资源上依次占视觉 80 ms、音频 60 ms、Thinker 120 ms、Talker 40 ms、waveform 60 ms，共 360 ms。单会话需求为 18%，八会话为 144%，超过该资源的稳定容量。若阶段实际位于不同资源，应分别计账，再沿依赖 DAG 求首音频关键路径；既不能无依据取最大值，也不能把真实重叠阶段全部串行相加。\n\n首音频路径包括合法块形成、准备、encoder、首个可消费条件、足够的 code、DiT、vocoder、发送及播放缓冲。需要一个声学 lookahead 块不表示必须等待它代表的全部墙钟播放时长；code 若生成更快，可以提前取得，代价是额外初始计算和驻留。首文本、首 PCM、客户端首播放及整请求完成应分别报告。\n\n## 条件变化后的选择与恢复\n\n更小输入块可能减少块形成等待，却增加调用、位置边界和同步次数；前提是模型允许新块长。减小网络包不会改变模型输入契约。改变声学块长也必须重新核验 DiT mask、求解边界、codebook 完整性和 vocoder 裁剪。缺少边界规则时，应采用已支持的块配置或离线完整解码，不能依靠等待不可能到达的上下文。\n\n分辨率、抽帧率、音频 hop 和重采样改变实际输入及位置身份。迟到帧可以等待、明确丢弃或使用模型允许的缺失标记，但这些方案具有不同语义。processor 改变后旧特征即使形状相同也不一定可复用。\n\nLmax 较大可以吸收 Talker 短暂落后，但增加 hidden 驻留、取消浪费和文字领先；较小 Lmax 会更早暂停文本，可能降低设备复用。若真实瓶颈是 vocoder 或网络，单独增大 hidden 队列不会增加稳态服务能力。客户端缓冲过大还会延长打断残留。选择由资源需求和用户消费时钟决定。\n\n视频在场的双向语音任务可比较：A 等一段完整输入后串行处理；B 采用合法块处理及有界流水，共享设备；C 把感知和语音输出放到不同设备或执行池。A 边界简单但感知等待较大；B 复用较好但有资源争用；C 有隔离价值，同时增加权重驻留、特征传输和调度同步。若共享资源需求已经是设定的 144%，只增加队列不能恢复稳定；若分池传输耗时大于省下的排队，C 也可能更慢。离线总结可以接受 A，而临近播放欠载的任务可能需要 B 的准入限制或 C 的隔离。\n\n恢复包需保存：源快照及最终处理状态、已交付块与位置基址、known 与逐层有效 n、H/logits 的预测位置与依赖版本、RESERVED/SELECTED 事务和 RNG、p_T/p_K、Talker 双轨状态与 j_A、未封闭 code 块、DiT solver 步和窗口、vocoder overlap、样本提交和发送前沿，以及协议提供的确认前沿。已选而未消费的 token 不能恢复成已有 KV；已发布而未确认的输出不能盲目重发。\n\nOpenTelemetry context propagation 支持在服务边界注入/提取关联上下文，但父子 span 树不能自动表达多分支、多请求 batch 与多代次。事件还要显式携带 q、g、模态、源区间、位置范围和分支。保存摘要通常足以定位身份错误，不需要把原始媒体写入全部 trace。\n\n模型或 processor 变化后重查整个依赖闭包；浮点重算不天然逐位一致。打断取消的是未来提交资格，回收等待物理完成；恢复继承的是任务允许且已确认的历史，不能恢复已经播放之前的外部世界。\n\n## 竞争解释、反证与检查边界\n\n| 现象 | 竞争解释 | 区分实验与不同预测 |\n|---|---|---|\n| 满队列后文本和语音都停住 | 合法背压；发布顺序错误；消费者也被领先门挡住 | 固定 p_T=8、p_K=3、Lmax=5，禁止新源但保留条件；正确路径拒绝新提交并允许 p_K 增长。若消费者仍等额度，查错误的共享门 |\n| 源暂缺时断音 | 没有声学条件；局部 WAIT 提前返回；网络未可写 | 预置条件和可发送 PCM，再撤走新源；正确调度仍排空。若仅恢复源就让旧 PCM 突然发送，支持调度门错误 |\n| 首块始终等待 | 真实右上下文不足；错误等待负编号；缺少边界契约 |
