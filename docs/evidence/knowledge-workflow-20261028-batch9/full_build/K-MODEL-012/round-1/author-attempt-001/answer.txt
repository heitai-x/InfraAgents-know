  "chapter": "# K-MODEL-012：全模态系统：多时钟、分支依赖与背压\n\n全模态推理不是把文本、音频和视频压成同一个 token 长度的批处理问题。每个模态有自己的采集时钟、处理块和可消费边界；Qwen2.5-Omni 的 Thinker/Talker 又让文本思考与语音生成成为两个有依赖的分支。系统若只记录“某分支已完成”，却不记录它对应哪个源时间、哪个模型位置、哪个代次，就会把“已经算完”误当成“下游可以消费”，在首包、背压、打断和恢复上得出错误结论。\n\n## 对象、时钟与状态定义\n\n设请求身份为 r=(q,g,v)，其中 q 是逻辑请求，g 是执行代次，v 是模型、processor 与模板版本。模态 m∈{txt,aud,vid}；源块 s_{m,k} 带有源标识、源时间区间 [τ0,τ1)、内容摘要和到达时间。源时间不是接收时间：网络抖动、重传和乱序会让“先收到的块”不代表“更早的内容”。\n\n对一个模型规定的块长 Δ_m，块编号为 b=floor(τ/Δ_m)，块区间取半开 [bΔ_m,(b+1)Δ_m)。半开边界防止 2 秒边界同时属于两个块。Qwen2.5-Omni 报告用 2 秒块组织带声音的视频表示，并把视觉表示放在块前、音频表示放在块后交错排列；这是该模型报告的块契约，不是任意 100 ms 输入都能立即影响输出的证明。\n\n位置坐标要单独记录。对音频，报告说明一个时间 ID 对应 40 ms；在恰好为 40 ms 整数倍的点上，可把请求内音频时间轴写成 q_aud(τ)=floor((τ−τ_anchor)/40 ms)。对视频，帧时间按实际时间调整时间 ID，使一个时间 ID 对应 40 ms；非整数倍点的取整或对齐规则由 processor 定义，不能由本章擅自指定。图像的时间 ID 在各视觉 token 上保持不变，高、宽分量随 token 的空间位置变化。模型把多个模态接在一起时，后一模态的位置编号从前一模态最大位置 ID 加一开始。于是可把模态 m 的位置写成 P_m(k)=base_m+q_m(k)，其中 base_m 由排列顺序和前一模态最大值决定。这个式子表达的是位置身份，不是把不同模态的 token 数强行等价。\n\n每个请求至少有这些状态：\n\n| 状态 | 含义 | 不能混淆的点 |\n|---|---|---|\n| ALIGNED | 源块已按半开区间形成模型块，位置元数据已分配 | 还没有 encoder 结果 |\n| ENCODED | 该模态块的 encoder 所有层已完成并提交 | 不代表 Thinker 已消费 |\n| THINKER_COMMITTED | Thinker 已产生并提交一个文本位置及其 hidden 表示 | 文本可发送，但不等于音频可播放 |\n| TALKER_CONSUMED | Talker 已读取某个已提交条件并推进声学状态 | 不代表 mel/PCM 已稳定 |\n| ACOUSTIC_READY | 声学块已按 lookback/lookahead 契约解码出稳定片段 | 还要经过发送和播放缓冲 |\n| SENT | 已交给网络发送缓冲 | 不证明客户端已消费 |\n| PLAYED/ACKED | 客户端按协议确认已播放到某 sample offset | 只有协议明确支持时才有此状态 |\n\n状态机的分支状态包括：各模态的 encoded frontier；Thinker 的 known 文本、已提交 hidden frontier、最后语义位置 p_T；Talker 已消费条件位置 p_K、声学 code 块和 solver 状态；DiT 的窗口、BigVGAN 的 lookback 与累计 sample offset；发送队列、客户端确认偏移和 RNG/约束状态。所有对象都应带 q、g、m、源区间、模型版本和位置范围，否则旧结果无法与新一代请求区分。\n\n必须保持的不变量：\n\n1. 同一模态的源区间单调、无未声明空洞；完全重复的块可幂等忽略，内容不同的重叠必须拒绝。\n2. 每个模型输入位置都能回溯到源区间、processor 版本和位置坐标；不能用 encoder 行号直接冒充音频 sample 偏移。\n3. Talker 的条件同时包含 Thinker 的 hidden 表示和已采样文本 token 的 embedding；只给 hidden 或只给文本都不满足该分支的输入定义。\n4. 下游只能读取已提交的完整块；部分层、部分 solver 步或未完成的 PCM 不能作为稳定结果发布。\n5. 领先距离和每个队列都在容量内；达到上限时，生产者停止提交而不是无限积压。\n6. 代次 g 单调；旧代次的迟到 hidden、code、PCM 或网络包不得写入新代次。\n7. 请求完成至少要求其承诺的文本已发送、音频已按协议发送；若协议跟踪播放，还要区分 sent 与 acked/played。\n\n## 合法性：模型契约与消费时钟\n\n合法性先问“模型允许什么”，再问“当前实现选择什么”。Qwen2.5-Omni 报告描述了 2 秒音频/视频块、音频 block attention、视觉 14 像素 patch 与相邻 2×2 合并、Talker 接收 Thinker 高维表示和采样文本 token，以及 DiT 的滑动窗口：当前块访问前 2 块、当前块和后 1 块，共 4 块感受野；BigVGAN 再按固定感受野分块生成波形。这些是模型和报告的契约事实。不能由“支持 streaming”推出任意长度的输入都能立即被消费，也不能由“文本已生成”推出“对应音频已可播放”。\n\n一个块要进入执行，至少满足：源区间完整覆盖该半开块，或处于模型明确允许的 flush/末块规则；位置坐标连续且与模态排列一致；该块依赖的 encoder 输出已提交；下游队列有空间。只有部分覆盖的末尾块不能补成完整块，除非模型定义了 padding、边界 mask 或末块规则；否则应等待更多输入或返回明确的不足上下文错误。\n\nTalker 的合法性还受领先距离约束。用语义位置或经模型定义的对齐单位定义 p_T 和 p_K，领先量 L=p_T−p_K。同步说写产品要求 L 不超过一个可听语义区间 Lmax；文字优先产品可以允许更大 L，但必须同时约束待消费 hidden 字节、未解码声学块、发送队列和客户端未播放时长。L 用“文本 token 数”代替会失真，因为文本 token、声学 code 和波形样本不是同一单位。\n\n声学解码的 lookahead 是另一条合法性边界。若要把块 b 的 mel 视为稳定，需要 code 块 b−2、b−1、b、b+1 可用。若 b+1 尚未生成，系统可以等待，也可以在 code 生成快于实时时提前生成它；后者付出额外模型步骤和驻留，不表示可以跳过依赖。只有请求已 flush 且模型允许边界规则时，才可以对缺失的右上下文采用明确的 padding/mask；否则不能把未完成的块当成可播放音频。\n\n打断时，新代次 g+1 必须大于旧代次。旧代次的在途 kernel、DMA、发送和 codec overlap 可能仍持有缓冲；代次只能撤销其提交资格，不能假装它们已经停止。旧代次已经播放的 sample 不可撤销，新代次从协议规定的确认偏移之后开始。\n\n## 核心算法：对齐、分支推进与提交\n\n下面的伪代码给出机制，不规定某个引擎的类结构或线程数。实际实现可以一次处理多个块，但提交顺序和依赖必须保持。\n\n```pseudocode\nALGORITHM AlignChunk(r, m, chunk)\n输入：请求 r=(q,g,v)，模态 m，chunk=(源ID, τ0, τ1, bytes, digest)\n输出：ALIGNED 块列表、WAIT、GAP 或 REJECT\n1. 若 g != r.epoch：返回 REJECT_STALE_EPOCH\n2. 若 τ1 <= τ0 或 digest 与已有同源块冲突：返回 REJECT_BAD_SOURCE\n3. 将 [τ0,τ1) 插入 r.media[m]；完全重复的块只保留一份；\n   与已有区间部分重叠但内容不同则返回 REJECT_CONFLICT\n4. 若 [τ0,τ1) 前存在未解释空洞：按任务策略返回 WAIT_GAP 或标记 r.gap[m]\n5. 重复：\n      b ← 最早尚未产出的完整块编号；\n      I_b ← [bΔ_m, (b+1)Δ_m)；\n      若 I_b 未被 r.media[m] 完整覆盖：跳出；\n      分配 block_id=(m,b,g)；\n      计算源时间范围和位置坐标范围 P_b；\n      将块置为 ALIGNED，但不标记 ENCODED；\n6. 若收到 FLUSH 且模型允许末块部分覆盖：\n      以 partial=true 产生最后一个 ALIGNED 块，记录允许的 padding/边界 mask；\n   否则保留未完成输入，返回 WAIT_MORE\n7. 返回新产生的 ALIGNED 块\n```\n\n```pseudocode\nALGORITHM OmniStep(r, budget)\n输入：请求 r、当前代次状态、时间片 budget\n输出：COMPLETE、PAUSED_BUDGET、WAIT_SOURCE、WAIT_LOOKAHEAD、CANCELLED 或失败\n1. 若 r.epoch 已变化或已取消：停止新提交，返回 CANCELLED\n2. 在 budget 内推进各模态 encoder；只有完整层完成才把块提交为 ENCODED\n3. 若 Thinker 的输入前缀未完整：返回 WAIT_SOURCE\n4. 若存在连续 ENCODED 输入块和合法位置，推进 Thinker：\n      a. 计算下一位置 hidden；\n      b. 按模型采样文本 token y；\n      c. 原子提交 hidden 与 y 的 Talker 条件；文本可发送；\n      d. 若停止条件或长度条件成立，记录 TEXT_DONE，但不等于音频完成\n5. 计算 L=p_T−p_K；若 L 已达到 Lmax 或 hidden 字节达到上限：\n      不提交新的 Thinker 文本条件，先推进 Talker 或等待消费者\n6. 若 Talker 有已提交条件且 L 在合法范围：\n      a. 消费最早未消费条件，生成声学 code 块；\n      b. 只把声学 code 块提交到 Q_code，不把未完成 mel/PCM 当可播放\n7. 若存在声学块 b，且 b−2、b−1、b、b+1 的 code 窗口齐全：\n      执行 DiT/Flow-Matching 与 BigVGAN 分块解码；\n      裁去 lookback 重叠，按累计 sample offset 提交 PCM 块；\n   否则：\n      若已 FLUSH 且模型允许边界解：按边界规则解码；\n      否则返回 WAIT_LOOKAHEAD\n8. 将 PCM 放入有界发送队列：\n      若队列已满：不提交更多 PCM/Talker 输出，按策略暂停或拒绝；\n      发送成功后只更新 sent offset；若协议要求，另记 acked/played offset\n9. 若文本目标完成且所有文本已发送，并且音频目标完成且所有承诺 PCM\n   已发送或按协议确认：返回 COMPLETE；\n   否则若 budget 用尽：返回 PAUSED_BUDGET\n```\n\n```pseudocode\nALGORITHM Interrupt(r, new_epoch)\n输入：请求 r，新代次 new_epoch\n输出：新代次提交资格与旧代次清理责任\n1. 断言 new_epoch > r.epoch\n2. r.epoch ← new_epoch；按任务策略决定继承已确认上下文还是清空会话\n3. 旧代次所有未提交 hidden、code、mel 和 PCM 标记 STALE；\n   不得写入新代次，也不得覆盖新代次槽位\n4. 旧代次在途 kernel、DMA、发送和 codec overlap 只撤销提交资格；\n   等待其完成事件后再回收缓冲\n5. 记录旧代次最后 acked sample offset；新代次从协议规定位置开始\n6. 返回新代次的准入结果；旧代次的迟到完成事件只能释放资源，不能重新激活回复\n```\n\n算法中的关键提交点不是“函数返回”而是“依赖完整且身份匹配”。Thinker 的 hidden 可以在采样前算出，但 Talker 条件必须等文本 token 已选择并提交；声学 code 可以在 mel 前生成，但 PCM 必须等 DiT 和 BigVGAN 的窗口满足。不同分支可并行推进，不能把跨分支耗时直接相加成关键路径。\n\n## 成本模型：块、队列、带宽与驻留\n\n全模态成本分成计算、访存、通信、准备、同步和驻留。计算包括视觉/音频 encoder、Thinker、Talker、DiT 和 vocoder；访存包括权重、hidden、KV、code、mel 和 PCM；通信包括特征从 encoder 到主干、hidden 到 Talker、PCM 到客户端；准备包括媒体解码、重采样、mel、resize/crop 和 tokenization；同步包括块形成、lookahead、发送缓冲和客户端播放；驻留包括排队中的源块、hidden、声学块、PCM 和 KV。\n\n设阶段 i 在资源 j 上每块占用 w_{i,j}，块周期为 Δ，则单会话在该资源上的理想需求为 ρ_j=(1/Δ)Σ_i w_{i,j}。若 N 个独立会话共享同一串行资源且没有重叠，需求为 Nρ_j；稳定性的必要条件是 Nρ_j<1，但它不保证尾延迟，因为到达突发、服务方差和排队仍会改变等待。若阶段在不同资源上可重叠，就不能把 w 全部相加；应按资源分别计，再用依赖图的最长路径求首内容时间。\n\nQwen2.5-Omni 报告给出的输入参数可用于推导媒体准备量：音频重采样到 16 kHz、128 通道 mel、25 ms 窗、10 ms hop，音频编码器约每 40 ms 一帧。由此，1 秒有约 100 个 mel 帧，2 秒块约 200 个 mel 帧；若每帧对应一个音频表示，2 秒块约有 50 个 40 ms 的音频单位。16-bit 单声道 16 kHz PCM 每秒 32,000 字节，2 秒为 64,000 字节；mel 的实际字节还取决于元素类型、布局和是否保留中间量。这些是参数推导，不是对某个引擎峰值显存的测量。\n\n视觉侧，Qwen2.5-VL 报告的视觉编码器采用 14 像素 patch、相邻 2×2 合并和 112×112 窗口（对应 8×8 patch），只有少数层做全注意力。若处理后的图像为 H×W 且尺寸可被 14 整除，patch 数约为 P=(H/14)(W/14)；按 2×2 合并后，进入语言侧的视觉 token 约为 P/4。若视觉编码器按两个连续帧成组，时间维还会改变每帧摊到的 token 数。窗口注意力把大部分层的成对工作从随 P 二次增长变成随 P 乘窗口规模增长，但全注意力层、合并 MLP、位置编码和特征传输仍要单独计。这个公式是几何下界，不能替代具体 processor 的裁剪、抽帧和 merge 规则。\n\n声学分支的 DiT 只访问 4 个 code 块窗口；若每块有 C 个 code、hidden 维为 d，则一次窗口注意力的规模随 4C 增长，计算约随 (4C)^2 d 增长，具体还受层数、head 数和 solver 步数影响。BigVGAN 的固定感受野意味着它也要按块运行并保留 overlap；波形输出还要按采样率、位深和声道数计算字节。24 kHz、单声道、16-bit PCM 的 2 秒音频为 96,000 字节，这是通用换算，不表示 Qwen2.5-Omni 的输出采样率就是 24 kHz。\n\n队列和领先距离可写成离散更新。对有界队列 Q：Q(t+1)=min(cap,max(0,Q(t)+a(t)−c(t)))。对领先量：L(t+1)=max(0,L(t)+p_T(t)−p_K(t))，并要求 L≤Lmax。对客户端播放缓冲，以“秒音频”计 B(t+1)=max(0,B(t)+a_p(t)−1)，其中 1 表示每秒消耗 1 秒音频；平均 a_p>1 不排除某个瞬间 B 降到 0，首包和尾部欠载必须分别看。\n\n驻留可写成 M_hidden≈L·d_h·b_h（若每个语义位置保留一份 hidden；多层或多副本要另加），M_pcm≈B_seconds·sample_rate·bytes_per_sample·channels。发送队列、codec overlap、mel 中间量和 KV 是不同对象，不能重复加算同一块共享存储。若 hidden 在 CPU 与设备之间复制，还要把 staging 和传输时间计入准备/通信，而不是只算模型 FLOPs。\n\n沿用本章的设定算例：假设视觉阶段在某个不能与其他阶段重叠的资源上占 80 ms，音频 60 ms，Thinker 120 ms，Talker 40 ms，waveform 60 ms，2 秒块共 360 ms。单会话该资源需求为 360/2000=18%，八会话为 144%，所以同一串行资源无法稳定承接；即使每条分支单独测量都快于实时，也不代表组合后满足。若真实引擎能把视觉、Thinker 和声学放在不同资源上重叠，应按各资源分别计，不能无依据地取五个时间的最大值，也不能把可重叠部分仍按串行相加。\n\n首音频时间应按依赖图的最长路径定义，而不是所有阶段之和。路径至少包含：等待合法块形成、媒体准备、encoder、Thinker 首个可消费条件、Talker、DiT、BigVGAN、发送/播放缓冲。文本首 token 与首音频包是不同 SLO；文本已发送、音频已发送、客户端已播放又是不同完成点。报告可以分别给出这些时间，但不能用总 tokens/s 替代。\n\n## 条件变化后的保留、调整与放弃\n\n改变块长 Δ 会改变等待和调用次数。更小的块可能降低首包等待，却增加每块调度、封包、窗口边界和位置对齐成本；更大的块提高复用，却增加首内容等待和打断时的浪费。只有在模型支持相应块契约并重新验证位置、mask 和 lookahead 后，才能把 Δ 调小；不能把 2 秒报告事实当成任意块长的性能承诺。\n\n改变分辨率、抽帧率或音频采样率会改变模型输入，而不只是吞吐数字。更高分辨率增加 patch 数和视觉窗口工作；更低抽帧率可能减少 token，却可能丢失事件时间；改变音频 hop 会改变 mel 帧和 40 ms 对齐。若源帧迟到，策略可以是等待、丢弃过期帧或发布带缺失标记的输入；三者对模型语义不同，必须在任务中明确。\n\n并发上升时，先看哪个资源先饱和。若某串行资源 ρ 接近 1，增加并发主要增加排队和尾延迟；若容量受 hidden 领先或 PCM 缓冲限制，应调整 Lmax、队列或消费者，而不是盲目加 worker。低并发且权重放置紧张时，共享同一执行池可能比拆池更合算；感知突发持续损害播放时，拆分或更细的准入隔离可能必要，但拆分增加特征传输、权重复制和常驻成本。\n\n### 组合轨迹：视频在场的双向语音交互\n\n设任务持续接收摄像和语音，允许用户在系统说话时打断并开启新回复；输出要求文字与可播放语音内容一致，旧回复已播放部分不混入新代次。候选 A 等待一段完整输入后串行处理；B 采用模型允许的分块感知和分支有界流水，共享设备；C 把感知与语音输出分配到不同设备或执行池。A 的边界简单但感知等待大；B 复用高但争用共享资源；C 更易隔离播放 deadline，但增加特征传输、权重驻留和放置成本。\n\n用上面的 2 秒设定算例，A 在块完成后才启动全部阶段，首音频至少等待块形成；B 可在块内完成编码后推进 Thinker，并用有界领先允许 Talker 消费较早条件；C 若把 waveform 放到独立池，可能缩短播放路径，却要把 hidden 或 code 传过去。若传输耗时超过节省的等待，C 不反转；若共享资源已经 144% 饱和而独立池有真实余量，C 才可能改变结果。这个选择由模型可见性、用户消费时钟和实际资源决定，不由一个总 tokens/s 指标决定。\n\n时间轨迹应按事件记录：源块到达、块封闭、encoder q、g、m、源标识、源时间区间、分支、位置范围和块序号定位。跨阶段迁移还要说明它依赖哪个源版本、哪个 processor 版本和哪个位置基址。前缀缓存如果只按文本 token 相同命中，可能忽略视觉/音频特征、位置基址或模板变化；反过来，同一媒体的特征可复用也不代表 Talker 条件可复用。\n\nOpenTelemetry 的 context propagation
