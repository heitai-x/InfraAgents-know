## 这份文档定义了什么

异步执行。GPU 操作默认异步：调用把操作入队到设备后立即返回。同一设备按入队顺序执行，框架在主机与设备、设备与设备之间复制数据时自动插入同步，因此单 stream 下调用者看不到异步。两个直接后果：错误在实际执行时才报告，栈不指向发出点；不同步的计时不准，需要用事件记录再同步。

stream 与分配器的两个独立关系。同一 stream 内按创建顺序串行；不同 stream 之间可以任意相对顺序并发，除非显式同步。使用非默认 stream 时同步由用户负责，而且同步在没有读依赖时仍然必要：一个张量的内存可能是缓存分配器刚回收、尚有旧操作未完成的地址。因此跨 stream 使用张量要做两件事：等待生产 stream（执行顺序），并告知分配器该张量被另一 stream 使用（生存期），后者防止它在消费完成前被回收重用。

缓存分配器。释放不触发设备同步，未用内存仍被进程持有并在外部工具中显示为已用；分配器行为可通过环境配置调整（后端选择、分块上限、可扩展段等）。

CUDA Graph 的约束与收益。重放牺牲动态性换取大幅降低的 CPU 开销：参数与 kernel 固定，重放跳过参数设置与分派的全部层次。可捕获的前提：不与主机同步、无基于数据的动态控制流（除显式支持的形式）、捕获期间进程内无未捕获的 CUDA 工作、CPU 工作不被捕获而在重放时被省略、每次重放读写同一组虚拟地址、形状与布局固定。捕获时的分配来自图私有内存池，池与图及捕获期间创建的张量同生命期；默认每次捕获一个私有池，多图可以共享一个池，条件是它们总按捕获顺序重放且从不并发；共享池时一张图的重放可能覆盖另一张图的输出，除非事先复制。文档指出这一模式常见于接受可变 batch 的推理服务器。

## 本库据此推导

- 执行顺序与地址生存期是两个独立关系，异步程序要同时满足，见 [Stream 与分配器](../frameworks/streams-allocator.md)。
- 图固定的是地址、形状与 kernel 序列，不是地址里的内容；内容的并发保护（代次、双缓冲）要另行设计，见 [CUDA Graph](../frameworks/cuda-graph-buffers.md)。
- 多桶图共享私有池的安全条件（顺序重放、不并发、输出先复制）直接进入图池的容量账，见同章"图池应进入容量和收益账"。
- 不同步的计时不准，是主机/设备时间线分析的基础事实，见 [主机与设备时间](../system-semantics/host-device-timing.md)。

## 适用边界

这是一个框架在一个提交上的语义说明；其他框架的 stream 与分配器约定不必相同。设计推导为独立分析，不是目标机器实测；版本日期不证明模型训练实际包含该资料。
