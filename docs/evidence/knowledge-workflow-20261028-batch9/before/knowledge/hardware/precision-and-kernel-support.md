# K-HW-004：数值格式、打包布局与矩阵指令

硬件能表示一种 dtype、库的接口接受该 dtype、目标 shape 在目标二进制中 dispatch 到预期 kernel，是三层不同能力。推理实现还必须把数值格式、分组元数据、物理布局和执行指令放在同一契约里；其中任一层的“支持”都不能替代其余层。

## 格式、指令与 dispatch 的证据层次

设执行请求 P=(dtype、M/N/K、stride、对齐、目标架构、库版本、编译选项、数值策略)。对一个候选格式，应分别记录：

- E0 可表示：格式定义存在，能够编码相应值域内的数。
- E1 API 接受：类型、shape 或编译接口不拒绝该请求。
- E2 执行契约满足：dtype、布局、对齐、leading dimension、参与线程和完成依赖符合目标接口。
- E3 实际 dispatch：目标二进制和运行时确实选择预期函数、内核或指令路径。
- E4 目标负载成本：在相同输入、质量约束和计时边界下，观测实际字节、时间线、驻留与同步。

例如库接受 INT4 权重，可能在 tile 内解包到半精度，也可能走低位整数指令，或退回普通算子。三条路径都可能数值正确，但转换、工作区和吞吐不同。E0/E1 不能证明 E3；E3 也不能单独证明端到端收益。

本章的容量与成本算例都是条件化推导。逻辑权重字节减少，只改变容量和读取候选；实际收益仍取决于解包、参数访问、矩阵形状、缓存、驻留和同步。

## 数值格式与量化契约

一个浮点格式不只是“16 bit”或“8 bit”。至少需要说明指数范围、有效数位、特殊值、舍入和转换规则。

| 格式 | 结构或输入解释 | 需要单独确认 | 不能由此推出 |
|---|---|---|---|
| FP16 | 1 符号、5 指数、10 小数位 | 乘法、累加、输出精度；非有限值和次正规数策略 | FP16 输入意味着整个归约按 FP16 执行 |
| BF16 | 1 符号、8 指数、7 小数位 | 指数范围较宽但有效数位较少；累加路径 | 指数范围接近 FP32 就等于 FP32 精度 |
| TF32 | 保留 FP32 指数范围，乘法输入采用约 10 位尾数路径 | 转换发生点、舍入及具体算子开关 | FP32 存储意味着完整 FP32 乘法 |
| FP8 E4M3 / E5M2 | 不同的指数与有效数分配 | 具体变体、缩放粒度、饱和、非有限值和累加 | FP8 是唯一格式，或整个模型自动使用 FP8 |
| signed INT8 | 码域 [-128,127] | zero-point、scale 轴、累加宽度、补偿 | 任意分组尺度或零点均可直接套入整数 GEMM |
| packed signed INT4 | 码域 [-8,7]，两个 nibble 占一个字节 | nibble 顺序、符号扩展、组轴、行尾 | nibble 0xF 按无符号解释为 15 |

存储精度、乘法精度、累加精度和输出精度必须分别描述。低精度输入配较高精度累加很常见，但真实路径还可能采用 TF32、reduced-precision reduction 或分批累加。溢出、下溢、次正规数清零、饱和及非有限值传播有不同机制，不能都归入“舍入误差”。

设量化标量为 x，步长 s 有限且 s>0，整数码域为 [q_min,q_max]。两种重建规则是：

- 实数偏移 REAL：q=clip(R((x-b)/s),q_min,q_max)，x̂=b+s·q。
- 整数零点 ZERO：q=clip(R(x/s)+z,q_min,q_max)，x̂=s·(q-z)，其中 z 是码域内整数。

R 的身份及发生位置属于编码契约。即使 b=-s·z，重新编码是否等价仍取决于 R(t+z)=R(t)+z；最近偶数舍入不对所有整数 z 满足这一关系。例如 s=1、z=1、x=0.5，先最近偶数舍入再加 z 得 1，先加 z 再舍入得 2。既有码流的重建只依赖解码规则，不能反过来证明两种编码次序等价。

后文具体 INT4 编码固定 R(t)=floor(t+1/2)，即最近舍入、半整数向正无穷取整；不把宿主语言默认 round 当作协议。无裁剪、精确最近舍入时，单元素误差至多 s/2；该界不覆盖饱和、参数存储误差或实际浮点计算误差。

在线性层 y=Wx 中，令 ΔW=Ŵ-W、Δx=x̂-x，则 ŷ-y=ΔW·x+W·Δx+ΔW·Δx。权重逐元素误差不是层输出误差的完整目标，校准输入的结构决定误差如何传播。GPTQ 类方法关注层输出重建；其校准设置不能直接作为目标模型的质量保证。

## 合法性：格式、分组与执行条件

合法实现必须保持数值含义、索引身份和完成依赖。

- s 有限且严格为正；ZERO 的 z 是码域内整数。NaN、Inf、尺度下溢为零或尺度溢出必须拒绝，或进入明确的高精度例外路径。
- 每个有效元素恰好属于一个组。组长不必整除 K，但尾组长度、逻辑组身份和参数表顺序必须明确。
- 会被消费的填充必须是数学中性值。ZERO 可填 q=z；REAL 没有精确零码时必须屏蔽无效位置或另证处理。不能把近零码称为精确零。
- 打包协议包含位宽、有符号性、低位顺序、行跨度、组轴、参数顺序、预转置、有效长度和版本。重排权重也必须重排参数或保留明确映射。
- 参数最终存储精度参与数值契约。先将 scale 转成制品实际存储值，再用这个值编码；导出后不得再次改变它而仍沿用原重建结论。
- scale 位于归约轴内部时，应对相应 K 段的部分结果分别应用；只有可在归约外提出的尺度才能由单一 epilogue 直接承接。
- 矩阵接口的 dtype、形状、布局、leading dimension、基址对齐和参与线程都须合法。不透明 fragment 不能按内部数组下标猜测行列。
- 输入生产、消费者可见和最后读者结束分别建立依赖。矩阵集体调用的一致参与，不自动替代前后任意共享内存交接。

组长、对称或非对称、动态或静态尺度、敏感层是否恢复高精度属于方案选择。合法只是前提，质量、实际 dispatch 和完整成本决定是否采用。

整数矩阵乘仍有溢出边界。对未经 zero-point 修正的 signed INT8 乘积，绝对上界可用 128²=16,384。K=4,096 时为 67,108,864，小于 INT32 最大值 2,147,483,647；K=131,072 时达到 2³¹，已经不能用同一界证明有符号 INT32 安全。初始 accumulator、bias、补偿项和更窄中间累加需另计。最终结果因抵消而较小，也不保证中间求和安全。

## 打包、解包与分组尺度：固定 INT4 算法

本节具体布局仅支持 b=4；编码器和解码器均必须拒绝其他位宽。通用 b-bit 的量化数学可以另行定义，但不能复用本节两个 nibble 的字节协议。

设 W 为 d_out×d_in，G 为正整数，沿输入列分组。W[r,j] 的组身份是 (r,floor(j/G))，参数表 S 的形状为 d_out×ceil(d_in/G)。格式版本固定为 SYM4-ROW-LOWFIRST-v1：每行从新字节开始，行跨度 H=ceil(d_in/2) 字节，行间不共享尾字节；本版不加额外对齐。

对有效列 j，码字节偏移为 rH+floor(j/2)，位移为 4·(j mod 2)。这是逻辑元素、物理码和组参数之间的完整映射。

```pseudocode
算法 PACK-UNPACK-SYM4
输入：有限权重 W[d_out,d_in]、正整数 G、位宽 b、已约定的 scale 存储转换
输出：码流 P、冻结尺度表 S、shape、组有效长度、格式版本 v

1 校验 b 恰为整数 4，否则拒绝；q_min=-8，q_max=7
   校验 shape 非负、G 为正整数、v 为 SYM4-ROW-LOWFIRST-v1
   H=ceil(d_in/2)；每行单独分配 H 字节
2 对每个输出行 r 和每个非空组 g：
     有效列为 [gG,min((g+1)G,d_in))
     a=max_j |W[r,j]|
     若 a=0，候选 s=1；否则候选 s=a/7
     将候选 s 转成制品实际存储值；若不再有限且为正则拒绝
     保存 S[r,g] 及该组有效长度
   冻结整个 S，此后不再拟合或重写尺度
3 对每个有效元素 W[r,j]：
     s=S[r,floor(j/G)]
     q=clip(floor(W[r,j]/s+1/2),-8,7)
     得到逻辑码 Q[r,j]
4 逐行打包：
     对 h=0,...,H-1：
       low=Q[r,2h] 的 4 位补码，即 Q[r,2h] mod 16
       若 2h+1<d_in，high=Q[r,2h+1] mod 16；否则 high=0
       P[rH+h]=low+16·high
     奇数行尾的高 nibble 不属于任何有效元素或量化组
5 返回 P、原样冻结的 S、shape、组长度和 v
6 解码前再次检查 b=4、v、码流长度 d_out·H、尺度表和组覆盖
   奇数行尾要求未使用的高 nibble 为 0；不消费该位置
   对每个有效 (r,j)：
     从 P[rH+floor(j/2)] 取位移 4·(j mod 2) 的 nibble u
     若 u>=8，q=u-16；否则 q=u
     读取 S[r,floor(j/G)]，重建 W_hat[r,j]=S[r,floor(j/G)]·q
7 缺失参数、重复或错误组身份、非法长度和版本不匹配均拒绝
```

零元素张量没有非空组，也不对空组求最大值；空行码流长度为零。全零组采用 s=1、q=0。非零常数组仍按最大绝对值构造，不会除以 max-min=0。负端多出的 -8 是合法码，但未舍入尺度的最大绝对值构造通常只需 [-7,7]；实际存储尺度改变后，裁剪仍按 [-8,7] 执行。

正确性不变量是：每个有效元素对应唯一字节/nibble 和唯一冻结尺度；4 位补码解码恢复原整数码；行尾不跨行借位；无效高 nibble 不参与归约。尺度存储转换可能改变近似误差，但编码和解码必须使用同一存储值。

固定 nibble 方案不能声称支持 b≥2。例如 b=8 时，[16,0] 和 [0,1] 都是合法 INT8 码对；错误地继续使用 low OR (high 左移 4 位)，两者都得到 0x10。本版在进入打包和解码前拒绝 b=8，而非靠往返容差掩盖碰撞。对合法 INT4，[-1,1] 应得到 0x1F；把 0xF 解成无符号 15 会把第一个重建值改变 16s。

分组尺度也不能随意提出归约。G=2、尺度为 0.5 和 2、四个码和激活均为 1，正确点积为 0.5·(1+1)+2·(1+1)=5；全部整数项先相加再乘最后尺度得到 8。两组尺度相同的测试不能区分这两个算法。

## 固定平台能力应落到具体接口

下表保留 CUDA 12.8 指南的接口范围；它不是完整 GPU 产品目录，也不能替代目标编译产物核验。

| 具体路径 | 输入与累加 | 文档中的形状或架构条件 | 不能由此推出 |
|---|---|---|---|
| WMMA 半精度 | FP16×FP16，FP32 或 FP16 accumulator | 列出 16×16×16、32×8×16、8×32×16；warp matrix 支持从 CC 7.0 起 | 所有 FP16 张量乘法均使用该路径 |
| WMMA BF16 | BF16×BF16，FP32 accumulator | 相应 alternate floating point 功能从 CC 8.0 起，形状对应 half 的相关组合 | BF16 与 FP32 精度相同 |
| WMMA TF32 | 规定转换后的 float 输入，FP32 accumulator | 16×16×8，CC 8.0 起的相应功能 | FP32 存储自动完成完整 FP32 乘法 |
| WMMA 整数 | signed/unsigned 8-bit 输入，int accumulator | 特定 16×16×16 等组合，仍需核对目标架构 | W8A16 或任意零点、组尺度可直接套入 |
| experimental sub-byte WMMA | s4/u4 输入，int accumulator | 8×8×32，布局和步长受限；相关 s4/u4 变体在 sm_90 移除 | 更新设备一定保留旧 INT4 接口 |
| CC 9.0 Tensor Core FP8 | E4M3 或 E5M2 输入能力 | 架构节列出 FP8；具体指令、累加和缩放另核 | 普通 WMMA 表就是完整 FP8 API |

fragment 是架构相关的不透明分布，不是稳定的行列数组或跨不兼容编译架构的 ABI。实际 dispatch 还受目标二进制、运行时库、stride、对齐和 shape 影响。

## 从逻辑 tile 到矩阵指令：共享存储交接

下面选用一个完整 warp、普通同步 WMMA、FP16 输入及 FP32 accumulator 的 16×16×16 路径，计算独立输出 C=AB，不读取旧 C，没有 bias。A 为 M×K、B 为 K×N，维度非负；本例全局输入按行主序保存，可在暂存时转换为 FP16。转换和累加的舍入属于数值路径，不能把数学 AB 当作浮点逐位结果保证。非有限值或转换溢出须按调用者约定拒绝或进入明确的例外策略。

每个输出 tile 的起点为 (m0,n0)=(16bm,16bn)。它独占有效输出与该 tile 的交集。M=0 或 N=0 时无输出工作；K=0 时有效输出为零。全体 32 个 lane 保持存活；无效输出不使部分 lane 提前退出。

A_s、B_s 是各 16×16 的 FP16 行主序共享矩阵，C_s 是 16×16 FP32 行主序共享矩阵，三者基址均按 32 字节对齐，leading dimension 均取 16。目标接口须接受 matrix_b 的本例 row-major 配置；改变到 col-major 时重算共享布局，不能仅改标签。

协作搬运可明确分配给 lane λ∈[0,32)：对 u∈[0,8)，取 t=λ+32u，i=floor(t/16)，j=t mod 16。A_s[i,j] 和 B_s[i,j] 各有唯一写者；C_s 写回后的普通读取也可按这个分配进行。全局输入有效时的字节地址分别为 base_A+s_A·((m0+i)K+k0+j) 和 base_B+s_B·((k0+i)N+n0+j)，其中 s_A/s_B 为输入元素字节数；共享地址分别为 base_As+2t、base_Bs+2t，输出读取为 base_Cs+4t。非连续输入必须恢复为实际 stride 地址式。

```pseudocode
算法 WMMA16-STAGE
输入：A[M,K]、B[K,N]、独立输出 C[M,N]、有效输出 tile 起点 (m0,n0)
状态：单 warp 私有 A_s/B_s/C_s、跨 K 阶段保留的 FP32 accumulator fragment

1 检查 16×16×16、FP16 输入、FP32 accumulator 和操作数布局受目标 API 支持
   检查 A_s/B_s/C_s 基址均为 32 字节对齐
   half leading dimension 为 8 元素倍数，float 为 4 元素倍数；本例均为 16
2 全 warp 一致初始化 accumulator 为 0；输入槽初始可写
3 对 k0=0,16,32,... 且 k0<K：
     确认上一阶段所有共享输入读者已结束，才允许覆盖 A_s/B_s
     每个 lane 按 t=lane+32u 分工写满 A_s/B_s：
       有效全局下标加载并转换为 FP16
       无效位置写 FP16 零，不计算并解引用越界地址
     全部 32 个 lane 执行同一全掩码 warp 同步：
       所有有效写入与零填先完成，并对该 warp 的消费者建立内存顺序及可见性
       单 warp 普通共享内存交接可使用全体参与的 __syncwarp
     此后全体成员以一致参数集体加载 A/B fragment
     按普通同步 WMMA API 的调用依赖完成装载，再执行矩阵乘加
     保留 accumulator，等待本阶段 API 规定的输入读取完成
     全部 32 个 lane 再执行全掩码 warp 同步，确认所有旧输入读者均已结束
     此后输入槽可供下一轮覆盖
4 全部 K 阶段完成并使 accumulator 可消费后，全 warp 集体按 row-major 写回 C_s
5 在 C_s 的全部写回完成后，全体 32 个 lane 执行全掩码 warp 同步，
   为随后的普通共享内存读取建立完成与可见性
6 lane 按 t=lane+32u 的明确行列分工读取 C_s[i,j]
   仅当 m0+i<M 且 n0+j<N，才写全局 C[m0+i,n0+j]
7 C_s 若要复用，等待所有读取它的 lane 完成后再覆盖
```

输入槽的状态顺序为“可写 → 写入与零填 → warp 发布 → fragment 消费 → 全部读者结束 → 可写”；输出槽为“集体写回 → warp 发布 → 按行列读取 → 可复用”。装载之后再等待，不能补救装载时已经读到的旧值；输出 store 的集体一致性也不能省略与后续普通读取之间的交接。

本例的同步作用域足够，是因为 A_s/B_s/C_s 的写者和读者都限定在同一个完整 warp 内。跨 warp 协作应建立覆盖所有参与者的 CTA 同步或其他正确协议；局部 __syncwarp 不会使另一个 warp 的写入自动就绪。若改为 cp.async、TMA 或异步矩阵指令，还须先满足各自的复制、代理和操作数读取完成契约，不能把普通 warp barrier 当成通用异步等待。

处理完 t 个 K 阶段后，数学 accumulator 对应前 min(16t,K) 项乘积之和；实际计算还受 FP16 转换和 FP32 累加舍入影响。尾块在 A/B 的相同无效 K 位置均填零，不改变有限输入的有效归约。fragment 内部映射始终由公开 API 承担；需要逐行非均匀处理时，先写回 C_s 再读取明确行列。

与压缩权重组合时，若 B[k,n]=Ŵ[n,k]，暂存写者先从权重行 n 的字节 n·ceil(K/2)+floor(k/2) 提取 nibble，再符号扩展，读取 S[n,floor(k/G)]，重建并转换为 B_s[k-k0,n-n0]。因此逻辑转置可以在搬运时完成，无须完整物化高精度权重。码、尺度和重建值全部生成后，仍须经过装载前发布。若另选整数部分和路径，跨组尺度则必须在相应部分和上应用，不能借用本例已反量化 FP16 的数据流来省略尺度处理。

## 条件化成本：字节、计算、准备与驻留

设 D=d_out、K=d_in，每组元数据合计 m 字节。本节逐行 INT4 布局的精确码容量为：

B_code=D·ceil(K/2)，B_meta=D·ceil(K/G)·m，B_weight=B_code+B_meta+B_align。

更一般的连续 b-bit 位流才可使用 ceil(DKb/8)；逐行从新字节开始的布局应使用 D·ceil(Kb/8)。例如 D=3、K=3 的 INT4 码占 6 字节，不能用整张量连续位流的 5 字节估计本版布局。有效位宽为 8B_weight/(DK)，仅对 DK>0 定义。

对 4,096×4,096、4 bit、G=128、m=4，码为 8,388,608 字节，元数据为 524,288 字节，总计 8,912,896 字节，即 8.5 MiB、4.25 bit/weight；元数据是码字节的 6.25%。m=4 是成本设定，不声明本例对称格式必须存放零点。对齐、长度表、版本、重打包副本和工作区另计。

若 M 行激活的一次前向只读取每个权重和元数据一次，忽略尾组、激活与输出，权重读取口径的算术强度约为 16M/(b+8m/G) FLOP/字节。M=1、b=4、G=128、m=4 时约为 3.76；它不是完整设备算术强度，更不是设备事务或实际带宽。

完整解包到 FP32 时，上述压缩权重另产生 64 MiB 高精度副本。若每轮都写出再读取该副本，至少新增该副本的写读交通；容量与带宽收益可能被抵消。tile 内解包避免完整物化，却可能重复提取码和读取参数。需要比较移位、符号扩展、尺度乘法、类型转换和后续复用，不能从压缩比直接推算时间。

WMMA 算例的两个 FP16 输入 tile 合计 1,024 字节，FP32 输出暂存为 1,024 字节。accumulator 有 256 个 FP32 值，按 32 lane 平均为每线程 8 个累加值；实际寄存器还包括 fragment 输入、地址和临时量。输入单缓冲与独立输出暂存合计 2 KiB 共享容量，双缓冲另加 1 KiB 输入空间。

对 J=ceil(K/16)，仅按逻辑有效载荷计，输入暂存的共享写和 fragment 读取合计约 2,048J 字节，输出写回再普通读取为 2,048 字节；这些不是 bank 事务或 HBM 字节。本例保守同步组织有每阶段发布、每阶段读完及一次输出发布，共 2J+1 个 warp barrier。能否合并某些边界必须依据新的完成证明，不能从成本账直接删同步。

当 M=1 直接使用 16 行 tile，有效行利用率仅为 1/16；K 非整除还浪费末段乘加。可比较 scalar/GEMV、其他合法 tile、跨请求合批或 split-K。大 prefill 对权重的多行复用更高，固定转换和装载开销更易摊薄，但计算吞吐和驻留也更可能成为限制。

按组整数归约时，K=4,096、G=128 有 32 组。若 16×16 输出 tile 同时保留每组 FP32 部分和，仅它们就需 256×32×4=32 KiB。逐组缩放后累加可缩短生存期，但改变指令组织和浮点顺序；跨线程或跨 CTA 分组还增加部分和写读、通信和合并同步。

准备包括校准、量化、打包、布局转换、JIT 与图捕获。一次准备为 C_prep、每次节省 Δt、实际复用 R 次，只有 RΔt>C_prep 才可能在该边界内收回；形状未命中和重新打包另计。峰值驻留分别相加：packed 权重、尺度、同时存活的解包片段、高精度副本、工作区和图缓冲，不能因文件为 4 bit 就把运行时驻留按 4 bit 计算。

通信按实际物理副本计。尺度随权重复制到多个 rank，就有多份容量及传输；跨分片组还需保留逻辑组身份或生成新制品。动态激活尺度若依赖跨 rank 统计，需要归约及其完成同步。共享 HBM、执行单元或网络的阶段不能同时领取各自的理想重叠收益，应按依赖图和竞争资源估计关键路径。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的关系 | 调整对象与成本 | 放弃或改选条件 |
|---|---|---|---|
| 小 batch decode，权重读取主导 | 压缩可减少候选读取字节 | 比较 tile 内解包、参数访问、启动、实际 dispatch | 新增转换和同步超过读取节省时保留较高精度路径 |
| 大 prefill，计算主导 | 同一权重可服务更多行 | 比较低位矩阵路径、转换后矩阵乘和成熟高精度 kernel | 低位路径不能有效使用计算单元时改选 |
| G 变小 | 更细网格可能减少近似误差 | 重建码与参数，增加组数、元数据和部分和成本 | 参数流量或工作区成为主项时增大组或改布局 |
| scale 存储精度降低 | 码由实际保存尺度解释 | 先转换并冻结尺度，再编码和验证 | 尺度不再有限且为正时拒绝配置 |
| b 从 4 改为 8 或其他值 | 量化数学和组身份可重新定义 | 更换完整位流版本、偏移与解码规则 | 本版 nibble 编解码直接拒绝，不沿用左移 4 位 |
| 目标架构改变 | 数值契约可保留 | 重核指令、布局、对齐、线程范围和驻留 | 无合法高效 kernel 时选成熟路径或重新打包 |
| 单 warp 改为多 warp | 生产后消费、读完后复用仍成立 | 将同步范围扩至全部真实写者和读者 | 只保留局部 warp barrier 时拒绝该执行组织 |
| K 非整除或奇数行尾 | 有效元素与逻辑组身份不变 | 增加掩码、尾组元数据及独立行尾字节 | 填充被消费或组错位时修格式，不能放宽数值容差 |
| KV 使用 FP8，Q/O 为 FP16 | attention 的状态定义可保留 | 区分 KV 存储、反量化、QK/PV 算术与输出 | 无证据时不推广成整个 attention 的 FP8 算术 |
| 敏感层恢复高精度 | 模型接口和消费者保持一致 | 重算驻留、传输、切换和工作区 | 质量或 SLO 仍不满足时放弃组合 |

SmoothQuant 的 Wx=(WD)(D⁻¹x) 在实数上等价，要求 D 可逆且所有消费者补偿同一变换；量化后的误差仍需验证。FlashInfer 固定论文附录 F 的一条路径是 FP8 KV 存储、FP16 query/output 并执行反量化，不能据此声称整条 attention 均采用 FP8 矩阵算术。

## 诊断：竞争解释、独立参考与负对照

先用同一码和冻结参数做独立解码，再比较解量化后的高精度算子与目标 kernel，最后比较量化模型与原模型质量。三个边界分别定位表示/布局、执行数值和算法近似。

| 观察 | 竞争解释 | 区分实验 | 反证后的修正 |
|---|---|---|---|
| W4 比 W8 慢 | 解包、参数流量、fallback、小 M 启动或驻留下降 | 固定质量与 shape，改变 batch/组长，记录实际内核、local 交通、工作区和时间线 | 字节下降但耗时不降时查新增阶段和瓶颈位置 |
| shape 正确但数值错误 | nibble 顺序、符号扩展、组轴或尺度导出改变 | 用固定字节和独立解码，分别改变一组尺度或一个 nibble | 解码失败先修格式，再讨论量化质量 |
| 非默认位宽往返失败 | 用固定 nibble 协议解释其他 b | 尝试 b=8 的 [16,0]、[0,1]，要求编码和解码入口拒绝 | 若碰撞被接受，收紧契约或实现新版本完整位流 |
| 同一码的点积不同 | 分组尺度提出归约、累加顺序或转换精度不同 | 两组不同尺度，与逐元素解量化参考比较，注入单一 epilogue | 解码相同而归约错时修单位与应用位置 |
| WMMA 偶发错误 | 输入未发布、旧输入被覆盖、布局/ld 错 | 软件模型推迟发布和读完；设备上另做合法 load→store 交接并核验同步 | barrier 放在装载后仍错时移到消费前，重新证明作用域 |
| C_s 按行读取错误 | 集体写回未对普通读取可见、fragment 行列猜测或掩码错 | 先集体 store，再显式同步并按 C_s 下标比较；注入缺失输出发布 | 交接失败先修完成依赖和布局，不归因于量化误差 |
| FP8 出现 inf/NaN | 输入饱和、scale 下溢、累加溢出或输出转换 | 用固定极值分别改变转换、累加和输出策略，检查每个边界 | 先定位表示、算术或 epilogue，再调整方案 |
| API 接受但性能不变 | 内部转换/fallback，或其他资源主导 | 查实际选中内核和生成指令，分开准备与稳态，改变 shape | fallback 存在则修 dispatch；目标路径成立则重查瓶颈 |
| INT8 长归约越界 | 采用 127² 的错误界，或遗漏初值/bias | 比较 K=131,072 的 128² 与 127² 界，加入非零初值 | 修中间范围或使用更宽累加 |

负对照必须进入实际被检路径。符号检查要真的打包含负码的字节；尺度检查要让各组尺度不同；同步模型要先读未发布输入再晚发布，确认晚等待不能修正已取得的值。正确的同步伪代码是契约论证，软件事件模型仍不能证明 GPU 内存语义已经执行正确。

随附 tools/check_k_hw_004_full.py 使用 Python 标准库，确定性、离线且只读。它穷举全部 256 个 INT4 码对，用独立算术字节参考验证唯一性和往返，覆盖空输入、奇尾、逐行容量、非法码、非 4 位拒绝及原 b=8 碰撞负对照；以 Fraction 枚举最近网格验证有理数子域的参数冻结与编码；检查分组尺度、容量和 INT8 界。共享存储部分用明确的“待发布/可见”状态模拟逻辑 tile，与独立稠密乘法比较，覆盖 K=0/1/16/17/32，并检测装载前未发布、C_s 读取前未发布、下一轮覆盖前未确认读完三种故障。

该检查中的矩阵运算只使用可精确表示的小整数，未模拟真实 fragment lane 分布、FP16/FP32 的完整舍入、GPU 调度或缓存一致性。它不执行 CPU/GPU 目标 kernel、不生成机器指令、不记录事务或时间，也不评价模型质量。E3/E4 仍须在目标环境取证。

CPU 核验还应记录线程池、NUMA、预打包缓存、ISA 与 shape 专门化，确认是否重复打包、误入 fallback 或由 unpack 主导。GPU 则观察转换、矩阵计算、epilogue、工作区和同步的完整时间线。性能结论应来自相同工作量与质量约束，不能以“dtype 支持”或软件模型通过替代。
