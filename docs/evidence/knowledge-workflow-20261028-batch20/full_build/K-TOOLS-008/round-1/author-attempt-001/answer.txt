{"chapter":"# K-TOOLS-008：GPU 从零表征：可持续带宽、矩阵吞吐与测量条件\n\n资源模型里的带宽、算力和提交成本应来自目标设备上、与服务形态匹配的测量；铭牌峰值、异代结果和未声明条件的单次最高值不能直接代入。本章把从零表征视为辨识一个带条件的资源参数包，而不是给设备打一个分数。能力表与 compute capability 事实见硬件章节，本章不列 CC 差异表。\n\n## 表征对象、条件身份与合法性\n\n一次测量至少绑定条件元组\n\n`c = (设备与介质, 主机拓扑, 驱动与运行时, kernel 或库路径, dtype 与 shape, 访问形态, 工作集, 并发与共置, 时钟与功耗状态, 计时边界, 持续时长)`。\n\n输出不是裸标量，而是带条件谓词的参数条目\n\n`p = (名称, 数值, 单位, 适用条件, 不确定范围, 证据身份)`。\n\n同一设备上，顺序大块读、跨步随机读、L2 命中路径、矩阵指令路径、主机设备链路和短 kernel 提交是不同资源轴。一个条目只有在其适用条件被当前 workload 蕴含时才能进入成本模型；条件不蕴含时应重测、换条目或保留未知。把 `B_HBM(seq)` 代入不规则 KV 读取，或把 L2 命中后的表观速率当作 HBM 带宽，都是条件身份错误，不是精度问题。\n\n定义本次执行范围内的有效需求字节 `D_use`、实际事务字节 `D_tx` 和完成时间 `T`：\n\n`B_use = D_use / T`，`B_tx = D_tx / T`，放大 `A = D_tx / D_use`。\n\n`D_use` 是消费者真正需要的有效字节，`D_tx` 是同一请求集合在指定边界上实际传送的事务字节。两者必须来自同一请求集合和同一时间窗；若有效负载 128 B 被拆成 160 B 事务，匹配模式的有效带宽与事务带宽会给出同一时间，不能把 160 B 再除以已经包含放大的 128 B 速率，重复惩罚同一次浪费。\n\n计算侧定义 `F` 为按声明计数规则得到的有效算术工作，`P_eff = F / T`。矩阵乘一般按一次乘加为 2 FLOPs 计主项，但 padding、重复计算、指数、解包和转换要另列，不能未经说明一起除以矩阵峰值。\n\n计时边界必须单独声明：host API 返回、设备事件完成、输出消费者完成和完整请求完成是不同事件。CUDA API 可以异步返回，host 计时若未与设备完成对齐，会把排队或未完成工作算成很短；设备事件也可能不覆盖输出复制和消费者。只有边界相同的量才能相减或相除。\n\n合法性条件包括：被测工作确实完成；分母与有用工作属于同一范围；计时区没有未声明的分配、首次缺页或额外同步；工作集、cache 状态、并发和时钟策略已记录；重复观察没有显示强非平稳。冷 cache 与热 cache 都可以测量，但必须分别标记，不能把冷启动结果外推为稳态，也不能把热态命中速率写成全局 HBM 能力。锁定时钟是一种实验选择，不保证目标服务的功耗和散热条件。\n\n单次最高值不是可持续参数。至少保留重复层级、范围或离散程度，并区分短窗 boost 与长窗可持续点。测得的有效速率是带条件的估计，不是数学上不可突破的硬上限；它能支持相应条件下的成本预测，不能单独证明某个 kernel 已经达到硬件极限。\n\n## 从测量计划到参数包\n\n表征的状态链是：计划已定义 → 输入已准备并预热 → 样本已采集 → 条件与分母已核对 → 交叉条件已检验 → 条目已发布或标为未决。未决条目不能悄悄用默认峰值补洞。\n\n```pseudocode\n算法 CharacterizeDevice\n输入：设备与拓扑身份；服务形态集合；候选访问形态与 shape 网格；时间与存储预算\n输出：带条件标签的参数条目；未决原因；下一项区分实验\n\n1 固定设备、驱动、运行时、kernel 或库路径、计时边界和并发集合\n   记录实际内存介质、链路代数与宽度、时钟策略、功耗模式和机箱条件\n2 为每个资源轴列出能区分解释的访问形态：\n   顺序与跨步；工作集小于与大于 L2；dtype 与 shape 角点；\n   单向与双向链路；不同消息大小；单消费者与声明强度的多消费者\n3 对每个候选建立有效输入，分离首次分配、首次缺页和预热\n   计时区只包含声明的工作；需要冷 cache 时显式清理并记录\n4 采集重复样本：记录完成时间、有效字节或 FLOPs、事务字节（若有）、\n   时钟、功率、并发、失败与未完成状态\n   若计时边界不是设备完成，不能把 host 返回当设备完成\n5 对每个样本按同一范围计算 B_use、B_tx 或 P_eff\n   拒绝零或负时间、分母缺失、未完成工作、条件字段缺失的样本\n6 改变一个相关条件做交叉对照：\n   扩大工作集削弱 L2 复用；改变跨度改变事务数；改变并发观察份额；\n   改变持续时长观察降频；改变链路方向观察共享上游\n7 若模型预测随干预按预期改变，保留条目及其条件谓词\n   若多个解释仍不能区分，保留未决项和原始证据，不发布单一常数\n8 将条目连同环境、方法、重复范围、证据身份和日期交给观测记录\n   后续服务形态改变时重新选择条目或重测，不覆盖旧条件的历史\n```\n\n数据流上，候选先变成可执行测量，再变成原始样本，再变成按边界计算的速率，最后才变成参数条目。`D_use`、`D_tx`、`F` 和 `T` 的轴与单位在这一链中不能换名。测量本身也有成本：计算、访存、通信、准备、同步和驻留都会消耗预算；重复次数增加会提高证据量，也会增加热、功耗和存储成本。\n\n## 可持续主存带宽：顺序、随机与事务粒度\n\n设备主存可能使用 HBM 或 GDDR；测量边界应说明实际介质。顺序大块读、跨步随机读、读写混合和不同事务粒度会得到不同数值。把其中最大者当作设备带宽，会系统性低估不规则访问服务路径的成本。\n\n在固定 CUDA 12.8.0 文档的 CC≥6.0 标量访问模型中，32 个 lane 各读一个 32-bit 字，字节地址可写为\n\n`addr(λ) = base + o + 4λ`，`λ = 0,…,31`。\n\n一次请求覆盖的 32 B 段集合为 `{floor(addr/32)}` 的并集。若 `base` 按 32 B 对齐、`o=0`，128 B 有效负载覆盖 4 个段；`o=4` 时覆盖 5 个段；跨度改为 8 B 时，32 个 4 B 字分布到 8 个段。这里数的是请求覆盖段，不是最终 HBM 事务；相邻 warp 的 cache 复用、L1/L2 命中和写合并还会改变设备主存字节。\n\n设定算例：工作集 8 GiB、顺序读可持续 1.0 TiB/s，同一设备上 128 B 跨步随机读测得 0.35 TiB/s。把 decode 的 KV 不规则读取代入 1.0 TiB/s，会把流量时间下界压低约 2.9 倍。这不是某卡实测，只说明访问形态必须进入带宽身份。\n\n常见误读包括：把 cache 命中后的瞬时速率当作 HBM 带宽；把未合并事务的设备字节当作有效张量字节；在多进程共享同一控制器时，把单消费者结果当作服务可用份额。跨步请求的段数增加也不自动等于 HBM 字节同比增加，必须继续查 cache 与下层事务。\n\n接到资源模型时，至少建立 `B_HBM(seq)` 与 `B_HBM(random, granule)` 两个身份；若服务混合顺序权重读取和不规则 KV/索引读取，不能用一个标量同时代表两者。\n\n## L2：容量边界与表观带宽\n\nL2 复用会让观察到的 HBM 字节低于张量逻辑读取字节。设同一请求集合的逻辑有效字节为 `D_use`，其中已证实由 L2 满足的字节为 `D_hit`，则只有在该命中字节确实属于同一请求集合时，才能写\n\n`D_HBM = D_use − D_hit`。\n\n表观速率 `D_use/T` 不是 HBM 速率；它混合了片上命中路径和主存路径。表征至少需要两个工作集：明显小于估计 L2、明显大于估计 L2，并记录命中相关计数或 HBM 事务差。工作集跨过有效容量后，同一 kernel 的表观带宽会贴近 HBM，但拐点受并发、替换策略和其他消费者影响。\n\n设定算例：工作集 8 MiB 时某读核表观 2.5 TiB/s，工作集 2 GiB 时降至 0.95 TiB/s。服务若每步重扫数 GiB 权重，应以后者为流量下界输入；若某层激活反复命中 L2，则应对该层单独减小 `D_HBM`，而不是抬高全局 `B`。\n\n常见误读是：用单点工作集外推所有形状；把 L2 命中节省重复计入融合收益和带宽提升；在改变复用距离后仍沿用冷缓存微基准。L2 容量提示也不是保证，多个 stream 或其他消费者会竞争同一保留区和 cache 容量。\n\n接到资源模型时，在流量账中区分 `D_HBM` 与 `D_L2`；复用距离改变时重测或把命中项标为未知，而不是把表观速率写成全局主存能力。\n\n## 各 dtype 与 shape 家族的矩阵吞吐\n\n矩阵能力随 dtype、累加精度、布局、M/N/K、是否使用专用矩阵路径以及是否受占用率或共享存储限制而变。FP16 峰值不能外推到 INT8 或 FP8；同一 dtype 下小 M 的 decode 形与大 M 的 prefill 形也不是同一参数。\n\n测量条件应声明：库或 kernel 路径、是否允许宽松累加、输入是否已在设备、是否计入 host 打包、形状网格是否覆盖目标服务的 decode 与 prefill 角点。吞吐用有效 FLOPs 除以墙钟，同时记录是否触顶功耗或降频。若自动调优只报告最好 shape，不能把它当作全服务常数；布局转换、padding 和一次性的权重打包要另列。\n\n设定算例：某形态下 BF16 GEMM 可持续 150 TFLOP/s，同设备 FP32 为 40 TFLOP/s；另一形态 M=1 的 GEMV 有效算力远低于大矩阵屋顶。将大矩阵屋顶代入 batch=1 decode，会得到虚假松弛的计算下界。\n\n接到资源模型时，为关键算子族建立 `P(dtype, shape_family)`；算术强度用匹配的 `P` 与对应边界的 `B`。若一次 dispatch 实际回退到另一指令路径，源码声明支持该 dtype 不能证明本次执行使用了预期矩阵路径。\n\n## Launch、图重放与提交边界\n\n大量短 kernel 时，主机提交、依赖解析与空档可与设备工作同量级。设每轮 eager 路径有 `K` 次提交，单次主机提交与分派成本约 `h`，设备工作为 `D`，主机项可写 `H_eager = K h`。若主机与设备能充分重叠，单轮稳态近似受\n\n`T_round ≈ max(H_eager, D)`；\n\n若同一请求必须等主机提交完成后再启动，或依赖链使两项不能重叠，则应把相应串行段相加。图重放把重复提交摊薄为 `g`，但捕获、实例化和失效摊销另有成本。\n\n若图路径每轮主机成本为 `H_graph = g`，捕获与准备一次性成本为 `C0`，则粗略盈亏平衡调用数满足\n\n`N > C0 / (T_eager − T_graph)`，分母必须为正。\n\n设定算例：eager 每步 80 次 launch，平均提交空隙 15 μs，合计 1.2 ms；同工作图 replay 设备侧 0.2 ms。若同步 HBM 流量下界已 12 ms，提交项不是主矛盾；若流量下界仅 0.8 ms，提交项进入关键路径。若捕获成本 10 ms，而每轮只从 1.2 ms 降到 0.8 ms，盈亏平衡约为 25 轮；没有足够复用次数时，图路径可能不回本。\n\n常见误读是：把图加速比当成算子变快；在地址或形状每步变化时仍引用稳态 replay 成本；忽略捕获、桶切换和旧图排空的一次性延迟。图不改变内部长 GEMM 的算术与 HBM 项，只摊薄重复提交；若 host 已不在关键路径，图路径对完整 ITL 的改善可能很小。\n\n## PCIe 或其他主机设备链路：方向与双工\n\n主机设备链路有方向、并发复制引擎数量和上行共享。设 H2D 与 D2H 的字节分别为 `V_H2D`、`V_D2H`，对应单向可持续速率为 `B_H2D`、`B_D2H`。完全串行时\n\n`T_serial = V_H2D/B_H2D + V_D2H/B_D2H`；\n\n两个方向能独立重叠时，若每个方向各有可持续容量，则 `T_full = max(V_H2D/B_H2D, V_D2H/B_D2H)`；若两者共享同一上游开关，则应使用双工实测曲线或共享容量 `B_shared`，例如 `T_shared = (V_H2D + V_D2H)/B_shared`。不能无条件把两个单向峰值相加。\n\n测量条件至少固定：PCIe 代数与链路宽度或报告拓扑；钉住主机内存；分别测纯 H2D、纯 D2H、双向；消息大小从小于到大于 page 或 segment；说明是否使用 GPUDirect 或额外 bounce；声明是否有磁盘、NIC 或其他 DMA 争用同一根复合体。\n\n设定算例：单向 H2D 可持续 28 GiB/s，双向各方向约 20 GiB/s。若每步必须同步回传 64 MiB logits，并与 256 MiB 输入预取重叠，链路时间不能再用单向峰值估算；双向共享时的总时间要按双工曲线或共享上游容量计算。\n\n常见误读包括：用设备互连数字填 PCIe 项；把 pinned 与 pageable 混用后的结果当链路能力；忽略与其他设备共享的上游开关；把 host API 返回当作复制完成。\n\n## 持续负载下的时钟、功耗与漂移\n\n短微基准可在 boost 区间跑完；服务长窗常触及功耗、温度或空闲降频。表征需要在目标功耗模式与机箱散热条件下，记录可持续 SM 与内存时钟、整卡功率以及是否触发限流。\n\n测量条件：负载持续足够长以越过瞬态；同步采集功率与时钟；区分空载、仅拷贝、仅计算与混合服务负载；声明是否锁定应用时钟。设短窗测得的矩阵吞吐为 `X`，连续 60 s 同核因降频降到 `0.85X`，把 `X` 写入长时间 ITL 预算会高估算力。这个数值是设定算例，不是某卡实测。\n\n功耗墙应作为独立约束进入成本账，而不是事后装饰。若服务持续时间、机箱风扇曲线或共置负载改变，原来短窗参数失效；需要重新测可持续点，或把结果标为只能支持短窗结论。\n\n## 并发消费者与资源份额\n\n多进程、多上下文或多流消费者共享 HBM、L2、复制引擎与 SM。单消费者表征给出上界；服务实例数、同卡训练作业或同机其他 GPU 的 DMA 都会改变可用份额。\n\n设单消费者速率为 `R(1)`，`n` 个同强度消费者的总吞吐为实测 `R_total(n)`。等分时每消费者份额约为 `R_total(n)/n`，不能写成 `n R(1)`。设定算例：单进程顺序读 1.0 TiB/s；两进程各打满时合计 1.1 TiB/s、每进程约 0.55 TiB/s。第二个服务副本不能按再乘一个 1.0 扩容。\n\n测量条件应固定干扰源集合与强度，报告每消费者分得的有效带宽或算力，以及总吞吐是否次线性。区分时间片共享与真正并行；MPS 或分片配置下的隔离不等于物理带宽加倍。\n\n## 参数包如何写入资源模型\n\n一次从零表征产出的不是单一 GPU 分数，而是带条件标签的参数包：`B_HBM(seq)`、`B_HBM(random,granule)`、L2 有效容量提示、`P(dtype,shape_family)`、`c_launch`、`c_replay`、`B_H2D`、`B_D2H`、双工曲线、可持续时钟与功率点、多消费者曲线。服务 roofline 选用与当前关键路径形态匹配的条目；形态改变则重选或重测。\n\n对独立资源轴，局部下界可写为\n\n`T_lb = max_j (F_j/P_j, D_j/B_j)`；\n\n若两个阶段有依赖或共用同一独占资源，不能直接取 max，应按依赖路径相加，或把共享资源的总需求合并后用同一容量估值。`max` 是各项必要时间的下界，即使资源不能重叠仍成立；把它当作可达到的完成时间，需要足够并行度、独立资源和充分重叠。\n\n组合轨迹的设定算例：一轮读取 8 GiB 顺序权重、2 GiB 不规则 KV；顺序项约 7.8125 ms，随机项约 5.58 ms。两者共用 HBM，不能各取一份独立带宽后只取 max；若分阶段执行，流量下界约为两者之和，若混合并发则要用混合访问实测曲线。另有 64 MiB D2H logits，按 28 GiB/s 约 2.29 ms；它属于另一条链路，可与 HBM 工作并行时进入 max，若必须先回传再继续则进入串行路径。80 次 launch 的主机项约 1.2 ms，在 HBM 主导时可能被隐藏，在 0.8 ms 流量下界时则可能进入关键路径。这里所有数值都是设定计算，不是设备测量。\n\n微基准与完整服务之间保留校准差：把预测下界与实测迭代时间的差额拆成重复流量、同步、争用与排队。差额不能用调高某个峰值参数来抹平。\n\n| 成本类别 | 表征与模型中的对象 | 需要防止的重复计算 |\n|---|---|---|\n| 计算 | 有效 FLOPs、padding、转换、归约 |
