{"chapter":"# K-ENGINE-004：前缀复用决策：树、块链与状态保护\n\n前缀复用的动机是相同依赖产生的中间状态可以避免重复计算。索引回答在哪里找到可能相同的前缀，恢复与所有权机制回答它是否能被当前请求安全使用；两者不能合并成一个“命中”布尔值。SGLang 的 RadixAttention 把 token 前缀树、KV 状态、活跃引用和叶优先淘汰放进同一运行时决策，但树路径只给出候选；调度器还必须确认共同可恢复位置、末行输出资格、物理页和容量。\n\n## 问题、对象与身份\n\n固定影响前向状态的等价条件 η，包括模型与权重版本、规范化 tokenizer 与模板、adapter、位置与窗口规则、外部特征身份、数值合同和隔离命名空间 ns。请求的已知输入为 x[0:n)。位置 p 表示已经消费 x[0:p) 且对应状态 S(p) 已就绪；它不是“已生成 token 数”的同义词。普通因果 decoder 的 S(p) 主要是逐层 K/V，混合模型还可能包含窗口、递归或外部控制状态。\n\n本章把一次可复用对象写成 v=(label,parent,children,pages,ref,cached,last_used,ns)。label 是父节点之后、本边新增的 token 切片；pages 指向该切片实际占用的物理页或页内有效范围；ref 是正在消费该路径的请求数；cached 表示目录是否为了未来命中而保留它；last_used 只参与淘汰排序，不是正确性条件。根节点不代表任何 token 状态。沿根到 v 的标签连接必须等于一个逻辑前缀，边的 token 粒度与物理页粒度可以不同。\n\n一次安全命中因此返回四元组 (p,覆盖节点,受保护路径,状态清单)。p 是所有必要状态族共同有效的恢复点；覆盖节点说明索引找到哪段路径；受保护路径保证读取期间不被回收；状态清单说明层、分片、表示和有效范围。只返回最长 token 匹配长度，会把“索引存在”误当成“当前请求可以执行”。\n\n## 合法性、共同恢复点与方案选择\n\n相同 token 前缀只有在相同 η 与 ns 下才可能复用。token 串相同但 adapter、位置规则、图像内容或数值表示不同，必须走不同根或不同身份记录。匹配落在边内部时，只有该位置能由状态切片、页边界和所有状态族的共同恢复位置表示，才能作为 p。普通完整页协议把 p 向下取整到页边界；单 token 页可以在任意 token 边界切分，但其他实现不能照搬这个结论。\n\n完整 KV 命中没有末行 logits 时，普通生成仍要安全重算最后一个已知 token，通常取 p≤n−1；若任务只恢复状态或另有合格 logits 票据，才可能允许 p=n。空输入是否可启动生成由任务接口定义，不能从空树自动生成一个已知末行。\n\n树、固定块链和直接重算都可以合法。树适合多级共享和边内分叉，成本是查找、切边、引用和淘汰元数据；块链以父块身份表达前缀，查找简单但中间分叉与尾块粒度受页长限制；直接重算不保留索引状态，适合短前缀、低重用或容量被更有价值工作占用的情况。选择取决于重用轨迹、边切分是否可表达、索引/驻留成本和读保护，而不是树一定优于其他结构。\n\n切边本身只重排索引和状态切片描述。若节点仍有活跃引用，原地把引用计数切成两半会产生无法配对的读者；本章的保守算法只在无活跃引用的节点上原地切边，有活跃引用时停在已有节点边界或等待保护结算。生产实现若要在活跃边上切分，必须有明确的引用继承、叶身份和回收顺序，不能仅把标签改短。\n\n## Radix 树的匹配、切边与保护\n\n匹配从根开始，用首 token 找子边，再比较整段标签。若查询在边内结束或与边在中间分叉，可以在合法切片边界建立中间节点；旧子节点改挂到新节点下并保留剩余标签与剩余物理切片。之后所有请求都能显式共享这段公共前缀。\n\n```pseudocode\n算法 MATCH_AND_PROTECT(root, ns, x[0:n), k ← 最长公共前缀长度(L, x[p:n))\n    k ← 向下取整到 child 可切分且可恢复的边界\n    若 k = 0：结束循环\n    若 k < L长度：\n        若 child.ref > 0 或 child 不能被切片：\n            只在 v 的已有节点边界停止；结束循环\n        建立 u，label ← L[0:k]，pages ← child.pages 的前 k 个单元\n        把 child 的 label 改为 L[k:]，pages 改为剩余单元\n        把 v 中原 child 替换为 u，并把 child 挂到 u 下\n        v ← u；p ← p＋k；把 u 加入 path；结束循环\n    否则：\n        v ← child；p ← p＋k；把 child 加入 为真只表示目录保留，不表示任意设备已经可见，也不表示末行 logits 已存在。匹配结束后，调度器只应把 p 作为可跳过上限，还要按本轮 q 检查容量和输出资格。\n\n## 发布、淘汰与缓存感知调度\n\n请求完成后，已经计算的完整状态可以进入目录。插入先在树中找到公共前缀；需要分叉时在合法边界切边，再为私有后缀建立新节点。新节点只有在全部必要层和范围完成并可见后才设置 cached。若相同身份已有可用节点，不能让两个目录项互相覆盖；重复副本应由各自的页和读者责任结算。\n\n```pseudocode\n算法 PUBLISH_COMPLETED(req, x[0:n), 新页)\n输入：完成请求、完整 token 序列、已完成的私有物理页\n输出：更新后的树和发布结果\n\n在协调区内：\n    v, p0, path ← MATCH_WITHOUT_PROTECT(root, req.ns, x[0:n))\n    若 p0 < n：\n        若有活跃边阻止切分：等待保护结算后重试，不发布部分状态\n        在 p0 处切分或在 v 下建立后缀节点\n        为 x[p0:n) 建立节点链，标签和 pages 按合法切片对应\n        核对新页覆盖全部必要状态和有效范围\n 与阻塞原因\n```\n\n排序只决定尝试顺序；真正防止超额承诺的是保护与预留的原子检查。把共享前缀的页数从每个请求各算一份会高估容量；把受保护页仍算作可淘汰又会低估需求。两个错误方向都会造成调度失败或运行期覆盖。\n\n## 条件化成本与反转\n\n匹配成本取决于沿路径比较的 token 数和子边定位方式。设等待请求数为 W、平均已知长度为 n、树节点数为 E，直接逐候选匹配约 O(Wn)，按 p 排序 O(W log W)，叶扫描淘汰最坏 O(E)。切边若只改标签、父指针和切片描述，是 O(1) 量级的元数据操作；若需要搬移物理内容或转换布局，则必须另计复制和同步。插入一条新后缀最坏 O(n)，目录元数据随 E 和边数增长，但物理 KV 按唯一页计算，不能把共享祖先重复计入容量。\n\n一次路径的时间可以写成串行事件账：\n\nT_path(p) = T_match(p) + T_protect(p) + T_wait + T_suffix(p) + T_publish\n\n其中 T_suffix(p) 已包含从 p 处理剩余输入及其对历史前缀的 Attention；T_wait 含排队和容量等待。与从零开始的 T_full 比较，净收益为 T_full − T_path(p)。若把完整 prefill 的节省和 suffix 的 Attention 对同一前缀重复相加，就会高估收益。\n\n设定一个长前缀 p=8192 的请求完整路径为 46 ms；命中后匹配与保护 0.3 ms、驻留机会成本 2 ms、suffix 计算 6 ms、发布 0.1 ms，路径为 8.4 ms，净节省 37.6 ms。另一个短前缀完整路径为 2.5 ms；命中路径为 0.3 ms 匹配保护、1.5 ms 驻留机会成本和 1.0 ms suffix，合计 2.8 ms，反而更慢。这里的数值是设定账，不是 GPU 实测；真实判断要测同一到达轨迹、同一完成边界和同一质量合同。\n\n离线理论给出一个有用但受限的结论：若同一批请求的缓存容量不小于最长请求长度，按 radix 树的深度优先顺序访问，可使每条边的 KV 只计算一次，达到该设定下的最优命中率；最长共享前缀优先在该条件下等价于 DFS。在线到达会破坏 DFS 连续性，活跃引用与短前缀请求会使贪心排序偏离该结论，因此不能把离线定理直接写成在线最优或公平性保证。\n\n## 反例、区分实验与检查边界\n\n反例一：token 字符串相同但 ns、adapter 或位置规则不同，却命中了同一棵树。它通常表现为结果内容错误而不是形状错误；应固定 token、改变一个参与前向的条件，要求命中位置从正数变为零或进入不同根。\n\n反例二：请求 A 正在读取公共前缀，淘汰器只看到缓存叶的 last_used 很老就释放祖先页。祖先的 ref 应因 A 的保护路径大于零；若释放后 A 仍能运行，只是时间上尚未读到，这种“暂时正确”不能证明协议正确。区分实验是延迟 A 的读取并强制容量压力，核对 ref、可淘汰集合和物理页是否保持。\n\n反例三：完整 KV 命中但末行 logits 不存在，调度器把 p 设为 n，下一轮 q=0，形成没有后继事件的停滞。修正应把生成资格与 KV 命中长度分开，安全重算最后一个已知 token 或读取合格票据；只改队列顺序不能修复。\n\n反例四：排序只看命中 p，不看截止时间和等待，长共享前缀请求持续插队，短请求或新请求饥饿。区分实验固定总工作与容量，只改变排序策略，记录每请求等待、完成和拒绝；若命中率上升而尾部时延恶化，应把公平约束或 deadline 放回准入，而不是继续增大 p 的权重。\n\n| 观察 | 竞争解释 | 区分改变与反证 |\n|---|---|---|\n| 命中率高但 TTFT 不降 | p 太短、共同状态未就绪、suffix 仍读取长历史、排队增加 | 固定 p 比较本地与重算；分别记录匹配、保护、suffix 和等待 |\n| 频繁淘汰且命中抖动 | 活跃引用保护了祖先、缓存感知排序造成抖动、容量不足 | 固定请求集改变容量；观察 ref
