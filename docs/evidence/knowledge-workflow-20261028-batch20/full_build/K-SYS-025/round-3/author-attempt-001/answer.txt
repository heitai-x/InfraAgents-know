K-SYS-025：已知张力：单实例交互式服务中的机制冲突\n\n单实例交互式生成服务把权重、KV、图缓冲、workspace、主机运行时和输出交付放在同一服务边界内。若干机制分别合法，却会争用同一带宽、容量或关键路径。本章把这种有条件的冲突称为张力：它不是实现错误的同义词，也不是任务必须逐项消除的缺陷清单。\n\n判断张力需要回答三个问题：改变了什么状态或资源需求；哪些依赖仍然存在；变化是否进入所关心的服务指标。图重放减少主机提交、分页减少重复驻留、投机增加每轮产出，都不能单独证明完整服务变快。\n\n## 对象、状态与统一账本\n\n限定普通 causal decoder 时，以 P 表示 prompt 终点，A 表示已确认 token 的右开边界，c 表示所有必要层均完整、可复用的连续 KV 右开边界，ℓ 表示尚未消费的末行 logits 票据。请求代次 g、执行事务 tx、物理分配代次分别保护业务归属、完成去重和地址生存期，不能相互代替。\n\nprefill 中 A=P、c<P；中间块只推进 c，不产生生成输出。普通生成中，A=c 且有 ℓ 时先采样确认 token[c]，使 A=c+1；随后计算该 token 的 KV，成功后 c 增一。A=c 而 ℓ 缺失时，应恢复末行输出或等待合法生产者，不能把不存在的 token[c] 送入 decode。投机另有暂定候选边界，只有接受路径进入正式历史。请求取消抑制业务交付，不证明已经提交的物理访问结束。\n\n一个执行视图 V 包含请求及其代次、输入行、逻辑位置、可见集合、页表版本、图桶、固定地址绑定和输出归属。诊断输入为相同模型、数值合同和外部请求轨迹下的视图及事件记录；输出为候选的合法性、条件化成本、竞争解释和下一次可区分的实验。\n\n| 账目 | 对象和单位 | 不能替代的量 |\n|---|---|---|\n| 计算 | 有效及实际执行的 FLOPs、解包、采样和归约工作 | padding、废弃候选和重算仍付计算成本 |\n| 访存 | 指定边界、方向的有效字节与实际事务字节 | 逻辑 KV 大小不等于 HBM 事务；容量去重不等于读取去重 |\n| 通信 | H2D、D2H、实例内 collective、状态迁移和网络交付 | 不能使用 HBM 带宽解释主机设备链路 |\n| 准备 | 分词、调度、页表、mask、打包、计划、预热和捕获 | 冷路径与逐轮准备分别摊销 |\n| 同步 | 生产可见性、反馈依赖、槽等待、最后消费者和排空 | host 返回不等于设备或消费者完成 |\n| 驻留 | 同时存活的唯一物理 backing，单位 byte；驻留积分为 byte·s | 池及池内对象不重复相加；取消后在途对象仍存活 |\n\n物理容量为 C(t)=Σ_{x∈Live(t)}bytes(x)，峰值为 C_peak=max_t C(t)，驻留积分为 ∫C(t)dt。相同物理键的多个持有区间先取并集；地址复用后属于新分配代次。分别取各类峰值相加通常只是保守上界，不能冒充已经发生的必要峰值。\n\n对同一资源上的消费者先合并需求，再估计 D_j/B_j 或 F_j/P_j；不能让两个 HBM 消费者各自领取完整独占带宽。整体还受阶段 DAG 的最长依赖路径约束。各资源必要时间的 max 是下界，不是任意执行的完成时间；串行前后继必须保留先后关系。匹配访问形态的可持续带宽是带条件的表征参数，改变共置、频率、工作集或访问模式后应重估，不能当成不可突破的硬件上限。\n\nITL_r,k 是同一请求相邻两个约定可见输出事件的时间差；TTFT 是到首个该类事件的等待。内部确认、服务端发送和客户端可见是不同口径。goodput 按同一窗口内满足质量与联合 SLO 的请求或 token 计算，并记录拒绝、失败和未完成工作。平均每 token 时间不能代替最大输出空档或尾分位 ITL。\n\n## 从候选到反证的判定算法\n\n先排除语义错误，再比较成本。合法性包括：模型、adapter、位置和缓存表示相容；每行只消费自己的合法历史；未发布状态不可读；写入共享尾部前隔离；固定图与其捕获地址绑定一致；输入生产先于消费；最后物理使用结束后才复用。桶、批、chunk、量化分组和调度优先级是这些条件内的选择。\n\n```pseudocode\n算法 O(v+e)，资源调度或候选枚举另计。请求扫描、计划准备和诊断采集也消耗主机预算，不能把控制算法视为免费。\n\n该流程只组织证据，不保证一定存在满足所有目标的候选。没有可行最小时间片、资源无法排空或 offered load 长期超过服务率时，应明确过载和恢复边界，不能用持续等待宣称可行。\n\n## Decode 带宽、批大小与逐请求间隔\n\n在每轮读取权重主项 W、各请求分别扫描可见 KV、同组 query heads 理想复用 KV 的模型中，读取主项为\n\nD_round≈W+c_KVΣ_r n_r。\n\nc_KV 是每个可见 token 的全层 KV 字节，n_r 是本轮实际可见位置数；当前行若已经计入 n_r，就不能再重复列为历史读取。新 KV 写入、激活、metadata 和事务放大另列。共享前缀可能只减少唯一驻留，各请求仍分别读取它。\n\n若每请求每轮确认一个 token，并且整轮完成是下一次输出的前提，则每请求仍等待 T_round。T_round/b 是全批每输出 token 的摊薄成本，不是该请求的 ITL。增加 batch 可使 W/b 下降，同时增加整轮 KV 流量与排队。\n\n在串行轮外成本 T_other 固定、平均历史 n_avg 固定的简化模型中，目标 D_ITL 要求\n\nW+b c_KV n_avg≤B_HBM(D_ITL−T_other)。\n\n当每请求 KV 项为正时，最大可行正整数 b 由右侧扣除 W 后向下取整得到；结果小于1表示没有正批可行。每请求成本为零时应单独处理，不能除以零。这个条件仅筛查该读取模型，不证明其他工作也满足预算。\n\n设 W=8 GiB，B_HBM=0.8 TiB/s，c_KV=128 KiB/token，n_avg=1024，T_other=1 ms，D_ITL=20 ms。19 ms 的读取预算为15.5648 GiB；扣除权重后剩7.5648 GiB，每请求128 MiB，因此 b_max=60。边界为：\n\n| batch | 读取加轮外成本 |\n|---:|---:|\n| 60 | 19.9208984375 ms |\n| 61 | 20.073486328125 ms |\n| 64 | 20.53125 ms D_HBM，应重新记账。若只优化提交而实际设备流量与完整ITL均不变，提交主导解释被削弱；若减少合法读取后设备时间随之下降，则支持相应条件下的流量解释。分离prefill/decode会增加状态传输、两侧排队和驻留，不能当作免费消除流量。\n\n## Prefill 切片与 Decode 干扰\n\n设已缓存前缀为H，prompt终点为P，待算后缀N=P−H。正块长q_i满足Σq_i=N，第i块起点h_i=H+Σ_{j<i}q_j。块内第j行位于h_i+j，只读取0到h_i+j的合法key，不能在块边界重置位置或历史。\n\n每块有效query-key对数为\n\nV_i=q_i h_i+q_i(q_i+1)/2，\nΣV_i=P(P+1)/2−H(H+1)/2。\n\n总对数相同只证明计数恒等式；遗漏过去位置、补入未来位置也可能保持数量，因此独立参考应比较具体可见集合，数值执行另比较输出。\n\n块执行成功后才推进c；中间块不采样，最后块产生位置P−1的logits。失败保持旧提交边界，已接受的设备访问先排空再回收。混合批的线性层可处理压紧的全部行，attention仍按请求自己的页表与可见集合执行。padding行不属于任何请求，不能写有效KV或进入采样。\n\n解释性成本可写为\n\nT_hat(V)=C0+α M_bar(V)+βΣ_r V_r+T_copy+T_comm+T_finish，\n\n其中M_bar是选桶后实际执行行数；各项只有在所定义范围串行时才直接相加。准备若已含在C0，就不能再次从预算扣除。融合线性层的权重读取也不能重复归给prefill与decode。\n\n选块时枚举合法q，对每个q加入所有已选decode，重新选择桶、计算padding、历史对数、COW、新页、workspace和完整时间；只有整个视图可行才接受。没有prefill候选时保留可行decode-only路径。桶或kernel路径跳变时，不能假定成本处处平滑并无条件二分。\n\n取H=1000、N=4096，无padding及其他请求，C0=2 ms、α=0.01 ms/行、β=10^-6 ms/对。整段有12,486,656对，时间55.446656 ms。切成8个512-token块，总时间69.446656 ms，比整段多7次固定项，即14 ms。最后一块从h=4584开始，时间9.598336 ms。扣除分块额外成本时应减7次，不能减8次而漏掉整段本身的一次固定成本。\n\n历史重读另计。在“每块完整扫描一次此前和本块KV”的粗模型中，K个等长块累计读取的token状态数为KH+N(K+1)/2；它不同于QK配对数，也不同于实测HBM事务。缩小块会缩短单次不可抢占区间，却可能增加准备、launch、重读和块间等待。\n\n固定到达轨迹后，若小块设备段缩短但客户端间隔增大，应分别改变准备组织、页容量和输出消费者，检查空档是否随之变化。没有decode等待、输入很短或主机固定成本占优时，大块可能更合适；严格ITL且长prefill干扰突出时，切片、准入或阶段分离才有对应价值。\n\n## 投机的平均收益与输出空档\n\n令γ为候选预算，n为首次拒绝前连续接受数。没有提前停止时，每轮产出Y=n+1，因此\n\nE[Y]=1+Σ_{i=1}^γ Pr(n≥i)。\n\n独立固定接受率α近似下，E[Y]=Σ_{i=0}^γ α^i；求和式同时覆盖α=0、α=1和γ=0。提前EOS或输出预算会截短实际产出，应按实际分布重新计算。\n\n合法随机协议使用实际目标分布p、实际提议分布q和相同条件前缀。候选x以min(1,p(x)/q(x))接受；首次拒绝后从完整token空间的正残余norm([p−q]_+)修正。候选KV在决定前是暂定状态；只提交接受前缀，修正或bonus token通常尚未作为输入计算自身KV。目标契约、父行logits索引和全层共同提交不能因收益不佳而放宽。\n\n设相同b条请求的普通轮次为T_b，投机完整轮次为T_sp，平均每请求产出E[Y]。全批摊薄成本分别为T_b/b与T_sp/(bE[Y])，收益条件等价于T_sp/E[Y]<T_b。不能拿全批摊薄时间与某条请求的整轮等待直接比较。\n\nT_sp应沿真实关键路径包含草稿、验证、管理、通信和提交；其他请求被挤占的等待另在服务轨迹中计量。已经执行但后来拒绝的行、临时KV、草稿权重、logits、图padding和排空均留在成本中。\n\n设一轮总成本24单位，γ=4、α=0.8，则E[Y]=3.3616，平均成本为24/3.3616≈7.139457单位。相同口径普通成本为10时有益，为6时变慢。另一设定若实际平均产出为3，则成本为8；不能把这两个产出假设混为一个算例。\n\nbatch增大时，普通路径的全批每token成本可能下降，而验证行与驻留更容易触及饱和，投机可能失去收益。但普通请求的T_b不必随batch下降；结论必须来自同口径比较，不能由W/b单独推出。\n\n平均成本改善也不能证明ITL合格。若可见输出时间为0、10、10、10、20、20、20 ms，平均相邻间隔为20/6≈3.333 ms，最大空档仍为10 ms。以平均产出把10 ms除以3，会隐藏轮间停顿。若协议平滑逐token发送，发送本身又增加等待和输出驻留，应重建实际交付轨迹。\n\n区分接受率下降与验证饱和，应固定目标合同和外部轨迹，扫描batch与γ，分别记录逐深度生存概率、草稿、验证、普通轮次、其他请求等待和交付空档。接受长度稳定而验证及排队增加时，应调整预算或关闭投机；关闭投机始终是合法运行点。\n\n## KV 量化：残余、封组峰值与质量\n\n理想位宽只描述码字，不能直接承诺可驻留并发。KIVI固定来源的K按通道建立跨token组，V按token建立跨通道组；二者残余生命周期不同。K残余累积到R后批量量化并清空，V保留最近R个高精度token，较旧token逐步转入量化区。要求R为token组长的整数倍。\n\n设各层几何相同，E=L H_KV d为单个token单侧K或V的元素数。采用高精度每元素s字节、量化位宽b、K跨token组长G_t、V跨通道组长G_c。令当前实际残余长度为r_K、r_V，则数据主项为\n\nC_data=(2N−r_K−r_V)E b/8+(r_K+r_V)E s。\n\n若量化K区由完整token组组成，K组数为(N−r_K)E/G_t；V组数为(N−r_V)L H_KV ceil(d/G_c)。再加入每组实际参数字节、码打包尾部、对齐、页尾、workspace和转换副本。异构层应逐层求和，不能沿用一个E。\n\n下列流程描述封组与发布的责任，不复制上游实现：\n\n```pseudocode\n算法 ms独立重叠可为20 ms；存在串行反馈或同一独占资源时为30
