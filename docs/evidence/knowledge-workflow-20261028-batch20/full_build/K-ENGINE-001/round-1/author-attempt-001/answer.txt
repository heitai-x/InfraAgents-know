{"chapter":"# K-ENGINE-001：调度决策：进度、就绪与资源承诺\n\n动态服务中，请求长度、输入就绪、缓存状态与设备完成不在同一时刻变化。调度器不能只回答下一批是谁，还要回答本轮允许推进哪段逻辑范围、这段范围依赖什么、取得哪些容量承诺，以及结果返回后哪些状态可以确认。按 token、请求、时间片或其他单位选择都是设计点，不能由默认队列顺序推出最优性。\n\n## 问题、状态与不变量\n\n对请求 r 固定模型、adapter、位置规则、输入身份和请求代次 g_r。已知 token 序列为 x_r[0:n_r)，n_r 是 prompt 与已接受生成 token 的总数。把进度拆成：\n\n| 量 | 含义 | 不能推出 |\n|---|---|---|\n| c_r | 已确认、所有必要层完整且可复用的连续 KV 终点 | 未来 token 已采样，或设备上的全部异步访问已结束 |\n| s_r | 已承诺给在途执行视图的逻辑终点，即调度前沿 | 对应 KV 已写入设备，或结果已可提交 |\n| n_r | 已知 token 终点 | 第 n_r 个 token 的 KV 已经计算 |\n| a_r | 已为请求取得逻辑写入资格的容量，按 token 计 | 物理页的全部消费者已经结束 |\n| ℓ_r | 绑定末行位置与请求代次的 logits 票据 | 任意时刻都可以重新采样同一票据 |\n\n基线模型每请求至多一个未解析视图，且 0≤c_r≤s_r≤n_r≤L_model，s_r≤a_r；未解析逻辑范围为 [c_r,s_r)。提交成功后 c_r 可推进到结果终点；失败或投机拒绝后 s_r 回滚到真实可恢复边界。多视图、树验证或异步投机需要把 [c_r,s_r) 换成带视图号和分支号的区间集合，不能只保留两个整数。\n\n所核对的 vLLM 机制说明指出，调度后内部进度可能提前增加，结果返回时再校正。本章用 s_r 表示这个已安排前沿，用 c_r 表示可恢复确认边界。名为已计算或已调度的计数不能直接当作设备完成证据。\n\n任何策略至少保持：正式输入来自已确认序列；同一逻辑范围不重复提交；新范围在模型长度和物理容量内；每个结果属于正确的请求、代次和视图；预留先于执行承诺；取消或失败不把部分结果写成成功；物理存储到最后访问结束才复用。\n\n## 合法性、就绪与选择\n\n硬合法条件与可替换策略要分开。硬条件包括：tokenizer 和输入版本已固定；prefill 只处理已知 token；decode 的位置有已确认输入 token；多模态 encoder 特征或外部状态已经到达；所需 KV 前缀在模型、位置、adapter 和数值表示上相容；页、工作区、输出占位和执行视图身份可唯一绑定；结果通知能匹配请求代次与视图。未满足这些条件时，高优先级也不能让请求执行。\n\n优先级、先来先服务、短任务偏好、deadline、running-first、长 prefill 阈值、单轮 token 上限和预留 lookahead 是策略选择。它们改变等待、公平和吞吐，不改变上述身份与容量条件。running-first 通常保护已有 decode 的间隔，却可能让新请求长期得不到首 token；轮转或欠额服务可以限制这种饥饿，但需要记录等待或累计服务。\n\n容量不足时可缩小 q、等待页、拒绝或按明确规则抢占；抢占后保留、换出和重算的成本不同。不能把一种实现的 max_num_seqs、max_num_batched_tokens 或页长写成所有引擎的合法条件。\n\n## 一轮调度的完整算法\n\n以下是与既有字段无关的语义算法。π 可以是 running-first、FCFS、轮转或 deadline；只要它返回不超过 q_upper 的 q。\n\n```pseudocode\n算法 1：SCHEDULE_ROUND\n输入：请求集合 R，token/sequence/encoder 预算 B_tok、B_seq、B_enc，页池 P，模型上限 L_model，策略 π\n输出：冻结执行视图 V，或空视图及每个候选的具体阻塞原因\n\n初始化 V←空，used_tok←0，used_seq←0，reasons←空，SAMPLE←空\n按 π 排列 R，但保留每个候选项的请求身份 (r,g_r)\nfor each r in 排序后的 R:\n    若 r 已结束或 g_r 与当前授权不符：记录 stale；continue\n    若输入未就绪，或需要的 encoder 特征未到：记录 not_ready；continue\n    若 r 存在未解析在途视图：记录 inflight；continue\n    若 0≤c_r≤s_r≤n_r≤L_model 或 s_r≤a_r 不成立：记录 invalid_state；continue\n\n    若 c_r=s_r=n_r：\n        若 ℓ_r 是绑定位置 n_r−1 且未消费的有效票据：\n            将 r 加入 SAMPLE_READY；不占模型 token 预算；continue\n        若仍需生成、n_r≥1 且恢复合同成立：\n            若 used_tok+1>B_tok：记录 budget；continue\n            尝试预留一行私有写区、历史读取保护和输出目标\n            失败则记录 capacity；成功则加入 RECOVER_LAST 候选（start=n_r−1,q=1）\n            used_tok←used_tok+1\n            continue\n        记录 blocked_no_logits；continue\n\n    // 没有在途视图，故 s_r=c_r；只从未确认前缀之后安排范围\n    q_upper←min(n_r−s_r, a_r−s_r, B_tok−used_tok, π 的单请求上限)\n    若 q_upper≤0：记录 budget 或 capacity；continue\n    q←π.choose_q(r,q_upper)\n    若 q≤0：记录 policy_reject；continue\n    在 P 中尝试预留 [s_r,s_r+q) 的新增页、写区、输出占位和必要 encoder 块\n    若预留失败：撤销本次已取得的局部预留，记录 capacity；continue\n    start←s_r\n    V.add(r,g_r,start,q,kind=COMPUTE,页承诺=...)\n    r.s_r←start+q       // 仅推进已安排前沿\n    used_tok←used_tok+q\n    used_seq←used_seq+1\n    used_enc←used_enc+本段 encoder 需求\n    if used_tok=B_tok 或 used_seq=B_seq 或 used_enc=B_enc: break\nend for\n\n先检查 V 不含零长度 COMPUTE，也不含同一请求的两个未解析视图\n若 V 为空且没有 SAMPLE_READY 或 RECOVER_LAST：返回 BLOCKED(reasons)\n冻结 V 中的请求、代次、起点、q、页承诺、输出目标和执行视图号\n返回 V；此时尚未提交任何成功边界\n```\n\nRECOVER_LAST 不是普通 prefill 或 decode。它重算最后一个已知 token 以取得缺失的末行 logits，读取 [0,n_r−1) 的既有历史，把本行 K/V 写入私有区，不能覆盖共享命中页或在途页。完成后只安装 logits 票据，c_r 保持 n_r；因此恢复不追加 token，也不重复计算已确认 KV。\n\n## 结果、失败和状态变化\n\n调度视图提交后，执行器按冻结的请求、代次、起点和 q 构造 query、位置、页表和输出目标。结果回传必须经过同一映射。提交返回、设备完成、业务确认和消费者可见是不同边界。\n\n```pseudocode\n算法 2：COMMIT_RESULT\n输入：冻结视图中的条目 a=(r,g,view,start,q,kind)，结果事件 e，完成证据\n输出：更新后的请求状态、输出事件或回滚\n\n若 e 的请求、代次、视图、start 或 q 与 a 不匹配：\n    只结算可匹配的物理责任；逻辑状态不变\n若 e.status=FAIL，或完成证据没有覆盖必要 KV 与目标：\n    若 r.s_r=start+q：r.s_r←start\n    撤销未兑现的逻辑承诺；物理页在最后访问结束后回收\n    不推进 c_r，不产生采样后继\n若 kind=COMPUTE 且 e.status=OK：\n    要求 [start,start+q) 的每层 KV 和目标输出均完成\n    若 start=r.c_r：r.c_r←start+q\n    r.s_r←max(r.s_r,r.c_r)\n    若 r.c_r=r.n_r 且 logits 票据完整：登记 SAMPLE_READY\n若 kind=RECOVER_LAST 且 e.status=OK：\n    安装绑定 r、g、n_r−1 的 logits 票据；c_r 不变\n若结果属于投机验证：\n    设 q_acc 为被接受前缀；只把 c_r 推进到 start+q_acc\n    r.s_r←r.c_r；未接受分支的输出和 KV 不得进入主状态\n```\n\n正常轨迹是 WAITING_INPUT 或 WAITING_RESOURCE → READY_UNCOMPUTED → IN_FLIGHT → 成功确认或失败回滚。c_r=s_r=n_r 且票据有效时进入 SAMPLE_READY；票据缺失时进入 RECOVERY 而不是永久等待。取消撤销未来业务提交资格，但已提交的设备读写必须保留到结束证据；迟到通知不能修改新的执行视图。\n\n## 成本、容量与反转\n\n设候选数为 R、选中请求数为 K、页条目数为 P。扫描和排序的主机工作约为 O(R log R)，保持到达顺序时可为 O(R)；状态与视图构造约 O(R+K)，页分配与释放按实际页数计。每次调度还有 lock、队列、metadata、提交和完成通知的固定成本，不能只用一个 token 数表示。\n\n对选中请求 i，q_i 个 query 从 start_i=s_i 开始，基线历史长度为 h_i=start_i。普通稠密 causal attention 的合法 query-key 对数约为\n\nV_i=q_i h_i+q_i(q_i+1)/2，V=Σ_i V_i。\n\n若模型有 J 层、H_q 个 query head、键和值维度 d_k、d_v，QK 与 PV 主工作量约为 2 J H_q (d_k+d_v) V FLOPs，按乘加计两次运算；softmax、线性层、MLP、采样和位置变换另计。相同 q 在不同 h 下不是同一成本。\n\n每 token 每层完整 K/V 的逻辑字节为 b_KV=J H_kv (d_k+d_v) s_bytes。新增逻辑写入至少 Q b_KV；实际 HBM 读取受页布局、KV head 分组、query 复用、dtype 和合并访问影响，不能把逻辑字节直接当作实测事务。\n\n页长 B 时，无额外预留、尾页独占的普通新增页数为\n\nΔpages=ceil((s+q)/B)−ceil(s/B)。\n\n例如 B=16、s=31、已持有 ceil(31/16)=2 页，q=2 时需再加 1 页；若另预留 16 个位置，则需再加 2 页。预留提高未来推进余量，也挤占其他请求容量。页表中的共享前缀可以减少唯一物理页，却不一定减少每个请求自己的索引条目和在途保护。\n\n时间上可写为 T_round ≈ T_scan + T_prepare + T_alloc + T_submit + T_dev + T_correct，但各项可能重叠。乐观前沿允许调度与上一轮设备执行重叠，代价是需要保留视图、校正记录和失败回滚；保守方案等待结果再推进，状态简单，却可能增加 host 等待并降低流水。重合工作时按关键路径计算，不能把全部阶段无条件相加。\n\n## 条件变化后的保留、调整与放弃\n\n保留的是 c_r 与 s_r 的区别、输入就绪、逻辑范围不重复、预留先于承诺、结果身份和最后使用条件。页长、模型上限、dtype、encoder 路径、投机分支或策略改变后，重新计算 q、页数、桶和同步边界。\n\n长 prefill 干扰已有 decode 时，可切块、限制单轮 q、提高 running 优先或分离 prefill/decode；切块不减少语义工作，且增加准备次数。页紧张时，缩短 lookahead、缩小 q 或延后准入通常比先承诺再等待回收更安全；缓存命中率上升若同时延长驻留，可能压低可准入请求数。\n\n完整 KV 命中而缺少末行 logits 时，不能因为 n_r−c_r=0 选择 q=0 后停滞。应安全重算最后一个已知 token，或使用绑定相同模型、完整输入和数值路径的 logits 缓存；共享尾页必须先 COW 或使用经证明的私有写区。若实现无法隔离重算写区，应放弃该恢复路径，而不是原地覆盖共享内容。\n\n投机验证需要额外保存草稿分支、接受前缀和拒绝后的回滚边界；没有这些身份时，应放弃投机或退化为普通 decode。模型、位置规则、量化尺度或 adapter 改变后，旧票据和旧页不能继续作为可复用状态。\n\n## 诊断与区分实验\n\n固定同一到达轨迹、模型、输入输出分布、取消行为和资源预算，逐轮记录请求代次、n_r、c_r、s_r、a_r、选中范围、页承诺、就绪信号、提交/完成/排空事件、可见输出与等待。不要只记录总 token/s。\n\n| 观察 | 竞争解释 | 区分干预与预测 |\n|---|---|---|\n| 调度计数增加但输出未出现 | 乐观前沿、设备未完成、结果未提交或输出未发送 | 延迟完成通知；s 可增加而 c 与可见输出不变；若 c 提前增加则是提交语义错误 |\n| 同一 decode 被执行两次 | 用 n−c 而不是 n−s 选范围，或在途视图未排除 | 注入一个未确认视图；正确调度器应从 s 继续或等待，重复区间检查应失败 |\n| 空闲但请求未推进 | token 预算、页不足、encoder 未就绪、无 logits 或恢复合同不支持 | 保持输入不变分别改变页池、token 预算和 encoder 到达；原因计数必须互斥 |\n| 命中完整 KV 后停滞 | q=0 被当作无工作，或缺少末行 logits | 令 c=n 且无票据；应出现 RECOVER_LAST 或明确阻塞，不得永久空转 |\n| 结果延迟或投机拒绝后进度倒退错误 | c 与 s 未分开，或乐观推进未校正 | 在提交后、完成前拒绝结果；c 必须保持旧值，s 回滚，旧页仍受保护 |\n| 吞吐上升但尾延迟变差 | 策略改变 offered 工作、running-first 饥饿、长片或驻留压力 | 固定 offered 工作，分别改排序与片长；报告 TTFT、ITL、拒绝和等待分布 |\n\n失败注入是必要负对照：延迟结果、取消请求、拒绝投机、令页预留失败、把完成通知换成旧视图号。若这些变化仍推进 c
