  "chapter": "# K-SYS-017：向量检索与 RAG：索引、版本与端到端质量\n\n检索系统把查询转换成表示，在某个已发布的索引版本和合法候选集合中搜索，再取回材料、重排并组装上下文。索引近邻准确率、材料相关性和最终回答质量是三个不同层次；只有把编码函数、索引版本、过滤语义和 RAG 时间链连起来，局部检索加速才有明确意义。\n\n## 查询函数、合法候选集与结果语义\n\n固定文档侧编码函数 f_A 与查询侧编码函数 g_A。正文把材料 d_i 转成向量 x_i=f_A(d_i)，把查询 s_q 转成 q=g_A(s_q) 后，才谈距离。A 至少包含模型权重、tokenizer、模板、截断、特殊 token、位置、pooling、归一化、投影和数值格式。维度相同只说明张量能相乘，不证明两个坐标空间相容。\n\n对查询 q、索引版本 V 和主体/租户 u，合法候选集记为 C_V(u,q)。它由租户、权限、语言、时间、材料删除状态和查询约束共同决定。索引近似搜索返回的是 C_V(u,q) 上的近邻，而非全库上的任意近邻。\n\n内积检索取最大，L2 检索取最小：\n\nTop_k^IP(q;C_V)=k-argmax_{i∈C_V} ⟨q,x_i⟩，\n\nTop_k^L2(q;C_V)=k-argmin_{i∈C_V} ‖q−x_i‖₂。\n\n返回平方 L2 还是 L2 只改变阈值解释，不改变同一候选集合内的排序。双方单位归一化时，‖q−x‖₂²=2−2⟨q,x⟩。未归一化时，向量范数会改变内积排序。例如 q=(1,1)、a=(10,0)、b=(1,1)，内积为 10 与 2，偏向 a；余弦为 1/√2 与 1，偏向 b。把未归一化内积称作余弦，会改变候选选择，而不只是改变显示单位。\n\n“先在全库取 top-k，再过滤”与“只在合法集合取 top-k”不是同一算法。固定单位查询 q=(1,0)，文档 a=(1,0)、b=(0.8,0.6)、c=(0,1)，禁用 a 后合法 top-1 必须是 b。全库 top-1 再过滤会得到空结果，缺失并非因为 b 不相似，而是因为过滤发生在配额之后。\n\n排序还需要明确全序。可以用分数降序、文档 ID 升序、稳定出现 ID 作为决胜；如果选择按原索引顺序决胜，就不能同时要求置换不变。浮点容差适合比较结果，不能把“差值小于容差”直接当成可传递的相等关系。\n\n## 索引版本、构建与发布状态\n\n一个可查询版本不能只是向量文件。正文采用如下合同：\n\nV=(A,E,P,C,M,F,L)。\n\nA 是编码与前处理身份；E 是粗聚类、码本、图结构或训练参数；P 是向量或代码及列表偏移；C 是 ID 到逻辑材料的映射；M 是租户、权限、时间、删除等过滤元数据；F 是材料定位与版本；L 是发布清单、校验信息和完成边界。\n\n构建状态至少区分 ABSENT、BUILDING、SEALED、PUBLISHED、RETIRED 和 FAILED。某个文件写完、某个分片可读、某个向量已编码，都不等于版本可以发布。查询只应看到 PUBLISHED；旧快照在读者结束前继续受保护。\n\n```pseudocode\n算法 PublishIndex\n输入：候选版本 V、全部必需分片与依赖、校验规则、预期发布代次\n输出：已发布快照、明确拒绝或未知状态\n\n1. 校验编码身份、维度、距离合同、码本/图结构、ID 映射、过滤元数据和材料定位完整。\n2. 对所有分片核对逻辑范围、数量、长度、校验信息和重复 ID；任何必需分片缺失则失败。\n3. 在未发布区域完成写入，不覆盖当前已发布版本。\n4. 等待全部写入、转换和持久化依赖完成；读取成功不能替代完成证据。\n5. 构造不可变清单，记录 V 的摘要、分片范围、过滤代次和材料版本。\n6. 在权威发布域中重新核对当前代次与旧版本读者保护：\n   若清单或依赖不完整，拒绝发布；\n   若代次已变化，返回冲突或重新规划；\n   否则原子安装新版本，使新查询只能看到完整 V。\n7. 旧版本不因新版本发布立即删除；只在读者、恢复引用和快照责任结束后回收。\n8. 答复丢失时查询原发布操作，不按超时猜测回滚。\n```\n\n查询必须固定快照。打开快照时先绑定版本和读保护，再读取向量、ID 映射和材料；不能先读 latest，过一会儿才登记读者，否则旧版本可能已被回收。删除过滤器要在返回材料前得到一致解释；只从向量索引删掉 ID，而材料缓存仍按旧标识命中，会留下不一致路径。\n\n## 搜索算法：Flat、IVF、图与压缩域\n\nFlat 是精确参考。它扫描全部合法向量，适合构造 ground truth、较小库或必须严格精确的路径。批量查询可以把距离计算组织成矩阵运算，但 top-k 选择和输出仍需成本。\n\n```pseudocode\n算法 SearchFlat\n输入：查询 q、固定版本 V、合法集合 C_V、整数 k、距离合同\n输出：按 (分数,文档 ID) 全序排列的结果或明确失败\n\n1. 若 k<0 则拒绝；k=0 返回空；q 或 V 不合法则失败。\n2. 初始化大小为 k 的最大堆或最小堆，具体取决于距离方向。\n3. 对每个 i∈C_V：\n   取得本版本向量 x_i；若向量缺失或校验失败，记录错误并按合同终止或跳过。\n   计算 score(q,x_i)；按声明的分数方向与 (score,id) 决胜比较。\n   若结果未满 k，压入；否则在优于当前最差项时替换。\n4. 等待所有被消费向量读取完成，按全序输出 (score,id)。\n```\n\nIVF 在构建时训练粗聚类，把向量放入倒排列表。查询时先算查询到粗中心的距离，选 nprobe 个列表，再扫描其中向量。固定 N、列表数 K、nprobe 为 p，且列表完全均匀、粗量化精确、列表未压缩时，距离计算主项为\n\nN_dist=K+pN/K。\n\n它在 K=√(pN) 附近取得最小值。这个式子只解释均匀列表的粗模型；真实列表偏斜、过滤、压缩和并发会改变扫描字节和尾延迟。\n\n```pseudocode\n算法 SearchIVF\n输入：q、V、粗中心集合、倒排列表、nprobe、合法集合 C_V、k\n输出：候选结果或失败\n\n1. 计算 q 到全部粗中心的距离，按距离和中心 ID 稳定排序。\n2. 选择前 nprobe 个列表；若 nprobe 超过合法列表数，只取实际存在者。\n3. 对每个被选列表：\n   按列表当前已发布范围读取代码或向量；\n   对每个 i∈C_V 计算距离并更新 top-k；\n   若索引还有压缩副本，保留压缩码，供精排使用。\n4. 若有 delta 索引，分别搜索后按 ID 去重、删除语义和版本优先级合并，再取全局 top-k。\n5. 若当前版本异常、分片缺失或读取失败，不得把不完整结果冒充完整结果。\n```\n\nPQ 把向量拆成 M 个子向量，用各自码本编码。查询可为每个子空间预计算查表值 LUT_m[j]；内积估计为 Σ_m LUT_m[c_m]。L2 可使用 ‖q−x′‖²=‖q‖²+‖x′‖²−2⟨q,x′⟩，其中 ‖x′‖² 由码本表或额外存储提供。PQ 压缩改变距离，IVF/图搜索减少访问范围；两者叠加时，应分别判断误差来自候选没被访问，还是访问后压缩排序改变。\n\n图索引通过邻接遍历和候选队列寻找近邻，搜索宽度控制探索。它引入边、随机访问和构建成本，适合中等规模且内存允许的情形；图索引不保证任意删除和增量更新都可低代价支持。\n\n精排对 shortlist 读取原始或较高精度向量，重新计算同一距离，或交给交叉编码器重新评分。前者提高候选内部排序，不能找回粗召回从未返回的材料；后者改变评分函数，不能把质量变化解释成近邻搜索误差。\n\n## 过滤、分片、更新与快照\n\n过滤发生在搜索之前、搜索之中还是搜索之后，必须显式声明。若过滤只去掉很少候选，候选生成后过滤可能足够；若过滤后合法集合很小，先按全库取 top-k 再过滤会漏掉合法近邻。正确做法是让候选生成、过滤和 top-k 使用同一合法集合。\n\n按文档 ID 分片时，每片先搜索本地 top-k。若每片都使用精确距离、相同合法集合和相同全序，返回本地 top-k 后合并可得到全局 top-k。若近似检索或本地候选预算更小，合并只得到更大候选集上的近似结果，不能声称全局 top-k。\n\n一个反例：q=(1,0)，分片 1 有 0.99、0.98，分片 2 有 0.97、0.10。全局 top-2 是 0.99 与 0.98。若每片只返回 1 个，合并得到 0.99 与 0.97，漏掉同一分片中的第二项。\n\n更新可采用不可变主索引加小增量索引。查询同时搜索两路，按 ID 去重；同 ID 的删除记录优先于旧向量，更新版本覆盖旧版本。删除标记必须在返回材料前再次过滤；慢分片缺失不能被当作完整结果。\n\n```pseudocode\n算法 MergeShardResults\n输入：各路结果、ID 版本、删除标记、k、最终全序\n输出：去重后的全局结果或明确部分结果\n\n1. 校验每路结果属于同一查询、同一快照、同一合法集合和同一距离合同。\n2. 若任一路报告失败且合同要求完整结果，立即返回失败，不静默丢弃该路。\n3. 按 ID 合并：删除优先于未删除；同 ID 取更新版本；同版本冲突报告错误。\n4. 对所有存活记录按 (score,id) 全序排序，取前 k。\n5. 返回结果并记录缺失分片、重复 ID、过滤和部分结果标记。\n```\n\n版本切换、删除和读者保护必须组合。查询固定快照后，材料更新、索引重建和缓存淘汰都不能悄悄改变这次查询看到的映射。若业务要求权限撤销立即生效，则固定旧索引仍不足以授权返回旧材料，必须在返回前核对当前权威过滤状态。\n\n## RAG 的完整数据流与成本\n\n完整在线链为：入口排队、查询编码、候选搜索、材料读取、重排、截断与排列、prompt 构造、模型 prefill、首 token 提交、后续 decode。各阶段只有在依赖允许且资源不冲突时才能重叠；串行阶段必须相加，共享带宽或算力不能把全部耗时简单取最大值。\n\n若各阶段串行，则\n\nT_RAG=T_queue+T_encode+T_search+T_fetch+T_rerank+T_prompt+T_prefill+T_submit+…。\n\n只测 prefill 的 TTFT 应明确起点；用户端 TTFT 包含检索和材料读取。增加候选数会同时改变搜索、读取、重排和上下文长度；减少候选数可能降低时延，却可能丢失回答所需证据。扩大上下文也不保证质量单调上升，中间位置的信息可能被模型忽略。\n\n| 成本 | 检索与 RAG 必须计入的内容 |\n|---|---|\n| 计算 | 查询编码、距离计算、top-k 选择、PQ 查表、重排、prompt 组装、prefill/decode |\n| 访存 | 向量或代码、码本、粗中心、ID 映射、过滤元数据、材料、重排工作区和 KV |\n| 通信 | 分片 fanout、候选合并、材料读取、跨设备传输、共享缓存和多阶段服务 |\n| 准备 | 训练粗聚类、建图、码本、切分、离线编码、索引发布、预热和加载 |\n| 同步 | 查询编码完成、分片屏障、top-k 合并、材料可见、版本固定、提交和回收 |\n| 驻留 | 向量副本、索引结构、材料缓存、delta 索引、旧快照、重排工作区和 KV |\n\nFlat 的搜索计算主项约为 N d 次乘加，top-k 维护约 O(N log k) 或 O(N) 的堆选择。IVF 的构造通常包含 k-means 训练和向量分配；查询成本由粗中心距离、扫描列表和合并决定。PQ 的容量为码本、代码、列表偏移和 ID 之和；代码大小是 M log₂K 位。图索引的边和邻接表也占容量，不能只算压缩向量。\n\nGPU 更适合较大批量、规则的距离计算和选择；CPU 对小批、不规则遍历和部分过滤有不同成本。选择时要计入编码器输出位置、查询搬运、索引驻留、结果回传和与生成模型共享的 HBM/算力。把检索放上同一 GPU 并不自动减少完整 RAG 延迟。\n\n## 条件变化与方案反转\n\n| 条件变化 | 保留的关系 | 调整或放弃的依据 |\n|---|---|---|\n| 库很小、内存充足或必须精确 | 距离合同与合法集合 | Flat 可能比复杂索引更简单；索引加速不值得准备成本 |\n| 库变大、内存受限 | 压缩与候选裁剪 | 使用 IVF/PQ 或外部存储；重新验证 recall、延迟和容量 |\n| 过滤变得很窄 | 合法集合必须先行 | 预过滤或过滤感知索引；全库 top-k 后过滤可能漏结果 |\n| 过滤很宽 | 候选裁剪仍可先发生 | 过滤成本低时可后过滤，但必须检查 k 与召回 |\n| 查询批量变大 | 规则距离计算可摊销 | GPU 或矩阵运算可能占优；仍要计搬运和结果回传 |\n| 更新频繁 | 不可变快照与增量层 | 采用主索引加 delta、删除集和周期重建；不能假设所有图索引支持低代价修改 |\n| 材料更新或权限撤销 | 材料版本和快照 | 删除传播、权限检查和索引版本需共同解释 |\n| 候选数增加 | 质量约束与上下文成本 | 搜索、重排、读取和上下文都变长；质量不保证单调 |\n| 非前缀 KV 复用 | 精确前缀或选择性重算 | 只做位置旋转不能恢复跨片段 attention；需要 K-ALG-022 的融合和验证 |\n\n## 区分实验与反证\n\n| 观察 | 竞争解释 | 区分实验与修正 |\n|---|---|---|\n| 过滤后结果变少 | 合法集合本来小；过滤发生太晚；分片缺失 | 固定原向量和合法集合，分别运行全库 top-k 后过滤与过滤感知 top-k；构造被禁用 top-1 的负例 |\n| recall 下降但答案质量变化不大 | 搜索误差；材料相关性未变；生成器忽略上下文 | 先固定精确合法近邻，再固定 shortlist 比较重排，最后单列端到端答案 |\n| 索引更新后旧结果仍出现 | 双索引合并优先级；删除标记未传播；旧快照 | 构造同 ID 更新和删除，检查返回前过滤；固定版本与不固定版本分别对照 |\n| 分片合并漏结果 | 本地预算不足；分片失败；去重覆盖 | 用两个同片高分项构造全局 top-2 反例；检查本地 k 和完整分片集合 |\n| 搜索从 8 ms 降到 4 ms，端到端只降 4 ms | 串行链真实缩短；其他阶段主导；测量口径不同 | 单列每阶段与完整链，保持同一请求人口；若总降幅与搜索降幅一致，支持串行解释 |\n| 位置修正后跨片段回答仍错 | 位置正确但 cross-attention 缺失；选择性重算不足；材料本身错 | 固定片段和查询，对照完整 prefill、独立片段 KV、选择性重算；检查 attention 与答案 |\n| 加候选后答案反而变差 | 质量非单调；lost-in-the-middle；重排或 prompt 过长 | 固定材料和顺序，只改变候选数；再固定候选，只改变排列或重排 |\n\n负对照必须真的改变被观察量。例如“全库 top-k 再过滤”在禁用 a 的例子中必须得到空结果；如果它在测试中仍返回 b，说明测试没有真正禁止 a 或没有使用目标合法集合。\n\n## C12-B：检索与 RAG 的完整验证场景\n\n设定 N=1,000,000、d=768、FP32。Flat 向量本体为 1,000,000×768×4=3,072,000,000 字节，约 2.86 GiB；另计 8 字节 ID、过滤元数据、材料定位和列表结构。候选 A 是 Flat 精确扫描。候选 B 是 4,096 列表的 IVF，加 96 个 8-bit 子量化器。\n\nB 的代码为 1,000,000×96=96,000,000 字节；64-bit ID 为 8,000,000 字节；粗中心为
