# K-TOOLS-001：可观测性：执行事件与采集事件的映射

trace 是由采集范围和工具机制生成的观测，不是系统全部执行事实的无损副本。执行事件经过探针、运行时收集、缓冲、刷新、导出、查询和身份连接之后，才成为能够支持结论的证据。某一层没有记录，不等于此前没有执行；某条记录存在，也不等于它属于目标请求。

## 问题、事件与时间对象

把观测问题写成 Q=(k,S,W,C,τ)：k 是事件类型，S 是目标主体或集合，W=[W0,W1) 是查询窗口，C 是主张，τ 是时间语义。主张可以是存在、缺失、持续时间、请求归属或因果关系；时间语义可以是事件开始于窗口内、事件在窗口内活动，或事件完整位于窗口内。这些问题需要不同证据，不能共用一个未经说明的时间过滤条件。

事件实例写成 e=(d,k,s,z,T,a,g,p)。d 是采集域，k 是事件类型，s 是逻辑主体，z 是进程、线程、设备、context、stream、QP 等作用域，a 是执行尝试，g 是对象代次，p 是字段。s 可以是请求、批次、对象范围或队列项，不等于地址、线程号或 correlation ID。T 必须区分两种对象：

- 点事件 Point(t)：发生、完成被观察、CQE 被取回、通知被处理等具有明确语义的发生点。对 W 的成员判定为 W0≤t<W1；它可以证明存在，但不贡献忙碌时间。
- 持续事件 Span(s,e)：采用半开区间 [s,e)，要求 s<e；持续时间为 e−s。讨论窗口内活动时，要求与 W 有正长度重叠。

零长半开集合 [t,t) 是空集，不能直接承担点事件的存在语义。若导出格式以 start=end 表示一个真实零持续时间记录，而且 schema 明确保证该行代表一次发生，则规范化为带发生点的零持续时间事件：存在性走 Point(t) 路径，持续时间账仍为零。若相等端点来自时钟分辨率或舍入，观测到的是一次发生及零个可分辨时间单位，不能证明真实执行耗时为零。若 schema 没有说明该行是否代表发生，保留 UNKNOWN_GEOMETRY，阻断依赖它的缺失证明，不能静默删除。

覆盖块、忙碌区间和事件记录不是同一个对象。零长覆盖块不覆盖任何时间；零持续时间事件可以真实存在。负长度、非有限时间、单位不一致或无法识别的时间对象必须报告非法或未知，不能先裁剪再掩盖问题。

采集配置记为 c=(D,Z,Wc,B,F,X)：D 记录支持与启用的域，Z 是覆盖作用域，Wc 是采集窗口，B 是缓冲预算，F 是刷新策略，X 是导出表和字段。查询还包含域过滤、时间映射、时间语义和主体连接规则。Obs(e;c;Q) 表示某条观测路径成功，至少需要事件类型被支持并启用、作用域被覆盖、时间范围可见、记录没有丢失、导出包含记录、查询没有错误排除记录，以及归属问题所需的有效身份连接。

因此，工具不支持、支持但未启用、作用域外、采集窗口外、缓冲丢失、导出缺表、有表但字段值非法、查询排除、记录无法关联和记录成功关联，是不同状态。它们不能都写成零条，更不能都解释成零成本。

## 观测包络与状态推进

记录状态应逐事件解释。下面的层次用于定位证据断点，不表示整个会话只能具有一种状态，也不表示所有失败必须顺序发生。

| 状态 | 已取得的证据 | 尚不能推出 |
|---|---|---|
| UNSUPPORTED / DISABLED | 工具或本次配置未提供该域 | 事件没有发生 |
| OUT_OF_SCOPE | 对象不在本次采集作用域 | 其他进程、设备或队列没有工作 |
| OUT_OF_WINDOW | 在可信时间映射下确定不满足窗口语义 | 其他窗口没有执行 |
| LOST / UNKNOWN_LOSS | 存在丢失或无法排除丢失 | 未记录部分成本为零 |
| NOT_EXPORTED | 导出没有所需表或字段 | 原始采集中没有记录 |
| EXPORTED_NOT_QUERIED | 有记录，但查询排除了它 | 执行不存在 |
| INVALID / UNKNOWN_AT_BOUNDARY | 字段、时间或边界不足以裁决 | 可以把该行删除后证明缺失 |
| PRESENT_UNJOINED | 相应域中有事件证据，但目标归属未知 | 事件属于目标请求或确定不属于它 |
| PRESENT_JOINED | 事件与目标具有可核对连接 | 连接本身证明因果、独占或完整持续时间 |

发生时刻、写入采集缓冲时刻、刷新时刻、导出处理时刻和主机读取回调时刻必须分开。只记录回调处理，会混入通知与调度延迟；host API 开始或返回，也不等于设备执行开始或结束。原始时间戳与转换后的会话时间戳必须保留其时间域和单位，不能混用。

点事件同样经过这些层。例如，CQE 被轮询取回的主机时刻，是主机取得完成证据的发生点；它不是天然精确的设备完成时刻。通知处理记录可以存在而 CQ 已被先前的 poll 清空。两种记录不能因都没有持续长度而消失，也不能合并成一个含义模糊的完成字段。

## 覆盖矩阵与覆盖算法

覆盖审计由问题决定，不能只保留已开启 profiler 这一项。

| 需要区分的问题 | 至少需要的观测 | 单独不足的信号 |
|---|---|---|
| 主机计算、阻塞或线程排队 | 线程运行与阻塞区间、调用路径、同步包装、CPU 采样或上下文切换 | 进程总 CPU 百分比；只有 kernel 表 |
| 本地或跨 NUMA 访问 | 线程与页放置、对应内存域计数、受控放置对照 | 一个总 cache miss 值 |
| 设备是否执行及其区间 | API、设备 kernel/copy、设备与 stream、关联字段 | GPU utilization；API 时长；kernel 名 |
| 框架算子身份与形状 | 算子、shape、调用栈、设备关系及记录窗口 | 仅按 kernel 名聚合 |
| 文件读取来自缓存、队列还是设备 | 文件范围、软件排队、硬件派发、完成 tag、字节和错误 | 单个 read 调用总耗时 |
| RDMA 提交、CQE、通知与消费 | WR/wr_id、CQ/CQE、状态、通道事件、应用接管点 | 通知次数；网络字节；本地 CQE |
| 自定义范围对应哪些设备工作 | NVTX/框架范围的 domain、闭合关系、关联与设备投影 | 只有 CPU 范围或未闭合范围 |
| 输出生成、发送或客户端背压 | 生成、封包、发送、对端可见边界和队列 | 内部 token 生成速率 |

表中信号是所需证据的定义，不保证任一 profiler 自动提供全部信息。Nsight Systems 的 CUDA API 和 GPU workload 是不同记录类别，可以通过作用域内的关联字段连接；CPU 指令指针采样、上下文切换和系统级事件计数则提供另外的观测。系统级 CPU 事件计数不直接归属某个进程或线程，采样间隔还可能因节流而不规则。工具支持哪些字段、权限是否允许、所选粒度是否逐事件完整，都要在具体采集清单中记录。

设 C_i 是针对所需域、作用域且具有可信损失状态的覆盖块。对查询 W，要求 Cov(W)=∪_i(C_i∩W)=W，才能说时间上完整覆盖。[0,5) 与 [5,10) 能覆盖 [0,10)，[0,5) 与 [6,10) 不能。不能仅用最早开始与最晚结束代替内部覆盖。

```pseudocode
算法 覆盖审计(chunks, W, domain, scope)
输入：覆盖块及其域、作用域、时间映射和损失证据；W=[W0,W1)
输出：状态、合并覆盖与缺口；另保留不合格覆盖块的原因

验证窗口端点有限、单位相同且 W0<=W1；非法则拒绝
若 W0==W1，返回 EMPTY_QUERY，不签发覆盖或无事件结论
usable=空；reasons=空
对每个覆盖块：
    先验证原始端点、作用域与损失状态
    域或作用域确定不匹配：不作为覆盖证据
    字段非法、损失未知或时间映射未知：记录原因，不作为可靠覆盖
    把覆盖转换为查询时间域中保证被覆盖的区间
    与 W 相交，仅保留正长度部分
按开始、结束排序 usable；合并相交或端点相接的区间
cursor=W0；gaps=空
依次读取合并区间 [a,b)：
    若 b<=cursor，继续
    若 a>cursor，记录 [cursor,min(a,W1))
    cursor=max(cursor,b)
    若 cursor>=W1，结束扫描
若 cursor<W1，记录 [cursor,W1)
返回合并覆盖、gaps 和 reasons
```

若覆盖块本地为 [a,b)，共同偏移 δ∈[lo,hi]，所有可行映射的交集为 [a+hi,b+lo)；这个区间为空时，该块不能提供保证覆盖。使用可能覆盖的并集，会把不确定区域错误升级为完整覆盖。块间校准关系更复杂时，应计算保守保证覆盖，不能套用独立恒定偏移模型。

时间覆盖还不等于逐事件完整。采样、时长阈值、只记录 graph 整体而不记录节点、未排空设备缓冲、未完成导出，都可能使窗口内事件不可见。无事件证书需要与 k、τ 一致的完整性依据。若事件只在开始时登记，查询窗口内活动还需知道此前已开始的在途事件；可以取得起始快照，或在有可靠最大持续时间 Lmax 时扩展采集前沿至少 Lmax，并完成相应刷新。只有窗口覆盖而没有这些边界记录，仍不足以证明窗口内没有活动。

## 身份、时间映射与三值判定

correlation ID 是连接字段，不是全局主键。物理实例身份至少需要采集会话、进程或设备作用域、域、context/stream 及 launch 或记录实例标识；重试、对象复用和队列 tag 还需要尝试、范围与代次。一个 API 可以关联多个设备实例，因此 correlation 相同不能直接去重。两个进程的同值 correlation 也不能直接连接。

分别保留 physical_id、logical_id 以及两个方向的映射。一个批次 kernel 可以服务多个请求，一个请求也可能触发多个 kernel、复制、转换或重试。这不是一对一关系。主体匹配返回 MATCH、NO_MATCH 或 UNKNOWN：有效且完整的映射明确排除目标，才是 NO_MATCH；缺少身份值、映射不存在或代次不明，是 UNKNOWN。SQL 连接后没有行不能自动解释为 NO_MATCH。

对于持续事件，重叠长度为 o(I,W)=max(0,min(e,W1)−max(s,W0))。精确同钟时，窗口内活动要求 o>0，开始于窗口内要求 W0≤s<W1，完整包含要求 W0≤s 且 e≤W1。对于点事件，三种语义都使用 W0≤t<W1，完整包含不要求正持续长度。忙碌并集为零，不能推出事件数为零。

时间转换必须先于窗口过滤。下面给出共同恒定偏移模型的完整分支。设查询域读数等于记录域读数加 δ，δ∈[lo,hi]，端点和偏移单位相同，W0<W1，持续事件 s<e。

| 时间对象及问题 | 至少一种可行映射满足 POSSIBLE | 所有可行映射满足 CERTAIN |
|---|---|---|
| 点事件，或持续事件的开始点 t | t+lo<W1 且 t+hi≥W0 | t+lo≥W0 且 t+hi<W1 |
| 持续事件在 W 内活动 | s+lo<W1 且 e+hi>W0 | s+hi<W1 且 e+lo>W0 |
| 持续事件完整位于 W 内 | 存在 δ∈[lo,hi] 同时满足 δ≥W0−s、δ≤W1−e | s+lo≥W0 且 e+hi≤W1 |

完整包含的 POSSIBLE 可以通过 max(lo,W0−s)≤min(hi,W1−e) 检查。时间分类为 CERTAIN、IMPOSSIBLE、UNKNOWN_AT_BOUNDARY：所有映射满足才确定命中；没有映射满足才确定不命中；其余保留可能命中。偏移缺失、映射过期或误差无界则返回 TIME_UNKNOWN，不能使用名义时间预筛掉记录。

例如 W=[0,10)，名义持续事件 [10,11)，δ∈[−2,0]。名义时间不相交，但 δ=−2 时变成 [8,9)，所以结果是可能命中，不能支持缺失。精确点 t=0 属于窗口，t=5 属于窗口，t=10 不属于窗口；δ∈[−1,0] 的名义 t=10 则仍可能属于窗口。

表中假设两个端点共享同一个恒定偏移，不涵盖任意漂移或独立端点误差。若校准后的漂移与时间戳精度有界，应先把它们纳入可靠可行映射集合；没有可靠界限时保留未知。恒定偏移不改变 e−s，但这并不免除完整包含、记录闭合和端点精度检查。

## 从原始记录到结论的观察审计

算法的候选不变量是：每一条尚可能属于目标窗口和主体的原始记录，最终必须成为可信命中、确定不匹配，或保留为阻断证书的未知；不能在验证、连接、去重或时间过滤时无痕消失。清单条件必须有明确真值和依据，缺项不默认为通过。

结论另有一个不变量：只要 trusted 非空，目标存在已得到支持，同一目标、窗口与时间语义下的缺失就已被反驳。其他位置的覆盖缺口或其他行的未知原因仍保留，但不能把 REFUTED 降成 UNSUPPORTED。后者表示没有取得足以证明缺失的证据；前者已有反例证明缺失主张不成立。

```pseudocode
算法 观察审计(Q, capture, export, query)
输入：Q=(kind,subject,W,claim,time_semantics)
      采集清单、原始导出表、schema、时钟证据和主体映射
输出：目标存在状态、缺失状态、可信记录、未归属记录、未知候选、原因和证书条件账

1. 验证 Q、单位和非空半开窗口；空窗口返回 NO_QUERY；非法输入拒绝
2. 初始化 reasons、trusted、unjoined、uncertain、excluded、conditions
3. 逐项核查并登记 PASS 或 FAIL/UNKNOWN 及依据：
     事件域支持且启用；主体与全部必要作用域覆盖
     针对该事件语义的逐事件完整性，不只是采样已运行
     覆盖审计没有缺口；损失状态足以排除相关记录丢失
     采集结束、设备缓冲刷新和导出完成
     表与必要字段存在；字段语义与版本已识别
     查询保留所需域和全部可能候选，不是未经审计的过滤结果
     所需时钟映射和误差界有效；窗口前后沿记录条件成立
   任一不通过即加入对应原因；不得因原始表为空而跳过这些条件
4. R_raw=所需域的原始导出记录，先不按名义时间或目标连接结果裁剪
   若只能取得已经过滤的结果且无法证明保留全部可能候选：加入 CANDIDATE_INCOMPLETE
5. 对每条原始行：
     检查事件类型、作用域、必要字段值、身份、代次及时间对象
     独立可靠字段能确定属于其他类型或作用域：记入 excluded
     否则字段非法、身份缺失或时间对象不明：保留原始行及 INVALID 原因
     检查时间映射与不确定性；未知时保留 TIME_UNKNOWN
     使用可行映射集合和 time_semantics 分类，不先按名义时间排除
     原因不能因后续过滤、零持续长度或无法连接而被删除
6. 只对身份完整、内容一致的重复导出去重
   相同物理键却内容冲突：隔离整个冲突组，加入 DUPLICATE_CONFLICT
   correlation 相同但物理实例不同：全部保留
7. 对规范化记录求主体关系 MATCH / NO_MATCH / UNKNOWN
   NO_MATCH 需要可信且完整的映射；缺身份或连接失败只能 UNKNOWN
8. 对每条记录：
     时间 IMPOSSIBLE 或主体确定 NO_MATCH：记录排除依据
     时间或主体 UNKNOWN，且不能可靠排除：加入 uncertain 和阻断原因
     域事件确定在窗口内但主体 UNKNOWN：另记 unjoined
     字段合法、时间 CERTAIN 且主体 MATCH：加入 trusted
9. 使用以下互斥分支，只赋予一组存在/缺失结论：
   若 trusted 非空：
       presence=SUPPORTED
       absence=REFUTED
   否则：
       presence 根据域内事件证据为 PRESENT_UNJOINED 或 UNKNOWN
       若 uncertain 为空、reasons 为空，且 conditions 每项显式 PASS：
           absence=SUPPORTED_UNDER_CERTIFICATE
       否则：
           absence=UNSUPPORTED
10. 汇合两条分支，保留全部原因与证书条件账；此处不返回、不重新赋值 absence
11. 持续时间只对相应条件成立的闭合记录计算；裁剪或精度不足单独标为 PARTIAL
    点事件与可信零持续时间记录仍可计发生次数，但不增加忙碌长度
12. 因果主张另需有依据的依赖边；时间命中和身份连接本身不提供因果边
13. 返回状态、记录、原因与证书条件账；不把未知阶段成本写成零
```

第 9 步中的缺失证书判定只能在 trusted 为空的分支中执行。第 10 步是控制流汇合点，两条路径都继续到持续时间和因果处理，不能用提前返回跳过这些处理，也不能在汇合后无条件重跑缺失判定。

| 可信目标命中 | 其他候选、原因和条件 | presence | absence |
|---|---|---|---|
| 至少一个 | 全部清单通过，无其他问题 | SUPPORTED | REFUTED |
| 至少一个 | 另有覆盖缺口、非法行或未知归属 | SUPPORTED | REFUTED |
| 没有 | 有确定在窗口内但无法归属的域事件 | PRESENT_UNJOINED | UNSUPPORTED |
| 没有 | 仍有可能命中或任一证书条件未通过 | UNKNOWN，或有域证据时 PRESENT_UNJOINED | UNSUPPORTED |
| 没有 | 无未知候选、无原因、全部必要条件显式通过 | UNKNOWN | SUPPORTED_UNDER_CERTIFICATE |

最后一行的 presence=UNKNOWN 表示没有正存在见证；有条件的缺失证书由 absence 字段单独表达。该状态对不是两个互相覆盖的成功标志。

第 5 步可以采取保守实现：对不能独立证明无关的非法行，即使名义时间在窗口外，也保留证书阻断原因。这可能拒绝部分本可进一步证明的缺失结论，但不会通过删除坏数据制造证书。只有建立可信的不相关证明后，才能缩小阻断范围。

正存在证据与完整覆盖的要求不同。有效记录明确命中目标，可以支持这一次存在，即使其他窗口有缺口；缺口仍禁止推断完整次数或总体成本。缺失是全称主张，需要排除所有可能目标事件。一个字段合法但主体连接未知的候选，就足以阻断它；一份空表若时钟、刷新或逐事件完整性未知，也不能签发证书。

四个反例贯通执行顺序与状态。第一，W=[0,10) 内 Point(5) 的忙碌长度为零，但必须产生 SUPPORTED/REFUTED。第二，窗口内唯一行缺少 physical_id 或请求身份时，删除该行后得到的空集合必须携带 INVALID_IDENTITY，而非缺失证书。第三，名义 [10,11)、偏移 [−2,0] 必须在可能命中集合中保留；在时间转换前预筛，会漏掉可行映射。第四，可信 Span(4,9) 与其他位置的缺口 [0,1) 同时出现时，存在/缺失仍是 SUPPORTED/REFUTED；缺口限制完整性，不撤销已有见证。这四种情况分别针对事件几何、候选保留、时间过滤和结论覆盖。

如果工具没有提供足够的无损失与完整性证据，且没有可信目标命中，缺失结论可以最终停在 UNSUPPORTED。已知 marker 出现可以证明某条路径在该处有效，却不能独自证明整个窗口所有事件都未丢失。

## 聚合与共享工作的归属

对已限定资源作用域、统一时间域并去除重复导出的正持续区间，定义累计时长 S=Σ_i(e_i−s_i)，忙碌覆盖 U=|∪_i[s_i,e_i)|，最大并发 K=max_t|{i:s_i≤t<e_i}|。重叠时 S≥U，互不重叠时相等。点事件另计 N_point，不进入 U 或持续活动并发 K；U=0 与 N_point>0 可以同时成立。

计算 U 时，先检查原始区间合法性，再按声明的窗口裁剪，按开始和结束排序；新区间起点不大于上一合并区间终点时延长终点，否则追加。K 可通过开始 +1、结束 −1 的扫描取得，同刻先处理结束，避免把相邻半开区间误计为同时活动。排序为 O(N log N)，扫描为 O(N)。U 只是所选活动的覆盖，不能自动解释为 SM 忙碌、整机忙碌或请求独占。

去重按物理实例及范围、尝试、代次进行，不能按 kernel 名去重。同名工作可以是不同执行，一次物理工作也可能重复导出。相同主键但时间、设备或负载冲突，说明身份或数据存在问题，不能任意保留一条后继续证明缺失。

对服务多个请求的物理工作 p，时长为 d_p。资源分摊可选择非负权重 w_(p,r)，满足 Σ_r w_(p,r)=1，charged(p,r)=w_(p,r)d_p。该规则保持资源账总和为 d_p，但不是唯一合法分摊方案。若请求路径报告它等待了整段共享工作，各请求都可以引用 d_p 解释延迟；这些完整等待不能再相加成设备物理时间。

没有可靠分摊规则时，分别报告物理覆盖、逻辑等待和未分摊共享时长。文件读取可能由页缓存满足而对应零个块请求，也可能拆分、合并或重试；逻辑 token、张量字节、系统调用字节、块层字节和设备传输字节应分别统计。

## 条件化成本与缓冲容量

同一候选必须在同一问题、窗口和作用域中列账，观测成本不限于一个 profiler 开销百分比。

| 成本 | 计量对象及条件 |
|---|---|
| 计算 | 每事件探针、shape、stack、内存跟踪、采样中断、解析、排序与连接 |
| 访存 | 事件负载和元数据写入、缓冲复制、文件、索引及查询结果；不可只计有效 payload |
| 通信 | 多机 trace 汇聚、远程导出和控制消息；关联 ID 字节不等于链路延迟 |
| 准备 | 域与窗口配置、权限检查、schema 识别、时钟校准和请求映射 |
| 同步 | 刷新、等待报告和导出就绪、工具引入的同步；可能改变队列和重叠 |
| 驻留 | 未导出缓冲、文件与索引、未闭合记录、框架 profiler 保留的张量引用 |

若原始行数为 N，覆盖块数为 M，请求—物理工作映射边数为 L，哈希去重和索引连接的预期时间为 O(N+L)，覆盖与区间排序为 O(M log M+N log N)，保留全部证据与映射的空间为 O(N+M+L)。这些是选用哈希索引的条件化成本；无索引的逐对连接可能退化为平方量级。为了省空间提前聚合，会失去实例、边界和共享归属信息，不能再声称具有相同审计能力。

缓冲模型必须同时说明累计量、时间原点和单位。设本轮从 t=0 开始观察，关注 0≤t≤F，F 以秒计；P0 是初始占用，B 是预算，单位均为字节。A(t) 是从时间原点之后累计要求写入的字节，D(t) 是同一缓冲实际排空的字节，A(0)=D(0)=0；原点处已存在的字节计入 P0，之后的瞬时突发计入 A 的跳变。无丢弃模型满足：

P(t)=P0+A(t)−D(t)，0≤D(t)≤P0+A(t)。

排空还必须满足实际服务和可用数据约束，不能把空缓冲期间未使用的带宽存成未来排空额度。若发生丢弃 L(t)，实际占用为 P0+A−D−L；因此实际占用一直低于 B，不证明没有丢失。容量推导应使用不裁掉溢出字节的需求模型，或同时核对 L。

对已知 A、D，完整区间的容量条件是：

sup_(0≤t≤F)[P0+A(t)−D(t)]≤B。

这里只能使用可行且属于同一缓冲的 D。若未来轨迹未知，容量承诺需要对所有允许轨迹检查该上界。分段常速率加跳变的轨迹，峰值出现在段端点或跳变的前后；同一时间写入与排空的次序未知时，使用写入先发生的保守峰值，不能依靠时间戳相同假设相互抵消。

一个便于规划的简化条件需要更强假设：A 连续且无突发，逐时到达速率 A'(t)≤a；只要缓冲非空，实际排空速率至少为 d；a、d 的单位都是字节/秒，服务没有启动停顿、批量刷新或未计入的阻塞。此时非空期间 P'(t)≤a−d，空缓冲不能变成负占用，因此：

P(t)≤P0+max(0,a−d)t，充分条件为 P0+max(0,a−d)F≤B。

a<d 时仍必须检查 P0≤B，不能用区间末尾的负净增长抵扣初始峰值。空缓冲时实际排空受可用字节限制，不要求它继续以 d 排出不存在的数据。这个简化式不覆盖原子事件记录突发、服务暂停或仅在 F 末尾统一刷新的策略。

若只能给出累计到达上包络 α(t) 和实际排空下包络 β(t)，两者单位都是字节，则可检查 P0+sup_t[α(t)−β(t)]≤B；必须保证这些包络对整个区间逐时有效。空缓冲或服务停顿时，通常不能声称实际 D(t)≥dt。无法证明排空下界时，可取 β=0；例如 A(t)≤σ+at，σ 是字节突发上界，则 P0+σ+aF≤B 是忽略排空的保守条件。平均速率不能替代逐时包络。

设定手算轨迹如下，时间单位为秒、容量为字节，B=10：

| 时刻/边界 | A | D | 无丢弃需求占用 |
|---|---:|---:|---:|
| 0，初始占用 P0=2 | 0 | 0 | 2 |
| 1，写入 9 字节后尚未刷新 | 9 | 0 | 11 |
| 2，此后排空 10 字节 | 9 | 10 | 1 |

末尾占用 1≤10，但中途需要 11，固定容量 10 无法无损容纳；容量 11 在这条设定轨迹中满足峰值条件。若真实容量只有 10 并丢弃 1 字节，实际占用会被截到 10，这不修复无损失证书。只看末尾净量的错误版本，应在此例失败。

固定 B 是规划模型，不是所有工具的实现保证。所供 Nsight Systems 文档说明刷新策略可能改变开销和内存使用，一些条件下会继续分配缓冲；因此超过预算也可能表现为额外驻留，而非立刻丢记录。模型不能替代工具诊断、版本行为和真实损失证据。

trace 文件大小主项约为 Σ_k N_k b_k，N_k 为保留记录数，b_k 为平均记录及元数据字节；导出与索引另有临时空间和处理时间。大型采集的导出可能耗时数分钟，采集结束不等于查询就绪。

CPU 采样不是逐事件日志。名义采样频率 fs 对应约 1/fs 的间隔，短事件可能没有样本，节流会使间隔不规则。perf 计数需要记录实际运行时间和运行比例；复用、缩放与统计范围改变含义。IPC 的分子分母必须来自相同对象、作用域和时段。

框架 profiler 的等待、预热、记录和保存状态限定实际输出范围，shape/stack 等细节会增加成本，部分形状跟踪会保留张量引用。RDMA 的通知是一次性请求触发的通道事件，数量不等于 CQE 数量；本地 CQE 不证明远端应用已经消费。块 I/O 的软件队列、硬件派发和乱序完成也不能被一个系统调用持续区间代替。

## 条件变化后的保留与调整

| 条件变化 | 保留的依据 | 调整或放弃的结论 |
|---|---|---|
| 多进程、多设备或多节点 | 独立作用域、物理身份、映射与时钟界 | 不把同名表或同值 correlation 直接合并 |
| 单 stream 变多 stream | 真实生产、完成、消费和最后使用关系 | 放弃单一全序；分别限定资源并集 |
| 查询从持续活动变成完成/通知 | 事件类型与发生点语义 | 改用点成员判定；零忙碌时间不支持无事件 |
| 窗口扩大、缩小或移动 | 可能命中范围、保证覆盖与前后沿条件 | 扩窗重算缓冲与导出；缩窗保留跨边界事件 |
| 校准老化或时间精度变差 | 可靠身份、当地经过时间、有效误差界 | 扩大可能候选；无法裁决边界时放弃缺失证书 |
| 采样率下降或启用阈值过滤 | 样本和过滤的真实语义 | 放弃逐事件缺失证明，需要事件计数或更完整采集 |
| 开启 shape、stack 或内存细节 | 机制诊断目标与额外成本 | 若时序或驻留改变，性能结论回到普通执行验证 |
| 缓冲预算不足或刷新停顿 | 初始占用、突发、全区间峰值与损失状态 | 缩窗或缩域；不能用末尾空缓冲证明无丢失 |
| RDMA 通知与 poll 交错 | WR、CQE、通道事件和应用消费点 | 不按通知数计算完成数，检查一次性重挂和错误 |
| I/O 完成乱序、重试或 tag 复用 | 对象范围、尝试、代次和成功字节 | 不按提交顺序配对，不把部分完成发布为完整结果 |
| 已有可信命中后发现额外观测缺口 | 原命中记录及其独立有效性、缺口原因 | 保持存在支持与缺失反驳；撤回完整次数和总体成本推断 |

增加缓冲只处理相应容量风险，不能解决错误过滤、采样遗漏或身份缺失。更细的采集适合定位机制，其扰动可能使它不适合作为最终服务性能数字。如果新证据推翻了原命中的身份、时间或字段有效性，应重新分类该记录；仅仅发现别处有未知，不等于推翻原见证。

## 区分实验与反证修正

下表是实验设计，未声称已在目标机器执行。干预应使竞争解释产生不同预测，并保留输入、对象身份、完成边界与有效工作量。

| 观察与竞争解释 | 区分实验 | 预测与反证后的修正 |
|---|---|---|
| kernel 表缺失：未启用、作用域错、窗口外、导出不全或未执行 | 核对清单与表；在同作用域和查询中加入已知会执行的 marker；检查刷新完成 | marker 也缺失说明路径未闭合；出现只证明该处路径有效，不能独自证明整窗无丢失 |
| GPU 图有空洞：主机供给不足、其他 stream、查询遗漏或覆盖缺口 | 同时记录线程运行/阻塞、输入就绪和设备全部必要作用域 | 主机等待与消费延后支持供给解释；补表才填图而完成点不变，支持观测解释 |
| API 很长：主机工作、内部等待、提交阻塞或采集扰动 | 分记 API、设备开始/完成和输出消费，对照普通执行与细节采集 | API 变短但输出不变支持等待位置移动；关闭细节后变化则重查扰动 |
| 查询无完成：没有发生、点事件被当空区间或时间边界未知 | 放入内部点、左右端点及零持续记录；保留时间误差界 | 内部与左端点必须出现，右端点排除；不确定跨界只能未知 |
| 请求连接为空：确实无匹配或身份坏值被过滤 | 同一原始行分别提供有效身份、缺身份和可信其他主体身份 | 前者可证明存在；缺身份阻断缺失；可信其他身份才支持确定排除 |
| 名义窗口为空：真实无活动或跨钟偏移 | 使用 [10,11)、偏移 [−2,0] 与 W=[0,10) 的受控材料 | 名义空而可行映射命中，必须阻断缺失；校准收紧后才重新裁决 |
| 有可信命中却报告缺失证据不足：真实见证失效或后续分支覆盖 | 固定 Point(5) 或 Span(4,9)，分别添加窗口外侧覆盖缺口、另一条未知候选及两者组合；记录分支后状态 | 见证始终有效时必须保持 SUPPORTED/REFUTED；只在执行缺失分支后改变，定位为状态覆盖；持续时间与因果处理仍须到达 |
| 采集末尾缓冲很空：容量足够或中途已溢出 | 保留初始占用与写入/排空边界，比较全峰值和末尾值 | 峰值超 B 而末尾低于 B 反驳末尾充分性；扩大预算只在真实损失路径改善时支持容量解释 |
| 两请求各有 5 ms：两次物理执行或一次共享 | 核对物理实例、batch 映射与逻辑等待 | 一次物理实例只能计一次资源；两个请求可同时等待它 |
| read 很慢：缓存、软件排队、硬件等待或设备服务 | 分记文件范围、缓存状态、派发、完成 tag 和字节 | 无物理请求支持缓存路径；乱序 tag 反驳按提交顺序配对 |
| RDMA 通知少：无 CQE、未重挂、先被 poll 或应用未消费 | 分记 WR、CQE 状态、通道事件和应用确认 | poll 有 CQE 而通知无新事件支持通知路径解释；本地完成仍不支持远端消费 |
| 抽样与持续区间不一致：真实工作变化、别名或节流 | 改采样频率并检查诊断、运行比例与独立完成边界 | 随间隔系统性变化支持抽样解释，不能把样本空白当无执行 |

负对照必须改变结论而不是重复一遍实现。[0,10) 与 [5,15) 的累计为 20、并集为 15，可检出累计冒充覆盖；[0,5) 与 [6,10) 可检出只看包络；零持续记录可检出忙碌长度冒充存在性；非法身份删除和名义时间预筛可检出错误证书；峰值 11、末尾 1 可检出缓冲末尾检查。把第 9 步的证书判定搬到互斥分支之后无条件执行，则可信点和可信持续事件都会从 REFUTED 错变为 UNSUPPORTED；检查必须实际构造并检出这个错误版本。

反证出现后，应修改证据状态或机制解释。若普通执行下收益消失，profiler 下的收益不能证明服务加速。若补表后设备工作出现但输出时间不变，先修正观测路径解释，不能把补出的工作直接当成新的关键路径成本。独立重复和性能口径见[性能实验](statistical-experiments.md)。

## 组合轨迹：共享批次与完成观察

设 W=[0,12) ms，目标请求 R1、R2 同属批次 B。以下都是设定记录：

| 记录 | 区间或时刻 | 域与身份 | 含义 |
|---|---|---|---|
| R1 范围 | [0,9) | 业务请求 R1 | 业务范围边界 |
| R2 范围 | [0,10) | 业务请求 R2 | 业务范围边界 |
| API A | [1,2) | 主机 API，作用域内 correlation=7 | 提交 B 的调用 |
| kernel K | [4,9) | 同一设备的一个物理实例，correlation=7 | 一次执行服务两个请求 |
| 完成观察 O | Point(10) | 主机轮询观察，关联本次批次 | 主机发现完成的发生点 |

先核对采集域、作用域、时钟、窗口覆盖、逐事件完整性、刷新和导出，再检查原始值。假定这些条件成立且 B 的请求映射有效：

- K 是一次可信物理执行，存在/缺失为 SUPPORTED/REFUTED，持续 5 ms；A 与 K 通过具体作用域和实例连接，而非单凭数值 7。
- A 返回于 2，K 开始于 4。中间 2 ms 允许排队、依赖未满足或主机控制等解释，不能直接说 CPU 计算了 2 ms。
- R1、R2 都包含 K 的时间范围不自动证明归属；B→{R1,R2} 的可信映射才支持共享关系。
- 设备物理覆盖 U=5 ms。把完整 5 ms 记入两个请求的等待解释可以成立，把两份等待相加成设备忙碌 10 ms 则错误。平均分摊时两个请求各承担 2.5 ms，资源总账仍为 5 ms。
- K 在 9 结束，O 在 10 被观察，间隔 1 ms 可能含完成通知、轮询和调度，不能加进 kernel 持续时间。
- 查询完成观察域的 [9,12) 时，O 存在，发生数为 1，忙碌长度为 0。查询 [0,10) 时 O 在右端点，应排除；查询 [10,12) 时 O 在左端点，应保留。
- 查询 kernel 域的 [9,12) 时没有 K 的活动，与主机完成观察在 10 存在并不矛盾。只有该 kernel 域证书完整时，才支持该窗口没有匹配 kernel；导出最后一条止于 9，不证明采集也止于 9 或覆盖至 12。

现在把保证覆盖改成 [1,12)，留下 [0,1) 的缺口，同时另有一条身份未知的记录。K 和 O 自身的身份、时间映射及记录有效性保持不变。两者各自的存在主张仍获得 SUPPORTED，其对应缺失主张仍为 REFUTED；WINDOW_GAP 与未知身份原因必须随结果保留。算法随后仍可处理 K 的完整 5 ms 记录，因为它完整处于可信覆盖内；仍不能推断整个 W 的完整工作总量，也不能仅凭这些记录给 A、K、O 补造因果边。

若只启用 NVTX，未启用 CUDA workload，仍可能看到 R1、R2，却无法从该导出判断 K 是否执行或计算设备覆盖。若 O 的时间映射未知，则保留完成记录与边界未知；若 B 的身份字段缺失，则保留设备事件和无法归属，不能连接后删除记录再签发请求无工作证书。这里改变的是见证本身的有效性，与“有效见证旁边还有其他未知”必须分开。

同一规则适用于 I/O 与通信：read 是逻辑操作，可能对应零个或多个块请求；tag 需要范围和代次保护；WR 提交、CQE 取回、通知处理和应用消费分别推进不同状态。观测重建不能以通知数补造 CQE，也不能以本地完成补造远端消费。

## 配套检查与证据边界

配套文件为 `tools/check_k_tools_001_full.py`。脚本只使用 Python 标准库，离线、确定性、只读，不导入项目或上游实现，不启动进程，不访问网络、凭据或文件。它以单元集合核对区间并集和窗口覆盖，以偏移枚举核对点成员及持续活动的时间分类，以逐字节队列核对缓冲峰值，并核对无突发流体上界与共享账守恒。

结论解析器与正文第 9 步采用相同的外层可信命中分支、内层证书分支，不用可信命中时提前返回的方式绕过汇合路径。独立状态契约表检查有见证时缺失恒为 REFUTED；实际审计案例覆盖可信内部点、零持续记录、可信持续事件，以及同时出现其他缺口和未知原因的情况。故意把证书判定改成汇合后无条件执行的版本，必须在这些案例中被检出。审计在结论分支之后计算可用的持续时间贡献，并保留因果证据需求，用以检查后续处理仍可达；它不实现真实依赖图解析。

本轮实际在工具 V8 中运行了对应模型：48 个结论状态组合符合独立契约，其中 24 个可信命中组合检出无条件缺失判定的错误版本；8 个点/持续事件与缺口、未知原因的组合保持 SUPPORTED/REFUTED 并到达后续处理。另有 441 个区间案例、6,048 个活动时间分类、2,187 个字节队列案例与独立参考一致，1,600 个无突发分段常速率案例满足上界。这些不是所交付 Python 文件的执行结果。交付 Python 尚待协调者隔离运行并保存结果，旧轮次预检不代表本轮脚本已通过。

模型不执行 Nsight Systems、PyTorch profiler、perf、CUDA、块设备、RDMA 或真实服务，不证明设备可见性、无损失采集、真实时钟校准、GPU/CPU 性能或 Agent 使用效果。清单真值是显式输入假设，不能证明真实工具满足它们。Python 时间分类检查限定窗口内活动；开始于窗口内、完整包含的通用分类，以及带偏移覆盖块的保证覆盖公式，没有作为完整分类器在脚本中枚举。任意实数端点、非恒定漂移、独立端点误差、工具解析与版本行为、实际缓冲调度、阈值遗漏和性能扰动仍需对应证据。
