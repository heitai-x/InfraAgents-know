# K-MODEL-014：视觉识别与卷积：空间布局、预处理与任务输出

视觉识别的请求从图像字节开始，经过确定的几何和颜色变换、卷积或视觉编码器，再产生分类、检测等任务输出。空间分辨率、布局与预后处理会改变模型函数和资源成本，不能用生成式模型的输入 token 数直接代替。

## 原始图像到模型张量的契约

解码器、颜色通道顺序、值域、方向、resize 插值、裁剪或 letterbox、归一化与布局共同定义输入。训练时随机增强不能直接作为确定推理的默认行为。改变 resize、中心裁剪或多视图测试，是改变实际输入/评估方案；仅比较相同模型名称不足以证明公平。

输入可采用 NCHW、NHWC 或分块通道布局。逻辑索引相同不代表物理 stride 相同；转换布局需要真实读取和写入，若每层来回变换，可能抵消单个卷积 kernel 的优势。batch 中混合分辨率时，padding 与有效区域的含义必须贯穿后续计算。卷积会读取局部邻域，简单补零后再对有效像素裁切输出，也未必等同于独立处理原图，尤其涉及池化、全局统计或边界传播时。

视觉 encoder 若采用 patch/attention，应按实际模型处理位置和网格；本章的卷积成本公式不适用于所有视觉网络。视觉识别、视觉语言模型的图像编码阶段与图像生成的去噪循环也有不同任务输出和状态。

## 卷积的计算与中间表示

设 batch 为 B，输入 Cin 个通道，输出 Cout 个通道，卷积核 Kh×Kw，组数 G，输出空间 Hout×Wout。乘加数为 B Hout Wout Cout (Cin/G) Kh Kw；若一次乘加计两次浮点操作，FLOPs 为其两倍。stride、padding 和 dilation 决定输出形状，不能把它们只当作性能参数。

直接卷积按空间邻域加载；显式 im2col 将输入窗口展开成矩阵，再执行 GEMM，改善规则计算却可能产生大临时区；隐式 GEMM 在读取时构造逻辑窗口，避免完整展开，但增加索引和边界处理。Winograd/FFT 等变换路线有各自适用形状、额外变换和数值条件；仅凭卷积核大小不能假定目标 backend 已选中某条路线。

1×1 卷积、深度可分离卷积和普通 3×3 卷积的复用不同。depthwise 降低计算，却也降低算术强度，可能更受访存和提交限制。应分别记录权重、输入/输出、中间工作区、布局转换与 epilogue，而不是用统一峰值算力预测全部层。

## 残差、归一化与合法融合

ResNet 固定论文中的残差块将 F(x) 与 x 或投影 W_s x 相加，再按相应结构激活。两支必须有相同空间形状和通道解释；降采样位置与 shortcut 形式是 checkpoint 契约。相加前 x 仍活跃，原地覆盖它会破坏后面的 shortcut，即使顺序执行没有并发也会出错。

固定推理统计的 BatchNorm 是按通道的仿射变换。对于卷积 y=W*x+b，令 a=γ/√(variance+ε)，可以构造 W′=aW、b′=a(b−mean)+β。这个代数合并要求统计和参数固定，并与实际精度/舍入相容；若运行中仍计算 batch 统计，则不能用同一常量折叠。量化后的 scale、bias 和饱和位置也需重新核对。

卷积、bias、固定 BN、激活的融合可减少中间写读；残差 add 融合还要满足另一输入的生命周期、布局与 dtype。融合改变归约或舍入次序时，使用允许误差与任务质量验证。更多融合也可能增加寄存器、工作区或限制库调用，不能保证端到端单调变快。

## 分类与检测是不同输出链

分类路径通常经过特征提取、pooling 和分类头，返回类别分数及其映射。单标签 softmax、多标签 sigmoid、top-k 与阈值策略必须遵循任务定义。类别表版本和输出顺序属于结果身份。

ResNet v1 附录 A–C 给出一个具体检测路线：整图共享卷积特征，经 proposal 网络产生候选区域，再做 RoI pooling、区域级计算、分类与框回归；后续可加入 box refinement、NMS 和多尺度。这里的候选数、RoI 形状和后处理带来数据相关工作。该历史实现支撑机制说明，不把其固定阈值或 proposal 数当作所有检测器的默认配置。

检测输出必须带回原图坐标。resize 比例、padding、crop 偏移、坐标格式、边界是否包含末端以及 NMS 的同分顺序都要统一。对框先裁剪再做 IoU，与先 NMS 后裁剪可能不同；某些流程可以合法使用不同顺序，但必须与参考定义一致。分类正确不能代替定位正确，最终指标应包含相应 IoU 条件下的 AP/mAP。

## 请求执行与资源放置

CPU 解码/预处理、设备搬运、GPU 执行、CPU/GPU 后处理可以分阶段聚批，但需要携带图像 ID、几何变换及有效输出范围。一个阶段 batch 大小最优，不意味着完整请求适合等待同样大的批。解码和 NMS 可能成为 CPU 瓶颈，长分辨率或候选数多的请求也会拖长尾部。

异步流水中，输入图像缓冲、转换后张量、模型工作区和输出各有最后消费者。取消只移除客户端结果需求，不代表设备已停止读写。图捕获和编译分桶可以管理有限分辨率与 proposal 容量，超出容量应明确换路径，不能静默裁掉对象以保持固定 shape。

## C12-C：视觉识别与检测的完整验证场景

设定一个固定 checkpoint、224×224 单裁剪分类契约，并考察其中一层 B=1、56×56、Cin=Cout=64、3×3、G=1、stride=1、保持空间尺寸的卷积。其乘加数为 56²×64×64×9=115,605,504；FP16 输出为 401,408 字节。显式 im2col 的输入展开有 56²×(64×9) 个元素，即 3,612,672 字节，约为原输入的 9 倍，尚未计 GEMM 工作区。换成 depthwise 是不同算子，其乘加仅 1,806,336，不能在未改变模型的优化比较中直接替换。

候选 A 保持统一布局并用库卷积，候选 B 使用有目标 shape 依据的编译/融合路径。两者以相同图像字节、前处理和权重执行，先比较解码后像素、卷积边界、残差输出和最终 logits，再比较固定测试集 top-1/top-5。测试纯色、单像素脉冲、非整除通道、非连续 stride、极小图、不同宽高比与混合批，定位插值、边界和布局错误。

检测子场景固定一个有完整任务头的模型及其 resize/NMS 规则。用可手算矩形验证坐标映射与 IoU：A=[0,0,2,2]、B=[1,0,3,2]，采用连续坐标面积，交集 2、并集 6，IoU=1/3；是否抑制由既定阈值和比较符号决定。分别检查空检测、同分重叠框、跨类别框、padding 区域、裁剪边界与 proposal 容量超限，再测任务规定的 AP/mAP，不能只对照框数量。

性能报告完整图像/s、端到端 p95/p99、解码/搬运/模型/后处理时间与峰值内存；冷编译、预热与稳定态分开。大 batch、固定分辨率时，稳定布局与编译摊销可能收益明显；低到达率、多分辨率或后处理主导时，更简单路径和短等待可能更优。降低分辨率、减少 proposals 或改为单裁剪若带来收益，应同时报告质量和任务定义的变化。
