# K-SYS-004：取消与完成：业务终止、设备排空和资源回收

取消撤销未来服务意图，完成证明既有访问已经结束。物理资源重用必须汇合逻辑拥有者、执行使用者与输出消费者的结束证据；业务终止、设备完成、输出提交和地址可复用是四个不同的边界。

## 请求终止与对象生命期

请求可能在接收、排队、准备、执行、生成或输出阶段终止。EOS、长度上限、取消、deadline、内部错误和网络断开有不同的业务含义，但都不能直接证明 kernel、DMA、存储读取或响应消费者已经停止访问对象。

请求实例 r 不复用；其执行代次为 I=(r,g)。物理槽 s 的一次分配生命期为 x=(s,e)，e 是槽代次，不能与请求执行代次 g 混用。完整对象描述还包括对象种类、底层存储范围、模型与表示版本。同一底层存储上的别名必须合并保护，或证明各自访问范围确实不重叠；只按张量名字建账不能保护别名写入。

对对象 x 定义：

- L_x：逻辑拥有者集合，例如请求、缓存目录或恢复副本责任方。
- U_x：已经取得启动资格、尚未证明最后访问结束的使用责任集合。
- O_x：已经取得输出读取权、尚未结束的消费者集合。
- B_x：仍有效的长期绑定，例如应用图缓冲的地址资格。
- Q_x：尚未解决的隔离原因集合。

对象进入物理空闲需要满足

retiring_x ∧ L_x=∅ ∧ U_x=∅ ∧ O_x=∅ ∧ B_x=∅ ∧ Q_x=∅。

retiring 表示不再接纳新的拥有者或长期绑定。已有拥有者可以在释放自己的 L 之前继续登记合法使用；最后一个 L 被撤销、检查空集合与关闭分配生命期必须在同一个串行状态域内完成。这样不会出现“检查为空之后，另一个线程又取得旧对象”的窗口。

集合不是可以由任意通知递减的计数。两个使用者分别持有 uid₁、uid₂；uid₁ 的重复完成只能再次命中 uid₁ 的已结束记录，不能抵消 uid₂。计数可以作为集合的缓存，但不能代替责任身份。

请求业务状态为 LIVE 或 TERMINATED(reason)，执行阶段与它正交。取消后的 SUBMITTED 工作仍然需要接收完成事件。DRAINED 只表示本章登记的物理访问已经结算，不恢复请求的业务资格，也不表示分配器向驱动归还了全部缓存。

## 三种引用分别证明什么

逻辑引用回答“谁仍有权使用或保留这个对象”。A、B 共享前缀时，取消 A 只撤销 A 的持有；B 的拥有权、缓存目录持有和共享下载的其他等待者继续存在。公共权重通常随模型版本存在，不能由单请求取消直接卸载。

执行引用回答“哪些已经取得启动资格的访问仍可能发生”。登记必须先于启动，且覆盖准备任务、kernel、graph replay、DMA、外部库读者和存储读取。主机提交返回通常只说明提交阶段结束；一个 stream 的完成事件也只覆盖其实际排序到的访问，不能代表任意外部传输结束。

输出引用回答“哪些消费者仍需读取结果”。业务取消阻止新业务提交，但无法撤回已经交给发送缓冲或客户端播放队列的内容。ASGI 的 HTTP response body send 成功返回意味着该 body 已交给服务器发送缓冲，不证明客户端已经消费。应用原输出缓冲何时可释放，取决于适配层是复制内容还是继续借用它；不应统一等待远端确认，也不能统一在 send 调用发出时释放。

B_x 记录具体绑定要求。应用维护的固定图输入地址可以要求保留地址资格；CUDA 图内存节点则有 GPU ordered lifetime，固定虚拟地址不意味着物理 backing 必须在全部图节点生命期内独占保留。应按实际分配与图契约建账，不能把所有图对象一律解释成永久物理占用。

## 完成证书、隔离与迟到事件

为每项使用登记票据 τ=(r,g,x,uid,range,kind)。range 是该责任可能访问的底层字节范围，kind 区分准备、计算、传输与其他使用。完成适配器把平台事件转换为证书 κ，说明它覆盖哪张票据、哪些最后访问已经结束、业务结果是否有效。

“访问已经结束”和“结果成功”分别记录。失败操作若提供完整的最后访问结束证据，可以结算自己的 U，但其部分数据仍不能发布。部分范围成功、仅收到通知、提交返回或等待超时，都不足以结算整项责任。本章算法采用保守的整票据结算；需要分段回收时，应在启动前拆出范围互不混淆的票据。

证书处理分三类：已登记且匹配的完成结算自己的责任；已结束票据的重复完成无状态变化；身份、范围或证据不匹配的事件保留原责任并记录诊断。无法归属的旧事件不能反过来清除或隔离当前新对象。

Q_x 必须带原因和解除条件。若隔离原因只是“票据 τ 超时，尚无最后访问证据”，后来 τ 的真实完整完成可以同时移除 U 中的 τ 和对应隔离原因。其他票据、注册区或故障域的隔离不能随之清除。若上下文失效后已经无法取得单项完成，只能依靠平台明确支持的整个访问域停止、映射撤销或重建证据解除相应隔离；不能用第二次超时代替证据。

仅递增 e 或 g 可以拒绝旧结果提交，不能阻止旧 DMA 写入同一物理地址。地址必须保持隔离到最后访问结束，或者通过有明确停止保证的平台路径撤销旧访问权。

## 不同终止阶段的合法动作

| 触发点 | 可以立即改变 | 必须继续保留的责任 |
|---|---|---|
| 尚未提交的排队请求 | 撤出队列，撤销业务资格 | 已取得启动资格的解析、分词或读取任务 |
| 准备中取消 | 禁止后继提交，放弃未启动阶段 | 已启动的快照、页表、转换和预取访问 |
| GPU 执行中取消 | 禁止后续迭代和新业务输出 | 已提交 kernel、graph 及独立读者的最后访问 |
| 存储读取或转换失败 | 不发布失败范围，停止其依赖计算 | 仍可能写入 staging 的 I/O 与转换任务 |
| 传输中取消 | 停止新 WR 或分段，撤销未授权接管 | 已提交部分、目标写入和源恢复副本责任 |
| 已提交输出后断开 | 禁止新输出，通知相关消费者结束 | 已借用的发送缓冲、编码任务或客户端旧代队列 |
| worker 或执行组失效 | 撤销路由和后续业务提交 | 外部拥有者、注册区、对端和执行组的清理责任 |

请求取消不能让某个 rank 单独跳过其他 ranks 已经进入的 collective。受影响组需要按相应通信库和[恢复协议](serving-recovery.md)共同结束或重建。请求数归零也不能作为模型卸载完成条件：预取、图、编译、传输和输出仍可能持有版本状态。

## 终止、提交与回收的事件算法

以下是一种保守实现：状态拥有者串行处理事件；多线程实现用等价的锁或原子事务提供线性化顺序。它按整个物理对象回收，不提供任意字节段的并行重分配。事件处理不能在等待设备或满数据队列时占住唯一状态线程，否则完成通知可能永远无法解除责任。

生产者只修改本代私有候选，不直接推进请求历史、RNG 或对外输出。COMMIT 的资格检查和安装属于同一个事务。迁移场景还必须使用下一节的权威提交域：源端预先读取一次授权，随后在本地独立安装结果，不满足这里的原子性要求。

```pseudocode
算法 请求终止与对象回收
输入：请求、分配、使用、提交、消费者结束和故障事件
输出：唯一业务终态、已提交输出序列、空闲对象和具体阻塞责任

初始化：
  request、object、operation、已结束票据记录为空
  对每槽 s：current[s]=空，epoch[s]=-1
  对每对象：L、U、O、B、Q 为空；retiring=false；freed=false

循环取事件，在同一状态域内处理：

ARRIVE(r,规范化输入,limit)：
  若 r 已存在：执行入口去重，不重建其状态
  验证输入；建立 live=true、active_g=0、输出序号=0、提交记录为空
  若输入非法：TERMINATE(r,ERROR)
  否则若 limit=0：TERMINATE(r,LENGTH)
  否则进入等待队列

ALLOCATE(s,r)：
  要求 r 仍可服务，current[s]=空，旧生命期无未结责任
  失败：不改变 epoch、current 或任何引用
  成功：e=epoch[s]+1；建立 x=(s,e)，L_x={r}
        epoch[s]=e；current[s]=x；记录实际物理容量

ATTACH_OWNER(x,o)：
  要求 x 尚未释放且未 retiring，拥有者具有合法取得资格
  原子加入 L_x；拒绝事件不生成拥有权

START_OPERATION(I,uid,对象与范围集合)：
  要求请求 LIVE、I 为当前可启动代次、对象身份与快照一致
  要求启动者持有各对象的 L，且范围、权限、依赖合法
  先对每个对象登记对应 τ 到 U，并保存 operation 记录
  再发起实际操作；主机返回不结算已提交的 τ
  若明确全部未启动：以未启动证据撤销本次登记
  若部分提交：只撤销已证明未启动的部分
  若提交结果不明确：保留可能启动的责任及隔离原因

TERMINATE(r,reason)：
  若已终止：幂等确认，保留第一次确定的业务终态
  否则在提交状态域内设置 live=false、commit_eligible=false、terminal=reason
  撤销未取得启动资格的后继任务
  撤销 r 的逻辑持有；不删除其他拥有者或任何 U、O、B
  对不再保留的私有对象发起 RETIRE
  继续接收其在途完成事件

COMPLETE(τ,κ)：
  若 τ 已结束且证书身份匹配：返回 DUPLICATE，无状态变化
  若票据不存在或证书不能覆盖登记范围的最后访问：
      保留原责任；记录可归属的隔离原因；返回 INVALID
  从对应对象的 U 删除 τ，记录 τ 已结束
  只解除由 τ 的缺失完成证据造成的 Q
  若结果失败：标记对应产物不可发布；终止或进入显式恢复路径
  若结果成功：更新该产物的完成范围
  不因完成事件恢复已撤销的业务资格
  对受影响对象调用 RECLAIM

COMMIT(I,commit_id,candidate)：
  在同一个原子事务内检查并执行：
    请求仍 LIVE、可提交，I 与模型/输入/状态版本均匹配
    candidate 所需全部范围成功完成且对消费者可见
    若 commit_id 已提交：返回原提交结果，不重复推进序号或 RNG
    检查当前提交授权；迁移时通过权威接收端验证 term 和提交票据
    安装状态增量、token/RNG 更新和唯一输出记录
    在释放生产侧持有之前，为实际输出消费者登记 O
    保存 commit_id
  事务完成后才启动借用输出的消费者
  取消先于此事务：拒绝候选；提交先于取消：保留已提交记录

CONSUMER_END(x,cid,结束证据)：
  证据匹配时只删除自己的 O；重复通知不影响其他消费者
  未证明结束则继续持有；调用 RECLAIM(x)

DROP_OWNER(x,o) / UNBIND(x,b)：
  幂等删除对应 L 或 B；调用 RECLAIM(x)

RETIRE(x)：
  停止接纳新的拥有者和绑定；设置 retiring=true
  已有拥有者在释放 L 前仍受保护
  调用 RECLAIM(x)

TIMEOUT(当前请求期限或已登记操作)：
  请求期限到达时执行 TERMINATE
  对无法证明结束的使用保留 U，并登记具体隔离原因
  不伪造 COMPLETE，不提前扣减物理占用

RECLAIM(x)：
  若 x 已 freed：幂等返回；不得改写 current[x.slot]
  若未 retiring 或 L/U/O/B/Q 任一非空：报告阻塞集合后返回
  使缓存目录中的旧身份失效
  完成必要清理，或保证新生命期所有可读范围重新初始化
  要求 current[x.slot]=x；否则报告身份冲突，不清除新对象
  标记 freed=true；仅清除属于 x 的 current 和容量责任
  后续 ALLOCATE 才建立下一 e

停止准入后的排空：
  持续处理完成和消费者结束事件
  若所有待回收对象满足条件，报告达到声明的空闲基线
  若仍有 U/O/B/Q，报告对象、票据、最后事件与解除条件
  等待期限到达只能报告未排空，不能报告回收成功
```

登记后启动解决的是回收窗口，还需要处理“登记了但没有启动”的分支。若始终不撤销明确未启动的票据，会产生永远等不到的完成；若提交异常时直接清空全部票据，则可能释放已经被部分提交访问的对象。RDMA 链表提交在首个立即失败的 WR 处停止，正是需要区分已提交前缀和未提交后缀的具体例子。

已释放对象的墓碑和已结束票据记录不必永久保留。只有在明确的消息保留期限、执行域排空或代次水位证明旧事件不再可能被解释为当前责任后，才能压缩这些记录；压缩本身不授权物理地址提前重用。

## 共享前缀、在途写入和旧代重用的一条轨迹

以下时间与容量全部为设定。A、B 共享 2 MiB 前缀 P；A 有 64 MiB 私有槽 X=(s,0)，其中 kernel 和 DMA 分别持有 u_k、u_d；另有 1 MiB 已提交输出 Y 被发送消费者 c 持有。暂不计权重与池空闲保留。

| 时间 | 事件 | 责任与可执行动作 |
|---|---|---|
| 0 ms | A、B 已取得共享前缀，A 的两项访问已登记 | P 的 L={A,B}；X 的 U={u_k,u_d}；Y 的 O={c} |
| 2 ms | 取消 A | 删除 A 的逻辑持有，拒绝未来提交；P 仍由 B 持有，X 与 Y 继续驻留 |
| 5 ms | kernel 完成 | 只删除 u_k；DMA 仍可写 X，不能重用 s |
| 6 ms | 等待 DMA 超时 | 保留 u_d；隔离原因绑定 u_d；递增业务代次也不能释放地址 |
| 7 ms | DMA 的真实完整完成到达 | 删除 u_d 及其对应隔离；X 满足回收条件后释放 |
| 7 ms 之后 | C 取得 s 的新生命期 X′=(s,1) | 新内容与拥有者属于 X′；物理容量仍只计这一个 64 MiB 槽 |
| 8 ms | A 的重复完成和重复释放到达 | 命中旧记录，无权删除 X′ 的使用或清除 current[s] |
| 9 ms | 输出消费者 c 结束 | Y 才能回收；已提交内容不能因 A 取消而回滚 |
| 12–13 ms | B 放弃 P，最后一个已登记读者随后结束 | 两个条件汇合后才可淘汰 P |

取消到私有槽可重用的延迟为 7−2=5 ms；若把输出也计入请求私有资源的最终排空，则到 9 ms 才结束。7 ms 前所列对象占 67 MiB；C 重用 X 不会再新增一份 64 MiB，9 ms 后所列占用为 66 MiB，其中包含 C 的新对象和 B 的前缀。

反例是在 5 ms 只看到 kernel 完成便把地址交给 C。即使 C 的提交携带新 e，旧 DMA 仍可能覆盖 C 的物理内容。另一个反例是在 8 ms 处理旧 RELEASE 时无条件设置 current[s]=空：它不会立即写坏数据，却会允许第三个请求再次取得 C 正在使用的槽。

## 迁移完成、提交静止与源回收

目标收到全部字节不等于已经接管请求；源端发送 staging 可复用也不等于最后一份恢复状态可丢弃。迁移还必须固定一个包含全部已提交状态的边界，并阻止旧提交穿越接管。

这里构造一种保守协议。权威提交域 A 串行维护请求存活状态、授权 (r,term,owner)、提交入口门控、已进入提交事务集合 J、已安装提交序号 v、幂等提交记录和迁移决定。A 可以由一个状态拥有者或具备相应事务保证的服务实现；必要前提是授权验证、提交安装与接管决定处于同一个线性化域。一个可线性化的 owner 键，加上独立的源端状态写入，不满足这个前提。

实际提交接收端就是 A。计算节点把私有候选和不可变状态描述符交给 A，不能凭先前读到的授权直接修改正式历史或发送新业务结果。A 在安装时重新检查 term、owner、当前票据、前驱版本和请求资格，并在同一事务内安装增量与输出记录。因此 fencing 发生在实际结果被接受的位置；源端读取授权只是可选的提前拒绝，不能替代接收端检查。

p 是最终业务提交序号，不是“已生成 token 数”或“KV 长度”的别名。快照 S_p 必须包含恢复该提交前缀所需的 token、真实已计算状态边界、模型与表示身份、RNG、约束状态，以及已提交输出记录与必要消费游标。已经选择但尚未计算 KV 的末 token 必须按其真实边界保存。输出发送是否已经被客户端确认另外记录，不能把 p 当作远端消费确认。

```pseudocode
算法 带提交静止点的责任转移
输入：A 中当前授权 (r,t,src)，目标 dst，不复用的迁移尝试 a
输出：ABORTED(a) 且 src 可继续，或 COMMITTED(a,t+1,dst,p)
初始化：请求 LIVE，gate=OPEN，J 为空，v 为已安装序号
          每个提交票据、commit_id 和迁移尝试保留幂等决定

正常提交入口 ENTER_COMMIT(src,t,uid,commit_id,base,candidate)：
  在 A 中原子检查：
    请求 LIVE，gate=OPEN，当前授权精确匹配 (r,t,src)
    uid 未使用，base=v；候选身份与所需完成证据合法
    若 commit_id 已提交：返回已有结果，不建立第二个提交
  登记 j=(uid,src,t,commit_id,base,candidate) 到 J
  返回已进入票据；此返回尚不代表业务提交成功

结算 INSTALL(j)：
  在 A 中同一个原子事务内：
    要求 j 仍在 J，授权仍为 j 的 owner 与 term，请求 LIVE
    要求 j.base=v，候选完整、可见，commit_id 尚未安装
    允许迁移 DRAINING 期间结算关门前已进入的票据
    安装状态增量、RNG、唯一输出记录和 commit_id；v 加一
    从 J 删除 j，保存唯一提交结果
  若前驱版本已变化：不安装；由显式 ABORT_TICKET 结算该票据
  若授权、票据或请求资格失效：拒绝，不产生业务副作用

ABORT_TICKET(j)：
  在 A 中原子撤销仍未安装的 j，保存撤销记录
  后续 INSTALL(j) 必须被实际接收端拒绝
  仍运行的私有计算或 DMA 继续持有 U，不能据此释放物理对象

开始迁移：
1. dst 预留独立 staging；可以先复制已封闭的不可变前缀。
2. A 原子核对 (r,t,src)、请求 LIVE、无其他有效迁移：
     将 gate 从 OPEN 改为 CLOSED，登记 a，进入 DRAINING。
   关门与 ENTER_COMMIT 在同一状态域内排序；源端所有提交入口受此门控。
3. 持续处理 J：每张已进入票据必须安装成功或在 A 中明确撤销。
   不在状态线程中阻塞等待；超时只报告未结，不能凭超时清空 J。
4. J 为空后，A 原子核对 a 与旧授权仍有效：
     固定 p=v，进入 FROZEN，保持 gate=CLOSED。
   固定 S_p；其底层对象必须不可变、COW 隔离或已等待全部可能写者结束。
   未提交候选不得原地修改 S_p。
5. 为源读取、网络操作和目标写入分别登记物理使用票据并传输。
   目标按范围验证同一个 S_p；部分成功保持未发布。
   完整、相容并对执行器可见后，登记 READY(a,p,manifest)。
   READY 不改变授权，也不允许目标业务提交。
6. A 原子核对：
     请求 LIVE，授权仍为 (r,t,src)，a 有效，状态 FROZEN，
     gate=CLOSED，J 为空，v=p，READY 精确匹配 S_p。
   在同一事务内：
     授权改为 (r,t+1,dst)，记录 COMMITTED(a,t+1,dst,p)。
     保持新提交门关闭，进入 TAKEN；旧源永久失去本次 term 的提交资格。
7. dst 查询并确认权威决定，按 S_p 恢复全部状态。
   A 核对新授权、相同 a/p 和恢复就绪后，允许 dst 打开新提交入口。
   dst 的第一个新提交以 p 为前驱，成功后序号为 p+1。
   重复激活只返回已有结果，不能把已推进的目标重新覆盖回 S_p。
8. src 的 staging 按本地最后使用结束回收。
   最后一份源恢复副本另等责任移交、恢复保留条件和全部访问结束后回收。

失败、取消与不确定结果：
  接管前放弃 a：在 A 中以当前 a、旧授权和未接管为条件，
    原子记录 ABORTED(a)，使旧 READY 和接管请求失效；
    请求仍 LIVE 时才重新打开 src 的提交入口。
    若尚在 DRAINING，保留未结票据，随后按正常规则结算。
  解除冻结后的新提交使旧 S_p 仅属于已放弃尝试，不得再次接管。
  请求取消与安装、接管在 A 中排序；取消先发生则拒绝后续安装/接管。
    未结票据需撤销，物理使用仍需排空；不得由迁移恢复 LIVE。
  接管或放弃的确认丢失：查询 a 的权威决定；重试相同操作返回原决定。
    不根据本地超时重新授权 src，不丢弃可能已经承担恢复责任的 dst。
  查询暂不可用：保持门控与副本责任，报告结果未知。
```

J 是业务提交事务集合，U 是物理访问集合。撤销 J 中的票据可以使旧事务再也不能安装业务结果，却不证明其 kernel 或 DMA 已经停止。固定快照也不是全设备同步：只有会修改 S_p 的访问必须结束或隔离，读取不可变前缀和无关请求可以继续。

同一前驱版本上可能已经进入多张票据。其中一张安装后，其他候选必须重新验证前驱；它们不能各自推进同一个 RNG 或输出序号。不能安装的票据需要显式撤销，随后才可形成 J=∅ 的冻结证明。

若副作用在 A 事务外发生，A 应先安装带唯一输出身份的 outbox 记录，再由交付者发送。接管后旧交付者继续发送已经安装的记录，不属于新的旧 term 提交；它仍需遵守输出身份、消费责任和协议去重。这个设计保证内部提交前缀，不自动提供网络恰好一次交付。无法参加事务、无法 fencing 且不能按身份去重的外部副作用，不在本协议的安全迁移范围内。

### 三种交错怎样被截断

| 交错 | 错误方案会发生什么 | 本协议的实际状态变化 |
|---|---|---|
| 已复制快照 p，源端想推进 p+1 | 只检查 owner 未变，目标可能从过期的 p 继续 | 预复制不是最终快照；先关门并结算 J，才固定最终 p。FROZEN 后新入口被拒绝，接管还核对 v=p |
| 旧事务读到 term=t 后暂停 | 接管后旧事务仍按缓存授权安装 | 若票据仍在 J，冻结与接管不能成功；它先安装则纳入最终 S_p。若票据已撤销，迟到安装在 A 被拒绝；接管后的旧 term 同样被拒绝 |
| 接管已成功，成功确认丢失 | 源按超时恢复，形成两端推进 | A 已保存 COMMITTED(a,t+1,dst,p)。源重新开门的条件更新失败；目标按同一决定恢复。查询失败时暂停，不能把未知结果解释为未接管 |

例如源已有 17 个正式提交，旧事务 j 已读到授权并暂停。关门后 J={j}，因此不能在 17 冻结并接管。若 j 安装第 18 项，先令 J=∅，最终 p=18；若 A 撤销 j，则最终 p=17，旧 j 无法再安装。两条路线都让目标恢复边界包含全部正式提交。反例是忽略 J，在 p=17 接管后让 j 安装第 18 项：单独的授权读与 owner CAS 都无法排除它。

门控的恢复也必须是原子条件更新。先查询看到仍由 src 持有，再在本地开门，中间可能发生接管；因此查询结果只能用于诊断，真正重新开门必须与 ABORTED(a) 的决定共同安装。目标 READY 的撤销或副本丢弃同理：接管结果未知时，不可单方面销毁可能已成为唯一恢复状态的副本。

协议以授权域不可用时停止推进为代价。它没有证明 A 的存储实现、跨故障域持久性、任意模型可重建或源崩溃后仍能取得完整 S_p。若源在最终快照形成前失效且没有可恢复提交日志或其他副本，应报告无法继续本次迁移。ServerlessLLM 的 token 重算是特定恢复路线；递归状态、约束、随机状态及外部动作仍需各自的恢复契约。

## 条件化成本与容量反馈

设取消时刻为 t_c，各对象最后访问、消费者结束和绑定解除时刻分别为 t_U、t_O、t_B。并行清理的最早回收边界由这些依赖的最大值和逻辑持有结束共同决定，再加真正位于其后的通知处理、清理或重新初始化时间。不能把全部 kernel、DMA 与输出耗时直接相加，也不能因其中一项完成较早便忽略另一项。

计算与访存：停止后续迭代可以避免未来计算，已提交 kernel 仍可能读取输入、写 KV 和 workspace。若没有受支持的中止路径，排空取决于剩余访问链，而不一定只是一项 kernel。清理还可能扫描页表、撤销目录或初始化 B 字节可读区；初始化的纯带宽下界约为 B/W_mem，实际事务量与布局、写分配及实现有关。

通信：仍需传输的 B_rem 字节在有效带宽 W_net 下有 B_rem/W_net 的纯传输时间下界，排队、重试和控制握手另计。源副本、目标预留和 staging 若是不同物理分配，应同时计容量；共享同一分配的多个逻辑引用只计一份。

准备与同步：按对象维护 L/U/O/B/Q 需要元数据和事件校验。使用哈希集合时，单项更新具有平均常数级查找成本，但一次操作仍需遍历它保护的 m 个对象或范围；扫描全部未结责任的排空检查为 O(m)。事件合并可以减少主机开销，前提是合并证据覆盖全部被撤销责任。粗锁简化线性化，可能限制完成处理率；细锁增加锁序和重复事件的验证成本。

迁移暂停另有业务关键路径。若关门后依次执行提交结算、最终增量传输、目标验证、授权切换和目标激活，则

T_pause = T_settle + T_delta + T_verify + T_transfer_authority + T_activate。

这是所选顺序的墙钟模型；能够重叠的验证与复制应按实际依赖重算。T_settle 只等待业务提交票据结算；为保护快照等待物理写者的时间仍需计入相应依赖。撤销提交票据可以减少业务等待，却可能继续保留 U 和私有候选容量。

设定 T_settle=3 ms，最终增量 32 MiB、有效链路 8 GiB/s，验证 1 ms，授权和激活各 1 ms，且各段串行，则纯传输为 3.90625 ms，暂停约 9.90625 ms。它不包含预复制、排队、重试和快照写者等待，是设定计算，不是设备观测。若整个 1 GiB 状态都需在关门后复制，同一带宽下仅传输就需 125 ms；预复制只有在前缀不可变、增量版本可识别时才能缩小这项成本。

A 还引入每次正式提交的事务处理与可能的网络往返。批量提交可以摊薄固定开销，但扩大一次进入 J 的工作单位，可能拉长静止等待。迁移决定、票据墓碑和提交去重记录需要驻留；记录压缩必须保留足以拒绝旧事务的代次与水位。不能为减少授权延迟把检查移到安装事务外。

驻留更适合用字节时间计算。设被取消对象的进入率为 λ_c，单位为对象/秒；对象在取消后额外持有的唯一物理字节为 b_i(t)，则稳定条件下平均额外驻留为

M_cancel = λ_c E[∫ b_i(t) dt]。

只有对象大小固定为 B、持有时长为 T 时，才能简写为 λ_cBT；大小与时长相关时不能无条件相乘两个均值。共享对象需要按物理并集或明确的唯一归属统计，不能分别把 A、B 的取消都加上一整份共享页。

设每秒有 20 个取消对象、每个额外持有 64 MiB、平均持续 0.5 秒，则平均额外驻留为 640 MiB，平均保护 10 个同大小槽。这是稳定队列算例；若完成处理拥堵让持有时间随并发增长，该占用又会减少准入容量，形成反馈，不能继续把 0.5 秒当常量。迁移门控期间也需同时保留源快照、目标副本及仍在途的私有候选，按实际物理并集计算峰值。

吞吐模型必须区分工作量与墙钟时间。设正常请求消耗 G 个设备秒，取消请求在取消前消耗 fG、之后仍消耗 D 个设备秒，取消比例为 c，设备可提供 P 个设备秒/秒。忽略其他瓶颈时，有用正常完成率满足

X_useful ≤ P(1−c) / [(1−c)G+c(fG+D)]。

D 是剩余设备工作，不能把纯网络等待或空闲隔离墙钟时间直接填入。隔离容量、CPU 锁、权威提交处理和带宽还会给出其他约束，因此该式不是服务吞吐的通用预测。

## 条件变化后的方案选择

| 条件变化 | 必须保留 | 可以调整及其反转信号 |
|---|---|---|
| 接口提供真正中止与结束证据 | 证据覆盖最后访问 | 用中止缩短排空；仅调用返回而无结束证明时继续隔离 |
| 单 stream 改为跨 stream 或外部 DMA | 全部实际使用者均受保护 | 重建 event、注册区和外部完成依赖，不能沿用单队列假设 |
| 共享前缀或共享下载增加 | 每个拥有者与在途使用独立结算 | 缓存可延迟淘汰；不能把单请求终止变成共享操作取消 |
| 高取消率与大对象 | 未释放物理容量仍计入准入 | 限制在途深度、缩短可中止工作单位或降低准入；加槽只缓解暂态 |
| 小对象与高事件率 | uid 幂等及覆盖关系 | 合并票据与批量处理；通知滞后超过收益时需缩小合并窗口 |
| 图或注册绑定长期存在 | 地址资格与访问责任分别成立 | 拆分生命期、解除不再需要的绑定；不能仅因一次 replay 完成就卸载 |
| worker 崩溃 | 外部责任和旧提交权可判定 | 按访问域重建、授权代次和对端协议清理；局部引用计数不再充分 |
| 输出消费者很慢 | 借用缓冲的实际结束边界 | 有界背压、复制后交还或终止消费者；复制减少设备驻留但增加主存与流量 |
| 提交域与业务状态分离 | 最终安装必须接受 fencing | 引入共同事务或权威提交接收端；单次读取授权方案应放弃 |
| 最终增量过大或静止等待过长 | 最终 p 覆盖全部已提交状态 | 在合法不可变前缀上预复制、缩小提交单位，或放弃本次迁移；不能放宽快照边界 |
| 授权服务不可达 | 未知接管结果不能恢复旧提交权 | 等待权威决定或按另有证明的恢复路线终止；不能靠本地超时双端推进 |

## 竞争解释、区分实验与反证修正

| 观察与竞争解释 | 区分实验 | 预测与修正 |
|---|---|---|
| 取消很快但槽迟迟不归还：设备排空、通知阻塞、输出借用或泄漏 | 分别延迟设备完成、主机通知处理和输出消费，记录三本账 | 归还随哪个延迟变化就优先查哪条责任；设备早已结束不能继续只归因 GPU |
| 新请求读到旧数据：提前回收、旧代提交或布局错误 | 分别保持旧存储存活、拒绝旧代提交、固定布局与物理页 | 保活消错支持物理生命期；仅提交门控消错支持结果归属；均无效则重查布局与范围 |
| 两个读者只有一个完成后就可回收：计数重复递减或 uid 混淆 | 交换结束顺序，重复同一证书，让两个代使用相同局部 uid | 同一票据重复必须无效；旧代同名 uid 不能清除新代使用 |
| 超时后仍写坏地址：把超时当完成或隔离解除范围过大 | 延迟真实 DMA 完成，对照仅换代次与隔离到结束 | 仅换代次仍出错支持物理访问问题；一个票据完成后其他访问仍应阻止重用 |
| used 回落但驱动占用不降：缓存池保留或其他绑定 | 停止准入并分记对象 used、池 reserved、图和注册责任 | used 回基线且 reserved 稳定支持合法保留；排空后不可解释增长才支持泄漏方向 |
| 迁移丢失或重复一个输出：最终快照过旧、旧事务穿越或交付重送 | 分别在最终快照后尝试源提交、在授权预读后暂停旧事务、仅重送已提交 outbox | 前两项应被门控或接收端 fencing 截断；内部日志正确而网络重复时转查交付身份与确认 |
| 接管确认丢失后双端推进：错误恢复旧授权或 READY 被当作授权 | 丢弃接管成功响应，再让源请求恢复、目标查询决定 | 源条件恢复应失败，目标按 COMMITTED 决定激活；查询不可达应暂停。若源仍可安装，检查是否绕过 A |
| 迁移暂停长：未结提交、快照写者、增量传输或授权服务 | 分别暂停一张 J 票据、一个 U 写者、网络完成和授权响应 | 各阶段应留下不同阻塞证据；撤销 J 后仍占内存说明物理责任尚在，不能判为提交门控失效 |

正确性数据应让各请求、对象代次与输出序号可区分。无效完成的测试必须先撤销其他会遮蔽错误的拥有者：若 L 仍非空，即使错误地删除 U，释放也可能继续被 L 阻挡，形成没有辨别力的“通过”。

参考回放必须服从动作接受结果。对“旧对象仍在途时尝试重用，重用被拒绝，随后旧对象完成”的轨迹，拒绝的重用不能出现在历史拥有者集合中。否则参考会凭空创造一个新拥有者，把合法释放判成错误。需要同时检查拒绝动作无资源副作用、正常成功轨迹和能触发错误的负对照。

迁移检查还应核对完整已提交前缀，而不只统计某一时刻 owner 的数量。一个系统可以始终只有一个 owner，却仍让目标从过旧快照恢复；也可以正确拒绝新源提交，却遗漏关门前已进入、尚未安装的事务。固定预期边界、内容、幂等身份和提交前驱，才能区分这些错误。

## 压力下的最终守恒检查

反复准入、取消、部分提交失败、重复完成和槽重用后，停止新请求并继续处理解除责任的事件。检查私有拥有权、在途访问和输出借用结束，共享引用恰好等于仍存活的拥有者，旧代次没有业务提交权，借用额度在真实释放后归还。

迁移停止后同时检查：每个尝试有唯一权威决定；放弃尝试的 READY 不可再次接管；成功接管边界等于关门并结算后的完整前缀；没有未结旧提交票据；已撤销票据与旧 term 不能安装；重复激活不回退目标状态。物理排空继续独立核对，不能由这些业务条件替代。

物理容量按唯一分配求和；池的 used 是 reserved 的一部分，不能二者相加。允许保留的权重、缓存和 arena 应有预先声明的基线。未完成对象必须列出具体票据和解除条件；不得把等待超时、请求数为零或进程退出写成全部资源已经回收。
