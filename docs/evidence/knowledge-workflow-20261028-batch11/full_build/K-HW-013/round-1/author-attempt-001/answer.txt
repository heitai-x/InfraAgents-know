{"chapter":"# K-HW-013：共享内存路径：统一地址、物理驻留与显式迁移\n\n同一个虚拟地址能被 CPU 和 GPU 解引用，只说明两者共享地址表示或存在合法映射，不说明它们读取同一份物理内存、拥有一致缓存、拥有相同访问能力，或不需要同步。设计共享路径时，先把地址空间、物理驻留、访问能力和同步契约分开，再在同一访问轨迹上比较显式复制、映射访问、可迁移统一内存与物理统一内存。\n\n## 问题、对象与四种关系\n\n设逻辑对象为 O=(id, va, bytes, version)。va 是进程可见的虚拟地址范围，bytes 是其有效字节数，version 标识内容代次。物理分配 P=(pid, pool, pages) 表示一组物理页及其所在内存池；迁移或复制会产生新的物理身份，不能因为 va 相同就把两个 P 当成同一对象。\n\n对一次访问 A=(O, range, processor, mode, stream) 至少需要四个关系同时成立：\n\n- 地址关系：range 已映射到可解引用的 va，且越界、别名和页表状态明确。\n- 物理关系：页当前驻留在某个池，或存在合法的远端访问映射；指针值本身不说明驻留位置。\n- 能力关系：processor 能对该范围执行所需 load/store 或原子操作，dtype、对齐、cacheability 与事务宽度满足要求。\n- 契约关系：生产者的写入已经对消费者可见，读者已经登记，覆盖或回收发生在最后一个使用者之后。\n\n| 路径 | 数据怎样被访问 | 主要合法性条件 | 主要成本 |\n|---|---|---|---|\n| 独立设备缓冲与显式复制 | CPU 与 GPU 各有目的缓冲，按依赖搬运 | 目的容量、传输能力、复制完成与源/目的生命周期 | 副本容量、DMA、传输完成、staging |\n| GPU 映射访问主机内存 | GPU 通过受支持的映射读取主机驻留页 | 映射能力、锁页/注册范围、访问宽度与同步 | 链路读取、事务放大、TLB、同步 |\n| 可迁移的统一内存 | 系统按页迁移或映射，访问可触发缺页 | 支持级别、页粒度、并发访问规则、完成关系 | 缺页、迁移、预取、来回迁移、页表 |\n| 物理统一内存 | CPU 与 GPU 使用共同物理池 | 同一池、共同可见性、执行依赖 | 共享带宽、缓存行为、容量竞争 |\n\n固定 MLX 文档说明 Apple Silicon 的 CPU 和 GPU 可以直接访问同一内存池，数组创建时不必指定位置，设备在操作执行时选择；框架会为受跟踪的跨设备数组依赖建立顺序。固定 CUDA 资料按系统和设备能力区分 Unified Memory 支持级别，并指出统一内存仍会发生数据移动。固定 PyTorch 文档说明 GPU 操作通常异步入队，跨 stream 顺序与 allocator 生存期需要显式处理。这些来源支持的是各自范围内的机制，不能因名称相近就套用同一套页迁移或 allocator 假设。\n\n## 合法性：能力、容量与可见性\n\n### 显式复制\n\n显式复制要求目的缓冲容量足够，复制范围与源代次匹配，消费者在复制完成后才读取。异步复制返回或调用返回不等于数据已经可读；必须取得覆盖本次复制的完成票据。源在 DMA 读取结束前不能改写，目的在复制写入结束前不能被读者消费。pageable 主机内存的异步传输可能经过额外 staging；锁页内存提供更稳定的 DMA 页面，但锁页本身有容量和准备成本。\n\n显式复制不自动提供 CPU/GPU 一致性。CPU 改写主机源后，若 GPU 仍读取旧设备副本，必须有新的 H2D 或重新映射；只比较指针不能证明内容同步。\n\n### 映射主机内存\n\n映射路径要求设备支持相应映射，并满足页锁定、注册范围、映射使能和访问宽度条件。固定 CUDA 摘录说明，映射页锁定主机内存可由设备直接访问，但仍须用 stream 或 event 同步读写，避免 RAW、WAR 和 WAW 冲突；映射内存上的原子操作不保证从主机或其他设备看来仍是原子的；设备发起且自然对齐的 1、2、4、8、16 字节单次访问有特定的保持单访问约束。\n\nwrite-combining 主机内存可以改善设备读取或释放缓存资源，但主机读取通常很慢，应主要用于主机只写的数据；CPU 对 WC 内存的原子操作也不应作为通用保证。映射路径没有显式 H2D 副本，不等于没有链路读取、事务重发或同步成本。\n\n### 可迁移统一内存\n\n可迁移统一内存要求目标系统支持相应级别。固定 CUDA 指南区分完整支持、仅 Managed Memory 支持和无并发支持等情形；不支持时继续使用属于未定义行为。统一指针可由多个处理器解引用，但物理页可能迁移，也可能被映射为远端访问。pointer attributes 说明分配或注册类型，不说明当前物理驻留。\n\n预取是 stream-ordered 的性能提示，不是正确性条件。所给 CUDA 摘录说明，迁移在 stream 中前序操作完成后才开始，并在后续操作前完成；数据在预取期间仍可能被访问，其他 stream 的读者不能把预取提示当成通用可见性屏障。缺页、迁移和预取都可能改变尾延迟，且提前量过大会挤出其他对象。\n\n### 物理统一内存\n\n物理统一内存要求 CPU 与 GPU 确实共享同一物理池，并满足执行依赖。统一地址不取消生产完成先于消费、最后读取先于覆盖的关系。固定 MLX 文档中的自动依赖适用于框架跟踪的数组操作；通过原生指针、外部库或其他进程访问时，仍要按互操作契约建立同步、复制或序列化。\n\n物理共享设备上，CPU 预处理、GPU 权重读取和其他进程会竞争共同带宽与容量。省掉显式副本不等于省掉读取字节，也不等于两个处理器的孤立时间可以取最大值。\n\n### 地址稳定、图与回收\n\nCUDA Graph 重放依赖稳定的虚拟地址和兼容的执行结构。固定 PyTorch 文档说明，图重放固定输入输出地址；若地址被释放或重分配给新 tensor，重放可能非法访问或破坏数据。捕获期的分配进入图私有池，池与图及捕获期 tensor 同生命期。多个图共享池只有在确定按捕获顺序重放且从不并发时才安全；共享池时一张图的重放可能覆盖另一张图的输出，除非先复制。\n\n因此，地址稳定是一条独立于内容版本的合法性条件。对象已经结束、但未来图仍可能重放其地址时，不能只按业务完成回收。\n\n## 成本模型：字节、事务、页与驻留\n\n以下符号均在同一访问轨迹和同一时间范围内使用：D 为对象逻辑字节数，x 为实际被访问的比例，R 为完整或局部重复访问次数，B_l 为链路或远端有效带宽，B_d 为设备本地有效带宽，B_s 为共享池在并发条件下的有效带宽，g 为页大小，N_p 为被触及页数，M 为总页迁移次数，F 为缺页或控制次数，T_f 为单次缺页/控制开销，α 为实际事务字节与有用字节之比。\n\n显式复制且复制先于本地读取、没有其他重叠时：\n\nT_copy ≈ D/B_l + R·D/B_d + T_prep + T_sync + T_stage。\n\n第一项是至少一次完整对象搬运，第二项是复制完成后的本地读取。复制与独立计算可以重叠，但复制完成之前消费者仍不能读取；不能把已经串行的复制链直接减去。若只访问对象的一小段而仍复制整个对象，应把 D 换成实际复制范围。\n\n映射远端读取近似为：\n\nT_map ≈ R·α·x·D/B_l + T_sync + T_prep_map。\n\nα 由访问是否合并、是否跨页、是否重复取表决定；稀疏小访问可能触发远大于有效载荷的事务。映射路径没有 D/B_d 的本地复制读取项，但有链路读取、TLB、同步和远端访问延迟。\n\n可迁移路径近似为：\n\nT_mig ≈ M·N_p·g/B_l + R_t·N_p·g/B_d + F·T_f + T_prefetch + T_sync。\n\n这里 N_p·g ≥ x·D，页放大为 A_p=(N_p·g)/(x·D)≥1。只访问一个元素也可能迁移整页；CPU 改写后再由 GPU 读取，可能产生回迁或远端映射。迁移期间源页和目的页可能同时驻留，容量账要包含在途页；预取一批页也会增加在途容量。若系统选择映射而非迁移，链路项应按实际远端读取重算，不能同时套用迁移字节公式。\n\n物理共享路径近似为：\n\nT_shared ≈ R·α·x·D/B_s + T_sync。\n\n它没有显式 D/B_l 复制项，但 B_s 是 CPU、GPU 与其他进程共同竞争后的有效带宽；容量也是共同池中的一份而不是两份。若 CPU 预处理和 GPU 读取同时进行，总需求可能超过 B_s，简单取两个孤立时间的最大值会低估。\n\n页大小改变两类成本：较小页减少内部碎片但增加 TLB 缺失和页表项；较大页减少 TLB 缺失但增加迁移粒度、尾部和一次迁移的延迟尖峰。固定 CUDA 摘录明确把这一权衡列为 Unified Memory 调优问题，不能脱离访问轨迹宣称某个页大小普遍最优。\n\n驻留峰值按物理身份去重：\n\nM_peak = max_t Σ_{p∈Live(t)} size(p)。\n\n同一物理页的多个视图、CPU/GPU 引用或共享前缀只计一次；显式设备副本、staging、锁定页、图私有池、页表和迁移在途页属于不同物理对象时才相加。逻辑释放但仍有读者或迁移在途的页仍占容量。逻辑字节、设备事务字节、容量峰值和关键路径时间必须分别记录。\n\n成本项可分开列账：计算通常不因路径改变而改变，但 CPU 预处理会与 GPU 竞争主存；准备包括锁页、注册、映射、首次触碰、页表和图捕获；通信包括 DMA 或远端读取；同步包括 stream、event、可见性和最后读者；驻留包括副本、锁定页、池保留和迁移在途页。可重叠项按依赖图计算，不能把全部阶段时间机械相加。\n\n## 路径规划与状态转换\n\n下面的算法是本章的逻辑规划协议，不是对某个运行时 API 的调用序列。它把路径选择、页粒度、容量预留、可见性和最后读者放在同一轨迹中；真实系统还需把抽象票据映射到目标平台的 stream、event、映射或迁移接口。\n\n```pseudocode\n算法 PLAN_PATH_AND_MOVE\n输入：对象 O=(id, va, D, version)，访问轨迹 A=[(phase, processor, mode, start, end, stream)]，\n      能力 C，容量预算 K，页大小 g，依赖图 G\n输出：路径、容量预留、复制/映射/迁移计划与完成票据；或拒绝原因\n\n若 D=0 或 A 为空：\n    返回 NO_ACCESS；不建立复制、不迁移页、不增加对象 epoch\n若 g<=0、存在负范围、start>=end、或 processor 未知：\n    返回 REJECT_ARGUMENT\n\n建立计划 P：\n    来源对象保持只读或按读者登记\n    目的对象/映射范围初始为空\n    每页 residency 记录所属池、代次、有效/脏状态\n    active_readers 为空，writer 为空，plan_epoch 等于 O.version\n\n第一步：枚举每个非空访问并计算页集\n    对 a in A：\n        S_a = { floor(b/g) | b in [a.start, a.end) }\n        记录 accessed_bytes(a)=a.end-a.start\n        记录 page_amplification(a)=|S_a|*g/accessed_bytes(a)\n\n第二步：筛掉不合法候选\n    显式复制候选：要求有目的容量 D、必要 staging 容量、传输能力，\n        且源在 DMA 读完前不会被改写\n    映射候选：要求 processor 对主机页有映射/锁页能力，\n        访问宽度、对齐、原子语义和目标版本满足要求\n    可迁移候选：要求系统支持级别允许该访问，\n        页表、并发访问和完成关系可建立\n    物理共享候选：要求同一物理池和访问权限，\n        且 CPU/GPU 共同依从同步契约\n    删除不满足依赖、版本、范围或容量者；没有候选则 REJECT_ILLEGAL\n\n第三步：在同一阶段边界上估算剩余候选\n    对每个候选 p：\n        按实际复制字节、映射访问字节、迁移页数或共享读取字节计算 T_p\n        按物理身份去重计算 M_peak(p)\n        检查 M_peak(p) <= K\n    选择合法且估算成本最低者；若成本相同，优先不增加物理副本、\n        不要求地址改变且不延长最后读者保护的候选\n\n第四步：执行计划并建立状态\n    显式复制：\n        预留目的和 staging；先提交复制\n        只有复制完成票据覆盖本次范围后，才发布 local_copy_valid\n        写入者要等目的旧读者结束；源在读取结束前保持该代次\n    映射：\n        建立/复用映射并发布 host_visible\n        每次主机写入产生新的 version；GPU 读取前等待该 version 可见\n        读者登记 active_readers；不能把映射存在当成读取完成\n    可迁移：\n        按 S_a 计算要迁移或预取的页\n        每页迁移有源读完成、目的写完成和发布三个关系\n        预取只提前发起，不替代消费前的完成检查\n        缺页可把访问改为远端映射或迁移；实际选择必须与计费口径一致\n    物理共享：\n        不建立链路复制；登记共同容量和执行依赖\n        共享容量只计一次物理页，带宽按当前并发负载估计\n\n第五步：提交、覆盖与回收\n    仅当所有被消费字节的完成票据覆盖、version 匹配且 active_readers 允许时，\n        发布新 version\n    写者覆盖前等待 active_readers 为空，或证明只访问不重叠范围\n    最后一个读者结束且没有在途迁移后，才允许回收、覆盖或交给下一 epoch\n\n取消或失败：\n    已经提交的复制/迁移继续按自己的完成票据排空\n    迟到完成携带旧 epoch 时不释放新对象，也不发布旧内容\n    不能证明访问结束时保留隔离和责任账，不宣称已经回收\n```\n\n关键不变量是：地址可解引用不等于内容已经可见；内容版本正确不等于地址可以回收；复制/迁移完成不等于全部读者结束。对象需要代次时，代次必须覆盖迟到完成、旧图重放和池复用，不能只在一个函数调用栈内有效。\n\n## 组合轨迹：CPU 预处理、GPU 读与回写\n\n设定对象 O 为 64 MiB，链路有效带宽 B_l=16 GiB/s，设备本地有效带宽 B_d=512 GiB/s，页大小 g=64 KiB。CPU 先写整对象；GPU 只读取其中 1 MiB；CPU 再修改同一 1 MiB；GPU 再读取该 1 MiB。所有数值是设定算例，不是设备实测。\n\n显式复制路径若先复制整个 64 MiB，再在 CPU 修改后补一次 1 MiB H2D，则链路共 65 MiB，本地 GPU 读共 2 MiB。忽略准备和同步，T≈65 MiB/(16 GiB/s)+2 MiB/(512 GiB/s)≈3.9673 ms+0.0038 ms≈3.9711 ms。容量上，主机源、锁定 staging 和设备副本可能同时存在，峰值至少包含 64 MiB 设备副本和主机侧预留。\n\n映射路径若把 64 MiB 主机范围锁定并映射，GPU 两次远端读取 1 MiB，访问连续且 α 接近 1 时，链路读取约 2 MiB/(16 GiB/s)≈0.1221 ms，另加映射准备和两次同步。没有 64 MiB 设备副本，但主机范围仍被锁定并占容量；CPU 写入后必须让 GPU 看到新 version，不能只比较指针。若访问退化为每页一个元素，α 可能接近 g/元素字节，远端读取会按整页事务放大。\n\n可迁移路径若第一次 GPU 读触发 16 个页迁移，共 1 MiB；CPU 修改后若页需要回迁，再迁 1 MiB 回主机；第二次 GPU 读再迁 1 MiB 到设备。总迁移量约 3 MiB，链路约 3 MiB/(16 GiB/s)≈0.1831 ms，本地读约 2 MiB/(512 GiB/s)≈0.0038 ms，另加 3 次缺页/控制开销和同步。若运行时选择远端映射而非回迁，应按实际远端读取重算，不能把 3 MiB 迁移量当成唯一可能路径。迁移在途时最多可能有页同时留在源和目的，容量账要加上这部分。\n\n物理共享路径没有链路迁移，GPU 两次读取同一 1 MiB 共享页，成本由共享有效带宽和同步决定。若并发负载下 B_s=200 GiB/s，两次读取约 2 MiB/(200 GiB/s)≈0.0098 ms，但 CPU 修改、其他进程和 GPU 读取竞争同一资源；这个数只说明在没有其它争用时共享路径可能很小，不能当成服务尾延迟承诺。容量只有一份 64 MiB 物理对象，但仍要与权重、KV 和工作区竞争。\n\n这组轨迹显示三种反转：只读一小段时，整对象显式复制可能远贵于映射或按页迁移；反复读取大对象时，本地副本可能摊薄复制；CPU/GPU 交替写读时，可迁移路径可能出现页来回迁移，物理共享路径则可能被带宽竞争限制。任何选择都必须绑定实际 x、R、页大小、同步次数和容量，而不是只绑定路径名称。\n\n## 条件变化后的保留、调整与放弃\n\n| 条件变化 | 保留的机制 | 调整或放弃信号 |\n|---|---|---|\n| 同一对象被 GPU 反复完整读取 | 本地副本可摊薄一次复制 | R 增大且容量足够时保留显式复制；副本挤出 KV 或准备成本过高时放弃 |\n| 只访问对象很小一部分 | 映射或页选择性迁移保留按需访问
