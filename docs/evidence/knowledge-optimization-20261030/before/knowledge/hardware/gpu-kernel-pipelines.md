# K-HW-011：GPU 矩阵与归约流水：布局、资源和完成依赖

一个 GPU kernel 的设计同时决定数据怎样进入计算单元、哪个线程持有什么片段、临时状态占多少资源，以及何时允许覆盖。tile 更大、流水更深或矩阵指令更多，都只有在这些关系成立时才可能改善性能。本章把逻辑 tile、数学累加状态、物理槽位和完成票据连接起来；性能结论必须绑定具体候选、输入、架构与计时边界。

## 问题、对象与不变量

对 C=A·B，令 A∈ℝ^{M×K}、B∈ℝ^{K×N}、C∈ℝ^{M×N}。输入还包括实际 stride、dtype、输出块 Mₜ×Nₜ、归约块 Kₜ、流水槽数 d、线程数 T、目标指令和编译选项。块尺寸与 d 为正整数，M、N、K 为非负整数。这里的基线只计算乘积，不读取旧 C；M=0 或 N=0 时没有输出工作，K=0 时有效输出为零。有限输入的数学乘积与真实浮点执行分别讨论；溢出、NaN 和特殊值需要另定数值策略，不能由零填充自动修复。

状态分三层。逻辑状态描述有效输出坐标、每个输出覆盖的 k 与输入掩码。数学状态描述累加器：消费前 j 个阶段后，acc 等于这些阶段所覆盖的乘积之和。执行状态描述物理槽 s、代次 g、逻辑阶段 j、复制完成范围、可见性与读者集合。数学上已经定义，不等于生产操作已经完成；复制完成，不等于所有消费者已经读完。

合法实现至少满足：每个有效输出恰有一个写者；每个有效 k 恰贡献一次；尾块不越界读取，补充值满足运算身份；累加器跨阶段保持；消费者只在本代整槽输入完成并建立可见性后读取；槽只在全部最后读者结束后覆盖；旧代通知不得改变新代状态；矩阵指令的形状、dtype、布局、对齐、参与线程与完成条件全部满足。浮点归约次序、输入精度、累加精度和输出舍入须明确，实数等价不保证逐位一致。

## GEMM 的数据依赖与资源账

一个阶段的数据依赖是：全局读取 → 片上数据就绪 → 矩阵乘加 → accumulator 可消费 → epilogue → 输出可见。下一个 K 阶段的读取可以提前，但不能覆盖仍被计算操作读取的片上缓冲。第 j 段更新为 C^{[j]}=C^{[j−1]}+A_jB_j；输出块固定，归约段沿 j 推进。

若输入每元素 s 字节，d 级输入缓冲主项为 d·s·(MₜKₜ+KₜNₜ)，输出累加主项为 a·MₜNₜ，a 为累加元素字节。累加器通常位于寄存器，不能把它不加区分地算入共享存储。对齐、barrier、描述符、转置区、地址与 epilogue 临时量分别计入实际所在资源。实际寄存器须按编译产物及分配粒度核对；逻辑状态字节不能直接代替编译后的寄存器分配。

设 Mₜ=Nₜ=128、Kₜ=64、输入 2 字节、累加 4 字节。每级输入缓冲为 32 KiB，三级为 96 KiB；输出 accumulator 为 64 KiB。128 个线程均摊时，仅累加就平均需要每线程 128 个 32 bit 值，尚未计输入 fragment、地址与循环。两级减少 32 KiB 输入缓冲，能否增加驻留仍取决于其他资源。这是资源算例，没有指定最佳 tile。

令每 CTA 实际共享分配为 S(d)、寄存器分配为 R(d)，目标 SM 的对应容量为 Sₛₘ、Rₛₘ，线程、warp、block 上限为 Tₛₘ、Wₛₘ、Bₛₘ。忽略分配粒度时，驻留 CTA 数至多为 min(⌊Sₛₘ/S(d)⌋,⌊Rₛₘ/R(d)⌋,⌊Tₛₘ/T⌋,⌊Wₛₘ/⌈T/32⌉⌋,Bₛₘ)。某资源需求为零时忽略对应除法项。真实配置还受每 block 上限、分配粒度、同步资源和调度约束；减线程数可能提高每线程寄存器需求，不能只从线程项推断驻留增加。

## 指令布局、线程映射与合法矩阵操作

矩阵指令要求的 fragment 布局不等于用户矩阵的行列布局。全局合并访问、共享 bank、矩阵操作数布局和输出交接应作为一条路径比较。转置或 swizzle 增加地址与搬运，却可能减少非合并请求和 bank 冲突；后续消费者也可能再付转换成本。

固定 [FlashAttention-3 v1](../sources/S-FLASHATTENTION3.md) §2–3 以 Hopper 的 TMA、异步 WGMMA 与 warpgroup 组织流水，warpgroup 由四个连续 warp 组成。论文说明 FP16 WGMMA 的共享操作数可接受 mn-major 与 k-major，而 FP8 WGMMA 只支持 k-major；FP32 accumulator 与 FP8 寄存器操作数的布局又不同。这些是特定指令路径的约束。[ROCm 文档](../sources/S-ROCM.md)描述 MFMA、VGPR/AGPR 与 LDS，wave 宽度随架构变化，不能继承 CUDA 的 32 lane 或固定 bank 数。

下面用普通 warp 矩阵接口给出完整路径：一个 warp 通过 16×16×16 FP16 输入、FP32 累加计算一个输出块。不猜 fragment 内部 lane/寄存器排列；需要明确行列归属时先集体写回共享存储。

```pseudocode
算法 WMMA16
输入：行主序 FP16 A[M,K]、B[K,N]；输出块起点(m0,n0)
输出：该块有效 FP32 C 元素；K=0 时写零
要求：目标支持所选形状与类型；32线程统一参加所有集体操作
共享独立对象：A_s[16,16]、B_s[16,16]为FP16，C_s[16,16]为FP32
三个基址分别按32字节对齐，三个共享leading dimension均为16元素
初始化不透明的16×16 FP32 accumulator acc为零
J←ceil(K/16)
对 j=0…J−1：
    lane λ 对 u=0…7：
        x←λ+32u；r←floor(x/16)；c←x mod16
        A_s[r,c]←有效时A[m0+r,16j+c]，否则零
        B_s[r,c]←有效时B[16j+r,n0+c]，否则零
        无效分支不解引用全局地址
    全warp建立共享写入可见性
    全warp以一致参数、行主序集体装载A_s和B_s到fragment
    集体执行acc←acc+A_frag×B_frag
    确认本段全部共享读取结束，再允许覆盖输入槽
全warp把acc按行主序集体写入C_s，并建立对普通读取的可见性
lane λ 对 u=0…7：
    x←λ+32u；r←floor(x/16)；c←x mod16
    若m0+r<M且n0+c<N：C[m0+r,n0+c]←C_s[r,c]
```

所选路径的矩阵首址按 256 bit，即 32 字节对齐。FP16 leading dimension 为 8 元素的倍数，FP32 为 4 元素的倍数；此处完整行还有至少 16 元素的存储。这里的 leading dimension 是共享矩阵参数，不要求任意原始 K、N 都整除 8：全局尾部先通过受保护的标量搬运进入合法共享布局。改变为向量搬运后，要额外证明源地址对齐和有效范围。

全部 warp 线程须以一致参数参加 load、mma、store；无效输出 lane 仍参加集体操作。fragment 只能在相容的编译契约内使用，不是跨架构稳定 ABI。普通共享写入的发布、矩阵接口的集体参与及最后读取完成各有职责；异步矩阵指令还须采用自己的完成等待，不能机械沿用普通 WMMA 的时序。

一个完整 K 段读取 A 512 字节、B 512 字节，共享写入 1024 字节，fragment 逻辑读取 1024 字节，执行 8192 FLOPs。J 段为 8192J FLOPs；尾部补零的乘加仍可能执行，受掩码保护的全局读取量则下降。输出交接另有 1024 字节共享写、1024 字节普通共享读与完整输出块的 1024 字节全局写。256 个 FP32 累加值平均每 lane 8 个，实际寄存器另含输入片段和地址。

共享容量按对象求和：A_s 为 16×16×2=512 字节，B_s 同为 512 字节，两个输入合计 1024 字节，即 1 KiB；独立 C_s 为 16×16×4=1024 字节，即 1 KiB。三个独立对象合计 2 KiB，尚未计额外对齐与同步对象。若只给输入扩展为 d 个槽、输出暂存仍为一个，共享主项为 1024d+1024 字节，双缓冲为 3 KiB。不能把单缓冲输入计成 2 KiB，也不能把独立输出不加说明地乘流水级数。即便输入与输出的有效访问生命期不重叠，独立静态分配仍占这份容量；要复用同一存储，须另证明全部输入读取结束、输出写入的对齐和覆盖关系。

## 一个完整的非矩阵指令映射：两 warp 共享输入

本例 A、B、C 均为行主序 FP32，累加也是 FP32，函数只为 C=AB。一个 CTA 有 64 线程，输出 tile 为 16×32，归约阶段为 8。输出起点 (m₀,n₀)=(16bₘ,32bₙ)，阶段 j 的 k₀=8j，J=⌈K/8⌉。这是说明映射与生命周期的小例子，没有声称接近矩阵单元吞吐。

线程 τ=32w+λ，w∈{0,1}、λ∈[0,31]。warp w 独占局部列 16w…16w+15。lane λ 保存 8 个累加量，u∈[0,7]，令 i=λ+32u，则局部坐标为 r=⌊i/16⌋=2u+⌊λ/16⌋、c=16w+(i mod16)。64×8=512 个坐标恰好覆盖 16×32，每个输出只有一个写者，不需跨 warp 合并输出。

每槽保存行主序 Aˢ[16,8] 与 Bˢ[8,32]。64 线程协作搬运：Aˢ 的线性下标 a=τ+64v，v=0,1，对应 (⌊a/8⌋,a mod8)；Bˢ 的下标 b=τ+64v，v=0,1,2,3，对应 (⌊b/32⌋,b mod32)。每个共享位置恰有一个写者。紧密行主序下的字节地址为：

- A：pA+4[(m₀+r)K+(8j+k)]，前提 m₀+r<M 且 8j+k<K。
- B：pB+4[(8j+k)N+(n₀+c)]，前提 8j+k<K 且 n₀+c<N。
- C：pC+4[(m₀+r)N+(n₀+c)]，前提 m₀+r<M 且 n₀+c<N。

带 stride 或存储偏移的 view 要改用各自真实地址式；不能把全局行距当作共享行距。非法输入填零且不解引用越界地址；非法输出不写回，线程继续参加同步。K 尾部的同一无效归约项在 A/B 中均为零，有限基线下不改变有效 C。

取 M=19、N=35、K=17，最后输出块起点为 (16,32)。j=1、r=2、k=3、c=2 对应 A[18,11]、B[11,34]、C[18,34]，字节偏移分别为 1268、1676、2656。j=2 只有归约位置 16 有效；该输出块只有 3×3 个有效输出。全局行跨度为 68、140 字节，不具有统一的 16 字节行对齐；4 字节元素复制可行，不代表更宽向量读也合法。

消费者沿 k=0…7 读取 Aˢ[r,k]、Bˢ[k,c]，更新自己的 8 个累加量。两个 warp 共享 A，分别读取 B 的不同半块。固定 u、k 时，同一 warp 的两组 16 lane 各读同一个 A 字，B 的 16 个不同字各被两 lane 读取。按[共享存储规则](../sources/S-CUDA-BEST.md)，同字读取属于广播；不同字落在同 bank 才形成该标量模型下的冲突。协作写入的字号 τ+64v 按 lane 分布到 32 个不同 bank。

这条路径连续给出逻辑 tile、地址、线程归属、共享布局和输出交接。替换成矩阵指令时，仍需重新证明形状、dtype、操作数布局与完成依赖；不能保留这份标量 lane 所有权后直接假定它就是 fragment 映射。[Attention 的 warp 矩阵实例](../frameworks/attention-backends.md)同样通过公开装载与存储接口交接，避免猜测内部排列。

## 从一个槽到多槽：每代数据的完整协议

定义 d≥1 个槽，每阶段身份为 I=(s,g,j)，s=j mod d、g=⌊j/d⌋。状态经历 EMPTY → FILLING → READY → READING → EMPTY。一个槽的 A/B 属于同一个 j，但可由多条复制组成；仅完成 A 或某一线程自己的复制，不足以发布整槽。两个 warp 都读取 A，分别读取 B 的半块，本例保守地一起释放 A/B。

复制完成使字节到达共享存储；适当作用域的同步使消费者能观察这些写入；全部消费者结束最后读取后才允许覆盖。若消费者使用异步矩阵指令，发射线程返回不等于该指令结束读取。代次校验也只保护账务身份，不能使仍在途的旧物理写入变安全；上一代真实访问必须先排空。

```pseudocode
输入：A、B、M/N/K、输出块坐标、d≥1
初始化所有lane的8个acc为0；建立d个EMPTY槽
定义提交(j)：
    I←(j mod d,floor(j/d),j)
    确认物理槽上一代全部复制、写者和读者已结束
    绑定I，状态设为FILLING，清除完成部分与读者状态
    按地址映射搬运合法元素，对其余位置写零
    将全部复制与零填纳入本代完成契约
定义接收完成(I,部分)：
    若I与槽当前身份不一致：忽略通知，不改本代任何字段
    否则记录该部分完成；全部输入完成并建立可见性后发布READY
若J=0：写有效输出零，不创建复制等待，结束
启动：提交0…min(d,J)−1
对j=0…J−1：
    明确s←j mod d，g←floor(j/d)
    等待身份(s,g,j)的整槽就绪与CTA可见性
    登记两个warp读者，进入READING
    每个warp沿k=0…7更新其独占输出
    每个warp在最后共享读取实际结束后发送本代读完通知
    身份匹配的首次通知只结束自己的读取责任
    全部读者结束才释放槽为EMPTY
    若j+d<J：提交j+d，和其他槽的工作重叠
排空全部已提交复制与消费者；每个阶段恰消费一次
每个lane只写回其有效输出
```

J=1 只提交、消费阶段 0；J=2 只消费 0、1；J=0 不等待不存在的最后票据。d>J 时多余槽保持空闲，静态容量仍可能付费。处理前 j 段后的 acc 等于这些段的和，同一输出沿 j、k 递增累加；交换两个 warp 的结束顺序不改变输出归属。

旧票据反例应落在新代真正存活的状态中：槽 0 完成阶段 0 后复用为阶段 2，身份从 (0,0,0) 变为 (0,1,2)。新代仅 A 部分完成时，copied=false、status=FILLING，读者尚未获得读取权。此时投递旧代 B 完成通知，本代身份、完成部分、copied、status、未结束读者和活跃读者必须逐字段保持不变；随后本代 B 的真实通知仍能发布 READY。若删掉身份校验，旧 B 会与新 A 拼成假完整输入，提前发布。观察器应从这个状态变化检出错误，无须实现自行报告错误标签。

只等待第一个读者也不合法：另一 warp 仍可能读旧 A，新代就已开始写入。精细拆开资源时，A 必须等待两个 warp，B 的各半块可分别等待对应 warp，但要为它们建立独立身份与复用条件。增加状态和同步的成本要与减少等待的收益一起比较。

取消应在统一边界停止新提交，排空已经发出的复制与消费者，再放弃输出；不能让部分线程跳过已参与的集体同步。C=AB 不把部分归约结果发布为完整 C。失败而无法证明访问结束时，槽保持隔离，不能因为业务请求取消或返回错误就立即复用。

## 同步契约：复制完成、可见性与最后读者

固定 [CUDA 12.8 指南](../sources/S-CUDA-ASYNC.md) §7.26–7.28 区分 barrier 阶段、异步复制和多级 pipeline。CTA 同步可建立普通共享写入的可见性，却不能替代尚未完成的异步复制等待。一个线程等完自身复制，也不能证明其他生产者完成或消费者读完；等待对象的参与者、作用域和覆盖范围必须一致。

所述 global→shared 硬件异步复制支持 4/8/16 字节粒度及相应地址对齐，API 还可能进行检查或选择其他实现。128 字节对齐是性能建议，不能混同为每次合法 4 字节复制的必要条件。SIMT 尾部可采用受保护的 4 字节复制和普通零填，但两类写入都要进入消费者可见性证明。TMA 的连续 bulk 与多维 tensor copy 具有不同描述符和完成契约；多维路径还涉及 tensor map、stride、box 与 swizzle，不能把普通复制的条件直接套上去。

commit、arrive 等操作须符合约定的参与和收敛关系。warp 实际批次序列与线程感知序列可因分歧而不同，产生额外等待；只数源程序循环或 wait 次数不足以证明真实覆盖。barrier 初始化先于使用，每代预期到达与实际参与者一致；无效输出 lane 继续参加，正是为了保持这份集体契约。

无相应硬件加速时，普通加载、寄存器中转和共享写入也能实现同一数学算法与槽生命周期，但指令、寄存器和暴露等待要重算。异步 API 被接受、生成相应指令、实际形成有益重叠是三个不同结论。

## 能力边界：无 TMA、无簇与不同代际

固定 CUDA 12.8.0 特性表把 TMA、线程块簇与分布式共享存储的所列支持边界列为 CC 9.0，把所述硬件 global→shared 异步复制与 split arrive/wait barrier 的边界列为 CC 8.0。没有硬件加速不等于没有软件同步，生产者/消费者依赖也不要求某一代专有指令。

| 8.9 | 1536 / 48 | 100 KiB | 99 KiB |
| 9.0 | 2048 / 64 | 228 KiB | 227 KiB |

没有 TMA 时，可由线程计算地址，通过普通加载或可用异步复制搬运，增加的索引、发射与中转进入成本。cp.async 的批次/同步契约与 TMA 的事务完成不同；一个逻辑 tile 也不等于一笔物理事务，应区分描述符、指令和实际存储请求。

跨 CTA 拆分归约时，普通独立 CTA 可把部分结果写入设备全局存储，由后续 kernel 或合适原子协议合并，新增部分和交通与完成边界。满足额外 launch/驻留条件的协作执行是另一选择；不能断言无簇时只能采用一种协议。不拆到多个 CTA 可免去部分和，却可能并行度不足。

三级 32 KiB 输入缓冲占 96 KiB，在每 block 99 KiB 上限下只余 3 KiB 给其他共享对象，无法再增加完整一级；在 227 KiB 上容量较松，多分配仍可能降低驻留。减少级数或 Kₜ 是候选；改线程数、输出 tile 或累加放置时，寄存器也必须重算。延迟隐藏可来自更多可运行 warp、指令级独立工作或异步重叠，不能由 CC 标签决定哪种占主导。

固定指南 §16.7–16.8 区分 CC 8.0/8.6/8.7 的第三代与 8.9/9.0 的第四代 Tensor Core 及输入格式；9.0 另有 warpgroup 范围的异步矩阵机制。具体形状、dtype、布局与工具链入口仍按目标指令核实，支持 FP8 不意味着任意矩阵 API 都支持 FP8。改用 warp 级接口或 ROCm 的 MFMA/LDS，要重新安排 accumulator、交接与完成范围。

## 工作、交通、同步与驻留：同一候选的账

两 warp SIMT 候选的完整归约阶段执行 2×16×32×8=8192 FLOPs，读取 A 512 字节、B 1024 字节，共 1536 字节有效输入请求；完整输出块最终写 2048 字节。令 Gₘ=⌈M/16⌉、Gₙ=⌈N/32⌉。各 CTA 独立读自己的输入、尾部不越界时，A 请求为 4MKGₙ、B 为 4KNGₘ、输出为 4MN；输入唯一持久字节为 4(MK+KN)。前者包含 CTA 间重读，后者是唯一对象容量，均不直接等于 HBM 事务。M 或 N 为零时没有 CTA 请求。

若保留填充乘加，执行工作为 2×16×32×8×GₘGₙJ，有效函数工作为 2MKN；小矩阵和尾部不能忽略其差额。每个乘加各读两个共享标量时，完整阶段的消费者逻辑共享读取为 32768 字节，生产者共享写为 1536 字节。广播和实际指令改变物理共享服务；这些逻辑共享字节不能再除 HBM 带宽加入时间。

每输入槽 1536 字节，d 槽为 1536d 字节。64 线程×8 个 FP32 累加量为 2048 字节逻辑寄存器状态；地址、循环、暂存、编译分配与 spill 另计。CTA 内共享交接是片上通信，本候选没有网络通信；跨 CTA 或跨设备拆分才增加对应部分状态交换。对齐、barrier 与 epilogue 对象按同时存活情况另计，不能重复把预留容量与其中对象相加。

完整调用包含参数/描述符准备、可能的编译与布局转换、launch、kernel 首尾和输出交接。准备按真实复用次数摊销，每次发生的转换每次计费。copy 等待已经包含在 kernel 关键路径时，不再作为额外同步重复相加。深流水让独立计算覆盖部分等待，没有消除字节、资源占用或依赖。

## 延迟模型、首尾与选择反转

只用加载时间 L 与计算时间 C 写 max(L,C)，会混淆延迟与吞吐。令 L 为一阶段发出到数据就绪的延迟，I 为相邻复制发出的最小间隔，C 为消费者处理一阶段的时间。理想模型假设复制可流水、阶段按序消费、同一 CTA 串行消费，槽到消费结束才复用，发出成本已含在 I 中。xⱼ 为发出时刻，yⱼ 为消费结束时刻：

```pseudocode
若J=0：返回空时间线，阶段耗时为0
x前←−I；y前←0
对j=0…J−1：
    xⱼ←x前+I
    若j≥d：xⱼ←max(xⱼ,yⱼ₋d)
    yⱼ←max(xⱼ+L,y前)+C
    x前←xⱼ；y前←yⱼ
返回所有y，最后一个y为模型完成时刻
```

这是可以及时发出复制的乐观模型。全 CTA 只在消费结束后提交下一槽的组织不一定实现每个理想发出时刻；需要时可采用专门生产者或不同指令调度，但仍须保持同一完成协议。不能把理想时序称为所写伪代码的真实设备耗时。

长序列平均周期受 I、C、(L+C)/d 三项下界限制；最后一项来自每槽至少占用 L+C 时间。有限 J 还要付首块的 L+C，不能用 J·max(I,C) 抹去首尾。d 足够后继续增加没有必然吞吐收益。

设 L=6、I=2、C=3，时间单位为 τ。J=8 时，d=1 的结束时刻为 9、18、27、36、45、54、63、72；d=2 为 9、12、18、21、27、30、36、39；d=3 为 9、12、15、18、21、24、27、30。四级仍为 30τ。J=1 各方案均为 9τ；J=2 时单级 18τ、两级及以上 12τ，第三槽没有收益。这些均是设定值。

再设假想 SM 扣除固定状态后只剩 6 KiB 输入槽预算，其他限制允许至少两个 CTA，同步对象已另预留。两级每 CTA 3072 字节，可驻留两个；三级 4608 字节，只能驻留一个。假设在各自驻留下，每 CTA 服务时间仍为 39、30τ，且没有额外共享通路争用，4 CTA 的分波估计为两级 2×39=78τ、三级 4×30=120τ。单 CTA 的胜者输掉整网格。6 KiB 不是真实 GPU 规格；若争用存在，L/I/C 应随驻留数重新校准。

预算提高到 9 KiB 后，三级也能容纳两个 CTA，同样假设下 4 CTA 为 60τ，优于两级 78τ。短 J、网格大小、寄存器和复制吞吐都能改变选择。分波模型也是条件化估计，没有包含实际设备调度与不同 CTA 的交错。

## Attention 中的在线归约与矩阵流水

对一行已经处理的非空可见集合 T，定义 m=max_{t∈T}z_t，ℓ=Σ exp(z_t−m)，U=Σ exp(z_t−m)V_t，输出 O=U/ℓ。可见分数与 V 要有限；空状态为 (−∞,0,零向量)，本章空行输出零并保留 empty 标志。不可见项不进入分母。

新块产生分数 S 后，m_new=max(m_old,m_blk)，r=exp(m_old−m_new)，P=exp(S−m_new)，更新 ℓ_new=rℓ_old+rowsum(P)，U_new=rU_old+PV。旧集合为空时 r=0；新块全空时保持旧统计、P=0、r=1，避免负无穷相减。新旧贡献都处于 m_new 尺度，因而逐前缀满足上面的统计量定义，详见 [attention IO](../algorithms/attention-io.md)。

取两块分数 0、2，V 为 1、0。正确输出为 1/(1+exp(2))≈0.119203。若同时把 ℓ 与 U 的旧贡献错误地乘 exp(m_new−m_old)，结果为 exp(2)/(exp(2)+1)≈0.880797。两者均在 [0,1]。错误更新仍使用正权重并归一化，故凸包检查是必要但不充分条件，不能拒绝这种双重反向缩放；应由独立整行参考或逐前缀 m/ℓ/U 不变量拒绝。

另一个故障是只把 U 反向缩放，而 ℓ 仍正确缩放。同一输入得到 exp(2)/(1+exp(−2))≈6.508259，超出 [0,1]，凸包和参考都能拒绝。两类故障必须分开命名和注入，不能以后一类的可检测性解释前一类。

QK、softmax、PV 在同块内存在顺序依赖。消费者内部流水可让当前 PV 与下一块 softmax 重叠，但统计量可能领先 U 一个块，必须明确其尺度与完成顺序：

```pseudocode
输入：固定query tile、J个K/V块及逐行可见集合
若J=0：按空行契约写回，结束
准备第0块QK，等待完成，按空/非空分支得到m0、ℓ0、P0
U←0；当前块←0
对j=0…J−1：
    若j+1<J：等待下一K就绪，向独立分数缓冲发出QK下一块
    等待当前P、V就绪，异步发出U←U+P当前·V当前
    若j+1<J：
        等待下一QK完成，计算下一P、m、ℓ及r
        下一块空则r=1；此前为空而新块非空则r=0
        其余情况r=exp(m当前−m下一)
    等待当前PV完成；此时才可访问U或释放当前P/V
    若j+1<J：U←r·U；交接下一P、m、ℓ
最后一次PV完成后，以最终ℓ归一化；空行写零与empty标志
```

第 j 次 PV 完成后，U 应处于 m_j 尺度；重标度后才进入 m_{j+1} 尺度。J=1 只有启动与收尾，J=2、3 时每块 QK/PV 各一次，不引用未生成的最后概率。当前 P/V 与下一 K/分数必须同时存活；Q tile 要到全部 QK 结束才可覆盖。成对 K/V 槽等两种最后读者的并集，独立缓冲才可分别释放。固定 FA3 v1 的打印缩放式和短循环边界须以这些不变量核对。

额外 Bq×Bk FP32 分数片段占 4BqBk 字节逻辑状态。例如 64×64 为 16 KiB，128 线程均摊平均额外 32 个 32 bit 值。更多缓冲、消费者和概率片段共同竞争寄存器与共享存储。FA3 的三级实验未获得普遍优势，不能由理论可重叠工作直接推出收益。

QK accumulator 到 PV 操作数之间还可能需要排列、缩放与类型转换。FP8 的 V 布局、概率转换、块尺度和异常值处理都进入成本与数值契约；若对 P 的列做排列 Π，V 必须做对应行排列，使 (PΠ)(ΠᵀV)=PV。增大 Bq 提高 K/V 复用，增大 Bk 改变加载与归约粒度；小 query、长历史 decode 又可能需要 KV 分区增加并行度并支付统计合并成本。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的关系 | 重算与反转条件 |
|---|---|---|
| J 很小、K 很短 | 归约完整覆盖、输出唯一写者 | 首尾与启动可能主导，深流水的多余槽没有收益 |
| d 增大 | 每代发布、最后读者与复用协议 | 重算共享容量、寄存器、驻留和整网格时间 |
| tile 增大 | 地址覆盖、输入重用与累加不变量 | 重读减少，但状态、尾部工作增加，任务数可能不足 |
| dtype 改为 FP8 | 函数和输出语义 | 重验布局、尺度、累加、异常值与质量；无合法高效路径则改选 |
| CUDA 转到 ROCm | 生产后消费、读完后覆盖 | 重做 wave、MFMA、LDS、寄存器和同步作用域映射 |
| 无 TMA、无簇 | 完成与可见性依赖 | 普通加载或可用异步复制增加指令；跨 CTA 合并另计交通 |
| M/N 很小 | 掩码和写者归属 | 比较小 tile、GEMV、合批或 split-K，不能继承大 prefill 结论 |
| 工作集越过 L2 | 逻辑请求数 | 实际 HBM 事务与重读改变，旧命中假设失效 |
| 取消或失败 | 已提交访问仍受保护 | 停新提交、排空或隔离，不能立即复用物理槽 |

## 诊断：竞争解释与区分实验

在两候选输出满足相同误差要求后，固定输入、tile、线程映射、预热和计时边界，仅改变缓冲级数。若目标设备上三级更慢，应区分以下解释；这些是实验推理，没有构成设备测量。

| 解释 | 可区分预测 | 干预与观测 | 反证后的修正 |
|---|---|---|---|
| 首尾比重增加 | 短 J 差距大，长 J 固定成本摊薄 | 固定实现扫 J，分辨固定项与稳态斜率 | 三级长 J 斜率更坏时，首尾不足以解释 |
| spill | 新增 local 交通随阶段持续支付 | 查生成程序与资源，缩短非关键临时量生命期并验证相同计算 | 无 spill 或消除后仍慢，降低该解释权重 |
| 驻留下降 | 单 CTA 可能更快，整网格反而更慢 | 分开测单 CTA 与多 CTA，核对实际资源和活跃 CTA | 驻留未变且无对应资源限制时，缺少支持 |
| 未形成预期重叠 | 异步表达增加，实际等待空洞未减 | 查指令、完成依赖与时间线，保持工作量可比 | 等待确已下降却更慢，调查新增交通与资源 |
| 准备或转换增加 | kernel 改善但完整调用未改善 | 分别量准备、转换、kernel、输出可消费时刻及真实复用 | 差异全在 kernel 内时，准备不能解释 |

设 T₂=10+2J、T₃=18+1.7J，单位为 τ。J=8 时为 26、31.6；J=64 时为 138、126.8，交点约 26.67。这与短输入受固定成本影响一致。若新增长输入符合 T₃′=18+2.4J，J=64 为 171.6，则更大的固定项已不足以解释，必须调查稳态瓶颈。这些是合成值。

若三级跨过共享驻留台阶且 local 交通没有增加，应降低 spill 假设权重，优先检验驻留。但因素可并存，消除一个后仍需复测。限制寄存器可能诱发 spill，不是隔离驻留的干净干预；改变 tile 也改变复用、任务数和算术强度。计数器 replay 的环境与普通执行须分别解释，差异落在重复测量的不确定区间内时保留未知。

正确性实验与性能归因分开：独立稠密参考覆盖 K=0/1/7/8/9/17、非整除 M/N 与空工作；延迟复制、交换读者顺序、投递旧代通知，并逐字段观察状态。分别注入漏末阶段、只等一个读者、旧票据发布新代和错误共享行距，确认同一观察器能拒绝对应故障，再讨论速度。参数化 WMMA 契约让合法和非法 leading dimension 进入同一判定路径，不能用常数取模冒充接口检查。

## 正确性检查、负对照与证据边界

配套 `tools/check_k_hw_011_full.py` 是 Python 标准库、确定性、只读离线的 CPU 模型。SIMT 路径执行协作装载、lane 累加和写回，以直接遍历原始矩阵的稠密乘法为参考，并核对请求与乘加计数。共享 bank 检查按不同字号集合区分广播与冲突；本例 A 行距 8 改成 9 会出现冲突，不能据此推论任意 padding 都更坏。

槽检查把执行器与观察器分开，覆盖输入分部分完成、重复通知、1/2/3 槽、新代 FILLING 时的旧复制票据、新代读者活动时的旧读完通知与两种读者结束顺序。观察器核对身份、完成部分、copied、status、未结束与活跃读者；随后用本代通知验证可继续推进。删除身份防护、提前发布或只等一个读者的变体必须由同一观察器拒绝，不依赖变体自报标签。

WMMA 检查通过同一个参数化入口检查形状、类型、对齐、leading dimension 与集体参与，并以对象字节枚举核对输入单/多缓冲与独立输出暂存。它只检查本章候选的参数契约，不执行矩阵接口或模拟 fragment。

时序检查以整数时间推进的事件模拟核对 L/I/C 递推，覆盖发出间隔、复制就绪、串行消费与槽释放；忽略复用条件的变体应在有限阶段上被拒绝。Attention 检查以 Decimal 整行及逐前缀统计为独立参考，覆盖空块、全 mask、首尾和极端有限分数；反向双缩放由参考拒绝，同时确认其凸包漏检。只错误缩放 U 是另外的负对照，不能混用证据。

检查覆盖说明不代替绑定当前脚本与输入的真实执行记录。上述模型不证明 CUDA/HIP 编译产物、barrier 可见性、真实竞态、TMA 事务、fragment 内部排列、FP16/FP32/FP8 完整舍入、spill、驻留、缓存、硬件重叠或性能，也没有模型质量或 Agent 使用效果证据。服务并发、真实取消恢复与设备失败路径仍需实现级验证。

缩短这些边界时，应固定目标架构、shape、dtype、stride、mask、编译选项和计时边界，核对生成指令、资源报告、实际事务、时间线与完整调用结果；CPU 标量结果不能写成 GPU 实测。
