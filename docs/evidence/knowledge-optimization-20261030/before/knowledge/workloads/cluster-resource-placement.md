# K-WORK-011：集群放置：资源向量、拓扑、执行组与故障域

单实例的计算与容量方案确定后，还要找到能够同时满足它的设备集合。集群总空闲资源足够只是必要条件；逐设备内存、节点聚合配额、CPU/NUMA、网络、存储局部性，以及故障后仍完整的服务容量，共同决定部署是否可行。放置输出应包含逐 rank 的实际资源映射、不可变执行身份、资源责任和未满足条件，而不只是节点名列表。

## 资源向量与可行集合

设执行组 G 有 P>0 个必要 rank。rank i 的需求为

r_i=(type_i,m_i,c_i,h_i,s_i,b_i)，

分别表示设备能力、设备内存字节、CPU 时间份额、主存字节、临时存储字节和声明窗口内的网络需求。CPU 时间份额的单位可用 CPU 秒/秒；它与绑核集合是不同约束。m_i 必须包含该执行配置下的权重分片、复制张量、KV 增长承诺、workspace 和其他同时存活对象，不能由组内总显存除以 P 得到。准备阶段的峰值还须另外核对。

把物理设备或明确可独占的设备分区记为槽 s。每个槽保留物理身份、所在节点、类型、实际可用内存和分配代次。节点 j 另有聚合供给向量 a_j，例如 CPU、主存、临时盘和 NIC 预算。相同型号但不同 NUMA、链路和 quota 的设备，不具有相同执行成本。

放置 π 将每个 rank 映射到一个槽，同时给出进程、主机 CPU/NUMA 和 NIC 的相容映射。本章的保守候选族每槽最多放一个 rank；共享设备需要另行提供容量和隔离机制，不能把访问份额当成新的物理卡。合法条件至少包括：

- rank 完整且槽互斥：每个必要 rank 恰好分配一次，不重复占用同一槽。
- 类型与执行能力相容：实际设备、驱动和执行路径支持该制品与布局；安装相同容器不是证明。
- 逐设备容量：每个 rank 的需求不超过所分槽的实际预算；总 GPU 内存不能替代此条件。
- 节点聚合：对资源维 q，Σ_{i:node(π(i))=j} r_{i,q}≤a_{j,q}。已有分配、预留和不可提前回收的责任已经从 a_j 扣除。
- 连接与路径：通信成员、方向可达性、权限、必要链路和声明的带宽/延迟条件成立。peer access 可用不表示等带宽，也不表示共享出口没有争用。
- 配额与身份：租户许可、模型制品、执行配置和分配代次相容；候选快照不能绕过提交时重检。

这些是硬条件。紧凑装箱、制品局部性、减少迁移和副本分散可以是软偏好；若服务契约明确承诺某种故障隔离，相关分散条件就成为硬约束。

设四节点各有 4 张同型卡，每节点当前各剩 2 张，总空闲为 8 张。A 的已验证配置要求同节点 4 卡，因此仍不可放置；单卡副本 B 则可以使用这些空位。类似地，2 张空闲 GPU 所在节点若只剩 0.5 CPU 秒/秒，而一个 rank 需要 2，则卡数并不构成可兑现供给。

[Borg](../sources/S-BORG.md) 将配额准入、资源可行性与位置评分分开，讨论装箱、碎片、包局部性和相关故障。本章将这些机制用于 GPU 执行组，但整组准入协议和逐槽模型是本库推导，不是 Borg 原有 GPU 事务或性能结论。

## 权威资源账与整组准入

这里选择一个足够保守的协调模型：只有一个活动控制器修改权威资源账；所有准入、取消、代次变更、资源释放和影响合法性的状态更新都经过同一串行临界区。临界区内没有节点 RPC、模型加载或设备执行；控制器在一次操作中不崩溃。节点遵守权威分配票据，外部程序不能绕过该资源账取得相同独占槽。

这是一种实现选择，其作用是给查重、资源扣账与唯一决定提供共同排序点。它不提供控制器崩溃后的持久恢复，也不能使延迟的节点健康报告变成物理现状。真实节点分配或准备失败仍要关闭就绪资格并走排空路线。

请求键 k=(G,e)，其中 G 是稳定组身份，e 是不复用的准入尝试代次。完整请求载荷摘要 h 绑定租户、制品版本 v、执行配置、rank 需求和硬约束；候选顺序不属于逻辑请求身份。同键不同载荷必须拒绝，不能用新需求覆盖原决定。同一逻辑组尚有旧代资源时，本算法不接受新代分配；滚动并存应使用明确不同的实例身份并共同计量容量。

资源账记录槽所有者和节点聚合扣账。一次候选尝试取得唯一所有权标识 t，临时改动逐项登记到本次日志 J。撤销只逆转 J 中仍由 t 拥有的条目，不能用旧快照覆盖整个资源账。

| 状态 | 资源与公开含义 | 允许的后继 |
|---|---|---|
| PENDING | 已登记请求，尚无完整组预留；候选尝试中的部分临时条目只在临界区内存在 | RESERVED 或 REJECTED |
| RESERVED | 全部 rank 的槽和聚合资源均已由本次 t 临时取得，尚无启动授权 | COMMITTED；失败则撤销至 PENDING |
| COMMITTED | 资源账与唯一准入决定共同提交，允许按票据准备 | RUNNING 或准备失败后的清理 |
| RUNNING | 必要 rank 完整、共同验证成功；能否接新请求另受路由与实时容量约束 | DRAINING 或 FAILED |
| DRAINING / FAILED | 禁止新准入，保留已有请求、在途访问和地址绑定责任 | 责任结清后 RETIRED |
| RETIRED | 资源已归还一次；历史决定继续保留以识别重试 | 不由旧通知重新激活 |
| REJECTED | 本次尝试没有取得正式分配，保存拒绝原因与搜索状态 | 新尝试使用新 e |

准入决定表与运行状态分开：历史 COMMITTED 决定不会因退役而消失。迟到重试返回原票据及当前生命周期状态，不重新扣账，也不重新启动已退役实例。只有形成新 COMMITTED 决定的调用负责本次首次准备派发；查询或重试原决定不取得这项责任。

```pseudocode
算法 GANG_ADMIT
输入：请求 k=(G,e)、完整载荷 h，权威状态 S，候选上限 K，展开预算 B
输出：同 k 的唯一 COMMITTED 或 REJECTED 决定、当前运行状态；
      首次提交还报告准备派发是否成功发起

1. 验证 P>0、数值非负且单位明确、身份与约束完整。
   初始化 result←空，prepare_commands←空。
2. 在权威临界区：
     若 k 已登记而载荷不同，返回身份冲突。
     若 k 已有终局决定，返回原决定及当前状态，不派发准备。
     核对当前意图及 e；确认没有禁止并存的旧代资源。
     首次请求登记 (k,h,PENDING)；取得只读快照 S0。
   离开临界区。
3. 在 S0 上运行 GENERATE_PLACEMENTS，得到已排序 C、停止状态和检查统计。
4. 再进入同一权威临界区，并保持到本次决定完成：
     重新核对 k、h；若另一调用已决定，返回其原决定及当前状态，不派发准备。
     重新核对当前意图、代次、授权和禁止并存的旧代资源。
     若已取消或失效，写唯一 REJECTED 决定，令 result 为该决定。
     否则按顺序遍历 C：
         对 π 重新检查完整 rank 覆盖、槽互斥、类型、容量、
         节点聚合、拓扑、配额及当前资源所有权。
         失败则累计具体原因，继续；快照上合法不授权跳过重检。
         创建本次唯一 t；J←空。
         逐 rank 在权威账取得槽和节点份额，每项注明 t 并加入 J。
         任一步失败：只撤销 J 中本次拥有的条目；保持 PENDING，继续。
         全部取得后，状态进入 RESERVED。
         核对 J 完整覆盖 π、所有者仍为 t，且账本无超额和重复槽。
         若失败：撤销 J，RESERVED→PENDING，记录原因并继续。
         在同一不可交错更新中：将这些条目标为正式分配，
         写入唯一决定 (k,h,π,t,COMMITTED)，更新运行状态。
         result←该决定。
         对每个必要 rank i，建立不可变准备命令 (k,v,π,t,i,π(i))。
         将这些命令保存到本调用的 prepare_commands。
         退出候选循环，不从 GANG_ADMIT 返回。
     若 result 仍为空：
         确认本次临时条目为空；写唯一 REJECTED 决定，
         附搜索停止状态和当前重检原因；result←该决定。
   离开权威临界区。
5. 若 prepare_commands 非空：
     在临界区外逐项向对应节点派发准备命令，记录每项发起结果。
     派发失败不撤销历史 COMMITTED 决定，也不直接归还正式分配；
     在权威临界区登记准备失败，关闭就绪资格，保留已有访问的清理责任。
6. 返回 result、读取到的当前运行状态及本调用的派发观察。
```

成功分支的局部命令列表将提交后的推进责任交给同一次调用的第 5 步。它是无崩溃前提下的局部后继工作，不是持久消息队列或崩溃恢复协议。节点发送可能阻塞或失败，因此放在临界区外；返回 COMMITTED 也不表示节点已经收到、开始或完成准备。节点只按仍有效的分配票据准备；取消、失效或退役不得因迟到命令重新激活。真实异步传输、撤销传播和节点票据检查需要单独验证。

RESERVED 在这套算法中是短暂的账本状态，不允许跨出临界区等待远端响应。因此两个同键调用即使各自在旧快照上找到不同位置，也只有第一个进入最终临界区的调用能形成决定并取得首次派发责任；后一个先查到该决定，返回同一票据。不同组竞争同槽时，后进入者会看到前者的扣账并拒绝。所有重试在同一排序模型内成立，不依赖客户端是否收到第一次响应。

例如 n0 有槽 a、b 和 4 个 CPU 份额，G 的两 rank 各需 2 份额。调用甲为 a、b 扣账后形成 RESERVED，再提交一次；同键调用乙即使带另一候选也只返回甲的决定。若甲在取得 a 后失败，则仅归还自己的 a 和 2 份额，不形成 RESERVED，不留下半组。若 H 已拥有其他资源，甲的撤销不能删除 H 的账。

提交后的事件还须满足以下顺序，账本正确不能代替这项核对：

| 调用或事件 | 权威状态变化 | 临界区外的准备效果 |
|---|---|---|
| 首次成功准入 G | 扣账一次，保存唯一 COMMITTED 决定 | 离开临界区后为每个必要 rank 派发一条准备命令，再返回 |
| G 的同键重试 | 返回同一票据，不再扣账 | 不产生新的准备命令 |
| H 因竞争而拒绝 | 保存 REJECTED，无 H 的正式资源责任 | 不产生准备命令 |
| G 的最后使用责任结束并退役 | 归还资源一次，保留历史决定 | 旧命令不再有启动资格 |
| G 退役后的同键重试 | 返回历史决定和 RETIRED 状态 | 不重新扣账或启动 |

若成功分支在写入决定后立即返回，前三类资源账检查仍可能全部正常，但首次准入缺少准备事件，组会停留在 COMMITTED。事件审计应直接拒绝这种轨迹。

COMMITTED 不等于可服务。节点须核对票据、实际设备、制品分片和执行组；必要 rank 全部准备完成且验证相容后才进入 RUNNING，并由显式路由准入公开容量。准备失败、取消或超时不能直接释放已提交 DMA、kernel 或通信仍在使用的资源；最后使用责任结束后才能回收，见[弹性服务](elastic-serving.md)。

单控制器重启、主从切换、网络分区后旧 worker 的隔离，以及持久决定与资源账的恢复不在上述证明内。若需要这些能力，必须增加可靠提交记录、代次隔离和恢复核对，不能把进程内锁称为通用分布式事务。

## 候选生成、搜索预算与评分

候选输出上限 K 与搜索工作上限 B 是两个量。无解时一个候选也不产生，但失败分支仍可能很多。本算法把一次尝试扩展“当前部分映射＋一个 rank 到一个实际槽”计为一次展开，成功和失败尝试都消耗预算。节点/槽按稳定次序遍历；可用类型索引减少扫描，但不能改变硬条件。

```pseudocode
算法 GENERATE_PLACEMENTS
输入：G、只读资源与拓扑快照 S0，K≥1，整数展开预算 B≥0
输出：候选 C，停止状态 stop，实际展开数 E、完整检查数 Q、拒绝原因计数

展开实际槽及其物理属性；固定 rank 顺序和槽遍历顺序。
初始化 C←空，E←0，Q←0，π←空，已用槽←空，逐节点累计需求←0。
stop←COMPLETE。

过程 SEARCH(i)：
    若 i=P：
        Q←Q+1；检查完整组连接、路径共享预算及其他完整硬约束。
        若合法，复制当前完整 π 保存到 C。
        若 |C|=K，设置 stop←CANDIDATE_LIMIT 并停止后续搜索。
        返回。
    对有限槽列表中的每个槽 s：
        若已经停止，返回。
        若 E=B，设置 stop←BUDGET_EXHAUSTED 并返回。
        E←E+1。
        检查 s 未使用、类型与单槽内存相容、节点累计需求可容纳，
        以及已绑定 rank 之间必需的连接条件。
        只用能够证明当前部分映射无法合法扩展的条件剪枝。
        若失败，累计原因并继续。
        保存本层变更；将 i→s 加入 π、标记槽并增加节点需求。
        SEARCH(i+1)。
        无论普通返回还是预算停止，都撤销本层变更。

SEARCH(0)。
为保存的候选计算声明的评分；按评分和稳定并列规则排序。
返回 C、stop、E、Q 和原因摘要。
```

同节点约束可在首次绑定后限定其余 rank 的节点。全连接或共享出口限制则可能需要完整映射才能检查；不能根据一个尚未确定的路径过早剪去合法分支。回溯撤销必须恢复槽占用、节点需求和路径累计量，不能只删除 π 的最后一项。

三种停止状态分别解释为：COMPLETE 表示声明候选树已遍历完；只有此时 C 为空才能判定这个候选族在该快照下无解。CANDIDATE_LIMIT 表示已取得 K 个合法候选，尚未证明遍历完整。BUDGET_EXHAUSTED 表示展开预算用尽；空结果只能称为“预算内未找到”。预算耗尽但已有合法候选时仍可尝试提交它们。提交时全部失效表示这些候选当前不能提交，也不证明整个集群无解。

放宽软偏好、改 rank 顺序或换候选族可以另开一次有预算的搜索；不能隐藏一个无限重试循环。若同时枚举多种执行配置，应声明 B 是总预算还是每配置预算，否则总等待仍可随配置数增长。B 约束展开次数；单次拓扑检查仍须是有限算法，操作数预算本身不是墙钟期限保证。

评分只比较已合法候选。可以采用字典序目标，或把通信时间、碎片、准备与迁移代价分别除以明确的参考尺度后加权，取总惩罚较小者。不同单位的原始量不能直接相加。碎片也不等同“剩余连续编号卡数”：卡编号相邻不保证拓扑相邻。应针对待调度的合法资源形状估计搁浅供给，或明确使用的近似。

保存首 K 个合法候选再评分，只寻找这个集合内的最好结果。它既不保证全局最优，也不保证大型执行组不饥饿；公平和等待控制需要跨请求的队列、老化或预留策略。

## 从 rank 映射到共享路径

下面是解释放置账的设定模型，不是设备规格或测量。两节点 A、B 各有两个可用槽，每槽 16 GiB；两个节点各有 4 个 CPU 份额。四 rank 各需 12 GiB 和 2 个 CPU 份额：

| rank | 物理槽 | 主机亲和与网络接口 | 机架 |
|---|---|---|---|
| 0 | A:a0 | A 的 NUMA0、NIC_A | rackA |
| 1 | A:a1 | A 的 NUMA0、NIC_A | rackA |
| 2 | B:b0 | B 的 NUMA0、NIC_B | rackB |
| 3 | B:b1 | B 的 NUMA0、NIC_B | rackB |

每设备需求均低于 16 GiB；每节点 CPU 合计为 4，恰好达到预算。模型输入还规定这些 CPU/NIC 亲和可实现、所需 peer 权限有效，并给出方向路径。仅有这张表仍不足以证明链路成本。

设执行使用 0→1→2→3→0 的 ring：0→1 和 2→3 走各自节点的本地互联；1→2 走 a1→A 的 PCIe 根路径→NIC_A→网络 A→B→NIC_B→B 的 PCIe 根路径→b0；3→0 走 b1 到 a0 的对应反向路径。本地与 PCIe 方向能力设为 40 GiB/s；网络两方向共用一个 10 GiB/s 的半双工服务资源，其余资源不成为瓶颈。路径服务在各真实资源上分别计费，PCIe 字节不再重复计入同一个网络服务资源。

每 rank 的 AllReduce 输入设为 16 MiB，均分四块。在这一指定 ring 模型中，reduce-scatter 与 all-gather 各三轮，每轮四条消息、每条 4 MiB；两条跨节点消息使共享网络每轮服务 8 MiB。网络服务下界为

8 MiB / (10 GiB/s)=781.25 微秒/轮。

六轮合计 4.6875 ms。若每轮另有明确串行的 5 微秒启动项，模型时间为 4.7175 ms。全组端点发送为 6×4×4=96 MiB，其中跨节点发送为 48 MiB。若两网络方向实际上独立全双工，每方向每轮只有 4 MiB，对应模型时间变为 2.37375 ms；不能用全双工时间兑现半双工预算。

上述只展开所选通信候选。实际 collective 算法、有效带宽、归约、暂存、消费者可见性与其他流争用都可能改变完成时间，详见[通信拓扑](../hardware/topology-parallelism.md)。放置时要把这种路径账接到候选上，不能把“通信组能建立”作为成本相同的理由。

## 碎片、执行组依赖与故障余量

紧凑放置可为大型实例保留完整空间，也可能集中 CPU、NIC 和 SSD 争用。分散放置减少局部干扰和相关失败，却可能增加通信距离、冷加载和小碎片。前述四节点各剩两卡时，可以保留即将释放的完整节点给 A，让 B 使用其他位置；代价是等待期暂留部分空卡。也可以把 A 改为两节点各两卡，但那是新的执行配置，必须重新核对逐 rank 容量、通信、组准备、故障条件和 SLO。迁移已有任务还要支付传输、排空及在线干扰成本。

故障域不能简化为执行组的一个代表机架。令 R_g 是固定执行配置 g 的必要资源集合，包含所有必要 rank 的设备/主机，以及运行中必须存活的链路、网络出口、存储服务等依赖。若权重加载完成后不再依赖原存储出口，该出口只属于准备期依赖，不能无条件写成运行期单点。

对必要资源 x，令 A_x 是能使它不可用的故障域标签集合，例如设备、节点、机架、供电和共享出口。标签采用完整身份；机架与供电可以交叉覆盖，并不一定构成一棵树。把资源所在节点及其相关祖先域、共享依赖域显式展开，得到

D_g=∪_{x∈R_g} A_x。

F 是失效域集合；单域故障写作 F={d}。对没有冗余、故障后不重配置的固定组，若所有必要依赖均已纳入，则

alive_g(F)=1[D_g∩F=∅]。

失去一个必要 rank 或唯一通信出口，整个组就不再计为完整可服务组。不能对集合 D_g 使用“D_g 不属于 F”来代替交集检查。若存在冗余链路、备用分片或允许成员重构，应使用一般存活谓词：故障后仍有完整且相容的必要 rank、可行路径、状态与有效就绪资格。替代路径可能是“至少一条可用”，不再等于所有依赖都必须存活；重新组成的新组也必须经过准备和准入，不能直接把幸存 rank 数折算成原组容量。

只有在存活组仍能兑现同一负载口径下的 μ_g，且这些服务率满足共同资源预算时，才可计算

μ_avail(F)=Σ_g alive_g(F) μ_g。

若故障导致绕行、剩余出口拥塞或负载组成变化，应重算条件化 μ_g(F) 及其共同资源约束。各副本独占测试所得的峰值不能直接相加。μ_avail(F)≥λ 只是平均容量的必要核对；等号没有排队余量，尾延迟和突发仍需分析与测量。

三个独立机架的完整副本组各提供设定的 40 请求/s，到达为 70 请求/s。失去任一机架后为 80；两个副本同机架时，失去该机架只剩 40。进一步设一个跨 rackA、rackB 的两 rank 组 X 提供 40，另有 rackC 中的完整组 Y 提供 40。X 的运行还必须使用共享出口 storageX，则 D_X 包含 rackA、rackB、storageX。失去其中任一域，X 整组不计容量，只剩 Y 的 40；把 X 代表域记成 rackB 会错误地在 rackA 失效后继续计出 80。前节四 rank 组同样依赖两个机架，任一必要机架失效都不能保留原组服务率。

超售也须区分资源。CPU 时间可能通过节流归还；正在使用的 GPU 权重与 KV 不会因降低调度权重立即消失。借用显存需要结束、换出、迁移或重算等实际释放路线，不能把不可回收的活跃状态承诺给下一个组。

## 搜索、准备与驻留的条件化成本

设有 M 个节点、S 个实际候选槽、P 个 rank、d 个聚合资源维；搜索实际尝试 E 次扩展，完整检查 Q 个叶子，保存 n≤K 个候选。E≤B，P>0 时 Q≤E。令 c_inc(a) 是第 a 次增量拓扑/约束检查成本，c_full(q) 是第 q 个完整组检查成本，c_score 是每个保存候选的评分成本。忽略固定宽度键的常数比较，控制面搜索成本为

T_search=O(T_pre+Σ_{a=1..E}(d+c_inc(a))+Σ_{q=1..Q}c_full(q)+n(P+c_score)+n log n)。

T_pre 包含读取快照、展开/分桶槽和准备索引；nP 包含复制候选映射，n log n 是排序。评分若重新扫描全部节点、模拟负载或估计迁移，相关工作必须进入 c_score，不能藏成常数。

未限制工作时，逐 rank 尝试 S 个槽的搜索树最坏随 S^P 增长；K 只限制保存的成功叶子，不能限制失败分支。预算限制的是 E，因此无解也能在明确工作量后返回未知状态。

若通信约束涉及 E_t 个 rank 对或消息，路径最长 L 段，则读取既定路径并累计共享资源通常需要 O(E_t L) 操作；全 rank 对检查可有 E_t=Θ(P²)。需要现算路径时还要增加相应图搜索成本。只有合法路径与相关指标已经预计算、每 rank 只查常数个摘要、评分不重新做成对检查且维数固定时，评分才可简化为 O(nP)；预计算的时间、缓存空间和失效维护仍另计。真实提交时的硬条件重检不能因评分缓存命中而省略。

保存候选需要 O(nP) 空间，回溯路径与日志为 O(Pd) 量级，节点资源账为 O(Md)，槽索引为 O(S)，拓扑状态和预计算另计。准备命令可共同引用一份不可变 π，每 rank 只增加固定字段，命令描述主项为 O(P)；若每条消息都序列化完整 π，P 条命令的映射字段总量可达 O(P²)。失败原因可用分类计数与首个样例，避免为每个失败分支保存整份映射。若保留全部分支日志，还会增加 O(E) 或更高的证据驻留。

最终准入临界区与快照上的搜索分开列账。令 A 是本次实际进入重检的候选前缀，m=|A|≤n；首次成功即退出循环，后续候选不再重检、取得或回滚。对每个 i∈A，C_recheck(i) 包含实际执行的完整合法性重检，以及到达 RESERVED 时的最终完整性核对；C_acquire(i) 包含逐 rank 的取得检查、账项更新与日志登记；C_rollback(i) 是失败后撤销本次日志的工作，成功候选及未产生临时条目的候选在此项为零。用同一控制面操作量单位表示，有

C_critical=C_gate+Σ_{i∈A}[C_recheck(i)+C_acquire(i)+C_rollback(i)]+C_decision。

C_gate 是进入后的身份、意图和历史决定检查；C_decision 是最终接受或拒绝的记录工作，首次成功时还包括正式提交与准备命令构造。命令构造若共享 π 或在此处复制完整 π，按前述实现分别计量；临界区外派发阶段的序列化另计。上述操作量不是毫秒；实际持锁时间还受各操作的实现、访存和调度影响。

至多 P 个 rank 的取得与撤销是**每次候选尝试**的界。一次失败可以在取得全部 P 个 rank 后才发生；其回滚结清后还可继续下一候选。若每 rank 的槽所有权、日志及 d 个聚合资源账项均以常数时间更新，则单次取得和回滚主项分别至多 O(P(1+d))，全部尝试的取得/回滚主项至多 O(mP(1+d))，从而最坏为 O(nP(1+d))；d 固定时才可简写为 O(nP)。完整拓扑、属性及合法性重检仍按 Σ_i C_recheck(i) 单列，不能据此把整个临界区无条件写成 O(nP)。

以下四条轨迹均以身份/意图检查有效且尚无可复用历史决定的新准入调用为前提。以下手算只计实际取得和撤销的 rank 责任，不把重检次数或最终驻留量混入这一累计账；P=2，候选按 C1、C2 顺序处理：

| 候选轨迹 | 实际重检候选数 | 取得的 rank 责任次数 | 撤销的 rank 责任次数 | 收尾 |
|---|---:|---:|---:|---|
| C1 取得两 rank 后在 RESERVED 核对失败；结清回滚；C2 同样失败 | 2 | 2+2=4 | 2+2=4 | 无临时条目，写 REJECTED |
| C1 取得两 rank 并提交成功 | 1 | 2 | 0 | 立即停止候选循环，C2 不进入重检；随后在临界区外派发 |
| C1 只取得第一 rank 就失败并撤销；C2 取得两 rank 后成功 | 2 | 1+2=3 | 1 | 只保留 C2 的正式责任，随后派发 |
| 候选为空 n=0 | 0 | 0 | 0 | 仍需身份/状态检查和拒绝决定，不能称为零成本调用 |

第一条轨迹反驳“整个临界区最多取得或撤销 P 个 rank”的旧界：取得和撤销各为 4，均超过 P=2，总更新责任次数为 8。由于每次失败都先撤销再继续，累计取得四次并不表示同时驻留四份 rank 资源。临时日志峰值仍受单次尝试限制，而持锁工作按所有尝试累计；同一串行权威区内的其他准入可能因此等待更久。节点派发与设备准备仍在临界区外，不计入这里的持锁操作量。

这些手算沿正文的多候选循环核对累计界。随章 Python 准入模型每次调用接收单个计划；其既有通过记录不能作为上述多候选累计成本已经执行验证的证据。

| 成本 | 对应账与条件 |
|---|---|
| 计算 | 搜索、完整合法性、评分、排序；最终临界区按实际候选前缀累计完整重检、各次取得与回滚，再计最终决定/提交。每次候选至多涉及 P 个 rank，全部尝试的取得/回滚主项最坏为 O(nP(1+d))，完整重检成本另计 |
| 访存 | 节点向量、逐槽属性、所有权、请求决定表、拓扑和制品位置；增量索引减少全扫，但引入更新与缓存失效 |
| 通信 | 心跳、首次提交后的准备指令、节点状态回报和执行组通信；本算法临时预留是权威内存账操作，不表示节点 RPC 已完成 |
| 准备 | 读取和校验制品、布局转换、H2D、通信组建立、编译/图和共同预热；冷缓存与共享出口按实际路径计量 |
| 同步 | 权威临界区等待、临界区外派发和组准备屏障；准备时间取决于依赖与慢 rank，不能把各 rank 平均时间当作组就绪时间 |
| 驻留 | 候选、日志、命令描述、决定记录，以及 RESERVED/COMMITTED 的已占资源；新旧版本、加载目的区和在途缓冲的峰值按唯一物理 backing 并集计量 |

逐项派发只说明调用顺序；若第 i 个节点在时刻 a_i 收到有效指令，本地准备耗时 D_i，随后共同验证耗时 T_g，且没有额外争用或前驱，则绝对就绪时刻为 max_i(a_i+D_i)+T_g。只有派发差异可忽略、以共同起点计时，才能简写为 max_i D_i+T_g。共享磁盘、NIC、PCIe 或 CPU 会增加资源次序，不能同时给各 rank 一份独占带宽。COMMITTED 等待期间资源已经被占用，尚未产生路由可用容量；长时间准备会使装箱率和实际合格吞吐分离。

## 条件变化后的选择

| 变化 | 保留的关系 | 需要调整或放弃的选择 |
|---|---|---|
| 节点故障或维护 | 请求身份、完整组与所有权约束 | 使旧候选失效；重算 D_g、剩余容量和新候选，不提前释放在途资源 |
| 负载下降 | 副本功能、状态与最后使用责任 | 可合并或缩容，排空结束后才归还资源 |
| 负载上升或突发 | 逐设备硬容量与 SLO 口径 | 重算组形状、排队及故障余量，不能仅凭总空闲卡扩容 |
| 新设备型号加入 | 能力相容性要求 | 重验执行路径、表示与缓存身份，重新校准准备和通信代价 |
| 链路或共享出口降级 | 通信成员与数据依赖 | 失效路径摘要；重算成对/共享预算，必要时改布局或减少并行度 |
| 碎片增加 | 资源各轴和硬约束 | 比较预留完整节点、迁移、改变配置与等待，不以 GPU 总量替代 |
| 搜索预算不足 | 已找到候选的合法性 | 增加预算、改顺序或索引；把预算耗尽保留为未知，不改写成无解 |
| 租户优先级变化 | 授权、配额和物理账 | 调整队列与预占策略；被预占任务未完成释放前不能作为空闲供给 |

## 诊断与区分实验

实验固定制品、执行配置、有效配额、实际映射与 offered 轨迹，记录拒绝、未完成请求和等待原因。候选评分变好不能单独证明 SLO 改善。[AlpaServe](../sources/S-ALPASERVE.md) 用配置枚举与模拟比较放置，其一次前向和模拟器条件不能直接套到逐 token decode。

| 观察 | 竞争解释 | 区分干预与预测 | 反证后的修正 |
|---|---|---|---|
| 总空闲很多，大组仍 pending | 碎片；某资源维耗尽；能力/拓扑不符 | 固定到达，保留一个完整节点；分别记录 CPU、显存和路径拒绝原因 | 保留节点仍失败时，不能继续只归因卡数碎片 |
| 空候选但准入延迟很长 | 真无解；失败分支多；拓扑检查昂贵 | 分别固定 K 改 B，记录 E、Q、每类检查耗时与停止状态 | 随 B 出现合法候选时撤回无解判断；E 小但慢则检查单次成本 |
| 同键重试后占用翻倍 | 查重与扣账未共同排序；载荷身份冲突；孤儿预留 | 让两调用先取得同一旧快照，再按两种临界区进入顺序推进 | 任一顺序出现第二票据或无决定资源，即反驳幂等实现 |
| 已 COMMITTED 却没有节点准备 | 提交后提前返回；派发失败；消息未达；节点拒绝票据 | 分记提交、离开临界区、逐 rank 派发、接收与票据校验；先用可靠事件接收器固定传输因素 | 接收器也无事件时修控制流；已有派发才继续定位传输或节点，不先归因加载慢 |
| 两组都得到同一个槽 | 过期候选未重检；节点绕过账本；所有权覆盖 | 两组共用候选，逐步记录权威所有者与节点实际分配 | 权威账正确而节点重叠时，修设备分配/隔离路径 |
| 故障后副本数足够但容量不足 | 跨域组不完整；共享出口；μ 估计失效 | 分别使一个必要 rank、机架和共享出口不可用，按完整组核对存活集合 | 存活集合正确而容量不足时，重算共同争用和 μ_g(F) |
| 容量平均值够但尾延迟超标 | 无排队余量；突发相关；慢 rank/冷准备 | 固定平均到达，改变突发相关性，分记准备期与稳态 | 只在突发或启动期恶化时，调整余量与准备策略 |
| 迁移降低碎片却损害 SLO | 迁移带宽；冷缓存；新拓扑更远 | 固定迁移量，对比分阶段流量与迁移后稳态 | 稳态仍慢则修拓扑选择；不能只优化装箱率 |

逻辑事件模型可以检查排序、所有权和首次派发不变量；真实系统还须验证锁覆盖全部修改入口、节点遵守票据、健康失效传播、最后使用完成与故障后的路由行为。故障模拟和设备注入的证据范围应分别报告。

## 检查覆盖与未验证边界

配套检查 tools/check_k_work_011_full.py 是确定性、标准库、只读、离线的 CPU 逻辑模型。放置参考先展开实际槽，再枚举互斥 rank→槽的排列，在完整映射上独立核对同节点、逐槽类型/内存和节点 CPU 总量；候选算法则使用增量资源账回溯。审计器同时核对可行性与返回映射，不能只比较两个布尔值。

检查包含有限小域枚举、空供给、类型不匹配、容量恰好、节点 CPU 不足、槽互斥，以及候选上限和展开预算停止。只看总卡数与总内存的负对照必须在单卡内存不足和同节点槽数不足时偏离参考，并被同一结果审计器拒绝；重复使用槽的错误映射也必须被拒绝。断言条件使用显式异常，检查失败会使进程非正常退出，不能只打印分歧后成功结束。

组准入模型将权威决定作为一次不可交错操作，准备派发则位于该操作之后。检查两种调用顺序、同键重试、不同组竞争、载荷冲突、代次拒绝、部分取得失败和 RESERVED 后失败的回滚；账本审计从正式分配与历史决定重建槽及 CPU 责任，拒绝重复正式分配和无决定的孤儿扣账。

独立事件审计按每次调用的 COMMIT、EXIT、PREPARE 和 RETURN 记录核对：首次成功提交必须为全部必要 rank 产生身份相符的准备命令，位置在离开临界区之后、返回之前；拒绝和历史重试没有新准备。理想无在途责任的退役事件归还资源后，旧键重试必须保留 RETIRED 且不重启。故意遗漏派发的错误版本可以通过账本审计，却必须被事件审计拒绝；临界区内派发、拒绝后派发和历史重试再派发也作为负对照。这个事件接收器只代表控制器发起命令，不代表网络送达、节点实际启动或准备完成。

故障参考先按失效域移除实际资源，再检查组所需资源是否全部存在；与依赖域并集模型对照。检查覆盖独立机架、同机架副本、跨两机架组、共享出口以及至多两个域同时失效，使用错误代表域容量作为必须被拒绝的负对照。

这些模型没有运行真实并发线程，不证明生产锁、一般拓扑搜索与性能评分、控制器崩溃恢复、节点异步撤销、真实 GPU 分配、显存连续性、CUDA/NCCL 路径、网络服务率、准备期峰值、故障排空或端到端 SLO。来源与 CPU 模型也不能证明知识改善了 Agent 构建能力。模型通过条件不应改写成设备实测结论。
