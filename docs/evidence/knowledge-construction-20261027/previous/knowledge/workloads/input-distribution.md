# K-WORK-003：工作负载分布：长度、复用、模态与相关性

系统成本由输入输出的联合分布决定；平均长度会丢失影响缓存、批次和尾部行为的结构。

## 不止两个平均数

prompt 长度影响 prefill、KV 初始容量和传输；输出长度影响请求驻留时长、decode 工作和尾部；两者相关性决定长输入是否还占用很长输出时间。相同均值可以由全为中长请求，或极短与极长混合组成，调度结果很不一样。

还应描述前缀共享长度与访问间隔、adapter 分布、grammar 类型、多样本分支、取消率和流式消费速度。视频帧数、分辨率、音频时长与 codec 设置形成额外几何，不能折算为文本字符数后丢失。

## 复用有时间结构

两条请求共享长前缀，只有在缓存尚未淘汰且被路由到可访问位置时才形成命中。把同一输入重复连续发送会得到近乎完美命中，与真实交错多租户的复用间隔不同。缓存容量、淘汰和亲和路由要在这个时间序列上一起分析。

## 合成负载怎样保持问题结构

可以用少量有含义的分层：短交互、长文档、长输出、共享系统提示、多模态与取消密集。每层保留长度范围、到达方式和质量目标，再按目标比例混合。这样能解释整体变化来自哪层，而不是只看一个总吞吐。

长度边界也有实现意义：页长前后、窗口 rollover、图桶边界、最大上下文和 tokenizer 特殊 token。为机制验证构造边界输入，为容量验证保留真实分布，两类输入回答不同问题。

## 输出长度是实现结果的一部分

不同 EOS、stop string、采样或错误可能让优化版本更早结束，造成表面 throughput 提高。比较时应同时看质量、输入条件与实际输出长度；若任务允许不同长度，采用与业务目标对应的 goodput，而不是假设每输出 token 同等有用。

## 为不同推理家族建立负载档案

| 负载 | 至少保留的联合变量 | 容易误造的理想条件 |
|---|---|---|
| 多轮与 Agent 调用 | 回合依赖、历史增长、思考/工具时间、分支宽度 | 把依赖调用全部并行，或假设会话永不淘汰 |
| RAG 与 reranking | 查询、候选数、文档长度、过滤与索引版本 | 只测热向量索引，不计取文档和重排 |
| 离线批生成 | 批任务大小、期限、输入/输出联合长度、质量 | 只计算最快子集，忽略排空尾部 |
| Embedding | 文本/图像长度、batch、向量维度、输出与归一化 | 固定极短输入却外推完整数据集 |
| 推荐 | 稀疏特征数、表大小、热门度、重复 ID、dense 部分 | 所有 embedding 行都留在 cache |
| 图推理 | 节点/边、度分布、邻居扩展、特征局部性 | 用均匀小图替代真实高阶节点 |

这些变量不是额外的统一指标，它们决定不同执行图和资源需求。家族之间可能共享矩阵内核，却不能共用同一份输入分布假设或成功标准。

## 保留相关性，再做有解释的分层

长 prompt 与长输出同时出现时，会把输入计算和状态驻留压力叠加；热门 adapter 也可能与长前缀相关。独立抽样各变量会破坏这种结构。优先保留真实联合记录，再按长度、复用或模态进行分层；资料不足时明确哪些相关性是设定，做敏感性分析。

取消并非总是均匀随机事件。客户端可能在等待过久、工具失败或用户改问后取消，所以取消率与延迟、历史长度相关。慢客户端的消费速度也会改变输出缓冲和 KV 驻留。把它们独立均匀化，可能低估真正的高压状态。

## 开发、校准与保留集合

机制边界集用来检查页长、桶边界和状态转换；代表分布集用来评估真实运行点；保留集检验反复搜索后的泛化。对量化，校准集还要覆盖敏感激活分布。三个用途可以来自同一总体，但必须记录划分和重用方式，不能看过保留结果后继续调参而仍称它独立。

若只有一个 synthetic workload，结论应限定在其设定；变更长度长尾、复用间隔或到达方差后重新扫描，能够判断设计选择是否稳定。保存每层结果与总体加权结果，并解释权重来源，避免用有利的样本配比掩盖某类任务退化。
