# K-FW-011：权重加载：从制品身份到可执行布局

加载的结果是一组能够共同实现指定模型函数的张量、配置和执行布局。文件已读完、张量已分配和服务可以接收请求是三个不同的完成事件。

## 先还原张量之间的关系

一个模型制品至少要确定配置、权重分片、张量名称与形状、数值表示、tokenizer/processor 和特殊 token 约定。配置中的层数、hidden、head 数与 FFN 维度必须和张量对应。文件可以按保存顺序排列，执行器却可能需要转置、QKV 合并、按 rank 切分或低位预打包；文件偏移不能直接当成计算布局。

把每个张量描述为“逻辑名称、轴含义、源表示、目标表示、放置、共享关系”。例如线性层采用 Y=XW 时，W 的 K×N 与文件中的 N×K 是一个显式变换。QKV 合并还要区分 Q head 和 KV head 的数量，不能把三个分段默认等分。并行切片应在轴语义上定义，随后才选择连续读取、跨片拼接或加载后切分。

tied weights 是两个逻辑用途共享同一个参数的关系；加载两份相同值可以暂时给出相同输出，却改变容量账和后续更新行为。别名还可能是同一存储的不同视图。去重应依据制品契约，不应仅凭名称或当前数值恰好相等。量化权重的 scale、zero point、分组轴和排列同样属于参数，不能在加载后猜测。

## 两条加载路径及其成本

整体加载先把所有分片反序列化到主存，再统一转换和复制。它容易检查完整性，也容易同时持有源权重、目标权重和转换临时区。分块流水逐块读取、转换、传输，在最后一个消费者完成后重用缓冲；它降低峰值，但需要显式依赖和失败处理。[ServerlessLLM 的固定版本](../sources/S-SERVERLESSLLM.md) §4 将顺序块读取、张量索引和多级流水连接起来，是后一条路线的一种具体实现。

设文件有效数据 Wₛ、最终驻留权重 W𝒹、主机块缓冲 b、同时在途块数 n、转换临时区 C。一个理想的流式实现主机工作集约为 nb+C，设备还要容纳 W𝒹 与设备端临时区；整体转换则可能同时持有 Wₛ+W𝒹+C。这里没有把操作系统页缓存、原模型初始化副本、框架 allocator 保留池或共享进程重复驻留藏入常数，它们都要另列。

设定算例：源和目标权重各 14 GiB，主存预算 20 GiB，工作区 1 GiB。若先保存完整源再构造完整目标，28+1 GiB 已超预算；两个 256 MiB 块交替转换时，显式主机缓冲和工作区为 1.5 GiB。这个结果只在原权重副本可释放、加载器不隐式保留全部对象时成立。文件映射的虚拟地址长度不等于驻留内存，读取它仍可能触发实际 I/O 和页缓存占用。

对 n 个等大块，读取、转换和设备传输分别耗时 tᵣ、t𝒸、t𝒹。若三阶段资源独立且缓冲足够，理想完成时间为 tᵣ+t𝒸+t𝒹+(n−1)max(tᵣ,t𝒸,t𝒹)。若读取与传输竞争同一主存带宽或 PCIe 路径，不能直接采用这个下界。小块增加提交和索引成本，大块延长第一块可用时间并抬高峰值；应该比较启动关键路径，而不只看单次读带宽。

## 发布可执行版本的边界

| 状态 | 已经成立 | 尚不能推断 |
|---|---|---|
| 制品已解析 | 名称、范围、形状和依赖可检查 | 内容完整且语义正确 |
| 块已读取 | 源字节进入指定缓冲 | 转换、DMA 或设备消费者已完成 |
| 张量已就绪 | 对应目标位置可安全读取 | 其他层、rank、编译对象也已就绪 |
| 模型已验证 | 必要参数齐备且参考检查通过 | 预热容量足够、服务协议可用 |
| 实例已就绪 | 执行、必要预热及准入预算均已建立 | 任意超范围请求都能成功 |

原始块只有在转换与传输都不再读取它时才能覆盖；取消加载也要等已有异步消费者结束。缺片、范围重叠、尺寸不符和转换失败应使该模型版本不可发布，不得留下一部分旧权重与一部分新权重组成的“成功”对象。多个 rank 可以并行加载，但路由发布必须等待所需 rank 的同一版本共同就绪。

预热可能分配 KV、工作区、编译缓存和图缓冲；峰值常发生在权重就绪之后。若还要求新旧版本并存，应把旧实例在途请求保护的权重、KV 与新实例启动峰值相加。单个版本能装入设备不意味着无中断切换也能装入。

## 验证与选择反转

先比较独立解码的少量 tensor 切片，再比较完整前向的中间层和 logits；名称和形状正确不足以排除转置或 head 排列错误。边界样本覆盖跨分片张量、空/缺分片、tied weights、奇数尾块、低位元数据以及加载取消。分别测冷页缓存、热页缓存和已驻留模型，说明初始化、读取、转换、传输与预热各自的时间。

当模型常驻且只加载一次，复杂流水的收益可能很小；频繁切换、共享存储拥塞或模型接近主存上限时，局部缓存和流式加载改变可行性。预先转换布局把启动计算移到离线，但会增加制品存储和对目标硬件/并行配置的依赖。比较两种方案时，必须把转换次数、缓存失效和分发字节计入整个模型生命周期。
