# 覆盖面审计：完整推理引擎的知识地图与 v2.2-r2 的对照

日期 2026-10-27。对象是 `base-gpt-6-astra-2026-04-30-v2.2-r2` 的 108 篇活动正文。审计问题只有一个：一个完整推理引擎在其全部生命周期里需要哪些知识，这些知识在当前正文里是覆盖、部分覆盖还是缺失。审计不绑定任何具体 Task、硬件或模型；"重要程度"一列只表示该子题对"从空工程构建并持续优化单实例推理引擎"这一研究目标的影响，不是对其他平台或负载的否定。

方法：以 [范围说明](../../inference-coverage.md) 的 24 个能力域和三项平台依赖为骨架，按生命周期重新展开成子题；用 `ops/knowledge-audit-20261027/extract_structure.py` 提取全部章节的二级标题，用 `gap_terms.py` 统计 27 组术语在正文中的出现章节，再对核心章节逐篇阅读确认。"覆盖"表示至少一章以机制、成本或不变量层面展开；"部分"表示只有一句或一节提及、或只在来源归档中存在而正文没有展开；"缺失"表示没有章节承担。

## 结论

域级覆盖完整：24 个能力域和三项平台依赖都有章节承担，用户点名的 CPU–GPU 协同与 HBM/DRAM/SSD 多级存储各有 5–6 章，深度足够。子题级缺口集中在三处：

1. GPU 硬件的"表征方法"与"代际事实"。没有一章说明怎样从零测量一块 GPU 的可持续带宽、矩阵吞吐、launch 与图重放成本、时钟/功耗行为；按 compute capability 的执行资源事实只在 K-HW-004 以矩阵指令形状出现，SM 驻留上限、共享内存上限、8.x 与 9.0 的特性差异没有写入正文，而来源归档 S-CUDA-CAPABILITY 已经包含这些表。
2. 问题侧内容。专用化杠杆（固定模型、固定负载、固定硬件各自释放的自由度）没有章节；单实例服务里有来源支撑的设计张力与公认次优区域分散在各章，没有汇总为探索起点；只有 8 章在正文里使用"设计轴/不变量/设计空间"的组织方式。
3. 少量机制点：L2 驻留与访问策略窗口、持久 kernel 作为 launch 开销的替代轴、SSD 到 GPU 的直通路径、无模型草稿的投机、小模型中词表投影的成本占比。它们影响有限，但对单卡交互式服务的探索有直接作用。
