# 知识使用场景与探索边界

InfraAgents 的研究任务是让 Agent 从空工程构建并优化完整的专用推理引擎。这里的“从空工程”描述任务起点；允许复用哪些库、需要满足哪些功能与质量目标，由具体 Task 决定。知识 base 提供技术事实、条件化机制和可检验关系，不能自行增加组件划分、实施顺序或阶段验收要求。

这份修订替代上一版的流程式组织。上一版新增的构建章、设计决定章和贯穿 U01–U07 的示例容易形成默认路线；即使有“非强制”声明，也不足以抵消其表格、标题和导航中的顺序引导。本轮撤回这两篇独立章节，并把有增量的技术内容归回既有专题。

## 可执行知识提供什么

可执行性来自技术说明足够具体：对象与函数是什么；在什么条件下成立；一个参数、布局、状态或同步关系怎样改变结果与成本；什么观察可以检验该解释。Agent 据此可以实现、组合、改写或拒绝某个机制。知识不预先决定 Agent 必须交付哪套中间文档、采用几个候选、什么时候才能开始性能探索。

例如，跨 stream 使用同一缓冲时，生产、消费和回收的关系需要与实际平台语义相容；实现可以使用不同事件、所有权、分配或整体执行方式。一次布局转换的成本可以被单独测量、被融合消除，也可能通过改变上下游表示不再发生。知识给出这些关系，不把其中一种实现写成唯一答案。

## 区分四种不同性质的内容

| 内容性质 | 约束从哪里来 | 对探索的含义 |
|---|---|---|
| 任务约束 | 用户和已固定的 Task、资源与质量要求 | 最终交付需满足；base 不自行扩充要求 |
| 数学或 API 语义 | 所选模型函数、平台及固定版本接口 | 使用该函数或接口时适用；换表示、接口或算法后重新判断前提 |
| 机制与成本解释 | 有范围的推导、原始来源和实际测量 | 可用于比较和提出假设；前提不成立时不能机械套用 |
| 设计示例与启发式 | 某组声明条件下的一个组织办法 | 可跳过、重排、改写或替换；不形成候选空间和实现路径的封闭集合 |

来源是否允许读取、时间资格、版本冻结和知识发布是访问及证据边界；它们不把“知识库中没有该方案”转换成“禁止探索该方案”。新假设可以在任务许可的范围内提出和试验。只有在形成经验结论或知识更新时，再依既有规则处理依据、适用范围和观察日期。

## 允许不同的构建与探索方式

在任务允许的资源和工具范围内，Agent 可以整体生成一个原型、从编译或执行表示入手、先建立外部协议、先做局部成本实验，或并行探索多个相互影响的部分。接口也可以与实现共同演化。知识使用不要求先完成单请求，再做增量状态，再做并发，最后才优化。

早期 microbenchmark 可以用于判断一个方向是否值得继续，尚未实现的服务功能不会使该局部观察失去其声明范围内的意义。相应地，局部成本不能自动证明目标引擎已经完整或质量合格。验证层次说明证据覆盖范围，不规定研发顺序；最终验收仍依原 Task。

同一技术问题可以采用与示例不同的架构。例如，固定离线批可通过整体编译执行，不必拆成在线请求池、独立调度器和网络适配层；计算与状态布局可以协同设计，不必先冻结一套内部 API。只有实际选定方案涉及的对象和语义才产生相应检查。

## 对既有运行时的准确描述

当前运行时提供 design/diagnosis 检索、冻结章节读取和 knowledge_used 版本记录。这些入口没有把 U01–U07 编译成阶段状态机。知识使用声明的检查针对被声明的条目、版本、读取记录和用途，不验证实现是否照搬章节路线。

正文仍会进入模型上下文，因此表述、摘要、重复内容和导航可能影响 Agent 的方案选择。代码中没有强制顺序不能证明没有行为偏置；本轮只审查并修正内容和接口边界，未测量模型实际受到的影响。

## 扩充时优先修改知识对象本身

先对照现有目录和正文确定缺失的对象或关系，再决定归属。已存在的 CPU–GPU、collective、算子和服务专题增加相关完整节；跨专题使用问题通过链接连接。只有出现不能被现有主题自然容纳的独立技术对象时，才新建章节，不按工作阶段复制同一机制。

本轮保留真实的 API、地址/布局、缓冲数量、通信容量和 oracle 增量，撤回六个新设章节。来源上限仍为 2026-04-30，所有设定算例保留假设身份。原 v2.2 的检查记录属于其当时内容；修订版另有新的身份与验证记录。

## 后续怎样检查知识是否帮助探索

可在相同任务、模型、工具和预算下比较旧 base 与修订 base，观察完整引擎交付、成本和质量/SLO，同时分析是否出现超出示例的合法方案、能否因实测反证改变方向、是否把建议当作硬要求。路径不同本身不是收益，路径相同本身也不是失败；判断依据仍是任务结果和选择理由。

这些是研究者的评估问题，不向构建中的 Agent 下发“必须设计多种架构”或“必须偏离示例”的奖励目标。没有实际对照实验之前，不宣称已证明探索多样性或 RSI 收益提升。
