# 章节深度修订范式

本文件保留前一轮讨论记录。当前制作标准以[知识库构建与修订方法](../../knowledge-method.md)为准：允许算法伪代码，使用用户确定的六项内容标准，不要求固定反例数、固定标题或只留来源指针。下文有冲突的旧规则不再用于新修订。

2026-10-27。本文是对单个知识章节做深度修订时的判断标准与操作流程；第一个按此处理的单元是 K-FW-006 及其来源说明，后续章节逐个照此处理。标准来自 [写作约定](../../../knowledge/templates/entry.md) 与 [设计文档 40 §4.3](../../../../../repo/docs/infraagents-design/40-knowledge-base-for-exploration.md)；本文只把它们落成可逐项核对的清单。

## 检验标准

读完一章后，读者应能回答：若不采用本章列出的任何方案，我仍须满足哪些不变量、支付哪些成本项、用什么观测区分候选。能回答，说明章节教的是问题；只能复述某个库怎么做，说明章节教的是答案。

## 一章应有什么

1. 开头一句论点，说明本章对象是什么关系的交集或什么量的来源，不是某个库的介绍。
2. "问题、不变量与设计轴"节：问题用解法中立的语言陈述；列出任何解都必须满足的不变量；列出成本项并指明各项在哪个频率上发生；列出设计轴，把已有方案作为轴上的点并写出前提与代价；以"轴上未列点同样合法"结束。
3. 机制节：每节解释一个机制怎样工作、改变了哪项成本、增加了哪项成本，用数学关系、状态关系或时序关系展开，不以某个引擎或库的组件划分为骨架。
4. 设定算例：每条关键成本关系至少一个可复算算例，明确全部设定值与假设，并登记到 `tools/check_knowledge_examples.py`。
5. 反例：至少两个能证伪朴素实现的可复算反例。
6. "诊断线索"节：表格列出现象、能区分解释的检查、对应机制。运行时检索的 diagnosis 模式对该节加权。
7. 反转条件：本章方案在什么条件下不再占优，涉及其他机制的张力指向 [已知张力](../../../knowledge/system-semantics/known-tensions.md) 或在本章说明。

## 一章不应有什么

8. 正文不含绑定固定提交或版本的接口行为：函数名、参数名、分支行为、提交哈希、裸 arXiv 编号。版本事实若作为机制的证据，用一句话说明机制并链接来源说明，不复述细节。
9. 不含编辑元话语："本次扩写""本库把……放在""这里依据的是""本章没有报告"。读者要的是关系，不是编辑过程。
10. 不含对读者的规定性措辞："必须选""应该先"；"必须"只用于陈述不变量。
11. 不以"指针"代替内容：一段只说"详见某来源说明"而自身没有陈述关系的段落应删除。

## 来源说明应有什么

12. "来源支持的机制与定义"：该来源展示或定义了哪些机制关系，可带节号；不罗列接口事实。
13. "InfraAgents 如何据此推导"：本库从中抽出了哪条版本无关的关系，链接到使用它的章节。
14. "适用边界"：说明它是一个实现在一个版本上的选择，不证明接口必须如此；接入该版本时按归档原文逐项核对，本说明不复述参数。

## 元数据与版本

15. catalog 条目：title 与 summary 反映问题与关系而不是方案名；tags 以概念为主、库名与版本为辅；补 `questions`（3–5 条本章回答的解法中立问题）、`symptoms`（读者看到后会来读本章的现象）、`assumes`（本章推导依赖的前提）；`related` 双向。
16. revision 加一；旧正文与旧条目按原字节归档到 `knowledge/history/<id>/<rev>.md|.json`；INDEX 与分类 README 由 `knowledge_index.indexes` 再生成；temporal-audit 再生成；VERSION 与 change-manifest 更新。这些由 `ops/knowledge-audit-20261027/rebuild_release.py` 统一完成。

## 验证

17. `tools/validate_knowledge.py` PASS；`tools/check_knowledge_examples.py` PASS 且本章算例计入；正文 LF、无 URL、无代码块；`ops/knowledge-audit-20261027/scan_pinned.py` 对本章零命中。
18. 修订记录写入本目录 review.md：改了什么、删了什么、为什么。

## 来源说明的写法（修订）

第 12–14 条的边界更正如下。来源说明不是指针，而是对原文的一次核对后的提炼：论文给出可直接打开的原始 PDF 链接（归档中已有 `references/<id>/original.pdf`），然后用自己的话写出该论文的算法（允许伪代码级的步骤）、关键结论（含论文报告的数字与条件）、本库从中抽出的版本无关关系并链接到使用它的章节、以及适用边界。源码类来源不复述参数名与分支，但要写出它相对论文或文档多出来的、对设计有意义的事实（例如调用如何分段、哪些转换是复制、workspace 由什么构成）。判断一份来源说明是否合格的方法：读者不打开原文，能否据此在另一个硬件上重写该算法并知道会遇到什么代价；能，则合格。

章节正文对来源的引用同样要带内容："某论文给出 X，代价是 Y"，不能只写"见某来源"。章节不提供源代码，但提供算法骨架。
