# K-TOOLS-008：GPU 从零表征：可持续带宽、矩阵吞吐与测量条件

资源模型里的带宽、算力和提交成本应来自目标设备上、与服务形态匹配的测量；铭牌峰值、异代结果和未声明条件的单次最高值不能直接代入。本章描述从零建立一组可复用设备参数的方法：每项写测量条件、常见误读，以及如何接到容量、流量与计算账。能力表与 compute capability 事实见硬件章节，本章不列 CC 差异表。

## 可持续设备主存带宽：顺序、随机与粒度

设备主存可能使用 HBM 或 GDDR；测量边界应说明实际介质。有效带宽是这段路径传送的有用字节除以完成时间，物理事务字节与有效字节要分别计量。顺序大块读、跨步随机读、读写混合和不同事务粒度会得到不同数值；把其中最大者当作“设备带宽”会系统性地低估不规则访问服务路径的成本。

测量条件至少固定：独占或声明的并发、时钟是否锁定或报告、工作集是否明显大于 L2、读写方向、元素大小与对齐、每线程/每 warp 的访问跨度，以及计时是否排除分配与首次缺页。预热轮次与统计轮次分开；短窗峰值与可持续均值分开报告。

设定算例：工作集 8 GiB、顺序读测得可持续 1.0 TiB/s，同设备上 128 B 跨步随机读测得 0.35 TiB/s。把 decode 的 KV 不规则读取代入 1.0 TiB/s 会把流量时间下界压低约 2.9 倍。这不是某卡实测，只说明访问形态必须进入带宽身份。

常见误读：把 cache 命中后的瞬时速率当 HBM 带宽；把未合并事务的设备字节当有效张量字节；在多进程共享同一控制器时，把单消费者结果当作服务可用份额。

接到资源模型：为顺序权重读取与不规则 KV/索引读取建立不同有效带宽符号；流量账按实际跨 HBM 边界 的方向与形态选对应项，而不是共用一个标量。

## L2：容量边界与命中后的表观带宽

L2 复用会让观察到的 HBM 字节低于张量逻辑读取字节；工作集越过 L2 有效容量后，同一 kernel 的表观带宽会突然贴近 HBM。表征需要至少两个工作集：明显小于估计 L2、明显大于估计 L2，并记录命中相关计数或 HBM 事务差。

测量条件：固定地址流与复用距离；避免与无关 kernel 交错污染；说明是否锁定频率。L2“带宽”若来自命中路径，不能当作 HBM 项写入 roofline。

设定算例：工作集 8 MiB 时某读核表观 2.5 TiB/s，工作集 2 GiB 时降至 0.95 TiB/s。服务若每步重扫数 GiB 权重，应以后者为流量下界输入；若某层激活反复命中 L2，则应对该层单独减小 D_HBM，而不是抬高全局 B。

常见误读：用单点工作集外推所有形状；把 L2 命中节省重复计入“融合收益”和“带宽提升”。

接到资源模型：在流量账中区分 D_HBM 与 D_L2；复用距离改变时重测，而不是沿用冷缓存微基准。

## 各 dtype 的矩阵吞吐

矩阵能力随 dtype、累加精度、布局、M/N/K、是否使用专用矩阵路径以及是否受占用率/共享存储限制而变。FP16 峰值不能外推到 INT8 或 FP8；同一 dtype 下小 M 的 decode 形与大 M 的 prefill 形也不是同一参数。

测量条件：声明库/kernel 路径、是否允许 TF32 等宽松累加、输入是否已在设备、是否计入 host 打包、形状网格覆盖目标服务的 decode 与 prefill 角点。吞吐用有效 FLOPs（按约定的乘加计数）除墙钟；同时记录是否触顶功耗或降频。

设定算例：某形态下 BF16 GEMM 可持续 150 TFLOP/s，同设备 FP32 为 40 TFLOP/s；另一形态 M=1 的 GEMV 有效算力远低于屋顶。将大矩阵屋顶代入 batch=1 decode 会得到虚假松弛的计算下界。

常见误读：用理论峰值填 P；把一次自动调优的最好 shape 当作全服务常数；忽略布局转换一次性成本。

接到资源模型：为关键算子族建立 P(dtype, shape_family)；算术强度用匹配的 P 与对应边界的 B。

## Launch 与图重放成本

大量短 kernel 时，主机提交、依赖解析与空档可与设备工作同量级。单独测量：空 kernel 或极短 kernel 的 launch 间隔；相同拓扑 CUDA Graph 的捕获一次成本与稳态 replay 成本；从参数更新到可重放的计划失效路径。

测量条件：固定 CPU 亲和与驱动版本；区分第一次捕获与稳态；声明 graph 是否与其他流并发；计时点落在 host API 返回还是 device 完成事件。图不改变内部长 GEMM 的算术与 HBM 项，只摊薄重复提交。

设定算例：eager 路径每步 80 次 launch，平均提交空隙 15 μs，合计 1.2 ms；同工作图 replay 设备侧 0.2 ms。若同步 HBM 流量下界已 12 ms，提交项不是主矛盾；若流量下界仅 0.8 ms，提交项进入关键路径。

常见误读：把图加速比当成算子变快；在地址或形状每步变化时仍引用稳态 replay 成本；忽略捕获与桶切换的一次性延迟。

接到资源模型：增加提交次数 N_launch 与单次成本 c_launch，或图路径的 c_replay 与失效摊销；与流量/计算下界并列取关键路径。

## PCIe（或其他主机设备链路）双向

主机↔设备链路有方向、并发复制引擎数量和上行共享。单向 H2D、单向 D2H、双工同时打满，结果通常不同；与磁盘或 NIC 争用同一根复合体时，服务可用份额会再下降。

测量条件：固定 PCIe 代数/链路宽度或报告拓扑；钉住主机内存；分别测纯 H2D、纯 D2H、双向；消息大小从小于到大于 page/segment；说明是否 GPUDirect 或额外 bounce。

设定算例：单向 H2D 可持续 28 GiB/s，双向各方向约 20 GiB/s。若每步必须同步回传 64 MiB logits 且与 256 MiB 输入预取重叠，链路时间不能再用单向峰值估算。

常见误读：用设备互连（如 NVLink）数字填 PCIe 项；把 pinned 与 pageable 混用后的结果当链路能力；忽略与其他设备共享的上游开关。

接到资源模型：D_H2D、D_D2H 分项，双向重叠时对共享链路求和或按实测双工曲线取值。

## 持续负载下的时钟与功耗墙

短微基准可在 boost 区间跑完；服务长窗常触及功耗、温度或空闲降频。表征需要在目标功耗模式与机箱散热条件下，记录可持续 SM/内存时钟、整卡功率与是否触发限流。

测量条件：负载持续足够长以越过瞬态；同步采集功率/时钟；区分空载、仅拷贝、仅计算与混合服务负载；声明是否锁定应用时钟。

设定算例：空核 2 s 测得某矩阵吞吐 X，连续 60 s 同核因降频降到 0.85X。把 X 写入长时间 ITL 预算会高估算力。

常见误读：用瞬间最高功率反推可持续；在风扇曲线或机箱不同的机器间直接搬时钟曲线。

接到资源模型：P 与 B 取与目标运行时长同量级的可持续点；功率上限作为独立约束进入成本账，而不是事后装饰。

## 并发消费者干扰

多进程、多上下文或多流消费者共享 HBM、L2、复制引擎与 SM。单消费者表征给出上界；服务实例数、同卡训练作业或同机其他 GPU 的 DMA 都会改变可用份额。

测量条件：固定干扰源集合与其强度；报告每消费者分得的有效带宽/算力，以及总吞吐是否次线性；区分时间片共享与真正并行。

设定算例：单进程顺序读 1.0 TiB/s；两进程各打满时合计 1.1 TiB/s、每进程约 0.55 TiB/s。第二个服务副本不能按“再乘一个 1.0”扩容。

常见误读：把 MPS/分片配置下的隔离当成物理带宽加倍；用空闲卡上的微基准解释生产共置。

接到资源模型：对共享资源引入可用份额系数或直接写入多消费者实测曲线；容量账仍按字节，流量账按份额后的 B。

## 测量包如何写入资源模型

一次从零表征产出的不是单一“GPU 分数”，而是带条件标签的参数包：B_HBM(seq)、B_HBM(random,granule)、L2 有效容量提示、P(dtype,shape_family)、c_launch、c_replay、B_H2D/B_D2H、可持续时钟/功率点、多消费者曲线。服务 roofline 选用与当前关键路径形态匹配的条目；形态改变则重选或重测。

微基准与完整服务之间保留校准差：把预测下界与实测迭代时间的差额拆成重复流量、同步、争用与排队。差额不能用调高某个峰值参数来“抹平”。统计重复与区间见实验章节；单次表征只建立参数身份。

设计轴包括：访问形态集合、工作集相对缓存层级、dtype×shape 网格密度、计时边界（host API / device event）、独占与共置、时钟策略。轴上未列点同样合法。

## 从测量构造可复用参数的步骤

表征是辨识一个带条件的成本模型。它的输入是访问模式、工作集、并发、数值类型、计时边界和运行状态；输出是这些条件下的有效速率、延迟及其变化范围。单次最快结果不能代表未知形态，更不能反推实际业务已经饱和该资源。

```pseudocode
定义要辨识的资源边界，列出可能混入的准备、cache 与同步成本
选择能区分解释的工作集、形状或消息大小，而非只选有利点
建立有效输入并预热；保留首次运行与稳态运行的区别
重复观察完成时间、有效字节/运算量和所需设备或主机信号
按同一观察边界计算速率，并报告重复层级、范围与干扰状态
改变一个相关条件或做交叉对照，检验模型的预测能否成立
将参数连同环境、测量方法、证据与日期交给观测记录；不写成通用常数
```

例如顺序读与不规则读不同，可由事务合并效率、cache 命中或并行度不足解释。扩大工作集以削弱 cache 复用、改变跨度以改变事务效率，再观察物理字节和并发任务数，能区分部分解释。没有相应计数器时，保留未知项，不把推测写成测量结果。
