# K-HW-006：ROCm 平台：CU、Wave 与 AMD 算子路径

ROCm 移植需要保持模型函数，同时把逻辑 tile 重新映射到 AMD 的 CU、wave、LDS、寄存器和算子路径。HIP 接受一次调用，只说明接口边界通过；实际选择了哪个 kernel、线程和存储映射是否合法、是否新增转换或准备工作，需要分别核对。

## 问题：函数、数学状态与执行所有权

对一个请求的某个 query head，设 Q∈ℝ^{L×d}、K∈ℝ^{S×d}、V∈ℝ^{S×dv}，缩放为 a，位置偏置为 bᵢⱼ，每行可见 key 集合为 Aᵢ。推理前向、不使用 dropout 时，模型函数为：

zᵢⱼ=a·QᵢKⱼᵀ+bᵢⱼ，pᵢⱼ=exp(zᵢⱼ)/Σ_{t∈Aᵢ}exp(zᵢₜ)，Oᵢ=Σ_{j∈Aᵢ}pᵢⱼVⱼ。

不可见位置不进入分子和分母。GQA 的 query head 到 KV head 映射、非方形因果对齐、分页位置、dtype、舍入和统计量底数都是函数契约。移植可以改变执行组织，不能偷偷改变这些关系。

一次执行的输入条件可写为 P=(算子、dtype、shape、stride、paged layout、mask、目标架构、编译目标、库版本、数值策略)。P 决定合法候选集，库名或 dtype 名称不能决定真实 kernel。需要区分三层状态：

- 逻辑状态：Q/K/V、页表、绝对位置、可见集合和输出位置。
- 数学状态：每行的最大值 m、归一化质量 ℓ、未归一化加权和 U。
- 执行状态：每个 lane 持有哪些元素、LDS 槽的写者与读者、何时发布和允许覆盖。

本章标量基线要求 L、S 为非负整数，d、dv 为正整数；输入、参与计算的 V、可见偏置以及计算后的可见分数均有限。点积溢出、NaN、正无穷与特殊值策略超出该基线，调用方须拒绝或选择另有定义的路径。L=0 没有输出工作；S=0 或整行不可见时，本例规定 O 为零、empty 为真。这个空行契约不自动代表任意库接口。

## 合法执行：wave、CU、LDS 与指令契约

固定 HIP 硬件说明把计算资源组织为 shader engine、shader array 和 compute unit。CU 内以 wave 为指令发射与活跃掩码粒度；同一 workgroup 的 wave 被安排在同一 CU，才能使用 workgroup 范围的同步和 LDS 通信。workgroup 到 CU 的映射不确定，算法不能依赖固定 CU 编号。

wave 宽度不是跨架构常数。所供概述以 RDNA 的 wave32 和 CDNA 的 wave64 说明主要组织；实际执行模式仍须绑定编译目标。CDNA 的 SIMD、寄存器和矩阵资源也随代际变化。把 32 当作全部 AMD GPU 的宽度，或用 wave64 的 lane 编号解释 wave32 活跃集合，会破坏归约、写者归属和同步参与条件。

SPI 跟踪影响并发执行的 warp slot、VGPR、SGPR 和 LDS。增加寄存器可能减少可驻留 wave；增加 LDS 可能减少可驻留 workgroup。驻留只是资源约束，不能单独推出性能。所供 LDS 说明给出 CDNA/CDNA2/CDNA3 的 32 个 4 字节 bank，以及 CDNA4、RDNA2/3/4 的 64 个 4 字节 bank。不同地址落在同一 bank 可能串行化；相同地址的多 lane 读取可以广播。服务周期还取决于指令、lane 分组和行距，不能只看逻辑数组名。

MFMA 是 CDNA 的矩阵加速入口。所供示例 `v_mfma_f32_16x16x4f16` 表达 16×16、内维 4、FP16 输入和 FP32 累加；操作数使用寄存器，支持的架构还可能使用 AGPR。示例支持指令形状和资源入口的说明，没有提供任意 tile 的 lane 到 fragment 元素排列。缺少目标 ISA 或编译接口契约时，不能猜内部 fragment。

合法映射至少要满足：

- 目标 wave 宽度、活跃集合、线程分工和同步作用域一致；所有真实生产者和消费者被所用完成契约覆盖。
- 每个非原子输出元素有唯一写者；相同写值不能使多个并发写者自动合法。标记数组也属于输出。
- LDS 输入先完整写入并发布，再被消费；最后一个读者结束后才允许覆盖。复制完成、消费者可见和读者结束是不同条件。
- 分页与普通张量地址使用实际 stride、有效长度和足够宽的整数索引。无效地址不得先解引用再靠输出 mask 补救。
- MFMA 的形状、dtype、操作数布局、参与范围和完成依赖由目标接口支持。FP32 accumulator 不能概括输入转换、概率精度或输出舍入。
- 输出彼此不重叠，也不覆盖仍会读取的输入；需要原地更新时另证访问次序。

下面选用一个 workgroup 恰有 64 个线程、目标恰以一个 wave64 执行的基线。所有交接使用覆盖这 64 个线程的 workgroup 同步。这样可以明确同步契约，又不把 wave 锁步执行当成任意 LDS 访问已经完成的证明。

## 一条完整的 wave64 子组 attention 轨迹

选择 Br=4、Bc=16，把一个 wave64 分成四个 16-lane 子组。lane∈[0,64)，g=⌊lane/16⌋，l=lane mod16。子组 g 负责 query_row=r0+g；lane 的子组内编号 l 同时指定本块的一个 key。输出 value 维归属为 D_lane={l+16q | q≥0，l+16q<dv}。因此每个有效输出元素只有一个 lane 持有 U 和执行写回。

协作装载所有权与计算所有权不同。搬运 Q 的线性位置 a=lane+64v 对应 g2=⌊a/d⌋、t=a mod d，其全局行是 load_row=r0+g2。load_row 只能用于这次搬运，不能成为 lane 的 query 身份。每个 lane 在装载完成后独立绑定 query_row=r0+g，后续分数、mask、bias、有效行和输出判断始终使用它。

设页大小为 Gp，逻辑 key j 的物理页为 T[⌊j/Gp⌋]，页内位置为 j mod Gp。以元素为单位，K 的地址为：

addrK(j,t)=baseK+bK·(offsetK+T[⌊j/Gp⌋]·sKpage+(j mod Gp)·sKtoken+t·sKdim)。

V 用自己的基址、元素字节和 stride 替换；Q、O 也按实际 stride 寻址。页表长度至少覆盖 ⌈S/Gp⌉ 个逻辑页，末页只消费有效 token。计算块大小 16 不要求等于页大小；一块跨页时，每个位置分别定位。不同逻辑页可以合法共享只读物理内容，但其位置偏置和可见性仍绑定逻辑 key。

本例 LDS 全部采用 FP32：Q_s 的行跨度为 d；K_s、V_s 按行连续；Z_s、P_s 的行跨度为 17，只使用前 16 列。增加这一列是可替换的布局选择，不构成无 bank 冲突的证明。m、ℓ 在同一子组的 16 个 lane 中复制，U 只按 value 维分片。下面的 m_lane、ell_lane 和 rescale 都是 lane 私有状态。

```pseudocode
输入：Q[L,d]、分页 K/V、页表、S、实际 stride、scale、bias、可见性 A(r,j)
      d>0、dv>0；workgroup=64 线程；目标为单个 wave64
      Br=4、Bc=16；本 workgroup 负责 r0..r0+3
输出：独立 O[L,dv]，独立且每行一个可寻址 32-bit 元素的 empty[L]

lane∈[0,64)；g=floor(lane/16)；l=lane mod16
D_lane={u | u=l+16q，q≥0，u<dv}
LDS：Q_s[4][d]、K_s[16][d]、V_s[16][dv]
     Z_s[4][17]、P_s[4][17]、M_s[4]、Sum_s[4]
m_lane=-∞；ell_lane=0
对 u∈D_lane：U_lane[u]=0

对 a=lane；a<4·d；a=a+64：
    g2=floor(a/d)；t=a mod d；load_row=r0+g2
    若 load_row<L：Q_s[g2][t]=按实际 stride 读取 Q[load_row,t]
    否则：Q_s[g2][t]=0，不访问 Q
同步整个 workgroup，发布 Q_s
query_row=r0+g                 # 独立绑定；不使用 load_row 的最终值

对 k0=0,16,32,… 且 k0<S：
    对 a=lane；a<16·d；a=a+64：
        j=floor(a/d)；t=a mod d；key_pos=k0+j
        若 key_pos<S：K_s[j][t]=按页表和实际 stride 读取 K[key_pos,t]
        否则：K_s[j][t]=0，不访问 K 或该越界位置的页表
    对 a=lane；a<16·dv；a=a+64：
        j=floor(a/dv)；u=a mod dv；key_pos=k0+j
        若 key_pos<S：V_s[j][u]=按页表和实际 stride 读取 V[key_pos,u]
        否则：V_s[j][u]=0，不访问 V 或该越界位置的页表
    同步整个 workgroup，发布本块 K_s/V_s

    pos=k0+l；z=-∞
    若 query_row<L 且 pos<S 且 A(query_row,pos)：
        acc=0
        对 t=0..d-1：acc+=Q_s[g][t]·K_s[l][t]
        z=scale·acc+bias(query_row,pos)
    Z_s[g][l]=z
    同步整个 workgroup，发布 Z_s

    若 l=0：M_s[g]=max_{q=0..15} Z_s[g][q]
    同步整个 workgroup，发布 M_s
    bmax=M_s[g]

    若 bmax>-∞：
        m_new=max(m_lane,bmax)
        若 ell_lane=0：rescale=0
        否则：rescale=exp(m_lane-m_new)
        p=(z>-∞) ? exp(z-m_new) : 0
    否则：
        m_new=m_lane；rescale=0；p=0
    P_s[g][l]=p
    同步整个 workgroup，发布 P_s

    若 l=0：Sum_s[g]=Σ_{q=0..15} P_s[g][q]
    同步整个 workgroup，发布 Sum_s

    若 bmax>-∞：
        对 u∈D_lane：
            add=0
            对 q=0..15：
                prob=P_s[g][q]
                若 prob>0：add+=prob·V_s[q][u]
            U_lane[u]=rescale·U_lane[u]+add
        ell_lane=rescale·ell_lane+Sum_s[g]
        m_lane=m_new
    同步整个 workgroup，确认本块所有读者结束后才进入下一轮

若 query_row<L：
    对 u∈D_lane：
        若 ell_lane>0：O[query_row,u]=U_lane[u]/ell_lane
        否则：O[query_row,u]=0
    若 l=0：empty[query_row]=(ell_lane=0)   # 每行恰写一次，位于 value 循环外
```

处理完任意前缀 key 后，同一有效行的各 lane 持有相同的 m 和 ℓ；m 是该前缀内可见分数最大值，ℓ=Σexp(z−m)，每个 U_lane[u]=Σexp(z−m)V[u]。新块把最大值改为 m_new 时，旧 ℓ 和旧 U 同乘 exp(m_old−m_new)，再加入新贡献。最终 U/ℓ 恢复整行 softmax。数学等价不代表真实 FP32 归约、指数或输出转换逐位相同。

首个非空块取 rescale=0，避免计算 −∞−有限值；全空块完全保持旧 m、ℓ、U。全空块可能出现在第一个非空块之前、两个非空块之间或最后，不能只验证 S=0。非空状态在精确模型中有 ℓ≥1，故 ell=0 可以识别尚无可见项的状态；实际数值路径仍须排除溢出等例外。

Q_s、K_s、V_s 的每个槽按线性位置模 64 唯一分配给装载者；Z_s[g][l]、P_s[g][l] 由对应 lane 写，M_s[g]、Sum_s[g] 仅由 l=0 写。O 的 value 维模 16 唯一，empty 的每行仅由 l=0 写。empty 采用独立的 32-bit 行元素，避免把此处证明错误推广到多个线程对位打包标记的读改写。

无效 query 行的 lane 仍装载分配给自己的输入并到达所有同步，不写输出，也不读取该行 mask 或 bias。每块有六次完整同步：输入、Z、M、P、Sum 的发布，以及最后读者结束；Q 开始另有一次发布。下一块不得提前覆盖仍在被读取的 K/V/P。扩大 workgroup 后，即使每个 wave 的 LDS 区不重叠，仍须保证所选同步参与者及循环次数合法；不能让不同 wave 在不同次数的 workgroup barrier 上等待。

这是一条普通标量运算与显式 LDS 交接路径，没有声称是 AITER 的实现或 CDNA 高吞吐路径。改用 MFMA 时，QK/PV 数学与在线状态可以保留；fragment 装载、矩阵指令参与范围、累加器归属、概率到矩阵操作数的布局转换和完成依赖必须重新证明。

## 算子库与真实分派

ROCm attention 可以经框架可用实现、Triton 或 AITER 等路径接入。真正兼容性是模型语义、dtype、shape、stride、分页布局、mask、图执行要求和目标架构的交集。

所供 S-AITER 原文只有 README，没有算子实现。它说明 AITER 汇集 Triton、模板 C++ 和手写汇编等后端，覆盖 attention、MoE、块级缩放 GEMM、归一化、量化和通信等算子族，并按设备与模型发布调优配置。设备支持程度不同；这不能证明每种 shape、dtype、mask 或分页组合具有同一路径。以下是本章的接入推导，不冒充 AITER 内部 dispatch。

```pseudocode
输入：op、arch、dtype、shape/stride、paged 与 mask 模式、图执行要求
      模型/设备配置、库版本、数值策略和质量约束
输出：合法后端及配置，或明确回退/拒绝

1 核对接口接受的函数、几何、页表单位、mask、dtype 和编译目标
2 核对执行契约：目标二进制、wave、LDS/寄存器、矩阵或向量操作数布局
3 形成候选集合；每个候选保留自己的设备、shape、layout 与数值条件
4 按实际 arch、shape 桶、layout、mask、数值策略及配置选择候选
5 无合法候选时使用数值等价通用路径，或明确拒绝；不截断输入或改写可见集合
6 记录实际后端及配置身份；对照独立参考后，再比较完整调用成本
```

形状桶、页模式、mask、设备、dtype 或库版本变化，可能使旧分派和准备状态失效。Triton 的机制说明也区分逻辑 tile、编译变体、合法域、搜索候选和最终配置；看到一个 tile 参数不能反推出真实 lane/LDS 布局。

预打包、gather、转置、dtype 转换、JIT、调优、参数准备、launch 和输出交接应按真实发生频率计费。跨 backend 共用模型文件不证明共用设备内布局。准备成本 Cprep 若可复用 R 次、每次执行节省 Δt，只有 R·Δt>Cprep 才能在该范围内收回准备；输入变化导致失效时重新计费。图支持还需验证稳定地址中的内容与本次输入匹配。

## 条件化成本：容量、逻辑交通与服务周期

以下数字对应上述全 FP32 标量候选，不能用于某个未知 MFMA kernel。每个 workgroup 的 LDS 容量为：

C_LDS=4·[Br·d+Bc·d+Bc·dv+2·Br·17+2·Br] 字节。

取 Br=4、Bc=16、d=128、dv=16：Q_s 为 2,048 B，K_s 为 8,192 B，V_s 为 1,024 B，Z_s/P_s 各 272 B，M_s/Sum_s 各 16 B，合计 11,840 B，即 11.5625 KiB。填充列占容量但不被本算法读取。对齐、编译器额外 LDS 和同步实现另计。双缓冲 K/V 另加 9,216 B；不能把容量增加等同于读取字节增加，也不能在算法没有复制 Q/Z/P 时给所有对象都乘二。

满块、四行有效且全部 16 个 key 可见时，QK 和 PV 的乘加主项为 2·Br·Bc·(d+dv)=18,432 FLOP；softmax、scale/bias、U/ℓ 重标度、归约和归一化另计。一次 PV 更新还为每个 U 元素执行旧值缩放与相加。mask 会减少这里按分支写出的标量乘加，但生成程序的指令数、尾部浪费和时间未必按相同比例减少。

指数必须分开计数。本例每 lane 计算自己的概率，满块共有 64 次概率指数；首次非空块没有重标度指数。后续非空块中，旧 ℓ>0 的每个 lane 还执行一次 exp(m_old−m_new)。本伪代码把 m/ℓ 和重标度计算复制在子组内，因此四行均已有贡献时另有 64 次重标度指数，合计 128 次。某行当前块为空则两类指数均不执行；此前只有空块的行在第一次非空时仍无需重标度指数。可以改为每子组指定 lane 计算一次 rescale 后发布，把额外指数降至每行一次，但那是另一个候选，需要补共享状态、读取和同步证明。数学 exp 也不直接等于某条 ISA 指令的数量，底数转换与编译降低须检查生成程序。

按实际伪代码逐个标量读取计，满块且概率为正时，主要 LDS 消费读取如下：

| 消费对象 | 读取元素数 | 给定参数下的 FP32 字节 |
|---|---:|---:|
| QK 中 Q_s | Br·Bc·d | 32,768 B |
| QK 中 K_s | Br·Bc·d | 32,768 B |
| PV 中 P_s | Br·Bc·dv | 4,096 B |
| PV 中 V_s | Br·Bc·dv | 4,096 B |
| 上述主项合计 | 2·Br·Bc·d+2·Br·Bc·dv | 73,728 B |

因此 Q/K 两类合计是 65,536 B，不能把它们合并成只有一次 Br·Bc·d 的读取。PV 中每个输出维各读一次概率，不能只按 64 个概率值计一次。概率为零时本代码跳过相应 V 读取，但仍先读取 P。

另外，l=0 扫描 Z 和扫描 P 求和各读 256 B；64 个 lane 读取 M 和 Sum 各读 256 B。在四行非空的满块中，这些辅助读取再加 1,024 B，总逻辑消费读取为 74,752 B。每块逻辑 LDS 写入为 K/V 的 9,216 B、Z/P 的 512 B、M/Sum 的 32 B，合计 9,760 B；Q 的 2,048 B 写入只在开头发生。尾部仍填满片上输入槽，但不为无效位置发出全局读取。

这些是程序逻辑读写，不是 bank 服务周期。Q_s 同行元素可能被子组广播；K_s 的同一元素可能被不同子组读取；P_s 也可能广播。广播可以改变物理服务工作，不能回头从已声明的逻辑读取计数中删掉读者。bank 周期须结合生成的标量或向量指令、服务 lane 分组、行距和 32/64 bank 单独分析。增加 padding 也不保证同时改善 Q、K、P 与协作写入。

每个 workgroup 对全局张量的有效请求，忽略 mask/bias、页表、cache 和输出标记时，为 Q 的有效行数·d·4、K/V 的 S·(d+dv)·4、O 的有效行数·dv·4。empty 另写每有效行 4 B。ceil(L/4) 个 workgroup 独立遍历 K/V，所以总请求可能重复；cache 可以减少 HBM 事务，却不是该映射的保证。分页带来页表读取、整数寻址与非连续事务，页表查询是否被合并或复用由实际生成程序决定。

U 总共只有 Br·dv 个 FP32 值，dv=16 时为 256 B；但 m 和 ℓ 在 64 个 lane 中复制，单这两类持久状态就有 128 个 FP32 值，即 512 B。每 lane 的 U 数量最多 ceil(dv/16)，地址、分数、概率、m_new、rescale 和循环临时量另计。这些是逻辑状态，不能直接宣称真实 VGPR 分配或是否 spill。

本基线不需要跨 workgroup 输出通信；LDS 发布、串行行归约和六次每块同步仍有成本。实际驻留同时受 VGPR、SGPR、LDS、线程及 wave slot 限制，还受分配粒度和每组上限约束。来源未给本候选的编译资源和目标 CU 完整配置，不能据容量公式算出实测占用率。HBM、LDS、VALU、指数与同步可能互相覆盖或竞争；不能把各自理想耗时机械相加。

## 条件变化后的保留、调整与放弃

| 条件变化 | 保留的关系 | 调整对象与新增成本 | 放弃或改选条件 |
|---|---|---|---|
| d、dv 增大或不相等 | query 身份、可见集合、在线状态不变 | Q/K/V 容量与每 lane 的 U 增大；重新计装载和地址 | LDS、寄存器或索引超限时缩块、改变分工或选库路径 |
| Bc 超过 16 | key 分块和最大值重标度不变 | 每 lane 持多个 key或多次子块；修改 scratch、归约与 PV 遍历 | 继续使用单个 l 代表全部 key 时该映射已不合法 |
| L 很小 | 函数与 KV 状态不变 | 四行一个 wave 留下空子组，比较更小 Br、合批或 KV 分区 | 空 lane、启动和同步抵消复用时保留更简单路径 |
| wave32/wave64 改变 | 输出与归约集合不变 | 子组数、线程数、写者、屏障参与者重推 | 沿用旧 lane 编号或旧参与集合时拒绝 |
| bank 数或行距改变 | 逻辑地址与所有权不变 | 重新推各指令的访问、广播和冲突 | padding 的容量或转换成本超过收益时撤回 |
| 使用 MFMA | QK/PV 数学与 m/ℓ/U 不变 | fragment 装载、概率转换、布局交接与完成依赖 | 缺合法形状、dtype 或布局证据时保留标量或成熟库 |
| AITER/框架无合法候选 | 模型函数不变 | 回退可能增加转换、工作区和启动 | 不能满足语义或质量约束时拒绝该候选 |
| 异步搬运或预取可用 | 生产、发布、消费和读完关系不变 | 增加缓冲、完成状态及驻留；核对目标支持 | 等待减少却因容量、spill 或转换变慢时降低深度 |
| KV 在主存而非 HBM | 同一位置、mask 与归一化不变 | 比较搬历史、远端访问和在 CPU 计算后传结果 | 交换、主存竞争或计算成本超过收益时改变放置 |

长 prefill 可让更多 query 行重用 K/V，但增加 Br 也增加片上状态并可能降低驻留。小 batch decode 的 L 很小，沿 KV 拆成多个 workgroup 可以增加并行度，同时增加部分状态写读和合并同步。

若分区 c 的非空统计为 (m_c,ℓ_c,U_c)，先取 M=max_c m_c，再计算 ℓ=Σ_c exp(m_c−M)ℓ_c、U=Σ_c exp(m_c−M)U_c，最后 O=U/ℓ。空分区直接略过；全部为空时走空行契约。分区必须互不重叠且覆盖合法集合，统计量必须使用同一分数单位和指数底数。只平均各分区归一化输出，会忽略它们不同的概率质量。

所供 HIP 概述提及 CDNA3/4 的异步批量搬运，但不能据概述推定每个编译目标都提供某个可直接使用的调用，或已经与计算重叠。应核对目标入口、完成条件和生成程序。换成普通加载时，上述槽生命周期仍成立，只是发射、寄存器中转与暴露等待可能不同。

KV 的主存放置还涉及统一地址与物理驻留的区别。地址可被 GPU 使用不证明数据已在 HBM，也不证明无需迁移或同步。若选择 CPU attention，必须比较同一函数的完整计算与 query/结果交换，不能继承 GPU 标量模型的成本；机制边界见相邻共享内存和异构放置章节。

## 诊断：具体反例、竞争解释与反证

行身份可以被低维输入与高维输入以不同方式破坏。旧装载循环若把 load_row 命名成 row，后续直接使用其最终值：d=128 时，每个 lane 的最后一次装载都属于 g2=3，因而四个子组都拿第 3 行做 mask/bias 判断；d=4 时只有 lane 0..15 进入装载循环，其余 48 个 lane 的 row 根本未初始化。

取 L=4、S=2、d=128、Q/K 全零、bias=0、V=[1,3]，令第 0 行只见 key0、第 3 行只见 key1。正确第 0 行输出为 1；如果 Q_s 仍取子组 0、mask 却取装载遗留的第 3 行，则输出为 3。再令所有位置可见、第 0 行偏置为 [ln3,0]、第 3 行为 [0,ln3]，正确输出分别为 1.5 和 2.5；这能单独检出 bias 的行身份错误。Q/K 全零使结果不受点积差异干扰，不能用误差容限解释这两个失败。

写者检查也要超出最终数值比较。dv=16 时，在每个 value 元素写回处同时写 empty，会让同一行有 16 次标记写入；dv=33 时有 33 次，其中有的 lane 写多次。串行 CPU 覆盖会掩盖并发写者问题，必须记录逻辑写事件，验证每个 O[r,u] 和每个 empty[r] 恰有一个写者，并验证标记写者满足 l=0。

另一个语义反例是把不可见位置当 score=0、V=0 的填充项加入归一化。只有一个合法 key、z=−2、V=1 时正确输出为 1；额外加入一个假项后得到 exp(−2)/(exp(−2)+1)≈0.1192。检查必须让假项实际进入分母，而不能只比两个独立指数值。输入填零仅保证安全装载，不能替代可见集合排除。

scratch 的槽位归属也应具体核对。假设一个独立的四行 16 槽 scratch 用地址 g·stride+l：stride=16 时 64 个写者互不别名；错误 stride=8 时四个区间为 [0,15]、[8,23]、[16,31]、[24,39]。相交的是子组 0/1 的槽 8..15、1/2 的槽 16..23、2/3 的槽 24..31，各有 8 槽。对相邻子组 g、g+1，槽 8(g+1)+t 的两个写者是 (g,8+t) 和 (g+1,t)，t∈[0,8)。0/2、1/3 均不相交。

因此这个反例证明了 64 个逻辑写者只占 40 个槽，产生 24 个重复占用；若将该错误行距用于 Z 或 P，发生别名的是对应的逐 key 分数或概率存储。实际保留哪个写值及最终最大值是否受损，还取决于指令与读写次序。本章不以这份地址枚举声称已经模拟了块最大值被覆盖。

| 观察 | 竞争解释 | 可区分的干预与观测 | 反证后的修正 |
|---|---|---|---|
| 行间结果互换，某些 d 才失败 | 装载临时变量泄漏，或 mask/bias 行索引错误 | 固定 Q/K 为零，逐行改变可见集合，再单独改变 bias；枚举进入计算前的 query_row | 行身份正确而结果仍错时，转查归约和概率到 V 的绑定 |
| 数值通过却有标记输出竞态 | 多个相同值写者被串行模型掩盖 | 记录 O 与 empty 的写事件及 lane，扫描 dv=1/16/17/33 | 写者唯一后仍失败，不能继续归因于标记竞争 |
| HIP 接受调用但部分 shape 不正确 | 函数适配错误或实际 dispatch 不同 | 固定输入，记录后端、编译目标、页表单位与 mask 对齐；对照独立参考 | 多个后端都错时，先检查共同索引和数学定义 |
| K/V 请求减少但总时间变慢 | LDS 服务、spill、驻留或同步增加 | 查生成程序、LDS 访问、VGPR/local 交通和时间线；分别改变行距与临时量寿命 | 没有 spill 且消除冲突仍无收益时，降低对应解释权重 |
| 同一算子库有时快有时慢 | shape 命中、预打包、转换或回退不同 | 分开准备、转换、kernel 和输出可消费时刻，记录候选身份 | 同一路径且准备相同时，改查资源竞争与访存 |
| wave64 比 wave32 慢 | 空 lane、行数、bank 访问或同步组织不同 | 对各自合法映射比较活跃元素、资源和服务事件 | 同时改变工作量时不能只归因于 wave 宽度 |
| 更多缓冲没有降低时间 | 未发生重叠，或重叠收益被容量成本抵消 | 检查发出、完成、最后读者和覆盖时间线，并记录驻留与 spill | 等待确实下降却更慢时，优先检查新增资源成本 |

性能实验先固定模型函数、输入、dtype、质量要求和计时边界，再比较 Br、Bc、LDS 行距、wave 分工或预取深度。改变 tile 会同时改变复用、任务数和资源，不能把每次变快都归因于单个计数器。准备、转换与 kernel 的计时范围也不能混用。以上是待实施的设备实验，不是本库已取得的 GPU 结果。

随附 tools/check_k_hw_006_full.py 是确定性、只读、离线的 Python 标准库候选检查。它实际执行协作 Q/K/V 装载、每 lane 的分数与在线更新、非整页定位以及输出写事件；使用直接读取原始逻辑输入的整行稠密参考，同时检查每块前缀的 m、ℓ、U。它覆盖小 d 与 d=128、不同 value 维、无效 query 子组、尾块、首尾空块、全空行、S=0 和 L=0，并注入装载遗留行、重复 empty 写者、不可见项进入分母、反向重标度及错误 scratch 冲突配对。成本检查按模型访问计数核对满块 Q/K/P/V 读取和两类指数。

这份 Python 脚本本轮未执行，不继承旧脚本的通过结果。本轮另用 JavaScript 独立枚举确认了两种 d 的变量生命周期、四种 dv 的旧标记写次数、scratch 具体相交关系，以及容量、主要逻辑读取和标量反例。两者都不是 GPU 测量：不能证明真实 barrier 可见性、bank 周期、MFMA fragment、异步搬运、dispatch、HBM 事务、编译寄存器、驻留或性能，也不证明模型质量和 Agent 使用效果。
