# K-FW-006：Attention 执行：数学语义、分块归约、低精度与硬件数据流

Attention 的设计从数学语义进入数据流：每个 query 对哪些 key 可见、Q/K/V 的几何、K/V 的状态表示，以及准备与执行怎样分段，共同定义输入与依赖。分块、工作划分、异步和低精度分别改变并行度、读取、驻留与误差；本章从算法推到成本和可否定的实验预测，性能排名只对确定的运行点成立。

## 问题、不变量与设计轴

问题：引擎持有的是逻辑状态——每个请求的绝对位置、有效长度、页表或偏移、head 映射、量化尺度——而 kernel 接受的是张量、索引数组与标志。要回答的是：怎样把逻辑状态变成 kernel 输入，每次调用付出哪些工作，哪些工作能在多次调用间摊销，换一个 kernel 时什么必须原样保持。

任何解都要满足的不变量：每个 query 行实际读取的 key 集合恰好等于模型定义的集合，包括因果对齐、窗口、填充与自定义规则，多读或少读都是另一个函数；query 长度与 KV 长度、Hq 与 Hkv 的映射、QK 维与 VO 维各自独立表达，不能靠相等假设省略；每个逻辑位置的 K、V 与量化尺度一致，同一槽位的并发更新具有明确的次序或合并语义，不能让无序覆盖改变状态；scale、softmax 稳定化、累加精度与分区合并在约定容差内保持同一函数；拆开计算的 key 子集互不重叠且并集完整。

成本项：转换（gather、转置、dtype 变换、mask 打包）、准备（消费 metadata、划分工作、选择实现）、执行（kernel 本身、输出与统计量的分配、事后缩放）、驻留（workspace、metadata 缓冲、布局副本）、同步（host 读取设备侧长度、图外提交）。每一项都要问它在哪个频率上发生：每任务、每模型加载、每形状、每层、每 batch 还是每 decode 步。

设计轴与已有方案所在的点：状态表示——稠密 padded、ragged 偏移、分页索引，padded 简单且图友好但付无效行，分页用间接寻址换容量；准备与执行的边界——每次调用全部重算、按几何缓存计划、把工作划分写成固定缓冲中的数据，摊销边界本身是设计变量；布局——页内 token 优先或 head 优先，K/V 合并或分离，生产者按消费者布局写出、消费前转换或 kernel 直接读生产者布局；可见性表达——布尔 mask、结构参数（因果、窗口）、块稀疏索引，结构参数最省也最弱；分区与合并——不拆，或沿 KV 拆再合并统计量。轴上未列点同样合法；下面各节按轴展开已知点的前提与代价。

## 先写出共同函数

对一个请求和一个 query head，设 Q∈ℝ^{L×dₖ}、K∈ℝ^{S×dₖ}、V∈ℝ^{S×dᵥ}，输出 O∈ℝ^{L×dᵥ}。L 与 S 不必相等，dₖ 与 dᵥ 也不必相等。给定缩放 a（通常为 1/√dₖ）、位置偏置 bᵢⱼ 和合法 key 集合 Aᵢ，定义 zᵢⱼ=a·QᵢKⱼᵀ+bᵢⱼ，pᵢⱼ=exp(zᵢⱼ)/Σ_{k∈Aᵢ}exp(zᵢₖ)，Oᵢ=Σ_{j∈Aᵢ}pᵢⱼVⱼ。不可见位置不进入分母。这里讨论推理且不施加 dropout；若模型需要随机丢弃，概率与随机流是另一个明确契约。

分组查询还需要一个 query head 到 KV head 的映射 h。常见均匀分组令每 Hq/Hkv 个 query heads 共享一组 K/V；整除是这种映射的前提，不是所有可能 head 映射的数学必然。物理页号、压缩布局和稀疏索引只在保持相同 Aᵢ、h 和内容时属于等价表示。删除合法 key 则改变模型函数。

问题出现于中间矩阵：直接计算会生成 L×S 个分数和概率，而最终只需要 L×dᵥ 个输出。长历史放大临时驻留与重复读写；短 query 又使按 query 切分的并行度不足。可用的片上存储、数据重用与并行任务数共同决定算法组织，不能只按 FLOPs 判断。

实现选择可以放在运行时分派、编译/调优或显式计划中；一条实现也可以同时采用几种方式。框架算子提供统一语义并根据条件分派，调用方仍需核对可见性和实际路径；融合实现控制数据流但可能要求特定几何；准备/执行分段可摊销 metadata 工作，也引入计划有效性与驻留成本。它们是可组合的设计轴，不能仅由库名推断成本。框架语义实例见 [S-SDPA](../sources/S-SDPA.md)。

## 从零实现时的算法骨架

下面给出一种精确稠密 Attention 的分块表达，不排除其他等价算法。先固定合法集合与有限的可见分数；输入含 NaN 或正无穷时要另行约定处理。为使空行行为可检查，本节示例规定无合法 key 的行输出零并标记为空；这是本例的契约，不能据此推断任意接口都采用它。

```pseudocode
输入：Q、K、V，缩放 a，位置偏置，合法集合 A，每块大小 Br、Bc
对每个 query 块，载入 Q；逐行初始化最大值 m←−∞、质量 ℓ←0、加权和 U←0
    对每个 K/V 块，按逻辑位置或页表载入所需 K、V
        计算 z←a·QKᵀ＋偏置，仅保留 A 中的位置
        对本块至少有一个合法 key 的行：
            m新←max(m，本块合法 z 的最大值)
            r←exp(m−m新)；首次非空块时 r←0
            P←exp(z−m新)，非法位置的 P←0
            U←r·U＋PV；ℓ←r·ℓ＋每行 P 的和；m←m新
        本块没有合法 key 的行保持原状态
    ℓ>0 的行输出 O←U/ℓ、LSE←m＋ln ℓ
    ℓ=0 的行输出零并标记为空，LSE←−∞
```

不变量是：处理完任意一组 key 后，m 是这组合法分数的最大值，ℓ=Σexp(z−m)，U=Σexp(z−m)V。新块改变 m 时，旧 ℓ 与 U 同乘 exp(m旧−m新)，于是旧贡献与新贡献仍处于同一尺度。最后 U/ℓ 恢复整体 softmax。只保存分块中间量，避免将 L×S 矩阵写入设备主存；浮点计算仍受归约顺序和精度影响，数学等价不表示逐位相同。

按单个 query head、Q 在外层并忽略 cache 命中，K/V 重读字节约为 ⌈L/Br⌉·S·(dₖ+dᵥ)·b，b 是输入元素字节数；另计 Q 读取、输出写回、索引和统计量。GQA 跨 head 复用需要另建共享映射，不能自动把这个单 head 公式乘 Hkv。Br 增大可减少遍历次数，却增加 Q、FP32 U、分数片段与多级缓冲的片上需求，进而影响驻留任务数或引发 spill。将 K/V 置于外层则改变哪些状态需要反复写回；循环顺序是存储和并行度的交换。

decode 的 L 很小时，可以把合法 K/V 切成互不重叠的 C 个分区；每区使用同一算法，保留归一化输出和 LSE，再按下一节的合并关系得到最终输出。C 增大会增加可调度任务，也增加 C·L·dᵥ 量级的部分输出与统计量、合并读取和提交成本。C=1 是合法候选；分区数应由真实并行度与完整调用成本决定。按长度估计任务成本并做最长任务优先分配，是 [FlashInfer 论文](../sources/S-FLASHINFERPAPER.md) Algorithm 1 的一个实例，其固定工作区上界依赖该算法的具体划分规则，不能外推到任意切分。

矩阵乘、softmax 与搬运之间还可建立流水。只有硬件允许相关指令异步推进、且缓冲生命周期满足依赖时，重叠才能实现；更深流水会延长分数与部分输出的存活时间。寄存器、共享存储和驻留任务数可能使收益反转，见 [GPU 流水](../hardware/gpu-kernel-pipelines.md) 与 [S-FLASHATTENTION3](../sources/S-FLASHATTENTION3.md)。

分页使逻辑 K/V 块经页表定位到物理块，并要求处理页边界和最后一页的有效长度；物理页大小与计算 tile 不必相同。分页控制分配碎片并支持共享，代价包含索引、非连续事务及可能降低的向量化效率。[PagedAttention](../sources/S-PAGED.md) §7.1 在图 18 所示设置与 FasterTransformer 基线的比较中报告 kernel 额外开销；该数字只属于那个比较。共享前缀可通过读取复用或独立计算后合并复用，不保证无需额外 metadata 或合并缓冲。

[FlashAttention](../sources/S-FLASH.md) 定理 2 在其二级存储模型、N×d 输入与 d≤M≤Nd 条件下给出 Θ(N²d²/M) 次元素级 IO；M 是可容纳的标量元素数，换成字节要统一元素精度。其命题 3 排除在整个 M 区间上一致达到更低阶 IO 的算法，没有证明每个固定 M 上的参数化下界，更没有证明某个现成 kernel 对任意硬件最优。

## FlashAttention-1、2、3 分别解决什么问题

它们计算相同的 Attention 数学函数，但针对不同的成本改写数据流。下面按前向推理展开；数学等价不保证不同有限精度实现逐位一致，FP8还引入额外量化误差。

这里CTA指协作线程块；warp是协同执行的一组线程（这里的NVIDIA硬件为32线程），FA3所用Hopper warpgroup由4个连续warp组成。

| 路径 | 为什么需要它 | 具体改变 | 新的代价与条件 |
|---|---|---|---|
| FlashAttention-1 | 完整分数与概率矩阵的主存读写/驻留很大 | 分块、融合与在线 softmax，避免写出 L×S 中间量 | 片上容量、重读、归约和工作划分仍限制效率 |
| FlashAttention-2 | IO减少后，非矩阵操作、并行度不足和warp通信仍耗时 | 推迟输出归一化；沿query块增加CTA；以sliced-Q减少warp间输出合并 | tile大小、K/V重读、寄存器与驻留任务数的交换 |
| FlashAttention-3 | Hopper可异步搬运/矩阵计算，但同步时序留下空档 | 生产者/消费者、跨warpgroup乒乓、消费者内部GEMM/softmax流水；FP8布局与精度设计 | 额外分数/概率状态、同步与代次、架构要求、量化误差 |

[FA2论文](../sources/S-FLASHATTENTION2.md)与[FA3论文](../sources/S-FLASHATTENTION3.md)是独立来源，不能只靠某个实现仓库的 README 代替。一个实现可以组合这些设计，也可以选其他数据流；版本号不决定它在当前运行点更快。

## FlashAttention-2：少做归一化，并重新划分工作

前文的 U=Σexp(z−m)V 是未归一化加权和。若每个块都把 U/ℓ 写成归一化 O，下次又恢复旧贡献并除新分母，会反复支付标量缩放/除法。FA2 §3.1 保留 U，只在最后做一次输出归一化；最大值改变时的 r·U 与 r·ℓ 仍不可省略。这不减少 QK/PV 的主要乘加，却减少吞吐相对较低的非矩阵工作。

FA2 §3.2 将独立 query 行块交给不同 CTA。假设每个 query head 独立调度，则任务数由 batch·Hq 扩展为约 batch·Hq·⌈L/Br⌉。例如L=8192、Br=128提供每head64个query块；它们输出行不重叠，前向无须跨CTA合并。更大Br能重用更多K/V，也会减少任务数、增加片上状态；decode只有一行query时，这条轴无法独自提供64份并行工作，需要另看KV分区。

FA2 §3.3 则改变 CTA 内部归属：sliced-K 让多个 warp 对同一 query 行计算不同 key 子集，产生需要合并的输出；sliced-Q 让各 warp 拥有不同 query 行，共享 K/V、各自维护 m/ℓ/U，省去这种输出合并。

```pseudocode
把当前 query tile 的行分给各 warp，建立唯一的输出行归属
共同加载本次需要的 K/V tile，等待可消费
每个 warp 对自己的行更新分数、m、ℓ、U
确认所有读取者结束后复用 K/V 缓冲，继续下一块
各 warp 对自己的输出行做最终归一化并写回
```

这里省去的是跨 warp 的部分输出归并，不是所有 barrier。矩阵指令对 fragment 的要求、共享缓冲就绪、尾行和寄存器预算仍须满足。对照 sliced-Q 与 sliced-K 时，应记录共享存储事务、同步、寄存器与完整时间，而不只比较主存流量。FA2在A100上的论文结果不能直接外推成当前设备、所有长度或decode的加速比。

## FlashAttention-3：用异步时序重叠搬运、矩阵乘和 softmax

FA3在Hopper上把加载交给生产者warpgroup，把矩阵乘和softmax交给消费者。生产者只在缓冲可覆盖时发出TMA加载，完成后发布就绪；消费者在数据就绪后发出WGMMA，在最后读取完成后释放对应代次。多个消费者共享同一槽时，任一消费者提前释放都可能破坏另一方的输入。

跨消费者的乒乓调度与消费者内部流水是两条不同的重叠轴。乒乓让一组做softmax时另一组执行矩阵乘；内部流水则让当前PV与下一块softmax重叠。其关键不是省略等待，而是把等待推迟到真正的消费者依赖处：

```pseudocode
启动：计算并等待第一块分数，得到P当前、m、ℓ，初始化U
每轮：
    还有下一块时，发出下一块QK，保留独立分数缓冲
    发出当前PV对U的累加，不立刻等待
    若还有下一块，等待下一块QK完成，计算下一块P、缩放r及新的m、ℓ
    等待当前PV完成
    若还有下一块，按下一块r缩放U，并交接到下一块
收尾：等待最后PV完成，再按最终ℓ归一化
```

空行规则与前文一致。时序要求当前V与下一K可同时存活，并让当前P在PV读完前不被覆盖；成对环形缓冲需足够槽位，或用独立K/V缓冲提供等价关系。只有一块时只做启动与收尾，两块时应恰有两次QK和两次PV，不能照搬不完整的示意循环边界。

两级流水多保存一份Br×Bc的FP32分数。以64×64为例，它增加16 KiB逻辑片段；128线程均摊时平均额外32个32位寄存器，还不含U、概率、地址与barrier。更深流水可能隐藏更多等待，也可能因寄存器、spill和驻留下降而反转。真正的重叠需要检查生成指令与时间线，源级异步调用本身不是证明。

FP8路径还要处理V与矩阵操作数布局、块尺度和异常值。对Q/K施加同一正交变换可保持未量化点积，却不消除量化误差；不同块的PV贡献必须恢复到共同尺度再累加。布局转换、额外状态与质量检查都应计账。没有TMA/WGMMA的硬件可以借鉴依赖组织，不能照搬其指令与性能数字。

## 异步缓冲：发布、读取、释放与代次

数学状态 (m, ℓ, U) 与执行状态不能互相代替。令物理槽 s 保存逻辑块 j，代次 g 随该槽的重用递增；完成事件至少绑定 (s,g,j,操作)。环形位置相同并不表示内容相同。这里给出一种便于验证的协议，具体 barrier 和指令可以不同。

| 对象 | 可消费条件 | 最后读者/完成条件 | 允许的下一次覆盖 |
|---|---|---|---|
| Q tile | Q 的加载和布局转换完成 | 使用它的全部 QK 完成 | 本 query tile 的计算结束 |
| Kⱼ | 本代加载完成并发布 | 全部有关消费者的 QKⱼ 完成 | K 槽释放后 |
| Vⱼ | 加载及所需转置/排列完成并发布 | 全部有关消费者的 PVⱼ 完成 | V 槽释放后 |
| Pⱼ | 对应分数、mask、最大值尺度与概率转换完成 | PVⱼ 完成其读取 | 另一个 P 写者获得该槽后 |
| U | 上一项 PV 累加完成 | 本次重标度或最终归一化完成 | 下一项更新按顺序开始 |

K/V 若共用成对槽，释放条件是两者最后读者的并集；若分开分配，可以分别释放。共享给两个消费者时，第一方完成不能替第二方释放。数据复制完成后若还有转置，原始字节已到达也不代表消费者所需布局已就绪。

```pseudocode
生产者取得空槽及新代次，绑定逻辑块；此时禁止消费者读取
发出加载，等加载和布局处理完成，再发布本代就绪
消费者核对槽、代次、逻辑块；就绪后才发出使用它的计算
每个消费者在最后一项异步读取完成后登记本代结束
全部必要读者结束后释放本代；下一写者才能覆盖并递增代次
迟到的旧代完成事件不得改变新代的所有权
```

这套协议约束的是依赖，不规定用哪一种线程分工。弱化任一条件都能构造反例：提前发布让 QK 读到未完成 K；只等 QK 就重写成对槽会破坏仍在读取 V 的 PV；把旧代完成记入新代会过早释放新数据。将加载故意延迟、交换独立完成事件、缩到1/2个槽并跨多次回绕，是有限状态模型和真实实现都可采用的检查。符号模型只能检查声明过的事件关系，设备内存可见性和硬件 barrier 语义还要按所用平台验证。

## 一个完整的 warp 映射：16×16 分块与显式交接

下面构造一个便于独立实现、而非声称高性能的前向实例：一个CTA只有一个32线程warp，一个query head，dₖ=dᵥ=16，Br=Bc=16，输入FP16、矩阵乘累加与行统计为FP32。Q/K/V按行连续；每个CTA负责最多16行query，依次消费全部KV块，不做跨CTA归约。矩阵操作采用[CUDA 12.8.0文档的16×16×16 warp矩阵契约](../sources/S-CUDA-CAPABILITY.md)，不要求TMA/WGMMA。这里不是把逻辑矩阵大小直接当作线程数。

先规定物理缓冲。共享存储中Q、K、V、P各占16×16×2=512字节，分数Z与本块加权值T各占16×16×4=1024字节，合计4096字节；六个基址各按32字节对齐。半精度矩阵行距16元素，FP32矩阵也取16元素，分别满足文档要求的8/4元素倍数。全部warp线程以相同参数、相同控制流参加矩阵加载、乘加与写回；数据就绪及复用处还有显式warp内存同步，不能只依赖“恰好是同一个warp”。

全局地址先从逻辑坐标推出。本例还规定Q/K/V首址按32字节对齐；带存储偏移的view不满足时，要改用合法加载并重新计算交通。query块起点q₀、KV块起点k₀，元素Q[r,c]的字节地址为Q基址+2((q₀+r)·16+c)，K/V则用k₀替代q₀。完整块可按两个FP16合成一个32-bit字搬运：lane λ在u=0…3时负责字w=λ+32u，对应行⌊w/8⌋、列2(w mod 8)及下一列；源字节偏移为4w。每轮32个lane搬128个连续字节，在32字节边界对齐的访问模型下需要4个32字节请求段，四轮搬完512字节。它是请求合并的账，不是实际设备主存字节保证。共享字w的bank为w mod 32，因此这种标量32-bit搬运每轮不冲突；矩阵加载指令内部的访问仍需单独检查。[访存与bank模型](../sources/S-CUDA-BEST.md)给出这里的依据。

QK不需要先把K真的转置：A按row-major解释Q，B按col-major解释同一份行连续K，便有B[c,j]=K[j,c]、地址为K共享基址+2(16j+c)。将B误当row-major会计算另一个矩阵。将零累加片段与A/B做矩阵乘，得到16×16的FP32分数，按row-major写到Z。

矩阵fragment内部的“第几个寄存器对应哪一行列”在这个API契约中未公开保证。本例不猜它，而是经Z/T的有定义地址重新分配所有权。令t=0…7，lane λ拥有线性位置i=λ+32t，即行r=2t+⌊λ/16⌋、列c=λ mod 16；32个lane恰好覆盖两行，八轮覆盖全部16×16元素。在Z/T上的每轮32-bit访问正好覆盖32个bank。若改用i=8λ+t，虽然仍覆盖整个矩阵，每轮却只有4个bank服务32个不同字，产生8路冲突；覆盖正确不代表访问高效。

同一个16-lane子组拥有同一行、不同列。它以异或距离8、4、2、1交换并归约，分别得到行最大值和指数和。每个lane保留八行的m[t]、ℓ[t]以及自己八个输出元素U[t]；同一行的m/ℓ在16个lane中复制，而U没有复制。这个选择简化交接，却使持久逻辑状态达到每lane24个FP32值、全warp3072字节，尚未计矩阵fragment、地址与临时量，不能当作编译后的寄存器数。

```pseudocode
warp共同加载Q；同步；每lane初始化八组m←−∞、ℓ←0、U←0
对每个KV块：
    warp共同加载K/V；有效元素按地址读，缺失元素填零；同步
    全warp执行16×16×16矩阵乘Q·Kᵀ，零累加；将FP32结果写Z；同步
    对t=0…7，所有lane都参加对应16-lane归约：
        取得自己拥有的Z[r,c]，在真实分数单位加scale/偏置，按绝对位置排除非法key
        归约本行块最大值；本块全空时保留m/ℓ/U并令概率为零
        否则计算m新、r；首次非空取r←0；求高精度P与行和
        ℓ[t]←r·ℓ[t]＋行和；U[t]←r·U[t]；m[t]←m新
        将P就近舍入为FP16；相邻lane交换两个值，由偶数lane打包写一个共享字
    同步；全warp加载P、V，零累加计算T←P·V；按row-major写T；同步
    各lane按i=λ+32t取得T，执行U[t]←U[t]＋T[r,c]
    同步后才允许覆盖本轮K/V/P/Z/T
ℓ>0时各lane按同一坐标写出U[t]/ℓ[t]，否则写显式空行结果；只写有效query行
```

这里“高精度P构成分母、FP16 P参加PV”是一处明确近似，验证参考必须包含这次转换；FP32 accumulator不等于整条算法为FP32。矩阵累加顺序与指数实现的硬件误差另行验证。缺失key即使已填零，仍要从softmax排除；末块一个32-bit字只有一个有效FP16时，应分别保护两半，不能整字越界读取。无效query行继续参加warp集体操作但不写结果；不能让一部分lane提前返回。

完整块每轮两次矩阵乘共约16384 FLOPs，K/V请求1024字节，Q在本CTA开始时另读512字节。按上述对象各一次读写计，K/V写共享、Q/K矩阵读、Z写读、P写、P/V矩阵读、T写读合计7680字节逻辑片上交通；实际fragment复制与事务须看生成程序。这暴露了一个可改进点：显式交接换来了清楚的元素归属，也多付Z/T写读与重复统计状态。可比较有证据支持的指令布局、不同lane归属或多warp组织来减少它们；每种改动都应重新证明地址、行归约、完成依赖和数值参考。这个同步小tile实例是可推导的起点，不是FA2/FA3的最佳实现，也没有目标GPU实测。

## FP8：从量化输入到输出的完整尺度路径

本节在 [FA3 §3.3 的块量化、布局转换与非相干处理](../sources/S-FLASHATTENTION3.md)基础上，构造一条尺度明确的前向算法示例；不声称复述其全部实现细节或提供最佳量化策略。它近似原高精度 Attention，必须按允许的误差与模型质量验收。先考虑有限输入，推理无 dropout，每个计算块不跨越不同 Q/K/V 量化尺度；跨越时要拆开处理或显式按分组恢复单位。

定义一个量化器。F 是选定有限格式的最大正数；须同时确定可表示值集合、是否保留次正规数、舍入与饱和规则。对高精度块 X，取 t=max|X|，sX=t/F（全零块取1），X₈=round_F(clip(X/sX,−F,F))，解码为 X̂=sX·X₈。本例使用就近舍入、平局取偶和有限饱和；这些是示例选择，不是“FP8”三个字自动确定的语义。scale 的保存精度、溢出及下溢也属于真实实现的契约；若计算出的非零块尺度不能表示为有限正数，应采用已定义的更宽尺度/下限策略或拒绝，不能静默除以零。分数及统计量的有限数值域也需验证。

若采用非相干处理，先在位置变换等模型规定的 Q/K 操作之后，对 Q 和全部对应 K 使用同一个正交 M，再量化。可用归一化 Hadamard 与固定随机符号对角矩阵构造 M；相应维度不支持该构造时可选择单位矩阵或另一个已验证的正交变换。M 的身份应随 head/模型配置与缓存保持一致；跨 decode 步更换 M 而不转换旧 K 会改变点积。不能随意把 M 移到 RoPE 前面，因为两种变换未必可交换。V 不参与这一点积恒等式，无须因此跟随 Q/K 旋转。

```pseudocode
输入：高精度 Q/K/V、可见性/偏置、a、量化格式与规则、可选固定正交 M
在规定位置变换之后得到 Q′←QM、K′←KM（不用时 M 为单位矩阵）
分别按块生成 (Q₈,sQ)、(K₈,sK)、(V₈,sV)，保存量化块与逻辑位置映射
对每个 query 块初始化 m←−∞、ℓ←0、U←0
    对每个 K/V 块，先按 sQ·sK 恢复分数单位：Z←a·sQ·sK·(Q₈K₈ᵀ)＋偏置
    用合法集合排除不可见位置；空块保持状态，首次非空块取 r←0
    计算 m新、r←exp(m−m新)、高精度 P←exp(Z−m新)
    从这个高精度 P 更新 ℓ←r·ℓ＋rowsum(P)
    对本块 P 逐行量化得到 P₈、每行尺度 sP，非法位置保持精确零
    等旧 U 的异步写依赖完成，更新 U←r·U＋diag(sP)·(P₈V₈)·sV
    更新 m；P/V 的布局与代次按最后读者规则交接
按最终 ℓ 归一化 U；空行采用显式契约，按输出格式舍入写回
```

这里 ℓ 使用量化前的 P，而分子使用 P̂=P₈sP，两者因舍入不再构成原精确概率加权和；这是明确的一处近似，不能把 numerator 的码字之和当作 ℓ，也不能忘记 sP 或 sV。不同分区仍要携带相同 Z 定义下的 LSE，与其近似分子保持同一最大值尺度。改变tile或分区若改变了量化分组，就会改变解码值或概率近似；验证纯归约重排时应固定这些分组，不能把相同原始Q/K/V当作相同数值参考。偏置应在 QK 恢复到真实分数单位后加入。mask 不能用某个随意有限负值代替而又声称覆盖任意输入。

PV 的布局可以用一个简单恒等式核对：对 key 轴排列矩阵 Π，同时采用 PΠ 与 ΠᵀV，乘积仍为 PV；只排列 P 或只排列 V 则改变函数。它解释了为什么为匹配指令 fragment 而重排概率列时，V 的行归属也必须一致。物理转置/排列改变的是存取组织，不改变逻辑 key、mask 与 scale 的绑定。

持久 KV 还多一个更新问题。本算法先量化已给定的块，不自动解决流式追加：若新 token 改变块的 sK/sV，只更新 scale 而保留旧码字就会改变全部旧值。一种合法设计是保留高精度可变尾块，满块后封存量化块及尺度；消费尾块时临时量化，增加尾块驻留和转换成本。另一些设计可以采用固定尺度或受控重编码，但须说明误差累积、并发读者与代次，不能将“按块量化”直接当作完整缓存更新算法。

误差可以分层定位：A 用原高精度 Q/K/V 做稠密参考；B 用解码后的 Q̂/K̂/V̂ 做稠密参考，A/B 差异反映输入量化及所选变换；C 用同一解码输入和块划分再量化 P，B/C 分离概率近似；真实 kernel 对照 C 检查额外算术、布局和同步差异。B/C 的对照需保持数学分数计算相同，真正硬件 QK/PV 的有限精度由最后一项覆盖。

对一行，若高精度概率为 p、值为 V，实际概率系数为 p̃、解码值为 V̂，则任意输出分量的误差不超过 Σ|p̃−p|·|V|＋Σ|p̃|·|V̂−V|，还需加上实际累加/输出舍入误差。这个三角不等式解释了为什么只看 Q/K 的均方误差不足以判断输出质量。高精度输入分支、输入量化分支、概率量化分支和真实 kernel 分别记录误差，随后再验证模型层与任务质量；单个格式没有通用的合格误差常数。

## 从形状推到工作、流量、驻留和时间

为把前面各项串起来，先取同长的非因果 batch：B 个请求、Hq/Hkv 个 head、query/KV 长 L/S、维度 dₖ/dᵥ，输入每元素 b 字节。主要乘加 F≈2BHqLS(dₖ+dᵥ)。因果/稀疏情形先用真实参与的 query-key 对数替代 LS；如果实现仍遍历被屏蔽的 tile，实际工作和字节可能更大。指数约随有效分数数增长，每轮 U 重标度约随 query 行数、K/V 轮次和 dᵥ 增长，不能将它们按矩阵峰值折算。

令 g=Hq/Hkv；考虑一类同 KV head 内联合消费 R 个 query heads 的设计，R 整除 g。若每个 CTA 处理 Br 行、一个 head 组及一个 KV 分区，任务数约 G=B(Hq/R)⌈L/Br⌉C。它以更多输出/分数驻留换 K/V 共享。若每个 K/V 块只在该组内部加载一次、各分区不重叠，忽略 cache 和尾部浪费，消费者请求的 K/V 字节为 Dreq≈B(Hq/R)⌈L/Br⌉S(dₖ+dᵥ)b。

持久 KV 唯一数据量则是 Dstate=BHkvS(dₖ+dᵥ)b。R=1 时 Dreq 可能是 Dstate 的 g⌈L/Br⌉ 倍；R=g 能消除组内重复，但不能自动消除 query 块间重读。Dreq 不是物理设备事务：L2 命中可减少设备主存字节，非合并访问、页尾、索引、spill 可增加它。应分别核对唯一驻留、逻辑请求、L2/设备主存事务。沿 KV 增加 C 在理想分区中不改变其总读取集合，但会改变任务大小、命中、实际事务与启动效率。

若分区输出为 FP32 的 O 和一项 FP32 LSE，暂不计空行标记、对齐和索引，C>1 的部分结果容量为 E=BHqLC(dᵥ+1)·4 字节，额外写入和合并读取约2E；最终输出另计。C=1 可直接输出，无须强行分配此区。若存的是 U/m/ℓ，则按那种表示重新计账。CTA 内共享的通信、经设备主存的跨 CTA 合并、host/device metadata 传输是不同边界；本节单设备算例没有网络通信，多设备方案另加其真实链路与同步。

片上账也由选择决定：仅 U 就有4RBrdᵥ字节，m/ℓ另有8RBr字节；一份 FP32 分数片段有4RBrBc字节。K/V 的 n 级输入缓冲主项为 nbBc(dₖ+dᵥ)，另计 Q、概率、转置区、地址与 barrier。每个对象放寄存器还是共享存储要单独分配，不能把全部逻辑字节都算进同一个池。实际寄存器分配、对齐和复制由生成程序核对。R 增大不意味着计算减少；Br、R 和级数同时增加，可能让合法域或驻留先触顶。

有顺序依赖的一条完整调用可写为 T≈T准备/n复用＋T转换＋T主计算＋T合并＋T暴露同步。只把确实发生、且未计入前项的等待算入最后一项。主计算的资源下界可由 max(F/P有效,D设备主存/B有效,非矩阵需求/相应速率) 辅助分析；启动、尾部、工作分布与资源争用还要校准。有重叠时沿依赖关键路径计时，不能把各 kernel 总时长与同一段等待重复相加。能力参数取得方法见 [GPU 表征](../tools/gpu-characterization.md)。

## 一个完整的 GQA decode 取舍算例

以下全部是设定值，用于复算，不是设备实测。取 B=1、Hq=32、Hkv=8、L=1、S=8192、dₖ=dᵥ=128、FP16 输入，均匀分组。KV 唯一驻留为32 MiB；独立 query head、无 cache 复用时请求128 MiB。主要乘加为134,217,728 FLOPs，增加 KV 分区不减少它。

先固定 R=1、Br=1；容量取足够，工作无重叠。假定可持续设备主存带宽1 TiB/s，且该形态的并行利用系数 U(C) 在 C=1/4/8/16 时分别为0.25/0.75/1/1。这是专为算例给定的曲线，真实曲线必须测量，不能由任务数直接断言。准备平均8 μs，主 kernel 启动3 μs；C>1 另有合并启动3 μs，合并读写带宽也设为1 TiB/s，其他项假定不主导。于是主流量项为128 MiB/(1 TiB/s·U(C))。

| C | CTA数 | 部分结果 E | 主流量项 | 完整调用估计 |
|---|---:|---:|---:|---:|
| 1 | 32 | 0 | 488.281 μs | 499.281 μs |
| 4 | 128 | 64.5 KiB | 162.760 μs | 176.881 μs |
| 8 | 256 | 129 KiB | 122.070 μs | 136.311 μs |
| 16 | 512 | 258 KiB | 122.070 μs | 136.551 μs |

这组条件下，C从1增至8补足并行度，而16已没有主项收益，却多付部分结果成本。若原来的U(1)已为1，C=1估计133.070 μs，会优于分区路径；若更大的 batch 已提供足够任务，原来的选择就可能反转。若工作区成为容量限制，少0.24 μs并不能自动胜过更少驻留。模型的作用是给出可否定预测，而不是把C=8写成经验常数。

再考虑 R=4 的组内 K/V 共享。C=1 时任务数变成8，请求字节降至32 MiB，U/分数状态变大。不能复用 R=1 的 U(C) 曲线后直接宣称4倍加速。需要比较新任务数、驻留、实际设备主存事务及完整调用。长 prefill 若 L=8192、Br=128，则 R=1、C=1 已有2048个任务，R=4为512个；沿query并行与沿KV分区解决的短缺可能已不同。这里给出的是另一个数据流选择，未要求沿用现有引擎的 head 分工。

同样方法可接入 FP8：减少的是哪些跨边界字节，新增的是量化、正交变换、转置和误差检查中的哪些工作？前置步骤已融合也不等于额外状态与指令不存在；若数据在每步被重复转换，须按每步计费。先还原成本发生频率，再比较精度和性能。

## 这几类优化何时应该保留、调整或放弃

如果主存事务已经下降而时间仍长，检查非矩阵指令、CTA数量和warp通信，才能判断是否受FA2所针对的问题限制。如果矩阵单元与softmax交替空闲且有异步能力，再看FA3的重叠；若等待减少却出现spill或驻留下降，缩小tile或减少级数可能更好。短query的并行度、长历史流量、分页间接寻址与准备成本也可能先成为瓶颈。

原论文v1的部分打印式把旧U写成反向缩放。这里坚持由定义得到的 U新=exp(m旧−m新)U旧+PV：两块分数0、2，V为1、0时结果应为0.1192；错误放大会越出[0,1]。对1、2、3块和尾块先核对数学与事件次序，再判断异步路径是否带来真实收益，避免把版本名称或论文排版当作等价性证据。

## 非等长 causal 是一个具体反例

设 Q 长 2，K 长 5，Q 对应历史尾部位置 3、4。期望第一行可见前 4 个 K、第二行可见 5 个。常用接口对非方形因果 mask 有两种对齐约定：右下对齐给出期望结果；左上对齐让第一行只看 1 个、第二行只看 2 个。同一个布尔参数在两类接口上含义不同，直接互换会静默改变函数。应以绝对位置关系构造等价 mask，或选择明确支持相应对齐的接口。

另一个常见差别是布尔 mask 的 true 含义：不同算子可能分别表示保留或屏蔽。dropout 概率也可能由算子参数直接控制，不能假定外部推理模式自动将它清零。模型语义优先于同名参数。

## 用契约表组织选择

| 场景 | 必须能表达的内容 | 决定额外成本的项 |
|---|---|---|
| 稠密 prefill | 因果/非因果、变长 query | padding、tile、是否物化 mask |
| 分页 decode | 页表、tail、Hq/Hkv | 准备段、间接读取、split-K |
| Cross-attention | 独立 Q/KV 分段与源可见性 | 投影缓存、独立几何 |

## 适配器应承接什么

一个清晰的适配层可把引擎逻辑状态转换成 kernel 输入，说明是否发生 gather、transpose、dtype conversion 或额外 copy。这样的转换可能比 kernel 本身更贵，benchmark 应覆盖它们。fallback 也应保持同一数学契约，不能在不支持窗口时静默改为全 attention。

不同 prefill/decode 实现可共享持久缓存，但布局、量化 scale 和写入约定必须一致。跨实现比较使用固定张量与可见关系，再评价端到端成本，才能区分数学接入错误和资源效率差异。

## 分区 attention 合并的额外不变量

若同一 query 的合法 K/V 集合拆成互不重叠的 I、J，且每一部分使用相同 score 定义和位置/数值解释，可以保留归一化输出 O 与 log-sum-exp l。取 m=max(l_I,l_J)，权重 a=exp(l_I−m)、b=exp(l_J−m)，合并输出为 (aO_I+bO_J)/(a+b)，新的 l=m+log(a+b)。用 max 做平移避免直接 exponent 大 l 溢出。

互不重叠是必要条件：共享前缀已经在 I 中出现，就不能在 J 的完整历史中再计一次，否则它的概率质量被重复增加。只有输出 O 而没有归一化尺度，通常不能通过普通平均恢复整体 attention。空分区、全 mask 行、LSE 是自然对数还是其他底、scale/softcap 的顺序也必须统一。

共享 prefix 的多个 query 仍有各自 Q，复用主要是 K/V 的读取与存储；不能共享本应不同的 attention 输出。分页表示本身只说明存储间接寻址，稀疏可见性若删除了原函数允许访问的位置，则是另一个质量敏感算法，不能从“同为块稀疏表示”推出精确等价。

## 转换成本与可复算反例

设一层 K/V 各有 L=8,192、Hkv=8、d=128、FP16，合计 2×8,192×8×128×2=32 MiB。若每次调用先完整 gather 到连续布局，需要读取旧布局并写入新布局，单是转换至少产生约 64 MiB 有效字节，之后 attention 还会读取新缓冲。更快的连续 kernel 只有在抵消这些转换、额外驻留与同步后才构成收益。

独立小例中，对同一 query 设两个 logits 都为 0，V 分别为 0、2，则整体输出为 1。各分区输出为 0 和 2、LSE 同为 0，合并得 1；若第二分区同时包含第一个位置，错误合并会重复计数，得到 2/3。对 Q 长 2、K 长 5 的因果输入，再显式验证两行可见集合，而不只比较输出 shape。

接入测试应覆盖 GQA 的 head 映射、QK 与 VO 维度差异、非整页、窗口边界、prefix/suffix 不重叠、无可见 key、位置偏置和 quantization scale。对同一逻辑状态依次记录转换、准备、kernel、合并和输出路由的耗时/内存，并用独立稠密数学参考验证。长历史、低 batch 时分区可能增加并行度；短历史或转换占主导时，简单路径可能更快。选择应由接口交集与完整执行成本决定。

## 准备与执行：成本发生的频率

接入成本从逻辑请求状态可用时开始，到输出可被下一组件消费时结束。面向服务的接口普遍把工作分成两段：依赖 metadata 的准备——读取或整理分段与页表信息、划分工作、选择实现、更新缓冲——和依赖张量的执行——可能分配输出、准备布局、执行 kernel、缩放输出。把计时窗口只放在最后一个 kernel 上，不能代表这条路径。

准备段的成本来自 host 对 metadata 的消费：长度信息已在 CPU 还是必须从设备读回、mask 是否已预先打包、图模式下是否要把更新后的元数据复制到保留缓冲。一个“非阻塞”标志不会消除这些工作，只是改变它们与设备工作的重叠方式。

准备段能否复用，由它真正依赖的条件决定：几何、batch 成员、分段、KV 长度、mask 与实现选择。多层共享同一几何时，一次准备可以服务多层；条件改变后旧计划不再有效。这是一个摊销边界，是设计变量，而不是“初始化时发生一次”的常数。把每步成本当成一次性初始化会虚增收益，把一次性成本重复计入每步会错误淘汰方案；可复算的摊销算例见下文。

执行段的辅助工作同样可观察：未传输出缓冲时的分配与清零、额外统计量（如 LSE）的分配、某些路径在主 kernel 之后另行应用的缩放。它们影响完整调用时间与临时驻留，应与 kernel 时间分开报告。

## 数据驱动的工作划分与图执行

工作划分决定每个 CTA 处理哪些 query 行与哪些 key 块。若划分结果直接决定 launch 的 grid 形状，那么 KV 长度变化就会改变 grid，图重放失效。另一条路是把划分结果作为数据写入固定容量的工作队列，由固定 grid 的 kernel 读队列执行；动态任务由此进入静态图，代价是队列容量上界、空闲 CTA 以及分区合并的额外输出。

这条轴上有两个必须分开判断的性质：归约顺序是否确定（影响逐位可复现）与 launch 配置是否固定（影响图兼容）。固定划分粒度可以让归约顺序确定，却不保证 CTA 数不随长度变化；固定 grid 也不保证合并顺序确定。从一个标志推出另一个性质是常见错误。

容量上界属于计划：最大 query 行数、页索引数、末页长度与部分输出数量都要按所选路径建立上界；超界时切换到另一张图、普通执行或拒绝该计划，不应截断页表让重放勉强运行。

## metadata 的单位与实际分派

页表和分段数组不能仅凭名字与 shape 对接。query 的分段偏移可以表示 token 行偏移，另一条接口可能表示元素偏移；页偏移表示页索引数组中的区间，页索引再指向物理页，末页长度则以有效 token 计。把其中两个量当成同一单位，在小 batch 或某个特殊 head 数下可能偶然不出错，换形状才暴露问题。同一入口下的不同实现分支也可能用不同单位核对输入，适配不能只替换一个名字。

“自动选择实现”通常不是每次调用都重新寻找当前最佳实现：实现会在准备段解析设备、位置模式、归约方式、mask 与 dtype 条件，把结果固定在对象内部供后续执行使用。输入能力组合变化后，需要确认既有对象仍适用，必要时建立另一配置或显式选择路径；之前成功运行一次不构成对后来所有条件的支持。

可用路径还可能直接拒绝某些组合（布局、因果模式、构造方式）。这些是函数与版本的边界，不能推导成整个库或整个硬件不支持该语义；替代路径可能是另一接口、另一实现或受控的布局适配。反过来，某库存在该能力，也不表示当前调用实际选择了它。

## cache 布局、workspace 与并发必须共同设计

页内 token 优先与 head 优先只是轴顺序，K/V 的容器还可能是合并的五维张量或两个四维张量。逻辑页表中的索引关系不因 transpose 自动改变；变换时必须保持每个逻辑位置对应的 K、V 和 scale 一致。只转换数据、漏掉量化 scale 或末页有效长度，会产生无法用 shape 检查排除的错误。

“支持两种布局”不等于“两种布局的成本相同”。对普通可接受 stride 的数据，transpose 可以只是视图；对要求连续或带块级 scale 的量化分支，完整复制是真实成本。若 prefill 写入一种布局、每步 decode 又转换整段历史，转换量随已驻留 KV 而非本次新增 token 增长。

缓存写入有接口特定的别名条件：在原地更新缓存的接口上，同一槽位的重复写入是否有确定结果由该接口规定；共享只读 prefix 与多个逻辑更新写入同一槽位具有不同含义，不能从“接口接受索引数组”推断任意重复写入都有确定结果。独立尾槽、依序更新或另一种缓存更新实现可以改变写入依赖。

workspace 影响能否同时运行多个批次。分区归约的中间结果、整型与 pinned host 工作区、可变计划状态都占用容量；建议容量不是所有形状的硬下界，也不是空闲时没有驻留成本的承诺。共享同一 scratch 或复用同一可变对象时，需要以实际读写区域和完成顺序解释能否复用；不同 stream 的输出彼此独立不足以说明内部辅助状态独立。

图模式把这个问题放大：采用固定容量对象时，metadata 缓冲与其地址须满足图的生存期。需要 host 读取、决策或不支持捕获操作的准备段留在捕获之外；纯设备准备能否捕获取决于所用操作和依赖。活跃请求数仍可通过显式分桶或其他合法组织方式变化，但引擎必须保证 inactive 槽、实际长度和页表内容的约定一致，不能把固定外形当成固定请求状态。split 配置、输出分配与 workspace 地址也必须满足当前捕获路径，见 [Stream 与分配器](streams-allocator.md) 与 [CUDA Graph](cuda-graph-buffers.md)。

## 组合案例：共享前缀、量化尾块与图中的在途读者

考虑一个明确的状态设计：每页4个token、一个KV head、dₖ=dᵥ=16；只有封存的满页可共享。满页保存有限FP8码和各一个FP32的K/V尺度，高精度尾块保存FP16；本例消费时将封存页解码为FP16操作数，尾块直接用FP16，随后按上一节的矩阵契约计算。它是“FP8存储、FP16矩阵输入”的混合算法，区别于前文原生低精度操作数示例；解码到FP16本身的舍入也进入参考。封存改变近似表示，不能宣称所有快照与原高精度模型逐位相同。

请求A、B共同拥有位置0…7的两页封存前缀，各有位置8、9的独立尾块。共享身份至少包含模型/层/head、位置规则、相关前缀内容、量化格式/尺度与所用变换的身份，不能只比较token数量。为保持例子简单，正在变化的尾块不共享；其他设计若共享它，就必须另行解决写时复制和发布。

执行图有两个固定地址的数据包，每包容纳A/B两个行槽、各自的完整尾块缓冲、描述符、输出和workspace。描述符保存请求身份/代次、有效长度、页句柄与尾块位置；每行最多4个逻辑页，grid按容量固定，inactive行不读页表也不发布输出。页池基址稳定，页号是数据。图捕获不把描述符内容变成永远有效；更新描述符、填充数据与消费者之间仍须有stream顺序或完成事件，包中任何尚被使用的区域都不能改写。

为了可核对，采用保守的复制后发布：追加到另一份尾块，封存写入新的页及新尺度，旧快照保持不变。一次可见快照为(请求身份、状态代次、有效长度、页及尺度句柄、尾块内容、数值策略)。构造新快照不等于已发布；K、V、scale和metadata全部就绪后才能让消费者取得它。本例在独立包中写完描述符，再通过同stream顺序或跨stream事件启动消费者，因此不假定多字段metadata写入天然原子。中途取消或失败时丢弃未发布的新状态，并等写者结束后回收构造缓冲，不能只更新长度或scale。

| 时点 | 事件 | 必须保持的关系 |
|---|---|---|
| e0 | A/B各追加已就绪的位置10，复制到包0的独立尾块，长度变11 | 旧内容与新token属于同一逻辑序列；每行只看到其自己的尾块 |
| e1 | 数据/metadata就绪，包0图执行；为其页和尾块登记在途读取凭据 | prefix页被两个行读取；凭据绑定包代次与资源代次，输出还绑定请求身份 |
| e2 | A取消；从逻辑所有者中移除A | A的尾块仍被包0读取，不能回收；旧输出也不能路由给复用同一行槽的新请求 |
| e3 | B的位置11已由上游合法产生，在包1的尾块复制8…10并追加11，另建封存页 | 不能修改包0的尾块；量化写者未完成时新页不可消费或回收 |
| e4 | 新页K/V及两项scale就绪；发布B的新代次，长度12、三个封存页、空尾块 | 旧B尾块的逻辑所有权可以结束，在途读取凭据仍保留；不得拿新scale解旧码 |
| e5 | 包1用新快照执行，A行inactive | 两个包的metadata、输出和workspace不互相覆盖，页池引用的内容稳定 |
| e6 | 各包最后一次读取及输出消费分别完成 | 按各自凭据释放；旧代完成不得扣除新代计数，全部条件满足后才复用 |

e3的前提是新Q/K/V已经可用，例如已知输入的合法追加；自回归的下一个未知token仍依赖前一步模型输出，不能因为有第二个图包就提前生成它。这条时间线表达可并存的状态，不伪造上游计算依赖。e6也不要求两个包按同一顺序结束。

资源r允许复用的一个充分条件是：逻辑所有者数=0、在途读取凭据数=0、未完成写者数=0。逻辑引用计数与执行凭据分别回答“以后还会不会使用”“已经提交的工作是否结束”。页池位置复用时递增代次；完成凭据必须至多消费一次。若共享页仍被B拥有，A取消不会释放它；若A的独占尾块已经无人逻辑拥有，但包0未结束，仍不能释放。

图包也有自己的代次：空闲→构造→就绪→执行/输出消费→空闲。这里保守地等包内所有消费者结束后整体复用；细分缓冲生命周期可以更早释放部分区域，但需要逐区域证明。容量超界应使用另一个满足条件的配置、普通执行或明确拒绝，不能截断页表。A行槽换成C时，旧A结果与完成事件不得获得C的新身份。

容量账可以复算：一个封存页的码为4·(16+16)=128字节，两项FP32尺度8字节，逻辑136字节；若每页起点按32字节对齐，取页距160字节。两页共享prefix实际占320字节，两份各自保存需640字节。一个高精度尾块的容量为4·(16+16)·2=256字节；两包×两行已经预留1024字节尾块容量，空尾块也不会自动退还这块预留。

封存B时，旧尾块256字节、构造中的新尾块256字节与新页160字节可同时存活，共672字节。这两个尾块若来自已预留的图包，不能又在总容量中重复相加；672描述相关对象的同时存活，1024描述尾块池的预留。prefix、其他页、描述符、workspace和输出分别另计。复制三个旧token需要读写各192字节；将满尾块量化至少消费256字节输入并写136字节码/尺度，求amax及实际融合可能增加读取。包0/包1各自读共享prefix也不会因为“只保存一份”就自动只产生一次请求；实际cache命中和跨query共享另算。

独立验证应按每个快照解码页/尺度、拼接它自己的尾块、重建绝对位置可见性，再算稠密参考，随后加入矩阵操作数和P的舍入。旧快照读旧尾块、新快照读新封存页，本来就可能存在约定的量化差异。可注入的错误包括提前发布长度、只换scale、提前回收取消请求、覆盖仍在读的图包、旧代事件重复完成、超界截断以及把B尾块接到A；这些错误分别破坏发布、数值身份、生命周期或请求身份。用正向结果加这些负对照，才能区分“近似允许的变化”和“执行了错误的状态”。

如果封存转换/复制位于每步关键路径，或双包驻留挤占了可服务容量，应重新比较固定尺度、不同页粒度、另一种尾块表示、较少并发图包或普通执行；它们改变误差、复制、并行度和状态持有时间。这里演示的是一种完整可检查的组合，不要求引擎采用这种组件划分。页共享和异步所有权的来源分别见[S-PAGED](../sources/S-PAGED.md)、[S-TORCH-CUDA](../sources/S-TORCH-CUDA.md)，组合协议与容量数字是本库独立推导。

## 两个可复算的接入反例

第一个反例是 GQA 的物化扩展。设 Hq=32、Hkv=8，某层 FP16 K/V 长度 L=8192、d=128，则逻辑 KV 为 32 MiB。若通用路径把 K/V 真正复制为 32 个 head，临时 KV 表示成为 128 MiB，并增加生成该表示的读写。直接消费分组 head 的内核有机会避免这一扩展；但文档中的等价数学表达出现 repeat，并不能证明选定实现实际物化了它。需要通过实际分派、分配与设备流量判断，不能仅按概念公式给库记账。

第二个反例是准备段的摊销。设两个候选除公共工作外，A 每次 kernel 为 20 μs，B 为 12 μs，但 B 的一次合法准备为 160 μs。若同一计划只使用一次，B 为 172 μs；若确实能供 32 次相同几何调用使用，平均为 17 μs，才优于 A。若每次调用还伴随 6 μs 的不可摊销 metadata/输出工作，B 的平均又成为 23 μs。所有时长都是设定值，用于展示成本结构；真实多层或跨步复用是否合法，须先通过接口契约判断。

这两个例子说明适配器需要记录成本发生的频率：每任务、每模型加载、每形状、每层、每 batch 或每 decode 步。把一次准备成本重复计入会错误淘汰方案，把每步成本当成一次初始化则会虚增收益。

## 用同一逻辑状态比较实现

比较时先固定绝对位置、合法 key 集合、head 映射、K/V 内容和数值策略，使稠密参考与候选表达同一个问题。然后分别测已准备输入上的 kernel、真实适配后的完整调用，以及与投影、cache 更新和输出消费连接后的模型层。让 causal 对齐、GQA 分组、分页尾页和窗口边界逐项改变，可以区分数学接入错误与分派条件变化。

性能变化若只出现在首次形状，优先检查编译、准备、分配与缓存；若随历史长度线性增加而 kernel 时间未相应增加，检查 gather、布局转换及 metadata 路径；若并发执行后正确性失效，检查 workspace、可变对象状态和缓存写入是否共享。观测应对应可否定的解释，而不是把所有慢路径统称为性能差。

最后回到完整服务的吞吐、延迟与容量。某路径节省 attention 时间却多占一份历史缓存，可能减少可容纳的并发请求；另一条路径单次略慢却避免 CPU 同步，可能改善调度重叠。结论只能覆盖已测模型、硬件、长度与并发条件。短历史小 batch 下简单稠密路径可能占优，长历史小 batch 下分区并行占优，大 batch 下准备段摊销充分而转换成本显现；workspace 与副本对 KV 容量的挤占见 [已知张力](../system-semantics/known-tensions.md)。

## 诊断案例：三级流水为何比两级更慢

这是可调整的局部研究方法，不是构建引擎的必经顺序。研究对象固定为相同输入、mask、精度和数学工作量的两个候选；先保留各自合法的 tile/线程/级数、编译产物和资源记录。若两条路径为了合法性已换 tile，就分别比较完整候选与尽量保持其他条件的机制对照，不把所有差异归给级数。

| 竞争解释 | 可否定的预测 | 有区分力的干预与观测 | 解释不足的情形 |
|---|---|---|---|
| 启动/收尾更长，稳态更快 | 块数增加后差距应缩小并可能反转 | 固定tile，改变KV块数，分别看首尾与稳态周期 | 长输入稳态周期仍更慢，不能只用首尾解释 |
| 额外状态造成spill | 新增local/global事务随迭代累积 | 核对生成程序的spill与流量，缩小tile或减少活跃片段再对照 | 无spill不能证明没资源问题；还可能降低驻留 |
| 寄存器/共享存储降低驻留 | 更多独立任务时仍有资源约束，减少资源可能改变驻留 | 记录实际驻留、块数与资源；控制计算量比较可行配置 | occupancy升高却未加速，不能单凭occupancy认定根因 |
| 编译未形成预期重叠 | 源级异步增加，但指令和时间线中的可重叠区未增加 | 对照生成指令、等待位置与设备时间线；核对工具扰动 | SASS交错不单独证明真实并行，多个瓶颈仍可共存 |
| 额外转换或计划重建 | kernel局部改善，完整调用却变慢 | 分开计量转换/准备/执行，固定或改变计划复用条件 | 无法用kernel计数解释host准备；需观察相应边界 |

可复算的判别例：设只有首尾开销和稳态周期，T₂(N)=10+2N、T₃(N)=18+1.7N，单位μs，N为KV块数。N=8时分别26/31.6，N=64时138/126.8，交点约26.7块；短输入上三级更慢与稳态有效并不矛盾。若实测长输入仍越来越落后，该首尾解释就不够。另一条设定曲线T₃′=18+2.4N在N=64时为171.6，提示稳态本身恶化；至于是spill、驻留还是未重叠，要由上表的不同观测继续区分。这些曲线不是论文或目标机的结果。

实验重复以独立运行/时间区组为单位，均衡候选顺序，区分冷编译、预热和稳态；保持质量和完成点一致。最终时延使用正常路径测量，profiling产生的同步和replay另报。差异小于噪声时保留未区分；若候选越界、质量失败或资源超限，不以性能抵消。统计与保留验证见 [性能实验](../tools/statistical-experiments.md)。

将结论写为“在这些输入、编译和资源条件下，某项观测支持/不支持哪种解释，并预测条件变化后的结果”。换shape、硬件或并发后，先检查预测是否仍成立。单个计数器、最短时间或版本名称不应直接变成跨条件的知识。

## 诊断线索

| 现象 | 能区分解释的检查 | 对应机制 |
|---|---|---|
| 换接口后短序列正确、长序列或多分区输出漂移 | 固定输入比较分区合并前后的 m、ℓ；核对 LSE 底数与缩放方向 | 分区合并不变量 |
| 非方形 prefill 的首行或末行输出错误 | 用绝对位置构造期望可见集合，逐行比对 | causal 对齐约定 |
| 首次形状调用远慢于后续，形状变化时再次变慢 | 分别计时准备段与执行段；改变 batch 成员观察是否重新准备 | 准备段摊销边界 |
| 延迟随历史长度线性增长而 kernel 时间不变 | 计量 gather/转置字节是否随驻留 KV 增长 | 布局适配位置 |
| 显存按 Hq/Hkv 倍增长 | 检查实际分派是否物化扩展 K/V | 几何不变量与物化反例 |
| 并发两批后出现错误结果 | 单批正确、双批错误时检查 workspace 与可变计划状态是否共享 | workspace 并发 |
| 图重放后输出混入上一批 | 核对 metadata 缓冲的代次与在途读取 | 时间所有权 |
| 某组合直接报错不支持 | 区分函数边界与库/硬件边界；换接口、换布局或受控适配 | 分派与被拒绝组合 |
