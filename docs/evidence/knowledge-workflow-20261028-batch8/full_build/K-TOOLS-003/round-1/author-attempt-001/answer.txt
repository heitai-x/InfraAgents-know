{"chapter": "# K-TOOLS-003：Kernel 计数器：吞吐、访存与 Replay 语境\n\n计数器回答的是“某个逻辑 kernel 实例，在某个采集契约和某个时间窗内，硬件或软件记录了多少事件”。它不自动回答“瓶颈是什么”。同一组计数在正常服务、隔离 kernel、cache 被清空或时钟被固定的条件下可能对应不同的执行，因此本章把计数器、派生指标和 replay 放在同一状态模型中讨论。输入是时间线选出的候选实例、待区分假设、可用事件与重放能力；输出是带范围标签的原始样本、只在合法条件下计算的派生量和仍需服务测量确认的结论。\n\n## 计数器的对象、状态与可回答的问题\n\n定义逻辑实例 X=(进程, 设备, 上下文, stream, launch 序号, kernel 名, grid, block, shape, 执行阶段)。只按 kernel 名聚合会把不同 shape、不同上下文或不同阶段的执行混在一起。时间窗 W=[t_0,t_1) 是计数器实际启用的范围；T_obs 是同一范围经过的墙钟时间。对事件 k，记原始计数 C_k(W)，启用比例为 r_k=T_enabled,k/T_obs。若事件率在这个窗内可代表整个 W，缩放估计可写成 C_hat_k=C_k(W)/r_k；否则缩放只是把不均匀活动外推，不能恢复短 burst。\n\n派生量必须带边界。对目标链路，有效负载 D_use 与事务字节 D_tx 的率分别为 B_use=D_use/T_obs、B_tx=D_tx/T_obs；放大 A=D_tx/D_use，效率 E=D_use/D_tx。计算量 F 与墙钟时间的比是 F/T_obs，不是器件铭牌峰值。占用率 O=W_active/W_max 是活跃 warp 数与可驻留上限之比；它是资源驻留描述，不是“有效工作比例”。计数器里的占比还要说明峰值口径：burst 峰值、sustained 峰值和实际可达到速率不是同一参数；文档说明 sustained 口径在边缘情况下可能超过 100%，不能把它当成错误或硬上限。\n\n采集状态至少包括：逻辑实例身份、pass 编号 p、事件组、启用区间、cache 策略、时钟策略、是否串行化、并发 kernel 集合、指标来源是硬件计数器还是软件插桩。kernel 内部状态至少包括：执行前的内存 M_0、每个 pass 后的内存 M_p、写集 W_set、缓存状态、时钟状态和是否已完成恢复。application replay 还要记录整个应用 run 的身份和匹配键。没有这些标签的数值只能作为原始观察，不能直接进入因果解释。\n\n## 合法性：哪些计数可以放在同一命题里\n\n同一条派生指标首先要求分子、分母属于同一逻辑实例、同一范围和同一分母口径。命中次数来自 pass 1、查询次数来自 pass 2，或 instructions 取线程范围而 cycles 取系统范围，都不能组成一个有意义的比率。多事件复用计数器时，只有实际启用区间具有代表性，缩放才可解释；不同事件在不同 burst 上启用时，缩放后的比值仍可能失真。\n\n第二，字节口径必须匹配。有效张量字节、请求字节、L1 sector、L2 sector、DRAM sector、NVLink 字节和 PCIe 字节属于不同边界。相同张量的 HBM 读取、L2 命中后的读取和主机传输不能相加后称为一种带宽。读写方向、对齐和是否包含重复读取也属于量的身份。ramp 或 stride 改变时，应重建 D_use、D_tx，而不是沿用原来的放大倍数。\n\n第三，replay 必须保持被解释的状态。kernel replay 在需要多 pass 时，首次 pass 保存 kernel 可访问的 GPU 内存；之后确定被写的子集，并在每个后续 pass 前恢复该子集，使各 pass 看到相同内存内容。单 pass 不需要这套保存恢复。若 kernel 依赖主机响应、与其他 kernel 协同或写入持久状态，kernel replay 可能停滞或改变语义。application replay 重跑整个应用，不保存恢复 kernel 内存，但会重复主机工作和启动成本；跨 pass 匹配依赖应用对 kernel 活动、设备、上下文、stream 和可能的 range 具有确定性。默认匹配按同一进程、同一设备上的 kernel 名和 grid 进行，同名同 grid 的多次 launch 再按执行顺序区分。\n\n第四，并发和共享单元要单独处理。需要正确并发执行的 kernel 不应被强制串行化成单 kernel 观测；range replay 以整个 API/kernel 范围为单位，允许工具不串行化 kernel，但指标对应的是范围而非单个 kernel，并可能保存恢复主机和设备内存。MIG 的 shared compute instance、green context 的非独占单元以及多进程共享的 L2/DRAM/NVLink，可能使计数不属于单一消费者；工具文档明确 shared unit 的计数限制，不能把不可归因的共享计数当作本实例独占资源。\n\n第五，occupancy 只是上限描述。忽略分配粒度时，每 SM 的 CTA 数受 N_cta <= min(floor(S_sm/S_cta), floor(R_sm/R_cta), floor(T_sm/T_cta), floor(W_sm/W_cta), B_max) 约束；R_cta 应是按硬件分配粒度取整后的寄存器量，实际还受每 block 上限、cluster 和调度影响。低 occupancy 总会削弱隐藏延迟的能力，但更高 occupancy 不保证更快；它可能只是增加排队、cache 压力和同步。stall 采样也只有在调度器确实有无可发射周期时才说明问题。\n\n第六，CPU 事件必须固定运行范围与分母。线程、进程、CPU 集合、系统、cgroup 和 per-core/per-socket 聚合是不同观察对象；IPC 要求 instructions 与 cycles 来自同一范围和同一时段。事件分组用于尝试同时调度；分组变松可能提高单个事件被调度的机会，却降低比率同时刻成立的准确性。计数器复用后的原始值要结合启用时间或运行比例解释。\n\n## 算法：从时间线实例到可复核指标\n\n```pseudocode\n算法 CollectAndValidateCounters\n输入：时间线 TL；候选逻辑实例 X；假设集合 H；事件计划 M；可用 replay 模式；服务测量 S\n输出：带标签的原始样本、合法派生量、未解释项和下一步实验\n\n从 TL 选择代表实例，记录 X=(进程,设备,上下文,stream,launch序号,kernel,grid,shape,阶段)\n为每个假设 h 写出预测：应出现的事件、应不出现的替代事件、独立算术下界\n把 M 分成尽量少的 pass 组；每组只收集回答当前问题所需的事件\n判断实例是否写内存、依赖主机、要求并发、属于 graph、或跨多个 kernel：\n    需要并发正确性 → 选 range 或 application-range，不选强制串行化的单 kernel 模式\n    kernel 依赖主机响应 → 选 application replay；kernel replay 可能缺少响应\n    需要匹配多次 application 执行 → 要求确定性；否则缩窄 range 或改造实验\n    普通且自包含 → 可选 kernel replay；多 pass 时准备写集恢复\n估算 pass 数、保存/恢复字节、cache 清空、时钟固定和串行化的测量成本\n若成本超过预算：减少指标、缩小问题、改变工作负载长度或放弃该测量\n初始化 p=0，M_0=选定的初始内存，cache/clock/并发策略记为标签\n若 kernel replay 且预计多 pass：首 pass 保存可访问内存；否则不做无必要的保存\n对每个 pass p：\n    建立或恢复本 pass 的初始状态；p>0 时恢复上一 pass 确定的写集\n    启用事件组，记录实际启用比例、开始/结束和并发集合\n    执行实例，收集原始计数；保留异常值、溢出、未支持和共享单元标记\n    将样本标为 (X,p,事件组,范围,单位,峰值口径,缩放,工具模式)\n若 X 或 launch 匹配失败：停止派生，报告匹配失败而不是拼接不同实例\n对每个派生量：\n    只有分子和分母的 X、p、范围、单位合法时才计算\n    不能同 pass 取得时，标记 unresolved 或重跑为单组事件\n把派生量与独立算术下界、时间线和服务测量对照\n输出确认项、被反证项、未解释项和下一项能区分竞争解释的干预\n```\n\n数据流可以概括为：时间线给出实例身份 → replay 计划确定哪些状态要保持 → 每次 pass 产生带标签原始样本 → 校验器检查实例、pass、范围和单位 → 合法派生量才进入资源解释 → 最后用正常服务测量确认收益。任何一步把不同实例或不同 pass 的数值拼接，后面的算术都不能恢复原来的对应关系。\n\n## 条件化成本：计算、访存、准备、同步和驻留\n\n计数器本身不是免费的。多收集一组硬件事件可能增加 pass 数；多 pass 需要写集恢复，cache 默认清空会改变命中，时钟可能被固定到基频，kernel 可能被串行化，首次 profiled kernel 还可能产生一次性的指标配置开销。一个记账骨架是 C_replay >= C_setup + P*T_exec + (S_save+(P-1)*W_written)/B_restore，其中 S_save 是首次 pass 的可访问内存保存量，W_written 是写集，B_restore 是保存/恢复路径的可持续速率。这个式子只用于数量级和预算，不是工具总耗时的精确公式；传输可重叠、首 pass 不一定保存全部主机内存、单 pass 完全不做保存恢复。设可访问 1 GiB、写集 4 MiB、P=4，则保存约 1 GiB，后续恢复约 3×4=12 MiB；即使 kernel 很快，采集也可能被这套状态搬运主导。application replay 没有这套内存恢复，却重复整个应用的主机活动，因此两种成本不能只比较 pass 数。\n\n| 成本 | 本章对应对象 | 合法记法 | 常见误算 |\n|---|---|---|---|\n| 计算 | 算术事件、指令、矩阵管道 | 同一实例的 F/T 或管道占比 | 把峰值百分比当成实际利用率 |\n| 访存 | 有效字节、请求、sector、wavefront、DRAM 事务 | 每个边界、方向和读写分别记账 | 把 L2 命中、DRAM 和链路字节相加 |\n| 通信 | NVLink、PCIe、互连 fabric 或跨设备同步 | 与目标链路能力匹配的字节和时间 | 用 HBM 带宽解释主机设备传输 |\n| 准备 | 首次指标配置、编译、cache 清空、保存/恢复 | 按实际复用次数摊销 | 把 profiler 准备算进服务稳态 |\n| 同步 | 串行化、事件等待、kernel 间依赖 | 关键路径上不可重叠的等待 | 把重叠区间直接相加 |\n| 驻留 | 寄存器、shared/LDS、local memory、保存缓冲 | 同一物理资源只计一次 | 把逻辑累加字节当真实寄存器占用 |\n\n访存账要下到请求和事务。一个 warp 的标量 32-bit 访问在特定代际可合并成若干 32 字节段；地址偏移可能多取一段，stride=2 可使每次事务只用一半字节。但段数、sector 数和 wavefront 不是同一层：同一请求可以有 4 个 sector、1 个 wavefront，也可以有 4 个 sector、2 个 wavefront；后者表示流水占用更多周期。计数器给出 request:sectors、wavefronts:sectors 的 1:N 关系时，不能反过来用 sector 数唯一推出周期。相邻 warp 的 cache 复用还可能把看似 4/5 的放大变成 9/10；这是特定访问模式和设备上的文档例子，不是通用常数。\n\nCPU 侧可用同一思路。若两个区间分别为 2.0e9 instructions、1.0e9 cycles 和 1.0e9 instructions、0.75e9 cycles，则 IPC 分别为 2.0 和约 1.333；第二段 IPC 更低，却使用更少 cycles，若频率和有效工作相同，可能反而更快。IPC 不是速度的同义词；频率、等待、指令组合和并发都进入墙钟时间。若某事件只在一部分测量窗启用，且事件率非平稳，按启用比例缩放后的 IPC 也不应被当成整窗真值。\n\n## 条件变化后的保留、调整与放弃\n\n| 条件变化 | 保留的机制 | 要调整或放弃的部分 |\n|---|---|---|\n| 增加指标组 | 实例身份和问题分解 | pass 数、保存恢复、cache 清空和串行化成本上升；优先减指标而不是拼不同 pass |\n| cache 敏感或分析应用内状态 | 逻辑实例和内存恢复要求 | 默认清空 cache 的隔离结果不能代表应用热态；必须在同一 cache 策略下比较，必要时放弃隔离结论 |\n| 时钟被固定或热降频 | 事件与时间的关系 | 基频下的时间不能外推服务；热限制可能覆盖工具设置 |\n| kernel 必须并发 | range 级指标和完成依赖 | 放弃单 kernel replay 的串行化读数；range 指标不能归到单个 kernel |\n| 应用依赖主机响应或不确定 | application replay 或更窄 range | kernel replay 可能停滞；application replay 匹配失败时不能拼接 launch |\n| graph 内部有并发节点或设备端 launch | graph 作为工作负载 | 不把节点间不 purge cache 的图结果当成普通单 kernel 结果；部分指标不可用 |\n| MIG/green context 共享单元 | 独占单元计数 | 共享 L2/DRAM/互连计数不可归因；放弃单消费者解释 |\n| 换到 AMD 或其他平台 | 假设、单位和范围定义 | CU 数、wave 宽度、VGPR/SGPR、LDS bank 和事件名都改变；不复制 CUDA 的 lane/bank 常数 |\n| CPU 从线程改为 cgroup 或系统范围 | 事件和 IPC 定义 | 分母、迁移、SMT 共享和聚合层级改变；旧缩放不沿用 |\n| 工作负载太短 | 问题与实例选择 | 可能达不到稳定状态；扩大同类工作或使用 range，但不把长窗结果外推到短 burst |\n\n这些选择不是“越隔离越正确”。隔离能减少其他引擎和 cache 的污染，却可能删掉服务中真实存在的并发、热 cache 和排队。正确的做法是让采集条件与要回答的问题匹配，并把不匹配的部分标成未知。\n\n## 竞争解释、反例与区分实验\n\n| 观察 | 竞争解释 | 可控干预与预测 | 反证后的修正 |\n|---|---|---|---|\n| DRAM 带宽低且计算也低 | occupancy 不足、依赖长、访问不规则、启动/串行化主导 | 固定工作量，改变资源预留或 block 数，记录 achieved occupancy、issue slot 和事务字节；若增加驻留仍不提高事务率，降低 occupancy 解释权重 | 不把“低带宽”直接称为 DRAM 未饱和 |\n| cache 命中率很高但 kernel 慢 | 命中仍可能受 L1/L2 流水、wavefront 或依赖限制 | 改变工作集越过 L2、比较 cache 清空与保留、记录各层 sector 和 wavefront | 命中率高不证明数据供给是瓶颈 |\n| 同一命中率在不同 pass 差异大 | 分子分母来自不同 pass，或工作分布在 replay 间变化 | 减少事件组使 hits/queries 同 pass，延长稳定工作，检查每次 pass 原始值和启用比例 | 比率越界或无法复现时，先修测量而不是解释 cache |\n| profiler 下 kernel 更快 | cache 被清空、时钟被固定、kernel 被串行化或测量开销改变 | 切换 cache/clock 策略，比较单 kernel 与 range，再回到无 profiler 服务测量 | profiler 结果不能直接作为服务时间 |\n| occupancy 更高反而更慢 | 更多驻留带来 cache 争用、同步或排队；工作分布不均 | 保持工作量和 tile，改变动态共享资源以改变驻留，记录活跃 warp、同步等待和完整网格时间 | 驻留上升而 stall 和总时间也上升时，不能只追求 occupancy |\n| 出现 local memory 流量 | 寄存器压力造成 spill，或本来就有局部数组 | 查生成资源报告和 local 读写；缩短临时量寿命或改变 tile，再核对相同计算的 traffic | 没有 local 流量时，不能把慢归因于 spill |\n| CPU IPC 下降但程序更快 | cycles 更少、频率更高、工作阶段不同或范围不匹配 | 在同一线程/cgroup 范围内同时取 instructions 与 cycles，比较 wall time 和阶段工作量 | 用更低 IPC 直接判定更慢是错误 |\n| 总字节下降但服务不变 | 只减少副本，读取仍由每个请求承担，或瓶颈在同步/排队 | 固定请求和历史，分别记录有效字节、事务字节、L2/HBM 和端到端时间 | 容量或字节收益不等于带宽或延迟收益 |\n\n反例一：同一请求有 4 个 sector，可能只需 1 个 wavefront，也可能需要 2 个。若只按 sector 数估算 L1TEX 周期，会把流水占用漏掉。反例二：stride=2 的标量访问在文档模型中只有 50% 的 load/store 效率，但相邻 warp 的 cache 复用会改变实际 DRAM 需求；不能用效率公式替代事务计数。反例三：较低的 IPC 可能对应更少 cycles，因而在相同频率下更快；必须把 instructions、cycles 和 wall time 分开。反例四：低 occupancy 会削弱隐藏延迟的能力，但提高 occupancy 不保证提高性能；这两种说法并不矛盾，前者是能力下界，后者是完整关键路径问题。\n\n组合轨迹可以这样检查：一个会写输出的 kernel 在 kernel replay 下，首 pass 保存可访问内存并执行，工具确定写集；第二 pass 前恢复写集、清空 cache、按固定时钟再执行，样本才与第一 pass 具有相同初始内存。若写集恢复遗漏，第二 pass 可能读取第一 pass 的输出，后续派生量看似正常却没有相同逻辑输入。若该 kernel 还需要与另一个 kernel 并发，单 kernel replay 的串行化会破坏正确性，应改用 range 或 application-range，并接受范围指标、并发共享和非归因边界。若输入来自异步存储 I/O，块层的软件队列、硬件派发和完成可能乱序；I/O 完成事件与 kernel 计数必须分别记录，不能把等待 I/O 的时间当成 kernel 计算时间。S-LINUX-IO 的文档只支持这种完成与范围区分，不提供本目标设备的带宽结论。\n\n<!--
