{"chapter":"# K-MODEL-004：SSM 与混合模型：递归状态、扫描与恢复\n\n递归状态是到某个逻辑位置为止的摘要，不是可以任意倒回的历史。这个差别决定了 decode 的状态更新、prefill 的扫描执行、前缀命中、投机提交和混合层缓存的恢复方式。\n\n## 递推状态、输入输出与压缩边界\n\n固定模型参数和输入前缀后，第 l 个递归层在消费完 x₀…x_t 后保存一个有限维状态。一种常见的选择性 SSM 写为\n\nh_t[d,n]＝Ā_t[d,n]h_{t−1}[d,n]＋B̄_t[d,n]v_t[d]，\ny_t[d]＝Σ_n C_t[n]h_t[d,n]＋D_skip[d]v_t[d]。\n\nd 是递归层的通道轴，n 是每个通道的状态轴；v_t 是经过该层输入投影、短卷积和模型规定门控后真正送入 SSM 的向量，不是原始 token 向量。Mamba 的一种常见形式令 A 在每个通道上为对角矩阵，Δ、B、C 依赖输入；若具体制品按 d 分别生成 C，则把 C_t[n] 换成 C_t[d,n]，不能仅凭名称相同就套用本式。\n\n连续参数先按模型选择的离散化规则变为离散参数。以零阶保持为例，令 z=Δ_t[d]A[d,n]，\n\nĀ_t[d,n]＝exp(z)，\nB̄_t[d,n]＝((exp(z)−1)/z)Δ_t[d]B_t[n]，\n\nz→0 时取极限 B̄_t[d,n]→Δ_t[d]B_t[n]。不同实现可以使用别的离散化或直接参数化离散系数；合法性要求是：同一 checkpoint、同一层、同一位置使用的离散化、轴顺序、门控和 skip 项必须与训练及完整前向一致。公式中的 D_skip 是可选旁路，某些模型把它放在 SSM 输出上，某些公式省略；不能把省略形式当成所有实现的共同接口。\n\n状态 S(p) 表示已经正确消费 x₀…x_{p−1} 后的完整模型状态。对递归层，至少包含 h_{p−1}；对带局部卷积的块，还要包含该卷积最近 K_c−1 个输入历史；对混合模型，还要包含全注意力 KV、窗口 KV、逻辑位置和表示元数据。h 的维数通常是 D_r×N，随模型层配置固定，不随上下文长度增长。卷积环和 attention KV 的大小另有规则，不能只说“递归模型没有 KV”。\n\n这里的“压缩”有两个不同含义。容量上，递归状态对每个请求是固定字节数；计算上，decode 每一步仍要读取并更新这些字节，且输入投影、短卷积、门控和输出投影仍要执行。状态小不等于更新免费，也不等于可以从最终状态随机读取任意旧位置。\n\n## 合法性：递推、卷积边界与扫描代数\n\n把单步递推看成作用在旧状态上的仿射变换 T_t(h)＝a_t h＋b_t，其中 b_t 已包含该步输入作用。两个连续变换的合成为\n\n(a₂,b₂)∘(a₁,b₁)＝(a₂a₁,a₂b₁＋b₂)，\n\n其中先作用左元，再作用右元。该合成满足结合律；对角 A 时可以逐元素计算。因此同一层内多步状态可以组织为并行前缀扫描，而不必每步启动一个小 kernel。输入相关系数必须由该层当前输入正确产生；扫描律不允许把不同网络层、不同请求或包含额外非线性状态更新的步骤混成一个线性扫描。\n\n局部卷积是另一个状态。设卷积核长度为 K_c，因果卷积在位置 t 使用当前及之前的投影输入。初始位置把不存在的历史视为零；分块 prefill 的下一块必须接收上一块的末 K_c−1 个卷积输入和末递归状态。因为扫描而重置卷积环、或每块从零状态开始，会在块边界产生语义错误，不是浮点容差。把多个独立文档拼成一个序列时，若模型要求边界重置，还应同时重置递归状态、卷积环和位置规则；不能只在 attention mask 中隔开。\n\nprefill scan 与逐步 recurrence 在实数数学上可以给出同一结果，但归约次序不同会产生有限精度差异。比较时应固定初始状态、卷积历史、有效 token 边界、离散化、C 和输出头。若单块结果一致而多块结果不一致，优先检查边界状态传递；若所有块都有小差异且提高精度后缩小，才考虑归约舍入。不能要求跨 backend 逐位相同。\n\n一般不应假定递推可逆。即使 Ā 在代数上可逆，B̄v 的输入作用、数值稳定性和状态轴都可能使从 S(p₂) 倒推 S(p₁) 不可靠。服务端的合法回滚手段是保存准确位置的快照或从更早的合法状态重放，而不是把长度字段改小。\n\n## 单步推进与分块扫描算法\n\n下面的 RecurrentStep 只描述一个递归块的数据流；完整模型还要按原图执行输入投影、门控、残差、归一化和输出投影。state 中的 h 是消费到上一位置后的状态，ring 保存卷积前投影的最近 K_c−1 个向量。\n\n```pseudocode\n算法 RecurrentStep\n输入：h[D,N]、ring[K_c−1][D]、当前 token 或特征 x、位置 p、模型层参数\n输出：y[D]、新 h、新 ring；是否可提交由上层模型决定\n1 核对 p 是下一个待消费位置，h 与 ring 属于同一请求和同一模型版本\n2 pre←该层输入投影(x)；按模型图决定 pre 是否再经过门控分支\n3 若 K_c>1：window←ring连接pre；否则 window←[pre]\n4 对 d：u[d]←Σ_j w[K_c−1−j]·window[j][d]\n5 对 d：v[d]←该层激活或门控(u[d],pre[d])；这是送入 SSM 的输入\n6 对 d：Δ[d]←softplus(a_d·pre[d]+b_d)\n7 由 pre 产生 B_t[n] 和 C_t[n]；按具体模型核对是否在 d 上广播\n8 对 d,n：\n     z←Δ[d]·A[d,n]\n     Ā←exp(z)\n     B̄←((exp(z)−1)/z)·Δ[d]·B_t[n]，z接近0时取极限\n     h_new[d,n]←Ā·h[d,n]+B̄·v[d]\n9 对 d：y[d]←Σ_n C_t[n]·h_new[d,n]；若模型有 skip，再加上 D_skip[d]·v[d]\n10 若 K_c>1：ring_new←(ring连接pre)的末K_c−1项；否则ring_new为空\n11 返回 y、h_new、ring_new。只有后续层、输出头和提交边界都完成后，逻辑位置才推进到 p+1\n```\n\n分块 prefill 复用同一结合关系。下面的 AffinePrefixScan 是双缓冲并行前缀模板；生产实现可以用工作高效的分层扫描减少重复工作，但必须保持同样的左右次序和块边界状态。\n\n```pseudocode\n算法 AffinePrefixScan\n输入：每步系数 a[t,n]、b[t,n]，t=0…L−1；初始状态 h0[n]\n输出：每个 t 消费后的状态 h[t,n]，以及末状态 hL[n]\n1 若 L=0：返回空状态序列和 h0\n2 cur_a←a，cur_b←b；d←1\n3 当 d<L：\n     nxt_a←全零，nxt_b←全零\n     对每个 i,n：\n       若 i≥d：\n         nxt_a[i,n]←cur_a[i,n]·cur_a[i−d,n]\n         nxt_b[i,n]←cur_a[i,n]·cur_b[i−d,n]+cur_b[i,n]\n       否则：\n         nxt_a[i,n]←cur_a[i,n]；nxt_b[i,n]←cur_b[i,n]\n     cur_a←nxt_a；cur_b←nxt_b；d←2d\n4 对每个 t,n：h[t,n]←cur_a[t,n]·h0[n]+cur_b[t,n]\n5 hL[n]←cur_a[L−1,n]·h0[n]+cur_b[L−1,n]\n6 返回 h 和 hL\n```\n\n```pseudocode\n算法 ChunkedPrefill\n输入：输入范围 x[p:p+L)、初始 h_start、初始 ring、层参数、块长 C\n输出：输出 y、h_end、ring_end，或失败而不发布部分状态\n1 核对 p、h_start、ring 的同一请求身份和层版本\n2 若 L=0：返回空 y、原 h_start、原 ring\n3 把范围分成不超过 C 的块；h_cur←h_start，ring_cur←ring\n4 对每个块：\n    对块内每个位置 t：\n       pre_t←输入投影(x_t)\n       用 ring_cur 和块内更早的 pre 计算因果卷积，得到 u_t\n       v_t←门控/激活(u_t,pre_t)\n       计算 Δ_t、B_t、C_t，进而得到 a_t＝Ā_t、b_t＝B̄_t v_t\n    用 AffinePrefixScan 对本块 a_t、b_t 求 h_t，初始状态为 h_cur\n    对每个 t 计算 y_t\n    只在本块全部必要写入和依赖完成后，h_cur←本块末 h，ring_cur←本块末 ring\n5 返回 y、h_cur、ring_cur；不能先发布 y 再补写状态\n```\n\n实际 kernel 可以把离散化、扫描和 C 的乘加融合，在片上保留中间状态，只把必要输出和边界状态写回 HBM。这个融合改变的是临时物化和同步成本，不改变状态语义。若框架在多个张量之间物化完整的 B×L×D×N 中间量，即使最后只保留一个小状态，瞬时峰值和 HBM 流量仍可能很大。\n\n## 状态包、检查点与共同恢复位置\n\n令 B_S 为一个完整递归状态包的字节数。若每层递归状态为 D_l×N_l 个 b_h 字节，卷积历史为 D_l(K_c,l−1) 个 b_z 字节，另有元数据 m_l，\n\nB_S＝Σ_l[D_lN_lb_h＋D_l(K_c,l−1)b_z＋m_l]。\n\n全注意力 KV、窗口 KV 和输出 logits 另计。检查点包含的是准确消费位置的完整状态；只保存 h 而漏掉卷积环、位置或必要 logits，不能构成可继续的状态包。恢复到 p 后若要从 p 生成，还需要 p−1 位置的输出分布，或选择一个更早的合法起点安全重算末行。\n\n设每 P 个 token 保存一次检查点，包括位置 0，则长度 n 的请求约有\n\nN_ckpt(n)＝⌊n/P⌋＋1\n\n个快照，容量约 N_ckpt(n)B_S。最坏重放步数不超过 P−1；目标位置在区间内均匀时，平均重放步数约为 (P−1)/2。P 变小会降低重放成本，却增加快照容量、写流量和 copy-on-write 峰值；P 变大则相反。这个权衡只在给定状态大小、重用分布和每步重放成本下成立，不能说某个 P 普遍最优。\n\n例如设一个完整递归加卷积状态包为 4.375 MiB，P=256，n=8192，则约 33 个快照，占用约 144.4 MiB；这是设定算例，不是引擎实测。若每 256 token 保存一次，命中长度 700 时最近的检查点是 512，需要重放 188 步；不能凭 768 的最终状态倒推 700。若 700 位置还有全注意力 KV，也只能说明该层可追加恢复，不能替代递归层的准确检查点。\n\n共同直接可恢复位置是各状态族可恢复集合与输入身份的交集：\n\nD＝I∩R_full∩R_window∩R_conv∩R_rec。\n\n全注意力保留 [0,b) 时可直接支持消费位置 0…b；窗口保留 [a,b)、窗口宽 W 时，正位置 p 要满足 max(0,p−W＋1)≥a 且 p≤b；卷积历史按 K_c−1 个旧输入同样检查；递归族只支持其检查点集合以及初始化位置 0。任何一族不满足，就不能把该位置称为完整可消费位置。存在缺页、sink token 或稀疏可见集合时，应按实际可见集合逐范围核对，不能压成一个最大长度。\n\n```pseudocode\n算法 PlanRecovery\n输入：目标 p、输入身份 I、全 KV 范围、窗口范围、卷积范围、递归检查点集合、状态包大小、资源预算\n输出：DirectPlan(p)、ReplayPlan(c,p) 或失败原因\n1 核对 p 在允许范围、I 相容、所有状态属于同一模型和请求代次\n2 若 p=0：检查初始化和固定源状态，必要时返回直接初始化计划\n3 对全 KV、窗口、卷积和递归族分别计算可恢复位置集合\n4 若 p 在交集中：保护命中对象，计算搬运/转换/可见性资源，尝试全量预留\n5   成功则返回 DirectPlan；失败则撤销保护并报告容量不足\n6 否则从小于等于 p 的位置中找最大的共同可恢复 c；没有则失败\n7 核对输入记录 x[c:p) 完整，且模型执行和数值契约支持重放\n8 计算重放所需 h/ring、私有尾页、窗口槽、暂存和输出资源\n9 尝试一次性预留这些资源；失败则撤销保护，不发布部分状态\n10 重放 c→p，逐位置提交完整状态族；任一位置失败则终止事务\n11 最终核对每族位置、表示、代次和可见性，发布 RecoveryView\n```\n\n重放 c→p 使用的输入已经确定，不是重新采样一条路径。读取 c 的视图时，全 KV 必须截到有效范围，窗口和卷积只暴露 c 需要的历史；即使物理页还存着更后的内容，也不能让重放 query 读到它们。共享前缀保持只读，递归状态和卷积环的写入使用私有副本或写时复制，直到整包提交。\n\n## 混合层、分页和联合成本\n\n混合模型把若干更新规则不同的状态族放进一个请求。设一个组有 m 层、每层每 token 的 KV 为 c 字节、token 块长为 P，则该组的页字节为\n\nM_group＝mPc。\n\n递归层每层保存一个状态快照 s_l 字节，卷积环另计。统一物理池要求不同组的页字节相同；若全注意力、窗口和递归状态的页字节不同，可以按族独立池，也可以同字节池、子分配或增大页并对齐。固定历史 vLLM Hybrid KV Cache Manager 文档在 Mamba 类不同状态大小下采用的办法是增大注意力块长，使 P·c_att≥s_mamba，再把每个 Mamba 状态填充到 P·c_att，然后采用不规则分组。该文档同时指出这可能使块长超过 400，并给出另一种填充方向仍为未完成设计；所以它是带条件的方案，不是统一最优解。\n\n对齐的代价是可见的：填充不产生有效历史，却占页容量；大页增加尾部浪费和分叉复制粒度；检查点若跟着大页走，会放大写流量。页字节相等只解决“一个池只有一种分配尺寸”，不证明共同恢复位置成立。\n\n混合 decode 的主项可以分层写成\n\nM_step≈M_weights＋Σ_full B L_l c_l＋Σ_window B W_l c_l＋Σ_rec B(s_l＋s_conv,l)＋M_meta，\n\n其中 B 是 batch，L_l 是该全注意力层当前可见长度，W_l 是窗口宽，s_l 是递归状态字节，s_conv,l 是卷积环字节。若状态被原地更新，还要按实际读写次数计入读和写；若状态在多步之间常驻片上，则 HBM 项可以减少，但这需要持久执行或明确的驻留证明。权重、KV、递归状态和临时展开不能重复相加；同一物理页的共享前缀只计一次。\n\nprefill 的临时物化是另一个成本。设 B=1、L=8192、D=2048、N=16、每元素 2 字节，则完整 B×L×D×N 中间状态约为 512 MiB；而末状态只有 2048×16×2＝64 KiB/层。融合扫描的意义是避免这个 512 MiB 临时量反复进出 HBM，不是把数学状态变小。能否融合仍受片上容量、块长、布局和输出需求限制；分块后必须携带边界状态，边界同步又可能成为短块的主要成本。\n\n混合模型的层组也不是同一种 kernel。全注意力层在长上下文下按 KV 读取增长；窗口层按 W 读取；递归层按状态和卷积环读取。把所有层强行套入同一种分页接口，可能浪费容量，也可能掩盖“某层尚未提交”的恢复条件。应按层组分别计算算术强度、字节数和同步，再看共享权重与调度能否重叠。\n\n## 投机、分支与覆盖式回滚\n\n投机验证从已知状态 S(p) 出发，一次计算多个候选位置，但最终只接受前缀中的一部分。设从 S(1024) 验证 4 个候选，最终只接受前 2 个；需要提交的是 S(1026)，不是把 S(1028) 的长度字段改成 1026。可选方案有三类：在每个可接受边界保存完整状态；保留 S(1024) 并重放已接受的两步；保存末行 logits 和足够的输出状态，但仍需证明后续递归状态可恢复。三者分别支付快照字节、重算时间或额外的输出状态。\n\n若递归加卷积完整状态包为 4.375 MiB，保留 4 个候选边界另需约 17.5 MiB，并产生相应写流量；只保留起点 S(1024) 时新增快照少，但接受后最多重放两个已接受 token。哪个更便宜取决于接受长度分布、状态读写带宽和重放成本，不能从“递归状态不随上下文增长”推出投机快照免费。\n\n混合 attention 层可以缩小未接受 KV 的有效范围，但未接受的窗口环槽可能已经覆盖旧历史；若窗口槽被覆盖，恢复还需要窗口快照或足够早的重放起点。RNG、grammar、输出缓冲和停止条件也必须与同一接受边界一起提交。一个常见错误是只恢复递归 h、把 KV 长度改小，或只恢复 token 计数器；这些都不构成完整状态回滚。\n\n多样本和搜索分支同理。共享的不可变前缀可以共用 KV 或递归检查点，但每个分支的覆盖式状态、随机轨迹和输出归属必须独立。分支淘汰后物理空间要等最后读者结束再回收；不能因为分支逻辑上已删除，就让仍在途的写覆盖下一分支。\n\n## 条件变化后的选择与区分实验\n\n条件变化时，先判断哪条依赖被改变。上下文更长且状态包固定时，检查点的容量占比下降、重放步数的绝对值仍由 P
