  "chapter": "# K-MODEL-007：窗口与稀疏 Attention：可见性、位置和状态保留\n\n窗口限制每个 query 的直接可见历史，使相关层的 attention 工作与 KV 保留量不再随全部历史等比例增长。逻辑位置仍持续增加，较早信息也可能经前层隐藏状态传播到更远处；因此丢弃旧 KV 不等于模型只利用最近 W 个原始 token。本章从可见集合出发，贯通保留对象、逻辑到物理映射、读取保护、分块归约和恢复条件。\n\n## 问题、函数与状态\n\n令 l 为层，t 为从 0 开始的 query 逻辑位置。窗口宽 W_l≥1 包含当前 token，普通窗口为 L_{l,t}=[max(0,t−W_l＋1),t] 的整数集合。因果窗口层的可见集合定义为\n\nA_{l,t}=L_{l,t}∪S_{l,t}∪G_{l,t}，\n\n其中 sink 集合 S 与 global 集合 G 都必须限制在 [0,t]，并按集合去重。全 attention 层为 A_{l,t}=[0,t]。这里讨论因果推理；能够读取未来位置的双向 global 规则需要完整的其他依赖图，不能直接使用本章的增量缓存算法。\n\n对 query head h，令 φ(h) 为其 KV head，q_{h,t}∈ℝ^d，k_{φ(h),j}∈ℝ^d，v_{φ(h),j}∈ℝ^{d_v}。无 dropout 的 attention 为\n\nz_{h,t,j}=a q_{h,t}·k_{φ(h),j}+b_{h,t,j}，\n\no_{h,t}=Σ_{j∈A_{l,h,t}} exp(z_{h,t,j}−m)v_{φ(h),j}/Σ_{j∈A_{l,h,t}} exp(z_{h,t,j}−m)，\n\nm=max_{j∈A_{l,h,t}} z_{h,t,j}。普通窗口通常各 head 共用集合，写成 A_{l,t} 即可；按 head 选择历史时必须保留 h 轴。要求可见分数与 V 有限；空集合的接口在本章规定输出零、质量为零，不能计算空最大值或除零。普通 W≥1 且当前 token 有效时，该行至少包含自己。\n\n输入是本层隐藏状态、窗口/全层/sink/global 规则、位置与偏置规则、query 到 KV head 的映射，以及已发布 KV、对象身份和完成票据。当前层投影产生 Q/K/V，K 按模型约定进行位置处理，再与合法历史参与归约，输出继续进入下一层。高层新 KV 来自高层输入，不能直接从原始 token 构造。输出包括 attention、本层新 KV 与物理映射，以及可共同提交的消费位置。\n\n状态至少包括计算身份 η、已提交消费长度 p、每层规则版本、对象目录、槽的逻辑位置和代次、可获取/关闭状态、在途读者票据、当前 chunk 的独立 staging 与归约状态。η 应区分模型、权重、输入前缀、位置规则和数值表示。必须区分“已分配”“已写入”“已发布”“仍保留”；任何一个长度字段都不能独立证明其他事实。\n\n## 窗口端点与合法选择\n\n若接口的 window_left=L 表示左侧 token 数，则范围为 [max(0,t−L),t]，对应本章 W=L＋1。Mistral 7B 的文字范围 i−W 到 i 含 W＋1 个整数位置，而图注和 rolling buffer 又描述最多 W 个 token 与 W 个槽。接入具体模型必须统一端点，让 mask、槽容量、恢复旧历史与检查使用相同合同；本章统一采用包含当前 token 的 W。\n\n原生窗口属于模型函数。给全 attention 模型缩小窗口，或按重要性删除当前仍可见的历史，会改变函数，需要独立质量评估。量化改变数值表示，卸载改变驻留位置，可恢复副本淘汰改变跨请求复用资格；这些变化应分别列账。全层与窗口层交替时，全层仍需完整历史，不能把一个 window 配置传播成所有层的覆盖许可。\n\n位置编码、相对偏置和 mask 使用逻辑位置及模型约定的位置坐标。槽 t mod W 只决定地址。已旋转 K 与未旋转 K 有不同的读写合同；覆盖后沿用旧位置、把槽号当位置或重复旋转都会改变函数。不可见项必须排除于 softmax 分子和分母；把 score 乘零不能保证其概率为零。\n\nGQA 中 H_q 个 query heads 共享 H_kv 个 KV heads。若不同 query heads 选择不同历史，必须声明共享选择、评分聚合或保留并集；并集会增加驻留，复制则增加唯一对象和读取。共享 KV 不自动消除各 query head 的点积与加权计算。\n\n## 额外保留对象与环形映射\n\n本章采用可直接实现的扩展：每层在执行前声明保护位置集合 P_l，包含该请求未来可能被 sink/global 规则重新读取的所有位置。对任何执行位置 t，要求 S_{l,t}∪G_{l,t}⊆P_l。P 可以包含尚未生成的位置；对象在该位置生成时才物化。普通窗口位置与 P 重合时只消费一次。\n\n窗口层有两个不相交的物理区域：W 个 ring 槽，以及按逻辑位置索引的 protected 对象表。j∈P 时只写 protected[j]，其余位置写 ring[j mod W]。读取始终使用同一分支；不能先在窗口内取模、窗口外再查 protected，否则同一个位置的地址会随 query 改变。ring 中允许出现未使用的槽或已经无资格的旧标签，这不构成额外可见历史。\n\n此基线将 protected 对象从生成保留到请求结束。临时 global 即使当前不活跃，也保留其对象供未来重新激活。它牺牲部分容量以得到明确的生命周期；若 P 随长度线性增长，额外驻留也线性增长，不能继续声称总缓存受 W 限制。输入已知且规则可预先枚举时，P 可以直接构造；若运行时才决定提升一个旧位置，必须在其原对象仍受保护时复制到独立对象、等待复制完成，并在同一目录协调点发布新映射。已经覆盖的内容只能从合法副本或模型重算恢复，改一张集合表不能生成它。\n\n```pseudocode\n函数 Visible(l,t):\n    若 t<0：返回空集合\n    若 Kind(l)=full：返回整数区间 [0,t]\n    A←整数区间 [max(0,t-Window(l)+1),t]\n    A←A∪(Sink(l,t)∩[0,t])∪(Global(l,t)∩[0,t])\n    要求加入的额外位置都属于 P_l\n    返回去重后的 A\n\n函数 Locate(l,j):\n    若 Kind(l)=full：返回 full_l[j]\n    若 j∈P_l：返回 protected_l[j]\n    返回 ring_l[j mod Window(l)]\n\n函数 WriteKV(l,t,k,v):\n    前提：本请求的推进所有者持有本层操作权\n          新数据位于独立 staging；被替换内容不再被待执行模型行需要\n    在目录协调区：\n        o←Locate(l,t)；首次使用时创建对象/槽描述\n        若 o 是已发布且同身份同位置的不可变对象：校验内容合同后复用，不覆盖\n        否则要求本次拥有写权；记录旧代 g\n        o.gate←CLOSING                  # 阻止新的旧代获取\n    离开协调区，等待 o 的旧代全部票据物理最后使用结束\n    将 staging 中本位置 K/V 及其元数据写入 o；等待写入完成和必要可见性\n    在同一协调区：\n        要求旧代票据为空、写者身份仍匹配\n        o.logical_pos←t；o.generation←g+1；o.identity←η\n        o.state←READABLE；o.gate←OPEN   # 原子发布新身份和获取资格\n    若写入失败：关闭该对象并使本次推进失败，禁止发布新消费位置\n```\n\nW=4、P={0} 时，写入 0 到 4 后，protected[0] 保存位置 0；ring 槽 1、2、3、0 分别保存位置 1、2、3、4。query 4 读取 {0,1,2,3,4}，位置身份与内容均存在。若再将位置 2 设为稍后才激活的 global，位置 2 也从生成时进入 protected[2]；它不会在位置 6 写入 ring 槽 2 时丢失。只在可见集合加上 0 或 2，而仍统一取模，会实际读到其他位置。\n\n## 读取获取、最后使用与淘汰\n\n身份核对和读者登记必须是同一个可线性化操作，且与关闭获取共享协调关系。可用互斥区、原子协议或具有同等保证的执行器实现；下面选择每层目录协调区来表达，不指定 GPU 原子指令。\n\n```pseudocode\n函数 AcquireSet(l,J,consumer):\n    tickets←空\n    在目录协调区内执行整个获取事务：\n        对 j∈排序去重(J)：\n            o←Locate(l,j)\n            若 o 不存在，或 gate≠OPEN，或 state≠READABLE，\n               或 identity≠η，或 logical_pos≠j：\n                撤销本事务已取得且尚未提交物理使用的全部票据\n                返回获取失败\n            创建唯一票据 τ=(对象句柄,generation,j,consumer,操作序号)\n            将 τ 加入 o 的在途集合及 tickets\n    返回绑定对象与代次的 tickets\n\n函数 Consume(ticket):\n    前提：票据仍有效，生产者完成和设备可见性已建立\n    从票据绑定的对象读取 K/V、位置和表示元数据\n    已获取旧代的消费者允许在 gate=CLOSING 时完成读取\n\n函数 Release(ticket,terminal_event):\n    核对事件与完整票据，且事件证明该操作不再物理访问对象\n    在协调区删除匹配的在途票据一次\n    未知、重复、错误位置或旧代事件不改变其他票据\n```\n\n正常释放发生在最后一次源对象读取结束后。若数据先复制到私有 tile，源对象可在复制真正完成后释放，而 tile 自身须保留到 QK/PV 最后使用结束。获取失败且未发出物理工作时立即撤销已取得票据；已提交工作失败或取消时，要等可靠终结事件排空，业务取消通知不能代替物理完成。\n\n读者获取成功后，写者只能关闭获取并等待；写者先关闭时，迟到读者获取失败，不得绕过 gate。旧协议允许“检查位置 0 成功→写者见读者为空并覆盖成 4→读者登记新代再读”，代次字段无法撤回错误读取。新协议把核对与登记绑定，明确排除了中间窗口。\n\n票据只保证已经获取的物理使用，不保证将来尚未登记的模型 query 仍能取回内容。本章另规定每请求同层一次只有一个推进操作：chunk 开始先取得全部旧历史保护，chunk 完成后才更新 ring，下一 chunk 在更新完成后开始。异步导出等额外读者仍遵守上述 gate 协议。允许多个模型 chunk 同时推进的引擎必须在退休前保护所有待执行依赖，或保留不可变版本；只等待当前票据为空不够。\n\nprotected 对象在此基线中只在请求结束、全部持有者解除且物理使用排空后回收；full 对象同理。ring 覆盖还要满足顺序推进后的语义条件。共享前缀对象不可原地改写，分叉需要私有槽或写时复制。若采用更早淘汰 protected 的策略，必须证明未来不再使用、所有已准入依赖已结束且无需承担恢复责任，再关闭获取和排空。\n\n## 分块 prefill：互斥归约与安全更新\n\nquery chunk 为 [b,e)，Q=e−b；每行使用自己的 A_q。本层输入已经由前层生成，当前 chunk 的 K/V 放入独立 staging，不先灌入 ring。旧历史为\n\nU=∪_{q∈[b,e)}(A_q∩[0,b))。\n\n对每行定义 O_q=A_q∩[0,b)、C_q=A_q∩[b,e)。因果条件保证 O_q∩C_q=∅、O_q∪C_q=A_q；每个 key 必须恰好贡献一次。候选块覆盖 U 不表示整块都属于 U。\n\n逐行归约状态为 X=(m,ℓ,N)，空状态为 (−∞,0,0)。加入有限分数 z 和 value v 时，若 ℓ=0，置 X=(z,1,v)；否则令 m′=max(m,z)，r=exp(m−m′)、w=exp(z−m′)，更新 ℓ′=rℓ+w、N′=rN+wv、m←m′。结束输出 N/ℓ。这样分母与分子具有相同尺度；块式合并也必须满足集合不重叠。\n\n```pseudocode\n函数 PrefillChunk(l,b,e,B):\n    要求 B≥1、0≤b≤e，且 b 是本请求当前已提交的本层起点\n    若 b=e：返回空输出，不写缓存或等待不存在的票据\n    取得本请求本层推进权；冻结本次规则、位置和目录视图\n    从本层输入生成 [b,e) 的 Q/K/V；按位置合同处理 K，放入私有 staging\n    对 q∈[b,e)：A_q←Visible(l,q)；X_q←空归约状态\n    U←∪(A_q∩[0,b))\n    tickets←AcquireSet(l,U,本chunk)\n    若获取失败：不发布输出；释放未提交使用的保护并返回具体缺项\n\n    old_blocks←排序去重 {floor(j/B) | j∈U}\n    对 k∈old_blocks：\n        J←[kB,min((k+1)B,b))∩U\n        对 j∈J：通过 tickets 中绑定的对象取得本代 K/V\n        对 q∈[b,e)：\n            对 j∈J∩A_q：用本行分数和 V[j] 更新 X_q\n\n    对 k 覆盖 [b,e) 的逻辑块，按块号递增：\n        J←[max(kB,b),min((k+1)B,e))\n        只从 staging 载入 J 内真实 K/V\n        对 q∈[b,e)：\n            对 j∈J∩A_q：用本行分数和 V[j] 更新 X_q\n\n    等待全部旧对象物理最后使用，按完整票据释放保护\n    对每行：ℓ>0 时输出 N/ℓ；否则按空行合同输出零\n    等待本chunk归约与输出完成；失败则不发布完整成功\n    若为 full 层：将当前 [b,e) 全部位置写入私有/独占追加区\n    否则：\n        T←([b,e)∩P_l)∪[max(b,e-W),e)\n        对 t∈排序去重(T)：WriteKV(l,t,staging.K[t],staging.V[t])\n    全部必要写入成功后，提交本层边界 e；解除推进权\n```\n\n旧路径实际加载的逻辑位置被截到 [0,b) 并与 U 相交；当前路径实际加载被截到 [b,e)。尾部填充 lane 不生成或解引用越界地址。ring 跨末端或 protected 分散时，一个逻辑 key block 需要按 Locate 拆成多个物理片段，不能把块号乘 stride 当成连续地址；向量加载也只能覆盖属于已保护对象的真实字节。mask 不能使非法地址读取合法。\n\n写回只保留当前 chunk 中最终窗口尾部和 P 中的新位置，避免长 chunk 在写回时无意义地逐项覆盖；不在 T 中的 staging 在最后使用后释放。已有 protected 历史继续保留。归约前不覆盖旧 ring，因此即使 Q>W，也保留了第一行需要的旧历史。W=1 时旧局部历史为空，当前路径仍能完成自身 attention；sink/global 的旧对象照常从 protected 获取。\n\n取 W=4、[b,e)=[5,7)、B=4，U={2,3,4}。旧逻辑块 1 的几何范围还包括 5、6、7，但旧路径只消费其中的 4。query 5 的旧项是 {2,3,4}，当前项是 {5}；query 6 分别为 {3,4} 和 {5,6}。等分数且 V[j]=j 时，query 5 输出 3.5。若旧路径只检查 j∈A_5，会额外消费 staging 中的 5，当前路径再消费一次，输出变成 3.8。集合并集检查会漏掉这种重复，必须同时检查贡献次数或数值。\n\n本层提交不是整个模型恢复视图的发布。其他层及状态族必须支持同一个消费位置，才能对外发布共同边界。基线的原地写回若中途失败，可能已改变部分槽；它不承诺回滚到 b，应使本次状态失去继续资格，从稳定副本或合法共同起点重放。需要失败后保留旧视图时，应使用私有候选、写时复制和统一提交，并将其峰值成本计入。\n\n## 恢复与块表的有效范围\n\n下一 query 位于 p 时，普通窗口需要的旧位置为 [max(0,p−W＋1),p)，当前位置 p 由新输入产生。为支持本章 P 的未来激活规则，窗口层恢复包要求\n\nR_l(p)=[max(0,p−W_l＋1),p)∪(P_l∩[0,p))。\n\n只核对当前活跃 global 集合不够：一个目前不可见、稍后重新激活的位置仍属于保留责任。全层要求 R_l(p)=[0,p)。W=1 且 P 为空时 R_l(p) 为空，初始化合法即可恢复。\n\n```pseudocode\n函数 RestoreLayer(l,p,source):\n    核对 η、前缀身份、规则版本、位置与表示合同\n    按 R_l(p) 取得源对象保护；逐项核对内容位置、范围和完成状态\n    任一缺项：返回缺项或合法重放需求，不修改可执行长度\n    创建私有目标映射；P 中位置放 protected，其余按 j mod W 放 ring\n    复制/映射必需内容和数值元数据；建立目标端完成与可见性\n    目标对象使用本地新代次；不借用源端未结算票据\n    全部完成后提供未对外发布的本层候选\n    所有必需层/状态族在同一 p 齐备后，才发布共同恢复视图\n    失败时停止新提交，排空已发出操作，再释放源保护和私有目标\n```\n\n恢复的旧窗口只有 W−1 个位置，模 W 互不冲突；P 与 ring 地址域分开。共享对象继续只读，下一次写入进入私有区域。若只有 KV 而没有末行 logits，恢复成功还不等于已经取得第一个生成分布；需保存相同合同的 logits，或从合法共同起点安全重算所需后缀，不能仅改长度。\n\n规则窗口的候选块可以由端点推导，不规则集合则需要扫描、排序或压紧。对 query 块 R，候选表为排序去重的 {floor(j/B) | q∈R,j∈A_q}，逐行仍需 mask。追加、窗口移动、P/global 规则版本变化、环槽复用和 batch 重排都会使几何或地址映射失效；图模式仅保留表地址不能证明表内容正确。\n\nW=256、B=64 时，t=255 的窗口 [0,255] 覆盖 4 块；t=256 的 [1,256] 覆盖 5 块。Q 个相邻 query 的局部窗口并集最多 W＋Q−1 个位置，块对齐还可能增加候选块数。固定只取 4 块可能漏首块或尾块，取决于错误的起点算法；只用最后行窗口会漏掉前面行的旧历史。\n\n##
