{"chapter":"# K-ALG-015：推理并行：张量分解、流水、专家与上下文\n\n并行策略不是把模型平均切到更多设备。它改变每个张量的所有者、每层的同步边界、每类状态的驻留位置，以及失败时需要保留或重建的对象。一个可用方案必须同时说明：哪些维度被切分，哪些状态被复制，通信在何处发生，消费者何时可以读取，以及条件变化后哪项成本会反转选择。\n\n## 问题、对象与不变量\n\n设第 l 层输入为 H_l，形状 T×d，T 是本地有效 token 数，d 是 hidden 维；权重矩阵为 W，激活和权重元素字节数分别为 b_a、b_w。层输出 H_{l+1} 仍属于同一逻辑模型函数。并行计划 π 把逻辑对象映射到 rank：层区间、输出通道、输入通道、query/KV head、专家、上下文 token 区间和请求副本。映射的对象身份至少包含模型版本、层、token 位置、head 或专家编号、dtype、量化和布局。\n\n一次并行执行的状态不是只有权重。它还包括：每 rank 的权重分片、KV 或 MLA latent、流水中的激活与微批记录、EP 的路由表与接收桶、CP 的局部 softmax 统计、通信缓冲、工作区，以及未完成集合通信或传输的完成责任。输入是请求 token、模型权重和并行计划；输出是下一层 hidden、logits 或生成 token；中间状态必须可解释为哪一次尝试、哪一逻辑对象和哪一消费者仍持有访问权。\n\n正确性不变量如下：\n\n1. 未被声明为复制的逻辑元素只能有一个最终所有者；归约必须对所有分片恰好执行一次。\n2. 复制必须带同一模型版本、精度和布局契约；同名副本不代表数值等价。\n3. 集合通信的参与者必须执行相互匹配的逻辑操作，count、datatype 和调用顺序不能被某个 rank 因本地空工作而跳过。\n4. 消费者只在生产完成、布局可见且身份校验后读取；发送调用返回不等于目的端可复用。\n5. padding、空专家、空 KV 分片和零 token rank 不得进入有效语义、归约分母或采样结果。\n6. 失败或取消后，已提交操作仍须排空；逻辑终止不等于物理缓冲立即可重用。\n\n合法条件与方案选择要分开。维度可整除、后端支持对应集合操作、GQA/MLA 的全局 head 映射存在、PP 层区间完整覆盖、EP 每个被选专家贡献恰好一次、CP 使用全局位置和正确 mask，这些是合法性条件。某实现选择 ring 还是树形 all-reduce、连续还是交错层切分、是否复制热点专家、是否把 attention 与 MoE 分成不同执行组，则是带前提的方案选择。\n\n## 张量并行：矩阵分片、通信与所有权\n\n对线性层 Y=XW，X 为 T×d_in，W 为 d_in×d_out。列并行把 W 的输出通道切成 p 份，rank r 计算 Y_r=XW_r，得到 T×(d_out/p) 的部分输出；若后续消费者需要完整输出，则要按输出列拼接。行并行把 W 的输入通道切成 p 份，同时把 X 的列切成 p 份，rank r 计算 P_r=X_rW_r，完整输出是 Y=Σ_r P_r，必须执行求和归约。\n\nTransformer 常把 QKV 投影和 FFN 上投影做列并行，把 attention 输出投影和 FFN 下投影做行并行。这样 attention 在各 rank 上处理本地 heads，行投影只产生部分和，再用一次 all-reduce 得到完整 hidden。该组织是一种常见候选，不是唯一合法布局；融合算子、reduce-scatter、sequence parallel 或不同的 residual 归属会改变通信次数和缓冲生命周期。\n\n```pseudocode\n算法 TP_ROW_COLUMN_LAYER\n输入：X（T×d_in），权重 W，并行度 p，模式 m∈{COLUMN,ROW}，rank r\n输出：COLUMN 模式下本 rank 的局部输出；ROW 模式下归约后的完整 Y\n前提：所选维度的分片合法；任何 padding 已标记且不进入语义分母\n\n1 若 m=COLUMN：\n2   要求 d_out 可被 p 整除，或使用显式不均匀切片并记录每 rank 范围\n3   W_r ← W 的第 r 个输出列区间\n4   Y_r ← X W_r\n5   返回 Y_r\n6 若 m=ROW：\n7   要求 d_in 可被 p 整除，或使用显式不均匀切片并记录每 rank 范围\n8   X_r ← X 的第 r 个输入列区间\n9   P_r ← X_r W_r\n10  Y ← ALLREDUCE_SUM(P_r, group=TP)\n11 返回 Y\n```\n\n列并行的输出分片若直接供下一个行并行层使用，可以避免中间 gather；但 attention 输出投影、residual 和下一层输入需要完整 hidden 时，必须明确由哪次归约产生完整值。行并行的部分和不能在没有归约时被当作最终输出。归约后的 residual 加法也要保持每个 token 只加一次，不能让各 rank 分别加完整 residual 后再次求和。\n\n设一个完整 hidden 张量为 A=T d b_a 字节。对 ring all-reduce，在理想均匀、无争用、每 rank 输入 A 字节的设定下，每 rank 的发送量约为 2(p−1)A/p 字节；接收是另一计量边界，不在发送量中重复相加。若一个 Transformer 块有两次这样的行并行归约，合计每 rank 发送 4(p−1)A/p 字节。设 p=4、d=4096、b_a=2，T=1 时 A=8 KiB，两次发送合计 24 KiB；T=2048 时 A=16 MiB，两次合计 48 MiB。这里只算发送账，启动延迟、packing、暂存和慢 rank 另计。\n\nTP 的收益来自每 rank 计算和权重驻留下降，代价是每层高频集合通信。小 batch decode 的矩阵乘计算时间短，all-reduce 的启动与同步容易占主导；prefill 的 T 较大，数据量和有效带宽更可能成为主项。KV heads 少于 TP 数时，attention 可能复制 KV 或采用部分头复制；每 rank KV 不能机械地除以 TP。MLA 若在 TP 组内复制整份 latent，则每 rank 的 attention 状态仍按完整 latent 计，不能把 TP 名称直接当作状态压缩。\n\n非整除 hidden、FFN、head 或 vocabulary 维度可以用不均匀分片、显式 padding 或改变并行度处理。padding 不得进入有效词表采样、softmax 分母或损失；以均匀 shape 分配后静默舍弃尾部则不合法。以最大 rank 的实际分片计算时间和容量，不能只看平均值。\n\n## 流水并行：时间线、气泡与状态\n\nPP 按层或层组把模型分为 P 个阶段，阶段 s 只持有 L_s 层。前向时，阶段 s 接收上一阶段激活，执行本阶段层，再把激活交给下一阶段。多个微批可以填充流水，使某些阶段在等待其他微批时仍有工作；单个请求的 token 仍要经过全部阶段，因此 PP 主要帮助容纳大模型和提高吞吐，不自动降低单请求的计算总延迟。\n\n理想模型先令阶段 s 的执行成本为 c_s，微批数为 M，忽略通信和资源冲突。1F1B 或等价同步流水在等成本阶段、无重叠损失时，最后完成时间可写成 (M+P−1)c，其中 M c 是有效工作，P−1 个 c 是填充/排空气泡。气泡比例为 (P−1)/(M+P−1)。当 M 增大时气泡比例下降，但同时增加在途激活、接收槽和状态驻留。单请求 M=1 时没有其他微批可填气泡，延迟仍接近各阶段成本之和加阶段通信。\n\n```pseudocode\n算法 IDEAL_PIPELINE_COMPLETION\n输入：阶段数 P，微批数 M，阶段成本 c[0..P−1]\n输出：无资源冲突时的完成时间与气泡\n\n1 对 s=0..P−1、m=0..M−1：\n2   prev_stage ← 0 若 s=0，否则 finish[s−1][m]\n3   prev_mb ← 0 若 m=0，否则 finish[s][m−1]\n4   start[s][m] ← max(prev_stage, prev_mb)\n5   finish[s][m] ← start[s][m] + c[s]\n6 返回 max_m finish[P−1][m]\n```\n\n实际 PP 还要维护微批状态：激活属于哪个请求、哪个版本和哪个位置；阶段 s 只能在接收完成后读取；阶段 s 的发送完成不等于下游已经计算完成。源阶段在发送完成后可以释放本地发送副本，但下游仍持有接收副本；若要取消或重试，必须区分已提交阶段、未提交阶段和在途传输。阶段边界还可能携带 metadata、位置、cache 页表或量化尺度，不能只搬 hidden 字节。\n\n阶段不均衡会破坏气泡公式。若某个阶段成本为 max_s c_s，其他阶段等待它，流水吞吐受慢阶段限制。阶段切分应按实际 attention、专家和通信成本，而不是只按层数均分。解码逐 token 自回归、长度不同、慢阶段和请求到达轨迹都会改变理想条件；通信重叠只有在存在可独立推进的微批、足够缓冲且传输与计算不争同一资源时才成立。\n\n## 专家并行：路由、分派与合并\n\nMoE 层对每个 token 先计算路由分数，选择 k 个专家，并按模型契约得到 gating 权重。Mixtral 的公式可写为 G(x)=Softmax(TopK(xW_g))，输出为 Σ_i G(x)_i E_i(x)；每个 token 只激活部分专家，总参数和每 token 激活参数是不同数量。DeepSeek-V3 v1 则使用 sigmoid affinity、带 bias 的 top-k 选择，但 gating 仍由原始 affinity 归一化得到；bias 只用于路由选择，不能混入最终加权。不同模型的 router 和共享专家规则必须在实现前固定。\n\nEP 把专家放到不同 rank。每个逻辑 item 是 (token, expert, gating weight, origin)。目的 rank 由专家放置映射决定；远端 item 需要 dispatch hidden，专家计算后把结果返回 origin 并 combine。每个 token 的每个被选专家贡献恰好一次，是比“消息发送成功”更强的正确性条件。\n\n```pseudocode\n算法 EP_FORWARD\n输入：本地 token 集 B_r，router 规则，专家放置 owner(e)，专家函数 FFN_e\n输出：本 origin 的 token 输出\n\n1 对每个 t∈B_r：\n2   s_t ← router(x_t)\n3   S_t ← TopK(s_t, k)\n4   g_t ← 按模型契约归一化选中项\n5 生成 item (t,e,g_t,e,origin=r)，目的者为 owner(e)\n6 按目的 rank 和专家分桶；同一 token 到同一目的 rank 可去重 hidden 或建立引用\n7 各 rank 对每个非空专家桶执行 grouped GEMM；空桶不执行\n8 为每个 item 生成返回记录，保持 t、e、origin、gating weight\n9 目的端可按 (t,origin) 预合并同一 token 的多个专家输出；否则逐项返回\n10 origin 按 t 聚合全部已选专家；缺失、多出或代次不符都失败\n11 返回 y_t；共享专家和模型特有条目另按契约加入\n```\n\n设 d 为 hidden 维，f 为 expert 中间维，N_items=Σ_t |S_t|。若一个专家由三个 d×f 矩阵组成，routed 算术主项可记为 6df N_items；两矩阵 FFN 则是 4df N_items。这个量是有效算术，不是权重驻留量。全部专家权重、shared 专家、冗余副本和 grouped GEMM workspace 分别进入容量账。\n\n跨 rank 流量按远端 item 数 N_remote 和远端 token-destination 对数 D_remote 计。每个远端 item 的 dispatch 主项为 d b_h 字节，返回主项为 d b_y 字节；若同一 token 到同一目的 rank 只发一份 hidden，则 dispatch 用 D_remote d b_h。返回若逐 item 发送则为 N_remote d b_y，若目的端预合并则为 D_remote d b_y。metadata、计数、padding、重传和下一步 TP 布局转换另计。去重 hidden 不能证明专家中间激活消失，也不能证明 combine 已完整。\n\n热点专家会使一个 rank 成为慢端。训练统计的均衡不保证在线小批均衡；冗余副本可以分担同一专家函数，但会增加权重驻留和副本读取，并可能拆小组长。DeepSeek-V3 v1 报告 prefill 使用 32 GPU、decode 使用 320 GPU 的分阶段部署，并用冗余专家处理在线偏斜；这些是该固定版本的部署策略，不是模型理论最少硬件或通用最优布局。\n\n## 上下文并行：在线 softmax 的分片合并\n\nCP 把长上下文的 token 位置分片。对 query q 和 key 集合中的位置 j，分数为 s_j=q·k_j/√d_h。把 key 位置划分为若干分片 G_r，每个分片可独立计算局部最大值 m_r、局部指数和 l_r=Σ_{j∈G_r} exp(s_j−m_r)，以及局部加权值 a_r=Σ_{j∈G_r} exp(s_j−m_r)v_j。合并两个分片时，令 m=max(m_1,m_2)，则\n\nl = exp(m_1−m)l_1 + exp(m_2−m)l_2\n\na = exp(m_1−m)a_1 + exp(m_2−m)a_2\n\n最终输出为 a/l。空分片用 m=−∞、l=0、a=0 表示，它是该合并运算的单位元。这个代数恒等式是在线 softmax 可合并的基础；它不消除跨分片通信，也不证明浮点逐位一致。\n\n```pseudocode\n算法 CP_ATTENTION_MERGE\n输入：query q，K/V 分片列表，全局位置，causal 或窗口 mask\n输出：该 query 的 attention 输出\n\n1 对每个分片 r：m_r←−∞，l_r←0，a_r←0\n2 对分片 r 中每个位置 j：\n3   若 j 不被该 query 的全局 mask 允许，跳过\n4   s ← q·k_j/√d_h\n5   若 s>m_r：\n6     scale ← exp(m_r−s)，若 m_r=−∞ 则 scale←0\n7     l_r←l_r·scale；a_r←a_r·scale；m_r←s\n8   w←exp(s−m_r)\n9   l_r←l_r+w；a_r←a_r+w·v_j\n10 按分片顺序合并所有 (m_r,l_r,a_r)\n11 若合并后 l=0，按模型契约处理空可见集合；否则返回 a/l\n```\n\ncausal mask 必须使用全局位置。把局部 token 从零重新编号会改变可见关系，把后一片的 key 错当成前一片的 key 也会改变输出。窗口 attention 或稀疏可见性改变每个 query 的合法 key 集合，从而改变应交换的数据量；不能把全上下文的 K/V 交换量直接套给窗口模型。若 query 本身也分片，每个 query 只读取自己的输出，K/V 分片仍要按全局位置和 mask 组织。\n\nCP 的通信可以有多种方案：每 rank 保留本地 Q，轮流接收其他分片的 K/V；先 all-gather K/V；或按 head/sequence 轴重排。不同方案的通信次数、临时空间和查询复制不同。应分别记录持久 K/V、当前查询展开、远端接收暂存、softmax 统计和合并 workspace。不能同时取一种方案的低流量和另一种方案的低暂存，作为同一个候选。\n\n## 组合候选：四卡 MLA/MoE 的容量与时间账本\n\n以下全部为设计设定，不是 DeepSeek 型号规格或性能实测。任务为 16 个并发生成请求，prompt 为 2048–8192 token，输出目标 128 token，客户端 ITL 目标 40 ms；使用固定 MLA/MoE checkpoint 和 BF16 参考质量。资源为 4 张各 24 GiB 可供本任务使用的 GPU。假设权重共 48 GiB，其中 attention/其他 dense 部分 12 GiB、所有专家 36 GiB；模型 32 层、latent 512 维、RoPE key 64 维、状态 BF16。最长输入下每请求逻辑缓存 288 MiB，16 请求共 4.5 GiB。\n\n候选 A 在四卡上做 TP4，专家矩阵也切分；候选 B 保持 attention TP4，MoE 改为 EP4；候选 C 为 PP2×TP2，每个阶段各持一半层。A/B 若各 rank 复制所服务请求的整份 MLA latent，则每卡权重 12 GiB、prompt 结束时 KV 4.5 GiB，另设 workspace/通信 2 GiB，主项 18.5 GiB。C 按等层切分使 prompt 结束时每卡 KV 2.25 GiB，在相同设定下主项 16.25 GiB，但逐请求增加跨阶段依赖及流水气泡。不能仅因 C 占用更低便断言它的 ITL 最小。\n\n为输出的 128 个 token 预留新增状态时，每请求再增 4.5 MiB；16 请求在完整 latent 复制的每个 rank 上增 72 MiB，即 0.0703125 GiB，A/B 主项成为 18.5703125 GiB。C 每 rank 只持一半层，增 36 MiB，主项为 16.28515625 GiB。这仍不是完整峰值保证：页尾、程序与运行时、量化元数据、加载和其他在途缓冲必须继续预留；若最后输出 token 尚不进入模型状态，预留可略多于实际使用，不能反过来省掉必要增长预算。\n\n| 候选 | 主要机会 | 需要区分的代价 |\n|---|---|---|\n| A：全层 TP4 | 权重均匀分担，避免专家目的端偏斜 | 每层归约、小 expert 分片 GEMM、latent 复制 |\n| B：attention TP4 + MoE EP4 | 专家矩阵更完整，grouped GEMM 与副本可调 | 分派/返回、热点专家、边界 token 所有权 |\n| C：PP2×TP2 | 每卡状态下降，TP 组较小 | 阶段激活、气泡、慢阶段及单请求完整往返 |\n\nB 的 attention 输出在组内复制时，MoE 边界先为每个 token 选定唯一派发所有者；不能让四个 rank 都重复发送同一完整 hidden。设一层 top-2、16 token、hidden 4096、BF16，远端分派比例为 3/4，且未做同目的去重，则 24 个远端项各发送 8 KiB，返回同样大小，组级专家 dispatch/return 主流量合计 384 KiB，另有 metadata。所有者完成 combine 后，还要按下一 attention TP
