# K-MODEL-012：全模态系统：多时钟、分支依赖与背压

全模态推理包含多个有依赖的计算分支。源采样、模型位置、文本生成、声学生成和客户端播放各有自己的时钟。系统必须记录一个结果属于哪个请求、代次、源区间和计算前沿，才能判断它是否允许被消费。“算完”“已提交”“已发送”和“已播放”是不同事实。

Qwen2.5-Omni 的 Thinker/Talker 是具体实例：Thinker 产生文本及高维表示，Talker 接收这些条件，自回归生成语音 token，随后由 Flow-Matching DiT 和 BigVGAN 转为波形。不同阶段既有重叠机会，也有必须满足的依赖。把各分支耗时相加可能高估延迟，直接取最大值又会漏掉串行依赖。

## 对象、坐标与提交前沿

请求身份记为 r=(q,g,v)：q 为逻辑请求，g 为执行代次，v 包含模型、processor、模板与声学边界契约版本。模态 m∈{txt,aud,vid}。源块携带源标识、半开源区间 [τ0,τ1)、内容摘要和到达时间。源时间与接收时间分开保存；乱序与重传不能改变媒体事件的时间。

给定锚点 τ_anchor 和模型输入块长 Δ_m，第 b 块覆盖 [τ_anchor+bΔ_m,τ_anchor+(b+1)Δ_m)。边界只属于后一块。Qwen2.5-Omni 报告对带声音视频按实际时间划分 2 秒块，块内视觉表示在前、音频表示在后；音频 encoder 也按 2 秒块做 attention。输入块、Talker 声学 code 块和网络包是三个对象，不能默认块长相同。

TMRoPE 将位置分为时间、高和宽。报告中一个音频时间 ID 对应 40 ms，视频时间 ID 按实际帧时间调整；图像视觉 token 的时间 ID 不变，高宽 ID 随空间位置变化。对恰好位于 40 ms 格点的相对时间，可写 q_aud(τ)=(τ−τ_anchor)/40 ms。非格点的取整、抽帧与插值由固定 processor 决定。后一模态的位置编号从前一模态的最大位置 ID 加一开始；不能把 encoder 行号当原始 sample offset，也不能把时间 ID 当作不同模态 token 数的等价单位。

本章用排他前沿计数，初始均为 0：

| 状态或前沿 | 精确定义 |
|---|---|
| ALIGNED / ENCODED | 源区间已形成合法输入块 / 该块全部 encoder 层与桥接已完成并发布 |
| Thinker known、n_T | 已知输入序列 / 所有 Thinker 层共同完成的输入位置数 |
| p_T | 已提交条件记录数；c_0,…,c_{p_T−1} 可被 Talker 读取 |
| p_K | 已完整纳入 Talker 持久状态的条件记录数；未消费队列为 [p_K,p_T) |
| TEXT_ACTIVE / TEXT_DONE | Thinker 允许继续生成 / 文本生成已不可逆停止 |
| condition_final | 条件流关闭时冻结的最终 p_T；关闭后不能追加条件 |
| n_K、j_A | Talker 已消费的内部输入位置数 / 已选择的有效声学 code 数 |
| Q_code、b_D | 已封闭 code 块及末尾未封闭块 / 下一个待解码块编号 |
| pcm_end、sent_end | 已稳定生成 / 已交给协议发送层的排他 sample offset |
| acked_end / played_end | 仅在客户端协议提供确认时记录的接收或播放前沿 |

p_T、p_K 的共同单位是“一个 Thinker 条件记录”，包括模型规定的结束控制记录。它们既不是声学帧数，也不直接代表秒数。领先量 L=p_T−p_K。固定每记录一个文本 token 时，L 也是待消费文本条件数，但 token 数不等于可听语义时长；同步说写还应另测文本与音频的语义滞后。

条件 c_k=(q,g,v,k,i,H_i,y_k) 同时包含 Thinker hidden 和采样文本 token。位置 i 是产生预测的已消费输入位置，y_k 是该预测选择的下一 token。报告说明仅 hidden 可能保留语义相似性而不能消除发音歧义，因此不能省去 y_k 的 embedding。

所有成功提交保持：各层有效 KV 长度等于相应 n；下游只读完整、身份匹配的产物；队列不丢弃已承诺内容；p_K≤p_T；sample offset 单调且无重复区间。TEXT_DONE 后 p_T、文本事件序列和 condition_final 冻结，但 Talker、声学解码、发送和确认仍可继续。代次门拒绝旧结果发布，物理缓冲还必须等最后访问完成才能重用。

## 合法输入、声学窗口与首尾边界

源输入只有完整覆盖模型块，或满足明确的末块规则时才可进入 encoder。部分末块需要固定的 padding、有效长度与 mask；填充值不算真实源数据。内部缺口不能借用“末块不足”规则跳过。更改已编码区间、processor 或多模态排列，会改变后续函数和缓存身份。

encoder 的稳定提交还要求其所有合法上下文就绪。代表块式 encoder 可在块内做双向 attention，访问哪些历史块由模型 mask 决定；不能把当前完成的一行在其他必需上下文未到时提前发布。各层依次从输入特征计算 Q/K/V，在合法位置集合上做缩放点积、稳定 softmax 和 V 加权，再执行投影、残差、norm 与 FFN。视觉 patch 的空间网格和 merge、音频卷积或降采样均先按 processor/encoder 契约完成，桥接特征与位置元数据一起发布。视觉几何的进一步展开见[视觉语言模型](vision-language.md)。

生成侧也必须固定源可见性。本章逐层推导采用一次回复的固定合法多模态 prompt：源可以分块准备和 prefill，回复生成使用其已承诺快照。若模型支持在同一回复中继续插入媒体，必须另给出插入位置、mask 和旧状态稳定性契约。不能因为 encoder 支持块处理，就默认任意追加源都能沿用正在生成的全部 KV。持续摄像与打断可由后续回合或新代次组织。

报告的 DiT 窗口包含前 2 块、当前块和后 1 块。内部块 b 的逻辑窗口为 {b−2,b−1,b,b+1}，但首尾必须分别处理：

- 左边界：b=0 的 −2、−1，b=1 的 −1 不会由生产者生成。初始化时必须提供模型参数 B_left，说明这些位置采用哪些已核验的初始状态、mask 或填充；续接旧音频时则使用属于同一合法流的真实历史。二者不可互换。
- 右边界：只有 Talker 已产生合法语音结束、code 流已封闭为 N 个块时，位置 j≥N 才能交给 B_right 处理。输入源 FLUSH、Thinker TEXT_DONE 与 code 流结束是不同事件；前两者不能单独授权右侧补齐。
- 窗口内的非负历史位置必须来自真实且已封闭的 code 块；缺失意味着等待实际生产、非法缺口或过早回收，不能用左边界契约覆盖。
- BigVGAN 还需独立提供初始状态、固定感受野、尾部处理、overlap 裁剪及实际样本长度规则。DiT 就绪不自动表示 PCM 已稳定。

固定报告没有给出上述边界参数的全部数值和实现。本章将 B_left、B_right、B_vocoder 列为部署模型必须提供并核验的参数；缺失时返回 FAILED_BOUNDARY_CONTRACT，不能等待负编号块。检查中的“屏蔽负编号位置”只是显式声明的合成契约，不是 Qwen2.5-Omni 的已核验实现。

因此非 FLUSH 的首包路径可以是：真实 code 0、1 已封闭，左侧由 B_left 合法初始化，解码块 0；此时不需要语音结束。只有 code 0 时仍需等待真实 code 1。若整个语音只有一个块，则语音结束后才可用 B_right 处理其右侧。空语音是否允许、末块是否可不足整块，也由模型契约规定。

容量还必须支持这些依赖。按顺序解码并保留前两块时，常规四块窗口需要能够同时保留相关 code；若容量只能容纳当前块却必须先生成下一块，背压会形成循环。准入应保证最小窗口、未封闭块及一个最大输出事务的容量。永久不可能装下的原子事务应拒绝，不能无限 WAIT_CAPACITY。

## 从已知输入到文本与双轨声学状态

先展开两个 decoder 共用的代表性逐层机制。它用于恢复输入、KV、logits 和选择的对应关系，不宣称报告公开了所有层配置。实际 norm 顺序、GQA、位置变换、激活和头结构必须采用固定模型定义。

设非空 prompt 为 z_0,…,z_{m−1}，其位置可包含文本 embedding 和桥接后的媒体特征。后续 z_{m+k}=y_k。消费位置 i 后得到末层 H_i，logits_i 预测位置 i+1。故首个 y_0 配对 H_{m−1}，一般 c_k 配对 H_{m+k−1} 与 y_k。选择 y_k 后，其自身位置 m+k 尚无 KV；下一次消费它才产生该位置的 KV。生成终止并不要求再消费最后的 EOS 或长度截断 token。

代表的 pre-norm decoder 在第 l 层执行：a=Norm_l(u)；q=aW_Q、k=aW_K、v=aW_V，对 q/k 应用规定的位置变换；把当前 k/v 暂写到位置 i。每个 query head 对允许的 j≤i 计算 s_j=q·k_j/√d_h+bias(i,j)，在合法集合内减最大值、指数归一化，再求 Σ_j softmax(s)_j v_j。拼接各 head 后投影并加残差得到 u′，再由模型 FFN 和残差得到下一层输入。例如门控 FFN 可写 u″=u′+[σ(Norm(u′)W_g)⊙Norm(u′)W_u]W_d；这只是代表结构，不能替换模型的实际激活。末端 norm 与输出头形成 logits。

```pseudocode
ALGORITHM ConsumeKnown(D, purpose)
输入：decoder D，known 输入、n、逐层 KV、固定位置与 mask
purpose：GENERATE 或显式授权的 STATE_ONLY
前提：n < length(known)，本位置所需上游和 KV 增量容量均已就绪
1. 若 D 是 Thinker 且已 TEXT_DONE，purpose=GENERATE：返回 STOPPED；
2. i ← n；u ← known[i] 对应的合法输入 embedding/特征；
3. 为位置 i 建立逐层暂写区，所有有效层前沿仍为 n；
4. 对 l 从第一层到末层：
      依该层 norm 与投影得到 q、k、v，并应用位置变换；
      在第 l 层位置 i 暂写 k/v；历史位置不得再次追加；
      对 mask 允许的历史和当前位置执行缩放点积 attention；
      按固定结构执行输出投影、残差、norm 和 FFN，更新 u；
5. H ← 末端处理(u)；需要时计算输出头；
6. 全层完成且代次仍有效后，原子提交位置 i：n ← i+1；
   若该输入是 Talker 条件 C_k，同时令 p_K ← k+1；
7. 仅当 purpose=GENERATE、分支仍允许生成且 n=length(known) 时，
   保存 (H, logits, predicts=n, prefix_version)；否则清除生成用 logits；
8. STATE_ONLY 不选择 token、不发布条件、不改变 p_T、停止原因或输出事件；
9. 失败时不推进有效 n；撤销暂写或令请求失败。
```

这里预算在一个可提交操作前检查。若实现允许在层间暂停，应保存层号、暂写区和完成事件，再从下一层继续；不得重跑已追加的位置。对外仍不能看到各层长度不一致的状态。GPU 操作已提交但未完成时返回的是等待完成事件，不能将其当作预算暂停后可立即重写的空闲区域。

known、有效 logits、已选 token 和发布是四个边界。完整 KV 命中而没有末行 logits 时，必须保留对应 H/logits 或按明确路径重算最后已知位置；不能对同一位置再次追加 KV，也不能凭 KV 长度推断可采样。相关的一般 decoder 机制见[Encoder-decoder](encoder-decoder-streaming.md)。

### Thinker 的预留、选择与终止提交

每个未消费条件的实际字节为 h_k；除 hidden 外还计其 token、身份元数据及必要副本。令 R 为尚未发布但已预留的条件数，M_res 为相应预留字节，M_live 为队列及尚未完成最后访问的原 hidden 字节。必须保持 L+R≤Lmax，M_live+M_res≤Hcap。KV、logits 暂存和文本发送队列也有独立容量；不能把条件队列限制当全部内存限制。

初始化设 TEXT_ACTIVE、条件流 OPEN、p_T=p_K=0、无发布事务。max_new_tokens 是固定的非负生成上限，本章把合法 EOS 也计为一个已选择 token。上限为 0 时，在任何采样前原子提交 TEXT_DONE(LENGTH)、condition_final=0、条件流 CLOSED 和唯一 TEXT_END；不虚构一个文本或条件 token。空条件对应的音频如何结束须由模型契约允许，否则明确失败。

```pseudocode
ALGORITHM ThinkerPublishOne(r)
前提：正确预测位置及源快照对应的 H/logits，或本事务的 SELECTED 状态
1. 在单写者/锁保护下检查 TEXT_ACTIVE、条件流 OPEN、当前代次和依赖版本；
   若已 TEXT_DONE 或流已关闭：撤销未发布事务及其预留，清除生成用 logits，
   返回 STOPPED；不得因为残留 known、logits 或 SELECTED 重新激活。
2. 若尚无事务：
      检查生成数尚未达到上限、L+R+1≤Lmax、
      M_live+M_res+h_k≤Hcap；
      预留条件槽、文本事件槽及本次可能需要的 TEXT_END 槽；
      任何容量不足：不采样、不推进 p_T，记录实际释放事件；
      永久装不下最大事务则失败；
      成功则建立 RESERVED(k=p_T, H位置, 依赖版本, 容量令牌)。
3. 若状态为 RESERVED：
      按固定约束、temperature、top-p 等规则处理 logits；
      合法候选为空则失败并撤销事务；
      选择 y，持久化 y、RNG 和约束状态，置 SELECTED；
      暂停后恢复此选择，不再次使用同一 logits 采样。
4. 对 SELECTED，在实际提交点再次检查：
      代次与依赖有效、TEXT_ACTIVE、条件流 OPEN、k=p_T、
      容量令牌有效、生成数未达到上限；
      检查失败时不追加任何条件或输出，撤销未发布事务。
5. terminal ← y 是合法 EOS，或提交本 token 后达到长度上限；
   在同一个原子提交中：
      追加 known 中的 y 和 c_k=(q,g,v,k,i,H_i,y)；
      非 EOS 按协议追加本 token 的文本内容事件；
      p_T ← p_T+1；预留转为实际占用；清除事务和生成用 logits；
      y 自身的 KV 尚未计算，n_T 不变；
      若 terminal：
          状态 ← TEXT_DONE；原因优先记 EOS，否则为 LENGTH；
          condition_final ← p_T；条件流 ← CLOSED；
          追加唯一 TEXT_END(原因, condition_final)，排在最终内容事件之后。
6. 已发布结果不因下游容量不足回滚；取消或失败仅撤销未发布事务。
```

最后条件、停止状态、条件流关闭和结束事件具有同一个逻辑提交点。并发消费者只能看到提交前或提交后的整体，不能观察到流已关闭却缺少最后条件，或看到 TEXT_END 后又追加新条件。持久化恢复需要使用同一事务序号重放或去重。内部写入顺序不能代替跨线程或设备的发布可见性保证。

EOS 控制记录不作为可见正文发送，但仍按已核验的条件接口交给 Talker；流关闭元数据不再增加 p_T。长度终止保留 LENGTH 原因，不能冒充模型 EOS。若实际 Talker 接口不接受这种条件表示或不支持截断后的合法尾部，适配层必须提供核验过的结束路径，或者明确失败，不能擅自补一个语音 EOS。

本代表路径只允许一个待发布 Thinker 事务。批量发布可一次预留全部增量，也可逐个提交合法前缀；不能先发布整批再检查。若 p_T=8、p_K=3、Lmax=5，新记录必须被挡在发布前。若 p_T=7、p_K=3，只能再提交一条；申请两条的事务必须拒绝或拆成合法的一条。

TEXT_DONE 是吸收状态。同一代次不再消费 Thinker known 以继续生成，不再选择，不再发布。若为了下一回合缓存而显式补算最后已知 token，只能走 STATE_ONLY；其完成回调也不得保存可采样 logits。整请求 COMPLETE 不要求 n_T=length(known)。例如 EOS 已发布、n_T 尚未包含 EOS 时，可以直接让 Talker 和发送继续排空。

消费者没有“L 必须严格小于 Lmax”的门。达到上限正是应排空的状态。Talker 将 c_k 完整纳入持久状态后才推进 p_K；原 hidden 在最后读取完成后才能释放字节额度。若先复制成设备暂存再推进消费，复制目标、在途原副本及后续条件状态必须分别计账。

### Talker 的条件前沿与双轨前沿

报告说明 Talker 为双轨自回归 decoder，生成文本与音频 token，但未公开足以唯一重建的全部轨道排列、延迟、融合和结束细节。以下给出一种完整代表结构，用于说明状态转换；它不是对 Qwen2.5-Omni 源码的断言。部署时必须核验并替换输入投影、轨道分布和排列参数；缺失时不能声称已经实现该模型。

代表结构把 Talker 的因果内部输入分为两种记录：条件输入 C_k=A_h H_i+A_y Embed_T(y_k)+type_C，以及生成对输入 A_j=E_text(u_j)+E_audio(a_j)+type_A；二者都加模型规定的位置。初始非空输入含 BOS、音色信息及合法历史表示。代表历史可以逐位置投影 Thinker prompt hidden 后作为前缀输入，投影和位置属于固定参数；报告所说“共享历史”不能证明任意缓存字节可直接共享。

内部输入流逐条调用 ConsumeKnown，每条输入只产生一份逐层 KV。条件 C_k 完整消费时推进 p_K；生成对输入被消费时只推进 n_K，不改变 p_K。末层 hidden 分别经文本头和音频头得到两个分布。本代表选择条件独立的双头分布 P(u_j,a_j|prefix)=P_text(u_j|prefix)P_audio(a_j|prefix)；若实际模型采用顺序条件头或不同排列，必须采用其真实因子分解。

定义模型参数 d(j)：选择第 j 个声学位置前至少要消费多少条 Thinker 条件，d 单调不减。它规定因果可见性，不宣称一个文本 token 对应固定数量声学帧。模型也可用等价的在线规则产生 d。条件流关闭后，d 不得请求超过 condition_final 的条件。文本轨 EOS 后的 PAD/结束输入、是否允许强制文本轨、语音 EOS 和空语音均须由固定契约提供。

```pseudocode
ALGORITHM TalkerOne(r)
1. 若已 TALKER_DONE：不再生成，返回本分支终止状态。
2. 若有未消费的 known 输入：
      对最早输入执行 ConsumeKnown；若它是 C_k，则原子推进 p_K；
      记录原 hidden 的最后使用事件；返回本分支进展。
3. 否则若 p_K < d(j_A)：
      若 p_K < p_T 且有条件输入/KV 容量：
          将唯一的 C_{p_K} 追加到 Talker known，清除旧 logits；
          不提前推进 p_K；下一次消费该输入。
      若条件流已关闭且 condition_final < d(j_A)：
          失败 INVALID_TRACK_CONTRACT；
      否则记录等待条件发布或容量释放。
4. 否则若双头 logits 有效、没有未消费输入、下一个声学输出槽已预留：
      按轨道分布选择 (u_j,a_j)，原子保存两个结果、RNG 与约束状态；
      对尚未结束的轨道更新停止状态；已结束文本轨只用契约规定的输入；
      若 a_j 为普通有效 code：
          追加到当前未封闭块；j_A ← j_A+1；
          达到规定块长且所有 codebook/延迟轨到齐时封闭该块；
      若 a_j 为语音 EOS：
          验证条件流已关闭、p_K=condition_final=p_T，
          以及模型的文本轨结束要求；
          按末块规则封闭非空残块，无残块时不创建空块；
          关闭 code 流并记录最终块数 N 与实际长度；
      若仍需下一次预测，将本生成对追加到 known，清除旧 logits；
      刚选出的生成对没有 KV，下一次只消费一次。
5. 只有各轨道合法结束、必要条件消费完且残块封闭后，记录 TALKER_DONE。
```

每次重入先消费已有 known，再决定是否补入新条件或采样，避免对过期 logits 重新选择。提前结束但仍有必要条件未消费时是契约错误，不能偷偷丢弃这些条件，也不能无限等待一个已经出现的 EOS 自行改变。模型若允许局部结束，必须另外定义局部到最终结束的状态关系。

Thinker TEXT_DONE 后 Talker 仍可进行多步声学生成。例如 d(j)=(1,1,2,2,2)，五个有效 code 只需要两条条件。块长设为 2 时，块长依次为 2、2、1，末块在合法语音 EOS 时封闭；条件消费数为 2，声学前沿为 5。这是代表轨迹，不是报告的真实帧率或轨道参数。一个条件也可能只承担结束控制而生成零个音频 code，不能通过“消费一条条件就生成一个整块”实现所有长度关系。

## 对齐返回、分支调度与波形提交

对齐接口同时返回已交付块列表和尾部状态。尾部等待不能覆盖本次已经形成的块。

```pseudocode
ALGORITHM AlignChunk(r, m, optional_chunk, flush)
输入：源身份、整数采样/时间刻度区间、内容、固定块长和边界契约
输出：(new_blocks, tail_state)
1. 检查代次、区间非空、摘要和源身份；先验证再修改区间表。
   完全相同的重复输入幂等；非相同的重叠按本路径拒绝；
   FLUSH 后只接受幂等重传，不能接入新的源内容。
2. 将合法新区间放入乱序缓冲，next_b 指向最早未交付块。
3. new_blocks ← 空列表；
   当 next_b 的整个半开区间均已覆盖：
      构造源映射、有效长度和位置元数据，追加 ALIGNED 块；
      next_b ← next_b+1；同一块不再产出。
4. 若 flush：
      若没有未交付数据：tail_state ← FINAL，不创建额外空块；
      否则若当前块起点到真实源末端存在内部空洞：tail_state ← FAILED_GAP；
      否则若模型允许该非空部分末块：
          按末块契约追加一次 partial ALIGNED 块，记录真实长度；
          推进交付记录，tail_state ← FINAL；
      否则 tail_state ← FAILED_PARTIAL_CONTRACT。
5. 否则：若存在阻挡连续前沿的空洞，tail_state ← WAIT_GAP；
   若有不完整连续残留，tail_state ← WAIT_MORE；否则 tail_state ← EMPTY。
6. 无论 tail_state 是等待还是最终状态，均返回 (new_blocks, tail_state)。
```

完整一块的普通输入返回非空列表和 EMPTY；完整块加残留返回非空列表和 WAIT_MORE；重复输入不重复交付。FLUSH 恰好在整块边界只结束尾部。失败尾部与先前合法块的账务仍需保留，是否对外发布部分任务由任务协议决定。

声学解码对 b_D 按顺序执行。取逻辑四块窗口，负编号由 B_left 解释；非负编号优先读取真实块；只有 code 流已结束的 j≥N 才由 B_right 解释。固定求解步数为 S 时，保存初始噪声/RNG 和 solver 当前步，按模型给定的速度场与积分规则逐步更新 mel 状态，例如显式 Euler 代表式 x_{s+1}=x_s+(t_{s+1}−t_s)v_θ(x_s,t_s,window)。求解器和步表属于模型配置，此式不规定实际部署必须采用 Euler。

完成全部 solver 步才发布稳定 mel。BigVGAN 依固定卷积/上采样网络和边界状态产生扩展波形；从扩展结果中仅提交本块拥有的稳定 sample 区间 [pcm_end,new_end)，裁去已发布 lookback 与尚不稳定的右侧。保存下一块需要的 overlap；最后一块按真实长度裁剪。若模型没有足够规则确定该区间，就不能承诺流式 PCM 正确。窗口、mel、PCM 和发送槽在各自事务前预留。

调度中的 runnable 指依赖和容量均满足、除了当前时间片预算以外可以启动的操作。在途设备操作尚未完成时，它本身不是 runnable，而是具有完成事件的等待。wake_set 只包含已登记且能够改变当前阻塞条件的事件，例如源到达、设备完成、socket 可写、协议确认或实际启用的超时；不能给已关闭的源登记一个永远不会发生的新块，也不能把循环等待中的容量释放当作有外部生产者的事件。

```pseudocode
ALGORITHM OmniStep(r, budget)
1. 汇合到达、完成、发送和确认事件；旧代次事件只执行安全清理。
   若取消：撤销未来提交资格，返回 CANCELLED 并保留在途清理责任。
2. 执行有界、公平的调度轮次，各操作启动前检查预算：
      a. 尝试发送已有文本/PCM；只更新协议承诺的 sent 前沿；
         未成功发送的内容保留，登记相应可写/完成事件。
      b. 判断整请求完成：所需源最终处理已完成、TEXT_DONE、条件流关闭、
         TALKER_DONE、全部 code 已解码、vocoder 已结束、输出队列排空，
         且满足任务要求的发送/确认边界；若成立，返回 COMPLETE。
      c. 若声学/vocoder 分支 runnable，在预算内推进一个可恢复操作；
         窗口不足只阻塞此分支；非法边界直接失败。
      d. 若 Talker runnable，执行一个 TalkerOne 操作；
         Thinker 等源、已 TEXT_DONE 或领先达到上限均不阻止其排空。
      e. 仅当 Thinker 为 TEXT_ACTIVE 且条件流 OPEN：
          若有已保存发布事务或有效 logits，尝试 ThinkerPublishOne；
          否则若最早 known 依赖完整且 KV 容量足够，
              执行 ConsumeKnown(Thinker, GENERATE)；
         若已 TEXT_DONE：不执行这两种生成操作，不为残留 known 等待新源；
         所有提交点仍重查终止门、代次、依赖和容量。
      f. 对合法 ALIGNED 块推进一个 processor/encoder 操作；
         完整块提交 ENCODED；局部等待不阻止其他分支。
3. 汇合本轮提交结果，重新判断完成、runnable 和实际 wake_set：
      若满足整请求完成条件，返回 COMPLETE；
      若已有失败，返回相应失败；
      若存在 runnable：
          若剩余预算不能启动下一合法操作，返回 PAUSED_BUDGET；
          否则继续下一公平轮次；
      否则：
          若 wake_set 为空，返回 FAILED_CONTRACT_DEADLOCK；
          否则原子登记等待并返回 WAIT(wake_set)。
```

完成判定优先于预算暂停和等待；最后一次操作恰好耗尽预算但已满足完成条件时，仍返回 COMPLETE。没有 runnable 时，预算耗尽不能掩盖无事件死锁。反过来，有合法工作但当前预算不足时，返回 PAUSED_BUDGET，由下一时间片继续，不伪造一个输入等待。

等待登记还要避免丢失唤醒：读取阻塞状态和事件版本，登记监听后再核对版本；期间若有变化则重新调度。设备完成、可写与取消事件的实际注册属于运行时责任。若无 runnable、无在途操作、无合法未来输入或其他实际事件，WAIT(空集合) 没有后继，应报告契约死锁，保留依赖环及容量账用于诊断。

一条组合轨迹是：Thinker 暂时没有新源，队列已有 c_0；Talker 消费它并生成 code 0、1；在没有语音 FLUSH 时，块 0 用 B_left 和真实右上下文解码并发送。块 1 等右上下文时，之前的 PCM 仍可发送。Thinker 最后发布 EOS 或达到长度上限，在同一事务关闭条件流并产生 TEXT_END；其未消费的最后 token 留在 known，但不再进入生成路径。之后若干轮 Talker 消费剩余条件、生成剩余 code、合法结束，尾块用 B_right 解码，发送队列继续排空。期间 p_T 和文本事件数始终不变；最后 PCM 满足交付边界后直接 COMPLETE，不检查不存在的下一块。

打断将 g 增加，撤销旧代次的新提交资格；旧 kernel、DMA、codec overlap 和发送操作仍可能访问原缓冲。只有引用归零且最后使用事件完成才回收。客户端按协议丢弃未播放的旧代次数据；已经播放的样本不可撤销。新代次从约定的确认位置继承或重新开始，不能将旧尾音直接拼接到新回复。

## 条件化成本：计算、流量、队列与资源

六类成本都要落在同一请求范围和候选方案中：计算包含 encoder、两个 decoder、DiT 与 vocoder；访存包含权重、逐层 KV、hidden、code、mel、PCM 与暂写；通信包含特征/条件跨设备传输和客户端音频；准备包含媒体解码、重采样、mel、resize、抽帧与分词；同步包含块形成、条件等待、lookahead、solver 完成和发送缓冲；驻留包含所有活跃、预留和仍在途的对象。

设阶段 i 每块在资源 j 上占用 w_{i,j} 秒，同类块周期为 Δ 秒，则单会话资源需求为 ρ_j=Σ_i w_{i,j}/Δ。N 个同类会话共享串行资源时，稳定性必要条件为 Nρ_j<1；这不保证尾延迟。分支以不同频率运行时，应使用各自 λ_i，写成 ρ_j=Σ_i λ_i w_{i,j}，不能把每个文本 token、每个音频块和每个视频块当作相同频率。

报告的音频参数为 16 kHz、128 通道 mel、25 ms 窗与 10 ms hop，encoder 表示约每 40 ms 一帧。稳态 1 秒约 100 个 mel hop，2 秒约 200 个；严格首尾帧数还取决于窗中心、padding 和 flush。2 秒约有 50 个 40 ms 表示单位。16-bit 单声道输入 PCM 每秒 32,000 字节，2 秒 64,000 字节；这是原始输入大小，不是 encoder 激活或设备峰值。

视觉侧，处理后 H×W 且尺寸满足网格要求时，14 像素 patch 给出 P=(H/14)(W/14)，空间 2×2 merge 后约 P/4 个语言侧视觉 token。视频两帧成组还会改变时间维，不能再按每原始帧重复计同一输出。Qwen2.5-VL 的 112×112 窗口对应最多 64 个 patch，大部分窗口层 attention 约 O(P·64·d)，全注意力层仍约 O(P²d)，投影与 FFN 另计。报告的 VL 层数和 KV 配置不能直接当 Omni 的全部配置。

对本章代表 decoder，宽 d、FFN 宽 d_ff、上下文 n 的一次单位置推进，投影/FFN 工作约 O(d²+d·d_ff)，attention 约 O(n·d)，再乘实际层数和模块数。逐层 KV 容量为 nΣ_l(D_K,l b_K,l+D_V,l b_V,l)，分别对 Thinker 与 Talker 计账。Talker 的 n_K 包括条件输入、历史前缀和已消费生成对，不能用 p_K 或 j_A 直接替换。每条条件消费和每个生成对消费均有 decoder 工作；双头词表投影、采样和轨道 mask 也有成本。

若 DiT 每 code 块 C 个位置、窗口宽 4C、宽度 d_D、S 个 solver 步，则固定窗口代表结构的 attention 工作约 O(S·L_D·(4C)²d_D)，投影/FFN 约 O(S·L_D·4C·d_D²)，具体还取决于 mel/code 对齐和条件路径。首尾边界可能改变有效位置，不能未经核验假定总是实算四个满块。BigVGAN 的卷积、上采样、overlap 和工作区按实际网络计。

队列使用守恒式而非截断式：Q_{t+1}=Q_t+A_t−C_t，0≤Q_{t+1}≤cap，其中 A_t、C_t 是真正获准提交和消费的数量，0≤C_t≤Q_t+A_t。申请但未获准的工作留在上游；用 min(cap,…) 隐去溢出会掩盖丢内容。

前沿的正确更新为：

L_{t+1}=p_T(t+1)−p_K(t+1)=L_t+Δp_T−Δp_K。

Δp_T、Δp_K 均以条件记录计，L 非负由消费合法性保证，不能靠 max(0,…) 掩盖超前消费。以 p_T=6、p_K=3 为例，不动时 L=3；仅提交一条为 4；仅消费一条为 2；同时提交两条、消费一条为 4。TEXT_DONE 后 Δp_T=0，消费者继续推进时 L 只会减少。把累计位置差再次加到旧 L 会在没有工作时虚构驻留增长。

等宽单份 hidden 时，未消费主项为 L·d_h·b_h；实际条件容量还包括预留、元数据、副本和最后使用尚未完成的退休对象。消费后进入 Talker KV 的历史仍驻留，不能说 p_K 增长就释放了全部语音状态。物理峰值应取 max_t[各类同时存活且不共享的字节]，共享存储只计一次，预留池和其中对象也不能重复相加。终止后的 STATE_ONLY 补算若被选择，会增加计算与 KV 驻留，须另计；它不是文本或音频完成的默认前提。

### 播放到达时间与 PCM 驻留

播放缓冲 B 的单位为秒音频。先固定消费契约：从观察起点开始持续请求播放，速率为每秒消耗一秒音频；空缓冲时累计欠载，音频到达后立即恢复。若产品先等待启动水位、主动暂停或改变播放速率，必须显式增加这些状态，不能套用本段的连续消费假设。

设事件 a_i 秒音频在墙钟 t_i 到达并变为可播放，事件时间单调。这里的可播放要求身份正确、样本不重复、偏移连续且客户端已完成必要解码；乱序网络包收到时可能还不算 a_i。同一时刻事件可合并；在时间 t_i 先播放此前区间，再加入该时刻的到达，瞬时事件不消耗时间。

若上次事件后缓冲为 B_{i−1}，δ_i=t_i−t_{i−1}，累计欠载为 U，则：

- 实际播放量 P_i=min(B_{i−1},δ_i)。
- 到达前缓冲 B_i⁻=B_{i−1}−P_i=max(0,B_{i−1}−δ_i)。
- U_i=U_{i−1}+δ_i−P_i。
- 到达后缓冲 B_i=B_i⁻+a_i。

最后一个到达之后，还要按相同方法推进到观察终点 T；可以追加 a=0、t=T 的观察事件。该递推同时给出期末驻留和中途欠载，并保持 B(T)=B(0)+Σ_i a_i−(T−t_0)+U(T)，其中 U(t_0)=0。

```pseudocode
ALGORITHM AdvancePlayout(B0, t0, arrivals, T)
输入：非负初始秒数 B0，按时间排序的可播放到达 (t_i,a_i)，观察终点 T
输出：期末 B、累计欠载秒数 U、事件前后缓冲轨迹
1. 检查 T≥t0、t0≤t_i≤T、a_i≥0；B←B0；U←0；last←t0；
2. 按顺序遍历 arrivals，再处理观察事件 (T,0)：
      δ ← t_i−last；played ← min(B,δ)；
      B ← B−played；U ← U+(δ−played)；
      记录到达前 B；B ← B+a_i；记录到达后 B；last ← t_i；
3. 返回 (B,U,轨迹)。
```

无条件使用 max(0,B0+Σa_i−δ) 会丢失区间内到达时刻。反例：B0=0，观察 1 秒，1 秒音频在 0.9 秒到达。前 0.9 秒欠载，到达后只播放 0.1 秒，故期末 B=0.9 秒、U=0.9 秒；同样的音频若在 0 秒到达，则 B=0、U=0。两条轨迹的到达总量相同，播放结果不同。

聚合式只有在明确条件下才可用：若全部到达已在区间起点加入缓冲，则 B_end=max(0,B0+A−δ)、U=max(0,δ−B0−A)；或已由事件轨迹证明整个区间无正时长欠载，此时 B_end=B0+A−δ、U=0。只有总量足够不能证明第二个条件成立。

未播放 PCM 的逻辑字节为 B×sample_rate×bytes_per_sample×channels。24 kHz、单声道、16-bit 的 2 秒为 96,000 字节；迟到反例的期末 0.9 秒为 43,200 字节。这些是通用换算，不是 Omni 输出采样率事实。若队列按整块分配，已经播放一部分的块可能仍占整个物理缓冲；压缩包、解码副本和其他端点的队列也需分别计账。统计峰值还要观察到达后的瞬时 B，不能只取观察终点。

保留原设定的资源算例：2 秒输入区间在同一不能重叠的资源上依次占视觉 80 ms、音频 60 ms、Thinker 120 ms、Talker 40 ms、waveform 60 ms，共 360 ms。单会话需求为 18%，八会话为 144%，超过该资源的稳定容量。若阶段实际位于不同资源，应分别计账，再沿依赖 DAG 求首音频关键路径；既不能无依据取最大值，也不能把真实重叠阶段全部串行相加。

首音频路径包括合法块形成、准备、encoder、首个可消费条件、足够的 code、DiT、vocoder、发送及播放缓冲。需要一个声学 lookahead 块不表示必须等待它代表的全部墙钟播放时长；code 若生成更快，可以提前取得，代价是额外初始计算和驻留。首文本、首 PCM、客户端首播放及整请求完成应分别报告。

## 条件变化后的选择与恢复

更小输入块可能减少块形成等待，却增加调用、位置边界和同步次数；前提是模型允许新块长。减小网络包不会改变模型输入契约。改变声学块长也必须重新核验 DiT mask、求解边界、codebook 完整性和 vocoder 裁剪。缺少边界规则时，应采用已支持的块配置或离线完整解码，不能等待不可能到达的上下文。

分辨率、抽帧率、音频 hop 和重采样改变实际输入及位置身份。迟到帧可以等待、明确丢弃或使用模型允许的缺失标记，但这些方案具有不同语义。processor 改变后旧特征即使形状相同也不一定可复用。

Lmax 较大可以吸收 Talker 短暂落后，但增加 hidden 驻留、取消浪费和文字领先；较小 Lmax 会更早暂停文本，可能降低设备复用。若真实瓶颈是 vocoder 或网络，单独增大 hidden 队列不会增加稳态服务能力。客户端缓冲过大还会延长打断残留。若欠载来自到达时间的突发，平均到达总量与期末正缓冲都不足以决定水位，应比较事件轨迹上的 U 和峰值驻留。

视频在场的双向语音任务可比较：A 等一段完整输入后串行处理；B 采用合法块处理及有界流水，共享设备；C 把感知和语音输出放到不同设备或执行池。A 边界简单但感知等待较大；B 复用较好但有资源争用；C 有隔离价值，同时增加权重驻留、特征传输和调度同步。若共享资源需求已经是设定的 144%，只增加队列不能恢复稳定；若分池传输耗时大于省下的排队，C 也可能更慢。离线总结可以接受 A，而临近播放欠载的任务可能需要 B 的准入限制或 C 的隔离。

恢复包需保存：源快照及最终处理状态、已交付块与位置基址、known 与逐层有效 n、H/logits 的预测位置与依赖版本、RESERVED/SELECTED 事务和 RNG、TEXT_ACTIVE/TEXT_DONE 与原因、condition_final、结束事务/事件序号、p_T/p_K、Talker 双轨状态与 j_A、未封闭 code 块、DiT solver 步和窗口、vocoder overlap、样本提交和发送前沿，以及协议提供的确认前沿。已选而未消费的 token 不能恢复成已有 KV；已发布而未确认的输出不能盲目重发。恢复出的 TEXT_DONE 优先于任何残留 logits 或 SELECTED，不能因恢复程序发现可用计算结果就重新开放条件流。

OpenTelemetry context propagation 支持在服务边界注入/提取关联上下文，但父子 span 树不能自动表达多分支、多请求 batch 与多代次。事件还要显式携带 q、g、模态、源区间、位置范围和分支。保存摘要通常足以定位身份错误，不需要把原始媒体写入全部 trace。

模型或 processor 变化后重查整个依赖闭包；浮点重算不天然逐位一致。打断取消的是未来提交资格，回收等待物理完成；恢复继承的是任务允许且已确认的历史，不能恢复已经播放之前的外部世界。

## 竞争解释、反证与检查边界

| 现象 | 竞争解释 | 区分实验与不同预测 |
|---|---|---|
| EOS 后又出现文本或条件 | 终止门缺失；已选事务迟到；重复交付 | 发布合法 EOS 后保持音频与发送尚未排空，多次重入；p_T、文本事件与 condition_final 应冻结。仅发送序号重复支持协议问题，p_T 增长支持生成提交门失效 |
| 长度终止后语音还在继续 | 正常尾部排空；Thinker 被错误重启；声学 EOS 契约不满足 | 同时记录 TEXT_DONE、p_T、p_K、j_A；p_T 不动且 j_A 增长可能是合法排空。p_T 增长则反驳终止状态机；条件已消费完却无法合法结束应检查轨道契约 |
| 请求永远不再被调度 | 合法等待；空集合 WAIT；容量依赖环；唤醒登记竞争 | 分别构造真实设备事件等待和无工作/无事件状态；前者 WAIT 非空集合，后者明确失败。事件已发生但仍等待，查登记与版本复核 |
| 满队列后文本和语音都停住 | 合法背压；先发布后检查；消费者也被领先门挡住 | 固定 p_T=8、p_K=3、Lmax=5，禁止新源但保留条件；正确路径拒绝新提交并允许 p_K 增长 |
| 源暂缺时断音 | 没有声学条件；局部 WAIT 提前返回；网络未可写 | 预置条件和可发送 PCM，再撤走新源；正确调度仍排空。仅恢复源就让旧 PCM 突然发送，支持调度门错误 |
| 首块始终等待 | 真实右上下文不足；错误等待负编号；缺少边界契约 | 提供真实 code 0、1 且不结束语音，安装 B_left；应可解码 0。移除 B_left 应明确失败，移除 code 1 应等待真实 code |
| 文本或音频重复 | 选择状态未持久化；采样后提前记 KV；重复区间未去重 | 在消费末 prompt、选择 token、发布条件三个边界暂停；比较完整前缀 forward 与逐层 KV 身份，检查同一 logits 只选一次 |
| 条件数与语音长度被错误绑定 | 一条件一 code 假设；实际对齐规则变化 | 固定两条条件、五个 code 的代表轨迹，应形成 2、2、1 的块；只改变声学长度，p_K 不应被迫等于 j_A |
| 领先量随空闲时间增大 | 实际条件增加；累计位置递推错误 | 保持 p_T=6、p_K=3 不动，比较队列记录数和直接差值；任何 6、9、12 的增长均反驳更新式 |
| 最后 PCM 已发送仍不结束 | 等确认；结束事件缺失；先检查不存在的下一窗口 | 分别关闭/开启确认要求；全部承诺已满足时直接 COMPLETE，不能再 WAIT_LOOKAHEAD |
| 相同到达总量却出现不同欠载与驻留 | 到达时刻不同；启动/暂停规则不同；重复或乱序音频被误计 | 固定播放规则与总量，仅把 1 秒音频从 0 秒移到 0.9 秒；事件参考预测 U 与期末 B 均从 0 变为 0.9 秒。若观测不同，核对真正可播放时间与消费状态 |
| 打断后有旧尾音 | 旧代次再次提交；旧包已在客户端；overlap 未重置 | 分开服务端和客户端 sink，核对代次及 sample offset；服务端已停而客户端仍响支持客户端积压，旧代次新提交支持提交门失效 |

负对照必须经过与正常路径相同的不变量或参考判定：先发布后检查额度应触发容量不变量；局部 WAIT 提前返回应违反已有工作可排空的预测；要求真实负编号应无法通过非最终首包检查；提前追加刚选 token 的 KV 应违反层长度；整块 FLUSH 产生空块应违反区间分割。新增的三个故障分别是移除 TEXT_DONE 门后消费最后 token 并再次发布、把 WAIT 返回放在空集合失败之前、忽略事件时刻只用到达总量。这些故障不能仅靠打印“检测成功”关闭。

随章检查 tools/check_k_model_012_full.py 使用合成边界、标量 causal decoder 和有界事件模型。区间分割、队列记录与容量、完整前缀重算分别作为对齐、预留和 KV 的参考；EOS 与长度终止轨迹在 Talker/发送多轮排空期间检查冻结状态，并单独检查提交点拒绝迟到事务及 STATE_ONLY 不产生 logits。调度检查覆盖完成、预算暂停、真实事件等待与无事件失败。播放事件递推与独立逐刻度消费参考比较，覆盖同总量不同时间、起点/终点到达、初始缓冲和多次到达。

这些是确定性的 CPU 逻辑检查，不能证明 Qwen2.5-Omni 的实际轨道排列、模型质量、GPU 内存可见性、kernel 抢占、网络交付或客户端播放。真实系统需沿同一请求记录源到达、块封闭、逐分支提交、code 封闭、PCM、发送、播放及打断事件，再用反证修正模型。报告基准分数不能替代目标服务实测。
