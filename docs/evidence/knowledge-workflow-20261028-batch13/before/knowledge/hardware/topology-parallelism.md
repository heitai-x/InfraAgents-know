# K-HW-002：通信拓扑：从 Rank 组到瓶颈链路

多卡性能由数据经过的实际路径、共享资源和消费者依赖决定；rank 数只是拓扑模型的一部分。communicator 能建立，不证明其集合操作走等带宽、低争用的路径。本章先把逻辑归约展开成消息与块状态，再把这些消息映射到物理资源，推导条件化成本。

## 通信身份、路径与资源容量

一次操作的逻辑身份记为 K=(C,e,seq)，其中 C 是有序 communicator，e 是执行代次，seq 是共同操作序号。P 个 rank 编号为 0…P−1；π 将每个 rank 映射到进程、GPU、CPU NUMA 域和 NIC。root 是 communicator rank，不是设备编号。改变 π 会改变物理路径，但 AllGather 的逻辑输出仍按 rank 排列。

物理拓扑是有向图 G=(V,A)。节点可包含 GPU、CPU NUMA 域、PCIe 端口、NIC 和网络交换节点。弧 a 的容量 B_a>0，单位为字节/秒；固定延迟 ℓ_a≥0，单位为秒。消息 f 的路径 R_f 是有序弧列表，保留每次经过的弧实例。设备对可达，不意味着两个方向容量相同，也不意味着没有主机中转。

仅列弧容量不能表达半双工、交换出口、共享总线和 NIC 总注入限制。为这些资源建立组 g，容量为 C_g>0，单位为等效服务字节/秒；h_(g,a)≥0 表示一个净荷字节经过弧 a 时，需要多少组服务字节。κ 记录弧与资源组的关联；一个弧可以同时受多个资源约束。

消息 f 的净荷为 b_f 字节，其对组 g 的服务需求为

D_(g,f)=b_f Σ_(弧经过实例 a∈R_f) h_(g,a)。

这个和按真实服务次数计费。同一消息先后两次使用同一串行总线，就计两次；若图中两条弧只是同一次硬件服务的重复表示，应合并表示，或只在一个规范计费弧上赋 h=1，另一个赋 0。计费约定必须说明物理含义，不能一面重复计量，一面把结果解释成真实网络字节。

例如两个方向弧各有 B=100 字节/秒。半双工描述增加一个 C=100 的共享组，两个方向 h 都为 1；全双工独立方向则使用两个 C=100 的组，各覆盖一个方向。消息和定价算法相同，只改变资源描述。

rank 端点另有发送容量 B_r^out 和接收容量 B_r^in。若收发共用同一引擎，还要增加覆盖两个方向的资源组，不能把两个端点容量当成独立服务能力。

这些容量是模型输入。只有使用确实不可能超过的服务率约束时，容量商才是严格时间下界；将微基准平均有效带宽代入时，应称为该条件下的预测，不能自动提升为硬件保证。

## 阶段预算与共享占用

令同步阶段 p 中的消息集合为 F_p。分别记录以下计量边界：

- 弧字节 D_(p,a)=Σ_f b_f × f 在路径中经过 a 的次数。
- 组服务字节 D_(p,g)=Σ_f D_(g,f)。
- 端点发送 O_(p,r)=Σ_(src(f)=r)b_f，接收 I_(p,r)=Σ_(dst(f)=r)b_f。
- 路径延迟下界 L_p=max_f Σ_(a∈R_f)ℓ_a；没有消息时取 0。

阶段纯服务预算下界为

τ_p=max(L_p, max_a D_(p,a)/B_a, max_g D_(p,g)/C_g, max_r O_(p,r)/B_r^out, max_r I_(p,r)/B_r^in)。

不同资源的时间约束取最大值，因为同一个字节可能同时占用端点和链路；同一资源内部的全部使用者则必须累加。α_p 若表示明确串行放在服务之前的启动、匹配开销，阶段权重为 w_p=α_p+τ_p。无法证明这种串行关系时，容量下界取 α_p=0，将控制活动另接入依赖图。

τ_p 不保证存在恰好在该时间完成所有流的调度。多跳存储转发、包粒度、队列、归约计算和消费者可见性都可能增加时间。单消息的 α+Σℓ+b/min B 是初始估算，也不能解决并发竞争。

输出不能只给一个最大值，还应保留 D_(p,g) 和 D_(p,g)/C_g。给定服务窗口 t_p≥τ_p，可以计算组的模型平均占用

ρ_(p,g)=D_(p,g)/(C_g t_p)，

平均剩余服务率 C_g−D_(p,g)/t_p，以及窗口服务余量 C_g t_p−D_(p,g)。t_p=0 只允许零需求，占用约定为 0。用下界 τ_p 代入得到的余量只是窗口账，不证明实际排程可行，也不是可以直接分配给新流的瞬时空闲带宽。

两条反向消息各 100 字节，方向弧和独立端点各 100 字节/秒：全双工组分别服务 100 字节，τ=1 秒；半双工组服务 200 字节，τ=2 秒。忽略组约束得到的 1 秒仍是较弱下界，但不能兑现半双工占用预算。

对共享出口也一样。8 个 rank 各向其余 7 个发送 1 MiB，端点发送合计 56 MiB。若这些字节各一次经过同一个 25 GiB/s 出口，其服务下界为 56/25600 秒，即 2.1875 ms；逐流取最大只得到 0.0390625 ms。若部分消息不经过该出口，应从出口账中剔除，不能机械使用全组字节。

## 合法条件与候选范围

共同操作描述包含 kind、count、dtype、归约方式、root、K 和逻辑偏移解释。固定 NCCL 文档要求所有 rank 使用相同 count 和 datatype 组成完整 collective；应用还须保证操作、顺序、归约方式、root 和逻辑对象匹配。形状相同而 seq 不同的两个 AllReduce 不能替代彼此，group calls 不修复错序。

本地没有有效 token，不授权该 rank 跳过共同约定的正 count 操作。只有全组共同改变操作，或数学契约允许用单位元表达零贡献时，才能改变局部处理。AllReduce 的输入 count、AllGather 的贡献 count 和 ReduceScatter 的接收 count 含义不同。

物理合法性要求输入已产生、方向可达、所选传输权限及注册有效，接收范围和在途资源充足。MR、BAR、WR/CQ、接收槽或暂存不足时，应拒绝、分块或采用明确展开的流控，不能静默截断。注册要求取决于实际传输路径，不能要求所有本地路径都采用 RDMA 注册。

块记录包含 (K,块 j,持有 rank r,版本 v)，以及偏移、dtype、字节数、贡献集合 A 和生产者。版本标识生产结果，不等于物理地址。同一地址复用后，旧完成不能放行新版本。每个不可变记录有唯一生产者；AllGather 会产生多个等价完整副本，因此同一逻辑块可以有多个持有者。

下面完整展开的候选限定为同步分轮的 ring AllReduce，使用允许该贡献顺序的交换、结合归约。CPU 检查采用精确整数 SUM；浮点重排只按约定误差判断，不能用实数结合律证明逐位一致。树和分层方案在本章只讨论成本与选择条件。

## Ring 的生产、消费与状态更新

每个 rank 输入同一逻辑 N 元素范围，元素占 e_b 字节，n=N e_b。所有 rank 共同采用整数块长 L[0…P−1]，满足 L_j≥0、ΣL_j=N。块 j 的偏移 o_j=Σ_(i<j)L_i，字节数 b_j=e_b L_j。均衡切分可令 q=N div P、u=N mod P，前 u 块长 q+1，其余长 q，不产生分数字节。

这里的非均匀块表示匹配的变长点对点消息候选，或库内部等价分块。固定 NCCL ReduceScatter 公共接口规定等长接收块，不能直接给不同 rank 传不同 recvcount 来实现任意 L。只能使用等 count 接口时，应 padding、重新分片或拒绝该候选。

初始 H[r,j] 的贡献集合为 {r}、版本为 0，值为 I_r[o_j:o_j+L_j)。发送不删除源记录；接收归约产生新的逻辑版本，再更新当前 H 指针。旧物理内容在最后读者完成前继续受保护。

定义 succ(r)=(r+1) mod P。reduce-scatter 第 s 轮，s=0…P−2，rank r 发送 j=(r−s−1) mod P。接收 rank d=succ(r) 将该部分结果与自己尚未加入的本地块 j 归约。每轮开始冻结全部源指针；全部消息完成后统一更新，不能在同一轮消费邻居刚产生的下一轮版本。

第 s 轮发送部分含 s+1 个贡献，接收后含 s+2 个；接收方本地集合为 {d}，必须与来包集合不交。最后 rank r 持有的完整归约块是 j=r。

all-gather 第 s 轮发送 j=(r−s) mod P，接收方只复制完整块，不再归约。经过 P−1 轮，每个 rank 按全局偏移拥有全部完整块。

```pseudocode
算法 EXPAND_RING
输入：共同身份 K，P≥1，非负整数块长 L，元素字节 e_b>0，各 rank 输入 I
输出：块生产记录、分轮阶段 DAG、最终持有表、逐 rank 发送账；或 REJECT

验证所有输入长度相同且等于 ΣL，所有 rank 使用相同分块
为每个 r,j 建立 H[r,j]=(K,j,r,v=0,A={r},输入块范围)
sent[r]←0；DAG←空；前驱←空
若 P=1：返回初始记录、空 DAG 和零发送账

对 s=0..P−2：
    p←新 RS 阶段，依赖前驱阶段全部完成
    snapshot←当前 H 指针；updates←空
    对每个 r：
        j←(r−s−1) mod P；d←succ(r)
        x←snapshot[r,j]；y←snapshot[d,j]
        要求 y.A={d} 且 x.A∩y.A=空
        建立消息，引用源 x、目的 d、块 j、字节 b_j
        建立归约消费，引用 x 与 y
        z←新记录，holder=d，chunk=j，version=s+1
        z.A←x.A∪y.A；z.value←逐元素 reduce(x.value,y.value)
        z 的唯一生产者为 p；消息引用 z 作为接收后产物
        updates[d,j]←z；sent[r]←sent[r]+b_j
    实际执行须等传输、归约及可见性完成，再应用 updates
    将 p 加入 DAG；前驱←p

要求每个 H[r,r].A=全部 ranks
H←仅保留 H[r,r] 作为当前完整块表

对 s=0..P−2：
    p←新 AG 阶段，依赖前驱阶段全部完成
    snapshot←当前 H 指针；updates←空
    对每个 r：
        j←(r−s) mod P；d←succ(r)
        x←snapshot[r,j]；要求 x.A=全部 ranks
        建立消息，引用源 x、目的 d、块 j、字节 b_j
        z←复制 x 的完整值与贡献集合的新记录
        z.holder←d；z.version←P+s；z 的生产者为 p
        updates[d,j]←z；sent[r]←sent[r]+b_j
    实际执行须等传输及可见性完成，再应用 updates
    将 p 加入 DAG；前驱←p

要求每个 r,j 都有完整记录，按 o_j 恢复输出
返回记录、DAG、H、sent
```

展开器建立的是逻辑依赖，实际推进要以完成和可见性为依据。输入记录是外部已就绪生产者；其他消费者只能读取祖先阶段产生的版本。发送、接收和归约用同一消息身份关联，不因两端各记一次账而重复累计端点发送净荷。

零长度块仍保留索引、贡献和版本元数据，净荷为零。本候选保留规定轮数，因此 P>1、n=0 时仍有启动项；这不证明真实库也执行相同零长度路径。P=1 直接交付输入，没有网络阶段。

### 四 rank 的完整轨迹

| 轮次 | rank 0 发送块 | rank 1 发送块 | rank 2 发送块 | rank 3 发送块 |
|---|---:|---:|---:|---:|
| RS 0 | 3 | 0 | 1 | 2 |
| RS 1 | 2 | 3 | 0 | 1 |
| RS 2 | 1 | 2 | 3 | 0 |
| AG 0 | 0 | 1 | 2 | 3 |
| AG 1 | 3 | 0 | 1 | 2 |
| AG 2 | 2 | 3 | 0 | 1 |

追踪块 0：rank 1 的 {1},v0 到 rank 2，与本地 {2} 合成 {1,2},v1；下一轮到 rank 3 得到 {1,2,3},v2；再到 rank 0 得到完整集合,v3。AG 中完整块从 0 到 1 产生 v4，从 1 到 2 产生 v5，从 2 到 3 产生 v6。AG 不能再次加入接收方原始贡献。

一般地，块 j 从 rank (j+1) mod P 出发，RS 沿环访问其余 P−1 个 rank，最终到达 j。每次只加入此前未访问的本地贡献，所以覆盖完整且不重复；AG 再将这个完整结果复制给其余所有 rank。这也给出独立于逐 rank 索引公式的审计参考。

## 展开计划怎样进入硬件定价

PRICE_COLLECTIVE 的输入 S 是已经展开的阶段 DAG。每个块有唯一生产者、范围、贡献集合、版本和持有位置；每条消息引用源记录、目的和接收产物；归约另引用本地记录。每个被消费记录必须由阶段祖先产生，或是外部已就绪输入。只给字符串“ring”“树”不满足输入契约。

本章由 EXPAND_RING 生成 ring 计划。物理绑定另提供每条消息的路径、分配代次、读写保护区间、完成责任、所选传输必需的权限及注册。缺少这些条件时，不能将未知值补成零成本。

```pseudocode
算法 PRICE_COLLECTIVE
输入：共同操作描述、展开计划 S、映射 π、有向图 G
      组容量 C_g、系数 h_(g,a)、端点容量、各阶段 α_p
      分配与保护区间、完成/可见性依赖、容量预留
输出：逐消息/弧/组/端点服务账、阶段预算、窗口占用和网络下界

1 验证共同描述、块范围、唯一生产者、DAG 无环及最终覆盖
  验证消费只引用祖先或外部输入；归约贡献不交且数值操作相容
2 按 π 验证分配代次、权限、必需注册及所选方向
  按同时存活的物理范围并集检查容量，包含全部未完成读写
  必需证据缺失或容量超限：REJECT
3 按拓扑顺序处理每个阶段 p：
    D_a、D_g、O_r、I_r←0；L_p←0
    对每条消息 f：
        从源记录取得实际 holder，核对版本、范围与目的
        route←计划给出的有向弧列表
        验证每跳存在、连续、方向允许，首尾与 π 相符
        O_src←O_src+b_f；I_dst←I_dst+b_f
        对 route 中每次经过的弧 a：
            D_a←D_a+b_f
            对关联的每个组 g：D_g←D_g+h_(g,a)b_f
        L_p←max(L_p,Σ_route ℓ_a)
    τ_p←max(L_p,max_a D_a/B_a,max_g D_g/C_g,
             max_r O_r/B_r^out,max_r I_r/B_r^in)
    w_p←α_p+τ_p
    输出完整服务账和指定窗口下的占用、余量
4 求 DAG 最长依赖路径的 w 权重和
  对每个物理资源另求全部阶段总需求/容量
  T_lb←依赖下界与全部资源总量下界的最大值
5 返回模型结果；实际状态只按完成与可见性事件推进
```

串行 ring 的网络下界为 Σ_p w_p，归约和消费者等待尚未计时。一般 DAG 中，两个无依赖阶段也可能争用同一资源；总量下界补充这一限制，但仍不是可执行并发排程。要预留真实可用容量，需要进一步安排时间窗口，汇总所有重叠消息并检查其资源需求。

路径列表是候选的明确输入，不证明 NCCL 实际采用该路径。未知路由应保留未知或拒绝精确定价，不能凭设备位置猜直连。

## 实际块长与 Ring 成本

均匀块 b=n/P、独立等带宽方向 β、端点不成为瓶颈、没有额外共享限制、每轮启动 α 时：

S_r=2(P−1)n/P，

T_ring≈2(P−1)α+2(P−1)n/(Pβ)。

带宽项按发送量和单向容量计，同时发生的接收不再重复加入。P=4、n=16 MiB、α=5 微秒、β=40 GiB/s，得到 615.9375 微秒；n=8 KiB 时为 30.286102294921875 微秒。这是设定模型，不是设备测量或 NCCL 算法选择证据。

非均匀块时，RS 的 rank r 发送除块 r 外的全部块，AG 发送除块 (r+1) mod P 外的全部块。因此 P>1 时：

S_r=2n−b_r−b_((r+1) mod P)，Σ_r S_r=2(P−1)n。

全组恒等式不能代替逐 rank 发送账。独立直连环、方向容量 B_r、端点足够快时：

T=Σ_(s=0…P−2)[α_RS,s+max_r b_((r−s−1) mod P)/B_r]
 +Σ_(s=0…P−2)[α_AG,s+max_r b_((r−s) mod P)/B_r]。

若存在多跳、共享组或端点瓶颈，每轮改用 PRICE_COLLECTIVE。

```pseudocode
算法 RING_COST
输入：合法整数块长 L、元素字节 e_b、映射、资源描述与每轮启动项
输出：逐轮消息、逐 rank 发送账、服务需求、阶段预算和串行网络下界

S←EXPAND_RING(共同身份,P,L,e_b,输入)
绑定 S 中每条消息的物理路径与所需资源
priced←PRICE_COLLECTIVE(S,物理绑定,资源描述,启动项)
T←Σ_(p∈S) priced.w_p
返回 S.messages、S.sent、priced、T
```

反例一：P=2、块字节 [2,1]、α=0、独立方向容量 [1,1] 字节/秒。RS 每 rank 发送 [1,2]，AG 发送 [2,1]；两轮都需要 2 秒，总计 4 秒，每 rank 发 3 字节。用平均块长 1.5 得到 3 秒，会低估同步阶段的最大服务需求。

反例二：P=3、块字节 [3,1,2]、方向容量 [1,2,3] 字节/秒、α=0、端点足够快。逐轮账为：

| 轮次 | 按 rank 排列的发送字节 | 按方向容量相除 | 阶段服务秒数 |
|---|---|---|---:|
| RS 0 | [2,3,1] | [2,3/2,1/3] | 2 |
| RS 1 | [1,2,3] | [1,1,1] | 1 |
| AG 0 | [3,1,2] | [3,1/2,2/3] | 3 |
| AG 1 | [2,3,1] | [2,3/2,1/3] | 2 |

总时间是 8 秒，逐 rank 发送 [8,9,7]，全组 24 字节。第二轮的最大值是 1，不能沿用上一轮的 3/2；因此 17/2 秒不是该输入的正确结果。审计应同时核对消息矩阵、每轮最大值与总和，避免只修改一个预期总数而保留错误推导。

## 一次硬件映射与共享资源的组合

设四 rank 中 0、1 位于节点 A，2、3 位于节点 B，环为 0→1→2→3→0。节点内方向路径、跨节点 PCIe 方向及端点容量设为 40 GiB/s，网络方向弧各为 10 GiB/s。以下都是演算输入。

| 消息方向 | 物理路径 | 服务计费 |
|---|---|---|
| 0→1 | GPU0→本地互联→GPU1 | 本地实际有向弧一次 |
| 1→2 | GPU1→PCIe_A→NIC_A→网络 A→B→NIC_B→PCIe_B→GPU2 | 各实际方向弧一次；网络计费弧对网络组计一次 |
| 2→3 | GPU2→本地互联→GPU3 | 本地实际有向弧一次 |
| 3→0 | GPU3→PCIe_B→NIC_B→网络 B→A→NIC_A→PCIe_A→GPU0 | 各实际方向弧一次；反向网络计费弧对网络组计一次 |

若两网络方向共用 10 GiB/s 半双工资源，两个网络计费弧的 h 都为 1；PCIe 弧不再计入同一个网络组，其容量另约束。若网络全双工，则换成两个各 10 GiB/s 的独立方向组。

每 rank 输入 16 MiB，均分四块，每轮每消息 4 MiB，α=5 微秒，演算中路径延迟取 0。每轮两条跨节点消息：半双工组服务 8 MiB，τ=781.25 微秒，六轮总计 4.7175 ms；全双工组各服务 4 MiB，τ=390.625 微秒，总计 2.37375 ms。本设定的本地弧和端点都没有成为最大项。

全组端点发送共 96 MiB，两个跨节点方向各发 24 MiB，半双工组共服务 48 MiB。以每轮 τ 为服务窗口，网络组平均占用为 1、服务余量为 0；归约与可见性不因此自动完成。

从准备到回收还要按以下顺序推进：固定 π 和分配代次；产生输入并准备所需注册与工作区；RS 每轮固定发送读范围与接收槽，提交匹配传输，确认完成并建立 GPU 消费依赖，归约后发布新版本；AG 复制及可见后发布完整块；全部块就绪后下游读取；通信与下游各自最后使用结束后，才允许复用相应物理范围。

一种简单分配是每 rank 保留 n 字节原始输入、n 字节工作输出和 max_j b_j 接收暂存。本例主项为 36 MiB/rank，协议缓冲和注册资源另计。逻辑不可变版本不要求永久保留历史 payload：可以在最后读者结束后更新工作区；若增加双缓冲、历史副本或并发微批，就增加其实际存活容量。

## 六类成本与完成边界

| 成本 | 同一候选中的条件化账 |
|---|---|
| 计算 | RS 全组进行 (P−1)N 次二元元素归约；rank r 接收归约 N−L_((r−1) mod P) 个元素。AG 只复制。packing、转换和索引另计 |
| 访存 | 已落入暂存的 b 字节进行一次未融合归约，逻辑上读接收值 b、读本地部分 b、写结果 b；网络落地、发送读取、输出初始化及 AG 写入另列 |
| 通信 | 消息净荷、各弧经过次数、共享组服务量、端点需求、协议头及重传。端点发送与多跳服务分开统计 |
| 准备 | 分配、布局检查、padding、pinned staging、MR/BAR 注册、注册缓存核验、描述符和 group 构造 |
| 同步 | 输入就绪、发起确认、传输完成、归约完成、CUDA 消费依赖、CQ poll 和应用提交；不能用提交返回替代完成 |
| 驻留 | 输入/输出、接收槽、暂存、注册区、在途 WR/CQE、重试及待排空对象；峰值按同一时刻存活物理范围的并集计量 |

未融合归约的 3b 是指定边界的逻辑访存，不是 HBM 事务保证。融合、缓存和传输落地方式都可能改变真实事务。准备、网络、归约与访存重叠时，应接入依赖及资源模型，不能机械相加全部耗时。

主机线程、pinned 页和网卡位于远端 NUMA 域时，控制和 staging 可能额外穿过 CPU 互联。直接 GPU 路径减少某些主机搬运，不消除主机分配、控制和 CPU quota 的影响。记录 π 时须同时记录实际 NUMA 与接口亲和。

GPUDirect 固定文档指出 GPU pinning 可花费至毫秒级，因此注册缓存与延迟 unpin 能摊薄成本；缓存仍必须检测释放、重分配和映射撤销。GPU/NIC 配对还受根复合体、IOMMU 直通、BAR 和平台支持约束，一个配对成功不能推广到全部配对。

GPUDirect 文档 §2.7 要求外部 DMA 写相对于发起依赖 CUDA API 的 CPU 线程先完成，再通过适用的 CUDA 提交或同步关系启动消费者。CQE 成功不等于远端应用已处理，也不证明任意并发 GPU kernel 看到了完整新数据。

verbs 固定文档要求按完成规则保护本地 buffer，inline 有明确例外。批量 post 可能部分提交，已接受的 WR 仍须结算；失败 CQE 只有部分字段有效。CQ 通知是一次性的，通知和 poll 交错还可能出现没有剩余 CQE 的额外事件，不能把通知数当完成数。逻辑取消、超时或旧版本拒绝发布，都不能单独证明 DMA 已停止。

## 条件变化后的保留、调整与放弃

小消息主要暴露启动、准备和同步，可以研究减少轮次或合并提交；大消息更应检查实际块长、共享组和驻留。group 减少 launch，却可能等待最晚输入、推迟最早消费者并延长全部 buffer 的寿命。若拖慢关键路径或造成容量超限，应缩小或放弃聚合。

P 增大保留数学归约契约，但 ring 轮数增加、单块变小，且可能新增跨节点共享资源。TP 每层频繁同步，小 batch 更敏感于等待；EP 全交换更受热点目的端、metadata 和双向共享影响；PP 看阶段依赖与在途激活；P/D 和缓存读取常搬较大状态，更敏感于容量、转换和出口。

树广播的理想逐层模型约为 d(α+n/β)，d 为树深；父节点扇出、单端口和共享上行会改变每层预算。直接 all-to-all 可用 P−1 轮候选，第 k 轮 r 向 (r+k) mod P 发送真实矩阵项 m_(r,d)，逐轮沿路径汇总弧、组与端点。分层方案可先局部聚合、再跨节点通信、最后恢复本地输出，减少外层服务却增加本地轮次、中间状态和重排。本章不提供这些方案的完整展开器；只有补齐各自生产消费计划，才能与 ring 在相同完成边界比较。

改变 π、peer access、IOMMU、NIC 亲和或带宽配额后，应重建路径与执行身份，重新定价。需要 host staging 时加入复制、主存、NUMA 和暂存需求。缓存热点副本、P/D、TP 和制品加载共用出口时，应合并其重叠窗口服务账；更多 GPU 可能增加对同一缓存节点的读取。

若通信不在关键路径，增加链路或层次可能只增加准备与驻留。独立 stream 也不证明有效重叠：共用 HBM、PCIe、NIC 或 SM 时，增加并发流不能消除资源总需求。选择应由合法性、消费者完成时间和容量共同决定。

## 区分实验与反证修正

| 观察 | 竞争解释 | 区分实验与修正 |
|---|---|---|
| 双向并发耗时翻倍 | 半双工；NIC 收发共享；端点处理受限 | 固定两方向字节，比较单向、双向及改变端点放置。若路径独立且端点未饱和仍翻倍，加入遗漏资源或修正服务系数 |
| 非均匀块比平均公式慢 | 最大块与慢方向配对；padding；归约慢 | 保持总字节，旋转块长与 rank 映射，记录逐轮消息。时间随配对移动支持容量解释；不移动则检查固定等待和计算 |
| P 增大后变慢 | 启动轮数；跨节点组；慢 rank | 分别控制 P、放置和消息大小。仅小消息退化支持启动项；大消息随放置变化支持共享容量；不符时重建实际消息和路径 |
| peer access 已启用但慢 | 共享上行；host staging；NUMA；消费者晚 | 对比同根、跨根、直接与 staging 路径，保持消息和完成边界相同。不能用可达性解释全部带宽差异 |
| 真实 EP 比均匀全交换慢 | 热点目的；计数/metadata；网络组；专家计算 | 固定总 item，对比均匀与真实分布，分开计数、dispatch、专家和 return。只有真实分布慢支持偏斜；两者都慢需检查共同资源 |
| 时间线重叠但不加速 | 共用 HBM/NIC；输入晚；消费者等待；错误依赖 | 比较仅计算、仅通信、正确依赖下同时执行。资源分离后改善支持争用；缺依赖的错误结果不能当性能证据 |
| 消费者读旧内容 | 未建立 CUDA 可见性；提前复用；旧代次票据 | 分别注入三种错误，记录完成、提交与分配身份。补足顺序仍错时检查对象身份和其他写入者 |

这些是诊断设计，未声称完成目标设备实验。设备验证需要固定版本、π、消息大小、dtype、并发、路由、完成及可见性证据；只报总网络利用率无法解释阶段慢端。

## 检查范围与未测边界

随章 `tools/check_k_hw_002_full.py` 是确定性、离线、只读的 Python 标准库 CPU 模型。它展开 ring，并用独立的逐块行走参考审计消息来源、目的、版本、贡献集合、整数值与最终覆盖；用逐字节服务令牌参考审计弧、共享组、端点需求、预算和窗口占用。

脚本覆盖 P=1…5、整数块长 0…2、元素宽度 1/2、异构方向容量，以及半/全双工和同一流多次使用组资源。4 秒反例与异构算例的消息矩阵、[2,1,3,2] 秒阶段列表和 8 秒总和分别核对。忽略共享组的负对照保留真实服务账，必须因预算不足被拒绝；平均块长负对照必须被实际消息需求拒绝。漏消息、破坏贡献和消费尚未生产的版本也必须被拒绝。

本轮实际执行的是内存 JavaScript CPU 复核：363 组 ring 轨迹经过逐块行走对照与发送守恒检查，异构轨迹得到 [2,1,3,2] 和总和 8；另用共同定价路径及字节令牌参考核对半/全双工、重复服务和忽略共享组负对照。交付 Python 脚本尚未在本轮执行，不能把上述复核记作 Python 通过。

这些检查不证明一般 DAG 的可执行并发排程、真实 HBM 事务、设备注册及驻留峰值、包调度、CUDA 可见性、取消排空、浮点误差或 NCCL 实际算法选择。容量、启动项和服务系数仍须按目标设备校准；没有 GPU/NIC/PCIe 性能测量，也没有知识改善 Agent 使用效果的证据。
