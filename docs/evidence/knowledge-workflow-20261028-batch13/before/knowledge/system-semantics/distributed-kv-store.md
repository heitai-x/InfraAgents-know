# K-SYS-013：分布式 KV 存储：目录、有效副本与可恢复状态

分布式 KV 存储把状态保存位置与计算实例分开，使多个实例能够复用已经计算的前缀。一次目录命中只说明找到了候选对象；计算身份、完整范围、存活副本、读取保护、目标恢复能力与取得成本仍要逐项确认。目录可以重建，可重算的 KV 可以丢失，但输出提交、请求控制状态和不可重建的随机状态不能因为共用缓存基础设施就一并丢弃。

## 对象、身份与目录

固定一次前向计算的等价条件记为 η，包括模型与权重版本、adapter、规范化输入规则、影响状态的位置与窗口规则、外部特征身份、数值合同以及隔离命名空间。表示合同还须说明 dtype、量化格式和尺度、K 的位置变换状态、层与 head 几何、分页与分片方式。相同 shape 或相同 token 不足以证明状态可以互换；有损表示只能在明确允许的误差与质量合同内复用。

令已知输入为 x[0:N)，位置 p 表示已经消费 x[0:p)，下一次处理 x[p]。本章的完整块索引选择固定正整数页长 P，完整块数 m=⌊N/P⌋，第 j 块 κⱼ=x[jP:(j+1)P)，j=0,…,m−1。未满尾块保持私有，不进入这个完整块目录。这是索引粒度选择，不是模型语义要求。

明确区分根身份和块身份：

h₋₁=H(根域标签,η)，
hⱼ=H(块域标签,hⱼ₋₁,κⱼ,jP,(j+1)P,状态几何,表示合同)，j=0,…,m−1。

因此首块身份 h₀ 使用根 h₋₁ 和 κ₀，第二块 h₁ 使用 h₀ 和 κ₁。目录 D[hⱼ] 的块下标是 j；取得前 b 块覆盖的是 [0,bP)，其逻辑恢复位置为 p=bP。N=0 或 N<P 时没有完整块身份，根身份也不是一个非空 KV 副本。

父身份进入子身份，使相同 token 片段在不同上文之后具有不同的候选身份。序列化必须表达字段类型、长度与边界；哈希只缩小候选集合，还需核对完整计算身份、父身份和内容，不能用父哈希相同再次证明父内容相同。父依赖可以用共享的不可变身份结点表达，无须为每块复制完整 prompt。身份元数据存活与祖先的 KV 字节驻留是不同责任。

一个物理副本至少记录

r=(rid,h,node,incarnation,slot,generation,layout,coverage,range,state,digest)。

node 与 incarnation 标识节点及其本次存活实例；slot 与 generation 标识一次物理分配。coverage 指明状态族、层、head、通道与分片覆盖，range 使用绝对逻辑位置及有效尾长。layout 指明目标如何解释字节；源地址不能直接当成目标页表项。目录保存对象身份到候选副本及生命周期的映射，可以列出多份等价只读副本，也可以列出供合并构建请求的 BUILDING 记录。

目录最长匹配、物理可读长度和本轮可准入位置需要分别记录。前者表示索引发现了什么；第二项还要求完整内容与有效读保护；第三项还受目标容量、状态族恢复边界和任务输出要求限制。将它们合成一个 hit 布尔值，会把索引记录误当成执行许可。

## 合法副本与共同恢复位置

副本对某项状态需求 u 可用，需要同时满足：身份与完整父依赖一致；命名空间与权限允许读取；节点实例和分配代次仍有效；状态为 READY；覆盖包含需求的全部层、head、通道与逻辑范围；内容完整；源端已有适用的可见性；目标可直读或具有满足数值合同的转换路径。READY 不表示任意设备都已经能读取它。远端 READY 字节在目标侧完成到达、转换和消费者可见性之前，仍不能被目标执行器消费。

令 F 为本次需要恢复的状态族集合。每个状态族 f 有允许恢复的位置集合 Rᶠ；任务自身允许的位置集合为 I。I 可以限制输入终点、执行授权及末行输出资格。共同恢复位置必须满足

p∈I∩⋂_{f∈F}Rᶠ。

本章完整块方案还要求 p∈E={0,P,2P,…,mP}。对于非完整块检查点，可以采用另外声明的索引粒度；不能把 p/P 非整数的检查点向下改一个长度，就声称已经得到更早的递归状态。

Rᶠ 是位置资格，实际交付还需一份对应 p 的充分状态清单 M_f(p)。几种典型清单如下：

| 状态族 | 位置 p 的交付内容 | 不能使用的替代证据 |
|---|---|---|
| 完整因果 KV | 所有必要层与分片的 [0,p)；本方案为块 0…p/P−1 | 更深的一个孤立块 |
| 原生窗口状态 | 模型规定的历史窗口及位置描述，例如 [max(0,p−W),p) | 循环缓冲的槽号或一个最大长度 |
| 递归状态 | 精确对应消费终点 p 的检查点 S_f(p) | 修改 S_f(q) 的长度字段，q≠p |
| 外部位置状态 | 对应 p 的版本化控制快照、位置或其他必要状态 | 当前最新版本或只匹配请求 ID |

窗口跨页时，清单列出覆盖该逻辑范围的所有物理对象和有效切片；即使只读一个切片，目标若按整页分配也要计整页容量。递归和外部快照必须绑定相同 η、前缀与位置。缺少任一必要项就不能交付 S(p)。清单中的本地副本也需要保护，不能因为不走网络就省略所有权。

分别取各状态族最大位置，再取这些最大值的最小值，只对从零开始连续的资格集合成立。例如两个状态族分别允许 {0,4,8,12} 与 {0,6,10}，最大值的最小值是 10，但共同位置只有 0。另一例中，完整 KV 到 12，递归检查点为 {4,8,12}，窗口只支持 {8,12}，外部快照当前只支持 8，则共同恢复位置为 8。

位置 0 也要有语义依据：只有模型初始状态和必要控制状态确实可以初始化时，才把 0 加入各恢复集合。若不可重建的外部状态已经丢失，集合可能为空，此时应寻找其他恢复依据或明确失败，不能无条件退回 0。

完整 KV 不自动提供生成第一个新 token 所需的末行 logits。若任务要生成、只保存 KV、没有合法的末行票据，本完整块方案将 I 限制到 p≤N−1，再按块边界选择恢复点；N=8、P=4 时可能需要从 p=4 重算整页。若保存了满足同一输出合同的 logits 或 token 票据，可以允许 p=N。重算写区保持私有，不能覆盖其他请求共享的命中页。没有合法起始输入的空生成请求应拒绝；仅恢复空状态的任务可以返回 S(0)。

## 从候选位置取得状态与容量

下面的取得协议返回逻辑位置 p、完整状态清单、源读租约和目标容量预留。它尚未搬运或发布目标状态。恢复集合、清单和目标布局是显式输入，不能只输入身份链后返回匹配块数。

每个候选 p 的目标计划列出所有需要新建的物理分配、目标已有且受保护的对象、转换工作区、缓冲和本轮增长预留。分配按实际物理绑定去重；同一共享页只计一次，不同节点或不同目标 rank 的必要副本分别计。保守实现可同时预留这些对象的总和；使用生命周期复用来降低峰值时，必须提供相应排空与复用顺序，不能先扣除尚在使用的缓冲。

```pseudocode
ACQUIRE_RECOVERABLE(req, h[0:m), P, I, {R_f}, {M_f(p)}, target_plan, quota)
输入：严格身份链、任务位置资格、各状态族恢复集合与充分状态清单
      每个候选的目标物理分配计划、当前容量与源副本目录
输出：(p, manifest, holds, reservation)，或明确 miss

核对 req 的 η、权限、输入、父链及恢复清单的模型合同
E ← {0,P,2P,…,mP}
candidates ← E ∩ I ∩ 所有 R_f 的交集，按位置递减
对每个 p ∈ candidates：
    manifest ← 所有 M_f(p) 的并集，保留每项的族、位置、范围和身份
    holds ← 空；failed ← false
    按固定次序遍历 manifest 中每个不同源对象需求 u：
        从目录定位候选；本地已有对象也作为候选
        在候选的源端保护操作中重新核对：
            完整身份、范围、READY、可见性、节点实例、分配代次和读取资格
        选择一个可满足 u 的候选，原子地建立覆盖实际读取范围的读租约
        若没有候选能成功取得：failed ← true；停止本候选
        将源句柄、代次、范围与租约票据加入 holds
    若 failed：
        恰好一次地撤销本候选全部 holds；继续下一个 p
    在目标协调区内：
        重新验证 target_plan[p] 的已有对象、分配绑定及当前请求资格
        将新分配按物理绑定求并集，计入工作区、缓冲和增长预留
        若当前可用容量足够：原子取得完整目标预留 reservation
        否则：reservation ← 失败
    若 reservation 失败：
        撤销本候选全部 holds；继续下一个 p
    返回 p, manifest, holds, reservation
返回 miss；不留下本次源租约或目标预留
```

源端的“核对并建立保护”必须相对淘汰具有线性化效果，不能先读目录、稍后对可能已复用的地址增加引用。分布式实现可以使用带副本身份与代次的源端 pin 请求；无需假定整个集群存在一把共享锁。取得多个源对象时，后续失败要结算此前已经成功的票据。这里尚未提交数据访问，所以失败候选可以结束其临时租约；一旦传输已被接受，必须按后续完成协议释放。

该算法按递减位置枚举，选择的是当前清单、指定目标计划和副本选择规则下，第一个能够完整取得的位置。它不保证该位置最快，也不保证找到了所有布局与副本组合中的全局最优解。合法取得后，仍要与更短恢复、直接重算比较成本。容量也不一定随 p 单调：不同检查点、窗口表示和工作区可能改变占用，因此不能在一个候选容量失败后直接宣布所有更早位置都失败。

一个完整轨迹取 P=2、N=13，完整 KV 到 12；递归集合为 {0,4,8,12}，窗口和外部快照集合均为 {0,8,12}。假定 0 的初始化合法，所有非零清单使用完整 KV 前缀、该位置的窗口、递归和外部快照。每个 KV 块 4 MiB，窗口包 2 MiB，递归与外部包各 1 MiB，工作区与增长预留共 2 MiB，目标预算为 26 MiB。

| 事件 | 资格、租约与容量 | 结果 |
|---|---|---|
| 查询 | 完整块目录可匹配 6 块，即逻辑位置 12 | 还不能返回 12 |
| 尝试 12 | 取得 6 个 KV 对象及 3 个快照对象的临时租约 | 需要 24+2+1+1+2=30 MiB，容量失败 |
| 撤销 | 本候选尚未发起传输，结束其全部 9 份租约 | 不留下多余读者或目标预留 |
| 选择下一交点 | 位置 10 虽能容纳 5 个 KV 块，但不是共同检查点 | 跳过 10，尝试 8 |
| 取得 8 | 取得 4 个 KV 对象及位置 8 的 3 个快照对象 | 需要 16+2+1+1+2=22 MiB，原子预留成功 |
| 交付 | 返回 p=8、7 份源租约、完整清单与 22 MiB 预留 | 后续处理 x[8:13)，不能按 6 块命中跳到 12 |

即使预算增加到 30 MiB，若位置 12 的递归快照仍为 BUILDING 或属于旧分配代次，也必须回退到 8。若位置 8 也缺必要状态，应继续检查其他共同位置；不能只保留 KV 租约并返回一个不完整的 S(8)。

## 私有构建、发布与最后使用

不可变前缀可以存在多个等价副本；可变尾块必须冻结版本或使用明确的更新协议。目标构建只写入本次独占的私有分配，不能把网络接收区直接指向正在共享读取的尾页。

```pseudocode
FILL_AND_PUBLISH(req, p, manifest, holds, reservation)
输入：取得协议返回的完整状态与容量责任
输出：目标可消费的 S(p)，或失败及待排空责任

为目标私有分配建立新的 allocation generation 和操作账
登记 BUILDING 记录；它只能供构建合并与等待，不能作为 READY 命中
为每项清单建立源范围、目标范围、转换和完成依赖
对每项需要搬运的内容：
    保持源租约、注册区及描述有效，记录实际接受的传输操作
    等待该范围的成功完成，并建立目标侧消费者可见性
    在私有区完成必要的布局转换、重分片或量化重建
    核对内容、有效范围、辅助参数及目标代次
若任一项失败、取消、接受状态未知或发布资格失效：
    停止新增提交，不推进目标可消费位置
    撤销未发布的发现资格，进入 DRAINING
    对已接受及接受未知操作保留源、目的、暂存与注册保护
    取得相应排空证据后，结束租约并释放不再使用的私有分配
    保留原有有效副本和旧请求快照；返回失败责任
全部必要状态族、层组与范围完成后，在目标协调区复核：
    req、p、清单、目标代次及发布授权仍属于本次尝试
    原子安装共同状态视图与页表，发布 READY 和位置 p
    将预留交接为明确的目标拥有责任
按每项最后实际使用结束源租约；不能只按主机函数返回释放
返回可消费的 S(p)
```

实际数据流为：目录身份查询 → 源端核对与读租约 → 源范围定位及必要注册 → 传输到目标或暂存区 → 完整到达与目标可见性 → 转换与辅助状态核对 → 页表安装 → 共同状态发布 → 引擎消费。主机 post 返回、NIC 完成、GPU 可见、模型执行结束和请求输出提交是不同事件。直接 GPU 路径仍须遵守实际平台的外部写入排序合同；普通网络完成不能任意放行已经运行的并发 kernel。

TP/PP 或布局变化时，清单要显式绑定源、目标的层、逻辑位置、唯一 KV head、通道及物理副本。一个唯一 head 在多个目标 rank 上需要副本时，每个落点都需要字节、容量与完成证明。仅改描述符不会把 NHD 字节转成 HND，也不会把源进程指针变成目标有效地址。

single-flight 可以合并同身份的构建，减少重复读取；取消一个等待者不能释放其他等待者仍需的构建责任。两次构建产生两份等价只读副本也可以合法保留，分别记录其分配与读者。立即改写另一个正在执行的请求页表来去重，需要额外的快照交接，不能由内容等价直接推出。

```pseudocode
RETIRE_AND_RECLAIM(rid, expected_generation)
在副本协调区内：
    核对 rid 与分配代次
    若仍有必须保留的恢复责任或不能撤销的构建依赖：返回不可淘汰
    撤销新读者的目录可发现性，标记 RETIRED
    若索引声称连续前缀可恢复，修正受影响的恢复资格
离开协调区；已有读者继续由各自租约保护
等待所有实际读写、转换、网络访问与注册使用结束
确认没有剩余拥有责任后释放物理范围，再为下一内容递增分配代次
```

目录撤销、逻辑请求结束和物理地址可复用是三个事件。超时不是排空证明，代次检查也不能阻止一条已经发出的旧 DMA 覆盖新对象；首先必须隔离旧范围直到物理访问终止，代次再负责拒绝迟到的逻辑完成。

连续前缀索引通常可采用叶优先淘汰。若删掉某块的最后可用副本，使更深 KV 无法与完整父状态组成恢复包，应撤销相应的连续可恢复声明。其他节点仍有父块时，可以继续从它们取得。独立窗口或递归快照若本身已构成充分状态，可以使用不同依赖索引；不能把完整 KV 前缀的叶规则强加到所有状态族。

## 同一请求终点上的成本比较

候选必须从同一个起点计时，例如请求输入和身份已确定、尚未开始本次恢复决策；终点也相同，例如同一合法输出合同下完成规定数量的生成并提交。候选可以使用不同的恢复位置 p，但不能把一条路径计到状态就绪，另一条计到生成结束。

定义

T_suffix(p)=T_input(p,N∣S(p))+T_gen(p,N,G)，

其中第一项是从 S(p) 处理剩余输入 x[p:N) 的成本，包括后缀对历史的 Attention；第二项是在相同任务终点下生成并提交规定输出的成本。必要的末行重算必须已经反映在 p、输入计划或准备项中。于是 T_suffix(0) 已包含全部输入计算，不能再加一次完整 prefill。

以串行估算为例：

T_local≈A_local+T_idx+T_map+T_suffix(p_local)，
T_remote≈A_remote+T_idx+T_pin+T_dir+T_q+T_cap+D_wire/B+T_conv+T_pub+T_suffix(p_remote)，
T_recompute≈A_recompute+T_suffix(0)。

A 表示各候选确实需要且尚未计入的准备成本。目录、源租约和目标容量等待即使没有 payload 也可能有成本；已经发生的公共准备不能在某条路径重复加入。目标容量根本不足时，该候选不合法，不能仅用一个很大的 T_cap 掩盖无可执行计划。

设定六个输入分段沿固定执行轨迹分别需要 3、4、5、6、5、7 ms，总计 30 ms；公共生成阶段需要 10 ms。某合法恢复点覆盖前三段，剩余输入仍需 18 ms，取得与发布开销为 20 ms。重算完整请求为 30+10=40 ms，远端路径为 20+18+10=48 ms，应选择重算。错误地写成 30+T_suffix(0) 会得到 70 ms，并错误选择 48 ms 的远端路径。这个分段算例是可独立核对的事件账，不表示真实 prefill 可以按命中 token 比例线性扣除。

沿用另一个设定：对象 512 MiB，有效带宽 20 GiB/s，纯传输为 0.5/20 s=25 ms；目录、排队和转换另需 15 ms，则取得阶段共约 40 ms。在两条候选具有相同后续工作时，若被替代的前缀重算只需 30 ms，远端命中更慢；若需要 180 ms，则可能有收益。这些 30/180 ms 只表示被替代部分，不能与上一例的完整请求 40 ms 混用。

若 k 个等长块依次经过传输 b 和转换 c，固定启动为 a，并且两阶段资源独立、缓冲足够，理想流水时间为

a+b+c+(k−1)max(b,c)。

共享 NIC、HBM、CPU 或暂存不足会破坏该假设。串行工作才能直接相加，重叠工作应沿真实依赖与共享资源计算关键路径。

负载到达率 λ、远端读取比例 h、每次实际读取 D 字节时，平均读取需求为 λhD。取 λ=4 次/秒、h=0.3、D=0.5 GiB，得到 0.6 GiB/s，即 4.8 Gibit/s，换成十进制链路单位为

0.6×2³⁰×8/10⁹≈5.154 Gbit/s。

复制、写入、重试与元数据另计，5 Gbit/s 链路即使没有其他流量也不足以持续承载这个平均读取需求。平均需求小于链路能力仍不保证突发和尾延迟满足 SLO。多个读者共用同一出口时，总需求相加，不能为每个请求都沿用独占 20 GiB/s 的估计。

| 成本 | 必须计入的工作或对象 |
|---|---|
| 计算 | 身份序列化、匹配、内容校验、清单展开、格式转换、解码、重算和剩余模型执行 |
| 访存 | 源读、打包与暂存写读、目标写、参数与页表、转换工作区和重复展开 |
| 通信 | 实际编码载荷、辅助状态、控制消息、目标副本、重试与后台复制 |
| 准备 | 恢复集合求交、源保护、目标规划、注册、页表和描述构造 |
| 同步 | 源保护线性化、容量预留、传输完成、消费者可见性、发布与排空 |
| 驻留 | READY、BUILDING、旧读者、私有目标、双缓冲、增长预留及元数据 |

若恢复集合以有序列表表示，可通过多路推进求交；直接枚举 m+1 个完整块边界并检查 F 个集合，需要 O(mF) 次资格查询。每个候选还要展开其清单并核对副本。逐候选重建整个 KV 前缀最坏可产生 O(m²) 个描述访问，回退也会增加 pin/unpin 往返。可以复用已核对的不可变身份和增量清单，但源存活与保护仍须重新成立；不能用历史核对结果替代当前租约。

## 副本、热点与驻留预算

复制热门前缀能降低单源排队、分散路由并提高故障覆盖，但不会自动减少总读取字节。若各副本在观察窗口内可用的概率为 aᵢ，且确实近似独立，至少一份可用的概率才可写成 1−∏(1−aᵢ)。同机架、同出口、同版本失效或共同过载会造成相关性，目录中的副本数量不能直接当成独立服务能力。

可比较固定副本数、按读取压力增减、按预测收益放置和仅在请求到来时拉取。增加副本前，比较预计减少的源排队与重算、后台网络、驻留机会成本和失效管理。若所有新副本仍共享同一个出口，单源队列可能下降，但总关键路径不变；热点变化后应减少无收益副本，给新请求和其他前缀让出容量。

物理容量按实际驻留并集计算：

C_phys=bytes(READY∪BUILDING∪待排空旧对象∪实际预留范围)+C_metadata。

这个并集中的对象按物理分配身份去重。缓存保留、活动请求映射和传输读者若指向同一页，只占一份字节；两个节点各有副本则确实占两份。若增长预留和缓冲已经包含在一个预分配池内，应在池内核算，不能再把池总容量与其中对象相加。尚未兑现为物理范围的容量承诺另记准入账，并保证它与已占容量共同不超过预算。

保留一份缓存的价值取决于未来复用概率、可避免的净关键路径和驻留期间阻挡其他工作的代价。LRU、访问价值或重建成本只决定合法淘汰候选的排序；仍被实际读者使用的冷页不能立即增加可用容量。池中全是只读热点副本时，新请求也可能没有接收与增长空间。

模型或 adapter 改变时重新建立 η；布局改变时重算转换、目标容量与读取路径；带宽下降、源排队增长或重算加速时，重新比较完整候选，允许缩短恢复点或放弃远端恢复。窗口覆盖和递归状态改变后，必须重建恢复集合与清单，不能只沿用“命中长度”。

## 故障、竞争解释与区分实验

| 故障或竞争 | 合法处理 | 错误替代 |
|---|---|---|
| 目录列出 BUILDING | 等待、另选副本或回退 | 目录存在即交付 |
| 状态族缺失或检查点不共同 | 选择更早共同位置并重新核算容量 | 只返回各族最大值的最小值 |
| 容量截断落在非检查点 | 回退到满足全部条件的交点 | 返回能放下的 KV 块数 |
| 源在部分传输后退出 | 目标保持未发布，保留操作账并恢复或排空 | 发布部分状态 |
| 地址被复用、旧通知迟到 | 排空后复用，并按原代次结算通知 | 只凭地址相同更新新对象 |
| 发布前目标取消 | 停止新增提交，私有范围待排空 | 取消即释放全部容量 |
| 全 KV 命中但无末行票据 | 合法重算末段或读取同合同票据 | 直接开始采样 |
| 控制状态不可重建 | 寻找完整恢复依据或失败 | 将所有状态当成可丢缓存 |

“远端命中仍慢”至少允许目录控制开销、源热点、目标容量等待、传输和转换等竞争解释。区分实验要固定身份、输入、合法恢复点和任务终点，分别改变一个可解释因素，并记录阶段边界。

保持字节和目录记录不变，只让源副本从 BUILDING 转成 READY；消费者只能在真实就绪后获得状态。若仅改目录标签就能提前消费，说明就绪核对缺失。若两种情况都慢，应继续检查排队与数据路径，不能据目录命中率归因。

保持源、目标与 payload 不变，只改变目标空闲容量，观察准入、回退位置、临时租约与 T_cap。若延迟或拒绝随空闲页改变，支持容量解释；固定容量后改变有效带宽，才区分传输解释。将递归检查点设为 {0,4,8,12}、预算设为只能容纳到 10 的 KV，取得路径必须实际返回 8，并证明位置 12 的临时租约已经结算；单独测试集合交集不足以证明这一点。

保持传输字节和块数不变，只切换目标是否需要布局转换，分别记录到达、转换结束、页表安装和发布。到达时间相似而发布变慢，支持转换或准备解释。增加热门副本时记录每个源队列、每条共享链路字节及尾延迟；源队列下降而尾延迟不变，应转查共同出口或目标消费能力，不能继续仅以命中率证明收益。

故意延迟一个读者和旧完成通知，再尝试复用物理槽。若故障只在读者未结束或旧通知迟到时发生，支持生命周期或代次解释。固定地址、代次和完成次序后仍能重现的错误，更应检查内容身份、范围或布局。代次拒绝测试与真实物理排空测试分别进行。

成本核对使用独立事件账，包含非零剩余输入和公共生成阶段；故意加入一次重复完整输入计费，要求它被参考账拒绝。网络单位从字节/秒独立换算为 bit/秒，不能只验证 0.6 这个中间数。

随章 Python 检查交付给 tools/check_k_sys_013_full.py。它把共同恢复资格、源状态、代次、清单、容量及租约结算放入同一取得路径，与从副本全集和逐位置枚举构造的参考比较；负对照包括跳过恢复集合、目录存在即命中、忽略代次/身份/范围、回退泄漏租约和重复输入计费。它只建模空目标上的确定性串行控制逻辑与设定容量，不实现网络、转换 kernel、发布事务或真实异步排空。

本轮实际执行的是内存 JavaScript CPU 模型：128 个确定性组合核对了容量、缺块、BUILDING、旧代次与回退租约，另核对共同位置反例、40/48/70 ms 成本反例和单位换算。交付 Python 脚本尚未在本轮执行。上述模型均不证明真实目录并发原子性、GPU 可见性、NIC/RDMA 排空、设备转换、带宽、SLO 或知识改善 Agent 的使用效果。
