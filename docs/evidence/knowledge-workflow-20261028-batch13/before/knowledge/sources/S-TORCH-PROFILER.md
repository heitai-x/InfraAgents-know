## 从操作归属到时间窗口

框架 profiler 的价值是把高层操作、设备工作、输入形状、调用栈与内存活动放到可联系的记录中。归档支持等待、预热、记录与记录后保存等状态；调用方推进步计数，采样窗口按状态切换。预热初始化采集路径，实际输出只覆盖所选记录窗口，不能把未采集区间解释成没有工作。

```pseudocode
定义要区分的问题与所需事件，选择采集活动和字段
按步推进等待、预热和记录状态
在记录窗口收集操作/设备/内存信息，窗口结束时保存
依据操作与设备事件的关联解释瓶颈，再用普通执行检验端到端结果
```

形状与栈采集增加开销，部分形状跟踪会保留张量引用，可能改变引用计数相关优化和内存表现。设备事件区间与 host 调用区间也不是同一计时边界。详细采集结果适合诊断，服务性能结论需要说明采集扰动并由相同条件下的普通执行支持。

## 应怎样检验解释

保持输入与设备条件相同，改变是否采集形状/栈和采集窗口，观察时间与峰值内存是否随之改变。若某优化只在 profiler 下变快，先检查采集路径与生命周期变化。机制展开见[框架 profiler](../tools/framework-profiler-scope.md)；混合归档中的文档原文保留可读，源码仅作核验。
