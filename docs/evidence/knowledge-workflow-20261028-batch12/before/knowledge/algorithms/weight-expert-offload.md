# K-ALG-019：权重与专家卸载：重用、路由与在途版本

权重卸载在容量不足时改变参数取得路径。它要解决两个问题：下一次计算怎样获得完整、相容的权重；同一份载入权重怎样服务更多合法工作。稠密层按模型顺序执行，MoE 的专家集合由路由决定，激活稀疏则依赖非零贡献或预测契约，三者不能共享一个未经区分的“只加载需要的参数”假设。

本章先讨论单 GPU、主存保存不可变权重的执行器；SSD 可以成为其上游，专家并行可以成为其下游，但两者的传输分别计账。算法支持一个完整层或专家能够装入可执行空间的情况。对象超过空间时，必须另行证明分片执行或改用 CPU 放置，不能仅把文件拆块便宣称能够计算。

## 函数、输入输出与必须保存的身份

稠密层的边界记为 H_(l+1)=F_l(H_l,KV_l;W_l)。F_l 包含模型规定的归一化、attention、FFN 和 residual；卸载可以改变遍历顺序、位置和表示准备，不能删去依赖。一个请求的下一生成步必须等待当前步末端输出及所需状态确认，不能把连续自回归 token 当成独立微批。

对一层 routed MoE，输入 X 有 N 个有效 token 行，hidden 维为 d。token 身份 τ 包含请求或 origin 及其内部位置；两个 origin 都有 token 0 时仍是不同对象。router 产生选中集合 S_τ 与门控乘数 g_(τ,e)，输出为

y_τ = Σ_(e∈S_τ) g_(τ,e) E_(v,l,e)(x_τ)。

shared expert、residual 和其他分支按模型另加一次。N 是这一层的 token 行数；只有每请求推进一个 token 的 decode 中，它才等于请求数。prefill 的并集统计应计所有输入行。

[Mixtral](../sources/S-MIXTRAL.md) §2.1 使用选中 logits 上的 softmax，即 G(x)=Softmax(TopK(xW_g))，固定模型为 8 个专家、top-2、SwiGLU。这里的稀疏性来自模型函数本身。缓存缺失不授权改选邻近专家、减少 k、删掉较小门控贡献或重新归一化剩余项。实数等价也不保证浮点逐位相同，重排和 combine 顺序须服从既定误差与可复现性契约。

输入还包括容量预算、权重副本目录、表示转换计划、执行器数值契约和取消状态。输出是同一调用快照下的完整 hidden，或明确失败/取消；未完成的部分和不作为完整层发布。

| 对象 | 至少绑定的身份与状态 | 防止的具体错误 |
|---|---|---|
| 逻辑权重 K | 模型版本 v、层 l、专家 e 或稠密范围、表示 r、分片 p | 同 expert ID 读到另一模型或另一量化布局 |
| 物理载入槽 | 地址、大小、lease、当前 K、加载状态、实际访问集合 | 旧完成通知释放新代槽；在途覆盖 |
| 层调用 G | 尝试代次、模型版本、层、冻结路由及放置快照 | 重试或切换目录后混入旧结果 |
| item | (G,τ,e)、g、执行位置、预期权重 K | 重排后贡献归错 token，或门控乘两次 |
| 合并状态 | Expected、Seen、部分结果、提交资格 | 漏贡献、重复贡献或取消后发布 |

模型版本在请求承诺的范围内固定。若请求跨层都承诺使用 v，不能因目录已经切到 v+1，就让后半模型读取新版本。固定 staging 地址或固定图指针也不证明其中内容仍属于原版本；与 [权重加载](../frameworks/checkpoint-loading.md)、[CUDA Graph](../frameworks/cuda-graph-buffers.md) 的身份和布局条件同时检查。

## 稠密层：交换循环以摊薄载入

设一个 decode 轮次推进 N 个独立请求，拆为 M=ceil(N/b) 个微批，b 为单次 GPU 执行的行数，末微批只处理实际有效行。逐微批跑完整模型会反复访问各层；按层处理全部微批，可以让同一份权重服务更多行。这是 [FlexGen v1](../sources/S-FLEXGEN.md) §4 的 block schedule 动机，主要服务允许较长等待的吞吐任务。反复访问是否造成反复复制，还取决于槽容量、初始内容和淘汰策略。

```pseudocode
算法 DENSE_LAYER_MAJOR
输入：固定模型版本 v；N 个请求当前步的合法输入与 KV；微批上界 b>0
输出：各请求本步的完整模型输出和对应 KV，或明确失败
1 若 N=0，返回空结果，不载入权重
2 按冻结的请求顺序构造微批，保留请求、位置与有效行映射
3 对 l=0..L-1：
    为当前层全部微批的输入、输出、KV 与工作区建立容量账
    核对缓存中是否已有完整、可见且身份匹配的 (v,l) 权重
    命中时取得读权，不产生新的权重复制事件
    缺失时取得可执行空间，只淘汰没有读权和实际访问的副本
        绑定新 lease，登记复制和转换责任，从不可变源载入
        记录实际提交的复制范围与字节；等待成功且对消费者可见
        失败则撤销本轮提交资格，不把部分权重作为命中
    对每个微批 m：
        等待 H[l,m] 和对应 KV 输入就绪
        登记当前权重、激活、KV 和输出区的实际访问责任
        执行 F_l，保留原请求与位置映射
        等待本微批执行及必要输出搬运完成，确认 H[l+1,m] 就绪
        只解除已经结束的实际访问；保存下一层仍需的激活与 KV
    最后一个权重读者结束后，允许保留或淘汰本层权重
4 所有层、输出映射和必需状态完成后，按请求提交本步结果
5 若失败或取消：停止提交后继，排空已有访问，不发布不完整结果
```

这是可实现的串行基线。预取下一层可以加入独立队列，但不能覆盖当前层仍在读取的槽；激活换出也必须完成其源读取后才复用源区。某层的所有输入必须先经过上一层，层间交换循环只利用不同请求或微批的独立性。空层列表是数学边界，不代表制品缺层可以被接受。

先固定一个轮次和相同权重表示。令 C 为轮次开始时未在设备中有效驻留、但本轮必需的层权重集合，S_l 为其所计链路载荷字节，W_off=Σ_(l∈C)S_l。这里“初始冷”不意味着后续每次访问仍然缺失。若常驻部分不被驱逐，且按层路径让每个初始冷层只载入一次、服务全部微批后再释放，则 D_layer=W_off。只有额外规定逐微批基线在每个微批都重新载入全部 C、无跨微批有效保留时，才有 D_row,forced=M W_off，以及两者相差 (M−1)W_off。强制清空、容量与具体替换规则导致的全缺失轨迹，都可以形成这一基线；仅有模型总权重大于槽容量并不足以推出它。

一般路径按实际事件计账。令 Λ_H 是计量窗口内所有 H2D 权重复制事件构成的多重集合，则 D_H=Σ_(a∈Λ_H)bytes(a)。同一权重淘汰后重载会再次进入集合；有效命中不进入集合。无预取、每次缺失恰好完整载入一次时，也可按访问序列写成 Σ_i miss_i S_(l_i)，其中 miss_i 必须由第 i 次访问前的有效槽内容、淘汰和此前复制结果决定，不能恒设为 1。有预取、重试或填充时，应回到复制事件账，并另标需求、重载和未消费载荷。跨轮保留也须携带实际初始状态，不能每轮同时声称全冷和保留命中。

一个反例可以完整展开。三层 A/B/C 各 S 字节，两个各能装下一层的槽，初始全冷，无永久常驻层，N=2、b=1。已知固定访问次序时，选择保留下一次较早使用的层即可得到：

| 次序 | 槽操作 | 操作后有效内容 | 累计载荷 |
|---|---|---|---:|
| 第一个微批 A | copy A 到槽 0 | A、空 | S |
| 第一个微批 B | copy B 到槽 1 | A、B | 2S |
| 第一个微批 C | 淘汰 B，copy C 到槽 1 | A、C | 3S |
| 第二个微批 A | hit A | A、C | 3S |
| 第二个微批 B | 淘汰 A，copy B 到槽 0 | B、C | 4S |
| 第二个微批 C | hit C | B、C | 4S |

它保持每个微批的 A→B→C 函数顺序，模型总权重 3S 也确实超过槽容量 2S，却只复制 4S。按层访问 A,A,B,B,C,C 只需 3S；这一对轨迹节省 S。若在微批边界清空有效槽，逐微批路径才变成 6S；FIFO 在本例也会产生 6S。这些是不同缓存轨迹，不能把强制重载的 3S 节省套给已经保留命中的路径。使用已知未来次序只是本例可替换的合法策略，不构成一般在线策略或变长对象的最优性证明。

在 D_layer=W_off 的既定前提下，链路有效带宽 β_H 给出其传输下界 W_off/β_H，摊到每输出 token 为 W_off/(Nβ_H)，仅对 N>0 定义。一般路径相应使用实际 D_H。吞吐摊销不等于每请求 ITL：每个请求仍经过全部层，通常还等待其他微批。

这种循环交换会延长激活和请求状态生存期。若相邻层边界的全部 hidden 都写回主存再读入，decode 激活往返主项为 2N d b_a (L−1) 字节，b_a 是 hidden 元素字节数；此式针对 L≥1 的该换出方案，不适用于始终在设备保存 hidden 的路径，L=0 时无层间迁移。KV 读写、embedding、logits、路由和 padding 另计。扩大 N 必须同时重算 KV、激活、工作区与主存容量，不能只看权重摊销。

## MoE：从路由并集构造载入任务

冻结路由后，定义专家桶 I_e={(τ,g_(τ,e)):e∈S_τ}，桶长 n_e=|I_e|，本轮工作集合 U={e:n_e>0}。同一专家服务所有桶内行时，可以只加载一次权重。若按 token 顺序逐项载入而缓存很小，相同专家会重复缺失。

设 E 个专家、每 token 选 k 个不同专家；不同 token 的路由独立，专家 e 的边缘选中概率为 q_e，则

E[|U|] = Σ_e [1−(1−q_e)^N]。

推导只需对每个专家计算“所有 token 都未选中”的概率，再对出现指示量求和；同一 token 内的 k 个选择不要求互相独立。均匀时 q_e=k/E，得到 E[1−(1−k/E)^N]。E=64、k=2 时，N=1 为 2，N=16 约为 25.5，N=64 约为 55.6。每专家假设 128 MiB、全部冷、每个只加载一次时，逻辑传输仍可接近全部专家大小。

独立性是实质条件。若一个 batch 的所有 token 总选择相同的一组 k 个专家，其并集恒为 k，即使跨 batch 的边缘分布均匀，也不能套用独立公式。实际应记录路由轨迹、并集和重用距离。[Mixtral](../sources/S-MIXTRAL.md) §5 报告部分较深层的相邻 token 路由局部性，提示缓存机会，也可能形成热点；它不证明任意输入都有相同命中率。

初始可用缓存集合为 R_0、专家传输大小为 S_e 时，理想必要缺失载荷为 D_min=Σ_(e∈U且e∉R_0) S_e。它假设初始命中的专家在消费前保持有效，且每个缺失专家只加载一次。可以先消费初始命中的桶，再串行处理缺失桶以实现这一本轮权重账；如果先为别的缺失驱逐尚未使用的命中，则实际流量还要加上重载。缓存命中统计不能提前记入已节省的字节。

当 |U| 大于槽数时，不必同时放入整个并集。按桶执行、保存受保护的输入与结果，一次完成一个专家即可推进。例如两个 token 都选 {e0,e1}、只有一个专家槽：逐 token 固定次序为 e0,e1,e0,e1，共四次加载；按专家桶执行为 e0 的两行、再 e1 的两行，共两次加载。每 token 仍等待两个贡献，函数不变。只有全部专家权重同时到齐才启动计算的方案，在并集大于容量时会无后继事件；应改变调度粒度，而不是静默删路由。

## 有界载入、执行与完整合并

以下采用完整专家为载入单位、独占调度拥有者管理状态、已冻结输入、结果在独立受保护区保存的方案。多个 stream 或工作线程可以实现它，但所有状态变化必须保留同样的原子边界。权重已就绪时，检查身份和登记读权必须是同一次接纳，避免两者之间被淘汰。

槽的状态为 FREE → COPYING → READY；失败进入 FAILED_DRAINING，结束后进入 FAILED 或释放。READY 表示完整可执行范围成功产生且可见，不表示没有读者。槽另有读权和实际访问集合：已接纳但尚未提交的 kernel 持有读权，已提交的 DMA、转换、kernel 等持有实际责任。这样不会在复制刚结束、kernel 尚未提交的空隙误回收。

```pseudocode
算法 OFFLOADED_EXPERT_LAYER
输入：调用 G、X、冻结 S/g、权重目录；有界主机/设备槽与结果空间
输出：完整 y，或失败/取消及尚待排空的责任
1 校验 token、路由、权重版本、表示和目标执行器相容
  建立 I_e、U、Expected={(G,τ,e):e∈S_τ}；Seen←空
  每个桶←PENDING；结果←未发布；eligible←true
2 验证每个必需专家能单独装入某条合法执行路径
  预留本调用的输入、描述符、结果和至少一个可推进工作单元
  不要求同时预留全部 U 的设备权重
3 循环直到所有桶 DONE，或 eligible=false：
    处理完成事件，只匹配完整的操作身份、K、槽和 lease
    复制/转换全部成功且完整可见时，才将对应槽置 READY
    优先选已有同 K 的 READY 槽对应的待执行桶
    若无此桶，按确定的需求次序选一个 PENDING 桶 e：
        取得能装入 e 的槽；只能淘汰没有读权、没有实际访问的副本
        没有槽时，等待能释放槽的在途工作；无后继事件则明确失败
        递增槽 lease，绑定 K，置 COPYING，并将桶置 WAIT_WEIGHT
        提交前登记源、目标与转换临时区的全部实际访问
        从不可变源读取；完成后检查范围、表示和结果状态
    对权重 READY、输入就绪、结果空间充足的桶：
        原子核对 K 并取得权重读权，将桶移出待选择集合
        按 I_e 收集输入行，保留 (G,τ,e,g) 映射
        登记执行访问后提交专家；必要时将桶内行分为有界 chunk
        每个 chunk 执行完整专家函数，不能跨非线性随意拆开归约
        把每行专家结果乘对应 g 一次，写入私有 item 结果区
        执行最后读取结束后解除权重读权；输出消费者另行结算
    对完成 item：
        验证 G、τ、e、K 与冻结计划匹配
        重复 item 不再次累加；缺项不标记完成
        按约定顺序或数值契约合并，Seen 加入该 item
    完成所有 chunk、结果交接与责任结算后，桶←DONE
    可选预取只使用剩余容量和带宽，不阻塞当前必需缺失的推进
4 仅当 eligible 且 Seen=Expected，shared/residual 也完成时发布结果
5 失败或取消时撤销 eligible，停止新工作，丢弃未发布逻辑结果
  已提交访问继续按原身份排空；结束证据缺失的对象保持隔离
  任何迟到成功均不恢复本次调用的发布资格
```

输入重排可以用计数、前缀和与散写：先统计 n_e，再令 offset_(e+1)=offset_e+n_e，按每个 item 写入对应桶的下一个位置。专家输出通过保存的映射返回原 token；不以物理桶行号或槽号替代身份。空桶不执行专家；N=0 不加载权重。k=0 可以作为通用归约检查的边界，固定 top-2 模型不能为省成本临时采用它。

输出可以按完成顺序到达。若要求固定累加顺序，先按 item 保存，覆盖完整后按模型约定顺序求和；这会增加结果驻留。允许误差契约内的归约重排时也要保留 Expected/Seen。设备侧重复写同一个 partial 区可能已经污染数值，host 去重标记无法修复；重试应使用隔离结果区，或由执行协议提供真正的唯一写入关系。

需求加载、固定热门驻留、近期路由更新和预测预取都是可替换策略。它们必须服从同一读取与回收条件。大小不同的专家不能仅按命中次数排序；避免的暴露时间、权重字节、重建成本、未来使用概率和 deadline 均可能改变选择。按“预期节省时间/字节”排序可生成候选，但不证明带容量、依赖和公平约束的全局最优。

## 异步流水的真实依赖与版本切换

权重从 SSD 到普通主机缓冲、转换到可传输布局、H2D 到设备槽、专家读取到结果合并，是多种资源上的依赖。源文件字节、主机打包字节与设备可执行字节可能不同。量化解包、转置、scale 和分片必须共同完成；单个矩阵到齐而其他矩阵缺失时，完整 SwiGLU 专家尚不能执行。

[CUDA 异步来源说明](../sources/S-CUDA-ASYNC.md) 区分 host 返回、设备执行完成和跨队列依赖。实现应使消费队列等待该权重实际复制及转换的完成事件，再记录覆盖所有读取的最后完成事件。主机 staging 在所有 DMA 及其他读者结束前保活，设备槽在最后权重读者结束前不覆盖。设备内 global→shared 的 cp.async 是另一段搬运，不能用其 CTA barrier 直接证明 H2D 已结束，或证明整个 kernel 已不再读取设备权重。

可计算的两槽模型如下。依次处理 m 个独立桶或层工作块，一台复制引擎串行载入，一条计算队列串行计算；两槽交替使用，输入均已就绪、没有其他读者，载入和计算时间分别为 t_i、c_i。令 D_i 为第 i 块复制结束时间，C_i 为计算结束时间，越界前项取零：

D_i=max(D_(i−1),C_(i−2))+t_i，
C_i=max(C_(i−1),D_i)+c_i。

D_i 等待同一复制引擎，也等待两块之前的消费者释放槽；C_i 等待前一计算及本块权重。m=0 时结束时间为零。t=[4,4,4]、c=[6,6,6] 的设定单位下，D=[4,8,14]、C=[10,16,22]，总计 22；完全串行需 30。该模型已包含启动与排空，不能只用 max(Σt_i,Σc_i)=18 作为完成时间。若两槽大小不足、输入未就绪、输出读者延长生存期或 HBM 争用改变 c_i，必须重建递推。

一次版本切换可以沿以下轨迹检查。设设备仅有一个 128 MiB 专家槽；数字为容量设定，事件不代表实测。

| 事件 | 存活责任及合法后继 |
|---|---|
| G0 绑定 v1，槽 s 的 lease=7 开始复制专家 e | 源与目标都有复制责任，不能执行或覆盖 s |
| 复制完成，G0 接纳两个 chunk | 权重 READY；两个 chunk 的读权保护 s，提交间隙仍不能覆盖 |
| 第一个 chunk 结束；新请求改用 v2 | 第二个读者仍保护 v1。目录切换不改变 G0，也不能把同 e 的 v2 当作命中 |
| G0 被取消，第二个 chunk 仍在执行 | 撤销业务发布，继续保留设备槽、输入与在途结果区 |
| 最后权重读取结束，结果复制仍在读独立输出区 | 权重槽可在无其他读权后复用；输出区继续受其消费者保护 |
| s 取得 lease=8，开始复制 v2；lease=7 的重复通知到达 | 旧通知不解除 lease=8 的责任，G0 迟到结果也不提交给新请求 |

若要求 v1/v2 同时执行，必须增加另一份可用存储，或等待旧读者结束；版本号不能提供额外物理容量。只有一个槽仍然可以正确推进，只是无法用该槽同时重叠新旧权重。

## 条件化成本：容量、工作量与关键路径分开

对同一候选和计量窗口，分别列出下列成本。

| 成本 | 条件化主项与必要补项 |
|---|---|
| 计算 | SwiGLU 专家中间维 f 时，每 item 的三个矩阵乘主项约 6df FLOPs，合计 6dfΣ_e n_e；router、激活、门控、shared、padding 与 combine 另计 |
| 设备访存 | 每个触及专家至少一次逻辑权重读取是理想复用账；实际 kernel 分块、chunk、cache 与重读决定 HBM 事务，不能用 H2D 字节替代 |
| 通信与迁移 | D_H 从实际复制事件求和，再区分首次必要载入、淘汰后重载、无用预取及所计格式填充；SSD 读取 D_S、激活/KV 迁移、CPU 结果和 EP dispatch/return 分别列账 |
| 准备 | 离线统计、预测器训练、打包与布局转换；在线路由、分桶、索引、动态解包与任务提交。静态准备 C_p 复用 R 次才可摊为 C_p/R，在线工作不能移到一次性账 |
| 同步 | 权重就绪、输入可见、最后读取、结果覆盖与提交；除事件管理本身，还计暴露的缺失等待、慢专家和排空 |
| 驻留 | 常驻权重、载入目的空间、旧版本、输入、KV、结果、中间激活、元数据及工作区在同一时刻的物理并集 |

对三个 d×f 量级矩阵、权重元素 b_w 字节的专家，执行表示大小约为 3df b_w，量化元数据、对齐和额外布局副本另计。忽略其他读写且每权重读取一次时，单专家权重口径算术强度为 6df n_e/(3df b_w)=2n_e/b_w FLOP/byte；BF16 时约为 n_e。更大桶利于重用，却可能扩大专家并集和激活峰值，两者需要同时算。

设备峰值为 max_t bytes(Resident(t)∪Reserved(t)∪Active(t)∪Other(t))，并集按唯一物理存储计。READY 权重若位于预分配槽池内，计完整槽池后不再另加同一权重；池外的常驻专家和旧版本才另加。主机源、普通读取缓冲、锁页池、转换副本也按此口径区分。只申请淘汰而仍有读者的对象，不能从容量中扣除。

若 D_H、D_S 是同一轮实际传输量，T_GPU、T_CPU 是实际计算资源工作量，必要资源下界可写为 max(D_H/β_H,D_S/β_S,T_GPU,T_CPU)，但它不是充分完成时间。因果链上的 SSD→转换→H2D→kernel 以及启动、队列和排空可能暴露；共享链路上的权重、KV 和预取流量先相加，再除该链路有效带宽。不同 stream 不能让同一资源同时为各项提供独立满速。

设全部冷的本轮专家并集为四个，每个 128 MiB，H2D 有效带宽设为 16 GiB/s，至少搬 512 MiB，单计复制下界 31.25 ms。两个 128 MiB 槽占 256 MiB，容量增加不会把这一首次必要载荷减为一半；若只一个槽，仍可串行推进，但缺少同槽复制/读取重叠。另有一次错误预取 128 MiB 时，本轮载荷变为 640 MiB，下界为 39.0625 ms，除非它在明确的其他计量窗口已经完成，不能从账本消失。

CPU 冷专家路径比较传结果而非搬权重：搬权重的串行粗模型为 S_e/β_H+T_GPU,e；CPU 路径为 A_e/β_H+T_CPU,e+T_sync/combine。A_e 由真实输入与返回组织决定，不能混用 EP 的远端 payload。两条路径能否被其他工作覆盖，应接入完整依赖图。[计算放置](heterogeneous-execution.md) 展开其函数与合并条件；小批中 A_e 可能远小于 S_e，但 CPU 主存带宽、线程和冷工作量仍可能使它更慢。

## 激活稀疏、预测与方案反转

[PowerInfer v1](../sources/S-POWERINFER.md) §3–6 采用热点神经元 GPU 驻留、冷神经元 CPU 执行、在线活跃预测和结果合并。这是神经元粒度的异构执行，不是任意 MoE 的专家缓存。其评估涉及 OPT 及特定 ReLU/ReGLU 模型变体，不能把结果直接推广到普通 SwiGLU 的精确零比例。

对两层 ReLU FFN，y=Σ_j max(0,x·u_j)d_j。已证明 max 项为零时，可以精确跳过该项；预测为零却实际为正时，丢失贡献 max(0,x·u_j)d_j，通常改变函数。预测误报只增加工作，漏报可能改变输出，两类错误须分开。要求精确函数时，需要充分的零证明或覆盖所有漏报的补算路径；若允许近似，预测器、输入分布和质量回归属于模型契约。

预测专家预取与预测神经元跳算也不同：错误预取只要不删真实需求，可以保持函数，但会消耗带宽与容量；错误跳算则可能直接删贡献。预测提前量为 a、取权重时间为 t，在无争用且确会使用的设定下，最多隐藏 min(a,t)，仍暴露 max(0,t−a)。预测命中率不能单独给出收益，还需计无用载荷、挤出的命中和准备成本。

| 条件变化 | 保留的关系 | 调整或放弃依据 |
|---|---|---|
| N 增大或进入长 prefill | 路由贡献完整，token 身份不变 | 重算专家并集、n_e、KV 和结果驻留；CPU 冷部分或近全专家读取主导时，减少卸载、改放置或减并发 |
| 热点稳定或漂移 | 缓存只能改变取得路径 | 固定热门驻留与近期更新比较；计入更新迁移和生效滞后，命中下降时撤回旧热点假设 |
| 设备容量减少 | 在途对象不提前释放 | 减少预取和并发，按桶/chunk 排空；最小完整工作单元仍装不下时改 CPU、合法分片或拒绝 |
| 稠密槽数或淘汰策略改变 | 各微批的层依赖不变 | 重放实际访问与槽事件，重算跨微批及跨轮命中；不继续套用 M W_off |
| 链路变慢或 KV 流量增加 | 真正依赖仍需满足 | 按共享资源重算；传输下界已超过 deadline 时，单纯增加槽数不能挽救 |
| 表示、模型版本或分片改变 | 逻辑权重身份必须匹配 | 重新打包、转换并验证；旧缓存不能按 expert ID 直接复用 |
| 所有专家能常驻 | 同一模型函数继续成立 | 将全驻留作为对照，删除人为引入的每轮加载成本，再比较缓存管理是否仍有必要 |
| 预取准确率或提前量下降 | 真需求仍执行 | 限流或取消预测预取；需求加载和 CPU 冷执行成为候选 |
| 激活稀疏性下降 | 非零贡献不能遗漏 | 调整分工与稀疏算子；CPU 或预测成本超过收益时改稠密路径 |

FlexGen v1 的 §5 在计算前恢复 FP16，并因其 CPU 解压开销在启用量化时关闭 CPU delegation。不能把该论文不同配置的量化收益与 CPU 委托收益直接相乘。新组合需重新验证解码、布局、主存竞争和质量。

## 区分实验、反例与检查边界

正确性先固定制品、输入、路由、门控、表示和容差，对照全驻留逐 token 公式，再改变完成顺序、容量和版本交错。性能另使用相同 workload 和质量约束，记录冷启动、准备、每轮唯一需求字节、实际重复加载、无用预取、在途峰值、慢专家、完成吞吐及 ITL 分布。

| 观察与竞争解释 | 区分实验及独立证据 | 反证后的修正 |
|---|---|---|
| 稠密循环交换的节省小于 M 倍：原路径已有跨微批命中，或新路径另有流量 | 固定输入、层顺序、初始槽和表示，分别启用保留、微批边界清空与按层执行；记录每次 hit、evict、copy 和字节 | 保留路径少于 M W_off 时关闭全缺失假设，改用实际复制事件；另查激活/KV 迁移 |
| batch 增大后变慢：并集扩大，或计算/状态变重 | 固定路由只复制相同选中集合，与扩展为不同专家集合分别比较；记录 U、D_H、n_e 和 KV | U/D_H 不增而时间仍升，不能归因于加载更多专家，继续查计算、准备与状态 |
| 命中率高而 ITL 差：命中大多是小专家，或慢缺失挡住提交 | 按专家大小列加载字节，记录最后必需贡献及等待；比较同命中数但不同缺失大小的轨迹 | 命中不代表节省关键路径，策略改用有条件的字节和时间价值 |
| 预取开启后更慢：错误流量、驱逐或转换争用 | 固定真实路由，分别用完美提示、错误提示、关闭预取；记录未消费载荷、重载与准备 | 完美提示也不改善时，检查提前量和资源争用，不能只要求更准预测器 |
| 两槽未加速：无独立计算，或同资源争用 | 固定载荷与计算，改变可覆盖区间；使用设备时间线及真实完成事件 | 已有依赖无法覆盖或 c_i 随重叠变大时，修正理想递推，不继续盲目增槽 |
| 输出随容量或返回次序变化：错归属、漏项或浮点重排 | 用两个 origin 的同名 token、不同门控与非对称权重；对照逐 item 参考，并检查 Expected/Seen | 身份与覆盖失败先修协议；两者正确后才按既定数值契约判断累加误差 |
| 版本切换偶发错误：旧副本命中，或实际提前覆盖 | 让旧 kernel 延迟读取，交错取消与新版本复制；记录 K、lease、所有读者和槽字节 | 版本标签正确仍可能物理污染，补足最后读取门控；仅丢旧结果不足以修复 |
| 激活预测省计算但质量变化：漏报，或表示近似 | 固定权重表示，比较完整计算、真实零掩码和预测掩码，分别注入漏报与误报 | 只有预测掩码失败时修预测或补算；不能把漏项解释为正常卸载差异 |

随章交付的唯一检查为 tools/check_k_alg_019_full.py。它是 Python 标准库、确定性、离线、只读的软件模型：用逐 token 的精确有理数参考对照单槽分桶执行与乱序合并；用路由组合枚举对照并集期望；保留微批优先与层优先的输出等价及错误层序检查；用逐时刻资源模拟对照两槽递推。

稠密流量由有界槽模型的真实载入分支产生 copy 事件，命中只产生 hit 和 read，淘汰明确移除旧身份。独立账本重放事件、校验容量与每次读取身份并累计载荷；FIFO 的独立队列参考核对一般和非等大对象轨迹，小型状态空间枚举核对等大对象的未来访问策略。检查覆盖跨微批保留、边界强制清空、跨轮保留、全可驻留、单槽、空输入和短微批。三层两槽反例要求 4 次、3 次和 6 次复制分别成立；错误地把所有访问计为缺失的变体必须被实际事件账驳回。原先只比较预写序列长度与集合大小的检查由实际单槽读写轨迹取代。

本轮实际在 functions.exec 中执行内存 JavaScript 交叉检查：640 组稠密输出与三种流量路径、3,279 组等大对象缓存轨迹、56 组并集期望、820 组两槽时序，以及 12 组合成专家乱序合并；另触发访问当缺失、错误层序、六类合并错误、六次不安全槽操作及把资源下界当完成时间的负对照。JavaScript 专家算术将门控统一放大四倍，使用整数核对；交付 Python 则使用精确有理数。Python 脚本本轮尚未执行，结果须由协调者对最终脚本单独记录，不能继承历史脚本的通过记录。

这些检查只涉及 CPU 算术和抽象事件。合成专家使用 ReLU 两矩阵函数，只为检验加载身份、数据流与合并，不验证真实 SwiGLU、router、量化解码、浮点误差、GPU kernel、stream/event 可见性、DMA 排空、HBM 事务、服务性能或知识对 Agent 的使用效果。事件载荷也不是 PCIe 协议开销或设备计数器实测。
