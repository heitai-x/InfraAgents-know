# K-SYS-018：推理存储服务：制品、缓存、索引与提交记录

推理存储既包含权重等稳定制品，也包含可重算 KV、检索索引和不可随意丢弃的提交记录。它们要求的持久性、访问粒度、更新方式与故障处理不同。把所有对象放入同一个高速缓存，或者全部按最强持久化处理，都可能付出不必要的代价。

## 先定义对象契约

| 对象 | 主要读取/更新模式 | 丢失后的恢复条件 |
|---|---|---|
| 模型、adapter、tokenizer 与量化制品 | 版本内只读，分片/范围读取，批量分发 | 从可信且完整的相同版本重新取得；缺片不能继续发布 |
| 可复用 KV 或中间状态 | 按前缀/层/块读取，逐步产生或封闭 | 只有保留完整输入、模型身份和恢复语义时才可重算 |
| embedding 与检索索引 | 查询、批量构建、增量更新或整体替换 | 需要原始文档、embedding 版本、索引参数与删除/更新记录 |
| 请求提交、计费或必须保留的事件 | 追加和查询，通常小而频繁 | 能否丢失与重放由协议决定；不能由“模型可重算”推断 |
| 临时 staging、可再生编译缓存 | 短期读写，格式与环境绑定 | 可删除重建，但重建成本和峰值必须进入启动预算 |

可重算只描述恢复路线，不等于恢复免费。缓存丢失后集中重算会争用 CPU/GPU，影响仍正常的请求；索引重建还可能包含长时间的数据扫描。某些递归状态、工具结果和随机过程无法仅凭文本恢复，必须明确保留范围。

## 对象、文件与块的接口选择

对象接口用键与版本定位整体对象或范围，适合不可变分片和分发，但不能假设跨多个对象的原子发布或目录 rename 语义。文件接口提供路径、偏移与文件系统操作，具体原子性、缓存可见性和持久性仍依赖所选实现。块接口提供地址空间与 I/O，文件布局、版本和发布由上层负责。

这些接口不是天然的快慢顺序。大量小元数据请求可能限制启动，大对象顺序读则可能受出口带宽限制。范围读取是否真正减少下游字节、直接 I/O 的对齐与并发条件、mmap 是否产生缺页或双重缓存，都要接回[存储 I/O](../hardware/storage-io.md)与[加载布局](../frameworks/checkpoint-loading.md)。

[Ceph 2006](../sources/S-CEPH06.md) 展示数据与元数据路径分离、计算式放置、跨故障域副本以及可见确认和落盘提交的区别。它是机制来源；当时原型的安全协议和 MDS 恢复尚未完整实现，不能据此承诺当前后端的 API、可靠性或性能。

## 完整版本如何发布与读取

写入者先产生不可变分片，再检查完整集合的大小、表示和必要内容校验，最后发布能引用全部已完成对象的版本清单。读者先取得一个确定的清单版本，再按该版本读取所有分片；不能在每次读取时重新解析可能变化的 latest 指针，从而把新旧权重拼在一起。

发布指针的原子性需要所选存储提供明确操作，或由外部权威记录维护；没有跨对象事务时，不应假装多次上传天然原子。部分写入失败留在未发布集合，重试不会让半成品进入可读版本。回退改动新请求的版本选择，旧读者仍须能够完成；删除旧版本应等待实际读者和保留策略允许。

数据已到客户端内存、已被多个副本接收、可供其他客户端读取、已达到所需持久性，是不同完成点。对请求提交日志尤其要说明何时可以对外承诺成功；对可重算缓存则可以选择较弱持久性并承受 miss，但有效性和租户身份检查不能因此省掉。

## 分发、复制与恢复的共同带宽

设定一个制品 32 GiB，16 个节点同时从共享出口获取，出口有效读带宽为 8 GiB/s。没有本地命中或对等分发时，总出口需要交付 512 GiB，最后全部取得的纯传输下界为 64 s，不能为每节点都使用 4 s 的独占估计。若每机已有一份相同版本的本地缓存，出口流量可减少，但本地读、校验、转换与 H2D 仍在关键路径。

树形或对等分发减少集中出口压力，代价是节点间链路、临时存储和额外失败路径；收到的内容仍须属于同一清单版本。缓存可以合并并发 miss，避免相同分片被重复拉取，但取消一个等待者不能误删其他等待者还需要的共享下载。

容量账要区分逻辑数据与副本。设逻辑制品 100 GiB、三副本，则数据主项已为 300 GiB，尚未包含元数据、旧版本、恢复过程的新副本与临时写入。恢复和重平衡还会消费在线读取所需的磁盘和网络；后端报告“可恢复”不等于恢复期间仍满足原来的启动或 KV 延迟。

## 故障验证与选择反转

测试缺片、截断、错误版本、过期目录、部分范围完成、读过程中版本切换、旧版本清理、共享下载取消、节点失效和恢复流量并发。成功条件是读者只得到完整且相容的对象，失败可以定位到阶段，原有有效副本的责任没有提前消失。

性能分别测元数据操作、冷读/热读、范围读取、并发启动与恢复期尾延迟。权重长期稳定且节点重复启动时，本地缓存更有价值；模型版本频繁变化或节点短命时，共享源与分发效率更关键。对 KV，比较远端恢复、压缩和重算的完整费用；对不可丢的提交状态，则先满足协议的持久性要求，再优化路径。
