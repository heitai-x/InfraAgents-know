K-SYS-011：模型生命周期：加载、就绪、排空与版本切换\n\n模型服务的版本是一组共同定义输入到输出函数的制品和执行约束。权重、配置、tokenizer/processor、adapter、量化参数以及执行布局必须在同一次请求中保持相容。生命周期管理解决的不是单纯启动或停止进程，而是三个问题：何时有资格接收请求；切流后谁继续履行旧请求；何时能够把旧资源交给另一个版本。\n\n文件存在、端口能连接、加载调用返回和路由已经更新，分别只证明一部分工作完成。把这些事件混成一个 ready 标志，会使未完成的执行组接收请求，或让旧请求读取已经被覆盖的权重。\n\n## 版本、实例和就绪范围\n\n区分三个身份。\n\n- 制品身份 v：固定清单所引用的权重、配置、processor、adapter、量化与必要布局依赖。读取清单后固定其版本，不能逐片重新解析 latest。\n- 加载实例 g：一次具体加载及其执行组。相同 v 的重试也创建新 g；旧尝试的完成通知不能使新尝试就绪。\n- 路由代次 e：一次准入配置的身份。即使别名经历 v1→v2→v1，e 仍递增，防止第一次 v1 的过期路由重新有效。\n\n实例内还要保存逻辑 rank 到实际设备、设备资源与地址绑定的映射。容器里的 device 0 不是稳定物理身份；设备重建、MIG 配置或执行组改变后，需要重新验证相应依赖。[部署环境](deployment-environment.md)解释设备暴露与真实资源边界。\n\n将请求 r 的一次合法执行写为\n\n(y,S′)=F_v(x,S;θ_r)，\n\n其中 x 是已经按该版本解释的输入，S 是 KV、递归状态、RNG、grammar 等请求状态，θ_r 是采样与执行选项，y 是本次产生的结果。生命周期输出除了 y，还包括请求的绑定 (r,v,g)、准入票据、状态归属与最后使用责任。processor 参与输入解释，因此不能先用可变别名对应的 tokenizer 编码，再随意绑定另一个版本。可以先固定版本并持有其责任后处理输入，也可以在正式准入时验证输入解释身份一致。\n\n就绪证书可描述为\n\nC_g=(v,g,E_g,P_g,Ω_g,Π_g)，\n\nE_g 是环境和执行依赖身份，P_g 是完整 rank/设备/布局计划，Ω_g 是允许公开的请求范围，Π_g 是制品检查、完成证据和代表路径验证记录。Ω_g 应能判定模型、dtype、输入几何、上下文上限、adapter 路径、图桶或受验证回退路径是否合法。代表输入通过是该路径的证据，不是整个 Ω_g 的数值正确性证明；范围的推广还要依靠形状 guard、容量边界和执行契约。\n\n就绪资格与瞬时可接收容量分开。C_g 仍有效，但 KV 满了，可以暂时拒绝或排队；一个 rank 或设备依赖失效，则撤销相关资格。不能把暂时过载变成反复重启，也不能把历史预热成功当作失效环境仍然有效的证明。\n\n## 从制品到就绪的准备算法\n\n采用 PREPARING、READY、OPEN、DRAINING、RETIRING、RETIRED，以及失败状态 FAILED。READY 的新准入门仍关闭；OPEN 表示可按当前路由取得新准入；DRAINING 允许已有请求继续，却不允许新请求绑定。状态名称可以合并，以下完成条件不能合并。\n\n```pseudocode\n输入：不可变清单 v；不复用的实例身份 g；执行计划 P；公开范围 Ω；资源预算\n输出：未发布的就绪实例 C_g，或带明确阶段与未结责任的失败结果\n\n1. 创建 PREPARING(g)，关闭准入门；初始化 rank 完成集合为空。\n2. 固定清单与全部依赖身份；检查必要分片、长度、完整性、张量关系、\n   processor、adapter 和量化/布局元数据。发现缺片或不相容则转失败。\n3. 按每个设备和主机统计准备期间的唯一存储并集与预留。\n   同时计入仍存活的旧版本、转换区、图池、通信区和预热状态。\n   取得全部必要资源的预留；任一处不足则等待、调整计划或失败。\n4. 对每个 rank，按 P 加载并转换完整张量，建立真实设备与布局映射。\n   每次异步访问在提交前登记使用责任；源与目的地址受保护到最后访问结束。\n5. 建立完整执行组及所需通信上下文；共同核对 v、g、P 和操作协议。\n6. 为实际公开的执行变体建立或核对编译产物、图及工作区。\n   复用 key 包含其真实依赖，不以模型名称单独判断命中。\n7. 在实际执行线程设定模型评估行为和所需推理上下文。\n   运行代表路径、边界与独立参考比较；检查必要 rank 的共同结果。\n   预热的 KV、RNG、输出与测试请求使用隔离状态。\n8. 等待影响执行可读性的加载、转换和初始化完成证据。\n   清理或隔离预热状态；不能把测试请求历史交给正式请求。\n9. 每个 rank 仅为当前 (v,g,P,Ω) 报告完成；重复或旧尝试报告不改变资格。\n   只有全部必要 rank、依赖和验证条件满足，才发布 C_g 并进入 READY。\n10. 任一步失败：关闭准入，记录最早失败与已完成范围，进入 FAILED。\n    停止后续准备，排空已提交访问，解除绑定后释放可回收资源。\n    超时只记录未结责任；重试使用新的 g，不复活这个失败尝试。\n```\n\n第 3 步需要逐设备判断。两个 rank 总需求小于两张卡的总容量，不保证某个 rank 的局部峰值可行。设备插件的 time-slicing 份额也不会创造额外显存或独立故障域；固定 v0.16.1 的共享资源声明只能支持相应访问与限额契约，不能代替这里的容量检查。\n\n第 7 步同时涉及模型行为与运行簿记。[S-TORCH-INFERENCE](../sources/S-TORCH-INFERENCE.md) 的机制说明指出 inference_mode 是线程局部状态，不会自动调用 eval。入口线程进入推理模式，不证明后台执行线程相同；关闭 autograd 也不证明 Dropout、统计 buffer 或其他可变模型状态已经符合服务契约。\n\n编译产物的失效范围由依赖决定。权重作为运行时参数、ABI 和布局保持相容时，数值替换不一定要求重编译；常量折叠、预打包格式或捕获地址改变时，则要重建受影响产物。无论是否复用编译代码，旧图仍引用的地址都不能被原地覆盖。详见[编译与动态形状](../frameworks/compile-dynamic-shapes.md)和[CUDA Graph](../frameworks/cuda-graph-buffers.md)。\n\n## 准入与切流必须有共同排序点\n\n定义权威路由 A=(e,g)，并为实例保存准入门。下面选择一个保守模型：路由变更、门控和请求责任登记在同一串行状态域中排序，设备资源由该域可核对的预留账保证。它说明需要的原子关系，不要求把所有设备工作放进一个锁。\n\n```pseudocode\n准入(r, 请求摘要, 期望路由 e/g, 请求范围 σ)：\n  在权威状态域中：\n    若 r 已有准入记录：\n      同身份与摘要的重试返回已有记录；冲突输入拒绝。\n    核对当前 A=(e,g)，实例为 OPEN，C_g 有效，σ 属于 Ω_g。\n    核对输入解释身份与 v 一致。\n    计算本请求所需的逐设备增量预留 δ，包括已承诺的在途增长上界。\n    若资源不足，按既定策略返回等待或拒绝，不创建半份正式请求。\n    原子取得预留，登记逻辑请求责任 R_g 中的 r，\n      写入不可变绑定 (r,v,g) 与准入票据，再返回接受。\n\n切流(op, 期望代次 e, 目标 h)：\n  在同一权威状态域中：\n    若 op 已有决定，核对参数一致并返回原决定。\n    核对路由代次仍为 e。\n    核对 h 为 READY，或为尚未进入 RETIRING 且重新验证合格的 DRAINING；\n      C_h、分配和环境依赖仍有效。\n    关闭旧目标 g 的新准入门，令其进入 DRAINING。\n    打开 h 的新准入门，令其进入 OPEN。\n    原子写入 A=(e+1,h) 和 op 的已提交决定。\n    保留全部已接受请求的原绑定和预留。\n```\n\n准入先发生，旧请求已经在 R_g 中，即使队列消息在切流后才抵达 worker，仍由 g 履行。切流先发生，拿着旧 e/g 的新准入必须被拒绝或重新解析路由。不能先在路由器读取 g，再在另一处无条件递增引用计数；两步之间可能完成排空和卸载。\n\n缓存路由只用于提出候选，不能自行签发旧版本的新准入。若使用分散式租约代替共同权威域，需要另行给出签发、撤销、租约存活与排空之间的证明；单纯等待一个估计的缓存传播时间不足以完成这个证明。多控制节点也不能各自根据本地超时开放实例。\n\n跨节点预留若需多步完成，先取得临时预留，全部成功并重新核对路由后才安装正式准入。未提交预留失败时撤销；已经发出的设备访问继续承担排空责任。上述原子步骤不能直接推断任意远程 allocator 天然具有跨节点事务。\n\n切流确认丢失时，控制者查询 op 的权威决定；相同 op 的重试返回原结果。结果未知时保留原资源责任，不能根据本地超时反向切流。回退是另一项有新 op 和新 e 的切流：它改变后续准入，不能撤回已经交付的回答，也不能重新绑定 v2 的活跃请求。\n\n若旧实例仍完整驻留、尚未 RETIRING 且资格重新验证有效，可以重新开放它。已经开始拆除图、通信组或权重的实例必须重新准备，不能仅把状态标签改成 OPEN。别名回到同一个 g，也不使早期 e 的票据重新有效。\n\n## 排空、取消与卸载算法\n\n对实例 g 分开记录四类责任：R_g 是仍可继续执行的逻辑请求；U_g 是已经登记的 kernel、复制、传输等实际访问票据；B_g 是图、注册区和执行对象的地址绑定；O_g 是仍借用实例资源的输出消费者。每张票据含实例身份、用途和不复用的操作身份。请求数为零不等于后三者为空。\n\n```pseudocode\n已有请求继续执行：\n  核对正式准入票据与不可变 (r,v,g)，不重新读取当前别名。\n  核对请求仍有效，实例没有进入 FAILED、RETIRING 或 RETIRED。\n  在提交任何异步访问前，为其全部实际资源登记 U 票据。\n  对必要 rank 提交相容计划；发生部分提交失败时停止受影响尝试，\n    按执行组恢复契约处理，排空已经发出的操作。\n  输出若借用资源，先登记 O 再交给消费者，不能留下无人保护的交接窗口。\n\n请求结束或取消：\n  关闭该请求的新业务提交与新执行入口；按协议确定其终态。\n  解除 R 与可解除的逻辑预留。\n  保留已有 U、B、O；取消通知和终态标签不充当物理完成证据。\n\n开始拆除实例：\n  核对新准入门关闭，实例不再是有效路由目标，R 为空。\n  原子进入 RETIRING；从此拒绝新请求、重新开放和新的地址绑定。\n  停止准备及后台产生新工作的入口。\n  在相关重放结束后拆除图、注册与通信绑定，逐项结束 B。\n  持续处理真实完成证据，逐项结束 U 和 O。\n  完成通知必须匹配 (g,操作身份,受保护范围)；旧代或重复通知不修改新责任。\n  U、B、O 全部结束后，销毁执行对象并归还资源，进入 RETIRED。\n\n排空期限到达：\n  对仍活跃请求执行预先声明的终止、恢复或合法迁移策略。\n  不伪造成功完成，也不把期限到达当作设备停止。\n  无法证明结束的资源保持隔离，列出具体责任及解除条件。\n```\n\n这里选择整实例保守拆除。实际可以在对象级分别回收：若输出已经复制到独立主存且不再借用权重或设备缓冲，它不必延长这些对象的生命期；但复制完成与消费者交接必须有明确证据。反过来，主机响应线程结束也不证明设备 DMA 已经完成。\n\n逻辑请求在 DRAINING 中仍可执行，因而不能仅因准入门关闭便拒绝所有旧迭代。取消则关闭该请求未来工作，但不能让某个 rank 单独跳过其他 rank 已经参与的 collective。执行组错误与单请求业务终态必须分别处理，见[推理服务恢复](serving-recovery.md)及[取消与完成](cancellation-resource-completion.md)。\n\n本状态机的安全条件是：全部访问提交入口受责任登记约束，完成证据真实覆盖最后使用，控制决定有共同排序，接收端核对准入与执行身份。它不自行实现分布式共识、持久日志或设备中止。控制记录丢失、worker 崩溃或故障域不明确时，需要相应恢复协议；本地引用计数不能独立证明远端访问已经结束。\n\n## 三种切换路线及状态相容边界\n\n停止旧服务、排空后加载新版本，峰值较低，但存在服务空窗。新旧并存后切流，可以在准备新版本时继续服务旧请求，代价是双版本及准备过程的容量和资源争用。滚动更换多个副本，把容量峰值和容量下降分到多步，却要求每一步的剩余合格容量都足够。以上是带前提的策略选择，不是三种不同正确性要求。\n\n一次请求始终绑定原 v。adapter 更新也以新不可变对象发布；不能在旧地址原地覆写 A/B、scale 或描述符。相同 adapter 名称、相同 shape 和相同物理地址都不证明内容身份相同。KV 的相容身份要覆盖影响该状态的依赖闭包，默认把模型与 adapter 版本纳入其中，见[多 LoRA 服务](../algorithms/lora-serving.md)。\n\n会话下一轮使用新版本是协议选择。可以保留原版本并支付驻留，也可以用新 processor 重新解释可重放输入、重新计算状态；不能默认把旧 KV 接到新权重后继续。若声称某类状态可跨版本保留，需要证明该状态的全部生成依赖与后继消费契约相容，而不是只比较张量尺寸。\n\n迁移地点与切换模型版本也不同。ServerlessLLM §5 利用相同只读模型下的 token 重算来重建 KV，并让目标先处理前缀、最后处理源端新增 token。这支持特定 Transformer 状态恢复路线，不证明任意模型状态只靠 token 即可恢复。通用迁移仍需冻结共同恢复边界、保存 RNG/grammar/递归与输出状态，并只移交一份提交权。\n\n设已知 token 为 x[0,n)，已有完整模型状态到 p，p≤n。已采样或已交付 token 不一定已有自己的 KV。重建应明确恢复到 p，还是合法推进到另一个边界，避免重复采样或遗漏末行 logits。目标 READY 只说明具备接管条件，不等于已取得业务提交权。完整迁移与确认丢失处理沿用[取消与完成](cancellation-resource-completion.md)中的授权协议，本章的路由切流不替代它。\n\n## 启动、驻留和有效容量的条件化成本\n\n启动时间取决于资源等待、取得制品、加载转换、执行组建立、编译与预热、路由生效之间的依赖。对任务图中事件 j，若前驱集合为 pred(j)，独立资源且没有额外争用时有\n\nF_j=max_{i∈pred(j)}F_i+t_j。\n\nF_j、t_j 的单位为秒；无前驱时以前置可开始时刻为边界。共享 SSD、NIC、CPU 或主存的任务还要加入资源顺序或有效能力约束。不能同时给每个任务独占带宽并声称它们完全重叠。\n\n若各 rank 独立完成本地流水，资源排队 q_r 发生在其前，L_r 已包含本地加载、检查、编译与预热，则\n\nT_ready=max_r(q_r+L_r)+T_group。\n\nT_group 只计真正位于这些工作之后的共同验证或屏障；已包含在 L_r 中的事件不能再加。两个 rank 的本地工作均需 4 s，排队分别为 0、1 s，之后共同验证为 0.5 s，则准备完成为 5.5 s。路由安装及必要传播另计；过期路由被安全拒绝期间，实际可接收吞吐仍可能下降。\n\nServerlessLLM §6.2 用 q+n/b 估计特定加载路径，其中 n 为模型分片字节，b 为所用流水中的慢层带宽。该系统以每服务器顺序加载减轻争用。这个估计不能直接覆盖任意并发、编译、预热和分布式准备图，也不能把热缓存下的 b 外推为冷启动带宽。\n\n六类费用应在同一次切换范围中核对。\n\n|
