# K-FW-004：编译与动态形状：Guard、分桶和变体成本

编译把一组可证明成立的执行假设变成专门程序；动态服务需要管理这些假设覆盖的形状与状态空间。

## 特化得到什么

编译器可以融合算子、消除中间张量、选择 tile 和简化控制流，这些改进依赖 shape、stride、dtype、常量或其他 guard。guard 失效可能触发重编译或回退。动态 shape 支持让部分维度符号化，但数据相关控制流、固定 workspace 和特定 kernel 仍可能要求静态边界。

batch size 相同但 stride 不同、长度分布不同或不同 LoRA rank，都可能走不同变体。只记录一个“batch=8”不足以解释编译缓存。形状签名应描述实际引发特化的条件。

## 分桶的优化目标

将长度 n 映射到桶 b≥n，以 padding 换稳定形状。线性工作浪费近似随 b−n，密集 attention 的浪费则与 b²−n² 有关。bucket 越密，运行浪费越小，但编译时间、可执行程序数量、图和 workspace 驻留越多。

可把总成本写为请求分布下的期望执行成本＋摊销编译成本＋驻留资源代价。某个很少出现的长度值得直接 eager，未必值得专门编译。batch、context、query 数、模态网格是联合维度，对每轴独立细分可能产生组合爆炸。

## 一个分桶推导

假设输入多集中在 100–128 和 900–1024，少量到 2048。只用 2048 桶给短输入造成巨大无效工作；按 128、1024、2048 三桶可能大幅减少它。是否增加 256/512 桶取决于真实分布质量，而非照搬二次幂。前缀命中后待算 query 长度还可能与总历史长完全不同，需要分别考虑。

## 与 CUDA Graph 的关系

编译程序处理算子计算，CUDA Graph 处理一段设备命令的重放。动态编译并不自动使图能改变全部地址和拓扑；固定图也可以调用未编译的 kernel。两者组合时，应先明确编译变体和图桶各自的 key，再说明持久缓冲与有效长度如何输入。

冷启动包括模型加载、编译、autotune、图捕获和内存池建立。稳定态测量可以排除这些成本，部署可用性和首次请求目标则必须包含。重新编译频繁会把所谓稳定服务变成持续冷路径，需从 guard 失效原因推导应符号化还是分桶。

## 从模型函数到 IR、lowering 和执行计划

图获取把某次或一组合法执行的算子与依赖变成中间表示。它必须保留张量 shape、stride、dtype、常量、别名与副作用：写 KV、更新随机状态、通信和事件不能仅当作可任意重排的纯函数。数据相关控制流可能留在宿主、分图或通过受支持表示进入编译；图获取成功不证明所有路径均被覆盖。

图级 IR 描述算子之间的数据流，适合常量折叠、代数改写、融合分组和全局布局传播；算子/循环级 IR 描述每个输出元素的索引、归约域和存储位置，适合 tile、向量化、线程绑定及片上数据复用。Lowering 再把这些计划映射成库调用、目标指令与实际内存操作。TVM 固定论文将计算定义、schedule 和硬件 intrinsic 分开，正是为了让同一函数能有多种合法实现。

编译器可以生成同步与缓冲复用，但其证明范围只覆盖所见依赖。服务执行器仍负责选择变体、提供合法输入、保持在途对象寿命，并协调编译区域外的拷贝、调度和状态提交。将异步 copy 放到另一个 stream，却未将事件关系传入执行计划，不会因模型已经编译而变安全。

## 融合与布局传播需要完整消费者关系

以 Y=activation(XW+b) 为例，GEMM 的 epilogue 可在输出尚在寄存器时完成 bias 与激活，避免中间写读。若未激活的 XW 同时有另一消费者，则要保留该值、复制它或改变融合边界。若归约次序、dtype 或饱和点变化，需验证数值契约；不能只由最终张量 shape 相同判断合法。

把权重预打包成某个内核布局，可在模型加载阶段摊销；运行时激活转换通常按请求付费。一个较快算子若要求额外两次布局转换，可能令整段更慢。图级选择应比较整条 producer→consumer 链，包括 residual 分支、外部库边界、别名和最终输出布局。静态内存复用也必须依据最后消费者，异步执行时不能只按宿主调用返回顺序判定结束。

动态尺寸与动态 rank 需要区别。固定 PyTorch 2026-04-30 文档说明动态 shape 以符号维度描述变化，不支持一般的输入 rank 变化；shape 条件分支仍可产生特化。0/1 等特殊尺寸、stride、数据相关输出数量和自定义 kernel 的 constexpr 也可能影响覆盖范围。标记一个维度动态不会自动解除每个 backend 的静态容量要求。

## 编译缓存与在线变体的实际身份

可执行产物应绑定其真实依赖：算子语义和图、目标架构、编译器/库版本、优化及数值选项、shape/stride/dtype guard 和已折叠常量。若权重只是运行时参数且 ABI/布局不变，不必把每个数值变化都当作重新编译理由；若权重已折叠、预打包格式改变或图捕获保存了地址，则要重建对应产物。缓存失效范围应由依赖决定。

编译、autotune、权重打包和 CUDA Graph 捕获产生不同对象，复用 key 及释放条件也不同。清除编译缓存不代表已实例化 graph 不再引用旧缓冲；更换图桶也不保证旧编译 module 可以立即卸载。新模型版本准备与旧请求 drain 期间，要把两套常量、可执行产物与工作区的并存峰值计入。

一个摊销设定：编译与调优共耗 3 s，每次合法调用节省 0.05 ms，至少需 60,000 次调用才能仅从总计算时间回本；这还未计额外驻留和首请求等待。少见形状可以采用受验证的通用路径，高频形状值得特化。若初始小样本未覆盖长尾，在线不断生成新变体会同时消耗主机与设备资源，应根据实际变体分布重新设计符号范围和桶，而非无限扩大缓存。

## 搜索、回退与验证共同约束编译优化

Ansor 固定论文通过结构草图、细节参数和硬件测量搜索完整张量程序，并把调优预算偏向影响端到端成本的子图。这给 InfraAgents 的设计探索提供一个具体启示：成本模型用于选下一批实验，不能代替合法性与目标硬件测量；局部子图最快也不自动意味着服务尾延迟最佳。

验证至少覆盖 guard 边界内外、非连续输入、别名、特殊尺寸、不同 batch 组成、首次与重复调用，以及更新模型后的缓存命中。保存参考函数并比较分段边界，遇到差异可定位到哪次改写/精度选择。回退路径必须执行相同任务语义，并记录发生条件和占比；静默改变 mask、截断输出或绕开质量约束不属于合法回退。

最终测量包含运行时转换、计划生成、冷编译和长时间变体增长。固定形状、大量复用且融合节省中间流量时，专门编译更有利；高度动态、外部状态多、成熟库已接近瓶颈上限或部署寿命短时，部分编译或直接库调用可能更合适。
