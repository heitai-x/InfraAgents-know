# K-FW-010：NKI：Partition 轴、片上生存期与 Attention 数据流

NKI 的 tile 是带硬件轴语义的片上对象。布局、dtype、存储位置与生存期共同决定 DMA、矩阵和归约引擎能否正确供给和消费；总字节装得下只是其中一个条件。

## 问题、轴语义与状态

固定 Trainium2 文档给出 NeuronCore-v3 每核 SBUF 28 MiB，即 128 个 partition、每 partition 224 KiB；PSUM 为 2 MiB。HBM 与 SBUF 之间主要由 DMA 搬运，PSUM 与 SBUF 之间由计算引擎的 ISA 指令搬运。TensorE 承担矩阵乘与矩阵转置，VectorE 处理逐元素与归约，ScalarE 处理逐元素、非线性等操作，GpSimdE 承担一般程序。一个 tile 因此还要说明谁读写它、以哪个轴供数、输出落在哪一层。

对一个 head 的无 dropout 推理前向，令 Q[L,d]、K[S,d]、V[S,dv]，缩放为 a，位置或加性偏置为 bᵢⱼ，可见集合为 Aᵢ。定义 zᵢⱼ=a qᵢ·kⱼ+bᵢⱼ，pᵢⱼ=exp(zᵢⱼ)/Σ_{k∈Aᵢ}exp(zᵢₖ)，oᵢ=Σ_{j∈Aᵢ}pᵢⱼvⱼ。要求可见分数和参与计算的 V 有限；NaN、正无穷或运算溢出需要拒绝或另定特殊值路径。用负无穷表示 mask 时，应先将它解释为不可见关系。

对已处理的非空可见集合 T，保存 m=max zⱼ、ℓ=Σ exp(zⱼ−m)、U=Σ exp(zⱼ−m)vⱼ；空集合使用 E=(−∞,0,零向量)。m、ℓ、U 是跨 tile 的数学状态；地址、就绪事件、读者集合和槽位代次是执行状态。数学结果正确不能证明异步输入已经可读。

HBM 中按行连续的 [R,C] 张量，C 为最内层连续维时，普通 HBM→SBUF DMA copy 将这一维映射到 free 轴，将行维映射到 partition 轴。TensorE 要求收缩维进入 partition 轴时，只改逻辑 view 或 stride 不一定满足物理布局。QKᵀ 中的 K 若在 HBM 按 [S,d] 保存，需要形成 [d,S] 一类片上布局；文档所述 HBM→SBUF DMA transpose 正是让源最内层维成为目标 partition 维。

对普通 BF16/FP16 矩阵 tile A[M,K]B[K,N]，一个收缩块可写成 A_s[p,m]=A[m,p]、B_m[p,n]=B[p,n]，p∈[0,P_rt)、P_rt≤128，输出 C[m,n]=Σ_p A_s[p,m]B_m[p,n]。M/N 对应输出行列，p 对应本次指令处理的收缩位置；更长的 K 需要多块累加。这是逻辑坐标到指令输入的契约，不把某种循环顺序规定为所有 NKI 程序的唯一选择。

Double-FP8 将最大收缩维从 128 扩到 256，物理 partition 数仍为 128。文档给出的最大 stationary tile 为 [128,2,128]，moving tile 为 [128,2,512]，输出为 [128,512]。收缩维拆为 partition 轴和最外层 free 轴 2：A_s[p,q,m]=A[m,p+P_rt q]，B_m[p,q,n]=B[p+P_rt q,n]，C[m,n]=Σ_pΣ_q A_s[p,q,m]B_m[p,q,n]，其中 q∈{0,1}。同一处理单元接收相隔 P_rt 的两对元素，执行两次乘法并累加；q 不是独立 batch 维。奇数收缩长度需要显式补零。

映射 k=p+P_rt q 覆盖 0…2P_rt−1，且为双射。若 A、B 同时改用另一双射 k=2p+q，只是改变收缩项的排列，实数域稠密点积不变，浮点结果可能因求和次序而不同。它可以违反指定的地址布局，却不能作为必然产生数值误差的负对照。A、B 使用不同配对、漏掉 q=1 或重复某些项，才会改变求和内容。

一个片上对象至少绑定缓冲位置和轴布局、dtype 和累加精度、逻辑块身份、槽位代次及完成状态。异步搬运已提交、字节已到达、消费者已获得可见性、最后读者已结束，是不同事件。忽略最后读者会让新块覆盖仍被 PV 读取的旧 V；忽略事件代次则会让旧完成通知错误释放新块。

## 合法条件与选择边界

分块必须让每行的可见 key 子集互不重叠、并集恰好等于 Aᵢ。偏置、位置、缩放和 GQA 的 query-head 到 KV-head 映射不能因 tile 变化而改变。这里规定空行输出零向量、empty 为真、可选自然对数 LSE 为 −∞；这是一种接口选择，不代表所有后端采用相同契约。d、dv、Bq、Bk 为正整数。L=0 返回空输出，S=0 时所有 query 行为空，不创建不存在的加载等待。尾块只处理真实行列，padding 不进入 softmax 分母或输出。

NKI/TensorE 的轴条件来自指令。普通 BF16/FP16 单指令收缩块不超过 128，更大 K 拆块并保留输出累加。Double-FP8 支持 FP8_E4、FP8_E5 及文档允许的混合输入，使用 FP32 累加；partition 收缩块不超过 128，最外层 free 维必须为 2，最大 M、N 分别为 128、512。较小 tile 可以作为候选，但第二维为 2 不是可自由关闭的性能参数。该模式不能与 column tiling、sparse matmul 或 TensorE transpose mode 组合。FP8_E3 的矩阵性能与 BF16/FP16 相同，不能按 Double-FP8 计吞吐；固定资料中被 TODO 注释的稀疏 API 也不构成已交付接口依据。

DMA transpose 支持 HBM→SBUF 与 SBUF→SBUF，文档明确覆盖 2 字节和 4 字节数据的 bit-accurate 转置。输出 partition 维为 128 的倍数、最内层 free 维为 16 的倍数，是最佳吞吐利用条件，并非任意可用形状都必须满足的功能条件。文档给出 HBM2SBUF transpose 最高约 90% DMA 利用率、SBUF2SBUF 最高约 50%、普通 copy 最高约 100%；这些是固定资料的性能说明，本章没有测量这些数字。1 字节 FP8 不能沿用 2/4 字节证明，Double-FP8 又不能同时开启 TensorE transpose mode；需要转换布局时，必须另行证明预布局、独立转换阶段或其他路径合法。

TensorE 显式 transpose mode 能正确转置含 NaN/Inf 的数据。普通矩阵乘以单位矩阵仍执行乘加，NaN/Inf 会沿累加链传播，不能替代这一语义。显式模式可为 FP16/BF16 输入产生 16 位 PSUM 输出；FP8 输入产生 16 位元素，高 8 位补零。其资源路径包括 TensorE、PSUM，以及结果被其他引擎消费前的 PSUM→SBUF 转移。DMA transpose 可直接读写 SBUF，但竞争 DMA 和相关存储端口；选择取决于哪条资源路径拥塞。

硬件 DGE 按需生成 DMA 描述符，避免静态描述符占 HBM，也不占用 GpSimd 的软件生成工作。文档说明从 ScalarE 触发时，DGE 与 ScalarE 计算流水独立，前序独立计算可能隐藏其执行；每条约 600 ns 是该固定文档的说明，不能当作所有形状的实测延迟。该版本硬件 DGE 不支持 indirect gather/scatter，分页或间接访问需要另找合法路径。

SBUF/PSUM 总容量只是必要条件。partition 分布、PSUM bank、单指令 tile 上限、转换临时量和同时活跃对象都可能先成为限制。VectorE 与 GpSimdE 可并行访问 SBUF，但部分性能模式共享总线；VectorE 与 ScalarE 同时访问 PSUM 的全带宽条件包括不冲突于同一个 bank。不能从引擎可并行或总量可容纳，直接推出所有阶段均能全速重叠。

## 完整数据流与伪代码

### 一个 Double-FP8 矩阵 tile

以下只表达坐标契约和完成顺序，不代替 NKI API 或编译器的分配、同步与指令选择。

```pseudocode
输入：A[M,Kraw]、B[Kraw,N]，输入格式满足 Double-FP8 条件
      1≤M≤128，1≤N≤512，1≤P_rt≤128，Kraw≤2P_rt
输出：C[M,N]，FP32 PSUM 累加
前提：未组合 column tiling、sparse matmul 或 TensorE transpose mode

对 p=0..P_rt−1、q=0..1：
    k = p + P_rt q
    对 m=0..M−1：A_s[p,q,m] = A[m,k] 若 k<Kraw，否则为 0
    对 n=0..N−1：B_m[p,q,n] = B[k,n] 若 k<Kraw，否则为 0
等待输入布局与补零全部完成并可读
C = 0，位于 PSUM
LOAD_STATIONARY(A_s)
对 n=0..N−1 沿 free 轴推进：
    对 p=0..P_rt−1、q=0..1、m=0..M−1：
        C[m,n] += A_s[p,q,m] · B_m[p,q,n]
等待矩阵累加完成
若后续消费者需要 SBUF：完成 PSUM→SBUF 转移及所需类型转换后再发布
返回 C
```

普通 BF16/FP16 对应没有 q 轴的输入关系。Double-FP8 的两个 q 贡献合入同一输出，不能把它们当作两个独立输出矩阵。补零只增加无效工作，不应改变有效输出；真实 FP8 编码、舍入与模型质量还需另外验证。

### Attention tile 与槽位交接

采用 query tile 在外、K/V tile 在内的组织，可让本 query 块的 Q 和在线统计量跨全部 KV 块驻留。合并两个不重叠集合时，令 m新=max(m₁,m₂)，r₁=exp(m₁−m新)、r₂=exp(m₂−m新)，则 ℓ新=r₁ℓ₁+r₂ℓ₂，U新=r₁U₁+r₂U₂。这来自逐项恒等式 exp(z−m新)=exp(m旧−m新)exp(z−m旧)。必须先处理空状态，避免 −∞−(−∞)。实数域合并可结合，浮点实现仍有归约顺序和舍入差异。

槽位的完整事件身份为 t=(e,s,g,j)：e 唯一标识本次调用及 query 块，s 是物理槽，g 是该上下文内的代次，j 是逻辑 KV 块。若物理槽跨上下文复用，可以使用始终递增的代次；若按 query 块重新编号，则事件必须同时携带 e，禁止让旧上下文与新上下文具有相同完整身份。代次不能在旧通知仍可能到达时绕回。

```pseudocode
输入：Q[L,d]、K[S,d]、V[S,dv]，缩放 a、偏置 b、可见谓词 vis
      正整数 Bq、Bk，D≥1 个成对 K/V 槽
输出：O[L,dv]、empty[L]，以及请求的自然 LSE[L]

函数 合并(X1=(m1,ℓ1,U1), X2=(m2,ℓ2,U2))：
    若 ℓ1=0 且 ℓ2=0：返回 E
    若 ℓ1=0：返回 X2 的副本
    若 ℓ2=0：返回 X1 的副本
    m新=max(m1,m2)
    r1=exp(m1−m新)；r2=exp(m2−m新)
    返回 (m新,r1ℓ1+r2ℓ2,r1U1+r2U2)

函数 提交(e,s,g,j)：
    确认槽 s 上一代所有写者及最后读者已结束，状态为空闲
    建立身份 t=(e,s,g,j)，状态改为加载中
    本代 pending={QK最后读者,PV最后读者}
    搬入本块 K/V，完成所需布局和尾部零填
    将全部写入纳入本代完成契约
    发布事件必须匹配当前完整身份；全部写入完成并建立可见性后改为可读
    返回不可变票据 t

函数 读者完成(t,reader)：
    原子地校验 t 等于该物理槽当前完整身份
    若不匹配：拒绝事件，槽身份、pending 与状态全部保持原值
    确认 reader 属于本代登记的读者
    若该 reader 已完成：幂等处理，不重复扣减
    否则确认本代可读，从 pending 删除该 reader
    只有 pending 为空时，状态才改为空闲

对 q0=0,Bq,2Bq,… 且 q0<L：
    建立本 query 块唯一上下文 e，建立 D 个空闲槽
    R=[q0,min(q0+Bq,L))
    只加载真实 Q 行，完成布局转换并发布 Q 可读
    对每个 r∈R：X[r]=E
    Tc=ceil(S/Bk)
    对 j=0..min(D,Tc)−1：提交(e,j mod D,0,j)
    对 j=0..Tc−1：
        s=j mod D；g=floor(j/D)；t=(e,s,g,j)
        等待身份 t 的全部 K/V 写入和布局转换完成，并获得可见性
        对每个 r∈R：
            C={k∈[jBk,min((j+1)Bk,S))：vis(r,k)}
            local=E
            若 C 非空：
                z[k]=a·dot(Q[r],K[k])+b[r,k]
                mb=max(z[k]，k∈C)
                w[k]=exp(z[k]−mb)
                lb=Σ(k∈C)w[k]
                Ub=Σ(k∈C)w[k]·V[k]
                local=(mb,lb,Ub)
            X[r]=合并(X[r],local)
        等待本块所有 QK 最后读取结束，交付 读者完成(t,QK最后读者)
        等待本块所有 PV 最后读取及必要累加结束，交付 读者完成(t,PV最后读者)
        若 j+D<Tc：等待槽 s 空闲，再提交(e,s,g+1,j+D)
    对每个 r∈R：
        若 X[r].ℓ=0：O[r]=零向量；empty[r]=真；LSE[r]=−∞
        否则：O[r]=X[r].U/X[r].ℓ；empty[r]=假；LSE[r]=X[r].m+log(X[r].ℓ)
        写回输出和请求的统计量
    排空本上下文已提交的写者和消费者，再结束其缓冲生存期
```

QK/PV 在这里各代表一个聚合后的最后读者事件。若分别登记多个 query 行组或矩阵指令，则 pending 要保存它们的唯一读者身份集合，等待全部结束；不能用任意一个消费者的完成代替整个集合。身份校验和状态更新必须作为不可被复用操作穿插的步骤；CPU 顺序事件模型只描述这一要求，不证明设备上的原子性或内存可见性。

以 D=2、Tc=3 展开一次复用：启动时槽 0 装块 0、槽 1 装块 1，代次均为 0。块 0 的 QK 完成后，槽 0 仍有 PV 读者，此时预取块 2 必须失败或等待。PV 完成后槽 0 才释放，随后建立块 2、代次 1，重新登记 QK/PV。此时即使块 0 的两个完成通知再次到达，它们也必须在修改任何字段前因身份不匹配被拒绝。计算按顺序消费块 1，再消费块 2；块 2 的真实 QK 完成只移除本代 QK，真实 PV 完成才释放槽 0。相同代次但逻辑块错误的通知也必须被拒绝。

若释放函数只接收两个完成布尔值，旧块的两个通知就能把新代槽置为空闲；只在下一次预取时检查 expected generation 无法修复这个错误，因为新代已被错误释放。区分实验必须实际投递旧代完成通知，而非只构造一个错误的预取参数。

处理完前 j 个 KV 块后，X[r] 恰好代表这些块中该行可见集合的统计量，这是逐步正确性不变量。空块的 local 必须完整初始化为 E，合并后 m、ℓ、U 全部不变。Tc=0 时不提交或等待槽；D≥Tc 时额外槽不产生工作，但静态分配仍可能付容量。

| 对象 | 可消费条件 | 最后读者与覆盖条件 |
|---|---|---|
| Q tile | 加载及布局转换完成并发布 | 本 query 块全部 QK 结束后才能覆盖 |
| K_j | 本代加载、转换、零填完成并发布 | 所有相关 QK 结束；成对槽还需等待 PV |
| V_j | 本代加载与排列完成并发布 | 所有相关 PV 结束后才能覆盖 |
| 分数/权重 tile | QK 完成，归约和 PV 所需布局已建立 | softmax 与 PV 最后读取结束后才能复用 |
| U | 上一项 PV 累加完成 | 然后才能重标度、归一化或交给下一写者 |
| 槽身份与 pending | 完整身份匹配的本代事件 | 全部本代最后读者结束后才可进入下一代 |

### 矩阵、归约与存储路径的连接

对 BF16/FP16 的 QK 子问题，可取 stationary Q_s[p,r]=Q[r,p]、moving K_m[p,k]=K[k,p]。HBM 中 Q/K 的连续 head 维需要进入 partition；加载转换后，TensorE 将多个 d 收缩块累加到分数 PSUM[r,k]。分数完成后，通过计算引擎指令转移到归约引擎可读的 SBUF 布局，沿真实 key 范围计算偏置、mask、行最大值和指数。PSUM→SBUF 不是 DMA copy。

PV 的收缩维变为 key。对一段 key，输入应满足 P_s[k,r]=P[r,k]、V_m[k,c]=V[k,c]，输出为 [r,c]。因此前一阶段按行归约的权重布局与 PV 的收缩布局可能需要转换。Bk 大于单指令收缩上限时，进一步拆 key 段并累加同一输出；不能把 Bk=512 的逻辑块误写成普通 BF16 单指令收缩 512。概率转成目标矩阵路径接受的 dtype 时，其舍入、转换和临时容量必须计入；数学上的精确 attention 不保证低精度执行逐位相同。

局部 Ub 伪代码便于表达合并，也可以采用省去独立 Ub 的融合组织：本块非空时先求 m新，将旧 U 乘 exp(m旧−m新)，将权重改为 P[k]=exp(z[k]−m新)，然后直接执行 U+=PV；ℓ 同尺度更新。旧状态为空时旧贡献取零，本块为空时直接保留旧状态。若 PV 异步执行，下一次重标度必须等它完成。U 放在 PSUM 或 SBUF 会改变重标度、转换和 bank 访问路径，不能只在容量公式中删去一个输出 tile。

## 成本：工作、交通、驻留与准备

矩阵主工作为 2MKN FLOPs，乘与加各计一次。Double-FP8 在 M、N 不变时把收缩从 128 扩到 256，逻辑工作翻倍。稠密 attention 主矩阵工作为 2LSd+2LSdv，此外还有偏置、mask、exp、行归约和旧状态重标度。令 H=ceil(S/Bk)，单个 query tile 每块的旧 U 缩放涉及至多 Bq·dv 个元素；遍历全部 query 块和 KV 块约为 H·L·dv 量级，首块和空块可减少这些操作。

HBM 逻辑交通取决于循环顺序。query tile 在外且无 spill 时，Q/K/V/O 主项为 D_Q=Ld·s_Q+GSd·s_K+GSdv·s_V+Ldv·s_O，G=ceil(L/Bq)，s 表示相应元素字节。这包括读取和输出写入，忽略 cache、对齐、事务放大和 padding；不是总 IO。显式偏置、mask、页表、量化尺度和输出统计要另列。K/V 在外可以只装入一遍 K/V，却要按 H 轮访问 Q、输出及统计量；具体收益取决于这些对象的相对大小及驻留条件。

矩阵 tile 的活跃主项为 MKs_A、KNs_B、MN·a，其中 a 为累加元素字节；输入双缓冲使前两项加倍。对齐、描述符、转换临时区、输出与 epilogue 另计。

对 attention，采用分数/P 共享一份存储、直接融合累加到 U、没有独立 Ub 的组织时：C_active≈Bq·d·s_Q+D·Bk·d·s_K+D·Bk·dv·s_V+Bq·Bk·s_P+Bq·dv·s_U+Bq·(s_m+s_ℓ)。若逐字实现局部 Ub 与旧 U 同时存活的伪代码，再加 Bq·dv·s_Ub。若布局转换同时保留源和目标，或者下一块分数提前生成，还需增加对应活跃对象。总逻辑字节跨 SBUF、PSUM 等位置分布，不能直接除某一层容量推算驻留数。

设 BF16 矩阵 M=128、K=128、N=512，FP32 累加：A 为 32 KiB，B 为 128 KiB，输入双缓冲为 320 KiB，PSUM 输出为 256 KiB。平均到 128 个 partition，双缓冲输入为 2.5 KiB/partition，输出为 2 KiB/partition；平均值不是实际 partition/bank 分配证明。相同 M、N 的 Double-FP8 取 K=256、输入一字节，输入容量仍分别为 32 KiB、128 KiB，PSUM 仍为 256 KiB，但逻辑 FLOPs 翻倍。文档称这两种指令序列耗时相同；完整内核还要加布局、padding、归约、同步和输出转换，不能直接据此宣布两倍内核加速。

若完整 K=1024，普通 BF16 分为 8 个收缩块，共 134,217,728 FLOPs；逻辑输入 A 为 256 KiB、B 为 1 MiB，BF16 输出为 128 KiB。同一 PSUM 输出保持到 8 块结束，可避免中间和反复写回 HBM；发生提前 evict 时应重新计额外读写。

两个 attention 容量设定均采用 Q/K/V 两字节、分数/P、U、m/ℓ 四字节，并省去独立 Ub；KiB=1024 B：

| 候选 | Q | K | V | 分数/P | U | m/ℓ | 单槽合计 | K/V 双缓冲合计 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Bq=128、Bk=512、d=dv=128 | 32 KiB | 128 KiB | 128 KiB | 256 KiB | 64 KiB | 1 KiB | 623,616 B＝609 KiB | 885,760 B＝865 KiB |
| Bq=Bk=64、d=dv=64 | 8 KiB | 8 KiB | 8 KiB | 16 KiB | 16 KiB | 0.5 KiB | 57,856 B＝56.5 KiB | 74,240 B＝72.5 KiB |

小候选若同时保存独立 FP32 Ub，另加 16,384 B：单槽变为 74,240 B＝72.5 KiB，双缓冲变为 90,624 B＝88.5 KiB。大候选另加 65,536 B 的 Ub。57,856 B 可以写成 57.856 kB，却不能写成 57.9 KiB。这些仍是设定下的逻辑活跃量，不是 NKI 实际分配；转换、对齐、临时量、PSUM 路径和 bank 约束可能增加峰值。2 MiB/256 KiB=8 只是总量之比，不证明八组输出可同时推进。

转置按资源分账。DMA transpose 消耗 DMA 和 SBUF 端口；TensorE transpose 消耗矩阵引擎与 PSUM，随后要搬回 SBUF。Scalar/Vector 归约是慢端时，前者可能释放该路径；DMA 已被 K/V 加载占满时，同样的选择可能使关键路径变长。应比较整条转换与消费路径，不能仅比较转置逻辑字节。

准备包括编译、调优、分桶、布局准备与描述符。静态描述符占 HBM；软件 DGE 占 SBUF 和 GpSimd；硬件 DGE 避免这些存储与软件生成工作，但仍有发出、执行与 DMA 依赖。首次准备、按形状复用和逐请求生成具有不同摊销边界。

时间下界受矩阵工作/有效吞吐、实际边界字节/可持续带宽、非矩阵工作/对应吞吐等资源约束。独立工作可以重叠，同块 QK→softmax→PV 和必要转移则有顺序依赖；沿实际关键路径计时间。DMA copy 与 DMA transpose 竞争同一资源时，需求应合并计账。槽位等待已经位于 kernel 时间内时，不能再作为额外同步重复相加。单核片上数据共享不产生网络流量；跨核或跨设备 KV 分区需要另计 Q、部分统计量交换与完成边界。

## 条件变化与选择反转

| 条件变化 | 可保留的机制 | 应调整或放弃的选择 | 需要重算的量 |
|---|---|---|---|
| 长 prefill，L、S 大 | 在线统计和 Q tile 驻留 | 增大 Bq 减少 K/V 轮次，同时扩大分数与 U，可能减少独立任务 | G、H、活跃集合、DMA 等待、驻留 |
| 短 decode、长 KV | 同一统计量合并公式 | query 任务不足时可拆 KV，再付部分状态与合并；设备已饱和后继续分区可能变慢 | Q 重读、workspace、最终归约和同步 |
| K/V 复用更重要 | 数学函数与合法坐标 | 改为 K/V 在外，但 Q、输出和统计重读增加 | 两种循环顺序的全部交通 |
| DMA 已饱和 | 在线归约不变 | DMA transpose 可能加重等待；比较 TensorE 转置的完整路径 | DMA、TensorE、PSUM、eviction |
| Scalar/Vector 为慢端 | 精确状态关系不变 | DMA transpose 可能释放计算路径，但需要 DMA 余量 | 引擎占用、SBUF 端口、暴露等待 |
| FP8 且需要轴转换 | 逻辑点积与 FP32 累加 | 2/4 字节 DMA 转置证明不覆盖 FP8；不能叠加 Double-FP8 与 transpose mode | 预布局、合法转换、padding 和误差 |
| SBUF 或 PSUM bank 紧张 | 统计量定义与最后读者协议 | 减小 tile、减少槽或改变累加位置；更深流水可能降低驻留 | 实际分配、bank、转换、spill |
| 只改变共同收缩排列 | 稠密点积不变量 | 输出相等不能证明地址布局合法，应单独核对坐标与指令输入 | 地址映射、配对、生成指令和吞吐 |
| 动态长度变化 | 有效范围、空行与尾块契约 | 分桶、padding 或重编译；桶太大浪费，桶太多增加驻留 | 分布、填充工作、编译与加载摊销 |

这些调整不能改变模型规定的可见集合和归一化。Double-FP8 改变执行数值格式，数据表示合法、误差或质量达标、完整执行更快需要分别验证。槽位数量和 tile 大小是依赖与资源约束下的选择，没有跨条件固定最优值。

## 诊断与区分实验

attention 参考应独立构造整行可见集合与偏置，做整行稳定 softmax，不能复用被测合并函数。逐块将 m、ℓ、U 与已处理 key 前缀的独立统计比较，能定位漏项、重复项和空块残留。矩阵参考按原始 k 求和，另查坐标覆盖、配对与补零；事件模型则检查所有权、完整身份和最后读者。

两块分数为 0、2，对应 V 为 1、0。第一块后状态为 (0,1,1)，第二块局部状态为 (2,1,0)。令 e=exp(2)，正确合并为 (2,1+1/e,1/e)，输出 1/(1+e)≈0.119202922。分开注入三种错误：

| 错误 | 第二块后分母与分子 | 输出 | 凸包检查 |
|---|---|---|---|
| 只将旧 U 反向乘 exp(+2)，ℓ 正确更新 | ℓ=1+1/e，U=e | e/(1+1/e)≈6.508259021 | 越出 [0,1]，可以发现 |
| 旧 ℓ 与 U 同时反向乘 exp(+2) | ℓ=1+e，U=e | e/(1+e)≈0.880797078 | 仍在 [0,1]，无法发现 |
| 旧 ℓ 与 U 都漏掉重标度，系数取 1 | ℓ=2，U=1 | 0.5 | 仍在 [0,1]，无法发现 |

前一版脚本的 faulty='rescale' 在这个输入上将旧系数设成 exp(m₂−m新)=1，实际演示的是第三种漏重标度，并没有验证反向指数的数值。本版使用明确命名的三种注入，分别用 Decimal 计算的独立闭式结果核对，避免只证明“某个错误会有差异”。空块复用旧局部状态属于另一种重复归约错误，应单独检查；有时重复同一贡献不改变最终 O，却会改变 ℓ、U，因此只比输出也不充分。

Double-FP8 的共同置换是正向不变量观察。可检测负对照采用 A 使用 q、B 使用 1−q，或漏掉一个半区。若所谓负对照只是共同双射，输出相同是数学预期，不能把未报错归咎于检查器或解释为设备布局已通过。

| 竞争解释 | 可区分预测 | 干预与反证修正 |
|---|---|---|
| 事件缺少代次校验 | 新代建立后，旧 QK/PV 通知会改变 pending 或释放槽 | 在新代加载中、可读及仅剩最后读者时投递旧通知，逐字段核对；随后用本代真实通知验证仍能推进 |
| 只在预取时检查代次 | 错误预取会被拒绝，但旧完成通知仍可能释放新代 | 将负对照放在 release 路径；不能用 expected generation 错误的预取替代 |
| 轴或半区配对错误 | 精确标量计算也出现确定性差异，尾块改变可定位漏项 | 对照原始 k 求和与坐标表；共同置换无差异时检查地址契约 |
| 只是浮点归约差异 | 误差随块界、精度和归约树变化 | 固定输入改变块界；出现 NaN、漏项或重复项时先修算法 |
| 缩放错误被凸包检查漏过 | 反向缩放分母分子或漏缩放仍在合法值域 | 比较独立闭式结果与逐步统计量，分别注入三种错误 |
| DMA 转置改善慢端 | Scalar/Vector 等待下降而 DMA 压力上升 | 同时观测两条资源路径和完整时间；DMA 饱和且变慢时修正选择 |
| TensorE 转置更合适 | TensorE/PSUM 占用和 eviction 改变关键路径 | 比较同一结果、特殊值语义、PSUM 生存期与完整交接 |
| 深流水隐藏加载 | 单 query tile 等待下降，但多任务驻留可能下降 | 固定工作改变 D，分开测单块与整网格；D≥Tc 后额外槽不应产生加载收益 |
| 总字节足够就能驻留 | 相同总量下，布局或 bank 不同仍可能失败 | 保持总字节改变轴或槽位；失败随布局改变时优先查分配与合法性 |

随章脚本 `tools/check_k_fw_010_full.py` 提供待执行的只读离线检查：整行与逐前缀 attention 参考、空行和空块、显式偏置、L=0/S=0、尾部、极端有限分数、三种重标度闭式负对照；Double-FP8 坐标、奇数收缩补零、共同置换和半区错配；矩阵与两组 attention 容量账；旧代释放事件、重复通知、错误逻辑块和多槽首尾推进。释放负对照故意删除事件身份校验，要求检查确实观察到新代被提前释放。

这些是 CPU binary64、Decimal 和有限顺序事件模型的检查，不执行 NKI，也不模拟真实 FP8 编码、设备并发、DMA 内存可见性或性能。设备实验需固定 shape、dtype、布局、mask、数值与计时边界、预热条件，核对生成指令、SBUF/PSUM 分配、bank、spill、实际事务、等待与完整调用时间。本轮没有 Neuron/GPU 实测，也没有 Agent 使用效果证据；Python 候选脚本的实际执行结果由协调者另行保存。
