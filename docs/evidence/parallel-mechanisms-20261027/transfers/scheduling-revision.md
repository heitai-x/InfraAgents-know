# 调度迁移练习：第二阶段证据更新

日期2026-10-28。第一阶段答卷、JSON和实现保留原样。本页仅根据[第二阶段任务](../tasks/scheduling-feedback.md)提供的合成证据更新判断；下述41/161μs与6μs都不是目标GPU观测。

## 数值与支持程度

固定q=Q=4，起始历史h=4时，pairs=4×4+4×5/2=26。设定模型预测20+2×4+0.5×26=41μs。历史改为h=64时，pairs=4×64+10=266，预测20+8+133=161μs。多出240个合法query-key对，对应模型时间增加120μs，恰好与给定设备段差一致。

两者主机准备/提交段均为6μs，因此在本设定和给定不确定性内，“同Q，差距一定来自CPU准备”被反驳。这里没有把主机段无条件加到设备段得到端到端时间；是否重叠和是否另有排队仍要看实际事件依赖。

第一阶段本来就保留了历史、kernel路径、CPU准备和争用等解释，没有唯一归因。新证据增强“历史变化导致设备工作与读取变化”的支持，降低“本次全部差距来自主机准备”的支持，并不需要推翻未提出的唯一结论。与q/h模型精确吻合只说明该合成关系自洽，不构成其系数在真实机器上的校准。

## 尚不能区分的机制

这组数据不能单独区分Attention算术工作与历史KV读取。固定q时，增加h既增加QK/PV的乘加对数，也增加通常需要访问的KV集合；两者都近似随h线性增长。模型的0.5μs/pair可以吸收计算、内存或其他相关开销，不能因为它叫pairs系数就把它解释为纯算术耗时。

此外，历史长度改变可能跨过不同tile/分区/图桶，改变padding、任务数、合并开销、驻留、cache命中和实际事务。输入就绪和主机描述结构相同，并不证明设备派发路径、物理存储布局和所有争用都相同。给定的两个点与这些解释可能同时相容；没有观察到其对应指标，就保留未知。

## 下一次能区分什么

先记录两历史条件下实际派发路径、tile/分区、有效与执行工作、设备事务、资源和等待位置，确认时间窗口与输出正确。然后对每个固定的h分别比较同一份Q/K/V、mask、dtype、scale、地址和kernel，改变KV的cache驻留状态：例如在计时前只预热相同KV读集合，另设未预热对照，并保持权重和其他前置状态可比，预热开销放在单独窗口报告。两种处理必须产生相同逻辑函数和相同有效计算，不能删历史或改变offered工作量来制造更快结果。

若预热使设备主存字节显著下降，时间也随之下降，则支持原条件有内存交通瓶颈；若字节下降但时间不变，单纯主存带宽解释受到削弱，要继续看计算、共享交通或其他关键路径。cache实验本身仍可能同时影响其他数据、指令和占用，需核对计数器及权重状态，不能只凭“热了就快”宣称完全隔离KV带宽。

可再在合法工具和设备条件允许时，独立改变计算与存储通路服务能力，并为每种条件重做相关微基准校准，在同一h、同一输入、同一算法下观察时间敏感性。实际频率变化可能联动延迟/带宽，需要记录这些影响；因此它是补充证据，不是完美单因素开关。比较另一种减少重复KV读取的数据流也有价值，但必须重算它引入的寄存器、任务数和同步，不能将所有变化仅归因于带宽。

## 取消与物理复用的确认

不把这些页交给新B。owner=0只说明旧B不再逻辑拥有它们，执行票据仍在就表明设备可能尚在读写原页或页表。host处理了取消，并没有因此终止已提交的设备操作，也没有建立最后一次读取/写入完成的证据。

旧轮次的设备完成边界与相关消费者结束被确认后，按旧票据恰好一次归还物理执行引用；在没有其他逻辑拥有者、读写者或未完成消费者时才可重用，随后递增物理代次。新B使用新生命期，旧通知只清理旧清单；既不能为新B提交旧结果，也不能因生命期已变就跳过旧资源清理。若host尚未收到通知但能通过另一个有正确作用域的完成查询确认设备结束，查询可以成为依据；“取消已处理”本身不行。
