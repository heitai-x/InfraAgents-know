# 分页迁移练习：收到新证据后的修正

日期为 2026-10-28。此阶段仅依据[第二阶段题设](../tasks/paged-feedback.md)给定的合成证据更新解释支持程度；不是 GPU 实测记录。第一阶段答卷、JSON 与独立脚本保持原样。

## 哪些解释得到支持

第一阶段列了提前回收、描述/结果归属失配、重复旧完成与有效长度越界，并未选唯一原因。新证据中，页的最后物理读者完成前没有重分配，资源代次相符，COW尾页与B的页分开，旧页字节没有被追加覆盖。在这些记录确实覆盖所有相关访问的前提下，主数据页提前回收和对共享旧尾页原地修改的解释明显减弱；不能仅因症状发生在取消附近继续把它们当作主要结论。

描述包隔离后相同轨迹不再复现，恢复共享且尚在途的描述包又恢复故障，这组干预较强支持设备描述生命周期错误。一个具体机制是R0本应消费长度5、页表[5,2]，共享设备包却在它读取完之前被R1写成长度6、页表[5,7]。即使所有KV字节都正确保存，R0仍可能使用错误的可见长度与页表。题设尚未直接记录设备当时读到这些具体字段，因此这个过程是有根据的机制推断，不能写成已经观测到的逐指令事实。

结果归属错配的支持需要再细分。如果结果被正确计算却由CPU按当前活跃行归还给错误请求，新证据没有直接证明这一环节有错；仅改变设备描述包就能控制故障，使这个独立CPU路由解释相对减弱。但设备描述包也可能含请求行、输出地址或结果标识，覆盖它可能同时导致错误读取和错误归属。还不能只凭包隔离排除所有路由问题。重复完成或越界错误也没有由本次证据普遍否定；它们只是目前不必引入就能解释这条合成轨迹。

## CPU不可变对象与设备消费对象不同

CPU快照可以是不可变的长度、页表与身份集合；GPU实际读取的往往是另一个设备缓冲。两份CPU快照分别正确，不能阻止它们被先后复制到同一设备地址，更不能保证第一份内容一直保留到R0最后读取结束。异步复制还要求主机源缓冲在复制完成前保持有效；设备描述内容在消费完成前保持有效。这两个最后使用边界都需要证明。

因此应为每个在途消费者绑定设备描述包及其代次，或者证明消费者已一次性读取到独立存储且不再访问原包，再允许改写。数据页的读票结束条件不自动覆盖描述包；图的地址稳定同样不等于地址内内容稳定。描述包准备完成还需先于其消费者读取，不能只延长包的生存期却漏掉准备依赖。

## 怎样取得更直接的因果证据

下一次保留每份CPU快照与设备包的对应：请求生命期、执行票据、包地址/代次、有效长度、页表与布局身份；记录复制提交/完成、计算提交、描述最后使用、允许复用的事件依赖。让诊断版本由设备回写实际消费的描述摘要或选定字段，并与R0/R1各自的期望快照比较。记录每行原始结果的目标地址与请求身份，再在交付前核对，可以区分计算上下文错误和计算正确但路由错误。

继续采用“独立包→共享忙包→独立包”的控制，保持数据、工作量、取消轨迹及数值契约不变，并检查隔离没有通过改变容量/调度掩盖另一个问题。若共享忙包时设备回写的R0描述与R1相同或出现混合版本，而独立包时恢复正确，且原始数值结果随该字段变化，因果链会更直接。诊断本身可能改变时序，应同时保留未插桩的复现率与有限插桩结果。即使此路径被确认，也不证明所有类似尾块污染只有这一个原因。

## 复制完成、尚未发布的暂存页仍有责任方

独立反证揭示的是W——事务写入/暂存保留权——被遗漏。K/V复制完成只表示相关复制指令已结束，不表示该事务已把页交给已发布请求，也不表示放弃流程已完成。此时可能O=0、R=0，但W=1，页仍由事务负责。仅按O和R回收，会让新请求占用同一页，而旧事务随后执行放弃、释放或迟到发布；即使没有后续设备写，也可能破坏新生命期的所有权账。

取消应先撤销该事务的发布资格。事务在协调关系中确认复制及所有可能写入已完成，完成“放弃”状态转换，恰好一次地释放绑定页代次的W；此后O=R=W=0才可重用。若复制尚未结束，取消不会跳过等待。若已经完成，可以立即推进合法的放弃转换，但不能省略这一步而因O/R为零自动回收。若发布已成功，则W交接给请求映射O，取消通过当前请求映射的责任方撤销O，不能又按旧暂存状态重复释放。

“取消后不发布”描述提交权；“何时可以重用”描述对象生命周期。二者共同受协调协议约束，前者成立不推出后者已经成立。代次与一次性释放能阻止旧完成误伤新页，但不能代替事务仍持W时的保留规则。
