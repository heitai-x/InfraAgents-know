# 第二阶段：给分页答卷的新证据

以下是主审给定的合成证据，不是实际GPU故障记录；保留第一阶段文件。

针对偶发尾块污染，进一步记录显示：所有数据页都保留到其最后物理读者完成才重分配，页代次匹配，复制出的尾页与B的数据页始终不同，原页字节未被追加覆盖。问题仍可复现。每次重放使用独立且不提前覆盖的设备描述包后，问题在相同的延迟/取消/页复用轨迹下消失；把两快照放回同一个尚在途的描述包又恢复。CPU侧快照对象一直不可变。

据此更新对提前回收、原地修改、设备描述覆盖与结果归属错配的支持程度。为什么CPU对象不可变不足以证明设备消费的描述也稳定？这是否证明描述覆盖是所有类似故障的唯一原因？下一次应记录什么以建立更直接的因果证据？

还有一条独立反证：某事务的K/V复制已完成但尚未发布，请求此时取消；分配器只看O=R=0便把暂存页发给新请求，旧事务随后处理放弃。解释哪种保留责任仍未结束，怎样保证“取消后不发布”不会变成“取消后立即可复用”。
