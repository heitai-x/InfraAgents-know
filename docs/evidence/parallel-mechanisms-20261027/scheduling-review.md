# 连续批处理：从边界到执行视图的深化记录

本轮以 Attention revision8 的展开方式深化 K-ALG-001，不增加全库验收标准。范围包括连续批处理正文、ORCA/SARATHI 两份来源说明及独立 CPU 状态检查；全库身份、修订号、导航与最终验证由主 Agent 统一登记。完成核对日期为 2026-10-28，来源事实仍受 2026-04-30 上限约束。

## 核心修订及其理由

原章已解释迭代边界、设计轴、成本与公平问题，但关键状态和跨阶段算法仍有空白。现在明确 n 是已知且确认 token 前缀，k 是全层完成 KV 边界；末行采样后 n 增加但 k 不变。完整伪代码连接就绪、候选、页与工作预算、临时预留、不可变视图、提交、完成、EOS、取消和物理回收。它是保守的单请求一轮在途设计，并非对既有引擎字段的转写。

主审指出完整 KV 前缀命中而无末行 logits 时，直接设置 k=n 会让候选区间为空。正文已修正为：仍需生成时最多复用 n−1 个 token 的 KV，安全重算最后已知位置；n=1 从零历史开始。共享尾页必须先隔离可写区；恢复已确认输出不能重新采样。该修复不是扩大生成依赖。

P=4 的 A/B/C 轨迹贯穿混合 query 行、末行采样、在途取消、重排和重复旧通知。页引用与业务提交分离，旧请求结果不能按当前活跃行猜归属。配套成本按 Q、causal 对数 V、页增量、元数据、准备、提交、驻留和输出责任建立；实际物理事务与真正并行关键路径仍需运行观测。

设定模型 Tdev=4+0.015Q+0.0000005V ms 给出可复算反转：16 条 h=8192 的 decode，与新 prefill 混合，在 5.6ms 设备预算下，h=0 容许 q=86，h=4096 容许 q=75；P=16 且仅有 20 个空闲页时，decode 已消耗 16 页，使 prefill 只能 q≤64。512-token prompt 拆 8 片不减少 causal 对数，却增加固定成本，说明无竞争时整段与需频繁服务时小片的不同选择。所有数字均是设定算例，未声称目标硬件测量。

公平部分保留策略选择，给出有限活跃请求、最小服务片可行、资源最终完成等前提下的轮转进度证明，并解释持续短工作偏好怎样饥饿长请求。诊断案例把“设备段变短、ITL 却变差”分为主机空档、页等待、入选频率和设备路径四种解释，给出不同预测、干预和会改变结论的证据。

## 来源事实与独立构造

固定 ORCA 原文 §3–4.2、Algorithm 1 核对了迭代调度、选择性聚批、首次按最大 token 上限预留和多批 worker 流水。来源说明已区分其狭义 Attention 选择与数学上可构造的多段执行，明确全量预留的保证不能直接移植到逐轮按需分配。

固定 SARATHI v1 §4、Figure 6 核对了增长 causal mask、单 prefill 块加 decode-maximal batching，以及固定块会重复 KV 访问与准备的条件。本章时间预算模型、n/k 字段、事务式预留、单轮在途、轮转证明、A/B/C 轨迹和诊断数据均为本库独立构造，来源说明明确归属。既有归档字节、身份、版本、事实日期和阅读策略未改变。

## 实际验证与边界

[CPU 检查报告](scheduling.json)由 [check_iteration_schedule.py](../../../tools/check_iteration_schedule.py)生成，绑定正文和两份来源说明的 SHA。实际运行 PASS：48 个具名检查，135 个不同页长/块长/输入长/部分或完整命中的差分情形，6 种声明范围内的取消/到达/完成次序。

增量路径通过页表访问玩具递推状态；独立参考用整个 token 前缀的闭式表达重新计算，比较逐请求生成序列。覆盖未知后继拒绝、EOS、总长度/生成数量上限、n=1、完整命中无 logits、私有缓存导入、未就绪队首、页不足、结果槽预算、确定未提交的回滚、部分执行失败、取消延迟回收、旧页代次和重复完成；成本关系由独立 causal 关系枚举及整数边界核对。脚本编译检查通过。

检查没有运行 Transformer、真实 kernel、网络交付或 GPU 内存/同步/重叠；私有缓存导入不证明共享 COW 协议。有限事件模型不穷尽生产并发或过载公平。没有受控 Agent 构建/迁移/诊断对照，不能用检查数量声称达到这类效果。后续应通过正文未直接演示的任务检查迁移推导，保留答卷、可见资料、实现产物与失败原因。
